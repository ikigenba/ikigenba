# D02-cli

gmail as a command: what `cli.Run` does with its arguments, the exit codes, `db status`, and the three constants whose text is fixed here, the usage text, the manifest and the nginx fragment, with the two files under `etc/` that copy the last two. It is gdrive's command with gmail's name, its own manifest (two more settings, a larger memory bound) and the bus-only fragment every app without a private route has.

An empty `Args` means serve (`D03-serve`). `--version` writes `Process.Version`, the display string `main` read (`D01-layout-and-run-seam`), and a newline; `manifest` writes `Manifest`; `--help` writes `Usage`; `db status` writes what appkit's `db.Status` writes for `state/gmail.db` and the root package's `Migrations()`. Any other `Args` is a usage error: `gmail: unknown option '<arg>'` or `gmail: unknown command '<arg>'`, an empty line, and the hint to run `gmail --help`. A command touches nothing but what it names: `db status` does not create the database, and no command reads the environment, the services file, a sibling or Gmail.

## The manifest

The manifest is a program-parsed file: opsctl, the sandbox and home read it, so its text is contract and is stated here byte for byte, and `etc/manifest.toml` holds the same bytes. It names the app `gmail`; its description, decision 1's text, the same as `pages.Description` (`D08-pages`); that it is not the default app; that it is an MCP service (`mcp = true`), so the gateway offers its tools; that it does not serve guests (`guests = false`), so the host's nginx admits only a request with a credential; no secrets, since Google's token comes from connections over its socket; an `[env]` table holding the seven settings' defaults as strings, in the order `settings.Read` reads them (`D03-serve`), so the values the host writes into gmail's environment are the ones gmail applies when a setting is unset; the `[database]` table that has the host keep and replicate `state/gmail.db`; a `[resources]` table whose only line is `memory_max = "256M"`, room for two pulls at the 50 MiB cap each holding about four thirds of its attachment encoded (decision 12); and, last, a `[home]` table whose only line is `group = "core"`. `DRAIN_SECONDS` is not in `[env]`: it is the space's, as for every app.

## The nginx fragment

The fragment, `NginxConf`, answers the event bus's two paths, `/events` and `/declarations`, 404 at the public name, as every app's fragment does. gmail has no route of its own that must stay on the host, and takes no request body larger than an MCP call, since attachment bytes move between Gmail and artifacts and never through nginx.

## Exit codes

`ExitSuccess` (0), `ExitServerFailed` (1) and `ExitUsage` (2), as every app: a usage error, a setting refused or a socket missing is 2; a database that will not open, a start refused or a drain that ran out is 1.

## Recorded decisions

- The usage text, the manifest and the fragment are contract, not copy: each is a command's standard output or a file a program parses, so each is spelled here. The usage text's prose is gmail's own.
- The description is decision 1's text, spelled in `Manifest` and declared with the same value as `pages.Description` (`D08-pages`); a test compares the two.
- The `[env]` values are compared with `settings.Defaults()` (`D03-serve`), so a default cannot drift between the manifest and the code. `TRANSFER_MAX_BYTES` is 52428800 (50 MiB, Gmail's receive limit) where gdrive's is a gigabyte, and `DRAFT_KEEP_DAYS` and `DRAFT_KEEP_COUNT` are gmail's own (decision 18).
- `memory_max` is `256M` where gdrive's is `128M`: gdrive streams every byte, while a gmail pull holds one encoded copy of the attachment (decision 12).
- No release is named in the manifest or in any requirement (root ruling A10).
- `Manifest` and `NginxConf` are copied into `etc/` byte for byte, which a test proves through the root package's `Etc`.

## Consumer tasks

An operator's host reads `gmail manifest` and `etc/manifest.toml` to learn the app, its settings' defaults and its database, and drops `etc/nginx.conf` into gmail's server block. A developer runs `gmail --help`, `gmail --version` and `gmail db status` from the install directory. A test builds a `cli.Process` with only `Args`, `Stdout`, `Stderr` and `Dir` (an empty temporary directory) set, calls `cli.Run`, and compares the returned value with `cli.ExitSuccess` or `cli.ExitUsage`, `Stdout` with `p.Version + "\n"`, `cli.Manifest` or `cli.Usage`, and `Stderr` with the exact diagnostic; to prove nothing else is touched it sets every other function field to one that records a call, `Rand` to a reader, the sinks to captures and `HTTP` to a client whose transport records any request, and asserts none was used and `Dir` is still empty. A test of `db status` makes a database under its `Dir` with `db.Open` and the root package's `Migrations()`, closes it, runs `cli.Run` with `Args` `["db", "status"]`, and compares `Stdout` with what its own `db.Status` call writes. A test compares `cli.Manifest` with `pages.Description` and with the fields of `settings.Defaults()`, and reads `manifest.toml` and `nginx.conf` from the root package's `Etc()` with `fs.ReadFile` to compare them with `cli.Manifest` and `cli.NginxConf`.

- R-WGM9-HDE5: The `internal/cli` package MUST export `Manifest` as a string constant whose value is exactly `app = "gmail"\ndescription = "Gmail messages read, attachments pulled into artifacts, drafts composed and sent"\ndefault = false\nmcp = true\nguests = false\nsecrets = []\n\n[env]\nTRANSFER_MAX_BYTES = "52428800"\nTRANSFER_MAX_ACTIVE = "2"\nTRANSFER_MAX_QUEUED = "10"\nTRANSFER_KEEP_DAYS = "15"\nTRANSFER_KEEP_COUNT = "100"\nDRAFT_KEEP_DAYS = "15"\nDRAFT_KEEP_COUNT = "100"\n\n[database]\nengine = "sqlite"\npath = "state/gmail.db"\n\n[resources]\nmemory_max = "256M"\n\n[home]\ngroup = "core"\n`, each `\n` denoting one line feed and each `"` one double quote.
- R-WHU5-V54U: `cli.Manifest` MUST contain the line `description = "` followed by exactly the text of `pages.Description` (`D08-pages`) followed by `"`, so that the description the manifest publishes and the one the about screen shows are the same string.
- R-WJ22-8WVJ: The `[env]` table of `cli.Manifest` MUST hold, in this order and as the only lines between the line `[env]` and the empty line that follows it, `TRANSFER_MAX_BYTES = "`, `TRANSFER_MAX_ACTIVE = "`, `TRANSFER_MAX_QUEUED = "`, `TRANSFER_KEEP_DAYS = "`, `TRANSFER_KEEP_COUNT = "`, `DRAFT_KEEP_DAYS = "` and `DRAFT_KEEP_COUNT = "`, each followed by the decimal form of the field `TransferMaxBytes`, `TransferMaxActive`, `TransferMaxQueued`, `TransferKeepDays`, `TransferKeepCount`, `DraftKeepDays` and `DraftKeepCount` respectively of `settings.Defaults()` (`D03-serve`) and a closing `"`, so that the defaults the host writes into gmail's environment are the ones gmail applies when a setting is unset.
- R-WK9Y-MOM8: The `internal/cli` package MUST export `const NginxConf = "location = /events { return 404; }\nlocation = /declarations { return 404; }\n"`.
- R-WLHV-0GCX: The contents of `manifest.toml` and `nginx.conf` in the file system the root package's `Etc` returns MUST be exactly the bytes of `cli.Manifest` and `cli.NginxConf` respectively.
- R-WMPR-E83M: The `internal/cli` package MUST export `ExitSuccess`, `ExitServerFailed` and `ExitUsage` as untyped integer constants with the values 0, 1 and 2 respectively, and every call of `Run` MUST return one of them and no other value.
- R-WNXN-RZUB: When `Args` is exactly `["--version"]`, `["manifest"]` or `["--help"]`, `Run` MUST write exactly `p.Version + "\n"`, `Manifest` or `Usage` respectively to `Stdout` and nothing else, write nothing to `Stderr`, and return `ExitSuccess`; so that an empty `p.Version` writes exactly `"\n"`.
- R-WP5K-5RL0: `Run` MUST treat `Args` as a usage error unless it is empty or exactly one of `["--version"]`, `["manifest"]`, `["--help"]` and `["db", "status"]`; the offending argument MUST be `Args[0]` when it is none of `--version`, `manifest`, `--help` and `db` or when `Args` is exactly `["db"]`, `Args[2]` when `Args[0]` is `db` and `Args[1]` is `status`, and `Args[1]` otherwise; so that `["db"]` names `db`, `["db", "bogus"]` names `bogus`, `["db", "status", "extra"]` names `extra` and `["manifest", "extra"]` names `extra`.
- R-WQDG-JJBP: On a usage error from `Args`, `Run` MUST write exactly `"gmail: unknown option '" + arg + "'\n\nsee 'gmail --help' for usage\n"` to `Stderr` in one call to `Stderr.Write` when the offending argument `arg` begins with `-`, and exactly `"gmail: unknown command '" + arg + "'\n\nsee 'gmail --help' for usage\n"` otherwise, write nothing to `Stdout`, and return `ExitUsage`; so that `["bogus"]` writes `gmail: unknown command 'bogus'` and `["--bogus"]` writes `gmail: unknown option '--bogus'` as its first line.
- R-WRLC-XB2E: When `Args` is not empty, `Run` MUST return without calling `LookupEnv`, `Unsetenv`, `Inherit`, `Now`, `Sleep`, `After`, `Banner` or `MCP`, without calling `Rand`'s `Read`, without sending any request through `HTTP`, without calling the `Deliver` of `Sink` or `EventSink`, without taking file descriptor 3 and without sending anything to a notification socket, so that a `Process` whose `Args`, `Stdout`, `Stderr` and `Dir` alone are set is enough for every command; and, unless `Args` is exactly `["db", "status"]`, without creating, removing or changing anything under `Dir`.
- R-WST9-B2T3: When `Args` is exactly `["db", "status"]`, `Run` MUST write to `Stdout` exactly the bytes, and nothing else, that appkit's `db.Status` (package `github.com/ikigenba/ikigenba/appkit/db`) writes when called with a context that is not done and a `db.Config` whose `Path` is `filepath.Join(Dir, "state", "gmail.db")` and whose `Migrations` is the root package's `Migrations()`, over the database as it is when `Run` is called, and MUST leave a `Dir` that names an empty directory empty; and when that call returns nil, `Run` MUST write nothing to `Stderr` and return `ExitSuccess`.
- R-WU15-OUJS: When `Args` is exactly `["db", "status"]` and the `db.Status` call R-WST9-B2T3 describes returns a non-nil error `err`, `Run` MUST write exactly `"gmail: " + r + "\n"` to `Stderr` in one call to `Stderr.Write`, `r` being `err.Error()` with every newline replaced by one space, and return `ExitServerFailed`; so that a `Dir` whose `state/gmail.db` is a regular file that is not a SQLite database gets that one line on `Stderr`.
