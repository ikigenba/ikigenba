# D04-store

The records: `internal/store`, which owns gmail's two tables in its SQLite database, `state/gmail.db`: `transfers`, one row per transfer a `pull` or `push` recorded (decision 11), and `drafts`, one row per draft `compose` made (decision 10), each until the prune removes it. It says what a transfer and a draft hold, the words their direction, status and failure reason are spelled with, how each is recorded and moved from state to state, which reads the engine, the drafts service, the pages and the tools have, how the prunes decide what is past keeping, the errors every consumer tells apart, and the one line every consumer answers when the database cannot be reached. Opening, migrating, transactions, `db status` and the failure seam are appkit's `db`; `D01-layout-and-run-seam` resolves the path and declares the root package's `Migrations()`. It is gdrive's store with mail's references in the transfer and a second record beside it.

## One database, one writer

gmail is the only writer of its database, and the database is the only record of its transfers and drafts; there are no blobs. A draft's body is kept here, and only here, so that `push` can rebuild the message (decision 9); it never reaches telemetry, the bus or a page (`D09-trail`). `store.New` builds a store over a handle and opens or creates nothing. What a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds; a test proves the records that way, never by reading tables. A store whose handle is failing (`SetFailing(true)`) answers every call with `ErrUnreachable` and changes nothing. `Config.Now` is the clock every stamp and every prune comparison is read from, and `Config.Rand` the source ids are drawn from; `Run` hands in `Process.Now` and `Process.Rand`, and the store has no default for either.

## Transfers

A **transfer** is one move of one attachment, one whole message or one artifact, made for one user. Its **id** is `xfr_` and 16 lowercase hexadecimal digits, 8 bytes drawn from the random source when the transfer is recorded, drawn again when they are a transfer's id already. Its **direction** is `pull` (Gmail to artifact) or `push` (artifact onto a draft). It keeps `message`, the Gmail message id (a pull's source; a push's draft message, refreshed when the upload completes, since `drafts.update` gives the draft a new message), `attachment`, the part id of a pulled attachment (empty for a whole message and for a push), `draft`, the `drf_` id a push attaches to (empty for a pull), `name` (the attachment's filename, the message's subject for a whole message, the path's last segment for a push, as `D06-transfers` sets it), the artifact's `path`, the `content_type` the bytes carry, `bytes`, the count moved so far and final when done, **started** and **finished**, each UTC to the second, and, once done, the artifact's `url`, the Gmail `link`, and the artifact's id when artifacts' `Put` answered one, which only a pull has. It also keeps the caller it was made for, the user id, the email and the originating request id, so the work runs as that caller when no request is left and every read is scoped to the user.

Its **status** is one of four words: `queued`, `running`, `done` and `failed`. A failed transfer has one of seven **reasons**: `not_found`, `forbidden`, `too_large`, `reconnect`, `provider`, `artifacts` and `interrupted`; which failure is which is `D06-transfers`'.

A transfer has four writes. `AddTransfer` records it once, `queued` or `running` as the engine decides, stamping started and minting the id. `StartTransfer` moves a `queued` transfer to `running`. `SetTransferBytes` records progress on a `running` one. `FinishTransfer` ends it exactly once: a `running` one as `done` or `failed`, a `queued` one only as `failed`; a done ending carries the url, the link, the artifact's id and, for a push, the draft's new message id. Of two calls racing on the same transfer one succeeds and the other is told it is no longer in the state it needed (`ErrEnded`). Nothing moves a transfer back.

## Drafts

A **draft** is one message `compose` made at Gmail for one user, and the composition the connector keeps to rebuild it (decision 9). Its **id** is `drf_` and 16 lowercase hexadecimal digits, drawn as a transfer's is; it is the connector's own, because Gmail's draft id ends at send. It keeps `gmail_draft`, Gmail's draft id while `open`; `message`, the draft's message id, and `thread`, its thread id, both refreshed on each push and on each probe that finds Gmail holding others, and set from the sent message once sent; the composition: `to`, `cc` and `bcc` (each a list of addresses in order), `subject`, `body` (plain text), `reply_to` (the Gmail message id it replies to, empty when not a reply) and the two header values a reply carries, `In-Reply-To` and `References`; the **attachments**, each `path`, `name`, `content_type` and `bytes`, in the order attached; **created**, **modified** (always set, advancing on each push, send or discard) and **sent**; and the user it was made for. Its **link** is not stored but derived on every read from its status and message: `urls.DraftLink(message)` while open, `urls.MessageLink(message)` once sent, empty once discarded (the orchestrator's settled forms, `D01-layout-and-run-seam`).

Its **status** is `open`, `sent` or `discarded`. A draft has five writes. `AddDraft` records it `open`, stamping created and modified and minting the id. `AttachToDraft` appends one attachment to an `open` draft and refreshes its message and thread, once the push's upload has completed (decision 9, root ruling A6). `MarkDraftSent` ends an `open` draft as `sent`, with the sent message's id, its thread and the time it was sent: the time given, or the clock's when none is given, so a draft found sent in Gmail can carry the message's own time (root ruling A6). `MarkDraftDiscarded` ends an `open` draft as `discarded`, keeping its message. Each of the three advances modified. A fifth write, `SetDraftMessage`, stores an `open` draft's current message id and thread when a reconciling probe finds Gmail holds others, without advancing modified (root rulings A18, A19). Gmail's draft id is cleared when a draft ends. A write on a draft that is not `open` is refused with `ErrNotOpen`; of two racing, one succeeds.

## Reads and the prunes

`GetTransfer` and `GetDraft` answer one of a caller's own records, so another user's is indistinguishable from none. `ListTransfers` is one user's transfers newest first (descending started, then descending id); `ListDrafts` one user's drafts newest first (descending created, then descending id). `UnfinishedTransfers` is every transfer still `queued` or `running`, of every user, which the start finishes as `failed` with `interrupted`. `PruneTransfers` removes, in one write, every transfer neither `queued` nor `running` that started more than the keep days before the moment given and is not among its user's newest keep count in list order, every transfer of the user counting toward that rank. `PruneDrafts` removes, in one write, every finished draft, `sent` or `discarded`, whose modified, the moment it ended, is more than the keep days before the moment given and which is not among its user's newest keep count of finished drafts in `ListDrafts` order (root ruling A12); an `open` draft neither counts toward the keep count nor is ever removed (decision 17). A pruned record is gone from every read; the artifact, message or draft it made is not the store's to touch. All lists are never nil.

## Errors

`ErrNotFound`, `ErrEnded` and `ErrNotOpen` are answers about the records. Every other error satisfies `errors.Is(err, ErrUnreachable)`, and every consumer answers it with `Unreachable` (or, for a page, `D08-pages`' unavailable answer), never quoting the cause. A done context, a failing handle, a random source that fails and a write given a value no consumer sends all end there, the last changing nothing.

## Recorded decisions

- The schema is two migrations. `0001_transfers.sql`: `transfers` (`id` primary key, `direction`, `status`, `reason`, `message`, `attachment`, `draft`, `name`, `path`, `content_type`, `bytes` integer, `started`, `finished`, `url`, `link`, `artifact_id`, `user_id`, `user_email`, `request_id`), with an index on `user_id` and `started`. `0002_drafts.sql`: `drafts` (`id` primary key, `gmail_draft`, `message`, `thread`, `status`, `to_addrs`, `cc_addrs`, `bcc_addrs` and `attachments`, each a JSON array as text, `subject`, `body`, `reply_to`, `in_reply_to`, `references_header`, `created`, `modified`, `sent`, `user_id`), with an index on `user_id` and `created`. Times are RFC 3339 UTC to the second; an empty `finished` or `sent` is one not yet set. No requirement states the schema, since a test proves the records through the store; the sandbox check, which sets a transfer to `running` by hand, writes these columns. `to`, `references` and the other SQL keywords are avoided as column names.
- The attachments live in a JSON column of `drafts`, not a third table: decision 17 names two tables, and an attachment is read only with its draft.
- The draft's `link` is derived, not stored: it is a function of status and message, and storing it would let the two disagree. A transfer's `link` is stored, because it is a snapshot taken when the transfer finished (orchestrator's settlement).
- `Transfer.ArtifactID` is kept as gdrive keeps it, though decision 11 does not list it: the transfer page links to the artifact's page by id (`D08-pages`). A draft attachment keeps no id, since `Head` answers none; its link is derived from its path (`D01-layout-and-run-seam`).
- `Ending.Message` exists because `drafts.update` gives a draft a new message id (root ruling A6): a push's transfer and its draft both carry the new id once the upload completes, so the done push's `link` names the draft Gmail holds. A `FinishTransfer` with an empty `Message` keeps the recorded one, as every pull's does.
- `AttachToDraft` takes the attachment, the new message id and the thread in one write, so a draft is never left holding an attachment Gmail does not, or a message id that does not name its contents.
- `SetDraftMessage` exists for root rulings A18 and A19: every `drafts.update`, a person's edit in Gmail included, gives the draft a new message id, and a draft that is not a reply a new thread id too (observed, `D07-drafts`); the next probe that sees them stores them, so the link names the message Gmail holds and a later reconciliation looks in the thread the draft is in. A thread given empty keeps the stored one, as Gmail's answer may lack it. It leaves `modified` alone, because nothing the connector did changed the draft.
- `MarkDraftSent` takes the sent time because a draft sent by the person in Gmail is learned later (decision 10); a zero time means the clock's. `D07-drafts` passes the sent message's internal date when the reconciliation finds it and none for its own send. It takes the thread because Gmail answers the sent message with one, the thread the record then names.
- The composition keeps the reply's `In-Reply-To` and `References` header values, so every push rebuilds a reply without fetching the original again. These are technical fields no tool answers.
- Drafts are pruned by age from `modified`, not `created`: a draft kept open for weeks and then sent is kept for the full keep days after it was sent.
- Drafts are kept by gdrive's rule for transfers, both conditions together, with one difference (root ruling A12): only `sent` and `discarded` drafts count toward `DRAFT_KEEP_COUNT`, so open drafts, which are never pruned, never push a finished one out of the kept count.
- The store's methods are renamed from gdrive's (`Add` to `AddTransfer`, `Start` to `StartTransfer`, `SetBytes` to `SetTransferBytes`, `Finish` to `FinishTransfer`, `Get` to `GetTransfer`, `List` to `ListTransfers`, `Unfinished` to `UnfinishedTransfers`, `Prune` to `PruneTransfers`, and `IDPrefix` and `ValidID` to `TransferIDPrefix` and `ValidTransferID`), because one store now holds two kinds of record and each name says which it touches.
- The store does not scope its writes by user: the engine and the drafts service read the caller's own record with `GetTransfer` or `GetDraft` before writing, as in gdrive.
- `ErrNotOpen` is a sentinel of its own rather than `ErrEnded`, so the tools map it to `not_open` without asking which kind of record failed.
- `Draft.UserID` is the only caller field a draft keeps: no work runs later as a draft's caller, since a push's work runs as its transfer's caller.
- A write given a value no consumer sends answers an error matching `ErrUnreachable` and changes nothing, as in gdrive; there is no `ErrInvalid`.
- The id redraw is bounded at 8 candidates per record, as in gdrive.

## Consumer tasks

The engine, `c` the caller, records a pull with `t, err := st.AddTransfer(ctx, store.Transfer{Direction: store.DirectionPull, Status: store.StatusRunning, Message: m, Attachment: part, Name: filename, Path: path, ContentType: ct, UserID: c.UserID, UserEmail: c.Email, RequestID: c.RequestID})`, later `st.StartTransfer`, `st.SetTransferBytes(ctx, t.ID, n)` and `st.FinishTransfer(ctx, t.ID, store.Ending{Status: store.StatusDone, Bytes: n, URL: meta.URL, Link: urls.MessageLink(m), ArtifactID: meta.ID})`. A push records `Direction: store.DirectionPush, Draft: d.ID, Message: d.Message`, and on completion calls `st.AttachToDraft(ctx, d.ID, store.Attachment{Path: path, Name: name, ContentType: ct, Bytes: n}, newMessage, newThread)` and `st.FinishTransfer(ctx, t.ID, store.Ending{Status: store.StatusDone, Bytes: n, Message: newMessage, Link: urls.DraftLink(newMessage)})`. The drafts service calls `st.AddDraft(ctx, store.Draft{GmailDraft: g, Message: m, Thread: th, To: to, Cc: cc, Bcc: bcc, Subject: s, Body: b, ReplyTo: r, HeaderInReplyTo: irt, HeaderReferences: refs, UserID: c.UserID})`, `st.GetDraft(ctx, c.UserID, id)`, `st.MarkDraftSent(ctx, id, sentMessage, sentThread, time.Time{})`, `st.MarkDraftDiscarded(ctx, id)` and `st.SetDraftMessage(ctx, id, message, thread)`, `store.ErrNotOpen` answering `not_open`. The start calls `st.UnfinishedTransfers(ctx)`; the sweep `st.PruneTransfers(ctx, now, s.TransferKeepDays, s.TransferKeepCount)` and `st.PruneDrafts(ctx, now, s.DraftKeepDays, s.DraftKeepCount)`. The tools and pages call `st.ListTransfers`, `st.GetTransfer`, `st.ListDrafts` and `st.GetDraft`, `store.ErrNotFound` answering not found and `store.ErrUnreachable` with `store.Unreachable`. A test opens its own database with `db.Open` and the root package's `Migrations()`, builds `store.New(d, store.Config{Now: clock, Rand: rnd})`, records another user's records, flips `d.SetFailing(true)`, and reopens the path to prove what persists.
