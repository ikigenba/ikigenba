# Decision 21 — Gmail's outbound calls move onto the shared instrumented HTTP client

**Problem.** Every call gmail makes to Google — the OAuth token refresh and
every Gmail REST v1 request — leaves the box through a client gmail builds
itself: `NewClient(cfg, nil)` falls back to a bare
`&http.Client{Timeout: 100 * time.Second}`, and the composition root
(`cmd/gmail/main.go`) passes exactly that `nil`. Those calls are invisible to
the suite's telemetry, which is precisely the blind spot the capability exists
to close: a forensic agent can see that an MCP `send` was called but not that
Gmail accepted it, how long Google took, or how large the response was.

**Decision.** gmail keeps its existing injection seam and changes only what the
**default** is. The `*http.Client` parameter on `NewClient` stays (tests inject
a stub `RoundTripper` and run offline); the nil case is now filled at the
**composition root** with appkit's shared instrumented client, and the
package-level fallback stops being a bare client.

Consumed from appkit's design (see `project/research/research.md` — gmail
designs none of its internals). The chassis exposes the instrumented client
directly off the runtime, so gmail never names `appkit/telemetry`:

```go
// appkit — the service-facing seam.
func (rt *Router) HTTPClient(timeout time.Duration) *http.Client
```

`cmd/gmail/main.go`, inside the `Handlers` hook where the three `GMAIL_*`
secrets are already read, is a one-liner:

```go
client := gm.NewClient(cfg, rt.HTTPClient(100*time.Second))   // gmail's existing timeout
```

and `internal/gmail`'s fallback becomes an instrumented-shaped client rather
than a bare one, so a caller that passes `nil` cannot silently reopen the blind
spot. Below the composition root there is no runtime to ask, so this one site
names the underlying package (with no recorder — it records nothing, which is
correct for a client no `Handlers` hook wired):

```go
func NewClient(cfg Config, httpClient *http.Client) *Client {
    hc := httpClient
    if hc == nil {
        hc = httpclient.New(httpclient.Options{Timeout: 100 * time.Second})
    }
    …
}
```

**One client, both paths.** `NewClient` already hands the same `*http.Client`
to the REST `Client` and to the embedded `tokenSource`. That stays true and
becomes load-bearing: the `oauth2.googleapis.com` token refresh is an outbound
call like any other and must be recorded too. A build that instruments only the
REST path leaves every credential exchange unrecorded.

**What gmail does not do.** The recording itself — `kind` `outbound`, the
`<METHOD> <host><path>` op, status, duration, request/response sizes and
digests — and the rule that `X-Correlation-Id` is propagated **only** to
loopback suite peers and never to Google are the transport's, proven by
appkit's own ids. gmail's obligation is exactly that its clients are built
through that transport; it re-verifies none of the chassis's behavior.

**Scope: the service binary only.** `cmd/consent` is a one-time operator CLI
run off-box to mint a refresh token. It has no appkit runtime, no recorder, and
no service identity, and the suite contract excludes operator tooling from
recording. Its `http.DefaultClient` call stays as it is.

**Judgment calls recorded.** (a) The nil-fallback is filled with an
*uninstrumented-but-instrumented-shaped* client (a `httpclient.New` with no
recorder) rather than left as a bare `http.Client`, so there is exactly one way
gmail builds an outbound client and a future call site cannot regress by
omission. (b) The 100-second timeout is carried across verbatim rather than
adopting the chassis's 30-second default — Gmail attachment fetches are slow
and shortening the timeout would be a behavior change smuggled in under a
telemetry adoption. (c) `Base` is left at its default in production; tests
inject a whole `*http.Client` at the existing seam, or a stub through
`httpclient.Options.Base`, rather than gmail composing a transport of its own.

**Rejected.**
- **Removing the `*http.Client` parameter and building the client inside
  `internal/gmail`** — the parameter is how every existing offline test drives
  the client without a network; deleting it would rewrite the entire test suite
  to gain nothing.
- **Passing the recorder into `internal/gmail` and letting it construct the
  instrumented client** — pushes an appkit runtime dependency below the
  composition root, which the module's convention (all environment and runtime
  wiring at the boundary) forbids.
- **Wrapping gmail's existing client with a hand-rolled recording
  `RoundTripper` here** — duplicates the shared transport, and the
  correlation-propagation rule (loopback only) would then have eight
  independent implementations to get wrong.
- **Instrumenting only the REST client and leaving `tokenSource` on a bare
  client** — token refreshes are the calls most worth seeing when the connector
  breaks, and the two already share one client.

**Verification.** The first two ids are proven **by the record that arrives**,
not by a type assertion: a real `httptest.NewServer` stands in for Google, a
real `telemetry.Recorder` drains to a live in-process ingest sink, and the test
asserts an `outbound` record for the call reaches that sink. This is the
substrate that can falsify the claim — asserting "the transport is the
instrumented type" is a proxy a stub also satisfies, and it would not prove the
service actually re-pointed its client. (The claim that a **real Gmail** call
still succeeds through the instrumented transport is **not** re-minted here —
it is D19's existing live round-trip id `R-3NGL-AMPW`, `-tags live` against the
real API, which exercises this client end to end once the default changes.)
- R-ZUC0-6K42 — driving a Gmail REST call through the client the composition
  root builds — assembled the way `Handlers` assembles it, against an
  `httptest` server, with the runtime's recorder draining to a live sink —
  delivers an `outbound` record to that sink naming the call's method and the
  test server's host and path. A build that hands `gm.NewClient` a bare
  `&http.Client{…}` (or leaves the `nil`) delivers no record and fails.
- R-ZWRS-Y3LG — an OAuth **token refresh** driven through that same assembled
  client likewise delivers its own `outbound` record to the sink, so credential
  exchanges are recorded and not just REST calls. A build that gives the
  embedded `tokenSource` its own client, or `http.DefaultClient`, delivers only
  the REST record and fails.
- R-ZXZP-BVC5 — `gm.NewClient(cfg, hc)` with a non-nil `hc` whose transport is
  a test `RoundTripper` uses **that** client for both a REST request and a
  token refresh: the stub observes both round trips and no request escapes to
  the network. The offline injection seam is unchanged by this Decision.
- R-ZZ7L-PN2U — the timeout on the client the composition root builds is
  exactly `100 * time.Second` — not the chassis's 30-second default and not
  zero (no timeout). A build that adopts the default fails.
