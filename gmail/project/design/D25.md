# Decision 25 — Testing-language conformance: adopt the suite contract and make the live layer reachable

**Decision.** gmail adopts the suite testing-language contract
**`root project/design/D23.md`** by value: the four layer names
(hermetic / composed / live / manual), the rule that the default gate carries
only hermetic and composed tests, the single live mechanism (`//go:build live`
plus a documented invocation, hard-failing on absent credentials), the ban on
`t.Skip` outside live-tagged files, and the requirement that the tree declare its
testing facts in `AGENTS.md`. The contract is cited, never restated — nothing
here redefines a layer or re-specifies the mechanism.

**gmail's declared facts.** These are the tree-specific values the contract asks
each adopter to state; they are what the `AGENTS.md` Tests section and the design
Conventions must say:

| fact | value |
|---|---|
| default-gate test command | `cd gmail && go test ./...` |
| layers present | **hermetic**, **composed**, **live** |
| environmental preconditions beyond the Go toolchain | none |
| GOWORK mode | workspace (the repo-root `go.work`); the production build forces `GOWORK=off` via `bin/ship gmail` |
| live invocation | `cd gmail && go test -tags live ./...` |
| live credentials | `GMAIL_CLIENT_ID` / `GMAIL_CLIENT_SECRET` from the operator's environment (channel 2) and `GMAIL_REFRESH_TOKEN` from the local `state/` file the client reads (channel 5, `project/design/D28.md`; seeded by `consent` or `opsctl seed-state`) — the same credentials, from the same places, the deployed service uses; all required, the live test **fails loudly** if any is missing |
| when the operator runs live | at **deploy verification** for gmail, and whenever a change touches the Gmail client (`internal/gmail/client.go`), the attachment/multipart path, or the OAuth token exchange |

The **composed** layer is `cmd/gmail`'s boot and wiring tests over the shipped
`share/www` tree and the assembled chassis handler; the **hermetic** layer is
everything else in the default gate, including the `etc/nginx.conf` content
assertions. gmail has no **manual**-layer check of its own.

**gmail's live mechanism is already conformant; its reachability was not.**
`internal/gmail/live_test.go` carries `//go:build live`, and its
`requiredLiveCredential` helper already `t.Fatalf`s on an absent variable rather
than skipping — it is the shape the contract asks every tree for, and no code in
it changes. The defect is documentary: D19's id **R-3NGL-AMPW** sits behind a
build tag that **no committed document tells anyone to run**. The `AGENTS.md`
Tests section names only the package checks, and the design Conventions named no
live invocation, so a coverage grep sees a realized id while the behavior is in
practice never exercised — a dead test wearing a live test's clothes. The fix is
the contract's own remedy: the tree states the invocation, the credentials, and
the occasion, which is what makes a tagged id legitimately reachable rather than
dead. That statement is the Conventions block plus the `AGENTS.md` declaration,
and it is the whole of this Decision's change to the live layer.

Because gmail's default gate contains no `t.Skip` today, the adopted scan id
below passes on the day it lands. It is still carried, not waived: the contract
marks it `[proof: per-service]` precisely so the property is re-checked on every
gate run rather than asserted once at authoring time.

**Rejected.**

- *Treating gmail as already conformant and adding no Decision.* Conformance is
  the default and needs no Decision, but gmail is **not** conformant: it declares
  none of the four facts the contract requires of every tree, and its live id is
  unreachable by any documented command. Silence here would leave both gaps.
- *Documenting the live invocation only in `AGENTS.md`.* The contract asks a tree
  with a live layer to state the invocation, credentials, and occasion **in its
  design Conventions**; `AGENTS.md` carries the tree's testing-facts declaration.
  Both are required, and they say different things — Conventions is where the
  Decisions that own live ids point.
- *Skipping the `t.Skip` scan because gmail has no skips.* A property that holds
  today and is never checked is a property that stops holding quietly. The scan
  is cheap and its whole value is being run on every gate.
- *Folding the live invocation into the existing "Test command" bullet.* The
  default gate and the live invocation are different commands with different
  preconditions and different occasions; collapsing them is exactly the
  ambiguity the contract's layer split exists to remove.
- *Restating D23's layer definitions in this design.* A local copy of a suite
  contract is drift by construction; the citation is the whole mechanism.
- *Minting fresh gmail ids for the two contract behaviors.* The contract marks
  both `[proof: per-service]`; citing them is adoption, and re-minting would
  create a second handle for one behavior.

  environmental precondition beyond the Go toolchain, and its GOWORK mode —
  failing if any declaration is absent or names a layer gmail does not have.

  Adopted from `root project/design/D23.md` (`[proof: per-service]`).

  Adopted from `root project/design/D23.md` (`[proof: per-service]`).
