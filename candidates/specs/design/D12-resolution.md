# D12-resolution

Resolution: how rows become candidates and how the owner's rulings move them (decisions 4, 5, 6 and 10). It owns the normalized keys a reading carries (`sources.NameKey`, `sources.PhoneKey`, `sources.DomainKey`, `sources.County`, `sources.SourceKey`), the **match key**, a candidate's **display** (the fields and tags it shows, from its freshest evidence that gives each), and the three store writes that change which candidate a row belongs to: `store.Attach` (the attach rule), `store.MarkGone` (a row absent from its scraper's latest run) and `store.Decide` (the five rulings). The records and their shapes are `D04-store`'s; what a source reads from a row is `D05-sources`'; what a judge writes, and the effect of `exclude` and `include` on the assessment, are `D13-scoring`'s; the engine that calls `Attach` and `MarkGone` is `D06-passes`'; the `decide` tool is `D10-tools`'.

## Candidates

A candidate is a record with an opaque, permanent id, `cand_` and 16 lowercase hex digits drawn from the random source when it is created, never derived from a name, an address or a DOT number (`D04-store` mints it). It is `active` or `merged`, with the id it was merged into; it is never deleted, its id never changes, and a merged candidate never becomes active again. The valid set is every candidate not merged; excluded is a flag on the assessment, so an excluded candidate is still valid (`D13-scoring`).

An active candidate shows its **display**. Its name and address (street, city, state, ZIP and county) are its **display link**'s, its freshest evidence, which is the first of its links in the order `store.Links` answers them: not gone first, then newest filing date, then newest last seen (decision 4), so a candidate whose every link is gone shows its freshest gone link. Its phone, email, people and class tag each come from the first of its **giving links** that gives a value for it: the giving links are its links not gone, in that order, or all of its links when every one is gone. So a link that says nothing about a field never blanks it: a PPP row, which carries no phone, email, people, class or cargo, can lead a candidate's name and address without hiding the carrier's phone or its `for_hire` class. Its cargo tags are, as before, the union of its links' cargo tags, gone ones included. Its `names` are every name any of its links uses, each link's name before its other names, the display name first. Every write that changes a candidate's links leaves its display current, and `updated` moves only when a field of the candidate changed. A merged candidate keeps the display fields and tags it had at the merge; only its links move.

## Keys

The **name key** is the name upper-cased, punctuation stripped, white space collapsed, and the legal suffixes `INC`, `LLC`, `CO`, `CORP`, `LTD` and `COMPANY` dropped from the end. The **match key** is the name key with the row's state and five-digit ZIP; a reading without all three has none, so a row with no name or no ZIP never joins another (under-merging is the intended failure). City and street are evidence, not key. The phone key (digits, last ten), the domain key (the email's domain, lower-cased, none for a free provider) and the county (`MN-115`) are stored for later use and take no part in matching this pass. The **source key** is `<scraper>:<source_id>`, how a split names the links it moves.

## The attach rule

`Attach` takes a batch of observations, rows as their source read them, and applies each in order, in one transaction (decision 5):

1. A link already holding the row's source key keeps the row on its candidate, whatever its keys now say. Its digest unchanged (and not a rebuild), the row is **unchanged**: last seen moves, the run is recorded, a gone link returns. Otherwise it is **changed**: the link takes the new reading and digest as well.
2. Otherwise the row is **new**: when it has a match key and an active candidate one of whose links, gone or not, holds the same match key, the oldest such candidate takes it, by `match_key` with confidence 0.8. A `not_same` ruling is honored here: a row whose key matches both of a ruled pair goes to the older.
3. Otherwise a candidate is created for it, and the link that founds it attaches by `source_key` with confidence 1.0.

Each step reads by key, never the whole of the links (`D04-store`): the first step finds the row's link by its source key, the second the oldest active candidate holding the row's match key, through the links' index on name key, state and ZIP; and the display of each candidate one of whose links the batch wrote is re-derived from that candidate's own links once, at the end of the batch. Identical keys collapse at creation, since a later row of the same batch meets the candidate an earlier one created; so there are never more candidates than rows. A link moved by a ruling attaches by `decision` with confidence 1.0, and a link keeps how it came to its candidate until a ruling moves it. Matching reads only the links: it never calls scrapes.

`MarkGone` marks gone, in one bounded statement per `MarkGone` call, over that call's scraper's links last seen in a run other than that call's run, every link the run a pass just read no longer holds. A gone link is kept, with its last seen; it still counts for identity and no longer for the judgments (decision 6). `MarkGone` then re-derives by key, from their own links, the display of the candidates whose links it marked, bounded by those candidates, since a link that is gone no longer leads the display or gives a field of it. A row that returns is unmarked by `Attach`.

## Rulings

A ruling is made only by hand, through `decide`; nothing in the pipeline rules on its own. Each records its kind, the candidates involved, who, when and why, and is never changed or removed (decision 10).

- `merge` names the survivor and the other: the other's links move to the survivor, which is judged again; the other is marked `merged` into it and keeps everything else it had at the merge (display fields, tags, estimates and its last assessment).
- `split` names a candidate and the source keys to move out, a proper subset of its links: a new candidate is created for them, and the pair is recorded `not_same` in the same call, so matching never rejoins them.
- `not_same` names two active candidates and changes nothing else.
- `exclude` and `include` name one candidate; the latest of the two on it stands (`D13-scoring`).

A ruling on a merged candidate, a merge or `not_same` of a candidate with itself, a split naming keys the candidate does not hold or all of them, are refused `ErrInvalid`. Rulings are applied throughout and never overwritten: a pass or a rebuild moves no link a ruling moved, revives no merged candidate and changes no ruling, since the attach rule keeps every row on the candidate its link names. `Decide` judges the candidates it touches in the same call (`D13-scoring`), so a ruling shows on the shortlist at once; nothing else in this document judges.

## Recorded decisions

- **Punctuation is removed, not spaced**: every rune that is not a letter, a digit or white space is dropped, so `J.B. HUNT` keys as `JB HUNT` and `SMITH-JONES` as `SMITHJONES`; a variant spelled with spaces then misses, which under-merging accepts. Suffixes drop repeatedly from the end while more than one word is left, so `ACME CO INC` keys as `ACME` and a business named `COMPANY` keeps its name.
- **A match key needs all three parts**, a non-empty name key, a state and a ZIP of five ASCII digits; the document's "name plus place" is read as all of the place.
- **The free-provider list** is exact domains, lower-cased: `aol.com`, `arvig.net`, `att.net`, `bellsouth.net`, `centurylink.net`, `centurytel.net`, `charter.net`, `comcast.net`, `earthlink.net`, `embarqmail.com`, `frontier.com`, `frontiernet.net`, `gmail.com`, `gmx.com`, `googlemail.com`, `hotmail.com`, `hughes.net`, `icloud.com`, `live.com`, `mac.com`, `mail.com`, `mchsi.com`, `me.com`, `midco.net`, `msn.com`, `outlook.com`, `protonmail.com`, `q.com`, `qwest.net`, `rocketmail.com`, `sbcglobal.net`, `tds.net`, `usfamily.net`, `verizon.net`, `windstream.net`, `yahoo.com` and `ymail.com`: the document's providers with their sister domains and the residential ISPs of Minnesota and Wisconsin.
- **The phone key keeps fewer than ten digits** when that is all there is: the document says digits only, last ten, and names no floor.
- **A link keeps its reason** when a later pass re-attaches it by source key: a founding link is `source_key`, a key match stays `match_key` at 0.8 until a ruling moves it, and a moved link stays `decision`. Rewriting a key match as `source_key` at the next pass would erase the uncertainty the confidence records and the trace of a ruling.
- **`linked` counts every changed row and every new row that joined a candidate**, so `created + linked = new + changed` on every batch; the first pass has `created + linked = rows`, a rebuild `linked = rows`.
- **An unchanged row keeps its stored reading**: its digest says the row is the same, and a change of rules is a rebuild, which rereads every row (decision 11).
- **Every candidate a call writes a link of is touched**, the unchanged ones included, and `Attach` and `MarkGone` answer their ids. An ingest pass judges nothing (`D06-passes`): the daily judge, a rebuild or a ruling brings their judgments up to date.
- **A display link exists for every active candidate**: one is created with a link, a merge leaves the survivor all of both, and a split moves a proper subset; so the name and address are always one link's. When every link is gone, the freshest gone link shows.
- **A link that gives no value does not blank one** (root ruling, intent decision 20): a PPP row "adds no phone, email or people", yet a PPP link approved after a carrier's last filing leads the `Links` order, and as the display link it would blank the candidate's phone, email, people and class, so the class and cargo filters and the phone search would lose a candidate whose newest evidence is a loan. Phone, email, people and class therefore each come from the first giving link that gives a value; name and address stay the display link's, so the shown place is always one row's whole address and the drive minutes read its ZIP. Matching is unchanged. Each of those fields is one link's, never a merge of several, since the class is one carrier's registration. Cargo stays the union over every link, gone ones included, as decision 4 says "its links" and as the previous release had it: a PPP link has no cargo, so the union already keeps it, and this is the smallest change. The giving links are those not gone, as a gone row no longer counts (decision 6), except when every link is gone: then they are all of them, so such a candidate shows what its rows last said rather than nothing.
- **A merged candidate keeps everything it had at the merge but its links** (coordinator ruling): its display fields, tags, estimates and last assessment stay as they were, never judged again, so its assessment stays as the last judge wrote it; and the shortlist never answers it (`D13-scoring`); only its links move, so "no evidence" is no links. Chains of merges are left as they are, each record naming the id it merged into.
- **A split writes two rulings**: the `split` (naming the new candidate as its other, with the keys it moved) and then a `not_same` between the pair, with the same who, when and why; `Decide` answers the `split`. The sandbox check sees "a new candidate and a `not_same` ruling".
- **`Decide` refuses in this order**: a context done and a failing store (`D04-store`); a ruling with no user id (`ErrUnreachable`, a value no consumer sends, since the tool always has a caller); a malformed ruling (`ErrInvalid`: an unknown kind, a why that is blank, a merge or `not_same` with no other, a split with no keys); a candidate or other the store does not hold (`ErrNotFound`); a ruling the records forbid (`ErrInvalid`); then a random source that fails while minting a split's candidate. A field the kind does not take is ignored.
- **`include` needs no earlier `exclude`**: the latest of the two stands, so an `include` on a candidate never excluded changes nothing shown. The rules no longer exclude (`D13-scoring`): a government name pattern is a fact on the assessment, so only a ruling hides a candidate.
- **A merge of a pair ruled `not_same` is not refused**: the owner may change their mind, and the merge is the later ruling.

## Consumer tasks

The engine (`D06-passes`) attaches each batch with `n, touched, err := st.Attach(ctx, run, rebuild, batch)`, gathering the ids every batch answers, and marks the absent rows with `g, gone, err := st.MarkGone(ctx, "fmcsa", run)` once the stream has ended; an ingest pass judges nothing. A judge pass calls `c, err := st.JudgeAll(ctx)`, and a rebuild does the same after its ingests. The `decide` tool (`D10-tools`) calls `r, cs, err := st.Decide(ctx, store.Ruling{Kind: store.KindSplit, Candidate: a, Keys: []string{sources.SourceKey("fmcsa", id)}, Why: why, UserID: c.UserID, UserEmail: c.Email})` and answers `r` with `cs[1]`, the new candidate; `store.ErrNotFound` is `not_found` and `store.ErrInvalid` `invalid`. A page names a link's source key with `sources.SourceKey(l.Scraper, l.SourceID)`. A test builds `store.Observation{Scraper: "fmcsa", SourceID: "1023916", Digest: "d1", Reading: sources.Reading{NameKey: sources.NameKey("Acme Trucking, Inc."), State: "MN", Zip: "55072", Name: "ACME TRUCKING INC"}}`, attaches it and a second with the same keys and another source id, and checks that `st.Links(ctx, id)` answers both on one candidate, the second with `store.LinkMatchKey`. A test of the display attaches an FMCSA observation with `Phone: "3205550134"`, `Class: sources.ClassForHire` and `Cargo: []string{"genfreight"}` and a PPP observation sharing its match key with a later `Filed` and no phone, class or cargo, and checks that `st.GetCandidate(ctx, id)` answers the PPP reading's name and address with the FMCSA reading's phone, class and cargo.
