# D08-pages

What candidates draws as HTML: `internal/pages`, the six templates `landing`, `candidate`, `pass`, `tools`, `about` and `notfound` and the data each is executed with, and the handler that answers `/`, `/candidates/<id>`, `/passes/<id>`, `/tools`, `/about` and every other path the route table (`D03-serve`) hands it (decision 15). It is scrapes' pages with the shortlist and the passes on the landing page, a page per candidate and a page per pass below it.

## The pages

The landing page shows the shortlist under the default filters, the shortlist query's own defaults (`scoring.DefaultMaxMinutes` and `scoring.DefaultMinRevenue`), the first `pages.ShortlistShown` ranked, each linked to its candidate's page; then every kept pass, newest first in the store's pass order, each linked to its page. The two cutoffs are template data, so the sentence that names them follows the query; the origin, the number shown and every other constant of the rules version are copy in the template. No row of either list shows a phone or an email.

`/candidates/<id>` is one candidate: its display fields and tags, its assessment with the effective numbers computed at the request, each estimate with the facts it used, each link with its last seen and gone, linked to its row's page at scrapes, and the rulings that name it. A merged candidate's page shows its id, status, the candidate it was merged into (linked), its created and updated times and its rulings, and no display field, tag, assessment, estimate or link: the store keeps its display fields as they were at the merge, and the page data blanks them, so the page says only what it merged into (the template's comment). An active candidate not yet scored shows the template's not-scored state.

`/passes/<id>` is one pass's record in full; when it failed, the reason's sentence, which the template chooses from `Reason`; when a delivery started it, its trigger linked to the run's page at scrapes. A pass still `running` shows its record as it stands; the page does not stream.

An unknown candidate id, an unknown or pruned pass id, and a path whose id is not a well-formed candidate or pass id are answered alike, the not-found page with 404, byte for byte the not-found page of any other path.

The tools page lists the seven tools in the catalog's order (`D10-tools`), each with its one-line description. The about screen shows the service's name, the banner's `Release` and `Commit` and `pages.Description`. Any other path is the not-found page, 404, whatever the method.

The landing page is the root of the banner's trail; a candidate page is one level below it, named by the candidate's id at `/candidates/<id>`; a pass page one, named by the pass's id at `/passes/<id>`; and the tools page and the about screen one, `pages.ToolsLevel` and `pages.AboutLevel`. The banner's user is the caller's email, with auth's profile and sign-out addresses built on `urls.Auth` (`D01-layout-and-run-seam`).

## Who started a pass

A pass a `rebuild` call started shows its caller's email, or user id when the caller has no email; one a delivery started shows its trigger, the run id, linked to the run's page at scrapes, and the template names scrapes as its starter. The data carries `StartedBy` (a rebuild's caller's email, or its user id when the email is empty; empty for a delivery) and `RunPage` (empty for a rebuild); the template keys the starter on `Trigger`, and the words are the template's. An assessment's exclusions are handed as stored, whether or not it is excluded; the template lists them only when it is.

## Numbers as shown

The templates receive numbers already formatted, as their comments name them: dollars as `$` and the whole number of dollars with a comma between each group of three digits (a score or a base, which are not whole, rounded to the nearest dollar first); confidences, freshness and link confidences with two decimals; drive minutes on the candidate page as decimal text, empty when absent; filing dates as `YYYY-MM-DD` in both the `datetime` and the text; other times RFC 3339 to the second for a `time` element's `datetime`, and a `...Text` field in the page's layout, `pages.MinuteLayout` for the landing's passes, a link's first and last seen and a ruling's time, `pages.SecondLayout` for a candidate's created and updated, an assessment's scored and the pass page. Counts, ranks, the landing's minutes and cutoff and the rules version are integers. A time not yet set gives both strings empty.

## Pages show what is stored

Pages make no call to scrapes and change no record: a pass's page shows the status the store holds, and the effective confidence, freshness and score are computed from the stored assessment and the clock (`scoring`, `D13-scoring`). Candidates and passes belong to no one (decision 14), so every signed-in user sees the same pages.

## Guests and methods

The manifest says `guests = false` (`D02-cli`), so nginx sends a request with no credential to sign in before it reaches candidates, and `D03-serve` mounts this handler inside `identity.Require`. A request to a page path whose method is not `GET` or `HEAD` is 405 with `Allow: GET, HEAD`, decided before the store is read. The landing, candidate and pass pages answer 503 with a read refusal (`D03-serve`) when the store cannot be read; the about, tools and not-found pages are served without reading it.

## Recorded decisions

- Candidate pages at `/candidates/<id>` and pass pages at `/passes/<id>` (decision 15). A path whose id fails `store.ValidCandidateID` or `store.ValidPassID` is not looked up.
- `ServiceName` and `Description` are `D01-layout-and-run-seam`'s; the layouts and `ShortlistShown` are contract constants with values here, as in scrapes.
- One data type per thing a template draws, each field list the template comment's in its order. Every value a template receives is a string, a bool, an `int64`, a slice or a pointer to a struct; the template comments' `int` fields are `int64`, as the store holds counts.
- The shortlist's two cutoffs are template data (`MaxMinutes`, `MinRevenue`) taken from `scoring`'s defaults, so the landing's sentence cannot drift from the query; the origin's name, the number shown and the freshness window are copy in the template, constants of the rules version.
- The landing's shortlist numbers are the store's: `store.Shortlist` computes each entry's effective confidence and score at its own `Now` (`D04-store`); the candidate page computes them with `scoring` at `Config.Now`. In `Run` both are `Process.Now`.
- A merged candidate's page data blanks its display fields and tags, and carries no assessment, estimate or link, as the template's comment and the mock show; the store keeps them (decision 10, coordinator decision C3). Its rulings are shown, since they record the merge.
- Money is shown in whole dollars: a score is a product of a dollar figure and a confidence, so its cents are noise; it is rounded half away from zero (`math.Round`).
- The landing lists every kept pass (decision 15, the template's comment): retention keeps `CANDIDATES_KEEP_PASSES` done and as many failed (20 each by default), and the prune bounds the list, so the page needs no cap of its own.
- An unknown, pruned or malformed id is one not-found answer, byte for byte the not-found page of any other path; a database outage is a plain-text 503 read refusal, as in scrapes.

## Consumer tasks

`web.Handler` (`D03-serve`) builds `s, err := pages.Load()` and mounts `pages.Handler(pages.Config{Banner: cfg.Banner, Pages: s, ServicesPath: cfg.ServicesPath, Store: cfg.Store, Now: cfg.Now})` inside `identity.Require` for the page paths. `D01-layout-and-run-seam`'s about requirement executes `about` with `pages.AboutData{Banner: b, Description: pages.Description}` and `b.Trail` set to `[]page.Level{pages.AboutLevel}`. The handler builds the landing with `st.Shortlist(ctx, store.ShortlistFilter{MaxMinutes: scoring.DefaultMaxMinutes, MinRevenue: scoring.DefaultMinRevenue}, 0, pages.ShortlistShown)` and `st.ListPasses` paged until it answers fewer than it was asked for; a candidate page with `st.GetCandidate`, `st.GetAssessment`, `st.Estimates`, `st.Links` and `st.Rulings`, a link's address with `urls.RowPage(urls.Scrapes(cfg.ServicesPath), l.Run, l.SourceID)` and the effective numbers with `scoring.Freshness`, `scoring.Effective`, `scoring.Point` and `scoring.Score` at `cfg.Now()`; a pass page with `st.GetPass` and `urls.RunPage(urls.Scrapes(cfg.ServicesPath), p.Trigger)`. A test builds a store over its own database with a clock it sets, replaces the ZIP table with `candidates.ZipDrive()`, attaches observations it builds, re-scores them, records rulings with `Decide`, records passes and finishes or fails them, builds its own set with `pages.Load()`, serves `identity.Require(pages.Handler(cfg))` with a fixed banner and a services file whose `scrapes` entry names a URL it chose, sends raw requests with `X-User-Id` and `X-User-Email`, and compares each body with what executing the named template writes for a `LandingData`, a `CandidateData`, a `PassData`, a `ToolsData` built from `tools.Catalog()`, an `AboutData` or a `NotFoundData` it builds by the definitions below; it asks a pruned pass and a malformed id and gets the not-found page, and turns the store's failing switch on to see the 503.
