# D03-serve

The serve path: what happens between `cli.Run` being called with no arguments and the process being gone, the services file, the terms candidates serves on, the listener's life and the route table the handler keeps. It is scrapes' serve path with the pass engine in place of the run engine, the ZIP table loaded at the start, and no sibling read path of its own: candidates is read by people and agents only, through its pages and `/mcp`. `internal/server` is scrapes', unchanged.

`D01-layout-and-run-seam` declares the run seam, the settings, the database path, the addresses and the refusal of a setting; `D02-cli` the exit codes; `D04-store` the store, the ZIP table's write and the prune; `D06-passes` the engine and everything the start and the stop do to passes: the settling before ready (`Engine.Recover`), the prune before ready and on each sweep, the sweep itself, and the drain (`Engine.Drain`); `D07-events` what `/declarations` answers and what a delivery of `scrape.finished` does; `D08-pages` the pages; `D09-trail` the trail and its secrecy; `D10-tools` the tools; `D11-on-a-space` the nginx fragment and the trust.

## The services file

`IKIGENBA_SERVICES` names the services file. candidates uses four of its entries (decision 17): `scrapes`, whose socket the passes read through appkit's `scrapes` client; `events` and `telemetry`, appkit's sinks' (`D01-layout-and-run-seam`); and `auth`, read afresh per request by the pages through `urls.Auth` (`D08-pages`). The pages also read the entry `scrapes` afresh per request, through `urls.Scrapes`, for the links to scrapes' pages. `Run` reads the file once, when it starts to serve, and builds the `scrapes` client from the entry `scrapes` it finds then, or none (`passes.Config.Scrapes` nil) when there is no such entry; with no client, `rebuild` is refused `unavailable` and a delivery of `scrape.finished` is answered as `D06-passes` states. A changed `scrapes` entry therefore reaches the passes at the next start. `Run` hands the path to the handler as `web.Config.ServicesPath`. With `IKIGENBA_SERVICES` unset, naming no file, or naming one `services.Read` refuses, the start is not refused.

## The terms candidates serves on

candidates serves only on a listening socket it inherits, taken as `sd_listen_fds(3)` documents, and reports readiness with `READY=1` to `NOTIFY_SOCKET` as `sd_notify(3)` documents. It trusts `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx sets them, and trusts the MCP gateway to have forwarded them (decision 21, `D11-on-a-space`). Every request has an id: the one nginx or the caller set, or 32 lowercase hexadecimal digits appkit's telemetry middleware draws from `Process.Rand`.

The events app reaches candidates at its socket on `/events` and `/declarations`. candidates emits the two pass events and accepts exactly `scrape.finished` (`D07-events`), so it mounts appkit's `events.DeliveryHandler` over the engine's handlers and `events.DeclarationsHandler` over its emitter, built with `trail.Emits()`, and the same handlers. These two paths sit outside the identity gate, as scrapes' do; the fragment answers both 404 at the public name (`D11-on-a-space`).

## The route table

Every request goes through appkit's `telemetry.Middleware`. Then, by the path alone, compared by hand so that nothing is cleaned and nothing redirected, the bus's two paths, `/mcp` and `/_appkit/` on `URL.Path`: exactly `/events` and exactly `/declarations` go to the event bus's two handlers; every other request goes through `identity.Require`. Past the gate: exactly `/mcp` goes, through `events.Middleware`, to the MCP server, on which the seven tools of `D10-tools` are registered once when the handler is built; a path beginning `/_appkit/` goes to `page.Static()`; and every other path to the page handler (`D08-pages`), which answers `/`, `/candidates/<id>`, `/passes/<id>`, `/about`, `/tools` and, for everything else, the not-found page.

The handler is built from a `web.Config` carrying what the routes need: the banner source, the MCP server, the services file's path, the store, the engine, the writer, the emitter and the clock the pages and the tools compute effective numbers at (`D01-layout-and-run-seam`).

A **read refusal** is the plain-text answer a page gives when the database cannot be read: a status, `text/plain; charset=utf-8`, the line `store.Unreachable` and a newline, no body on `HEAD`, as scrapes answers.

## The start

With `Args` empty, `Run` checks the settings (`D01-layout-and-run-seam`), then whether exactly one socket was passed in, with the diagnostics below. It removes the three `LISTEN_*` variables, takes descriptor 3, and opens the database with `db.Open` at `state/candidates.db`; a failure is `candidates: cannot open database state/candidates.db: ` and the reason, exit 1. It builds the store, the writer, the emitter, the scrapes client, the registry and the engine, and records `service.started`, so that it is the first event of every run. Then it loads the ZIP table: the root package's `ZipDrive()` replaces the store's `zip_drive` table whole (`store.ReplaceZipDrive`, decision 9), so the table a running candidates scores with is always its release's, whatever an earlier release left. Then the engine settles what a dead process left, failing every pass still `running` with `interrupted` (`Engine.Recover`), and the store prunes once, as `D06-passes` states. A ZIP load or a settling that fails, the database having failed under it, refuses the start with `candidates: ` and `store.Unreachable`, exit 1; a prune that fails does not, and the start goes on to ready (`D06-passes`). Then `Run` builds the handler, sends `READY=1`, and serves; the sweep waits on `Process.After(cli.SweepInterval)` between prunes (`D06-passes`).

## Stopping

When `ctx` is done (in the binary, on `SIGTERM` or `SIGINT`, the signal's name being the cause) `Run` stops the sweep, drains the engine as `D06-passes` states (a running pass is cancelled and failed `interrupted`), and at the same time drains the server for `DRAIN_SECONDS`, waits within the same window for the emitter to deliver what it holds, shuts the writer down with the cause's text as `service.stopping`'s reason, shuts the emitter down, and closes the database. From the drain deadline on, `Run` hands neither sink anything: an event recorded after it reaches standard error as appkit's `lost event` and `undelivered event` lines. A pass interrupted never makes the exit non-zero; a drain that runs out on requests is `candidates: stopped with <n> request(s) unfinished`, exit 1.

## Recorded decisions

- **No sibling read path.** Nothing reads candidates but people and agents (decision 1 names no consumer), so the route table has the pages, `/mcp`, `/_appkit/` and the bus's two paths, and no JSON path of its own; scrapes' read path has no counterpart.
- **The scrapes client is built once, at the start**, from the entry the services file names then: appkit's `scrapes.NewClient` takes the entry as a value (`ClientConfig.Service`), and `D01-layout-and-run-seam` reads `IKIGENBA_SERVICES` once. A services file edited while candidates runs reaches the passes at the next start; the pages, which only build addresses, read it afresh per request as scrapes' pages read `auth`.
- **The ZIP table is loaded after `service.started` and before the settling**, in the settling's failure class (a failed prune is not one: it is retried at the next sweep, `D06-passes`): the database opened but a write failed, so the start is refused with `store.Unreachable` and the trail holds `service.started` alone, as scrapes refuses a settling that fails. Loading it before the settling means a pass the start's own settling or the first delivery begins already scores with the release's table.
- **The start's answer to a failing database is described, not required.** Once the database has opened, a store failure is provoked only with `SetFailing(true)` on a handle the test hands in (candidates/AGENTS.md), and `cli.Run` builds its store over a handle of its own, so no permitted test can fail the ZIP load or the settling under `Run`. The guarantees are stated where the store is handed in: a failing store's `ReplaceZipDrive` answers `ErrUnreachable` and changes nothing (`D04-store`, R-OD8H-2EDG), and so does `Engine.Recover` (`D06-passes`, R-ZELD-BYPF); the refusal of the start that follows is this overview's, as scrapes leaves what its stream does after a failure undeclared.
- **A missing identity is `identity.Require`'s 500** on every route behind the gate, as in scrapes; the public name's 302 to sign-in is nginx's (`D11-on-a-space`).
- The bus's two routes are scrapes': outside the gate, inside the telemetry middleware, over the engine's handlers (`passes.Engine.Handlers`), with the emitter given to `events.DeclarationsHandler` because candidates emits as well as accepts.
- `web.Config` carries `Now`, unlike scrapes', because the pages and the tools compute a candidate's effective confidence and score at the moment of the request (decision 8: freshness is judged at query time); it carries no random source, which the store, the writer and the emitter hold.
- The settings, the database path and the sweep interval are `D01-layout-and-run-seam`'s; the settling, the prunes, the sweep and the drain's effect on passes are `D06-passes`'; this document states only the order of the start's steps, the ZIP load, the refusals of the start, and the stop's effect on the process.

## Consumer tasks

`Run`, serving, calls `s, err := settings.Read(p.LookupEnv)`, checks the socket, unsets the three `LISTEN_*` variables and takes `ln, _ := p.Inherit(3)`; opens the database (`D01-layout-and-run-seam`); builds `st := store.New(d, store.Config{Now: p.Now, Rand: rnd})`, the writer `w`, the emitter `em` with `trail.Emits()`, `sc` from `services.Read(path)` and `scrapes.NewClient` (nil without an entry `scrapes`), `reg := sources.New(fmcsa.New())` and `eng := passes.New(passes.Config{Store: st, Sources: reg, Scrapes: sc, Telemetry: w, Events: em})`; calls `w.Ready()`; calls `st.ReplaceZipDrive(bg, candidates.ZipDrive())`, `eng.Recover(bg)` and `st.PrunePasses(bg, s.KeepPasses)`; builds `h := web.Handler(web.Config{Banner: p.Banner, MCP: p.MCP(w), ServicesPath: path, Store: st, Passes: eng, Telemetry: w, Events: em, Now: p.Now})`; sends `READY=1`; and calls `server.Serve(ctx, ln, h, s.Drain(), eng.Drain)`. A test of the handler builds `web.Handler` over a store on its own database, an engine over a `scrapes` client built on a fake's socket, a writer and an emitter over captures and a server from `mcp.NewServer`, serves it with `httptest`, and sends raw requests with the identity headers set or left out; it fails the store with `SetFailing(true)` on its handle. A test of the start drives `cli.Run` with a listener, a `NOTIFY_SOCKET` it binds, a `Now`, an `After` and a `Rand` it controls, a services file whose `scrapes` entry names a fake's socket, and captures; seeds the database first through its own store (a pass left `running`, `done` passes past keeping, a ZIP table of its own); waits for `READY=1`; drives `/mcp` with `mcp.Client` and `POST /events` with raw HTTP; cancels; and reopens the database.
