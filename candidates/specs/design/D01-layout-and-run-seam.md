# D01-layout-and-run-seam

candidates is stages two and three of the funnel, resolve and qualify: one Go binary that turns the rows scrapes collects into candidate businesses, one per real business with every row that describes it attached as evidence, and judges each twice, how sure it is that the business is operating today and how big it is, so the owner can read them through **cohorts**, saved searches whose members are worked out each time one is read (`D14-cohorts`). A **source** is Go code in the service that knows how a row of one scraper becomes match keys, tags, a size estimate, a filing date, operating evidence, a known-since date, a category and a government name match; the registry is fixed and holds two sources, `fmcsa` and `ppp` (`D05-sources`). A **pass** is one ingest, judge, rebuild or enrich, recorded at once and worked in the background (`D06-passes`): an **ingest** is started by a `scrape.finished` delivered on the bus and reads that run's record and rows from scrapes over its socket through appkit's `scrapes` client; a **judge** is started by the daily `cron.judge_candidates.fired` delivered on the bus and reads nothing from scrapes; a **rebuild**, started by the `rebuild` tool, ingests every source's current run and then judges; an **enrich**, started by an ingest that ends `done` or by the `enrich` tool, runs the **website check** on the candidates that are due, fetching the home page of the domain of each one's display email and recording what it found as an **enrichment** on the candidate (`D15-website-check`), and starts a judge when it recorded any and no other pass runs (`D06-passes`). A **candidate** gathers **links**, one per row attached to it (`D12-resolution`); each source gives a candidate an **estimate**, and each candidate has one **assessment**, its two judgments, operating confidence and revenue, with the facts beside them, its website among them, written only by a judge (`D13-scoring`); the owner's **rulings** override matching (`D12-resolution`); and the owner's **rejects** take a candidate out of one cohort (`D14-cohorts`). All of it lives in the app's own SQLite database, `state/candidates.db` (`D04-store`). Each pass's start and end is an event on the bus and in the trail (`D07-events`, `D09-trail`). Sixteen MCP tools are offered at `/mcp` (`D10-tools`); a landing page, a page per cohort, per candidate and per pass, a tools page, an about screen and the not-found page are served to a signed-in user (`D08-pages`).

This design is the structural ground the others stand on: where the code lives and what each package is for, every name that crosses a package boundary with its shape, the seam through which the process is run so that every part can be tested without a real process, the settings, the path, the addresses, where the identity and the display string come from, and the binary's wiring. The command line is `D02-cli`'s; the store's whole surface is `D04-store`'s; the serve path, the services file and the route table are `D03-serve`'s. It follows scrapes' layout and run seam, with the sources in place of the scrapers, the pass engine in place of the run engine, and appkit's `scrapes` client in place of scrapes' HTTP client for its siblings; the HTTP client candidates does take, `Process.HTTP`, is the website check's alone.

The module is `github.com/ikigenba/ikigenba/candidates`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/candidates`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/candidates` is wiring only.

## The dependencies

candidates depends on two modules besides the standard library: `github.com/ikigenba/ikigenba/appkit`, required at a published release with no `replace` directive, and `golang.org/x/net`, whose `html` package the website check parses a page's title with (`D15-website-check`, decisions log P5). Its `db` package brings the pure-Go SQLite driver, which keeps the release build cgo-free. candidates uses appkit's `db`, `version`, `services`, `page`, `identity`, `mcp`, `telemetry`, `events` and `scrapes`, and restates none of their contracts. It uses neither `artifacts` nor `connections`. It calls one sibling, scrapes, only through appkit's `scrapes` client built from the services file's `scrapes` entry; the event bus and the telemetry socket are reached through appkit's sinks. Outside the suite it calls nothing but the websites the website check fetches, over outbound HTTP through `Process.HTTP`; with `IKIGENBA_SANDBOX` present it fetches only from an in-process stub on loopback (`D15-website-check`). Which release of appkit or `golang.org/x/net` is data that `AGENTS.md` and `go.mod` hold.

## Where the environment is read

`main` makes the one read of the environment that is not `Run`'s own: it calls appkit's `version.Read` exactly once, first, and holds the result, the **identity**, whose `String()` is the **display string**. It hands the identity to `page.New`, whose banner carries its `Release` and `Commit` to every page's footer and to the about screen, and the display string to the `mcp.ServerConfig` its `Process.MCP` builds and to `Run` as `Process.Version`. Nothing below `main` calls `version.Read`. `Run` reads every variable through `Process.LookupEnv`: `DRAIN_SECONDS` and `CANDIDATES_KEEP_PASSES` once at start, through `settings.Read`; `LISTEN_PID`, `LISTEN_FDS` and `NOTIFY_SOCKET` for the socket and readiness; `IKIGENBA_SERVICES` once, when it starts to serve; and `IKIGENBA_SANDBOX`, whose presence chooses the website check's fetcher (`D15-website-check`). appkit's constructors also read `IKIGENBA_SERVICES` from the process environment; that read is appkit's.

## Packages

The root package, named `candidates`, holds what the module embeds: `Assets` (the seven templates `about.html`, `candidate.html`, `cohort.html`, `landing.html`, `notfound.html`, `pass.html` and `tools.html`), `Etc` (`manifest.toml` and `nginx.conf`), `Migrations` (the seven files that create seven of the eleven tables `D04-store` describes, one each, in decision 16's order, `0008_windows.sql`, which only expands: it adds the stored scores, creates the eighth table, `candidate_cargo`, and adds the list windows' indexes, `0009_judgments.sql`, which gives the assessments their two judgments and the facts beside them and the passes their kind and origin and is frozen, and `0010_cohorts.sql`, which creates the ninth and tenth tables, `cohorts` and `rejects`, gives the assessments their fleet verdict and counts, and drops the stored scores and the columns only the shortlist read, and `0011_enrichments.sql`, which creates the eleventh table, `enrichments`, gives the assessments their website and the passes the enrich counts, and drops the assessments' columns `fleet`, `low` and `high`, `D04-store`'s) and `ZipDrive`, the ZIP drive-time table read from the embedded `share/zip_drive.csv`, as a map from a five-digit ZIP to whole minutes from the origin. The start loads `ZipDrive()` into the store whole (`D03-serve`); a test that needs drive minutes reads them from `ZipDrive()`.

The internal packages hold the concerns, one each. Each package's shapes that another package uses are declared here (the store's in `D04-store`); the behavior of each name is the document named:

- `internal/cli`: the run seam (this document), the command, the manifest and the usage text (`D02-cli`), the serve path (`D03-serve`), `cli.SweepInterval` (this document; the sweep itself is `D06-passes`'), and `cli.NginxConf` (`D11-on-a-space`).
- `internal/settings`: the two settings (this document).
- `internal/server`: a listener's life (`D03-serve`).
- `internal/web`: the route table, `web.Config` and `web.Handler` (`D03-serve`).
- `internal/store`: every record and every read and write of them: candidates, links, estimates, assessments, rulings, cohorts, rejects, enrichments, passes and the ZIP table (`D04-store` declares the whole surface and owns the pass records, the reads, the cohort and reject writes, the ZIP table and the prune; `D12-resolution` owns `Attach`, `MarkGone` and `Decide`; `D13-scoring` owns `Judge` and `JudgeAll`; `D14-cohorts` defines what a cohort is, the terms its reads answer by).
- `internal/sources`: what every source shares: a source's reading of a row (`sources.Reading`, `sources.Estimate`, `sources.Evidence`, `sources.Person`) and a category with the source that gave it (`sources.Category`), the `Source` interface and the fixed registry, the class tags, the fleet verdicts, the category names, the evidence kinds and the government name match (`D05-sources`); the website check's kind and the website states (this document, used by `D15-website-check` and `D13-scoring`); the normalized keys and the source key (`D12-resolution`); the rules version (`D13-scoring`).
- `internal/fmcsa`: the FMCSA source (`D05-sources`).
- `internal/ppp`: the PPP loan source (`D05-sources`).
- `internal/scoring`: the judgment rules as functions of values: the combined estimate, the freshness weight, a piece of evidence's weight at a moment, the operating confidence and the integer it is ordered by (`D13-scoring`).
- `internal/passes`: the engine, `passes.Engine` built by `passes.New(passes.Config)`: starting a pass by `rebuild`, by `enrich`, by a delivery of either event it accepts and by another pass, the work in the background, the identity of its reads, the start's settling (`Engine.Recover`), the drain (`Engine.Drain`), the pass record's JSON and every refusal word (`D06-passes`).
- `internal/website`: the website check: a domain's attempts and their result, the pace and the concurrency of a pass's checks, the real fetcher and the in-process loopback stub the sandbox fetches from (`D15-website-check`, which declares the whole package).
- `internal/trail`: the pass events, the two events accepted, and their declarations (`D07-events`); the trail as a whole and its secrecy (`D09-trail`).
- `internal/urls`: the auth address and the addresses of scrapes' pages (this document).
- `internal/tools`: the sixteen tools, their catalog and their refusal sentences (`D10-tools`).
- `internal/pages`: the templates' data and the page routes (`D08-pages`); `pages.ServiceName` and `pages.Description` (this document).

`internal/scoring` is warranted: the judgment rules are pure functions of estimates, evidence, a filing date and the clock that the store's judge applies, and a test proves them by calling them; in `internal/sources` they would join a second concern to the sources', and in `internal/store` they could not be proved without a database. `internal/ppp` is a package the scaffold's test-file list does not yet name; it sits beside `internal/fmcsa` because each source keeps its own facts, formulas and parsing, as scrapes keeps one package per scraper, and the delivery adds it to that list. `internal/website` is warranted: the website check is outbound HTTP, a pace and a stub server, a concern no other package has, and it is proved by calling it over an injected client; in `internal/passes` it would join a network client to the engine, and the store must stay free of HTTP. No matching package is added: the attach rule reads and writes links in one transaction per batch, so it is a store write (`store.Attach`, `D12-resolution`), and the normalization it compares is the sources' (`sources.NameKey` and its siblings), since a source produces a row's keys.

The registry lives in `internal/sources` with no default list: `fmcsa` and `ppp` import `sources` for the reading's types, so a registry that named either source there would make them import each other. `Run` builds the fixed registry, `sources.New(fmcsa.New(), ppp.New())`, whose order, `fmcsa` then `ppp`, is the order a rebuild ingests in (`D05-sources`). Which package imports which is guidance, not contract.

Template data types, tool argument and result types, copy constants and the constants a package uses only itself are declared by the document that owns the package's behavior, not here.

## The run seam

The run seam is `cli.Run`, which takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package, and returns the exit code. It is scrapes' seam with `HTTP` kept for one use: scrapes is reached over the socket the services file names, so a `Run`-level test serves a fake scrapes on a Unix socket its services file's `scrapes` entry names, and the only address candidates reaches of its own choosing is a candidate's website, fetched through `HTTP`. A nil `HTTP` is no website check at all, so a `Run`-level test that sets neither `HTTP` nor `IKIGENBA_SANDBOX` fetches nothing, and one that sets `IKIGENBA_SANDBOX` in its lookup checks against the stub on loopback (`D15-website-check`). `Now` is the clock every time candidates stamps or compares is read from: a pass's started and finished, a link's first and last seen, a candidate's created and updated, a ruling's time, an assessment's calculated time, the moment a judge measures a filing's freshness at, the prune's ordering, every event's time. `Sleep` is the pause the writer and the emitter wait with between delivery attempts. `After` is the sweeper's timer (`D06-passes`) and the website check's, for each attempt's timeout and the pace between checks (`D15-website-check`). `Rand` is the source of every value candidates mints: request ids, pass ids, candidate ids and bus event ids. `Inherit`, `Now` and `Rand` are the caller's to give whenever `Args` is empty: `Run` has no default for any of them, and the choice of the process's own descriptor 3, `time.Now` and `crypto/rand.Reader` is made once, at the process boundary, by `cmd/candidates`. The event bus, telemetry and scrapes sockets reach `Run` through the services file `IKIGENBA_SERVICES` names (`D03-serve`). There are no live tests. The one test that execs the binary never starts a pass.

## Settings

candidates reads two values at start, in this order: `DRAIN_SECONDS`, the space's, and `CANDIDATES_KEEP_PASSES`, the one its manifest's `[env]` declares (decision 17). An unset or empty one is its default: 5 seconds and 20 passes. Both are spelled as opsctl writes an integer: one or more ASCII digits, no sign, no leading zero, so `0` is refused. Digits beyond what an `int64` holds read as the largest `int64`. `settings.Read` refuses the first value in that order that is not acceptable with a `*settings.Error` naming it, quoting its value and saying what was wanted, and `Run` writes its text after `candidates: ` as a usage error before it looks for its socket. The origin, the rules' numbers and evidence weights, the free-provider list, the government patterns, the NAICS prefixes, the page sizes, the batch size, the hourly sweep and the website check's tuning numbers and refresh ages are constants of the documents that use them.

## Paths

Relative to `Process.Dir` (the process's working directory when empty) the database is `state/candidates.db`, opened with `db.Open`, the root package's `Migrations()` and `Process.Now`; `state/` is created when absent. candidates writes nothing outside `Dir` and nothing under it but the database: a run's rows are streamed and handled a batch at a time (decision 1), and the store reaches each record a batch needs by key, so a pass costs in proportion to its rows (`D04-store`, `D06-passes`).

## The addresses

`internal/urls` holds the addresses candidates builds that are not its own paths. The **auth address** is the `URL` of the services file's entry `auth`, trailing `/` removed, or, with no such entry, built from the request's scheme and host with a leading `candidates.` removed (`urls.Auth`), which the pages' banner links to (`D08-pages`). The **scrapes address** is the `URL` of the services file's entry `scrapes`, every trailing `/` removed (`urls.Base`, `urls.Scrapes`), and empty when the file has no such entry: a relative address would name a page of candidates' own. On it are built a row's page at scrapes, `<scrapes address>/runs/<run>/rows/<source id>` (`urls.RowPage`, decision 15), which a candidate's links point to, and a run's page, `<scrapes address>/runs/<run>` (`urls.RunPage`), which an ingest pass, started by a `scrape.finished` delivery, points to; each is empty when the address, the run or the source id is empty. The source id is path-escaped, so an id holding `/` stays one segment. The page paths `/cohorts/<id>`, `/candidates/<id>` and `/passes/<id>` are spelled by the templates, which build them from the data they receive.

## Recorded decisions

- The layout is scrapes' with `internal/sources` in place of `internal/source` and one package per source, `internal/fmcsa` and `internal/ppp`, as scrapes has one per scraper, `internal/passes` in place of `internal/runs`, and `internal/scoring` added; scrapes' `internal/scrapers` registry package has no counterpart because the registry is `sources.Registry` and `Run` lists its two sources. The PPP source is a package beside the FMCSA one, the smallest change to this layout; no other package is added.
- The domain records (`store.Candidate`, `store.Link`, `store.Assessment`, `store.Ruling`, `store.Cohort`, `store.Reject`, `store.Pass`) are the store's, as scrapes' `store.Run` is; a source's per-row reading and per-source estimate are the sources' (`sources.Reading`, `sources.Estimate`), since a source makes them and the store keeps them as given. A link keeps its row's whole reading, evidence, dates and category included, so a judge needs no read of scrapes.
- Matching, merging and splitting are store writes (`store.Attach`, `store.MarkGone`, `store.Decide`), each one transaction, so a ruling and the links it moves, or a batch and the candidates it creates, cannot be seen half done. `decide`, `exclude` and `include` reach the store directly, as the cohort and reject tools do; the engine is not in their path, since neither a ruling nor a cohort reads scrapes or waits for a pass.
- The root package exports the ZIP table as a typed map, `ZipDrive() map[string]int64`, rather than the CSV file: every consumer wants minutes by ZIP, and a test reads the embedded table through it without opening the checkout.
- No `Process` field names scrapes' address: the services file names its socket, as it names the bus's and telemetry's.
- `Process.Inherit`, `Process.Now` and `Process.Rand` are required whenever `Args` is empty, as in scrapes; no requirement states the precondition, because no permitted test can observe a default.
- A `scrape.finished` delivery reads the run's record from scrapes before it records a pass (orchestrator ruling; the behavior is `D06-passes`'): a run not found or not `done` is `Skip` with no pass recorded; any other failed read records the pass and fails it `scrapes`, answering `OK`; `Fail` is kept for a pass already running, the drain and the database failing. `Deliver` holds the delivery's context and calls `store.AddPass` and `store.FailPass` after that read, so no signature changes. A `cron.judge_candidates.fired` delivery reads nothing from scrapes; `Deliver` tells the two by the event's name, so the engine gains no entry point.
- A pass started by a delivery reads scrapes as the service identity (decision 12, binding); that identity is the engine's (`D06-passes`), and no `Process` field carries it.
- candidates accepts the judge's trigger by its exact name, `trail.AcceptedJudge`, `cron.judge_candidates.fired` (cron emits `cron.<slug>.fired`), with no pattern, as scrapes accepts its triggers; the slug `judge_candidates` is the one the owner creates on a space.
- `sources.Rules`, the rules version, is declared without its value: no requirement states a version, a test reads the value the source declares, and `D13-scoring`'s prose says which it is.
- The category names and evidence kinds are stored and answered as given, so they are contract constants with their values (`sources.Category*`, `sources.Evidence*`); an evidence item's description is copy, a constant `D05-sources` declares without its value.
- A reading carries one category word and its evidence items each name their source; `sources.Category` pairs a category with the source that gave it, for the assessment (`D04-store`). `Evidence.Source` is any source's name, not only a scraper's, and `scoring.Operating` takes any evidence list, so evidence from an enrichment joins a candidate's without a new shape: the website check's evidence, `sources.EvidenceWebsiteLive`, names `sources.WebsiteCheck` as its source (`D13-scoring`).
- Cohorts add no package: a cohort's constants, validators, types and reads are the store's (`D04-store`) and what a cohort is `D14-cohorts`', because the tools and the store both need the validators and both already import `store`.
- The fleet verdict is a reading's before it is an assessment's (cohorts decisions log 11): the judge reads the stored link reading, not the row, so `sources.Reading` carries `FleetVerdict`, with the row's `PowerUnits` and `Drivers`, right after `Fleet`, which is still written so the release before reads new readings. The verdict words are stored and answered as given, so they are contract constants with their values (`sources.FleetPass`, `sources.FleetFail`, `sources.FleetUnknown`), beside the class tags; a link an earlier release stored reads with an empty verdict, which its readers take as unknown (`D05-sources`, `D13-scoring`).
- `passes.Record` gains the pass's `Kind` and `Origin`, and its count of candidates judged is `Judged`, where `Rescored` was; its JSON is `D06-passes`'.
- The website check's vocabulary is `internal/sources`', beside the class tags and fleet verdicts: the kind `sources.WebsiteCheck`, which is also the source its evidence names, and the states `sources.WebsiteHTTPS`, `WebsiteHTTP`, `WebsiteNone` and `WebsiteUnknown`, stored and answered as given, so contract constants with their values. `internal/store` and `internal/scoring` both need them and already import `sources`; the pass vocabulary (`store.KindEnrich` and the origins) stays the store's, beside the other kinds (`D04-store`). `sources.Rules` is still declared without its value; the website check raises it, and `D13-scoring`'s prose says to what.
- `passes.Config` gains `Website`, the checker the engine's enrich work fetches with, nil meaning no check: `Enrich` is then refused and an ingest starts no enrich (`D06-passes`). `passes.Record` gains the enrich counts `Due`, `Fetched`, `HTTPS`, `HTTP` and `None` after `Unranged`, whose meaning is `D15-website-check`'s and whose JSON is `D06-passes`'.
- **The fetcher is a `Process` field, as scrapes' is** (decisions log P2, revised): `Process.HTTP`, the last field, is the client the website check fetches with, and `cmd/candidates` passes the real fetcher, `website.Client()`. A nil `HTTP` is no checker rather than `http.DefaultClient`, so every `Run`-level test that leaves it zero stays offline without saying so. When `IKIGENBA_SANDBOX` is present, whatever its value, `Run` checks against the in-process loopback stub instead, whatever `HTTP` is; the sandbox and its manifest change nothing, and the variable joins the keys `Run` looks up. The selection is `D15-website-check`'s. No requirement states that the binary passes `website.Client()` as `HTTP`, as none states its `Inherit`, `Now` or `Rand`: the one exec'ing test never starts a pass and is offline, and with `IKIGENBA_SANDBOX` set the stub is used whatever `HTTP` is, so no permitted test can observe the binary's fetcher; the consumer tasks show the wiring.
- **The website check reuses `Process.After`** for each attempt's timeout and the pace between checks, told from the sweeper's waits by the duration it is called with, rather than a second timer field (`D15-website-check`, `D06-passes`).
- **Departure: a second dependency and outbound network.** This document said candidates depends on appkit alone and calls no service outside the suite; the website check fetches candidates' own websites over outbound HTTP, and parses a page's title with `golang.org/x/net/html`, a dependency the owner decided (decisions log P5) so the build may add `golang.org/x/net` to `go.mod`. The real fetcher refuses non-http(s) schemes and addresses that resolve to loopback, private or link-local ranges (decisions log P6), and in the sandbox nothing is fetched but the loopback stub (`D15-website-check`). candidates' `AGENTS.md` still says otherwise.

## Consumer tasks

`main` calls `id := version.Read()` and `v := id.String()` and hands `cli.Run` a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Version` is `v`, whose `Banner` is `page.New(pages.ServiceName, id).Banner`, whose `Inherit` takes the process's own descriptor 3, whose `Now` is `time.Now`, whose `Rand` is `crypto/rand.Reader`, whose `After` is `time.After`, whose `MCP` returns `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Version: v, Telemetry: w})` and whose `HTTP` is `website.Client()`, leaving the rest zero; it cancels the context on `SIGTERM` or `SIGINT` with a cause whose `Error` is the signal's name, and exits with what `Run` returns.

`internal/cli`, serving, reads `s, err := settings.Read(p.LookupEnv)`; opens `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "candidates.db"), Migrations: candidates.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: p.Stderr})`; builds `st := store.New(d, store.Config{Now: p.Now, Rand: rnd})` and calls `st.ReplaceZipDrive(ctx, candidates.ZipDrive())`; reads `list, _ := services.Read(path)` and, when `e, ok := list.Find("scrapes")` finds the entry, `sc := scrapes.NewClient(scrapes.ClientConfig{Service: e, Telemetry: w})`, nil otherwise; builds `reg := sources.New(fmcsa.New(), ppp.New())` and `em := events.New(events.Config{..., Emits: trail.Emits()})`; builds the checker, when `_, ok := p.LookupEnv("IKIGENBA_SANDBOX")` reports present, as `ck := &website.Checker{Client: stub.Client(), After: p.After}` over `stub, err := website.NewStub()`, closed at stop, otherwise, when `p.HTTP` is non-nil, as `ck := &website.Checker{Client: p.HTTP, After: p.After}`, and otherwise leaves `ck` nil; builds `eng := passes.New(passes.Config{Store: st, Sources: reg, Scrapes: sc, Telemetry: w, Events: em, Website: ck})`; calls `eng.Recover(ctx)` and `st.PrunePasses(ctx, s.KeepPasses)` before ready and again on each `p.After(cli.SweepInterval)`; serves `web.Handler(web.Config{Banner: p.Banner, MCP: p.MCP(w), ServicesPath: path, Store: st, Passes: eng, Telemetry: w, Events: em})` with `server.Serve(ctx, ln, h, s.Drain(), eng.Drain)`. `web.Handler` builds `set, _ := pages.Load()`, `tools.Register(cfg.MCP, tools.Config{Passes: cfg.Passes, Store: cfg.Store})` and `pages.Handler(pages.Config{Banner: cfg.Banner, Pages: set, ServicesPath: cfg.ServicesPath, Store: cfg.Store})`, and mounts `events.DeliveryHandler(cfg.Passes.Handlers())` and `events.DeclarationsHandler(cfg.Events, cfg.Passes.Handlers())`.

The engine, for each row `r` a pass streams with `sc.Rows(ctx, run, fn)`, takes `src, ok := reg.Get(r.Scraper)` and gathers `store.Observation{Scraper: r.Scraper, SourceID: r.SourceID, Digest: r.Digest, Reading: src.Read(r)}` into a batch for `st.Attach`, and judges nothing; a judge pass calls `counts, err := st.JudgeAll(ctx)` and a rebuild does so once every source's run is ingested. The store's judge weighs each piece of a link's evidence at the judge's moment `t` with `scoring.Weight(e, l.Reading.Filed, t)`, folds a candidate's evidence with `op := scoring.Operating(evidence)` and orders by `scoring.OperatingKey(op)`, and combines its estimates with `scoring.Combine(estimates)`; it takes the assessment's verdict from `l.Reading.FleetVerdict` of the freshest FMCSA link, an empty one read as `sources.FleetUnknown`, and the counts from `l.Reading.PowerUnits` and `l.Reading.Drivers` (`D13-scoring`). The tools answer `rebuild` with `passes.RecordOf(p)` from `p, err := eng.Rebuild(ctx, c)` and `enrich` with it from `p, err := eng.Enrich(ctx, c, olderThanDays)`, tell a refusal with `var rf *passes.Refusal; errors.As(err, &rf)`, and, for `read, err := st.ReadCohort(ctx, id)`, show each member `m` of `read.Members` with its numbers from the stored `m.Assessment.Operating`, `m.Assessment.RevenueLow`, `m.Assessment.RevenueHigh` and `m.Assessment.RevenueConfidence` and its verdict from `m.Assessment.FleetVerdict` (`D13-scoring`, `D14-cohorts`). The pages build a link's address with `urls.RowPage(urls.Scrapes(cfg.ServicesPath), l.Run, l.SourceID)`, a pass's with `urls.RunPage(urls.Scrapes(cfg.ServicesPath), p.Trigger)` when `p.Origin` is `store.OriginRun`, the banner's user with `urls.Auth(r, cfg.ServicesPath)`, and the tools page from `tools.Catalog()`.
