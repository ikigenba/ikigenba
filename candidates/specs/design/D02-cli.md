# D02-cli

candidates as a command: what `cli.Run` does with its arguments, the exit codes, and the two constants whose text is fixed here, the usage text and the manifest, with the file under `etc/` that copies the manifest. It is scrapes' command with candidates' name and its own manifest: one setting, the `application` group and no secrets (decisions 1 and 17). The nginx fragment and `etc/nginx.conf` are `D11-on-a-space`'s; `db status` is `D04-store`'s.

An empty `Args` means serve (`D03-serve`). `--version` writes `Process.Version`, the display string `main` read (`D01-layout-and-run-seam`), and a newline; `manifest` writes `Manifest`; `--help` writes `Usage`; `db status` writes what appkit's `db.Status` writes for `state/candidates.db` and the root package's `Migrations()` (`D04-store`). Any other `Args` is a usage error: `candidates: unknown option '<arg>'` or `candidates: unknown command '<arg>'`, an empty line, and the hint to run `candidates --help`. A command touches nothing but what it names: `db status` does not create the database, and no command reads the environment, the services file or a sibling.

## The manifest

The manifest is a program-parsed file: opsctl, the sandbox and home read it, so its text is contract and is stated here byte for byte, and `etc/manifest.toml` holds the same bytes. It names the app `candidates`; its description, which says what candidates is now that the owner reads it through cohorts, the same as `pages.Description` (`D01-layout-and-run-seam`); that it is not the default app; that it is an MCP service (`mcp = true`), so the gateway offers its tools; that it does not serve guests (`guests = false`), so the host's nginx admits only a request with a credential; no secrets, since candidates holds none of its own: the only thing it calls outside the suite is the website check, which fetches public pages and needs no credential (`D15-website-check`); an `[env]` table holding `CANDIDATES_KEEP_PASSES`'s default as a string, so the value the host writes into candidates' environment is the one candidates applies when the setting is unset; the `[database]` table that has the host keep and replicate `state/candidates.db`; a `[resources]` table whose only line is `memory_max = "256M"`, room enough since a run's rows are streamed and handled a batch at a time (decision 1); and, last, a `[home]` table whose only line is `group = "application"`: candidates is the funnel's, not the suite's (decision 1). `DRAIN_SECONDS` is not in `[env]`: it is the space's, as for every app.

## Exit codes

`ExitSuccess` (0), `ExitServerFailed` (1) and `ExitUsage` (2), as every app: a usage error, a setting refused or a socket missing is 2; a database that will not open, a start refused or a drain that ran out on requests is 1.

## Recorded decisions

- The usage text and the manifest are contract, not copy: each is a command's standard output or a file a program parses, so each is spelled here. The usage text's prose is candidates' own; with the cohorts change it says the tools keep the owner's cohorts and the page at `/` shows the cohorts, where it said they ranked one shortlist.
- The description began as decision 1's text; the cohorts change drops its "ranked against the fit test", since there is no longer one ranked list, and says candidates are judged and read through the owner's cohorts (cohorts decisions log 21). It is spelled in `Manifest` and declared with the same value as `pages.Description`; a test compares the two.
- The `[env]` value is compared with `settings.Defaults()` (`D01-layout-and-run-seam`), so the default cannot drift between the manifest and the code.
- `secrets = []`, `group = "application"` and `memory_max = "256M"` are decision 1's; `CANDIDATES_KEEP_PASSES = "20"` is decision 17's.
- No release is named in the manifest or in any requirement.
- `Manifest` is copied into `etc/manifest.toml` byte for byte, which a test proves through the root package's `Etc`; `etc/nginx.conf` is `D11-on-a-space`'s.
- `db status` is stated in `D04-store`, which owns the database; this document only routes `["db", "status"]` to it and names the arguments that are a usage error around it.

## Consumer tasks

An operator's host reads `candidates manifest` and `etc/manifest.toml` to learn the app, its setting's default and its database. A developer runs `candidates --help`, `candidates --version` and `candidates db status` from the install directory. A test builds a `cli.Process` with only `Args`, `Stdout`, `Stderr` and `Dir` (an empty temporary directory) set, calls `cli.Run`, and compares the returned value with `cli.ExitSuccess` or `cli.ExitUsage`, `Stdout` with `p.Version + "\n"`, `cli.Manifest` or `cli.Usage`, and `Stderr` with the exact diagnostic; to prove nothing else is touched it sets every other function field to one that records a call, `Rand` to a reader that records a read and the sinks to captures, and asserts none was used and `Dir` is still empty. A test compares `cli.Manifest` with `pages.Description` and with `settings.Defaults().KeepPasses`, and reads `manifest.toml` from the root package's `Etc()` with `fs.ReadFile` to compare it with `cli.Manifest`.

## REQUIREMENTS

- R-VR0S-Y3YB: The `internal/cli` package MUST export `Usage` as a string constant whose value is exactly `"Usage: candidates [command]\n\nCandidate businesses for agents: MCP tools at /mcp keep the owner's cohorts,\nread each candidate with its evidence and record the owner's rulings,\nwith the cohorts and the passes at /, on the socket systemd\npasses in.\nWith no command, serve.\n\nCommands:\n  manifest    print the app manifest\n  db status   print applied and pending migrations\n\nOptions:\n  --help      print this help\n  --version   print the version\n\nExit codes:\n  0  success\n  1  failure\n  2  usage error\n"`.
- R-VS8P-BVP0: The `internal/cli` package MUST export `Manifest` as a string constant whose value is exactly `app = "candidates"\ndescription = "Candidate businesses resolved from the records scrapes collects, judged and read through the owner's cohorts"\ndefault = false\nmcp = true\nguests = false\nsecrets = []\n\n[env]\nCANDIDATES_KEEP_PASSES = "20"\n\n[database]\nengine = "sqlite"\npath = "state/candidates.db"\n\n[resources]\nmemory_max = "256M"\n\n[home]\ngroup = "application"\n`, each `\n` denoting one line feed and each `"` one double quote.
- R-39QN-IG1B: `cli.Manifest` MUST contain the line `description = "` followed by exactly the text of `pages.Description` (`D01-layout-and-run-seam`) followed by `"`, so that the description the manifest publishes and the one the about screen shows are the same string.
- R-3AYJ-W7S0: The `[env]` table of `cli.Manifest` MUST hold, as the only line between the line `[env]` and the empty line that follows it, `CANDIDATES_KEEP_PASSES = "` followed by the decimal form of the `KeepPasses` of `settings.Defaults()` (`D01-layout-and-run-seam`) and a closing `"`, so that the default the host writes into candidates' environment is the one candidates applies when the setting is unset.
- R-3C6G-9ZIP: The contents of `manifest.toml` in the file system the root package's `Etc` returns MUST be exactly the bytes of `cli.Manifest`.
- R-3DEC-NR9E: The `internal/cli` package MUST export `ExitSuccess`, `ExitServerFailed` and `ExitUsage` as untyped integer constants with the values 0, 1 and 2 respectively, and every call of `Run` MUST return one of them and no other value.
- R-3EM9-1J03: When `Args` is exactly `["--version"]`, `["manifest"]` or `["--help"]`, `Run` MUST write exactly `p.Version + "\n"`, `Manifest` or `Usage` respectively to `Stdout` and nothing else, write nothing to `Stderr`, and return `ExitSuccess`; so that an empty `p.Version` writes exactly `"\n"`.
- R-3FU5-FAQS: `Run` MUST treat `Args` as a usage error unless it is empty or exactly one of `["--version"]`, `["manifest"]`, `["--help"]` and `["db", "status"]`; the offending argument MUST be `Args[0]` when it is none of `--version`, `manifest`, `--help` and `db` or when `Args` is exactly `["db"]`, `Args[2]` when `Args[0]` is `db` and `Args[1]` is `status`, and `Args[1]` otherwise; so that `["db"]` names `db`, `["db", "bogus"]` names `bogus`, `["db", "status", "extra"]` names `extra` and `["manifest", "extra"]` names `extra`.
- R-3H21-T2HH: On a usage error from `Args`, `Run` MUST write exactly `"candidates: unknown option '" + arg + "'\n\nsee 'candidates --help' for usage\n"` to `Stderr` in one call to `Stderr.Write` when the offending argument `arg` begins with `-`, and exactly `"candidates: unknown command '" + arg + "'\n\nsee 'candidates --help' for usage\n"` otherwise, write nothing to `Stdout`, and return `ExitUsage`; so that `["bogus"]` writes `candidates: unknown command 'bogus'` and `["--bogus"]` writes `candidates: unknown option '--bogus'` as its first line.
- R-3I9Y-6U86: When `Args` is not empty, `Run` MUST return without calling `LookupEnv`, `Unsetenv`, `Inherit`, `Now`, `Sleep`, `After`, `Banner` or `MCP`, without calling `Rand`'s `Read`, without calling the `Deliver` of `Sink` or `EventSink`, without taking file descriptor 3 and without sending anything to a notification socket, so that a `Process` whose `Args`, `Stdout`, `Stderr` and `Dir` alone are set is enough for every command; and, unless `Args` is exactly `["db", "status"]`, without creating, removing or changing anything under `Dir`.
