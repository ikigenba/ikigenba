# D05-git-and-source

How scripts reads repos' repositories. This document is `internal/git`, the one way scripts runs the host's `git`, and `internal/source`, which reads a repository through it four ways and no other: its owner, its name, a ref resolved to a commit, and a commit's files unpacked into a directory the caller names. It declares every exported name of both packages and states what each does. `D01-layout-and-run-seam` declares `cli.Process`, whose `Environ` is the environment of every git run and whose `After` is the timer each git run's `OPERATION_SECONDS` ends on, and resolves `REPOS_DIR` into the directory `Config.Repos` names; `D03-serve` finds git with `git.Find` at start and turns its failure into the start refusal `scripts: git not found on PATH`; `D12-limits` owns `TREE_MAX_BYTES` and `OPERATION_SECONDS` as applied, the `limits.Limits` this document is bounded by (its `Settings`, `Operation` and `Halt`), and the sentinels `limits.ErrTooLarge`, `limits.ErrTimedOut` and `limits.ErrHalted` this document returns; `D04-store` owns the failure reasons a run is recorded with; `D07-runs` resolves and unpacks a run's commit and records what came of it; `D11-tools` checks a repository's id, owner and a ref at `create` and `update`; `D08-pages` shows a repository's name.

`internal/git` is a copy of sites' package of the same name, as sites copied it; with scripts it exists in more than two apps, which makes it a candidate for appkit. Promoting it is a separate change, and until it lands the copy is a debt this design records rather than designs away.

## Reading a repository

repos publishes its on-disk layout for siblings: one bare repository per repository at `<REPOS_DIR>/<rep id>.git`, the id being `rep_` and 16 lowercase hexadecimal digits, `HEAD` naming `refs/heads/main`, and the repository's own config holding `ikigenba.id`, `ikigenba.name`, `ikigenba.owner` and `ikigenba.created`. scripts reads it with the host's `git` and nothing else, four ways, each with its argument list fixed below; repos receives no request on scripts' account, and scripts never writes there. A read never names a repository by its name, so a rename in repos changes nothing for a script, and every read looks at the directory afresh: nothing about a repository is remembered between calls.

- **Owner**: `git config --file <dir>/config --get ikigenba.owner`. git-config(1): `--get` emits the last value of a key and exits 1 when the key is not present; with `--file` only that file is read, so neither the system nor the global config can supply a value the repository does not hold, and a directory with no `config` file is exit 1 too. An unset owner is no one's: `create` refuses it as it refuses a repository that is not there (`D11-tools`).
- **Name**: `git config --file <dir>/config --get ikigenba.name`, read the same way, whenever a page shows the repository. A repository whose directory is gone, whose config holds no name, or whose name git cannot read in time is shown by its id, muted, one treatment for all of them (`D08-pages`); so `Name` answers a name or nothing, never why.
- **Resolve**: `git --git-dir=<dir> rev-parse --verify -q --end-of-options <ref>^{commit}`. git-rev-parse(1): `--verify -q` prints the object name on success and otherwise exits non-zero, silently when the argument names no object; `--end-of-options` keeps a ref that begins with `-` from being read as an option. Exit 1 is a ref that names no commit: an unknown ref, a malformed one such as `..bad`, the empty string, an absent sha, the sha of a tree. Exit 128 is a `--git-dir` that is not a repository, which is why the directory is looked at first.
- **Archive**: `git --git-dir=<dir> archive --format=tar <sha>`. git-archive(1): the commit id rides in a global extended pax header, which is not a file of the tree; regular files, directories and symbolic links are the entries, a submodule is an empty directory, an empty tree is no entry at all.

`<dir>` is `RepoDir(repo)`; a relative `Config.Repos` is taken relative to the process's working directory, but `D01-layout-and-run-seam` has already joined a relative `REPOS_DIR` with `Process.Dir`, so in a running scripts it is absolute or relative to the same place.

## Unpacking into a run's tree

`Archive` unpacks one commit into the directory its caller names, the run's `tree/` (`D07-runs`): it makes that directory and writes the commit's files into it exactly as `git archive` emits them, the same paths and bytes, symbolic links as links, with no `.git`. There is no staging and no cache: the run keeps its own tree, every run unpacks, and a failed unpack leaves what it had written where it wrote it, because a failed run's folder holds what was produced. `git mktree` will make trees git itself would never check out, a symbolic link and a directory of the same name or two entries of one name, and `git archive` emits them; `Archive` refuses such a stream instead of writing through the link, and writes nothing outside the directory it was given whatever the stream holds.

## Bounds

Every unpack is bounded by `TREE_MAX_BYTES`, measured as sites measures a site's size: the sum of the sizes of the regular files in the tar stream, symbolic links and directories counting nothing; a sum of exactly the limit unpacks, one byte more does not. The unpack stops when the sum passes the limit, deciding from the entry headers as they arrive, so the file whose size passes the limit is never written and a commit whose first archived file is far over the limit and whose next file's blob is missing is `too_large`, never git's failure (git streams tar records of 10240 bytes, so a first file of 65536 bytes announces itself before git fails). Every git run, an owner or name read, a resolve, an archive, is timed on its own under `OPERATION_SECONDS`, through the context of its own `Limits.Operation` call, one per git start attempt and none for a call that starts no git, and is killed with every process it started when that context ends: at its deadline, at `Limits.Halt`, or when its caller's context ends. Once `Halt` has returned no git starts at all.

## Why a run could not start

`Reason` turns an error of `Resolve` or `Archive` into the word a failed run is recorded with (`D04-store`):

| reason | when |
|---|---|
| `repository_missing` | the id is not a repository id, or `RepoDir(repo)` is not a directory |
| `commit_missing` | the resolve exits 1: the ref names no commit |
| `too_large` | the tree's files sum to more than `TREE_MAX_BYTES` |
| `timed_out` | a git run passed `OPERATION_SECONDS` |
| `git_failed` | anything else: git exited non-zero otherwise, git could not be started, a refused tar stream, a tree that cannot be written, a halt, the caller's context ending |

When the error carries a `*git.Error`, its `Stderr` is git's own words, exactly as git wrote them; `D07-runs` writes them into the run's `stderr` file and nowhere else.

## What is someone else's

The refusal texts of the tools and the order they check in are `D11-tools`'; how a run's folder is made, when write permission is taken from `tree/`, what is kept or removed of a failed or cut-off run, and the run's `stderr` file are `D07-runs`'; the muted id and its title are `D08-pages`'; the limit values, their defaults and parsing are `D12-limits`'; the start refusal `scripts: git not found on PATH` is `D03-serve`'s. Nothing in these two packages records an event or writes to the process's standard streams.

## Decisions

- The owner and the name are read with `config --file <dir>/config` rather than `--git-dir=<dir> config`, so a global or system config can never make a repository look owned or named.
- `Name` answers `ok` false for every way a name cannot be had, an empty value included, because the pages treat them all alike; it returns no error to be told apart.
- Resolve passes `--end-of-options`, so a branch named `-x` resolves and no ref is read as an option.
- `ValidRef` is git-check-ref-format(1)'s rules 1 and 3 to 10 with rule 2 waived (`--allow-onelevel`), checked in process, as sites checks it; `run` does not check it, since a ref git cannot accept names no commit and is `commit_missing` (stories, `S08`).
- `Archive` makes the directory it is given, so a run whose ref did not resolve, or whose repository is gone, has no `tree/`; it refuses a directory that already exists rather than writing into one.
- `Archive` decides `too_large` from the headers and stops reading there, so its git may still be writing the rest of the stream into a pipe no one reads; it kills that git and waits it out before it returns, as it does for every other failure, so a tree one byte over the limit leaves no git behind. pipe(7) documents that a write to a full pipe blocks, its default capacity being 65536 bytes, which is why the test's later file is larger than that.
- A failed `Archive` removes nothing it wrote: a partly unpacked tree is what the run's folder holds. A tar entry of a type git does not emit for a tree (anything but a regular file, a directory, a symbolic link or the pax global header) is refused like a hostile entry.
- `Reason` lives here, returning the words `D04-store` exports, so the run core and the tools share one mapping; `source` therefore imports `store` besides `git` and `limits`, as `D01-layout-and-run-seam`'s guidance lists.
- An id that is not a repository id never reaches git (`ErrRepositoryMissing`), and a sha that is not 40 lowercase hexadecimal digits never reaches git (`ErrNoCommit`).

## Consumer tasks

At start (`D03-serve`): `g, err := git.Find(path, p.Environ)` with the `PATH` value, `errors.Is(err, git.ErrNotFound)` being the start refusal; then `src := source.New(source.Config{Repos: <resolved REPOS_DIR>, Git: g, Limits: l})`.

Creating a script (`D11-tools`): `source.ValidRepo(repo)`, then `owner, err := src.Owner(ctx, repo)`: `errors.Is(err, source.ErrRepositoryMissing)` or an `owner` other than the caller's id is `no repository '<repo>'`; any other error is answered as `D11-tools` states. `source.ValidRef(ref)` decides `invalid ref`; updating a ref uses `source.ValidRef` alone and runs no git.

Starting a run (`D07-runs`): `sha, err := src.Resolve(ctx, sc.Repo, ref)`; on a nil error `err = src.Archive(ctx, sc.Repo, sha, <run folder>/tree)`; a non-nil error from either is a failed run with reason `source.Reason(err)`, except one matching `limits.ErrHalted` or the cause of the run call's own context (`errors.Is(err, context.Cause(ctx))`), each a call cut off that records no run (`D07-runs`), never `git_failed`, although `Reason` would map either to it; when `errors.As(err, &ge)` finds a `*git.Error`, `ge.Stderr` is written to the run's `stderr` file.

Showing a repository (`D08-pages`): `name, ok := src.Name(ctx, sc.Repo)`; `ok` false is the muted id.

A test finds the real git with `exec.LookPath`, calls `git.Find` with a `PATH` holding its directory and an `environ` returning its own git environment, builds the limits `D12-limits` declares with a timer whose channels it fires, and makes a source over a temporary `Repos` holding bare repositories it made with fixed dates (and hostile trees made with `git mktree`, and a commit whose blob it removed from the object store). It holds a git run at its start by putting `GIT_TRACE=<fifo>` in that environment and opening the FIFO when it chooses, and reads the same trace to count and see the git commands run; it calls `Halt` before a call to see a halted one start nothing; it snapshots the repository directory before and after to see nothing written; it removes the git it found (a symbolic link in its own `PATH` directory) to see a start failure; and it removes the write permission of `dir` while the archive git is held at its start to see a tree that cannot be written, and of `dir`'s parent before the call to see a `dir` that cannot be made.
