# D06-runner

How scripts starts a script's process and ends it. This document is `internal/runner`, the seam between the run core and the operating system: `Start` launches `python3.12 main.py` in a directory the caller names, with exactly the environment the caller gives, in a process group of its own, and returns a `*Process` whose `Wait` answers how `main.py` ended and whose `Kill` ends the whole group and says whether it ended `main.py` before `main.py` ended on its own. It declares every exported name of `internal/runner` but the Python version, which `D01-layout-and-run-seam` declares here (`PythonVersion`, `Interpreter`), and states what each does. `D07-runs` composes the environment, makes the run's folder, bounds the output through the writers it hands in, enforces `SCRIPT_SECONDS`, decides what status an ending is recorded with, and maps a failed `Start` to `start_failed`; `D03-serve` looks for the interpreter on `PATH` at start with `Find` and turns its absence into the start refusal `scripts: python3.12 not found on PATH`.

## The contract and the wrapper

The contract is the command, `python3.12 main.py`, the working directory, the environment, the two output streams, the process group, and what an ending reads as. How the process is wrapped is the runner's own: the first implementation is a plain `exec` of the interpreter, and bubblewrap is the planned second, which binds the run folder at a fixed path, binds `tree/` read-only and cuts the network while keeping the services' sockets reachable. Nothing above this package knows which is in use, so every requirement here is one both satisfy: a script finds its paths only through the variables it is given, signal deaths read as 128 plus the signal, and the group is killed whole. The run core never names the interpreter's path, never sets a process attribute, and never sends a signal itself.

## Starting

`Start` looks for `Interpreter` on the `PATH` the caller's environment carries, each time it is called, the way `Find` looks: so a `python3.12` removed from the host after scripts started makes the next `Start` fail, which the run core records as `start_failed`. It runs it with the one argument `main.py` and does not look for `main.py` itself: a tree with no `main.py` is a process that the interpreter ends with exit status 2, not a failed start. The process runs as scripts' own user and group, whatever the script holds. Its working directory is `Spec.Dir` as the process sees it (the bubblewrap runner may bind it elsewhere), its environment is exactly `Spec.Env`, nothing added, its standard input is empty, so a read sees end of file at once, and it holds no open descriptor but its three standard streams, whatever the calling process has open: scripts' own listening socket and database are never a script's. It is the leader of a new process group, so it and everything it starts that stays in that group can be ended with one signal. `Start` returns as soon as the process is running; it never waits for it. A context ended before `Start` starts nothing; once `Start` has returned, the context is no longer consulted, because a run outlives the request that started it and is ended only by `Kill`.

## Output

What the process and its group write to standard output and standard error is copied to `Spec.Stdout` and `Spec.Stderr` as it arrives, in order, every byte written before `main.py` exited delivered before `Wait` returns. A writer that fails does not stop the process or block it: the rest of that stream is read and dropped. Bounding what is kept is the writer's business (`D07-runs`). A nil writer discards its stream.

## Ending

A run is `main.py`'s: `Wait` returns when `main.py`'s own process has ended, whatever it started. When it ends, the runner kills whatever is left in its process group before it collects `main.py`'s status, and `Wait` returns only once every process of the group is gone, collected or a zombie, since `SIGKILL` takes effect asynchronously; while the group's id is still `main.py`'s and cannot be reused by another run's group; so nothing a script starts and leaves in its group outlives the run, writes to its output after it, or holds `Wait` open. A process that left the group (with `setsid`, say) is out of reach of the plain runner; it cannot hold `Wait` open either, since the runner stops reading the streams once the group is gone, and what it writes afterwards is dropped. Bubblewrap's own process namespace closes that gap.

`Wait` answers one number, the run's exit code under the status rule: the status `main.py` exited with, or 128 plus the signal's number when `main.py` died of a signal, so 143 for a `SIGTERM` it sent itself and 137 for a `SIGKILL`, the kernel's out-of-memory kill included. `Kill` sends `SIGKILL` to the whole process group, `main.py` and every process in its group, and answers true when it reached `main.py` before `main.py` had exited; `Wait` then answers 137. It answers false when `main.py` had already ended on its own, which is how the run core refuses a `cancel` that lost the race to the run's own exit (`D07-runs`). Which ending the run core records, `exited`, `killed` or `timed_out`, is decided by who called `Kill` and why, which the run core knows and the runner does not. `Kill` and `Wait` may be called from any goroutine, any number of times; `Kill` after `Wait` has returned does nothing and answers false.

## Proofs

Linux facts the requirements rest on, from the manual pages and observed with the host's `python3.12` started from Go: setpgid(2), a process made with a process group id of 0 becomes the leader of a new group whose id is its pid (observed: `os.getpgrp() == os.getpid()`, different from the parent's group); kill(2), a negative pid sends the signal to every process of that group; wait(2) and waitid(2), a child killed by a signal reports `WIFSIGNALED` and the signal, and `WNOWAIT` leaves the child waitable, so its pid, and with it the group id, is not reused until it is collected (observed: `kill(-pid, SIGKILL)` after `waitid(..., WEXITED|WNOWAIT)` killed a child `main.py` left running, which was gone afterwards); execve(2), a descriptor without close-on-exec stays open across exec (observed: a descriptor the parent opened without `O_CLOEXEC` was open in the script, so the runner must close it); and that a child left holding the output pipe keeps a plain `exec.Cmd.Wait` from returning (observed), which is why the group is killed before the status is collected and the streams are not waited on past it; and that `SIGKILL` is asynchronous (observed: in 200 trials of 200, a process just sent `SIGKILL` through `killpg` still showed state `R` in `/proc/<pid>/stat` immediately afterwards), which is why `Wait` waits until every process of the group is gone rather than returning when the signal is sent. execve(2) and credentials(7): a process keeps its parent's user and group ids across fork and exec unless the file executed is set-user-ID or set-group-ID, which an interpreter on `PATH` is not, so the plain runner sets no credential and the script runs as scripts does (observed: `os.getuid()`, `os.geteuid()`, `os.getgid()` and `os.getegid()` printed by `python3.12` equal the starting process's ids). Python's own: `python3.12` exits 2 when it cannot open the script file (observed: `can't open file ... [Errno 2]`, exit 2); `sys.executable` is the interpreter's own path (the `sys` module's documentation), so a fixture starts a child interpreter without naming the command; `/proc/self/environ` holds exactly the environment the process was started with, while Python's `os.environ` gains `LC_CTYPE=C.UTF-8` when started with no locale variable at all (PEP 538's coercion), which `LANG=C.UTF-8` in the run's environment avoids.

## Decisions

- The command is fixed in the runner, not passed in `Spec`: the contract is `python3.12 main.py`, and a caller that cannot name another command cannot drift from it.
- `Start` looks the interpreter up on `Spec.Env`'s `PATH` rather than once at start, so a removed interpreter is a `start_failed` run rather than a failure nobody records.
- `Wait` returns one `int`; whether a signal was the runner's own is told by `Kill`'s answer, and a writer's failure is the writer's to remember.
- `Kill` answers a `bool` because only the runner can tell, without a race, whether the kill reached `main.py` before it exited; the run core uses it to refuse a `cancel` of a run that had already ended.
- The group is killed before `main.py`'s status is collected, so `Kill` never signals a group id another run may have taken.
- `Find` is exported for `D03-serve`'s start check, so the start and every run look for the interpreter the same way.

## Consumer tasks

At start (`D03-serve`): `_, err := runner.Find(path)` with the `PATH` value; `errors.Is(err, runner.ErrNotFound)` is the start refusal.

Starting a run (`D07-runs`): `p, err := runner.Start(ctx, runner.Spec{Dir: <run folder>/tree, Env: env, Stdout: out, Stderr: errw})`, `env` being the twelve variables `D07-runs` composes, `out` and `errw` its bounded writers over the run's `stdout` and `stderr` files; a non-nil `err` is a failed run with `store.ReasonStartFailed`; otherwise the run is recorded `running` and a goroutine calls `code := p.Wait()` and records the ending. `cancel`, the drain deadline, a script's deletion and `SCRIPT_SECONDS` call `p.Kill()` and record `killed` or `timed_out` when it returns true; a `cancel` whose `Kill` returns false is refused as a run that has already ended.

A test finds the interpreter with `exec.LookPath(runner.Interpreter)`, writes a `main.py` into a temporary directory, and calls `runner.Start` with an `Env` holding a `PATH` of that interpreter's directory, `HOME` in its temporary directory and `LANG=C.UTF-8`, and writers it reads; the script tells the test what it saw by printing it (its argument list, working directory, `/proc/self/environ`, `/proc/self/fd`, process group, what it read from standard input) or writing its child's pid; the test waits for `Wait` with a deadline that fails the test, and checks that a pid is gone through `/proc/<pid>/stat`.

## REQUIREMENTS

- R-IT1C-MIBU: The `internal/runner` package MUST export `type Spec struct { Dir string; Env []string; Stdout io.Writer; Stderr io.Writer }`, where `io` is the standard library's `io`; `Dir` is the directory the process runs in, `Env` the whole environment it is given as `KEY=value` strings, and `Stdout` and `Stderr` where its standard output and standard error go, a nil writer meaning the stream is discarded.
- R-9LE2-6YPB: The `internal/runner` package MUST export `type Process` as a struct type with no exported fields, `func Start(ctx context.Context, s Spec) (*Process, error)`, and the methods `func (p *Process) Wait() int` and `func (p *Process) Kill() bool`.
- R-IVH5-E1T8: The `internal/runner` package MUST export `func Find(path string) (string, error)` and `var ErrNotFound error`, non-nil.
- R-9K65-T6YM: scripts' design defines a process as **gone** when no directory `/proc/<pid>` exists for its pid or the state field of `/proc/<pid>/stat` is `Z`; every requirement of scripts' design that names a gone process MUST denote this.
- R-IWP1-RTJX: `runner.Find(path)` MUST start no process, and MUST return `<entry>/` followed by the value of `Interpreter`, and a nil error, for the first entry of `path`, split at `:` and in that order, that is an absolute directory holding an entry named the value of `Interpreter` that is, after following symbolic links, a regular file with at least one execute permission bit set, skipping an entry that is empty or not an absolute path; and when there is no such entry, an empty `path` and a `path` whose only such file is in a relative entry included, MUST return the empty string and an error for which `errors.Is(err, runner.ErrNotFound)` is true.
- R-X4A6-K5JZ: When `ctx` is not done, `Spec.Env` holds exactly one element beginning `PATH=`, `Find` given the rest of that element returns a nil error, and `Spec.Dir` is a directory, `Start(ctx, s)` MUST start the interpreter that `Find` call finds, with exactly the one argument `main.py` and with `Spec.Dir`, as the process sees it, as its working directory, and return a non-nil `*Process` and a nil error; so that a `main.py` printing `sys.argv`, `sorted(os.listdir(os.getcwd()))` and `"%d.%d" % sys.version_info[:2]` prints `['main.py']`, the names of the entries of `Spec.Dir` in sorted order, and the value of `PythonVersion`.
- R-IZ4U-JD1B: The process `Start` starts MUST be started with exactly the elements of `Spec.Env` as its environment and no other variable, so that, for an `Env` with no two elements of the same key, a `main.py` that writes the bytes of `/proc/self/environ` shows exactly the elements of `Env`, each followed by one NUL byte, and nothing else, whatever the calling process's own environment holds.
- R-J0CQ-X4S0: The process `Start` starts MUST be the leader of a new process group, so that a `main.py` printing `os.getpgrp() == os.getpid()` and `os.getpgrp() == os.getpgid(os.getppid())` prints `True` and `False`.
- R-J2SJ-OO9E: The process `Start` starts MUST have an empty standard input, so that a `main.py` that calls `sys.stdin.read()` and prints the length of what it read prints `0` and goes on without waiting.
- R-J40G-2G03: The process `Start` starts MUST hold no open file descriptor other than 0, 1 and 2 when `main.py` begins, whatever descriptors the calling process holds open, those opened without close-on-exec included; so that a `main.py` that lists `/proc/self/fd` finds, besides the descriptor that listing itself opened, exactly `0`, `1` and `2`, when the test process holds a descriptor it opened with `syscall.Open` without `O_CLOEXEC`.
- R-XADO-H09G: The process `Start` starts MUST run with the calling process's real and effective user ids and group ids, so that a `main.py` printing `os.getuid()`, `os.geteuid()`, `os.getgid()` and `os.getegid()` prints the values the test process's `os.Getuid()`, `os.Geteuid()`, `os.Getgid()` and `os.Getegid()` return.
- R-X6PZ-BP1D: Every byte that any process of the group `Start` made writes to its standard output or standard error before `main.py`'s process exits MUST be written, in the order each stream received it, to `Spec.Stdout` or `Spec.Stderr` respectively, all of it before `Wait` returns; so that for a `main.py` that starts a child with `sys.executable` that prints `tick` with `flush=True`, writes its pid to a file and then loops for ever without writing, waits until that file exists, prints `main done` with `flush=True` and exits 0, `Stdout` has received exactly `tick`, a newline, `main done` and a newline once `Wait` has returned.
- R-9NTU-YI6P: When `Spec.Stdout` or `Spec.Stderr` returns an error from a `Write`, the process MUST NOT be killed or blocked for it, the rest of that stream being read and dropped; so that a `main.py` that writes 1048576 bytes to standard output and exits 0, given a `Stdout` that fails every `Write` after its first, has `Wait` return 0.
- R-9P1R-C9XE: When `Spec.Stdout` or `Spec.Stderr` is nil, that stream MUST be read and dropped without blocking the process; so that a `main.py` that writes 1048576 bytes to each of standard output and standard error and exits 0, given a nil `Stdout` and a nil `Stderr`, has `Wait` return 0.
- R-9Q9N-Q1O3: `Start` MUST return while the process it started is still running, without waiting for it to end, so that a `main.py` that prints a line with `flush=True` and then sleeps for ever has that line delivered to `Stdout` after `Start` has returned and before `Kill` is called.
- R-9RHK-3TES: When `main.py`'s process exits on its own with status `n`, `Wait` MUST return `n`, so that a `main.py` calling `sys.exit(3)` gives 3 and one that returns normally gives 0.
- R-X7XV-PGS2: When `Spec.Dir` is a directory holding no `main.py`, `Start` MUST return a non-nil `*Process` and a nil error, and `Wait` MUST return 2, the status the interpreter `Interpreter` names exits with when it cannot open its script file.
- R-JA3X-ZAPK: When `main.py`'s process dies of a signal `Kill` did not send, `Wait` MUST return 128 plus that signal's number, so that a `main.py` that sends itself `SIGTERM` gives 143.
- R-X95S-38IR: `Wait` MUST return once `main.py`'s own process has ended, without waiting for other processes of its group to end on their own, and when it returns every process that was in that group MUST be gone (R-9K65-T6YM), every process `main.py` left in it having been killed and waited out; so that for a `main.py` that starts a child with `sys.executable` that loops for ever, writes the child's pid to a file, and exits 0, `Wait` returns 0 and the child is gone the moment `Wait` returns.
- R-JCJQ-QU6Y: `Wait` MUST return once `main.py`'s own process has ended and its group has been killed even when a process that left the group, with `os.setsid()`, still holds standard output or standard error open, what that process writes afterwards being dropped.
- R-9WD5-MWDK: `Kill` MUST send `SIGKILL` to every process of the group `Start` made, `main.py`'s process and every process it started that is still in that group; so that for a `main.py` that starts a child that loops for ever, writes the child's pid to a file, and then loops for ever itself, `Kill` makes `Wait` return 137 and the child is gone (R-9K65-T6YM) the moment `Wait` returns.
- R-9XL2-0O49: `Wait` MUST be safe to call from several goroutines at once and any number of times, every call blocking until `main.py`'s process has ended and every process of its group is gone (R-9K65-T6YM), and every call returning the same value.
- R-9YSY-EFUY: `Kill` MUST return true exactly when its `SIGKILL` reached `main.py`'s process before that process had exited, and false otherwise; when a `Kill` call returns true, `Wait` MUST return 137, and at most one `Kill` call on one `*Process` MUST return true; so that `Kill` on a `main.py` that loops for ever returns true, a second `Kill` on it returns false, and `Wait` returns 137.
- R-A00U-S7LN: A `Kill` call made after `Wait` has returned MUST return false and have no effect, `Wait` going on returning the value it returned; so that for a `main.py` that exits 0, `Kill` after `Wait` returned 0 returns false and `Wait` still returns 0.
- R-A18R-5ZCC: `Kill` MUST be safe to call from several goroutines at once and while `Wait` is blocked, and MUST return without waiting for the process to end.
- R-JG7F-W5F1: When `ctx` is done when `Start` is called, `Start` MUST start no process and return a nil `*Process` and an error for which `errors.Is(err, context.Cause(ctx))` is true.
- R-JHFC-9X5Q: When `Spec.Env` holds no element beginning `PATH=`, or `Find` given that element's value returns an error at the time of the call (the interpreter removed from that directory after an earlier `Start` included), `Start` MUST start no process and return a nil `*Process` and an error for which `errors.Is(err, runner.ErrNotFound)` is true.
- R-A2GN-JR31: When `Spec.Dir` is not a directory (absent, or a regular file), or the process cannot otherwise be started, `Start` MUST return a nil `*Process` and a non-nil error, and every process the call started, if any, MUST be gone (R-9K65-T6YM) when it returns.
- R-JJV5-1GN4: Once `Start` has returned a `*Process`, the end of `ctx` MUST change nothing about the process: a `main.py` that prints a line after reading a file the test writes once it has cancelled `ctx`, and exits 0, prints that line and has `Wait` return 0.
- R-JMAX-T04I: `Start`, `Find`, `Wait` and `Kill` MUST write nothing to the calling process's `os.Stdout` or `os.Stderr`, whatever the process writes to its own streams.
