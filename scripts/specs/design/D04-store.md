# D04-store

The catalog: `internal/store`, which owns scripts' one SQLite database, `state/scripts.db`, and everything it records — every script's id, name, owner, repository, ref and created time, every subscription of a script to an event pattern, every run's id, script, sha, ref, user, request id, trigger, event, status, exit code, times, output sizes, truncation and failure reason, and the memory of which event each script has had a run from — together with the rules a script's name and an event pattern obey, the words a run's status, failure reason and trigger are spelled with, and the one line every consumer answers when the catalog cannot be reached. `D01-layout-and-run-seam` declares `cli.Process`, whose `Dir`, `Now` and `Rand` reach the catalog through `cli.Run`, resolves the path the catalog lives at, declares the root package's `Migrations`, the schema's migrations, and declares the entity ids this package exports (`ScriptPrefix`, `RunPrefix`, `NewScriptID`, `NewRunID`, `ValidScriptID`, `ValidRunID`); `D03-serve` opens the catalog with appkit's `db.Open` at start, builds the store over that handle, writes the diagnostic for a catalog that will not open, and closes the handle after the drain. Opening, migrating, the journal mode, transactions and the failure seam are appkit's `db` (its D15 and D16), which this document restates none of. This document declares every other exported name of `internal/store` and states what each does. What a tool checks before it calls the store and what it answers is `D11-tools`'; what the pages show of a record is `D08-pages`'; when a run is recorded, ended, recovered and pruned, and its folder, are `D07-runs`'; which subscriptions a delivered event starts runs for is `D14-delivery`'s; the repositories under `REPOS_DIR` are `D05-git-and-source`'s. The store holds no file but the database, runs no git and starts no process.

## One catalog, one writer

scripts is the catalog's only writer, and no sibling reads it. Metadata is in the catalog and bytes are on disk: a run's output, input, tree and files are under its folder (`D07-runs`), and the catalog keeps only what lists and pages are drawn from, so a list or a page is one read of the catalog. A run's record survives its folder going missing. What is contract is what a reader and a restart see: what a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds, field for field. A test proves the catalog's content that way, by closing the handle and opening another, never by reading tables.

The schema is contract too, because a migration is applied to a catalog that already exists and the migrations must agree with what earlier releases left on disk. It is two migrations. `0001_catalog.sql` is the schema scripts has always created: a table `catalog` with the columns `id`, an integer primary key that only the value 1 may take, and `value`, a blob, not null, holding the whole catalog's scripts and runs in one row, as `encoding/gob` writes one value whose two fields are the scripts and the runs, each keyed by its id. Written with `CREATE TABLE IF NOT EXISTS` and seeding nothing, it creates the table on a fresh catalog and changes nothing on a catalog an earlier scripts kept, which `db.Open` then records as having had `0001`, so that catalog's scripts and runs are served as they were. `0002_subscriptions.sql` adds two tables: `subscriptions`, one row per subscription, with the columns `script` and `event`, text, together the primary key, so a script never holds one pattern twice, and `created`, an integer; and `event_runs`, one row per script and event id a run was made for, with the columns `script` and `event`, text, together the primary key. `event_runs` is the delivered-event memory: a row is written in the same write as the event run it records, is kept when that run is pruned, and goes only with its script, so the same event delivered again starts no second run of a script even after its run is gone. `0002` applies after `0001` on a fresh catalog and on one that has had `0001` alone, which is every catalog the previous release kept, and changes nothing in `catalog`. Its tests are of the shape every service has: open a fresh catalog with `scripts.Migrations()` and inspect `sqlite_master` and `PRAGMA table_info`; for adoption, build a catalog in the stored form an earlier scripts wrote, with no `schema_migrations`, and see a store over the opened handle answer its scripts and runs; and build one that has had `0001` alone, open it with `scripts.Migrations()`, and see the same scripts and runs, none subscribed, and a subscription made and kept. Beyond what those tests need, how the records are laid out is not contract: no sibling reads the database, and the host's replication copies it whole. A later change to the schema is a new migration file, never an edit of one already released.

The store does not open anything. `store.New` builds a store over a handle `db.Open` returned, with the clock and random source it stamps and draws from; every read is a `DB.Read` and every write a `DB.Write` on that handle, so the handle's one writer serializes the writes and the store keeps no lock of its own. A write that must check and change together — a create's name check and insert, a run's script check and insert, an event run's insert with its delivered-event row, a subscription's check and insert or removal, an ending's check that the run is still running, a script's removal with its runs — does both inside one `DB.Write`, which is what keeps the catalog's invariants under concurrent calls.

A catalog that fails is a **failing** store: from a `SetFailing(true)` on its handle until a `SetFailing(false)`, and once its handle is closed, every method answers a catalog error and changes nothing. That is the one failure seam: a test that needs a call's reads to succeed and its write to fail turns it on from an injected function the call calls between them — a test's `runs.Config.Now`, or the `After` of the test's `limits.Clock`, called before each git run, as `D11-tools` does before a `run`'s git — and never takes a permission away, which under WAL does not reliably fail a write. `cli.Run` holds its handle itself, so a test of `Run` that needs the catalog to fail after `Run` opened it does so from outside, as `D03-serve`'s consumer tasks describe.

## Scripts

A script's **id** is `scr_` and 16 lowercase hexadecimal digits (`D01-layout-and-run-seam`), drawn from the random source when the script is created and never changed. Its **name** is 1 to 64 bytes, each a lowercase ASCII letter, a digit or `-`, the first not `-`, and none of `about`, `mcp`, `events` and `declarations`, since `/about`, `/mcp`, `/events` and `/declarations` are scripts' own paths; it is taken as given, never trimmed or folded, and never changes, since there is no rename. Names are one namespace for the whole space, because the name is the URL segment: a name is **taken** when any script, of any owner, has it. Its **owner** is the user id of the caller that created it. Its **repository** is a repository id as repos names its directory, kept verbatim, so a script keeps working across a rename in repos; the store never looks at it. Its **ref** is what a run without a ref of its own resolves, `main` unless the creator gave another, and the one field `SetRef` changes. **Created** is the time of the create in UTC to the second, the precision the tools answer it in.

Every read that returns a script returns it with its **last run**: the newest of its runs, in the order `Runs` answers them, or none for a script that has never run. The catalog page, `list`, `show`, `create` and `update` all show it, so it is part of the record a reader gets rather than a second query.

Every read that returns a script returns it with its **subscriptions** too, so `show`, `create`, `update`, `subscribe` and `unsubscribe` answer them and `list` counts them without a second query.

## Subscriptions

A **subscription** is a pair, one script and one event pattern, kept as the exact string given, with **created**, the time of the `Subscribe` that made it, in UTC to the second. An **event pattern** is two or more words joined by single `.`s, each word either a lowercase letter followed by lowercase letters and digits, single `_` allowed between them, or exactly `*`; a pattern with no `*` is an event name. `ValidEvent` is the rule, exported because the tools check it, after finding the script, before they call the store, and the store refuses a pattern it fails as it refuses an invalid script name. It is the pattern rule of appkit's `events` package, which exports `Match` but no validator of its own, so the store states it as a regular expression. A pattern **matches** an event name of as many words, word for word, each `*` standing for exactly one word: `cron.*.fired` matches `cron.hourly.fired` and not `cron.fired` or `cron.a.b.fired`, and `repo.pushed` matches only itself. That is appkit's `events.Match`, which the store may use. `Subscribers` answers by matching; everything else compares patterns as strings: `Subscribe` is idempotent for the exact string, so subscribing a script to a pattern it already holds changes nothing and keeps the time it was made, and a retried call answers what the first did, while another string, even one matching the same names, is another subscription. `Unsubscribe` removes only the subscription whose pattern is the string given, never one that matches it or that it matches, and a pair the store does not hold is refused with `ErrNotSubscribed`, so a caller that mistyped learns nothing was removed. A script's subscriptions are listed in ascending byte order of the pattern. `SetRef` keeps them, and `Delete` removes them with the script. Subscriptions say nothing about runs: making one runs nothing, and removing one touches no run.

## Runs

A run's **id** is `run_` and 16 lowercase hexadecimal digits, minted by the run core with `NewRunID` before the run is recorded, because its folder is named by it (`D07-runs`). Its **script** is its script's id, the one reference from a run to its script. Its **sha** is the 40-hexadecimal-digit commit the run resolved, empty only for a run that failed before its ref resolved. Its **ref** is the ref it was resolved from. Its **user** and **request id** are those it acts as and was caused by. Its **trigger** is `manual` for a run the `run` tool asked for and `event` for one a delivered event started (`D14-delivery`), and its **event** is, for an event run, the id of the event it was made for, and empty otherwise. Its **started** and **finished** times are the run core's, kept in UTC to the second; started is the moment the run was asked for, whether its process started then or later, and finished is zero while the run is queued or running. **Stdout bytes** and **stderr bytes** are how many bytes of each stream the run kept, recorded when the run is recorded failed or ends; while a run is queued or running the record holds zero and its files, if any, are the measure (`D07-runs`). **Truncated** says either stream was cut at `OUTPUT_MAX_BYTES`. Its **status** is one of six words, and its **exit code** and **reason** apply only to one of them each:

- `queued` while the run waits for a slot to run in, its tree unpacked and no process of it started (`D07-runs`);
- `running` while the process lives;
- `exited` when the process ended on its own, with its exit code, from 0 to 255, 128 plus the signal's number for a signal scripts did not send;
- `killed` when scripts killed it, or took it out of the queue before it started: on `cancel`, on its script's `delete`, at the drain deadline, or at the next start for a run still recorded `running`;
- `timed_out` when scripts killed it at `SCRIPT_SECONDS`;
- `failed` when the script never started, with one of seven reasons: `repository_missing`, `commit_missing`, `too_large`, `git_failed`, `timed_out` (git outlasted `OPERATION_SECONDS`), `start_failed` and `queue_abandoned` (the run was still waiting for a slot when scripts stopped, or when the next start found it recorded `queued`).

The status and reason words are exported constants of this package, beside the record whose field they fill, because the store refuses a record that does not use them and every consumer — the run core that writes them, the tools, pages and trail that show them — already imports the store; a reason's sentence on the run page is `D08-pages`'.

A run has three transitions in the catalog. `AddRun` records it once: `running`, after its process has started; `queued`, when every slot is taken and it must wait; or `failed`, when it could not start; `D07-runs` decides which and when, and a run cut off before any is never recorded. `StartRun` moves a `queued` run to `running` once its process has started, keeping its `started`. `FinishRun` ends a run exactly once: a `running` run as `exited`, `killed` or `timed_out`, and a `queued` run as `killed` (cancelled or deleted before it started) or `failed` with `start_failed` or `queue_abandoned`, with no output, since it never ran. Of two calls racing to end the same run, one succeeds and the other is told the run has already ended (`ErrEnded`), which is how `cancel` racing a run's own exit is refused; `StartRun` of a run no longer queued is told the same. Nothing moves a run back to `queued` or `running`, and nothing makes a running run `failed`.

## Reads

`Find` is a caller's own script by name, so another owner's script is indistinguishable from none; `List` is one owner's scripts, in ascending byte order of name; `Taken` is the space-wide name check. `FindRun` is a run of one of a caller's own scripts, so another owner's run is indistinguishable from none; `RunByID` is any run, for the run core. `Subscribers` is every script, of every owner, holding a subscription that matches one event name, each once, for the delivery (`D14-delivery`); `Delivered` says whether a script has had a run from one event id. `Runs` is one script's runs, newest first: in descending order of started, and among runs started in the same second in descending byte order of id. `Running` is every run still recorded `running`, of every owner, which a start marks `killed`, and `Queued` every run still recorded `queued`, which a start marks `failed` with `queue_abandoned` (`D07-runs`). `PastKeeping` is every run past keeping at a moment, over the whole catalog: a run that is neither `running` nor `queued`, that started more than `RUN_KEEP_DAYS` days of 24 hours before that moment, and that is not among its script's newest `RUN_KEEP_COUNT` runs in the order `Runs` answers them; every run counts toward that rank, a running or queued one included. The store reads neither setting; `D07-runs` hands in the values `D12-limits` read. All lists are never nil.

## Writes

`Create` mints a script's id and stamps its created time. `SetRef` changes a script's ref and says whether it changed, so a same-ref `update` records no event (`D10-trail`). `Delete` removes a script and every run record of it, whatever their status, in one step; the run core kills its running runs and removes its folders before that call (`D07-runs`). `Subscribe` and `Unsubscribe` add and remove a subscription and answer the script as it is after the call. `AddRun`, `StartRun` and `FinishRun` are the three transitions above; `AddRun` of an event run also records its script and event id, in the same write, and refuses a second run of one script for one event id with `ErrDelivered`, which is what makes a redelivered event start nothing. `DeleteRun` removes one run record, which is what pruning removes once the run core has removed the folder (`D07-runs`); it leaves the delivered-event memory, so `Delivered` still answers true for a pruned event run. At every moment every run the store holds names a script the store holds, so a run recorded while its script is being deleted is either refused or removed with it.

## Errors

`ErrNotFound`, `ErrNameTaken`, `ErrEnded`, `ErrNotSubscribed` and `ErrDelivered` are answers about the catalog's content. Every other error from a method is answered as the catalog being unreachable: every consumer answers it with `Unreachable`, never quoting the underlying error. A failing store, a random source that fails and a context already done all end there. So does a write given a value no consumer sends — a name `ValidName` refuses, an event pattern `ValidEvent` refuses, an empty owner, repository or ref, a run that breaks the record's rules — which changes nothing. When one call meets several of these conditions, one fixed precedence decides its answer: a done context, then a failing store, then an invalid argument, then a missing record, then a taken name, an ended run, a missing subscription or an event already delivered.

## Decisions

- Ids are 8 bytes of `Rand`; a drawn script id already catalogued is drawn again, up to eight candidates in all, after which `Create` gives up with a catalog error, so a `Rand` that repeats itself cannot hold a call for ever. A run id already catalogued is a catalog error from `AddRun`; with 64 random bits the run core does not plan for it.
- Run times are given by the run core, not stamped by the store, because started is the moment of the `run` call and finished the moment the run core saw the end; the store keeps them to the second.
- The order of `Runs` breaks a tie of started by descending id, so the whole list is the exact reverse of ascending (started, id); the stories fix that ties go by id and leave the direction open.
- Pruning is split: the store answers which runs are past keeping and deletes a record; the run core removes the folder first, so a failure between the two leaves a record whose files are gone, a state the stories already show, never a folder no record names.
- A queued run is a record before its process exists, because `run` answers it at once and `runs` and `result` show it; `StartRun` is its own transition, not a second `AddRun`, so its `started` stays the moment it was asked for. The queue's order is the run core's, held in memory; the store keeps only the status, and `Queued` exists for the start that finishes what a dead scripts left waiting.
- `Delete` removes running runs' records too: the store does not wait for a process, and `D07-runs` ends every running run before calling it.
- The store has no `Open` and no `Close`: the handle is appkit's, opened and closed by `cli.Run`, and a store over it lives as long as it does.
- The baseline migration is the table every earlier scripts made, `CREATE TABLE IF NOT EXISTS`, so an earlier catalog is adopted with nothing changed; the stored form, one gob value in one row, is contract only as far as adopting that catalog needs (R-94EX-UQKT).
- The delivered-event memory is a table of its own, not the run record: runs live in the gob blob, which has no unique index, and a run is pruned while the memory must outlive it (`S19`, `S27`); recording both in one write keeps the pair and the run together, so no memory exists without the run it names until pruning removes the run.
- `Run.Event` is a gob field of the stored run; a catalog an earlier scripts kept decodes with it empty, every such run being `manual`.
- Subscriptions are rows of `subscriptions`, kept out of the blob so the pair's uniqueness is the table's primary key; the store reads them with the script, and a gob entry's `Subscriptions` field, which the stored form carries because `Script` has it, is never read (R-G6AU-28DY).
- The tables `subscriptions` and `event_runs` and their columns are a recorded decision, stated as requirements because a migration, once released, binds every later one. A test proves their shape only, through `DB.Read` of `sqlite_master` and `PRAGMA table_info`, and never reads their rows beyond R-RVSC-1DRN's emptiness on a fresh catalog: that subscriptions and the delivered-event memory live there is proved, as far as tests reach, by behaviour — `Subscriptions` and `Delivered` answering the same across a closed and reopened handle, `Delivered` surviving `DeleteRun` and ending with `Delete`, and a catalog that has had `0001` alone gaining both tables empty.
- `0002` runs only on a catalog `0001` made, fresh or adopted, so it creates its two tables without `IF NOT EXISTS` and touches nothing else.
- Matching is done when an event is delivered, over the patterns as stored: a pattern is kept as given, so `show` and `unsubscribe` see exactly what `subscribe` took, and no schema change is needed, the table's primary key still holding one pattern once per script.
- `Delivered` answers false, not `ErrNotFound`, for a script id the store does not hold: the run core asks it before anything else and a missing script is found by `AddRun`.
- Only whole-second UTC times are accepted from an earlier catalog, because every earlier scripts stored its times so, and so that every record the store returns has the shape R-9371-GYU4 states.

## Consumer tasks

`cli.Run` opens the catalog with `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "scripts.db"), Migrations: scripts.Migrations(), Now: p.Now})`; on any error while `ctx` is not done it writes `D03-serve`'s diagnostic with the error's text as the reason; otherwise it builds `st := store.New(d, store.Config{Now: p.Now, Rand: rand})`, hands it to the run core and the handler, and calls `d.Close()` after the drain.

The tools (`D11-tools`), `u` being the `identity.Caller` of the call: `list` is `s.List(ctx, u.UserID)`, each `Script`'s `Last` giving `last_run`; `show` is `s.Find(ctx, u.UserID, name)`; `create` checks `store.ValidName(name)`, then `s.Taken(ctx, name)`, then the repository and ref, and calls `s.Create(ctx, store.Draft{Owner: u.UserID, Name: name, Repo: repo, Ref: ref})`, `store.ErrNameTaken` still answering `already exists` when a racing create won; `update` is `s.Find` then `s.SetRef(ctx, sc.ID, ref)`, its `changed` deciding the event; `subscribe` is `s.Find`, then `store.ValidEvent(event)`, then `s.Subscribe(ctx, sc.ID, event)`; `unsubscribe` is `s.Find`, then `store.ValidEvent(event)`, then `s.Unsubscribe(ctx, sc.ID, event)`, `store.ErrNotSubscribed` answering `'<name>' is not subscribed to '<event>'`; every answered `Script`'s `Subscriptions` giving `subscriptions`, each `Event` and `Created`, and its `len` `list`'s count; `delete` is `s.Find` then the run core's deletion, which ends with `s.Delete(ctx, sc.ID)`; `runs` is `s.Find` then `s.Runs(ctx, sc.ID)`; `result` and `cancel` are `s.FindRun(ctx, u.UserID, id)`, `cancel` then handing the run to the run core, whose `s.FinishRun` answering `store.ErrEnded` is the refusal `run '<id>' has already ended`. `store.ErrNotFound` is `no script named '<name>'` or `no run '<id>'`; an error matching no sentinel is `store.Unreachable`. A `Run`'s `Status` compared with `store.StatusExited` decides whether `exit_code` is present, with `store.StatusFailed` whether `reason` is, and its `Trigger` compared with `store.TriggerEvent` whether `event`, its `Event`, is.

The run core (`D07-runs`): `id, _ := store.NewRunID(rand)`; after the process has started, `s.AddRun(ctx, store.Run{ID: id, Script: sc.ID, SHA: sha, Ref: ref, User: u.UserID, RequestID: u.RequestID, Trigger: store.TriggerManual, Status: store.StatusRunning, Started: started})`, or for an event run `Trigger: store.TriggerEvent, Event: req.Cause.ID` (`D14-delivery`), whose `store.ErrDelivered` means the script already has its run from that event, after a `s.Delivered(ctx, sc.ID, req.Cause.ID)` asked first; or, when every slot is taken, the same with `Status: store.StatusQueued`, and once its process has started `s.StartRun(ctx, id)`; or for a run that could not start the same with `Status: store.StatusFailed`, `Reason` its reason and `Finished` set, `SHA` empty when the ref did not resolve (`SHA: ""`, `Reason: store.ReasonCommitMissing`, say) and the resolved sha otherwise (`Reason: store.ReasonTooLarge`, say); when the process ends, `s.FinishRun(ctx, id, store.Ending{Status: store.StatusExited, ExitCode: code, Finished: now, StdoutBytes: n, StderrBytes: m, Truncated: cut})`; for a queued run cancelled, `s.FinishRun(ctx, id, store.Ending{Status: store.StatusKilled, Finished: now})`, and abandoned, `store.Ending{Status: store.StatusFailed, Reason: store.ReasonQueueAbandoned, Finished: now}`; at start, `s.Running(ctx)` and a `FinishRun` with `store.StatusKilled` for each, and `s.Queued(ctx)` and a `FinishRun` with `store.StatusFailed` and `store.ReasonQueueAbandoned` for each; after every end, `s.PastKeeping(ctx, now, days, count)`, each run's folder removed, then `s.DeleteRun(ctx, r.ID)`; to delete a script, `s.Runs(ctx, sc.ID)` to find what is running or queued, the kills and `FinishRun`s, then the folder `state/runs/<script id>/` removed, then `s.Delete(ctx, sc.ID)`.

The pages (`D08-pages`, `D09-run-files`): the catalog is `s.List(ctx, u.UserID)`; a script page is `s.Find` and `s.Runs`, `len` of which is the runs kept; a run page and its files are `s.Find` then `s.FindRun`, the run's `Script` compared with the script's `ID`. Each answers `store.Unreachable` and a newline, as plain text with status `503`, for an error matching no sentinel.

A test opens a handle with `d, err := db.Open(ctx, db.Config{Path: filepath.Join(t.TempDir(), "state", "scripts.db"), Migrations: scripts.Migrations(), Now: clock})` and builds a store with `store.New(d, store.Config{Now: clock, Rand: bytes.NewReader(known)})`; creates, finds, lists and deletes scripts; adds, finishes, lists and deletes runs; subscribes and unsubscribes scripts, patterns among them, and lists an event name's subscribers; adds event runs and asks `Delivered` before and after `DeleteRun` and `Delete`; asks which are past keeping at a moment it chooses; closes the handle and opens another on the same path to see the same records; and calls `d.SetFailing(true)`, before a call or from a hook the call runs after its reads, to see a catalog error, and `d.SetFailing(false)` to see the same store answer again. A schema test opens a fresh catalog with `scripts.Migrations()` and, inside a `d.Read`, queries `sqlite_master` and `PRAGMA table_info`. An adoption test opens a handle on a file with an empty migrations file system, creates the table `catalog` by R-94EX-UQKT's statement and writes its one row, the gob encoding of scripts and runs it chose, through `d.Write`, drops `schema_migrations`, closes the handle, and opens the file again with `scripts.Migrations()`. A test of the previous release's catalog opens a handle with a `fstest.MapFS` holding only `0001_catalog.sql`, its bytes read with `fs.ReadFile(scripts.Migrations(), "0001_catalog.sql")`, writes the `catalog` row through `d.Write`, closes it, and opens the file again with `scripts.Migrations()`.

## REQUIREMENTS

- R-XVW7-CY8N: The `internal/store` package MUST export `type Config struct { Now func() time.Time; Rand io.Reader }`, `type Store`, and `func New(d *db.DB, cfg Config) *Store`, where `db` is appkit's package `github.com/ikigenba/ikigenba/appkit/db` and `io` and `time` are the standard library's packages; the handle passed as `d` is the store's **handle**, `Now` the clock a script's created time is read from (nil meaning `time.Now`), and `Rand` the source script ids are drawn from (nil meaning `crypto/rand.Reader`).
- R-R2IQ-UVYZ: The `internal/store` package MUST export `type Script struct { ID, Name, Owner, Repo, Ref string; Created time.Time; Subscriptions []Subscription; Last *Run }`; a `Script` is one script of the catalog: its id, name, owner's user id, repository id, ref, the time it was created, its subscriptions, and its newest run, nil when it has none.
- R-G2N4-WX5V: The `internal/store` package MUST export `type Subscription struct { Event string; Created time.Time }`; a `Subscription` is one subscription of a script: the event pattern it is subscribed to, exactly as `Subscribe` was given it, and the time the subscription was made.
- R-R4YJ-MFGD: The `internal/store` package MUST export `type Run struct { ID, Script, SHA, Ref, User, RequestID, Trigger, Event, Status string; ExitCode int; Started, Finished time.Time; StdoutBytes, StderrBytes int64; Truncated bool; Reason string }`; a `Run` is one run of the catalog: its id, its script's id, the commit it resolved (empty when none), the ref it was resolved from, the user id it acts as, the request id it was caused by, its trigger, the id of the event it was made for (empty for a run no event made), its status, its exit code, the times it started and finished (the zero `time.Time` while running), how many bytes of its standard output and standard error it kept, whether either was cut, and its failure reason (empty unless failed).
- R-RMLU-90BA: The `internal/store` package MUST export `type Draft struct { Owner, Name, Repo, Ref string }`, the fields of a script `Create` makes.
- R-RNTQ-MS1Z: The `internal/store` package MUST export `type Ending struct { Status string; ExitCode int; Finished time.Time; StdoutBytes, StderrBytes int64; Truncated bool; Reason string }`, the fields `FinishRun` records when a queued or running run ends, `Reason` being the failure reason of a queued run that ends `failed` and empty otherwise.
