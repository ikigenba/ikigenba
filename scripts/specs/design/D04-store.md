# D04-store

The catalog: `internal/store`, which owns scripts' one SQLite database, `state/scripts.db`, and everything it records — every script's id, name, owner, repository, ref and created time, and every run's id, script, sha, ref, user, request id, trigger, status, exit code, times, output sizes, truncation and failure reason — together with the rule a script's name obeys, the words a run's status, failure reason and trigger are spelled with, and the one line every consumer answers when the catalog cannot be reached. `D01-layout-and-run-seam` declares `cli.Process`, whose `Database`, `Now` and `Rand` reach the store through `cli.Run`, resolves the path the catalog lives at, and declares the entity ids this package exports (`ScriptPrefix`, `RunPrefix`, `NewScriptID`, `NewRunID`, `ValidScriptID`, `ValidRunID`); `D03-serve` opens the store at start, writes the diagnostic for a catalog that will not open, and closes it after the drain. This document declares every other exported name of `internal/store` and states what each does. What a tool checks before it calls the store and what it answers is `D11-tools`'; what the pages show of a record is `D08-pages`'; when a run is recorded, ended, recovered and pruned, and its folder, are `D07-runs`'; the repositories under `REPOS_DIR` are `D05-git-and-source`'s. The store holds no file but the database, runs no git and starts no process.

## One catalog, one writer

scripts is the catalog's only writer, and no sibling reads it. Metadata is in the catalog and bytes are on disk: a run's output, input, tree and files are under its folder (`D07-runs`), and the catalog keeps only what lists and pages are drawn from, so a list or a page is one read of the catalog. A run's record survives its folder going missing. Which tables hold a record is not contract: the host's replication copies the database whole. What is contract is what a reader and a restart see: what a `*Store` holds when it is closed is what the next `Open` of the same source holds, field for field. A test proves the catalog that way, by closing and reopening, never by reading tables.

`Open` takes the source `cli.Run` gives it. An ordinary filesystem path is a database file whose missing parent directories `Open` creates; a missing file, or one of no bytes, is a new empty catalog. The empty string and `:memory:` are a catalog in memory that lives as long as the `*Store`. A failed `Open` leaves the directory that holds `Source` exactly as it found it, with no `-wal` or `-shm` file beside the database, since SQLite creates those on a connection's first use of a WAL database even when the write then fails. A file that is not a database, one the process cannot write, a directory that cannot hold the database, and a parent that cannot be created are failures matching `ErrDatabase`, whose text is the underlying failure's alone so `D03-serve` can write it after `scripts: cannot open database state/scripts.db: `; a failed `Open` leaves an existing file exactly as it was. A catalog `Open` returns is in SQLite's WAL journal mode, because the host's replica needs it: the manifest's `[database]` (`D02-cli`) has opsctl back `state/scripts.db` up with litestream, which follows the `-wal` file beside it, exactly as sites' catalog is kept.

A catalog that fails in the middle of the work is a closed store: once `Close` has returned, every method answers a catalog error. A test that needs a failure after a call's reads closes the store, or breaks its database, from an injected function the call calls between them: a test's `Now` (`cli.Process.Now`, `runs.Config.Now`), as `D03-serve` breaks its own catalog once `state/runs` exists, or the `After` of the test's `limits.Clock`, called before each git run, as `D11-tools` closes the store before a `run`'s git; never by taking a permission away after `Open`.

## Scripts

A script's **id** is `scr_` and 16 lowercase hexadecimal digits (`D01-layout-and-run-seam`), drawn from the random source when the script is created and never changed. Its **name** is 1 to 64 bytes, each a lowercase ASCII letter, a digit or `-`, the first not `-`, and neither `about` nor `mcp`, since `/about` and `/mcp` are scripts' own paths; it is taken as given, never trimmed or folded, and never changes, since there is no rename. Names are one namespace for the whole space, because the name is the URL segment: a name is **taken** when any script, of any owner, has it. Its **owner** is the user id of the caller that created it. Its **repository** is a repository id as repos names its directory, kept verbatim, so a script keeps working across a rename in repos; the store never looks at it. Its **ref** is what a run without a ref of its own resolves, `main` unless the creator gave another, and the one field `SetRef` changes. **Created** is the time of the create in UTC to the second, the precision the tools answer it in.

Every read that returns a script returns it with its **last run**: the newest of its runs, in the order `Runs` answers them, or none for a script that has never run. The catalog page, `list`, `show`, `create` and `update` all show it, so it is part of the record a reader gets rather than a second query.

## Runs

A run's **id** is `run_` and 16 lowercase hexadecimal digits, minted by the run core with `NewRunID` before the run is recorded, because its folder is named by it (`D07-runs`). Its **script** is its script's id, the one reference from a run to its script. Its **sha** is the 40-hexadecimal-digit commit the run resolved, empty only for a run that failed before its ref resolved. Its **ref** is the ref it was resolved from. Its **user** and **request id** are those it acts as and was caused by. Its **trigger** is `manual`; `event` arrives with the event bus and is not yet a word the store accepts. Its **started** and **finished** times are the run core's, kept in UTC to the second; finished is zero while the run is running. **Stdout bytes** and **stderr bytes** are how many bytes of each stream the run kept, recorded when the run is recorded failed or ends; while a run is running the record holds zero and its files are the measure (`D07-runs`). **Truncated** says either stream was cut at `OUTPUT_MAX_BYTES`. Its **status** is one of five words, and its **exit code** and **reason** apply only to one of them each:

- `running` while the process lives;
- `exited` when the process ended on its own, with its exit code, from 0 to 255, 128 plus the signal's number for a signal scripts did not send;
- `killed` when scripts killed it: on `cancel`, on its script's `delete`, at the drain deadline, or at the next start for a run still recorded `running`;
- `timed_out` when scripts killed it at `SCRIPT_SECONDS`;
- `failed` when the script never started, with one of six reasons: `repository_missing`, `commit_missing`, `too_large`, `git_failed`, `timed_out` (git outlasted `OPERATION_SECONDS`) and `start_failed`.

The status and reason words are exported constants of this package, beside the record whose field they fill, because the store refuses a record that does not use them and every consumer — the run core that writes them, the tools, pages and trail that show them — already imports the store; a reason's sentence on the run page is `D08-pages`'.

A run has two transitions in the catalog. `AddRun` records it once, either `running`, after its process has started, or `failed`, when it could not start; `D07-runs` decides which and when, and a run cut off before either is never recorded. `FinishRun` moves a `running` run to `exited`, `killed` or `timed_out`, exactly once: of two calls racing to end the same run, one succeeds and the other is told the run has already ended (`ErrEnded`), which is how `cancel` racing a run's own exit is refused. Nothing moves a run back to `running`, and nothing makes a running run `failed`.

## Reads

`Find` is a caller's own script by name, so another owner's script is indistinguishable from none; `List` is one owner's scripts, in ascending byte order of name; `Taken` is the space-wide name check. `FindRun` is a run of one of a caller's own scripts, so another owner's run is indistinguishable from none; `RunByID` is any run, for the run core. `Runs` is one script's runs, newest first: in descending order of started, and among runs started in the same second in descending byte order of id. `Running` is every run still recorded `running`, of every owner, which a start marks `killed` (`D07-runs`). `PastKeeping` is every run past keeping at a moment, over the whole catalog: a run that is not `running`, that started more than `RUN_KEEP_DAYS` days of 24 hours before that moment, and that is not among its script's newest `RUN_KEEP_COUNT` runs in the order `Runs` answers them; every run counts toward that rank, a running one included. The store reads neither setting; `D07-runs` hands in the values `D12-limits` read. All lists are never nil.

## Writes

`Create` mints a script's id and stamps its created time. `SetRef` changes a script's ref and says whether it changed, so a same-ref `update` records no event (`D10-trail`). `Delete` removes a script and every run record of it, whatever their status, in one step; the run core kills its running runs and removes its folders before that call (`D07-runs`). `AddRun` and `FinishRun` are the two transitions above. `DeleteRun` removes one run record, which is what pruning removes once the run core has removed the folder (`D07-runs`). At every moment every run the store holds names a script the store holds, so a run recorded while its script is being deleted is either refused or removed with it.

## Errors

`ErrNotFound`, `ErrNameTaken` and `ErrEnded` are answers about the catalog's content; `ErrDatabase` is `Open`'s failure. Every other error from a method is answered as the catalog being unreachable: every consumer answers it with `Unreachable`, never quoting the underlying error. A closed `*Store`, a database that fails, a random source that fails and a context already done all end there. So does a write given a value no consumer sends — a name `ValidName` refuses, an empty owner, repository or ref, a run that breaks the record's rules — which changes nothing. When one call meets several of these conditions, one fixed precedence decides its answer: a done context, then a closed store, then an invalid argument, then a missing record, then a taken name or an ended run.

## Decisions

- Ids are 8 bytes of `Rand`; a drawn script id already catalogued is drawn again, up to eight candidates in all, after which `Create` gives up with a catalog error, so a `Rand` that repeats itself cannot hold a call for ever. A run id already catalogued is a catalog error from `AddRun`; with 64 random bits the run core does not plan for it.
- Run times are given by the run core, not stamped by the store, because started is the moment of the `run` call and finished the moment the run core saw the end; the store keeps them to the second.
- The order of `Runs` breaks a tie of started by descending id, so the whole list is the exact reverse of ascending (started, id); the stories fix that ties go by id and leave the direction open.
- Pruning is split: the store answers which runs are past keeping and deletes a record; the run core removes the folder first, so a failure between the two leaves a record whose files are gone, a state the stories already show, never a folder no record names.
- `Delete` removes running runs' records too: the store does not wait for a process, and `D07-runs` ends every running run before calling it.
- A zero-length database file counts as absent; created directories get mode `0700`.

## Consumer tasks

`cli.Run` opens the catalog with `store.Open(ctx, store.Config{Source: src, Now: p.Now, Rand: p.Rand})`, `src` being `p.Database` or, when that is empty, `state/scripts.db` under `p.Dir`; on any error while `ctx` is not done it writes `D03-serve`'s diagnostic with `err.Error()` as the reason; otherwise it hands the `*store.Store` to the run core and the handler, and calls `Close` after the drain.

The tools (`D11-tools`), `u` being the `identity.Caller` of the call: `list` is `s.List(ctx, u.UserID)`, each `Script`'s `Last` giving `last_run`; `show` is `s.Find(ctx, u.UserID, name)`; `create` checks `store.ValidName(name)`, then `s.Taken(ctx, name)`, then the repository and ref, and calls `s.Create(ctx, store.Draft{Owner: u.UserID, Name: name, Repo: repo, Ref: ref})`, `store.ErrNameTaken` still answering `already exists` when a racing create won; `update` is `s.Find` then `s.SetRef(ctx, sc.ID, ref)`, its `changed` deciding the event; `delete` is `s.Find` then the run core's deletion, which ends with `s.Delete(ctx, sc.ID)`; `runs` is `s.Find` then `s.Runs(ctx, sc.ID)`; `result` and `cancel` are `s.FindRun(ctx, u.UserID, id)`, `cancel` then handing the run to the run core, whose `s.FinishRun` answering `store.ErrEnded` is the refusal `run '<id>' has already ended`. `store.ErrNotFound` is `no script named '<name>'` or `no run '<id>'`; an error matching no sentinel is `store.Unreachable`. A `Run`'s `Status` compared with `store.StatusExited` decides whether `exit_code` is present, and with `store.StatusFailed` whether `reason` is.

The run core (`D07-runs`): `id, _ := store.NewRunID(rand)`; after the process has started, `s.AddRun(ctx, store.Run{ID: id, Script: sc.ID, SHA: sha, Ref: ref, User: u.UserID, RequestID: u.RequestID, Trigger: store.TriggerManual, Status: store.StatusRunning, Started: started})`, or for a run that could not start the same with `Status: store.StatusFailed`, `Reason` its reason and `Finished` set, `SHA` empty when the ref did not resolve (`SHA: ""`, `Reason: store.ReasonCommitMissing`, say) and the resolved sha otherwise (`Reason: store.ReasonTooLarge`, say); when the process ends, `s.FinishRun(ctx, id, store.Ending{Status: store.StatusExited, ExitCode: code, Finished: now, StdoutBytes: n, StderrBytes: m, Truncated: cut})`; at start, `s.Running(ctx)` and a `FinishRun` with `store.StatusKilled` for each; after every end, `s.PastKeeping(ctx, now, days, count)`, each run's folder removed, then `s.DeleteRun(ctx, r.ID)`; to delete a script, `s.Runs(ctx, sc.ID)` to find what is running, the kills and `FinishRun`s, then the folder `state/runs/<script id>/` removed, then `s.Delete(ctx, sc.ID)`.

The pages (`D08-pages`, `D09-run-files`): the catalog is `s.List(ctx, u.UserID)`; a script page is `s.Find` and `s.Runs`, `len` of which is the runs kept; a run page and its files are `s.Find` then `s.FindRun`, the run's `Script` compared with the script's `ID`. Each answers `store.Unreachable` and a newline, as plain text with status `503`, for an error matching no sentinel.

A test opens a store with `store.Open(ctx, store.Config{Source: filepath.Join(t.TempDir(), "state", "scripts.db"), Now: clock, Rand: bytes.NewReader(known)})`, or with `Source` empty where nothing must survive; creates, finds, lists and deletes scripts; adds, finishes, lists and deletes runs; asks which are past keeping at a moment it chooses; closes and reopens to see the same records; and makes the database fail as sites' store tests do.
