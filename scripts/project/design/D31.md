# Decision 31 — nginx fragment: capture the edge-minted chain id on the gated locations, strip it on the ungated one

> **⛔ EXTERNAL ORDERING (operator-sequenced, not built by any scripts phase).**
> The header `X-Correlation-Id`, the strip-then-mint rule for ungated
> locations, and the id shape are **suite constants** owned by
> `docs/telemetry-protocol.md`, defined in `eventplane/correlation` and applied
> by appkit's middleware. scripts uses them by value. The fragment itself is
> inert configuration and can be shipped before the libraries land; its effect
> becomes observable when they do.

**Decision.** nginx is the sole trust boundary, so it is also where a
**client-supplied** correlation id must die. The dashboard's introspection
endpoints mint the chain id for every gated route and return it on the auth
subresponse; `scripts/etc/nginx.conf` captures it and forwards it, overwriting
anything the client sent. The one ungated location that proxies forwards an
explicitly empty header, so the service mints its own and a public caller can
never inject a chain id.

**Gated locations — capture and forward.** Each of the three locations that
runs an `auth_request` gains two lines beside the existing owner-header
plumbing (D4/D15/D16), through its own service-prefixed variable:

| location | gate | variable |
|---|---|---|
| `location /srv/scripts/` (bearer prefix, MCP) | `/_authn` | `$scripts_corr` |
| `location = /srv/scripts/` (session landing) | `/_session-authn` | `$scripts_session_corr` |
| `location /srv/scripts/static/` (session assets) | `/_session-authn` | `$scripts_static_corr` |

```
auth_request_set $scripts_corr $upstream_http_x_correlation_id;
proxy_set_header X-Correlation-Id $scripts_corr;
```

The identity-hygiene argument D16 already makes for the owner headers carries
over unchanged: nginx forwards no inbound client header unless explicitly set,
and the last `proxy_set_header` for a name wins, so one set from the
auth-subrequest variable **replaces** any client-smuggled `X-Correlation-Id`.
Three distinct names keep every variable in this fragment unique inside the one
apex `server` block every service fragment is included into, and keep it
unambiguous which tier set the value. If the subresponse carries no such header
the variable is empty and the service mints — degrading to the strip case, never
to a stale id.

The static-assets tier forwards no owner headers (unchanged) but **does**
forward the chain id: it is gated, the dashboard mints an id for it anyway, and
letting the service mint a second one would split one page view across two
chains.

**The ungated location — strip.** The unauthenticated PRM bootstrap
`= /srv/scripts/.well-known/oauth-protected-resource` has no auth subrequest and
therefore no minted id; it forwards an explicitly empty header so the service's
read-or-mint middleware mints:

```
proxy_set_header X-Correlation-Id "";
```

**`= /srv/scripts/feed` needs nothing** — it `return 404`s and proxies to
nothing. Direct loopback `/feed` consumers are inside the trust boundary and
carry their own id on their own request.

Nothing else in the fragment changes: every tier's gate, precedence, upstream,
owner-header plumbing and the `@scripts_authn_500` re-emit are untouched, and
the string `prompts` still does not occur anywhere in the file (D16).

**Rejected.**
- **Trusting a client-supplied `X-Correlation-Id` at the edge.** The entire
  point of the edge rule: outside the loopback trust boundary anyone could join,
  poison, or merge another chain by sending a header. Inside it the header is
  trusted; at nginx it is overwritten.
- **Omitting the header on the ungated PRM location instead of setting it
  empty.** nginx would forward nothing today, but the intent would be
  unrecorded and ungreppable, and a future change to header-forwarding
  behaviour would silently let a client value through.
- **One shared `$scripts_corr` across all three gated tiers.**
  `auth_request_set` is per-request and only the matched location sets it, so it
  would work — but D16 already pays the one-variable-per-concern cost so a
  fragment never leaves it ambiguous which tier a forwarded value came from.
- **Skipping the static-assets tier.** It is gated and the dashboard mints for
  it regardless; dropping the id there splits one human page view into two
  chains for no reason.
- **Substituting the header name or the port at install time.** The fragment is
  authored and shipped **verbatim** (D01/D04); every value in it is a literal.

**Verification.** This Decision is **structural**: it changes committed
configuration only and mints **no** requirement ids. Its text is pinned by the
deterministic content greps its plan phase carries (exact match counts against
`scripts/etc/nginx.conf`, a file outside `project/`), and its behavioral
consequence — that a chain id reaching the scripts binary was minted by the edge
or by the chassis and never by a client — is proven by the chassis's own
middleware coverage in appkit and by D29's storage claims over the id the
context carries.
