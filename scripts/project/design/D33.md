# Decision 33 — Env-channel conformance: the run TTL surfaces in the manifest

**Problem.** `SCRIPTS_RUN_TTL` (each run's wall-clock bound, the runaway
backstop, default `30m`, read via `config.EnvOrDuration` at
`cmd/scripts/main.go`) is an operator-facing tuning knob that sits outside
every configuration channel (root `project/design/D21.md`): its default exists
only in code, so no production channel states or sets it, while the retention
knobs in the same `Spec` are already manifest-surfaced.

**Decision.**

1. **The run TTL is a channel-1 manifest knob.** `Spec.ManifestExtras` gains,
   after the existing retention pair:

   ```go
   {Key: "SCRIPTS_RUN_TTL", Value: "30m"},
   ```

   and the committed `scripts/etc/manifest.env` gains the same line. The read
   is unchanged; in production the launcher exports every manifest key, so the
   manifest line is what the process receives, and the code default becomes
   dev fallback that must agree with the manifest's stated value. The existing
   drift proof (R-8IAN-FB87, adopted in D10) pins the byte agreement
   automatically.

2. **Channel classifications recorded**, so no value is channel-less (root
   `project/design/D21.md`): scripts holds no customer data (its app-config
   parameter is deliberately `{}`); `DROPBOX_BASE_URL` and the per-upstream
   `SCRIPTS_<SRC>_FEED_URL`/`_FROM` consumer overrides are dev-only overrides
   with registry-derived production defaults (channel 4), as are the standard
   appkit `<APP>_*` knobs.

3. **Adoption of the box-path-literal guard.** This Decision adopts the root
   env contract's `[proof: per-service]` id **R-VKB6-SHHV** (root
   `project/design/D11.md`): a source-scan test in `cmd/scripts/main_test.go`
   walks scripts' non-test `.go` files and fails on any `"/opt` string
   literal — scripts is clean today, and the guard keeps it that way.

4. **The run TTL is bounded per the run-lifetime contract.** This Decision
   adopts `root project/design/D26.md`: `SCRIPTS_RUN_TTL` is validated at the
   composition root against the contract's hard **6h** maximum (a named
   constant), and a configured value over 6h — or zero/negative — refuses to
   boot: `serve` exits nonzero with an error naming `SCRIPTS_RUN_TTL`, the
   configured value, and the maximum. The run-token lifetime derives from
   this bounded value (D36); there is no other cap anywhere.

**Rejected.**
- *Leave the run TTL code-default-only.* Same class as the retention knobs the
  manifest already carries; one class, one channel. Rejected.
- *Promote the consumer feed overrides too.* Their production values are
  registry-composed loopback URLs — derived, not tuning; a manifest line would
  restate what the registry owns. Rejected — channel 4.

**Verification.**
- R-HDCE-C6WU — with no environment set, the resolved `SCRIPTS_RUN_TTL`
  equals the value stated in the committed `scripts/etc/manifest.env` (parse
  the committed file, compare against the code's resolved default) — an edit
  to either side alone fails. Substrate: unit test in
  `cmd/scripts/main_test.go` reading the committed manifest.
- Adopts **R-VKB6-SHHV** (root `project/design/D11.md`, `[proof: per-service]`)
  — no `"/opt` string literal in scripts' non-test Go source. Substrate: the
  source-scan test in `cmd/scripts/main_test.go`.
- Adopts **R-34EZ-J9BF** (root `project/design/D26.md`,
  `[proof: per-service]`) — with `SCRIPTS_RUN_TTL=7h`, `serve` fails at
  startup: exits nonzero, error output names `SCRIPTS_RUN_TTL` and the `6h`
  maximum, no server starts; with `SCRIPTS_RUN_TTL=6h` it boots. Substrate:
  hermetic test driving the serve path with an injected environment.
