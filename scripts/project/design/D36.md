# Decision 36 — The version-plane client: `internal/repos` behind a domain seam, injected at the composition root

> **Suite adoption (operator-sequenced).** The verb surface this client speaks
> to — repository create/rename/delete/archive, commit, ref resolution, tree
> reads, and run-token minting — belongs to **repos** and is specified by
> `root project/design/D24.md` and repos' own spec. **The exact loopback route
> shapes are repos' spec's to own**; this Decision fixes only scripts' side:
> the seam, what scripts sends, what it consumes, and how failures become
> domain errors. Until repos ships those routes, this Decision's phase builds
> against its recording test substrate and the wire agreement is exercised when
> the suite runs (`bin/start`), not in this tree.

**Problem.** D35 makes the repository the definition, so every write verb
(`create`, `update`, `import`, `delete`, the rename inside `update`) and every
run spawn now needs to talk to repos. Left unstructured that becomes HTTP
scattered through `internal/script` — the exact drift `suite.mcp` exists to
prevent on the Python side. scripts needs one client, one seam, one error
mapping.

**Decision.**

1. **A domain-facing interface, a loopback implementation.** `internal/script`
   declares the seam it needs and never imports `net/http` for it:

   ```go
   // internal/script/version.go
   type VersionPlane interface {
       Create(ctx context.Context, key, clientID string) error
       Commit(ctx context.Context, key string, files map[string]string, message, clientID string) (sha string, err error)
       Head(ctx context.Context, key, branch string) (sha string, err error)
       ReadFile(ctx context.Context, key, ref, path string) ([]byte, error)
       Rename(ctx context.Context, oldKey, newKey, clientID string) error
       Delete(ctx context.Context, key, clientID string) error
       RunToken(ctx context.Context, key string) (token, cloneURL string, err error)
   }
   ```

   `internal/repos.Client` is the only implementation: `repos.New(base string,
   hc *http.Client) *Client`. `Service.Plane VersionPlane` is field-injected at
   the composition root exactly as `Service.Fetcher` already is, so every
   domain test drives a fake and the wire shape is tested once, in
   `internal/repos`.

2. **The base is resolved by name.** `cmd/scripts/main.go` builds the client
   from `registry.BaseURL("repos")` — `registry` stays a composition-root-only
   import (D10) and **no `127.0.0.1:30xx` literal** enters `internal/repos`.
   There is no env override: the base names a fixed registry port on this box,
   and a knob nobody can meaningfully set is drift surface (D25's rejection,
   unchanged).

3. **Attribution rides on `X-Client-Id`.** Every mutating call carries
   `X-Client-Id: scripts:<script_id>` — the suite's `svc:<id>` machine-identity
   convention `suite.py` already uses (D22) — so repos attributes the commit to
   the acting script rather than to a nameless service. `Commit` additionally
   carries the caller-supplied message; the owner's identity is **not** sent as
   an owner header, because repos custody is service-keyed: scripts owns the
   `scripts/` kind and vouches for the write.

4. **`Commit` is a whole-file put of the named paths.** `files` maps
   tree-relative path → content; repos writes exactly those paths onto `main`
   and returns the resulting commit sha. `create`/`update` send one entry
   (`main.py`); `import` sends one entry per imported file (D37). Deleting a
   path is out of scope for this client — a file is removed by a git push, the
   plane's own channel.

5. **Failures map onto scripts' existing sentinels.** The client returns
   domain errors, never HTTP details, so `internal/mcp`'s error taxonomy (D19,
   D20) needs no new codes:

   | condition | error |
   |---|---|
   | transport failure (refused, timeout, torn body) | `ErrSourceUnavailable` |
   | 404 | `ErrNotFound` |
   | 409 | `ErrConflict` *(new sentinel, see below)* |
   | 400 / 422 | `ErrValidation` |
   | any other non-2xx | a plain error → `internal` |

   `ErrConflict = errors.New("script: conflict")` joins the sentinel set in
   `internal/script/model.go` and maps to the closed-vocabulary code `conflict`
   in `structuredError` (D19's mapping table gains one row; the vocabulary
   itself is unchanged — `conflict` was already in it, previously unreachable).

6. **No retries, one timeout.** A 30-second per-request timeout on the shared
   `http.Client`; a caller that wants retry writes it. This mirrors `suite.py`'s
   posture (D21 §8) so the two clients behave alike under a stalled peer.

**Rejected.**
- **Calling repos through MCP (`POST /mcp` `tools/call`) from Go.** The MCP
  surface is the *agent* door; a service-to-service call over loopback is
  ordinary HTTP, and wrapping it in JSON-RPC would add an envelope, a text/
  structured result split, and a second error taxonomy for no gain. (Scripts'
  Python runs *do* use `suite.mcp` for repos verbs like `merge` — that is the
  authored-workflow path, D38, and it is deliberately the same door every other
  service's tools use.)
- **Pinning repos' route paths in this design.** They are repos' to own; a copy
  here would be a second statement of someone else's contract, stale the first
  time it moves — the citation-not-restatement rule (`$ikispec`).
- **A generic "content-plane holder" client instead of a version client.**
  Reading `main.py` at `main` is a content read, but creating repositories,
  committing, renaming, and minting run tokens are not; one seam for the whole
  relationship beats a content client plus four one-off calls.
- **Injecting a per-verb client into each service method.** Field injection on
  `Service` matches `Fetcher`'s established shape and keeps every existing
  signature; a parameter on every write verb would churn the whole domain API
  to express one dependency.
- **Adding new error codes for plane failures.** The closed vocabulary
  (`validation | not_found | conflict | too_large | source_unavailable |
  internal`) already spans them; inventing `repo_unavailable` would break the
  closed-vocabulary contract for one caller's convenience.

**Verification** (real substrate: `internal/repos` tests drive the real
`Client` against a **real local HTTP server** — `net/http/httptest` on loopback
playing repos — that records method, path, headers, and body and returns canned
responses and statuses. The agreement between those canned shapes and repos'
actual routes is **not** proven in this tree: scripts declares no live layer
(D34), and the plane's door is repos' own proof obligation under
`root project/design/D24.md`; it is exercised end-to-end when the suite runs.)

- R-25E7-7ZFH — `Commit(ctx, "scripts/nightly", {"main.py": src}, msg,
  "scripts:S1")` issues **exactly one** request whose recorded body carries the
  key, the `main.py` entry with `src` **byte-identical**, and the message, whose
  recorded headers carry `X-Client-Id` exactly `scripts:S1`, and which returns
  the server's sha **verbatim** as `sha`. A client that drops the attribution
  header or re-encodes the content fails it.
- R-27TZ-ZIWV — `Head(ctx, "scripts/nightly", "main")` returns the sha the
  server reported, and `ReadFile(ctx, key, sha, "main.py")` returns the served
  bytes byte-identical (including a body containing NUL and non-UTF-8 bytes —
  the read is not text-massaged); `RunToken(ctx, key)` returns the server's
  token and clone URL verbatim and issues exactly one request.
- R-291W-DANK — status mapping discriminates: a 404 yields `ErrNotFound`, a 409
  yields `ErrConflict`, a 400 yields `ErrValidation`, a 500 yields an error that
  is **none** of those sentinels, and a base pointing at a **closed loopback
  port** yields `ErrSourceUnavailable` — proving transport failure is
  distinguishable from absence and from a bug.
- R-2A9S-R2E9 — the composition root builds the client from
  `registry.BaseURL("repos")`: the constructed base equals that value, a
  repo-wide grep shows **no** `127.0.0.1:30` literal anywhere under
  `internal/repos`, and `Service.Plane` is non-nil on the assembled service.
