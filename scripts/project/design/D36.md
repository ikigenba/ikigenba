# Decision 36 — The version-plane client: `internal/repos` behind a domain seam, injected at the composition root

> **Suite adoption (operator-sequenced).** The surface this client speaks to
> belongs to **repos** under `root project/design/D24.md`: domain verbs
> (create/rename/archive) live only on repos' MCP door, and bytes move over
> repos' loopback plumbing routes. The request shapes this Decision pins are
> **scripts' own emission contract** — what this client sends — sourced from
> repos' shipped door at seal time. The one repos-side addition scripts relies
> on, the optional `ttl` field on run-token minting, is repos' own queued work
> (operator-sequenced: run repos' loop first); until it ships, repos ignores
> the unknown field and mints with its env default, so nothing here hard-fails.

**Problem.** D35 makes the repository the definition, so every write verb
(`create`, `update`, `import`, `delete`, the rename inside `update`) and every
run spawn now needs to talk to repos. Left unstructured that becomes HTTP
scattered through `internal/script` — the exact drift `suite.mcp` exists to
prevent on the Python side. scripts needs one client, one seam, one error
mapping — and, after the first build of this Decision shipped a client speaking
routes repos never served, the seam's **exact wire shapes pinned here**, so a
wrong-surface client fails an in-tree test instead of a live suite.

**Decision.**

1. **A domain-facing interface, a loopback implementation.** `internal/script`
   declares the seam it needs and never imports `net/http` for it:

   ```go
   // internal/script/version.go
   // Owner is the identity a domain verb is scoped to — the same owner_id /
   // owner_email the scripts row already stores.
   type Owner struct {
       ID    string
       Email string
   }

   type VersionPlane interface {
       Create(ctx context.Context, nameKey string, owner Owner, clientID string) error
       Commit(ctx context.Context, nameKey string, files map[string]string, message, clientID string) (sha string, err error)
       Head(ctx context.Context, nameKey, ref string) (sha string, err error)
       ReadFile(ctx context.Context, nameKey, ref, path string) ([]byte, error)
       Rename(ctx context.Context, oldNameKey, newNameKey string, owner Owner, clientID string) error
       Delete(ctx context.Context, nameKey string, owner Owner, clientID string) error
       RunToken(ctx context.Context, nameKey string, ttl time.Duration) (token, cloneURL string, err error)
   }
   ```

   `internal/repos.Client` is the only implementation: `repos.New(base string,
   hc *http.Client) *Client`. `Service.Plane VersionPlane` is field-injected at
   the composition root exactly as `Service.Fetcher` already is, so every
   domain test drives a fake and the wire shape is tested once, in
   `internal/repos`.

   **The kind is baked in.** Methods take the bare **name key**; the `scripts`
   kind is a package constant in the client's request construction. Nothing in
   scripts can address `sites/…` or `code/…` repositories — the scope boundary
   is structural, not a review habit. (The old `RepoKey` composed-key helper
   goes with this: callers pass `sc.NameKey`, never a `scripts/…` composite.)

2. **Two wire families, matching the two things the plane offers.**

   **Domain verbs speak MCP.** `Create`, `Rename`, and `Delete` (repos-side
   archive) each issue exactly one `POST {base}/mcp` carrying a JSON-RPC 2.0
   `tools/call` envelope:

   ```json
   {"jsonrpc":"2.0","id":"create","method":"tools/call",
    "params":{"name":"create",
              "arguments":{"kind":"scripts","name":"<name key>"}}}
   ```

   (`rename` adds `"to":"<new name key>"`; `delete` is the tool name for
   archive.) These requests carry three identity headers — `X-Owner-Id` and
   `X-Owner-Email` (the owner the scripts row stores; repos owner-scopes every
   verb on `X-Owner-Id`), and `X-Client-Id: scripts:<script_id>` (attribution).
   scripts is inside the trust boundary and asserts the identity itself — the
   same contract nginx fulfills for outside callers, and the same shape sites'
   client already speaks.

   **Bytes speak the plumbing routes.** Everything else is plain loopback HTTP
   against repos' content-plane routes, `kind=scripts` in the query or body:

   | seam method | request |
   |---|---|
   | `Commit` | `POST {base}/commit` — JSON body `{"kind":"scripts","name":"<name key>","message":…,"actor":"scripts:<script_id>","changes":[{"op":"put","path":"main.py","content_b64":…}, …]}` → `{"rev":"<sha>"}` |
   | `Head` | `GET {base}/list?kind=scripts&name=<name key>&ref=<ref>` → the top-level `"rev"`; an empty `rev` (a repository with no commits) maps to `ErrNotFound` |
   | `ReadFile` | `GET {base}/content?kind=scripts&name=<name key>&ref=<ref>&path=<path>` → the raw body bytes |
   | `RunToken` | `POST {base}/run-token` — JSON body `{"kind":"scripts","name":"<name key>","ttl":"<Go duration>"}` → `{"token":…,"expires_at":…,"clone_url":…}` |

   Plumbing requests carry **no owner headers and no `X-Forwarded-Proto`** —
   the marker repos' loopback guard keys on to refuse front-door traffic.
   `RunToken`'s `ttl` is the run's TTL plus a five-minute margin, passed by the
   runner, so a token does not outlive its run by hours; repos owns the ceiling
   and may grant less.

3. **Attribution rides `X-Client-Id`; scoping rides `X-Owner-Id`.** Every
   mutating call names the acting script (`scripts:<script_id>`) — on the MCP
   verbs as the `X-Client-Id` header, on `Commit` as the body's `actor`, which
   repos writes as the commit author. The owner's identity **is** sent on the
   MCP verbs, because repos custody is owner-scoped there: scripts vouches for
   the owner its own row already binds the script to.

4. **`Commit` is a whole-file put of the named paths.** `files` maps
   tree-relative path → content; the client base64-encodes each into one
   `changes` batch, repos writes exactly those paths onto `main` in **one**
   commit, and the returned `rev` is the new head sha. `create`/`update` send
   one entry (`main.py`); `import` sends one entry per imported file (D37).
   Deleting a path is out of scope for this client — a file is removed by a git
   push, the plane's own channel.

5. **Failures map onto scripts' existing sentinels.** The client returns
   domain errors, never HTTP details, so `internal/mcp`'s error taxonomy (D19,
   D20) needs no new codes. Plumbing routes map from the HTTP status; the MCP
   door returns 200 with an error envelope, so the client maps from
   `result.isError` + `result.structuredContent.code`:

   | condition | error |
   |---|---|
   | transport failure (refused, timeout, torn body) | `ErrSourceUnavailable` |
   | plumbing 404 / envelope code `not_found` | `ErrNotFound` |
   | plumbing 409 / envelope code `conflict` | `ErrConflict` |
   | plumbing 400 or 422 / envelope code `validation` | `ErrValidation` |
   | any other non-2xx status or envelope code | a plain error → `internal` |

   `ErrConflict = errors.New("script: conflict")` stays in the sentinel set in
   `internal/script/model.go`, mapped to the closed-vocabulary code `conflict`
   in `structuredError` (D19).

6. **No retries, one timeout.** A 30-second per-request timeout on the shared
   `http.Client`; a caller that wants retry writes it. This mirrors `suite.py`'s
   posture (D21 §8) so the two clients behave alike under a stalled peer.

**Rejected.**
- **A REST twin for the domain verbs (`POST /repositories/create` and kin).**
  The first build of this Decision invented exactly that surface, and it does
  not exist: repos serves domain verbs only on its MCP door (`root
  project/design/D24.md`'s single-verb-surface rule), and every create in the
  suite 404ed until this rewrite. The JSON-RPC envelope is a real cost, but the
  alternative is a surface repos deliberately refuses to ship — and sites'
  working client is the precedent that the envelope cost is small: one encode,
  one decode, one error field.
- **Leaving the wire shapes out of this design ("they are repos' to own").**
  That was the prior text, and it is what let an invented surface pass a green
  suite: with no shape pinned in-tree, the recording test peer mirrored the
  client's own wrong paths and agreed with them. What this client **sends** is
  scripts' own observable behavior; pinning it here is stating our contract,
  not restating repos'. A future repos surface change is an operator-sequenced
  cross-tree move that revisits this Decision — exactly as this rewrite is.
- **A generic "content-plane holder" client instead of a version client.**
  Reading `main.py` at `main` is a content read, but creating repositories,
  committing, renaming, and minting run tokens are not; one seam for the whole
  relationship beats a content client plus four one-off calls.
- **Injecting a per-verb client into each service method.** Field injection on
  `Service` matches `Fetcher`'s established shape and keeps every existing
  signature; a parameter on every write verb would churn the whole domain API
  to express one dependency.
- **Adding new error codes for plane failures.** The closed vocabulary
  (`validation | not_found | conflict | too_large | source_unavailable |
  internal`) already spans them; inventing `repo_unavailable` would break the
  closed-vocabulary contract for one caller's convenience.

**Verification** (real substrate: `internal/repos` tests drive the real
`Client` against a **real local HTTP server** — `net/http/httptest` on loopback
playing repos — that records method, path, query, headers, and body and returns
canned responses. The recorded **paths and envelopes are asserted against the
literal shapes pinned above**, so a client speaking any other surface —
`/repositories/*` included — fails mechanically in this tree.)

- R-IKGJ-ND9W — `Create`, `Rename`, and `Delete` each issue **exactly one**
  `POST` whose recorded path is exactly `/mcp`, whose body is a JSON-RPC 2.0
  `tools/call` naming the tool `create`/`rename`/`delete` with arguments
  carrying `"kind":"scripts"` and the bare name key (and `to` on rename), and
  whose recorded headers carry `X-Owner-Id`, `X-Owner-Email`, and
  `X-Client-Id: scripts:<id>` exactly as supplied. A client issuing any other
  path (`/repositories/create`), omitting the owner headers, or sending a
  composite `scripts/<key>` name fails it.
- R-ILOG-150L — against a 200 response whose envelope carries
  `result.isError: true` and `structuredContent.code` of `conflict`,
  `not_found`, and `validation` in turn, the MCP verbs return `ErrConflict`,
  `ErrNotFound`, and `ErrValidation` respectively (each carrying the envelope's
  message); a non-error envelope returns nil; an unrecognized code returns an
  error that is none of the sentinels.
- R-IO48-SOHZ — `Commit(ctx, "nightly", {"main.py": src}, msg, "scripts:S1")`
  issues **exactly one** `POST /commit` whose recorded body carries
  `"kind":"scripts"`, the name key, the message, `"actor":"scripts:S1"`, and
  one `changes` entry `{"op":"put","path":"main.py"}` whose `content_b64`
  decodes **byte-identical** to `src` (proven with a body containing NUL and
  non-UTF-8 bytes), and returns the server's `rev` verbatim as `sha`.
- R-IPC5-6G8O — `ReadFile` issues `GET /content` with query `kind=scripts`,
  the name key, `ref`, and `path`, returning the served bytes byte-identical;
  `Head` issues `GET /list` with `kind=scripts` and `ref`, returns the
  response's top-level `rev`, and maps an **empty** `rev` to `ErrNotFound`; and
  the plumbing status mapping discriminates — 404 → `ErrNotFound`, 409 →
  `ErrConflict`, 400 → `ErrValidation`, 500 → an error that is none of those,
  and a closed loopback port → `ErrSourceUnavailable`.
- R-IQK1-K7ZD — `RunToken(ctx, "nightly", 35*time.Minute)` issues **exactly
  one** `POST /run-token` whose body carries `"kind":"scripts"`, the name key,
  and `"ttl":"35m0s"`, and returns the server's `token` and `clone_url`
  verbatim; and **no** plumbing request across `Commit`, `Head`, `ReadFile`,
  and `RunToken` carries an `X-Owner-Id`, `X-Owner-Email`, or
  `X-Forwarded-Proto` header.
- R-2A9S-R2E9 — the composition root builds the client from
  `registry.BaseURL("repos")`: the constructed base equals that value, a
  repo-wide grep shows **no** `127.0.0.1:30` literal anywhere under
  `internal/repos`, and `Service.Plane` is non-nil on the assembled service.
