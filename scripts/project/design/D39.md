# Decision 39 — `repos` becomes a trigger source: scripts is the suite's CI runner

**Problem.** A pinned clone with a push token (D38) makes a script capable of
being a workflow, but nothing can *start* one when code changes. The version
plane publishes a `push` family on every ref update
(`root project/design/D24.md`) precisely so checks can fire; without a
subscription, scripts is a workflow runner nobody can trigger, and "CI" would
have to be built into repos — which that contract explicitly refuses.

**Decision.** `repos` joins the consumed sources, by the ordinary D17
mechanism and with no new machinery.

1. **The family table gains one entry** (`internal/script/trigger.go`):

   ```go
   var knownFamilies = map[string][]string{
       "cron":    {"tick"},
       "crm":     {"contact.created", "contact.updated", "contact.tagged", "contact.untagged"},
       "ledger":  {"recorded"},
       "dropbox": {"create", "modify", "delete"},
       "prompts": {"run.succeeded", "run.failed"},
       "repos":   {"push"},
       // still deliberately no "scripts" entry: self-chaining remains out (D11, D17).
   }
   ```

   Everything else in D17 is unchanged: the source segment stays literal, the
   known set is now **six**, and unknown-source rejection names all six. A push
   event's subject is the plane's `/<kind>/<name>`, so canonical filters read
   `repos:push/sites/blog`, `repos:push/scripts/nightly-export`, or
   `repos:push/code/**` — ordinary globs over the shared matcher, needing no
   scripts-side parsing of the subject.

2. **A sixth consumer entry.** `cmd/scripts/main.go` adds
   `scriptsConsumerEntry("repos")` to `Spec.Consumers`; the subscription filter
   stays the honest catch-all `"**"` and `consume.Handler` is untouched — the
   fan-out is per-source and already generic. The upstream feed URL default is
   chassis/registry-resolved like the other five (D10, D11).

3. **The workflow shape this enables is authored, not built.** A check script
   sets `repos:push/code/api`, reads `suite.event()` for the branch and sha,
   works in its own pinned clone (D38), and reports with
   `suite.mcp("repos", "status_set", …)`; a merge happens only if its author
   wrote `suite.mcp("repos", "merge", …)`. scripts adds no CI concepts — no
   pipeline, no job, no status model of its own — and `describe` teaches the
   pattern (D26).

**Rejected.**
- **Subscribing only to `repos:push` events whose subject starts with
  `/scripts/`.** It would make scripts able to react to its *own* definitions
  changing but not to anything else's — the opposite of a suite CI runner, and a
  filter the user can already write themselves.
- **A dedicated `on_push` trigger field beside the canonical filter.** A second
  trigger vocabulary for one source; D17's whole point is one string, one
  matcher.
- **Building status/pipeline concepts into scripts.** Statuses live in repos and
  are posted by ordinary tool calls; a scripts-side model would be a second,
  drifting copy of someone else's state.
- **Adding `scripts` as a self-chaining source while in here.** Unchanged
  rejection from D11/D17: a new upstream is its own behavior change.

**Verification** (real substrates: validation claims run the real
`eventplane/routing` matcher and the real `outbox.Registry.CouldMatch` over the
revised family table; the wiring claim reads the assembled `scriptsSpec()`).

- R-2TS6-VE9D — `repos` validates as an ordinary source:
  `repos:push/scripts/nightly-export` and `repos:push/**` are **accepted**,
  `repos:nosuchkind/**` is **rejected** with `ErrValidation`, and an unknown
  source (`github:push/**`) is rejected with an error naming all **six** known
  sources — `repos` included and `scripts` still absent.
- R-2V03-9602 — `scriptsSpec()` declares **six** consumer entries whose sources
  are exactly `cron`, `crm`, `ledger`, `dropbox`, `prompts`, `repos`, each with
  a single subscription whose `Filter` is exactly `"**"`; and
  `ScriptsForEvent(ctx, "repos", "repos:push/sites/blog")` over real SQLite
  returns the script holding `repos:push/sites/**` and **not** one holding
  `repos:push/scripts/**`.
