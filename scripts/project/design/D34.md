# Decision 34 — Testing-language conformance: adopt the suite contract and make `python3` a hard precondition

**Decision.** scripts adopts the suite testing-language contract
**`root project/design/D23.md`** by value: the four layer names
(hermetic / composed / live / manual), the rule that the default gate carries
only hermetic and composed tests, the single live mechanism, the ban on `t.Skip`
outside live-tagged files, and the requirement that the tree declare its testing
facts in `AGENTS.md`. The contract is cited, never restated — nothing here
redefines a layer or re-specifies the mechanism.

**scripts's declared facts.** These are the tree-specific values the contract
asks each adopter to state; they are what the `AGENTS.md` Tests section and the
design Conventions must say:

| fact | value |
|---|---|
| default-gate test command | `cd scripts && go test ./...` |
| layers present | **hermetic**, **composed** — scripts has **no live layer and no manual layer** |
| environmental preconditions beyond the Go toolchain | **`python3` on `PATH`** and **`git` on `PATH`** |
| GOWORK mode | workspace (the repo-root `go.work`); the production build forces `GOWORK=off` via `bin/ship scripts` |
| live invocation | none — the tree has no live layer, so it declares no `-tags live` command and no credentials |

scripts has no live layer by construction, and that is a property of the design
rather than an omission: the service's one external effect is spawning a local
`python3` process, which is a **local subprocess** and therefore hermetic under
the contract. Its upstream and downstream neighbours are reached only through the
event plane and loopback HTTP, both of which the existing tests drive against
real `httptest` servers on loopback. Nothing in scripts talks to a third-party
API or to the live box, so there is nothing for a live test to falsify. The
**composed** layer is `cmd/scripts`'s boot and shipped-tree wiring; everything
else in the gate — including the `internal/runner` spawn tests and the `suite.py`
probe harness — is **hermetic**.

**`python3` becomes a declared precondition and a hard failure.** The tree's only
`t.Skip` is `requirePython` in `internal/runner/runner_test.go`, which skips when
`exec.LookPath("python3")` fails. Under the contract a tool the tests need is an
**environmental precondition**: declared in `AGENTS.md` and a hard failure when
absent, because a skipped requirement test launders a gap into green — and the
gap here is total. `python3` is not incidental to scripts; it is the runtime the
service *is*. Every spawn, lifecycle, exit-code, output-capture, and `suite.py`
claim in the tree runs through it, so on a machine without `python3` the skip
turns the service's entire core into a silent pass. `requirePython` therefore
becomes a `t.Fatalf` naming `python3` and pointing at the declaration.

After this change `t.Skip` does not appear anywhere in the tree.

**`git` is the same kind of precondition** (D38). Since a run is a real clone,
the `git` binary is as load-bearing as `python3`: the pin, the checkout, the
credential helper, and the run's own push are all proven by driving real `git`
against a real bare repository on disk. A helper that skipped when
`exec.LookPath("git")` failed would launder the entire run-materialization
surface into green, so it is a `t.Fatalf` naming `git` and pointing at this
declaration, exactly like `requirePython`. Local `git` against a `file://`
remote is a **local subprocess** and therefore hermetic under the contract —
it adds no live layer.

**Rejected.**

- *Keeping the skip so the suite "still runs" on a machine without `python3`.*
  What it runs there is not scripts: the runner, the lifecycle, and the entire
  `suite.py` surface vanish, and the gate reports green over the hole. A tree
  whose product is executing Python cannot treat the Python toolchain as
  optional.
- *Detecting `python3` once in a `TestMain` and failing there instead of per
  test.* It reads tidier but reports worse — a single opaque failure at package
  init instead of a named failure on each test that actually needed the tool,
  and it would not survive a future package that needs the precondition without
  a `TestMain`. The per-helper `t.Fatalf` keeps the message attached to the
  claim.
- *Reclassifying the `python3`-dependent tests to the manual layer.* The manual
  layer is for checks automation cannot reach even with credentials. These are
  fully automated and run in the default gate on every developer machine and
  every build host; moving them out would delete real coverage to accommodate a
  machine that cannot run the service anyway.
- *Declaring a live layer "for symmetry" and tagging the `suite.py` probes.* They
  drive local subprocesses and loopback `httptest` servers — hermetic by the
  contract's definition. Tagging them would move real coverage out of the gate
  and buy nothing.
- *Restating D23's layer definitions in this design.* A local copy of a suite
  contract is drift by construction; the citation is the whole mechanism.
- *Minting fresh scripts ids for the two contract behaviors.* The contract marks
  both `[proof: per-service]`; citing them is adoption, and re-minting would
  create a second handle for one behavior.
