# Decision 45 — The subject page (`GET /subject/{type}/{slug}`)

> **Re-rooted by D76/D78.** The route is now `GET /{tier}/{scope}/subject/{type}/{slug}` under both tiers; resolution and link projection are scope-bounded (D74), absolute links compose with the tier+scope (D76), and the public tier serves it only for a public scope (D76 404 wall). Behaviors below otherwise stand.

**Decision.** Following any link lands here. The route (D42) rejoins `{type}/{slug}` into the public path (D11) and calls the injected `PageFinder.PageByPath(ctx, path)`, which resolves the subject **alias-aware** (D29 `Resolver.ResolveByPath` — a folded-away path forwards to the survivor) and projects its links read-time (D12 `Service.PageWithLinks`). The page renders the compiled prose with a footer of **outbound** + **inbound** subject links. The web adds no domain logic — it is an HTML rendering of D12/D29 data.

## The `PageFinder` seam returns structured links, not a markdown footer

The MCP page surface returns `{Path, Title, Body}` where `Body` already has D12's **markdown** footer baked in (`RenderFooter`). The web needs the prose and the link sets **separately**, to render HTML `<a>` links. So the web seam returns a structured view; the `cmd/wiki/main.go` adapter builds it from `PageWithLinks` **without** calling `RenderFooter`:

```go
// SubjectView is the web projection of a subject's page (D12 LinkedPage).
type SubjectView struct {
    Title    string // page title (the subject's display name)
    Body     string // the compiled prose with D58 inline first-occurrence links (own subject excluded); no footer (RenderFooter is MCP/markdown)
    Outbound []Ref  // D12 Mentions:    subjects this page's prose names (by name/alias)
    Inbound  []Ref  // D12 MentionedBy: subjects whose page names this one
}
// PageFinder.PageByPath resolves path alias-aware (D29) and projects links (D12).
// A genuinely-unknown path (D29 ErrSubjectNotFound) maps to web.ErrNotFound.
var ErrNotFound = errors.New("web: subject not found")
```

Adapter: `Resolver.ResolveByPath(path)` → on hit, `svc.PageWithLinks(subject.ID)` → `SubjectView{Title: page.Title, Body: svc.LinkifyMentions(ctx, page.Body, webBase, subject.ID), Outbound: refs(page.Mentions), Inbound: refs(page.MentionedBy)}`, mapping each `wiki.Ref{Path,Name}` → web `Ref{Href: webBase + Path, Name}` (the **absolute** front-door URL, D59). The `Body` is the stored prose passed through the D58 linkifier — the first occurrence of each *other* mentioned subject wrapped as an inline front-door link, the page's **own** subject excluded (`excludeID = subject.ID`, so a page never inline-links to itself, mirroring D12 self-exclusion). On `ErrSubjectNotFound` → `ErrNotFound`. Because the served fields derive from the **resolved** subject, an alias-forwarded path renders **identically** to the survivor's own path (D29 `R-AL5R-PL1P`).

## Layout (`subject.tmpl`)

- **The header question form** replaces the old "Ask another question" link
  (which is gone entirely — no such anchor renders anywhere on the page). On
  every subject page, found and not-found, the D80 header carries the tier's
  question form (D79 labels and busy behavior: **Ask** private / **Search**
  public) immediately **after the scope-selector form**, as the last element of
  the right-aligned header group: a text input named `q` plus a submit button,
  the form's action resolving to the base `.` (= the D43 home), so submitting
  asks (or searches) directly from the subject page and lands on the answer
  page. Compact styling is D80's (`--control-h-sm`, fixed width, right-aligned
  group).
- **Full-width content.** Title, prose, and the links section all span the
  full D80 boxed column — no narrower content cap — so every section shares
  the same page width as the header and footer.
- **Title** (H1, display type) — the subject's name.
- **Compiled prose body** — `SubjectView.Body` (already D58-linkified: first-occurrence inline front-door links, own subject excluded) rendered as **sanitized markdown HTML** via the D48 `md` template func (`{{ md .Subject.Body }}`), so the compiled page reads like an article (headings, emphasis, lists, GFM tables, and the inline subject links — both the injected first-occurrence links and any the prose itself contains) rather than showing literal `##`/`**`. goldmark renders the injected `[…](https://…)` as `<a>` and bluemonday passes the absolute https href. The injection guard is D48's sanitizer — raw HTML is stripped and `javascript:` link schemes neutralized — not template escaping. The not-found body ("No page exists for this subject.") is fixed plain text and `md` round-trips it to a paragraph.
- **Links section** — `RenderFooter`'s HTML analogue, built from the structured
  Refs, styled as a **quiet two-column block** below the prose (per the
  approved mockup):
  - Both sections render inside **one wrapper element** (`class="links"`):
    **Mentions** (outbound) before **Mentioned by** (inbound); each is a nav
    with a heading and a list of `<a href="{{.Href}}">{{.Name}}</a>` whose
    `Href` is the **absolute** front-door URL (`webBase + Path`, D59). A
    subject named in the prose thus appears both inline (first mention) and in
    the outbound list, at the identical absolute URL.
  - **Presentation** (CSS in the D80 layout, tokens only): the wrapper sits
    under a top hairline with extra vertical separation from the prose
    (`margin-top: var(--space-8)` above its `--space-6` padding); the two navs
    sit **side by side** as equal grid columns divided by a **hairline
    vertical rule** (left border + padding on the second nav), stacking to one
    column with a horizontal rule below 640px; the `Mentions` / `Mentioned by`
    headings are small mono uppercase labels (`--text-label-size`) in
    `--color-text-muted` at **`font-weight: 700`** (the self-hosted IBM Plex
    Mono set ships 400/500 only — the browser synthesizes the bolder weight;
    no new font assets, D50 unchanged); the link lists are `--text-small-size`
    in `--color-text-muted`, darkening to `--color-text` on hover/focus.
  - A section is omitted when its slice is empty; the **whole wrapper** (and its rule) is omitted when both are empty — mirroring D12's footer discipline. De-duplicated and path-ordered by the adapter (D12).

## Not-found

A path resolving to neither a live subject nor an alias (D29 `ErrSubjectNotFound` → web `ErrNotFound`) renders a **styled Carbon 404 page** — same layout shell, the header question form and Home affordances intact — with HTTP status **404**, never a raw `http.Error` text or a 500. The human who followed a stale link gets an on-brand page back to home.

**Rejected.**
- **Reusing the MCP `{Path,Title,Body}` (markdown-footer) shape.** The web must render HTML links and place outbound/inbound as styled sections; a pre-baked markdown footer string can't be turned back into structured links without re-parsing. The seam returns structured Refs + prose. Rejected.
- **Emitting the body as plain HTML-escaped text** (the prior approach). Showed the compiled prose's literal `##`/`**`/`|` instead of formatting — the product now requires the page to read like an article. The injection concern it addressed is handled instead by D48's sanitizer (raw HTML stripped, `javascript:` neutralized), which is stronger than escaping and still emits formatted output. Rejected.
- **A bare `http.NotFound` (plain text) on a miss.** Breaks the on-brand human surface; a person following a dead link should get a styled page home, not `404 page not found`. Rejected.
- **Making the web seam alias-*unaware* (plain `GetByPath`).** Would 404 a folded-away path that D29 forwards for `page`/`claims`, making the web inconsistent with MCP. The seam uses `ResolveByPath`. Rejected.
