# Decision 78 — Both tiers serve ask: the public tier gets the full experience

**Decision.** The public tier serves the **same experience as the private
tier**: every scope home's question form runs **`ask`** — hybrid retrieval
(both lanes) plus the two synthesis calls — no matter the tier. The operator
explicitly accepts that an anonymous visitor to a public scope spends
inference (one query embedding plus up to two chat calls per question) with no
per-visitor guard; ask is the product, and a public wiki that can only grep
itself is not the product. This Decision owns the public tier's page states
and the both-tiers ask wiring.

## Public tier states (per public scope)

- **Public home** (`GET /public/{scope}/`, no `q`) — the D43 page shape on the
  public tier: the title, the header question form (Ask-labeled per D79,
  resolving against the tier+scope base), and the **Suggested pages** section —
  the scope's seven newest subjects (D81). The D80 shell frames it as
  everywhere.
- **Public ask result** (`GET /public/{scope}/?q=…`) — the **D44 ask page**,
  identical in shape to the private tier's: the handler calls
  `Asker.Ask(ctx, scope, owner, q)` and renders `answer.tmpl` — linkified,
  markdown-rendered answer prose, outbound mention footer, honest-empty as an
  ordinary page. Retrieval is the full D33 hybrid (keyword + meaning lane);
  the keyword-only public search page is retired.
- **Public subject page** (`GET /public/{scope}/subject/{type}/{slug}`) — the
  D45 rendering unchanged (prose through the D48 `md` renderer, D58 inline
  links, outbound/inbound footers), scoped and composed with public-tier
  links.

The private tier's states are the same D43/D44/D45 behaviors at
`/private/{scope}/`; the two tiers differ only in the D76 visibility wall
(which scopes each serves) and the D77 gating — never in capability.

## One wiring, both tiers

Both tiers' route registrations share the same handler wiring: `Asker`,
`Mentioner`, and `Linkifier` (D44) are injected once and reached from either
tier — the former public-only wiring that omitted `Asker` structurally is
gone. **`owner` is a pass-through, not a gate:** the handler forwards
`r.Header.Get("X-Owner-Email")` verbatim (D44); on the session-gated private
tier nginx supplies it, on the ungated public tier it is absent and `Ask`
receives the empty string. `owner` is call-recording scope only (D9/D44) — an
empty owner records an anonymous ask; it changes nothing about the answer.

**Rejected.**
- **Keyword-only public search, no public inference (the prior shape of this
  Decision)** — retired by operator direction: the operator accepts the
  anonymous-inference cost/abuse exposure to make public scopes fully useful.
- **Rate-limiting public ask** — still rejected, now from the other side:
  the suite has no per-anonymous-visitor identity to hang a limit on, an
  nginx per-IP limit is weak protection not worth the config surface, and the
  operator accepted the exposure plainly.
- **A sentinel owner label for anonymous asks** (e.g. `"anonymous"`) — a
  second vocabulary for "no owner" that every consumer must know; the absent
  header's natural empty string already is that value, and prompts' record
  stores it as-is.
- **Keeping a public FTS-results page beside public ask** — two result pages
  for one form is the drift D80's single-affordance rule exists to prevent;
  the keyword lane still serves everywhere as half of the D33 hybrid.

**Verification.** httptest against the web handler (stub seams; real temp
SQLite where the scope wall is the substrate; the public home's list content
is D81's R-HOPU-H1YI):

- R-4Q8B-N9SX — **Ask runs on both tiers.** `GET /public/{scope}/?q=…` (public
  scope) invokes `Ask` exactly once with that scope and the decoded question
  and renders the D44 answer page (stub `Asker`'s `Answer.Text` in the body);
  `GET /private/{scope}/?q=…` does the same — a public-tier `?q=` that renders
  a keyword-result list, or invokes `Ask` zero times, fails.
- R-4RG8-11JM — **Owner passes through, empty when anonymous.** A private-tier
  `?q=` request carrying `X-Owner-Email: a@b.c` reaches the recording `Asker`
  stub with `owner == "a@b.c"`; a public-tier `?q=` request with no such
  header reaches it with `owner == ""` — and the empty owner produces the
  ordinary 200 answer page, never an error or a redirect.
- R-HY3J-G43Z — The public subject page renders the compiled prose as
  sanitized markdown with the D58 inline links and both footers, every subject
  link composed on the public tier (`/public/{scope}/subject/…`); a
  private-scope subject requested on the public tier stays the D76 404.
