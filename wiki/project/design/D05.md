# Decision 5 — The LLM seam (`internal/llm`): the prompts completion-queue client

**Decision.** All chat inference goes through one seam, `internal/llm`, now a thin HTTP client for the prompts service's **completion queue** (D1; API footprint in research §12). The synchronous `/complete` call is gone from the vocabulary — every chat generation is a durable queue item that wiki *ensures* and later *collects*. The seam serves wiki's two consumption shapes, and **each shape owns its own queue partition**: the **live path** (`Do` — ensure + poll one item to terminal; used by ask, whose caller holds an open request) submits under consumer **`service:wiki.ask`**, and the **handoff verbs** (`Ensure`/`Inbox`/`Ack` — used by the ingest pipeline's split producer/applier, D4) submit and drain under consumer **`service:wiki`**. The partitions never mix: the applier's inbox drain (D4) sees only pipeline items, so its ack-and-discard rule can never delete an item a live `Do` is still polling — sharing one partition made the applier's 2 s tick a deterministic killer of every live ask slower than a tick (the 2026-08-11 local verification: `completion gone while polling`). An ask item orphaned by a crashed poll simply rests in the ask partition until prompts' 7-day TTL reaps it; nothing drains that partition, so it can block nothing. prompts now guarantees every `done` result is syntactically valid JSON, so `ExtractJSON` and the decoration-carving machinery retire; wiki keeps only **semantic** judgment — decoding `result` into its stage types and validating domain rules — and retries semantics by ensuring a **new** corrective item, never by re-asking the same one. No agentkit type appears anywhere in the package.

```go
package llm

// Consumer is the ingest pipeline's queue partition (the only one the
// applier's inbox drain touches). ConsumerAsk is the live path's partition:
// Do submits there, so no inbox drain can ack an item mid-poll.
const (
    Consumer    = "service:wiki"
    ConsumerAsk = "service:wiki.ask"
)

// Client speaks the prompts completion-queue verbs. Built once at the
// composition root from registry.BaseURL("prompts"); concurrency-safe; the
// shared http.Client carries no fixed timeout (every verb returns immediately
// server-side; call deadlines are the ctx's).
type Client struct { baseURL string; http *http.Client }
func New(baseURL string) *Client

// Config / CallSite / Attribution — unchanged vocabulary (D19 owns values).
type Config struct {
    Model       string   `json:"model"`
    Provider    string   `json:"provider,omitempty"`
    Temperature *float64 `json:"temperature,omitempty"`
    MaxTokens   int      `json:"max_tokens,omitempty"`
    Effort      string   `json:"effort,omitempty"`
    Thinking    *bool    `json:"thinking,omitempty"`
}
type CallSite struct { Stage, System string; Config Config; MaxParseRetries int }
type Attribution struct { Origin, GroupID string } // D62 attribution; GroupID = the chain id (D64/D65)

// Message is the stateless replay unit — wire keys exactly `role` and `text`.
type Message struct { Role, Text string }

// Request is one unit of queue work.
type Request struct {
    Key      string    // consumer-scoped idempotency key, attempt-suffixed by JSON/the applier: "<base>/a<attempt>"
    Context  []byte    // opaque envelope, echoed back verbatim (pipeline: the D4 apply envelope; ask: empty)
    Site     CallSite
    Attr     Attribution
    Attempt  int       // the consumer attempt number carried in the payload (matches the key suffix)
    Messages []Message // full history: first attempt [user]; corrective [user, assistant, user]
}

// Item is a queue item as wiki reads it.
type Item struct {
    ID, Key, Status string          // status: queued|running|done|failed
    Context         []byte          // verbatim echo
    Result          json.RawMessage // done only — guaranteed valid JSON by prompts
    Error           string          // failed only
    Usage           json.RawMessage // aggregate usage (D18 reads output tokens from it)
    CostUSD         float64
}

// ErrGone marks a Get on an id the queue no longer holds (acked or expired).
var ErrGone = errors.New("llm: completion gone")

func (c *Client) Ensure(ctx context.Context, r Request) (Item, error)      // POST /completions under Consumer (202 new / 200 existing)
func (c *Client) Get(ctx context.Context, id string) (Item, error)         // GET /completions/{id}; 404 → ErrGone
func (c *Client) Inbox(ctx context.Context) ([]Item, error)                // GET /completions?consumer=service:wiki
func (c *Client) Ack(ctx context.Context, id string) error                 // DELETE /completions/{id}; 404 is success

// Do is the live path: Ensure under ConsumerAsk (never Consumer — the
// applier's drain must not see live items), then poll Get on a fixed short
// interval (500 ms) until the item is terminal; ack it; return it. A failed
// item is (ackErr-tolerant) acked and returned as an error carrying the
// queue's error string. ErrGone mid-poll is a terminal failure whose error
// names the id that vanished (the id is captured before the failed Get — the
// message is diagnostic, not decorative). ctx cancellation aborts the poll
// with ctx.Err() (the item keeps executing server-side and rests in the ask
// partition until prompts' TTL reaps it; nothing drains that partition).
func (c *Client) Do(ctx context.Context, r Request) (Item, error)

// JSON runs one structured LIVE generation (ask's path) and returns a
// validated T: Do → decode Item.Result into T → validate. A decode/validate
// failure is a SEMANTIC failure: JSON ensures a new corrective item — key
// "<base>/a<n+1>", Attempt n+1, messages replaying the original user turn,
// the bad result as an assistant turn, and a corrective user turn — up to
// site.MaxParseRetries, then errors (never a silent zero T). Truncation
// (usage output at the site's MaxTokens ceiling, D18) returns ErrTruncated
// immediately with no corrective item. A queue-failed item or an Ensure 400
// errors immediately (fail loud; a config bug never retries).
func JSON[T any](ctx context.Context, c *Client, site CallSite, attr Attribution, baseKey, userText string, validate func(*T) error) (T, error)
```

- **`WithSystemComposer`** (D82) is unchanged: call-time system composition applies to the `Request`'s rendered `Site.System` before Ensure.
- **Keys are the consumer's recipe** (prompts treats them as opaque): the base identifies the unit of work — the pipeline uses `<jobID>/<stage>/<unit>` (D4 owns the recipe), ask uses `<chain-id>/<stage>` — and the `/a<attempt>` suffix makes each semantic attempt its own item, so re-ensuring after a crash always dedupes against exactly the work already queued.
- **Stateless by construction** — every item carries its complete `messages` replay; nothing is held between calls.
- **`ExtractJSON` retires** (and its ids/tests with it): prompts' envelope contract means `Result` is already a parsed-clean JSON value; a decoration-carver would be dead code guarding an impossibility.
- **`validate` stays caller-supplied** (extract D6 / compile D7 / ask D9), so domain rules stay co-located without `internal/llm` knowing the domain.
- **Usage on the item** is read for the D18 truncation check and otherwise ignored: accounting is prompts' job.
- **Testing:** the falsifying substrate is a `httptest.Server` playing the prompts queue — scripting 202/200/400 Ensures, staged `queued→running→done|failed` Get sequences, inbox pages, and 404s, while capturing raw request JSON. No provider mock, no network, no real time (the poll interval is injectable).

**Rejected.**
- **Keeping the synchronous `/complete` client (the prior form of this decision)** — the endpoint no longer exists; the synchronous concept was wrong (prompts D29): every completion slower than ~15 s died on the chassis write deadline as `Post /complete: EOF` while prompts recorded 200 (the 2026-08-11 ingest failures, jobs 008/009).
- **Keeping `ExtractJSON` "just in case"** — dead code that would mask a broken envelope contract instead of failing loudly on it.
- **Client-side transport retries** — unchanged doctrine (D1), and now largely moot: Ensure is idempotent, so the one interesting transport failure (did my enqueue land?) is answered by re-ensuring, which the pipeline does naturally on redelivery.
- **Long-polling or SSE instead of interval polling in `Do`** — a held response reintroduces the write-deadline race this redesign exists to kill; a 500 ms loopback poll against a `RecordExclude`-ed route costs nothing perceptible against multi-second generations.
- **Wiki-side enforcement of the JSON envelope** — prompts owns syntax (its D29 envelope + internal corrective loop); duplicating it in wiki splits one contract across two services. Wiki judges semantics only.
- **One shared consumer partition for both shapes (the prior form of this decision)** — the applier's stray-discard rule and the live path's poll then race on the same inbox: every live item is "not a pipeline envelope" to the applier, so the 2 s tick deterministically acked ask items out from under `Do` (observed 2026-08-11: every web/MCP ask died `completion gone while polling`). Partitioning removes the collision by construction instead of teaching the applier to recognize live items.
- **Making the applier skip (not ack) unrecognized items instead of partitioning** — unacked foreign items accumulate at the head of the oldest-first inbox, and at prompts' 100-item cap they starve the ingest drain entirely for up to the 7-day TTL. A rule that rate-limits the failure lost to one that removes it.

**Verification.**
- R-JW4G-367U — The captured raw Ensure request carries the full wire contract: `consumer` = `service:wiki`, the caller's `origin`/`group_id`/`attempt`, `key` with its `/a<attempt>` suffix, the verbatim `context` bytes, `name` = `wiki.<stage>`, config keys verbatim from the `CallSite`, `system` from the site, and a `messages` array whose elements carry exactly the keys `role` and `text` with a final `user` turn (asserted on raw JSON, never through the client's own structs).
- R-JXCC-GXYJ — `Get` decodes every stage faithfully (`queued`/`running` with no result, `done` with `Result`/`Usage`/`CostUSD` and verbatim `Context`, `failed` with `Error`) and maps 404 to `ErrGone`; `Inbox` GETs `?consumer=service:wiki` and decodes the item list; `Ack` DELETEs the id and treats 404 as success.
- R-JYK8-UPP8 — `Do` ensures, polls a scripted `queued → running → done` sequence to completion, acks the item, and returns it; cancelling the ctx mid-poll returns `ctx.Err()` without further polls.
- R-JZS5-8HFX — `Do` on an item that reaches `failed` acks it and returns an error carrying the queue's error string; `Do` whose mid-poll `Get` returns `ErrGone` errors terminally; neither path re-ensures or retries.
- R-K101-M96M — `JSON` returns the validated `T` decoded from a `done` item's `Result`, with the caller's `validate` applied.
- R-K27Y-00XB — A semantic failure (decode or validate) ensures a **new** corrective item: key `<base>/a2`, `attempt` 2, messages replaying the original user turn, the bad `Result` as an assistant turn, and a corrective user turn; a valid second result succeeds. The first item was `<base>/a1` with a single user turn.
- R-K3FU-DSO0 — When every attempt fails semantically, `JSON` returns an error after exactly `MaxParseRetries` corrective items, never a silent zero `T`.
- R-K4NQ-RKEP — An Ensure `400` returns an error naming prompts' `{"error":…}` body immediately: no poll, no corrective item, no further HTTP call.
- R-UCLK-JDHN — The two shapes partition: `Do`'s captured raw Ensure request carries `consumer` = `service:wiki.ask` while a handoff `Ensure`'s carries `consumer` = `service:wiki` (both asserted on raw JSON), and `Inbox` queries only `?consumer=service:wiki` — no live-path call ever names the pipeline partition and no handoff call the ask partition.
- R-UDTG-X58C — `Do`'s ErrGone failure names the vanished item's id: when a mid-poll `Get` returns 404, the returned error string contains the exact id `Do` was polling (a message with an empty or missing id fails the test).

(Truncation behavior at this seam — detection from the item's usage, `ErrTruncated`, terminal-no-corrective — is owned by D18 and keeps its ids there.)
