# Decision 80 — The page shell: boxed top-down layout, header bar (brand mark + universal question form), footer

**Decision.** Every page of the web surface — both tiers, all states (scope
home, ask result, search results, subject page, styled 404) — renders inside
one shared **shell**, replacing the vertically-centered single-column layout:

- **A boxed column.** All shell content lives in a centered column of
  `max-width: var(--layout-max-width)` (1120px) with `var(--layout-gutter)`
  (32px) side padding. The header bar's bottom hairline and the footer's top
  hairline are drawn **inside** that column (on the boxed element, not the
  viewport), so the whole page — header included — reads as one bounded page.
- **Top-down document flow.** Content builds from the top of the viewport; the
  old `align-content: center` vertical centering is gone. The footer sits at
  the bottom of the viewport on short pages (flex column, `main` flexes), but
  content never floats to the vertical middle.
- **The header bar** is the first element of `<body>`: a full-column row,
  hairline-bordered below, carrying — in document order, identical on every
  page and both tiers:
  1. **The brand mark** (far left): an anchor wrapping the suite logo image,
     `<a class="brand" href="/"><img src="static/logo.png" alt="ikigenba"></a>`.
     The `href` is the **host-absolute literal `/`** — the dashboard's default
     landing on the same host — deliberately unaffected by the page's `<base>`
     and needing no configuration (the D59 fully-qualified rule governs
     *subject links* that get copied out of context, not header navigation).
     The image is the committed asset `share/www/static/logo.png` (192×192
     PNG), served through the existing D52 `static/` route with no new asset
     plumbing, and rendered at `height: var(--space-8)` (32px, `width: auto`,
     `display: block`) so it stays crisp on high-DPI displays. The anchor
     takes `flex: none` so the mark never shrinks.
  2. **The Home link** (mono uppercase label style — target and id owned by
     D41).
  3. **The scope selector**, restyled from the input-look form to a compact
     control: a mono uppercase `Scope` label plus a `--control-h-sm` bordered
     `<select>` — it must not read as a twin of the question form. Its
     listing/preselection behavior is unchanged (D76 R-HQS5-5HNT); its
     `select`-action GET form is unchanged (D76 R-HOCC-DY6F). The selector
     takes `margin-left: auto` so it and the question form read as one
     right-aligned group.
  4. **The question form** — on **every** page, both tiers, all states
     (including the styled 404): a text input named `q` plus a submit button,
     the form's `method="get"` action resolving to the base `.` (the tier+scope
     home), so submitting the input navigates to `?q=<question>` — the exact
     key D42's root dispatch (R-WFPZ-2LTM) splits on — asking on the private
     tier (D44) and searching on the public one (D78). Labels, `aria-label`s,
     and busy behavior are D79's (**Ask**/`Asking…` private, **Search**/
     `Searching…` public). Compact styling: `--control-h-sm` control heights,
     a fixed width (360px), `margin-inline: 0`. On a `?q=` result page (ask
     answer, private; search results, public) the input carries the submitted
     query as its `value`, ready to edit and resubmit; on no-`q` pages it is
     empty. This header form is the surface's **only** ask/search affordance:
     no page renders a question form in `main`, and no "ask another question"
     anchor exists anywhere (the D44 link is retired; D45 already dropped its
     copy).
- **Selecting a scope navigates immediately.** A small inline script in the
  layout submits the selector form on the select's `change` event; the visible
  `Go` button is gone, and a submit button renders **only inside
  `<noscript>`** so the selector keeps working with scripts disabled
  (progressive enhancement, the D79 rule: nothing on the surface *requires*
  JS). The selector form still carries no `data-busy` (D79).
- **The footer** closes every page: the service name + version as a mono
  uppercase label above nothing, below a top hairline inside the column
  (preserves D39's name+version promise, R-LAND-NMVR).
- **The scope-home content** (title + suggested pages) is D43/D78/D81's; this
  Decision owns the frame around every page and the header question form on
  all of them.

All styling consumes the shared Carbon semantic tokens (`share/www/static/
tokens.css`, unchanged); fonts stay the self-hosted set (D50). Templates live
in `share/www/layout.tmpl` (`head`/`foot` blocks) per D52 — this Decision
rewrites those blocks and the layout CSS. The one new asset is the committed
`share/www/static/logo.png` (placed by the operator; the build loop never
authors binaries), reachable through the existing D52 static route — no new
asset routes and no handler signature changes.

**Rejected.**
- **Keeping the vertically-centered hero layout** — the operator reviewed a
  top-down boxed mockup against it and chose the mockup; centered content
  floats on tall viewports and the header/footer hairlines spanning the full
  viewport made the page read as unbounded.
- **Full-viewport header/footer bars with only the content boxed** — reviewed
  and rejected by the operator: the bars ran much wider than the content.
- **A shared `Go` button kept beside the select** — the mockup's compact
  selector has no button; auto-submit-on-change with a `<noscript>` fallback
  keeps script optional without the visual noise.
- **Per-page shells** — one layout template already frames every state (D52);
  diverging frames per page would re-introduce the drift this shell removes.
- **The body question form (centered on the scope home, `--control-h-lg`)** —
  the prior shape of this Decision, retired by operator direction after
  reviewing a header-bar mockup: one compact form in the header on every page
  replaces the large scope-home form and the subject-only header form, so the
  header is identical everywhere and asking never needs a trip home.
- **Making the brand mark's href a fully-qualified URL derived from the
  configured web base** — adds config-threading mechanism for no observable
  difference in a same-host navigation; D59's copy-out-of-context rationale
  does not apply to a header control. The literal `/` is the whole mechanism.
- **Pointing the brand mark at the wiki landing (a second Home)** — the
  operator pinned the split: the mark leaves for the dashboard's landing;
  `Home` (D41) stays the wiki's own.

**Verification.** httptest against the web handler with stub seams (markup
contracts; the shell is pure templating):

- R-HG6J-SNRN — **Every page wears the shell.** The private scope home, the
  ask result page (`?q=`), a subject page, the public scope home and its
  search results, and the styled 404 each render, in document order: a header
  element containing both the Home link and the scope-selector form, then the
  page's own content, then a footer containing the service name and version —
  the header markup preceding the content and the footer following it in the
  body on every one of those states.
- R-HHEG-6FIC — **The selector auto-submits, with a script-free fallback.**
  The layout ships an inline script that submits the scope-selector form on
  its select's `change` event, and the selector form's only submit button is
  inside a `<noscript>` element — a layout whose selector has a visible
  always-rendered submit button, or one with no `<noscript>` fallback button,
  or no change-submit wiring, fails.
- R-2MYX-Y4PN — **The brand mark opens the header and targets the dashboard.**
  On the private scope home, a subject page, and the public scope home alike,
  the header's **first** link is an anchor with `href` exactly `/` (not the
  mount, not a fully-qualified URL) containing an `<img>` whose `src` resolves
  to the `static/logo.png` asset and whose `alt` is `ikigenba`, and that
  anchor precedes the Home link in document order — a header without the
  mark, one whose mark follows Home, or one whose href is the mount or a
  qualified URL, fails. A `GET` of the static logo route itself returns 200
  with a `image/png` content type, proving the committed asset is actually
  served. *(httptest, stub seams + the real embedded static assets)*
- R-2O6U-BWGC — **The question form is in the header on every page.** The
  private scope home, the ask result page (`?q=`), a found subject page, the
  styled 404, the public scope home, and its search results each render,
  **inside the header element** after the scope-selector form, a
  `method="get"` form whose single text input is named exactly `q` and whose
  action resolves to the base — with the tier's D79 button label (**Ask**
  private / **Search** public). A page whose header lacks the form, or whose
  form posts, or whose input is named anything but `q`, fails. *(httptest,
  stub seams, both tiers)*
- R-2PEQ-PO71 — **The header input keeps the query on result pages.** On the
  private ask result page for `?q=who+is+acme` and the public search results
  for `?q=acme`, the header question input's `value` is exactly the submitted
  query; on the private scope home, the public scope home, and a subject page
  (no `q`), the input's `value` is empty — a header form that drops the query
  on a result page, or leaks one onto a no-`q` page, fails. *(httptest, stub
  seams, both tiers)*
- R-2QMN-3FXQ — **The header form is the only ask/search affordance.** On
  every state of both tiers (private scope home, ask result, subject page,
  styled 404, public scope home, search results): the document contains
  **exactly one** text input named `q` — the header's — with no question form
  inside `main`, and no "ask another question" anchor renders anywhere in any
  document. A scope home still rendering its old body form, or an answer page
  still rendering the retired link, fails. *(httptest, stub seams, both
  tiers)*
