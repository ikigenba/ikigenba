# Decision 80 — The page shell: boxed top-down layout, header bar, footer

**Decision.** Every page of the web surface — both tiers, all states (scope
home, ask result, search results, subject page, styled 404) — renders inside
one shared **shell**, replacing the vertically-centered single-column layout:

- **A boxed column.** All shell content lives in a centered column of
  `max-width: var(--layout-max-width)` (1120px) with `var(--layout-gutter)`
  (32px) side padding. The header bar's bottom hairline and the footer's top
  hairline are drawn **inside** that column (on the boxed element, not the
  viewport), so the whole page — header included — reads as one bounded page.
- **Top-down document flow.** Content builds from the top of the viewport; the
  old `align-content: center` vertical centering is gone. The footer sits at
  the bottom of the viewport on short pages (flex column, `main` flexes), but
  content never floats to the vertical middle.
- **The header bar** is the first element of `<body>`: a full-column row,
  hairline-bordered below, with the **Home link** (mono uppercase label style,
  left — target and id owned by D41) and the **scope selector** (right). The
  selector is restyled from the input-look form to a compact control: a mono
  uppercase `Scope` label plus a `--control-h-sm` bordered `<select>` — it must
  not read as a twin of the question form. Its listing/preselection behavior is
  unchanged (D76 R-HQS5-5HNT); its `select`-action GET form is unchanged (D76
  R-HOCC-DY6F).
- **Selecting a scope navigates immediately.** A small inline script in the
  layout submits the selector form on the select's `change` event; the visible
  `Go` button is gone, and a submit button renders **only inside
  `<noscript>`** so the selector keeps working with scripts disabled
  (progressive enhancement, the D79 rule: nothing on the surface *requires*
  JS). The selector form still carries no `data-busy` (D79).
- **The question form** is restyled to match: a `--control-h-lg` input and a
  **separate** primary button (radius, gap between them — no longer one fused
  bordered strip). Labels and busy behavior stay D79's.
- **The footer** closes every page: the service name + version as a mono
  uppercase label above nothing, below a top hairline inside the column
  (preserves D39's name+version promise, R-LAND-NMVR).
- **The scope-home content** (title + question form + suggested pages) is
  D43/D78/D81's; this Decision owns only the frame around every page.

All styling consumes the shared Carbon semantic tokens (`share/www/static/
tokens.css`, unchanged); fonts stay the self-hosted set (D50). Templates live
in `share/www/layout.tmpl` (`head`/`foot` blocks) per D52 — this Decision
rewrites those blocks and the layout CSS, no new asset routes and no handler
signature changes.

**Rejected.**
- **Keeping the vertically-centered hero layout** — the operator reviewed a
  top-down boxed mockup against it and chose the mockup; centered content
  floats on tall viewports and the header/footer hairlines spanning the full
  viewport made the page read as unbounded.
- **Full-viewport header/footer bars with only the content boxed** — reviewed
  and rejected by the operator: the bars ran much wider than the content.
- **A shared `Go` button kept beside the select** — the mockup's compact
  selector has no button; auto-submit-on-change with a `<noscript>` fallback
  keeps script optional without the visual noise.
- **Per-page shells** — one layout template already frames every state (D52);
  diverging frames per page would re-introduce the drift this shell removes.

**Verification.** httptest against the web handler with stub seams (markup
contracts; the shell is pure templating):

- R-HG6J-SNRN — **Every page wears the shell.** The private scope home, the
  ask result page (`?q=`), a subject page, the public scope home and its
  search results, and the styled 404 each render, in document order: a header
  element containing both the Home link and the scope-selector form, then the
  page's own content, then a footer containing the service name and version —
  the header markup preceding the content and the footer following it in the
  body on every one of those states.
- R-HHEG-6FIC — **The selector auto-submits, with a script-free fallback.**
  The layout ships an inline script that submits the scope-selector form on
  its select's `change` event, and the selector form's only submit button is
  inside a `<noscript>` element — a layout whose selector has a visible
  always-rendered submit button, or one with no `<noscript>` fallback button,
  or no change-submit wiring, fails.
