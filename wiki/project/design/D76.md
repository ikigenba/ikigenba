# Decision 76 — The scoped web surface: tier + scope in every URL, the landing cookie, the selector

**Decision.** The web surface adopts the D74 scope model with the **sites-style two-tier URL scheme**: every content URL names its visibility tier and its scope — in-process `/{tier}/{scope}/…` for `tier ∈ {public, private}`, externally `/srv/wiki/public/{scope}/…` (no auth at nginx) and `/srv/wiki/private/{scope}/…` (session-gated) — so every link and citation fully identifies its content and is shareable on its own. The cookie is a **landing preference only**: it decides where the bare root redirects, never what a URL serves.

## Routes (in-process; nginx strips the mount — D77 owns the gating)

| In-process pattern | Serves |
|---|---|
| `GET /{$}` | **Redirect** — 303 to `{mount}private/{cookie-scope}/`, falling back to `{mount}private/default/` when the cookie is absent or names an unknown scope. (Session-gated at nginx, so only logged-in humans reach it.) |
| `GET /{tier}/{scope}/{$}` | Scope home (± `?q=`) — private: D43/D44 home/ask; public: the D78 read-only home/search |
| `GET /{tier}/{scope}/subject/{type}/{slug}` | Subject page (D45 shape, scoped) |
| `GET /{tier}/{scope}/select` | **Selector action** — `?to=<scope>`: sets the cookie to `to` and 303s to `{mount}{tier}/{to}/` — that scope's home **in the caller's tier** |
| `GET /static/` | Shared assets (chassis mount, unchanged; ungated at nginx so public pages can style — D77) |

- `{tier}` admits only the literals `public`/`private` (two explicit route registrations, not a wildcard) — any other first segment is the styled 404.
- Every scoped handler resolves `{scope}` against the registry first: unknown scope → styled 404 (any tier). Then the **tier/visibility wall**: the `private` tier serves any known scope (the viewer is authenticated — no ACLs, D74); the `public` tier serves a scope iff its visibility is `public`, and answers the styled **404** for a private scope — indistinguishable from a scope that does not exist, so the public tier leaks no scope names.
- **Redirect `Location`s are mount-prefixed.** nginx strips the mount on the way in but never rewrites a path-only `Location` header on the way out, so a service-relative redirect target escapes `/srv/wiki/` at the front door and lands on the apex. Every `Location` the handler emits (the landing 303 and the selector 303) is therefore composed as `{mount}…` from the mount configured at construction — the same mount the cookie path and `<base href>` already use. Route *patterns* stay service-relative; only emitted URLs carry the mount.
- **Only the selector sets the cookie.** Following a shared link to another scope leaves the visitor's landing preference unchanged; picking a scope in the selector is the one deliberate act that moves it. The cookie (`wiki_scope`, value = the scope name, path = the wiki mount, `SameSite=Lax`) is a preference, not identity — tampering with it can at most change which page a redirect lands on.
- **The selector UI** renders at the top of every page: a plain `<form method="get">` over a `<select name="to">` + Go button targeting the current tier+scope's `select` action. On the private tier it lists **all** scopes; on the public tier it lists **public scopes only** (the anonymous viewer must not learn private scope names). The current scope is preselected.
- **Link composition stays inside the page's own tier and scope.** The D42 `<base href>` becomes `{mount}{tier}/{scope}/` so the existing relative links (`subject/…`, `.`, the search form) resolve within the tier+scope without template changes; the absolute front-door subject links (D59) are composed as `{origin}{mount}{tier}/{scope}/subject/{path}`.

## Citations and absolute links pick the tier by visibility

The D56 MCP `ask` citations and every D58/D59 absolute front-door URL now require a tier and a scope. The tier is chosen by the **scope's visibility at composition time**: a public scope's links use `/public/{scope}/…` (openable by anyone the link is passed to), a private scope's use `/private/{scope}/…` (opens after sign-in via the D60 bounce). The page base is therefore no longer a startup constant — it is composed per call from `rt.AuthServer()` + mount + tier(visibility) + scope. A visibility flip changes the URLs a *later* call composes; previously-issued links go stale in the flip direction the operator accepted (public→private links 404 on the public tier).

**Supersessions (edited in place, notes added).** D42's route table and single-`<base>`; D43/D44/D45/D46 (the states now render per tier+scope; ask/orphans become private-tier-only per D78); D56's startup `pageBase`; D59's absolute-URL form. Their behaviors otherwise stand and their R-ids are re-proven through the scoped routes by the phases realizing this Decision and D78.

**Rejected.**
- **Cookie-only scope (no scope in the URL)** — a shared URL would open in the *receiver's* cookie scope: wrong content or 404, and MCP citations could not be written at all. Rejected outright; the operator pinned scope-in-path for shareability.
- **Stable URLs with an nginx auth fall-through (one tier, wiki decides)** — keeps URLs across visibility flips, but is a novel edge pattern with no suite precedent and muddies the single-trust-boundary story. The sites tier precedent wins; stale links on a flip are the accepted cost.
- **Every page load updates the cookie** — casually following a colleague's link would silently move your landing preference; only the deliberate selector act should.
- **A `default`-scope shorthand URL (`/srv/wiki/` serving content directly)** — two URLs for the same content; the redirect keeps one canonical form per page.
- **Distinct 403 for a private scope on the public tier** — confirms the scope exists to an anonymous visitor; the uniform 404 leaks nothing.
- **A JS-driven selector** — a form + redirect does it; script on the surface is permitted (D79) but buys nothing on an instant navigation.
