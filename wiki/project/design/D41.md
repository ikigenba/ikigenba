# Decision 41 — The header-bar Home link targets the wiki's own landing

**Decision.** The **Home link** in the D80 header bar — present on every page
of the web surface, both tiers — returns the viewer to the **wiki's default
landing page**: its `href` is exactly the configured **mount** (externally
`/srv/wiki/`), the bare root whose D76 redirect lands a signed-in viewer on
their remembered scope's home. The link text is `Home`, styled with the mono
uppercase label tokens.

- **Composed from the injected mount, never a literal.** The href is the same
  `mount` value the layout already threads into `<base href>` and every
  emitted `Location` (D42/D76) — under a different mount the link follows it.
- **One target everywhere.** The same href on every page and both tiers, with
  no special-casing: the bare root is session-gated, so an anonymous public-
  tier viewer who clicks it gets the apex sign-in bounce (D60). The operator
  accepted that; Home means "the wiki's landing", unconditionally.
- The dashboard is reachable through the D80 **brand mark** beside this link
  (`href="/"`, the apex landing); wiki's Home is wiki's. The two targets are
  deliberately distinct and neither duplicates the other.

**Rejected.**
- **Targeting the dashboard apex (`href="/"`)** — the previous behavior of
  this Decision, retired by operator direction: Home on a wiki page should
  return to the wiki's own landing, not leave the service.
- **A tier-aware target (public tier → `{mount}public/{scope}/`)** — proposed
  so anonymous viewers avoid the sign-in bounce; the operator pinned one
  unconditional target: the wiki's default landing.
- **Labeling it with the service or scope name** — `Home` says what it does;
  the scope selector beside it already names the scope.

**Verification.** httptest against the web handler with stub seams:

- R-HIMC-K791 — **Home links to the mount, threaded not hardcoded.** On the
  private scope home, a subject page, and the public scope home alike, the
  header's Home anchor has `href` exactly equal to the configured mount — a
  handler built with mount `/srv/zzz/` renders `href="/srv/zzz/"` (not
  `/srv/wiki/`, not `/`), distinct from the page's `static/` asset references.
