# Decision 9 — `ask` (`internal/ask`): hybrid-retrieval pipeline, grounded/cited/honest-empty

> **Scoped by D74.** `Ask` takes the scope as a leading parameter; retrieval, citations, and the honest-empty judgment are all bounded to that scope's pages (D74 R-GYQG-CRLU). The pipeline below is unchanged within a scope.

**Decision.** `ask` prepares the question, searches the pages with the hybrid retriever, and synthesizes a cited answer from the pages it finds. Control flow is a **deterministic pipeline** in Go: analyze → retrieve → gather → synthesize. The LLM is invoked twice as structured generations through `llm.JSON[T]` (D5) — once to analyze the question (D36), once to synthesize — plus the query-embedding call inside the meaning lane (D34). **No exact-name resolution, no tool-loop, no source/claims drill-down**: `ask` answers from the compiled pages only, found by search. Strictly read-only, permanently.

```go
package ask

type Answer struct {
    Found     bool       // false → the wiki holds nothing relevant to the question
    Text      string     // synthesized answer, or the fixed honest-empty sentence
    Citations []Citation // the pages the answer drew on
}
// Citation identifies a cited page by its public type/slug Path (D11), never the internal id.
type Citation struct { Path, Title string }

type Asker struct {
    search     Retriever           // hybrid SearchAnalyzed (D33)
    pages      *wiki.PageStore     // fetch page bodies for the synthesis context
    c          *llm.Client
    analyzeSite llm.CallSite        // stage 1: question analysis ("ask-subject", D36)
    synthSite   llm.CallSite        // stage 3: grounded synthesis ("ask-synthesis")
    floor       float64             // cosine relevance floor (honest-empty gate); config knob, default 0.30
    bodyBudget  int                 // bytes of page bodies gathered for synthesis; default wiki.AskBodyBudget (98304)
}
func (a *Asker) Ask(ctx context.Context, owner, question string) (Answer, error)
```

**Flow — analyze → retrieve → gather → synthesize:**

1. **Analyze (one LLM call, D36).** `Analyze` turns the question into a `QueryAnalysis{SubQueries, Keywords, Aliases}`.
2. **Retrieve (deterministic + one query-embed inside the lane).** `search.SearchAnalyzed(ctx, qa, retrieve.LimitCap)` — the request is the seam's ceiling (20), not a smaller fixed count; how much is *read* is bounded by the byte budget below, so there is no reason to ask retrieval for less than it can rank. It returns a `retrieve.Result{Hits, TopDense, Pinned}` — the fused top pages, the best raw meaning-match score, and whether an exact-name page was pinned (D33).
   - **Honest-empty gate:** if **no** exact-name pin fired **and** `TopDense` is below `floor`, return `Answer{Found:false, Text:<fixed sentence>, Citations:nil}` and make **no synthesis call**. Fuzzy search always returns *some* top page, so this relevance bar — judged on the raw cosine, not the fused rank score — is what restores an honest "nothing here," and skipping the synthesis call is the deterministic anti-fabrication lever (the model never runs against irrelevant pages). An exact-name pin always clears the gate (a verbatim-named subject is relevant by definition).
3. **Gather under a byte budget (deterministic).** The hits are walked in fused rank order and each page's whole body is added to the synthesis context until the **body-byte budget** is spent: a page whose body would overflow the remaining budget is **skipped whole** and the walk continues (greedy first-fit — a large mid-rank page never starves smaller pages below it). Partial bodies are never included: a truncated body could ground a half-true answer and breaks the citation contract, so a page is in the context entirely or not at all. The budget is `wiki.AskBodyBudget = 98304` bytes (96 KB = 8 × the 12,000-char D7 page cap — exact parity with the old fixed-8 worst case, while letting up to `LimitCap` small pages in), surfaced in the manifest as `ASK_BODY_BUDGET` exactly as `SEARCH_DEFAULT` is (a `wiki` package constant declared in the composition root's manifest key list). The budget is the honest name for what the old fixed count pretended to be: a context-size bound, not a relevance bound.
4. **Synthesize (one LLM call).** Run `llm.JSON[answerResult]` over **the gathered page bodies only**.
   ```go
   type answerResult struct {
       Found     bool       `json:"found"`
       Text      string     `json:"text"`
       Citations []Citation `json:"citations"`
   }
   ```

**Grounding & anti-fabrication (pages-only) — unchanged guarantees:**
- A `Found:true` answer **must carry ≥1 citation**; a found-with-no-citation reply is **downgraded to honest-empty**.
- Each citation is **validated against the retrieved set**; a citation to a page not retrieved this turn is **dropped**. Surviving citations come from the page store, so they are real pages, and each is mapped from subject id to the public `type/slug` **Path** (D11) before returning — never an internal id.
- The synthesis prompt is fed **only the retrieved page bodies** — never raw claims or original source text. No drill-into-source path exists in `ask`.

**`ask` is strictly read-only — permanently.** `Asker` only reads (search + `GetBySubject`); no write path exists on any branch, including honest-empty and parse-failure.

**The relevance floor is a config knob.** Default **0.30** — deliberately conservative; tuned later against real in/out-of-corpus questions. A `_RELEVANCE_FLOOR` manifest knob (fail-loud parse, like the D19 knobs) moves it without a recompile. Raising it above a page's cosine forces honest-empty; lowering it admits the page.

**Prompts.**
- analyze (`ask-subject`) — owned by D36.
- synthesis — the instruction preamble lives as **`internal/ask/synthesis-prompt.txt`**, embedded by the package and sent as **`synthSite.System`**; the **user message is only the rendered input** (the question plus the retrieved page bodies — `synthPrompt` no longer prepends instructions). Content: answer **only** from supplied pages; cite each page drawn on by subject id + title (`ask` maps id to public path after validation); return `found:false` if the pages don't answer; never fabricate a fact, page, or citation; surface contradictions with both sides; read-only. JSON output schema + example. This matches the external tuning tool's call shape (research §13); the committed tune folder `autotune/synthesis/prompt.txt` (D71) starts as a plain copy with no mechanical tie.

**Call sites** (defaults, configurable per D19): `analyzeSite` = `ask-subject`; `synthSite` = `ask-synthesis`. Both carry the ask's D62 attribution (`user:<email>` origin, the per-ask correlation id as `group_id`); the query-embedding call is `wiki.embed-query` (D34) under the same attribution.

**This rewrites the prior D9.** The old pipeline extracted bare subject *names* and resolved them by **exact normalized name**, gathering one page per resolved name and returning honest-empty when no name resolved. That exact-name machinery is replaced by hybrid retrieval: stage 1 is now question analysis (D36) and stage 2 is search (D33), so the four exact-name behaviors retire (their ids and tests go) and are replaced by the retrieval-gather and cosine-floor behaviors below. The integrity guarantees — pages-only, every answer cited, honest-empty, read-only — are unchanged and keep their ids.

**Rejected.**
- **Keeping exact-name resolution as the primary path.** That is the limitation this upgrade removes — a question that doesn't name a subject verbatim found nothing. The exact-name case survives only as the rank-1 pin inside D33.
- **Honest-empty on the fused rank score instead of raw cosine.** The fused score is uncalibrated (rank-based), so a fixed threshold on it is meaningless; the raw cosine is a real similarity the floor can be set against.
- **Agentic tool-loop (model drives retrieve/read).** Makes the honest-empty gate fuzzy and stages hard to pin with checkable ids; the deterministic pipeline keeps the gate in Go.
- **`read_source` / raw-claims drill-down.** Pages-only is the product decision.
- **A larger fixed page count instead of a byte budget.** Any fixed count is the wrong dimension: it wastes context when pages are small (the live corpus averages ~1 KB/page, so a fixed 8 read ~8 KB of a 96 KB-safe window) and can overflow it when they are large. The budget bounds what actually matters (bytes fed to the model) and lets the page count float.
- **Truncating a page body to fit the remaining budget.** A partial body can ground a half-true answer and still earn the page a citation; whole-page-or-skip keeps every citation backed by everything the cited page says.

**Verification.**
- R-BAFW-D24P — `Ask` drives retrieval from the analyzed question: it calls `Analyze` (D36) then `SearchAnalyzed` (D33) and passes the **retrieved** pages (not exact-name-resolved subjects) to synthesis — a mock retriever's returned hits are exactly the pages fed to the synthesis call.
- R-BBNS-QTVE — **Honest-empty floor gate:** when no exact-name pin fired and the result's `TopDense` is below `floor`, `Ask` returns `Found:false` with the fixed honest-empty text and empty citations and makes **no synthesis LLM call**; when a hit clears the floor (or a pin fired), synthesis runs.
- R-BCVP-4LM3 — The floor is an effective knob: with the same retrieval result, a floor set **above** the top cosine yields honest-empty (no synthesis call), and a floor set **below** it proceeds to synthesis — the threshold, not a hardcode, decides.
- R-5UPD-VVNA — A `Found:true` answer carries ≥1 citation; a synthesis reply claiming found with no citation is downgraded to honest-empty.
- R-5VXA-9NDZ — Each surfaced citation is one of the pages retrieved this turn; a citation to a page not in the retrieved set is dropped (no fabricated citations).
- R-690G-MZTK — **Pages-only grounding:** only the retrieved page bodies are fed to synthesis — no raw-claims or original-source text reaches the synthesis call, and no source/claims read path exists on the `Asker`.
- R-5X56-NF4O — `ask` performs no writes under any path (including honest-empty and parse-failure) — DB state is identical before and after a call (strictly read-only).
- R-6A8D-0RK9 — `Ask` returns the `Answer{Found,Text,Citations{Path,Title}}` contract synthesized by the deterministic analyze → retrieve → gather → synthesize pipeline (parsed from the synthesis call's structured result).
- R-05CG-3H6Y — Each returned citation identifies its page by the public `type/slug` Path (D11), mapped from the validated subject; no internal subject id appears in any citation.
- R-9ZPI-IIDS — The captured `/complete` request for a synthesis call carries `system` equal to the embedded `internal/ask/synthesis-prompt.txt` contents and a user message containing **only** the question and the retrieved page bodies — the instruction preamble appears in `system` and nowhere in the user turn.
- R-NFXF-9QGN — `Ask` requests the retrieval ceiling: the limit handed to `SearchAnalyzed` is `retrieve.LimitCap` (20), not a smaller fixed count — captured from a mock retriever.
- R-NH5B-NI7C — Budgeted gather, whole-page-or-skip: with hits of known body sizes and the budget set so hits 1–2 fit, hit 3 overflows, and hit 4 fits the remainder, the synthesis context contains exactly pages 1, 2, and 4 — page 3 is absent entirely (never truncated) — and moving the budget threshold moves which pages are included (the budget, not a hardcoded count, decides).
- R-NID8-19Y1 — The composed manifest declares `ASK_BODY_BUDGET` with value `98304` (the `wiki.AskBodyBudget` constant), alongside the existing search knobs.
