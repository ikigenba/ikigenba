# Decision 94 — The inbox drain contract: no item may stop the drain

**Decision.** The inbox drain classifies **every** item it is handed and never stops early. One document's failure ends that document, never the service.

The prior shape returned the first error to its caller, which left the failing item **unacked** and the rest of the tick's items **untouched**. `Inbox` is an oldest-first query, so the same item led every subsequent tick: a single unapplyable completion blocked ingest for every scope, indefinitely, across process restarts, because the item is durable in prompts and nothing in wiki could ever get past it. The drain's contract must make that unreachable.

**Every item yields an outcome, not an error.**

```go
type Outcome struct {
    Class  OutcomeClass // Applied | Discarded | JobFailed | Deferred
    Reason string       // stable token, e.g. "stale_plan", "prompts_unreachable"
    Err    error
}

type Drain struct {
    Seen, Applied, Discarded, JobsFailed, Deferred int
    Errs []error // aggregated for reporting, never propagated as control flow
}

func (s *Service) applyCompletion(ctx context.Context, item llm.Item) Outcome
func (s *Service) ProcessInbox(ctx context.Context) Drain
```

`ProcessInbox` returns `Drain`, not `error`. The only thing that ends a tick early is a canceled context.

**Ack policy is a property of the class, and there are only four.**

| class | job | ack | when |
|---|---|---|---|
| `Applied` | advanced or `done` | yes | the completion was integrated |
| `Discarded` | untouched | yes | the item is irrelevant: unknown job, terminal job, stale stage/units, non-pipeline envelope, aborted job |
| `JobFailed` | `failed`, staging cleared, lease released | yes | the completion cannot ever be applied: model-side failure, semantic retries exhausted, missing staging row, corrupt staged payload, stale plan, constraint violation, an `Ensure` rejected as invalid |
| `Deferred` | untouched | **no** | the failure is a property of the environment, not the item: prompts unreachable, transport error, database busy |

**Only `Deferred` skips the ack, and deferral is bounded.** An item that defers repeatedly is counted; past a small bound of consecutive deferrals it is **reclassified `JobFailed`** — its job fails with the last error and the item is acked. This is the rule that makes a wedge impossible: no item can be deferred forever, so the head of the queue always clears. The bound is held in memory deliberately — a deferral is an environment condition ("prompts is down"), not a durable property of the item, and a restart is exactly when re-trying is worth it again.

**Default is permanent.** Only an explicit transient set defers; every unrecognized error fails its job. The asymmetry is deliberate: mistaking a permanent failure for a transient one produced the outage, while mistaking a transient one for permanent fails a single document loudly and leaves `rerun` available.

**Ack is always last.** Every consequence — staged writes, the integrate commit, corrective ensures — is durable before the item is acked. A crash between the consequence and the ack redelivers the item, and redelivery is a no-op: the guarded terminal write finds the job already terminal and discards. Post-commit work that is separately self-healing (embedding writes, which `DrainEmbeddingCatchUp` reconciles) never re-drives the item and never blocks the ack.

**Only terminal items are ever acked.** `Ack` deletes unconditionally, so acking a non-terminal item would destroy work in progress. The drain sees only terminal items today; the invariant is stated so it stays true.

**A failed job's error is written for the person who will read it.** Ingest runs unattended: the job list is the only place this surfaces. The recorded error names what failed and what to do, not a raw driver string.

**Rejected.**
- **Returning the first error to the caller** — the shipped behavior, and the outage: it skipped the ack and abandoned the rest of the tick, converting one bad item into a permanent service-wide stall.
- **Retrying a permanent failure forever** — a stale plan or a corrupt payload is deterministic; replay cannot change the outcome and the retry is what blocks everyone else.
- **A durable dead-letter table with its own MCP verbs** — recovery is already expressible: the document's job goes `failed` with a reason, and `rerun` retries it. Ingest is unattended, so the surface that matters is the job list a caller already queries, not a second vocabulary of stuck items.
- **Skipping the ack on a permanently-failed item to preserve it for forensics** — preserves the item by starving the queue; `Inbox` returns a bounded page, so retained poison items eventually crowd out live work. Telemetry keeps the record instead.
- **Unbounded deferral for transient errors** — indistinguishable from the outage whenever the "transient" condition is permanent.

**Verification.**
- R-P56S-5BZJ — A drain over an inbox whose **first** item fails to apply still applies every subsequent applicable item in the **same** tick, and the failing item does not prevent any later item from being applied on that tick or the next (returning on the first error is the failing case).
- R-P6EO-J3Q8 — An item whose completion can never be applied (stale plan, corrupt staged payload, missing staging row, model-side failure) ends its job `failed` with a non-empty error naming the cause, clears its staging, releases its lease, **and acks the item** — a second drain over the same inbox sees it gone.
- R-P7MK-WVGX — An item failing with a transient condition (prompts unreachable) is **not** acked and is retried on the next drain; after the bounded number of consecutive deferrals it is reclassified permanent — its job ends `failed` and the item is acked — so the drain makes progress rather than deferring indefinitely.
- R-P8UH-AN7M — Ack happens only after every consequence is durable: a failure injected between the integrate commit and the ack leaves the job `done` and the item unacked, and the redelivery is discarded without altering committed state.
