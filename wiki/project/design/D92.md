# Decision 92 — Ask-serving routes clear the chassis write deadline

**Decision.** The chassis HTTP server carries a 15 s `WriteTimeout` — an absolute write deadline set at request start. `ask` is a live wait (analysis + retrieval + synthesis, now queue-round-trips to prompts, D5/D9): its response routinely forms later than 15 s after the request began, so without intervention wiki severs its **own** callers exactly the way prompts' synchronous `/complete` severed wiki (the handler completes and records success; the client reads EOF). The fix is the established in-suite pattern (`eventplane/outbox/feed.go`, dashboard `grants.go`): the ask-serving handlers clear the per-request write deadline via `http.NewResponseController(w).SetWriteDeadline(time.Time{})` before doing slow work.

Two mounts get it, both wiki-owned:

- **The web ask route** (`GET /{$}` with `?q=…`, D44): the handler clears the deadline first thing on the ask branch (the no-`q` home render stays under the default deadline).
- **The MCP mount**: `cmd/wiki` wraps the handler it passes as `Spec`/`Options.MCP` in a one-line middleware that clears the deadline, then delegates. Every MCP tool is affected uniformly — correct, since `ask` is reachable through it and the others answer fast regardless; the wrapper sits in wiki's composition root, not in appkit.

The chassis default stays untouched for every other route — the deadline remains the right guard for handlers that have no business being slow. nginx's own proxy timeouts (60 s read default) remain the edge's bound; this decision only stops wiki's loopback server from cutting the connection underneath a legitimately slow ask.

The chassis's middleware chain supports this today: appkit's telemetry response writer implements `Unwrap`, so `ResponseController` reaches the real connection — no appkit change is needed or made (scope boundary).

**Rejected.**
- **Raising the chassis `WriteTimeout` for everyone** — an appkit change outside this tree, and wrong: it would relax the guard for every service and route to accommodate two handlers.
- **Bounding ask under 15 s instead** — ask's floor is the sum of two model calls; a deadline that tight would fail honest asks to protect a socket rule that per-handler clearing removes cleanly.
- **Streaming/flushing early to keep the socket alive** — changes the response contract of both surfaces for a plumbing concern.

**Verification.**
- R-KJAJ-CTB1 — The web ask branch clears the response write deadline before invoking the asker: a recording `ResponseWriter` (implementing `SetWriteDeadline` through `Unwrap`) observes `SetWriteDeadline(time.Time{})` on a `?q=…` request and observes none on the bare home render.
- R-KKIF-QL1Q — The composition root's MCP mount is the deadline-clearing wrapper: driving the wired MCP handler records `SetWriteDeadline(time.Time{})` before the inner handler runs, and the inner handler still receives the request unchanged.
