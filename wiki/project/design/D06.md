# Decision 6 — The extract stage (`internal/extract`)

> **System composition extended by D82.** R-9W1T-D75P below pins the captured `system` for a scope **without** instructions; when the job's scope carries instructions, the served system is the D82-composed form (this base prompt + the scope-instructions block — D82 R-8LZ1-MPCG).

**Decision.** A single-pass, tool-less, structured LLM call over the D5 `llm.JSON` helper: the whole source text plus a mechanical header → subjects, each with its **statements classified into claims and corrections** (D96). Ported from wiki.bak's extract, minus aliasing.

```go
package extract

type ExtractedSubject struct {
    Type       string   // "entity" | "event" | "concept"
    Kind       string   // freeform subtype, prompt-anchored ("person","company","method"…)
    Name       string   // primary name AS THE TEXT STATES IT (registry normalizes later)
    OccurredAt string   // ISO-8601 prefix (YYYY / YYYY-MM / YYYY-MM-DD); required for events, optional for entity/concept; "" only when the document states no defining date
    Claims      []string // short self-contained prose statements, no pronouns
    Corrections []string // statements the document phrases as RULINGS that a fact is false (D96); same prose discipline; empty for most documents
}

// DocumentHeader anchors relative-time resolution for real-world-present documents only (see prompt content); rendered verbatim, never model-inferred.
type DocumentHeader struct {
    Source     string    // phase 1: "mcp:ingest_text"
    Title      string
    Tags       []string
    ReceivedAt time.Time // rendered "received on: YYYY-MM-DD" (never "today is")
}

type Extractor struct { c *llm.Client; site llm.CallSite }
func New(c *llm.Client, site llm.CallSite) *Extractor
func (e *Extractor) Extract(ctx context.Context, h DocumentHeader, text string) ([]ExtractedSubject, error)
```

- **Prompt housing and the system/user split.** The extract instruction preamble lives as **`internal/extract/prompt.txt`**, embedded by the package (`//go:embed prompt.txt` → `var DefaultPromptInstructions string` — same exported name as before, now package-local). The call sends it as the **`System`** message of the site; the **user message is only the rendered input** — the mechanical document header plus the source text (`Render(h, text)` no longer prepends instructions). This matches the external tuning tool's call shape exactly (system = prompt under test, user = case input; research §13), so a tuned score predicts serving behavior. The committed tune folder `autotune/extract/prompt.txt` (D71) starts as a plain **copy** of this file with **no mechanical tie** — no test compares them, no build links them; adoption is a manual edit here.
- **Prompt content** — port wiki.bak's `DefaultExtractPrompt`, **dropping the `aliases` field and the within-doc alias/co-reference clause** (no aliasing in phase 1). Keep verbatim the two load-bearing rules: the **salience gate** ("extract a subject only when it is identifiable — the Wikipedia-article test — AND the document makes a concrete claim about it; never invent a subject to hold a stray fact") and the **claims discipline** ("each claim is a short SELF-CONTAINED prose statement, no pronouns; state only what the document ASSERTS — do not infer or synthesize"). Keep the dialog-awareness clause and a worked example (rewritten without aliases). Closed-set type. `occurred_at` is an ISO-8601 prefix the model fills **whenever the document states a defining date for the subject** — required for an `event`, equally welcome on an `entity` (birth, publication) or `concept` (when first named); `""` only when the document states no such date. **Relative time is anchored conditionally**: the received-on date resolves a relative expression **only when the document speaks from the real-world present** — notes, correspondence, news, minutes, anything where "yesterday" plainly means the day before receipt. When the text narrates from its own timeline — fiction, historical retelling, memoir, an in-world document — relative time **stays relative in the claim** ("founded 130 years before the story's present") and `occurred_at` stays empty: the extractor never converts relative time into an absolute date the document does not state. When in doubt, keep it relative — a wrong absolute date is frozen into the durable record, while a relative claim is merely less convenient. The prompt states this rule with the exact key phrases "only when the document speaks from the real-world present" and "When in doubt, keep it relative", and carries a short narrative counter-example beside the existing real-world example. **The classification discipline (D96 statements):** a statement is a **correction** only when the document itself *rules a fact false* — explicit denial or correction language ("X is false", "not in 2023", "contrary to earlier records") — and a plain assertion is always a claim, however confidently stated; a correction that also states the true fact yields **both** a correction and a claim; prose stays self-contained, no pronouns, both kinds. The prompt states this with the exact key phrases "only when the document itself rules a fact false" and "a plain assertion is always a claim", and carries a worked correction example (a denial-plus-truth sentence yielding one correction and one claim). The committed tune copy `autotune/extract/prompt.txt` (D71) is updated to the same content in the realizing phase (a one-time manual copy; the no-mechanical-tie rule stands), and the extract tune folder gains one committed narrative dev case pinning the behavior (R-8UIC-B3JB).
- **`validate`** (the D5 caller hook): every subject's `Type` ∈ `{entity,event,concept}`; `Name` non-empty after trim; ≥1 **statement** — at least one claim or correction — with every claim and every correction non-empty after trim (`Corrections` itself may be absent/empty); and **`OccurredAt`, when non-empty, is a valid ISO-8601 prefix** (`YYYY` / `YYYY-MM` / `YYYY-MM-DD`) for **any** subject type, and is **required** (non-empty, valid prefix) when `Type=="event"`. A violation is a parse-level failure → bounded re-prompt. A stated `OccurredAt` is **retained as extracted on every subject type — never coerced to `""` and never rejected for being present on a non-event**.
- **Empty is honest, not an error.** A text with no salient subject yields `[]`; the job completes with zero subjects. Extract never invents a subject to avoid emptiness.
- **Call site** — the package **owns** its designed defaults and exposes them so wiring cannot silently drop them: `extract.DefaultCallSite()` returns `{Stage: "extract", System: DefaultPromptInstructions, Config: {Provider: "openrouter", Model: "gpt-5.6-luna", Effort: "medium", MaxTokens: 16384}, MaxParseRetries: 2}` (values in the D5 `Config` vocabulary; overridable per D19's knobs). gpt-5.6 models are reasoning models addressed with `effort` — the old `Temperature: 0` / `Thinking: false` pins are not portable to them (research §13) and are **gone**: the default config carries no temperature and no thinking field. The non-zero `MaxTokens` (D18) keeps a large extraction off the 4096 adapter default that truncated jobs into `unexpected end of JSON input`. **The composition root constructs the extractor from `DefaultCallSite`, never a bare `llm.CallSite{…}`** — the original drift was exactly that bare construction, which ran extraction at provider defaults with **zero** retries (a single fenced-parse failure killed the job with no re-prompt). Single-pass and tool-less — reads only header + source text, reinforcing the anti-poisoning invariant (D4 R-MG31).

**Rejected.**
- **Keeping the `aliases` field** — feeds deferred alias machinery; in phase 1 it is dead weight that invites over-merging surface forms.
- **Treating empty `subjects[]` as a failure/retry** — would pressure the model to fabricate subjects, violating the salience gate. Empty is valid.
- **Haiku for extract** — cheaper, but extraction error is frozen into the durable record and silently recompiled forever (research §5); the stronger model is warranted (still a config knob).
- **Unconditional relative-time anchoring** (the original rule: always resolve relative time against received-on) — treats every document as speaking from the real-world present, so a narrative's "130 years ago" was minted as an absolute year computed from the ingest date — an inference the document never asserted, violating the prompt's own claims discipline and freezing a wrong date into the durable record (the observed Svenhold/1896 corruption). Conditional anchoring keeps the convenience for dated real-world documents without fabricating dates for narrative ones.
- **The `occurred_at`-empty-unless-event rule** — original D6 emptied (`coerce ""`), and the ported code went further and *rejected*, any date on a non-`event` subject. But the model naturally extracts a subject's defining date regardless of type (birth/publication/founding year), so the reject failed whole ingests **deterministically** (the "Gary Gygax" doc, where every `entity` carries a year) while the coerce variant silently discarded real durable temporal signal. `occurred_at` is now an optional, format-validated field on **every** subject type.

**Verification.**
- R-VYU0-BPAX — `validate` rejects an extraction containing a subject whose `Type` is outside `{entity,event,concept}` (a parse-level failure that triggers a re-prompt).
- R-XJBY-H8JZ — A valid extraction **retains** a non-empty `OccurredAt` on a non-`event` subject (`entity`/`concept`) exactly as extracted — a stated date on a person or work is never emptied, dropped, or rejected for being present on a non-event.
- R-XKJU-V0AO — `validate` rejects a subject whose non-empty `OccurredAt` is not a valid ISO-8601 prefix (any type) and rejects an `event` whose `OccurredAt` is empty (a parse-level failure → re-prompt); a valid prefix on an `entity`, `concept`, or `event` passes.
- R-W19T-38SB — A source with no salient subject yields an empty `[]ExtractedSubject` and a successful (non-error) extract — no invented subject.
- R-9UTW-ZFF0 — `extract.DefaultCallSite()` carries `Provider "openrouter"`, `Model "gpt-5.6-luna"`, `Effort "medium"`, `MaxTokens >= 16384`, **no** temperature and **no** thinking field, and `MaxParseRetries: 2`, and the extractor the composition root builds is constructed from it — so a parse/validate failure is actually re-prompted (a bad-then-good extraction succeeds through the production-configured extractor) rather than failing on the first attempt.
- R-9W1T-D75P — The captured completion item's payload for an extract call in a scope without instructions carries `system` equal to the embedded `internal/extract/prompt.txt` contents (`DefaultPromptInstructions`) and a user message containing **only** the rendered header + source text — the instruction preamble appears in `system` and nowhere in the user turn. (The with-instructions composed form is D82's R-8LZ1-MPCG.)
- R-8TAF-XBSM — `DefaultPromptInstructions` states the conditional relative-time rule: it contains the exact phrases "only when the document speaks from the real-world present" and "When in doubt, keep it relative", and does **not** contain the retired unconditional sentence "Resolve relative time against the header's" — so a regression to always-anchoring fails the content check.
- R-8UIC-B3JB — The committed extract tune folder carries the narrative dev case `autotune/extract/cases/dev/narrative-relative-time/`: its `input.txt` contains a relative-time expression inside narrative text (no real-world anchor), and its parsed `gold.json` expects `occurred_at` `""` on the affected subject with a claim that preserves the relative expression rather than an absolute year — asserted by the `autotune` test package.
- R-7BO4-JMO9 — `validate` accepts a subject carrying corrections (with or without claims) and one carrying claims with `Corrections` absent, and rejects (parse-level failure → re-prompt) a subject with an empty-after-trim correction entry or with zero statements of either kind.
- R-7CW0-XEEY — `DefaultPromptInstructions` states the classification discipline: it contains the exact phrases "only when the document itself rules a fact false" and "a plain assertion is always a claim" — so a regression that drops or loosens the correction gate fails the content check.
- R-7E3X-B65N — The committed extract tune folder carries a correction dev case `autotune/extract/cases/dev/correction-ruling/`: its `input.txt` contains an explicit denial-plus-truth sentence, and its parsed `gold.json` expects **both** a correction (the ruled-false fact) and a claim (the stated truth) on the affected subject, while a confident plain assertion elsewhere in the text yields a claim only — asserted by the `autotune` test package.
