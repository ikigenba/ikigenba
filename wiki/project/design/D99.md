# Decision 99 — Adopt the suite lint contract (`root project/design/D30.md`) at tier `strict`

**Decision.** This tree **adopts the suite lint contract** and registers at
tier **`strict`**: a committed one-line `wiki/.lint-tier` file containing
`strict`. The contract's content — the tier model and ratchet, the marker
semantics, the strict tier's rule list and thresholds, the
analyzers-skip-tests / gofumpt-everywhere policy, the pinned tool, and the
enforcement points — is the umbrella's and is not restated here; the enforcing
runner (`bin/lint`) and its proof live in `bin` (`[proof: bin]`), so this tree
carries no lint test of its own. This Decision owns only the local facts: the
marker exists, says `strict`, and the tree is clean at that tier.

Strict is the operator-chosen tier for this tree. Wiki's entry tier is `off`
(no marker), and the operator promotes it directly to `strict` in a single
upward step of the ratchet (`root project/design/D30.md`), which orders tiers
`off → cheap → strict` and never reverses but does not require halting at each
rung. Unlike a pure marker flip, reaching a clean strict run here requires
first resolving a body of findings — formatting, unused symbols, staticcheck
simplifications, and the strict-only complexity and judgment items — all
internal, fixable without changing any exported signature or seam; the adoption
phase carries that work, and the marker flip lands only once the tree is clean
at strict.

**Rejected.**

- *Relying on silence-is-conformance with no local Decision.* Silence covers
  conforming to a contract's ambient semantics; registering at a tier is an
  affirmative act (a committed marker plus a conformance obligation) and gets
  its own visible citation-is-adoption Decision, the same treatment other
  suite-level contract adoptions in this tree receive.
- *Remaining at `off`.* Off was this tree's entry state; the operator promotes
  to strict. Staying at off would leave the whole gate vacuous — findings
  reported but never enforced — while every peer tree in the suite is enforced.
- *Staging through `cheap` first (two phases).* Considered and rejected: a
  `cheap` marker would be an intermediate state immediately superseded by
  `strict`, so it would never appear in this current-statement design and would
  only add a second seal and build-loop pass to reach the tier the operator
  wants now. The direct `off → strict` step is valid under the ratchet and
  matches the single-Decision shape every peer tree carries; the build loop
  still resolves the cheap-tier findings on the way, since strict includes
  cheap.
- *Minting local ids for the marker or the clean state.* The behaviors are
  the runner's, proven in `bin`; the local obligation is structural and its
  proof is the phase's deterministic exit condition.

**Verification.** A structural decision: no ids minted, none cited — the lint
contract carries no per-service ids (`root project/design/D30.md`, Rejected:
*Per-service proof ids*). The checkable local facts are the phase's:
`wiki/.lint-tier` contains exactly `strict`, and `bin/lint wiki`
(run from the repo root, a read-only check over this tree) exits 0.
