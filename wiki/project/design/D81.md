# Decision 81 — Suggested pages: the scope's seven newest subjects on every scope home

**Decision.** Every scope home — private and public tier alike — lists the
scope's **seven most recently added subjects** under a mono-label heading
**Suggested pages**, newest first. This one list is the landing foothold on
both tiers; it **replaces** both prior home lists — the private tier's orphan
index (its Decision retired with this one) and the public tier's browse-all
subject index (D78, rewritten). Search reaches everything regardless of
inbound links, so neither orphans nor a full enumeration earn a place on the
landing page.

- **Recency = ULID order.** Subjects carry no created-at column; their ids are
  ULIDs (`internal/ids`), time-sortable by construction. "Seven most recently
  added" is exactly: the scope's subjects ordered by `id DESC`, `LIMIT 7`.
  No schema change.
- **The seam.** `internal/web`'s home-list dependency becomes:

  ```go
  // RecentLister lists a scope's most recently added subjects, newest first,
  // for the scope home's Suggested-pages section.
  type RecentLister interface {
      Recent(ctx context.Context, scope string, limit int) ([]SubjectRef, error)
  }

  // SubjectRef is a home-list entry: the mount-relative href tail, the
  // display name, and the subject's type for the row's type tag.
  type SubjectRef struct { Href, Name, Type string }

  func WithRecentLister(l RecentLister) Option
  ```

  It replaces `OrphanLister`/`WithOrphanLister` (deleted, along with the
  orphan query in `internal/wiki` and its tests). The adapter in
  `cmd/wiki/main.go` runs the `id DESC` query scope-bounded (D74 wall). The
  handler always calls it with limit **7**.
- **Rendering.** Below the question form: an `<h2>`-level mono uppercase
  label `Suggested pages`, then a hairline-ruled list — one row per subject,
  the name as the subject link (`subject/<type>/<slug>`, resolving through
  the page's tier+scope `<base>`, D76) on the left and the subject's type
  (`entity`/`event`/`concept`, mono uppercase) right-aligned on the same row.
- **Empty scope → no section.** When the scope has no subjects the whole
  section is omitted — no heading, no list markup; the question form and the
  shell remain. No empty-state copy.
- **Tier neutrality.** The section renders identically on both tiers (hrefs
  differ only through the tier's `<base>`); the public tier's visibility wall
  is untouched (D76), and the public tier serves the full ask experience
  (D78).

**Rejected.**
- **Keeping the orphan index (subjects with zero inbound mentions)** — an
  agent-introduced curation view the operator never asked for; orphan pages
  are exactly as findable by search as linked ones, and the orphan machinery
  (the single-pass mention scan) exists only to feed it. Retired outright.
- **Keeping the public tier's browse-all index** — the operator pinned one
  landing design for every scope: the seven newest. Keyword search remains
  the public enumeration path.
- **A `created_at` column instead of ULID order** — a migration to duplicate
  information the id already carries.
- **A configurable list length** — a knob nobody asked for; the operator said
  seven.

**Verification.** Real temp SQLite behind the adapter query (ordering, limit,
and the scope wall are engine properties), driven through the web handler:

- R-HJU8-XYZQ — **Seven newest, newest first, typed and linked.** With eight
  subjects inserted into one scope in a known order, its private-tier home
  renders a Suggested-pages section of exactly the **seven newest in
  insertion-descending order** — the first-inserted subject absent — each row
  carrying the subject's name as a link whose href is its
  `subject/<type>/<slug>` tail and the subject's type as its tag.
- R-HL25-BQQF — **The list honors the scope wall.** With subjects in two
  scopes, scope A's home lists only A's subjects — none of scope B's names
  appear anywhere in A's home markup.
- R-HMA1-PIH4 — **An empty scope omits the section whole.** For a scope with
  no subjects the home renders the question form but contains no
  Suggested-pages heading and no list markup — the section is absent, not
  rendered empty.
- R-HOPU-H1YI — **The public tier gets the same list, not a browse index.**
  A public scope's public-tier home renders the same seven-newest
  Suggested-pages section (subject links resolving inside
  `/public/{scope}/`), and does **not** render the retired browse-all index:
  with eight subjects, the oldest appears nowhere in the public home markup.
