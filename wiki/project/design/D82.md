# Decision 82 — Scope instructions: an operator-authored preamble on every inference call

**Decision.** Each scope carries one free-text **`instructions`** field — operator-authored standing context for how that scope's content is to be interpreted ("this scope is a fictional world; its timeline is in-world; never anchor its dates to the real world"). When non-empty, the text is injected into the **System** message of **all five completion stages** serving that scope — `extract`, `match` (D97; its composed-form id lives there), `compile`, `ask-subject`, `ask-synthesis` — as a delimited block appended after the stage's base prompt. Empty (the default for every scope, `default` included) means **no block at all**: the System is byte-identical to the base prompt, so the existing captured-system ids (D6 R-9W1T-D75P, D7 R-9YHM-4QN3, D36 R-A0XE-WA4H, D9 R-9ZPI-IIDS) keep pinning the no-instructions form and this Decision owns the composed form. The `/embed` calls carry no system and are untouched.

## Storage — one additive migration

A new timestamped migration (`bin/create-migration wiki <name>`) adds the column **additively** — production scopes rows hold live data and are preserved, never rebuilt:

```sql
ALTER TABLE scopes ADD COLUMN instructions TEXT NOT NULL DEFAULT ''
  CHECK (length(instructions) <= 4000);
```

The cap is a **product constant: 4,000 characters** (Unicode code points, the D7 convention — `utf8.RuneCountInString` in Go, `length()` in SQLite). The `CHECK` is the backstop; the store enforces the same limit with a typed error before the write.

## The seam

```go
// internal/wiki — extends the D74 registry store.
type Scope struct { Name, Visibility, Instructions string; CreatedAt int64 }

const InstructionsCharCap = 4000

// SetInstructions stores text byte-exact (no trim, no normalization); "" clears.

// utf8.RuneCountInString(text) > InstructionsCharCap (nothing stored).

// ComposeSystem returns base unchanged (byte-identical) when instructions is
// empty; otherwise base + "\n\n" + the wrapper line + "\n" + instructions.
func ComposeSystem(base, instructions string) string
```

The wrapper line — the precedence contract, stated once here and nowhere in any base prompt — is exactly:

```
Scope instructions (these override the general rules above where they conflict):
```

Base prompts stay self-contained and carry **no** deference clauses; the wrapper's precedence sentence is the whole conflict-resolution mechanism.

**Threading.** Instructions are fetched from the registry **once per unit of work** and passed to the stage calls, which compose the per-call `CallSite` System via `ComposeSystem` (the site's static `System` remains the base prompt; composition happens at call time):

- The **worker** reads the job row's `scope` (D74), loads that scope's instructions at job start, and passes them to the extract call, every match call, and every compile call of that job's pipeline (merge-triggered match and compile calls included — they run under the merge job's scope the same way).
- **`ask.Asker.Ask`** loads the scope's instructions once per ask and applies them to both the `ask-subject` and `ask-synthesis` calls.

A snapshot per job/ask is deliberate: an instructions edit mid-job does not change that job's calls, and takes effect on the next unit of work.

## The MCP verb

One new verb, **`instructions`** — a get/set property accessor (surface grows to twenty tools; supersessions below):

| input | behavior |
|---|---|
| `{scope (req), action:"get"}` | returns `{scope, instructions}` (empty string when unset) |
| `{scope (req), action:"set", text}` | stores `text` byte-exact (empty string clears), returns `{scope, instructions}` as stored |

- `action` is a **required** property with a two-value `inputSchema` `enum ["get","set"]`; an out-of-set value is a clean error naming the set. `text` is an optional string property; `set` without `text` present is a clean error; `text` on a `get` is ignored.
- An unknown scope is the typed `scope_not_found` error (D75 form, pointing at `scopes`). Over-cap text is a typed **`instructions_too_long`** error naming the 4,000-character limit; nothing is stored.
- The `scopes` list result is **unchanged** — the `get` action is the read path (operator's call: the smaller surface).
- The tool description (and the guide) state the remediation contract plainly: instructions apply to **future** inference only; already-ingested content is re-interpreted by re-running its jobs (`rerun`, D14) — there is no bulk verb.

**Out of autotune.** Scope instructions are operator **data**, not a tuned asset: the tune folders (D71) exercise the base prompts only, no folder exists for the wrapper, and no case carries an injected block. The tuner's system-under-test remains the base prompt, matching the serving shape of every scope without instructions.

**No web surface.** Instructions are read and written over MCP only; no web page displays or edits them.

**Rejected.**
- **Per-stage instruction fields** — config surface nobody would differentiate; the operator authors facts about the corpus, not per-pipeline-stage prompting.
- **Ask-only injection** — the observed corruption (a narrative's "130 years ago" anchored to the ingest date) happened at extract; the minting stage needs the context most.
- **Deference clauses woven into the base prompts** ("unless scope instructions say otherwise") — couples every tuned prompt's wording to a feature most scopes never use; the wrapper's single precedence sentence is the contract.
- **Separate `scope_set_instructions` + `instructions` in `scope_create`/`scopes`** — three surface touches where one verb suffices; the operator explicitly chose the smaller MCP area. (D75's rejection of a `scope <action>` mega-verb targeted heterogeneous actions; get/set of one field is a cohesive accessor.)
- **Presence-based dispatch (`text` present ⇒ set)** — makes "clear" ambiguous with "get"; the explicit `action` enum keeps both verbs' meanings exact.
- **Unbounded text** — rides every inference call in the scope; unchecked growth taxes each call and can drown the base prompt. 4,000 characters is ample standing context and an order of magnitude below competing with the base prompts.
- **A scope-wide bulk re-run verb for remediation** — saves a handful of calls but needs its own partial-failure and queue-flooding design; per-job `rerun` already replaces claims atomically (D14 R-0YGF-60EG).
- **Rebuilding the scopes table in the migration** (the D74 pattern) — D74's rebuild predated live data; scopes rows are now production state and the column is purely additive.
