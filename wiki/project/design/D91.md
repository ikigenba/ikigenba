# Decision 91 — The prompts seam proven against the real binary (composed)

**Decision.** The completion-queue wire contract gets one proof that no mock can fake: a **composed-layer** test (vocabulary per `root project/design/D23.md`, adopted by D73) that builds the sibling **prompts binary from the workspace**, boots it for real, and drives wiki's own `internal/llm` client against it. Every other inference test in this tree scripts a `httptest` server *playing* prompts (D5's stated substrate) — which is exactly why the 2026-08-11 seam break shipped: each tree's mock was faithful to its own reading of the contract, wiki's real bytes never met prompts' real decoder before production. This Decision makes that meeting part of the default gate.

**Mechanism.** A test in `internal/llm` (file named for the seam, e.g. `seam_composed_test.go`, ordinary build tags — this is the default gate, not the live layer):

1. **Build**: `go build -o <t.TempDir()>/prompts prompts/cmd/prompts`, run from the repository root so the root `go.work` resolves the sibling module (wiki's declared GOWORK mode is workspace; no wiki `go.mod` edit, no import of prompts packages — `internal/` walls hold, the binary is the interface).
2. **Boot**: `PROMPTS_DB_PATH=<t.TempDir()>/prompts.db`; run `migrate`, then `serve --port <free loopback port>`; wait for the port to accept; kill the process and delete the dir on cleanup.
3. **Drive**: point `llm.New` at the ephemeral base URL and exercise the wire contract with wiki's real request shapes — an object-shaped `Context` exactly as the D4 pipeline sends it. No provider key is set and none is needed: Ensure validates and stores without executing, so items rest `queued`; the contract under proof is acceptance + echo + idempotency, not inference.

**Error surface.** A build or boot failure (toolchain error, port never accepting, process exit before ready) **fails the test loudly** with the captured stderr — never a skip: the sibling tree is part of this mono-repo checkout and the Go toolchain is the suite's one stated precondition, so absence is a broken checkout, not an environment to tolerate. Timeouts are bounded (a few seconds to accept) so a wedged boot fails fast.

**Ordering note (non-contractual).** This proof is only as current as the checked-out sibling: it exercises whatever `prompts/` sits in the working tree. That is the point — drift between the trees fails the gate *here*, at build time, instead of in production.

**Rejected.**
- **Trusting the two trees' hermetic suites to compose** — the exact failure mode this Decision answers: both suites were green while every ingest 400-ed and every ask died, because each side's mock accepted what its own tree sent. A claim that hinges on a sibling's real decoder is not verified by a stub (the ikispec substrate rule).
- **Putting the proof in the live layer** (`-tags live`, `WIKI_LIVE_PROMPTS_URL`) — would have caught this only at deploy verification, after the build loops declared both trees done. The seam burned us in the default gate's blind spot; the proof belongs in the default gate. (The live `/embed` smoke R-15NY-IF46 keeps its place — it needs a *provisioned* prompts with real keys; this test deliberately needs neither.)
- **A shared contract-test package or fixture corpus consumed by both trees** — cross-tree test plumbing with two owners, drifting exactly like the prose did; the built binary is the one artifact that cannot disagree with itself.
- **Asserting terminal-state partition isolation here** (an ask item never surfacing in the pipeline inbox with both terminal) — needs executed items, hence provider keys, hence the live layer. The partition chain is already closed hermetically link by link: wiki sends distinct consumers (R-UCLK-JDHN), and prompts' own suite verifies that its inbox filters by consumer and its idempotency scopes to `(consumer, key)` (its D29 Verification list).

**Verification.**
- R-UF1D-AWZ1 — Against the freshly built and booted real prompts binary, the client's `Ensure` of a pipeline-shaped request whose `Context` is a JSON **object** is accepted (a new item, id non-empty, status `queued`), and a second `Ensure` with the same key returns the **same** id without creating new work (asserted via the real binary's responses, no mock anywhere).
- R-UG99-OOPQ — `Get` against the real binary returns the item's `Context` **byte-identical** to the serialization the client sent (compared as raw bytes, not after a decode/re-encode round trip).

**Testing.** The Decision is its own test plan; the two ids above are the composed layer's newest members and run in the default gate (`go test ./...`).
