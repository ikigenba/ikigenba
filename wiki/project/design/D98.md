# Decision 98 — The corrections read surface: labeled kinds and visible suppression on `claims`, and the guide

**Decision.** Suppression must be inspectable or a wrong correction is undetectable — so the **`claims` tool shows everything, labeled**, while every prose surface stays clean. No new MCP verb: the tool membership (D10 R-MUQ4-K1JS, nineteen verbs) is unchanged, because corrections enter by `ingest` and are undone by newer prose or `rerun` — there is nothing to add a verb *for*.

## The `claims` result, extended in place

The per-item shape (D10, paginated per D16) gains three fields:

```
{id, kind, text, job, suppressed, suppressed_by?}
```

- `kind` — `claim` or `correction` (D96), on every item.
- `suppressed` — boolean, on every item: `true` iff a **live** correction holds an edge to this row (D96 `Effective`'s `suppressedBy`), so an overruled correction shows `suppressed: true` exactly like a refuted claim.
- `suppressed_by` — present only when `suppressed`, the live suppressing correction row ids. Claim ids are already the tool's public row handles (D10); no other identifier is introduced, and the no-internal-subject-id guarantee is unchanged.

A correction's own coverage is readable from the same list (its targets carry it in `suppressed_by`); no separate edge-listing verb. The D61 output schema for `claims` is extended to declare the three fields.

**Prose surfaces are untouched.** `page`, `ask`, and the whole web surface read compiled pages, which are already built from the effective set (D97) — a pure denial leaves no trace in prose, a truth-carrying correction contributes its truth as an ordinary claim, and this Decision adds nothing to any of them.

## The guide and instructions text (D57 pattern)

The embedded guide document and the `initialize` `instructions` text gain the corrections model, stated for a prose-only user: state facts by ingesting; phrase a correction as an explicit ruling ("X is false", "contrary to earlier records…") — plain assertions merely coexist as conflicting accounts; a correction suppresses matching claims whenever they were or are ingested; corrections conflicting with corrections resolve by ingest order (latest ruling wins — fix a wrong correction by ingesting a newer statement of the fact); `claims` shows what is suppressed and by what; `rerun` re-digests a document under the current standing corrections. D57's two-places-only guide-pointer rule is unchanged.

**Supersession (edited in place).** D10's `claims` row and R-04HB-QM7T now describe the extended item shape; this Decision owns the new fields' behavior ids.

**Rejected.**
- **Hiding suppressed rows from `claims`** — makes a false-positive match (a wrongly killed true claim) undetectable; visibility is the safety valve the whole feature leans on.
- **A `corrections`/`retract` verb** — the settled interface is prose-only; a mechanical verb reintroduces storage vocabulary the user was promised not to need.
- **Surfacing suppression on the web subject page** — the web is the reading surface for compiled prose; the audit ledger is an operator/agent concern and stays on MCP.
- **A "Corrections" section in page prose ("earlier reports of X were erroneous")** — memorializes noise and drifts the page toward its own editing history; the falsehood's absence is the feature.

**Verification.**
- R-7WEF-1QA2 — Through the assembled MCP handler over a real store holding a claim, a live correction suppressing it, and an overruled older correction: every `claims` item carries `kind` and `suppressed`; the refuted claim carries `suppressed:true` with `suppressed_by` naming exactly the live correction's id; the overruled correction carries `suppressed:true` naming its overruler; unsuppressed items carry `suppressed:false` and **no** `suppressed_by` key; and no item carries a subject ULID or any identifier beyond `id`, `job`, and `suppressed_by`'s row ids. The declared output schema lists the three new fields.
- R-7XMB-FI0R — The embedded guide document describes the corrections model (prose-only entry, explicit-ruling phrasing vs conflicting accounts, suppression of matching claims regardless of order, latest-ruling-wins between corrections, `claims` as the suppression ledger, `rerun` re-digesting under standing corrections), the `initialize` `instructions` text mentions corrections, and no tool description other than `guide`'s own points at the guide (D57 rule preserved).
