# Decision 96 — Statements: claims and corrections, the suppression record, and the effective claim set

**Decision.** A document's extracted statements come in **two kinds**: a **claim** (an ordinary assertion — the existing concept, unchanged) and a **correction** (a statement that rules some asserted fact false). Corrections are **durable, standing rows stored in the `claims` table** under a `kind` discriminator, so they inherit every existing behavior for free — job provenance, rerun replacement (D14), merge repoint (D26), per-subject queries, scope walls (D74). A new **`suppressions`** table records which rows a correction covers. The **effective claim set** — what compile (D7) and every page is built from — is a pure function of a subject's rows and edges, computed in Go. This Decision owns the storage, the edge invariants, and the effective-set seam; how edges are *judged* (the match stage) is D97; the read surface is D98.

## Storage — one additive migration

One new timestamped migration (`bin/create-migration wiki <name>`; live rows are production data and are preserved, never rebuilt):

```sql
ALTER TABLE claims ADD COLUMN kind TEXT NOT NULL DEFAULT 'claim'
  CHECK (kind IN ('claim','correction'));

-- suppressions — one edge per covered row. `correction` and `suppressed` are
-- claims.id values (the source is always a kind='correction' row; the target is
-- a claim, or a strictly-older correction). Suite style: no FOREIGN KEY.
CREATE TABLE suppressions (
  correction TEXT NOT NULL,
  suppressed TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (correction, suppressed)
);
CREATE INDEX suppressions_suppressed ON suppressions (suppressed);
```

Existing rows take `kind='claim'`. Edges die with their rows: any transaction that deletes claim rows (a re-run's replacement, D14; a job's terminal cleanup) deletes, **in the same transaction**, every `suppressions` row whose `correction` *or* `suppressed` names a deleted row. A dangling edge is unrepresentable in committed state.

## Assertion order and the edge invariants

**Ingest order is assertion order.** A row's rank is the pair `(created_at, id)` — both minted in the integrate commit, so rows land in job-completion order and the ULID breaks intra-commit ties. Two hard invariants on every edge:

- **The source is a correction.** A `kind='claim'` row never suppresses anything.
- **A correction→correction edge points strictly backward and never within one job.** The source outranks the target by `(created_at, id)` **and** carries a different `job` — a document cannot out-rank itself, and edges that only point backward make the liveness evaluation below a single well-founded pass. A correction→**claim** edge carries **no** order constraint: a ruling covers a matching claim whenever it was asserted.

`SuppressionStore.Insert` enforces both and returns the typed `ErrInvalidSuppression` on a violation (fail loud — a violating edge reaching the store is a programming error upstream; D97's mechanical filter is what keeps model output from ever presenting one).

## The effective claim set — a pure function

```go
// internal/wiki

const (
    ClaimKind      = "claim"
    CorrectionKind = "correction"
)
// Claim gains Kind (one of the two constants).

type Suppression struct { Correction, Suppressed string; CreatedAt int64 }

var ErrInvalidSuppression = errors.New("wiki: invalid suppression edge")

// Effective partitions one subject's rows under its edges.
// A correction is LIVE iff no live, strictly-newer correction holds an edge to
// it — evaluated newest-first over the (created_at, id) order, a single pass,
// well-founded because edges only point backward. A row is SUPPRESSED iff a
// live correction holds an edge to it. Returns the effective claims (kind
// 'claim', not suppressed — the ONLY input compile may see) and, for the read
// surface, every row's live suppressors (row id → suppressing correction ids;
// absent = not suppressed).
func Effective(rows []Claim, edges []Suppression) (claims []Claim, suppressedBy map[string][]string)
```

The chain semantics fall out of liveness: correction C2 suppressing C1 revives C1's targets; a still-newer C3 suppressing C2 makes C1 live again, re-suppressing them. No recursion depth to bound — the pass is one walk down the order.

```go
type SuppressionStore struct { /* db handle */ }
func NewSuppressionStore(db DBTX) *SuppressionStore
func (s *SuppressionStore) Insert(ctx context.Context, e Suppression) error              // idempotent (INSERT OR IGNORE on the PK); ErrInvalidSuppression on an invariant violation
func (s *SuppressionStore) ListBySubject(ctx context.Context, subjectID string) ([]Suppression, error) // edges whose correction row belongs to the subject

```

`ClaimStore` reads and writes `Kind`; its insert path defaults nothing in Go — the kind is always explicit at the call site.

**No new MCP verb, no operator-facing mechanics.** Corrections enter exactly like claims: by ingesting prose (D6 classifies). Nothing in this Decision is addressable by a user; ids stay internal except as the `claims` tool's existing public row handles (D98).

**Rejected.**
- **A separate `corrections` table** — every lifecycle behavior (rerun replacement, merge repoint, provenance, scope reach-through) would need a second implementation; a `kind` column inherits all of it, and the D26 precedent (`jobs.kind`) is exactly this shape.
- **Hard deletion of refuted claims** — destroys the forensic record and makes a wrong correction unrecoverable; suppression keeps every row inspectable and reversal a pure data change.
- **A `retracted` flag on the claim row instead of an edge table** — loses *who* suppressed *what* (the read surface's "suppressed by" and the revival semantics both need the edge), and a flag cannot express a correction being itself overruled.
- **Mutual/forward correction→correction edges with a resolution rule at read time** — reintroduces order-dependence ambiguity; backward-only edges make recency structural and the liveness pass trivially terminating.
- **Recomputing all edges on every ingest (full re-match, mirroring full recompile)** — re-litigates every settled judgment on every touch of the subject, making suppression state churn under model nondeterminism; incremental matching of new pairs (D97) keeps past rulings stable while the durable rows still permit a deliberate future re-judgment (re-run the correction's job).

**Verification.**
- R-74CQ-9083 — Applying the full migration set to a database whose `claims` table already holds rows leaves those rows present with `kind='claim'`, the column `NOT NULL` with the two-value `CHECK` (a direct INSERT with `kind='x'` is rejected), and an empty `suppressions` table with the declared columns and PK present. *(real temp SQLite via the appkit runner: seed pre-column shape, run, inspect)*
- R-76SJ-0JPH — `Effective`: given claims A, B and a live correction X with an edge to A, the returned claims are exactly `[B]` (A excluded, X never included — corrections are not claims), and `suppressedBy[A] == [X]` while B is absent from the map.
- R-780F-EBG6 — `Effective` chain revival: with X suppressing claim A, a newer Y suppressing X yields A **effective** (Y revived it) and `suppressedBy[X] == [Y]`; adding a still-newer Z suppressing Y yields A **suppressed** again (X is live once more) — both states produced by the same single-pass evaluation.
- R-798B-S36V — `SuppressionStore.Insert` returns `ErrInvalidSuppression` (nothing written) for an edge whose source row is `kind='claim'`, for a correction→correction edge whose source does not strictly outrank its target by `(created_at, id)`, and for a correction→correction edge whose two rows share a `job`; a correction→**claim** edge from an *older* correction to a *newer* claim is accepted (no order constraint on claim targets).
- R-7AG8-5UXK — A claim row round-trips its `Kind` through the store, and `DeleteForClaims` run inside a transaction deleting a job's rows removes every edge naming a deleted row as **either** endpoint, so a target of a deleted correction is effective again immediately after commit. *(real temp SQLite)*
