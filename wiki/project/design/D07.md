# Decision 7 — The compile stage (`internal/compile`): full recompile from claims, 12k cap enforced

**Decision.** Compile rebuilds one subject's page from its **complete claim set** — identity + claims only, **never a prior page body, never the source document**. This full-recompile-from-claims path structurally immunizes against generational drift (research §5) and satisfies the D4 anti-poisoning invariant. It deletes wiki.bak's incremental-merge, superseded/citation-preservation, and stale-note machinery.

```go
package compile

const PageCharCap = 12000 // product constant (D3); characters = Unicode code points (utf8.RuneCountInString ↔ SQLite length())

type Compiler struct { c *llm.Client; site llm.CallSite; maxTighten int; log *slog.Logger }
func New(c *llm.Client, site llm.CallSite, log *slog.Logger) *Compiler

// Compile rebuilds ONE subject's page from its COMPLETE claim set — identity +
// claims only, never a prior page body, never the source document. Guarantees a
// body of ≤ PageCharCap characters.
func (c *Compiler) Compile(ctx context.Context, s wiki.Subject, claims []wiki.Claim) (title, body string, err error)
```

Each ingest that touches a subject recompiles its whole page from all its claims (this job's + every prior job's), O(claims) per affected subject — fine for a personal wiki. No prior-page-body parameter exists, so the broken-telephone loop is impossible by construction.

**Prompt housing and the system/user split.** The compile instruction preamble lives as **`internal/compile/prompt.txt`**, embedded by the package (`//go:embed prompt.txt` → an exported `DefaultPromptInstructions`), and is sent as the site's **`System`** message; the **user message is only the rendered input** — the subject identity plus its **plainly rendered claim set** (claim texts only, **no job-id tags, no internal ids of any kind**) and, on a tighten retry, the corrective note. This matches the external tuning tool's call shape (research §13); the committed tune folder `autotune/compile/prompt.txt` (D71) starts as a plain copy with no mechanical tie.

**The compiled page is clean article prose.** A page body contains **no internal identifiers of any kind** — no bracketed `[job-id]` citation markers, no ULIDs, no database ids. Provenance is not the page's job: every claim row already carries the job it came from, inspectable via MCP `claims`; the page is the readable synthesis. The only markup ever layered onto page prose for a reader is the read-time subject linking (D58/D12), which is applied outside this package and is unchanged. (The prior inline-citation discipline was never an operator requirement and is retired; the compile prompt and the D72 compile scorer are trued to this contract.)

**Prompt content** (port wiki.bak's `DefaultMergePrompt`, simplified to phase 1):
1. **Task framing** — given ONE subject's identity + its complete claim set; rebuild the page from these claims only; never see prior pages or source documents.
2. **Fold / prose discipline** — flowing prose, never a bullet ledger; corroborating claims fold into one statement rather than repeat; on contradiction keep **both** statements in a marked "Conflicting accounts" section, never silently overwrite. The body contains **no identifiers, citation markers, or bracketed ids** — nothing but prose a person would write.
3. **Lead discipline** — the first paragraph states what the subject IS in **natural category terms** (a king, a fortress, a battle, a company…), never internal record vocabulary: the words `entity`, `concept`, and `event` are the wiki's internal type names and must not be used as the subject's category, and no database/ingest vocabulary ("subject", "claim", "record") may describe the subject either.
4. **Size cap** — the page **must not exceed 12,000 characters**; when claims overflow, compress lower-salience detail rather than truncate mid-thought; keep the lead.
5. **Output schema** — `{title, body}` (single page; no `superseded`, no `stale_notes`, no multi-page write-set).
6. **Worked example.**

**The id sanitizer — mechanical enforcement of clean prose.** The prompt forbids identifiers, but an LLM instruction is not a guarantee, so `Compile` also **strips residual citation markers mechanically**: after each candidate is parsed (and before the cap is measured), every bracketed ULID marker — `[` + a 26-character Crockford-base32 ULID + `]` — is removed from the body and the surrounding whitespace tidied (no doubled spaces, no space before punctuation left behind). Prose brackets that are not ULID markers are untouched. Belt and braces: the rendered input carries no ids for the model to echo, the prompt forbids them, and the sanitizer guarantees none survive.

**12k enforcement — three layers (closes the wiki.bak gap):**
- **Prompt instruction** (§4 above).
- **Go enforcement in `Compile`:** the D5 `validate` hook asserts title/body non-empty; then `Compile` measures `utf8.RuneCountInString(body)` (after the id sanitizer runs). If over cap → **recompile-tighter**: re-prompt with a corrective note ("page is N chars; hard limit 12000 — compress lower-salience claims, keep the lead") up to `maxTighten` times. If still over → **last resort: truncate at a paragraph/rune boundary ≤ 12000 and log a warning** (truncation is acceptable loss, never corruption of the durable claims/raw record). `Compile` thus never returns a body > 12,000 characters.
- **DB `CHECK(length(body) <= 12000)`** (D3) — the backstop that turns any escaped bug into a loud tx abort, not silent corruption.

**Call site** — the package owns its designed defaults and exposes them so wiring cannot silently drop them: `compile.DefaultCallSite()` returns `{Stage: "compile", System: DefaultPromptInstructions, Config: {Provider: "openai", Model: "gpt-5.6-luna", Effort: "low", MaxTokens: 16384}}` (`maxTighten` is a separate `New` parameter, default 2; overridable per D19's knobs). The old `Temperature: 0` / `Thinking: false` pins are gone — gpt-5.6 models take `effort`, not temperature (research §13) — and the default config carries neither field. The non-zero `MaxTokens` (D18) keeps a claim-heavy compile off the 4096 adapter default. **The composition root constructs the compiler from `DefaultCallSite`, never a bare `llm.CallSite{…}`** — the original drift was that bare construction, which ran compile at provider defaults. (Compile sets no `MaxParseRetries`; the robust `ExtractJSON` carve in D5 covers its parse path.)

**Rejected.**
- **Inline `[job-id]` citations in the page body** (the prior discipline, agent-introduced) — never an operator requirement; it leaked raw ULIDs into every human and agent read surface, and sentence-level tracing bought nothing the claims' own `job` provenance (D3, MCP `claims`) doesn't already answer. Clean prose is the contract; no render-time scrubbing shim compensating downstream.
- **Stripping the markers at web render time instead of at the source** — leaves the stored body dirty and every non-web surface (MCP `page`, `ask` context) showing ids; a permanent scrubbing shim for a discipline nobody wanted. The compile stage stops producing them instead (existing stored bodies are handled operationally: the operator wipes and re-ingests — no migration, no sweep).
- **Incremental merge into the prior page body** (wiki.bak) — the broken-telephone / generational-drift path; full recompile from claims is the immunizing choice (research §5).
- **`superseded` citation-preservation + set-difference accounting** — under full recompile, page content is a pure function of the current claim set, so nothing carries across versions to preserve (answers research §6 Q7).
- **`stale_notes` neighbor flagging** — lint machinery, deferred.
- **Multi-page batch compile** — bought cross-page coherence, but phase 1 has no inter-page links; per-subject compile is simpler and matches the D4 stage factoring.
- **Failing the job when the cap can't be met** — would make a claim-heavy subject permanently un-ingestable; truncating the lossy page (logged) is the better failure mode.

**Verification.**
- R-FQLB-QWS6 — `Compile` is invoked with subject identity + claims only and has no prior-page-body parameter (full recompile from claims; anti-poisoning).
- R-FT14-IG9K — `Compile` never returns a body exceeding 12,000 characters under any input.
- R-FU90-W809 — Given an over-cap candidate followed by a within-cap candidate, `Compile` returns the within-cap candidate (recompile-tighter loop).
- R-FVGX-9ZQY — Given only over-cap candidates, `Compile` truncates the final candidate to ≤ 12,000 characters at a boundary and logs a warning (last-resort path).
- R-9X9P-QYWE — `compile.DefaultCallSite()` carries `Provider "openai"`, `Model "gpt-5.6-luna"`, `Effort "low"`, `MaxTokens >= 16384`, and **no** temperature and **no** thinking field, and the compiler the composition root builds is constructed from it — the running compile stage is the designed configuration rather than provider defaults.
- R-9YHM-4QN3 — The captured `/complete` request for a compile call carries `system` equal to the embedded `internal/compile/prompt.txt` contents and a user message containing **only** the rendered subject identity + plainly rendered claim texts (plus, on a tighten retry, the corrective note) — the instruction preamble appears in `system` and nowhere in the user turn, and **no claim's job id (no ULID) appears anywhere in the user message**.
- R-VA32-HERT — **The id sanitizer: no bracketed ULID survives.** Given a scripted model reply whose body embeds bracketed ULID citation markers mid-sentence (e.g. `"…final days. [01KZMQ6RHDG1G7KKH0JNT6J48P] In his youth…"`), `Compile` returns a body in which a scan for `[` + 26-char Crockford-base32 ULID + `]` finds **zero** matches, the surrounding prose survives intact with tidied whitespace (no doubled spaces, no space before punctuation), and a non-ULID bracketed phrase in the same body (e.g. `[sic]`) is left untouched.
