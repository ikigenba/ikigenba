# Decision 83 — The ask response cache: in-memory, LRU, shared by both surfaces

**Decision.** Production `ask` is served through an **in-memory response cache** that fronts the D9 pipeline for **both** doors — the MCP `ask` verb (D10) and the web ask page (D44) — so a repeated question is answered from memory with no analyze/embed/synthesis calls, and concurrent duplicates of one question share a single computation. The cache is process-lifetime (a restart clears it; nothing persists), holds at most a configured number of answers (default **500**) evicted **least-recently-used**, and is dropped **per scope** whenever that scope's knowledge changes, so a served answer always reflects the scope's current pages. A cache hit is indistinguishable from a fresh answer: no marker, no timestamp, no change to the MCP result shape or `answer.tmpl` — the only observable difference is speed.

## The seam (`internal/ask`)

A decorator with the same call shape as `Asker.Ask`, wired once at the composition root:

```go
package ask

// Provider is the computation the cache fronts — satisfied by *Asker.
type Provider interface {
    Ask(ctx context.Context, scope, owner, question string) (Answer, error)
}

// ComputeTimeout bounds one detached miss computation.
const ComputeTimeout = 2 * time.Minute

type Cache struct{ /* mutex, map[key]*entry, LRU list, next Provider, cap int */ }

// NewCache fronts next with a response cache of at most cap answers.
// cap == 0 disables the cache entirely: Ask is a pure pass-through on the
// caller's own context — no storing, no coalescing. cap < 0 panics (broken
// invariant: config parsing rejects it at startup, D19 discipline).
func NewCache(next Provider, cap int) *Cache

// Ask serves scope+question from the cache. Miss: one detached computation
// runs next.Ask and, on success, stores the Answer. Concurrent identical
// asks join the in-flight computation instead of starting another.
func (c *Cache) Ask(ctx context.Context, scope, owner, question string) (Answer, error)

// Invalidate drops every stored and in-flight entry for scope. An in-flight
// computation still delivers to its waiters but its result is not stored.
// Never errors; unknown scope is a no-op.
func (c *Cache) Invalidate(scope string)
```

- **Key** — `sha256(scope || 0x00 || strings.TrimSpace(question))`. The trim is the only normalization: casing, inner whitespace, and punctuation stay significant ("exact question" semantics). `owner` and the web tier are **not** in the key — the answer content is identity-independent (D44) and tier-independent (D78); a public-tier ask and an MCP ask share one entry. At ≤ cap entries a SHA-256 collision is a non-concern.
- **LRU** — a hit moves the entry to most-recent; storing the cap+1-th answer evicts the least-recently-used one. Honest-empty answers (`Found:false`, D9's fixed sentence) are cached exactly like found answers — they are computed results, and the per-scope invalidation below is what un-sticks them when the corpus grows.
- **Coalescing** — the first asker of a missing key becomes the leader; identical asks arriving while it computes wait on the same in-flight entry and receive the same `Answer` (or the same error). One question, one computation, regardless of arrival interleaving.
- **Detached computation** — the miss computation runs on `context.WithoutCancel(leader ctx)` bounded by `ComputeTimeout`, so an abandoning caller (closed browser, timed-out MCP call) does not kill the computation for its waiters: it runs to completion, delivers to whoever is still listening, and fills the cache. `WithoutCancel` preserves context **values**, so the leader's chain id (D64) and origin attribution (D62) ride the detached calls unchanged; a waiter contributes no identity — the recorded computation is the leader's.
- **Errors are never cached.** When `next.Ask` fails (LLM error, parse failure, timeout), the leader and every waiter receive that error verbatim and **no entry is stored** — the next identical ask recomputes. A waiter whose own `ctx` is done before the result arrives returns its `ctx.Err()`; the computation itself is unaffected. `Ask` adds no error vocabulary of its own: it returns exactly what `next.Ask` (or the waiter's context) produces, including `ErrScopeNotFound` (D74), which — being an error — is likewise never cached.

## Invalidation — the cache follows the corpus

A scope's entries are dropped at every point that scope's knowledge changes, keeping the D-README promise that answers reflect the current pages:

- **Job integrate commit** — the worker calls the invalidator with the job row's scope after any successful integrate (ingest, re-run, and merge jobs alike — they share the D14 atomic commit).
- **Scope instructions change** — `ScopeStore.SetInstructions` (D82) invalidates the scope on a successful write: instructions alter the synthesis system prompt, so cached answers predate them.
- **Scope delete** — `ScopeStore.Delete` (D74) invalidates the scope, so a later re-created scope of the same name can never serve a pre-delete answer.

Plumbing: `wiki.Service` (for the worker's integrate path) and `wiki.ScopeStore` each gain an optional, nil-safe callback field `AskInvalidate func(scope string)`; the composition root sets both to `cache.Invalidate`. A nil callback is a no-op (tests and a disabled cache need no stub). Aborts, failed jobs, and reads trigger nothing — only committed knowledge changes do.

## Configuration

One manifest knob, D19 fail-loud discipline: **`ASK_CACHE_CAP`** — the maximum number of cached answers. Unset defaults to `wiki.AskCacheCapDefault = 500`; `0` **disables the cache** (pass-through, no coalescing — a useful operator position for small boxes and for debugging a suspect answer); a negative or non-numeric value is a **startup error**, never a silent fallback. `Config` gains `AskCacheCap int`; the manifest declares `ASK_CACHE_CAP` with default `500` alongside the existing ask knobs. Capacity is tunable because it is a box-sizing lever (corpus breadth × memory), not a behavior lever.

## Wiring

`cmd/wiki/main.go` builds `askCache := ask.NewCache(asker, cfg.AskCacheCap)` and hands **it** — not the bare `Asker` — to both consumers: the web handler's injected `Asker` seam (D42/D44) and the MCP `handleAskCall` dispatch (D10). Both surfaces therefore share one cache by construction; neither surface changes shape, template, or result schema. The bare `*ask.Asker` no longer reaches a handler in production wiring.

**Rejected.**
- **Async pending answers** (a miss returns a "computing…" state the caller polls). Changes the MCP `ask` contract for every first ask and forces a poll loop on agents; a first answer costs seconds. Block-on-miss keeps both surfaces' contracts and still gives instant repeats. Rejected by operator direction.
- **No invalidation (staleness until eviction/restart).** Under LRU the *popular* question is exactly the one that never evicts, so the cache would be most stale precisely where it is most used — quietly breaking the product's answers-reflect-current-pages promise. Rejected.
- **TTL instead of write-triggered invalidation.** Recomputes on a clock, not on actual change — stale before expiry, wastefully recomputed after it when nothing changed. Rejected.
- **Caching errors (negative caching).** Pins a transient failure for up to an entry's lifetime. An error is cheap to retry; a wrong cached answer is not. Rejected.
- **Normalizing the question beyond a trim** (case-folding, whitespace collapse, punctuation stripping). Silently equates questions the operator asked distinctly; "exact question" is the stated semantics and the trim only removes form-submission lint. Rejected.
- **Owner or tier in the key.** Partitions identical content per caller for no gain — the answer is identity- and tier-independent by prior design (D44/D78). Rejected.
- **`golang.org/x/sync/singleflight` for coalescing.** A new module dependency for ~30 lines the entry map already needs (the in-flight entry *is* the flight); Conventions keep the dependency list minimal. Rejected.
- **A web-only cache.** Leaves the MCP verb paying full price for repeats and splits one question's cost by door; the operator chose one shared cache. Rejected.
- **Fixed capacity constant** (the `ASK_BODY_BUDGET` pattern). Capacity is a genuine per-box tuning lever; the operator chose a knob. Rejected.
