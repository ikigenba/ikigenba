# Decision 44 — The ask result page (`GET /{$}` with `?q=…`) + the `MentionsIn` seam

> **Re-rooted by D76/D78.** The ask page serves **both tiers** (`GET /{tier}/{scope}/?q=…` — D78): `Ask` and `MentionsIn` take the path scope (D74), every absolute link composes with the tier+scope (D76), and `owner` is the pass-through `X-Owner-Email` value — present on the session-gated private tier, absent (empty) for a public-tier anonymous ask (D78 R-4RG8-11JM). Behaviors below otherwise stand.

**Decision.** When the root route (D42) sees a non-empty `q`, it calls `Asker.Ask(ctx, owner, q)` (D9) and renders `answer.tmpl`. `owner` is the nginx-supplied `X-Owner-Email` header (the session-gated request carries it, D47); `ask` is owner-scoped only for call recording — the answer content is the same read-only synthesis D9 already produces. The web adds **no** answering logic; it renders D9's `Answer` and decorates it with a two-column links footer (cited pages + mentions).

**Layout, top to bottom (`answer.tmpl`):** *(no "ask another question" link —
retired; the D80 header question form on every page, carrying the submitted
query ready to edit (R-2PEQ-PO71), is the re-ask affordance, and D80
R-2QMN-3FXQ asserts the anchor's absence)*
- **Answer prose** — `Answer.Text` is first passed through `Service.LinkifyMentions(ctx, text, webBase, "")` (D58 — the first occurrence of each named subject wrapped as an inline link to its absolute front-door URL; no own-subject on ask, so `excludeID == ""`), then rendered as **sanitized markdown HTML** via the D48 `md` template func (`{{ md .Answer.Text }}` over the linkified text), not an escaped paragraph, so a synthesized answer reads like an article (headings, emphasis, lists, tables) with its named subjects linked inline at first mention. goldmark renders the injected `[…](https://…)` as `<a>` and bluemonday passes the absolute https href. On `Found:true` this is the cited synthesis; on `Found:false` it is D9's fixed honest-empty sentence (plain prose, which names no subject, so linkify is a no-op and `md` round-trips it to a `<p>`). **Both render identically** — the honest-empty text is just the body; there is no separate "no results" branch or styling. The injection guard is D48's sanitizer (raw HTML/`javascript:` neutralized), not template escaping.
- **Links footer** — the **same quiet two-column `links` block the subject page uses (D45)**: one wrapper element (`class="links"`) holding two nav sections side by side, styled entirely by the existing D80 `.links` CSS (no new styles, no new classes). On the ask page the two columns are:
  - **Cited pages** (first) — the pages the synthesis drew on: `Answer.Citations` (D9), in D9's order, each a subject link `<a href="{{.Href}}">{{.Name}}</a>` whose `Href` is the **absolute front-door URL** for the citation's path (composed per call with the tier+scope subject base, D76/D59), `Name` the cited page's title.
  - **Mentions** (second) — the distinct subjects whose name or alias occurs in the answer prose (`MentionsIn`, below), each an absolute front-door subject link (D59), de-duplicated and path-ordered (D12 discipline).

  A nav is omitted when its list is empty; the **whole wrapper** is omitted when both are empty (e.g. honest-empty, which cites nothing and names no subject) — mirroring D45's symmetric omission. There is no "Mentioned by" column: an answer is ephemeral, nothing points *to* it (product decision). A subject named in the answer thus appears both inline (at first mention) and in the Mentions column, pointing at the identical absolute URL; a cited subject typically appears in both columns, and that duplication is intentional (the columns answer different questions: *what the answer drew on* vs *what the prose names*).

## The `MentionsIn` seam

The outbound footer is **every subject/alias occurrence in the prose** (the product call), not the citations — so it is `Mentions(answerText, allSubjectKeys)`, the pure D12 matcher. D12 loads `SubjectKeys` (subjects ∪ D25 aliases) only inside `PageWithLinks`; this Decision exposes that over arbitrary text as a new method on `wiki.Service`, reusing the exact D12 matcher with no new matching logic:

```go
// MentionsIn loads the current SubjectKeys (all subjects ∪ their D25 alias keys)
// and returns every subject whose name or an alias key occurs as a whole,
// hyphen/edge-bounded run (D12 Mentions) in text — rendered as web Refs
// (Href = "subject/<type>/<slug>", Name = canonical display name). A match via an
// alias key resolves to the CANONICAL subject (D12), so a folded short name in the
// answer links to the survivor. Read-only; no write path.
func (s *Service) MentionsIn(ctx context.Context, text string) ([]Ref, error)
```

The web handler's ask path injects this as a second capability beside `Asker` (a `Mentioner` seam, `MentionsIn(ctx, text) ([]Ref, error)`), plus a `Linkifier` seam (`LinkifyMentions`, D58) for the inline prose links, and the `cmd/wiki/main.go` adapter maps `wiki.Ref{Path,Name}` → web `Ref{Href: webBase + Path, Name}` — the **absolute** front-door URL (D59), not the former relative `"subject/"+Path`. Targets are de-duplicated and deterministically ordered (by path), matching D12's footer discipline.

**Why the Mentions column is not the citations.** `Answer.Citations` (D9) are only the pages the synthesis drew on; the product requires linking *every* subject/alias the prose names, cited or not. `MentionsIn(answerText)` is that set and reuses D12 exactly, so the answer footer and a page footer share one matcher and one alias semantics. The citations render in their **own** column beside it — the two lists overlap by construction and neither substitutes for the other.

**Read-only.** `Ask`, `MentionsIn`, and `LinkifyMentions` (D58) only read; the ask page mutates nothing (D9 `R-5X56-NF4O` holds; neither `MentionsIn` nor `LinkifyMentions` has a write path).

**Rejected.**
- **Mentions column derived from `Answer.Citations`.** Links only cited subjects, contradicting the product's "every occurrence of any subject/alias." The citations get their own column; the mentions stay `MentionsIn`. Rejected.
- **Unlabeled stacked lists** (the prior presentation: two bare navs separated by hairlines). A reader cannot tell what either list is; the subject page already solved this with labeled side-by-side columns, and two footer presentations for one site is gratuitous divergence. The ask page reuses the D45 `links` block verbatim. Rejected.
- **A distinct honest-empty page/branch.** D9 already returns a usable `Answer.Text` for the empty case; rendering it as the ordinary body keeps one template and one code path, and the omitted-when-empty footer falls out naturally. Rejected.
- **Re-implementing mention detection in the web layer.** Would fork D12's alias-aware matcher and risk drift. `MentionsIn` reuses it. Rejected.
- **Threading `owner` into the answer rendering.** The answer is identity-independent content; `owner` is only `ask`'s call-recording scope. The template reads no identity. Rejected.
