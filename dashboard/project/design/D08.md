# Decision 8 — System font stacks: no web fonts, no font files, no preloads

**Decision.** The dashboard renders in the **system font stacks the wiki
uses** — its pages must use exactly the same fonts as the wiki's read surface.
The vendored `ui/static/tokens.css` re-points the three font tokens:

```css
--font-display: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
--font-body:    system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
--font-mono:    ui-monospace, "SFMono-Regular", "Cascadia Code", "Liberation Mono", Menlo, Consolas, monospace;
```

Everything the self-hosted web fonts required goes with them:

- the four `@font-face` blocks in `ui/static/tokens.css` are deleted;
- the `.woff2` files under `ui/static/fonts/` are deleted (the directory goes);
- every `<link rel="preload" as="font" …>` in every template `<head>` is
  deleted.

System fonts contact no external origin, so the property the self-hosting
bought (no third-party fetch, no metadata leak) is preserved with zero font
bytes shipped, and the FOUT problem this Decision previously solved with
`font-display: optional` + preloads cannot occur at all — there is no web font
to swap to. All non-font token *values* in `tokens.css` are unchanged.

**Rejected.**
- **Keeping the self-hosted Space Grotesk / IBM Plex families** — contradicts
  the settled goal that every dashboard page uses exactly the wiki's fonts; it
  also keeps ~4 font files and FOUT machinery for a look the suite is moving
  off.
- **`@import`ing Google Fonts (the `design/tokens.css` source form)** — an
  external origin on the auth surface; rejected before, still rejected.
- **Keeping the woff2 files embedded "in case"** — dead bytes in every binary;
  a future web font is a fresh decision.
