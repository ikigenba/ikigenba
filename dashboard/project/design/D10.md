# Decision 10 — The shared shell: the wiki page frame on every dashboard page

**Decision.** The dashboard adopts the **wiki read-surface shell** — the same
bounding column, header, footer, typography scale, and list idiom the wiki
serves — as one shared frame (kept **dashboard-local** for now: the CSS and
markup are vendored in this tree, not a suite contract; promoting the shell to
a root contract is a separate future decision). The reference look is the
mockup set in the repo-root `design/mockups/` (authoring reference only — the
normative statement is this file). It is realized as:

- **One shell template partial** (e.g. `html/partials/shell.tmpl` defining
  `shell_head` / `shell_header` / `shell_footer`) in the shared
  `template.ParseFS` set, so every page carries the identical frame and a
  broken shell fails startup. Each shell page's template composes: head →
  header → its own `<main>` body → footer (D9).
- **The bounding column.** `header`, `main`, and `footer` share one centered
  column: `max-width: var(--layout-max-width)` (1120px), horizontal padding
  `var(--layout-gutter)` (32px). `html` sets `scrollbar-gutter: stable` so the
  column never shifts between scrolling and non-scrolling pages. The page is a
  flex column with `main` flexed, so the footer sits at the bottom of short
  pages.
- **The header** (hairline bottom border, `--space-16` min-height): left to
  right —
  1. the **logo** (`<img src="/static/logo.png">`, height `--space-8`) linking
     to `/` — the wiki's logo asset, vendored into `ui/static/logo.png` and
     served by the existing `staticHandler`;
  2. three mono uppercase nav links in the wiki `.home` idiom:
     **Dashboard → `/`**, **Install → `/install`**, **Metrics → `/metrics`**;
     the link naming the current page carries `aria-current="page"` and
     renders in full text color (the others muted);
  3. right-aligned (`margin-left: auto`): the **sign-out** control — a
     bordered-neutral button (`--control-h-sm`, mono uppercase,
     `--color-border-strong` border) on the `POST /logout` form — then the
     **monogram avatar** (D5's identity affordance) as the last element. The
     avatar keeps its hover darkening to `var(--accent-700)`.
- **Session-less shell pages omit the identity controls.** A shell page
  rendered without an owner in hand (the OAuth authorize chooser, D29's
  provider choice) wears the same column, logo header, and footer but renders
  **no nav links, no sign-out, and no avatar** — chrome that needs a session
  has nothing true to say there.
- **Which pages wear the shell.** The logged-in home (`/`), `/install`,
  `/metrics`, `/profile`, the PAT show-once page (`pat_created`), and the
  OAuth authorize chooser (session-less form). The **logged-out login page
  does not** — its centered sign-in wall is unchanged (D7).
- **Typography scale.** Page bodies use the wiki scale: section headings are
  display `<h2>` (`--text-h2-*`, 30px), subsections display `<h3>`
  (`--text-h3-*`, 22px); mono uppercase label style is reserved for
  micro-labels (nav links, row metadata, snippet sub-labels, the footer). No
  page renders a display `<h1>` — the header's nav names the app; each page
  opens with its section `<h2>`. The profile page's sections accordingly
  render as `Profile` (`<h2>`) with `Personal access tokens` and
  `Connected MCP clients` as `<h3>`, and the profile page renders **no** live
  indicator next to the grants heading (the SSE refresh itself is unchanged,
  D4).
- **Metrics panels.** The metrics page's four charts (D14/D15, unchanged in
  mechanism) render inside a two-column grid of flat bordered panels
  (`--color-surface` background, hairline border, one panel per chart),
  stacking to one column under 768px.
- **`app.css` is rewritten** to this shell idiom (the mockups'
  `dashboard.css` translated in). The sign-in wall's existing rules are kept
  (D7 untouched); dead rules for the removed chrome (`.banner`, `.wordmark`,
  `.section-head`, tiles, `.list`/`.row` surface chrome) are deleted.

**Rejected.**
- **Promoting the shell to a root suite contract now** — settled: local now;
  contract once proven across more than two services.
- **Sharing CSS/template files with the wiki tree** — cross-tree file reuse
  breaks the scope boundary and couples deploys; the shell is vendored, like
  `tokens.css` already is.
- **A text wordmark instead of the logo image** — the wiki header leads with
  the logo; matching it is the point.
- **Keeping the display `<h1>` page title under the header** — with the brand
  in the header and one section per page, the big title restated the nav and
  pushed content down; section-scale headings carry the page.
- **A hamburger/overflow nav** — three links fit the header at every width the
  column supports.

**Verification.**
- R-VOCU-SJPQ — The logged-in `GET /`, `GET /install`, `GET /metrics`, and
  `GET /profile` (live session) each render the identical shell header: a
  logo `<img>` whose `src` is `/static/logo.png` wrapped in a link to `/`
  (and `GET /static/logo.png` itself returns `200` with a non-empty body),
  nav links `Dashboard`→`/`, `Install`→`/install`, `Metrics`→`/metrics`,
  a `POST /logout` sign-out control, and the monogram avatar as the last
  identity element.
- R-VQSN-K374 — On each shell page, exactly one header nav link carries
  `aria-current="page"`, and it is the link naming that page (`/`→Dashboard,
  `/install`→Install, `/metrics`→Metrics; `/profile` has none — the avatar,
  not a nav link, names it).
- R-VS0J-XUXT — The served `GET /static/app.css` sizes `header`, `main`, and
  `footer` with `max-width: var(--layout-max-width)` and
  `var(--layout-gutter)` horizontal padding, and sets
  `scrollbar-gutter: stable` on `html`.
- R-VT8G-BMOI — The PAT show-once page (the `POST /pat` confirmation, live
  session) renders the full shell (header with identity controls + footer);
  the OAuth authorize chooser renders the shell column with the logo header
  and footer but **no** nav links, **no** sign-out, and **no** avatar.
- R-VUGC-PEF7 — `GET /metrics` (live session) renders its four charts inside
  a panels grid: four panel containers each holding one chart, styled by the
  served `app.css` as a two-column grid of bordered surface panels.
- R-VVY7-ADWO — The served `app.css` defines a hover state for the avatar
  that sets its background to the darker accent (`var(--accent-700)`),
  giving the icon-only link a visible clickable affordance.
