# Decision 36 — Env-channel conformance: composed manifest root, manifest-surfaced authn knobs, and customer-data routing

**Problem.** Three of the dashboard's configuration values sit outside the
suite's four configuration channels (root `project/design/D21.md`): the
manifest/inventory root and the metrics disk-probe path fall back to a
compiled-in `"/opt"` (six literals across `cmd/dashboard/main.go`,
`internal/server/server.go`, `internal/metrics/collector.go`, and
`internal/metrics/readers.go`) — the exact box-path-literal pattern the root env
contract now forbids; and the two authn rate-limit knobs are env reads with code
defaults that no production channel states, so an operator has no supported way
to see or set them. `DASHBOARD_ADMINS` likewise has no declared channel.

**Decision.** Bring every dashboard value into its channel, per the routing
contract at root `project/design/D21.md`.

1. **The manifest root and disk path compose from `IKIGENBA_ROOT`** (root
   `project/design/D11.md`, adopted by D34). `cmd/dashboard/main.go` resolves
   the root **once**, by the contract's ladder:

   ```go
   // resolveManifestRoot: explicit override → IKIGENBA_ROOT → dev fallback.
   func resolveManifestRoot(getenv func(string) string) string {
       if v := strings.TrimSpace(getenv("DASHBOARD_MANIFEST_ROOT")); v != "" {
           return v
       }
       if root := strings.TrimSpace(getenv("IKIGENBA_ROOT")); root != "" {
           return root // /opt on a box: manifests at <root>/*/etc/manifest.env
       }
       return "." // dev checkout: bin/start runs from the repo root, where
                  // <svc>/etc/manifest.env resolves; the .envrc export wins anyway
   }
   ```

   The composed value feeds every consumer: `registerRoutes` (whose current
   re-derivation `if manifestRoot == "" { … "/opt" }` is deleted — the root
   arrives composed and non-empty), `server.Options.ManifestRoot`, and the
   metrics collector's `ManifestRoot` **and** `DiskPath` (the disk probe
   measures the volume backing the install root, so it takes the same composed
   value; dev fallback probes `.`).

2. **Internal packages stop re-defaulting — validate at the boundary, trust
   internal code.** `server.New` treats an empty `Options.ManifestRoot` as a
   constructor error (exactly like the missing-`CorrelationMinter` error above
   it), and its `Defaults to "/opt" when empty` doc line goes. The metrics
   `Config.withDefaults` drops its `ManifestRoot` and `DiskPath` arms, and the
   collector-worker constructor errors at startup when either is empty;
   `readers.readDiskFree` drops its `if path == "" { path = "/opt" }` arm
   (callers always pass the composed path). An empty root reaching an internal
   package is a programming error surfaced at construction, never a silent
   `/opt`. After this, **no `"/opt` string literal remains in the dashboard's
   production Go source**.

3. **The authn knobs surface in the manifest.** The `Spec` gains

   ```go
   ManifestExtras: []appkit.ManifestKV{
       {Key: "DASHBOARD_AUTHN_RATE_LIMIT", Value: "120"},
       {Key: "DASHBOARD_AUTHN_RATE_WINDOW", Value: "10s"},
   },
   ```

   and the committed `dashboard/etc/manifest.env` gains the same two lines
   after `PORT` (the adopted drift test R-8IAN-FB87 pins the byte agreement
   automatically — no new id is needed for that). The reads are unchanged
   (`config.EnvOrInt` / `config.EnvOrDuration` in `registerRoutes`): in
   production the launcher exports every manifest key, so the manifest line is
   what the process receives; the code defaults become dev fallback and must
   agree with the manifest's stated values.

4. **Customer-data routing recorded** (root `project/design/D21.md`, channel 2;
   parameter shape at root `project/design/D12.md`):
   - `DASHBOARD_ADMINS` (owner emails permitted to introspect any chain) is
     **customer data**: its channel is the app-config parameter, declared by
     the `.envrc` line form when an account first seeds an admin list
     (`~/.secrets/DASHBOARD_ADMINS`). Until seeded it is deliberately unset —
     no admins — and no other channel may carry it; in particular it never
     appears in the committed manifest.
   - `DASHBOARD_PUBLIC_BASE_URL` is a **dev-only override** (channel 4): its
     production value is the composed `cfg.AuthServer` (from
     `IKIGENBA_DOMAIN`), and a manifest line would restate a composed,
     account-varying value. It stays out of every committed file except the dev
     `.envrc`.

5. **Adoption of the box-path-literal guard.** This Decision adopts the root
   env contract's `[proof: per-service]` id **R-VKB6-SHHV** (root
   `project/design/D11.md`): the dashboard carries a source-scan test in
   `cmd/dashboard/main_test.go` that walks the dashboard's non-test `.go` files
   and fails on any `"/opt` string literal.

**Rejected.**
- *Keep the internal `/opt` fallbacks as belt-and-braces.* A silent fallback to
  a wrong-but-plausible box path is the exact failure mode the root env
  contract's fail-loud guard exists to prevent; defense-in-depth here is
  corruption-in-depth. Rejected for constructor errors.
- *Put `DASHBOARD_ADMINS` in `manifest.env`.* The manifest is committed and
  identical on every box; an admin list is per-account customer data. Rejected —
  channel 2.
- *Surface `DASHBOARD_PUBLIC_BASE_URL` in the manifest.* Its value embeds the
  account's domain — per-customer by construction — and production already
  composes it correctly from `IKIGENBA_DOMAIN`. Rejected.
- *A `".."`- or `os.Executable`-derived dev fallback for the manifest root.*
  The dev harness (`bin/start`) runs services from the repo root, so `.` is the
  checkout-correct fallback, and the `.envrc` explicit export remains the
  authoritative dev path either way; deriving from argv0 couples path policy to
  install location, the root contract's own rejected alternative. Rejected.

**Verification.**
- R-GBZ2-DNKQ — the manifest-root/disk-path resolution follows the ladder
  exactly: with `DASHBOARD_MANIFEST_ROOT=/x` set the resolved root is `/x`
  regardless of `IKIGENBA_ROOT`; with only `IKIGENBA_ROOT=/y` set it is `/y`;
  with neither it is `.` — never `/opt`. Substrate: unit test over the resolver
  with an injected `getenv`.
- R-GD6Y-RFBF — internal packages fail loudly on a missing root instead of
  defaulting: `server.New` with an empty `Options.ManifestRoot` returns an
  error (no server is constructed), and the metrics collector worker's
  construction with an empty `ManifestRoot` or `DiskPath` errors at startup —
  neither resolves to `/opt`. Substrate: unit test in `internal/server` (the
  metrics collector's matching guard is exercised alongside in `internal/metrics`).
- R-GEEV-5724 — with no environment set, the resolved authn rate limit and
  window equal the values stated in the committed `dashboard/etc/manifest.env`
  (parse the committed file, compare against the code's resolved defaults) — an
  edit to either side alone fails. Substrate: unit test in
  `cmd/dashboard/main_test.go` reading the committed manifest.
- Adopts **R-VKB6-SHHV** (root `project/design/D11.md`, `[proof: per-service]`)
  — no `"/opt` string literal in the dashboard's non-test Go source. Substrate:
  the source-scan test in `cmd/dashboard/main_test.go`.
