# Decision 43 — Antigravity is a fourth install-script agent

**Decision.** The `/install/<agent>` script surface gains a fourth literal
`agent` value, `agy`, registered at `GET /install/agy` on the existing
`handleInstall` seam. The human page presents this route as **Antigravity**
(D40); this Decision owns the script the route serves.

Unlike `claudeAgent`, `codexAgent`, and `grokAgent`, `agy` does **not** reuse
the shared `installScript` skeleton: Antigravity (the `agy` coding-agent CLI)
has no per-service `mcp add` / `mcp remove` command. It installs MCP servers as
a **plugin** — one directory holding a `plugin.json` manifest and an
`mcp_config.json` listing every server, imported in a single
`agy plugin install <dir>`. So `agy` owns its own script builder, producing the
plugin-install shape of the operator-provided `install-agy.sh`, templated over
the request's scheme/host and the live `MCP=true` inventory exactly as the other
three scripts are.

The served script, in order:

- **`#!/usr/bin/env bash`** then `set -euo pipefail`.
- **The missing-token guard** — `if [ -z "${IKIGENBA_TOKEN:-}" ]; then`, a
  three-step mint / export / re-run instruction block pointing at **this
  request's scheme and host** (the sign-in URL, the `~/.bashrc`
  `export IKIGENBA_TOKEN=...` line, and re-running the installer), then
  `exit 1`. `${IKIGENBA_TOKEN}` is written literally so the customer's bash,
  not the dashboard, evaluates it.
- **`echo "Installing N MCP"`** — `N` is the count of `MCP=true` inventory
  services.
- **A temp plugin dir** (`mktemp -d`, removed by a trap on `EXIT`) into which the
  script writes:
  - **`plugin.json`** — the fixed manifest
    `{ "name": "ikigenba", "description": "Ikigenba MCP tools" }`.
  - **`mcp_config.json`** — a `"mcpServers"` object with **one block per
    inventory service**, each already unrolled by the dashboard with the
    service's `mcpLocalName` and mount resolved (D5's helpers):

        "ikigenba_<svc>": {
          "serverUrl": "<scheme>://<host><mount>mcp",
          "headers": {
            "Authorization": "Bearer ${IKIGENBA_TOKEN}"
          }
        }

    the last block carries no trailing comma. `${IKIGENBA_TOKEN}` is left
    literal in the served bytes and expanded by the customer's bash when the
    heredoc runs, so the customer's own token is materialized into the temp
    `mcp_config.json` that `agy plugin install` imports; the temp dir (token and
    all) is removed on exit.
- **`agy plugin install "${TMP_DIR}"`** — the single import. On success the
  script prints `🟢 ikigenba_<svc>` for every service and counts each into `ok`;
  on failure it prints `🔴 ikigenba_<svc>` for every service (the per-service
  status reflects the one plugin-install result, matching `install-agy.sh`).
- **`echo "${ok} of N successfully installed."`** then `Done. Restart agy for
  the new MCP servers to load.`

Names and URLs are `mcpLocalName` / `mcpResourceURL` (D5's helpers) —
`ikigenba_<svc>` against `<scheme>://<host><mount>mcp`, the `Mount` value
carrying its trailing slash.

The route is public (no session) and `text/plain; charset=utf-8`, same as
`/install/claude`, `/install/codex`, and `/install/grok`. A failed
`inventory.Read` is `handleInstall`'s existing contract: HTTP 500, no script
body, no new named error. The visible agent word everywhere in the script and
the route is `agy`; only the human page (D40) reads **Antigravity**.

**Rejected.**
- **Forcing the shared `installScript` per-service `add`/`remove` skeleton** —
  `agy` exposes no `agy mcp add` / `agy mcp remove`; its only MCP-registration
  path is `agy plugin install` of a config directory. The skeleton's shape
  cannot be produced for it, so `agy` owns its own builder.
- **Serving `install-agy.sh` verbatim** — the file hardcodes
  `https://int.ikigenba.com` and a fixed fifteen-service list, wrong for any
  box that is not `int` and drift-prone as the inventory changes. The served
  script is templated over the request host and the live inventory like the
  other three.
- **Leaving `${IKIGENBA_TOKEN}` a single-quoted reference (Grok's shape)** —
  Grok's TOML expands `${VAR}` at load, so the reference survives; the
  Antigravity installer follows `install-agy.sh` and expands the token into the
  plugin config it imports. Matching Grok here would change the mechanism the
  operator supplied.
- **Using `Antigravity` as the route or in the script text** — the visible
  agent word stays `agy` (route `/install/agy`, `Restart agy`); only the page
  label is `Antigravity`, the same label/short-word split Claude Code already
  has.
- **A customer path other than `GET /install/agy`** — local operator scripts
  are outside this tree.

**Verification.**
- R-QFNA-KYOH — `GET /install/agy` with no session cookie, driven through the
  registered route table (`New` / `httptest`), returns `200` with
  `Content-Type` `text/plain` and a body that starts with `#!/usr/bin/env bash`.
- R-QGV6-YQF6 — That body, against a fixture of dashboard (no `MCP`) plus crm
  and ledger (`MCP=true`) requested as `https://int.ikigenba.com`, contains
  `echo "Installing 2 MCP"`, the manifest fields `"name": "ikigenba"` and
  `"description": "Ikigenba MCP tools"`, a `"ikigenba_crm"` block whose
  `serverUrl` is `https://int.ikigenba.com/srv/crm/mcp` and whose header line is
  `"Authorization": "Bearer ${IKIGENBA_TOKEN}"`, the matching `"ikigenba_ledger"`
  block, `agy plugin install`, `🟢 ikigenba_crm`, `🟢 ikigenba_ledger`,
  `if [ -z "${IKIGENBA_TOKEN:-}" ]; then`,
  `echo "${ok} of 2 successfully installed."`, and `Restart agy`; it does not
  contain `claude mcp`, `codex mcp`, `grok mcp`, or `--bearer-token-env-var`.
