# Decision 6 — `AGENTS.md` states the current page truth

**Decision.** The dashboard's standing scope rule that the apex `/` is a **single
hybrid page** that must **not** be split into a separate IAM console is **false**
— this change splits it — and `dashboard/AGENTS.md` states, in place, the truth
that replaced it: the apex serves **four** pages, one of which is the **metrics**
page, not a "telemetry" page. (`dashboard/CLAUDE.md` is a symlink to `AGENTS.md`;
editing `AGENTS.md` updates both.)

- **Remove** any bullet in `AGENTS.md` reading, in substance: *"Keep the apex `/`
  a single hybrid page. … Do not split it into a separate IAM console — that's
  product-scale breadth this scope rules out."*
- **State** the current truth: the apex serves the logged-out **login** page, the
  logged-in **landing/home** page (connect-your-agent install instructions + the
  clickable service list), the session-gated **profile** page holding
  personal-access-token and OAuth-grant administration (reached by clicking the
  owner's email), and the session-gated **metrics** page graphing the box's
  resource health. State that token/grant management lives on the profile page,
  **not** the landing.
- **The `internal/` package list must name `metrics`, never `telemetry`** — in
  this codebase that word now belongs solely to the suite's forensic record
  service, and a doc that still says otherwise sends the next reader to the wrong
  concept.
- **Doctrine:** docs state current truth — purge what the change falsified,
  rewrite in place, no archaeology, no "previously…" footnote. Touch only what is
  stale; leave the rest of the Scope section (bounded-breadth / production-depth)
  intact, as it is still true.
- This is a **build-loop step**, performed in the phase that realizes this
  Decision — not while authoring the design/plan docs. Code and docs evolve
  together, so the doc never describes a state that isn't built yet.

**Rejected.**
- **Leaving a stale rule and appending a contradicting note** — produces a doc
  that asserts both; the doctrine is purge + rewrite, not stack.
- **Leaving the page count at "three"** — the metrics page is a fourth apex page
  and has been since D11–D16; a count that is silently one short is the same
  class of stale claim as the hybrid-page rule it replaced.
- **Editing `CLAUDE.md` directly** — it is a symlink to `AGENTS.md`; the write
  goes through `AGENTS.md` (the refusal to write the symlink is expected).
- **Rewriting the whole Scope section** — only falsified statements change; the
  surrounding bounded-breadth posture is unaffected and must be preserved.

**Verification.**
- R-DB16-DOCS — `dashboard/AGENTS.md` contains neither the "single hybrid page"
  rule nor the "do not split … IAM console" rule, states the four-page truth
  (login / landing / profile / metrics, with token+grant management on the
  profile page), and its `internal/` package list names `metrics` with no
  occurrence of `telemetry` anywhere in the file. A text search for each stale
  phrasing finds nothing; a search for the four-page statement and for `metrics`
  finds them.
