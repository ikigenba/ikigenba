# Decision 6 — `AGENTS.md` states the current page truth, and a test holds it there

**Decision.** `dashboard/AGENTS.md` states the current truth about the apex web
surface, and that truth is **pinned by a test**, not by a one-time edit. The old
scope rule — that the apex `/` is a **single hybrid page** that must **not** be
split into a separate IAM console — is false; this design split it, and the doc
says so. (`dashboard/CLAUDE.md` is a symlink to `AGENTS.md`; editing `AGENTS.md`
updates both.)

The doc must state, and keep stating:

- The apex serves **four** pages: the logged-out **login** page, the logged-in
  **landing/home** page (connect-your-agent install instructions + the clickable
  service list), the session-gated **profile** page holding personal-access-token
  and OAuth-grant administration (reached by clicking the owner's email), and the
  session-gated **metrics** page graphing the box's resource health. Token/grant
  management lives on the **profile** page, **not** the landing.
- Neither the "single hybrid page" rule nor the "do not split … IAM console" rule
  appears anywhere in the file.
- The `internal/` package list names **`metrics`**, and the word **`telemetry`**
  does not occur anywhere in the file — in this codebase that word now belongs
  solely to the suite's forensic record service, and a doc that still says
  otherwise sends the next reader to the wrong concept.
- **Doctrine:** docs state current truth — purge what a change falsified, rewrite
  in place, no archaeology, no "previously…" footnote. Only falsified statements
  change; the rest of the Scope section (bounded-breadth / production-depth) stays
  intact, as it is still true.

**The proof is a Go test, because every other proof in this tree is.** Design's
*Conventions* declare one test command (`cd dashboard && go test ./...`) and one
place requirement-id tags live (files matching `*_test.go`). A claim proven only
by a human running `grep` has no such home: its id can never appear as a tag, so
the coverage check counts it as unrealized forever, and nothing re-checks the doc
after the phase that wrote it. The check itself is mechanical — fixed substrings
present, fixed substrings absent — so it is an ordinary table-driven Go test:
**`cmd/dashboard/docs_test.go`**, `package main`, reading `../../AGENTS.md` from
disk. That is the same substrate the committed-manifest tests in
`cmd/dashboard/main_test.go` already use for a committed file, and it costs the
suite nothing: no network, no DB, no build.

The doc edit itself is **already done** — `AGENTS.md` states the four-page truth
today. What remains is giving the claim its standing, executable proof so the doc
cannot silently drift back.

**Rejected.**
- **A shell/`grep` verification performed by hand (the previous shape).** It
  leaves `R-DB16-DOCS` with no possible tag site: the id matches the suite's
  coverage pattern and therefore sits in the denominator, but no `*_test.go` can
  ever carry it, so the tree reads as permanently short one id. It also proves the
  doc exactly once, at authoring time. Rejected.
- **Restating the claim as a structural Decision with no ids.** `R-DB16-DOCS` is a
  stable handle for a real, falsifiable behavior (the file's content), and the
  behavior is not going away — the ids rule deletes an id only when its behavior
  does. Dropping the id to dodge the proof-location problem hides a live claim
  instead of proving it. Rejected.
- **Retiring `R-DB16-DOCS` and minting a fresh id in the idgen shape.**
  `R-DB16-DOCS` matches the coverage pattern `R-[A-Z0-9]{4}-[A-Z0-9]{4}`
  character-for-character, so it is fully visible to every coverage tool, and it
  is one of a family of legacy hand-shaped ids this tree already carries
  (`R-DB01-PG3A`, `R-DB04-GATE`, …). Ids are stable handles and are never
  renumbered; churning this one buys nothing a tool can see. Rejected — the id
  stands as-is, and only newly added behaviors get freshly minted ids.
- **Asserting the file byte-for-byte against a golden copy.** Any wording change
  anywhere in `AGENTS.md` would fail the test, making the doc effectively frozen.
  The claim is about specific statements, so the test asserts those substrings.
  Rejected.
- **Leaving a stale rule and appending a contradicting note** — produces a doc
  that asserts both; the doctrine is purge + rewrite, not stack. Rejected.
- **Leaving the page count at "three"** — the metrics page is a fourth apex page
  and has been since D11–D16; a count silently one short is the same class of
  stale claim as the hybrid-page rule it replaced. Rejected.
- **Editing `CLAUDE.md` directly** — it is a symlink to `AGENTS.md`; the write
  goes through `AGENTS.md` (the refusal to write the symlink is expected).

**Verification.**
- R-DB16-DOCS — a Go test in `cmd/dashboard/docs_test.go` reads
  `dashboard/AGENTS.md` from disk and fails unless **all** of the following hold:
  the file contains no occurrence (case-insensitive) of `single hybrid page`, of
  `IAM console`, or of `telemetry`; it contains the four-page statement and names
  all four pages (`login`, `landing`, `profile`, `metrics`); it states that
  personal-access-token and OAuth-grant management live on the **profile** page,
  not the landing; and its `internal/` package list names `metrics`. Each
  condition reports its own failure, so a regression names the statement that
  broke. Substrate: the committed file on disk — the same artifact a reader
  opens — not a fixture and not a copy.
