# Decision 5 — Home composition: the MCP service directory

**Decision.** The logged-in home (`GET /` with a session) is the **MCP service
directory and nothing else**: one section headed **`MCP Services`**, rendered
inside the shared shell (D10). Install instructions live on `/install` (D40);
token/grant administration on `/profile` (D3, D4); metrics behind the shell
navigation (D16).

- **One section.** The page body is a single `<section>` whose `<h2>` reads
  exactly `MCP Services`, followed by the service rows. No other section, no
  intro prose — the heading plus self-evident rows carry the meaning.
- **Service rows, wiki-list idiom.** The list is an unordered list of rows
  (`<ul class="rows">`, one `<li>` per service), **not** a `<table>`, with no
  header row. Each row: the service **name** on the left, linked to that
  service's human landing at its mount root `/srv/<svc>/` (the
  `inventory.Read` `Mount` value, which carries its trailing slash); on the
  right the raw MCP **URL** in mono (`<code>`) and a **Copy** button. Rows are
  separated by hairline bottom borders; generous horizontal space
  (`--space-8`) separates the URL from its button.
- **Copy is a bordered button.** The copy control uses the same
  bordered-neutral button idiom as the shell's sign-out control
  (`--control-h-sm`, mono uppercase label, `--color-border-strong` border),
  reads `Copy`, carries an accessible name naming the service, and copies the
  row's MCP URL via the shared copy JS (which reads the sibling `<code>`).
- **Identity and navigation live in the shell.** The monogram avatar
  (profile link) and sign-out sit in the D10 header, present on the home page
  as on every shell page. The avatar is the only path to the profile page.

This decision governs only the **home** page body. The shell chrome around it
is D10; the `/services` JSON endpoint, install scripts, and `mcpResourceURL`
are unchanged.

**Rejected.**
- **Keeping install snippets on the home** — the home is a directory you
  return to; connect-your-agent is a task page you visit once (D40). Mixing
  them re-creates the hybrid page this design removed.
- **Linking the service name to the raw MCP resource URL** — that endpoint is
  a bearer-gated JSON-RPC surface, not a human page.
- **A `<table>` for the rows** — one list language across the app; the wiki
  row idiom is that language.
- **A flush borderless copy affordance on rows** (the snippet-embedded style) —
  free-standing row actions read better as real buttons; the flush style
  remains correct inside the install page's snippet boxes where the button is
  part of the box.
- **Section intro prose** — restates what the rows already show.

**Verification.**
- R-DB12-LINK — On the home page, each service row links its **name** to that
  service's mount root `/srv/<svc>/` (the `Mount` href), not to the MCP
  resource URL.
- R-XO4W-LKAI — On the home page's shell header, the profile affordance is a
  monogram avatar: a link to `/profile` (class `avatar`) whose text is the
  uppercased first letter of the owner's email and whose accessible
  name/`title` carries the full email; the email is **not** rendered as
  visible text. The avatar is the last (right-most) element of the identity
  nav, after the sign-out control.
- R-DB14-SOUT — The sign-out control (the `POST /logout` form) is present on
  the home page.
- R-OF1Q-VEDC — On the home page, the service list is an unordered list of
  rows (one `<li>` per service), **not** a `<table>`, and there is no
  `NAME`/`URL` header row.
- R-OG9N-9641 — Each service row shows its raw MCP `URL` in a `<code>`
  element accompanied by a copy control that copies that URL and carries an
  accessible name naming the service.
- R-OHHJ-MXUQ — The home page body renders no intro/explanatory paragraph in
  its services section — the section is heading plus rows only.
- R-VJH9-9GQY — The home page body contains the exact heading `MCP Services`
  and **no** install snippet (no occurrence of `/install/claude` or
  `/install/codex` in the logged-in home body).
- R-Y5OB-DAIR — The logged-in home body contains no occurrence of
  `/install/grok`.
