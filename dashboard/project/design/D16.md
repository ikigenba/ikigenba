# Decision 16 — Metrics entry: the shell header's nav link

**Decision.** The entry point to the metrics page is the **Metrics nav link in
the shared shell header** (D10) — present on every signed-in shell page, so
box health is one click from anywhere, not only from the home page. There is
no landing tile: the home body is the service directory alone (D5). The
logged-out login page carries **no** metrics link — box health is owner-only,
and the login page wears no shell.

The nav link's markup, placement, and `aria-current` behavior are owned by
D10 (R-VOCU-SJPQ, R-VQSN-K374); this Decision is **structural** apart from
the logged-out exclusion below, which it retains. The word *Telemetry*
continues to appear nowhere in the signed-in web surface — the label is the
literal `Metrics` and the href the literal `/metrics` (D14 owns the route).

**Rejected.**
- **The landing tile (this Decision's prior form)** — with the shell header
  giving every page a persistent nav, a body tile on one page is a redundant
  second entry; the header link is available everywhere the tile was and
  everywhere it wasn't.
- **Both tile and nav link** — two affordances for one destination on the
  same viewport is clutter.
- **Showing the link when logged out** — advertises a page that only
  redirects back to login.

**Verification.**
- R-X682-UBSK — the logged-out login page (`GET /` with no session) contains
  **neither** a `/metrics` link nor a `/telemetry` link (http test asserts
  both are absent).
