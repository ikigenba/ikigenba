# Decision 16 — Landing entry: a tile linking to the metrics page

**Decision.** The signed-in landing (`GET /` with a session) carries a
**tile/link to `/metrics`**, labelled **Metrics**, placed near the service list.
It is the only entry point to the metrics page (the operator chose a landing
tile over a banner link). The logged-out login page carries **no** such link —
box health is owner-only.

The link lives in `ui/html/index.html` inside the signed-in (`{{if .Owner}}`)
branch, styled with the existing landing chrome (a `.tile`/`.list` idiom already
present) — no new component, no change to the banner (D10) or the service rows
(D5). The href is the literal `/metrics` and the visible label is the literal
`Metrics`; the word *Telemetry* does not appear on the landing at all, so the
owner's nav uses the suite's one meaning of that word (the forensic service) and
never the old one.

```html
{{if .Owner}}
  …
  <a class="metrics-tile" href="/metrics">Metrics</a>
  …
{{end}}
```

**Rejected.**
- **Leaving the tile labelled "Telemetry" while the route moves.** The label is
  the whole of what the owner sees; renaming the route but not the word would
  keep the ambiguity exactly where it is most visible.
- **A banner link (shared chrome).** The operator chose a landing tile; the banner
  stays the two-control identity nav D10 settled.
- **Showing the tile when logged out.** The metrics page is session-gated;
  advertising it on the login page would offer a link that only redirects back to
  login.
- **A new tile component/CSS system.** The landing already has list/tile chrome;
  reuse it rather than introduce a second visual language for one link.

**Verification.**
- R-X506-GK1V — the signed-in landing (`GET /` with a valid session) renders an
  anchor whose href is exactly `/metrics` and whose visible link text is
  `Metrics`, and the rendered signed-in body contains no `/telemetry` href and no
  occurrence of the word "Telemetry" (http test).
- R-X682-UBSK — the logged-out login page (`GET /` with no session) contains
  **neither** a `/metrics` link nor a `/telemetry` link (http test asserts both
  are absent).
