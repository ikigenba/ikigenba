# D01-layout-and-run-seam

webhooks is the suite's webhook receiver: one Go binary that keeps webhooks, each a slug with a secret it mints, accepts deliveries from senders outside the suite at `POST /in/<slug>` (`D05-ingress`), keeps each accepted delivery's body in its own SQLite database, `state/webhooks.db`, for a retention window, emits an event on the suite's event bus for each delivery and each change to a webhook (`D07-trail`), offers six MCP tools at `/mcp` (`create`, `list`, `show`, `rotate`, `delete`, `delivery`; `D08-tools`), and serves a page of every webhook at `/`, a tools page at `/tools` and an about screen at `/about` to a signed-in user (`D06-pages`), whose footer, like every page's, shows the `Release` then the `Commit` of the identity the run read. This design is the structural ground the others stand on: where the code lives, the seam through which the process is run so that every part can be tested without a real process, the two settings and how they are read, the paths, the migrations, where the identity and the display string come from, and the binary's wiring. It follows cron's layout and run seam, which is the precedent for everything here.

The module is `github.com/ikigenba/ikigenba/webhooks`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/webhooks`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/webhooks` is wiring only.

## The dependencies

webhooks depends on one module besides the standard library: `github.com/ikigenba/ikigenba/appkit`, required at a published release with no `replace` directive. Its `db` package brings the pure-Go SQLite driver, which keeps the release build cgo-free. webhooks uses appkit's `db`, `version`, `services`, `page`, `identity`, `mcp`, `telemetry` and `events`, and restates none of their contracts. Which release is data that `AGENTS.md` and `go.mod` hold.

## Where the environment is read

`main` makes the one read of the environment that is not `Run`'s own: it calls appkit's `version.Read` exactly once, first, and holds the result, the **identity**, a `version.Identity` holding a `Release` and a short `Commit`, whose `String()` is the **display string**, the empty string when neither `IKIGENBA_COMMIT` (`version.CommitVariable`) nor `IKIGENBA_RELEASE` (`version.ReleaseVariable`) is set. It hands the identity to `page.New`, whose banner carries its `Release` and `Commit` to the footer of every page and to the about screen, and the display string to the `mcp.ServerConfig` its `Process.MCP` builds and to `Run` as `Process.Version`, which `Run` writes for `--version` and gives the run's writer as its `telemetry.Config.Version`, so it is `service.started`'s `version`. Nothing below `main` calls `version.Read` or `version.Display`, so a test of `Run` hands it any string as `Version` and sets no variable. How the identity and its string are built is appkit's contract, and webhooks' tests do not re-prove it; the binary's requirements compare with what `version.Read` returns under the same two values, so no test spells a version. `Run` reads every variable through `Process.LookupEnv`: `DRAIN_SECONDS` and `WEBHOOKS_RETENTION_DAYS` once at start, through `settings.Read`; `LISTEN_PID`, `LISTEN_FDS` and `NOTIFY_SOCKET` for the socket and readiness; and `IKIGENBA_SERVICES` once, when it starts to serve.

## Packages

The root package, `webhooks`, holds what the module embeds: `Assets` (the four templates), `Etc` (`manifest.toml` and `nginx.conf`) and `Migrations` (the one migration, `0001_webhooks.sql`, which creates the `webhooks` and `deliveries` tables `D04-store` describes).

Eleven internal packages hold the concerns, one each: `internal/cli` (the run seam, the command, the serve path), `internal/settings` (the two settings), `internal/server` (a listener's life), `internal/store` (the records), `internal/sweeper` (the retention sweep), `internal/trail` (the four webhook events), `internal/ingress` (the public ingress), `internal/urls` (the addresses webhooks builds), `internal/tools` (the six tools), `internal/pages` (the four templates' data and the page routes) and `internal/web` (the route table). Which imports which is guidance, not contract.

## The run seam

The run seam is `cli.Run`, which takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package, and returns the exit code; it is cron's seam, field for field. `Now` is the clock every time webhooks stamps or compares is read from: a webhook's `created`, a delivery's `received`, the sweep's cut-off, every event's time. `After` is the timer seam: every wait of the sweeper between two sweeps ends when a channel `After` returned delivers, so a test that hands in its own `After` learns each wait as it begins and delivers on its channel to make the next sweep run. `Rand` is the source of every id and secret webhooks mints: request ids, webhook ids, delivery ids, secrets and bus event ids.

## Settings

webhooks reads two values at start. `DRAIN_SECONDS`, the space's, 5 when unset or empty; and `WEBHOOKS_RETENTION_DAYS`, its own, which its manifest's `[env]` sets to 2, and 2 when unset or empty. Each is spelled as opsctl writes an integer — one or more ASCII digits, no sign, no leading zero, no unit, no white space — and digits beyond what an `int64` holds read as the largest `int64`. `settings.Read` checks them in that order and refuses the first that is not acceptable with a `*settings.Error`, whose text `Run` writes after `webhooks: ` as a usage error before it looks for its socket. A day is 24 hours.

## Paths

Relative to `Process.Dir` (the process's working directory when empty): the database is `state/webhooks.db`, opened with `db.Open`, `webhooks.Migrations()` and `Process.Now`, `state/` created when absent. webhooks writes nothing outside `Dir`.

## Recorded decisions

- appkit is required at the release `AGENTS.md` names, whose `page.Banner` carries the trail, the home link and the tools flag the templates use, so webhooks serves a tools page at `/tools` as the banner's page menu links it.
- The seam keeps cron's `After` name: here it serves the sweeper's wait and no other.
- The retention variable is `WEBHOOKS_RETENTION_DAYS`, named after events' `EVENTS_RETENTION_DAYS`, the most recent precedent of an app setting with a prefix.

## Consumer tasks

`main` calls `id := version.Read()` and `v := id.String()` and hands `cli.Run` a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Version` is `v`, whose `Banner` is `page.New(pages.ServiceName, id).Banner` and whose `MCP` returns `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Version: v, Telemetry: w})` over the writer `w` it is given, leaving the rest zero. A test of the run seam builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` over a map, an `Inherit` returning a listener it bound, a `Now`, an `After` and a `Rand` it controls, and capturing sinks, calls `cli.Run`, waits for `READY=1`, drives the listener with `mcp.Client` and raw HTTP, cancels, and inspects `Dir`, the captures and the streams. The one test that execs the binary composes non-empty `IKIGENBA_COMMIT` and `IKIGENBA_RELEASE` into the child's environment and, after setting the same two values with `testing.T.Setenv`, computes the identity it expects with `version.Read`, the display string with its `String`, and the about screen with the `Banner` method of `page.New(pages.ServiceName, id)`.
