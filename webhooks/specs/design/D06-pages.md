# D06-pages

What webhooks draws as HTML: `internal/pages`, the four templates `landing`, `tools`, `about` and `notfound` and the data each receives, and the handler that answers `/`, `/tools`, `/about` and every other path that reaches it. It follows cron's pages, with sites' guest rule: the handler runs under `identity.Optional` (`D03-serve`), so it sees guests, and a guest asking for a page is sent to sign in. There is no per-webhook or per-delivery page.

## The pages

The landing page shows every webhook in the space, whoever owns it, sorted by slug, each with its id, slug, scheme, the address a sender posts to, its owner's email, whether the caller owns it, and its last received time in RFC 3339 and to the minute. The tools page shows the six tools in registration order (`D08-tools`), each with the first line of its description. The about screen shows the service's name, the banner's `Release` and `Commit` as its version, and `Description`. Every page's footer shows the banner's `Release` then its `Commit`, the identity `main` handed `page.New` (`D01-layout-and-run-seam`). The landing page sits at the root of the banner's trail; the tools page and the about screen are one level below it, named by their path segment, `pages.ToolsLevel` and `pages.AboutLevel`, which the handler sets as the banner's trail. Any other path is the not-found page, status 404, to a signed-in user and a guest alike, with the footer only.

The banner's user is the caller's email, with auth's profile and sign-out addresses: auth's entry in the services file when it has one, and otherwise `auth.` and the request's host with a leading `webhooks.` removed, under the forwarded scheme (`https` unless `X-Forwarded-Proto` says `http`). A webhook's address is webhooks' entry's URL in the services file followed by `/in/<slug>`, or, with no such entry, the forwarded scheme and the request's `Host` followed by `/in/<slug>`.

## Guests and methods

A request to `/`, `/tools` or `/about` whose method is not `GET` or `HEAD` is `405` with `Allow: GET, HEAD`. A guest's `GET` or `HEAD` of one of them is `302` to auth's sign-in, `<auth>/?return=` and the query-escaped address of the page asked for, which is where the host's nginx sends a guest of an app with `guests = false`. The landing page answers `503` with `store.Unreachable` as plain text when the store cannot be read.

## REQUIREMENTS

- R-ZODQ-S4NP: The `internal/pages` package, imported from the path `github.com/ikigenba/ikigenba/webhooks/internal/pages` with the package name `pages`, MUST export `const ServiceName = "webhooks"`, `const Description string`, a non-empty copy constant, and the variables `ToolsLevel = page.Level{Name: "tools", URL: "/tools"}` and `AboutLevel = page.Level{Name: "about", URL: "/about"}`.
- R-ZPLN-5WEE: The `internal/pages` package MUST export `type Set`, `func Load() (*Set, error)`, the method `func (s *Set) Write(w http.ResponseWriter, r *http.Request, status int, name string, data any)`, `type Config struct { Banner func(u page.User) page.Banner; Pages *Set; ServicesPath string; Store *store.Store }` and `func Handler(cfg Config) http.Handler`.
- R-ZQTJ-JO53: The `internal/pages` package MUST export `type LandingData struct { Banner page.Banner; Webhooks []WebhookRow }`, `type WebhookRow struct { ID, Slug, Scheme, URL, Owner string; Mine bool; LastReceived, LastReceivedText string }`, `type ToolsData struct { Banner page.Banner; Tools []ToolRow }`, `type ToolRow struct { Name, Description string }`, `type AboutData struct { Banner page.Banner; Description string }` and `type NoticeData struct { Banner page.Banner }`.
- R-ZS1F-XFVS: `pages.Load` MUST return a nil error and a set holding appkit's `page.Templates()` and the four templates of the root package's `Assets`, so that executing `landing`, `tools`, `about` and `notfound` with a `LandingData`, `ToolsData`, `AboutData` and `NoticeData` returns a nil error.
- R-ZT9C-B7MH: `Set.Write` MUST answer `status` with `Content-Type: text/html; charset=utf-8` and the bytes the named template writes for `data`, and no body for a `HEAD` request.
- R-ZUH8-OZD6: For a signed-in caller — a first `X-User-Id` value that is not empty — `GET /` MUST be answered 200 with exactly what the template `landing` writes for the `LandingData` whose `Banner` is what `cfg.Banner` returns for the banner's user and whose `Webhooks` are one row per webhook `Store.List` returns, in that order, each with the webhook's `ID`, `Slug`, `Scheme`, its address, the owner's email as `Owner`, `Mine` true exactly when its `OwnerID` is the caller's `X-User-Id`, and, when it has received a delivery, `LastReceived` as RFC 3339 UTC to the second and `LastReceivedText` in the form `2006-01-02 15:04`, both empty when it has not.
- R-ZWX1-GIUK: For a signed-in caller, `GET /tools` MUST be answered 200 with exactly what the template `tools` writes for the `ToolsData` whose `Banner` is what `cfg.Banner` returns with its `Trail` set to the one level `ToolsLevel`, and whose `Tools` are one row per entry of `tools.Catalog()`, in that order, each with its `Name` and the first line of its `Description`.
- R-ZY4X-UAL9: For a signed-in caller, `GET /about` MUST be answered 200 with exactly what the template `about` writes for the `AboutData` whose `Banner` is what `cfg.Banner` returns with its `Trail` set to the one level `AboutLevel` and whose `Description` is `pages.Description`.
- R-ZZCU-82BY: A request whose path is none of `/`, `/tools` and `/about` MUST be answered 404 with exactly what the template `notfound` writes for the `NoticeData` whose `Banner` is what `cfg.Banner` returns for the banner's user, whatever its method and whether or not it carries `X-User-Id`.
- R-00KQ-LU2N: The banner's user MUST be the `page.User` whose `Email` is the request's `X-User-Email`, whose `ProfileURL` is auth's address followed by `/` and whose `LogoutURL` is auth's address followed by `/logout`, auth's address being the `URL` of the services file's entry `auth` without a trailing `/` when there is one, and otherwise the forwarded scheme, `://auth.`, and the request's host without its port and without a leading `webhooks.`; so that `Host: webhooks.sbx.ikigenba.dev` with `X-Forwarded-Proto: https` and no services file gives `https://auth.sbx.ikigenba.dev/`.
- R-01SM-ZLTC: A webhook's address on the landing page MUST be the `URL` of the services file's entry `webhooks` without a trailing `/`, or, when there is none, the forwarded scheme, `://` and the request's `Host`, followed by `/in/` and the webhook's slug.
- R-030J-DDK1: A request to `/`, `/tools` or `/about` whose method is neither `GET` nor `HEAD` MUST be answered 405 with an `Allow` header of exactly `GET, HEAD` and an empty body, whether or not it carries `X-User-Id`.
- R-048F-R5AQ: A `GET` or `HEAD` of `/`, `/tools` or `/about` with no `X-User-Id`, or an empty one, MUST be answered 302 with no body and a `Location` of auth's address followed by `/?return=` and the query escape (`url.QueryEscape`) of the forwarded scheme, `://`, the request's `Host` and its path and query, reading nothing from the store.
- R-05GC-4X1F: When the store cannot be read, a signed-in `GET /` MUST be answered 503 with `Content-Type: text/plain; charset=utf-8` and the body `store.Unreachable` followed by a newline, while `/tools`, `/about` and the not-found page are answered as when it can.
