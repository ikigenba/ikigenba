# Decision 20 — Adopt the suite testing-language contract

**Decision.** webhooks adopts the suite's testing-language contract,
`root project/design/D23.md`, by citation. That contract owns the four test
layers (**hermetic / composed / live / manual**) and what each may touch, the
single mechanism for live tests (`//go:build live`, invoked as
`go test -tags live ./...`, hard-failing on absent credentials), the ban on
`t.Skip` outside live-tagged files, the requirement that a manual-layer check
live in a committed runbook, and the requirement that every tree declare its own
testing facts in its `AGENTS.md`. This Decision restates none of that. It records
only the webhooks-specific facts the contract asks this tree to declare, adopts
the contract's two per-service ids, and settles the tree's long-standing
mismatch between what its design claimed about nginx and what its gate actually
runs.

**The layers webhooks has.** Two, both in the default gate:

- **hermetic** — the domain and store tests against real temp-file SQLite
  (`db.Open`) through the real migration runner, with a real `eventplane/outbox`
  and an injected deterministic `Clock`; the ingress and MCP handler tests over
  `httptest` against a real-SQLite `Service`; the landing tests over the
  `internal/web` handlers and embedded asset bytes; the **committed-fragment
  text assertions** over `etc/nginx.conf`; the committed-`manifest.env` scan; and
  the non-test-source guard, which shells out to a local `bash`/`grep` to prove a
  retired identifier is gone.
- **composed** — the boot smokes that build the real `cmd/webhooks` binary and
  run its `serve` verb: the install-layout smoke in `cmd/webhooks/main_test.go`
  and the launch/health smoke in `internal/e2e/e2e_test.go`, each reaching the
  running process's `/health` over a loopback address.

The `internal/e2e` package name is an **informal alias**, not a layer: the
contract assigns a layer per test by what that test touches, and this package
holds both hermetic fragment-text tests and one composed binary smoke. Nothing
in it contacts a non-loopback address.

webhooks has **no live layer**: no test here reads a credential or reaches an
external service, so no `//go:build live` file exists and the `-tags live`
invocation is not part of this tree's testing story. It carries **no
tree-local manual runbook** either; the one manual-layer check its surfaces
depend on is the suite-level one the contract already owns and locates (bring
the suite up via `bin/start` and verify health through nginx on `:8080`), which
belongs to the suite, not to `webhooks/`.

**Through-real-nginx is a manual-layer check, not a gate item.** This tree's
design has claimed since D7/D8 that the ingress, MCP, PRM, and feed tiers are
proven by driving the dev front door on `:8080` with the suite up via
`bin/start`. Nothing committed does that, and nothing should: the contract
files the assembled-stack check as manual-layer precisely because an automated
suite-level gate is slow, contends for shared host ports, and is unrunnable in
parallel worktrees. What the gate proves for those tiers is what a **content
assertion over the committed `etc/nginx.conf`** can falsify — the location's
match form, its `auth_request` (or deliberate absence), its captured and
forwarded headers, and its upstream target — together with the **composed**
tests that prove the service behind those locations answers as claimed. D7 and
D8 are rewritten in place to say that; the ids are unchanged handles for the
same tiers, restated against the substrate that actually runs them. Whether a
real nginx routes a real request through to a real dashboard introspection is
outside `webhooks/` and is the suite's manual-layer item.

**GOWORK mode.** webhooks tests, builds, and vets in **workspace mode** through
the repo-root `go.work`; the production build forces `GOWORK=off` (driven by
`bin/ship webhooks`) and is not part of the default gate.

**Environmental preconditions beyond the Go toolchain.** Two, both hard failures
when absent, never skips:

- The **`go` binary on `PATH` in the test process's environment** (not merely the
  toolchain that compiled the tests), with the module cache already resolving
  webhooks' `replace` siblings. Both composed smokes shell out to `go build`;
  neither does a network fetch and neither may acquire one.
- A POSIX **`bash`** with **`grep`**, for the non-test-source guard
  (`R-DXYA-NY06`), which runs its scan as a shell pipeline rather than in-process.

**Where this lands.** Nothing in webhooks' shipped source changes. The adoption
is carried by two tagged tests and by the `AGENTS.md` Tests section stating the
facts above; the plan phase that realizes this Decision does both. The D7/D8
rewrites are design-side only — they bring the written claims into line with the
tests that already exist, and schedule no new work.

**Rejected.**

- *Restating the layer definitions, the live-tag mechanism, or the skip ban in
  this design.* Citation is the mechanism (`$ikispec`, "cite, never restate"): a
  local copy of a suite contract is drift by construction the moment the umbrella
  moves. This file names only what is particular to webhooks.
- *Re-minting local ids for the two behaviors.* The umbrella marks R-O1AD-MRKW
  and R-O2IA-0JBL `[proof: per-service]`; citing those exact ids **is** the
  adoption, and a fresh local id would be a second handle for one behavior.
- *Keeping D8's six-layer local vocabulary alongside the contract's four.*
  Two vocabularies for one property is the exact confusion the contract was
  written to end, and D8's own layer names (`unit`, `store/service
  integration`, `end-to-end`) split by substrate detail rather than by what a
  test may touch. D8 keeps its **substrate rules**, which are webhooks-specific
  and load-bearing, and drops its layer table.
- *Keeping D8's "verification-gate honesty" paragraph.* It sanctioned a
  `t.Skip` "for local runs only" and asked the verify phase to bring the suite
  up. Both are now contract violations: skipping is banned outside live-tagged
  files, and the suite-level check is manual-layer. The paragraph's underlying
  worry — that an unrunnable layer must not launder into a pass — is answered
  better by having no unrunnable layer.
- *Building an automated `:8080` front-door test to make the old D7 wording
  true.* That is the umbrella's own rejected alternative, and it would make this
  tree's gate depend on a stack another worktree may own.
- *Deleting the four `:8080` ids outright as unprovable.* The behaviors they
  name (the ingress tier is ungated and injects no identity header; the MCP tier
  is bearer-gated; the PRM tier is open; the feed is 404-shielded) are real
  claims about a committed file, and a wrong fragment fails them. Only the
  claimed substrate was wrong, not the claim.

**Verification.**

- R-O1AD-MRKW — cited from `root project/design/D23.md` (`[proof:
  per-service]`); adopted here. A test reads webhooks' committed `AGENTS.md`
  from disk and asserts its Tests section declares the default-gate test
  command, the layers present in the contract's vocabulary (hermetic and
  composed), every environmental precondition beyond the Go toolchain (the `go`
  binary and `bash`/`grep`), and the tree's GOWORK mode. Substrate: hermetic
  (real committed file read from disk).
- R-O2IA-0JBL — cited from `root project/design/D23.md` (`[proof:
  per-service]`); adopted here. A source scan over webhooks' `*_test.go` files,
  excluding files carrying the `live` build constraint, finds **zero**
  occurrences of `t.Skip`, `t.Skipf`, or `t.SkipNow`. The scan assembles its
  needle from parts so it never matches itself. Substrate: hermetic (source
  scan).
