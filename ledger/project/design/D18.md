# Decision 18 — Testing-language conformance: the suite's four layers, declared in `AGENTS.md`

**Decision.** ledger adopts the suite's **testing-language contract** —
`root project/design/D23.md` — which owns the four layer names, the rule for what
each layer may touch, the `//go:build live` mechanism, the ban on skipping outside
live-tagged files, and the requirement that every tree declare its testing facts in
its `AGENTS.md`. This Decision is the **citation, and citation is adoption**: ledger
owns none of that contract's content and restates none of it normatively. What is
local — and all this Decision adds — is **ledger's own testing facts** and **where
the proof of the declaration lives**.

The contract carries two `[proof: per-service]` ids, which ledger therefore proves
in its own tree:

- `R-O1AD-MRKW` — the doc-truth test over the committed `AGENTS.md`.
- `R-O2IA-0JBL` — the source scan banning `t.Skip` outside live-tagged files.

**ledger's testing facts** (the content its `AGENTS.md` Tests section must declare,
and what the doc-truth test asserts):

- **Default-gate test command:** `cd ledger && go test ./...`, inside the green bar
  the design Conventions already fix (`go build ./...`, `go vet ./...`,
  `gofmt -l .` silent, `go test ./...`).
- **Layers present: hermetic and composed — no live layer and no manual layer.**
  - **hermetic** is the bulk of the suite: the `internal/ledger` domain and event
    tests over a real SQLite database migrated through ledger's full embedded
    migration set (the substrate that actually enforces the partial unique index
    and the `correlation_id` column, read back by direct SQL); the `internal/db`
    load and outbox-DDL drift guards; the `internal/mcp` tests driving
    `NewHandler(svc, rt)` through the real `appkit/mcp` `ServeHTTP` seam; the
    `cmd/ledger` web tests loading the repo-real `share/www` tree through
    `appkit/web` and driving it with `net/http/httptest`; the feed claim over the
    real eventplane `FeedHandler` on `httptest` — all in-process, loopback only;
    and the **shipped-file guards** — the `etc/nginx.conf` fragment content
    assertions (D9, D17), the committed-`manifest.env` scans, and the
    `loopback_guard` source scan — which read committed files from disk and touch
    nothing else.
  - **composed** is the boot smoke in `cmd/ledger/main_test.go`: it builds
    ledger's own binary, assembles an `/opt/ledger/`-shaped tree under
    `t.TempDir()`, runs it on a free loopback port, and asserts the served
    `/health`. It is offline by construction.
  - **no live layer.** ledger carries no `//go:build live` file and needs none: it
    depends on no external service. Its only trust-boundary collaborator is nginx,
    which the gate never runs and whose fragment is proven by content assertion
    instead.
  - **no manual layer.** ledger commits no runbook of its own; the suite-level
    "the whole stack composes" check belongs to the umbrella, not here.
- **Environmental preconditions beyond the Go toolchain: none.** The composed boot
  smoke shells out only to `go build` and the binary it just built; nothing needs
  `git`, `python3`, a browser, a credential, or a running suite.
- **GOWORK mode: workspace for the gate, plus a committed `GOWORK=off` build
  check.** The gate resolves `appkit`, `eventplane`, and `registry` through the
  repo-root `go.work` and the committed replace-siblings. ledger additionally
  commits an **isolated build check** — `cd ledger && GOWORK=off go build ./...` —
  which mirrors the production build's resolution (`bin/ship ledger`) and catches a
  dependency that only resolves through the workspace. It is a **build** check, not
  a test invocation: it compiles, runs nothing, and is stated as its own declared
  fact rather than folded into the default-gate command. This is the split
  `root project/design/D23.md` names as deliberate and per-tree, not a deviation
  from it.

**Where the proof lives.** Both adopted ids are proven in
**`cmd/ledger/docs_test.go`** — a new file at the composition root, the package
that already owns ledger's read-from-disk assertions over shipped artifacts
(`etc/nginx.conf`, `etc/manifest.env`, `share/www`). No new package is introduced.
The doc-truth test reads the committed `ledger/AGENTS.md` from disk and asserts its
Tests section declares the facts above — including **both** GOWORK facts, the
workspace gate and the `GOWORK=off` build check, since a declaration that mentioned
only one would be incomplete on the tree whose distinguishing fact it is. The
source scan walks the tree's `*_test.go` files, skips any file carrying the `live`
build constraint, and asserts zero occurrences of the skip verbs — assembling its
needle from parts so the scan never matches its own source.

**Rejected.**

- **Restate the contract's layer definitions locally so this design reads
  self-contained.** A local restatement is drift by construction: it goes stale the
  moment `root project/design/D23.md` is rewritten, and the suite's rule is cite,
  never restate. The citation is the whole mechanism. Rejected.
- **Keep the conventional `unit` / `integration` / `end-to-end` names and map them
  in prose.** Rejected by the contract itself, and for ledger specifically:
  `AGENTS.md` today calls the whole suite "Unit", which mislabels a boot smoke that
  compiles and runs a real binary. The layer names say what a test may *touch*,
  which is the property actually being policed.
- **Re-mint local ids for the two behaviors instead of citing
  `R-O1AD-MRKW` / `R-O2IA-0JBL`.** Both are `[proof: per-service]`: the ids are the
  suite's handles for one behavior each, proven once per adopting tree. Minting
  parallel local ids would give one behavior two handles and break the
  id-to-behavior invariant. Rejected.
- **Fold the `GOWORK=off` build check into the declared default-gate test
  command.** It compiles and runs no test; calling it part of the test command
  would misdescribe both. Declared as its own fact instead. Rejected.
- **Drop the `GOWORK=off` check now that a GOWORK mode is declared.** The
  declaration says which mode the gate uses; it does not prove standalone
  resolution. ledger's production build is exactly the `GOWORK=off` path, and the
  check is what catches a workspace-only dependency before `bin/ship` does.
  Rejected — kept and declared.

**Verification.**

Both ids below are **adopted**, not minted here: each belongs to the umbrella
Decision cited beside it, which states the behavior. These lines say only what
substrate proves it inside `ledger/`.

- `R-O1AD-MRKW` — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/ledger/docs_test.go` that reads the committed
  `ledger/AGENTS.md` from disk and asserts its Tests section declares the
  default-gate test command (`go test ./...`), the layers present (hermetic and
  composed; no live, no manual), that there are no environmental preconditions
  beyond the Go toolchain, and the GOWORK mode — both the workspace gate and the
  committed `GOWORK=off go build ./...` isolated build check.
- `R-O2IA-0JBL` — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/ledger/docs_test.go` that walks the `ledger/` tree's
  `*_test.go` files from disk, excludes any file carrying the `live` build
  constraint, and fails on any occurrence of `t.Skip`, `t.Skipf`, or `t.SkipNow`,
  with the needle assembled from parts so the scan cannot match itself.
