# D01-layout-and-run-seam

ledger is the suite's books: one Go binary that keeps the business's one set of books, with no `book` argument anywhere (seam 1, seam 2). It holds the **book**, one row with the currency, the lock date and the fiscal year start; the **accounts** of the chart, each opened and perhaps closed on a date; **transactions**, each a dated set of postings that sum to zero, append-only, whose words (flag, payee, narration, tags, links and metadata) are kept as numbered **annotation versions**, and which are corrected by a **reversal** rather than an edit; **balance assertions**, **notes** and **document references**, the last naming a file artifacts holds; and the reports read off them, the balances, the register, the balance sheet and the income statement (seam 2, seam 3). All of it lives in the app's own SQLite database, `state/ledger.db` (`D04-store`). It emits `transaction.posted` on the bus when a transaction is posted, a reversal included (seam 5, `D05-events`), records every mutation in telemetry's trail (`D08-trail`), offers twenty-three MCP tools at `/mcp`, its only API (seam 3, `D07-tools`), and serves a landing page relaying the book, a tools page, an about screen and the not-found page to a signed-in user (seam 4, `D06-pages`). Among its siblings it calls only artifacts, and outside the suite it reaches nothing (seam 1, seam 6). Decisions cited as seam N are /home/mgreenly/projects/ikigenba-ledger.md.

This design is the structural ground the others stand on: where the code lives and what each package is for, the seam through which the process is run so that every part can be tested without a real process, the one setting and how it is read, the path, where the identity and the display string come from, the binary's wiring, and the rule that ledger reaches only artifacts among its siblings and nothing outside the suite. It follows campaigns' layout and run seam, less what ledger has no use for: no settings of its own, no guest route, no addresses of its own package, no candidates client.

The module is `github.com/ikigenba/ikigenba/ledger`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/ledger`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/ledger` is wiring only.

## The dependencies

ledger depends on one module besides the standard library: `github.com/ikigenba/ikigenba/appkit`, required at a published release with no `replace` directive. Its `db` package brings the pure-Go SQLite driver, which keeps the release build cgo-free. ledger uses appkit's `db`, `version`, `services`, `page`, `paging`, `identity`, `mcp`, `telemetry`, `events` and `artifacts`, and restates none of their contracts. The release it requires is one whose `artifacts` client exports `Head` and `Show`, which `add_document` calls in that order, `Head` first to check the path and then `Show` for the artifact's id (seam 6); which release that is, is data that `AGENTS.md` and `go.mod` hold.

## Where the environment is read

`main` makes the one read of the environment that is not `Run`'s own: it calls appkit's `version.Read` exactly once, first, and holds the result, the **identity**, whose `String()` is the **display string**. It hands the identity to `page.New`, whose banner carries its `Release` and `Commit` to every page's footer and to the about screen, and the display string to the `mcp.ServerConfig` its `Process.MCP` builds and to `Run` as `Process.Version`. Nothing below `main` calls `version.Read`. `Run` reads every variable through `Process.LookupEnv`: `DRAIN_SECONDS` once at start, through `settings.Read`; `LISTEN_PID`, `LISTEN_FDS` and `NOTIFY_SOCKET` for the socket and readiness; and `IKIGENBA_SERVICES` once, when it starts to serve. That is the whole set: ledger has no setting of its own (seam 1: "no settings and no environment of its own beyond what appkit reads"), and it reads no `IKIGENBA_SANDBOX`, since it fetches nothing from outside the suite and appkit's `artifacts` client does not read it. appkit's constructors also read `IKIGENBA_SERVICES` from the process environment; that read is appkit's.

## Packages

The root package, named `ledger`, holds what the module embeds: `Assets` (the four templates `about.html`, `landing.html`, `notfound.html` and `tools.html`), `Etc` (`manifest.toml` and `nginx.conf`) and `Migrations` (`0001_ledger.sql`, whose bytes `D04-store` states). `share/icon.svg`, Tabler's `book` (seam 1), is packed beside `bin/` and `etc/` by `devctl build` and is not embedded (`D09-on-a-space`).

The internal packages hold the concerns, one each; the document named declares each package's shapes and their behavior:

- `internal/cli`: the run seam, `cli.Process` and `cli.Run` (this document); the command, the exit codes, `cli.Manifest` and `cli.Usage` (`D02-cli`); the serve path (`D03-serve`); `cli.NginxConf` (`D09-on-a-space`).
- `internal/settings`: the one setting, `DRAIN_SECONDS` (this document).
- `internal/server`: a listener's life (`D03-serve`).
- `internal/web`: the route table, `web.Config` and `web.Handler` (`D03-serve`).
- `internal/store`: every record and every read and write of them: the book, the commodities, accounts, transactions with their postings and annotation versions, assertions, notes and documents, their ids, the windows, the reports and the migration (`D04-store`).
- `internal/trail`: the bus event `transaction.posted`, `trail.Emits` and the bus's two paths (`D05-events`); the telemetry trail as a whole, its eleven other event names and its secrecy (`D08-trail`).
- `internal/pages`: the templates' data and the page routes, `pages.Handler`, `pages.Config`, `pages.Description`, and the auth and sign-in addresses `pages.Auth` and `pages.SignIn` (`D06-pages`); `pages.ServiceName` (this document).
- `internal/tools`: the twenty-three tools, `tools.Register` and `tools.Config`, their descriptions and their refusal sentences (`D07-tools`).

No package is added for amounts, reports or the artifacts check: an amount and its rendering, the balances and the statements are the store's, and the artifacts check is a step of `add_document` through appkit's client (`D07-tools`). Which package imports which is guidance, not contract.

Template data types, tool argument and result types, copy constants and the constants a package uses only itself are declared by the document that owns the package's behavior, not here.

## The run seam

The run seam is `cli.Run`, which takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package, and returns the exit code. It is campaigns' seam, field for field: ledger reaches artifacts over the socket the services file names, through appkit's client, so a `Run`-level test serves a fake artifacts on a Unix socket its services file's `artifacts` entry names, and ledger reaches no address of its own choosing; and ledger works nothing in the background, so it has no sweeper and no wait for a timer to end. `Now` is the clock every time ledger stamps or compares is read from: an account's opened and closed times, a transaction's posted time, an annotation version's written time, an assertion's, a note's and a document's added and retracted times, the book's updated time, the today a default date or a check is measured against (`D04-store`), and every event's time. `Sleep` is the pause the writer and the emitter wait with between delivery attempts. `Rand` is the source of every value ledger mints: request ids, the `txn_`, `bal_`, `note_` and `doc_` ids, and bus event ids. `Inherit`, `Now` and `Rand` are the caller's to give whenever `Args` is empty: `Run` has no default for any of them, and the choice of the process's own descriptor 3, `time.Now` and `crypto/rand.Reader` is made once, at the process boundary, by `cmd/ledger`. The event bus, telemetry and artifacts sockets reach `Run` through the services file `IKIGENBA_SERVICES` names (`D03-serve`); the absence of an `artifacts` entry never stops ledger serving, and leaves `add_document` refusing `unavailable` (seam 1, `D03-serve`, `D07-tools`). There are no live tests.

## Settings

ledger reads one value at start, `DRAIN_SECONDS`, the space's: how long a stopping server waits for requests in progress (`D03-serve`). An unset or empty one is its default, 5 seconds. It is spelled as opsctl writes an integer: one or more ASCII digits, no sign, no leading zero, so `0` is refused, and digits beyond what an `int64` holds read as the largest `int64`. `settings.Read` refuses an unacceptable value with a `*settings.Error` naming it, quoting its value and saying what was wanted, and `Run` writes its text after `ledger: ` as a usage error before it looks for its socket. The page sizes, the id lengths, the field limits and the refusal sentences are constants of the documents that use them.

## Paths

Relative to `Process.Dir` (the process's working directory when empty) the database is `state/ledger.db`, opened with `db.Open`, the root package's `Migrations()` and `Process.Now`; `state/` is created when absent. ledger writes nothing outside `Dir` and nothing under it but the database.

## The addresses

ledger builds two addresses that are not its own paths, the auth address the banner's profile and sign-out links are built on and the sign-in address a guest is sent to, and both belong to `pages`, their only consumer, as `pages.Auth` and `pages.SignIn` (`D06-pages`). It builds no address of a sibling: no page links to artifacts or anywhere else. The page paths `/tools` and `/about` are spelled by the templates.

## Siblings and the outside

Among its siblings ledger calls only artifacts, through appkit's `artifacts` client, `Head` and then `Show`, for `add_document` and nothing else, each call carrying the caller of the tool call it is made for (seam 6, `D07-tools`); besides it, it reaches the event bus and telemetry, which every app reaches through appkit's sinks. Outside the suite it reaches nothing (seam 6). The design makes this observable at three seams. `cli.Process` has no HTTP client, so ledger has no means to reach an address outside the suite. `Run` looks up no variable but the five this document names, so no setting points ledger anywhere. And a `Run`-level test that names every other sibling in the services file, each on a listener that records every connection, and exercises every tool and page proves none of them is reached and that the fake artifacts hears only from `add_document`.

## Recorded decisions

- The layout follows campaigns' layout and run seam, less the concerns ledger has no part in: the guest route and its package, the candidates client, the sibling links.
- **Departure: no `internal/urls` and no `internal/links`** (campaigns' `D01`). campaigns keeps `internal/links` for its guest route; ledger has no guest route (`D03-serve`, `D06-pages`). campaigns keeps `internal/urls` for the auth address, the sign-in address and the pages on its siblings; ledger's pages link to no sibling, so the two addresses that remain move to `pages`, their only consumer, as `pages.Auth` and `pages.SignIn` with campaigns' rules (`D06-pages` declares them), and a package of two functions used by one other is not kept.
- **Departure: no settings of ledger's own** (campaigns' `D01` and `D02`). Seam 1 gives ledger no settings and no environment beyond what appkit reads, so `internal/settings` holds `DRAIN_SECONDS` alone, there is no `settings.WantURL`, and the manifest has no `[env]` (`D02-cli`). `internal/settings` is kept, rather than reading `DRAIN_SECONDS` inside `cli`, so that `Settings`, `Read`, `Error` and `Drain` keep campaigns' shapes and a later setting is an added field, not a new package.
- **The settings live in this document, as campaigns' do.** `D02-cli` states that the manifest declares no `[env]`.
- **`Process` is campaigns' struct verbatim.** It keeps `Sleep`, because the writer and the emitter retry with it, and has no `After` and no `HTTP`: ledger has no sweeper, poll or fetch, and the absent client is part of the rule that ledger reaches nothing outside the suite (seam 6).
- **No `IKIGENBA_SANDBOX`.** appkit's `artifacts` client does not read it and ledger fetches nothing, so the variable has no use here and stays out of the key set. `IKIGENBA_COMMIT` and `IKIGENBA_RELEASE` are read by appkit's `version.Read` in `main`, not by `Run`.
- `Process.Inherit`, `Process.Now` and `Process.Rand` are required whenever `Args` is empty, as in campaigns; no requirement states the precondition, because no permitted test can observe a default.
- **No `Process` field names a sibling's address:** the services file names artifacts' socket, as it names the bus's and telemetry's, and its absence leaves `add_document` `unavailable` rather than stopping the start (seam 1).
- **`Migrations` names its one file here**, `0001_ledger.sql`, where campaigns' `D01` defers the set to its store document: the brief and `AGENTS.md` fix the file name, and `D04-store` states its bytes.
- **The exec'ing test calls `book`, `open_account` and `accounts`, and never `add_document`**: the binary's requirements below name only those tools, so the one test that execs the binary needs no fake artifacts and the binary never reaches one (`AGENTS.md`, `D02-cli`).
- **`pages.ServiceName` is declared here, as campaigns declares it in its `D01`:** `main`, the banner kit, the MCP server, the database and the manifest all need the name, and `D02-cli`, `D03-serve` and `D06-pages` use it; `pages.Description` stays `D06-pages`'.
- **"Reaches only artifacts, nothing outside the suite" is a section and three requirements** (seam 1, seam 6): the `Process` shape, the key set and the sibling set. That nothing in the source names another address cannot be proved by a permitted test, which never reads source, so it stands in prose; the sibling-set requirement is the observable form of it.
- Determinism at `Run` level is proved on every id kind ledger mints, not only on `txn_`, so that a `Run` which handed the store a `Rand` other than `Process.Rand` for any one kind fails.

## Consumer tasks

`main` calls `id := version.Read()` and `v := id.String()` and hands `cli.Run` a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Version` is `v`, whose `Banner` is `page.New(pages.ServiceName, id).Banner`, whose `Inherit` takes the process's own descriptor 3, whose `Now` is `time.Now`, whose `Rand` is `crypto/rand.Reader`, and whose `MCP` returns `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Version: v, Telemetry: w})` over the writer `w` it is given, leaving the rest zero; it cancels the context on `SIGTERM` or `SIGINT` with a cause whose `Error` is the signal's name, and exits with what `Run` returns.

`internal/cli`, serving, reads `s, err := settings.Read(p.LookupEnv)`; opens `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "ledger.db"), Migrations: ledger.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: p.Stderr})`; builds `st := store.New(d, store.Config{Now: p.Now, Rand: rnd})` over the one serialized reader of `p.Rand` it shares with the writer's and the emitter's ids; reads `list, _ := services.Read(path)` and, when `e, ok := list.Find("artifacts")` finds the entry, builds appkit's `artifacts.NewClient(artifacts.ClientConfig{Service: e, Telemetry: w})`, nil otherwise; and hands `s.Drain()` to `server.Serve` and `s` to `web.Config` (`D03-serve`).

A page builds `pages.SignIn(r, servicesPath)` for a guest and `pages.Auth(r, servicesPath) + "/"` and `+ "/logout"` for the banner (`D06-pages`).

A test of the run seam builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` over a map whose `IKIGENBA_SERVICES` names a services file whose `artifacts` entry names a Unix socket on which a fake artifacts answers appkit's `artifacts` client's `Head` and `Show` and records each request with its identity headers, an `Inherit` returning a listener it bound, a `Now`, a `Sleep` and a `Rand` it controls, and capturing sinks; calls `cli.Run`, waits for `READY=1`, drives `/mcp` with `mcp.Client` and the pages with raw HTTP, cancels, and inspects `Dir`, the fake's records and the captures. A test of settings calls `settings.Read` with a lookup over a map and compares with `settings.Defaults()` and `Drain()`.
