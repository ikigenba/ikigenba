# D02-cli

ledger as a command: what `cli.Run` does with the arguments `D01-layout-and-run-seam` hands it through `Process`, the exit codes it returns, what `db status` reports of the database, and the two constants declared here, the usage text and the manifest, with the file under `etc/` that copies the manifest. It is campaigns' command with ledger's name and its own manifest: no settings of its own and so no `[env]`, guests refused, the `application` group and no secrets. `D01-layout-and-run-seam` declares the names this design behaves through: `cli.Process` with its `Version`, the display string `main` read, `cli.Run`, the root package's `Etc` and `Migrations`, `pages.ServiceName` and the `settings` package; `D06-pages` declares `pages.Description` with its value; the nginx fragment `cli.NginxConf` and `etc/nginx.conf` are `D09-on-a-space`'s. Decisions cited as seam N are /home/mgreenly/projects/ikigenba-ledger.md.

## The commands

The arguments decide everything. An empty `Args` means serve, and everything from there is `D03-serve`'s. The three recognised single arguments each write one product to `Stdout` and return `ExitSuccess` without touching anything else: `--version` writes `Process.Version`, the display string `main` read (`D01-layout-and-run-seam`), and a newline, which is one empty line when the host set no identity; `manifest` writes `Manifest`; and `--help` writes `Usage`. The one two-word command, `db status`, reports the database's migrations (below). Any other `Args` is a usage error. The argument ledger complains about is the first one it does not take: the first element when that is not a recognised word, or when it is `db` standing alone; the word after `db` when that is not `status`; the word after `db status`; and otherwise the second, which is surplus whatever it says. An argument that starts with `-` is an unknown option, any other an unknown command. The diagnostic follows the repository's command-line conventions: its first line begins `ledger: `, and after exactly one empty line comes the hint to run `ledger --help`. The usage text is never written to `Stderr`.

Arguments are checked before anything else. A command needs no socket and no setting, and only `db status` reads the database, so `ledger --version` succeeds with nothing passed in and `ledger bogus` fails whatever the environment holds. Unless `Args` is empty, `Run` touches none of the environment, the inherited descriptor, systemd's notification socket, the clock, the pause, the random source, the two sinks, the banner source or the server maker, and only `db status` reads anything under the working directory. A command other than `db status` creates, removes or changes nothing there; `db status` creates nothing in a directory that holds no database and leaves what `db.Status` reports unchanged, though appkit's read-only open of a database `db.Open` made in WAL mode may leave its `-shm` and `-wal` files beside it, so it is not held to leaving a database's directory byte for byte as it was, as campaigns' is not. A command records no event and emits nothing to the bus: the trail is what ledger records while it serves. Every diagnostic is one write to `Stderr`.

## db status

`db status` is an operator's look at the database: which of the migrations the binary carries `state/ledger.db` has had applied, and when, which it has not, and any it records that the binary does not carry. What it prints is appkit's `db.Status`, called with the path `state/ledger.db` (`D01-layout-and-run-seam`) resolved against `Process.Dir` and the migrations `ledger.Migrations()` returns, writing straight to `Stdout`; ledger adds nothing to the lines and states nothing about their format. `db.Status` only looks: it applies nothing and creates nothing, so before ledger's first start every migration is reported pending and the directory is left as it was. When it returns an error, ledger says so on one line, `ledger: ` and the error's text with each newline replaced by a space, and exits 1; whatever `db.Status` had already written to `Stdout` stays there, since findings are product.

## Exit codes

`ExitSuccess` (0), `ExitServerFailed` (1) and `ExitUsage` (2), as every app. A usage error, a setting refused (`D01-layout-and-run-seam`) or a socket missing or doubled (`D03-serve`) is 2; a database that will not open or a drain that ran out on requests (`D03-serve`), or a `db status` that fails, is 1. `Run` returns no other value.

## The usage text

`Usage` is what `--help` prints: the command's synopsis, what ledger is, the commands and options above, and what each exit code means. No program parses it, so it is a copy constant: its words live in the source and no requirement or test spells them; a test compares `Stdout` with the constant itself.

## The manifest

The manifest is a program-parsed file: opsctl, the sandbox, devctl and home read it, so its text is contract and is stated byte for byte, and `etc/manifest.toml` holds the same bytes (seam 1). It names the app `ledger`; its description is `pages.Description` (`D06-pages`), the line the about screen shows and the host publishes in its services file for the MCP gateway's instructions, and a second requirement ties the manifest's description line to that constant so the two cannot drift; it is not the default app; it is an MCP service (`mcp = true`), so the gateway offers its tools; it admits no guests (`guests = false`), so the host's nginx lets no request without a credential reach ledger, the pages and `/mcp` alike, while the pages still send a guest to sign in themselves (`D03-serve`, `D06-pages`); no secrets, since ledger holds none and reaches nothing outside the suite (`D01-layout-and-run-seam`, seam 1, seam 6); no `[env]` table, since ledger has no setting of its own (`D01-layout-and-run-seam`); the `[database]` table that has the host keep and replicate `state/ledger.db`; a `[resources]` table whose only line is `memory_max = "128M"`; and, last, a `[home]` table whose only line is `group = "application"`. `DRAIN_SECONDS` is not in the manifest: it is the space's, as for every app. The manifest declares no port, since ledger serves on the socket the host passes it.

`etc/manifest.toml` holds exactly the text of `Manifest`, and `devctl build` refuses an app where they differ. It is proved by use: the root package embeds `etc/` as `Etc` (`D01-layout-and-run-seam`), so a test in the external test package `ledger_test` compares the embedded `manifest.toml` with the constant.

## Recorded decisions

- **The manifest is stated byte for byte, description included.** campaigns states its description slot by shape because its `pages.Description` is a copy constant declared without a value. ledger's `pages.Description` is declared with its value by `D06-pages` (the departure is `D06-pages`'s to record; seam 1 fixes the manifest's bytes), so `Manifest` spells the description as candidates' does, and the second requirement still binds the description line to `pages.Description`, so the manifest and the about screen publish one string. That value holds no `"`, `\` or control character, so written between the quotes unescaped its TOML value is itself.
- **Departure: `guests = false`.** campaigns sets `guests = true` because its guest route `/t/<token>` must reach a visitor without a credential. ledger has no guest route (`D03-serve`) and its pages are for a signed-in user only (seam 4), so the manifest refuses guests and the host's nginx gates every path; the pages' own redirect of a guest to sign in is `D03-serve`'s and `D06-pages`'s, kept as a second gate in campaigns' pattern.
- **Departure: no settings of ledger's own and no `[env]`.** campaigns' manifest carries an `[env]` table of its two settings' defaults, bound to `settings.Defaults()` by a requirement. ledger has no setting of its own (seam 1: no environment beyond what appkit reads); `settings` holds `DRAIN_SECONDS` only, which is the space's (`D01-layout-and-run-seam`), so the manifest has no `[env]` table and this design no requirement binding one.
- **`Usage` is a copy constant,** as campaigns' is (a departure there from candidates and cron): no program parses `--help`, so it is copy under the spec's own test, declared by name, and a test compares `Stdout` with the constant. The usage-error diagnostic stays spelled because it is an error line a caller matches, which the same rule names as contract.
- `secrets = []` follows from seam 1 and seam 6: ledger calls no sibling but artifacts and nothing outside the suite, and holds no credential. `memory_max = "128M"` and `group = "application"` are seam 1's, the figures campaigns uses.
- **`db status` is exempt from "creates nothing" only as campaigns' is:** a directory that holds no database stays empty, and what `db.Status` reports is the same after as before, because appkit's read-only open of a WAL database may leave `-shm` and `-wal` files.
- **The exit codes are three declarations and one behaviour,** split as campaigns splits them, so a renamed or revalued constant re-mints one id.
- **`db status` is stated here, as campaigns' `D02` states it:** it is a command, its output is appkit's and its path and migrations are `D01-layout-and-run-seam`'s, so `D04-store` says nothing of it.
- No release is named in the manifest or in any requirement.

## Consumer tasks

`main` hands `cli.Run` the process's arguments after the program name, with the other `Process` fields `D01-layout-and-run-seam` names, and exits with what it returns. A developer types `ledger --version`, `ledger manifest` or `ledger --help` and reads stdout; an operator types `ledger db status` in the working directory before or after a deploy; `devctl build` runs `ledger manifest` and compares its output with the release's `etc/manifest.toml`; opsctl reads the manifest and finds no `[env]` to write into ledger's environment.

A test builds a `cli.Process` with only `Args`, `Stdout` and `Stderr` (two `bytes.Buffer`s), `Dir` (an empty temporary directory) and, for `--version`, `Version` set, calls `cli.Run(ctx, p)`, and compares the returned value with `cli.ExitSuccess` or `cli.ExitUsage`, `Stdout` with `p.Version + "\n"`, `cli.Manifest` or `cli.Usage`, and `Stderr` with the exact diagnostic; it then lists `Dir` and finds it empty. To prove nothing else is touched it sets `LookupEnv`, `Unsetenv`, `Inherit`, `Now`, `Sleep`, `Banner` and `MCP` to functions that record a call, `Rand` to a reader that records a read and `Sink` and `EventSink` to sinks that record any use, and asserts none was used. A test of `db status` makes a database under its `Dir` with `db.Open` and `ledger.Migrations()` (or puts a file there that is not a database), closes it, runs `cli.Run` with `Args` `["db", "status"]`, and compares `Stdout` with what its own `db.Status` call writes for the same path and migrations before `Run` is called and with what it writes after, and `Stderr` with `"ledger: "` and that call's error text. A test checks the line of `cli.Manifest` that begins `description = ` against `pages.Description`; a test in package `ledger_test` reads `manifest.toml` from `ledger.Etc()` with `fs.ReadFile` and compares it with `cli.Manifest`.

The one exec'ing test in `cmd/ledger` runs the binary with `--version`, with `manifest` (comparing its stdout with `cli.Manifest`) and with `bogus` (expecting `cli.ExitUsage` and the diagnostic), as well as serving; when it serves, the tools it calls are `book` and `open_account` then `accounts` (`D07-tools`), never `add_document`, so the binary never reaches artifacts. What the binary must do when serving, and the determinism of the first transaction id `Run` mints from a `Rand` yielding `0x5a`, are `D01-layout-and-run-seam`'s.

- R-V8TJ-5H53: The `internal/cli` package MUST export `Manifest` as a string constant whose value is exactly `app = "ledger"\ndescription = "Keep the business's books: accounts, transactions and statements."\ndefault = false\nmcp = true\nguests = false\nsecrets = []\n\n[database]\nengine = "sqlite"\npath = "state/ledger.db"\n\n[resources]\nmemory_max = "128M"\n\n[home]\ngroup = "application"\n`, each `\n` denoting one line feed, each `"` one double quote and `'` one apostrophe.

- R-VB9B-X0MH: The contents of `manifest.toml` in the file system the root package's `Etc` returns MUST be exactly the bytes of `cli.Manifest`.
- R-VCH8-ASD6: The `internal/cli` package MUST export `ExitSuccess` as an untyped integer constant with the value 0.
- R-VDP4-OK3V: The `internal/cli` package MUST export `ExitServerFailed` as an untyped integer constant with the value 1.
- R-VEX1-2BUK: The `internal/cli` package MUST export `ExitUsage` as an untyped integer constant with the value 2.
- R-VG4X-G3L9: Every call of `Run` MUST return one of `ExitSuccess`, `ExitServerFailed` and `ExitUsage` and no other value.
- R-VHCT-TVBY: When `Args` is exactly `["--version"]`, `["manifest"]` or `["--help"]`, `Run` MUST write exactly `p.Version + "\n"`, `Manifest` or `Usage` respectively to `Stdout` and nothing else, write nothing to `Stderr`, and return `ExitSuccess`; so that an empty `p.Version` writes exactly `"\n"`.
- R-VIKQ-7N2N: `Run` MUST treat `Args` as a usage error unless it is empty or exactly one of `["--version"]`, `["manifest"]`, `["--help"]` and `["db", "status"]`; the offending argument MUST be `Args[0]` when it is none of `--version`, `manifest`, `--help` and `db` or when `Args` is exactly `["db"]`, `Args[2]` when `Args[0]` is `db` and `Args[1]` is `status`, and `Args[1]` otherwise; so that `["db"]` names `db`, `["db", "bogus"]` names `bogus`, `["db", "status", "extra"]` names `extra` and `["manifest", "extra"]` names `extra`.
- R-VJSM-LETC: On a usage error from `Args`, `Run` MUST write exactly `"ledger: unknown option '" + arg + "'\n\nsee 'ledger --help' for usage\n"` to `Stderr` in one call to `Stderr.Write` when the offending argument `arg` begins with `-`, and exactly `"ledger: unknown command '" + arg + "'\n\nsee 'ledger --help' for usage\n"` otherwise, write nothing to `Stdout`, and return `ExitUsage`; so that `["bogus"]` writes `ledger: unknown command 'bogus'` and `["--bogus"]` writes `ledger: unknown option '--bogus'` as its first line.
- R-VM8F-CYAQ: When `Args` is not empty, `Run` MUST return without calling `LookupEnv`, `Unsetenv`, `Inherit`, `Now`, `Sleep`, `Banner` or `MCP`, without calling `Rand`'s `Read`, without calling the `Deliver` of `Sink` or `EventSink`, without taking file descriptor 3 and without sending anything to a notification socket, so that a `Process` whose `Args`, `Stdout`, `Stderr` and `Dir` alone are set is enough for every command; and, unless `Args` is exactly `["db", "status"]`, without creating, removing or changing anything under `Dir`, so that a `Dir` naming an empty directory is still empty when `Run` returns.
- R-VNGB-QQ1F: When `Args` is exactly `["db", "status"]` and `Dir` names an empty directory, that directory MUST still be empty when `Run` returns.
- R-VOO8-4HS4: When `Args` is exactly `["db", "status"]`, the bytes appkit's `db.Status` writes for a `db.Config` whose `Path` is `filepath.Join(Dir, "state", "ledger.db")` and whose `Migrations` is the root package's `Migrations()` MUST be the same after `Run` returns as before `Run` was called.
- R-VPW4-I9IT: When `Args` is exactly `["db", "status"]`, `Run` MUST write to `Stdout` exactly the bytes, and nothing else, that appkit's `db.Status` (package `github.com/ikigenba/ikigenba/appkit/db`) writes when called with a context that is not done and a `db.Config` whose `Path` is `filepath.Join(Dir, "state", "ledger.db")` and whose `Migrations` is the root package's `Migrations()`, over the database as it is when `Run` is called; and when that call returns nil, `Run` MUST write nothing to `Stderr` and return `ExitSuccess`.
- R-VR40-W19I: When `Args` is exactly `["db", "status"]` and the `db.Status` call that writes the status returns a non-nil error `err`, `Run` MUST write exactly `"ledger: " + r + "\n"` to `Stderr` in one call to `Stderr.Write`, `r` being `err.Error()` with every newline replaced by one space, and return `ExitServerFailed`; so that a `Dir` whose `state/ledger.db` is a regular file that is not a SQLite database gets that one line on `Stderr`.
