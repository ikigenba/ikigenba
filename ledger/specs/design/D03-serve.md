# D03-serve

The serve path: what happens between `cli.Run` being called with no arguments and the process being gone, the services file and the one sibling client built from it, the terms ledger serves on, the listener's life, and the route table its one handler keeps with the identity each route takes. It is campaigns' serve path less the `candidates` client, the guest route and the two link settings: ledger has one sibling, artifacts, no route outside identity but the bus's two paths, and no setting of its own. The identity gate keeps campaigns' shape (appkit's `identity.Optional` before the pages and the shared files, `identity.Require` at `/mcp`), while the manifest's `guests = false` has nginx gate every path as well. This document declares `internal/server` and `internal/web`. Decisions cited as seam N are /home/mgreenly/projects/ikigenba-ledger.md.

`D01-layout-and-run-seam` declares the run seam (`cli.Process`, `cli.Run`), the settings (`settings.Settings`, `settings.Read` and `Drain()`), the database path, `pages.ServiceName` and the root package's `Migrations()`; `D02-cli` the exit codes (`ExitSuccess`, `ExitUsage`, `ExitServerFailed`) and the manifest; `D04-store` the store (`store.New`, `store.Config`); `D05-events` the bus event, `trail.Emits()` and what `/events` and `/declarations` answer; `D06-pages` the pages (`pages.Load`, `pages.Handler`, `pages.Config`), the auth and sign-in addresses (`pages.Auth`, `pages.SignIn`), the sign-in redirect a guest gets and the tools page; `D07-tools` the tools (`tools.Register`, `tools.Config`, `tools.Catalog`) and their refusals; `D08-trail` the trail as a whole, `sibling.called` and its secrecy; `D09-on-a-space` the nginx fragment and the trust. appkit's `db`, `telemetry`, `events`, `identity`, `page`, `mcp`, `services` and `artifacts` packages own their contracts; this document wires them and restates none of them.

## The services file

`IKIGENBA_SERVICES` names the services file. ledger uses four of its entries: `artifacts`, whose socket `add_document` reaches through appkit's `artifacts` client, `Head` then `Show` (seam 6); `auth`, read afresh per request by the pages through `pages.Auth` and `pages.SignIn` for the banner's links and a guest's sign-in address (`D06-pages`); and `events` and `telemetry`, appkit's sinks', which read the file afresh on each delivery.

`Run` reads the file once, when it starts to serve, and builds the `artifacts` client with `artifacts.NewClient(artifacts.ClientConfig{Service: e, Telemetry: w})` from the entry `artifacts` it finds then, or none (a nil client) when the file holds no such entry. Building it does no I/O and cannot fail, so an entry whose socket nothing serves on refuses nothing at the start; the first `add_document` call finds out. With no client, or with one whose sibling does not answer, `add_document` is refused `unavailable` (`D07-tools`); everything else serves as with it. A missing entry never stops the start (seam 1). With `IKIGENBA_SERVICES` unset, naming no file, or naming one `services.Read` refuses, the start is not refused and ledger serves as with a file holding no entry. A changed `artifacts` entry reaches the tools at the next start; a changed `auth` entry reaches the next page request.

Every request the client sends carries the caller of the tool call it is sent for, forwarded by appkit's client from the context, so artifacts sees the signed-in user, and each is recorded by the client as `sibling.called` (`D08-trail`).

## The terms ledger serves on

ledger serves only on a listening socket it inherits, taken as `sd_listen_fds(3)` documents, and reports readiness with `READY=1` to `NOTIFY_SOCKET` as `sd_notify(3)` documents. It trusts `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx sets them, and trusts the MCP gateway to have forwarded them (`D09-on-a-space`). Every request has an id: the one nginx or the caller set, or 32 lowercase hexadecimal digits appkit's telemetry middleware draws from `Process.Rand`.

The manifest declares `guests = false` (`D02-cli`), so nginx admits no request without a credential, to the pages and to `/mcp` alike. A request with no `X-User-Id`, or an empty one, is a **guest**, whatever `X-User-Email` it carries; on a host none reaches ledger but on the bus's two paths, which the events app calls over the socket, and the handler still answers one as below.

The events app reaches ledger at its socket on `/events` and `/declarations`. ledger emits one bus event and accepts none (`D05-events`), so it mounts appkit's `events.DeliveryHandler` with no handlers and `events.DeclarationsHandler` over the run's emitter, built with `trail.Emits()`, with no handlers. These two paths sit outside the identity gate; the fragment answers both 404 at the public name (`D09-on-a-space`).

## The route table

Every request goes through appkit's `telemetry.Middleware` over `Config.Telemetry`, which records the request pair (`D08-trail`) and puts the request's caller on its context. Then, by `URL.Path` alone, compared by hand, so nothing is cleaned and nothing redirected:

- exactly `/events` and exactly `/declarations`: the event bus's two handlers, every method, with or without identity.
- exactly `/mcp`: appkit's `events.Middleware`, then `identity.Require`, then the MCP server `Config.MCP`, on which the tools of `D07-tools` are registered with `tools.Register` once, when the handler is built. A guest is answered `identity.Require`'s 500 with `identity.MissingBody`, which on a host never happens because nginx demands a credential first.
- a path beginning `/_appkit/`: `identity.Optional`, then `page.Static()`; nothing there is private.
- every other path: `identity.Optional`, then the page handler, `pages.Handler` over `pages.Config` (`D06-pages`), which sends a guest a 302 to the sign-in address and draws the page for a signed-in user. So `/`, `/about`, `/tools`, and `/nope`, `/t/x`, `/mcp/`, `/events/`, `/declarations/` and `/_appkit` all reach it.

There is no guest route. This document states the routing only: which handler answers which path, under which identity. What a page, a tool or a bus path answers is the owning document's. No answer on any route carries `Set-Cookie`.

The handler is built from a `web.Config` carrying what its routes need: the banner source, the MCP server, the services file's path, the store, the writer, the emitter, the artifacts client (nil when the services file named none at the start) and the settings. `web.Handler` builds the page handler and the tool registration from it; which fields each of `pages.Config` and `tools.Config` takes is that document's.

## The start

With `Args` empty, `Run` checks the settings (`D01-layout-and-run-seam`), then whether exactly one socket was passed in, with the diagnostics below. It removes the three `LISTEN_*` variables, takes descriptor 3, and opens the database with `db.Open` at `state/ledger.db` with `ledger.Migrations()` and `Process.Now`; a failure is `ledger: cannot open database state/ledger.db: ` and the reason, exit 1. It builds the store with `store.New` and `store.Config` over `Process.Now` and `Process.Rand` (`D04-store`), the run's writer, the run's emitter with `trail.Emits()`, and the artifacts client from the services file; records `service.started`, so that it is the first event of every run; builds the handler, calling `Process.MCP` once with the writer; sends `READY=1`; and serves. Nothing is settled, swept or loaded at the start: ledger works nothing in the background.

## Stopping

When `ctx` is done (in the binary, on `SIGTERM` or `SIGINT`, the signal's name being the cause) `Run` drains the server for `DRAIN_SECONDS` (`settings.Settings.Drain()`), waits within the same window for the emitter to deliver what it holds, shuts the writer down with the cause's text as `service.stopping`'s reason, shuts the emitter down, and closes the database. From the drain deadline on, `Run` hands neither sink anything: an event recorded after it reaches standard error as appkit's `undelivered event` and `lost event` lines. A drain that runs out on requests is `ledger: stopped with <n> request(s) unfinished`, exit 1.

## Recorded decisions

- **`internal/server` is campaigns', unchanged**: one function and one error type, declared here because `D01-layout-and-run-seam` assigns the listener's life to this document.
- **Pages use `identity.Optional` and a 302 to sign in, and the manifest says `guests = false` so nginx gates too** (orchestrator decision). The identity gate keeps campaigns' shape, `identity.Require` at `/mcp` alone and `identity.Optional` before the pages and the shared files, so a guest that reaches a page anyway is sent to sign in by the page handler (`D06-pages`) rather than answered a 500; and with `guests = false` nginx demands a credential on every path, so on a host no guest reaches either. Departure from candidates, whose every route but the bus's sits behind `identity.Require` and whose guest is answered `identity.Require`'s 500 at the handler; ledger keeps the page handler's redirect as campaigns has it. The 302 is `D06-pages`'; this document only routes the guest there.
- **No guest route.** Departure from campaigns' `/t/`: ledger has no record a visitor without a credential may reach (seam 4, every page is for a signed-in user), so no path sits outside identity but the bus's two, and a path beginning `/t/` is the page handler's like any other.
- **`/_appkit/` goes through `identity.Optional`**, as campaigns' does: the shared files are not private, and the wrapper changes no answer.
- **The artifacts client is built once, at the start**, from the entry the services file names then, as campaigns builds its sibling clients; the pages, which only build addresses, read the file afresh per request (`D06-pages`).
- **`web.Config` carries the client, not the services entry**, so every `add_document` call shares one client, built with the run's writer so its `sibling.called` events reach the trail.
- **`web.Config` carries the settings whole**, as campaigns' does, though ledger's settings hold only `DrainSeconds` (`D01-layout-and-run-seam`), which the handler does not read; a setting a handler needs later is added to `settings` without reshaping `web.Config`.
- **`web.Config` carries no clock and no random source**, as campaigns' carries none: every time ledger stamps and the today it measures against are the store's `store.Config.Now` (`D04-store`), and every id the store's `store.Config.Rand`; the writer and the emitter hold their own. A handler that needs one later adds it here with a new id.
- **`/events` is `D05-events`'**, which states it at `web.Handler`; this document states `/declarations` at the handler, since `D05-events` states only what `events.DeclarationsHandler` answers and the body it publishes.
- **The start's answer to a failing database after `db.Open` is not required.** The start reads nothing from the store before ready, so there is no settling to fail; a store failure is provoked only on a handle a test hands in (ledger's AGENTS.md pattern), which `cli.Run` never takes.

## Consumer tasks

`Run`, serving, calls `s, err := settings.Read(p.LookupEnv)`, checks the socket, unsets the three `LISTEN_*` variables and takes `ln, _ := p.Inherit(3)`; opens `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "ledger.db"), Migrations: ledger.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: stderr})`; builds `st := store.New(d, store.Config{Now: p.Now, Rand: rnd})` (`rnd` the one serialized reader over `p.Rand` it shares with the writer and the emitter), `w := telemetry.New(...)`, `em := events.New(events.Config{..., Telemetry: w, Emits: trail.Emits()})`; reads `list, err := services.Read(path)` and builds `ac := artifacts.NewClient(artifacts.ClientConfig{Service: e, Telemetry: w})` when `e, ok := list.Find("artifacts")` finds an entry (nil otherwise); calls `w.Ready()`; builds `h := web.Handler(web.Config{Banner: p.Banner, MCP: p.MCP(w), ServicesPath: path, Store: st, Telemetry: w, Events: em, Artifacts: ac, Settings: s})`; sends `READY=1`; and calls `server.Serve(ctx, ln, h, s.Drain(), stop)`, `stop` flushing `em`, then `w.Shutdown(c, context.Cause(ctx).Error())`, then `em.Shutdown(c)`; answers a `*server.DrainError` with `ledger: ` and its text, `ExitServerFailed`; closes `d`.

`web.Handler(cfg)` calls `tools.Register(cfg.MCP, tools.Config{Store: cfg.Store, Telemetry: cfg.Telemetry, Events: cfg.Events, Artifacts: cfg.Artifacts})` once, loads `set, err := pages.Load()`, builds `pages.Handler(pages.Config{Banner: cfg.Banner, Pages: set, ServicesPath: cfg.ServicesPath, Store: cfg.Store, MCP: cfg.MCP})`, mounts `events.DeliveryHandler(nil)` at `/events` and `events.DeclarationsHandler(cfg.Events, nil)` at `/declarations`, and returns `telemetry.Middleware(cfg.Telemetry, mux)`.

A test of the handler builds `web.Handler` over a store on its own database, a writer and an emitter over captures, a server from `mcp.NewServer`, `settings.Defaults()` and an appkit `artifacts` client built on a fake's socket (or nil), serves it with `httptest`, and sends raw requests with the identity headers set or left out, and `/mcp` calls through `mcp.Client`. A test of the start drives `cli.Run` with a listener, a `NOTIFY_SOCKET` it binds, a `Now`, a `Sleep` and a `Rand` it controls, a services file whose `artifacts` entry names a fake's socket (or that leaves it out) and whose `auth` entry names a URL of its own; waits for `READY=1`; drives `/mcp` with `mcp.Client` and the pages with raw HTTP; rewrites the services file; cancels; and inspects the fake's records, the captures, the streams and the exit code.
