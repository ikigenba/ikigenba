# D08-trail

The trail as a whole: the eleven trail-only events that tell ledger's mutations, the closed set of event names ledger records, the request pair the telemetry middleware records for every request, `sibling.called` for every request to artifacts, the one trail event each mutation records, the clock and the random source every event is stamped and named from, and secrecy, stated once for the whole app. Decisions cited as seam N are /home/mgreenly/projects/ikigenba-ledger.md.

Who records each name is another document's, but for the eleven declared here. The request pair is appkit's `telemetry.Middleware`'s, which `D03-serve` mounts on every request; `tool.called` is appkit's MCP server's; `service.started` and `service.stopping` are `D03-serve`'s, through the run's writer; `event.lost` is appkit's emitter's, since the emitter is built with the writer; `sibling.called` is appkit's `artifacts` client's, which records one for every request it sends. `transaction.posted`, its constant `trail.EventTransactionPosted`, and the functions `trail.TransactionPosted` (trail and bus, for `post`) and `trail.ReversalPosted` (bus only, for `reverse`) are `D05-events`'. The eleven trail-only names, their constants and the eleven functions that record them are declared here, in the same package `trail`. Which tool calls change something, and so call which function, is `D07-tools`'; what a change is, and whether one happened, is `D04-store`'s. This document states what each function records and what the assembled run shows of all of them.

## The eleven trail-only events

Each mutation but a posting is told in the trail by one event, with fixed attribute keys, every key always present (seam 5):

- `account.opened`: `account` (the account's name), `date` (its open date).
- `account.closed`: `account`, `date` (its close date).
- `transaction.annotated`: `transaction` (the transaction's id), `version` (the number of the annotation version the call wrote, an integer).
- `transaction.reversed`: `transaction` (the reversal's id), `reverses` (the original's id), `date` (the reversal's date).
- `assertion.added`: `assertion` (the assertion's id), `account`, `date`, `amount` (the expected amount as the store renders it), `commodity` (its commodity's code).
- `assertion.retracted`: `assertion`.
- `note.added`: `note` (the note's id), `account`, `date`.
- `note.retracted`: `note`.
- `document.added`: `document` (the document's id), `account`, `date`, `transaction` (the transaction it names, empty when none), `artifact` (the artifact's id artifacts answered).
- `document.retracted`: `document`.
- `book.changed`: `lock_date`, `fiscal_year_start`, the book as it stands after the change.

Every value is a string but `version`, an `int64`. The time of each is the event's own `Time`, and who made the change is the event's `User`, the caller's user id, so no attribute repeats either. No event carries a narration, a payee, a note's text, a metadata value or an email.

Each function takes the call's context and plain values, records one event through the writer it is given, under the request id and user of the `identity.Caller` on that context, queues and returns, returns nothing, and is safe to call from many goroutines at once. None takes an emitter: these names never go on the bus.

## One event per mutation

Seam 5 has every mutation record one event in the trail. A `post` records `transaction.posted` through `D05-events`' `TransactionPosted`, which also emits it on the bus. A `reverse` records `transaction.reversed` here, naming both ids, and its `transaction.posted` goes on the bus only, through `D05-events`' `ReversalPosted`, so the trail holds one event for the reversal, not two. Every other mutation records the one event above that names it. Each is recorded under the tool call's context, before that call's `tool.called`. A read, a refused call and a call that changes nothing record none of the twelve; which calls those are is `D07-tools`'.

## The request pair

Every request, whatever its path and whether or not it carries an identity, is recorded by the telemetry middleware as one `request.started` (method, path) and one `request.finished` (status, duration, bytes), under its request id and its caller's user. The path is the request's URL path without its query. A guest's request to a page is answered with a redirect to sign in (`D06-pages`) and records the pair with no user; a request to `/mcp` with no identity is refused by appkit's `identity.Require` and records the pair likewise. A delivery from the bus, `POST /events`, answered by appkit's delivery handler with no handlers, records the pair alone. ledger has no guest route: every event it records of its own is made inside a signed-in call and names that call's user.

## The bus and the trail

The trail record of a change does not depend on the bus. A bus that refuses or loses every event leaves the same twelve-name events in the trail, and appkit's emitter, built with the run's writer, records one `event.lost` for each bus event it drops, with `event`, the bus event's id, and `cause`, its cause, under the bus event's request id and user; the trail shows both that the change happened and that the bus never heard of it. The line a drop writes to standard error is `D03-serve`'s.

## sibling.called

One `sibling.called` per request to artifacts: `target` `artifacts`, the services file's entry name, with the method and path appkit's `artifacts` client sends for each of `Head` and `Show`, which `add_document` calls in that order, `Show` only once `Head` has passed (seam 6, `D07-tools`). Each carries the request id and user of the tool call it was made for, since appkit's client forwards the caller on the context. ledger calls no other sibling (seam 1, `D01-layout-and-run-seam`), so no `sibling.called` names another target. What artifacts answers beyond the artifact's id, its owner, content type and address, reaches no event.

## The clock and the random source

Every event's time is read from `Process.Now`, and every request id the run mints and every bus event id are drawn from `Process.Rand` (`D01-layout-and-run-seam`). A test fills them with a fixed clock and a constant reader and finds the stamps and ids those give. Which ids and times the store mints from the same two is `D04-store`'s.

## Secrecy

No event, in the trail or on the bus, carries a payee, a narration, a note's text, a metadata value or an email (seam 5). Events carry ids, dates, account names, amounts and commodity codes, keys, flags, version numbers, tool names, methods and paths, counts and times. The rule is proved at the run seam, by use: the test's payees, narrations, note texts, metadata values and identity emails each hold a random **marker**, a fake artifacts answers with a marker in each of its metadata's content type, owner and address, fails some requests with a body holding every marker, and refuses some `show` calls with a refusal whose text holds every marker, and every capture of the run, and both output streams, are searched for every marker.

## Recorded decisions

- **Departure: the trail-only names and their functions are declared here** (from campaigns' trail, which declares no name and leaves every constant and function to its events document). campaigns' trail-only name was one beside three bus names; ledger has one bus name and eleven trail-only ones, so `D05-events` declares the bus half of package `trail` and this document the rest. Each name is still declared once, and `D05-events` cites these by name.
- **One trail event per mutation, so a reversal's `transaction.posted` is not in the trail** (seam 5; the root's ruling): the reversal's trail record is `transaction.reversed`, which names both ids, and its bus event goes through `ReversalPosted`, which takes no writer. The departure from campaigns' "two ways at once" for every bus event is `D05-events`' to record; this document states the trail's side of it.
- **The user is the event's `User`, not an attribute**: seam 5 has attributes carry "the user id"; appkit's writer stamps every event with the caller's user from the context, so a second copy as an attribute would invite two answers.
- The recording functions take plain values, not store records, as campaigns' do, so the trail's contract does not move when a store record gains a field.
- `version` is an `int64`, the one non-string attribute, because it is a number the `history` tool answers as one; appkit's attributes allow integers.
- `amount` in `assertion.added` is the expected amount as `store.Amount`'s `String` renders it, with `commodity` beside it, as every answer renders an amount (`D07-tools`), so the trail and the tools agree on one text.
- `book.changed` carries both of the book's editable values as they stand after the change, whichever one the call changed, so the trail alone shows the book at each change.
- **What is not a marker**: account names, keys, tags, links, metadata keys, artifact paths and every id. Account names, amounts and keys are what the events carry by design (seam 5); an artifact path reaches `sibling.called`'s `path` because appkit's client sends it in the request path, and a path names a file the space keeps; tags, links and metadata keys are the caller's labels, not words about a counterparty. Only the five kinds seam 5 names are markers.
- **Departure: secrecy under a failing database is not proved here**, as in campaigns' trail: the run builds its store over its own handle, so the run seam cannot provoke it, and a store failure's refusal is fixed copy (`D07-tools`) holding no value the store or a sibling supplied.
- Markers are compared without regard to letter case.

## Consumer tasks

The tools (`D07-tools`) call, each with the tool call's context and only once the store has reported the change made: `trail.AccountOpened(ctx, cfg.Telemetry, a.Name, a.Open)` for an `open_account` that opened, `trail.AccountClosed(ctx, cfg.Telemetry, a.Name, a.Close)` for a `close_account` that closed, `trail.TransactionAnnotated(ctx, cfg.Telemetry, t.ID, t.Annotation.Version)` for an `annotate` that wrote a version, `trail.TransactionReversed(ctx, cfg.Telemetry, r.ID, r.Reverses, r.Date)` beside `trail.ReversalPosted` for a `reverse` that made a reversal, `trail.AssertionAdded(ctx, cfg.Telemetry, row.Assertion.ID, row.Assertion.Account, row.Assertion.Date, row.Assertion.Expected.String(), row.Assertion.Expected.Commodity)`, `trail.AssertionRetracted(ctx, cfg.Telemetry, row.Assertion.ID)`, `trail.NoteAdded(ctx, cfg.Telemetry, n.ID, n.Account, n.Date)`, `trail.NoteRetracted(ctx, cfg.Telemetry, n.ID)`, `trail.DocumentAdded(ctx, cfg.Telemetry, d.ID, d.Account, d.Date, d.Transaction, d.Artifact)`, `trail.DocumentRetracted(ctx, cfg.Telemetry, d.ID)`, and `trail.BookChanged(ctx, cfg.Telemetry, s.Book.LockDate, s.Book.FiscalYearStart)` for a `set_book` that changed the book. A unit test builds a writer with `telemetry.New(telemetry.Config{Service: "ledger", Sink: capture, Now: now, Rand: rnd})` over a `*telemetry.Capture`, calls a recording function under `identity.NewContext(ctx, identity.Caller{UserID: u, RequestID: q})`, flushes the writer, and compares the captured events' `Name` with the constant, and their `Attrs`, `RequestID` and `User`. A run-level test drives `cli.Run` with a `*telemetry.Capture` as `Sink`, an `*events.Capture` as `EventSink`, buffers as `Stdout` and `Stderr`, a `Now` returning one fixed time, a `Rand` that never repeats an id (a constant reader only for the determinism test of R-7TH1-P4P5), and a services file whose `artifacts` entry names a Unix socket on which a fake artifacts answers appkit's `artifacts` client and records every request; waits for `READY=1`; calls every change tool with `mcp.Client`, each call with an `X-Request-Id` of its own; requests the pages as a guest and as a user; cancels; and compares each captured event's `Name` with the closed set, the twelve names under each call's request id with that call's `tool.called`, and the `sibling.called` events with the fake's recorded requests. A test of the drop hands `EventSink` one that answers every `Deliver` with an error wrapping `events.ErrRejected`. A test of secrecy runs the conditions R-OPVI-XV46 names and searches both captures and both streams for every marker.
