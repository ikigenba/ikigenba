# D03-serve

The serve path: what happens between `cli.Run` being called with no arguments and the process being gone, the trail artifacts records of itself, the hourly sweep of expired artifacts, and the route table its handler keeps. It is webhooks' serve path with four differences: every route but the events app's two is behind appkit's `identity.Require`, as prompts' are, since the manifest says `guests = false`; the paths under `/files/` reach the files surface (`D05-files`) with the path exactly as sent; the start makes the blob directory and reconciles the store against it before anything is served; and the sweeper's deletions, and the reconcile's, are told as `artifact.deleted` events. `internal/server` is webhooks', unchanged.

## The terms artifacts serves on

artifacts serves only on a listening socket it inherits, taken as `sd_listen_fds(3)` documents, and reports readiness with `READY=1` to `NOTIFY_SOCKET` as `sd_notify(3)` documents. It trusts `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx sets them, and trusts the MCP gateway calling it at its socket to have forwarded them. Every request has an id: the one nginx set, or 32 lowercase hexadecimal digits appkit's request middleware draws from `Process.Rand`.

The events app reaches artifacts at its socket on `/events` and `/declarations`. artifacts accepts no event, so it mounts appkit's `events.DeliveryHandler` with no handlers, and `events.DeclarationsHandler` over its emitter, built with the three declarations of `trail.Emits()` (`D07-trail`). These two paths sit outside the identity gate, since a delivery carries no user; the fragment answers both 404 at the public name (`D02-cli`).

## The route table

Every request goes through appkit's `telemetry.Middleware`, which records `request.started` and `request.finished`. Then, by path alone, whatever the host, compared by hand so that nothing is cleaned and nothing redirected: exactly `/events` and exactly `/declarations` go to the event bus's two handlers; every other request goes through `identity.Require`, which answers a request with no `X-User-Id` 500 with `identity.MissingBody` before its path or method is looked at. Past the gate: exactly `/mcp` goes, through `events.Middleware`, to the MCP server with artifacts' own base on the context for the tools (`urls.NewContext`, `D08-tools`); a files request, whose escaped path begins `/files/`, goes through `events.Middleware` to `files.Handler`, with the path untouched, so `/files/a//b` is the files surface's 400 and never a redirect; a path beginning `/_appkit/` goes to `page.Static()`; and every other path to `pages.Handler` (`D06-pages`), which answers `/`, `/about`, `/tools`, `/<id>` and the not-found page. On a host nginx demands a credential before any of these, so the gate's 500 is only seen by a caller on the socket.

## The start

With `Args` empty, `Run` checks the settings (`D01-layout-and-run-seam`), then whether exactly one socket was passed in, exactly as webhooks does, with the same diagnostics after `artifacts: `. It removes the three `LISTEN_*` variables, takes descriptor 3, and opens the database with `db.Open` at `state/artifacts.db`; a failure is `artifacts: cannot open database state/artifacts.db: ` and the reason. It then makes `state/blobs` when absent; a failure, as when a regular file stands there, is `artifacts: cannot create directory state/blobs: ` and the reason. It builds the store, the writer and the emitter, and reconciles the store against the blob directory (`store.Reconcile`, `D04-store`); a failure is `artifacts: ` and `store.Unreachable`. Each refusal is exit 1, with nothing sent to the notification socket and no connection accepted. Then it records `service.started`, so that it is the first event of every run, records each record the reconcile removed as `artifact.deleted` under its owner, starts the sweeper, which sweeps once before it goes on, builds the handler, sends `READY=1`, and serves.

## The sweeper

The sweeper deletes every artifact whose expiry has come (`store.Sweep`), once at start and then each time a wait of `sweeper.Interval`, one hour, on `Process.After` ends. Each artifact it deletes is told as `artifact.deleted` through `trail.Record`, as its owner: a context `identity.NewContext` builds with the owner's user id and email, no request id and no event cause. A sweep that fails, the database being unreachable, is silent and tried again at the next interval, as webhooks' is.

## Stopping

When `ctx` is done `Run` stops the sweeper, drains the server for `DRAIN_SECONDS`, waits within the same window for the emitter to deliver what it holds, shuts the writer down with the cause's text as `service.stopping`'s reason, shuts the emitter down, and closes the database. A drain that runs out is `artifacts: stopped with <n> request(s) unfinished`, exit 1. Between its start and its return a serving `Run` writes nothing to standard output or standard error.

## Recorded decisions

- `guests = false`, so the gate is `identity.Require` on every route but the events paths, `/_appkit/` and `/files/` included, as in prompts; webhooks' `identity.Optional` and its sign-in redirect have no counterpart, and `urls` has no `SignIn`.
- `/files/` goes through `events.Middleware` as `/mcp` does, so that a caller that forwards `X-Event-Cause` and `X-Event-Depth`, a script run by an event say, makes events that carry the cause and the depth, and the events app's depth limit stops a script subscribed to `artifact.*` that writes artifacts from looping forever. webhooks' ingress ignores those headers because its callers are outside the suite; artifacts' are inside it.
- The files route is chosen on the escaped path and the router never cleans or redirects, so the path grammar is the files surface's alone (`D05-files`).
- `service.started` is recorded before the reconcile's and the first sweep's deletions are told, and so before `READY=1` is sent, where webhooks records it after: those deletions are events of this run, and `service.started` is to be the first. The reconcile and the first sweep still finish before `READY=1`, so a start never serves a record without its file, or an expired artifact a sweep could have removed.
- A record the reconcile removes is told as `artifact.deleted` under its owner, both ways, like a swept one, so a subscriber hears of every artifact that goes, in one vocabulary (decisions document, decision 15, which asks that it be recorded in the trail). A file the reconcile removes is a crash's leftover that no record named, and is told nowhere.
- The database is opened before `state/blobs` is made, so a regular file named `state` is the database's line, as in webhooks, and only a regular file at `state/blobs` is the blob directory's.
- A failed reconcile refuses the start, as prompts' failed `Recover` does: serving over records whose files may be gone would answer 503 or 404 where a record says otherwise. The line quotes no cause.
- A sweep that fails is silent, at start too, as webhooks' is.
- `web.Config` carries the run's `Settings`, `Now` and `ImportAfter`, which webhooks' does not, so the files surface gets its cap and the tools their cap, clock, import bound and timer (`D08-tools`, `D09-import`). The files surface needs no clock of its own: its expiry check is the store's, whose `Now` is `Process.Now`.

## Consumer tasks

`Run`, serving, calls `s, err := settings.Read(p.LookupEnv)`, checks the socket, unsets the three `LISTEN_*` variables and takes `ln, _ := p.Inherit(3)`; calls `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "artifacts.db"), Migrations: artifacts.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: p.Stderr})`; makes `blobs := filepath.Join(p.Dir, "state", "blobs")`; builds `st := store.New(d, blobs, store.Config{Now: p.Now, Rand: rand})`, `w := telemetry.New(...)` and `em := events.New(events.Config{..., Telemetry: w, Emits: trail.Emits()})`; calls `gone, err := st.Reconcile(ctx)`; calls `w.Ready()` and, for each `a` of `gone`, `trail.Record(identity.NewContext(bg, identity.Caller{UserID: a.OwnerID, Email: a.OwnerEmail}), w, em, trail.Deleted, a)`; calls `sw := sweeper.Start(ctx, sweeper.Config{Store: st, Now: p.Now, After: p.After, Telemetry: w, Events: em})`; builds `h := web.Handler(web.Config{Banner: p.Banner, MCP: p.MCP(w), ServicesPath: path, Store: st, Telemetry: w, Events: em, Settings: s, Now: p.Now, ImportAfter: p.ImportAfter})`; sends `READY=1`; and calls `server.Serve(ctx, ln, h, s.Drain(), stop)`, `sw.Stop()` coming first once `ctx` is done. A test of the start drives `cli.Run` with a temporary `Dir`, a listener on a Unix socket in a short temporary directory, a `NOTIFY_SOCKET` it binds, a `Now`, an `After` and a `Rand` it controls, a `*telemetry.Capture` and an `*events.Capture`; it seeds `Dir` beforehand, through its own `db.Open` and a store over it, with artifacts whose files it then removes or whose expiry has passed, or with stray files in `state/blobs`, or with a regular file at `state` or at `state/blobs`, or with a database in which its own handle dropped the table `artifacts` through `DB.Write`. A test of the handler builds `web.Handler` over a store on its own database and blob directory, a writer and an emitter over captures, and a server from `mcp.NewServer`, serves it with `httptest`, and sends raw requests with the identity headers set or left out. A test of the sweeper calls `sweeper.Sweep` and `sweeper.Start` with a `Now` and an `After` it controls and inspects the store and the captures.
