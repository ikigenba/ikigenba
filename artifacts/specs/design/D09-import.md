# D09-import

How an agent learns to put a file: the `import` tool's behavior (`D08-tools` declares the tool, its arguments and its place in the catalog). `import` moves no bytes and stores nothing. Given a path, and optionally a content type and an expiry, it answers the plan an agent follows from its own shell: the URL, the method, the headers and short instructions. The agent then sends the file itself, a `PUT` to that URL (`D05-files`), and only that `PUT` creates or replaces the artifact; a `GET` of the same URL reads it back.

## The plan

The answer is a JSON object of four members, `tools.Plan`. `url` is the artifact's address on the artifacts host, `urls.File` of `tools.Config.Base`, which `web.Handler` sets to `urls.Configured` of the services file (`D03-serve`, `D05-files`): the URL of the services file's entry `artifacts` followed by `/files/` and the path, or `/files/<path>` alone when no entry names artifacts, as in a bare test process. It is not the request's base: through the gateway a request's `Host` is the gateway's backend name, an address the agent cannot reach. `method` is `PUT`. `headers` is an object naming the headers to send by their exact names: `Authorization`, always, holding `tools.BearerPlaceholder`, which stands for the agent's own bearer token; `Content-Type`, always, the `content_type` given, or `application/octet-stream` when none is given; and `X-Artifact-Expires`, only when `expires` was given, holding it as given. `instructions` is `tools.ImportInstructions`.

## Refusals

`import` refuses up front what the `PUT` it plans would refuse, so an agent learns it before sending a byte: a path that breaks the rule (`tools.InvalidPath`), an `expires` that does not parse as the `PUT`'s `X-Artifact-Expires` must (`tools.InvalidExpiry`), an expiry not later than now (`tools.PastExpiry`), and a path whose artifact another user owns (`tools.NotOwner`); and the database with `store.Unreachable`. The owner of the path's artifact gets a plan, which replaces it when followed. A refusal is the error result `D08-tools` describes.

## Recorded decisions

- `import` answers a plan instead of fetching a file from a sibling: no tool carries bytes, and the agent's own `PUT` is the one way a path is created or replaced. The fetch went with it: `internal/fetch`, the sibling client, the services file as an allow list of origins, `IMPORT_SECONDS` and its timer (`D01-layout-and-run-seam`).
- `import` is a read tool (`D08-tools`): it reads the store to judge the owner, and records nothing but the `tool.called` every tool call records.
- The checks run in the order path, expiry's form, expiry not later than now, store, owner. The checks that need no store come first, as `show` and `delete` judge a path before they ask the store, so, unlike a `PUT`, whose failing handle comes before its past-expiry check (`D05-files`, `D04-store`), `import` refuses a past expiry even while the store cannot be read; the store is then asked, and the owner judged from what it answers.
- A malformed `expires` is refused, beside the three refusals the decision names, because the `PUT` refuses such an `X-Artifact-Expires` with 400 (`D05-files`), so a plan holding it would fail; the parse is the `PUT`'s, `time.Parse` with `time.RFC3339`. The value is answered as given, not normalised, since the `PUT` parses it the same way.
- An empty `content_type` is answered as `application/octet-stream`, since the `PUT` stores that for an empty `Content-Type` (`D05-files`).
- `PlanHeaders` carries the header names as its JSON keys, `Content-Type` and `X-Artifact-Expires` with a hyphen and the last with `omitempty`. appkit's typed `mcp.AddTool` refuses such a property name and any tag holding a comma, panicking when the tool is registered, so `import` is registered as `show` is, through appkit's `mcp.AddRawTool` with its `Plan` encoded by `encoding/json`; no requirement asks for an output schema derived from `Plan`.
- The copy is `tools`' own. Non-normative guidance, which binds nothing and which the build may use: `tools.BearerPlaceholder` "Bearer <your token>"; `tools.ImportInstructions` "Send the file as the request body. 201 means created, 200 means replaced. GET the same URL to read it back."

## Consumer tasks

An agent calls `import` with `{"path":"reports/q3.pdf","content_type":"application/pdf","expires":"2026-10-12T00:00:00Z"}` and is answered `{"url":"https://artifacts.<space>/files/reports/q3.pdf","method":"PUT","headers":{"Authorization":<tools.BearerPlaceholder>,"Content-Type":"application/pdf","X-Artifact-Expires":"2026-10-12T00:00:00Z"},"instructions":<tools.ImportInstructions>}`; it then runs `curl -sS -X PUT -T q3.pdf -H "Authorization: Bearer $T" -H 'Content-Type: application/pdf' -H 'X-Artifact-Expires: 2026-10-12T00:00:00Z' <url>`, reads 201 or 200 and the metadata object, and later `curl -sS -o q3.pdf -H "Authorization: Bearer $T" <url>`. A test registers the tools with a `tools.Config` whose `Base` it chooses, on a server serving inside `identity.Require` behind a handler that puts another base on the context, calls `mcp.Client.CallTool` with `tools.ImportArgs` encoded as JSON, decodes a success result's structured content into `tools.Plan` and its raw JSON into a map to see which members are present, compares with `tools.BearerPlaceholder`, `tools.ImportInstructions` and `store.DefaultContentType`, compares refusals with `tools.InvalidPath(p)`, `tools.InvalidExpiry(e)`, `tools.PastExpiry(e)`, `tools.NotOwner(p)` and `store.Unreachable`, and lists the store and the blob directory and inspects the captures after each call. A test through `web.Handler` writes a services file whose entry `artifacts` names a URL, or none, and calls `import` at `/mcp`.

## REQUIREMENTS

- R-TQTC-VFWT: The `internal/tools` package MUST export `type Plan struct { URL, Method string; Headers PlanHeaders; Instructions string }` and `type PlanHeaders struct { Authorization, ContentType string; Expires *string }`, `PlanHeaders`' fields tagged `json:"Authorization"`, `json:"Content-Type"` and `json:"X-Artifact-Expires,omitempty"` respectively, whose JSON encoding by `encoding/json` is, for a `Plan`, an object with exactly the members `url`, `method`, `headers` and `instructions`, in that order, and, for a `PlanHeaders`, an object with exactly the members `Authorization`, `Content-Type` and `X-Artifact-Expires`, in that order, `X-Artifact-Expires` omitted when `Expires` is nil; and `tools.Register` MUST register `import` so that the structured content of its success result is that encoding of its `Plan`, so that `Register` returns without panicking.
- R-UR80-HYJJ: The `internal/tools` package MUST export the copy constants `const BearerPlaceholder string`, the value a plan's `Authorization` header holds, standing for the agent's own bearer token, non-empty and holding no newline, and `const ImportInstructions string`, the instructions a plan carries, non-empty; and the copy functions `func InvalidExpiry(expires string) string` and `func PastExpiry(expires string) string`, each answering a non-empty string that contains its argument.
- R-USFW-VQA8: An `import` call whose `path` `store.ValidPath` accepts, which no artifact has or whose artifact's `OwnerID` is the caller's `UserID`, and whose `expires`, when given, `time.Parse(time.RFC3339, expires)` accepts as an instant that, truncated to the second, is later than `cfg.Now()` truncated to the second, MUST answer a success result whose structured content is exactly the `Plan` whose `URL` is `urls.File(cfg.Base, path)`, whose `Method` is `PUT`, whose `Instructions` is `tools.ImportInstructions`, and whose `Headers` has as `Authorization` `tools.BearerPlaceholder`, as `ContentType` the given `content_type` byte for byte when it is given and not empty and `store.DefaultContentType` otherwise, and as `Expires` nil when `expires` is absent and otherwise a pointer to the given `expires` byte for byte; so that the result's `headers` has an `X-Artifact-Expires` member exactly when `expires` was given.
- R-UTNT-9I0X: The `url` of the plan an `import` call answers MUST be `cfg.Base + "/files/" + path` when `cfg.Base` is not empty and exactly `"/files/" + path` when it is empty, whatever base the call's context carries (`urls.FromContext`); so that with `cfg.Base` `https://artifacts.sbx.ikigenba.dev` and `path` `reports/q3.pdf` it is `https://artifacts.sbx.ikigenba.dev/files/reports/q3.pdf`, and with `cfg.Base` empty it is `/files/reports/q3.pdf`, holding no `://`.
- R-UUVP-N9RM: When a handler `web.Handler(cfg)` returns serves `/mcp` with `cfg.ServicesPath` naming a services file whose entry `artifacts` has the `URL` `u` with no trailing `/`, an `import` call through appkit's `mcp.Client` for a valid path `p` no artifact has MUST answer a plan whose `url` is exactly `u + "/files/" + p`; when that entry's `URL` is `u + "/"`, likewise exactly `u + "/files/" + p`; and when `cfg.ServicesPath` names no file, or one with no entry `artifacts`, exactly `"/files/" + p`; in each case whatever the request's `Host` and `X-Forwarded-Proto`.
- R-TS19-97NI: For any one string `s`, the strings `tools.InvalidPath(s)`, `tools.NotOwner(s)`, `tools.InvalidExpiry(s)` and `tools.PastExpiry(s)` MUST be pairwise distinct and each differ from `store.Unreachable`, so that each `import` refusal R-UW3M-11IB names is told apart from the others by its text alone.
- R-UW3M-11IB: An `import` call MUST be refused with `tools.InvalidPath(path)` when `store.ValidPath(path)` is false; with `tools.InvalidExpiry(expires)` when `expires` is given and `time.Parse(time.RFC3339, expires)` returns an error, the empty string included; with `tools.PastExpiry(expires)` when it parses to an instant that, truncated to the second, is not later than `cfg.Now()` truncated to the second; with `store.Unreachable` when the store cannot be read, as when its handle is failing (`SetFailing(true)`); and with `tools.NotOwner(path)` when an artifact whose `OwnerID` is not the caller's `UserID` has `path`; a call meeting several of these being refused with the first in that order.
- R-UXBI-ET90: Every `import` call, answered or refused, MUST leave the store and its blob directory as they were before the call, creating, replacing and deleting no artifact and adding no entry to the blob directory, so that after a success for a path no artifact had a `show` of that path is refused with `tools.NoArtifact(path)`, and after one for the caller's own artifact a `show` answers it unchanged; and it MUST hand `cfg.Events` no event and record through `cfg.Telemetry` no event but the one `tool.called` appkit's MCP server records for the call, when that server was built with `cfg.Telemetry` as its `Telemetry`.
