# D04-store

The records and the bytes: `internal/store`, which owns artifacts' one table, `artifacts`, in its SQLite database, `state/artifacts.db`, and the blob directory, `state/blobs/`, where each artifact's bytes lie in a file of their own; the rules a path and an id obey; how a body is taken in, placed and recorded so that a reader never sees a record and a file that disagree; the errors every consumer tells apart; and the one line every consumer answers when the database or the blob directory cannot be reached. Opening, migrating, transactions and the failure seam are appkit's `db`. It follows webhooks' store, with files beside the table.

## One database and one directory, one writer

artifacts is the only writer of the database and of the blob directory, and the two together are the only record of its artifacts. `store.New` builds a store over a handle and a blob directory and opens or creates nothing; `Run` creates `state/blobs/` before it builds one (`D01-layout-and-run-seam`). What a store holds when its handle is closed is what a store over the next `db.Open` of the same path and the same blob directory holds; a test proves the records that way, never by reading tables. A test may list the blob directory and read its files, since what lies there is stated below. A store whose handle is failing (`SetFailing(true)`) answers every call with `ErrUnreachable` and changes nothing, in the table or in the directory.

## Artifacts

An artifact's **path** is one or more segments joined by `/`; a segment is 1 to 128 bytes, each an ASCII letter, a digit, `.`, `-` or `_`, and is neither `.` nor `..`; the whole path is at most 1024 bytes. So a path has no leading or trailing slash, no empty segment and no byte outside those, `%` and space included. Case is significant, and paths are one namespace for the whole space. Its **id** is `art_` and 16 lowercase hexadecimal digits, 8 bytes drawn from the random source when the path is first created, drawn again when they are an artifact's id already. Its **owner** is the creating caller's user id, kept with the email that caller's request carried; ownership is decided by the user id, and the email is what is shown. It has a **content type**, the caller's, stored verbatim and `application/octet-stream` when the caller gave none; its **bytes**, their count and their SHA-256 in lowercase hex; **created** and **modified**, UTC to the second; and an optional **expiry**, UTC to the second, the zero time when it never expires.

## Putting a body

`Put` takes a draft and a reader. It refuses a draft it can judge without the body — a bad path, an empty owner, a negative cap, an expiry not later than now, a path another user owns — before reading a byte of the body, so the answer to a non-owner never depends on what was sent. It then streams the body into a temporary file in the blob directory, counting and hashing as it goes, and stops reading at the first byte past the cap. When the body ends it places the file under a fresh name and records the artifact naming it in one write; after that write the file the record named before, on a replace, is removed. A put that fails for any reason leaves the table and the directory as they were, the existing artifact untouched. A replace keeps the id, the owner and `created`; a path deleted and put again is a new artifact with a new id.

## Listing

The store never hands out the whole set to a caller that lists. `List` answers one window at a time: at most `n` artifacts, of every owner, in ascending byte order of their paths, those whose path comes after a given position, or the first ones when no position is given. This is the suite's storage rule (`shape/`, Storage; appkit's D25, which this design cites and never restates): the query carries the position in its `WHERE`, the order in its `ORDER BY` and the window in its `LIMIT`, `WHERE path > ? ORDER BY path COLLATE BINARY LIMIT ?`, and the `path` column's `UNIQUE` index backs the order, so no migration is needed. The position is a path, compared byte for byte; it need not be the path of an artifact the store still holds, since the artifact a page ended on may have been deleted before the next page is asked for, and the window then starts at the next path after it. The tool and the landing page turn the position into the opaque token of appkit's `paging` (`D08-tools`, `D06-pages`), and the store knows nothing of tokens, limits or pages. A caller that wants one page and to know whether more follow asks for one more than the page. A window of fewer than one artifact is empty, never "no limit", whatever SQLite makes of a negative `LIMIT`. `dummy`'s store is the precedent: a SQL window keyed by `seq`, here keyed by `path`.

`TotalBytes` answers the bytes every artifact in the space holds, summed by the database in one query (`SELECT COALESCE(SUM(bytes), 0) FROM artifacts`), so the landing page can show the space's total while it reads only one window.

`Open` hands a reader the record and an open file of its bytes together, taken as one; since a replace or a delete never rewrites a file but only names another and removes the old, a file once opened keeps reading the bytes its record describes. `Sweep` deletes the artifacts whose expiry has come and answers them, so the sweeper can record each deletion as its owner. `Reconcile`, run at start before anything else, removes what a crash can leave: any file in the blob directory no record names, and any record whose file is gone, which it answers for the same reason.

## Errors

`ErrNotFound`, `ErrInvalid`, `ErrPastExpiry`, `ErrForbidden`, `ErrTooLarge` and `ErrBody` are answers about the call; every other error satisfies `errors.Is(err, ErrUnreachable)`, and every consumer answers it with `Unreachable`, never quoting the cause. One fixed precedence decides a call that meets several conditions: a done context, then a failing store, then an invalid argument, then an expiry not later than now, then a missing record, then another user's record, then a missing blob directory, then whichever of a body past the cap and a body that fails to read comes first in the body, then a context that ends while the body still reads, then a random source that fails. A body that fails to read is `ErrBody` even when the context has ended too: a client that goes away does both at once, and its answer is not a database outage.

## Recorded decisions

- The schema is the one migration `0001_artifacts.sql`: `artifacts` (`id` primary key, `path` unique, `blob`, `bytes`, `content_type`, `sha256`, `owner_id`, `owner_email`, `created`, `modified`, `expires`), with an index on `expires`. `blob` is the name of the artifact's file in the blob directory; `expires` is `NULL` when the artifact never expires. Times are RFC 3339 UTC to the second, which compare as text.
- Blob names are a fresh random name per put, never an id and never a hash (decisions D6): an id-named blob would have to be overwritten in place on a replace, and a hash-named one would be shared by two puts of the same bytes, so removing the old file could remove the live one. A final name is 16 lowercase hexadecimal digits; a temporary file's name begins `tmp-`. Neither convention is contract: `Reconcile` removes every entry no record names, whatever it is called, so no test can tell one name from another.
- Blob names are drawn from the store's own source, `crypto/rand`, not `Config.Rand`: `Rand` is read only for ids, so a test's `Rand` that yields one byte forever still replaces, and a `Rand` that yields exactly 8 bytes still creates.
- The non-owner check comes before the body is read, and is made again when the artifact is recorded, in case another user created the path while the body streamed.
- `ErrPastExpiry` and `ErrBody` are sentinels webhooks' store has no counterpart for: the first lets a tool refusal and a 400 say why without re-reading the clock, and the second keeps a client that went away from reading as a database outage.
- No body is ever held whole in memory: `Put` streams to a file and `Open` hands out a file, so memory does not grow with an artifact's size. No requirement states this, since a test cannot measure a heap; the manifest's `memory_max = "128M"` enforces it on a host, where a `Put` of a 1 GiB body that buffered would be killed, and the streaming requirements (the cap read past by at most one byte, the file `Open` answers) carry it in the tests.
- `Open` answers an `*os.File` so that `http.ServeContent` can seek it for `Range`; the caller closes it.
- No total is kept in a table: `TotalBytes` sums `bytes` over the table on each call, since the landing page, which reads only one window, must still show the bytes every artifact holds.
- `List` replaces the whole-table `List(ctx)`: the tool and the landing page were its only callers, and the storage rule forbids handing them the whole set. `Sweep` and `Reconcile` still scan the whole table inside their one write, since each must judge every artifact and neither is a list a caller pages.
- `List`'s position is `after *string`, nil for the first window, following `dummy`'s `after *int64`; the empty string is no artifact's path and sorts before every path, so `List` with a pointer to it answers what nil does.
- `List` takes any string as its position and refuses none: a valid token may carry a path no artifact has now, and the tool, not the store, decides which tokens it accepts (`D08-tools`).
- An expired artifact remains listed and fetchable until a sweep removes it; the store answers it like any other.

## Consumer tasks

The files surface, on a `PUT /files/<p>`, calls `st.Put(ctx, store.Draft{Path: p, ContentType: r.Header.Get("Content-Type"), Expires: exp, OwnerID: c.UserID, OwnerEmail: c.Email, Max: s.ArtifactMaxBytes}, r.Body)` and answers 201 or 200 by the `bool`, 400 on `ErrInvalid` or `ErrPastExpiry`, 403 on `ErrForbidden`, 413 on `ErrTooLarge` and 503 with `store.Unreachable` on `ErrUnreachable`; on a `GET` it calls `a, f, err := st.Open(ctx, p)`, defers `f.Close()` and serves `f` with `a.ContentType`, `a.SHA256` and `a.Modified`; on a `DELETE` it calls `st.Delete(ctx, p, c.UserID)`. The `list` tool calls `st.List(ctx, after, n+1)`, `after` nil for the first page and otherwise a pointer to the path its token decodes to, `n` the page size `paging.Window` gives; the landing page calls `st.List(ctx, nil, paging.DefaultLimit+1)` and `st.TotalBytes(ctx)`. The other tools call `st.Get(ctx, path)`, which `import` also calls to judge the path's owner, and `st.Delete(ctx, path, c.UserID)`; no tool calls `st.Put`. The artifact page calls `st.GetID(ctx, id)`. The sweeper calls `st.Sweep(ctx, now)` and records each artifact it answers; `Run` calls `st.Reconcile(ctx)` once, before the first sweep, and records each artifact it answers. A test opens its own database with `db.Open` and `artifacts.Migrations()` in its own temporary directory, makes a blob directory beside it, builds `store.New(d, blobs, store.Config{Now: clock, Rand: rnd})`, and checks `store.ValidPath`, `store.ValidID`, `store.IDPrefix`, `store.DefaultContentType`, `store.MaxSegment`, `store.MaxPath` and the error sentinels with `errors.Is`, listing the blob directory with `os.ReadDir` after each call.
