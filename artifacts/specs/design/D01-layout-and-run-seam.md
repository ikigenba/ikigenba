# D01-layout-and-run-seam

artifacts is the suite's blob store: one Go binary that keeps files agents and services share, each named by a path and holding an id, takes and serves their bytes at `/files/<path>` (`D05-files`) without ever holding a body in memory, keeps each artifact's record in its own SQLite database, `state/artifacts.db`, and its bytes in a file under `state/blobs/` (`D04-store`), emits an event on the suite's event bus for each artifact created, replaced or deleted (`D07-trail`), offers four MCP tools at `/mcp` (`list`, `show`, `delete`, `import`; `D08-tools`, `D09-import`), deletes artifacts whose expiry has passed once before ready and then hourly, and serves a page of every artifact at `/`, a page per artifact at `/<id>`, a tools page at `/tools` and an about screen at `/about` to a signed-in user (`D06-pages`), whose footer, like every page's, shows the `Release` then the `Commit` of the identity the run read. This design is the structural ground the others stand on: where the code lives, the seam through which the process is run so that every part can be tested without a real process, the three settings and how they are read, the paths, the migrations, where the identity and the display string come from, and the binary's wiring. It follows webhooks' layout and run seam, which is the precedent for everything here.

The module is `github.com/ikigenba/ikigenba/artifacts`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/artifacts`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/artifacts` is wiring only.

## The dependencies

artifacts depends on one module besides the standard library: `github.com/ikigenba/ikigenba/appkit`, required at a published release with no `replace` directive. Its `db` package brings the pure-Go SQLite driver, which keeps the release build cgo-free. artifacts uses appkit's `db`, `version`, `services`, `page`, `identity`, `mcp`, `telemetry` and `events`, and restates none of their contracts. Which release is data that `AGENTS.md` and `go.mod` hold.

## Where the environment is read

`main` makes the one read of the environment that is not `Run`'s own: it calls appkit's `version.Read` exactly once, first, and holds the result, the **identity**, a `version.Identity` holding a `Release` and a short `Commit`, whose `String()` is the **display string**, the empty string when neither `IKIGENBA_COMMIT` nor `IKIGENBA_RELEASE` is set. It hands the identity to `page.New`, whose banner carries its `Release` and `Commit` to the footer of every page and to the about screen, and the display string to the `mcp.ServerConfig` its `Process.MCP` builds and to `Run` as `Process.Version`, which `Run` writes for `--version` and gives the run's writer as its `telemetry.Config.Version`, so it is `service.started`'s `version`. Nothing below `main` calls `version.Read`, so a test of `Run` hands it any string as `Version` and sets no variable. `Run` reads every variable through `Process.LookupEnv`: `DRAIN_SECONDS`, `ARTIFACT_MAX_BYTES` and `IMPORT_SECONDS` once at start, through `settings.Read`; `LISTEN_PID`, `LISTEN_FDS` and `NOTIFY_SOCKET` for the socket and readiness; and `IKIGENBA_SERVICES` once, when it starts to serve.

## Packages

The root package, `artifacts`, holds what the module embeds: `Assets` (the five templates), `Etc` (`manifest.toml` and `nginx.conf`) and `Migrations` (the one migration, `0001_artifacts.sql`, which creates the `artifacts` table `D04-store` describes).

Twelve internal packages hold the concerns, one each: `internal/cli` (the run seam, the command, the serve path), `internal/settings` (the three settings), `internal/server` (a listener's life), `internal/store` (the records and the blobs), `internal/sweeper` (the expiry sweep), `internal/trail` (the three artifact events), `internal/files` (the `/files/<path>` surface and the metadata object), `internal/urls` (the addresses artifacts builds), `internal/fetch` (import's fetch from a sibling), `internal/tools` (the four tools), `internal/pages` (the five templates' data and the page routes) and `internal/web` (the route table). Which imports which is guidance, not contract.

## The run seam

The run seam is `cli.Run`, which takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package, and returns the exit code; it is webhooks' seam, field for field, with one field more. `Now` is the clock every time artifacts stamps or compares is read from: an artifact's `created` and `modified`, the expiry check of a PUT or an import, the sweep's cut-off, every event's time. `After` is the sweeper's timer: every wait of the sweeper between two sweeps ends when a channel `After` returned delivers, so a test that hands in its own `After` learns each wait as it begins and delivers on its channel to make the next sweep run. `ImportAfter` is import's timer: the `IMPORT_SECONDS` bound on each import's fetch ends when a channel `ImportAfter` returned delivers, so a test proves the bound without waiting real seconds. `Rand` is the source of every id artifacts mints: request ids, artifact ids and bus event ids.

## Settings

artifacts reads three values at start. `DRAIN_SECONDS`, the space's, 5 when unset or empty; `ARTIFACT_MAX_BYTES`, its own, the most bytes a body may hold, which its manifest's `[env]` sets to 1073741824, and 1073741824 when unset or empty; and `IMPORT_SECONDS`, its own, how long an import's fetch may take, which the manifest sets to 600, and 600 when unset or empty. Each is spelled as opsctl writes an integer — one or more ASCII digits, no sign, no leading zero, no unit, no white space — and digits beyond what an `int64` holds read as the largest `int64`. `settings.Read` checks them in that order and refuses the first that is not acceptable with a `*settings.Error`, whose text `Run` writes after `artifacts: ` as a usage error before it looks for its socket.

## Paths

Relative to `Process.Dir` (the process's working directory when empty): the database is `state/artifacts.db`, opened with `db.Open`, `artifacts.Migrations()` and `Process.Now`, and the blob directory is `state/blobs`; `state/` and `state/blobs/` are created when absent. artifacts writes nothing outside `Dir`.

## Recorded decisions

- `ImportAfter` is a field webhooks does not have. The import's bound is the one deadline other than the sweep a test must prove, and the test discipline forbids waiting real seconds, so it gets its own timer seam, as prompts' `ScriptAfter` bounds a run. It is separate from `After` so that a test driving the sweeper and a test holding an import never share a channel.
- `ARTIFACT_MAX_BYTES` and `IMPORT_SECONDS` carry no `ARTIFACTS_` prefix: the decisions document names them so, and the manifest's `[env]` sets them under those names.
- The cap is read as a count of bytes and kept as an `int64` field; the two time settings have methods that turn them into `time.Duration`.
- Blob names are not drawn from `Rand` (`D04-store`), so a `Rand` that yields one byte forever still serves a replace.

## Consumer tasks

`main` calls `id := version.Read()` and `v := id.String()` and hands `cli.Run` a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Version` is `v`, whose `Banner` is `page.New(pages.ServiceName, id).Banner` and whose `MCP` returns `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Version: v, Telemetry: w})` over the writer `w` it is given, leaving the rest zero; it cancels the context on `SIGTERM` or `SIGINT` with a cause whose `Error` is the signal's name, and exits with what `Run` returns. A test of the run seam builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` over a map, an `Inherit` returning a listener it bound, a `Now`, an `After`, an `ImportAfter` and a `Rand` it controls, and capturing sinks, calls `cli.Run`, waits for `READY=1`, drives the listener with raw HTTP to `/files/<path>` and `mcp.Client` at `/mcp`, cancels, and inspects `Dir` (listing `state/blobs/` among the rest), the captures and the streams. A test of settings calls `settings.Read` with a lookup over a map and compares with `settings.Defaults()`, `Drain()` and `Import()`. The one test that execs the binary composes non-empty `IKIGENBA_COMMIT` and `IKIGENBA_RELEASE` into the child's environment and, after setting the same two values with `testing.T.Setenv`, computes the identity it expects with `version.Read`, the display string with its `String`, and the about screen with the `Banner` method of `page.New(pages.ServiceName, id)`.
