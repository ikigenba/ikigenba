# D06-pages

What artifacts draws as HTML: `internal/pages`, the five templates `landing`, `artifact`, `tools`, `about` and `notfound` and the data each receives, and the handler that answers `/`, `/<id>`, `/tools`, `/about` and every other path the route table (`D03-serve`) hands it. It follows webhooks' pages, with prompts' rule for an app whose manifest says `guests = false`, and adds one page webhooks has no counterpart for: an artifact's own page, the precedent for which is scripts' run page. The pages are read-only; nothing on them changes an artifact.

## The pages

The landing page shows every artifact in the space, whoever owns it, sorted by path, each with its id, path, bytes, content type, the owner's email, its modified time and its expiry, each time in RFC 3339 and to the minute, and the total bytes the space holds, the sum of the rows' bytes. An artifact's page, at `/<id>`, shows the whole metadata object (`D05-files`): its id, path, the absolute `/files/<path>` address its bytes are got at (`urls.File` of `urls.Base`), bytes, content type, SHA-256, the owner's email, and its created, modified and expiry times, each in RFC 3339 and to the second; the template draws the download link from the address. The tools page shows the four tools in registration order (`D08-tools`), each with the first line of its description. The about screen shows the service's name, the banner's `Release` and `Commit` as its version, and `Description`. Bytes are carried as the plain integer, never a humanised size.

The landing page sits at the root of the banner's trail, so its trail is empty. The tools page and the about screen are one level below it, `pages.ToolsLevel` and `pages.AboutLevel`. An artifact's page is one level below it too, named by the artifact's path and pointing at `/<id>`. Any other path is the not-found page, status 404, whatever the method, drawn with the footer only. An id that names no artifact, or a path segment that is not an id, is the not-found page too. The banner's user is the caller's email, with auth's profile and sign-out addresses: auth's entry in the services file when it has one, and otherwise `auth.` and the request's host with its port and a leading `artifacts.` removed, under the forwarded scheme.

Page bodies are never artifact bodies. A path under `/files/` never reaches this handler (`D03-serve` routes it to the files surface, `D05-files`), so no answer of this design is ever given for one.

## Guests and methods

The manifest says `guests = false` (`D02-cli`), so the host's nginx sends a request with no credential to sign in before it reaches artifacts, and `D03-serve` mounts this handler inside appkit's `identity.Require`, which answers a request without `X-User-Id` itself. So, as in prompts, there is no guest branch and no sign-in address: the page handler is `pages.Handler` wrapped in `identity.Require`, and a test wraps it the same way. A request to `/`, `/tools`, `/about` or `/<id>` whose method is not `GET` or `HEAD` is `405` with `Allow: GET, HEAD`, decided before the store is read. The landing page and an artifact's page answer `503` with `store.Unreachable` as plain text when the store cannot be read, as webhooks' landing page does; artifacts has no `unavailable` template.

## Recorded decisions

- An artifact's page is new beside webhooks; its id is the address so a path, which may hold `/`, never has to be decoded from a page URL. Its trail level is the path, not the id (decisions D10).
- No guest branch and no `urls.SignIn`: prompts' `guests = false` precedent, where a request with no `X-User-Id` is `identity.Require`'s answer and draws nothing. The templates' remark that a guest is sent to sign in is nginx's doing.
- The `/<id>` segment is read from the request's escaped path, byte for byte, and must satisfy `store.ValidID`; a percent-encoded, upper-case or trailing-slash form is the not-found page, so there is one address per artifact.
- No `.Mine` on a row: per-user visibility was rejected, and nothing on the pages acts on ownership.
- The landing's times are to the minute (`2006-01-02 15:04`) as webhooks' are; the artifact page's to the second with the zone (`2006-01-02 15:04:05 UTC`), as its template comment says.
- The tools page reads `tools.Catalog()`, as webhooks' does.
- `Description` is a contract constant with its value stated, not a copy constant: decision 1 fixes it as the manifest's description, text the host parses (`D02-cli`), and the about page shows the same value.
- The about page carries a prose section explaining how the service works, beside the name, version and description list every other app's about page holds alone. It is a departure from every other app, accepted because the copy is useful to an agent reading the page (decisions D10); the design names only the template `about` and its data, `AboutData`, and states nothing of the section.
- A database outage is plain-text 503 with `store.Unreachable` followed by a newline, as webhooks; the about, tools and not-found pages are served without reading the store.

## Consumer tasks

`web.Handler` (`D03-serve`), whose `web.Config` carries no template set, builds one with `s, err := pages.Load()` and mounts `identity.Require(pages.Handler(pages.Config{Banner: cfg.Banner, Pages: s, ServicesPath: cfg.ServicesPath, Store: cfg.Store}))` for every path that is not `/files/`, `/mcp`, `/events`, `/declarations` or under `/_appkit/`. The about requirement of `D01-layout-and-run-seam` executes `about` with `pages.AboutData{Banner: b, Description: pages.Description}` where `b.Trail` is `[]page.Level{pages.AboutLevel}`; `D02-cli` builds the manifest with `pages.Description`; `main` names the service `pages.ServiceName`. A test builds a store over its own database, puts artifacts, builds its own set with `pages.Load()`, serves `identity.Require(pages.Handler(cfg))` with a `Banner` func returning a fixed banner, sends raw requests with `X-User-Id` and `X-User-Email`, and compares each body with what executing the named template of its own set writes for a `LandingData` of `ArtifactRow`s, an `ArtifactData` with an `ArtifactView`, a `ToolsData` of `ToolRow`s, an `AboutData` or a `NoticeData`; it turns on `SetFailing(true)` to see the 503.

## REQUIREMENTS

- R-NQFY-7UB1: The `internal/pages` package, imported from the path `github.com/ikigenba/ikigenba/artifacts/internal/pages` with the package name `pages`, MUST export `const ServiceName = "artifacts"`, `const Description = "Binary files agents and services share"`, the service's one-line description, and the variables `ToolsLevel = page.Level{Name: "tools", URL: "/tools"}` and `AboutLevel = page.Level{Name: "about", URL: "/about"}`, where `page` is appkit's package of that name.
- R-MSDH-H40V: The `internal/pages` package MUST export `type Set`, `func Load() (*Set, error)`, the method `func (s *Set) Write(w http.ResponseWriter, r *http.Request, status int, name string, data any)`, `type Config struct { Banner func(u page.User) page.Banner; Pages *Set; ServicesPath string; Store *store.Store }` and `func Handler(cfg Config) http.Handler`, where `store` is artifacts' `internal/store`.
- R-MUTA-8NI9: The `internal/pages` package MUST export `type LandingData struct { Banner page.Banner; Artifacts []ArtifactRow; TotalBytes int64 }`, `type ArtifactRow struct { ID, Path string; Bytes int64; ContentType, Owner, Modified, ModifiedText, Expires, ExpiresText string }`, `type ArtifactData struct { Banner page.Banner; Artifact ArtifactView }`, `type ArtifactView struct { ID, Path, URL string; Bytes int64; ContentType, SHA256, Owner, Created, CreatedText, Modified, ModifiedText, Expires, ExpiresText string }`, `type ToolsData struct { Banner page.Banner; Tools []ToolRow }`, `type ToolRow struct { Name, Description string }`, `type AboutData struct { Banner page.Banner; Description string }` and `type NoticeData struct { Banner page.Banner }`.
- R-MW16-MF8Y: `pages.Load` MUST return a nil error and a set holding appkit's `page.Templates()` and the five templates of the root package's `Assets`, so that executing `landing`, `artifact`, `tools`, `about` and `notfound` with a `LandingData` (with no row and with rows, an expiry set and not), an `ArtifactData` (with an expiry and without), a `ToolsData`, an `AboutData` and a `NoticeData` returns a nil error.
- R-MX93-06ZN: `Set.Write` MUST answer `status` with `Content-Type: text/html; charset=utf-8` and the bytes the named template writes for `data`, and with no body for a `HEAD` request.
- R-OUMA-CXCZ: artifacts' design defines the **page handler** for a `pages.Config` `cfg` as `identity.Require(pages.Handler(cfg))`, `identity` being appkit's package of that name, as `D03-serve` mounts it; every requirement of artifacts' design that states an answer of the page handler MUST denote its answer to a request carrying a non-empty `X-User-Id`.
- R-OS6H-LDVL: `GET /` MUST be answered 200 with exactly what the template `landing` writes for the `LandingData` whose `Banner` is what `cfg.Banner` returns for the banner's user with its `Trail` set to nil, whose `Artifacts` hold one row per artifact `Store.List` returns, in that order, each with the artifact's `ID`, `Path` and `Bytes`, its `ContentType`, its `OwnerEmail` as `Owner`, `Modified` as RFC 3339 UTC to the second and `ModifiedText` of the time in UTC, in the form `2006-01-02 15:04`, and, when its `Expires` is not zero, `Expires` and `ExpiresText` formed from it in the same two ways, both empty when it is zero; and whose `TotalBytes` is the sum of the rows' `Bytes`, 0 when there is none.
- R-OTED-Z5MA: A `GET` of `/` followed by a string `id`, where the request's escaped path is exactly that and `store.ValidID(id)` is true and `Store.GetID(id)` returns an artifact, MUST be answered 200 with exactly what the template `artifact` writes for the `ArtifactData` whose `Banner` is what `cfg.Banner` returns for the banner's user with its `Trail` set to exactly one `page.Level` whose `Name` is the artifact's `Path` and whose `URL` is `"/" + id`, and whose `Artifact` holds the artifact's `ID`, `Path`, `Bytes`, `ContentType`, `SHA256` and `OwnerEmail` as `Owner`, as `URL` what `urls.File(urls.Base(r, cfg.ServicesPath), path)` returns for the request `r` and the artifact's `Path`, and `Created`, `Modified` and, when not zero, `Expires`, each as RFC 3339 UTC to the second with its `Text` of the time in UTC, in the form `2006-01-02 15:04:05 UTC`, `Expires` and `ExpiresText` both empty when the artifact never expires.
- R-OX23-4GUD: A request whose escaped path is `/` followed by a string for which `store.ValidID` is true but which is no artifact's `ID` MUST be answered as R-N4KH-ATFT states for a path that is not a page, so that a `GET` of an artifact's page after its `delete` is answered 404 with the not-found page.
- R-OY9Z-I8L2: For an artifact whose `ID` is `id`, a `GET` of each of `/` followed by `id` with its hexadecimal digits in upper case, `/` followed by `id` less its last digit, `/` followed by `id` and one more hexadecimal digit, `/` followed by `id` and `/`, and `/` followed by `id` with its first byte percent-encoded (`%61rt_…`) MUST be answered 404 with exactly what the template `notfound` writes for the `NoticeData` of R-N4KH-ATFT.
- R-N3CK-X1P4: `GET /tools` MUST be answered 200 with exactly what the template `tools` writes for the `ToolsData` whose `Banner` is what `cfg.Banner` returns for the banner's user with its `Trail` set to the one level `ToolsLevel`, and whose `Tools` are one row per entry of `tools.Catalog()`, in that order, each with its `Name` and `tools.FirstLine` of its `Description`.
- R-N5SD-OL6I: `GET /about` MUST be answered 200 with exactly what the template `about` writes for the `AboutData` whose `Banner` is what `cfg.Banner` returns for the banner's user with its `Trail` set to the one level `AboutLevel` and whose `Description` is `pages.Description`.
- R-N4KH-ATFT: A request whose escaped path is none of `/`, `/tools`, `/about` and `/` followed by a string for which `store.ValidID` is true MUST be answered 404 with exactly what the template `notfound` writes for the `NoticeData` whose `Banner` is what `cfg.Banner` returns for the banner's user, whatever its method, reading nothing from the store.
- R-N70A-2CX7: The banner's user MUST be the `page.User` whose `Email` is the request's `X-User-Email`, whose `ProfileURL` is `urls.Auth(r, cfg.ServicesPath)` followed by `/` and whose `LogoutURL` is that followed by `/logout`, for the request `r`; so that `Host: artifacts.sbx.ikigenba.dev:443` with `X-Forwarded-Proto: https` and no services file gives the `ProfileURL` `https://auth.sbx.ikigenba.dev/`, and a services file whose entry `auth` has the `URL` `https://auth.example.test/` gives `https://auth.example.test/`.
- R-N886-G4NW: A request to `/`, `/tools`, `/about` or `/` followed by a string for which `store.ValidID` is true, whose method is neither `GET` nor `HEAD`, MUST be answered 405 with an `Allow` header of exactly `GET, HEAD` and an empty body, reading nothing from the store, so that the answer is the same whether or not an artifact has that id.
- R-N9G2-TWEL: When the store cannot be read, a `GET` or `HEAD` of `/`, and of `/` followed by a string for which `store.ValidID` is true, MUST be answered with a plain refusal (R-CHDX-Q2MD) with status 503 and line `store.Unreachable`, while `/tools`, `/about` and the not-found page of R-N4KH-ATFT MUST be answered as when it can.
- R-NANZ-7O5A: A `HEAD` of a page MUST be answered with the status and headers the `GET` of the same page is answered with and no body; and no answer of the page handler MUST change any artifact or set a cookie.
