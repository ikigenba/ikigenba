# D05-files

The bytes on the wire: `internal/files`, which answers every request for `/files/<path>`, the one way bytes enter and leave artifacts over HTTP, and the **metadata object** every surface shows an artifact as; and `internal/urls`, which builds the addresses artifacts hands out. An agent with a shell puts a file with one `curl -T` and its token, fetches it with one `curl`, and only the short JSON answer of a put ever reaches its context. There is no page here: every answer is the bytes, a short JSON object, a line of plain text, or nothing.

## The address

An artifact's address is artifacts' **base** followed by `/files/` and its path. The base is the `URL` of the services file's entry `artifacts`, without a trailing `/`; with no such entry, the request's forwarded scheme (`https` unless `X-Forwarded-Proto` says `http`) and its `Host`. Through the MCP gateway a request's `Host` is the gateway's backend name, so on a host and in a sandbox the services file decides, as in webhooks. `urls` also builds auth's address, which the pages put in the banner (`D06-pages`), and carries the base on a context to the tools (`D03-serve`, `D08-tools`). `urls.Configured` is the base with no request fallback, the services file's entry alone, or the empty string with none: `import`'s plan is built on it (`D09-import`), so with no entry its `url` is `/files/<path>` alone.

## The path on the wire

The path is read from the request's **escaped** path, the form `net/http`'s `URL.EscapedPath` gives, which is the target the client sent: the rest after `/files/` must be a path as `D04-store` defines it, byte for byte. Nothing is percent-decoded: `%` is not a path byte, so any escape is 400, and so is any empty segment, `.` or `..`. The route table never cleans or redirects the path (`D03-serve`), so `/files/a//b` and `/files/../x` reach this handler and are 400, never a 301. The query is ignored.

## The answers

The method is decided first: `GET`, `HEAD`, `PUT` and `DELETE` are served, and any other is 405 with `Allow: GET, HEAD, PUT, DELETE` and an empty body, whatever the path. Then a path that is not valid is 400. Then:

- `PUT` takes `X-Artifact-Expires`, if present, as an RFC 3339 instant, exactly what Go's `time.Parse` accepts for the layout `time.RFC3339` (so fractional seconds and any offset are accepted; the time package documents that a fractional second may follow the seconds when parsing); more than one such header, or one that does not parse, is 400; an instant not later than now, both to the second, is 400. A body past `ARTIFACT_MAX_BYTES` is 413 with `Connection: close`, read no further than one byte past the cap. Another user's path is 403, decided before a byte of the body is read. A body that fails to read — the client gone mid-body — is 400, which nobody receives. Otherwise the body is stored with the request's `Content-Type` verbatim (`application/octet-stream` when absent or empty), the expiry given or none, and the answer is 201 for a new path or 200 for a replace, with `Content-Type: application/json` and the metadata object. A replace without the header clears any expiry; it keeps the id, the owner and `created`.
- `GET` and `HEAD` answer the bytes as Go's `http.ServeContent` does, with `Content-Type` as stored, `Content-Disposition: attachment; filename="<last segment>"`, `X-Content-Type-Options: nosniff` and `ETag` the quoted SHA-256 set before it, and the artifact's `modified` as the modification time. So `Content-Length`, `Last-Modified`, `Range`, `If-Range`, `If-Match`, `If-None-Match`, `If-Modified-Since` and `If-Unmodified-Since` are handled as `net/http` documents for `ServeContent`: it handles those headers, uses an `ETag` the caller set in the header for the conditional ones, writes a `Last-Modified` from a modification time that is not zero, and does not sniff when `Content-Type` is already set. The last segment needs no quoting, since a path's bytes are letters, digits, `.`, `-` and `_`. The bytes are those of the record served with them, even when a replace or delete lands while they stream (`D04-store`).
- `DELETE` by the owner removes the artifact and answers 204 with an empty body; another user's path is 403.
- An unknown path is 404; a database or blob directory that cannot be reached is 503 with `store.Unreachable`.

Every refusal is plain text: `text/plain; charset=utf-8`, a copy constant and a newline, and no body on `HEAD`. Every change is told after it is committed: `artifact.created`, `artifact.replaced` or `artifact.deleted`, as the caller, through `trail.Record` (`D07-trail`). A request that changes nothing tells nothing, and no byte of a body ever reaches the trail, the bus or a stream.

## The metadata object

`id`, `path`, `bytes`, `content_type`, `sha256`, `owner` (the owner's email), `created`, `modified`, `expires` (absent when the artifact never expires) and `url`, the artifact's address. Times are RFC 3339 UTC to the second. It is the answer to a `PUT`, `show`'s answer and, less `created`, a `list` row (`D08-tools`); `Describe` makes it from a stored artifact.

## Recorded decisions

- The path is matched on the escaped form, not on `URL.Path`, so that `/files/a%2Fb` cannot name `a/b` and no two spellings name one artifact.
- `X-Artifact-Expires` is parsed by Go's `time.Parse` with `time.RFC3339` and nothing stricter; the instant kept is UTC truncated to the second, as every time artifacts keeps. A repeated header is refused rather than one picked.
- A body that fails to read is 400 with `files.BodyFailed`, never 503: the database did not fail, and the store keeps the two apart (`store.ErrBody`). Nothing is left behind, as for every failed put.
- The 413 carries `Connection: close` so that `net/http` does not drain the rest of an oversized body; the decisions document asks for it.
- The method is decided before the path, so a 405 never depends on what path was asked. The rest of the order follows the store's precedence (`D04-store`): the header is judged before the store is asked, and a failing store before anything the store decides.
- A `GET` whose `Range` names more than one range is answered as `http.ServeContent` answers it; no requirement fixes its bytes, since `net/http` draws the multipart boundary at random.
- The refusals are copy constants without arguments: an invalid path is not echoed, and the caller knows the path it asked.
- `files.Handler` reads the base for `url` itself, from `Config.ServicesPath` and the request, as the tools read it from the context; both give `urls.Base`.
- No `Now` in `files.Config`: the expiry check is the store's (`store.ErrPastExpiry`), against the store's clock.
- The refusal of an unknown path is plain text, not the not-found page: `/files/` is for programs (decisions document, decision 4).

## Consumer tasks

An agent runs `curl -sS -T report.pdf -H "Authorization: Bearer $T" -H 'Content-Type: application/pdf' https://artifacts.<space>/files/reports/q3.pdf`, reads `sha256` and `url` from the JSON, and later `curl -sS -o q3.pdf -H "Authorization: Bearer $T" <url>`; it sets `-H 'X-Artifact-Expires: 2026-10-12T00:00:00Z'` for a scratch file and `curl -X DELETE` to remove one. The route table mounts `files.Handler(files.Config{Store: st, Max: s.ArtifactMaxBytes, ServicesPath: path, Telemetry: w, Events: em})` for every escaped path beginning `urls.FilesPrefix`; the tools answer `files.Describe(a, base)` with `base, _ := urls.FromContext(ctx)`; the pages show the same fields and link `urls.File(base, a.Path)`, and put `urls.Auth(r, path) + "/"` and `+ "/logout"` in the banner. A test builds the handler over a store on its own database and blob directory, a writer over a `*telemetry.Capture`, an emitter over an `*events.Capture` built with `trail.Emits()`, wraps it in `identity.Require`, serves it with `httptest`, sends raw requests with `X-User-Id`, `X-User-Email`, `X-Request-Id`, `Host` and `X-Forwarded-Proto` set by hand, a body from a reader it controls (one that fails, one past the cap, one with no `Content-Length`), and compares a `GET` with what `http.ServeContent` writes into an `httptest.ResponseRecorder` for the same request; it compares refusals with the copy constants and `store.Unreachable`, failing the database with `SetFailing(true)`, and lists the blob directory after each call.
