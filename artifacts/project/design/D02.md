# Decision 2 — Data model, tokens & blob store

## Decision.

Two tables, one token generator, one blob directory. All owner columns follow
`root project/design/D17.md` (`owner_id` keys, `owner_email` write-once
display snapshot).

**`artifacts` — stored files (only completed uploads ever appear here):**

```sql
CREATE TABLE artifacts (
    id             TEXT PRIMARY KEY,              -- 30-char random token (below)
    owner_id       TEXT NOT NULL,
    owner_email    TEXT NOT NULL,
    filename       TEXT NOT NULL,                 -- validated, ≤128 bytes UTF-8
    description    TEXT NOT NULL DEFAULT '',
    visibility     TEXT NOT NULL CHECK (visibility IN ('public','private')),
    size           INTEGER NOT NULL,              -- bytes, as stored
    content_hash   TEXT NOT NULL,                 -- 64-hex sha256 of the bytes
    download_count INTEGER NOT NULL DEFAULT 0,
    created_at     TEXT NOT NULL,                 -- RFC3339 UTC
    updated_at     TEXT NOT NULL                  -- RFC3339 UTC
);
```

**`uploads` — pending signed links (D3 consumes them):**

```sql
CREATE TABLE uploads (
    token       TEXT PRIMARY KEY,                 -- 30-char random token
    owner_id    TEXT NOT NULL,
    owner_email TEXT NOT NULL,
    filename    TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    visibility  TEXT NOT NULL CHECK (visibility IN ('public','private')),
    created_at  TEXT NOT NULL,
    expires_at  TEXT NOT NULL,                    -- created_at + 24h
    consumed_at TEXT,                             -- NULL until success
    artifact_id TEXT                              -- set with consumed_at
);
```

**The token generator.** `artifacts.NewToken()` — 30 chars of lowercase
base32 (`a-z2-7`) from `crypto/rand` (150 bits), the sites-proven shape —
generates both artifact ids and upload tokens through an injectable seam.
Uniqueness is the primary key's job; a create retries once on collision.

**Filename validation.** `artifacts.ValidateFilename(name string) error`
accepts a name iff: valid UTF-8, 1–128 **bytes**, contains no `/`, `\`, or
NUL byte, and is neither `.` nor `..`. Rejection is an error naming the rule
violated; a too-long name is rejected, never truncated.

**The blob store.** `internal/artifacts.BlobStore` — a root-dir type over
`<state>/blobs/<artifact-id>` (flat; the id is the only key). Seams:

```go
type BlobStore struct{ Root string }
func (b *BlobStore) Create(id string) (io.WriteCloser, error)  // temp+rename: no partial blob is ever visible
func (b *BlobStore) Open(id string) (*os.File, error)
func (b *BlobStore) Remove(id string) error
```

`Create` writes to a temp file in the same directory and renames on close, so
a crashed upload never leaves a readable partial blob under the final name.
Both the DB and the blob root live under `state/` (the backed-up side of
`root project/design/D05.md`).

**Store API** (`internal/db`): `CreateUpload`, `GetUpload(token)`,
`ConsumeUpload(token, artifactID, now)` (single UPDATE guarded on
`consumed_at IS NULL`, reporting whether it won), `PurgeExpiredUploads(now)`
(deletes unconsumed rows whose `expires_at` ≤ now), `CreateArtifact`,
`GetArtifact(id)`, `ListArtifacts`, `UpdateArtifact(id, …)`,
`DeleteArtifact(id)`, `IncrementDownloadCount(id)`. Purge runs at boot and
opportunistically on every mint (D3) — no background timer.

**Migration immutability.** artifacts adopts `root project/design/D25.md`:
the committed `internal/db/migrations.sha256` manifest plus the mechanical
guard.

## Rejected.

- **Blobs inside SQLite.** 200 MiB rows bloat the DB, defeat streaming, and
  make backup/restore all-or-nothing; the filesystem already does large-file
  IO well, and the id-keyed flat directory keeps the mapping trivial.
- **One table with a `status` column.** A pending link and a stored file
  share almost nothing (no size/hash/count before upload; no token/expiry
  after), and separate tables make "only completed uploads are artifacts" a
  structural fact rather than a WHERE clause every query must remember.
- **A background purge timer.** Boot + per-mint purge bounds the garbage at
  no moving-part cost; expired rows are inert (their tokens already refuse).
- **Content-addressed storage (dedup by hash).** Dedup adds refcounting and
  delete complexity for a single-owner box; distinct ids per upload keep
  delete trivial and match the "every upload is a distinct file" promise.

## Verification.

(Store tests run against real temp-file SQLite through the real migration
runner; blob tests against real temp dirs.)

- R-3D7T-1KPU — the migrations apply cleanly to a fresh DB and yield both
  tables with the declared columns and CHECK constraints: an INSERT with
  `visibility` outside `('public','private')` fails on both tables.
  Substrate: hermetic, real SQLite.
- R-3EFP-FCGJ — `NewToken()` returns 30 chars drawn only from `a-z2-7`, and
  two calls return distinct values; the generator is consumed through the
  injectable seam (a store create with a colliding injected token retries
  once and succeeds). Substrate: hermetic.
- R-3FNL-T478 — `ValidateFilename` accepts a 128-byte UTF-8 name and rejects
  each of: 129 bytes, empty, invalid UTF-8, containing `/`, containing `\`,
  containing NUL, `.`, `..` — and the returned value is never a truncation
  (table-driven; a multibyte name whose **byte** length exceeds 128 while its
  rune count is under 128 is rejected, pinning the byte semantics).
  Substrate: hermetic.
- R-3GVI-6VXX — `BlobStore.Create` + write + close makes the blob readable at
  `<root>/blobs/<id>` via `Open` with byte-identical content; a writer that
  is abandoned (closed after error / never renamed) leaves **no** readable
  blob under the final id path. Substrate: hermetic, real temp dir.
- R-3I3E-KNOM — `ConsumeUpload` is single-winner: against one unconsumed row,
  two consume attempts report exactly one winner, and the row afterwards
  carries `consumed_at` and the winner's `artifact_id`. Substrate: hermetic,
  real SQLite.
- R-3JBA-YFFB — `PurgeExpiredUploads(now)` deletes exactly the unconsumed
  rows with `expires_at` ≤ now: an expired-unconsumed row goes, an unexpired
  row stays, and an expired-but-consumed row stays (it is the audit trail of
  a completed upload). Substrate: hermetic, real SQLite.
- R-3LR3-PYWP — `IncrementDownloadCount` adds exactly 1 per call
  (concurrent-safe: N sequential calls yield count N), and
  `UpdateArtifact` touches `updated_at` while leaving `created_at`,
  `owner_id`, and `owner_email` unchanged. Substrate: hermetic, real SQLite.

Adopted per-service contract id (its tagged test lives in this tree):

- R-NFQ1-NA7N (`root project/design/D25.md`) — the committed
  `migrations.sha256` manifest is total and true; the guard fails naming the
  offending filename on any drift.
