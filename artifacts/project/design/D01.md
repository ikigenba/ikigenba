# Decision 1 — Service skeleton, chassis adoption & composition root

## Decision.

artifacts is a standard suite service on the shared `appkit` chassis: one
static Go binary, verbs `serve`/`version`/`migrate`/`schema`, SQLite under
`state/`, loopback HTTP, MCP surface, event-plane producer. The tree:

- `cmd/artifacts/` — the composition root: the `appkit.Spec` (service name
  `artifacts`, port, DB path, migrations FS, web assets, MCP tool table,
  producer hook, HTTP mux).
- `internal/artifacts/` — the domain: upload lifecycle (D3), download serving
  (D4), content plane (D5), events (D7).
- `internal/db/` — store + embedded migrations (D2).
- `internal/mcp/` — the tool table (D6).
- `internal/web/` — landing template + Carbon assets (D9).
- `etc/` — the authored `manifest.env` and the nginx fragment (D8).
- `VERSION` — `v0.1.0` (product constant).
- `AGENTS.md` — the tree's map + Tests declaration (D10).

**Port by name.** The composition root resolves its own port strictly:

```go
Port: registry.MustPort("artifacts"),
```

resolved once at boot; no handler calls `registry`. No `127.0.0.1:30xx`
loopback-address string literal may appear anywhere in this tree's Go source
(guarded by source scan, mirroring the suite's established guard shape: the
needle assembled at runtime, the guard's own file skipped). The registry row
`{"artifacts", 3009, Core}` lives in the shared `registry` module and is a
precondition outside this tree.

**Env contract.** artifacts adopts `root project/design/D11.md` whole: the
committed `etc/manifest.env` is authored and portable, every on-box path is
composed from `IKIGENBA_ROOT`, and the compiled `Spec`'s emitted manifest
byte-agrees with the committed file. The manifest carries the one service
variable `ARTIFACTS_MAX_UPLOAD_BYTES=209715200` (D3 consumes it).

**Install-tree boot.** artifacts adopts the per-service boot proof of
`root project/design/D08.md`: a freshly set-up install boots and passes
`health`.

## Rejected.

- **A hardcoded port literal.** Drifts silently against the registry;
  `MustPort` by name is the suite's settled mechanism (every recent service).
- **A second config variable for the upload-link TTL.** The 24h lifetime is a
  product promise, constant by contract; a knob would invite divergence from
  the promise for no identified need.
- **Splitting the domain into per-feature modules.** One `internal/artifacts`
  package holds the domain; the service is small and the seams (store, blobs,
  clock, plane) are types, not packages.

- R-39K3-W9HR — a composed boot smoke builds the real `cmd/artifacts` binary,
  runs its `serve` verb against a temp `state/`, and `GET /health` over
  loopback returns the healthy envelope naming service `artifacts` and the
  `VERSION` value. Substrate: composed (real binary, real port, real temp DB).
- R-3AS0-A18G — a hermetic source scan over every non-test `.go` file in the
  tree finds zero `127.0.0.1:30`+two-digit loopback-address literals (needle
  assembled at runtime; the guard's own file excluded), and the composition
  root's `Spec.Port` is `registry.MustPort("artifacts")` (asserted by reading
  the composition-root source). Substrate: hermetic (source scan).
- R-3BZW-NSZ5 — the committed `VERSION` file parses as a valid v-prefixed
  SemVer and the tree carries the committed `etc/manifest.env` whose
  `ARTIFACTS_MAX_UPLOAD_BYTES` line is present with default `209715200`; the
  config loader parses that value and rejects (fails startup, nonzero exit,
  error naming the variable) a non-integer or non-positive value. Substrate:
  hermetic.
