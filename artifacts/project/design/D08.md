# Decision 8 — nginx location fragment (tiers)

## Decision.

`etc/nginx.conf` is the service's path-routed **location fragment** (no
`server{}`, `listen`, or cert), the loopback port a literal (artifacts'
fixed registry port `3009`), shipped verbatim, dropped at
`/etc/nginx/conf.d/locations/artifacts.conf`, included by the dashboard apex
block. Variable names are service-prefixed (`$af_…`) since every fragment
shares one server block. The tiers under `/srv/artifacts/`, following the
webhooks/sites shape (exact tiers beat prefixes; longest prefix wins;
nothing shadows):

1. **`= /srv/artifacts/.well-known/oauth-protected-resource`** — ungated
   exact proxy to the upstream metadata route (PRM bootstrap).
2. **`= /srv/artifacts/mcp`** — bearer-gated: `auth_request /_authn`,
   all-four owner-header capture (`$af_owner*`) + `X-Client-Id`, one
   `proxy_set_header` per name (identity hygiene), 429 re-emit via
   `@artifacts_authn_500`, correlation captured from the introspection
   subresponse and overwritten on the upstream request.
3. **`= /srv/artifacts/feed`** — `return 404;` (feed shield). There is
   deliberately **no** location for `/content` — the catch-all 404s it, so
   the holder endpoint (D5) is unreachable from off the box even before its
   handler guard.
4. **`= /srv/artifacts/`** — the landing page: session-gated
   (`auth_request /_session-authn`), all-four owner-header capture
   (`$af_session_owner*`, distinct namespace), `@login_bounce` opt-in (a
   logged-out human navigation goes to sign-in), proxy to upstream `/`.
5. **`/srv/artifacts/static/`** — landing assets: session-gated, proxy to
   `/static/`.
6. **`/srv/artifacts/f/`** — **public downloads**: NO `auth_request`, NO
   identity headers set, `X-Correlation-Id ""` (strip-then-mint,
   `root project/design/D14.md`), proxy to `/f/`.
7. **`/srv/artifacts/p/`** — **private downloads**: session-gated with the
   same capture-and-forward as the landing tier, `@login_bounce` opt-in (a
   logged-out click on a private link lands on sign-in, and after sign-in
   the file retrieves), correlation captured-and-overwritten, proxy to
   `/p/`.
8. **`/srv/artifacts/u/`** — **upload ingress**: NO `auth_request`, NO
   identity headers, `X-Correlation-Id ""`,
   `client_max_body_size 1g` (coarse outer guard; the handler's configured
   cap, D3, is the authoritative limit), proxy to `/u/`.
9. **`/srv/artifacts/`** — catch-all `return 404;`.
10. **`@artifacts_authn_500`** — the faithful 429 re-emit.

Dev wiring: the `nginx/run` dev harness (the `nginx/` tree) hardcodes its
service list, so adding `artifacts` to that loop is an **out-of-tree
precondition** handled in the nginx tree — not work of this tree. The
fragment itself ships verbatim, no substitution.

## Rejected.

- **Bearer-gating the private tier.** A human clicking a link holds a
  session cookie, not a token; `/_session-authn` is the correct gate, as
  sites' private tier proved.
- **A `client_max_body_size` equal to the configured cap.** The fragment is
  a verbatim literal file; coupling it to a manifest variable would need
  install-time substitution the suite deliberately avoids. `1g` well above
  any sane cap keeps the service's `413` authoritative.
- **Session-gating `/f/` with a public carve-out at the service.** Public
  means anyone; the tier must be open at nginx, and the handler's
  identity-header guard (D4) catches misrouted gated traffic.
- **Proxying `/content` with a guard.** Never reachable from off-box is the
  contract; no location at all (catch-all 404) is strictly stronger than a
  guarded proxy.

## Verification.

**Every id is a content assertion over the committed fragment file**
(`os.ReadFile` + string assertions scoped to the named `location` block —
the substrate that falsifies a wrong location; live routing is the suite's
manual-layer check, `root project/design/D23.md`, per D10).

- R-4TNH-HPLP — the PRM exact location carries no `auth_request` and
  proxies to the upstream metadata route; the fragment contains no
  `server{`/`listen` line (it is a fragment, not a vhost). Substrate:
  hermetic (fragment content assertion).
- R-4UVD-VHCE — `= /srv/artifacts/mcp` gates with `auth_request /_authn`,
  captures all four owner headers plus client id into `$af_`-prefixed
  variables via per-header `auth_request_set`, forwards each with a single
  `proxy_set_header` per name, and no `$http_`-sourced identity value is
  proxied. Substrate: hermetic.
- R-4W3A-9933 — `= /srv/artifacts/feed` is `return 404;`, the catch-all
  `location /srv/artifacts/` is `return 404;`, and **no** location in the
  fragment mentions `/content`. Substrate: hermetic.
- R-4XB6-N0TS — the landing exact `= /srv/artifacts/` and the
  `/srv/artifacts/static/` prefix are both session-gated
  (`auth_request /_session-authn`, never `/_authn`); the landing tier
  captures all four owner headers into `$af_session_`-prefixed variables
  (distinct from the bearer tier's) and opts into `@login_bounce`.
  Substrate: hermetic.
- R-4YJ3-0SKH — `location /srv/artifacts/f/` carries no `auth_request`,
  sets no identity header, sets `X-Correlation-Id` to `""`, and proxies to
  the upstream `/f/`. Substrate: hermetic.
- R-4ZQZ-EKB6 — `location /srv/artifacts/u/` carries no `auth_request`,
  sets no identity header, sets `X-Correlation-Id` to `""`, declares
  `client_max_body_size 1g`, and proxies to the upstream `/u/`. Substrate:
  hermetic.
- R-50YV-SC1V — `location /srv/artifacts/p/` is session-gated, captures and
  forwards the four owner headers, opts into `@login_bounce`, and proxies
  to the upstream `/p/`. Substrate: hermetic.
- R-526S-63SK — every gated location (mcp, landing, `/p/`) captures the
  introspection-minted correlation id with `auth_request_set` and
  overwrites `X-Correlation-Id` on the upstream request, and the
  `@artifacts_authn_500` location re-emits 429 with `Retry-After`.
  Substrate: hermetic.
