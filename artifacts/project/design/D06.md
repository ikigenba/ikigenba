# Decision 6 — MCP tool surface

## Decision.

The owner surface, conforming whole to `root project/design/D20.md`
(structured results with `outputSchema` + mirrored text, the closed error
vocabulary, the three discovery tiers) — cited, not restated. Identity
arrives per `root project/design/D17.md`; every write records the caller as
the row's owner pair.

**Scoping call: the inventory is box-shared.** `list`/`get` return every
stored artifact regardless of creator, and mutations are open to any
authenticated caller — matching the landing page (which lists everything) and
the private-download rule (any logged-in user). Rows still record their
creator (`owner_id`/`owner_email`) for display and audit; creator-restricted
mutation would be a future Decision if multi-user boxes ever need it.

The tool table (`internal/mcp`), all registered once with the chassis beside
the built-in `health`/`reflection`:

| tool | args | returns |
|---|---|---|
| `upload` | `filename` (required), `visibility` (required: `public`\|`private`), `description?` | `{upload_url, expires_at, curl}` — the signed link (D3) plus a ready-made `curl -T <file> <upload_url>` command string the agent relays |
| `import` | `source_url`, `filename`, `visibility` (all required), `description?` | the stored artifact record (below) — bytes pulled by the service (D5) |
| `list` | — | `{artifacts: [record…]}` |
| `get` | `id` | one record |
| `update` | `id`, `description?` | the updated record — patch semantics per `root project/design/D27.md`: an omitted field is unchanged, an empty string clears |
| `set_visibility` | `id`, `visibility` | the updated record (its `url` now on the other tier) |
| `delete` | `id` | `{deleted: true, id}` — row and blob gone, links dead |
| `guide` | — | plain text (Tier 2): field catalog + worked examples, including the full mint→curl→list flow and a dropbox import |

**The record** (the one artifact shape every tool returns):

```json
{
  "id": "…", "filename": "…", "description": "…",
  "visibility": "public",
  "size": 184230, "content_hash": "<64-hex>",
  "download_count": 3,
  "url": "https://<host>/srv/artifacts/f/<id>/<filename>",
  "content_url": "http://127.0.0.1:3009/content?id=<id>",
  "created_at": "…", "updated_at": "…",
  "owner_id": "…", "owner_email": "…"
}
```

`url` is the tier-correct human download URL (D4); `content_url` +
`content_hash` + `size` are the content-plane reference (D5). **No tool
accepts or returns file bytes in any encoding** — `upload`'s link and
`import`'s reference are the only ways in (the product's hard exclusion; the
content-plane acceptor's tight-cap inline-text carve-out is deliberately not
taken).

Errors use the closed vocabulary: `validation` (bad filename/visibility/
source URL/args), `not_found` (unknown id), `too_large` (import over cap),
`source_unavailable` (import fetch failure). Tier-0 `instructions` name the
service's vocabulary (files, uploads, download links, public/private) and
point at `guide`; tool descriptions carry when-to-use and the no-bytes rule.

## Rejected.

- **Creator-scoped reads/mutations.** Would make the MCP view narrower than
  the landing page and the private-download rule for no operator-stated
  need; the suite's boxes are single-owner in practice, and the recorded
  owner pair keeps a future tightening cheap.
- **A base64 convenience ingest under a small cap.** The operator's rule is
  absolute: signed links and imports only. The carve-out D19 permits is
  declined.
- **A `download` tool returning bytes.** Same rule outbound: agents get
  URLs and references, never content.
- **Separate `rename`.** Filename is identity-adjacent (it is baked into the
  URL); renames were not asked for and would either break issued links or
  demand link rotation — out of scope.

## Verification.

(Driven through the real chassis MCP layer over a real service — temp
SQLite, temp blob dir, stub holder where needed.)

- R-4CKW-4X7Z — `upload` returns structured content whose `upload_url` ends
  `/srv/artifacts/u/<30-char token>`, whose `expires_at` is 24h from the
  injected now, and whose `curl` string contains `curl -T` and the exact
  `upload_url`; a 129-byte filename yields an `isError` result with code
  `validation`. Substrate: hermetic.
- R-4DSS-IOYO — `import` against a loopback stub holder returns the stored
  record with the caller's filename, the fixture's size and sha256, a
  tier-correct `url`, and a `content_url` on artifacts' own port; the bytes
  then serve on that `url`. A non-loopback `source_url` yields code
  `validation`; a dead stub yields `source_unavailable`. Substrate:
  hermetic (real loopback HTTP).
- R-4F0O-WGPD — `list` returns every stored artifact **including one created
  under a different owner pair**, each record carrying the fields above with
  `url` matching its visibility tier; no record field contains the file's
  bytes in any encoding (asserted: a stored file whose content is a known
  sentinel never appears in the serialized result). Substrate: hermetic.
- R-4G8L-A8G2 — `get` of a stored id returns the full record; `get` of an
  unknown id returns `isError` with code `not_found`. Substrate: hermetic.
- R-4HGH-O06R — `update` with `description` set changes it; with
  `description` omitted changes nothing; with `""` clears it; each response
  is the fresh record and `updated_at` moves while `created_at` does not.
  Substrate: hermetic.
- R-4IOE-1RXG — `set_visibility(id, "private")` on a public artifact returns
  a record whose `url` is the `/p/` form; the `/f/` URL then 404s (D4);
  `set_visibility` with any value outside `public`/`private` yields code
  `validation` and changes nothing. Substrate: hermetic.
- R-4JWA-FJO5 — `delete` removes the row **and** the blob file from disk;
  a subsequent `get` is `not_found` and the download URL 404s; deleting an
  unknown id is `not_found`. Substrate: hermetic.
- R-4L46-TBEU — `tools/list` shows every domain tool above declaring an
  `outputSchema` (except `guide`, which declares none), and a `list` call's
  result carries `structuredContent` conforming to its declared schema plus
  a text block mirroring the same JSON. Substrate: hermetic, through the
  real chassis MCP layer.
- R-4MC3-735J — the server's `initialize` `instructions` mention upload
  links and the public/private download vocabulary and name `guide`; the
  `guide` result is plain text (no `structuredContent`) containing a
  `curl -T` worked example and an import example naming a loopback
  `source_url`. Substrate: hermetic.
