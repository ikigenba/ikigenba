# Decision 11 — Adopt the suite brand icon contract: the shipped icon set and its link markup

**Decision.** artifacts adopts the suite's **brand icon contract** —
`root project/design/D29.md` — which owns the shipped file set, the filenames,
the static location, the three `<link>` elements, and the pinned content types.
This Decision is the **citation, and citation is adoption**: artifacts owns none
of that contract's content and restates none of it normatively. What is local —
and all this Decision adds — is **where the files land in this tree, which
documents carry the markup, and where the proof lives**.

The contract carries three `[proof: per-service]` ids, which artifacts therefore
proves in its own tree:

- `R-RYDN-YNR5` — every HTML document the service serves carries all three link
  elements.
- `R-RZLK-CFHU` — each of the three asset paths answers `200` through the
  composition root with the pinned content type.
- `R-8MFA-HUNC` — the bare `GET /favicon.ico` answers `200` at the service's
  root path through the composition root, with the same bytes as the static
  path.

**Where the files land.** The three shipped files are committed into artifacts's
own disk-served static root, beside the `tokens.css` and `.woff2` fonts already
there:

    artifacts/share/www/static/favicon.ico
    artifacts/share/www/static/favicon-32.png
    artifacts/share/www/static/apple-touch-icon.png

They are copied from `design/brand/`, the suite's shared reference directory, by
the same hand-copy that already put `tokens.css` and the fonts in this tree.
They sit under the disk-served `share/www` tree (D9), shipped on disk as
`share/<v>/www/static` and served by the chassis, adding roughly 47 KB to the
shipped artifact.

**Which documents carry the markup.** artifacts serves one document,
`share/www/landing.html`, with a single `<head>`, already carrying
`static/tokens.css` and the font preloads.

**The `href` form** is the relative `static/…` form the page's stylesheet link
already uses, which resolves under the `/srv/artifacts/` mount and on the bare
loopback port alike. The contract fixes the target — the service's own static
mount — and not the string, so this form conforms.

**The routes are the chassis's.** artifacts declares `Spec.WWW` (D9), so appkit
mounts `GET /static/` for the asset subtree and answers the bare
`GET /favicon.ico` by re-dispatching it to `/static/favicon.ico` through the
same site handler (`appkit project/design/D07.md`) — the root path returns the
same bytes and the same pinned content type as the static path **by
construction**, and artifacts registers neither route itself. Content types are
pinned by `appkit/web` (`.ico` → `image/x-icon`, `.woff2` → `font/woff2`), not
inherited from the box. In production nginx strips the `/srv/artifacts/` prefix,
so `/srv/artifacts/favicon.ico` arrives as `/favicon.ico` and the chassis route
answers it; on the bare loopback port a browser issues it directly.

**Where the proof lives.** All three adopted ids are proven in
**`cmd/artifacts/`**, the package that assembles artifacts's real router
(`Spec.WWW` loaded from the committed `share/www`) and is therefore the only
place a request can reach the icon routes the way production does. The markup
assertion reads the committed documents through the same rendering path a user's
request takes; the asset assertion issues `GET` for each of the three paths
against the assembled router at its mounted prefix and checks status, non-empty
body, and exact content type. Neither test constructs a handler directly: a
directly-driven handler proves the bytes exist, never that the assembled service
serves them.

**Rejected.**

- **Restate the file set and the markup locally so this design reads
  self-contained.** A local restatement is drift by construction: it goes stale
  the moment `root project/design/D29.md` changes, and the suite's rule is cite,
  never restate. Rejected.
- **Re-mint local ids for the two behaviors instead of citing `R-RYDN-YNR5` /
  `R-RZLK-CFHU`.** Both are `[proof: per-service]`: each is the suite's handle
  for one behavior, proven once per adopting tree. Parallel local ids would give
  one behavior two handles and break the id-to-behavior invariant. Rejected.
- **Keep hand-wiring `GET /favicon.ico` and pinning `.ico` in the service's own
  static handler instead of adopting `Spec.WWW`.** That was the shape while
  artifacts embedded its assets and served them itself; now the chassis WWW
  mount provides both routes and pins both content types, so a local copy is a
  second place for the same contract to drift, for a route whose entire contract
  is that it returns exactly what the static path returns. Rejected in favour of
  the chassis mount.
- **Assert the markup by string-matching the committed HTML file on disk instead
  of through the render path.** It is the cheaper test and it is a proxy: it
  proves a file contains a substring, not that the served response does. For a
  template-rendered head the two can differ. Rejected.
- **Prove the assets by calling a handler directly.** Same proxy pattern: it
  cannot fail when the route is missing from the composition root, which is the
  failure actually worth catching. Rejected.

**Verification.**

All three ids below are **adopted**, not minted here: each belongs to
`root project/design/D29.md`, which states the behavior. These lines say only
what substrate proves it inside `artifacts/`.

- `R-RYDN-YNR5` — adopted from `root project/design/D29.md`. Substrate: hermetic
  — a Go test in `cmd/artifacts/` that renders every document artifacts serves
  through the real rendering path and asserts each response's `<head>` carries
  all three link elements: `rel="icon"` with `sizes="any"` at `favicon.ico`,
  `rel="icon"` with `type="image/png"` at `favicon-32.png`, and
  `rel="apple-touch-icon"` at `apple-touch-icon.png`. The document set is
  **enumerated from the committed tree**, not hard-coded, so a page added later
  without the links fails.
- `R-RZLK-CFHU` — adopted from `root project/design/D29.md`. Substrate: hermetic
  — a Go test in `cmd/artifacts/` that builds artifacts's real assembled router
  (`Spec.WWW` loaded from the committed `share/www`) and issues `GET` for
  `favicon.ico`, `favicon-32.png`, and `apple-touch-icon.png` beneath the
  mounted static prefix, asserting `200`, a non-empty body, and `Content-Type`
  exactly `image/x-icon` for the ICO and exactly `image/png` for both PNGs.
- `R-8MFA-HUNC` — adopted from `root project/design/D29.md`. Substrate: hermetic
  — a Go test in `cmd/artifacts/` that builds artifacts's real assembled router
  and issues `GET /favicon.ico` at the **root path**, asserting `200` (not a
  `3xx`, so a redirect to the static path fails), `Content-Type` exactly
  `image/x-icon`, and a body byte-identical to the same router's
  `GET /static/favicon.ico` response.
