# Decision 7 — Event production: `created` / `updated` / `deleted`

## Decision.

artifacts is an event-plane producer per `root project/design/D18.md` (cited,
not restated): the eventplane outbox shares the service DB, events are
written **in the same transaction** as the domain change they report, and the
chassis serves `/feed`.

Three kinds, subject always `/<artifact-id>`:

| kind | fired by | payload |
|---|---|---|
| `created` | a successful signed-link upload (D3 step 6) and a successful `import` (D5 step 4) | the full fact: `id`, `filename`, `description`, `visibility`, `size`, `content_hash`, `owner_id`, `owner_email`, plus the content-plane reference (`content_url`, `content_hash`, `size`) so a consumer can pull the bytes without a lookup |
| `updated` | `update` and `set_visibility` (D6) | `id`, `filename`, `description`, `visibility`, `owner_id`, `owner_email` — the post-change state |
| `deleted` | `delete` (D6) | `id`, `filename`, `visibility`, `owner_id`, `owner_email` |

Payloads carry the owner **pair** (`root project/design/D17.md`). Reflection
declares the three families (`created` / `updated` / `deleted`, subject
pattern `/<artifact id>`) with payload samples, so consumer filters like
`artifacts:created/**` validate.

## Rejected.

- **Per-visibility kinds (`published`, `unpublished`).** Visibility is a
  field of the fact, not a fact class; consumers that care filter on the
  payload in their handler, per the plane's payload-querying rejection.
- **A `downloaded` event.** The operator bounded downloads to a count; an
  event per download is a per-download log by another name.
- **Emitting events outside the domain transaction.** The atomic outbox is
  the plane's core rule: an event exists iff the fact does.

## Verification.

(Real DB: the outbox table is inspected in the same temp SQLite the domain
wrote.)

- R-4NJZ-KUW8 — a successful signed-link upload (`201`) leaves exactly one
  `created` outbox row: kind `created`, subject `/<new id>`, payload
  carrying the owner pair, filename, visibility, size, the 64-hex hash, and
  a `content_url` on artifacts' own registry port; a failed upload (`413`,
  bad token) leaves no outbox row. Substrate: hermetic.
- R-4PZS-CEDM — a successful `import` leaves one `created` row of the same
  shape; a refused import (validation / source_unavailable / too_large)
  leaves none. Substrate: hermetic.
- R-4R7O-Q64B — `update` and `set_visibility` each leave one `updated` row
  whose payload is the post-change state; `delete` leaves one `deleted` row
  naming the id and owner pair; subjects are all `/<id>`. Substrate:
  hermetic.
- R-4SFL-3XV0 — reflection declares exactly the families `created`,
  `updated`, `deleted` with a `/<artifact id>`-shaped subject pattern and
  payload samples, and the filter `artifacts:created/**` is accepted against
  the declaration. Substrate: hermetic.
