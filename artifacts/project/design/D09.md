# Decision 9 — The landing page: a sortable, filterable inventory

## Decision.

`GET /{$}` at the mount root is the service's owner-facing index — the full
stored inventory, rendered in-process from the DB (always accurate, no
generated file), session-gated at nginx (D8), read-only: it lists, links,
sorts, and filters; it mutates nothing.

The template and Carbon assets are the service's own copies, served
**from disk under `share/www/`** through the shared chassis web mount rather
than embedded into the binary — the suite's disk-served shape, matching
`sites`/`github` and every other current WWW service. The composition root
declares `Spec.WWW`, so at boot appkit loads the site at the configured
`ARTIFACTS_WWW_PATH` (default `./share/www`, composed from `IKIGENBA_ROOT` on
the box per `root project/design/D11.md`), mounts `GET /static/` for the assets,
and exposes the loaded site through `rt.WWW()`. The service owns only the one
page route `GET /{$}` and renders it through that site. The layout byte-conforms
to the cron canonical template outside the named per-service slots (spine
Conventions), and `share/www/static/` holds `tokens.css`, the woff2 fonts, the
client controller `landing.js`, and the three brand icons (D11).

The page route lives in the **composition root** (`cmd/artifacts/main.go`),
which builds the view from the store and renders it through the chassis site —
the `sites` pattern:

```go
type landingRenderer interface {
    Render(w http.ResponseWriter, name string, data any) error // rt.WWW()
}

type landingView struct {
    Service   string
    Version   string
    Artifacts []artifactRow
}

type artifactRow struct {
    ID            string // island data; not a visible column
    Filename      string // visible, linked row identity
    Description   string // visible; filter matches it
    URL           string // tier-correct absolute download URL (D4)
    Visibility    string // "public" / "private", rendered verbatim
    Size          string // human display ("1.2 MB")
    SizeBytes     int64  // island: machine sort key
    CreatedBy     string // owner_email snapshot (display; owner_id not exposed)
    CreatedAt     string // human display, UTC
    CreatedAtSort string // RFC3339 UTC: machine sort key
    Downloads     int64  // download_count
}

// landingHandler reads the live inventory from the store and renders
// "landing.html" through the chassis site (rt.WWW()).
func landingHandler(store *artifacts.Store, r landingRenderer, service, version string) http.Handler
```

The table renders one row per artifact — filename as
`<a href="{{.URL}}">{{.Filename}}</a>` (a working download link, per its
tier), description, visibility verbatim, size, created-at, creator, download
count — with an explicit empty state. Filename and description are user
text: the Go template's contextual auto-escaping makes rendering safe, and
the client rebuild uses `textContent`, never `innerHTML`.

**The JSON data island** — the same rows once more as
`<script type="application/json" id="artifacts-data">…</script>`, each
element `{id, filename, description, url, visibility, sizeBytes, createdAt,
createdAtSort, downloads}`, rendered from the **one** `Artifacts` slice so
table and island never disagree; empty slice → `[]`.

**The client controller** (`share/www/static/landing.js`, a static asset served
by the chassis `/static/` mount, island-fed; the server does no filtering,
sorting, or pagination):

- **Filter**: one text input, case-insensitive substring match over
  `filename` and `description`; a visibility select (`all`/`public`/
  `private`).
- **Sort**: clickable column headers for filename (lexicographic), size
  (`sizeBytes`), created (`createdAtSort`), downloads (numeric); a repeated
  click flips direction.
- Rebuilds rows via `textContent`/`createElement`; anchors keep row `url`.

**Errors.** A store read failure renders no partial page: the handler returns
`500` with a plain-text reason and no body written from the template. A
template execution error is a broken invariant (the committed template is
proven to parse and render, R-OSZJ-I2D8), so it surfaces as `500` rather than a
panic. The chassis fails loudly at boot when `share/www` is missing or holds no
parseable template — a WWW service launched without its assets dies at startup
rather than serving a broken page.

## Rejected.

- **Keep the embedded `internal/web` copy (`go:embed`) and the service's own
  `StaticHandler`.** `root project/design/D29.md` sanctions both the embedded
  and the disk-served shapes without preferring either, so this is a
  consistency choice, not a contract fix: the disk-served shape matches every
  other current WWW service, sheds artifacts' bespoke static handler and
  hand-wired favicon route in favour of the one chassis mount, and makes a
  template or asset edit live on refresh with no rebuild. Rejected in favour of
  `share/www`.
- **Server-side query params for sort/filter.** The inventory is one box's
  files; shipping it once and letting the client arrange it avoids a query
  surface, matches sites' settled pattern, and keeps the handler a plain
  render.
- **Showing `owner_id`.** Browser display uses the email snapshot only,
  exactly as sites' landing decided.
- **Action buttons (delete, visibility toggle).** The operator fixed the
  page read-only; every mutation is MCP's.
- **Pagination.** A single-box inventory in the hundreds renders fine; the
  filter is the scale tool. Revisit only with evidence.

## Verification.

- R-53EO-JVJ9 — the rendered page contains one row per stored artifact:
  the filename anchored to its tier-correct download URL (a private file's
  href uses `/p/`, a public one `/f/`), visibility verbatim, creator email,
  and the download count; with zero artifacts it renders the explicit empty
  state and no rows. Substrate: hermetic — the composition-root handler renders
  the committed `share/www` template (loaded via `appkit/web`) over a real DB.
- R-54MK-XN9Y — the island parses as JSON, has exactly one element per
  stored artifact with the declared fields, each element's `url` equal to
  its row anchor's href, `sizeBytes` numeric and `createdAtSort` RFC3339;
  empty inventory yields `[]`. Substrate: hermetic.
- R-55UH-BF0N — a headless-Chrome wiring proof (chromedp, test-only dep,
  hard-required by the gate — no skip): against a seeded auth-free
  `httptest` page rendered from the committed template, one session types a
  filter term and the visible rows narrow to the matching artifact; clears it;
  clicks the size header and the first visible row becomes the largest
  (second click: smallest); clicks the downloads header and order follows the
  count. Substrate: hermetic + real browser.
- R-572D-P6RC — a stored filename and description containing
  `<script>` markup render inert: the page source contains the escaped
  form in the table and a validly-parsing island, and the browser session
  above registers no alert/injected node. Substrate: hermetic + real
  browser (shares the R-55UH-BF0N session's seed).
- R-5AQ2-UHZF — the handler serves the page in-process **without** identity
  headers (the session gate is nginx's, D8), and the rendered version
  equals the committed `VERSION` value. Substrate: hermetic.
- R-OSZJ-I2D8 — the committed `share/www/landing.html` byte-conforms to the
  cron canonical template outside the named per-service slots (eyebrow,
  description line, `{{.Service}}`/`{{.Version}}`, the table/island/controller
  block), and on the **assembled router** (`Spec.WWW` loaded from the committed
  `share/www`) `GET /static/tokens.css` and each committed woff2 answer `200`
  with their pinned content types (`text/css`, `font/woff2`). Substrate:
  hermetic (committed-file comparison + assembled-router asset fetch).
- R-OU7F-VU3X — composition-root wiring: with one artifact seeded in a real
  store, `GET /{$}` issued against the **assembled router** (the real
  `cmd/artifacts` router with `Spec.WWW` loaded from the committed `share/www`,
  the landing rendered through `rt.WWW()`) answers `200` and its body carries
  that artifact's filename as a row — proving the disk site is loaded and the
  page route is wired through the composition root, not a directly-constructed
  handler. Substrate: hermetic (assembled router + real store).
