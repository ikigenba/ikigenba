# Decision 4 — The download surface: public and private tiers

## Decision.

Every stored file has exactly one canonical download URL, decided by its
visibility:

```
public:   https://<host>/srv/artifacts/f/<id>/<filename>
private:  https://<host>/srv/artifacts/p/<id>/<filename>
```

The `<id>` is the artifact's 30-char random token (D2) — the unguessable
element; `<filename>` is the stored filename (URL path-escaped), so the
browser saves a recognizable name. Two in-process handlers serve them; nginx
(D8) proxies `/f/` **ungated** and `/p/` **session-gated**:

- `GET /f/<id>/<filename>` — mounted bare, self-guarding like the upload
  ingress (any identity header present → `404`; it is the anonymous tier and
  must never see a gated request). Serves only artifacts with
  `visibility='public'`.
- `GET /p/<id>/<filename>` — mounted behind the chassis identity gate
  (`X-Owner-Id` required, per `root project/design/D17.md`; nginx's session
  tier injects it). Serves only artifacts with `visibility='private'`.

Shared serving logic `serveArtifact(w, r, wantVisibility)`:

1. Parse `<id>` and `<filename>` from the path; malformed → `404`.
2. `GetArtifact(id)`; unknown id, `filename` ≠ the stored filename (exact
   byte match after path-unescaping), or `visibility` ≠ the tier's → the
   **identical** `404`. A private file requested on `/f/` and a public file
   requested on `/p/` both 404 — the tier mismatch reveals nothing.
3. Stream the blob with `Content-Length: <size>`, `Content-Type` from
   `mime.TypeByExtension(filepath.Ext(filename))` falling back to
   `application/octet-stream`, and `Content-Disposition: attachment;
   filename="<filename>"` (RFC 5987-encoded when non-ASCII). `GET` only
   (`405` otherwise); no range support (permitted by the content plane to
   omit).
4. `IncrementDownloadCount(id)` after the response body is fully written
   without error (count only, D2 — no per-download row).

Visibility flips (D6 `set_visibility`) change **which tier serves the id**;
the id itself is stable, so the URL changes only in its `/f/` vs `/p/`
segment. MCP results and the landing page always render the URL matching the
current visibility.

## Rejected.

- **One tier with in-handler session checking.** Services run no token or
  session logic — nginx is the sole trust boundary. Splitting public/private
  into two nginx locations lets the existing `/_session-authn` gate do the
  private check, exactly as sites gates its private tier.
- **Rotating the id on visibility change.** sites rotates unlisted slugs
  because its slug doubles as the secret for a *shareable* tier; here the
  operator asked for a stable file identity, and a flipped-to-private file is
  protected by the session gate, not by link secrecy alone.
- **`Content-Disposition: inline`.** This is a download service; attachment
  is the promise. Inline rendering (and the content-sniffing risk of serving
  hostile HTML on the apex origin) is sites' domain, not artifacts'.
- **Serving on filename alone or id alone.** Filename alone collides (names
  are non-unique); id alone downloads as a meaningless token-named file. The
  pair gives unguessability and a human filename, and the exact-match rule
  keeps one URL per file.
- **Range/conditional support in v1.** Permitted, never required, by the
  content plane; plain streaming satisfies every stated promise.

## Verification.

(All via `httptest` over the real handlers, real temp SQLite + blob dir.)

- R-3WQ7-5WKY — a public artifact's `GET /f/<id>/<filename>` with **no**
  identity headers returns `200` with byte-identical content,
  `Content-Length` = size, an attachment `Content-Disposition` carrying the
  filename, and a `Content-Type` derived from the extension (a `.pdf` name
  yields `application/pdf`; an unknown extension yields
  `application/octet-stream`). Substrate: hermetic.
- R-3XY3-JOBN — a private artifact's `GET /p/<id>/<filename>` with
  `X-Owner-Id` present returns `200` with byte-identical content; the same
  request **without** `X-Owner-Id` is refused by the identity gate (`401`).
  Substrate: hermetic.
- R-3Z5Z-XG2C — tier mismatch is invisible: a **private** artifact on
  `/f/…`, a **public** artifact on `/p/…` (with identity), an unknown id,
  and a correct id with the wrong filename all return `404`s that are
  byte-identical within their tier. Substrate: hermetic.
- R-40DW-B7T1 — `GET /f/<id>/<filename>` carrying `X-Owner-Id` (a gated
  request leaking into the anonymous tier) returns `404`; carrying only
  `X-Forwarded-Proto` it serves normally. Substrate: hermetic.
- R-41LS-OZJQ — after `set_visibility` flips a public artifact private, the
  previously-serving `/f/` URL returns `404` and the `/p/` URL (with
  identity) serves the identical bytes under the **same id**; flipping back
  restores the `/f/` URL. Substrate: hermetic.
- R-42TP-2RAF — each completed download raises `download_count` by exactly 1
  (two downloads → count 2), and a `404` (wrong filename) raises nothing.
  Substrate: hermetic.
