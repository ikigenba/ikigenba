# Decision 9 — `bin/lint` enforces the suite lint contract, proven in `bin/bintest`

**Decision.** This tree **adopts the suite's lint contract**
(`root project/design/D30.md`) as its designated proof tree (`[proof: bin]`):
`bin/lint` is the one entry point through which any tree's style tier is
enforced, `bin/` carries the two committed tier configs, `bin/ship` gains the
release-time refusal, and `bin/bintest` carries the tagged tests that prove
all of it. The contract's content — the tier model, the `.lint-tier` marker
semantics, the rule lists and thresholds, the analyzers-skip-tests /
gofumpt-everywhere policy, the golangci-lint version pin — is the umbrella's
and is not restated here; this Decision owns only the enforcement mechanics
and their proof.

**The committed configs: `bin/lint.d/`.** Two complete golangci-lint v2
config files, `bin/lint.d/cheap.yml` and `bin/lint.d/strict.yml`, realizing
the contract's rule lists and thresholds verbatim. Each sets
`issues.max-issues-per-linter: 0` and `max-same-issues: 0` (the v2 defaults
truncate findings — see the umbrella's research), and expresses the test-file
exclusion as **per-linter path rules against `_test\.go`** so `gofumpt`
still covers test files (a global `run.tests: false` would silence it). The
two files are complete and independent — golangci-lint has no config
inheritance, so "strict extends cheap" is realized by content, and keeping
the two in agreement is this tree's job, checked by the contract's ids. The
configs are **governed source**: a threshold or rule edit without a matching
umbrella amendment is drift.

**`bin/lint [<tree>]` — resolution and flow.** Bash, like every `bin/`
command, execing golangci-lint as its only analysis engine:

1. **Version gate first.** Compare `golangci-lint version` against the pin
   cited from the contract. On mismatch (or a missing binary): loud non-zero
   exit *before any linting*, stderr naming the pinned and found versions and
   how to install the pin. It never judges with the wrong tool.
2. **Resolve the target root.** The repo root derives from `BASH_SOURCE`, the
   house style; the test seam is the usual **env override, inert when
   unset**: `LINT_REPO_ROOT=<dir>` retargets the *tree being linted* (its
   `go.work`, modules, and `.lint-tier` markers) at a fixture. The **configs
   always resolve from the script's own `bin/lint.d/`**, never from the
   target root — so a fixture exercises the real committed configs, which is
   the whole point of the config-behavior tests.
3. **Resolve the module set** from the target root's `go.work` (`go work
   edit -json`). A `<tree>` argument naming no member: loud non-zero exit
   listing the valid trees.
4. **Read the tier**: `<tree>/.lint-tier` under the target root; absent means
   `off`; content other than exactly `cheap`/`strict` (modulo trailing
   newline): loud non-zero exit naming the tree, the bad content, and the
   valid values. Never guess.
5. **Lint**: run golangci-lint with the tier's config over the module
   (`off` runs the cheap config **report-only**). With no `<tree>` argument,
   iterate every module **sequentially** — concurrent golangci-lint
   invocations contend on a shared lock (see research) — printing one
   scoreboard line per module: name, tier, finding count.
6. **Exit**: single-tree mode exits non-zero iff the tree's tier is enforced
   (`cheap`/`strict`) and findings exist; `off` always exits 0 with its count
   printed. Scoreboard mode exits non-zero iff **any** enforced module has
   findings.

Like every failure above, these are expected operator-facing errors on
stderr; `bin/lint` has no panic path (`set -euo pipefail` aborts are defects,
not contract).

**The ship gate.** `bin/ship <svc>` runs `bin/lint <svc>` **immediately after
its clone of `main` and before any build**, pointing `LINT_REPO_ROOT` at the
clone so the judged source is exactly the build source. A non-zero lint
(including version-gate and marker errors) aborts ship with no bundle
produced and no box contact — the same early-refusal posture as bump's
changelog gate. `--dry-run` runs the gate too: a red tree fails even the
rehearsal, so the operator learns before building.

**The proof substrate.** All of this is local file-and-process logic a
hermetic fixture *can* falsify, so it moves under the green gate (the D8
precedent), with one deliberate widening of this tree's preconditions,
recorded in Conventions: the **real pinned golangci-lint binary** is required
on `PATH` for these tests. A stub engine cannot falsify the committed
configs' behavior — that a strict run flags a complexity-16 function, that
analyzers skip `_test.go`, that gofumpt still covers it — and per the
substrate rule a proxy a stub also passes is not proof. Concretely, each test
builds in `t.TempDir()` a fixture repo root (its own `go.work`, tiny modules
authored with or without specific findings, `.lint-tier` variants) and execs
the real `bin/lint` with `LINT_REPO_ROOT` set. The two exceptions run against
controlled stubs **of the environment, not the engine**: the version-mismatch
test prepends to `PATH` a stub `golangci-lint` that reports a wrong version
(the gate must refuse before analysis, so the stub proves nothing is
analyzed), and the ship test uses a fixture clone source so ship reaches its
lint refusal with no network and no real build.

**Rejected.**

- *A stub golangci-lint for all tests, keeping the tree's "Go toolchain
  only" precondition.* The config-behavior ids would then assert only that
  `bin/lint` passes arguments — a claim a wrong config also satisfies. The
  substrate rule wins; the precondition is widened instead, loudly.
- *Skipping lint tests when the binary is absent.* The skip ban (D7 / root
  D23): a skipped requirement test is uncovered. Missing tool = red, naming
  the pin.
- *Resolving configs from the target root.* A fixture would then carry config
  copies, and the tests would prove the copies, not the committed configs.
  Script-relative resolution makes the real `bin/lint.d/` the only config
  source anywhere.
- *Flat config files (`bin/lint-cheap.yml`) instead of `bin/lint.d/`.* The
  flat `bin/` namespace is executables; a directory keeps the pair (and any
  future tier) as one visible unit, as `bintest/` already does for tests.
- *Parallel module linting in scoreboard mode.* golangci-lint's own lock
  serializes concurrent runs anyway (observed: stale-lock failures);
  sequential is the same wall-clock without the flake.
- *Gating ship on the operator's worktree instead of the clone.* Ship builds
  the clone of `main`; judging a different tree than the one shipped is
  exactly the desync the gate exists to prevent.
- *Skipping the gate under `--dry-run`.* The rehearsal exists to surface
  refusals early; a dry run that hides the newest refusal reports a ship that
  would not succeed.
