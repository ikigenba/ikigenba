# Decision 8 — `bin/bump` enforces the changelog contract, proven in `bin/bintest`

**Decision.** This tree **adopts the suite's changelog contract**
(`root project/design/D28.md`) as its designated proof tree (`[proof: bin]`):
`bin/bump` is the release-time gate that keeps every deployable app's
`CHANGELOG.md` from going stale, and `bin/bintest` carries the tagged tests
that prove the gate. The contract's content — which trees carry the file, the
file shape, the authoring discipline — is the umbrella's and is not restated
here; this Decision owns only bump's enforcement mechanics and their proof.

**The gate, in bump's flow.** After bump has validated its arguments, resolved
the repo root, confirmed the service is versioned, enforced `main`, parsed
`<app>/VERSION`, and computed the next version — and after the `--dry-run`
early exit, which deliberately precedes the gate — bump checks
`<app>/CHANGELOG.md` before writing anything:

- **Absent file → refuse.** No `<app>/CHANGELOG.md`: loud non-zero exit,
  `VERSION` unwritten, no commit, no push.
- **Mismatched heading → refuse.** The version token of the **first `## `
  heading** in the file must be exactly the version bump is about to mint
  (the first heading is the newest section per the contract's newest-first
  order). Anything else — the previous release's version, a malformed token —
  is the same loud refusal. Bump validates the version token only; the date
  and the entry text are the author's, unchecked.
- **Match → widened path-limited commit.** On success the single commit
  carries exactly two pathspecs — `<app>/VERSION` and `<app>/CHANGELOG.md` —
  so `main` never holds a version whose changelog disagrees. The commit stays
  path-limited: unrelated working-tree edits are never swept in.

The refusal message tells the operator what to do: author the new top section
for the version `--dry-run` reports, then re-run bump.

**The test seam: `BUMP_REPO_ROOT`.** Bump derives its repo root from
`BASH_SOURCE`; a hermetic test needs it to operate on a fixture instead. Per
Conventions, the seam is an **env override, inert when unset**:
`BUMP_REPO_ROOT=<dir>` makes bump `cd` there instead of the script-derived
root (mirroring `START_RUN_DIR`). The operator's ordinary invocation is
unchanged.

**The proof substrate.** The gate is pure local file-and-git logic — unlike
`ship`'s builds and remote copies, a hermetic fixture *can* falsify every
claim, so this slice of bump moves under the green gate rather than the manual
tier. Each test builds, in `t.TempDir()`: a git repo on a branch named `main`
with a committed `<app>/VERSION` (and `CHANGELOG.md` variant per case), plus a
**local bare repo wired as `origin`** so the success path's push completes
network-free. Tests exec the real `bin/bump` with `BUMP_REPO_ROOT` pointing at
the fixture, per the tests-exec-the-real-scripts rule.

**Rejected.**

- *Keeping the gate in the manual, deliberately-untested tier.* The umbrella
  marked these behaviors `[proof: bin]`, and the tier's rationale — no hermetic
  substrate can stand in for a build or a remote copy — does not apply: a
  fixture git repo falsifies every one of these claims. The precedent is D5/D6,
  where bin behavior that a fixture can falsify runs under the gate.
- *A flag seam (`--repo <dir>`) instead of the env override.* Conventions
  allow either, but the env override matches the existing `START_RUN_DIR`
  house style and keeps the operator-facing usage surface unchanged.
- *Stubbing the push (or asserting only the commit and skipping push).* A
  local bare `origin` costs two lines of fixture and lets the success-path
  test observe bump's real, complete flow; a stub would leave the push line
  unfalsifiable.
- *Validating the heading's date.* The contract makes the date the author's;
  a date check adds a failure mode with no drift it prevents.

**Verification.** No ids are minted here; **citing the umbrella's ids is
adoption**, and they enter this tree's coverage denominator like local ids.
All four are owned by `root project/design/D28.md` and realized by tagged
tests in `bin/bintest/*_test.go`:

- R-CKLX-X89X — with no `<app>/CHANGELOG.md` present, `bin/bump` exits
  nonzero, leaves `<app>/VERSION` unchanged, and creates no commit.
- R-CLTU-B00M — when the first `## ` heading of `<app>/CHANGELOG.md` carries
  a version token other than the exact version bump is about to mint (e.g.
  the previous release's), `bin/bump` exits nonzero, leaves `<app>/VERSION`
  unchanged, and creates no commit.
- R-CN1Q-ORRB — with a top heading matching the minted version, the single
  commit `bin/bump` creates contains exactly two paths: `<app>/VERSION` and
  `<app>/CHANGELOG.md`.
- R-CO9N-2JI0 — `bin/bump <app> <part> --dry-run` prints the next version and
  writes no file, creates no commit, and pushes nothing, even when
  `<app>/CHANGELOG.md` is absent or its top heading mismatches — so the
  author can learn the version before writing the heading.
