# Decision 5 — The manifest readers are proven under the green gate (`bin/bintest`)

**Decision.** The two manifest readers in this tree — `bin/registry` and the
staging half of `bin/start` (`stage_manifest_root`, which builds the prod-shaped
runtime manifest root under the run dir, D3) — **graduate out of the
deliberately-untested tier**. They are not orchestration: they read the on-disk
layout the box uses (the versioned `etc/<version>/manifest.env` behind an
`etc/current` symlink, whose contract is the umbrella's —
`project/design/D01.md` and `project/design/D11.md` at the repo root, not
restated here), and they have already diverged from it silently once — the
sibling-path drift the layout-parity fix repaired. A reader that can drift
without anything noticing is a reader that must be tested.

They are proven by a Go test module, **`bin/bintest/`** (module `bintest`),
registered in the repo-root `go.work` so its tests run under the repo's existing
green gate with no new runner.

- **Tests exec the real scripts** — `bin/registry` and `bin/start`, resolved
  from the `bintest` package directory's repo root — never a reimplementation of
  their logic. The scripts are the only substrate that can falsify these claims.
- **`bin/registry` needs no seam.** `REGISTRY_ROOT` already parameterizes it;
  tests point it at a fixture root in `t.TempDir()`.
- **`bin/start` gains two small seams, inert when unused:**
  - `--stage-only` — stage the runtime manifest root, then exit `0` **before**
    building or launching anything.
  - `START_RUN_DIR` — an environment override of the run dir
    (`RUN_DIR="${START_RUN_DIR:-$repo/tmp}"`), so a test stages into a
    `t.TempDir()` instead of the shared `tmp/`, which may belong to a running
    dev stack.
- **The rest of `bin/`** — `bump`, `ship`, `push-secrets`, `stop`,
  `create-migration`, and `start`'s build-and-launch half — stays in the
  untested tier per Conventions. This Decision carves out **only** the two
  layout-parity readers.

**Rejected.**
- *A `bin/*.test.sh` shell-test tier.* That tier existed and was removed (commit
  `019a99ee`) because nothing automated ran it — a test outside the gate rots.
  The Go module rides the gate that is already enforced on every build. Rejected.
- *Proving staging against the live suite* (`bin/start` up, then a request to the
  running dashboard). Not hermetic and not runnable under the gate: it needs
  ports, secrets, and a full build. The reader half of that end-to-end claim is
  already pinned hermetically by the chassis's inventory tests, so what remains
  to pin here is only the launcher's staged shape. Rejected.
- *Leaving both readers in the untested tier.* The behavior went unproven and the
  coverage check reported permanent false alarms, because the ids sat in a
  workspace whose scope could not reach these scripts. Rejected.
- *Reimplementing the readers' logic in Go and testing that.* A test that
  asserts against a second implementation proves the two agree, not that the
  script is right — and the drift being guarded against is precisely a script
  changing. Rejected for exec-the-real-script.

**Verification** (in `bin/bintest/*_test.go`, each test execing the real script).

- **R-V3XG-PB8R** — against a fixture `REGISTRY_ROOT` in a temp dir,
  `bin/registry` resolves a service whose manifest is at
  `<root>/<name>/etc/<version>/manifest.env` behind an `etc/current` symlink
  (`port`, `addr`, `mount`, and `feed-url` print the manifest-derived values;
  `list-mcp` includes the name when `MCP=true`), and does **not** resolve a
  service whose manifest exists only at the sibling
  `<root>/<name>/etc/manifest.env` (lookups exit nonzero; `list-mcp` omits it).
- **R-V6D9-GUQ5** — `bin/start --stage-only` with `START_RUN_DIR` pointed at a
  temp dir exits `0` and stages, for every service with an authored
  `<svc>/etc/manifest.env`, `<run>/opt/<svc>/etc/<version>/manifest.env` plus
  `etc/current` as a **relative** symlink to the version dir (`<version>` from
  the service's `VERSION` file, else `dev`), while creating no `*.pid` file and
  no built service binary under `<run>/bin`, and leaving the authored source
  manifests unmodified.
- **R-V7L5-UMGU** — with `APPKIT_PORT_OFFSET=<n>`, the staged manifest's `PORT`
  equals the authored `PORT` plus `n` while the authored source file keeps its
  base value; with the offset unset, the staged manifest's bytes equal the
  source's.
