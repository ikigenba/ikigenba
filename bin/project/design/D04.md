# Decision 4 — `bin/create-migration`: the single mint for a migration version

**Decision.** `bin/create-migration <service> <name>` is the **only** point at
which a schema-migration version comes into existence. No agent or operator
hand-picks a number or types a migration filename; the suite's two hard
migration rules (never hand-number, never modify a committed migration) rest on
this tool being the sole mint.

The version is a generated **14-digit UTC timestamp** (`date -u +%Y%m%d%H%M%S`),
so two agents on two branches minting a migration at different wall-clock
seconds get different versions and a merge carries both with no collision.
Timestamps sort strictly after the frozen legacy integer migrations
(`001_…`, `002_…`), so the two schemes coexist in one sorted run.

What the tool does, in order:

1. Validate that `<service>/internal/db/migrations` exists.
2. **Refuse** a `<name>` that slugifies to a library-coupled shared table
   (`outbox`, `feed_offset`) — those are frozen and owned by the event-plane
   library, not by a service.
3. Slugify `<name>`: lowercase; runs of non-alphanumerics collapse to a single
   underscore; leading and trailing underscores trimmed.
4. Stamp the version.
5. Write `<service>/internal/db/migrations/<ts>_<slug>.sql` with a templated
   header. If that exact path already exists, **fail** — never silently collide.
6. Print the created path.

The tool writes a migration and nothing else: it never applies one, never edits
an existing one, and never renumbers. The forward-only runner in the shared
chassis applies them.

**Rejected.**
- *A monotonically incrementing integer, read from the highest existing file.*
  Two branches authored in parallel pick the same number and collide on merge —
  the exact failure the timestamp removes. Rejected.
- *Letting an agent name the file directly, with the rule stated in
  documentation.* A convention nothing enforces is a convention that gets
  broken; making the tool the only mint makes the rule structural. Rejected.
- *Allowing a migration named for a shared event-plane table.* A service would
  redefine a table the library owns, and the divergence would surface as a
  runtime schema mismatch. Rejected for the explicit refusal.

**Verification.**

This Decision mints **no requirement ids**: `create-migration` is bash in the
deliberately-untested tier per Conventions, and its one property worth
proving — that two mints on the same day are distinct and ordered — is verified
**once, manually, outside the build loop**, when the tool is created or changed:
two successive invocations for the same service yield two distinct filenames
whose timestamps sort in creation order, a refused shared-table name exits
non-zero writing nothing, and a re-mint onto an existing path fails rather than
overwriting.
