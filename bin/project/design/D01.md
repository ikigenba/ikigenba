# Decision 1 — Version production: `bin/bump` and `bin/ship`

**Decision.** `bin/` owns the two **producers** of a release: the command that
advances a service's version and the command that turns that version into a
delivered artifact. Both conform to suite contracts they do not own — the
`v`-prefixed SemVer 2.0 version identity (`root project/design/D03.md`) and the
release bundle's versioned-tier layout (`root project/design/D02.md`) — and
restate neither.

**`bin/bump <svc> <major|minor|patch>`.** Reads `<svc>/VERSION`, increments the
requested field **carrying the `v`**, and writes the result back as a
path-limited commit on `main` carrying exactly two files: `<svc>/VERSION` and
`<svc>/CHANGELOG.md` — bump is the enforcement point of the suite's changelog
contract (`root project/design/D28.md`), refusing to mint a version whose
changelog record is missing or stale; the gate's mechanics and proof are D8's.
Which field to bump is
**always an operator-provided argument** — no policy for choosing it lives
anywhere in the suite; SemVer 2.0 itself defines what the fields mean.
`bump`'s domain is **bare `vMAJOR.MINOR.PATCH` only**: a `VERSION` file that is
anything else — bare (no `v`), partial, non-SemVer, or carrying a pre-release
or build-metadata suffix — is **rejected with a loud non-zero exit**, never
silently coped with. Pre-release and build-metadata forms remain valid suite
version *identity* (`root project/design/D03.md`), but `bump` does not produce
them: no committed `VERSION` has ever carried one, and dormant pre-release
arithmetic in the one tool that commits version state to `main` is complexity
with no consumer. If the suite ever starts cutting pre-release versions, this
Decision is rewritten then.

**`bin/ship <svc>`.** Builds `main` static for `linux/amd64` with `GOWORK=off`,
stamps the binary via `-ldflags` with the **full** version — the `VERSION` core
plus a `+<SHA>` build-metadata suffix taken from the built commit — then
assembles the release bundle and `scp`s **the bundle**, never a bare binary, to
the box's `/tmp`.

**What `ship` packages.** The service **authors its shipped tiers in source,
mirroring the install tree**: `<svc>/etc/nginx.conf`, `<svc>/etc/manifest.env`,
and an optional `<svc>/share/…`. `ship` packages exactly those, plus the built
binary, into the archive **in the exact tier layout `root project/design/D02.md`
defines** — the archive *is* the on-box tree for that one version, so the
on-box `stage` (`opsctl/project/design/D15.md`, informational) only unpacks and
places, and never remaps. Two producer obligations follow:

- The `share/` tier is **always present**, as an *empty* directory when the
  service ships no resources — `stage` requires the tier to exist, so a
  share-less service still gets one rather than a missing tier.
- `manifest.env` is **authored and portable** (`root project/design/D11.md`)
  and is packaged **verbatim**: `ship` does not generate, stamp, or rewrite it.

**Bundle filename.** `ship` names the delivered artifact by the suite's bundle
naming schema, which it does not own: the schema — and its worked examples —
belong to `root project/design/D02.md`, alongside the tier layout the archive
carries, because the on-box `stage` consumes both. `ship`'s obligations as the
producer are only these:

- It **constructs** the name from the canonical service name and the full
  version identity (`root project/design/D03.md`) — never by string-munging an
  existing filename.
- It always stamps the built commit, so a shipped bundle always carries `+<sha>`
  build metadata in that version identity.
- It passes the service name and the version to `stage` **explicitly**, so the
  name is constructed and validated on both ends and **never parsed back apart**.

The same filename is the box `/tmp` staging name.

Because the version embedded in the binary, the bundle filename, the archive's
versioned tiers, and the on-box deploy preflight all carry that one string,
`<svc> version`, the staged binary's filename, and the preflight agree by
construction.

**Rejected.**
- *Ship a bare binary and apply config/resources out of band.* A fragment change
  then never rides the version and cannot roll back with the binary. The bundle
  carries all shipped tiers as one versioned unit. Rejected.
- *Emit bare `X.Y.Z` and fix only the consumer side.* The `v`-everywhere gate on
  the box would reject the suite's own artifacts — the version contract binds
  **both** ends. Rejected.
- *Carry `-rel`/`+SHA` as out-of-band metadata rather than in the version
  string.* Defeats a single canonical identity the filesystem and the `version`
  verb share. Rejected.
- *Author the fragment and resources somewhere other than the service's own
  source tree (e.g. a central tooling directory).* Splits a service across two
  places' worth of intent and breaks "the service owns its shipped tiers."
  Rejected for `<svc>/etc/` + `<svc>/share/`.
- *A flat bundle (`<svc>`, `nginx.conf`, `manifest.env`, `share/…` at the root)
  with `stage` remapping it into the versioned tiers.* This was the original
  form, and it split layout knowledge across two producers — `ship` wrote flat,
  `stage` had to know the flat→tiered mapping — and the two drifted, so no real
  ship→stage round-trip worked. Rejected: packaging the exact tiered tree leaves
  **one** layout definition, in the umbrella, and `stage` only unpacks-and-places.
- *Teaching `stage` to accept a flat bundle instead.* Keeps two layout shapes in
  play and puts the mapping in the privileged on-box tool. Making the wire format
  equal the on-box tree removes the mapping entirely and keeps the change off the
  box. Rejected for the ship-side fix.

**Verification.**

This Decision mints **no requirement ids**. `bump` and `ship` are bash
orchestration — they build, stamp, archive, and `scp` — which per Conventions is
the deliberately-untested tier: no hermetic substrate can falsify a claim about
a remote copy or a release build, and a `t.Skip`-gated stand-in would count as
uncovered anyway. The one exception is `bump`'s changelog gate, which is pure
local file-and-git logic: that slice is D8's and runs under the green gate.
The rest is verified **once, manually, outside the build loop**,
when created or changed, against the behaviors stated normatively above:
`bump patch` on `v0.7.1` writing `v0.7.2`, rejecting a bare `0.7.1`, and
rejecting a pre-release `v0.7.1-rc.1` (outside `bump`'s bare-only domain);
`ship` stamping `v<core>+<sha>` into both the binary's `version` output and the
bundle name; the archive carrying the versioned-tier layout, `manifest.env`
verbatim, and a `share/` tier present even for a share-less service.

The bundle layout's **in-gate** proof lives on the consumer side: the on-box
`stage`'s bundle-path validation (`opsctl/project/design/D15.md`,
informational) rejects a malformed bundle, so a bundle that deploys has
round-tripped the contract.
