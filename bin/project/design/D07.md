# Decision 7 — The testing-language contract: `bin/bintest` is hermetic-only, and `bin/` gets an `AGENTS.md`

**Decision.** This tree adopts the suite's testing-language contract,
`root project/design/D23.md`, without deviation. The contract is cited, never
restated; this Decision records how `bin/`'s existing shape maps onto it and the
one gap adoption obliges the tree to close.

**The mapping.** `bin/` has one Go test module, `bin/bintest`, and a bash
orchestration tier that is deliberately untested (Conventions). In the
contract's vocabulary:

- Every test in `bin/bintest` is **hermetic**: it execs the real script under
  `bin/` as a local subprocess against fixtures in `t.TempDir()`, or parses
  committed `go.mod`/`go.work` bytes. No non-loopback address, no credential,
  no running suite. The contract names local subprocesses and temp-dir
  filesystems as hermetic substrates, so the existing tier needs no change to
  qualify.
- There is **no composed layer**: this tree builds no service binary to boot and
  drive. There is **no live layer**: nothing here talks to a real external
  service, so the tree commits no `//go:build live` file and defines no
  `-tags live` invocation.
- The **manual** layer is the bash orchestration tier the Conventions already
  describe — `bump`, `ship`, `push-secrets`, `start`/`stop`,
  `create-migration` — verified once by the operator when created or changed.
  Adoption does not change that tier's status; it only gives it the contract's
  name.

**The gap: `bin/` has no `AGENTS.md`.** The contract requires every tree to
commit its testing declaration, and `bin/` is the only tree in this pass with no
`AGENTS.md` at all to carry it. This Decision requires the file, and fixes what
it declares:

| fact | value |
|---|---|
| default-gate test command | `go test ./bin/bintest/...`, run from the repo root |
| layers present | hermetic (plus the manual bash tier); no composed, no live |
| preconditions beyond the Go toolchain | none |
| GOWORK mode | workspace — `bin/bintest` is a `go.work` member and resolves through it |

The GOWORK value is a deliberate deviation *from the other ops trees*, not from
the contract: the contract explicitly declines to unify GOWORK mode and requires
each tree to declare its own. `bin/bintest` is a repo-scoped test module whose
whole job (D5, D6) is reading other modules in this workspace, so workspace mode
is the correct resolution and `GOWORK=off` would be wrong here.

`AGENTS.md` also carries the ordinary tree preamble — what `bin/` is (repo-root
operator scripts plus the `bintest` proof tier), that it is spec-governed by
`bin/project/`, and that it is not versioned — so the file is a real tree doc,
not a single stanza.

**The repo-root aggregate gate stays where it is.** `suite_test.go` lives in the
repo-root module and is documented in `root project/design/README.md`
Conventions. It is deliberately **not** moved into `bin/bintest`: it fans out
over the repo's modules and would recurse if it were itself one of them, and
moving it would mean editing repo-root files, which is outside this tree's
scope boundary. This Decision records the choice so the absence reads as
intentional rather than as an oversight.

**Rejected.**

- *Declaring the testing facts in `bin/project/design/README.md` instead of an
  `AGENTS.md`.* The contract's declaration is meant to be found by whoever opens
  the tree, and every other tree carries it in `AGENTS.md`; a design spine is
  read by the build loop, not by a newcomer. Rejected.
- *`GOWORK=off` for consistency with `opsctl` and the services.* It would break
  the tree's own tests: D5 and D6 resolve sibling modules through the workspace
  by design. The contract keeps the mode per-tree for exactly this reason.
  Rejected.
- *Moving `suite_test.go` into `bin/bintest` so the repo has one test module for
  repo-scoped checks.* It would recurse (the fan-out would include its own
  module) and it would require editing repo-root files from inside this tree.
  Rejected.
- *Skipping the no-`t.Skip` scan because this tree has only three test files.*
  The scan's value is that it holds as the tree grows, and it costs one test.
  Rejected.

**Verification.**

- R-O1AD-MRKW [cited from `root project/design/D23.md`, `[proof: per-service]`]
  — a test reads the committed `bin/AGENTS.md` from disk and asserts its Tests
  section declares the default-gate test command
  (`go test ./bin/bintest/...`), the layers present (naming `hermetic`, and that
  there is no composed and no live layer), that there is no environmental
  precondition beyond the Go toolchain, and the GOWORK mode (workspace) — a
  build that edits `AGENTS.md` into disagreement with this Decision fails the
  gate. Substrate: hermetic (real committed file read from disk).
- R-O2IA-0JBL [cited from `root project/design/D23.md`, `[proof: per-service]`]
  — a source scan over `bin/bintest/*_test.go`, excluding any file carrying the
  `live` build constraint, finds **zero** occurrences of `t.Skip`, `t.Skipf`, or
  `t.SkipNow`; the scan assembles its needle from parts so the scanning file
  never matches itself. Substrate: hermetic (source scan).
