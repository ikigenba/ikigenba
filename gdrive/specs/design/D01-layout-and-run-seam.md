# D01-layout-and-run-seam

gdrive is the suite's first connector: one Go binary that moves files between a user's Google Drive and artifacts on that user's behalf, so that no byte and no credential passes through an agent's context. An agent finds a file with the read tools (`drives`, `list`, `search`, `show`) and asks for a **transfer** with `pull` (Drive to artifact) or `push` (artifact to Drive); the tool validates, records the transfer and answers at once, and the work runs in the background as the caller (`D06-transfers`), reaching Drive over REST v3 with an access token connections hands out (`D05-drive`) and artifacts over its socket. Transfers live in the app's own SQLite database, `state/gdrive.db` (`D04-store`); each transfer that begins and ends is an event on the bus and in the trail, and every Drive call is recorded as `drive.called` (`D05-drive`); eight MCP tools are offered at `/mcp` (`D09-tools`); and a page of the caller's transfers at `/`, a page per transfer at `/<id>`, a tools page at `/tools`, an about screen at `/about` and the not-found page are served to a signed-in user (`D07-pages`), every page's footer showing the `Release` then the `Commit` of the identity the run read. This design is the structural ground the others stand on: where the code lives, the seam through which the process is run so that every part can be tested without a real process, the settings and how they are read, the default client every Drive call goes through, the sweep's interval, the paths, the migrations, how the services file's sibling entries reach the clients, where the identity and the display string come from, and the binary's wiring. It follows connections' layout and run seam, the closest precedent, with artifacts' sweeper timer and scripts' transfer-shaped settings.

The module is `github.com/ikigenba/ikigenba/gdrive`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/gdrive`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/gdrive` is wiring only.

## The dependencies

gdrive depends on one module besides the standard library: `github.com/ikigenba/ikigenba/appkit`, required at a published release with no `replace` directive. Its `db` package brings the pure-Go SQLite driver, which keeps the release build cgo-free. gdrive uses appkit's `db`, `version`, `services`, `page`, `identity`, `mcp`, `telemetry`, `events`, `artifacts`, `connections` and `paging`, and restates none of their contracts. It speaks to Drive with the standard library's `net/http` alone; no Google library. Which release of appkit is data that `AGENTS.md` and `go.mod` hold.

## Where the environment is read

`main` makes the one read of the environment that is not `Run`'s own: it calls appkit's `version.Read` exactly once, first, and holds the result, the **identity**, whose `String()` is the **display string**. It hands the identity to `page.New`, whose banner carries its `Release` and `Commit` to every page's footer and to the about screen, and the display string to the `mcp.ServerConfig` its `Process.MCP` builds and to `Run` as `Process.Version`. Nothing below `main` calls `version.Read`. `Run` reads every variable through `Process.LookupEnv`: `DRAIN_SECONDS` and the five transfer settings once at start, through `settings.Read`; `LISTEN_PID`, `LISTEN_FDS` and `NOTIFY_SOCKET` for the socket and readiness; and `IKIGENBA_SERVICES` once, when it starts to serve.

## Packages

The root package, `gdrive`, holds what the module embeds: `Assets` (the five templates), `Etc` (`manifest.toml` and `nginx.conf`) and `Migrations` (two migrations: `0001_transfers.sql`, which creates the `transfers` table `D04-store` describes, and `0002_transfers_user_started_id.sql`, which adds the index that backs the paged read of a user's transfers, `D04-store`).

The internal packages hold the concerns, one each: `internal/cli` (the run seam, the command, the serve path, the default Drive client and the sweep interval), `internal/settings` (the six settings), `internal/server` (a listener's life), `internal/store` (the transfer records, `D04-store`), `internal/drive` (the Drive REST v3 client, the file object, the kinds and the export table, `D05-drive`), `internal/urls` (the connect page's address, an artifact's page and auth's address, `D06-transfers`), `internal/transfers` (the engine: validation and recording, the queue, the background work as the caller, the restart's settling, the drain and the prune, `D06-transfers`), `internal/trail` (the two transfer events and the app's secrecy, `D08-trail`; `drive.called` is `internal/drive`'s), `internal/tools` (the eight tools, `D09-tools`), `internal/pages` (the templates' data and the page routes, `D07-pages`) and `internal/web` (the route table, `D03-serve`). Which imports which is guidance, not contract.

## The run seam

The run seam is `cli.Run`, which takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package and the network, and returns the exit code. It is connections' seam without `Providers`, since gdrive has no provider table of its own, and with artifacts' `After`, since gdrive has a sweeper. `HTTP` is the client every call to Drive goes through: a test hands one whose transport answers every request as a fake Drive does, so no test reaches Google and no Process field names Drive's address. `Now` is the clock every time gdrive stamps or compares is read from: a transfer's started and finished times, the expiry check of a pull, the prune's cut-off, every event's time. `After` is the sweeper's timer: every wait between two prunes ends when a channel `After` returned for `cli.SweepInterval`, one hour, delivers. `Rand` is the source of every value gdrive mints: request ids, transfer ids and bus event ids. `Inherit`, `Now` and `Rand` are the caller's to give whenever `Args` is empty: `Run` has no default for any of them, and the choice of the process's own descriptor 3, `time.Now` and `crypto/rand.Reader` is made once, at the process boundary, by `cmd/gdrive`.

## The default Drive client

A nil `HTTP` is the client `cli.DefaultHTTP` returns. It has no overall `Timeout`, because a transfer of a gigabyte streams for minutes and the drain, not a clock on the whole exchange, is what ends a transfer cut short (`D06-transfers`). Its transport bounds the parts of an exchange that should be quick: the dial (`cli.DialTimeout`, 10 seconds), the TLS handshake (`cli.TLSHandshakeTimeout`, 10 seconds) and the wait for response headers once the request, body included, has been written (`cli.ResponseHeaderTimeout`, 60 seconds, enough for Drive to render an export or take a resumable upload's last chunk).

## Settings

gdrive reads six values at start, in this order: `DRAIN_SECONDS`, the space's, and the five its manifest's `[env]` declares (`D02-cli`): `TRANSFER_MAX_BYTES`, `TRANSFER_MAX_ACTIVE`, `TRANSFER_MAX_QUEUED`, `TRANSFER_KEEP_DAYS` and `TRANSFER_KEEP_COUNT`. Each is spelled as opsctl writes an integer: one or more ASCII digits, no sign, no leading zero, no unit, no white space; `0` is therefore refused for each, which keeps at least one transfer running, one waiting, one day's and one record's keeping. An unset or empty one is its default, the manifest's value: 5 seconds, 1073741824 bytes, 2 transfers, 10 transfers, 15 days and 100 transfers. Digits beyond what an `int64` holds read as the largest `int64`. `settings.Read` refuses the first value in that order that is not acceptable with a `*settings.Error` naming it, quoting its value and giving its unit, whose text `Run` writes after `gdrive: ` as a usage error before it looks for its socket. How the engine applies the five is `D06-transfers`'.

## Paths

Relative to `Process.Dir` (the process's working directory when empty) the database is `state/gdrive.db`, opened with `db.Open`, `gdrive.Migrations()` and `Process.Now`; `state/` is created when absent. gdrive writes nothing outside `Dir`, and keeps no blob on disk: bytes stream between Drive and artifacts.

## The siblings

`IKIGENBA_SERVICES` names the services file. Its entry `artifacts` is the `services.Entry` appkit's `artifacts.NewClient` is built with, and its entry `connections` the one `connections.NewClient` is built with, each with the run's telemetry writer, so every sibling call goes over the entry's socket, forwards the caller in the context and is recorded as `sibling.called`. `Run` reads the file once at start with appkit's `services.Read` and looks each entry up with `List.Find`, checking what it found (root decision R1): a client is built only over an entry found, never over a zero `services.Entry`. With `IKIGENBA_SERVICES` unset, naming no file, or naming one `services.Read` refuses, every entry is missing, and that never refuses the start, as connections' `urls.Configured` and scripts' instructions treat an unreadable file as one with no entry. A missing entry leaves the engine without that client, so a call that needs it is refused `unavailable` (`D06-transfers`, `D10-on-a-space`). The `URL` of the entry `connections` is also where the connect page a `not_connected` refusal names is built (`D09-tools`), and the `URL` of the entry `artifacts` where an artifact's page is (`D07-pages`), each through `internal/urls` (`D06-transfers`).

## Recorded decisions

- `Providers` is gone from connections' seam: gdrive serves no provider table, and Google's token comes from connections over its socket. `After` comes back from artifacts' seam: decision 12 asks for a prune once before ready and then hourly.
- No `Process` field names Drive's address. A test reaches its fake Drive through `HTTP`'s transport, as connections' tests reach `provider.invalid`, so the base URL stays a constant of `internal/drive` (`D05-drive`).
- `HTTP` nil means `cli.DefaultHTTP()`, with no overall timeout (orchestrator decision on the Drive client): connections' 30-second `Timeout` would cut off every large transfer. The three transport bounds and their values are this design's choice. The dial bound is declared but no requirement proves it is applied: a transport's dial function cannot be inspected, and observing it would need a real network wait. The meaning of a nil `HTTP` in `Run` is likewise a gloss no offline test can observe, as connections' was.
- `Process.Inherit`, `Process.Now` and `Process.Rand` are required whenever `Args` is empty: `Run` takes them as given and selects no default, and such a run with any of them nil is no case to design (the user's ruling on the process-defaults issue, after connections' broker). No requirement states this precondition, because no permitted test can observe it: a test never reads the real clock or randomness and never leaves the inherited-listener step unset, so a default could not be told from another source. What `Run` does with the sources it is given is stated by use (R-R49O-M31A, R-QUBF-CHWU, R-JHZC-E3RU), and the selection of the real ones lives only in `cmd/gdrive`, which is wiring. A command (`D02-cli`) touches none of the three, so a `Process` with them unset is still enough for every command.
- The constants for the default client and the sweep interval are declared in `internal/cli`, where `Run` uses them, rather than in `internal/drive` or `internal/transfers`: the client is a process-boundary choice like `time.Now`, and the timer is `Process.After`'s.
- The six settings follow scripts' reading (digits only, defaults from the manifest, `0` refused) and artifacts' error text; the transfer counts' unit is `transfers`, as scripts' run counts' is `runs`.
- The services file is read once at start for the sibling clients, as connections and scripts read theirs (root decision R1); a missing, unreadable or malformed file, or a missing entry, builds no client for that sibling rather than one over a zero entry, and the start goes on (connections' precedent). The pages read it afresh per request for the banner's addresses and an artifact's page (`D07-pages`).

## Consumer tasks

`main` calls `id := version.Read()` and `v := id.String()` and hands `cli.Run` a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Version` is `v`, whose `Banner` is `page.New(pages.ServiceName, id).Banner`, whose `Inherit` takes the process's own descriptor 3, whose `Now` is `time.Now`, whose `Rand` is `crypto/rand.Reader`, whose `After` is `time.After` and whose `MCP` returns `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Version: v, Telemetry: w})`, leaving the rest zero, so `HTTP` is `cli.DefaultHTTP()`; it cancels the context on `SIGTERM` or `SIGINT` with a cause whose `Error` is the signal's name, and exits with what `Run` returns. A test of the run seam writes a services file whose entries `artifacts` and `connections` name Unix sockets on which loopback fakes of the two siblings listen, builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` over a map naming that file in `IKIGENBA_SERVICES`, an `Inherit` returning a listener it bound, a `Now`, an `After` and a `Rand` it controls, an `HTTP` whose transport answers as a fake Drive, and capturing sinks; it calls `cli.Run`, waits for `READY=1`, drives the listener with `mcp.Client` at `/mcp` and raw HTTP to the pages, cancels, and inspects `Dir`, the fakes' requests, the captures and the streams. A test of settings calls `settings.Read` with a lookup over a map and compares with `settings.Defaults()` and `Drain()`. A test of the default client calls `cli.DefaultHTTP()` and inspects its `Timeout` and its transport. The one test that execs the binary composes non-empty `IKIGENBA_COMMIT` and `IKIGENBA_RELEASE` into the child's environment and computes the identity it expects with `version.Read` after setting the same two values with `testing.T.Setenv`; it never lets the binary reach Google, since nothing it asks makes a Drive call.
