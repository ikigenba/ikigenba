# D03-serve

The serve path: what happens between `cli.Run` being called with no arguments and the process being gone, the trail gdrive records of itself, the hourly prune of transfers past keeping, and the route table its handler keeps. It is artifacts' serve path with three differences: there is no blob directory, so the start opens the database and settles what a dead process left instead of reconciling files; the start's settling is scripts' (a transfer still `queued` or `running` was cut off and is finished `failed` with reason `interrupted` before ready); and the stop drains transfers as well as requests, as scripts drains runs. The sweeper's timer is artifacts': a prune once before ready, then one each time a wait of `cli.SweepInterval` on `Process.After` ends. `internal/server` is connections', unchanged.

## The terms gdrive serves on

gdrive serves only on a listening socket it inherits, taken as `sd_listen_fds(3)` documents, and reports readiness with `READY=1` to `NOTIFY_SOCKET` as `sd_notify(3)` documents. It trusts `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx sets them, and trusts the MCP gateway calling it at its socket to have forwarded them (`D10-on-a-space`). Every request has an id: the one nginx set, or 32 lowercase hexadecimal digits appkit's request middleware draws from `Process.Rand`.

The events app reaches gdrive at its socket on `/events` and `/declarations`. gdrive emits `transfer.started` and `transfer.finished` and accepts no event, so it mounts appkit's `events.DeliveryHandler` with no handlers, and `events.DeclarationsHandler` over its emitter, built with the declarations the trail owns (`D08-trail`). These two paths sit outside the identity gate, since a delivery carries no user; the fragment answers both 404 at the public name (`D02-cli`).

## The route table

Every request goes through appkit's `telemetry.Middleware`, which records `request.started` and `request.finished`. Then, by the URL path alone, whatever the host, compared by hand so that nothing is cleaned and nothing redirected: exactly `/events` and exactly `/declarations` go to the event bus's two handlers; every other request goes through `identity.Require`, which answers a request with no `X-User-Id` 500 with `identity.MissingBody` before its path or method is looked at. Past the gate: exactly `/mcp` goes, through `events.Middleware`, to the MCP server, on which the eight tools of `D09-tools` are registered once when the handler is built; a path beginning `/_appkit/` goes to `page.Static()`; and every other path to the page handler (`D07-pages`), which answers `/`, `/<id>`, `/about`, `/tools` and, for everything else, the not-found page. On a host nginx demands a credential before any of these, so the gate's 500 is only seen by a caller on the socket.

The handler is built from a `web.Config` carrying what the routes need: the banner source, the MCP server, the services file's path, the store, the transfer engine (`transfers.Engine`, `D06-transfers`), the Drive client (`D05-drive`), the writer and the emitter. It carries no connections client: the tools fetch the caller's Google token through the engine's `Token`, so the engine is the one holder of appkit's `connections` client. `Run` reads the services file once, at start, looks up the entries `artifacts` and `connections` with `List.Find`, and builds each sibling client only over an entry it found, leaving the engine's field nil otherwise (root decision R1, `D01-layout-and-run-seam`); a missing or malformed file is every entry missing and does not refuse the start. It builds the engine over them with `transfers.New`, whose `ConnectURL` is `urls.Connect(urls.Base(u))`, `u` being the `URL` of the entry `connections`, empty when the file has none (`D06-transfers`); the pages read the services file afresh for the banner's addresses and an artifact's page.

## The start

With `Args` empty, `Run` checks the settings (`D01-layout-and-run-seam`), then whether exactly one socket was passed in, exactly as artifacts does, with the same diagnostics after `gdrive: `. It removes the three `LISTEN_*` variables, takes descriptor 3, and opens the database with `db.Open` at `state/gdrive.db`; a failure is `gdrive: cannot open database state/gdrive.db: ` and the reason, exit 1, with nothing sent to the notification socket and no connection accepted. It builds the store, the writer, the emitter, the sibling clients, the Drive client and the engine, and records `service.started`, so that it is the first event of every run. Then the engine settles what a dead process left (`Engine.Recover`, `D06-transfers`): every transfer still `queued` or `running` is finished `failed` with reason `interrupted`. A settling that fails, the database having failed under it, refuses the start with `gdrive: ` and `store.Unreachable`, exit 1, as scripts refuses one: serving over transfers recorded `running` that nothing will ever end would show them running for ever. Then the engine prunes once (`Engine.Prune`, `D06-transfers`), removing every transfer past keeping as `store.Prune` decides with the run's `Now` and the two keep settings; a prune that fails is silent and tried again at the next interval, as artifacts' sweep is. Then `Run` builds the handler, sends `READY=1`, and serves.

## The sweep

While serving, each time a channel `Process.After` returned for a wait of `cli.SweepInterval` delivers, the engine prunes again with the `Now` of that moment, and `Run` waits again. A pruned transfer is gone from `transfers`, `transfer` and the pages; the artifact or Drive file it made is untouched (decision 12).

## Stopping

When `ctx` is done (in the binary, on `SIGTERM` or `SIGINT`, the signal's name being the cause) `Run` stops the sweep and calls `Engine.Drain` (`D06-transfers`) with a context that ends at the drain deadline, `DRAIN_SECONDS` after the signal: from then on a `pull` or `push` is refused with the drain refusal, word `stopping` (`D09-tools`); every transfer still `queued` is finished `failed` with reason `interrupted` at once; and every transfer `running` runs on until the deadline, so a small one finishes, and is then cancelled and finished `failed` with reason `interrupted`, the artifacts `Put` in flight leaving nothing and the Drive session creating nothing (decision 11). At the same time it drains the server for `DRAIN_SECONDS`, waits within the same window for the emitter to deliver what it holds, shuts the writer down with the cause's text as `service.stopping`'s reason, shuts the emitter down, and closes the database. From the drain deadline on, `Run` hands neither sink anything, as scripts' does: the `transfer.finished` of a transfer cut off at the deadline, and `service.stopping` after it, reach standard error as appkit's `lost event` and `undelivered event` lines, never the sinks; a stop in which every transfer and request ended in time delivers everything. A transfer abandoned is not a request cut off and never makes the exit non-zero; a drain that runs out on requests is `gdrive: stopped with <n> request(s) unfinished`, exit 1. Between its start and its return a serving `Run` writes nothing to standard output, and nothing to standard error unless the drain deadline found a transfer or a request unfinished.

## Recorded decisions

- `guests = false`, so the gate is `identity.Require` on every route but the events paths, `/_appkit/` included, as in artifacts and connections; there is no guest branch, and a page asked without a credential is sent to sign in by the host's nginx before it reaches gdrive (decision 14's "302 to sign-in" is nginx's).
- `/mcp` goes through `events.Middleware`, so a `pull` made by a script run by an event carries the cause and depth onward, and the `transfer.*` events the work emits carry them as `D08-trail` says.
- `service.started` is recorded before the settling and the first prune, as artifacts records it before its reconcile and first sweep, so it is the first event of every run and any event the settling records follows it.
- The settling runs before the first prune, so a transfer the dead process left and that is also past keeping is first finished and then removed in the same start. Both finish before `READY=1`: a start never shows a transfer `running` that nothing runs, or one a prune could have removed.
- A failed settling refuses the start (scripts, prompts); a failed prune does not (artifacts' sweep, webhooks'): a transfer past keeping that survives one more hour is harmless. That the failed prune is silent is not separately required: no `Process` hook fails the database after the settling, and the silence of a serving `Run` is proved over a healthy database.
- **Events at the deadline follow scripts' cutoff**: nothing is handed to a sink once the deadline has passed, so an event recorded after it, a cut-off transfer's `transfer.finished` above all, is written to standard error and is not on the bus. A script that waits on `transfer.finished` misses a transfer cut off at a stop; the next `transfer` call shows it `interrupted`.
- **The drain lasts up to `DRAIN_SECONDS`**: a transfer running at the signal that ends within it is recorded as it ends, `done` included, and from the drain's start a `pull` or `push` is refused `stopping`.
- The drain deadline is `DRAIN_SECONDS` on real time, never `Process.After`, as in scripts, so a drain test runs with `DRAIN_SECONDS=1` and waits about a second.
- Transfers abandoned at the stop never make the exit non-zero, as scripts' killed runs do not; only requests cut off do, through `*server.DrainError`.
- `web.Config` carries no clock or random source: the engine and the store hold `Process.Now` and `Process.Rand`, and the pages read only stored times. It carries the services file's path, which the pages read afresh per request, as artifacts' and connections' pages do.
- `web.Config` carries no `connections` client, and the tools are registered over the engine, the Drive client and the store alone (`D09-tools`): the engine's `Token` is the one place a missing or broken connection becomes a refusal, so nothing else needs the client. The engine's connect page is built from the entry `connections` with `urls` (`D06-transfers`), and `D09-tools` proves at the run seam that a `not_connected` refusal names it.
- No `Process` hook fails the database `Run` opens; a failing store is proved through `web.Handler` over a store whose handle the test fails, by the documents that own each route.

## Consumer tasks

`Run`, serving, calls `s, err := settings.Read(p.LookupEnv)`, checks the socket, unsets the three `LISTEN_*` variables and takes `ln, _ := p.Inherit(3)`; calls `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "gdrive.db"), Migrations: gdrive.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: p.Stderr})`; builds `st := store.New(d, store.Config{Now: p.Now, Rand: rand})`, `w := telemetry.New(...)`, `em := events.New(events.Config{..., Telemetry: w, Emits: <the trail's declarations>})`, `list, _ := services.Read(path)` and, when `artifactsEntry, ok := list.Find("artifacts")` finds it, `ac := artifacts.NewClient(artifacts.ClientConfig{Service: artifactsEntry, Telemetry: w})`, and when `list.Find("connections")` finds its entry, `cc := connections.NewClient(connections.ClientConfig{Service: connectionsEntry, Telemetry: w})`, each nil otherwise, `dc := drive.NewClient(drive.Config{HTTP: hc, Telemetry: w})` and `eng := transfers.New(transfers.Config{Store: st, Drive: dc, Artifacts: ac, Connections: cc, Telemetry: w, Events: em, ConnectURL: urls.Connect(urls.Base(connectionsEntry.URL)), MaxBytes: s.TransferMaxBytes, MaxActive: s.TransferMaxActive, MaxQueued: s.TransferMaxQueued, KeepDays: s.TransferKeepDays, KeepCount: s.TransferKeepCount, Now: p.Now})` (`D06-transfers`); calls `w.Ready()`; calls `eng.Recover(bg)` and `eng.Prune(bg)`; builds `h := web.Handler(web.Config{Banner: p.Banner, MCP: p.MCP(w), ServicesPath: path, Store: st, Transfers: eng, Drive: dc, Telemetry: w, Events: em})`; sends `READY=1`; and calls `server.Serve(ctx, ln, h, s.Drain(), stop)`, `eng.Drain(drainCtx)` beginning once `ctx` is done, `drainCtx` ending `s.Drain()` later. A test of the start seeds a temporary `Dir` beforehand through its own `db.Open` and a store over it whose clock it sets back, with transfers left `running` and `queued` and finished transfers past keeping, or with a regular file at `state`, or with a database in which its own handle dropped the table `transfers` through `DB.Write`; drives `cli.Run` with a listener on a Unix socket in a short temporary directory, a `NOTIFY_SOCKET` it binds, a `Now`, an `After` and a `Rand` it controls, an `HTTP` whose transport is a fake Drive, a services file naming loopback fakes of artifacts and connections, a `*telemetry.Capture` and an `*events.Capture`; waits for `READY=1`; asks `GET /<id>` with the identity headers; delivers on the channel `After` returned; cancels; and reopens the database to read the store. A test of the handler builds `web.Handler` over a store on its own database, a writer and an emitter over captures, a server from `mcp.NewServer`, an engine and clients pointed at fakes, serves it with `httptest`, and sends raw requests with the identity headers set or left out.
