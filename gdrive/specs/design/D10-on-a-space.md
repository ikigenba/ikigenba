# D10-on-a-space

What gdrive contributes when it runs on a space and in a sandbox, which entries of the services file it uses, and the trust it places in the identity it is sent. It follows connections' and artifacts' on-a-space designs. The guarantee those documents end with, that no secret and no byte of a body reaches the trail, the bus, a page, a tool answer or standard error, is `D08-trail`'s in gdrive, since the trail owns secrecy across the app.

## What ships

The release holds four members of gdrive's directory: `bin/gdrive`, `etc/manifest.toml`, `etc/nginx.conf` and `share/icon.svg`, the last Tabler's `brand-google-drive`, human-authored. No test reads the checkout, so the release and the icon are outside what a requirement can state; a developer checks them with `tar`. The manifest's lines carry what a space asks of it (`D02-cli`): `guests = false`, so the host's nginx puts every request through auth's `/check` and admits only one with a credential, to the pages and to `/mcp` alike; `mcp = true`, so the gateway offers its eight tools; `secrets = []`, since gdrive holds no credential of its own and Google's token comes from connections over its socket; `[env]` with the five transfer settings' defaults; `[database]` naming `state/gdrive.db`, which the host keeps and replicates; `[resources]` with `memory_max = "128M"`, enough because bytes stream between Drive and artifacts and are never held; and `[home]`, which puts gdrive in the `core` group of home's landing page, under Core Services, as decision 1 settles and the deferred `connectors` group would later change. The fragment answers the bus's two paths 404 at the public name. `DRAIN_SECONDS` is the space's, written into every app's environment by opsctl, not the manifest's.

## On a space

gdrive on a space is the same binary serving on the same terms as under a test: a socket passed as descriptor 3 (`/run/ikigenba/gdrive.sock`), `/var/opt/ikigenba/gdrive` as its working directory, so its state is `/var/opt/ikigenba/gdrive/state/`, its settings from `/etc/opt/ikigenba/gdrive/env`, and `IKIGENBA_SERVICES` naming the host's services file. Of that file it uses four entries: `artifacts`, whose socket the artifacts client puts and gets over and whose `URL` the pages build an artifact's page from (`D07-pages`); `connections`, whose socket the connections client fetches the caller's Google token over and whose `URL` the `not_connected` refusal's connect page is built from (`D09-tools`); `telemetry` and `events`, whose sockets appkit's sinks deliver to; and `auth`, whose `URL` the banner's profile and sign-out addresses use. `Run` reads the file once at start and looks each entry up with appkit's `List.Find`, building a client only over an entry it found (root decision R1); a missing file, one `services.Read` refuses, or a missing entry never refuses the start, as in connections. With no `connections` entry every Drive tool and both transfer tools are refused `unavailable` at the token, no request sent; with no `artifacts` entry a `pull` or `push` is refused `unavailable` where its `Head` would be sent (orchestrator P3, `D06-transfers`). No client is built over a zero entry, so such a refusal sends no request to any sibling and records no `sibling.called`, which appkit's clients record for every request they send. Since the clients are fixed at start, an entry cannot go missing between a call and its work. The connect page is relative, `/google/connect`, when the entry `connections` has no `URL` (decision 7); with no entry at all no `not_connected` can be answered, since there is no connections to answer it.

## In a sandbox

The sandbox builds gdrive from the worktree, gives it the five transfer settings from the manifest's `[env]`, puts every request through auth's `/check` because the manifest has `guests = false`, and includes `etc/nginx.conf` in gdrive's server. Its state is `<data>/apps/gdrive/state/`. An agent is curl on the developer's machine with the stored token, at `http://gdrive.<sandbox>.localhost:<port>/` for the pages and the gateway for the tools; the Google token comes from the sandbox's connections, whose grant the sandbox check seeds and removes (decision 19, outside this design).

## Trust

gdrive believes the identity it is sent, as every sibling does (decision 17, as artifacts and connections state it): `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx or the gateway set them on a request to its socket. It checks them against nothing, asks auth nothing, and sends the same three on to connections when it fetches a token and to artifacts when it puts or reads an artifact, through appkit's sibling client, so connections hands out that user's token and artifacts records that user as owner. The work a transfer does after its call has returned runs as the same caller, rebuilt from the user id, email and request id the record keeps (`D06-transfers`). A process that can reach gdrive's socket can therefore name any user and move that user's files; every service on the host is trusted, and the gateway and nginx are the only doors from outside.

## Recorded decisions

- The secrecy guarantee is `D08-trail`'s, not this document's, departing from connections' and artifacts' layout, where the on-a-space document holds it: the root's package map gives `internal/trail` the secrecy rules across the app.
- A missing `connections` entry, and connections unreachable at a tool call, are the refusal `unavailable` (orchestrator P3), stated at the run seam here and at the engine in `D06-transfers`. A missing `artifacts` entry is likewise `unavailable` at the call, at the point where a `pull` or `push` would send artifacts' `Head` of the path (orchestrator P1, P3); artifacts unreachable between the call and the work fails the transfer with reason `artifacts`, and connections unreachable then fails it `provider` (root decision R10). A missing or malformed `IKIGENBA_SERVICES` is every entry missing and does not refuse the start, connections' precedent.
- **Deferred** (decisions document): signed URLs on artifacts; the gmail, m365 and other connectors; Microsoft as a provider. **Rejected**: waiting for gmail to lift the connections client into appkit, since its interface is fixed by connections' design and waiting would buy only a second appkit release.
- `[home] group = "core"` (decision 1); a `connectors` group is deferred and rejected for now, since opsctl, the sandbox and appkit's services reader accept only `core` and `application`.

## Consumer tasks

An operator installs the release; opsctl reads `etc/manifest.toml`, writes the five settings and `DRAIN_SECONDS` into `/etc/opt/ikigenba/gdrive/env`, drops `etc/nginx.conf` into gdrive's server, adds gdrive's entry to the services file and starts the unit. A test builds a `cli.Process` with a temporary `Dir`, a services file whose entries `artifacts` and `connections` name Unix sockets on which loopback fakes listen and record every request's headers, or one lacking the `artifacts` or the `connections` entry, an `HTTP` whose transport is a fake Drive, capturing sinks, and its own `Now`, `After` and `Rand`; it calls `drives` and `pull` through `mcp.Client` with `X-User-Id`, `X-User-Email` and `X-Request-Id` values of its choosing, waits for the transfer to end, cancels, reopens the database, and compares the headers the fakes recorded and the stored record.
