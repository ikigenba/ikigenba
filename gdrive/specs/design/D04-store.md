# D04-store

The transfer records: `internal/store`, which owns gdrive's one table in its SQLite database, `state/gdrive.db`: `transfers`, one row per transfer a `pull` or `push` recorded and the prune has not yet removed. It says what a transfer holds, the words its direction, status and failure reason are spelled with, how a transfer is recorded, started, given progress and finished, which reads the engine, the pages and the tools have, how the prune decides what is past keeping, the errors every consumer tells apart, and the one line every consumer answers when the database cannot be reached. Opening, migrating, transactions, `db status` and the failure seam are appkit's `db`; `D01-layout-and-run-seam` resolves the path and declares `gdrive.Migrations()`, and `D02-cli` the `db status` command, which writes what appkit's `db.Status` writes for this database. It follows scripts' runs for the record made at once and observed later, and connections' store for its form: the store stamps its own times and mints its own ids.

## One database, one writer

gdrive is the only writer of its database, and the database is the only record of its transfers; there are no blobs, since bytes stream between Drive and artifacts. `store.New` builds a store over a handle and opens or creates nothing. What a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds; a test proves the records that way, never by reading tables. A store whose handle is failing (`SetFailing(true)`) answers every call with `ErrUnreachable` and changes nothing. `Config.Now` is the clock every stamp and every prune comparison is read from, and `Config.Rand` the source transfer ids are drawn from; `Run` hands in `Process.Now` and `Process.Rand`. Both are the caller's to give: the store has no default for either, and the choice of `time.Now` and `crypto/rand.Reader` is made once, at the process boundary, by `cmd/gdrive` (`D01-layout-and-run-seam`).

## Transfers

A **transfer** is one move of one file, made for one user. Its **id** is `xfr_` and 16 lowercase hexadecimal digits, 8 bytes drawn from the random source when the transfer is recorded, drawn again when they are a transfer's id already. Its **direction** is `pull` (Drive to artifact) or `push` (artifact to Drive). It keeps the Drive file's id (`file`, the target's for a followed shortcut, and for a push that creates a file empty until the file exists), its `name` and `kind`, the artifact's `path`, the `content_type` the bytes carry, the `format` a Google-native file was exported to (empty otherwise), `bytes`, the count moved so far and final when done, **started** and **finished**, each UTC to the second, and, once done, the artifact's `url`, the Drive file's `link`, and the artifact's `id` when artifacts' `Put` answered one, which only a pull has and from which the pages build the artifact's page. It also keeps the caller it was made for, the user id, the email and the originating request id, so the work runs as that caller when no request is left (`D06-transfers`) and every read is scoped to the user.

Its **status** is one of four words: `queued` while it waits for a slot, `running` while bytes move, `done` and `failed`. A failed transfer has one of seven **reasons**: `not_found`, `forbidden`, `too_large`, `reconnect`, `provider`, `artifacts` and `interrupted`; which failure is which is `D06-transfers`', and a reason's sentence on the transfer page is `transfer.html`'s (`D07-pages`). The direction, status and reason words are exported constants of this package, beside the record whose fields they fill.

## Transitions

A transfer has four writes. `Add` records it once, `queued` or `running` as the engine decides, stamping started from the clock and minting the id; it takes the descriptive fields and the caller and ignores the rest. `Start` moves a `queued` transfer to `running`, keeping its started. `SetBytes` records progress on a `running` transfer. `Finish` ends a transfer exactly once, stamping finished: a `running` one as `done` or `failed`, a `queued` one only as `failed` (cut off before it ran); a done ending carries the url, the link, the artifact's id and, for a push, the Drive id of a file it created and the name Drive answered. Of two calls racing to end or start the same transfer, one succeeds and the other is told the transfer is no longer in the state it needed (`ErrEnded`). Nothing moves a transfer back.

## Reads and the prune

`Get` is one of a caller's own transfers, so another user's is indistinguishable from none; `List` is one user's transfers, newest first: descending started, and among transfers started in the same second descending id. `ListAfter` is one window of that order: the user's transfers after a key, a started time and an id, at most `n` of them, from the start when the id is empty. It is how the `transfers` tool and the landing page read a page (`D09-tools`, `D07-pages`), as the suite's storage rule asks (`shape/`, Storage; appkit's D25): the database filters by user, orders by `started` then `id`, both descending, and windows with a row-value keyset condition, `WHERE user_id = ? AND (started, id) < (?, ?) ORDER BY started DESC, id DESC LIMIT ?`, asked for one more row than the page so the caller learns whether more follow without holding more than a page and one row; an index on `(user_id, started, id)` backs that order. `dummy`'s widget window is the precedent. How many rows a call holds no test can observe, so no requirement states it; the requirements state what the window answers, and the index's migration. Beside it sits the reversed window, `ListBefore`, which the landing page's backward step and its last window read (`D07-pages`): the user's transfers before a key in that order, the newer ones, nearest first, so by `started` then `id` ascending, at most `n` of them, from the end of the order when the id is empty; the key need not be any transfer's. It is a fixed statement like `ListAfter`'s, its values bound as parameters, `WHERE user_id = ? AND (started, id) > (?, ?) ORDER BY started, id LIMIT ?`, or the same without the keyset condition for the open end, and the same `(user_id, started, id)` index backs it, read the other way. `Unfinished` is every transfer still `queued` or `running`, of every user, which the start finishes as `failed` with `interrupted` (`D06-transfers`). `Prune` removes, in one write, every transfer past keeping at a moment and answers what it removed: one that is neither `queued` nor `running`, that started more than `TRANSFER_KEEP_DAYS` days of 24 hours before that moment, and that is not among its user's newest `TRANSFER_KEEP_COUNT` in the order `List` answers them, every transfer of the user counting toward that rank. The store reads neither setting; the engine hands in the values `Run` read. A pruned transfer is gone from every read; the artifact or Drive file it made is not the store's to touch. All lists are never nil.

## Errors

`ErrNotFound` and `ErrEnded` are answers about the records. Every other error satisfies `errors.Is(err, ErrUnreachable)`, and every consumer answers it with `Unreachable` (or, for a page, `D07-pages`' unavailable answer), never quoting the cause. A done context, a failing handle, a random source that fails and a write given a value no consumer sends all end there, the last changing nothing. One fixed precedence decides a call that meets several conditions: a done context, then a failing store, then an invalid argument, then a missing record, then a transfer no longer in the needed state, then an ending that does not fit, then the random source.

## Recorded decisions

- The schema is two migrations. `0001_transfers.sql`: `transfers` (`id` primary key, `direction`, `status`, `reason`, `file`, `name`, `kind`, `path`, `content_type`, `format`, `bytes` integer, `started`, `finished`, `url`, `link`, `artifact_id`, `user_id`, `user_email`, `request_id`), with an index on `user_id` and `started`. `0002_transfers_user_started_id.sql` adds the index `transfers_user_started_id` on `(user_id, started, id)`, which backs `ListAfter`'s order and keyset; it is an expand step, which a release that predates it runs on unchanged, ignoring the index, and it drops nothing, so `transfers_user_started` stays. Times are RFC 3339 UTC to the second, which compare as text; an empty `finished` is a transfer not yet ended. As in connections, no requirement states the table, since a test proves the records through the store; the one exception is the index migration's text (R-YVCF-BS1J), since an index changes no answer and no test could otherwise tell it is there; the sandbox check, which sets a row to `running` by hand to see it settled as `interrupted` (the decisions' Verification), writes these columns.
- The store mints the id and stamps started and finished from `Config.Now`, as connections' store does, rather than taking them from the caller as scripts' run core gives them: no folder is named before the record exists, so nothing needs the id first, and one clock keeps started and finished comparable. This departs from scripts' `AddRun`.
- `Prune` deletes in the same write that decides, rather than scripts' `PastKeeping` followed by `DeleteRun`: scripts splits them to remove a run's folder in between, and a transfer has no files (decision 16).
- Keeping follows scripts' rule, per user (decision 12): a transfer goes only when it is both older than the days and beyond the count, so a busy user's last fortnight is kept whatever its size and a quiet user keeps their newest hundred however old.
- No count of queued transfers is exported: the queue's order and size are the engine's, held in memory as scripts' run core holds them (`D06-transfers`); the store keeps only the status, and `Unfinished` exists for the start that settles what a dead process left.
- `ArtifactID` is a field of the record (orchestrator decision D6): appkit's `artifacts` client fills an id only from `Put`, so only a pull has one, and the landing page links to artifacts' `url` when it is empty.
- A write given a value no consumer sends (an unknown direction, status or reason, an empty user id or path, negative bytes) answers an error matching `ErrUnreachable` and changes nothing, as scripts answers an invalid record with a catalog error; there is no `ErrInvalid`, since no caller can reach it through a tool or a page.
- `File` is settable at `Finish` because a push that creates learns the Drive id only when its last chunk lands (decision 9); a `Finish` with an empty `File` keeps the one recorded.
- `Name` is settable at `Finish` too, because a push that replaces a file records the name Drive answers when the upload lands: the given `name`, which renames the file, or, with none, the name Drive kept (orchestrator P4, `D06-transfers`). A `Finish` with an empty `Name` keeps the one recorded, as every pull's does.
- `Config.Now` and `Config.Rand` are required: `New` takes them as given and selects no default, and a store built with either nil is no case to design (the user's ruling on the store-randomness issue, after connections' broker). No requirement states this precondition, because no permitted test can observe it: a test never reads the real clock or randomness, so a default could not be told from another source. What the store does with the sources it is given is stated by use (R-S8BB-13BB, R-6O61-3LDG), and the selection of the real ones lives only in `cmd/gdrive`.
- `ListBefore` mirrors `ListAfter` rather than taking a direction flag: each is one fixed statement, and the empty id means the open end on both, the start of the order for `ListAfter` and its end for `ListBefore`, since no valid id is empty. It answers nearest first, the order a keyset read from a position backwards takes, and the landing page reverses the window it draws. The engine and the tools never call it. The index `0002_transfers_user_started_id.sql` adds serves it, so it needs no migration.
- The id redraw is bounded at 8 candidates, as connections' and scripts' are; 8 collisions in a row says the random source is broken.

## Consumer tasks

`Run` opens the database with `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "gdrive.db"), Migrations: gdrive.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: p.Stderr})` and builds `st := store.New(d, store.Config{Now: p.Now, Rand: rand})`. The engine, `c` the caller: `t, err := st.Add(ctx, store.Transfer{Direction: store.DirectionPull, Status: store.StatusRunning, File: f.ID, Name: f.Name, Kind: f.Kind, Path: path, ContentType: ct, Format: format, UserID: c.UserID, UserEmail: c.Email, RequestID: c.RequestID})`, or `Status: store.StatusQueued` when every slot is taken and later `st.Start(ctx, t.ID)`; while bytes move `st.SetBytes(ctx, t.ID, n)`; at the end `st.Finish(ctx, t.ID, store.Ending{Status: store.StatusDone, Bytes: n, URL: m.URL, Link: link, ArtifactID: m.ID})`, or for a push `File: f.ID, Name: f.Name` too, or `store.Ending{Status: store.StatusFailed, Reason: store.ReasonTooLarge, Bytes: n}`; at start `st.Unfinished(ctx)` and `st.Finish(ctx, t.ID, store.Ending{Status: store.StatusFailed, Reason: store.ReasonInterrupted, Bytes: t.Bytes})` for each; once before ready and on each sweep `st.Prune(ctx, now, s.TransferKeepDays, s.TransferKeepCount)`. The `transfers` tool calls `st.ListAfter(ctx, c.UserID, started, id, n+1)`, `started` and `id` being what its `page` token carries (the zero time and the empty string for the first page) and `n` its page size, and the landing page one window per request, `st.ListAfter(ctx, c.UserID, started, id, paging.DefaultLimit+1)` for the first window (the zero time and the empty string) or an after-token, or `st.ListBefore(ctx, c.UserID, started, id, paging.DefaultLimit+1)` for a before-token, or for the last window with the zero time and the empty string (`D07-pages`); the `transfer` tool and the transfer page call `st.Get(ctx, c.UserID, id)`, `store.ErrNotFound` answering not found; every consumer answers `store.ErrUnreachable` with `store.Unreachable`. A test opens its own database with `db.Open` and `gdrive.Migrations()` in its own temporary directory, builds `store.New(d, store.Config{Now: clock, Rand: rnd})`, records another user's transfer, flips `d.SetFailing(true)`, and reopens the path to prove what persists.
