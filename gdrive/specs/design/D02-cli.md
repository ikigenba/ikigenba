# D02-cli

gdrive as a command: what `cli.Run` does with its arguments, the exit codes, `db status`, and the three constants whose text is fixed here, the usage text, the manifest and the nginx fragment, with the two files under `etc/` that copy the last two. It is connections' command with gdrive's name, its own manifest, scripts' `[env]` form for the five transfer settings, and the bus-only fragment every app without a private route has.

An empty `Args` means serve (`D03-serve`). `--version` writes `Process.Version`, the display string `main` read (`D01-layout-and-run-seam`), and a newline; `manifest` writes `Manifest`; `--help` writes `Usage`; `db status` writes what appkit's `db.Status` writes for `state/gdrive.db` and `gdrive.Migrations()`. Any other `Args` is a usage error, diagnosed as connections diagnoses one: `gdrive: unknown option '<arg>'` or `gdrive: unknown command '<arg>'`, an empty line, and the hint to run `gdrive --help`. A command touches nothing but what it names: `db status` does not create the database, and no command reads the environment, the services file, a sibling or Drive.

## The manifest

The manifest is a program-parsed file: opsctl, the sandbox and home read it, so its text is contract and is stated here byte for byte, and `etc/manifest.toml` holds the same bytes. It names the app `gdrive`; its description, the same text as `pages.Description` (`D07-pages`); that it is not the default app; that it is an MCP service, so the gateway offers its tools; that it does not serve guests (`guests = false`), so the host's nginx admits only a request with a credential; no secrets, since Google's token comes from connections over its socket; an `[env]` table holding the five transfer settings' defaults as strings, in the order `settings.Read` reads them (`D01-layout-and-run-seam`), so the values the host writes into gdrive's environment are the ones gdrive applies when a setting is unset; the `[database]` table that has the host keep and replicate `state/gdrive.db`; a `[resources]` table whose only line is `memory_max = "128M"`, enough because no byte of a file is ever held; and, last, a `[home]` table whose only line is `group = "core"`. `DRAIN_SECONDS` is not in `[env]`: it is the space's, as for every app.

## The nginx fragment

The fragment, `NginxConf`, answers the event bus's two paths, `/events` and `/declarations`, 404 at the public name, as every app's fragment does: the events app reaches them over the socket only. gdrive has no route of its own that must stay on the host, so the fragment is scripts', verbatim; connections' `/token/` line has no counterpart. It changes nothing else: gdrive takes no request body larger than an MCP call, since bytes move between Drive and artifacts and never through nginx.

## Exit codes

`ExitSuccess` (0), `ExitServerFailed` (1) and `ExitUsage` (2), as every app: a usage error, a setting refused or a socket missing is 2; a database that will not open, a start refused or a drain that ran out is 1.

## Recorded decisions

- `--help` and `Usage` are kept, as in every sibling, although the brief names only `--version`, `manifest` and `db status`: the command-line conventions require usage text on standard output and a hint to it on a usage error.
- The usage text, the manifest and the fragment are contract, not copy: each is a command's standard output or a file a program parses, so each is spelled here. The usage text's prose is therefore fixed by this design, as connections' and scripts' are.
- The description is the decisions document's text (decision 1), spelled in `Manifest` and declared with the same value as `pages.Description` (`D07-pages`); a test compares the two.
- The `[env]` values are compared with `settings.Defaults()` (`D01-layout-and-run-seam`) as scripts compares its own, so a default cannot drift between the manifest and the code.
- `[resources]` holds only `memory_max`, as artifacts' and connections' do; gdrive delegates no control group and runs no child process, so scripts' `slice`, `go_memory_limit` and `delegate` have no counterpart.
- `Manifest` and `NginxConf` are copied into `etc/` byte for byte, which a test proves through the root package's `Etc`; `D01-layout-and-run-seam` fixes the two names that file system holds.

## Consumer tasks

An operator's host reads `gdrive manifest` and `etc/manifest.toml` to learn the app, its settings' defaults and its database, and drops `etc/nginx.conf` into gdrive's server block. A developer runs `gdrive --help`, `gdrive --version` and `gdrive db status` from the install directory. A test builds a `cli.Process` with only `Args`, `Stdout`, `Stderr` and `Dir` (an empty temporary directory) set, calls `cli.Run`, and compares the returned value with `cli.ExitSuccess` or `cli.ExitUsage`, `Stdout` with `p.Version + "\n"`, `cli.Manifest` or `cli.Usage`, and `Stderr` with the exact diagnostic; to prove nothing else is touched it sets `LookupEnv`, `Unsetenv`, `Inherit`, `Now`, `Sleep`, `After`, `Banner` and `MCP` to functions that record a call, `Rand` to a reader, `Sink` and `EventSink` to captures, and `HTTP` to a client whose transport records any request, and asserts none was used and `Dir` is still empty. A test of `db status` makes a database under its `Dir` with `db.Open` and `gdrive.Migrations()`, closes it, runs `cli.Run` with `Args` `["db", "status"]`, and compares `Stdout` with what its own `db.Status` call writes for the same path and migrations. A test compares `cli.Manifest` with `pages.Description` and with the fields of `settings.Defaults()`, and reads `manifest.toml` and `nginx.conf` from `gdrive.Etc()` with `fs.ReadFile` to compare them with `cli.Manifest` and `cli.NginxConf`.
