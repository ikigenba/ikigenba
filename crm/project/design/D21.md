# Decision 21 — Testing-language conformance: the suite's four layers, declared in `AGENTS.md`

**Decision.** crm adopts the suite's **testing-language contract** —
`root project/design/D23.md` — which owns the four layer names, the rule for what
each layer may touch, the `//go:build live` mechanism, the ban on skipping outside
live-tagged files, and the requirement that every tree declare its testing facts in
its `AGENTS.md`. This Decision is the **citation, and citation is adoption**: crm
owns none of that contract's content and restates none of it normatively. What is
local — and all this Decision adds — is **crm's own testing facts** and **where the
proof of the declaration lives**.

The contract carries two `[proof: per-service]` ids, which crm therefore proves in
its own tree:

- `R-O1AD-MRKW` — the doc-truth test over the committed `AGENTS.md`.
- `R-O2IA-0JBL` — the source scan banning `t.Skip` outside live-tagged files.

**crm's testing facts** (the content its `AGENTS.md` Tests section must declare,
and what the doc-truth test asserts):

- **Default-gate test command:** `cd crm && go test ./...`, inside the green bar
  the design Conventions already fix (`go build ./...`, `go vet ./...`,
  `gofmt -l .` silent, `go test ./...`).
- **Layers present: hermetic and composed — no live layer and no manual layer.**
  - **hermetic** is the bulk of the suite: the `internal/crm` domain tests over a
    real migrated temp `modernc.org/sqlite`; the `internal/db` load and
    outbox-DDL guards; the `internal/mcp` tool-table tests driven through the real
    `appkit/mcp` JSON-RPC `ServeHTTP` seam; the `cmd/crm` web tests loading the
    repo-real `share/www` tree through `appkit/web` and driving it with
    `net/http/httptest`; the event-plane chain that drives the real outbox and
    `FeedHandler` over `httptest` — all in-process, loopback only; and the
    **shipped-file guards** — the `etc/nginx.conf` fragment content assertions
    (D8, D20), the committed-`manifest.env` scans, and the `loopback_guard`
    source scan — which read committed files from disk and touch nothing else.
  - **composed** is the boot smoke in `cmd/crm/main_test.go`: it builds crm's own
    binary, assembles an `/opt/crm/`-shaped tree under `t.TempDir()`, runs it on a
    free loopback port, and asserts the served `/health`. It is offline by
    construction.
  - **no live layer.** crm carries no `//go:build live` file and needs none: it
    depends on no external service. Its only trust-boundary collaborator is nginx,
    which the gate never runs and whose fragment is proven by content assertion
    instead.
  - **no manual layer.** crm commits no runbook of its own; the suite-level
    "the whole stack composes" check belongs to the umbrella, not here.
- **Environmental preconditions beyond the Go toolchain: none.** The composed boot
  smoke shells out only to `go build` and the binary it just built; nothing needs
  `git`, `python3`, a browser, a credential, or a running suite.
- **GOWORK mode: workspace.** The gate resolves `appkit`, `eventplane`, and
  `registry` through the repo-root `go.work` and the committed replace-siblings.
  The production build's `GOWORK=off` is `bin/ship crm`'s, not the test gate's, and
  crm commits no separate standalone build check.

**Where the proof lives.** Both adopted ids are proven in **`cmd/crm/docs_test.go`**
— a new file at the composition root, the package that already owns crm's
read-from-disk assertions over shipped artifacts (`etc/nginx.conf`,
`etc/manifest.env`, `share/www`). No new package is introduced. The doc-truth test
reads the committed `crm/AGENTS.md` from disk and asserts its Tests section declares
the four facts above; the source scan walks the tree's `*_test.go` files, skips any
file carrying the `live` build constraint, and asserts zero occurrences of the skip
verbs — assembling its needle from parts so the scan never matches its own source.

**Rejected.**

- **Restate the contract's layer definitions locally so this design reads
  self-contained.** A local restatement is drift by construction: it goes stale the
  moment `root project/design/D23.md` is rewritten, and the suite's rule is cite,
  never restate. The citation is the whole mechanism. Rejected.
- **Keep the conventional `unit` / `integration` / `end-to-end` names and map them
  in prose.** Rejected by the contract itself, and for crm specifically: `AGENTS.md`
  today calls the whole suite "Unit", which mislabels a boot smoke that compiles and
  runs a real binary. The layer names say what a test may *touch*, which is the
  property actually being policed.
- **Re-mint local ids for the two behaviors instead of citing
  `R-O1AD-MRKW` / `R-O2IA-0JBL`.** Both are `[proof: per-service]`: the ids are the
  suite's handles for one behavior each, proven once per adopting tree. Minting
  parallel local ids would give one behavior two handles and break the
  id-to-behavior invariant. Rejected.
- **Put the two tests in `internal/db` or a new `internal/docs` package.** Both
  assertions are about the tree as a shipped whole, not about a domain package, and
  `cmd/crm` is already where crm asserts over committed artifacts. A new package
  for two tests earns nothing. Rejected.
- **Fold this citation into the design spine's Testing strategy section instead of
  a Decision.** The spine holds cross-cutting facts and carries no ids; two adopted
  `[proof: per-service]` ids need a Decision to attach to, or the coverage check
  cannot see them. Rejected — the spine cites D21 instead.

**Verification.**

Both ids below are **adopted**, not minted here: each belongs to the umbrella
Decision cited beside it, which states the behavior. These lines say only what
substrate proves it inside `crm/`.

- `R-O1AD-MRKW` — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/crm/docs_test.go` that reads the committed `crm/AGENTS.md` from
  disk and asserts its Tests section declares the default-gate test command
  (`go test ./...`), the layers present (hermetic and composed; no live, no
  manual), that there are no environmental preconditions beyond the Go toolchain,
  and the GOWORK mode (workspace).
- `R-O2IA-0JBL` — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/crm/docs_test.go` that walks the `crm/` tree's `*_test.go`
  files from disk, excludes any file carrying the `live` build constraint, and
  fails on any occurrence of `t.Skip`, `t.Skipf`, or `t.SkipNow`, with the needle
  assembled from parts so the scan cannot match itself.
