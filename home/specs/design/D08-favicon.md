# D08-favicon

How home finds a bookmark's icon: the package `internal/favicon`, its limits `Budget`, `MaxPageBytes`, `MaxIconBytes` and `MaxRedirects`, its `Config`, and the `Fetcher` whose `Fetch` takes a page URL and gives back the bytes and media type of the site's icon, or nothing. This document owns what a fetch sends, which redirects it follows, how it reads the page, the order it tries candidates in, what it accepts, and the one deadline over all of it. `D01-layout-and-run-seam` owns the run seam's `HTTP`, the client a fetcher is built over, and builds the `User-Agent` value from `pages.ServiceName` and `pages.Description`, so `internal/favicon` imports nothing of home's; `D07-bookmarks-page` owns when a fetch runs (inside `POST /bookmarks`, after validation and before the insert) and what becomes of its result; `D06-bookmarks` owns the stored icon; `D05-on-a-space` owns the guarantee that nothing sent through `HTTP` carries a secret or an email.

## The fetch

A fetch is one call of `Fetch` with the URL a person typed. It never fails: it gives back an icon or no icon, and a bookmark is added either way. It asks for the page, reads at most `MaxPageBytes` of it, and when the answer is HTML it collects the page's icon links. It then tries each candidate in turn, the page's `icon` links first, then its `apple-touch-icon` and `apple-touch-icon-precomposed` links, then `/favicon.ico` at the page's own scheme and host, and keeps the first that answers 200 with an image media type and a non-empty body of at most `MaxIconBytes`, reading no more than one byte past that limit and closing every body it was given. The media type is the one `mime.ParseMediaType` reads from the answer's `Content-Type`, lowercased and without parameters, so `image/svg+xml; charset=utf-8` is kept as `image/svg+xml`.

The page is read whatever its status: a 404 page that names its icon still names it. A page that is not HTML, or that could not be fetched, has no links, and only `/favicon.ico` is tried. Links are found by an HTML tokenizer, not by a scan for text: attribute names in any case, values quoted any way, character references decoded, and a `<link>` written inside a comment or a script's text is no link. A link's `rel` is a list of tokens split on ASCII whitespace and compared case-insensitively, so `shortcut icon` and `ICON` are both icon links. Each `href`, trimmed of surrounding ASCII whitespace, is resolved against the final page URL, the URL that answered after redirects; a `<base>` element plays no part. An empty `href`, one that does not parse, and one that resolves to a scheme other than `http` or `https` (a `data:` URL, say) is skipped. Every candidate is tried in order, a URL listed twice tried twice, until one is accepted.

## Redirects

Each URL fetched, the page or a candidate, starts a chain: its request and the requests the redirects it follows lead to. A redirect is an answer 301, 302, 303, 307 or 308 with a `Location`. A chain follows at most `MaxRedirects` of them and only to `http` or `https`; the redirect it does not follow is the answer that ends the chain, so a page that redirects too often, or to `ftp:`, is read as that redirect answer. A chain that ends in an error, a refused connection or a `Location` that does not parse, say, has no final answer, and the fetch moves on to the next candidate; for the page, the final page URL is then the URL as given.

## What is sent

Every request goes through the client the `Config` names, `http.DefaultClient` when it names none, as scrapes declares its own. Each is a `GET` with no body and `User-Agent` exactly the configured value. None carries `Authorization` or `Cookie`, whatever cookie jar the client holds, and no request URL carries userinfo: Go's client turns userinfo into `Authorization: Basic`, so a bookmark URL `http://u:p@intranet/` is fetched as `http://intranet/`, and a `Location` or an `href` that carries userinfo is treated the same way. The URL is stored and shown as given; only what is sent is stripped.

## The budget

One deadline bounds every request of one fetch, its bodies' reads included: `Budget` after the call began, or the caller's own earlier deadline. It is a context deadline, not a client timeout, so it is the same instant for the page, every redirect and every candidate, and a slow page leaves less time for the icon. A request that ends because the budget is spent, or because the caller went away, ends the fetch with no icon and no further request.

## Proving the fetch

No test reaches the network or waits out the budget. A test hands `Config.HTTP` a client whose `Transport` is its own: it records every request it is given, with its method, URL, headers, body and its context's deadline, and answers from a table the test wrote, pages, redirects, icons, errors and all. The deadline is proved by reading `req.Context().Deadline()` in that transport and comparing it with times the test read just before and just after the call; the spent budget is proved by a transport that answers with `context.DeadlineExceeded`. The default client is not proved by a test, since using it reaches the network, as scrapes records of its own.

## Recorded decisions

- **No network reach is refused beyond the scheme** (decisions document, seam 3): a workgroup bookmarks its own intranet, and the host's loopback is where the suite's own apps live, so a member who adds `http://127.0.0.1:…` gets what that address serves and nothing more than the member could already reach from the host. The fetch keeps nothing of the page but the icon. Only a scheme other than `http` or `https` is refused, for the page, for a redirect and for a candidate.
- **No credential and no userinfo is sent** (decisions document, seam 3; root ruling 7.5): every request goes without `Authorization` and `Cookie`, and with userinfo removed from its URL, so Go's client derives no `Authorization` from it. The client's cookie jar is not used, so a caller's jar cannot add a cookie either. The URL is stored and shown as given.
- **The tokenizer is `golang.org/x/net/html`** (decisions document, seam 3, an accepted dependency, recorded in `go.mod` by the build): its `NewTokenizer`, `Next`, `TagName` and `TagAttr` give lower-cased tag and attribute names and unescaped values, and read a comment and a script's text as no tag (checked with `go doc` and a probe in a throwaway module). A hand-written scan for `<link>` was rejected: real pages put attributes in any order, quote them any way and nest them in comments and scripts.
- **One deadline, as a context** (orchestrator log D3): scrapes' client shape, nil meaning `http.DefaultClient`, with no per-phase timeouts of the client's own; the 10-second budget is a context deadline over every request and body of one fetch.
- **Links are collected whatever the page's status** (root ruling 7.6), when its media type is `text/html` or `application/xhtml+xml`.
- **The budget is proved without waiting** (root ruling 8.6): through the deadline the transport reads and a transport that answers `context.DeadlineExceeded`, never a real wait.
- **The `User-Agent` value is the caller's** (scrapes' `D05-scrapers` precedent): `cli` builds `pages.ServiceName + " (" + pages.Description + ")"` and hands it in, so `internal/favicon` imports nothing of home's.
- **Five redirects, not Go's ten** (decisions document, seam 3): a chain stops at `MaxRedirects`, and the redirect it does not follow ends the chain as its answer.
- Decisions of this design, where the document is silent: a chain that ends in an error that is not the budget spent or the caller gone, a refused connection or a `Location` that does not parse included, ends with no answer and the fetch moves on to the next candidate, as Go's client reports a `Location` it cannot parse; an empty 200 is not an icon, so it does not end the search; a page read that fails partway yields the links read before the failure; an attribute given twice counts once, the first; the final page URL of a page that answered nothing is the URL as given; `<base>` is not honoured, the document naming the final URL as the base; an empty `href` is skipped rather than resolved to the page; candidates are not de-duplicated; a `Content-Type` that `mime.ParseMediaType` cannot read is no media type, so neither HTML nor an image.

## Consumer tasks

`cli.Run` builds `fav := favicon.New(favicon.Config{HTTP: p.HTTP, UserAgent: pages.ServiceName + " (" + pages.Description + ")"})` and hands it to the pages handler as `Favicon` (`D04-pages`, `D03-serve`). The handler's `POST /bookmarks`, once validation passes, calls `data, typ := cfg.Favicon.Fetch(r.Context(), url)` with the trimmed URL and stores `bookmarks.Icon{Type: typ, Data: data}` in the draft (`D07-bookmarks-page`, `D06-bookmarks`); `len(data) == 0` is no icon and the redirect carries `?icon=none`.

A test of `internal/favicon` builds `favicon.New(favicon.Config{HTTP: &http.Client{Transport: rt}, UserAgent: "ua"})`, `rt` a transport of its own that records each request and answers from a table keyed by URL. It serves an HTML page whose links mix `rel` case and whitespace, put `apple-touch-icon` before `icon` in the document, carry relative, protocol-relative, `data:`, empty and userinfo `href`s, and hide a `<link>` in a comment and in a script; a page that redirects to another host; a page served 404 as HTML; a non-HTML page; a page larger than `favicon.MaxPageBytes` with a link before and after the limit; icons of exactly `favicon.MaxIconBytes` and one byte more, an icon of type `text/plain`, a 500, and an error. It calls `Fetch` and compares the recorded requests, in order, and the data and media type returned. For the budget it reads `time.Now()` before and after the call and checks every recorded deadline, with a background context and with one whose deadline is earlier, and it answers one request with `context.DeadlineExceeded` and checks that none follows. It runs several `Fetch` calls on one fetcher at once under the race detector.
