# D02-cli

home as a command: what `cli.Run` does with the arguments `D01-layout-and-run-seam` hands it through `Process`, the exit codes it returns, and the two constants whose text is fixed here — the usage text and the manifest — with the file under `etc/` that copies the manifest. `D01-layout-and-run-seam` declares the names this design behaves through: `cli.Process` with its `Version`, the display string `main` read, `cli.Run`, and the root package's `Etc`; `D04-pages` declares `pages.Description`. When `Args` is empty home serves, and everything from there is `D03-serve`'s.

The arguments decide everything. An empty `Args` means serve. The three recognised single arguments each write one product to `Stdout` and return `ExitSuccess` without touching anything else: `--version` writes `Process.Version`, the display string `main` read (`D01-layout-and-run-seam`), and a newline, which is one empty line when the host set no identity; `manifest` writes `Manifest`; and `--help` writes `Usage`. Any other `Args` is a usage error. The argument home complains about is the first one it does not take: the first element when that is not a recognised word, otherwise the second, which is surplus whatever it says. An argument that starts with `-` is an unknown option, any other an unknown command. The diagnostic follows the repository's command-line conventions: its first line begins `home: `, and after exactly one empty line comes the hint to run `home --help`, unprefixed because home is speaking for itself. The usage text is never written to `Stderr`.

## Exit codes

The help text names the exit codes: 0 for success, 1 for a failure, 2 for a usage error. `D03-serve` leans on that split: a start the caller got wrong (no socket, several sockets, a `DRAIN_SECONDS` that is not a positive whole number) exits 2, while trouble on the host once home is past its checks (a socket it cannot take, a readiness it cannot report, a drain that runs out) exits 1. `Run` returns no other value.

## Commands touch nothing

Arguments are checked before anything else. A command needs no socket, so `home --version` succeeds with nothing passed in and `home bogus` fails whatever the environment holds. Unless `Args` is empty, `Run` touches none of the environment, the inherited descriptor, systemd's notification socket, the banner source or the sink, and records no event: the trail is what home records while it serves. Every failure leaves `Stdout` empty, and every diagnostic is one write to `Stderr`, so a two-line diagnostic lands whole when journald interleaves another writer.

## The manifest

The manifest is a fact about the binary, so the binary carries it as the constant `Manifest` and prints it for `manifest`. Its text is fixed here: home's name; its description, which is `pages.Description`, the line the about screen shows and the host publishes in its services file; that it is the host's default app (`default = true`), so it answers at the space host itself as well as at `home.<space>`; that it is not one of the suite's MCP services; that it serves no guests (`guests = false`), so on a host with an authenticator nginx admits no visitor without a credential; no secrets; no `[env]` table, since home has no settings of its own and `DRAIN_SECONDS` is the space's; no `[database]` table, since home keeps nothing; the `[resources]` table opsctl writes into the service unit, whose only line is `memory_max = "128M"`; and, last, the `[home]` table, whose only line is `group = "core"`, marking home a core service. It declares no port, since home serves on the socket the host passes it. The description is copy: the manifest requirement fixes only that it is one line of characters a TOML basic string holds unescaped, and a second requirement ties it to `pages.Description`.

## The file under etc/

The committed `etc/manifest.toml` holds exactly the text of `Manifest`, and `devctl build` refuses an app where they differ. The build run writes it from the constant and keeps them in step. The file is proved by use: the root package embeds `etc/` and exports it as `Etc` (`D01-layout-and-run-seam`), so a test compares the embedded `manifest.toml` with the constant without ever opening the checkout, and a build whose `etc/` lacks the file, or holds a stale copy, fails to compile or fails that test. That test lives in the external test package `home_test` beside the root package, since it imports both the root package and `internal/cli`, which reaches the root package through `internal/pages`, so a test inside package `home` would form an import cycle.

## Recorded decisions

- The usage text's words are fixed here, as every app's are: `--help` output is a product a caller reads on stdout, and the precedent fixes it byte for byte.
- `[resources]` caps memory at 128M, as the precedent does; home's footprint is smaller, and lowering the cap is a later decision with nothing depending on it.

## Consumer tasks

`main` hands `cli.Run` the process's arguments after the program name, with the other `Process` fields `D01-layout-and-run-seam` names, and exits with what it returns. A developer types `home --version`, `home manifest` or `home --help` and reads stdout; `devctl build` runs `home manifest` and compares its output with the release's `etc/manifest.toml`; the help text tells a caller what `ExitSuccess`, `ExitServerFailed` and `ExitUsage` mean.

A test builds a `cli.Process` with only `Args`, `Stdout`, `Stderr` (two `bytes.Buffer`s) and, for `--version`, `Version` set, calls `cli.Run(ctx, p)`, and compares the returned value with `cli.ExitSuccess` or `cli.ExitUsage`, `Stdout` with `p.Version + "\n"` for a `Version` of its own choosing, the empty string included, `cli.Manifest` or `cli.Usage`, and `Stderr` with the exact diagnostic. To prove nothing else is touched it sets `LookupEnv`, `Unsetenv`, `Inherit` and `Banner` to functions that record a call and `Sink` to a sink that records any use, and asserts none was used. A test compares `cli.Manifest` with `pages.Description`. A test in package `home_test` reads `manifest.toml` from `home.Etc()` with `fs.ReadFile` and compares it with `cli.Manifest`.

With no command, serve.\n\nCommands:\n  manifest    print the app manifest\n\nOptions:\n  --help      print this help\n  --version   print the version\n\nExit codes:\n  0  success\n  1  failure\n  2  usage error\n"`.
- R-JTDB-TME1: The `internal/cli` package MUST export `Manifest` as a string constant whose value is exactly the Go string literal `"app = \"home\"\ndescription = \""`, then the **manifest description**, one or more characters none of which is `"`, `\` or a control character, then the Go string literal `"\"\ndefault = true\nmcp = false\nguests = false\nsecrets = []\n\n[resources]\nmemory_max = \"128M\"\n\n[home]\ngroup = \"core\"\n"`; the manifest description is copy, and no requirement fixes its words.
- R-5I9C-167I: `Manifest` MUST contain the line `description = "` followed by exactly the text of `pages.Description` followed by `"`, so that the description the manifest publishes and the one the about screen shows are the same string.
- R-4SNF-ZZMX: The `internal/cli` package MUST export `ExitSuccess`, `ExitServerFailed` and `ExitUsage` as untyped integer constants, so that each is usable as an operand of a constant expression and assignable to an `int`, with the values 0, 1 and 2 respectively.
- R-6LA4-9TXQ: Every call of `Run` MUST return one of `ExitSuccess`, `ExitServerFailed` or `ExitUsage` and no other value.
- R-4Q7N-8G5J: The contents of the file `manifest.toml` in the file system the root package's `Etc` returns MUST be exactly the bytes of `cli.Manifest`.
- R-7DBT-2JZP: When `Args` is exactly `["--version"]`, `Run` MUST write `p.Version` followed by a single `"\n"` to `Stdout` and nothing else, write nothing to `Stderr`, and return `ExitSuccess`, so that an empty `p.Version` writes exactly `"\n"`.
- R-5H1F-NEGT: When `Args` is exactly `["manifest"]`, `Run` MUST write exactly `Manifest` to `Stdout` and nothing else, write nothing to `Stderr`, and return `ExitSuccess`.
- R-4YQX-WUCE: When `Args` is exactly `["--help"]`, `Run` MUST write exactly `Usage` to `Stdout` and nothing else, write nothing to `Stderr`, and return `ExitSuccess`.
- R-7C3W-OS90: `Run` MUST treat `Args` as a usage error unless `Args` is empty or is exactly one of `["--version"]`, `["manifest"]` or `["--help"]`.
- R-5N4X-K96A: On a usage error from `Args`, the offending argument MUST be `Args[0]` when `Args[0]` is none of `--version`, `manifest` and `--help`, and `Args[1]` otherwise; so that `["bogus"]` names `bogus` and `["manifest", "x"]` names `x`.
- R-4E0N-EQQL: On a usage error from `Args`, `Run` MUST write exactly `"home: unknown option '" + arg + "'\n\nsee 'home --help' for usage\n"` to `Stderr` when the offending argument `arg` begins with `-`, and exactly `"home: unknown command '" + arg + "'\n\nsee 'home --help' for usage\n"` otherwise, in one call to `Stderr.Write`, MUST write nothing to `Stdout`, and MUST return `ExitUsage`, so that `["bogus"]` writes `home: unknown command 'bogus'` and `["--bogus"]` writes `home: unknown option '--bogus'`.
- R-46P9-44AF: When `Args` is not empty, `Run` MUST return without calling `LookupEnv`, `Unsetenv`, `Inherit` or `Banner`, without calling the `Deliver` of `Sink`, without taking file descriptor 3, and without sending anything to a notification socket, so that the outcome of a command or a usage error is the same whatever the environment holds, and a `Process` whose `Args`, `Stdout` and `Stderr` alone are set is enough for every command.
- R-4TVC-DRDM: When `Args` is not empty and `Run` returns a value other than `ExitSuccess`, `Run` MUST have written nothing to `Stdout`, and every diagnostic it wrote MUST have been delivered as a single call to `Stderr.Write` whose first line begins `home: `.
