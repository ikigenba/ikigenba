# D06-bookmarks

The space's bookmarks themselves: what one is, what makes one acceptable, and where the set of them is kept. This is the whole of `internal/bookmarks`: the one table of home's SQLite database, `state/home.db`, the store over it, the limits a name and a URL obey, the five sentences a refused field is answered with and the one line answered when the database cannot be reached, the errors every consumer tells apart, and the schema the migration `0001_bookmarks.sql` produces. No request, response, header, markup or event reaches this package. `D01-layout-and-run-seam` declares `cli.Process`, whose `Dir`, `Now` and `Rand` reach the store through `cli.Run`, resolves the path the database lives at, and declares and embeds the root package's `Migrations`; `D03-serve` opens the database with appkit's `db.Open` at start, builds the store over that handle and closes the handle at stop; `D04-pages` draws the landing page's bookmark tiles from `List`; `D07-bookmarks-page` owns the bookmarks page, the form, the icon and delete routes and the bookmark events; `D08-favicon` fetches the icon a `Draft` carries. Opening, migrating, transactions and the failure seam are appkit's `db`, which this document restates none of.

## One table, one writer

home is the database's only writer and the table is the only record of the space's bookmarks: a start that finds no database begins an empty one, and a database home has just created holds no bookmarks. The store does not open anything: `bookmarks.New` builds a store over a handle `db.Open` returned, with the clock it stamps created times from and the random source it draws ids from, and it neither owns nor closes the handle. What is contract is what a reader and a restart see: a store over a later handle on the same file holds what the earlier one held, field for field, its icons included. A test proves that by closing and reopening, and proves the schema by reading the catalogue inside a `DB.Read`.

The migration creates one table, `bookmarks`: `id`, the text primary key; `name`, text, not null, unique under SQLite's `NOCASE` collation, a constraint the database itself enforces, so a duplicate is refused whatever code inserts it, which a test proves by running a raw `INSERT INTO bookmarks` inside a `DB.Write` with a name that differs from a held one only in ASCII case and seeing the write fail and the table unchanged; `url`, text, not null; `icon`, a blob, null when no icon was found; `icon_type`, text, the icon's media type, null with it; `created_by`, text, not null, the caller's user id; and `created_at`, text, not null, the created time as RFC 3339 in UTC to the second. The database outlives a release, so the row's form is contract too: a later release reads what this one wrote, and a change to the table is a new migration under the expand-then-contract rule.

## A bookmark

A bookmark is an id, a name, a URL, who added it, whether it has an icon, and when it was added. Its **id** is `bmk_` and 16 lowercase hexadecimal digits, the 8 bytes one read of the store's random source gives, drawn again when they give the id of a bookmark the store holds; an id is opaque and never changes. Its **name** is what a person sees on the tile: trimmed of surrounding white space, 1 to 40 characters counted in runes, and unique across the space with ASCII letters compared case-insensitively, which is what `COLLATE NOCASE` decides, so `Docs` and `docs` cannot both be held while `Émile` and `émile` can. Its **URL** is an absolute `http` or `https` URL, trimmed, at most 2048 bytes, kept exactly as given; two bookmarks may share one. Its **icon** is the bytes and media type the favicon fetch found, or none; the `Bookmark` type carries only whether there is one, and `Icon` hands out the bytes, so a list never carries every icon. **Created** is the time of the create, in UTC to the second; **created by** is the caller's user id, never an email.

## Judging a submission

The form's two strings arrive raw, as a browser or `curl` sent them, and a refused form redraws them untouched, so `Submission` holds them raw and `Validate` judges them, trimming each itself. Each field gets at most one message, and the two are judged independently, so a submission wrong in both is told both at once. For the name: blank is `NameRequiredMessage`, then over `MaxNameRunes` runes is `NameTooLongMessage`. For the URL: over `MaxURLBytes` bytes is `URLTooLongMessage`, then anything that is not an absolute `http` or `https` URL with a host is `URLInvalidMessage`, a blank URL included. `Validate` reads no database, so it never reports a taken name: whether a name is held is decided by `Create`, in the same step as the insert, so two concurrent adds of one name cannot both win. The sentences themselves are copy constants beside the rules that raise them, so the page cannot word them differently; `NameTakenMessage` is declared with them for the page to place after `ErrNameTaken`.

## Reads and writes

`List` is every bookmark, in name order with ASCII letters folded to lower case, which is the order `COLLATE NOCASE` gives (the id breaks a tie the unique name never allows); it is read and shown whole. `Create` validates the trimmed values again, answering `ErrInvalid` to anything `Validate` refuses, then decides the name and inserts as one step, answering `ErrNameTaken` to a held name; it reads the random source only for a bookmark it adds. `Icon` hands out a bookmark's stored bytes and media type, or `ErrNotFound` when the bookmark is unknown or has none. `Delete` removes a bookmark and says whether it removed one; an unknown id is not an error, since removing is idempotent and the page answers both alike. A deleted bookmark's name is free at once.

## Errors

`ErrNotFound`, `ErrNameTaken` and `ErrInvalid` are answers about the bookmarks. Any other non-nil error a method returns means the database could not be reached, and every consumer answers it with `Unreachable`, never quoting the error. A test provokes it with the handle's `SetFailing(true)`, under which every method errors and changes nothing; once the switch is off the store answers as before. An invalid draft is refused `ErrInvalid` before the database is touched, whether or not it can be reached.

## Recorded decisions

- Departure: **the bookmarks are listed and read whole**, not paged or windowed (shape's Listing pages a list a person can add to, and its Storage windows a big list in the database): a space's bookmarks are a handful of links a workgroup keeps on its front door, configuration-sized, and the landing page and the bookmarks page show every one; `List` has no position or limit (decisions document, seam 1, which asks for this departure to be recorded).
- Name uniqueness and order are SQLite's `NOCASE`: ASCII letters fold, every other byte compares as it is (decisions document, seam 1). Folding other letters would need a collation SQLite does not ship.
- `Validate`'s precedence is the root's ruling (contract skeleton, section 5 item 9, adopted in section 7): a blank name before a long one, a long URL before an invalid one, a blank URL invalid; a taken name only from `Create`.
- `Create` refuses an invalid draft with `ErrInvalid` before it touches the database, so a failing store still answers `ErrInvalid` to one: the page validates first and never sends one, and the order makes the answer independent of the database (a decision of this design).
- There is no `ErrUnreachable` sentinel: every error other than the three is the unreachable answer (contract skeleton, section 2). A failing random source is one such error, as cron's store answers it, rather than dummy's fallback to `crypto/rand`; with the production source it does not happen.
- `Delete` answers a `bool`, not `ErrNotFound`: the page redirects alike for a known and an unknown id, and records `bookmark.deleted` only when one was removed (contract skeleton, section 2, which declares `Delete` as `(bool, error)`; events in `D07-bookmarks-page`).
- An `Icon` with empty `Data` is no icon, whatever its `Type`; a non-empty `Data` is stored with its `Type` exactly as given, so the store judges no media type (contract skeleton, section 2: `Icon` with empty `Data` is no icon, `HasIcon` is `len(d.Icon.Data) > 0`; the stored-as-given `Type` is a decision of this design; `D08-favicon` decides what is an icon).
- A nil `Now` or `Rand` in `Config` means `time.Now` or `crypto/rand.Reader`, which the binary wires through `cli.Run`; no requirement states it, since no permitted test reads the real clock or randomness (cron's store records the same).
- The row's on-disk form is stated, not only its round trip, because the database outlives a release and a later migration rewrites what this one wrote (a decision of this design; the column forms are decisions document seam 1 and contract skeleton, section 2).
- The field sentences arrive from Go as strings, as dummy's form passes them (orchestrator log D7).

## Consumer tasks

`cli.Run` (`D01-layout-and-run-seam`, `D03-serve`) opens the database with `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "home.db"), Migrations: home.Migrations(), Now: now, Service: pages.ServiceName, Stderr: stderr})` and builds `st := bookmarks.New(d, bookmarks.Config{Now: now, Rand: rand})`, handing it to `pages.Config.Store`. The landing page (`D04-pages`) reads `k, err := st.List(ctx)` and copies each `Bookmark`'s `ID`, `Name`, `URL` and `HasIcon` into a tile. The bookmarks page (`D07-bookmarks-page`) reads the same list for its table; for a `POST /bookmarks` it builds `sub := bookmarks.Submission{Name: name, URL: url}` from the form, redraws with `e := bookmarks.Validate(sub)` when `e.Any()`, otherwise fetches `data, typ := fetcher.Fetch(ctx, strings.TrimSpace(sub.URL))` (`D08-favicon`) and calls `b, err := st.Create(ctx, bookmarks.Draft{Name: sub.Name, URL: sub.URL, CreatedBy: userID, Icon: bookmarks.Icon{Type: typ, Data: data}})`, redrawing with `bookmarks.FieldErrors{Name: bookmarks.NameTakenMessage}` when `errors.Is(err, bookmarks.ErrNameTaken)`; the icon route answers `ic, err := st.Icon(ctx, id)`, `bookmarks.ErrNotFound` being the not-found page; the delete route calls `removed, err := st.Delete(ctx, id)`. Every route answers any other non-nil error with `bookmarks.Unreachable`.

A test opens a handle with `db.Open(ctx, db.Config{Path: filepath.Join(t.TempDir(), "state", "home.db"), Migrations: home.Migrations(), Now: clock})`, builds `bookmarks.New(d, bookmarks.Config{Now: clock, Rand: bytes.NewReader(known)})`, creates with `Create`, reads back with `List` and `Icon`, deletes with `Delete`, and closes the handle and opens another on the same path to see the same bookmarks. It reads `PRAGMA table_info(bookmarks)`, `sqlite_master` and a row of `bookmarks` inside `d.Read`. It inserts rows directly with an `INSERT INTO bookmarks` statement inside `d.Write`, bypassing the store, to see the database itself refuse a second row whose name matches a held one with ASCII letters folded, such as `DOCS` after `Docs`, leaving the table as it was, and accept one that differs, such as `émile` after `Émile`. It calls `d.SetFailing(true)` before a call to see an unreachable store and `d.SetFailing(false)` to see it answer again, and hands in a `Rand` that fails. It calls `bookmarks.Validate` on the accepted and refused values the requirements list and compares fields with the message constants, never their words.
