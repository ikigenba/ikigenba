# D14-apex

The root domain is not a space. It is one `A` record in the zone, at the root
itself, pointing at the Elastic IP of one space, and on that space one app
answers at it. `apex` is the command that makes, reads, and unmakes that choice
from the developer's machine, and `internal/apex` owns it. The record is `A`
only: `*.<root>` is never written, so nothing under the root resolves unless a
space owns it.

The vocabulary is the platform's. The root and its region come from the
checkout's root file (D04). The holder is the space whose Elastic IP the root's
`A` record points at, found the way `space list` and `space destroy` find it,
by `space.FindApex` (D06): the record, then the tagged addresses, then the
`Space` tag. A label has at most one Elastic IP, kept for the space's life, so
the record keeps pointing at the holder across a `space replace`, which
touches nothing about the apex. `set` finds its target by
`cloud.LookupInstance` (D03), so a space left with its address and no instance
is refused as every command that needs a host refuses it, and every command
here finds the holder the same way, since each needs the holder's host: a
holder left with only its address is refused with D03's `NoInstanceError`. No host is asked to learn the holder; a host is asked only which
app answers there, which is the opsctl configuration key `host.apex`. That
key, the certificate that carries the root as a third name, and the nginx
route from the root to the app are opsctl's, reached through its published
interface over ssh: the configuration store through `hostsetup`'s single-key
operations (D10), and `cert obtain` and `nginx apply` issued directly through
`(host.Host).Sudo` as every other host command is.

`set` takes the one app hostname devctl accepts, `<app>.<space>`, parsed by
`spaceref.ParseApp`; the reserved app names and the
refusal texts are D04's. Its preflight refuses before anything is printed or
changed: the target must exist and be running; the record, if there is one,
must point at a space's address; and the current holder, when it is another
space, must be running too, because its host is about to give the apex up.
Then five steps, in an order that never lets the root resolve to a host that
would refuse the handshake. `space` reports the target. `role` regenerates the
target's inline policy with the `_acme-challenge.<root>` permission, using
`space.PolicyDocument`, the builder `space create` uses (D06), so the two can
never disagree about what a space's role may do. `host` sets `host.apex`, reissues
the certificate, and applies nginx. `record` upserts the root's `A` record to
the target's address and waits for `INSYNC`. `previous` clears the old holder
in the reverse order, its policy narrowed first and then its host, or reports
`none`. Every step runs on every `set`, whether or not the target already
holds the apex, so a retry repeats from the start and a `set` that changes
nothing has the same shape as one that changes everything.

`space create` (D07) makes the account match a store that holds the apex the
way `set` does, and so `set`'s pieces that do not need the target's host are
exported and `set` is built from them: `CheckHolder`, the preflight that finds
the holder and refuses a record at no space's address or a holder that is not
running; `GrantApex`, the `role` step; `PointRoot`, the `record` step; and
`ClearPrevious`, the `previous` step. Each writes its own step line, so the
lines create prints are the lines `set` prints. Create calls them by name and
restates none of what they do; the `host` step stays `set`'s own, since
create's `init` obtains the certificate and applies nginx itself. Each piece
holds one record, one space, and one policy document at once; the only
listing any of them reads is the one `FindApex` and `LookupInstance` make (D03,
D06).

A failure stops the command at that step: the completed lines stay on stdout,
the failed step's error is the diagnostic, and nothing is undone. A cloud
failure is the `*cloud.Error` or `*space.WaitError` returned unchanged, as it
is in `space destroy`; a host command that exits non-zero is the
`*host.CommandError` that already carries the step name; and a host the probe
cannot reach is the `*host.UnreachableError`, wrapped so that the step name
leads the line, which is the one error shape this package adds for output.
The three refusals whose texts the stories fix and no other design declares —
a holder that is stopped while another space is about to take the apex, a
record that points at no space's address, and a holder whose host has no
`host.apex` — are this package's error types.

`show` prints the app's hostname and the address, one line, or nothing at all
when there is no record. `clear` is `set`'s reverse in the reverse order,
record, then role, then host, and needs no host when there is no record or
when the record points at no space's address. Both refuse a stopped holder and one with no instance. A
record that points at no space's address was not devctl's doing and is
reported, not guessed at; a holder whose host has no `host.apex` is the same
kind of inconsistency and `show` reports it the same way.

Ordering and the cli mapping are the shared rules and are not restated here:
usage errors first, then the root file, then the operand, then the first cloud
call (D04 R-N1LD-IX1I and R-ST4K-APZN); `cloud.Connect` with the root as the
profile and the root file's region (D02 R-YPS2-X32R); a `*cloud.NoSpaceError`
to `devctl: no space at '<domain>'`, exit 1 (D03 R-YTFS-2EAU); a `*cloud.Error`
or `*cloud.NotFoundError` to one line and exit 1 (D03 R-QZSL-ZMJL); the
checkout and root-file errors to exit 2 (D04 R-EX3T-CTOO); every error carrying
`ExitCode()` and `Detail()` (D05 R-D4G2-IO81); the fallback that turns a
`*space.NotRunningError` into `devctl: '<domain>' is stopped`, exit 1 (D05
R-0D99-FN33); and every step line written through `space.Step` (D06
R-SR5Y-JN2E). The host runner is D06's `internal/host`: `host.Host{Domain,
Deps}` with an empty `KnownHosts`, so every host is reached by its space
domain through the developer's own known hosts, `Wait`, `Sudo`,
`*host.CommandError`, and `*host.UnreachableError`. A label left with its
address and no instance reaches `cli.Run` as D03's `*cloud.NoInstanceError`,
`devctl: '<domain>' has no instance`, exit 1 (D03 R-NOWN-L0CJ).
