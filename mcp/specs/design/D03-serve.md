# D03-serve

The serve path: what happens between `cli.Run` being called with no arguments and the process being gone, and the two rules the gateway's handler keeps on every route — the identity gate and the discipline of its diagnostics. `D01-layout-and-run-seam` declares the names this design behaves through: `cli.Process`, `cli.Run`, the exit codes, `server.Serve`, `server.DrainError`, and `gateway.Config` and `gateway.Handler`. `D02-cli` decides that an empty `Args` means serve and that nothing else touches the environment. This design says how `Run` reads the drain deadline and the services path, takes the socket the host passes in, tells systemd it is ready, serves and stops, and how `Serve` treats the listener it is handed, in the shapes the serve stories show: a clean start, a stop that drains, a stop whose drain runs out, and the three ways a start is refused. What the handler answers on each route is `D04-connect`, `D05-assets`, `D06-mcp-endpoint`, `D07-describe-and-backend-hop` and `D08-call-and-mutate`.

## The terms every app serves on

mcp serves on the platform's common terms, the same as every app. It serves only on a listening socket it inherits and never opens one of its own. On a host, opsctl publishes `ikigenba-mcp.socket`, holding the Unix stream socket `/run/ikigenba/mcp.sock`, beside `ikigenba-mcp.service`, a `Type=notify` service that runs the binary with no arguments as the `ikigenba` user; nginx proxies to that socket. A deploy restarts the service alone, so the socket, and the connections queued on it, outlive every restart.

mcp takes the socket the way `sd_listen_fds(3)` documents: `LISTEN_PID` is its own process id, `LISTEN_FDS` counts the sockets passed, and the first is file descriptor 3. It removes `LISTEN_PID`, `LISTEN_FDS` and `LISTEN_FDNAMES` from its environment once it has taken the socket. Once it is ready it sends the datagram `READY=1` to the Unix datagram socket named by `NOTIFY_SOCKET`, as `sd_notify(3)` documents, a name beginning with `@` being in the abstract namespace. On `SIGTERM` or `SIGINT` it stops accepting, lets the requests it already accepted finish for at most `DRAIN_SECONDS`, then cuts off whatever is left, says how many it cut off, and exits 1. It closes its own copy of the socket and never removes the socket's path. `DRAIN_SECONDS` is a positive whole number of seconds, 5 when unset or empty, with no upper limit of mcp's own; opsctl owns its value and the unit's stop timeout.

The environment also carries `IKIGENBA_SERVICES`, the path of the host's services file. `Run` looks it up through `LookupEnv` when it starts to serve and hands the value to the gateway's handler as `Config.ServicesPath`; the handler reads the file afresh for every request (`D01-layout-and-run-seam`'s listed entries). Nothing about the variable or the file can stop a start: unset, empty, or naming a file that is missing, unreadable or malformed, mcp starts, serves and says nothing about it, and its connection reaches no MCP service. The file is read only while a request is being answered, so it can neither delay nor fail a start.

The suite is a closed system: an app trusts `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx sets them. mcp is the one app whose purpose is to call its siblings: while serving a request to `/mcp` it calls a backend directly at the socket that backend's entry names and forwards those three headers (`D07-describe-and-backend-hop`). A healthy app writes nothing; mcp's one exception is the line it writes for each request it makes to a backend, whatever the outcome. Apart from those lines, the only lines the handler ever writes are appkit's missing-identity lines, since the handler's only 5xx of its own making is that 500; a 4xx is the caller's to fix and writes nothing.

## Taking the socket

With `Args` empty, `Run` reads `DRAIN_SECONDS` first, so a bad value is found at start, and when both the drain and the socket are wrong the drain is the one reported. The value is spelled the way opsctl writes an integer: one or more ASCII digits, no sign, no leading zero, no unit, no whitespace. A value too large for a `time.Duration` is the longest drain a `time.Duration` holds rather than an error or a wrap. A value that is not acceptable is a usage error, quoted back verbatim.

A socket is passed in only when `LISTEN_PID` is exactly the decimal spelling of `Process.Pid` and `LISTEN_FDS` is a count of at least one. Anything else is no socket passed in, and a count above one is a unit mcp will not guess about. Both are usage errors with the detail line saying how to run mcp. None of the refused starts takes the descriptor, unsets a variable, serves anything or tells systemd anything.

With exactly one socket passed in, `Run` removes the three `LISTEN_*` variables through `Unsetenv` and takes descriptor 3 as its listener: through `Process.Inherit` when a test supplies one, otherwise with `net.FileListener` over the real descriptor. The Go `net` documentation of `UnixListener.SetUnlinkOnClose` states that a listener made by `FileListener` does not remove the socket file when closed, and `FileListener` documents that closing the listener does not affect the file it was made from, so the path systemd created stays and systemd's copy keeps queueing connections for the next mcp. If the descriptor cannot be made into a listener, that is trouble on the host: `mcp: ` and the error, exit 1.

With the listener in hand `Run` tells systemd it is ready and serves the gateway's handler on it until `ctx` is done. The socket has been listening since systemd made it, so ready is true before the first `Accept`, and a failure to send it is reported without anything having been served: `mcp: ` and the error, exit 1.

## Serving and stopping

`Serve` owns `ln` from the call. It serves plain HTTP/1.1 with `h` and blocks. When `ctx` is done, `Serve` closes the listener so nothing new is accepted, drops connections that carry no request, and lets every request already being handled finish and receive its whole response, for at most `drain`. If they all finish, it returns nil as soon as they have. If some are still being handled when `drain` runs out, it closes their connections without the rest of their responses and returns a `*DrainError` counting them, without waiting for the handlers themselves to return. A request waiting on a backend is a request being handled like any other: it is let finish within the drain, and cut off and counted after it. `Run` reports a cut-off as `mcp: stopped with <n> requests unfinished` (`1 request` when `<n>` is 1) and exits 1.

The drain is stated at two seams. At `Serve` a test hands in the duration. At `Run` it exists only as `DRAIN_SECONDS`, so the requirement is what a client sees: a request still being handled when `ctx` is done is given the drain deadline and cut off less than a second after it. A test holds a request open — a `POST /mcp` whose declared `Content-Length` exceeds the bytes it sends, or a `call` to an in-process backend that blocks on a channel — with `DRAIN_SECONDS=1`, unset and empty.

`Serve` is silent in its own right: Go's `net/http` documents at `Server.ErrorLog` that, when that field is nil, server errors go through the `log` package's standard logger to the real standard error, so `Serve` gives the server an `ErrorLog` that goes nowhere. A healthy run is silent from start to finish apart from the backend-call lines; nothing reaches `Stdout` while serving. Once `Run` has returned it writes nothing more: a backend-call line for a request the drain cut off appears before the stop line or not at all. `Run` makes sure no two writes to `Stderr` are ever in progress at once, and the handler does the same for `Config.Stderr`, because requests are concurrent and a test's `Stderr` is a `bytes.Buffer` the race detector watches. No read, write or idle timeouts are contract; the build sets `ReadHeaderTimeout` because the lint gate's gosec `G112` demands it, and must not set a write timeout that could cut a response short inside the drain or the backend budget.

## The handler's two rules on every route

`gateway.Handler` wraps its whole surface — `/`, `/_appkit/`, `/mcp`, `/mcp/<scope>`, and every path it does not serve — in appkit's `identity.Require`, named `mcp`, writing to `Config.Stderr`. So a request without `X-User-Id` is answered by appkit's middleware before the path, the method or the scope is looked at: a malformed scope without identity gets the 500, not the 404. What the middleware answers and writes is appkit's contract; the requirement below states only that the handler's answer is that middleware's, which a test proves by comparing against a handler it builds with `identity.Require` itself.

## REQUIREMENTS

- R-VVWG-U3YG: `Serve` MUST accept connections on `ln` and answer every request received on them over HTTP/1.1 with the response `h` produces for that request, and MUST NOT return while `ctx` is not done and serving has not failed.
- R-VX4D-7VP5: When `ctx` is done, `Serve` MUST stop accepting connections and close `ln`, and MUST close every connection that carries no request.
- R-VYC9-LNFU: When `ctx` is done, `Serve` MUST let every call to `h.ServeHTTP` already in progress continue and MUST deliver the complete response of every such call that returns within `drain` after `ctx` was done; when every such call has returned and its response has been delivered before `drain` has elapsed, `Serve` MUST return nil without waiting for `drain` to elapse.
- R-VZK5-ZF6J: When `n` calls to `h.ServeHTTP`, `n` at least 1, are still in progress once `drain` has elapsed after `ctx` was done, `Serve` MUST close the connections those requests arrived on without writing the rest of their responses and MUST return a `*DrainError` whose `Unfinished` is `n`, without waiting for those calls to return.
- R-W0S2-D6X8: `(*DrainError).Error` MUST return exactly `"stopped with 1 request unfinished"` when `e.Unfinished` is 1, and exactly `"stopped with " + strconv.Itoa(e.Unfinished) + " requests unfinished"` for every other value of `e.Unfinished`.
- R-W1ZY-QYNX: When serving fails while `ctx` is not done, `Serve` MUST return a non-nil error, and `Serve` MUST NOT return nil for any reason other than `ctx` being done.
- R-W37V-4QEM: `Serve` MUST write nothing to the `log` package's default logger and nothing to any process stream, whatever `ln` and `h` do, so that a test which points the `log` package's output at a buffer and drives `Serve` with a listener whose `Accept` returns a temporary error and a handler that panics finds the buffer empty when `Serve` returns.
- R-W5NN-W9W0: When `Args` is empty, `DRAIN_SECONDS` is set to a non-empty value `Run` does not accept, and no socket is passed in, the diagnostic `Run` writes MUST be the one R-W83G-NTDE states, and no other.
- R-W6VK-A1MP: `Run` MUST accept a non-empty `DRAIN_SECONDS` value if and only if it consists of one or more ASCII decimal digits, the first of which is not `0`, and no other characters, whatever the magnitude of the integer those digits denote, so that `0`, `-1`, `2.5`, `5s`, `05`, ` 5`, and `abc` are refused and no value is refused for being large.
- R-W83G-NTDE: When `Args` is empty and `LookupEnv("DRAIN_SECONDS")` returns `true` with a non-empty value `v` that `Run` does not accept, `Run` MUST write exactly `"mcp: DRAIN_SECONDS is '" + v + "', not a positive whole number of seconds\n"` to `Stderr` with `v` verbatim, write nothing to `Stdout`, call neither `Inherit` nor `Unsetenv`, send nothing to a notification socket, accept no connection on any listener, and return `ExitUsage`.
- R-W9BD-1L43: When `ctx` is done while `Run` is handling a request that arrived on the listener it took, `Run` MUST NOT close that request's connection, and MUST NOT return, before the drain deadline has elapsed since `ctx` was done, unless that request's handling has ended and its complete response has been delivered, and MUST deliver the complete response of that request when its handling ends before the drain deadline has elapsed; the **drain deadline** is 5 seconds when `LookupEnv("DRAIN_SECONDS")` returns `false` or the empty string, and otherwise, for the accepted value denoting the integer `n`, `n` seconds when `n` seconds is at most the largest `time.Duration` and the largest `time.Duration` when it is not.
- R-WAJ9-FCUS: When `k` requests that arrived on the listener `Run` took, `k` at least 1, are still being handled once the drain deadline of R-W9BD-1L43 has elapsed since `ctx` was done, a request waiting on a backend included, `Run` MUST, less than one second after the drain deadline has elapsed, close the connections those requests arrived on without writing the rest of their responses, write to `Stderr` exactly `mcp: `, the `Error()` text of a `*server.DrainError` whose `Unfinished` is `k`, and a newline, write nothing to `Stdout`, and return `ExitServerFailed`.
- R-WBR5-T4LH: `Run` MUST treat a socket as passed in if and only if `LookupEnv("LISTEN_PID")` returns `true` with a value equal to `strconv.Itoa(p.Pid)` and `LookupEnv("LISTEN_FDS")` returns `true` with a value of one or more ASCII decimal digits and no other characters denoting an integer of at least 1, that integer being the number of sockets passed in.
- R-WCZ2-6WC6: When `Args` is empty, `DRAIN_SECONDS` is unset, empty, or accepted, and no socket is passed in, `Run` MUST write exactly `"mcp: no socket was passed in\n\nrun it under systemd, with a listening socket passed in\n"` to `Stderr`, write nothing to `Stdout`, call neither `Inherit` nor `Unsetenv`, send nothing to a notification socket, accept no connection on any listener, and return `ExitUsage`.
- R-WE6Y-KO2V: When `Args` is empty, `DRAIN_SECONDS` is unset, empty, or accepted, and more than one socket is passed in, `Run` MUST write exactly `"mcp: " + v + " sockets were passed in, expected 1\n\nrun it under systemd, with a listening socket passed in\n"` to `Stderr` with `v` the value of `LISTEN_FDS` verbatim, write nothing to `Stdout`, call neither `Inherit` nor `Unsetenv`, send nothing to a notification socket, accept no connection on any listener, and return `ExitUsage`.
- R-TK3H-62D3: When `Args` is empty, `DRAIN_SECONDS` is unset, empty, or accepted, and exactly one socket is passed in, then by the time `Run` returns, when `Unsetenv` is not nil, each of `LISTEN_PID`, `LISTEN_FDS`, and `LISTEN_FDNAMES` MUST have been passed to `Unsetenv`, and no other key MUST have been passed to it, so that an environment that `Unsetenv` edits holds none of those three keys and has lost no other.
- R-TMJ9-XLUH: When `Args` is empty, `DRAIN_SECONDS` is unset, empty, or accepted, and exactly one socket is passed in, `Run` MUST serve on file descriptor 3 and on no other descriptor: when `Inherit` is not nil, on the listener `Inherit` returns for the argument 3, `Inherit` never being given any other argument, and when `Inherit` is nil, on the listening socket that is the process's file descriptor 3.
- R-WHUN-PZAY: When taking file descriptor 3 as a listener fails with an error `err`, `Run` MUST write exactly `"mcp: " + err.Error() + "\n"` to `Stderr`, write nothing to `Stdout`, send nothing to a notification socket, and return `ExitServerFailed`.
- R-WJ2K-3R1N: When `Run` has taken file descriptor 3 as a listener and has not failed to send `READY=1`, it MUST answer every request that arrives on that listener while `ctx` is not done, MUST NOT return while `ctx` is not done unless a call to that listener's `Accept` has returned an error that `Run` does not retry (R-WNY5-MU0F), and, once `ctx` is done and no request that arrived on that listener is being handled, MUST return `ExitSuccess` before the drain deadline of R-W9BD-1L43 has elapsed since `ctx` was done.
- R-WKAG-HISC: When `Run` has taken file descriptor 3 as a listener and `LookupEnv("NOTIFY_SOCKET")` returns `true` with a non-empty value `a`, `Run` MUST, after taking the listener and before accepting any connection on it, send exactly one datagram, whose content is exactly `READY=1`, to the Unix datagram socket whose address is `a`, an `a` beginning with `@` naming a socket in the abstract namespace; `Run` MUST send nothing to a notification socket on any other occasion.
- R-WLIC-VAJ1: When sending `READY=1` fails with an error `err`, `Run` MUST write exactly `"mcp: " + err.Error() + "\n"` to `Stderr`, write nothing to `Stdout`, accept no connection on the listener it took, and return `ExitServerFailed`.
- R-WNY5-MU0F: When `Run` has taken file descriptor 3 as a listener, has not failed to send `READY=1`, and a call to that listener's `Accept` returns, while `ctx` is not done, an error that `Run` does not retry, `Run` MUST write to `Stderr` exactly one line, beginning `mcp: ` and ending in a newline, MUST write nothing to `Stdout`, and MUST return `ExitServerFailed`; an error that is not a `net.Error` MUST be among the errors `Run` does not retry.
- R-WP62-0LR4: `Run` MUST write nothing to the `log` package's default logger, whatever happens while it serves, so that a test which points the `log` package's output at a buffer, serves with a banner source that panics when called and a listener whose first `Accept` returns an error `Run` retries, requests `GET /` with a non-empty `X-User-Id`, and cancels `ctx` finds the buffer empty when `Run` returns.
- R-WQDY-EDHT: When `Run` has taken file descriptor 3 as a listener and has not failed to send `READY=1`, it MUST write nothing to `Stdout`, and MUST write nothing to `Stderr` other than the lines its handler writes (R-WYX9-2ROO), the line R-WAJ9-FCUS states, and the line R-WNY5-MU0F states.
- R-WRLU-S58I: `Run` MUST NOT let two calls to `Stderr.Write` be in progress at the same time, those writing the lines its handler writes for requests it answers concurrently included, so that a `Stderr` that is not safe for concurrent use is never written concurrently.
- R-WSTR-5WZ7: When `Inherit` is nil and file descriptor 3 is a listening Unix-domain stream socket bound to a filesystem path, `Run` MUST leave that path in place and MUST NOT shut the socket down, so that after `Run` returns the socket still accepts connections into its queue for another process that holds it.
- R-BFHU-UIZS: When `Run` has taken file descriptor 3 as a listener and has not failed to send `READY=1`, every request that arrives on that listener while `ctx` is not done MUST be answered as the handler `gateway.Handler` returns for a `gateway.Config` whose `Banner` is `p.Banner`, whose `MCP` is `p.MCP`, whose `ServicesPath` is the value `LookupEnv("IKIGENBA_SERVICES")` returned before `Run` accepted its first connection on the listener it took (the empty string when it returned `false`), whose `Budget` is zero, and whose `Stderr` delivers each `Write` call made on it before `Run` returns to `p.Stderr` as one `Write` call with the same bytes; an answer `LookupEnv` gives for `IKIGENBA_SERVICES` after that MUST change no answer.
- R-WV9J-XGGL: Whatever `LookupEnv("IKIGENBA_SERVICES")` returns, and whatever the file it names holds, a file that does not exist, cannot be read or is not a services file included, `Run` MUST NOT refuse a start, write anything, or return on its account: given a socket passed in and an accepted or absent `DRAIN_SECONDS`, it MUST send `READY=1` as R-WKAG-HISC states and serve as R-WJ2K-3R1N states.
