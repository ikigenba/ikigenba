# D08-call-and-mutate

`call` runs a read tool of a service and `mutate` runs a write tool; each returns what the backend's tool answered. They share everything up to the backend's tool list with `describe`: the gateway call, the unknown-service and unavailable refusals, the hop to the entry's socket with the caller forwarded, the fresh `tools/list` and its failures, the unknown-tool refusal, the budget, cancellation, and the line written for every backend request are all `D07-describe-and-backend-hop`'s, and this design cites them rather than restating them. What is left is the part only these two tools have: the kind check, the backend's `tools/call`, how its answer becomes the gateway's, and the `args` argument. Their names, descriptions, input schemas and annotations — `call` read-only, `mutate` destructive — are `D06-mcp-endpoint`'s.

## The kind check

`call` is marked read-only, so a client may run it without asking its user; it must never change anything. `mutate` is marked destructive, so a client asks first. Each therefore runs only its own kind of tool (`D07-describe-and-backend-hop`'s kind): a write tool sent to `call`, or a read tool sent to `mutate`, is refused before it runs, and the refusal names the gateway tool that does run it. The check comes after the unknown-tool check and before the backend's `tools/call`, so a refused tool never reaches the backend.

## The tools/call and its arguments

A tool of the right kind is run with exactly one `tools/call` to the same backend, over the same hop. Its arguments are `args` as the model sent it, an object, or `{}` when the model left `args` out. The gateway does not hold them to the tool's input schema: that is the backend's to enforce, and its refusal is its answer like any other. A tool's arguments are a JSON object, so an `args` that is anything else, `null` included, does not fit the `{"type":"object"}` schema `D06-mcp-endpoint` declares for it and is refused in appkit's wording, as `D07-describe-and-backend-hop` states for every argument refusal, before anything else is looked at, which by `D07-describe-and-backend-hop` reaches no backend and writes nothing.

The arguments reach the backend equal, as a JSON value, to what the model sent. That is what appkit's decoding and its client promise for a value carried through a `json.RawMessage`; byte-level formatting of the object is not part of the contract.

## The answer

When the backend answers the `tools/call` with a result, error or not, that result is the gateway's answer, relayed verbatim — its `content`, its `structuredContent`, its `isError` and every other member — under the gateway's own envelope: on the `2026-07-28` revision appkit's server sets `resultType` and the `serverInfo` key of `_meta` to the gateway's own on every result, a relayed one included. The requirement states this as equality with the result appkit's server writes when a raw tool returns the backend's result, which a test computes by asking the backend directly through an appkit client and serving that result from a reference appkit server named `mcp` at the gateway's version.

When the backend does not answer with a result, the model is told what happened. Nothing reached and a JSON-RPC error read the same as for the `tools/list` (`D07-describe-and-backend-hop`). A timeout or an answer the gateway cannot read is different here: the tool may have done its work before the answer went wrong, so the model is told the call may still have completed rather than invited to retry, since running a write tool twice may make its change twice. A client that went away gets no answer, and the backend's request is abandoned with it (`D07-describe-and-backend-hop`).

## REQUIREMENTS

- R-RROF-HO4J: When the outcome (D07 R-RP8M-Q4N5) of the `tools/list` backend request of a `call` gateway call (D07 R-RQGJ-3WDU) with the service `s` and the tool `t` is `ok` and the tool named `t` the backend lists has the kind (D07 R-JP02-S57D) `write`, the call MUST be refused with (D07 R-JMKA-0LPZ) `Tool <t> of service <s> is a write tool. Use mutate to run it.`, where `<t>` and `<s>` are `t` and `s` verbatim, and the handler MUST send no `tools/call` request for it.
- R-KKPG-Q6HF: When the outcome of the `tools/list` backend request of a `mutate` gateway call with the service `s` and the tool `t` is `ok` and the tool named `t` the backend lists has the kind `read`, the call MUST be refused with `Tool <t> of service <s> is a read tool. Use call to run it.`, where `<t>` and `<s>` are `t` and `s` verbatim, and the handler MUST send no `tools/call` request for it.
- R-KLXD-3Y84: When the outcome of the `tools/list` backend request of a `call` gateway call with the tool `t` is `ok` and the tool named `t` the backend lists has the kind `read`, or that of a `mutate` gateway call with the tool `t` is `ok` and that tool has the kind `write`, the backend MUST receive exactly one `tools/call` request for the call, whose `params` member `name` is `t` and whose `params` member `arguments` is `{}` when the call's arguments hold no `args` member and otherwise a JSON value equal to the call's `args` value, whatever the tool's input schema allows.
- R-KN59-HPYT: When the outcome of the `tools/call` backend request of a `call` or `mutate` gateway call is `ok` or `tool error`, the result the handler writes for the call MUST be the result appkit's `Server`, named `ServiceName` with the version given to the `NewServer` call that returned `cfg.MCP`, writes on the same protocol revision for a `RawTool` whose handler returns, with a nil error, the `Result` an appkit `mcp.Client`'s `CallTool` returns for the backend's answer, so that every member of the backend's result is relayed, unchanged and in order, apart from the envelope members appkit's server sets on every result.
- R-KOD5-VHPI: When the outcome of the `tools/call` backend request of a `call` or `mutate` gateway call with the service `s` is `timed out`, the call MUST be refused with `Service <s> did not answer within <N> s; the call may still have completed.`, where `<N>` is the handler's budget seconds (D07 R-JRFV-JOOR).
- R-KPL2-99G7: When the outcome of the `tools/call` backend request of a `call` or `mutate` gateway call with the service `s` is `bad response (status <n>)` for any `<n>`, or `bad response`, the call MUST be refused with `Service <s> gave an answer the gateway could not read; the call may still have completed.`
