# D03-settings

events reads seven numbers from its environment once, when it starts to serve: `DRAIN_SECONDS`, the space's, which opsctl writes into every app's environment file, `/etc/opt/ikigenba/<app>/env`, and the six the manifest's `[env]` declares (`D02-cli`). `EVENTS_DEPTH_MAX` is the deepest an event's chain of causes may go (`D04-store` refuses a deeper one at `/emit`). `EVENTS_DELIVERY_TIMEOUT_SECONDS` is how long one delivery attempt may take, `EVENTS_DELIVERY_ATTEMPTS` how many times one event is tried before its subscriber is paused, and `EVENTS_INFLIGHT_MAX` how many deliveries may be in flight at once across all subscribers (`D07-delivery`). `EVENTS_RETENTION_DAYS` is how long an event stays in the log (`D04-store`, `D06-serve`). `EVENTS_DECLARATIONS_SECONDS` is how often events asks every enabled service again what it emits and accepts (`D05-declarations`, `D06-serve`). This document is `internal/settings`, which owns their spelling, defaults, order and conversions, and the refusal of a start whose settings are not acceptable. Where a serving `cli.Run` hands each value is `D06-serve`'s, and what each limit does is its consumer's.

## The settings

events reads the seven in this order: `DRAIN_SECONDS`, `EVENTS_DEPTH_MAX`, `EVENTS_DELIVERY_TIMEOUT_SECONDS`, `EVENTS_DELIVERY_ATTEMPTS`, `EVENTS_INFLIGHT_MAX`, `EVENTS_RETENTION_DAYS`, `EVENTS_DECLARATIONS_SECONDS`. Each is spelled as opsctl writes an integer: one or more ASCII digits, no sign, no leading zero, no unit, no white space. An unset or empty one is its default: 5 seconds, 8 levels, 5 seconds, 10 attempts, 4 deliveries, 2 days and 60 seconds. events sets no upper limit: digits beyond what an `int64` holds read as the largest `int64`, and keeping the drain inside the unit's stop timeout is opsctl's to enforce. `0` is refused for every one of them, as are `-1`, `2.5`, a unit suffix such as `5s`, `8x` or `2d`, and `abc`.

`settings.Read` takes the lookup `Run` hands it (`Process.LookupEnv`) and returns a `settings.Settings`, or, for the first value in that order that is not acceptable, a `*settings.Error` naming the variable, quoting its value verbatim and giving its unit in the words the stories use: `seconds` for the three timings, `levels` for the depth, `attempts`, `deliveries` and `days`. Its text, without a prefix, is what `Run` writes after `events: `: `EVENTS_DEPTH_MAX is 'abc', not a positive whole number of levels`. `settings.Defaults` is what `Read` returns when every variable is unset. Every field is an `int64` in the unit its name says; four methods turn the timings into `time.Duration`s, saturating at the longest duration, so every value `Read` accepts is usable.

## The refusal

A setting `Read` refuses is the caller's mistake, so `Run` refuses the start as a usage error: one line on `Stderr`, `events: ` and the error's text, and exit 2. `Run` reads the settings before it looks for its socket, so the refusal is the same whether or not a socket was passed in, and a refused start has touched nothing: no socket taken, no log opened or created, no notification sent, no event recorded, no service asked for its declarations, nothing swept.

## Where the values go

`Run` reads the settings once, at start, as `D06-serve` defines the settings of a call (`settings.Read(p.LookupEnv)`), and hands them on: `DepthMax` to the store, the whole `Settings` to the delivery loop, and `Retention()`, `DeclarationsInterval()` and `Drain()` to the server (`D06-serve`). Nothing in the log remembers a setting, so a restart under other values applies the new ones at once: a `depth` refused under one `EVENTS_DEPTH_MAX` is taken under a higher one. What each limit means beyond its value (which events count toward a depth, what a sweep spares, what a pause records, how backoff waits) is the consuming document's.

## Decisions

- One package for the seven, read before anything else, so `D06-serve` can refuse a start before it builds anything; `internal/delivery` takes the whole `Settings` (`D07-delivery`), and the store takes `DepthMax` through its `Config` (`D04-store`).
- Fields are plain `int64` numbers in the unit their names say, as the precedent's settings are; the duration methods exist so every consumer converts the same way and saturates the same way.
- Days convert as 24-hour days of the injected clock's time, not calendar days.
- Where each value goes is `D06-serve`'s serve-path wiring, stated once there; this document states only what `Read` returns and the start it refuses.

## Consumer tasks

The start (`D06-serve`): `s, err := settings.Read(p.LookupEnv)`; when `err != nil`, `Run` writes `"events: " + err.Error() + "\n"` and returns `cli.ExitUsage` before it looks for its socket. A test of the refusal uses `errors.As(err, &se)` with `var se *settings.Error` and reads `se.Name`, `se.Value` and `se.Unit`. Otherwise `store.New(d, store.Config{DepthMax: s.DepthMax, …})`, `delivery.New(delivery.Config{Settings: s, …})`, and `server.Run(ctx, server.Config{Retention: s.Retention(), Refresh: s.DeclarationsInterval(), Drain: s.Drain(), …})`; the delivery loop asks `TimeoutAfter(s.DeliveryTimeout())` for each attempt.

A test of the package calls `settings.Read` with a lookup over a map and compares the result with `settings.Defaults()` and with literal `Settings` values; a test of the conversions builds a `Settings` and calls `Drain`, `DeliveryTimeout`, `Retention` and `DeclarationsInterval`.

## REQUIREMENTS

- R-152N-8W4K: The `internal/settings` package, imported from the path `github.com/ikigenba/ikigenba/events/internal/settings` with the package name `settings`, MUST export `type Settings struct { DrainSeconds, DepthMax, DeliveryTimeoutSeconds, DeliveryAttempts, InflightMax, RetentionDays, DeclarationsSeconds int64 }`, its fields holding the value of the environment variables `DRAIN_SECONDS`, `EVENTS_DEPTH_MAX`, `EVENTS_DELIVERY_TIMEOUT_SECONDS`, `EVENTS_DELIVERY_ATTEMPTS`, `EVENTS_INFLIGHT_MAX`, `EVENTS_RETENTION_DAYS` and `EVENTS_DECLARATIONS_SECONDS` respectively, in the unit its name says.
- R-16AJ-MNV9: The `internal/settings` package MUST export `func Defaults() Settings`, `func Read(lookup func(key string) (string, bool)) (Settings, error)`, and `type Error struct { Name, Value, Unit string }` with the method `func (e *Error) Error() string`.
- R-17IG-0FLY: `Settings` MUST have the methods `func (s Settings) Drain() time.Duration`, `func (s Settings) DeliveryTimeout() time.Duration`, `func (s Settings) Retention() time.Duration` and `func (s Settings) DeclarationsInterval() time.Duration`, where `time` is the standard library's `time`.
- R-18QC-E7CN: `settings.Defaults` MUST return the `Settings` whose `DrainSeconds` is 5, `DepthMax` 8, `DeliveryTimeoutSeconds` 5, `DeliveryAttempts` 10, `InflightMax` 4, `RetentionDays` 2 and `DeclarationsSeconds` 60.
- R-19Y8-RZ3C: `settings.Read` MUST accept the value `lookup` returns for each of `DRAIN_SECONDS`, `EVENTS_DEPTH_MAX`, `EVENTS_DELIVERY_TIMEOUT_SECONDS`, `EVENTS_DELIVERY_ATTEMPTS`, `EVENTS_INFLIGHT_MAX`, `EVENTS_RETENTION_DAYS` and `EVENTS_DECLARATIONS_SECONDS` if and only if `lookup` returns false for it, returns an empty value, or returns a value consisting of one or more ASCII decimal digits the first of which is not `0` and no other characters, so that `0`, `-1`, `+5`, `2.5`, `5s`, `8x`, `10x`, `4x`, `2d`, `60s`, `1e1`, `05`, ` 5`, `5 ` and `abc` are refused for each of them and no value is refused for being large.
- R-1B65-5QU1: When `settings.Read` accepts the values of all seven variables, it MUST return a nil error and a `Settings` whose field for each of them is, for a variable `lookup` reports unset or returns empty, the same field of `settings.Defaults()`, and otherwise the integer the digits denote, or `math.MaxInt64` when that integer exceeds `math.MaxInt64`.
- R-1CE1-JIKQ: When `settings.Read` does not accept one or more of the values of the seven variables, it MUST return a non-nil error that `errors.As` finds to be a `*settings.Error` whose `Name` is the first variable not accepted in the order `DRAIN_SECONDS`, `EVENTS_DEPTH_MAX`, `EVENTS_DELIVERY_TIMEOUT_SECONDS`, `EVENTS_DELIVERY_ATTEMPTS`, `EVENTS_INFLIGHT_MAX`, `EVENTS_RETENTION_DAYS`, `EVENTS_DECLARATIONS_SECONDS`; whose `Value` is the value `lookup` returned for it, verbatim; and whose `Unit` is `seconds` for `DRAIN_SECONDS`, `EVENTS_DELIVERY_TIMEOUT_SECONDS` and `EVENTS_DECLARATIONS_SECONDS`, `levels` for `EVENTS_DEPTH_MAX`, `attempts` for `EVENTS_DELIVERY_ATTEMPTS`, `deliveries` for `EVENTS_INFLIGHT_MAX`, and `days` for `EVENTS_RETENTION_DAYS`.
- R-1DLX-XABF: `(*settings.Error).Error` MUST return exactly `Name + " is '" + Value + "', not a positive whole number of " + Unit`, so that the error `settings.Read` returns for `EVENTS_INFLIGHT_MAX` set to `abc`, every other variable unset, reads `EVENTS_INFLIGHT_MAX is 'abc', not a positive whole number of deliveries`.
- R-1ETU-B224: `settings.Read` MUST call `lookup` with no key other than the seven variables R-152N-8W4K names.
- R-1G1Q-OTST: For every `Settings` `s` whose `DrainSeconds` is between 1 and `math.MaxInt64` inclusive, `s.Drain()` MUST return `time.Duration(s.DrainSeconds) * time.Second` when that product does not exceed `math.MaxInt64` nanoseconds, and `time.Duration(math.MaxInt64)` otherwise.
- R-1H9N-2LJI: For every `Settings` `s` whose `DeliveryTimeoutSeconds` is between 1 and `math.MaxInt64` inclusive, `s.DeliveryTimeout()` MUST return `time.Duration(s.DeliveryTimeoutSeconds) * time.Second` when that product does not exceed `math.MaxInt64` nanoseconds, and `time.Duration(math.MaxInt64)` otherwise.
