# D01-layout-and-run-seam

events is the suite's internal event bus: one Go binary, behind the host's nginx at `events.<space>`, that takes the events every service emits to its socket at `/emit`, checks each against what its producer declared, keeps them in a retained log in its own SQLite database, and delivers each, in order, to every service that accepts it. It offers five MCP tools at `/mcp` (`catalog`, `search`, `subscribers`, `skip`, `resume`) and serves a landing page of its subscribers at `/` and an about screen at `/about`, all to a signed-in user only. This design is the structural ground the other designs stand on: where the code lives, which package owns which concern, the root package's embedded files, the version, the seam through which the process is run so that the command, the server, the store, the declarations, the delivery loop, the pages and the tools can be tested without a real process, and what `main` hands that seam.

The module is `github.com/ikigenba/ikigenba/events`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/events`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/events` is wiring only.

## The dependency

events depends on one module besides the standard library: `github.com/ikigenba/ikigenba/appkit`, required at a published release with no `replace` directive. Which release is data: `AGENTS.md` and `go.mod` name it, and no requirement names a version. The SQLite driver arrives through appkit's `db` package; events never imports it.

appkit is a sibling, reached only through its published packages. events uses seven of them. `db` gives the log's handle (`db.Open`, `DB.Read`, `DB.Write`, `DB.Close`, `DB.SetFailing`) and `db.Status`, the read-only report of which migrations a database has had. `events` gives the suite's event contract: `events.Event`, `events.Sink`, `events.EmitHandler` mounted at `/emit`, `events.ErrRejected`, the declarations path and shape, `events.Send` for a delivery, and `events.ServiceName`, `"events"`, the one name events goes by: the service the writer names, the banner's service, the MCP server's name and the services-file entry events never asks or delivers to. `telemetry` gives the trail's machinery: the writer, the request middleware, `telemetry.SiblingClient` and `telemetry.SocketTransport` for every call events makes to a sibling's socket, `telemetry.Capture` for tests, and `telemetry.NewSocketSink`, which finds the telemetry service afresh in the services file for every event. `page` gives the banner, the launcher, the footer, the template set and the shared files under `/_appkit/`. `identity` gives `identity.Require`. `mcp` gives the server mounted at `/mcp` and the client the tests drive it with. `services` gives `services.Read` and `List.Find`, through which every reader of the services file finds its entries, and `services.Variable`. appkit owns the contracts of all of these; events restates none of them.

## Where the environment is read

Nothing below `main` reads the real environment, with one exception events cannot route: appkit's `mcp.NewServer` reads `IKIGENBA_SERVICES` (`services.Variable`) from the process environment when it is called, and uses the value only when `ServerConfig.Instructions` is nil. events always supplies `Instructions`, built from the services path `Run` looked up through the seam, so the value `mcp.NewServer` reads decides nothing; a test that reaches that call still sets the variable with `testing.T.Setenv`, as `AGENTS.md` asks. events never calls `page.New`, which would read the variable too: the pages build their banner from the services path they are handed (`D08-pages`). The trail's sink is on the seam: `main` passes `telemetry.NewSocketSink()`, which reads the real environment on every delivery, as only `main` may; a test passes a `*telemetry.Capture` or a sink of its own.

## Packages

The module's root package, `events`, holds what only it can embed, since Go's `embed` reaches only files at or below the embedding package's directory. It exports `Assets`, the four human-authored templates in `assets/` (`landing.html`, `about.html`, `notfound.html`, `unavailable.html`), which `D08-pages` parses and executes; `Migrations`, the log's schema as numbered migrations, of which this events carries one, `0001_log.sql` (`D04-store` declares what it creates); and `Etc`, the two committed files under `etc/`, `manifest.toml` and `nginx.conf`, whose contents `D02-cli` fixes. Each is the same on every call and depends on no file beside the binary. A later migration is a new file with the next four-digit version; none is edited once released.

Nine internal packages hold the concerns, one each:

- `internal/cli` owns the program as a command: the version and the run seam (this document), the exit codes, the usage text, the manifest, the nginx fragment and the commands (`D02-cli`), and the serve path, which builds every package below and hands each what it needs (`D06-serve`).
- `internal/settings` owns the seven values events reads from its environment at start, their defaults, their spelling and the refusal of one that is not acceptable (`D03-settings`).
- `internal/store` owns the log: the schema, the `events.Sink` that takes an emitted event, the held declarations, the subscribers and their cursors, the catalog, the search, and the sweep (`D04-store`).
- `internal/declarations` owns asking each enabled service what it emits and accepts, and keeping the answers through the store (`D05-declarations`).
- `internal/web` owns the one handler: routing by exact path, `/emit` mounted outside identity and the request middleware, `/mcp`, `/_appkit/`, and the answers for a method a route does not take and a path that does not exist (`D06-serve`).
- `internal/server` owns the serving life: the start's sweep and refresh, readiness, the hourly sweep and periodic refresh, starting and draining delivery, the drain and the stop (`D06-serve`).
- `internal/delivery` owns the delivery loop (`D07-delivery`).
- `internal/pages` owns the pages' data and rendering (`D08-pages`).
- `internal/tools` owns the five MCP tools (`D09-tools`).

Dependencies point one way: `cmd/events` imports `internal/cli` and appkit's `telemetry`; `internal/cli` imports the root package and every internal package; `server` imports `store` and `declarations` and reaches delivery through its own `server.Delivery` interface; `web` imports no internal package and reaches the pages through its own `web.Pages` interface; `delivery`, `declarations` and `tools` import `store`; `pages` imports the root package and `store`; `delivery` imports `settings`; `store`, `settings` and the root package import nothing of events'. Which package imports which is not observable, so this paragraph is guidance, not a requirement.

## The run seam

The run seam is `cli.Run`. It takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package, and returns the exit code. `main` fills `Process` from the real process and cancels the context on a signal, with the signal's name, `SIGTERM` or `SIGINT`, as the cause; a test fills it with buffers, a map, a pid of its choosing, a listener it bound itself, a clock, timers and a pause it controls, a reader of known bytes, a temporary directory of its own as `Dir`, and a `*telemetry.Capture` as `Sink`.

Socket activation hands the process its listening socket as descriptor 3, and `Inherit` is the one step below the seam that touches a real descriptor: `main` leaves it nil, so `Run` takes descriptor 3; a test returns a listener it bound. The environment half of the protocol (`LISTEN_PID`, `LISTEN_FDS`, `NOTIFY_SOCKET`) arrives through `LookupEnv` with the settings and `IKIGENBA_SERVICES`, and removing the `LISTEN_*` variables goes through `Unsetenv`. What `Run` does with them is `D06-serve`'s.

Time is injected because events stamps and schedules by it. `Now` is the one clock: an event's `received`, a subscriber's `since`, the moment a sweep subtracts the retention window from, every event of the trail, and the time each migration is recorded as applied at. Each wait events schedules has a timer of its own, a `func(d time.Duration) <-chan time.Time`, so a test fires one without the others: `SweepAfter` between one sweep and the next (`D06-serve`), `RefreshAfter` between one refresh of the declarations and the next (`D06-serve`, `D05-declarations`), `AskAfter` for one declarations ask's deadline (`D05-declarations`), `TimeoutAfter` for one delivery attempt's deadline and `BackoffAfter` for the wait before a delivery's next attempt (`D07-delivery`). `Sleep` is the pause the telemetry writer waits between its attempts to hand an event to its sink. The drain deadline is measured in real time, never through these, because the drain is the one wait `AGENTS.md` lets a test keep to a few real seconds. `Rand` is the source the request ids are drawn from. Each nil field means the real thing: `time.Now`, `time.After`, a context-aware pause, `crypto/rand.Reader`.

`Dir` is the directory `Run` resolves `state/events.db` against. `main` leaves it empty, so the log is `state/events.db` relative to the working directory, `/opt/events` on a host; a test sets a temporary directory, so two `Run`s given the same `Dir` share one log and two given different ones do not. There is no field naming another database: appkit's `db` takes only a file path.

`Sink` is where every event of the trail goes. It is required: `Run`'s behaviour with a nil `Sink` is not contract, so `main` passes `telemetry.NewSocketSink()` and every test passes its own.

## The version

`cli.Version` is a variable in the source, never injected at build time, holding `v` and a Semantic Versioning version. It is the one version string events shows: `events --version` (`D02-cli`), the footer and the about screen (`D08-pages`), the MCP `serverInfo` (`D06-serve`), and `service.started`'s `version`. Its value is data the deploy sets; no test names it.

## Decisions

- The seam is named `cli.Process`, as in both precedents. Five timer fields rather than one, so a test fires the sweep, the refresh, an ask's deadline, a delivery's deadline or a backoff without firing the others.
- `Sink` is on the seam and required, rather than defaulting to the socket sink below `main`: that default would read the real environment on every delivery, which `AGENTS.md` lets only `main` do.
- No `Banner` or `MCP` fields: events never calls `page.New`, and the one environment read `mcp.NewServer` makes decides nothing because `Instructions` is always supplied.
- `Etc` returns an `embed.FS`, so its type alone proves the bytes come from a `//go:embed` of the committed files; `Assets` and `Migrations` return an `fs.FS` holding their files at the root, as `page.Templates` and `db.Config.Migrations` take them.
- That `cli.Version` is never injected at build time stays prose: no permitted test can tell a source literal from one a linker flag replaced, and the deploy's own check that the binary reports the tag catches a binary built otherwise.
- What `main` hands the seam is proved only at the binary, by the one exec'ing test `AGENTS.md` admits: it runs `--version`, `manifest`, `bogus`, a bare start with no socket, and a start on a socket it passes as descriptor 3, whose trail goes to a `telemetry` entry the test holds, stopped by `SIGTERM` and in a second run by `SIGINT`.

## Consumer tasks

The binary's start: `main` calls `cli.Run` with a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Sink` is `telemetry.NewSocketSink()`, and whose `Dir`, `Inherit`, `Now`, `Sleep`, `Rand` and timers are left zero, under a context it cancels on `SIGTERM` or `SIGINT` with a cause whose `Error` is the signal's name; it exits with what `Run` returns.

A test of the run seam builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` and an `Unsetenv` over one map, an `Inherit` returning a listener it bound on a Unix socket in a short temporary directory, `NOTIFY_SOCKET` naming a datagram socket it holds, a fixed `Now`, timers returning channels it owns, a `Rand` of known bytes and a `*telemetry.Capture` as `Sink`; sets `services.Variable` with `t.Setenv`; calls `cli.Run` with a context from `context.WithCancelCause`; waits for `READY=1`; drives the listener with `mcp.Client` and raw HTTP; cancels with `errors.New("SIGTERM")`; and inspects `Dir`, the capture and the streams. A test of the root package lists and reads `events.Assets()`, `events.Migrations()` and `events.Etc()` with `fs.ReadDir` and `fs.ReadFile`, from a working directory of its own made with `t.Chdir`.

## The documents

`D02-cli` is the command, the exit codes, the usage text, the manifest, the nginx fragment and the two files under `etc/`. `D03-settings` is `internal/settings` and the refusal of a start whose settings are not acceptable. `D04-store` is the log. `D05-declarations` is asking the services. `D06-serve` is the serve path, `internal/server` and `internal/web`. `D07-delivery` is the delivery loop. `D08-pages` is the pages. `D09-tools` is the five tools. `D10-trail` is the trail as a whole. `D11-on-a-space` is what events is on a host and in a sandbox.
