# D05-declarations

How events learns what each service emits and accepts: `internal/declarations` asks each service for its declaration at `GET /declarations` on its own socket, judges the answer, and keeps what it learns through the store (`D04-store`), which holds it in the database so it outlives a restart. events is never configured with the bus's shape; it is what the services answer. `D06-serve` builds the asker with the services file `cli.Run` was handed, calls `Refresh` before it reports ready and then every `EVENTS_DECLARATIONS_SECONDS` seconds; `cli.Run` passes `Ask` to the store as `store.Config.Ask`, which `Deliver` calls for an undeclared event. What the store does with a declaration — the catalog, the check at `/emit`, the subscribers — is `D04-store`'s.

## Whom events asks

The services file is read afresh at every `Refresh` and every `Ask`, through appkit's `services.Read`, at the path `Config.Services`. A service is **askable** when the file lists it with `"enabled": true` and it is not events itself. A missing or unreadable file, one that is not a services file, and an empty path give no list, so no service is askable. events never asks itself: the host's services file lists `events`, enabled, on its own socket, but events is the broker, neither emitting through `/emit` nor taking deliveries, and at start its socket is not yet served, so asking would only wait out the deadline. The same entry is never a delivery target (`D07-delivery`), and an emit claiming to be from `events` is refused as undeclared.

## Asking

An ask is one `GET /declarations` to the service's socket, made through appkit's `telemetry.SiblingClient` over `telemetry.SocketTransport`, so the trail gets the `sibling.called` record every sibling call gets, with status 0 when nothing answered. Each ask has its own deadline, `AskTimeout`, two seconds, measured by the timer `Config.AskAfter` gives, so a test fires it rather than waiting. The deadline is short because an emit of a name the held declaration does not list waits on the ask before it is answered, and the producer's emitter gives each attempt five seconds (appkit's `events.AttemptTimeout`).

An answer is a **declaration** when it is status 200 and its body is one JSON object with an `emits` array of `{"event", "attrs"}` objects and an `accepts` array, every `event` a name or a pattern (`D04-store`), every attribute name the attribute-key rule, and every element of `accepts` `*`, a name or a pattern. Anything else — nothing on the socket, the deadline, a 404, a 500, a body that is not JSON, `{"emits":"repo.pushed"}`, an `emits` naming `Repo.Pushed` or `cron.h*.fired` — is no answer, and events keeps the declaration it last had from that service.

## Refreshing

`Refresh` asks every askable service at once, without one ask waiting on another, and returns when each has ended. A service that answered with a declaration is declared to the store; one that did not keeps what the store holds for it; and every service the store holds a declaration for that the file no longer lists enabled is forgotten, which makes its subscriber `gone` (`D04-store`). A file that gives no list is another matter: at the start refresh, the first `Refresh` a `*Declarations` makes, nothing is declared, so every held declaration is forgotten; at any later refresh it is no answer from anyone, and every held declaration stays. A refresh changes nothing in the log.

## Asking on demand

`Ask` is the store's way to learn of a name a producer was deployed with since the last refresh. It asks only an askable service, so an emit claiming an unlisted, disabled or self service is refused without a call. A burst of emits of a new name asks once: an `Ask` while an ask made for another `Ask` to that service is in flight makes no request of its own and returns when that ask has ended, its result held, telling `Config.Joined` so a test knows it joined. An ask made for `Ask` runs to its answer or its deadline whatever happens to the emits waiting on it, so its answer is held for the next emit even when the first producer gave up; an `Ask` whose context is already done asks nothing. `Ask` never forgets: a service that does not answer keeps what it declared.

## Decisions

- Asks are coalesced per service but not rate-limited: each later emit of a still-undeclared name asks again, so a burst of emits of one new name asks once between the first post and its answer.
- The deadline is its own constant and timer, not `EVENTS_DELIVERY_TIMEOUT_SECONDS`, which is how long one delivery may take.
- An answer's body is read up to `events.MaxEventBytes`; a longer one is no declaration. A declaration is a short list of names, and the bound keeps a misbehaving sibling from holding memory.
- Unknown members are ignored, so a later appkit may add to the declaration without older events refusing it; an empty `emits` or `accepts`, a repeated name or pattern, and `*` beside names and patterns are allowed, as appkit's own `DeclarationsHandler` can write them. `Content-Type` is not looked at.
- A services file that gives no list after the start is a fault of the host, not a statement that the suite is empty, so a later refresh keeps every held declaration and turns no subscriber `gone`: a file briefly missing during a deploy costs nothing. At the start there is nothing better to go on, so with no list nothing is declared, every emit is refused as undeclared, and every subscriber turns `gone` until a refresh with a list, when they return at their cursors if their events are still retained. The start refresh is the first `Refresh` on a `*Declarations`; `cli.Run` builds one per run, so it is the refresh `D06-serve` makes before ready.
- `Refresh` asks on its own and joins nothing; a refresh and an emit's `Ask` racing for one service may both ask it, which costs one extra call.
- An `Ask` that races a `Refresh` dropping the same service may declare it just after the refresh forgot it; the next refresh forgets it again. The window is one ask long and a rule closing it would need a lock across the services file, the ask and the store, so it is accepted.
- declarations is handed no output stream and asking writes nothing to stdout or stderr; the run-level proof, a serve start with a services file whose `Stdout` and `Stderr` stay empty, is `D06-serve`'s and `D10-trail`'s.
- Names and patterns are judged by appkit's `events.Match`, the rule producers and the emit check share, not by an expression of events' own; appkit exports no validator, so a name is a string `Match` matches to itself and a pattern one that, not a name, matches some name (replacing each `*` word with a letter gives one). A name has two or more words, so `a.b.c.d` is one.
- `Config.Telemetry` must be non-nil: appkit's `telemetry.SiblingClient` requires a writer, and every ask is recorded.
