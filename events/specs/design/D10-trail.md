# D10-trail

events' trail as a whole: the telemetry records events makes while it serves, what each says, which request each belongs to, the order a request's records come in, and what no record ever carries. The trail is a different thing from the log. The log (`D04-store`) holds the events services emit, which other services act on; the trail is events' own account of what it did, sent to the platform's telemetry service like every app's.

Every record goes through one writer, the run's writer (R-98YL-W8I0), whose sink `main` makes with appkit's `telemetry.NewSocketSink`, so on a host each record goes to the socket of the services-file entry named `telemetry` (R-Q0YV-7I42); a record telemetry cannot take is written to standard error as one `events: undelivered event:` line and events carries on (R-98YL-W8I0, R-8T3W-X7UZ). Every record is stamped by the seam's clock, in UTC to the microsecond (R-ZTTZ-Z2G4), and names `events` as its service.

## Who records what

Each record is owned by the document whose part makes it, and this one cites them:

- `service.started`, with `version`, once events is serving, after the start's declaration asks (R-8LSI-MLET, R-8N0F-0D5I); `service.stopping`, with `reason`, last of all (R-BM0Q-O8OS).
- `sibling.called`, one per call to a sibling's socket: a declarations ask (R-355A-QQIN) or a delivery attempt (R-H68X-NE8X). This document closes the set (R-HJNT-UVEK).
- `event.accepted`, once per event the store keeps, none for a duplicate or a refusal (R-69AX-8R2N, R-RJAX-A1WF, R-2J73-UV65).
- `event.delivered` and a subscriber's own `event.skipped` (R-G1LB-MGO7, R-G2T8-08EW); `subscriber.paused` (R-GJ2U-DR5Q); an agent's `event.skipped` (R-YTM0-2PJ1).
- `request.started` and `request.finished` for every request but a post to `/emit` (R-EYWG-JUFR, R-F04C-XM6G; `/emit` records none, R-CWCX-7IV6), and `tool.called` for each tool call answered with a result (R-HG04-PK6H, R-HH81-3BX6; an `invalid_arguments` refusal records `duration_us` 0, since appkit's `mcp` server refuses the arguments before the handler runs, probed). These three are appkit's machinery (`telemetry.Middleware` and the `mcp` server), probed against the installed module, and stated here as events' own behaviour, so events' tests fail if a release of appkit stopped giving them.

## A request's records

nginx gives every request an `X-Request-Id` and the caller's `X-User-Id`; the request's records carry the first as their request id and the second as their user, and a request without an id gets one made up from the seam's random source (R-ZW9S-QLXI). That id is the one the caller in the request's context carries (R-CXKT-LALV), so an agent's `skip` records its `event.skipped` under it. A request's records come in one order: `request.started`, then the `event.skipped` of a `skip` that unstuck a subscriber, then `tool.called`, then `request.finished`, and nothing else carries its id (R-HIFX-H3NV). A read tool and `resume` therefore add three records, a page two, and an agent's `skip` four.

`request.started`'s `path` is the URL's path without its query, and the user is the caller's id, never the email: attributes name what happened and the ids of what it touched, never data. No record carries a bus event's attributes, a tool's arguments, a caller's email or a request's query (R-F9VJ-ZS40); the one piece of free text the trail carries is the error a subscriber gave when it was paused (R-GJ2U-DR5Q, R-FWPQ-3DPF).

## What the broker never records

events records ten names and no other (R-F8NN-M0DB). In particular it never records `event.lost`: an event that never reached events was never in its log, and the producer that gave up on it records the loss in its own trail.

## Order between the log and its deliveries

An event's `event.accepted` comes before every record of its delivery: the store records it before any `Next` answers the event (R-6BQQ-0AK1), and the loop finds each event through the store. This document states the order end to end, at `cli.Run` with a capturing sink (R-HKVQ-8N59), so a delivery that read the log by another way would still be held to it.

## Decisions

- **The request records are stated at `web.Handler`**, where `D06-serve` mounts `telemetry.Middleware`, so a web test with a `telemetry.Capture` proves them; the request id and user are stated once there, and `cli.Run` answers as `web.Handler` with the run's writer (R-9HHW-KMOV).
- **`tool.called` is stated at `cli.Run`**, where the MCP server and the tools share the run's writer: appkit's server, not `internal/tools`, makes the record, and `D09-tools` leaves it to this document (R-YR67-B61N, R-YSE3-OXSC).
- **`request_bytes` and `response_bytes` count body bytes read and written** (probed: a handler that read 10 bytes of a 37-byte body and wrote 3 is recorded 10 and 3; a `HEAD` the handler writes nothing for is 0). `duration_us` is only a non-negative integer, since the seam's clock may stand still.
- **Outcomes of `tool.called`**: appkit's server knows five (`ok`, `invalid_arguments`, `error`, `panicked`, `unencodable_output`, in the installed module's `mcp/tools.go`); events' tools, driven as permitted tests drive them, produce the first three (probed): `ok` for a result without `isError`, `invalid_arguments` for appkit's own refusal of the arguments, `error` for a refusal the tool made. The set is not stated as closed, so a panicking handler's `panicked` record is not forbidden. A call of a tool events does not have is a JSON-RPC error and records no `tool.called` (probed), nor does `tools/list`.
- **Request id and user of the broker's own records** (`sibling.called`, `event.accepted`, `event.delivered`, a subscriber's `event.skipped`, `subscriber.paused`) are not fixed, as `S14` leaves them; R-HIFX-H3NV only says none carries a request's id.

## Consumer tasks

A web test builds `web.Handler(web.Config{Pages: p, MCP: srv, Sink: st, Telemetry: w})` over a writer whose sink is a `telemetry.Capture`, serves `GET /?q=secret` with `X-Request-Id`, `X-User-Id` and `X-User-Email`, a `HEAD /about`, a `GET /` without identity and a `POST /emit`, flushes `w`, and finds two records per request but the emit, each pair under the request's id and user, `path` without the query, status 500 and an empty user for the one without identity.

A `cli.Run` test serves with a `telemetry.Capture` as `Sink` and a services file naming a subscriber socket the test holds: it emits at `/emit`, lets the subscriber answer an error with `EVENTS_DELIVERY_ATTEMPTS` 1, calls `skip` and `search` through `mcp.Client` with request ids of its own, gets `/`, stops with `SIGTERM`, and reads the capture: each request's records in order under its id, `tool.called` with its `kind` and `outcome`, `subscriber.paused` carrying the error, no record carrying the emitted event's attribute values, the caller's email or the search's arguments, and no name outside the ten.

## REQUIREMENTS

- R-EYWG-JUFR: For every request whose URL path is not exactly `/emit`, whatever its method, headers — an absent or empty `X-User-Id` included — and body, a handler `web.Handler(cfg)` returns MUST record through `cfg.Telemetry` exactly one telemetry event named `request.started`, before every other event recorded through `cfg.Telemetry` while that request is answered, whose `Attrs` are exactly `method`, the request's `Method`, and `path`, its `URL.Path`, which holds no query; so that a `GET /?q=x` is recorded with `path` `/`.
- R-F04C-XM6G: For every request whose URL path is not exactly `/emit`, a handler `web.Handler(cfg)` returns MUST record through `cfg.Telemetry` exactly one telemetry event named `request.finished`, once its answer is complete and after every other event recorded through `cfg.Telemetry` while that request is answered, whose `Attrs` are exactly `status`, the status code of the answer, `duration_us`, a non-negative integer, `request_bytes`, the number of bytes of the request's body read while it was answered, and `response_bytes`, the number of response body bytes the answer wrote; so that a `GET /` answered by the landing page records `status` 200 and `response_bytes` the length of the body, a `HEAD /` records `response_bytes` 0, and a request without identity records `status` 500.
- R-F1C9-BDX5: The `request.started` and `request.finished` of a request (R-EYWG-JUFR, R-F04C-XM6G) MUST both carry as `RequestID` the request's **request id** — its first `X-Request-Id` value when that is non-empty, and otherwise one id made up for that request and used for both — and as `User` the request's first `X-User-Id` value, the empty string when it has none; and the caller a handler `web.Handler(cfg)` puts in the request's context (R-CXKT-LALV) MUST carry that same request id as its `RequestID`; every requirement of events' design that names a request's id MUST denote it.
- R-HG04-PK6H: While `cli.Run` serves, for each request at `/mcp` carrying a non-empty `X-User-Id` whose message is a `tools/call` of `catalog`, `search`, `subscribers`, `skip` or `resume` that is answered with a result — one without `isError`, a refusal R-DFG6-RBKX describes and a refusal of the arguments R-YNII-5UTK states alike — the run's writer MUST record exactly one telemetry event named `tool.called`, with the request's id (R-F1C9-BDX5) as `RequestID` and its first `X-User-Id` value as `User`, whose `Attrs` are exactly `tool`, the tool's name; `kind`, `read` for `catalog`, `search` and `subscribers`, `destructive` for `skip` and `additive` for `resume`; `outcome`, `ok` for a result without `isError`, `invalid_arguments` for a refusal R-YNII-5UTK states and `error` for a refusal any other requirement of `D09-tools` states; and `duration_us`, a non-negative integer that is 0 when `outcome` is `invalid_arguments`; so that a `skip` or `resume` whose arguments R-YNII-5UTK refuses records `duration_us` 0.
- R-HH81-3BX6: While `cli.Run` serves, the run's writer MUST record no `tool.called` for a request at `/mcp` whose message is not a `tools/call`, `tools/list`, `server/discover` and `initialize` included, nor for a `tools/call` answered with a JSON-RPC error, a call of a tool events does not have included.
- R-HIFX-H3NV: While `cli.Run` serves with a `p.Sink` that takes every event, for each request whose URL path is not exactly `/emit` and whose `X-Request-Id` is non-empty and carried by no other request, the events delivered to `p.Sink` whose `RequestID` is that value MUST be exactly, in this order: the request's `request.started`; then, when it is a `tools/call` of `skip` that R-E06H-9F6Q answers, that call's one `event.skipped` (R-YTM0-2PJ1); then its `tool.called` when R-HG04-PK6H records one; then its `request.finished`; so that a `GET /` adds two records under its id, a `search` call and a `resume` call three each, and a `skip` of a paused subscriber four, and no `sibling.called`, `event.accepted`, `event.delivered`, `subscriber.paused` or `service.*` record carries a request's id.
- R-HJNT-UVEK: While `cli.Run` serves, every telemetry event named `sibling.called` that the run's writer records MUST be the record of one declarations ask (R-355A-QQIN) or of one delivery attempt (R-H68X-NE8X), none being recorded for any other call, the hand-over of its own records to `p.Sink` included; so that every `sibling.called` names as `target` a service other than `events.ServiceName`, with `method` and `path` either `GET` and `/declarations` or `POST` and `/events`.
- R-F8NN-M0DB: Every telemetry event the run's writer records while `cli.Run` serves MUST be named one of `service.started`, `service.stopping`, `request.started`, `request.finished`, `tool.called`, `sibling.called`, `event.accepted`, `event.delivered`, `event.skipped` and `subscriber.paused`, so that events never records `event.lost`.
- R-F9VJ-ZS40: While `cli.Run` serves, no event delivered to `p.Sink`, and no event written to `p.Stderr` as an undelivered event, MUST contain in its JSON form a string that, of everything the test hands `cli.Run` and the requests, emits, services file and sibling answers it serves, occurs only as a key or value within the `attrs` of an event posted to `/emit`, as the value of a request's `X-User-Email` header, within the query of a request's URL, or within the `arguments` of a `tools/call`; so that the trail carries no bus event's attributes, no caller's email, no query and no tool argument that is not also a service's name or an event's id.
- R-HKVQ-8N59: While `cli.Run` serves with a `p.Sink` that takes every event, for each event stored through a post to `/emit`, its `event.accepted` (R-69AX-8R2N) MUST be delivered to `p.Sink` before the `sibling.called` of every delivery attempt at that event (R-H68X-NE8X) and before every `event.delivered`, `event.skipped` or `subscriber.paused` whose `event` attribute is that event's id; so that a subscriber that answers the delivery ok, skip or an error leaves, after the event's `event.accepted`, the attempt's `sibling.called` and then its `event.delivered`, `event.skipped` or `subscriber.paused`.
