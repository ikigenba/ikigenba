# D04-store

The log: `internal/store`, which owns events' one SQLite database, `state/events.db`, and everything events keeps in it — every event it accepted and still retains, with its `seq` and `received`; the declaration it holds for each service; and each subscriber's status and place in the log. It is the `events.Sink` that appkit's `events.EmitHandler` hands every well-formed post to `/emit`, so the checks that come after the shape — the duplicate, the producer's declaration and the depth — are the store's, and the store records `event.accepted`. `D01-layout-and-run-seam` declares the root package's `Migrations`, which holds this document's one migration, and resolves the path; `D06-serve` opens the database with appkit's `db.Open`, builds the store over the handle, and runs the sweep. Opening, migrating, transactions and the failure seam are appkit's `db` contract, which this document restates none of. What asks a service for its declaration is `D05-declarations`; what the delivery does with `Next`, `Advance` and `Pause` is `D07-delivery`; what the tools answer from `Catalog`, `Search`, `Subscribers`, `Skip` and `Resume` is `D09-tools`; what the landing page shows of a subscriber is `D08-pages`.

## One log, one writer

events is the database's only writer and no sibling reads it. Every read is a `DB.Read` and every write a `DB.Write` on the handle `store.New` was given, so the handle's one writer serializes writes and a check-then-change (the duplicate check and the insert, a subscriber's status check and its change) happens inside one write. What is contract is what a reader and a restart see: what a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds. A test proves content that way, through the store's own reads, and proves the schema only through `sqlite_master` and `PRAGMA table_info`/`index_info` inside a `DB.Read`, because a released migration binds every later one.

The schema is one migration, `0001_log.sql`. `events` holds one row per retained event: `seq`, the `INTEGER PRIMARY KEY AUTOINCREMENT` that is the event's `seq`, so a `seq` is never handed out twice even after the sweep removed the event that had it; `id`, unique; `time` and `received` as integer microseconds from the Unix epoch; `service`, `event`, `request_id`, `user`, `cause`; `depth`; and `attrs`, the JSON text of the event's attributes as appkit writes them. `attrs` holds one row per attribute of each event, `seq`, `key` and `value`, the value's JSON text, which is what an attribute search matches on. `subscribers` holds one row per subscriber: `service`, its status, cursor and since, and while paused the stuck event's id, name and `seq` and the last error text. `declarations` holds the declaration events last had from each service, its `emits` and `accepts` as JSON text, and `asked`, the moment of the latest `Declare` for it, which is when the service last answered. Indexes serve each search filter in `seq` order and the sweep's `received` bound.

## Ingest

`Deliver` is the sink. It answers nil for an event whose `id` the log already holds, before it looks at anything else, so a producer's retry of an event events already has is a 204 and stores nothing (`S07`). Otherwise it judges the producer's declaration: an event is **declared** when the declaration the store holds for its `service` lists its name among `emits`. When it is not, the store calls `Config.Ask` for that service — `D05-declarations` asks it, joining an ask already in flight — and judges by what it holds once the ask is over, so a producer deployed with a new name since the last refresh has its first event accepted (`S06`). Still undeclared, the event is refused with `ErrUndeclared`; declared but deeper than `Config.DepthMax`, with `ErrTooDeep`; both wrap appkit's `events.ErrRejected`, which `EmitHandler` answers 422. An accepted event is stored with the next `seq` and `received`, the store's clock read during the call, both to the microsecond in UTC; `event.accepted` is recorded with the event's id and cause before the event can be read, so the record precedes anything a delivery of it records, and then every channel `Changed` handed out is closed. A database that cannot be written is an error that does not wrap `ErrRejected` (500), stores nothing and spends no `seq`.

## Declarations and subscribers

The store holds at most one declaration per service: `Declare` replaces it, `Forget` drops it. A service **accepts** an event name when the declaration the store holds for it lists that name or `*` among `accepts`. A **subscriber** is a row the store keeps for a service whose declaration once accepted something; it is never removed. It is `ok`, `paused` or `gone`. A `Declare` that accepts something makes a new subscriber `ok` at the head of the log, turns a `gone` one `ok` — at its old cursor when every event after it is still retained (`S10`, `S13`), at the head otherwise — and leaves an `ok` or `paused` one as it is. A `Declare` that accepts nothing, or a `Forget`, turns a subscriber that is not `gone` `gone`, keeping its cursor. Each change of status sets `since` to the store's clock.

The **head** is the `seq` of the last event ever stored, kept across a sweep and a restart; a subscriber's **cursor** is the `seq` of the last event it finished or passed over, and its **lag** the head minus its cursor, for every status, `gone` included. The delivery (`D07-delivery`) works through `Next`, which moves an `ok` subscriber's cursor past events it does not accept and hands back the next one it does, `Advance`, which moves the cursor past an event finished, and `Pause`, which stops the subscriber on an event with the last error. `Skip` and `Resume` are the agent's (`S12`, `D09-tools`): both refuse a service with no subscriber, then one that is not `paused`; `Skip` moves the cursor onto the stuck event and `Resume` leaves it, and both make the subscriber `ok`. `Changed` lets the delivery wait for work without polling.

## Sweep

`Sweep(before)` removes every event received before `before` that no `ok` or `paused` subscriber still needs: nothing above the lowest cursor among those subscribers goes, however old, and a `gone` subscriber holds nothing (`S13`). Age is `received`, never `time`. The server calls it with the moment minus the retention window, at start and hourly (`D06-serve`). The head, the declarations and the subscribers are untouched.

## Catalog and search

`Catalog` is `S08`'s catalog: every name a held declaration emits, plus every name a retained event carries, each with the services that declare it with their attribute names, the services that accept it, how many retained events carry it and the `received` of the newest. `Search` is `S09`'s search over the retained log, newest `seq` first, with telemetry's filter shape plus `Cause`, and a cursor that encodes a position only: it is checked before the database is read, and a cursor handed back with other filters, or pointing at a position the sweep has since passed, simply continues from there.

## Failure

From a `SetFailing(true)` on the store's handle until a `SetFailing(false)`, every method but `Changed` answers an error that is none of the store's sentinels and does not wrap `events.ErrRejected`, and changes nothing; `D09-tools` answers it `cannot reach the log; try again later`, and `EmitHandler` 500. A malformed cursor is still `ErrCursor`, since telling it needs no database.

## Decisions

- Times are kept as integer microseconds from the Unix epoch, the precision every time events answers has, so the sweep compares integers; a search's `since` and `until` are compared, as instants, with the event's `time` as it was stored, to the microsecond.
- `AUTOINCREMENT` makes the head survive a sweep that empties the log. The head is what the file holds, so a restore that puts back an older copy of the file (`S17`) puts back its head, its cursors and its log together, and the next `seq`s are handed out again from there; a `seq` names an event only within one history of the log.
- `event.accepted` is recorded inside the write that stores the event, before it commits, so no reader, the delivery included, can see the event before the record exists. A commit that fails after that leaves a record for an event not stored; a failing handle (`SetFailing`) fails before the write begins, so it never does.
- A failed write rolls its `seq` back, so no `seq` is spent on an event not stored, and the retained `seq`s above the lowest `ok`/`paused` cursor have no gaps, which is what lets `Next` leave a cursor one below the event it hands back.
- The search cursor is `base64.RawURLEncoding` of the last record's `seq` and a CRC-32 of it, telemetry's form with `seq` as the whole position; a checksum rather than a key, since a forged cursor only skips to a position of the caller's choosing in a log it may already read in full.
- The duplicate check precedes the declaration check and the depth check (`S07`), so a retry of an event whose producer has since dropped the name, or after `EVENTS_DEPTH_MAX` was lowered, is still a 204.
- `Pause` and `Advance` change only an `ok` subscriber: an attempt still in flight when a refresh makes its subscriber `gone` must neither pause it nor move its cursor, and a paused subscriber's cursor moves only by `Skip`, never backwards.
- No event above the cursor of an `ok` or `paused` subscriber is ever missing: the sweep's bound and a returning subscriber's cursor are decided against one state of the log, which is what lets `Next` leave a cursor one below the event it hands back.
- `Next` decides what it hands back and where it leaves the cursor against one state of the log, so a `Next` that finds nothing never moves the cursor past an event a concurrent `Deliver` stored after it looked (R-TIQ9-B2AD). `Config.Scanned` is the seam a test proves that through, as `Swept` is for the sweep: it runs between `Next`'s look and its move, outside any transaction, so a test delivers an accepted event from it and sees the next `Next` return it, where a `Next` that read the log and then moved the cursor to the head as it stood at the move would pass it over.
- The sweep runs in batches of `SweepBatch`, oldest `seq` first, each batch taking its bound afresh, so a write stays short and a subscriber that returns mid-sweep keeps its events; `Config.Swept` is the seam a test drives that through. Within a batch, attrs go first; that is not contract.
- A catalog entry lists a service once among `Emits` even when its declaration repeats the name, with the attribute names of the first entry.
