# Decision 17 — The testing-language contract: opsctl is hermetic + manual, and its out-of-loop ids are the manual layer

**Decision.** opsctl adopts the suite's testing-language contract,
`root project/design/D23.md`, without deviation. This Decision does not restate
the contract — it records how opsctl's existing testing shape *maps onto* it and
what that adoption obliges this tree to build.

**The mapping.** opsctl has always split its checks two ways: unit tests against
temp dirs through faked seams, and a handful of "real-substrate (live box
`int.ikigenba.com`)" ids that the build loop cannot run and an operator verifies
out of loop. Under the contract's vocabulary:

- The in-gate tier is the **hermetic** layer, and nothing weaker: its substrates
  are a real temp-dir filesystem, real archive files through the real `tar`
  binary, and faked privilege seams — never a network address, never a
  credential, and **never a sibling service**. opsctl's stage, deploy, rollback,
  and setup orchestration is proven against the faked `System` seam over a
  temp-dir filesystem, never by compiling (a `go build ./cmd/<name>` in a
  `../../../<svc>` sibling tree) or booting a real service binary. Whether a
  given service boots on the `state/` opsctl delivers is that service's own
  tree's proof, not opsctl's; opsctl's whole rotating-credential obligation is
  that `seed-state` delivers a credential to `state/` (D19), proven generically.
- The out-of-loop tier is the **manual** layer, *not* the live layer. Each of
  those ids needs privileged on-box state (root, real uid/gid switching, a real
  systemd unit, real nginx, a real object store reachable only from the box)
  behind an interactive `ssh int` session. That is the contract's definition of
  manual: what automation cannot reach *even with credentials*. So opsctl builds
  **no `//go:build live` files** and defines no `go test -tags live` invocation;
  a `live` invocation here would have nothing to compile.
- opsctl has **no composed layer**. It is a CLI whose "composed" form is a
  privileged binary acting on a real box; there is no loopback server to boot
  and drive, so the composed rung is empty by construction rather than by
  omission.

**The manual layer becomes a committed runbook.** The contract's requirement
that manual checks be committed rather than tribal is the one place opsctl was
short: the ids said "operator-verified out-of-loop" and named no document, and
`project/plan/README.md` pointed at a `*-verification.md` doc that did not
exist. This Decision fixes the document at
**`opsctl/project/opsctl-verification.md`**, following the suite's existing
pattern (`github/project/github-verification.md`): one entry per manual check,
each stating its positive check, the **negative** check proving the positive one
exercised the real thing, and where the result is recorded.

The runbook's contents are the union of two sets:

1. **opsctl's own manual-layer ids** — the eight design ids already marked
   *Real-substrate (live box)*: `R-WRJF-H7J9` (D1), `R-66UP-LI59` (D2),
   `R-6FE0-9WC4` (D3), `R-MYS7-2H2R` (D4), `R-AXY7-K8GA` (D8), `R-B0E0-BRXO`
   (D9), `R-JRO8-5Q0R` (D10), `R-MMF1-HFMO` (D11). Absorbing them into the
   runbook is what makes them checks rather than intentions; they remain design
   ids of their own Decisions and are not re-minted here.
2. **The suite's `web`-group access check** — the closing note of
   `root project/design/D01.md` places one contract behavior here: that a
   `web`-group process can read `state/www/{public,private}` and can neither
   read `state/<svc>.db` nor list `state/`. It hinges on real uid/gid switching,
   so it carries no id (the mode bits and the ownership plan are already
   asserted in-gate by that contract's `R-3SAU-8T9F`) and lives in the runbook
   as a named check with its positive and negative form.

**The two per-service ids.** The contract marks two ids `[proof: per-service]`,
and citing them is adoption: opsctl carries its own tagged tests for
**R-O1AD-MRKW** (a hermetic test reading the committed `opsctl/AGENTS.md` from
disk and asserting its Tests section declares the gate command, the layers, the
environmental preconditions, and the GOWORK mode) and **R-O2IA-0JBL** (a
hermetic source scan finding zero `t.Skip`/`t.Skipf`/`t.SkipNow` outside
live-tagged files, its needle assembled from parts so it never matches itself).
This supersedes the Conventions note that opsctl, being tooling rather than a
service, never adopts a per-service contract: the contract is about *trees*, and
opsctl is one.

**The facts opsctl's `AGENTS.md` must declare** (the contract requires the
declaration; these are its values for this tree):

| fact | value |
|---|---|
| default-gate test command | `GOWORK=off go test ./...` from `opsctl/` |
| layers present | hermetic, manual |
| preconditions beyond the Go toolchain | a real `tar` binary on `PATH` |
| GOWORK mode | `GOWORK=off` (mirrors the production build) |

`tar` is a genuine precondition, not a convenience: the backup/restore ids
(D13, and the umbrella's `[proof: opsctl]` archive-boundary ids) assert on a
real archive listing, and per the contract its absence is a hard failure, never
a skip.

**Rejected.**

- *Treating the live-box ids as the contract's `live` layer, under
  `//go:build live`.* The live layer means "a real external service, using real
  credentials, from an ordinary `go test -tags live` run". These checks need
  root on the box, real uid/gid switching, and a real systemd unit — no
  credential makes them runnable from a developer's checkout. Filing them as
  live would promise an invocation that cannot exist. Rejected.
- *Leaving the manual checks in the Decision files only.* That is the status quo
  the contract names as the defect: eight ids saying "operator-verified" with no
  document stating what the operator does, what a *failing* run looks like, or
  where the result lands. Rejected.
- *A separate runbook per Decision.* Eight small documents fragment one
  operator session that runs them all in sequence against the same box; the
  precedent (`github/project/github-verification.md`) is one document per tree.
  Rejected.
- *Making the runbook prose-only, with no in-gate check that it stays true.* The
  suite's recurring failure mode is exactly a doc that silently stops matching
  the design it describes. A hermetic doc-truth test costs one test and makes
  drift a red gate. Rejected.
- *Proving deploy against real service binaries — a per-service
  `build<Svc>Artifact` boot test that compiles a sibling `./cmd/<svc>` and runs
  the binary through health.* This couples opsctl's gate to eight sibling trees'
  boot contracts: a service changing its own startup (for instance reading a
  credential from `state/` instead of the environment) reddens opsctl though
  nothing opsctl owns changed. And a compiled, executed service binary is
  neither a temp-dir file nor a faked seam, so it breaks the hermetic contract
  above outright. The orchestration is proven against the fake `System` seam;
  a service's own boot is that service's own tree's proof. Rejected.

**Verification.**

- R-O1AD-MRKW [cited from `root project/design/D23.md`, `[proof: per-service]`]
  — a test reads the committed `opsctl/AGENTS.md` from disk and asserts its
  Tests section declares the default-gate test command, the layers present
  (naming `hermetic` and `manual`, and no layer this tree does not have), the
  environmental preconditions beyond the Go toolchain (`tar`), and the GOWORK
  mode (`GOWORK=off`) — a build that edits `AGENTS.md` into disagreement with
  this Decision fails the gate. Substrate: hermetic (real committed file read
  from disk).
- R-O2IA-0JBL [cited from `root project/design/D23.md`, `[proof: per-service]`]
  — a source scan over `opsctl/**/*_test.go`, excluding any file carrying the
  `live` build constraint, finds **zero** occurrences of `t.Skip`, `t.Skipf`, or
  `t.SkipNow`; the scan assembles its needle from parts so the scanning file
  never matches itself. Substrate: hermetic (source scan).
- R-2B4O-Z98N — the committed runbook `opsctl/project/opsctl-verification.md`
  covers **every** manual-layer id: a test collects the ids from
  `opsctl/project/design/D*.md` whose Verification entry marks them
  real-substrate/live-box, reads the runbook, and asserts each such id appears
  in it — and asserts the runbook names, for each, both a positive and a
  negative check. Adding a ninth live-box id to a Decision without adding its
  runbook entry fails; a runbook entry that states only the positive check
  fails. Substrate: hermetic (real committed files read from disk).
- R-E639-DSH5 — a source scan over opsctl's `*_test.go` files finds **zero**
  constructions that build a sibling service: zero three-parent path escapes
  (`../../..`) resolving a sibling service tree, and zero `go build ./cmd/<name>`
  invocations of one; the scan assembles its needle from parts so the scanning
  file never matches itself. Re-introducing a `build<Svc>Artifact` helper that
  compiles a sibling `./cmd/<svc>` fails the gate. Substrate: hermetic (source
  scan).
