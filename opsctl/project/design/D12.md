# Decision 12 — `cache/` is app-owned by construction: setup creates it owned by the service user; deploy re-asserts it alongside `state/`

## Decision

The `cache/` dir holds the generation sidecar
(`/opt/<app>/cache/<app>.db.generation`, `Layout.GenerationPath()`), which the
service binary opens for write **as the unprivileged `<app>` user** at serve
start. Today two verbs leave it root-owned and the unit crash-loops:

- **setup** creates `CacheDir()` with `mkdirAll755` as root in all three tree
  branches (DEFAULT, worker, fragment) and never hands it to the app user —
  the June 2026 telemetry first-deploy failed exactly this way
  (`generation sidecar: open …: permission denied`, restart-looped to start
  limit).
- **deploy** runs the root-run `migrate` (which can create or touch the
  sidecar as root, per the same reasoning D8 records for the DB and its
  `-wal`/`-shm`) and then hands back **only** `state/`; `cache/` keeps whatever
  root-owned content migrate left.

The other two tree-rebuilding verbs already honor app ownership — restore
recreates `cache/` owned `<app>:<app>` (D1) and rollback chowns `CacheDir()`
before restart — so this Decision closes the remaining two verbs to make the
invariant hold everywhere: **any verb that creates `cache/` or runs a
root-privileged step that may write into it leaves it owned `<app>:<app>`.**

Two changes, both in `internal/opsctl`:

1. **setup** — after creating the tree, every branch (DEFAULT, worker,
   fragment) hands `cache/` to the app user:

   ```go
   if err := o.System.ChownTree(ctx, app, app, l.CacheDir()); err != nil {
       return fmt.Errorf("setup: chown cache dir: %w", err)
   }
   ```

2. **deploy** — the existing post-migrate hand-back grows a sibling, exactly
   as unconditional and idempotent as the `state/` sweep and for the same
   reason:

   ```go
   o.logf("chown %s -> %s:%s", l.CacheDir(), app, app)
   if err := o.System.ChownTree(ctx, app, app, l.CacheDir()); err != nil {
       return fmt.Errorf("deploy: chown cache dir: %w", err)
   }
   ```

No layout change, no mode change (`cache/` stays 0755), no change to restore
(D1), rollback, or any other verb.

## Rejected

- **Fixing setup only.** The root-run `migrate` in deploy can still create or
  reclaim the sidecar as root inside an app-owned dir; only deploy's
  unconditional re-assert reclaims that on every deploy, mirroring the D8
  rationale for `state/`.
- **Fixing deploy only.** A freshly set-up service would still carry a
  root-owned `cache/` between `setup` and its first `deploy`; setup leaving a
  tree the service user cannot use contradicts setup's purpose of provisioning
  a servable tree, and D1/rollback already model creation-time ownership.
- **Moving the generation sidecar into `state/`** so the existing sweep covers
  it. A layout change rippling through appkit's env contract
  (`<APP>_GENERATION_PATH`), convert, restore, and rollback — far larger than
  the two one-line chowns, for no behavioral gain.
- **Chowning the single sidecar file instead of the tree.** The dir itself
  must be app-writable for the service to create the file at first serve; a
  file-scoped chown fixes only the already-exists case.

## Verification

- R-4ZI0-4CH5 — `setup` leaves `cache/` owned by the service user in **all
  three** tree branches: after a fragment-mode, a worker-mode, and a DEFAULT
  (`IsDefault`) setup run against the faked seams, the recorded `ChownTree`
  calls include `(app, app, CacheDir())` in each mode — a build that chowns
  cache in some branches but not others fails the uncovered branch.
- R-50PW-I47U — `deploy` re-asserts cache ownership after the root-run
  migrate: the recorded seam calls show `ChownTree(app, app, CacheDir())`
  invoked **after** the migrate step and **before** the unit restart, on an
  ordinary successful deploy (no special flag, no first-deploy condition) —
  a build that chowns only `state/` fails, as does one that chowns cache
  before migrate runs.
