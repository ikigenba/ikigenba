# Nginx author review — pending independent verification

## Canonical consumer usage

No nginx implementation existed in the previous D01–D05 design. The replacement target offers these complete operator tasks:

```sh
opsctl nginx --help
opsctl nginx -h
sudo opsctl config set host.name=ikigenba.dev
sudo opsctl nginx show
sudo opsctl nginx apply
sudo opsctl nginx apply
```

Both help forms print the exact story help for any user. `show` prints the frame on a bare host; with the story's crm/dashboard/gmail filesystem fixture it prints the exact application example, excluding gmail. Neither preview writes files or runs a process. Both applies publish identical generated bytes, test, and reload, returning no output on success. The host must already have nginx, systemctl, and the certificate; their absence is not silently repaired by nginx.

Complete package task, called within this module after CLI configuration loading:

```go
func previewThenApply(ctx context.Context, env host.Env, hostName string, out io.Writer) error {
    candidate, err := nginx.Render(ctx, env, hostName)
    if err != nil {
        return err
    }
    if _, err = out.Write(candidate); err != nil {
        return err
    }
    return nginx.Apply(ctx, env, hostName)
}
```

`nginx.Render` and `nginx.Apply` are declared in D06; `host.Env` in D01; context and io are standard library. This task shows two separate operations; apply re-discovers and re-renders, so changes between calls affect its candidate. CLI itself uses only one call for each user command.

Failure tasks:

```sh
sudo opsctl config del host.name
sudo opsctl nginx show
sudo opsctl nginx apply
sudo opsctl nginx
sudo opsctl nginx reload
```

The first two nginx commands each exit 1 with exactly `opsctl: host.name not set` plus LF on stderr. The latter two exit 2 with the respective missing/unknown diagnostic, one blank line, and the help hint. None changes host state. After configuring host.name but before obtaining a certificate, apply publishes then tests; if nginx rejects it, apply restores the old bytes/mode or previous absence and does not reload. Its failure line is `opsctl: nginx -t: exit status 1`; captured external lines follow one blank line, each prefixed `> `.

Preview/apply with multiple routed defaults or malformed manifests now reject without rendering or effects under R-G1J4-VLO8; [input ambiguities](resolved-nginx-input-ambiguities.md) records the root resolution. Complete corrected failure tasks appear in [webhost-corrections.md](webhost-corrections.md). Unresolved beside affected tasks: Apply after a successful test but failed reload follows [reload failure state](../issues/nginx-reload-failure.md). These are partial branches, not permission to infer behavior.

## Shared boundaries and evidence

D01 boundary coordinator confirmed `host.Env` carrying Root/Getenv/Execute/Now; `host.Command`, `host.Result`, and `*host.CommandError{Label, Result, Err}`; command failure means execution error or nonzero Result.ExitCode. D06 uses these names and owns no competing execution error type. D02 owns root check, common errors, and quoted captured output. No live execution fallback is introduced.

D08 coordinator confirmed `apps.Discover(root string) ([]Service,error)`, `Service{Name string, Manifest *Manifest, ManifestError error}`, `Manifest.Port int` (zero means absent), and `Manifest.Default bool`. Discovery supplies the name-sorted etc-or-state directory inventory. D06 renders valid parsed manifests with at most one routed default and rejects malformed manifests or conflicting defaults under R-G1J4-VLO8. CLI loads `config.Store` from D03; D06 passes hostName into the domain rather than importing config.

The parent collected live installed-tool help in [webhost-live-help.txt](webhost-live-help.txt), supporting nginx test grammar and systemctl reload availability. It reported no existing generated config evidence. Actual TLS rejection, wildcard/glob acceptance, certificate-path acceptance, and reload behavior of the generated bytes still require observations on the real host before check-spec; help output alone does not establish these effects. This author performed no live mutations and inspected no sibling internals.

The missing-certificate story displays unquoted nginx lines. Applicable AGENTS explicitly requires every line of another program's output to carry `> `. The parent instructed using that convention, and D06 does so; captured nginx content is not hardcoded as an opsctl-owned message.
