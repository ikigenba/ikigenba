# D06-nginx

The nginx configuration is generated from the host name, the apex app, the
discovered services, and which of them systemd reports disabled. A read-only preview, a write-only regeneration, and an
apply operation share the same rendering contract. Restore uses regeneration
without testing or reloading nginx; its sequencing belongs to D14.

Two configuration keys drive the rendering. `host.name` is the space's own
name; every routed service answers at `<name>.<host.name>`, and the one whose
manifest sets `default` answers at `host.name` as well. `host.apex` names the
app that answers at the parent of `host.name`: the apex hostname is never
stored, it is derived by D01's `host.Apex`, which refuses a host name with no
parent. The apex choice is independent of the manifest default, so one app may
hold the space's name and another the apex, or one app both. When the named app
is not routed, the apex name sits on the 404 block beside the space's name and
wildcard, so it answers 404 under the host's certificate rather than falling
to the handshake-rejecting default block. A `host.apex` set on a host whose
name has no parent is refused by every operation that reads it, before
anything is rendered, written, or executed. The CLI hands the domain
operations the stored `host.name` as D01's `host.NormalizeName` spells it,
so the name in the configuration, the lineage path, and the refusal is the
same one every other command uses.

No app listens on a TCP port. Every routed app is proxied to its Unix socket,
`/run/ikigenba/<name>.sock`, held by its socket unit (D09); a service is
routed when its manifest names its app. A routed app whose socket unit
systemd reports disabled (D10's `Disabled`) keeps its block and every name it
answers at, but the block answers 503 and proxies nowhere, so a disabled app
reads as unavailable rather than missing. Rendering therefore asks systemd,
read-only, about each routed app; `show` still writes nothing. nginx gives
every request one id: `X-Request-Id` is set to `$request_id` on every proxied
request and on the authenticator subrequest, overwriting the client's, and
the same id ends each access-log line in the generated `ikigenba` format.

A routed service named `auth` is the platform's authenticator, recognized by
its routed manifest and not its name alone. Its presence rewrites every other
routed service's block into the wired shape: a request reaches the app only
after an internal subrequest to the authenticator's `/check` answers it a valid
session; the client can forge no identity, because the subrequest carries none
and the app receives only what the authenticator returned; an absent session
becomes a redirect to the authenticator's sign-in host, while a refused one
passes through. The authenticator's own block stays unwired and answers its
public `/check` with 404, so the real check is reachable only as that
subrequest. With no routed `auth` on the host, every block is the plain proxy —
fail-open by honest absence, not a per-app choice. The authenticator is another
sub-project, reached only as an external tool through the published interface it
exposes; this design encodes only that observed grammar, never its internals.

Apply brings nginx to the generated configuration with
`systemctl reload-or-restart nginx`, which systemctl(1) documents as reloading a
unit that supports reload, and starting one that is not running. nginx's unit
declares `ExecReload`, so a running nginx is reloaded and keeps its connections,
while a host whose first boot enabled nginx without starting it comes up here
rather than failing init. `Update` is the conditional form `disable` and `enable` use: it publishes,
tests and reloads only when the rendered bytes differ from the file in place,
and reports whether it did, so an idempotent disable or enable reloads
nothing.

Application manifests belong to D08; the host
execution seam and the apex derivation belong to D01, and init sequencing
belongs to D05.
