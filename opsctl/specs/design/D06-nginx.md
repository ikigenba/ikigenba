# D06-nginx

The nginx configuration is generated from the host name and discovered services.
A read-only preview, write-only regeneration, and an apply operation share the
same rendering contract. Restore uses regeneration without testing or reloading
nginx; its sequencing belongs to D14.

Apply brings nginx to the generated configuration with
`systemctl reload-or-restart nginx`, which systemctl(1) documents as reloading a
unit that supports reload, and starting one that is not running. nginx's unit
declares `ExecReload`, so a running nginx is reloaded and keeps its connections,
while a host whose first boot enabled nginx without starting it comes up here
rather than failing init; see `specs/review/nginx-inactive-at-init-2026-09-17.md`.
Application manifests belong to D08; the host execution seam belongs to D01,
and init sequencing belongs to D05.

## REQUIREMENTS

- R-54PQ-5Q31: Package `internal/nginx` MUST own generation and application of `/etc/nginx/conf.d/ikigenba.conf`, depending within this module only on `internal/host` and `internal/apps`; `internal/cli` owns nginx command parsing, configuration-store reads, output, and exit codes.
- R-55XM-JHTQ: Package `internal/nginx` MUST export `Render(ctx context.Context, env host.Env, hostName string) ([]byte, error)`.
- R-575I-X9KF: Package `internal/nginx` MUST export `Apply(ctx context.Context, env host.Env, hostName string) error`.
- R-58DF-B1B4: `opsctl nginx --help` and `opsctl nginx -h` MUST, for every effective user id and without changing host state, exit 0, leave stderr empty, and write exactly `"Usage: opsctl nginx <subcommand>\n\nGenerate /etc/nginx/conf.d/ikigenba.conf from the configuration store and the\nservices under /opt. The file is generated, never edited; opsctl writes no\nother file under /etc/nginx.\n\nSubcommands:\n  show   print the configuration opsctl would write\n  apply  write the file, test it, and reload nginx\n\nConfiguration keys:\n  host.name  the fully-qualified name this host answers at\n\nA service is any /opt/<name>/ with an etc/ or state/ directory. One with an\netc/manifest.toml naming a port answers at <name>.<host.name>, and the one\nwhose manifest sets default answers at <host.name> as well. Its own\netc/nginx.conf, if it ships one, is included in its server block.\n"` to stdout; in the quoted string `\n` denotes one LF byte.
- R-FSNN-9FKB: `opsctl nginx` MUST accept the subcommands `show` and `apply`, each without options or positional arguments; a root invocation with no subcommand or an unknown subcommand MUST leave host state unchanged, write nothing to stdout, exit 2, and write exactly three LF-terminated stderr lines: respectively `opsctl: no nginx subcommand given` or `opsctl: unknown nginx subcommand '<name>'`, an empty line, and `see 'opsctl nginx --help' for usage`. A root invocation of `show` or `apply` with extra arguments or options MUST exit 2 with empty stdout and a D02 diagnostic before configuration reads, external execution, or state changes.
- R-5AT8-2KSI: Before invoking `Render` or `Apply` for a root `nginx show` or `nginx apply` command, `internal/cli` MUST obtain `host.name` from `config.Store` rooted at `Deps.Root`; an absent or empty value MUST cause exactly `opsctl: host.name not set` followed by LF on stderr, empty stdout, exit 1, and no host-state change.
- R-5C14-GCJ7: For a nonempty `hostName` and service manifests that parse successfully with at most one routed default, `Render` MUST return the configuration determined solely by `hostName` and `apps.Discover(env.Root)`, without writing files or executing commands; a service is routed exactly when its discovered `Manifest` is non-nil and its `Port` is nonzero, and the rendered service blocks follow ascending `Service.Name` order, omitting every unrouted service.
- R-5D90-U49W: For the successful input domain of `Render`, the generated bytes MUST begin with exactly `"# Generated by opsctl. Do not edit; run 'opsctl nginx apply'.\n\nserver {\n    listen      80 default_server;\n    listen      [::]:80 default_server;\n    server_name _;\n    return      301 https://$host$request_uri;\n}\n\nserver {\n    listen              443 ssl default_server;\n    listen              [::]:443 ssl default_server;\n    ssl_reject_handshake on;\n}\n\nserver {\n    listen              443 ssl;\n    server_name         {C};\n    ssl_certificate     /etc/letsencrypt/live/{H}/fullchain.pem;\n    ssl_certificate_key /etc/letsencrypt/live/{H}/privkey.pem;\n    return              404;\n}\n"` where `\n` denotes LF, `{H}` is `hostName`, and `{C}` is `hostName` followed by one space and `*.` followed by `hostName` when no routed service has `Manifest.Default` true, or just `*.` followed by `hostName` when one does; these substitutions affect only the marked placeholders.
- R-5EGX-7W0L: For each routed service, `Render` MUST append one LF followed by exactly `"server {\n    listen              443 ssl;\n    server_name         {S};\n    ssl_certificate     /etc/letsencrypt/live/{H}/fullchain.pem;\n    ssl_certificate_key /etc/letsencrypt/live/{H}/privkey.pem;\n\n    include /opt/{N}/etc/nginx.conf*;\n\n    location / {\n        proxy_pass       http://127.0.0.1:{P};\n        proxy_set_header Host              $host;\n        proxy_set_header X-Real-IP         $remote_addr;\n        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;\n        proxy_set_header X-Forwarded-Proto $scheme;\n    }\n}\n"` where `\n` denotes LF, `{H}` is `hostName`, `{N}` is `Service.Name`, `{P}` is the decimal `Manifest.Port`, and `{S}` is `<name>.<hostName>` with one space and `<hostName>` appended exactly when `Manifest.Default` is true; placeholders alone are substituted, and the include appears even when no app nginx fragment exists.
- R-5GWP-ZFHZ: For a root `opsctl nginx show` with a set nonempty `host.name`, `internal/cli` MUST call `Render` with that value and the host environment from `Deps`, write its successful returned bytes without alteration to stdout, leave stderr empty, and exit 0; failure MUST write no stdout, report the reason through the diagnostic convention of D02, and exit 1.
- R-5I4M-D78O: `Apply` MUST publish the successful bytes returned by `Render` at `/etc/nginx/conf.d/ikigenba.conf` under `env.Root` with mode `0644`, by writing a temporary file in that same directory and renaming it over the destination, so readers never observe a partial candidate; apart from that temporary file, cleaned up before return, and the destination, it MUST create, modify, and remove no file under `/etc/nginx`.
- R-2NUY-GTYW: After publishing a candidate, `Apply` MUST execute `nginx` with arguments `["-t"]` through `env.Execute` and, only if it returns no execution error and `ExitCode` 0, execute `systemctl` with arguments `["reload-or-restart", "nginx"]` through that same seam; it MUST return nil only when both commands succeed, MUST NOT execute `systemctl` with `stop`, `start`, or `restart` for nginx, and MUST repeat publication, testing, and the reload-or-restart on every call even when the rendered bytes equal the previous file.
- R-5KKF-4QQ2: When `nginx -t` fails by nonzero `ExitCode` or execution error after candidate publication, `Apply` MUST restore the previous destination bytes and file mode, or remove the candidate if the destination was previously absent, before returning failure, and MUST not invoke reload; if restoration itself fails it MUST return an error identifying both the original test failure and the restoration failure.
- R-2P2U-ULPL: A failed external command in `Apply` MUST return an error wrapping `*host.CommandError`, preserving the command's `Result` and execution error `Err`, with `Label` equal to `nginx -t` for the test or `systemctl reload-or-restart nginx` for the reload-or-restart; the CLI MUST format that failure using D02, with `opsctl: ` followed by its error text on the first diagnostic line and any captured external output after exactly one blank line, each output line prefixed `> `; subprocess success output MUST be suppressed.
- R-W6Y4-9GMN: For a root `opsctl nginx apply` with a set nonempty `host.name`, `internal/cli` MUST call `Apply` with that value and the host environment from `Deps`, leave stdout and stderr empty and exit 0 when it returns nil, and otherwise leave stdout empty, report the failure through D02, and exit 1.

- R-FTVJ-N7B0: A configuration-store read failure other than an unset or empty `host.name` during `nginx show` or `nginx apply` MUST cause exit 1 with empty stdout and a D02 diagnostic identifying the failure, without invoking `Render` or `Apply`, executing commands, or changing host state; corrupt configuration MUST retain its original bytes.
- R-G0B8-HTXJ: `Render` and `Apply` MUST propagate discovery, rendering, and filesystem errors as operational failures rather than returning success or incomplete configuration; failed `Render` MUST return no candidate bytes. If preparation of an `Apply` candidate fails, the destination MUST retain its previous bytes and mode or previous absence; unsuccessful preparation or publication MUST return an error, clean up any candidate temporary file, and invoke neither `nginx -t` nor reload. For standalone `opsctl nginx show` and `opsctl nginx apply`, the CLI MUST leave stdout empty, report the failure through D02, and exit 1; composed callers MUST apply their own command's output and exit policy to the propagated error.
- R-G1J4-VLO8: When `apps.Discover` returns any service with non-nil `ManifestError`, or more than one routed service with `Manifest.Default` true, `Render` and `Apply` MUST reject the input before rendering a candidate, emitting output, writing files, or invoking `env.Execute`, return an operational error identifying the malformed service and its manifest failure or the conflicting default services respectively, and leave host state unchanged; `Render` MUST return no candidate bytes. For standalone `opsctl nginx show` and `opsctl nginx apply`, the CLI MUST report the reason through D02 with empty stdout and exit 1; composed callers MUST apply their own command's output and exit policy to the propagated error; no service may be selected as the default to resolve a conflict.

- R-QC9K-4BIS: Package `internal/nginx` MUST export `Write(ctx context.Context, env host.Env, hostName string) error`.
- R-QDHG-I39H: `Write` MUST publish the successful bytes returned by `Render` at `/etc/nginx/conf.d/ikigenba.conf` under `env.Root` with mode `0644`, by writing a temporary file in that same directory and renaming it over the destination, so readers never observe a partial candidate; apart from that temporary file, cleaned up before return, and the destination, it MUST create, modify, and remove no file under `/etc/nginx`.
- R-QEPC-VV06: `Write` MUST invoke no external command, including through `env.Execute`, and MUST return nil after successful publication without testing the configuration or reloading, stopping, starting, or restarting nginx, even when the generated bytes equal the previous file.
- R-QFX9-9MQV: `Write` MUST propagate `Render` failures, including discovery errors, malformed service manifests, and conflicting routed defaults, as operational errors without writing a candidate or changing host state; preparation or publication failure MUST return an error, preserve the destination's previous bytes and mode or previous absence, and clean up any candidate temporary file before return.
