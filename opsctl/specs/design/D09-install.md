# D09-install

Installation turns an S3 artifact and host-local configuration into a running app.
The CLI composes routing and replication between installation and app startup.
Every attempted artifact download reports its success or failure. Installation
and restart report service completion; status separately reports host facts.
App-owned persistent data survives installation. The installed trees belong to
root and the service account reaches them through its group, so the app can
run and read its configuration but cannot write `bin/`, `etc/`, or `share/` or
the files in them, while `/opt/<app>` itself stays writable by the account so
the app can create `state/` and `cache/`.

- R-YNIK-9QOD: Package `internal/apps` MUST export `InstallHooks` as a struct with exactly `Report func(step, detail string, success bool) error` and `Configure func(context.Context, Manifest) error` fields.
- R-OLR2-NBFZ: Package `internal/apps` MUST export `Install(ctx context.Context, env host.Env, remote cloud.Env, store config.Store, uri string, hooks InstallHooks) error`.
- R-OMYZ-136O: Package `internal/apps` MUST export `InstallError` as a struct with exactly `Code int`, `Message string`, and `Cause error` fields; `(*InstallError).Error() string` MUST return `Message`, and `(*InstallError).Unwrap() error` MUST return `Cause`.
- R-ZZZM-YX8L: `opsctl install --help` and `opsctl install -h` MUST, for any effective user id, leave host state unchanged, perform no host-file access, command execution or cloud call, exit 0 with empty stderr, and write exactly "Usage: opsctl install URI\n\nInstall the app at URI, an s3:// object holding an <app>-<tag>.tar.xz built by\ndevctl. The app name, its port, and the secrets it needs are read from\netc/manifest.toml inside it; the secret values are read from the parameter\n/ikigenba/<host.name>/<app>.\n\nNothing under /opt/<app>/state/ or /opt/<app>/cache/ is touched, so installing\nover a running app keeps its data. - R-OPER-SMO2: The install action MUST accept exactly one absolute `s3://` URI with a nonempty bucket and object key and no userinfo, port, opaque form, query or fragment; before any host access, missing operands, multiple operands, and an invalid URI MUST respectively exit 2 with empty stdout and the three LF-terminated stderr lines `opsctl: install needs URI`, an empty line, `see 'opsctl install --help' for usage`, substituting `opsctl: install takes one URI` or `opsctl: install takes an s3:// URI` for the first line in the latter two cases.
- R-H3LD-O3WP: `Install` MUST reject invalid URI input, nil `hooks.Report` or `hooks.Configure`, or missing or empty `host.name` or `aws.region` before fetching or mutation; missing configuration MUST identify `<key> not set`; for valid configuration it MUST fetch the supplied object through `remote.Open` using `aws.region` and `Client.GetObject`, using the host cloud credentials and never receiving artifact bytes from command stdin or fetching secret values from the artifact.
- R-OT2G-XXW5: `Install` MUST validate the complete xz-compressed tar input before changing installed host state: it MUST require `etc/manifest.toml` parsed through `ParseManifest`, a nonempty `Manifest.App` accepted by `ValidateName`, a nonzero `Manifest.Port`, and an executable regular `bin/<app>`; it MUST accept optional `share/` and additional files under `bin/` and `etc/`, reject content outside those three top-level directories, duplicate archive paths, links, special files, absolute paths and `.` or `..` path components, and never follow an existing destination symlink to write outside the intended installed tree.
- R-OUAD-BPMU: Before changing installed host state, `Install` MUST use `Discover` to inspect every service manifest and reject discovery or per-service manifest failures; when the incoming manifest is default, it MUST reject any different service whose manifest is default with `<app>: <other> is already the default app`, while permitting replacement of the same default app and permitting a host with no default.
- R-OVI9-PHDJ: After artifact and default validation but before mutation, `Install` MUST obtain every distinct name in `Manifest.Secrets` from `/ikigenba/<host.name>/<app>` through `Client.ReadSecrets`; it MUST skip the parameter read for an empty secret list, omit unrequested parameter keys, and treat a missing parameter as containing no keys, reporting the first missing name in manifest order as `<app>: no value for '<name>' in /ikigenba/<host.name>/<app>`; an empty present value MUST count as present.
- R-OWQ6-3948: `Install` MUST validate that secret and plain-setting names match `[A-Za-z_][A-Za-z0-9_]*`, that neither source defines `PORT`, that the two sources have no overlapping names, and that values contain no NUL, CR or LF, rejecting violations before mutation without printing their values; the installed `etc/env` MUST have mode `0600`, one LF-terminated `NAME=value` entry per requested secret and plain setting plus `PORT` with the decimal manifest port, with values encoded for systemd EnvironmentFile syntax to preserve their literal value and no other parameter keys.
- R-OXY2-H0UX: After all artifact, default and secret validation succeeds, `Install` MUST replace `/opt/<app>/bin/`, `/opt/<app>/etc/`, and `/opt/<app>/share/` with the artifact contents, removing stale installed contents including an old share directory when the new archive omits it, and publish the generated `etc/env`; it MUST neither create nor touch `/opt/<app>/state/` or `/opt/<app>/cache/`, modify any other service's files or unit, run a schema migration, create a database, or load seed data.
- R-EPO4-BRY5: When `/opt` is absent under `env.Root`, `Install` MUST create it directly under `env.Root` owned by root with mode `0755`; an existing `/opt` MUST be left unchanged in ownership and mode.
- R-EKSI-SOZD: `Install` MUST publish `/etc/systemd/system/ikigenba-<app>.service` with `ExecStart=/opt/<app>/bin/<app>`, `WorkingDirectory=/opt/<app>`, `EnvironmentFile=/opt/<app>/etc/env`, `User=ikigenba`, `Restart=on-failure`, and installation wanted by `multi-user.target`; it MUST ensure a non-root system account named `ikigenba` exists without a login shell or creating a home directory and that a group named `ikigenba` is that account's primary group: when the account is absent it MUST create it by executing `useradd --system --no-create-home --shell /usr/sbin/nologin --user-group ikigenba` through `env.Execute`, and when the account exists it MUST determine the account's primary group name by executing `id --group --name ikigenba` through `env.Execute` and fail the unit stage, preserving the underlying error in `InstallError.Cause`, when that name is not `ikigenba`. It MUST execute `systemctl daemon-reload` and then `systemctl enable ikigenba-<app>.service` before reporting the unit complete. All host paths MUST follow D01's root boundary, including paths embedded in generated unit files. The `/opt/<app>` directory MUST be writable by that account so the app can create its own state and cache at startup, without creating or changing either directory during installation.
- R-EM0F-6GQ2: After every successful install, including one over an already installed app, every directory at or under `/opt/<app>/bin/`, `/opt/<app>/etc/`, and `/opt/<app>/share/` when present MUST be owned by user `root` and group `ikigenba` with mode `0750`, and every regular file beneath them MUST be owned by user `root` and group `ikigenba` with mode `0750` when its archived mode carried any execute bit and `0640` otherwise, except `etc/env`, which keeps mode `0600`; establishing that shape MUST NOT change anything under `/opt/<app>/state/` or `/opt/<app>/cache/`, and `/opt/<app>` itself MUST keep the ownership by the `ikigenba` account and the writability the unit stage gives it.
- R-EN8B-K8GR: In the unit stage, after account preparation succeeds and before the successful unit report, `Install` MUST apply installed-tree ownership through exactly one coreutils `chown --recursive root:ikigenba` invocation executed through `env.Execute`, naming exactly the existing trees `/opt/<app>/bin`, `/opt/<app>/etc`, and `/opt/<app>/share` in that order, each resolved under `env.Root`, and naming no path under `/opt/<app>/state/` or `/opt/<app>/cache/`; it MUST apply the installed-tree directory and file modes directly under `env.Root` so a test observes them with `Lstat`.
- R-EOG7-Y07G: A failure applying installed-tree ownership or modes MUST be the unit stage's failed outcome with the underlying error preserved in `InstallError.Cause`, and `Install` MUST emit no successful unit report after such a failure.
- R-P0DV-8KCB: `Install` MUST call `hooks.Configure` exactly once with the installed manifest after unit publication and enablement and before starting or restarting the app; the CLI-supplied callback MUST call `nginx.Apply` with `host.name`, report nginx completion only after success, then call `backup.Regenerate`, execute `systemctl restart litestream.service` exactly when regeneration returned changed, and report Litestream completion only after all required actions succeed; any failure MUST prevent later actions, including app start.
- R-P1LR-MC30: After successful configuration, `Install` MUST execute `systemctl restart ikigenba-<app>.service` when that app's unit was active at invocation and `systemctl start ikigenba-<app>.service` otherwise, determine the resulting unit state from systemd, and report success only for `active`; the installed binary invoked with `--version` MUST supply the reported version, with its trailing line ending removed, without inferring it from the URI, archive name, manifest or a remote record.
- R-P2TO-03TP: `Install` MUST send successful reports through `hooks.Report` only after the corresponding result holds, in the order `file`, `secrets`, `unpack`, `unit`, then the CLI callback's `nginx` and `litestream` reports, then `service`; details MUST be `<app>, port <port>` with `, default` appended for a default app, `<count> keys` counting distinct requested secrets, `/opt/<app>`, `ikigenba-<app>.service`, `<app>.<host.name>` with `, <host.name>` appended for a default app, the database's service-relative path when replication configuration changed or `unchanged` when it did not, and `<app> <version> active`, respectively. - R-UAOX-761Q: The file stage of `Install` MUST include complete artifact validation, discovery of installed manifests, competing-default validation, and the initial app-unit state observation needed to select start or restart; only after all succeed MUST it emit the successful file report, before obtaining required secrets. A failure in those checks MUST emit one failed file outcome and prevent the secrets stage and installed-state mutation. Failure of either file report callback MUST stop installation without retrying the report.
- R-OL1Q-ZER1: Throughout installation, the install operation and its CLI composition MUST NOT intentionally serialize secret or plain-setting environment values into reports, stdout, stderr diagnostics, or subprocess arguments on success or failure; key names, counts and separately specified manifest metadata such as the app name and port MUST remain reportable in their declared formats. This constraint governs emitting environment values as such, not coincidental matching bytes in metadata or relaying externally produced diagnostics. External journal output MUST be preserved without redaction or suppression even when it contains environment values, with each line quoted after one blank line according to the diagnostic convention.
- R-EKWN-JXML: The fetch stage of `Install` MUST begin with `remote.Open` after valid command, hook, and configuration inputs, and report exactly one outcome through `hooks.Report` before artifact validation: success true only after GetObject returned a reader, the complete object was read, and the reader closed successfully, with detail `<object-basename>, <size> MiB`, size being the received byte count divided by 1048576 rounded to one decimal place; success false for Open, credential, GetObject, missing-object, incomplete-read, read, or close failures, with detail explaining the failure and `<object-basename>: no such object` for a missing object. - R-EM4J-XPDA: For every attempted install stage, Install or its Configure callback MUST invoke its Report callback exactly once with that stage's outcome: success true renders exactly `<step>: ok (<detail>)` followed by LF to stdout, and success false renders exactly `<step>: failed: <detail>` followed by LF to stdout, where failed detail explains the stage failure with CR and LF replaced by literal `\r` and `\n` respectively. Unattempted later stages MUST emit nothing. Successful installation MUST exit 0 with empty stderr and end with `service: ok (<app> <version> active)` followed by LF, using the same three-value service format as restart; status retains its independent four-column D10 report. A report-write failure MUST fail the operation with Code 1, prevent later actions, and never retry or emit a second outcome for that stage.
- R-ENCG-BH3Z: After its fetch failure report succeeds, `Install` MUST return an `InstallError` with Message `artifact download failed` and Code 2 for a missing object or Code 1 for any other fetch failure. Missing manifests MUST produce Code 2 with failure reason `<object-basename>: no etc/manifest.toml in the file`; malformed manifests MUST produce Code 2 with reason `<object-basename>: etc/manifest.toml: <decoder complaint>`; unusable manifest names MUST produce Code 2 with reason `'<name>' is not a usable app name`; these artifact failures MUST emit a failed file outcome, leave installed host state unchanged, and emit no successful file or later-stage report. A fetch-report callback failure MUST instead return Code 1 while preserving any fetch failure through Cause.
- R-EOKC-P8UO: `Install` MUST return invalid archive/layout/manifest/URI failures as `InstallError` with Code 2 and operational failures, including configuration reads, cloud access other than missing objects, missing secrets, competing default, subprocess failures, callback failures and filesystem failures, with Code 1. For failure of an attempted workflow stage, the CLI MUST retain reports already written and write `opsctl: artifact download failed` followed by LF for a fetch failure or `opsctl: install failed` followed by LF for another stage failure; it MUST not copy the failed report or repeat its reason on stderr. External process failures MUST preserve host.CommandError in Cause and retain D02 quoted external detail, including the separately specified startup journal; cloud and report-write causes MUST not be automatically rendered as duplicate diagnostic reasons. A failure before the workflow begins MUST instead emit Message prefixed by `opsctl: ` and LF with no stage report. The CLI MUST return Code.
- R-P8X5-WYJ6: When app start or restart fails, or the resulting unit is not active, `Install` MUST fail with Message `<app>: service failed to start`, obtain that unit's journal through `env.Execute` using `journalctl --unit ikigenba-<app>.service --no-pager --lines 50`, and preserve its output for CLI detail after one blank line with each line prefixed `> `; failure to obtain the journal MUST retain the original start failure and identify the journal failure without printing a successful service report.
- R-PA52-AQ9V: A failure after installed files have been changed MUST stop subsequent work and retain completed installation effects without rollback, except for the rollback that `nginx.Apply` itself promises; a failed app MUST therefore retain its unpacked files, enabled unit and completed nginx and replication changes, and successful reinstallation of the same artifact MUST repeat the install reports and succeed while preserving state and cache and leaving byte-identical Litestream configuration and its unit untouched.

- R-AJZ2-XSUE: Install MUST attempt the existing stages in order fetch, file, secrets, unpack, unit, nginx, litestream, service, stopping at the first action or report failure. Install owns fetch, file, secrets, unpack, unit and service outcomes; the CLI Configure callback owns nginx and litestream outcomes and MUST propagate failure without Install inventing an additional stage outcome. The secrets stage includes parameter retrieval and environment-name/value validation; unpack includes installed-directory replacement and environment publication; unit includes account preparation, installed-tree ownership and mode application, unit publication, daemon reload and enablement; nginx includes nginx.Apply; litestream includes backup.Regenerate and any required restart; service includes app start/restart, resulting-state confirmation and binary-version reporting. Each failed stage MUST supply its failure reason to Report and preserve its underlying error in InstallError.Cause; a report callback error MUST stop work and preserve both errors when the stage also failed.
