# D12-service-backup

Service file backups preserve ordinary service data while Litestream owns the
declared databases. Init generates the file-backup schedules and the host's sole
certificate-renewal schedule from configuration.

## REQUIREMENTS

- R-FJVO-5X9J: Package `internal/backup` MUST export `SetupTimers(ctx context.Context, env host.Env, store config.Store) error`.
- R-FMBG-XGQX: `SetupTimers` MUST generate `ikigenba-backup-host.service`, `ikigenba-backup-services.service`, and `ikigenba-renew-certificate.service` under `/etc/systemd/system/` resolved under `env.Root`, as root oneshot services whose commands are respectively `/usr/local/bin/opsctl host backup`, `/usr/local/bin/opsctl backup`, and `certbot renew`; renewal MUST retain certbot's recorded hooks without replacing their behavior.
- R-FNJD-B8HM: `SetupTimers` MUST generate corresponding `.timer` files targeting those services under the same directory, with file-backup periods taken respectively from `backup.host_files_seconds` and `backup.service_files_seconds`; a positive decimal whole-second period MUST schedule its service after that many seconds from boot and that many seconds after its last activation, while absent, empty, or `0` periods MUST leave the pair present with its timer disabled and stopped and its service available for manual start; malformed or negative periods MUST return an error identifying the key before any unit file or unit state changes.
- R-FOR9-P08B: The generated renewal timer MUST use `OnCalendar=*-*-* 00,12:00:00`, `RandomizedDelaySec=1h`, and `Persistent=true`, target `ikigenba-renew-certificate.service`, and remain enabled and active independently of every backup period; no configuration key MUST disable renewal.
- R-FPZ6-2RZ0: `SetupTimers` MUST publish complete generated unit files, replacing prior generated content so configuration changes take effect on rerun, execute `systemctl daemon-reload` after publication, and reconcile each positive-period file-backup timer and the renewal timer by enabling and restarting it, and each zero or absent-period file-backup timer by disabling and stopping it; it MUST NOT start a backup service or write a backup object itself.
- R-FR72-GJPP: When the package-provided `certbot-renew.timer` exists, successful `SetupTimers` MUST leave it stopped and masked so only the generated renewal timer schedules renewal; absence of that package timer MUST be successful and MUST NOT create a mask for a nonexistent package timer.
- R-FSEY-UBGE: `SetupTimers` MUST return filesystem, configuration-read, context-cancellation, and unit-operation failures as errors, representing execution failures and nonzero process exits with `host.CommandError`; it MUST perform no later setup action after a failure and MUST preserve earlier successful setup effects without rollback, while limiting writes to generated unit files and their systemd enablement or masking state under `env.Root`.

- R-D7XD-PK5R: Package `internal/backup` MUST export `Files(ctx context.Context, env host.Env, cloudEnv cloud.Env, store config.Store, service string) ([]FileResult, error)`.
- R-D95A-3BWG: Package `internal/backup` MUST export `FileResult` with exactly the fields `Service string`, `Object string`, `Size int64`, and `Err error`; `Object` MUST be the uploaded object's basename and `Size` its compressed byte count for a successful service, while `Err` MUST carry a failed service's reason.
- R-DAD6-H3N5: `Files` MUST require nonempty `backup.s3_uri` and `aws.region`, checking the prefix before region, and return respectively `backup.s3_uri not set` or `aws.region not set` when absent or empty before reading service data or accessing cloud objects; a malformed S3 prefix or configuration-read failure MUST likewise return an operational error without service reads or object writes, and all object access MUST remain below the configured host prefix.
- R-RPWA-HQD2: With empty `service`, `Files` MUST select exactly the services identified by `apps.Discover` in ascending bytewise name order, returning an empty successful result when none exist; with nonempty `service`, it MUST select only that service by the D08 directory criterion and manifest rules without reading any other service, returning `no service '<service>'` when it is absent or holds neither `etc/` nor `state/`; a service name that is empty as a directory component, `.` or `..`, contains a slash or NUL, or equals `host` or `deploy` MUST be rejected as an operational error before service access for an explicit operand; during all-service selection, discovery manifest reads MUST be permitted, but each discovered service whose name fails that directory-component validation MUST yield a failed service result before archive construction, service data reads other than discovery manifest reads, or access to its cloud object prefix, and inability to enumerate services MUST be an operational error.
- R-DCSZ-8N4J: Each successful `Files` result MUST correspond to exactly one zstd-compressed tar object containing the selected service's existing `etc/` and `state/` trees with service-relative member names, including `etc/env`, preserving file contents, directory structure, permissions, and symlink targets without dereferencing symlinks outside the selected trees; it MUST exclude `cache/`, `bin/`, `share/`, host `/etc/`, nginx output, and generated systemd unit files, and for a declared database exclude exactly the paths and metadata subtree returned by `DatabaseFiles`; absent manifest or database declarations MUST leave the complete ordinary `state/` tree included.
- R-DE0V-MEV8: `Files` MUST perform no local filesystem mutations, unit control, database checkpointing, replication reconfiguration, cloud deletion, or bucket-lifecycle modification; the tar represents the ordinary files encountered during its filesystem walk and MUST NOT promise a transactional snapshot with the separately replicated database.
- R-I3CZ-C0Q2: A selected service's manifest-read, manifest-decode, archive-read, compression, or upload failure MUST yield a failed `FileResult` for that service and MUST NOT prevent attempts for the remaining selected services unless a whole-run operational failure interrupts the run; a failed local read or archive construction MUST publish no object for that service, and every failure MUST leave previous backups and Litestream replication untouched; operational failures affecting the run as a whole MUST be returned through the separate error result, retaining all earlier service results and a failed `FileResult` if a service archive was being attempted when the failure occurred; no result MUST be added for an unattempted service, and whole-run interruption MUST prevent later service attempts.
- R-I252-Y8ZD: `opsctl backup` and `opsctl backup SERVICE` MUST invoke `Files` for all or the named service, respectively, and print one stdout line per returned result in service-name order, formatted `<service>: ok (<object>, <size> MiB)` for success with compressed bytes divided by 1048576 and rounded to one decimal place, or `<service>: failed: <reason>` for failure; a completed report MUST leave stderr empty and exit 0 exactly when every result succeeded, otherwise exit 1, while a whole-run operational error MUST preserve every returned service row on stdout, use the D02 stderr diagnostic convention, and exit 1. For an interruption during an attempted archive the diagnostic first line MUST be `opsctl: backup failed at <service>` using the interrupted service's name, and for an interruption between completed service attempts it MUST be `opsctl: backup failed`, without repeating report findings; a preworkflow error with no attempted archive MUST leave stdout empty and retain its specific reason in the diagnostic. Captured subprocess output MUST appear only in D02 quoted stderr detail.
- R-DHOK-RQ3B: The `backup` command MUST accept zero or one service operand, with any unsupported option or excess operand producing exit 2, empty stdout, and an opsctl diagnostic followed by one empty line and `see 'opsctl backup --help' for usage` on stderr, without reading service files or performing cloud or unit operations.
- R-DIWH-5HU0: `opsctl backup --help` and `opsctl backup -h` MUST print exactly `"Usage: opsctl backup [SERVICE]\n\nCopy every service's etc/ and state/ to the prefix in backup.s3_uri, under the\nservice's own name, or just SERVICE when one is named.\n\nNever copied: cache/, anything opsctl generates, and -- for a service that\ndeclares a [database] -- the database file, its -wal and -shm, and its\nlitestream metadata directory. Those are replicated continuously by\nlitestream.service. The host's own /etc/ is 'opsctl host backup'.\n\nA service declares its database with a [database] table in etc/manifest.toml\nnaming its engine and its path. 'opsctl init' writes the timer that runs this\nat backup.service_files_seconds.\n\nConfiguration keys:\n  aws.region      the region the backup bucket lives in\n  backup.s3_uri   the prefix this host backs up to\n"` to stdout, leave stderr empty, and exit 0 for any effective user id without reading or changing host state.
- R-ZMEX-3VL4: `Files` MUST sample `env.Now` once and use its UTC RFC3339Nano representation followed by `.tar.zst` as the basename of every object in that invocation, writing each below `<backup.s3_uri><service>/`; timestamps with zero fractional seconds MUST use the whole-second story spelling, ordinary later runs MUST form a new set at their newly sampled timestamp, and uploads MUST use the create-only `cloud.Client.PutObject` contract so a collision matching `cloud.ErrAlreadyExists` produces a failed service result while preserving the existing object rather than overwriting it or independently advancing that service's timestamp.

- R-Z9DH-5EZK: Service archives produced by `Files` MUST preserve each archived member's numeric user and group ownership in its tar metadata and, when a source identity has a local symbolic name, preserve that name as well; source members owned by the D09 `ikigenba` account MUST carry owner name `ikigenba` so ownership can be mapped to a rebuilt host rather than assuming stable numeric account IDs. Identity queries MUST use `env.Execute` under the D01 boundary; an identity-query execution failure MUST fail that service's archive without publishing an object, while an unmapped numeric identity MUST remain representable without a symbolic name.
