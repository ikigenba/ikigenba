# D12-service-backup

Service file backups preserve ordinary service data while Litestream owns the
declared databases. Init generates the file-backup schedules and the host's sole
certificate-renewal schedule from configuration.

A service archive holds only that service's `state/`, from its data directory
`/var/opt/ikigenba/<service>/state/`, named `state/...`. What a deploy brought
under `/opt/<service>/` comes back by deploying it again, and the service's
environment file under `/etc/opt/ikigenba/` is generated, so neither is
archived; a service backup reads nothing under `/etc/`, and of
`/opt/<service>/` only the manifest. `cache/` is never archived, wherever it
is. A service whose `state/` is still under
`/opt/<service>/` is not backed up or snapshotted at all: it fails with a
reason saying to install it first, and the other services go on. The services
file under `/var/lib/ikigenba/` is never archived, because it is regenerated
(D15, R-LZ82-QJF7).

A snapshot is the one artifact that carries a service's data whole. It holds
what a service archive holds, so no credential, with a copy of its database that litestream rebuilds from the
service's own replica into a temporary file, so nothing is stopped and the
live database is never touched. Snapshots live under `snapshots/<service>/`,
so `snapshots` and `seed` are reserved beside `host` and `deploy` as names
a service directory cannot take. Nothing takes a snapshot on a timer.

## REQUIREMENTS

- R-FJVO-5X9J: Package `internal/backup` MUST export `SetupTimers(ctx context.Context, env host.Env, store config.Store) error`.
- R-FMBG-XGQX: `SetupTimers` MUST generate `ikigenba-backup-host.service`, `ikigenba-backup-services.service`, and `ikigenba-renew-certificate.service` under `/etc/systemd/system/` resolved under `env.Root`, as root oneshot services whose commands are respectively `/usr/local/bin/opsctl host backup`, `/usr/local/bin/opsctl backup`, and `certbot renew`; renewal MUST retain certbot's recorded hooks without replacing their behavior.
- R-FNJD-B8HM: `SetupTimers` MUST generate corresponding `.timer` files targeting those services under the same directory, with file-backup periods taken respectively from `backup.host_files_seconds` and `backup.service_files_seconds`; a positive decimal whole-second period MUST schedule its service after that many seconds from boot and that many seconds after its last activation, while absent, empty, or `0` periods MUST leave the pair present with its timer disabled and stopped and its service available for manual start; malformed or negative periods MUST return an error identifying the key before any unit file or unit state changes.
- R-FOR9-P08B: The generated renewal timer MUST use `OnCalendar=*-*-* 00,12:00:00`, `RandomizedDelaySec=1h`, and `Persistent=true`, target `ikigenba-renew-certificate.service`, and remain enabled and active independently of every backup period; no configuration key MUST disable renewal.
- R-FPZ6-2RZ0: `SetupTimers` MUST publish complete generated unit files, replacing prior generated content so configuration changes take effect on rerun, execute `systemctl daemon-reload` after publication, and reconcile each positive-period file-backup timer and the renewal timer by enabling and restarting it, and each zero or absent-period file-backup timer by disabling and stopping it; it MUST NOT start a backup service or write a backup object itself.
- R-FR72-GJPP: When the package-provided `certbot-renew.timer` exists, successful `SetupTimers` MUST leave it stopped and masked so only the generated renewal timer schedules renewal; absence of that package timer MUST be successful and MUST NOT create a mask for a nonexistent package timer.
- R-FSEY-UBGE: `SetupTimers` MUST return filesystem, configuration-read, context-cancellation, and unit-operation failures as errors, representing execution failures and nonzero process exits with `host.CommandError`; it MUST perform no later setup action after a failure and MUST preserve earlier successful setup effects without rollback, while limiting writes to generated unit files and their systemd enablement or masking state under `env.Root`.

- R-D7XD-PK5R: Package `internal/backup` MUST export `Files(ctx context.Context, env host.Env, cloudEnv cloud.Env, store config.Store, service string) ([]FileResult, error)`.
- R-Z4RN-NCQP: Package `internal/backup` MUST export `FileResult` with the fields `Service string`, `Object string`, `Size int64`, and `Err error`; `Object` MUST be the uploaded object's basename and `Size` its compressed byte count for a successful service, while `Err` MUST carry a failed service's reason.
- R-DAD6-H3N5: `Files` MUST require nonempty `backup.s3_uri` and `aws.region`, checking the prefix before region, and return respectively `backup.s3_uri not set` or `aws.region not set` when absent or empty before reading service data or accessing cloud objects; a malformed S3 prefix or configuration-read failure MUST likewise return an operational error without service reads or object writes, and all object access MUST remain below the configured host prefix.
- R-T7OU-NQ6M: With empty `service`, `Files` MUST select exactly the services identified by `apps.Discover` in ascending bytewise name order, returning an empty successful result when none exist; with nonempty `service`, it MUST select only that service by the `Discover` criterion of D08 R-G6SM-I0K3 and manifest rules without reading any other service, returning `no service '<service>'` when neither `/opt/<service>/etc/` nor `/var/opt/ikigenba/<service>/state/` exists, a `/opt/<service>/state/` by itself not making `<service>` a service; a service name that is empty as a directory component, `.` or `..`, contains a slash or NUL, or equals `host`, `deploy`, `snapshots`, or `seed` MUST be rejected as an operational error before service access for an explicit operand; during all-service selection, discovery manifest reads MUST be permitted, but each discovered service whose name fails that directory-component validation MUST yield a failed service result before archive construction, service data reads other than discovery manifest reads, or access to its cloud object prefix, and inability to enumerate services MUST be an operational error.
- R-F70X-J1QC: Each successful `Files` result MUST correspond to exactly one zstd-compressed tar object holding the existing `state/` tree of the selected service's data directory (D08 R-YW93-ZIXT), `/var/opt/ikigenba/<service>/state/`, as members named `state/...`, and no other member, preserving file contents, directory structure, permissions, and symlink targets without dereferencing symlinks outside that tree; it MUST hold no `etc/` member and nothing from `/opt/<service>/` or from `/etc/opt/` (the service's environment file, D08 R-045H-R9MT, among it), MUST exclude `cache/`, host `/etc/`, nginx output, and generated systemd unit files, and for a declared database exactly the paths and metadata subtree returned by `DatabaseFiles`; absent manifest or database declarations MUST leave the complete ordinary `state/` tree included, and a data directory holding no `state/` MUST be represented by its absence, giving an object with no member. `Files` MUST read nothing under `/etc/`, and nothing under `/opt/<service>/` but its `etc/manifest.toml`, so an unreadable `/etc/opt/ikigenba/<service>/env` or `/opt/<service>/etc/` file other than the manifest MUST NOT fail the service.
- R-DE0V-MEV8: `Files` MUST perform no local filesystem mutations, unit control, database checkpointing, replication reconfiguration, cloud deletion, or bucket-lifecycle modification; the tar represents the ordinary files encountered during its filesystem walk and MUST NOT promise a transactional snapshot with the separately replicated database.
- R-I3CZ-C0Q2: A selected service's manifest-read, manifest-decode, archive-read, compression, or upload failure MUST yield a failed `FileResult` for that service and MUST NOT prevent attempts for the remaining selected services unless a whole-run operational failure interrupts the run; a failed local read or archive construction MUST publish no object for that service, and every failure MUST leave previous backups and Litestream replication untouched; operational failures affecting the run as a whole MUST be returned through the separate error result, retaining all earlier service results and a failed `FileResult` if a service archive was being attempted when the failure occurred; no result MUST be added for an unattempted service, and whole-run interruption MUST prevent later service attempts.
- R-F88T-WTH1: A failure reading a file under a service `Files` selected MUST give that service's `FileResult.Err` the text `<path>: <cause>`, where `<path>` is the file's canonical host path without `env.Root`, `/opt/<service>/etc/manifest.toml` for its manifest and under `/var/opt/ikigenba/<service>/state/` for a file of `state/`, and `<cause>` the operating system's description, so an unreadable `/var/opt/ikigenba/crm/state/outbox` gives `/var/opt/ikigenba/crm/state/outbox: permission denied` and `opsctl backup` prints `crm: failed: /var/opt/ikigenba/crm/state/outbox: permission denied`.
- R-JIF3-56FZ: For a selected service whose `/opt/<service>/state` exists under `env.Root` as a directory entry of any type, whatever `/var/opt/ikigenba/<service>/` holds, `Files` and `Snapshot` MUST each yield a failed result for that service whose `Err` text is exactly `/opt/<service>/state has not moved; install <service> first`, the path written as the host path rather than resolved under `env.Root`, before reading that service's files other than discovery manifest reads, invoking `litestream` for it, or accessing its cloud objects, and MUST publish no object for it, archive no part of it from either directory, and go on with the remaining selected services; so `opsctl backup` prints `crm: failed: /opt/crm/state has not moved; install crm first` among its rows and exits 1, and `opsctl snapshot` prints the same row. A `/opt/<service>/cache/` with no `/opt/<service>/state` beside it MUST NOT cause this failure.
- R-I252-Y8ZD: `opsctl backup` and `opsctl backup SERVICE` MUST invoke `Files` for all or the named service, respectively, and print one stdout line per returned result in service-name order, formatted `<service>: ok (<object>, <size> MiB)` for success with compressed bytes divided by 1048576 and rounded to one decimal place, or `<service>: failed: <reason>` for failure; a completed report MUST leave stderr empty and exit 0 exactly when every result succeeded, otherwise exit 1, while a whole-run operational error MUST preserve every returned service row on stdout, use the D02 stderr diagnostic convention, and exit 1. For an interruption during an attempted archive the diagnostic first line MUST be `opsctl: backup failed at <service>` using the interrupted service's name, and for an interruption between completed service attempts it MUST be `opsctl: backup failed`, without repeating report findings; a preworkflow error with no attempted archive MUST leave stdout empty and retain its specific reason in the diagnostic. Captured subprocess output MUST appear only in D02 quoted stderr detail.
- R-DHOK-RQ3B: The `backup` command MUST accept zero or one service operand, with any unsupported option or excess operand producing exit 2, empty stdout, and an opsctl diagnostic followed by one empty line and `see 'opsctl backup --help' for usage` on stderr, without reading service files or performing cloud or unit operations.
- R-F9GQ-AL7Q: `opsctl backup --help` and `opsctl backup -h` MUST print exactly `"Usage: opsctl backup [SERVICE]\n\nCopy every service's state/, /var/opt/ikigenba/SERVICE/state/, to the prefix\nin backup.s3_uri, under the service's own name, or just SERVICE when one is\nnamed.\n\nNever copied: /opt/SERVICE/, which a deploy brings; cache/; anything opsctl\ngenerates, the service's environment file among them; and -- for a service that\ndeclares a [database] -- the database file, its -wal and -shm, and its\nlitestream metadata directory. Those are replicated continuously by\nlitestream.service. The host's own /etc/ikigenba/ and /etc/letsencrypt/ are\n'opsctl host backup'.\n\nA service declares its database with a [database] table in etc/manifest.toml\nnaming its engine and its path. 'opsctl init' writes the timer that runs this\nat backup.service_files_seconds.\n\nConfiguration keys:\n  aws.region      the region the backup bucket lives in\n  backup.s3_uri   the prefix this host backs up to\n"` to stdout, leave stderr empty, and exit 0 for any effective user id without reading or changing host state.
- R-ZMEX-3VL4: `Files` MUST sample `env.Now` once and use its UTC RFC3339Nano representation followed by `.tar.zst` as the basename of every object in that invocation, writing each below `<backup.s3_uri><service>/`; timestamps with zero fractional seconds MUST use the whole-second story spelling, ordinary later runs MUST form a new set at their newly sampled timestamp, and uploads MUST use the create-only `cloud.Client.PutObject` contract so a collision matching `cloud.ErrAlreadyExists` produces a failed service result while preserving the existing object rather than overwriting it or independently advancing that service's timestamp.

- R-Z9DH-5EZK: Service archives produced by `Files` MUST preserve each archived member's numeric user and group ownership in its tar metadata and, when a source identity has a local symbolic name, preserve that name as well; source members owned by the D09 `ikigenba` account MUST carry owner name `ikigenba` so ownership can be mapped to a rebuilt host rather than assuming stable numeric account IDs. Identity queries MUST use `env.Execute` under the D01 boundary; an identity-query execution failure MUST fail that service's archive without publishing an object, while an unmapped numeric identity MUST remain representable without a symbolic name.

- R-1G7W-5X2V: Package `internal/backup` MUST export `Snapshot(ctx context.Context, env host.Env, cloudEnv cloud.Env, store config.Store, service string) ([]SnapshotResult, error)`.
- R-1HFS-JOTK: Package `internal/backup` MUST export `SnapshotResult` with the fields `Service string`, `URI string`, `Size int64`, and `Err error`; for a successful service `URI` MUST be the complete `s3://` URI of the uploaded object and `Size` its compressed byte count, while `Err` MUST carry a failed service's reason.
- R-FAOM-OCYF: `Snapshot` MUST apply the configuration checks of R-DAD6-H3N5 and the service selection and service-name validation of R-T7OU-NQ6M exactly as `Files` does, with the same error texts, so `backup.s3_uri not set`, `aws.region not set`, and `no service '<service>'` are returned before any service data read or cloud access, and a discovered service whose name fails validation yields a failed `SnapshotResult` where `Files` yields a failed `FileResult`; all of its object access, the replica reads of R-FECB-TO6I included, MUST remain below the configured host prefix.
- R-1JVL-B8AY: `Snapshot` MUST sample `env.Now` once and write each selected service's object at `<backup.s3_uri>snapshots/<service>/<timestamp>.tar.zst`, where `<timestamp>` is that instant's UTC RFC3339Nano representation, keeping the whole-second spelling when fractional seconds are zero, so every object of one invocation carries the same timestamp and a later run writes a new set; it MUST upload through the create-only `cloud.Client.PutObject` contract, so a collision matching `cloud.ErrAlreadyExists` yields a failed result for that service and leaves the existing object unchanged.
- R-FD4F-FWFT: Each successful `Snapshot` object MUST be one zstd-compressed tar of the selected service's existing `state/` tree with the member names, contents, directory structure, permissions, symlink handling, and ownership metadata that R-F70X-J1QC and R-Z9DH-5EZK specify for a `Files` archive, and with the same exclusions, no `etc/` member, nothing from `/opt/<service>/` or `/etc/opt/`, the environment file holding the service's secrets among it, no `cache/`, host `/etc/`, nginx output, or generated unit files, and for a declared database none of the entries `DatabaseFiles` returns; except that for a service whose manifest declares a database it MUST contain one regular-file member at the database's `Path` holding the copy of R-FECB-TO6I. A service with no manifest or no declared database MUST have its complete `state/` included and MUST cause no `litestream` invocation, and `Snapshot` MUST read nothing under `/etc/`, and nothing under `/opt/<service>/` but its `etc/manifest.toml`.
- R-FECB-TO6I: For a selected service whose manifest declares a database, `Snapshot` MUST, through `env.Execute`, list the replica at `<backup.s3_uri><service>/` with `litestream ltx -level all -json <replica>` and rebuild its newest recoverable database with `litestream restore -o <file> <replica>`, where `<replica>` is that URL and `<file>` a path not yet existing in a temporary directory that lies under `env.Root` and outside both `/opt/` and `/var/opt/`, and the archive's database member MUST hold exactly the bytes litestream left in that file, with mode `0600` and the numeric and symbolic owner and group of the live database file at `Path` in the service's data directory (D08 R-YW93-ZIXT), `/var/opt/ikigenba/<service>/<Path>`, or of its parent directory when the live file is absent. It MUST NOT read the contents of, write, or checkpoint the live database, its `-wal` or `-shm`, or its litestream metadata directory, and MUST NOT stop, start, or reconfigure `litestream.service`.
- R-FFK8-7FX7: When the `litestream ltx` listing of R-FECB-TO6I exits 0 with a JSON array holding no file, or the `litestream restore` of R-FECB-TO6I fails with `no matching backup files` in its stderr, `Snapshot` MUST yield a failed result for that service whose `Err` text is exactly `no replica under the prefix`, publish no object for it, and go on with the remaining selected services; any other `litestream` execution failure or nonzero exit MUST likewise fail only that service, preserving `host.CommandError` through unwrapping.
- R-1OR6-UB9Q: `Snapshot` MUST remove every temporary file and directory it or `litestream` created before it returns, on success and on failure, and MUST otherwise perform no local filesystem mutation, unit control, replication reconfiguration, object deletion, or object overwrite; with a nonempty `service` it MUST read no other service's data.
- R-FGS4-L7NW: A selected service's manifest-read, manifest-decode, archive-read, database-copy, compression, or upload failure MUST yield a failed `SnapshotResult` for that service without preventing attempts for the remaining selected services, and MUST publish no object for it after a local read, copy, or archive-construction failure; a failure reading a file under the service MUST give the reason `<path>: <cause>`, where `<path>` is the file's canonical host path without `env.Root`, `/opt/<service>/etc/manifest.toml` for its manifest and under `/var/opt/ikigenba/<service>/state/` for a file of `state/`, and `<cause>` the operating system's description, so an unreadable `state/outbox` gives `/var/opt/ikigenba/crm/state/outbox: permission denied`; an operational failure affecting the run as a whole MUST be returned through the separate error, retaining every earlier result and a failed result for a service whose snapshot was being attempted, adding no result for an unattempted service, and attempting no later service.
- R-1R6Z-LUR4: `opsctl snapshot` and `opsctl snapshot SERVICE` MUST invoke `Snapshot` for all or the named service, respectively, and print one stdout line per returned result in service-name order, formatted `<service>: ok (<uri>, <size> MiB)` for success with compressed bytes divided by 1048576 and rounded to one decimal place, or `<service>: failed: <reason>` with the result's cause as one concise line without captured subprocess output; a completed report MUST leave stderr empty and exit 0 exactly when every result succeeded, otherwise exit 1. A whole-run operational error MUST keep every returned row on stdout and exit 1 with a D02 diagnostic whose first line is `opsctl: snapshot failed at <service>` for an interruption during an attempted service or `opsctl: snapshot failed` for one between attempts, without repeating report findings; an error before any attempt MUST leave stdout empty and make the diagnostic's first line `opsctl: ` followed by the error's text, so a missing service gives exactly `opsctl: no service '<service>'` and an unset prefix `opsctl: backup.s3_uri not set`. Captured subprocess output MUST appear only in D02 quoted stderr detail.
- R-1SEV-ZMHT: The `snapshot` command MUST accept zero or one service operand, with any unsupported option or excess operand producing exit 2, empty stdout, and an opsctl diagnostic followed by one empty line and `see 'opsctl snapshot --help' for usage` on stderr, without reading service files or performing cloud or unit operations; D02 root refusal MUST apply to valid invocations.
- R-FI00-YZEL: `opsctl snapshot --help` and `opsctl snapshot -h` MUST print exactly `"Usage: opsctl snapshot [SERVICE]\n\nCopy every service's state/, /var/opt/ikigenba/SERVICE/state/, and the\ndatabase of a service that declares a [database], to snapshots/<service>/\nunder the prefix in backup.s3_uri, or just SERVICE when one is named. Every\nsnapshot of one run carries the same timestamp.\n\nThe database copy is rebuilt from the replica litestream.service keeps, so\nnothing is stopped; it may trail the live database by the changes litestream\nhas not yet shipped. Never copied: /opt/SERVICE/, which a deploy brings;\ncache/; anything opsctl generates, the environment file that holds the\nservice's secrets among them; and the database's -wal and -shm and its\nlitestream metadata directory.\n\n'opsctl restore SERVICE --from URI' puts a snapshot back.\n\nConfiguration keys:\n  aws.region      the region the backup bucket lives in\n  backup.s3_uri   the prefix this host backs up to\n"` to stdout, leave stderr empty, and exit 0 for any effective user id without reading or changing host state.
