# D02-cli-conventions

Package `internal/cli` owns command grammar, help, dispatch, version, root refusal, and output conventions. All story command groups share this frame.

opsctl has no version of its own: it belongs to the suite release it was unpacked with, and `opsctl version` prints that release's display string, found from where its own executable is (D16). An opsctl outside every release folder, one a developer copied onto a host by hand, prints an empty line and still succeeds, so a caller reading the line is never refused.

## REQUIREMENTS

- R-N211-TYS0: The top-level grammar MUST be `opsctl [options] <command> [arguments]`, accepting exactly the options `-h`/`--help` and `-V`/`--version` before the command and no other top-level options.
- R-SV17-N1A7: The top-level command set MUST be exactly `activate`, `backup`, `cert`, `config`, `disable`, `dns`, `enable`, `host`, `init`, `nginx`, `restart`, `restore`, `retire`, `rollback`, `services`, `snapshot`, `status`, and `version`.
- R-SW94-0T0W: `opsctl --help` and `opsctl -h` MUST print exactly `"Usage: opsctl [options] <command> [arguments]\n\nOperate the ikigenba platform host. Must run as root.\n\nCommands:\n  activate  make an unpacked release the one this host runs\n  backup    back up a service's files to S3\n  cert      obtain and inspect the host's certificate\n  config    read and write the host configuration store\n  disable   stop an installed app and keep it from starting\n  dns       manage DNS records in the zones opsctl owns\n  enable    let a disabled app start again, and start it\n  host      back up and restore the host's own configuration\n  init      run the setup sequence behind one preflight\n  nginx     generate the platform's nginx configuration\n  restart   restart an installed app's service\n  restore   restore a service from its backups\n  retire    stop every service and take the host's final backup\n  rollback  go back to the release this host ran before\n  services  regenerate the services file\n  snapshot  copy a service's files and database to S3 as one tarball\n  status    print every service, its release and its state\n  version   print the release this opsctl belongs to\n\nOptions:\n  -h, --help     print this help\n  -V, --version  print the version\n\nExit codes:\n  0  success\n  1  the operation failed\n  2  usage error, or a preflight check failed\n  3  refused: opsctl must run as root\n\nRun 'opsctl <command> --help' for details on a command.\n"` to stdout, write nothing to stderr, and exit 0.
- R-CYFL-TDTY: An invocation with no command MUST write exactly the three lines `opsctl: no command given`, an empty line, and `see 'opsctl --help' for usage` to stderr, nothing to stdout, and exit 2.
- R-CZNI-75KN: An unknown command MUST write exactly the three lines `opsctl: unknown command '<name>'`, an empty line, and `see 'opsctl --help' for usage` to stderr, nothing to stdout, and exit 2.
- R-D0VE-KXBC: An unknown top-level option MUST write exactly the three lines `opsctl: unknown option '<option>'`, an empty line, and `see 'opsctl --help' for usage` to stderr, nothing to stdout, and exit 2.
- R-8PCC-RYAO: `opsctl version` MUST print exactly one line to stdout: when `release.Of(Deps.Root, <path>)` (D16), `<path>` being the path `Deps.Executable` returns, reports true, the returned release's `Display()`, so `r142 (c604e32)` with a label and `c604e32` without, and otherwise an empty line; an error from `Deps.Executable` MUST also give the empty line. The line MUST be identical whatever environment `Deps.Getenv` supplies and whatever the configuration store under `Deps.Root` contains, and an option that names a version, such as `--version=<v>`, MUST be rejected as an unknown top-level option.
- R-8QK9-5Q1D: `opsctl version`, `opsctl -V`, and `opsctl --version` MUST each print the line of R-8PCC-RYAO, all three the same, write nothing to stderr, and exit 0, also when that line is empty.
- R-ENLY-EGT2: Any invocation that would dispatch to a command's action with `Deps.EUID` not equal to 0 MUST write the single line `opsctl: must run as root` to stderr, write nothing to stdout, and exit 3 without reading or writing any host file, invoking an external command, or making a network request; help and version are exempt.
- R-ND05-9WG9: `--help`, `-h`, `--version`, `-V`, `version`, and `<command> --help` MUST succeed with `Deps.EUID` not equal to 0.
- R-EQ1R-60AG: The first line of every diagnostic `opsctl` writes to stderr MUST begin with `opsctl: `; any further detail MUST follow exactly one empty line, with output from another program quoted by prefixing every line with `> ` and opsctl-authored detail unprefixed; usage text MUST never be written to stderr.
- R-NGNU-F7OC: On success a command MUST write nothing to stderr.

- R-ER9N-JS15: Command stdout MUST contain only the command product (values, lists, or reports), without decoration, colour, or progress output; report findings, including unsuccessful findings, MUST remain on stdout, while an operation failure MUST explain its reason on stderr without copying report findings.
- R-8RS5-JHS2: Help, no-command errors, unknown-command errors, and unknown-top-level-option errors MUST leave host state unchanged and perform no host-file access, external command invocation, or network request; `version`, `-V`, and `--version` MUST leave host state unchanged, invoke no external command, make no network request, and read nothing but what `release.Of` reads.
- R-VW8X-AM1W: When a failed action returns an error containing `host.CommandError`, CLI diagnostics MUST identify that failure on the first line and include its captured `Result.Stdout` followed by `Result.Stderr` as detail after exactly one empty line, prefixing every captured output line with `> ` without otherwise changing its content; an empty capture MUST contribute no lines, and a final line without a newline MUST be terminated in the diagnostic. Captured failure detail MUST NOT be copied to stdout.
