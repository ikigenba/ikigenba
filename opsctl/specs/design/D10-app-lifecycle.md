# D10-app-lifecycle

App removal preserves data, restart reuses the installed configuration, and
status reports host facts. The CLI composes routing and replication around
apps-owned lifecycle operations.

Every app runs as a socket unit and a service unit (D09). Uninstall stops the
socket before the service, so no request starts the service again while it
is taken down, and removes both. Before it removes anything it applies D09's
data rules, so data an older install left under `/opt/<app>/` lands in the
data directory (D08) where every later command looks for it; a `data` line
appears only when something moved or was dropped, or when two `state/`
directories refuse the uninstall with nothing removed. It then removes
`/opt/<app>/` whole, an older install's `etc/env` with it, the app's
environment directory `/etc/opt/ikigenba/<app>/` (D08) when there is one,
naming it on the `files` line only then, and the data directory's `cache/`,
and keeps `/etc/opt/ikigenba/` and the data directory's
`state/`, which leaves a service the host still backs up. Restart restarts the service alone; the
socket keeps listening, so no request is refused, and the new process gets the
environment file its unit names, as the last install, activate, or `init`
wrote it. Status reports both units:
the socket's field reads `disabled` when systemd reports the socket unit
disabled.

Disabling is the operator's way to keep an installed app down without
uninstalling it: both units are stopped and disabled, and the app's names
answer 503 (D06). Nothing but systemd's enablement records the state, and
`Disabled` is the one predicate every consumer asks. A disabled app stays
disabled through every operation — install, activate, init, restart, restore,
retire —
and only `enable` enables it; uninstall ends the state by removing the units.
The authenticator, `auth`, is never disabled: every other app is checked
against it. Disable and enable are idempotent, and they regenerate nginx
through D06's `Update`, which publishes and reloads only when the rendered
file differs from the one in place. Uninstall, disable, and enable then rewrite
the services file (D15) and report the change to the app's entry on a
`services` line right after `nginx`; a no-op disable or enable leaves that
file byte for byte as it was. Install and restart share a service-completion
report, while status includes the database journal mode in its host report.

Uninstall's nginx line names every name the app stopped answering at: its own,
the host's when it was the default, and the root domain's apex when
`host.apex` names it. `host.apex` itself is read before anything is stopped or
removed, refused there when the host name has no parent domain, and otherwise
passed through, never changed, so the apex name falls back to the 404 block
until the app returns.
The parameter `/<host.name>/<app>` is devctl's and is never touched. The host
name uninstall checks, passes to nginx, and prints is `host.NormalizeName` of
the stored `host.name` (D01).

On a released host (D08) the apps are the ones the release `current` names,
each run by the units `activate` wrote (D17, D18), and restart, disable,
enable, and status work from them and write nothing under `/opt/ikigenba/`.
Uninstall, like install (D09), refuses there before it looks at the app: an
app leaves a released host only when an activate puts a release without it in
place. A service there that has only its data, an app a later release
dropped, has nothing to run, so restart, disable, and enable refuse it as not
in the current release, and status shows `-` in every field after its name.
Where these commands show an app's version they show its *reported version*:
the short sha of the release `current` names on a released host, the same for
every app since one commit built them all, and on any other host what the
app's own binary answers to `--version`. Status also shows the release's
label, the one the last activate of it gave, or `-` when it has none; a
per-app host's label field is always `-`, so every line has six fields
whatever the layout. A per-app host keeps every other rule and text here.
