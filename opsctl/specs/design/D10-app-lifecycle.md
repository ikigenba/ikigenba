# D10-app-lifecycle

App removal preserves data, restart reuses the installed configuration, and
status reports host facts. The CLI composes routing and replication around
apps-owned lifecycle operations. Install and restart share a service-completion
report, while status includes the database journal mode in its host report.

## REQUIREMENTS

- R-LM7Q-0199: Package `internal/apps` MUST own app removal, restart, and host-local status, using the D08 service model and D01 host boundary; `internal/cli` MUST own their grammar, rendering, and orchestration with nginx and backup, without adding an apps dependency on those packages.
- R-ES81-UK2R: Package `internal/apps` MUST export `UninstallHooks` as a struct with exactly `Report func(step, detail string, success bool) error` and `Configure func(context.Context, Manifest) error` fields.
- R-LONI-RKQN: Package `internal/apps` MUST export `Uninstall(ctx context.Context, env host.Env, app string, hooks UninstallHooks) error`.
- R-LPVF-5CHC: Package `internal/apps` MUST export `Restart(ctx context.Context, env host.Env, app string) (StatusRow, error)`.
- R-LR3B-J481: Package `internal/apps` MUST export `StatusRow` as a struct with exactly `Name string`, `Version string`, `State string`, and `JournalMode string` fields.
- R-LSB7-WVYQ: Package `internal/apps` MUST export `Status(ctx context.Context, env host.Env) ([]StatusRow, error)`.
- R-LTJ4-ANPF: Package `internal/apps` MUST export `LifecycleError` as a struct with exactly `Code int`, `Message string`, and `Cause error` fields; `(*LifecycleError).Error() string` MUST return `Message`, and `(*LifecycleError).Unwrap() error` MUST return `Cause`.
- R-017J-COZA: `opsctl uninstall --help` and `opsctl uninstall -h` MUST, for any effective user id, perform no host-file access, subprocess execution or cloud call, change nothing, exit 0 with empty stderr, and write exactly "Usage: opsctl uninstall APP\n\nTake APP off the host: stop and disable ikigenba-APP.service and remove it,\nthen remove /opt/APP/bin/, etc/, share/, and cache/. /opt/APP/state/ is kept\nuntouched, so APP is still a service the host backs up, and a later install\nlands over its data the way an install over a restore does. Removing state/ is\na decision made by hand, never here.\n\nThe nginx configuration and /etc/litestream.yml are regenerated from every app\nleft on the host, so APP's name stops answering, and a database APP declared\nstops being replicated once litestream has shipped what it holds.\n\nThe parameter /ikigenba/<host.name>/APP is not touched: it is devctl's.\n\nConfiguration keys:\n  host.name  the fully-qualified name this host answers at\n  aws.region  the region the backup bucket lives in\n  backup.s3_uri  the prefix this host backs up to\n  backup.service_db_seconds  how often a declared database is snapshotted whole\n  backup.service_wal_seconds  how often a declared database's committed changes are shipped\n" to stdout, where `\n` denotes one LF byte.
- R-LVYX-276T: `opsctl restart --help` and `opsctl restart -h` MUST, for any effective user id, perform no host-file access, subprocess execution or cloud call, change nothing, exit 0 with empty stderr, and write exactly "Usage: opsctl restart APP\n\nRestart ikigenba-APP.service and report the service as the last line of\n'opsctl install' does. Nothing on disk changes: the binary, the environment\nfile, and the unit are what the last install wrote, so a secret pushed since\nthen is not picked up here. A unit that is inactive or failed is started.\n" to stdout, where `\n` denotes one LF byte.
- R-LX6T-FYXI: `opsctl status --help` and `opsctl status -h` MUST, for any effective user id, perform no host-file access, subprocess execution or cloud call, change nothing, exit 0 with empty stderr, and write exactly "Usage: opsctl status\n\nPrint one line per service on this host, in name order: its name, the version\nits own binary reports, the state of its systemd unit, and the journal mode of\nthe database its manifest declares. A service is any /opt/<name>/ with an etc/\nor state/ directory; '-' means opsctl could not ask, or there was nothing to\nask.\n\nA declared database must stay in WAL mode: litestream cannot replicate one in\nany other mode, so a service reporting anything but 'wal' is a service whose\ndata is not reaching S3.\n\nThe exit code is 0 whatever the report says. A failed unit and an unreplicable\ndatabase are facts about the host, not failures of this command.\n" to stdout, where `\n` denotes one LF byte.
- R-LYEP-TQO7: The uninstall and restart actions MUST each accept exactly one APP; before host access, zero or multiple operands MUST exit 2 with empty stdout and respectively `opsctl: <command> needs APP` or `opsctl: <command> takes one APP`, followed by one empty line and `see 'opsctl <command> --help' for usage`, with every line LF-terminated; status with any operand MUST use the same formatting with `opsctl: status takes no arguments` and its own usage hint.
- R-LZMM-7IEW: `Uninstall` and `Restart` MUST reject names not accepted by `ValidateName` before host access with a `LifecycleError` of Code 2 and Message `'<name>' is not a usable app name`; a missing `/opt/<app>/` MUST return Code 1 and Message `no service '<app>'`, and an existing directory without `bin/<app>` MUST return Code 1 and Message `<app> is not installed`, without mutation, subprocess execution, or successful reports.
- R-M0UI-LA5L: Before removal, `Uninstall` MUST require non-nil hooks, a readable valid installed manifest matching the app, and a unit; it MUST retain the manifest for the Configure callback and reject missing or invalid prerequisites without mutation; the CLI MUST also require a nonempty configured `host.name` before invoking removal, reporting `host.name not set` when absent.
- R-M22E-Z1WA: `Uninstall` MUST stop an active `ikigenba-<app>.service` and disable the unit before removing any app files or unit file; an already inactive or failed unit MUST still be disabled and removed, and MUST report `stop` with detail `ikigenba-<app>.service already inactive, disabled` instead of the active-unit detail `ikigenba-<app>.service stopped, disabled`.
- R-M3AB-CTMZ: After successful stop and disable, `Uninstall` MUST remove `/etc/systemd/system/ikigenba-<app>.service`, execute `systemctl daemon-reload`, and report `unit` with detail `removed ikigenba-<app>.service` only after both succeed.
- R-M4I7-QLDO: After unit removal, `Uninstall` MUST remove `/opt/<app>/bin/`, `etc/`, `share/`, and `cache/`, treating an absent optional directory as already removed, and report `files` with detail `removed /opt/<app>/bin, etc, share, cache; kept state`; it MUST leave `/opt/<app>/state/` and all its descendants untouched, neither reading nor writing their contents or metadata directly, and MUST not follow symlinks in removed paths into preserved data or outside the app tree.
- R-M5Q4-4D4D: After files removal, `Uninstall` MUST invoke `hooks.Configure` exactly once with the removed manifest; the CLI callback MUST apply nginx using `host.name` and the remaining manifests, report `nginx` with detail `<app>.<host.name> removed` or `<app>.<host.name>, <host.name> removed` for a removed default, then call `backup.Regenerate` and restart `litestream.service` exactly when it returns changed, finally reporting `litestream` with detail `<database.path> removed` when the removed manifest declared a database and regeneration changed, `updated` for another configuration change, or `unchanged` otherwise.
- R-M6Y0-I4V2: Uninstall orchestration MUST finish stopping the app before restarting Litestream, so its existing replication process can perform its shutdown synchronization before the new configuration omits the removed database; it MUST preserve the database, WAL, SHM, and Litestream metadata for that synchronization, and on a successful shutdown synchronization the replica MUST contain the app's last committed transaction. This ordering MUST leave remaining databases configured and replicating after the restart.
- R-IKX4-P2D6: Successful uninstall of an app with an existing state directory MUST leave that retained state-only service discoverable, causing status to report `<app> - - -` when no binary, unit, or database declaration remains, and allowing backup to include all of its state under the manifest-free D11 rules; when no state directory existed, uninstall MUST not create one, and a remaining app directory with neither etc nor state MUST not be discoverable under D08. Uninstall MUST remove the app's nginx routes, including apex routing for a default, and MUST not change another app's files or unit or mutate remote parameters or deployment artifacts.
- R-ETFY-8BTG: Uninstall MUST emit exactly one outcome for each attempted stage in the order stop, unit, files, nginx, litestream through Report: successful effects use success true and render `<step>: ok (<detail>)` followed by LF to stdout; failed effects use success false and render `<step>: failed: <detail>` followed by LF to stdout, where detail explains the failure with CR and LF replaced by literal `\r` and `\n` respectively. Any action or report-write failure MUST prevent later stages, retain completed effects without rollback except nginx's own rollback, and return an operational error; unattempted stages MUST emit nothing, and a failed report callback MUST not be retried or cause a second outcome. Successful completion MUST exit 0 with empty stderr.
- R-MALP-NG35: `Restart` MUST execute `systemctl restart ikigenba-<app>.service` for an installed app regardless of whether its unit is active, inactive, or failed, and query its resulting systemd state; only active completion MUST succeed and return a row naming the app, its installed binary's `--version` response with the trailing line ending removed, and state `active`, with `JournalMode` set to `-` because restart does not query the database.
- R-MBTM-17TU: Restart MUST neither write app installation or configuration files nor enable or disable any unit, reload nginx, control Litestream, access remote secrets, or alter another app; the new app process MUST use the unchanged installed EnvironmentFile and unit, while app-owned writes made by that process remain outside opsctl's no-write guarantee.
- R-EUNU-M3K5: For an attempted Restart action, the CLI MUST emit exactly one service outcome on stdout: `service: ok (<app> <version> active)` followed by LF on success, or `service: failed: <reason>` followed by LF on failure, where reason is the LifecycleError.Message with CR and LF replaced by literal `\r` and `\n` respectively. Success MUST exit 0 with empty stderr; version MUST come from the installed executable, never an archive name, manifest, cached record, or remote deployment record. Failure to write either outcome MUST return an operational failure without retrying the report or emitting a second outcome.
- R-ME9E-SRB8: When restart fails or the resulting unit is not active, `Restart` MUST return a `LifecycleError` with Code 1 and Message `<app>: service failed to start`, obtain that unit's journal through `env.Execute` using `journalctl --unit ikigenba-<app>.service --no-pager --lines 50`, and preserve its output for CLI detail after one blank line with each line prefixed `> `; a failed journal query MUST preserve the original restart failure and identify the journal failure. No success line or rollback MUST occur, and a resulting failed unit MUST remain visible as `failed` to status.
- R-MFHB-6J1X: `Status` MUST use `Discover` to return exactly one row per discovered service in ascending bytewise name order, with each row derived independently from that service's current installed executable, systemd unit, and manifest-declared database; it MUST return an empty successful result when no service exists, including when `/opt` is absent.
- R-IJP8-BAMH: For each status row, `Status` MUST obtain Version by invoking `/opt/<name>/bin/<name> --version` through `env.Execute` and removing its trailing line ending, State from `systemctl show --property=LoadState --property=ActiveState ikigenba-<name>.service` only when `ValidateName(name)` succeeds, and JournalMode by reading the manifest-declared database mode without setting it; when name validation fails, State MUST be `-` and no systemd query for a unit derived from that name may occur, while independently queryable Version and JournalMode remain reportable. Absent or unqueryable fields MUST independently be `-`, an unloaded unit MUST give `-`, and readable active, inactive, failed, wal, and delete facts MUST be retained rather than treated as command failures.
- R-MHX3-Y2JB: Status MUST perform no writes to configuration, units, database files, sidecars or other service data, no journal-mode assignment, no service control, and no cloud access; a manifest error MUST make the journal-mode field `-` without suppressing independently queryable version or unit state. The process queries MUST use D01's injected execution and root boundary.
- R-MJ50-BUA0: On successful `Status`, the CLI MUST print each row as exactly `<Name> <Version> <State> <JournalMode>` followed by LF, with no header, alignment padding, blank rows or diagnostic copies; all per-service findings, including failed units, non-WAL modes and unavailable fields, MUST exit 0 with empty stderr, while failure to enumerate services or write the report MUST exit 1 and write a D02 diagnostic explaining the command failure.
- R-EVVQ-ZVAU: Lifecycle operational errors MUST use LifecycleError Code 1 with a concise Message and preserve underlying errors in Cause, including host.CommandError for external-process failures. For an attempted uninstall or restart workflow, the CLI MUST retain outcome reports already written and emit `opsctl: uninstall failed` or `opsctl: restart failed`, respectively, followed by LF on stderr, without copying a report or repeating its failure reason; D02 quoted external-process detail and the specified startup journal MUST remain available after one blank line. Report-write failures MUST use Code 1 and MUST not cause duplicate report or reason rendering. Before a workflow begins, failures MUST instead emit Message prefixed by `opsctl: ` and LF with no outcome report. The CLI MUST return Code and never write usage text to stderr.
- R-PWID-NYOW: The status JournalMode field MUST report the persistent database mode observable by a fresh read-only SQLite connection: `wal` for a valid SQLite file in WAL format and `delete` for a valid SQLite file in rollback format, with `-` for missing, unreadable, malformed or unsupported files; connection-local choices such as truncate, persist, memory and off MUST not be inferred from another process's connection, and obtaining this field MUST require no additional Go module or installed host executable.

- R-EX3N-DN1J: Uninstall and restart workflows MUST begin only after grammar, app-name validation, and required hook and configuration validation succeed; failures of those preliminary checks MUST produce diagnostics only. Uninstall owns stop, unit and files outcomes, while its CLI Configure callback owns nginx and litestream outcomes; a Configure failure MUST propagate without another outcome from Uninstall. The stop stage MUST include checking app-directory, binary, manifest and unit prerequisites, observing current unit state, stopping when required and disabling; the remaining stages encompass their existing named effects. Restart's service stage MUST include installed-app prerequisite checks, restarting the unit, observing its resulting state and obtaining its version. On an action failure, the owning stage MUST report failure before returning; error details MUST survive through LifecycleError.Cause, including both action and report callback errors when both occur. Plain Status table output MUST retain its existing four-column contract.
