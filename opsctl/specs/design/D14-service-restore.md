# D14-service-restore

Restore combines independently timed service files and database history.
An app's socket and service are both stopped for the restore, socket first,
because an idle service behind a listening socket would otherwise be started
again by the next request mid-restore; an app counts as running when its
socket is. A disabled app (D10) stays disabled: its data is restored and
neither of its units is started. The
selected archive declares the incoming database; application binaries and
unit installation remain deployment responsibilities. A failed restore retains
the app activation intent for a retry on the same running host.

The nginx configuration is regenerated after a restore through a callback the
CLI supplies, so the restored service's block appears without running init.
The CLI reads `host.apex` beside `host.name` for that callback (D06), so a
restored service that is the apex app answers at the parent domain again. As
install and uninstall do (D09, D10), the CLI checks a nonempty `host.apex`
against `host.name` before the workflow begins: a `host.apex` the host's name
cannot carry is refused with the shared D01 diagnostic before any object is
read, any unit stopped, or any file changed, so no step line is printed and
nothing is left stopped. The callback path remains the contract for a callback
failure of any other kind: it fails the restore at the nginx regeneration stage
with the completed steps and stopped units reported. The `host.name` the CLI
reads is passed through `host.NormalizeName` (D01) before the apex check and
the callback, so restore agrees with install and uninstall on the name.

## REQUIREMENTS

- R-1EYH-INPP: Package `internal/backup` MUST export `Restore(ctx context.Context, env host.Env, cloudEnv cloud.Env, store config.Store, service string, at *time.Time, regenerateNginx NginxRegenerator) (RestoreReport, error)`; nil `at` requests newest files and database, and non-nil `at` requests recovery at that instant.
- R-Y7LG-MDVA: Package `internal/backup` MUST export `RestoreStep` with exactly the fields `Name string`, `Detail string`, and `Err error`.
- R-RX15-3IAF: Package `internal/backup` MUST export `RestoreReport` with exactly the field `Steps []RestoreStep`; attempted report steps MUST be retained in execution order on both success and failure, including exactly one failed entry when an attempted report step fails and no entry for an unattempted step. The report steps MUST be `source` for object selection, retrieval, archive validation and incoming manifest validation, `stop` for unit discovery and stopping, `files` for account setup, target replacement and ownership application, `db` for database recovery, WAL-mode conversion and database ownership, `litestream` for configuration regeneration, and `start` for required unit starts; success details MUST retain their specified meanings, and a failed entry MUST have empty `Detail` and non-nil `Err`. Service-component, configuration, S3-prefix and callback-presence validation failures before these steps MUST return an empty report; activation-marker maintenance and the nginx callback MUST add no report step on either success or failure.
- R-FRLA-3A11: Package `internal/backup` MUST export `RestoreError` with exactly the fields `Service string`, `Stage string`, `Err error`, and `Stopped []string`, and `(*RestoreError).Error() string` and `(*RestoreError).Unwrap() error`; `Error` MUST return `Service + ": " + Stage + ": " + Err.Error()` and `Unwrap` MUST return `Err`, while `Stopped` lists units known to remain stopped because of this restore.
- R-FST6-H1RQ: `Restore` MUST reject a service component that is empty, `.` or `..`, contains slash or NUL, or equals `host` or `deploy` before accessing service files or objects; it MUST require nonempty `backup.s3_uri` followed by `aws.region`, returning `backup.s3_uri not set` or `aws.region not set` respectively, and reject malformed S3 prefixes before service reads, unit actions, or object access.
- R-FU12-UTIF: `Restore` MUST select from `cloud.Client.ListObjects` below the configured host prefix followed by `<service>/`, considering only immediate object basenames that are RFC3339Nano timestamps followed by `.tar.zst`; it MUST choose the greatest timestamp, restricted to timestamps at or before `at` when supplied, without confusing object modification time or Litestream objects with file-backup time.
- R-Y2PV-3AWI: When no file backups exist, `Restore` MUST return `no backups for <service> under <prefix>`; when file backups exist but none qualifies at the requested instant it MUST return `<service>: no backup at or before <timestamp>` using the requested RFC3339 instant; either case MUST return a single failed `source` entry without reading, writing, or creating anything under `/opt/<service>/` or stopping a unit.
- R-FWGV-MCZT: `Restore` MUST fetch the selected object through `cloud.Client.GetObject` and accept D12 zstd-compressed service-relative tar archives, validating complete archive structure and the incoming manifest with `apps.ParseManifest` before changing service data or stopping units; absolute member paths, traversal, members outside `etc/` and `state/`, and link traversal permitting writes outside those trees MUST fail without target writes, while valid file contents, directory structure, modes, and symlink targets MUST be restored without dereferencing symlinks outside the trees.
- R-FXOS-04QI: `Restore` MUST derive the database to restore from the incoming archive manifest, never from the installed manifest; an absent manifest or database table denotes no incoming database, a nonempty manifest app MUST match the service name, and invalid manifests MUST fail before target mutation or unit stops. Source success MUST append `RestoreStep{Name: "source", Detail: "<service>/<object>, <size> MiB"}`, with compressed bytes divided by 1048576 and rounded to one decimal place.
- R-XEAW-84OR: Before replacing target files, `Restore` MUST apply the app-unit name guard and, for an accepted app name, treat the app as *installed* exactly when `ikigenba-<service>.socket` is a loaded unit, as *active on entry* exactly when that socket unit is active at the stop step, and as *disabled* exactly when `apps.Disabled` (D10) reports it; for an installed app it MUST execute `systemctl stop ikigenba-<service>.socket` and then `systemctl stop ikigenba-<service>.service`, whatever their states, so no request starts the service again mid-restore, and independently of the app-unit guard it MUST ensure the shared `litestream.service` is stopped, after the app's units, whenever the incoming manifest declares a database; replacement MUST NOT occur while a unit holds a database being removed open. With `{U}` denoting `ikigenba-<service>.socket, ikigenba-<service>.service`, the successful `stop` detail for an incoming database MUST be `{U}, litestream.service` for an app active on entry, `litestream.service; {U} already inactive` for an installed app neither active on entry nor disabled, `litestream.service; {U} already inactive, disabled` for a disabled app not active on entry, `litestream.service, no ikigenba-<service>.socket` for an app not installed with an accepted name, and `litestream.service, no app unit` for a name rejected by the app-unit guard.
- R-G04K-RO7W: Successful files restoration MUST replace the complete target `etc/` and `state/` trees with the archive contents, including `etc/env`, removing prior entries absent from the archive rather than merging; an absent service root MUST be created with mode `0755` and contain only restored trees, while existing `bin/`, `share/`, and `cache/` remain unchanged. It MUST append a `files` step with detail `/opt/<service>/etc, /opt/<service>/state, <count> files`, where count is the number of restored nondirectory archive members.
- R-G1CH-5FYL: For an incoming database, `Restore` MUST invoke installed `litestream` through `env.Execute` only after files restoration to rebuild the declared path from `<backup.s3_uri><service>/`; nil `at` MUST select the newest recoverable database independently of the file-backup timestamp, and non-nil `at` MUST request that instant independently of the file-backup timestamp, accepting the nearest recoverable point at or before it when replication history has a gap. A successful `db` step MUST report `/opt/<service>/<database-path>, newest <recovered-timestamp>` for nil `at` or `/opt/<service>/<database-path>, at <requested-timestamp>` otherwise, without claiming the requested timestamp is the actual recovery point in a gap.
- R-G2KD-J7PA: After successful database restoration and while Litestream remains stopped, `Restore` MUST call `Regenerate` against the newly restored manifests; success MUST append a `litestream` step whose detail is `unchanged` when bytes were unchanged or the restored database service-relative path otherwise, and it MUST start `litestream.service` after successful regeneration even when bytes were unchanged, so a previously absent service is included without running init.
- R-XFIS-LWFG: On successful database restore, `Restore` MUST start the app only after files, database, regeneration, and nginx regeneration succeeded and Litestream started, and only when the app is installed, not disabled, and either active on entry or recorded by its restore activation marker as stopped by an earlier failed restore; starting MUST execute `systemctl start ikigenba-<service>.socket` and then `systemctl start ikigenba-<service>.service`, starting the service explicitly so an app the restored data breaks fails the `start` step. An installed app neither active on entry nor carrying that marker MUST remain inactive, and an app not installed MUST remain without units. With `{U}` denoting `ikigenba-<service>.socket, ikigenba-<service>.service`, the successful `start` detail MUST be `litestream.service, {U}` when the app was started, `litestream.service; {U} left inactive` for an installed app neither disabled nor started, `litestream.service; {U} left disabled` for a disabled app, and `litestream.service` for an app not installed or a name rejected by the app-unit guard; the `start` step MUST report success only after every required start succeeded, or failure if any required start fails, including a partial start that already brought another unit up. A retry after the missing-replica failure MUST therefore restart both Litestream and the originally active app once restoration succeeds.
- R-XGQO-ZO65: When neither installed nor incoming manifest declares a database, `Restore` MUST restore the whole archived state without invoking Litestream, regenerating its configuration, or controlling its unit; it MUST omit `db` and `litestream` steps and Litestream from stop/start details, start (socket, then service) an installed app that is not disabled and is active on entry or carries retained restore activation intent, and leave any other app as it was. With `{U}` denoting `ikigenba-<service>.socket, ikigenba-<service>.service`, its stop and start details MUST respectively be `{U}` and `{U}` for an app active on entry that is not disabled; `{U}` and `{U} left disabled` for a disabled app active on entry; `{U} already inactive` and `{U} left inactive` for an installed app inactive on entry without retained activation intent; `{U} already inactive` and `{U}` for an installed app inactive on entry with retained activation intent; `{U} already inactive, disabled` and `{U} left disabled` for a disabled app inactive on entry; `no ikigenba-<service>.socket` for both for an app not installed with an accepted name; and `no app unit` for both for a name rejected by the app-unit guard.
- R-Y55N-UUDW: If the incoming database has no replica snapshot, `Restore` MUST fail after successful `source`, `stop`, and `files` steps and append a failed `db` entry with cause text `no snapshot under the prefix`, returning `RestoreError` identifying the service, stage `litestream restore`, and cause text `no snapshot under the prefix`; the declared database MUST remain absent, both the installed app and Litestream MUST remain stopped, `/etc/litestream.yml` MUST remain unchanged, and no rollback, regeneration, or start MUST occur.
- R-G7FZ-2AO2: `Restore` MUST return configuration, cloud, archive, filesystem, context cancellation, and unit or Litestream execution failures as errors and perform no later restoration stage after failure, preserving earlier completed effects without rollback; subprocess failures MUST preserve `host.CommandError` through error unwrapping. A failure after stopping units and before successful restart MUST retain their stopped state and list it in `RestoreError.Stopped`; a restart failure MUST identify only units actually known stopped and MUST NOT falsely claim units already started remain stopped.
- R-1JU3-1QOH: `Restore` MUST limit service-data reads and writes to the selected service, allowing other manifests to be read only by shared `Regenerate` and the injected nginx regeneration; it MUST NOT change other services' data or unit states, enable or disable units, create an app unit or executable, reload nginx, change timers, invoke migrations or seed loading, or write or delete cloud objects. Litestream replication after restart remains Litestream's responsibility; restore MUST NOT delete later replica history or attempt to synchronize file and database clocks.
- R-XHYL-DFWU: `opsctl restore SERVICE [--at <timestamp>]` MUST read `host.name` and `host.apex` from the configuration store, taking `host.NormalizeName` of the `host.name` value as `hostName`, return an operational error for a store read failure of either key (other than `host.apex` being unset, which yields an empty `apexApp`) or `host.name not set` for a `host.name` that is absent or empty after normalisation, all before invoking `Restore`; after grammar validation and that `host.name not set` check, and before invoking `Restore` and so before any object access, unit stop, or file change, when `host.apex` is nonempty the CLI MUST call `host.Apex(hostName)` with that normalised value and, on error, write exactly `opsctl: host.apex is set but host.name '<hostName>' has no parent domain` followed by LF to stderr, quoting the normalised value, leave stdout empty with no step line, exit 1, and perform no cloud call, external command, or host-state change; it MUST supply a `NginxRegenerator` that calls `nginx.Write(ctx, env, hostName, apexApp)` (D06) with that normalised `hostName`, that `apexApp`, and the same host environment; it MUST then invoke `Restore` and print each returned step on stdout as `<name>: ok (<detail>)` for nil `Err` or `<name>: failed: <reason>` for non-nil `Err`, followed by LF, where `<reason>` is the step cause as a single concise line without captured subprocess output; success MUST exit 0 with empty stderr, and an operational failure MUST exit 1 with all returned stdout steps preserved and a D02 diagnostic on stderr. When a failed step is present, the diagnostic first line MUST be `opsctl: restore <service> failed at <step>` using that entry's name, without repeating its failure reason; failures without a failed report step MUST retain their specific command-failure reason in the diagnostic. For a `RestoreError` with stopped units, the diagnostic MUST include after exactly one empty line the units in the order the restore stopped them as `<unit> was left stopped` for one unit, `<unit> and <unit> were left stopped` for two, and, for three or more, the units separated by `, ` with `and ` before the last followed by ` were left stopped` (so `ikigenba-crm.socket, ikigenba-crm.service, and litestream.service were left stopped`); captured subprocess output MUST retain the D02 quoted-detail convention.
- R-GCBK-LDMU: The restore grammar MUST accept exactly one SERVICE and at most one `--at` with an RFC3339 timestamp, accepting the option before or after SERVICE; missing SERVICE, excess operands, and a missing or invalid timestamp MUST respectively produce `restore needs SERVICE`, `restore takes one SERVICE`, and `--at takes an RFC 3339 timestamp`. These errors, duplicate `--at`, and unsupported options MUST exit 2, leave stdout empty, and use a D02 diagnostic followed by one empty line and `see 'opsctl restore --help' for usage`, without service, cloud, or unit effects.
- R-XJ6H-R7NJ: `opsctl restore --help` and `opsctl restore -h` MUST print exactly `"Usage: opsctl restore SERVICE [--at <timestamp>]\n\nReplace /opt/SERVICE/etc/ and /opt/SERVICE/state/ with a backup, and, when\nSERVICE declares a [database], replace that database with what litestream\nholds. Without --at both halves are the newest there is. Nothing under bin/ or\nshare/ is touched.\n\nSERVICE's socket and service are stopped for the restore, socket first so no\nrequest starts the service again mid-restore, and started again after it; so\nis litestream.service, because the files step deletes the database the app and\nlitestream both hold open. A restore is a brief outage. An app whose socket\nwas already stopped is left stopped, unless an earlier failed restore stopped\nit: a successful retry on the same running host starts it again. A disabled\napp stays disabled: neither of its units is enabled or started. A failed\nrestore leaves them all stopped.\n\nBefore litestream.service comes back, /etc/litestream.yml is regenerated from\nthe manifest the restore put in place, so a database restored into a host that\nnever ran SERVICE is replicated from the start line on.\n\nOptions:\n  --at <timestamp>    restore the service as it was at this RFC 3339 moment\n\n--at governs both halves: the files come from the newest tarball written at or\nbefore that moment, and the database is rebuilt to the moment itself. The two\nare not the same instant, because the tarball is written on a timer and the\ndatabase is replicated continuously.\n\nConfiguration keys:\n  aws.region      the region the backup bucket lives in\n  backup.s3_uri   the prefix this host backs up to\n  host.name       the fully-qualified name this host answers at\n  backup.service_db_seconds  how often a declared database is snapshotted whole\n  backup.service_wal_seconds  how often a declared database's committed changes are shipped\n"` to stdout, leave stderr empty, and exit 0 for any effective user id without reading or changing host state.
- R-GERD-CX48: Every successful restore of a declared database MUST leave the restored SQLite database in WAL journal mode before starting the app, so the D08 discovered data-only service remains available to the status contract without needing an executable or installed app unit.
- R-GFZ9-QOUX: `Restore` MUST consume D01 `host.Env` and `cloud.Env` boundaries and D08 manifest declarations without importing `internal/cli`; display paths in its step details MUST use canonical host paths, while actual filesystem and process paths MUST resolve under `env.Root`, and sensitive restored environment contents MUST NOT appear in reports or diagnostics.

- R-1NHS-71WK: Package `internal/backup` MUST export the named function type `NginxRegenerator func(context.Context) error`.
- R-1OPO-KTN9: `Restore` MUST reject a nil `regenerateNginx` before service reads, object access, or unit actions; after successful files restoration and any required database restoration and Litestream configuration regeneration, it MUST invoke `regenerateNginx(ctx)` exactly once before starting any unit, including the no-database and data-only branches. Successful nginx regeneration MUST add no report step; a callback error MUST fail at stage `nginx regeneration`, preserve the error through `RestoreError` unwrapping, retain completed report steps and stopped-unit diagnostics, and prevent every subsequent start without rollback.
- R-1PXK-YLDY: Before deriving any app unit name for a systemd query or action, `Restore` MUST call `apps.ValidateName(service)`; rejection MUST treat the service as data-only with no app unit and MUST NOT query or control a unit derived from that name, while still allowing a service component accepted by the restore path validation to restore its data. In particular, `backup-host`, `backup-services`, and `renew-certificate` MUST never select generated platform units; incoming manifests remain subject to `apps.ParseManifest` validation.

- R-OPIE-CD52: After complete source archive and manifest validation and before replacing target trees, `Restore` MUST ensure the install design's non-root, no-login, no-home `ikigenba` system account exists when the incoming manifest's `App` equals the selected service or any archive member carries symbolic owner or group `ikigenba`; account lookup, creation and inspection MUST use `env.Execute` and D01's root boundary: when the account is absent it MUST create it by executing exactly `useradd --system --no-create-home --shell /usr/sbin/nologin --user-group ikigenba` through `env.Execute`, and when the account exists it MUST determine the account's primary group name by executing `id --group --name ikigenba` through `env.Execute` and treat any name other than `ikigenba` as an account setup failure. During extraction it MUST map symbolic owner `ikigenba` to that destination account's user ID and symbolic group `ikigenba` to its primary group ID, preserve other numeric user and group ownership and all archived permission modes, and leave symlink targets unfollowed. Account setup failure MUST return a `RestoreError` at stage `ownership` with completed source reporting retained, a failed `files` entry, and no target replacement; ownership-application failure MUST prevent a successful files step and every subsequent restore stage without rollback.
- R-ZBT9-WYGY: For a restore whose incoming manifest's `App` equals the selected service or whose archive contains a member with symbolic owner `ikigenba`, `Restore` MUST leave the rebuilt declared database and any WAL or SHM sidecars produced during restore or WAL-mode conversion owned by the destination `ikigenba` account and readable and writable by that account before reporting database success or starting units; a newly created database or sidecar MUST have mode `0600`. Its containing directories MUST retain archived modes and mapped ownership, including nested ancestors under `state/`, so an archive whose state directories were accessible and writable by the source `ikigenba` account remains so for the destination account despite different numeric IDs. Failures establishing this access MUST return a `RestoreError` at stage `database ownership`, retain completed steps, and prevent regeneration and starts; this requirement MUST NOT relax group or world permissions, take ownership of unrelated opaque service data, or promise accessibility for source directories already inaccessible to that account.

- R-D4R8-7TVQ: `Restore` MUST preserve app activation intent across failed invocations and retries on the same running host using the service-specific marker `/run/opsctl/restore/<service>.active` resolved under `env.Root`, with the marker mode `0600` and its `opsctl` and `restore` parent directories mode `0700`. After successful source validation and before stopping an initially active app, it MUST publish that marker; an existing marker MUST retain the original active intent when a retry finds the app inactive. An inactive app without a marker MUST NOT acquire activation intent. The marker MUST survive restoration failures and MUST be removed only after the intended app restart and all remaining restore actions succeed. Marker maintenance MUST produce no stdout step and MUST NOT change restored service data, host configuration, or unit enablement.
- R-XKEE-4ZE8: A disabled app MUST leave `Restore` disabled: `Restore` MUST never enable, disable, or start either unit of a disabled app, even when a restore activation marker exists for it, and MUST remove an existing marker for a disabled app once all remaining restore actions succeed; a failed restore stops units but never disables them, so a later retry of an app that was not disabled treats it by its marker as R-D4R8-7TVQ specifies.
- R-Y093-4019: `RestoreError.Stopped` MUST list, in the order the restore stopped them and omitting any it has started again, both `ikigenba-<service>.socket` and `ikigenba-<service>.service` exactly when the app was active on entry or carries restore activation intent from an earlier failed restore and is not disabled, and `litestream.service` exactly when this restore stopped it while it was active; the units of an app neither active on entry nor carrying that intent, and of a disabled app, MUST NOT appear even though the restore issued `systemctl stop` for them.
