# D13-host-backup

The host keeps its configuration and certificate separately from service data.
The backup package owns archive and retirement operations; the CLI renders their
results. Its existing D11 package boundary remains sufficient.

Retirement proves final database synchronization through Litestream's enabled
control socket before stopping `litestream.service`. The proof and its failure
policy are part of R-YUZK-TJ3U; a service-stop result alone is never
synchronization proof.

## REQUIREMENTS

- R-Y5DO-SCJ9: Package `internal/backup` MUST export `HostBackup(ctx context.Context, env host.Env, cloudEnv cloud.Env, store config.Store) (FileResult, error)`, using the D12 result shape for the host archive; CLI consumers MUST own textual rendering and exit-code selection.
- R-Y6LL-649Y: Package `internal/backup` MUST export `HostRestore(ctx context.Context, env host.Env, cloudEnv cloud.Env, store config.Store) (HostRestoreResult, error)`.
- R-HPY3-4JKF: Package `internal/backup` MUST export `HostRestoreResult` with exactly the fields `Object string`, `Size int64`, `Files int`, `SourceReady bool`, and `FilesRestored bool`, and `FailedStep string`.
- R-Y91D-XNRC: Package `internal/backup` MUST export `Retire(ctx context.Context, env host.Env, cloudEnv cloud.Env, store config.Store) (RetireResult, error)`.
- R-HR5Z-IBB4: Package `internal/backup` MUST export `RetireResult` with exactly the fields `Services []string`, `ServicesStopped bool`, `LitestreamStopped bool`, `SyncedDatabases []string`, `Files []FileResult`, and `Host FileResult`, and `FailedStep string`.
- R-YBH6-P78Q: `HostBackup`, `HostRestore`, and `Retire` MUST require nonempty `backup.s3_uri` and `aws.region`, checking the prefix first and returning respectively `backup.s3_uri not set` or `aws.region not set` before archive reads, object access, or unit operations when absent or empty; malformed S3 prefixes and configuration-read failures MUST likewise return operational errors before those effects, and all cloud object access MUST remain beneath the configured host prefix.
- R-YCP3-2YZF: Successful `HostBackup` MUST create exactly one zstd-compressed tar object containing the existing `/etc/ikigenba/` and `/etc/letsencrypt/` trees, with archive member names rooted at `etc/ikigenba` and `etc/letsencrypt`, preserving contents, directory structure, permissions, and symlink targets without dereferencing symlinks; missing source trees MUST be represented by their absence, and nothing under `/opt/`, `/etc/nginx/`, or systemd unit directories MUST be read or archived.
- R-YDWZ-GQQ4: `HostBackup` MUST sample `env.Now` once and name its object `<backup.s3_uri>host/<UTC RFC3339Nano timestamp>.tar.zst`, retaining the whole-second spelling when fractional seconds are zero, and use the create-only `cloud.Client.PutObject` contract; it MUST make no local filesystem mutations, unit operations, object deletions, or lifecycle changes, and MUST preserve every earlier object including on a collision matching `cloud.ErrAlreadyExists`.
- R-9TEE-6UL8: `HostBackup` MUST return a zero-value `FileResult` when no host archive was attempted and a `FileResult` with `Service` equal to `host` when an archive was attempted; `RetireResult.Host` MUST use the same zero-value-versus-`Service` discriminator. For a successful attempted archive, `Object` MUST equal the uploaded basename and `Size` MUST equal compressed bytes; archive-read, compression, and upload failures MUST populate its `Err` with a nil separate error, with no object published after a local read or construction failure, while configuration, cloud-opening, missing dependency, or cancellation failures before attempting the host archive MUST use the separate error with that zero-value result. Any failure after the host archive attempt begins MUST populate its `Err`, including an interruption; a whole-operation interruption MUST additionally use the separate error and retain that failed result.
- R-YGCS-8A7I: `HostRestore` MUST capture the configured source prefix and region and open its cloud client before replacing any configuration, list only the `host/` child of that prefix, and select the immediate child whose basename is a parseable RFC3339 timestamp followed by `.tar.zst` with the greatest timestamp instant, using ascending bytewise URI as the tie breaker; unrelated objects and nested keys MUST be ignored, `Object.Modified` MUST NOT determine recency, and no matching archive MUST return `no host backup found` without filesystem changes.
- R-YHKO-M1Y7: Before changing either destination tree, `HostRestore` MUST completely read and validate the selected archive, rejecting corrupt compression or tar data, absolute names, traversal components, entries outside `etc/ikigenba` and `etc/letsencrypt`, special device entries, and any extraction that would write outside those destination trees through links; download and validation failures MUST leave both existing trees untouched, and every returned object reader MUST be closed.
- R-YISK-ZTOW: Successful `HostRestore` MUST replace both destination trees with exactly their archived contents and permissions, preserving symlink targets and removing stale entries, including removing a destination tree omitted from the archive; it MUST use the captured source configuration throughout, leave `/opt/`, nginx output and unit files untouched, perform no unit control or nginx reload, and perform no cloud writes or deletions, so applying the restored configuration remains a subsequent `opsctl init` action.
- R-HUTO-NMJ7: `HostRestoreResult.Object` MUST be `host/` followed by the selected basename, `Size` MUST be the compressed bytes read, `SourceReady` MUST become true only after complete archive validation, `Files` MUST count restored regular files and symlinks but not directories, and `FilesRestored` MUST become true only after both replacements succeed; an operational failure MUST return the result of completed phases with an error, perform no later restore phase, and MUST NOT claim rollback of replacements already completed. `FailedStep` MUST be `source` for failure during object listing, selection, download, or archive validation, and `files` for failure during destination replacement; it MUST be empty on success or a configuration, dependency, cloud-opening or cancellation failure before source selection is attempted. A failed phase MUST NOT set its success flag, and an unattempted phase MUST have no outcome.
- R-I4KV-PSGR: `opsctl host backup` MUST call `HostBackup` and render a successful result as `host: ok (<object>, <size> KiB)` followed by a newline, dividing compressed bytes by 1024 and rounding to one decimal place; an archive result failure without a separate operational error MUST render `host: failed: <reason>` followed by a newline on stdout and exit 1 with empty stderr, success MUST exit 0 with empty stderr, and a separate operational error MUST exit 1 and use the D02 stderr diagnostic convention. If a host archive result accompanies that error, its success or failure row MUST remain on stdout and the diagnostic first line MUST be `opsctl: host backup failed`, without repeating the row's failure reason; otherwise stdout MUST remain empty.
- R-HX9H-F60L: `opsctl host restore` MUST call `HostRestore` and render each completed phase on stdout in order: `source: ok (<object>, <size> KiB)` with one decimal place for compressed bytes divided by 1024 when `SourceReady`, then `files: ok (/etc/ikigenba, /etc/letsencrypt, <count> files)` when `FilesRestored`, each followed by a newline; success MUST exit 0 with empty stderr, while an operational error MUST exit 1, retain completed stdout rows, and append `<step>: failed: <reason>` followed by a newline when `FailedStep` is nonempty, using that step name and the error's concise single-line cause without captured subprocess output. For a failed reported step the D02 diagnostic first line MUST be `opsctl: host restore failed at <step>` without repeating the failure reason; a preworkflow failure with empty `FailedStep` MUST leave stdout empty and retain its specific reason in the D02 diagnostic. Captured subprocess output MUST appear only in D02 quoted stderr detail.
- R-YOW2-WOED: `opsctl host --help` and `opsctl host -h` MUST print exactly `"Usage: opsctl host <subcommand>\n\nBack up and restore the host's own configuration: /etc/ikigenba/ and\n/etc/letsencrypt/, under 'host/' in backup.s3_uri. Nothing under /opt is\ntouched either way -- that is 'opsctl backup' and 'opsctl restore'.\n\nSubcommands:\n  backup    write /etc/ikigenba/ and /etc/letsencrypt/ to S3\n  restore   replace them with the newest backup\n\n'opsctl init' writes the timer that runs the backup at\nbackup.host_files_seconds.\n\nConfiguration keys:\n  aws.region      the region the backup bucket lives in\n  backup.s3_uri   the prefix this host backs up to\n"` to stdout, leave stderr empty, and exit 0 for any effective user id without reading or changing host state.
- R-YQ3Z-AG52: `opsctl host` with no subcommand MUST return exit 2 with empty stdout and exactly `opsctl: no host subcommand given\n\nsee 'opsctl host --help' for usage\n` on stderr; an unknown subcommand MUST do the same with first line `opsctl: unknown host subcommand '<name>'`; neither invocation MUST read or change host state.
- R-YRBV-O7VR: The action grammars MUST be exactly `opsctl host backup`, `opsctl host restore`, and `opsctl retire` with no operands or options; unsupported options or excess operands MUST produce exit 2, empty stdout, and an opsctl diagnostic followed by one empty line and `see 'opsctl host --help' for usage` for either host action or `see 'opsctl retire --help' for usage` for retire, on stderr without archive, cloud, or unit operations; D02 root refusal MUST apply to valid actions.
- R-YSJS-1ZMG: `Retire` MUST discover services by `apps.Discover` in ascending bytewise name order, include data-only services in the subsequent file backup, and stop each existing `ikigenba-<name>.service` before stopping `litestream.service`, without attempting to stop nonexistent service units; it MUST NOT stop a unit derived from a service name rejected by `apps.ValidateName`, and MUST return an operational error before any unit operations if discovery or validation of a discovered name fails.
- R-HYHD-SXRA: `Retire` MUST report successfully stopped existing service-unit names as directory basenames in `Services`, set `ServicesStopped` only once all selected existing app units are inactive, and set `LitestreamStopped` only once Litestream is inactive after the app units; service or Litestream stop failures MUST be returned as operational errors using `host.CommandError` for execution errors or nonzero process exits, prevent subsequent backup writes, and leave earlier stopped units stopped. `FailedStep` MUST be `services` for failure while discovering or validating service names, inspecting app units, or stopping them, and `litestream` for failure while stopping Litestream; it MUST be empty on success and on a preworkflow configuration, dependency or cloud-opening failure. Successful flags and prior archive results MUST survive later failures; no failed or unattempted phase MUST acquire a success flag.
- R-YUZK-TJ3U: After all app writers stop and while `litestream.service` is still running, `Retire` MUST synchronize every declared database serially in service-name order by executing `litestream sync -wait -timeout 60 -socket <root>/var/run/litestream.sock -json <root>/opt/<service>/<database.path>`, with the socket and database paths resolved under `env.Root`; it MUST make no automatic retry. A database is positively synchronized only when the command exits 0 and, allowing leading and trailing JSON whitespace only, stdout decodes as exactly one JSON object in which `db_path` is a string equal to the rooted database path and `txid` and `replica_txid` are both present unsigned-integer fields with equal values; a second JSON value, any other non-whitespace bytes, timeout, execution failure, nonzero exit, or context cancellation is a synchronization failure. After each positive proof, `SyncedDatabases` MUST append the declared database basename, retaining successful earlier entries if a later database fails. After all proofs succeed, or immediately after the first synchronization failure, `Retire` MUST attempt `systemctl stop litestream.service`; `LitestreamStopped` MUST become true only when that stop succeeds. A synchronization failure MUST remain the returned primary error with `FailedStep` equal to `litestream`, even if the subsequent stop also fails; it MUST prevent every D12 `Files` operation and `HostBackup`, leave app units stopped, and retain the successful synchronization entries. If synchronization and the subsequent stop both fail, the returned error MUST retain both causes with the synchronization failure first, so it remains the concise primary cause and D02 renders captured output from both command failures. A stop failure after otherwise successful proofs MUST likewise set `FailedStep` to `litestream`, retain `SyncedDatabases`, and prevent all archive operations. Only after every proof and the Litestream stop succeed may `Retire` invoke `Files` for all services and `HostBackup`, with their ordinary contents and database exclusions. `SyncedDatabases` MUST NOT be populated from declared names or merely because `systemctl stop` returned exit 0; when no database is declared, no sync command is run and the Litestream stop directly precedes archive operations.
- R-YW7H-7AUJ: `Retire` MUST sample its supplied clock exactly once for backup object naming and pass a copy of `env` whose `Now` returns that fixed instant to both `Files` and `HostBackup`, so every successful object of the invocation has the same UTC RFC3339Nano basename; a collision MUST remain a failed result rather than advancing one backup timestamp independently.
- R-DUOO-S3WL: During retirement file backup, a per-service failed `FileResult` without a separate whole-run operational error MUST NOT prevent attempts for remaining services or the host; a separate whole-run operational interruption MUST stop subsequent attempts while preserving all earlier results and the failed result of any archive being attempted; `RetireResult.Files` MUST retain every service result in service-name order and `Host` MUST retain the host result, earlier objects MUST remain untouched, and units MUST remain stopped after any archive failure without rollback, deletion, disablement, masking, timer changes, or automatic restart.
- R-DVWL-5VNA: For an ordinary successfully synchronized retirement whose archive run completes without a separate operational error, `opsctl retire` MUST render stdout lines in order: `services: ok (<comma-space-separated names> stopped)` or `services: ok (none)` when no existing app units were stopped; `litestream: ok (stopped, <comma-space-separated database basenames> synced)` or `litestream: ok (stopped)` when no databases were synchronized; then every service backup row using D12 formatting and the host row using `host backup` formatting, each newline-terminated; it MUST exit 0 exactly when all archive results succeeded, otherwise exit 1, with empty stderr in both cases.
- R-YZV6-CM2M: `opsctl retire --help` and `opsctl retire -h` MUST print exactly `"Usage: opsctl retire\n\nTake a host's final backup before it is discarded. Stop every service, then\nlitestream.service so it ships every committed change it holds, then copy\nevery service's files and the host's own configuration to backup.s3_uri\nexactly as 'opsctl backup' and 'opsctl host backup' would.\n\nNothing is deleted or disabled. The units are left stopped; a host kept after\nall comes back with 'systemctl start' or a reboot.\n\nConfiguration keys:\n  aws.region      the region the backup bucket lives in\n  backup.s3_uri   the prefix this host backs up to\n"` to stdout, leave stderr empty, and exit 0 for any effective user id without reading or changing host state.
- R-HZPA-6PHZ: When a retirement operational error occurs, the CLI MUST return exit 1, render completed report phases and any returned archive results on stdout, and append `<step>: failed: <reason>` followed by a newline when `FailedStep` is nonempty, using its name and the error's concise single-line cause without captured subprocess output. An operational failure during an attempted service or host archive MUST retain that failed archive result using its existing service or `host` row name; no additional failed phase row MUST duplicate it. The D02 diagnostic first line MUST be `opsctl: retire failed at <step>` when a failed phase or archive row identifies the failed step, or `opsctl: retire failed` for an interruption between completed steps, without repeating report findings; preworkflow failures MUST leave stdout empty and retain their specific reason in the diagnostic. Unattempted phases MUST have no row, no report MUST assert an uncompleted stop, synchronization, or backup succeeded, and captured subprocess output MUST appear only in D02 quoted stderr detail.
- R-Z2AZ-45K0: Host backup and restore MUST preserve the certificate material already present rather than request certificate issuance, and retirement MUST neither terminate the machine nor run another project; a caller such as an installed `devctl` remains responsible for deciding what to do after the reported result.
- R-Z3IV-HXAP: For a host with no discovered services and no declared databases, successful retirement MUST leave `Services` and `SyncedDatabases` empty, complete the Litestream stop phase, create only the host archive, and render exactly the `services: ok (none)`, `litestream: ok (stopped)`, and host backup lines, without enabling, disabling, masking, deleting, or restarting any unit.
