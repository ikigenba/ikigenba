# D05-init

`internal/cli` composes a complete, read-only preflight with the certificate,
nginx, replication and timer setup domains. Independent findings are reported
together; dependent checks disappear only when their inputs are unavailable.
Setup is ordered, idempotent, and silent on success. Domain designs own the
generated files and unit behavior.

The preflight also checks the two app timing keys, `apps.drain_seconds` and
`apps.stop_seconds` (D08), on its `timeouts` line, and the sequence ends with
the `apps` step, which writes their values into every installed app and
restarts the enabled apps whose values changed (D09). Changing either is
`config set` followed by `init`.

For names, the preflight looks only at `host.name`, the space's own name. `host.apex`
(declared in D06) is handed through untouched: every run reads it from the
store beside `host.name` and passes it to `cert.Obtain` and `nginx.Apply`,
whose contracts derive the apex name and refuse a value the host name cannot
carry. The `certificate` step is the first to read it, so such a refusal
surfaces as an ordinary first-step failure after a complete preflight report,
never as a preflight finding.

## REQUIREMENTS

- R-X0W0-0NJ4: `opsctl init --help` and `opsctl init -h` MUST, for any effective uid without reading configuration, running checks or setup, or changing state, exit 0 with empty stderr and stdout exactly the escaped string `"Usage: opsctl init\n\nRun the setup sequence behind one preflight. Every check is evaluated and\nreported, one line per check, before anything runs; when any check fails,\nnothing runs and init exits 2. Safe to re-run.\n\nChecks, in order:\n  nginx, certbot, systemctl  each found on PATH\n  litestream                 found on PATH\n  dns.provider, dns.zones    set, and the provider opens (see 'opsctl dns --help')\n  host.name                  set\n  timeouts                   apps.drain_seconds and apps.stop_seconds are positive\n                             whole seconds, stop greater than drain\n  zone NAME                  every configured zone is reachable and delegated\n  host NAME                  host.name lies at or under a configured zone\n  wildcard NAME              host.name and _opsctl-preflight.host.name resolve alike\n\nSequence:\n  certificate  obtain the host's certificate, or renew it if it is due\n  nginx.conf   generate /etc/nginx/conf.d/ikigenba.conf and reload nginx\n  litestream   generate /etc/litestream.yml and enable litestream.service\n  timers       write the backup and renewal units, enabling each backup timer\n               whose period is set and the renewal timer always\n  apps         write the drain and stop settings into every installed app,\n               restarting each enabled app whose settings changed; a\n               disabled app is rewritten and left disabled\n\nConfiguration keys:\n  host.name           the fully-qualified name this host answers at, at or under a configured zone\n  apps.drain_seconds  how long an app may drain when stopped (default 5)\n  apps.stop_seconds   how long systemd waits for an app to stop (default 10)\n"`.
- R-LHM7-9IEQ: `init` MUST be composed by `internal/cli` using the D1 `Deps` boundary and the D3 `config.Store` rooted at `Deps.Root`; the configuration key `host.name` MUST identify the one fully-qualified host name used by the host certificate, nginx, and service names, at or below a configured DNS zone.
- R-LIU3-NA5F: `init` MUST look up `nginx`, `certbot`, `systemctl`, and `litestream`, in that order, through `Deps.LookPath`, and print for each `<name>: ok (<path>)` with its returned path or `<name>: failed: not found on PATH` on a lookup error.
- R-LK20-11W4: `init` MUST validate `dns.provider` independently of `dns.zones`: print `dns.provider: failed: not set` when unset or empty, otherwise call `Deps.DNS.Open` with the configured provider value and print `dns.provider: ok (<value>)` on success or `dns.provider: failed: <error>` with its error text on failure; a nil opener MUST be treated as the D4 unknown-provider error, with no network call.
- R-LMHS-SLDI: `init` MUST validate `dns.zones` independently of the provider: print `dns.zones: failed: not set` when unset or empty; otherwise parse comma-separated name/id entries using exactly the D4 `dns.Open` grammar and normalization, print `dns.zones: failed: dns.zones malformed: <entry>` for the first invalid entry rendered with `%q`, or `dns.zones: ok (<names>)` with normalized names comma-separated in configured order.
- R-ZAOK-6AFV: When and only when the provider and zones checks pass, `init` MUST obtain the zone-check client through `dns.Open` with the current store and a `dns.Env` retaining `Deps.DNS.LookupNS` whose `Open` returns the already-opened provider without opening it again, call `Client.Check` for every configured zone, and print the corresponding D4 `dns check` line with only `zone ` prepended, so its full form is `zone <zone>: <status>` with the zone name appearing once before the status; a zone failure MUST NOT suppress any other zone check.
- R-LOXL-K4UW: When and only when the zones and host.name checks pass, independently of provider or zone-check success, `init` MUST use `dns.Client.ZoneFor` with the parsed zones to print `host <name>: ok (zone <zone>)` for the longest matching zone or `host <name>: failed: no configured zone contains it` for `dns.ErrNoZone`, with the normalized host name.
- R-LQ5H-XWLL: When and only when the host.name check passes, `init` MUST resolve both `<name>` and `_opsctl-preflight.<name>` through `Deps.LookupHost`, even if either lookup fails, without a cloud or instance-metadata query; it MUST print `wildcard <name>: ok (<addresses>)` only when both results succeed with equal nonempty sets after canonical IP spelling, IPv4-mapped IPv6 unmapping, sorting and deduplication, or `wildcard <name>: failed: <name> resolves to <a> but _opsctl-preflight.<name> resolves to <b>` when the sets differ or either is empty, or `wildcard <name>: failed: <error>` on a lookup error (the host lookup error takes precedence when both fail); sets MUST be comma-separated with an empty set rendered as an empty string, and an invalid returned address MUST be treated as a lookup error naming that address.
- R-X23W-EF9T: The report from `init` MUST contain exactly one newline-terminated line for each of `nginx`, `certbot`, `systemctl`, `litestream`, `dns.provider`, `dns.zones`, `host.name`, and `timeouts`, in that order, followed by eligible zone lines in configured order, then the eligible host and wildcard lines, in that order, entirely on stdout; every eligible check MUST run despite earlier findings and no setup action may run before the entire report has been written.
- R-LSLA-PG2Z: When any preflight check fails, `init` MUST exit 2 with empty stderr and without invoking any setup operation or creating, modifying or removing persistent host state; the preflight itself MUST be read-only even when all checks pass.
- R-X3BS-S70I: When all preflight checks pass, `init` MUST invoke exactly these domain operations in order, advancing only after success: `cert.Obtain` (D07) for `certificate`, `nginx.Apply` (D06) for `nginx.conf`, `backup.SetupReplication` (D11) for `litestream`, `backup.SetupTimers` (D12) for `timers`, and `apps.SetupTimeouts` (D09) for `apps`; the resulting certificate, nginx configuration, replication configuration and enablement, backup unit pairs and period-controlled timers, always-enabled renewal timer, and installed apps' drain and stop settings MUST satisfy those domain contracts.
- R-ZIB1-SI40: Every `init` run MUST read setup inputs from the current config store, including the current `host.apex` value (empty when unset), and pass the normalized `host.name` as `hostName`, the current `acme.email` (empty when unset) as `email`, and `apex` true if and only if that `host.apex` value is nonempty to `cert.Obtain` (D07); pass the normalized `host.name` as `hostName` and that `host.apex` value as `apexApp` to `nginx.Apply` (D06); and pass that store to `backup.SetupReplication` and `backup.SetupTimers`; each operation MUST receive `host.Env` carrying the normalized D1 dependencies and `Deps.Root`, and current manifests under that root MUST determine generated nginx and replication configurations as their domain contracts specify.
- R-ZKQU-K1LE: The `init` preflight MUST NOT read or report the config key `host.apex`: for any store, the preflight report on stdout, the set of checks run, and the preflight outcome (whether the sequence starts, or the exit 2 when a check fails) MUST be byte-identical whether `host.apex` is unset, empty, or set to any value, including one that `host.Apex` (D01) refuses for the normalized `host.name`.
- R-ZLYQ-XTC3: When every preflight check passes and the current `host.apex` is nonempty while `host.Apex` (D01) refuses the normalized `host.name`, `init` MUST fail at the `certificate` step: stdout MUST hold the complete preflight report, stderr MUST be exactly `opsctl: host.apex is set but host.name '<name>' has no parent domain\n` with `<name>` the normalized `host.name`, the exit code MUST be 1, no `host.Env.Execute` call may be made, `nginx.Apply`, `backup.SetupReplication`, and `backup.SetupTimers` MUST NOT be invoked, and no persistent host state may be created, modified, or removed.
- R-LW8Z-URB2: A successful setup sequence MUST leave stdout containing only the preflight report, leave stderr empty, and exit 0; re-running with unchanged store, manifests, prerequisite results and a certificate not due for renewal MUST preserve generated file bytes and configured unit state and produce byte-identical stdout and the same exit code.
- R-LXGW-8J1R: On the first setup operation error, `init` MUST stop the sequence, preserve earlier successful setup state without rollback, leave the completed preflight report on stdout, exit 1, and write `opsctl: <error>\n` to stderr with D2 failure-detail formatting when the error contains `host.CommandError`; no later setup operation may run.
- R-LYOS-MASG: An `init` invocation rejected for arguments MUST run no checks or setup operations and change no persistent state; configuration corruption or another store read failure preventing preflight MUST likewise change no persistent state, invoke no setup, and leave stdout empty, with non-corruption read failures producing exit 1 and stderr `opsctl: <error>\n`.
- R-LZWP-02J5: `init` MUST obtain all preflight configuration successfully before emitting the report; a missing config file or key MUST be treated as unset configuration findings rather than an operational error, and a corrupt store MUST retain exactly its original bytes.
- R-ZBWG-K26K: For an effective uid of 0, `opsctl init` with a nonempty argument list other than exactly `["--help"]` or exactly `["-h"]` MUST write exactly the three lines `opsctl: init takes no arguments`, an empty line, and `see 'opsctl init --help' for usage` to stderr, nothing to stdout, and exit 2.
- R-EFHE-I0W6: `opsctl init` other than `--help` and `-h` MUST be subject to the root check of D2.
- R-ELKW-EVLN: `init` MUST read the config key `host.name` and print `host.name: failed: not set` when it is unset or empty, and otherwise `host.name: ok (<name>)` where `<name>` is the value lowercased with one trailing dot stripped.
- R-3EJ4-MMM3: When `config.json` is corrupt, `opsctl init` MUST write nothing to stdout, write to stderr exactly the line `opsctl: <path> is corrupt` where `<path>` is the resolved path of `config.json`, and exit 1.

- R-X4JP-5YR7: `init` MUST obtain the app timing settings through `apps.ReadTimeouts` (D08) from the current store and print `timeouts: ok (drain <D>s, stop <S>s)` with the returned values in decimal, or `timeouts: failed: <error>` with the returned error's text when it reports an invalid or inconsistent value; this check MUST run independently of every other check, and a failed `timeouts` check is a preflight failure like any other, so nothing in the sequence runs and `init` exits 2. A store read failure from `ReadTimeouts` other than a timing finding MUST instead be handled as the other preflight configuration reads are.
- R-Y3WS-9B9C: Every `init` run that reaches the `apps` step MUST pass `apps.SetupTimeouts` (D09) the current config store and a `host.Env` carrying the normalized D1 dependencies and `Deps.Root`, so each installed app's `DRAIN_SECONDS` and service stop timeout take the store's values and restarts follow D09's `SetupTimeouts` contract, a disabled app being rewritten and left disabled.
