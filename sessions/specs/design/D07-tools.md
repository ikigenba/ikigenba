# D07-tools

The twelve MCP tools through which agents, and the `turns` command on each person's machine, reach sessions through the MCP gateway: `internal/tools`. They are sessions' only API. The `turns` command asks with `get_latest_turns` which turns the service already holds for each session it read, and sends the rest with `push_turns`. An agent lists root sessions with their figures with `list_sessions`, totals them by week or month, grouped by kind, person, tool or command, with `total_sessions`, and reads and keeps the three tables that turn turns into figures: the kind rules with `list_rules`, `add_rule` and `remove_rule`, the price table with `list_prices`, `set_price` and `remove_price`, and the away limit with `get_away_limit` and `set_away_limit`. Every signed-in caller reads every person's sessions and changes the tables (decisions log D1); the caller a tool is handed is used as the owner and person of a session a push creates, and as the trail's user. What is kept, what is refused and why, and how the figures follow a change are `D04-store`'s; the figures themselves are `D05-figures`'; the trail event and its recorders are `D08-trail`'s; where the tools are mounted and how the run builds their configuration is `D03-serve`'s; the tools page, which lists `mcp.Server.Tools()` in the catalog order `Register` registers them in, each description cut with `tools.FirstLine`, is `D06-pages`'.

## The tools

In catalog order, each with the effect appkit's `mcp` registers it with:

- `push_turns` (additive) takes `sessions`, a list of entries, each a session's `tool`, `id`, optional `parent` (a `tool` and `id`), `host`, `directory`, `headless`, optional `command` (`name` and `argument`) and `turns`, each turn a `moment`, `whose`, `model` and four token counts `input`, `cached`, `output` and `reasoning`. It keeps the batch whole or refuses it whole, and answers `sessions`, one entry per input entry in input order, each the entry's `tool` and `id` and `latest`, the latest moment held for that session after the write, left out when none is held.
- `get_latest_turns` (read) takes `sessions`, a list of `tool` and `id` pairs, and answers the same shape as `push_turns`, writing nothing.
- `list_sessions` (read) takes the optional filters `period` with `of`, `person`, `kind`, `tool`, `host` and `command`, and `page` and `limit`, and answers `sessions`, the root sessions newest first, each with its `tool`, `id`, `host`, `person`, `directory`, `headless`, `command` (left out when it has none), `first`, `last`, `kind`, `attention_seconds`, `wall_seconds`, `agent_seconds`, `tokens` (`input`, `cached`, `output`, `reasoning`, `total`), `unpriced`, `dollars` and `subagents`, then `next`.
- `total_sessions` (read) takes `period`, `from`, optional `to`, `group` and the same optional filters but the period, and answers `periods`, oldest first, each its `start` and `groups`, each group its `group` name, the same figures as a row and `sessions`, the number of root sessions in it.
- `list_rules` (read) answers `rules`, each its `host`, `directory`, `command` and `kind`.
- `add_rule` (additive) takes `host`, `directory`, optional `command` and `kind`, and answers the rule kept.
- `remove_rule` (destructive) takes `host`, `directory` and optional `command`, and answers the rule removed, its kind included.
- `list_prices` (read) answers `prices`, each its `model`, `effective` date and four rates `input`, `cached`, `output` and `reasoning`, in USD per million tokens.
- `set_price` (additive) takes a `model`, an `effective` date and the four rates, creates or replaces that row, and answers the price kept.
- `remove_price` (destructive) takes `model` and `effective`, and answers the pair it removed.
- `get_away_limit` (read) answers `minutes`.
- `set_away_limit` (additive) takes `minutes` and answers it.

sessions checks almost nothing itself: every value reaches the store as the caller gave it, and the store's refusal is relayed. The tools' own checks are the paging members of `list_sessions` and an empty `sessions` list on `push_turns`, which the store would accept as a query of nothing and the tool refuses with `store.NoSessions`, as `get_latest_turns`' empty list is refused.

## How a call runs

Each tool calls one store method, once, with the call's arguments byte for byte, the push and the read of the latest turns mapped member by member onto the store's own entry types. A change a rule, a price or the away limit makes recomputes every root session's figures inside the store call, so once a changing tool has answered, `list_sessions` and `total_sessions` answer over figures that reflect it. The outcome is the store's:

- It answered: the call is answered with the data the store returned, rendered as Answers says.
- It refused (`*store.RefusedError`): the call is refused with the refusal's `Reason`, unaltered.
- Anything else (`store.ErrUnreachable`, a failing or closed handle, a done context): the call is refused with `store.Unreachable`.

Each of the six changing tools records exactly one `change.finished` through its own recorder of `D08-trail`, on every one of those outcomes and on its own refusal of an empty push, before it answers: `push_turns` through `trail.PushTurns`, `add_rule` `trail.AddRule`, `remove_rule` `trail.RemoveRule`, `set_price` `trail.SetPrice`, `remove_price` `trail.RemovePrice`, and `set_away_limit` `trail.SetAwayLimit`, each with `trail.Result` of the store's error. A call appkit's `mcp` refuses for its arguments never reaches the tool and records nothing. Reads record nothing.

## Paging

`list_sessions` pages as the suite's listing convention asks, on the contract of appkit's `paging` package, as dummy's `list_widgets` does. Its input declares `page` and `limit` as pointer fields carrying `paging.PageDescription` and `paging.LimitDescription`; its answer is `sessions` then `next`, carrying `paging.NextDescription`, present exactly when at least one root follows. The order is the store's list order: first moment descending, then tool descending, then id descending. The token is `paging.Token{Tool: "list_sessions"}` over three fields, the last answered row's first moment as Unix milliseconds, its tool and its id; the next page is the roots that follow that position in list order, whether or not a root still holds it. The tool asks the store for one row more than the window and sets `next` only when that row came back. A `limit` outside 1 to `paging.MaxLimit` is refused with the text of `paging.Window`'s error, then a `page` the token does not decode with `paging.BadPage`, before the store is read; then the store's refusals of the filters follow. A token does not bind the filters, as appkit's paging says.

`get_latest_turns` and `push_turns` are bounded by the store's limits (`store.MaxLatestSessions`, `store.MaxPushSessions`, `store.MaxPushTurns`). `list_rules` and `list_prices` answer whole (see Recorded decisions). `total_sessions` is bounded by `store.MaxPeriods` periods and the groups of each.

## Answers

Moments are RFC 3339 in UTC with exactly three fractional digits and `Z`, as `2026-10-13T14:02:11.250Z`. Dates (a price's `effective`, a period's `start`) are `YYYY-MM-DD`. Durations are whole seconds, truncated, in members named with the unit. Dollars are decimal text to the cent, rounded half up from the exact amount (`figures.Money`'s `Dollars`); a total rounds its own exact sum. Rates are `figures.Rate`'s canonical text, so a price set as `0.20` is answered `0.2`. Token counts are integers, with `total` their sum. Every member is present, a list `[]` when empty, but `latest`, a row's `command` and `next` are left out when there is none.

## Refusals

A refusal is an MCP error result with one text block: one of the store's refusal constants (`D04-store`), `store.Unreachable`, or one of appkit's two paging texts. A refusal is its text alone.

## Recorded decisions

- Departure from the suite's RFC 3339 to the second: **moments are answered to the millisecond, always three fractional digits**. Two turns a second apart must stay ordered and distinct, the store keeps milliseconds (`D04-store`), and the `turns` command compares the `latest` it is answered with the moments it read; a fixed width keeps the text sortable as text.
- **Enumerated members are plain strings, not appkit enum types.** `tool`, `whose`, `kind`, `period` and `group` are validated by the store, which refuses with its own sentence, so an agent meets one kind of refusal for every bad value and a refused push is recorded in the trail as `refused`; an enum offence would be answered by appkit before the tool runs and leave no `change.finished`.
- **Optional members are pointers** (`parent`, `command`, the filters, `to`, a rule's `command`, `page`, `limit`), since appkit's schema derivation allows no `json` tag options; an absent, null or empty filter is no filter. Within an object every member is required: a `parent` names both `tool` and `id`, a `command` both `name` and `argument` (empty when none), a turn its model (empty for a person or tool turn) and all four counts.
- **`headless` and `turns` are required on every push entry**; an entry with `turns` `[]` writes nothing and reports `latest`, as `get_latest_turns` does.
- **An empty push is refused with `store.NoSessions`**, mirroring `get_latest_turns`, before the store is called, and recorded as `refused` with every count zero.
- **Argument descriptions are one copy constant per meaning, not per member name** (departure from accounts, whose three member names each meant one thing everywhere): `input` is a token count on a turn and a rate on a price, `host` is a session's machine on a push and a rule's key on a rule, `command` is an object on a push and a name in a filter or rule. One constant serves each member wherever its meaning is the same: `tool` and `id` in a push entry, a parent and a `get_latest_turns` pair; the five filters in `list_sessions` and `total_sessions`; a rule's key in `add_rule` and `remove_rule`; a price's key in `set_price` and `remove_price`. The struct tag repeats the constant because appkit reads only the tag, and a requirement binds the two.
- **Changes answer what they kept, not a count**: `add_rule` the rule, `remove_rule` the rule removed with the kind it held (which the call does not name), `set_price` the price with its rates in canonical text, `remove_price` the pair it removed, `set_away_limit` the minutes. The roots a change recomputed are the trail's (`D08-trail`), not the answer's.
- **`set_price` and `set_away_limit` are additive** although they replace a value, as ledger's `set_book` and candidates' `edit_park_rules`: nothing is lost that the caller cannot set back, and the turns are kept, so every figure follows.
- **Member names follow precedent where the sheet left them open**: durations carry their unit (`attention_seconds`, as candidates names units in members), rows identify a session by `tool` and `id`, the four token counts and their total sit in one `tokens` object, a list's collection member is its plural noun (`sessions`, `periods`, `rules`, `prices`, as dummy and accounts), and a removed price is answered as `model` and `effective`, the members the call named.
- Departure from `shape/`'s Listing, which pages any list an agent can add to: **`list_rules` and `list_prices` are answered whole**, with no `page`, `limit` or `next`. Both are configuration tables, a handful of rules and a price row per model and effective date, bounded in practice, and the contract for this delivery settled them whole; paging them would make an agent walk tokens to read a table it edits a row at a time.
- **The list token holds the first moment as Unix milliseconds**, an `int64`, then the tool and id, the store's keyset (`D04-store`); paging's token carries only `int64` and `string` fields.
- **A failure is answered with `store.Unreachable` alone**, as accounts, quoting nothing of the cause.
- Excluded from this document: which tools the one exec'ing test calls is `D01-layout-and-run-seam`'s; what each refusal constant says is copy.

## Consumer tasks

`web.Handler` (`D03-serve`) calls `tools.Register(cfg.MCP, tools.Config{Store: cfg.Store, Telemetry: cfg.Telemetry})` once; the tools page lists `srv.Tools()`, each description cut with `tools.FirstLine`.

The `turns` command, through the gateway, calls `get_latest_turns` with `{"sessions":[{"tool":"claude","id":"<id>"},...]}` for every session it read, then `push_turns` with `{"sessions":[{"tool":"claude","id":"<id>","parent":{"tool":"claude","id":"<parent>"},"host":"ld01","directory":"/mnt/projects/x","headless":false,"command":{"name":"/deliver","argument":"~/Documents/x.md"},"turns":[{"moment":"2026-10-13T10:00:00.000Z","whose":"person","model":"","input":0,"cached":0,"output":0,"reasoning":0},...]},...]}`, leaving out `parent` and `command` when it has none, and reads each entry's `latest`. An agent calls `total_sessions` with `{"period":"week","from":"2026-10-13","group":"command"}`, `list_sessions` with `{"command":"/deliver"}` and walks `next` as `page`, and changes the tables with `add_rule`, `remove_rule`, `set_price`, `remove_price` and `set_away_limit`. A rule moves sessions with no push: `add_rule` then `list_sessions` answers each matching root with the rule's kind; and a new away limit moves attention: `set_away_limit` then `total_sessions` answers the attention recomputed under it.

A test opens its own database with `db.Open` and `Migrations()`, builds `store.New` over it with its own clock and a writer with `telemetry.New` over a `*telemetry.Capture`, registers the tools on `mcp.NewServer`, serves it inside `identity.Require` with `httptest`, and calls `mcp.Client.CallTool` as one or two callers with `tools.PushTurnsArgs{...}` and the rest as JSON. It decodes `structuredContent` into `tools.LatestList`, `tools.SessionList`, `tools.Totals` and the rest, walks `next`, compares a refusal's text with a store constant it provoked, `store.Unreachable`, `paging.BadPage` and `paging.Window`'s error, compares answers with what a second store over its own database answers for the same calls, flips `SetFailing(true)` on the handle for failures, and after `Flush` reads `change.finished` events from the capture.
