# D01-layout-and-run-seam

sessions keeps the space's record of agent sessions: one Go binary behind the host's nginx that takes content-free turns pushed by the `turns` command from each person's machine, derives attention, wall time, agent time, tokens, dollars and kind of work from them under the rules, prices and away limit it holds, records every write in telemetry's trail, offers its MCP tools at `/mcp`, its only API, and serves a read-only landing page, a tools page, an about screen and the not-found page to a signed-in user (outcomes 1, 9 and 10). The turns, rules, prices and setting live in the app's own SQLite database, `state/sessions.db` (`D04-store`); the derivations are pure functions over them (`D05-figures`). It emits nothing on the bus and accepts nothing from it. Among its siblings it calls none, and outside the suite it reaches nothing. Outcomes cited as outcome N are those of /home/mgreenly/Documents/ikigenba-sessions.md.

This design is the structural ground the others stand on: where the code lives and what each package is for, the seam through which the process is run so every part can be tested without a real process, the settings and how they are read, the database path, where the identity and the display string come from, the binary's wiring, and the rule that sessions calls no sibling. It follows the suite's app layout less what sessions has no use for: no bus, no sibling client, no guest route, no address package, no host.

The module is `github.com/ikigenba/ikigenba/sessions`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/sessions`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/sessions` is wiring only.

## The dependencies

sessions depends on one module besides the standard library: appkit, required at a published release with no `replace` directive. Its `db` package brings the pure-Go SQLite driver, which keeps the release build cgo-free. sessions uses appkit's `db`, `version`, `services`, `page`, `paging`, `identity`, `mcp` and `telemetry`, and restates none of their contracts. It uses neither `events` nor any sibling client.

## Where the environment is read

`main` makes the one read of the environment that is not `Run`'s own: it calls appkit's `version.Read` exactly once, first, and holds the result, the **identity**, whose `String()` is the **display string**. It hands the identity to `page.New`, whose banner carries its `Release` and `Commit` to every page's footer and to the about screen, and the display string to the `mcp.ServerConfig` its `Process.MCP` builds and to `Run` as `Process.Version`. Nothing below `main` calls `version.Read`.

`Run` reads every variable through `Process.LookupEnv`: `DRAIN_SECONDS` once at start, through `settings.Read`; `LISTEN_PID`, `LISTEN_FDS` and `NOTIFY_SOCKET` for the socket and readiness; and `IKIGENBA_SERVICES` once, when it starts to serve. That is the whole set of five. appkit's constructors also read `IKIGENBA_SERVICES` from the process environment; that read is appkit's.

## Packages

The root package, named `sessions`, holds what the module embeds: `Assets` (the four templates `about.html`, `landing.html`, `notfound.html` and `tools.html`), `Etc` (`manifest.toml` and `nginx.conf`) and `Migrations` (`0001_sessions.sql`, whose bytes `D04-store` states). `share/icon.svg` is packed beside `bin/` and `etc/` by `devctl build` and is not embedded (`D09-on-a-space`).

The internal packages hold the concerns, one each; the document named declares each package's shapes and their behavior:

- `internal/cli`: the run seam, `cli.Process` and `cli.Run` (this document); the commands, the exit codes, `cli.Manifest` and `cli.Usage` (`D02-cli`); the serve path (`D03-serve`); `cli.NginxConf` (`D09-on-a-space`).
- `internal/settings`: the one setting, `DRAIN_SECONDS` (this document).
- `internal/server`: a listener's life (`D03-serve`).
- `internal/web`: the route table, `web.Config` and `web.Handler` (`D03-serve`).
- `internal/store`: the turns, sessions, rules, prices, away limit and the stored per-root summaries, and the migration (`D04-store`).
- `internal/figures`: the pure derivations of attention, wall time, agent time, tokens, dollars, kind and periods from turns, rules and prices, with no database and nothing of the app imported (`D05-figures`).
- `internal/trail`: the telemetry trail of every write (`D08-trail`).
- `internal/pages`: the templates' data and the page routes, `pages.Handler`, `pages.Config`, `pages.Description`, `pages.Set`, `pages.Load`, and the auth and sign-in addresses (`D06-pages`); `pages.ServiceName` (this document).
- `internal/tools`: the tools, `tools.Register` and `tools.Config`, their descriptions and refusals (`D07-tools`).

There is no events package: sessions emits no bus event and accepts none. There is no host package: sessions runs no program and reaches nothing outside the suite. Which package imports which is guidance, not contract; that `figures` depends on nothing of the app is the shape `D05-figures` gives it. Template data types, tool argument and result types, copy constants and the constants a package uses only itself are declared by the document that owns the package's behavior, not here.

## The run seam

The run seam is `cli.Run`, which takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package, and returns the exit code. sessions reaches no sibling, so `Process` carries no client and no sibling's address. The times sessions keeps are the ones pushed to it; `Now` is the clock the present moment is read from: the moment that places the current week the landing page shows, every event's time, and the time appkit's `db` records a migration applied at. `Sleep` is the pause the writer waits with between delivery attempts. `Rand` is the source of every request id the run mints; sessions mints no id of its own. `Inherit`, `Now` and `Rand` are the caller's to give whenever `Args` is empty: `Run` has no default for any of them, and the choice of the process's own descriptor 3, `time.Now` and `crypto/rand.Reader` is made once, at the process boundary, by `cmd/sessions`. Telemetry's socket reaches `Run` through the services file `IKIGENBA_SERVICES` names (`D03-serve`).

## Settings

sessions reads one value at start. `DRAIN_SECONDS`, the space's, is how long a stopping server waits for requests in progress (`D03-serve`); unset or empty it is 5 seconds, spelled as opsctl writes an integer, and refused otherwise, as every app of the suite reads it. The away limit is not a setting of the environment: it is a value the store holds and the tools change (`D04-store`, `D07-tools`).

## Paths

Relative to `Process.Dir` (the process's working directory when empty) the database is `state/sessions.db`, opened with `db.Open`, the root package's `Migrations()` and `Process.Now`; `state/` is created when absent. sessions writes nothing outside `Dir` and nothing under it but the database.

## What reaches the server, the tools and the pages

`Run` builds one store, over the database, and every tool and page of the run reads that one. It hands `web.Handler` (`D03-serve`) one `web.Config` holding the banner source, the MCP server, the services file's path, the store, the writer and the settings. From it the tools take the store and the writer (`tools.Config`, `D07-tools`), and the pages take the banner source, the template set, the services file's path, the store and the MCP server whose tools the tools page lists (`pages.Config`, `D06-pages`). No consumer holds a clock of its own: the store is built with `Process.Now` and the writer stamps events with its own; `pages.Config` carries no clock, so the present moment reaches the landing page through the store (`D04-store` declares how its config carries it). Those documents declare the fields; this one fixes only what reaches them.

## Siblings and the outside

sessions calls no sibling; telemetry is reached through appkit's sink, as every app reaches it. Outside the suite it reaches nothing: it runs no program, and no session file of Claude Code, Codex CLI or Grok CLI is read by it; turns reach it only in a push. The design makes this observable at three seams: `cli.Process` has no HTTP client and no sibling address; `Run` looks up no variable but the five this document names; and a `Run`-level test that names every sibling in the services file, each on a listener that records every connection, exercises every tool and page and proves none is reached.

## Recorded decisions

- **No events package and no `EventSink`**: sessions emits and accepts no bus event, so `Process` has no `EventSink`, `trail` holds only telemetry events, and the manifest declares no `[events]`.
- **No host and no `IKIGENBA_SANDBOX`** (departure from accounts): accounts reads `IKIGENBA_SANDBOX` and `ACCOUNTS_HOST_COMMAND` only to choose its host; sessions has no host and nothing that runs differently in a sandbox, so neither variable is read, `settings.Settings` holds only `DrainSeconds`, and there is no `HostFields`. This follows ledger and artifacts, whose key set is the same five. `IKIGENBA_COMMIT` and `IKIGENBA_RELEASE` are read by appkit's `version.Read` in `main`, not by `Run`.
- **`internal/figures` is added** to accounts' layout: the derivations are pure, so they are proved over turns, rules and prices a test composes, without a database (`D05-figures`).
- **`Rand` stays** although sessions mints no id: appkit's writer and request middleware draw request ids from it, and the test discipline injects it.
- **`Now` places the current week**: sessions stamps no created time of its own, since every moment it keeps is pushed; the present moment it reads is the one that places the landing page's current week, proved at `Run` level by a clock the test hands in.
- `Process.Inherit`, `Process.Now` and `Process.Rand` are required whenever `Args` is empty; no requirement states the precondition, because no permitted test can observe a default.
- **`Migrations` names its one file here**, `0001_sessions.sql`, whose bytes `D04-store` states.
- **The exec'ing test calls `push_turns` and `list_sessions`**, the write and the read every other check builds on.
- **`pages.ServiceName` is declared here**: `main`, the banner kit, the MCP server, the database and the manifest all need the name; `pages.Description` stays `D06-pages`'.

## Consumer tasks

`main` calls `id := version.Read()` and `v := id.String()` and hands `cli.Run` a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Version` is `v`, whose `Banner` is `page.New(pages.ServiceName, id).Banner`, whose `Inherit` takes the process's own descriptor 3, whose `Now` is `time.Now`, whose `Rand` is `crypto/rand.Reader`, and whose `MCP` returns `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Version: v, Telemetry: w})` over the writer `w` it is given, leaving the rest zero; it cancels the context on `SIGTERM` or `SIGINT` with a cause whose `Error` is the signal's name, and exits with what `Run` returns.

`internal/cli`, serving, reads `s, err := settings.Read(p.LookupEnv)`; opens `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "sessions.db"), Migrations: sessions.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: p.Stderr})`; builds `st := store.New(d, cfg)`, `cfg` the `store.Config` `D04-store` declares, carrying `p.Now`, and the writer `w := telemetry.New(telemetry.Config{Service: pages.ServiceName, Version: p.Version, Sink: sink, Stderr: g, Now: p.Now, Sleep: p.Sleep, Rand: rnd})`, `g` being a gate over `p.Stderr` that passes lines until `Run` closes it, once the writer is shut down, and drops them after, so nothing reaches `p.Stderr` after `Run` returns (`D03-serve`); and hands `web.Config` the banner, `p.MCP(w)`, the services path, `st`, `w` and `s`, and `s.Drain()` to `server.Serve` (`D03-serve`).

A test of the run seam builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` over a map, an `Inherit` returning a listener it bound, a `Now`, a `Sleep` and a `Rand` it controls, and a `*telemetry.Capture` as `Sink`; calls `cli.Run`, waits for `READY=1`, drives `/mcp` with `mcp.Client` and the pages with raw HTTP, cancels, and inspects `Dir` and the capture. A test of settings calls `settings.Read` with a lookup over a map.
