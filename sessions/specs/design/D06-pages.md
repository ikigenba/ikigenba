# D06-pages

What sessions draws as HTML: `internal/pages`, the four templates `landing`, `tools`, `about` and `notfound` of the root package's `Assets()` and the data each is executed with, `pages.Description`, the auth and sign-in addresses the pages build, and the page handler that answers `/`, `/tools`, `/about` and every other path the route table (`D03-serve`) hands it: the landing page, which shows the business's time in agent sessions for this week and the eight weeks before it, by kind of work (outcomes 7 and 9), the tools page, the about screen and the not-found page. The pages are read-only: they carry no form, no per-record page and no paging, change nothing in the record and reach no sibling; every change goes through a tool (`D07-tools`). A guest is sent to sign in. Outcomes cited as outcome N are those of /home/mgreenly/Documents/ikigenba-sessions.md.

`D01-layout-and-run-seam` declares `pages.ServiceName` and the root package's `Assets()`; `D03-serve` routes every path that is not `/mcp` and not under `/_appkit/` to this handler inside `identity.Optional`, and defines a request's caller and a guest; `D04-store` declares `store.Store`, its `Landing` report (`store.Landing`, `store.Week`, `store.KindTotals`), `store.ErrUnreachable` and `store.Unreachable`; `D05-figures` declares `figures.Figures`, `figures.Tokens`, `figures.Money`, `figures.Kinds` and `figures.Seconds`; `D07-tools` registers the tools the tools page lists, in its catalog order, and declares `tools.Register` and `tools.FirstLine`; `D09-on-a-space` carries `pages.Description` in the manifest. appkit's `page`, `identity`, `mcp` and `services` packages own their contracts.

## The pages

The landing page, `/`, is the root of the banner's trail. It asks the store for its landing report once per request and draws it: the away limit as it stands, and, when the store holds any session, nine weeks, the current UTC week first and the eight before it, newest first, each with one row per kind in the order plan, build, publish, operate, sell, customer, untagged, a total row, and the untagged share of the week's attention. When the store holds no session the page draws no week at all. Which root counts in which week and what each figure is are the store's and the figures' (`D04-store`, `D05-figures`); this page only turns them into the text the template shows. Every signed-in user sees the same page: the figures are the business's totals over every person's sessions, and nothing on it is one person's (D1).

The tools page lists every tool registered on the MCP server, in registration order, which is `D07-tools`' catalog order, each with the first line of its description as `tools.FirstLine` takes it; the about screen shows the service's name, the banner's `Release` and `Commit`, and `pages.Description`. Each is one level below the root, `pages.ToolsLevel` and `pages.AboutLevel`. Every other path is the not-found page, 404, whatever the method. The query is ignored on every page.

The banner's user is the caller's email with auth's profile and sign-out addresses built on `pages.Auth`. The **auth address** is the `URL` of the services file's entry `auth`, every trailing `/` removed, or, with no such entry, built from the request's scheme and host with any port and a leading `sessions.` removed. The **sign-in address** is the auth address, then `/?return=`, then the request's own address query-escaped (`pages.SignIn`).

## The landing's figures as text

Each figure the template shows is derived from the store's typed values in one stated way. A duration (attention, wall time, agent time, and the away limit) is drawn from its whole seconds, `figures.Seconds`, any part of a second dropped: the seconds, the whole hours in them, and the whole minutes left over, the seconds dropped. Tokens are the sum of the four counts, `figures.Tokens.Total`, written as a decimal integer grouped by commas in threes from the right. Dollars are `figures.Money.Dollars()`, which rounds to the cent once, from the exact sum. A week's start is its Monday as `YYYY-MM-DD`. The untagged share is the untagged row's whole seconds of attention over the total row's, as a whole percent rounded to nearest with halves up, and 0 when the total has no whole second of attention; it is computed over whole seconds so that it agrees with the durations the page shows, and the template draws no share at all for such a week.

## Guests, methods and failures

The handler decides in this order. A guest is answered 302 to `pages.SignIn` with an empty body, whatever its path and method, before anything else is read. A signed-in request to a path that is not one of the three page paths is the not-found page, whatever its method. A request to a page path whose method is not `GET` or `HEAD` is 405 with `Allow: GET, HEAD` and an empty body. None of these reads the store. Then the landing reads the store: when it cannot, the answer is 503 in plain text with the line `store.Unreachable`. The tools page, the about screen and the not-found page read nothing and are served the same while the store fails. `HEAD` is answered as `GET` without a body. No answer sets a cookie.

## Recorded decisions

- **One data type per thing a template draws**, each field list exactly the template comment's, in its order (the root `AGENTS.md`'s Web assets rule): `LandingData` with `Week`, `FiguresRow` and `Duration`, `ToolsData` with `ToolRow`, `AboutData` and `NotFoundData`. `FiguresRow` serves both an entry of a week's `Kinds` and its `Total`, since the template draws both with one figures template; the total's `Kind` is empty.
- **No paging, and no page values** (departure from accounts' landing, which pages two lists): the landing shows a fixed nine weeks of seven rows each, bounded whatever the store holds, so shape's Listing entry does not apply; the store answers the nine weeks from its stored summaries in one call (`D04-store`). A query on `/` is ignored, and the not-found template's comment, which says sessions has no page values, holds.
- **No host** (departure from accounts): sessions reaches no host, so `pages.Config` is accounts' less `Host`, and the only failure the landing answers is the store's.
- **No time layout** (departure from accounts' `MinuteLayout`): the pages show no stamp; a week's start is a date, `YYYY-MM-DD`, and its `time` element carries the same text.
- **Durations from whole seconds, truncated**: `figures.Seconds` drops any part of a second, so the minutes shown never round up past the figure the tools answer in `attention_seconds` and the like (`D07-tools`); hours are not capped at 24, since a week's attention may exceed a day.
- **The untagged share over whole seconds, halves up**: computed from the same whole seconds the template shows, so that 0 attention shows no share, and rounding half up as the suite rounds money; the template's "0 when the week has no attention" is read as "no whole second".
- **Tokens are the total of the four counts**, grouped by commas: the template's "every token the tool reported, of every kind". The unpriced count is not on the page; the template has no field for it.
- **A database outage is a plain-text 503 with `store.Unreachable`**, as the suite's apps answer where the answer is not a page; the landing template has no unavailable state.
- **The guest's redirect follows `D03-serve`** (pages inside `identity.Optional`, with `guests = false` in the manifest so nginx gates too). A guest is sent to sign in before the method or the query is looked at, and the 302 has an empty body.
- **`pages.Auth` and `pages.SignIn` are declared here**, with the host prefix `sessions.`: the pages are their only consumer and sessions has no address package (`D01-layout-and-run-seam`).
- **The tools page reads the MCP server's registered tools**, `mcp.Server.Tools()`, at each request: `D03-serve` hands `pages.Config` the server on which `tools.Register` registers `D07-tools`' tools in catalog order, so the page and `tools/list` cannot disagree, and each row's description is `tools.FirstLine` of the registered description.
- **`pages.Description` is a copy constant declared without a value**, and `D09-on-a-space` ties the manifest's description line to it by name.
- **`pages.Config` carries no clock**: the present moment that places the current week is the store's (`store.Config.Now`, `D04-store`), read at each request.

## Consumer tasks

`web.Handler` (`D03-serve`) calls `set, err := pages.Load()` once and serves every page path with `identity.Optional(pages.Handler(pages.Config{Banner: cfg.Banner, Pages: set, ServicesPath: cfg.ServicesPath, Store: cfg.Store, MCP: cfg.MCP}))`, `tools.Register` having filled the server.

The landing reads `l, err := cfg.Store.Landing(ctx)` and executes `landing` through `set.Write(w, r, http.StatusOK, "landing", pages.LandingData{Banner: b, AwayLimit: pages.Duration{…}, Weeks: []pages.Week{{Start: wk.Start.Format("2006-01-02"), Kinds: []pages.FiguresRow{{Kind: string(k.Kind), Attention: …, Wall: …, Agent: …, Tokens: "18,204", Dollars: k.Figures.Dollars.Dollars()}, …}, Total: …, UntaggedShare: …}, …}})`, `b` being `cfg.Banner(page.User{Email: …, ProfileURL: pages.Auth(r, cfg.ServicesPath) + "/", LogoutURL: pages.Auth(r, cfg.ServicesPath) + "/logout"})` with a nil `Trail`. The tools page maps `cfg.MCP.Tools()` to `[]pages.ToolRow{{Name: t.Name, Description: tools.FirstLine(t.Description)}, …}` with `b.Trail` set to `[]page.Level{pages.ToolsLevel}`; the about screen executes `about` with `pages.AboutData{Banner: b, Description: pages.Description}`, `b.Trail` set to `[]page.Level{pages.AboutLevel}`; the not-found page executes `notfound` with `pages.NotFoundData{Banner: b}`.

A test opens a store over its own database with a clock it sets, pushes sessions with `Push` and changes rules, prices and the away limit with the store's methods, writes a services file with a URL for `auth`, or none, and entries for at least one sibling naming a Unix socket on which a fake records each connection, builds its own set with `pages.Load()`, a server `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Telemetry: w})` (after `t.Setenv` of `IKIGENBA_SERVICES`) on which it registers tools, serves `identity.Optional(pages.Handler(cfg))` with a fixed banner, sends raw requests with and without `X-User-Id`, and compares each body with what `set.Write` writes for the data the definitions below build, from the store's `Landing` answer or from values it states. It turns the store's handle `SetFailing(true)` on to see the 503.
