# D02-cli

sessions as a command: what `cli.Run` does with the arguments `D01-layout-and-run-seam` hands it through `Process`, the exit codes it returns, what `db status` reports of the database, the usage text, and what the `sessions` binary answers to each command. `D01-layout-and-run-seam` declares the names this design behaves through: `cli.Process` with its `Version`, the display string `main` read, `cli.Run`, the root package's `Etc` and `Migrations` and the `settings` package. This document declares `cli.Manifest` and binds it to the embedded `etc/manifest.toml`; the manifest's bytes are `D09-on-a-space`'s, and so is `cli.NginxConf`. What happens when there are no arguments, serving and its refusals included, is `D03-serve`'s.

## The commands

The arguments decide everything. An empty `Args` means serve, and everything from there is `D03-serve`'s, the startup refresh and the answer when no socket is passed in included (`D03-serve` states it at `Run` and at the binary). The three recognised single arguments each write one product to `Stdout` and return `ExitSuccess` without touching anything else: `--version` writes `Process.Version`, the display string `main` read, and a newline, which is one empty line when the environment sets no identity; `manifest` writes `cli.Manifest`; and `--help` writes `Usage`. The one two-word command, `db status`, reports the database's migrations. Any other `Args` is a usage error. The argument sessions complains about is the first one it does not take: the first element when that is not a recognised word, or when it is `db` standing alone; the word after `db` when that is not `status`; the word after `db status`; and otherwise the second, which is surplus whatever it says. An argument that starts with `-` is an unknown option, any other an unknown command. The diagnostic follows the repository's command-line conventions: its first line begins `sessions: `, and after exactly one empty line comes the hint to run `sessions --help`. The usage text is never written to `Stderr`.

Arguments are checked before anything else. A command needs no socket and no setting, and only `db status` reads the database, so `sessions --version` succeeds with nothing passed in and `sessions bogus` fails whatever the environment holds, a refused `DRAIN_SECONDS` included. Unless `Args` is empty, `Run` touches none of the environment, the inherited descriptor, systemd's notification socket, the clock, the pause, the random source, the sink, the banner source or the server maker, and only `db status` reads anything under the working directory. The startup refresh is the serve path's (`D03-serve`). A command records no event: the trail is what sessions records while it serves.

## db status

`db status` is an operator's look at the database: which of the migrations the binary carries `state/sessions.db` has had applied, and when, which it has not, and any it records that the binary does not carry. What it prints is appkit's `db.Status`, called with the path `state/sessions.db` resolved against `Process.Dir` and the migrations `sessions.Migrations()` returns, writing straight to `Stdout`; sessions adds nothing and states nothing about the lines' format. `db.Status` only looks: before sessions' first start every migration is reported pending and the directory is left as it was. When it returns an error, sessions says so on one line, `sessions: ` and the error's text with each newline replaced by a space, and exits 1; whatever `db.Status` had already written to `Stdout` stays there, since findings are product.

## Exit codes

`ExitSuccess` (0), `ExitServerFailed` (1) and `ExitUsage` (2), as every app. A usage error, a setting refused (`D01-layout-and-run-seam`) or a socket missing or doubled (`D03-serve`) is 2; a database that will not open, a startup refresh that fails or a drain that ran out on requests (`D03-serve`), or a `db status` that fails, is 1.

## The usage text

`Usage` is what `--help` prints: the synopsis, what sessions is, the commands and options above, and what each exit code means. No program parses it, so it is a copy constant: declared by name, its words in the source, and a test compares `Stdout` with the constant itself.

## The binary

The one exec'ing test runs the built binary with `--version`, twice: once with `IKIGENBA_COMMIT` (longer than seven characters) and `IKIGENBA_RELEASE` set, expecting the display string it computes with `version.Read().String()` under the same two values, and once with neither, expecting exactly one empty line. It runs it with `manifest`, comparing stdout with `cli.Manifest`; with `bogus`, expecting `ExitUsage` and the diagnostic; and bare, with no socket passed in, expecting the answer `D03-serve` states.

## Recorded decisions

- **The pattern is accounts' `D02-cli`, minus its host.** sessions has no host package and runs no host command, so nothing here names a host command or the operator's CLI; every other choice follows accounts, the newest app, so that no departure from precedent is recorded here.
- **`cli.Manifest` is declared here, its bytes in `D09-on-a-space`.** The constant and its equality with the embedded `manifest.toml` belong with the `manifest` command, as the suite's apps place them; what the manifest says is a matter of the space, so `D09-on-a-space` states its value. `devctl build` refuses an app whose `manifest` output and `etc/manifest.toml` differ, and the equality requirement proves they cannot, by use: a test in the external test package `sessions_test` reads `manifest.toml` from `sessions.Etc()` with `fs.ReadFile` and compares it with `cli.Manifest`.
- **`Usage` is a copy constant**: no program parses `--help`. The usage-error diagnostic stays spelled because it is an error line a caller matches.
- **`db status` is exempt from "creates nothing" only as far as appkit's read-only open requires**: a directory that holds no database stays empty, and what `db.Status` reports is the same after as before, since a read-only open of a WAL database may leave `-shm` and `-wal` files.
- **The exit codes are three declarations and one behaviour**, so a renamed or revalued constant re-mints one id.
- **The bare invocation is `D03-serve`'s**: this document routes an empty `Args` to the serve path and states nothing more of it.
- **The binary's commands are stated at the binary as well as at `Run`**, because only the exec'ing test proves `main` hands `Run` the display string `version.Read` computes, shortened commit included, and the arguments after the program name.

## Consumer tasks

A developer types `sessions --version`, `sessions manifest` or `sessions --help` and reads stdout; an operator types `sessions db status` in `/var/opt/ikigenba/sessions` before or after a deploy; `devctl build` runs `sessions manifest` and compares its output with the release's `etc/manifest.toml`.

A test builds a `cli.Process` with only `Args`, `Stdout` and `Stderr` (two `bytes.Buffer`s), `Dir` (an empty temporary directory) and, for `--version`, `Version` set, calls `cli.Run(ctx, p)`, and compares the returned value with `cli.ExitSuccess` or `cli.ExitUsage`, `Stdout` with `p.Version + "\n"`, `cli.Manifest` or `cli.Usage`, and `Stderr` with the exact diagnostic; it then lists `Dir` and finds it empty. To prove nothing else is touched it sets `LookupEnv`, `Unsetenv`, `Inherit`, `Now`, `Sleep`, `Banner` and `MCP` to functions that record a call, `Rand` to a reader that records a read and `Sink` to a sink that records any use, and asserts none was used. A test of `db status` makes a database under its `Dir` with `db.Open` and `sessions.Migrations()` (or puts a file there that is not a database), closes it, runs `cli.Run` with `Args` `["db", "status"]`, and compares `Stdout` with what its own `db.Status` call writes for the same path and migrations before and after, and `Stderr` with `"sessions: "` and that call's error text.
