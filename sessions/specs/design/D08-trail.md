# D08-trail

The trail as a whole: the one event that tells every change a tool call asks of sessions, its result, the one event that tells the refresh serve finishes at startup, the closed set of event names sessions records, the request pair the telemetry middleware records for every request, and secrecy, stated once for the whole app. sessions calls no sibling and has no bus, so it records no `sibling.called` and no `event.lost`.

Who records each name is another document's, but for the two declared here. The request pair is appkit's `telemetry.Middleware`'s, which `D03-serve` mounts on every request; `tool.called` is appkit's MCP server's; `service.started` and `service.stopping` are the run's, through its writer (`D01-layout-and-run-seam` states what `service.started` carries). `change.finished`, `refresh.finished`, their constants, the three result constants, the six change recorders, `trail.Refresh` and `trail.Result` are declared here, in package `trail`. Which tool calls which recorder is `D07-tools`'; the startup refresh and where it sits in the start is `D03-serve`'s; what the store keeps, refuses and recomputes is `D04-store`'s. This document states what each recorder records and what the assembled run shows.

## One event per change

Each call of one of the six changing tools (`push_turns`, `add_rule`, `remove_rule`, `set_price`, `remove_price`, `set_away_limit`) is told in the trail by exactly one `change.finished`, whether the store made the change, refused it or failed. Every one carries `tool`, the name of the tool called, and `result`, `ok`, `refused` or `failed`; each tool then carries its own fixed further keys, every one always present:

- `push_turns`: `sessions`, the number of entries the push answered; `turns_new`, the turns it created; `turns_changed`, the held turns whose model or counts it changed. Counts only: no session id, parent, host, directory, tool, command, model or moment.
- `add_rule`: `host`, `directory`, `command` (the command name, empty for any command) and `kind`, as the call named them, and `roots`, the root sessions whose summary the change recomputed.
- `remove_rule`: `host`, `directory` and `command`, as the call named them, `kind`, the kind of the rule the store removed (empty when it removed none), and `roots`.
- `set_price`: `model`, `effective` (the date as the call named it) and `roots`.
- `remove_price`: `model`, `effective` and `roots`.
- `set_away_limit`: `minutes`, as the call named it, and `roots`.

Text values are strings; counts and minutes are integers. `ok` is a change the store made and answered; `refused` is one it refused for its input or its state (`D04-store`'s `*RefusedError`); `failed` is everything else, `store.ErrUnreachable` among it. A refused or failed call records every count zero: `sessions`, `turns_new` and `turns_changed` for a push, `roots` for a setting change, while the named configuration values (host, directory, command, kind, model, effective, minutes) are still the call's. `trail.Result` maps a store error to the three, so the tools classify an outcome one way.

The refresh a setting change starts is part of that call: it completes before the tool answers, and its count is the `roots` of the call's `change.finished`, not an event of its own.

The time is the event's own `Time`, read from the run's clock, and the caller is the event's `User`, with the call's request id as its `RequestID`; no attribute repeats either, and the caller's email is never recorded. The event is recorded under the tool call's context, before that call's `tool.called`. A read (`get_latest_turns`, `list_sessions`, `total_sessions`, `list_rules`, `list_prices`, `get_away_limit`), a page and any request that is not a tool call record none.

Each recorder takes the call's context, the writer and plain values, records one event under the request id and user of the `identity.Caller` on that context, queues and returns, returns nothing, and is safe to call from many goroutines at once.

## The startup refresh

serve finishes, before it listens, any refresh a crash left incomplete (`D04-store`'s `FinishRefresh`, `D03-serve`). Every start records it as one `refresh.finished`, with `roots` the root sessions it recomputed (zero when none was pending) and `result`, under no request id and no user, after `service.started` and before any request's events. `trail.Refresh` records it.

## The request pair

Every request, whatever its path and whether or not it carries an identity, is recorded by the telemetry middleware as one `request.started` (method, path) and one `request.finished` (status, duration, bytes), under its request id and its caller's user. A guest's request to a page is answered with a redirect to sign in (`D06-pages`) and records the pair with no user; a request to `/mcp` with no identity is refused by appkit's `identity.Require` and records the pair likewise.

## Secrecy

sessions holds no secret, but it holds what people did: where they worked, what they ran and with which model. Its events carry tool names, results, counts, the rules' and prices' configuration, the away limit, methods, paths, statuses and times. No event carries a session's id or its parent's, its host, its directory, its command's name or argument, a turn's model or moment, a caller's email, or any text a store refusal relays. The rule is proved at the run seam, by use: every session id, parent's id, host, directory, command name, command argument and turn model the test pushes, every session id it asks `get_latest_turns` about, every filter value the test hands a read, and every email header the test sends hold a random **marker**, and every capture of the run is searched for every marker without regard to letter case. Values the trail records by design (a rule's host, directory, command and kind, a price's model and effective date, the minutes, user ids, request ids and paths) hold no marker, so a marker found is always a leak; the test keeps its rules' directories apart from its sessions' directories so the two are never the same text. A failing store is reached only at the tools seam, so a second search runs there over calls whose store fails.

## Recorded decisions

- **The run-level promises are bounded to a clean run**, as accounts: they hold when the sink delivers without delay, serving does not fail before the stop signal, and no request is cut off at the drain deadline `D03-serve` states.
- **One name, `change.finished`, with the tool as an attribute**, as accounts and for its reason: a change is an attempt with three endings and every ending is recorded; a past-tense name per kind (`rule.added`) would read as done on a refusal. A query for one tool's changes filters on `tool`.
- **A key set per tool, not one set for every tool** (departure from accounts, whose four keys are on every `change.finished`). sessions' tools name different things (a batch of turns, a rule, a price, a limit); a union of every key, mostly empty, would be thirteen keys of which three mean something. Within a tool every key is always present, so a query never meets a missing key.
- **One recorder per tool, not one `Change` with free arguments** (departure from accounts' `trail.Change`). The keys differ per tool, and typed parameters fix them where the tools call them, so a tool cannot record another's keys; each recorder fixes its own `tool` value, so it is never spelled by the caller.
- **The push records counts only, and no host.** A batch may span sessions on several hosts; one host would misdescribe it, and a list would carry what the sheet keeps out (where people work). Which sessions a push touched is answered by `list_sessions`.
- **`remove_rule` records the removed rule's `kind` as the store answered it**, not an argument: the call names only the key. A refused or failed removal removed no rule, so its `kind` is empty.
- **No price rates in `set_price`'s event.** The rates are a value the database answers (`list_prices`); the event names which row changed.
- **A setting change's refresh is the call's `roots`, not a second event.** One call, one event, as accounts; the refresh completes inside the call before it answers. A refresh with no call, the one serve finishes at startup, has its own name, `refresh.finished`, since it has no tool, caller or request.
- **Every start records `refresh.finished`, `roots` zero included.** `FinishRefresh` answers zero both when nothing was pending and when a pending refresh had no roots, so the event cannot be kept to starts that did work; recording every start is deterministic and shows each start's refresh ended `ok`.
- **Counts zero on a refusal or a failure.** Nothing was written, so nothing is counted; the configuration the call named is kept, since it says what was attempted.
- **Counts, roots and minutes are integer values, not strings** (departure from accounts, whose attributes are all strings because all are names). appkit's contract carries integers in their basic form `int64`, and a count is filtered and summed as a number; a string would make every consumer parse it and sort `10` before `9`. Names stay strings.
- **Arguments recorded as the call named them**, not as the store normalized them, so a refused call records what was asked.
- **The caller is the event's `User`, not an attribute**, as accounts; the caller's email, which the store keeps as a session's person, never reaches the trail.
- **`trail.Result` is declared here**, as accounts, so the classification of a store outcome is one function the tools and this document's tests use. A store failure is the only failure a tool meets, so the tools never pass `ResultFailed` themselves.
- **`failed` is proved at the tools seam** (departure from accounts, which proves it at `cli.Run` through a stub host). sessions has no host; its only failure is the store's, provoked with `SetFailing(true)` on the handle the store was built over, which only a test that builds the tools' configuration holds.
- The time and request-id stamping of every event is `D01-layout-and-run-seam`'s (its writer's clock and random source); this document proves only that a change's event takes the request id of its call.
- Markers are compared without regard to letter case.

## Consumer tasks

The tools (`D07-tools`) call, with the tool call's context, once the store has answered: `trail.PushTurns(ctx, cfg.Telemetry, len(p.Sessions), p.New, p.Changed, trail.Result(err))` after `Push` answered `p, err`, passing zeros when `err` is not nil; `trail.AddRule(ctx, w, host, directory, command, kind, n, trail.Result(err))` with the call's arguments after `AddRule` answered `_, n, err`; `trail.RemoveRule(ctx, w, host, directory, command, string(r.Kind), n, result)` after `RemoveRule` answered `r, n, err`, `r` the zero rule when `err` is not nil; `trail.SetPrice(ctx, w, model, effective, n, result)` with the call's `model` and `effective`; `trail.RemovePrice(ctx, w, model, effective, n, result)`; `trail.SetAwayLimit(ctx, w, minutes, n, result)`; `n` zero whenever `err` is not nil. A call appkit's `mcp` refuses for its arguments never reaches the tool and records nothing. serve (`D03-serve`) calls `trail.Refresh(ctx, w, n, trail.Result(err))` after `FinishRefresh` answered `n, err`, with a context carrying no caller, after the writer's `Ready` and before it serves.

A unit test builds a writer with `telemetry.New(telemetry.Config{Service: "sessions", Sink: capture, Now: now, Rand: rnd})` over a `*telemetry.Capture`, calls each recorder under `identity.NewContext(ctx, identity.Caller{UserID: u, Email: e, RequestID: q})`, flushes the writer, and compares the captured event's `Name` with `trail.EventChangeFinished` or `trail.EventRefreshFinished`, and its `Attrs`, `RequestID` and `User`. A test of `Result` hands it nil, a `*store.RefusedError`, one wrapped with `fmt.Errorf("%w")`, `store.ErrUnreachable`, a wrapped `store.ErrUnreachable` and an `errors.New` error. A tools-seam test registers the tools with `tools.Register` on `mcp.NewServer` over a store on its own database, serves it inside `identity.Require`, calls each changing tool with `mcp.Client`, flips `SetFailing(true)` on the handle for failures, and reads the capture after `Flush`. A run-level test drives `cli.Run` with a `*telemetry.Capture` as `Sink`, a fixed `Now` and a `Rand` that never repeats an id; waits for `READY=1`; calls every tool, each call with an `X-Request-Id` of its own; requests the pages as a guest and as a user; cancels; and compares each captured event's `Name` with the closed set, the `refresh.finished` with its place, and the `change.finished` under each call's request id with that call and its `tool.called`. A test of secrecy runs the conditions R-I8ZH-K0MD names and searches the capture for every marker.
