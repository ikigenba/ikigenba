# D04-store

The record: `internal/store`, which owns sessions' tables in its SQLite database, `state/sessions.db`, and every read and write of them. It holds the sessions and their turns as the `turns` command pushes them, the three tables that turn turns into figures (the kind rules, the price table and the away limit), and one stored summary per root session, the figures `D05-figures` derives, kept so that the list's filters and order run in SQL over an index. This document declares the store's whole public surface: its records, every method with its signature, what each does, the refusals every consumer relays, the one error every consumer answers with one line when the database cannot be reached, the refresh that keeps the summaries true, and the migration. Which tool calls which method is the tools' (`D07-tools`); the landing page reads `Landing` (`D06-pages`); the trail reads the counts the changing methods answer (`D08-trail`). Opening, migrating, transactions and the failure seam are appkit's `db`; `D01-layout-and-run-seam` resolves the path, declares the root package's `Migrations()` and builds the store; `D03-serve` calls `FinishRefresh` before ready. The derivations themselves (root, attention, wall, agent time, tokens, dollars, kind, periods) are `D05-figures`' pure functions; the store keeps their results and never defines a figure of its own.

## One database, one writer

sessions is the only writer of its database. `store.New` builds a store over a handle and opens or creates nothing. What a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds; a test proves the record that way, never by reading tables. A store whose handle is failing (`SetFailing(true)`), or closed, answers every call with an error matching `ErrUnreachable` and changes nothing. `Config.Now` is the clock that places the current week for `Landing`, the one time the store reads itself; every other time it keeps is a moment a push carried. `Run` hands in `Process.Now`, and the store has no default for it.

## Inputs in wire form, outputs typed

Every input carries the wire's strings: moments as RFC 3339, dates as `YYYY-MM-DD`, rates as decimal text, and tools, kinds, periods and groups by name. The store validates each and refuses what it cannot accept with a `*RefusedError` whose `Reason` is one of its refusal copy constants, one constant per cause, which the tools relay as accounts' tools relay theirs. Outputs are typed: `figures.Tool`, `figures.Kind`, `time.Time` in UTC at millisecond precision, `figures.Figures` and `figures.Summary`. A refusal is decided before anything is written; a refused call changes nothing.

## Sessions and turns

A session is keyed by the pair (tool, id): the tool it ran in and the opaque id that tool gave it. Its parent, when it ran as a subagent, is another pair, possibly of another tool (a Codex job dispatched from a Claude session). A turn is keyed by its session's pair, its moment and whose turn it was; a turn pushed again under the same key is the same turn, and its model and four counts take the pushed values, so a turn first pushed mid-stream with partial counts is corrected by the next push, and a repeat of an identical push changes nothing. A push is all-or-nothing and one write: either every entry is valid and every turn is kept, with the summaries of every root the push touched recomputed in the same write, or nothing is written.

A session is created by the first push entry that carries a turn for it, with that entry's fields, the caller's user id as its owner and the caller's email as its person. Later entries change no field it holds, except that a command or a parent held empty is filled by the first later entry that carries one. A push for a session another user owns is refused. An entry with no turns is a query: it writes nothing and only reports the latest moment held, as `Latest` does for up to `MaxLatestSessions` pairs.

A parent link is kept only where it would not close a cycle: a parent that is the entry's own pair is refused, and a parent whose own chain of held parents reaches back to the entry's session is kept as none, so every chain ends and every session has one root. A session whose parent is not held is its own root until the parent arrives; then it, and everything under it, rolls up into the parent's root, and its own summary is no longer reported.

## The stored summary and its refresh

The store keeps one summary per root: its first and last moments, person, host, tool, command name and kind, and `figures.Summarize` of the root and its descendants under the rules, prices and away limit held. A push recomputes the summaries of the roots it touched inside its own write. A change of a rule, a price or the away limit recomputes every root before the method returns, in pages of `BatchSize` roots in key order, each page its own transaction (`shape/`'s Bounded work), and the change itself marks the refresh pending in the same write that makes it; the last page clears the mark. A process that dies between pages leaves the mark, and `FinishRefresh`, which serve calls before ready, recomputes the rest. So once a method has answered, `Sessions`, `Totals` and `Landing` answer over summaries that reflect it.

A root's tree, the root and every held descendant with their turns, is read by one query bounded by that root's own rows. `Sessions` is a window filtered, ordered and limited by the database, keyset by first moment descending, then tool descending, then id descending, over the index `summaries_first`; `Totals` walks the summaries in its range a page of `BatchSize` at a time and folds each into its period and group, holding only the answer.

## Errors

`ErrUnreachable` is the store's one error, and every consumer answers it with `Unreachable`, never quoting the cause: a failing or closed handle, a done context, and a call given a value no consumer sends (an empty user id). Before anything else, a done context and a failing or closed handle answer `ErrUnreachable`, whatever the arguments. Every other non-nil error the store returns is a `*RefusedError`.

## The migration

The schema is one migration, `0001_sessions.sql`, whose bytes are contract, as accounts' are: the tables `sessions`, `turns`, `summaries`, `rules`, `prices` and `settings`, the indexes behind the parent and root walks and the list's order, and the seed: the twelve prices of the decisions log's D11, each effective 2026-01-01; the three rules of D9 on host `ld01` with no command; and the away limit of 15 minutes with no refresh pending. Moments are kept as integer Unix milliseconds, durations as integer nanoseconds, rates as the decimal text they were given, and exact dollars as `figures.Money`'s text. A later release that needs more adds it by an expand migration.

## Recorded decisions

- **The derived figures are stored, one summary per root** (departure from every earlier app, whose lists read only what was written; the sheet's ruling): shape/'s Storage wants a list's filters, the kind among them, and its order in SQL over an index, and kind and figures computed on read would make every filtered page scan the turns. The cost is a recompute of every root after a rule, price or away-limit change, which shape/'s Bounded work allows as disk and time in pages, and a mark that survives a crash between pages so the start can finish it.
- **The session's person is the caller's email, kept beside the owner's user id** (departure from accounts, which keeps only user ids): the person filter, the rows and the grouping by person are read by agents, who know people by email, not by opaque ids. The owner, which decides who may push to a session, stays the user id; the email is the one at the session's creation and never changes.
- **Moments to the millisecond** (departure from the suite's RFC 3339 to the second, recorded on the wire in `D07-tools`): two turns a second apart must stay ordered and distinct, and a tool's turns often are. The store truncates finer digits, so two moments equal to the millisecond are one moment, and keeps integer milliseconds.
- **The migration's bytes are contract**, as accounts': the build run writes the file, and the seed is a decision (D9, D11) a byte-for-byte requirement keeps from drifting; the expand-migration requirement and a test's incomplete refresh name its tables and columns. A fresh store's answers are stated as well, so the seed is proved by use too.
- **A refresh's pending mark is a pair in `settings`**, `refresh_after_tool` and `refresh_after_id`: NULL for none, otherwise pending. The code may keep there the key of the last root recomputed, but the contract is only that `FinishRefresh` recomputes every root while a refresh is pending, so the invariant that every answered row is current holds once it returns. A test leaves a refresh incomplete by setting the empty pair through `DB.Write`, the one way to simulate a crash between pages deterministically. A change made while a refresh is pending restarts it from the first root.
- **`SessionRow` begins with `Tool` and `ID`** (the addendum listed `ID` first and `Tool` after `Directory`): the fields open with the session's key, as the (tool, id) pair identifies it everywhere.
- **The one-page-plus-one bound sits with the caller**: `Sessions` answers at most the `n` it is asked for, and the tool asks for paging's window plus one, so the store never holds more than the caller's page plus one row.
- **Moments before 1970 are refused**: the zero `time.Time` means "none held" in `LatestTurn`, so a moment at year 1 would be indistinguishable from none; no agent CLI writes a turn before the Unix epoch.
- **A parent that would close a cycle is kept as none**, not refused: the fill-once rule alone does not prevent cycles (a session held without a parent can later be given, as its parent, one of its own descendants, or two sessions can arrive in one push each naming the other), and refusing would block the pusher's whole batch on every retry. Entries are applied in input order, so the first-arriving link wins.
- **`BadParent` also refuses a parent whose tool `figures.ParseTool` refuses** (beyond the amendment's empty member): a parent is a session reference, and the vocabulary admits only the three tools, so a parent of any other tool could never be held.
- **`RemoveRule` answers the removed rule**, as held, so the trail's rule-removed event carries its kind, which the caller does not name.
- **Which refusal is answered is fixed**: the limits, then each entry in input order with its fields in a stated order, then ownership; so a test and an agent see one cause for one bad batch.
- **New and Changed count turn keys against what was held before the call**, so a key repeated within one push counts once, and its last occurrence is what is kept.
- **A turn count above `MaxTurnCount` (10^12) is refused**: `figures` sums saturate at their bound, and one absurd count would otherwise pin every total it reaches. No tool reports a single turn anywhere near a trillion tokens.
- **The refresh count is the roots held**: every table change recomputes every root, even when the change makes no difference to any figure, so its answer is predictable and the trail's `roots` is the size of the work done.
- **Totals ignore `Filter.Period` and `Filter.Of`**: the query's own period and range bound it.

## Consumer tasks

The tools (`D07-tools`), `c` the `identity.Caller` and `st` the store, call: `push_turns` `p, err := st.Push(ctx, c.UserID, c.Email, entries)`, answering `p.Sessions` (each `Latest` omitted when zero); `get_latest_turns` `ls, err := st.Latest(ctx, refs)`; `list_sessions`, after `n, err := paging.Window(a.Limit)` and decoding `a.Page` into the position's three fields (`First` as Unix milliseconds, `Tool`, `ID`), `rows, err := st.Sessions(ctx, f, pos, n+1)`, setting `next` from the `n`th row's `First.UnixMilli()`, `Tool` and `ID` when `n+1` rows came back; `total_sessions` `ps, err := st.Totals(ctx, store.TotalsQuery{...})`; `list_rules` `st.Rules(ctx)`; `add_rule` `r, roots, err := st.AddRule(ctx, a.Host, a.Directory, a.Command, a.Kind)`; `remove_rule` `r, roots, err := st.RemoveRule(ctx, a.Host, a.Directory, a.Command)`, the trail taking the removed rule's kind from `r`; `list_prices` `st.Prices(ctx)`; `set_price` `pr, roots, err := st.SetPrice(ctx, store.PriceInput{...})`; `remove_price` `roots, err := st.RemovePrice(ctx, a.Model, a.Effective)`; `get_away_limit` `d, err := st.AwayLimit(ctx)`; `set_away_limit` `roots, err := st.SetAwayLimit(ctx, a.Minutes)`. Each tells a refusal with `var r *store.RefusedError; errors.As(err, &r)`, answering `r.Reason`, and answers every other error with `store.Unreachable`. The landing page (`D06-pages`) calls `l, err := st.Landing(ctx)`. serve (`D03-serve`) calls `roots, err := st.FinishRefresh(ctx)` before ready, and the trail (`D08-trail`) records `roots` and each changing method's counts.

A test opens its own database with `db.Open` and the root package's `Migrations()` in a temporary directory, builds `store.New(d, store.Config{Now: clock})` with a clock it moves, pushes turns as two users, adds and removes rules and prices, sets the away limit, lists and totals, flips `d.SetFailing(true)` or closes `d`, and reopens the path to prove what persists. It leaves a refresh incomplete only through `DB.Write`, as R-C3UW-DYAT states. It computes an expected summary with `figures.Summarize` over the sessions it pushed, and compares. A test of the migration reads `fs.ReadFile(sessions.Migrations(), "0001_sessions.sql")`.
