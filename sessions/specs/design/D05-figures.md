# D05-figures

The derivations: `internal/figures`, a pure package that turns a session's turns, the kind rules, the price table and the away limit into the figures sessions reports: attention, wall time, agent time, tokens, dollars with the tokens left unpriced, the kind of work, and the roll-up of a session tree into its root. It also owns the enumerations every other package shares (tools, whose turn, kinds, periods), the token counts, the exact money and price types, and the UTC periods totals are bucketed by. It imports only the standard library, holds no state, reads no clock and opens no database; every function answers from its arguments alone and changes none of them. The store (`D04-store`) validates what is pushed and set, keeps the turns, rules, prices and away limit, builds each tree's sessions from its rows, and keeps the `Summary` this package computes; the tools (`D07-tools`) and the pages (`D06-pages`) render the figures they read. The trail (`D08-trail`) uses nothing here.

## Enumerations

A `Tool` is the agent CLI a session ran in, a `Whose` the party a turn belongs to (the person's turn, the agent's answer, a tool result), a `Kind` the kind of work, and a `Period` the bucket totals use. Each is a string type whose members are its constants, and each has a `Parse` function that accepts exactly its members' text, byte for byte, so the store refuses anything else by asking it. `Kinds` gives the seven kinds in the order every display uses, `untagged` last; `ParseKind` accepts all seven, and the store refuses `untagged` as a rule's kind, since `untagged` is no rule matching.

## Counts, durations and money

`Tokens` holds a turn's four counts, input, cached input, output and reasoning, and sums them; sums saturate at the largest `int64` rather than wrap. Durations are the standard library's `time.Duration`; every moment the store hands in is held to the millisecond, so every figure is a whole number of milliseconds. The wire speaks whole seconds: `Seconds` takes a duration's whole seconds, truncating, and a total takes the whole seconds of its own exact sum.

A `Rate` is a price in USD per million tokens: a decimal with at most six fractional digits, from 0 to 1000000, held exactly. A `Money` is an exact non-negative dollar amount, a whole number of picodollars (10^-12 USD), which is exactly the resolution a count times a six-digit rate per million needs. Its bound is 10^38 − 1 picodollars, about 10^26 dollars; an addition that would pass it stops at it. `String` and `ParseMoney` are a lossless round trip, the form the store keeps exact dollars in; `Dollars` rounds half-up to the cent and is used only for display, so a total is rounded once, from its exact sum, never as a sum of rounded parts. Both types hide their representation and compare with `==`.

## Periods

Weeks begin Monday 00:00 UTC and months are calendar months in UTC. `Start` gives the start of the period containing an instant, `Next` the start of the following one; the week of a date is `PeriodWeek.Start` of that date's midnight, which `ParseDate` gives. A root session belongs to the period containing its first moment.

## Kind

A rule names a host, a directory and optionally a command name, and a kind. A rule is a candidate for a session when the host is equal, the rule's directory is the session's directory or a path-component prefix of it (`/mnt/projects/biz` covers `/mnt/projects/biz/docs`, never `/mnt/projects/bizarre`; `/` covers every absolute path), and the rule names no command or the session's. The longest directory wins; at equal length, a rule with a command beats one without. No candidate is `untagged`.

## Price and cost

A turn is priced by its model's row with the latest effective date on or before the UTC calendar date of the turn's moment. A priced turn costs each count times its rate, per million; a turn with no such row adds its four counts to the unpriced tokens and nothing to dollars.

## Attention, agent time and wall

A session's turns are taken in turn order: by moment, and at equal moments person before agent before tool, so a person's prompt and the agent's first answer recorded in the same millisecond read as prompt then answer. Attention is the sum, over each person turn, of the time since the latest agent turn before it (or since the session's first moment), each capped at the away limit before summing; a headless session has none. Agent time splits the turns into spans, one before the first person turn and one beginning at each person turn, and counts each span from its beginning to its last agent turn; it is not capped. Wall is last moment minus first.

## Roll-up

A session is known by its `SessionKey`, the pair of its tool and its id, and its parent is such a pair too, the zero key for none; a parent may run in another tool than its child (a Codex job dispatched from a Claude session). `Root` follows parent links through held sessions. `Summarize` takes a root and every held descendant: kind, attention and wall are the root's own; agent time, tokens, dollars and unpriced tokens are over every session of the tree; `Subagents` counts the descendants.

## Recorded decisions

- **Rule specificity is prefix length before command** (the root's reading of outcome 6 of the decisions document, "the most specific match wins"): a folder says what the work was more precisely than a command does, so a rule on a deeper folder beats a rule with a command on a shallower one, and the command breaks ties only at the same folder. The cost: a command rule cannot override a deeper folder rule; a rule on the deeper folder with that command can.
- **Agent time is measured in spans** (the root's reading of outcome 4, which names agent time without defining it): from each person turn, or the session's start, to the last agent answer before the next person turn. Time after the last answer of a span, while the person reads or is away, is not agent time; tool results after the last answer do not extend it. It is not capped, since an agent working an hour is an hour of agent time.
- **Money is exact picodollars**, a departure from ledger's amounts (whole cents in an `int64`, refused past a bound at parse): six fractional digits per million tokens make one turn's exact cost a multiple of 10^-12 USD, which cents cannot hold, and the sheet forbids summing rounded values. The bound of 10^38 − 1 picodollars sits far above any real total: the store refuses a count above 10^12 (`store.MaxTurnCount`, `D04-store`), so one turn costs at most 4 × 10^12 dollars at the largest rate, and reaching the bound would take more than 10^13 such turns; sums saturate at it instead of failing, because a pure sum has no error to return.
- **Sums saturate**: token sums at the largest `int64`, durations at the largest `time.Duration`, money at its bound. Counts arrive non-negative (the store refuses others), so a sum only grows and saturating keeps every figure an upper-bounded honest answer instead of a wrapped negative one.
- **A rate is at most 1000000** USD per million tokens (a dollar a token), so the largest count times the largest rate stays inside the bound for one turn and a typo of extra digits is refused.
- **The price date is the UTC date**, as every period is UTC: a turn at 23:30 in New York on 9 March is priced as of 10 March.
- **A person turn with no agent turn before it counts from the session's first moment**, as the sheet says, so a session's opening prompt contributes zero and a person's second prompt before any answer counts the wait since the first.
- **Whole seconds truncate**: `Seconds` floors, and a total floors its own exact sum, as dollars round their own.
- **Two additions to the shared names**: `Seconds` and `ParseDate`, so the store, tools and pages share one reading of a wire duration and of a `YYYY-MM-DD` date.

## Consumer tasks

The store (`D04-store`) validates a push with `ParseTool` and `ParseWhose`, a rule with `ParseKind` (refusing `KindUntagged`), a price with `ParseRate` for each rate and `ParseDate` for its effective date, and a period with `ParsePeriod` and `ParseDate`. How the store finds a session's root and reads a tree is its own (`D04-store`); `figures.Root` states what the root is, given the parent links it is handed. To refresh a root the store builds the root and its descendants as `figures.Session` values with their `Turn`s, reads the rules, prices and away limit, and keeps `figures.Summarize(root, subs, rules, prices, away)`: the `Kind`, the three durations, the four counts, `Dollars.String()` and `Unpriced`, reading the money back with `ParseMoney`. Totals bucket each root by `p.Start(first)` and sum with `Figures.Add`; the landing page's nine weeks start at `figures.PeriodWeek.Start(now)` and step back by seven days. The tools (`D07-tools`) answer `figures.Seconds(f.Attention)` as `attention_seconds` (and likewise wall and agent), `f.Tokens.Total()` as `total`, `f.Dollars.Dollars()` as `dollars`, and each rate's `String()`; the pages (`D06-pages`) show the seven rows in `figures.Kinds()` order.

A test imports `figures`, builds `Session`, `Turn`, `Rule` and `Price` values with `time.Date` moments and rates from `ParseRate`, calls the functions, and compares durations, `Kind`s, `Tokens` and `Money` (by `==` against `ParseMoney`, or by `String` and `Dollars`).
