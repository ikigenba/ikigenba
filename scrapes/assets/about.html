How it works

scrapes collects public records about businesses in range. Each scraper knows one source: where it is, how it pages and how a record becomes a row. A run keeps every record its source answers inside the scraper's scope, the raw record beside a common envelope of name, names, address, people and facts.

scrape starts a run now and answers at once; the run lands in the background, one per scraper at a time. A cron trigger named scrape-<scraper> starts one each time it fires; create it and change its schedule in cron.

scrapers shows each scraper's current run, the latest done. runs and run show the runs, rows pages a run's rows and row answers one with its raw record. A run has rows only once it is done, and counts new, changed, unchanged and gone against the run before it; older runs are pruned.

Runs belong to no one: every signed-in user sees every run and row. A sibling service reads a whole run as JSON lines at /runs/<id>/rows.
