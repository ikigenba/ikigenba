# D01-layout-and-run-seam

scrapes is stage one of the funnel: one Go binary that turns public records about businesses in range into rows, kept per source and per run, for agents and a later `candidates` service to read. A **scraper** is Go code in the service that knows one source, where it is, how it pages and how a record becomes a row; the registry is fixed and holds two scrapers, `fmcsa` and `ppp` (`D05-scrapers`). A **run** is one walk of one scraper's source, recorded at once and worked in the background; its **rows** are the records the source answered inside the scraper's scope, each kept as a common envelope beside the raw record (`D05-scrapers`, `D06-runs`). Runs and rows live in the app's own SQLite database, `state/scrapes.db` (`D04-store`). A run is started by the `scrape` tool or by a cron trigger's fire delivered on the bus (`D06-runs`); each run's start and end is an event on the bus and in the trail (`D07-events`). Six MCP tools are offered at `/mcp` (`D10-tools`); a landing page, a page per run and per row, a tools page, an about screen and the not-found page are served to a signed-in user (`D08-pages`); a sibling reads a run whole over the socket (`D03-serve`).

This design is the structural ground the others stand on: where the code lives and what each package is for, the seam through which the process is run so that every part can be tested without a real process, the settings, the path, the addresses, where the identity and the display string come from, and the binary's wiring. The command line is `D02-cli`'s; the serve path, the services file and the route table are `D03-serve`'s. It follows gmail's layout and run seam, the newest app's, with the scrapers in place of the Gmail client and the run engine in place of the transfer engine.

The module is `github.com/ikigenba/ikigenba/scrapes`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/scrapes`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/scrapes` is wiring only.

## The dependencies

scrapes depends on one module besides the standard library: `github.com/ikigenba/ikigenba/appkit`, required at a published release with no `replace` directive. Its `db` package brings the pure-Go SQLite driver, which keeps the release build cgo-free. scrapes uses appkit's `db`, `version`, `services`, `page`, `identity`, `mcp`, `telemetry` and `events`, and restates none of their contracts. It uses neither `artifacts` nor `connections`: it calls no sibling but the event bus and the telemetry socket, which appkit's sinks reach. It speaks to its sources with the standard library alone (`net/http`, `encoding/json`, `encoding/csv`, `crypto/sha256`); the PPP file's bytes above `0x7F` are decoded by hand, with no `golang.org/x/text` (decision 4). Which release of appkit is data that `AGENTS.md` and `go.mod` hold.

## Where the environment is read

`main` makes the one read of the environment that is not `Run`'s own: it calls appkit's `version.Read` exactly once, first, and holds the result, the **identity**, whose `String()` is the **display string**. It hands the identity to `page.New`, whose banner carries its `Release` and `Commit` to every page's footer and to the about screen, and the display string to the `mcp.ServerConfig` its `Process.MCP` builds and to `Run` as `Process.Version`. Nothing below `main` calls `version.Read`. `Run` reads every variable through `Process.LookupEnv`: `DRAIN_SECONDS` and the six settings of the manifest's `[env]` once at start, through `settings.Read`; `LISTEN_PID`, `LISTEN_FDS` and `NOTIFY_SOCKET` for the socket and readiness; and `IKIGENBA_SERVICES` once, when it starts to serve.

## Packages

The root package holds what the module embeds: `Assets` (the six templates `about.html`, `landing.html`, `notfound.html`, `row.html`, `run.html` and `tools.html`), `Etc` (`manifest.toml` and `nginx.conf`) and `Migrations` (`0001_runs.sql` and `0002_rows.sql`, which create the two tables `D04-store` describes, `0003_list_indexes.sql`, which adds the indexes its runs window reads by, and `0004_row_names.sql`, which adds the side table of row names its rows window filters by). Its package name is `scrapes`.

The internal packages hold the concerns, one each, and each is declared in full by the document named:

- `internal/cli`: the run seam, the command and the serve path (this document, `D02-cli`, `D03-serve`), and the sweep interval (this document; the sweep itself is `D06-runs`').
- `internal/settings`: the seven settings (this document).
- `internal/server`: a listener's life (`D03-serve`).
- `internal/web`: the route table, `web.Config` and `web.Handler`, and the sibling read path (`D03-serve`).
- `internal/store`: the run and row records, their words, writes, reads and prune (`D04-store`).
- `internal/source`: what every scraper shares: the row envelope, its normalization, the digest, the `Scraper` interface and the name of `source.called` (`D05-scrapers`).
- `internal/fmcsa`: the FMCSA scraper (`D05-scrapers`).
- `internal/ppp`: the PPP scraper (`D05-scrapers`).
- `internal/scrapers`: the fixed registry of scrapers by name (`D05-scrapers`).
- `internal/runs`: the engine, `runs.Engine` built by `runs.New(runs.Config)`: starting a run, the work in the background, the delivery from the bus, the start's settling (`Engine.Recover`), the drain (`Engine.Drain`), the run record's JSON and the refusal words (`D06-runs`).
- `internal/trail`: the run events and their declarations (`D07-events`); the trail as a whole and its secrecy (`D09-trail`).
- `internal/urls`: the auth address the banner's links are built on (this document).
- `internal/tools`: the six tools (`D10-tools`).
- `internal/pages`: the templates' data and the page routes, `pages.ServiceName` and `pages.Description` (`D08-pages`).

`source`, `fmcsa`, `ppp` and `scrapers` are four packages, not one, because the registry names each scraper and each scraper builds the envelope: an envelope in the registry's package would make the two import each other, and a scraper in its own package keeps one source's constants and parsing out of the other's. Which imports which is guidance, not contract.

## The run seam

The run seam is `cli.Run`, which takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package and the network, and returns the exit code. It is gmail's seam unchanged. `HTTP` is the client every request to a source goes through: a test hands one whose transport answers every request as a fake Socrata does, counts, pages and failures included, or as a fake of the SBA's file folder does, a small CSV per file name, so no test reaches data.transportation.gov or data.sba.gov and no `Process` field names a source's address; `internal/fmcsa`'s and `internal/ppp`'s own tests may instead point the scraper's base URL at a loopback fake (`D05-scrapers`). A nil `HTTP` is `http.DefaultClient`; the bounds of a request are the scraper's (`fmcsa.RequestTimeout`, and for a PPP file a bound on the headers and another on the body, `D05-scrapers`), not the client's. `Now` is the clock every time scrapes stamps or compares is read from: a run's started and finished, a row's collected, the prune's ordering, every event's time. `Sleep` is the pause the writer and the emitter wait with between delivery attempts, and the one a scraper waits with between retries of a source request (`D05-scrapers`). `After` is the sweeper's timer (`D06-runs`). `Rand` is the source of every value scrapes mints: request ids, run ids and bus event ids. `Inherit`, `Now` and `Rand` are the caller's to give whenever `Args` is empty: `Run` has no default for any of them, and the choice of the process's own descriptor 3, `time.Now` and `crypto/rand.Reader` is made once, at the process boundary, by `cmd/scrapes`. The event bus and telemetry sockets reach `Run` through the services file `IKIGENBA_SERVICES` names (`D03-serve`). There are no live tests: no test reaches data.transportation.gov or data.sba.gov, and the sandbox check proves the real sources (`D11-on-a-space`). The one test that execs the binary never starts a run: it runs `scrapes` with a nil `HTTP`, so it never asks for a `scrape` and never reaches a source.

## Settings

scrapes reads seven values at start, in this order: `DRAIN_SECONDS`, the space's, and the six its manifest's `[env]` declares: `SCRAPE_KEEP_RUNS`, `FMCSA_STATES`, `FMCSA_MIN_POWER_UNITS`, `FMCSA_STATUS`, `PPP_FILES` and `PPP_STATES` (decisions 3 and 12; the PPP pass's decision 2). An unset or empty one is its default, the manifest's value: 5 seconds, 2 runs, `MN,WI`, 5 power units, `A`, `public_150k_plus_240930.csv` and `MN,WI`. `DRAIN_SECONDS` and `SCRAPE_KEEP_RUNS` are spelled as opsctl writes an integer: one or more ASCII digits, no sign, no leading zero, so `0` is refused. `FMCSA_MIN_POWER_UNITS` is the same but `0` is accepted, a floor of none. `FMCSA_STATES` is one or more two-letter capital codes joined by commas with no space, and `PPP_STATES` is spelled the same; `FMCSA_STATUS` is one capital letter. `PPP_FILES` is one or more file names joined by commas with no space, each of letters, digits, `_`, `-` and `.`, not beginning with `.`; the files are walked in the order written, duplicates kept. The three FMCSA settings are written into a Socrata `$where` and each name of `PPP_FILES` is appended to the path of `ppp.DefaultBaseURL` (`D05-scrapers`), so their spelling is strict: nothing that could close a quoted string or add a clause, and nothing that could leave the folder, start a query or a fragment or be decoded as an escape, gets through. `PPP_STATES` is compared with each record's state rather than sent, and is spelled as `FMCSA_STATES` so the two scopes read alike. Digits beyond what an `int64` holds read as the largest `int64`. `settings.Read` refuses the first value in that order that is not acceptable with a `*settings.Error` naming it, quoting its value and saying what was wanted, and `Run` writes its text after `scrapes: ` as a usage error before it looks for its socket. The page sizes, the hourly sweep, the Socrata page size, the request timeout and the retry rule are constants of the documents that use them.

## Paths

Relative to `Process.Dir` (the process's working directory when empty) the database is `state/scrapes.db`, opened with `db.Open`, the root package's `Migrations()` and `Process.Now`; `state/` is created when absent. scrapes writes nothing outside `Dir` and nothing under it but the database: a Socrata page is held decoded in memory while it is stored, a PPP file is read as it arrives and only a batch of its rows is held at once, and neither the raw pages nor the files are kept on disk (decision 1; the PPP pass's decision 3).

## The addresses

`internal/urls` holds the one address scrapes builds that is not its own path: the **auth address**, the `URL` of the services file's entry `auth`, trailing `/` removed, or, with no such entry, built from the request's scheme and host with a leading `scrapes.` removed (`urls.Auth`), which the pages' banner links to (`D08-pages`). The page paths `/runs/<id>` and `/runs/<id>/rows/<source_id>` are spelled by the templates, which build them from the data they receive.

## Recorded decisions

- The layout is gmail's with `internal/source`, `internal/fmcsa`, `internal/ppp` and `internal/scrapers` in place of `internal/gmail`, `internal/runs` in place of `internal/transfers`, and no `internal/drafts`. `internal/urls` keeps only `Auth`: scrapes links to no sibling's page, and the templates spell their own paths.
- The root package is named `scrapes`, after its directory; no package below it shares the name, so no file needs an alias.
- No `Process` field names a source's address, as gmail's names none for Gmail: a `Run`-level test reaches its fake Socrata or its fake SBA folder through `HTTP`'s transport, and the base URL is a field of each scraper's config that `Run` leaves empty, so its default holds.
- A nil `HTTP` is `http.DefaultClient`, not a client of the app's own with transport bounds as gmail's `DefaultHTTP` is: gmail's bounds guard a 35 MiB upload, while a scraper bounds each request with its own deadlines (decision 3; for a PPP file, one until the headers arrive and a fresh one over the body, the PPP pass's decision 3), which cover the dial, the handshake and the body. The default is not proved by a test, since using it reaches the network.
- `Process.Sleep` gains a third user, the scraper's retry backoff, so a test drives the three retries without waiting real seconds.
- The settings are declared here rather than in the serve document as gmail declares them, because five of them are a scraper's scope and the layout document is the one both the serve path and the scraper stand on.
- The FMCSA settings and `PPP_FILES` are refused unless strictly spelled, rather than quoted or escaped into the query or the path: the operator writes them once per space, a refusal at start says exactly what was wanted, and a value that reached the source malformed would fail every run with `source`, found only at the next scheduled run, a month later for FMCSA and a year later for PPP.
- `PPP_STATES` takes `FMCSA_STATES`' spelling and its refusal's word, `settings.WantStates`, rather than a constant of its own: the two say the same thing, two-letter capital codes, and a second constant would be the same copy twice. `PPP_FILES` has its own, `settings.WantFiles`.
- What each setting must be is said by a copy constant of `internal/settings` (`settings.WantRuns` and its five siblings), since the FMCSA and PPP settings have no unit word to put in gmail's `not a positive whole number of <unit>` shape; the refusal's frame, name and quoted value stay contract.
- `Process.Inherit`, `Process.Now` and `Process.Rand` are required whenever `Args` is empty, as in gmail; no requirement states the precondition, because no permitted test can observe a default.

## Consumer tasks

`main` calls `id := version.Read()` and `v := id.String()` and hands `cli.Run` a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Version` is `v`, whose `Banner` is `page.New(pages.ServiceName, id).Banner`, whose `Inherit` takes the process's own descriptor 3, whose `Now` is `time.Now`, whose `Rand` is `crypto/rand.Reader`, whose `After` is `time.After` and whose `MCP` returns `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Version: v, Telemetry: w})`, leaving the rest zero; it cancels the context on `SIGTERM` or `SIGINT` with a cause whose `Error` is the signal's name, and exits with what `Run` returns. `internal/cli` imports the root as `scrapes` and opens `db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "scrapes.db"), Migrations: scrapes.Migrations(), ...})`; it reads `s, err := settings.Read(p.LookupEnv)` and builds the registry with `scrapers.Default(scrapers.Config{HTTP: p.HTTP, Telemetry: w, Now: p.Now, Sleep: p.Sleep, UserAgent: pages.ServiceName + " (" + pages.Description + ")", Settings: s})` (`D05-scrapers`). A test of the run seam builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` over a map, an `Inherit` returning a listener it bound, a `Now`, a `Sleep`, an `After` and a `Rand` it controls, an `HTTP` whose transport answers as a fake Socrata or a fake SBA folder and records each request, and capturing sinks; calls `cli.Run`, waits for `READY=1`, drives `/mcp` with `mcp.Client` and the pages with raw HTTP, cancels, and inspects `Dir`, the transport's requests and the captures. A test of settings calls `settings.Read` with a lookup over a map and compares with `settings.Defaults()` and `Drain()`. The pages build the banner's user with `urls.Auth(r, servicesPath)`.
