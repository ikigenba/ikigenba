# D01-layout-and-run-seam

scrapes is stage one of the funnel: one Go binary that turns public records about businesses in range into rows, kept per source and per run, for agents and a later `candidates` service to read. A **scraper** is Go code in the service that knows one source, where it is, how it pages and how a record becomes a row; the registry is fixed and holds four scrapers, `fmcsa`, `form5500`, `mn_parcels` and `ppp` (`D05-scrapers`). A **run** is one walk of one scraper's source, recorded at once and worked in the background; its **rows** are the records the source answered inside the scraper's scope, each kept as a common envelope beside the raw record (`D05-scrapers`, `D06-runs`). A run's record lives in the app's own SQLite database, the **catalog**, `state/scrapes.db`, and a done run's rows in a SQLite file of their own, `runs/<id>.db`, written once when the run is loaded and read for as long as the run is kept (`D04-store`, `D06-runs`). A run is started by the `scrape` tool or by a cron trigger's fire delivered on the bus (`D06-runs`); each run's start and end is an event on the bus and in the trail (`D07-events`). Six MCP tools are offered at `/mcp` (`D10-tools`); a landing page, a page per run and per row, a tools page, an about screen and the not-found page are served to a signed-in user (`D08-pages`); a sibling reads a run whole over the socket (`D03-serve`).

This design is the structural ground the others stand on: where the code lives and what each package is for, the seam through which the process is run so that every part can be tested without a real process, the settings, the paths, the addresses, where the identity and the display string come from, and the binary's wiring. The command line is `D02-cli`'s; the serve path, the services file and the route table are `D03-serve`'s. It follows gmail's layout and run seam, the newest app's, with the scrapers in place of the Gmail client and the run engine in place of the transfer engine.

The module is `github.com/ikigenba/ikigenba/scrapes`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/scrapes`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/scrapes` is wiring only.

## The dependencies

scrapes depends on one module besides the standard library: `github.com/ikigenba/ikigenba/appkit`, required at a published release with no `replace` directive. Its `db` package brings the pure-Go SQLite driver, which keeps the release build cgo-free, and the two opens a run file needs beside the catalog's: a bulk open that builds one and an immutable open that reads one (`D04-store`); scrapes never imports the driver itself. scrapes uses appkit's `db`, `version`, `services`, `page`, `identity`, `mcp`, `telemetry` and `events`, and restates none of their contracts. It uses neither `artifacts` nor `connections`: it calls no sibling but the event bus and the telemetry socket, which appkit's sinks reach. It speaks to its sources with the standard library alone (`net/http`, `encoding/json`, `encoding/csv`, `archive/zip`, `crypto/sha256`); the PPP file's bytes above `0x7F` are decoded by hand, with no `golang.org/x/text` (decision 4). Which release of appkit is data that `AGENTS.md` and `go.mod` hold.

## Where the environment is read

`main` makes the one read of the environment that is not `Run`'s own: it calls appkit's `version.Read` exactly once, first, and holds the result, the **identity**, whose `String()` is the **display string**. It hands the identity to `page.New`, whose banner carries its `Release` and `Commit` to every page's footer and to the about screen, and the display string to the `mcp.ServerConfig` its `Process.MCP` builds and to `Run` as `Process.Version`. Nothing below `main` calls `version.Read`. `Run` reads every variable through `Process.LookupEnv`: `DRAIN_SECONDS` and the eleven settings of the manifest's `[env]` once at start, through `settings.Read`; `LISTEN_PID`, `LISTEN_FDS` and `NOTIFY_SOCKET` for the socket and readiness; and `IKIGENBA_SERVICES` once, when it starts to serve.

## Packages

The root package holds what the module embeds: `Assets` (the six templates `about.html`, `landing.html`, `notfound.html`, `row.html`, `run.html` and `tools.html`), `Etc` (`manifest.toml` and `nginx.conf`) and `Migrations` (`0001_runs.sql` and `0002_rows.sql`, which create the two tables `D04-store` describes, `0003_list_indexes.sql`, which adds the indexes its runs window reads by, and `0004_row_names.sql`, which adds the side table of row names its rows window once filtered by). The rows have moved to the run files, so the catalog's `rows` and `row_names` tables are no longer written or read; no migration drops them in this release, so the one before it still runs on this schema, and a later release drops them (`D04-store`). Its package name is `scrapes`.

The internal packages hold the concerns, one each, and each is declared in full by the document named:

- `internal/cli`: the run seam, the command and the serve path (this document, `D02-cli`, `D03-serve`), and the sweep interval (this document; the sweep itself is `D06-runs`').
- `internal/settings`: the twelve settings (this document).
- `internal/server`: a listener's life (`D03-serve`).
- `internal/web`: the route table, `web.Config` and `web.Handler`, and the sibling read path (`D03-serve`).
- `internal/store`: the catalog and the run files: the run records, their words, writes, reads and prune, and the building, reading and deleting of each run's file (`D04-store`).
- `internal/source`: what every scraper shares: the row envelope, its normalization, the digest, the `Scraper` interface and the name of `source.called` (`D05-scrapers`).
- `internal/fmcsa`: the FMCSA scraper (`D05-scrapers`).
- `internal/ppp`: the PPP scraper (`D05-scrapers`).
- `internal/mnparcels`: the MN parcels scraper (`D05-scrapers`).
- `internal/form5500`: the Form 5500 scraper (`D05-scrapers`).
- `internal/scrapers`: the fixed registry of scrapers by name (`D05-scrapers`).
- `internal/runs`: the engine, `runs.Engine` built by `runs.New(runs.Config)`: starting a run, the work in the background, the delivery from the bus, the start's settling (`Engine.Recover`), the drain (`Engine.Drain`), the run record's JSON and the refusal words (`D06-runs`).
- `internal/pace`: the pacing of each phase of a run: the write budget, the latency backoff and the pause while the I/O pressure file reads above the limit (`D06-runs`).
- `internal/trail`: the run events and their declarations (`D07-events`); the trail as a whole and its secrecy (`D09-trail`).
- `internal/urls`: the auth address the banner's links are built on (this document).
- `internal/tools`: the six tools (`D10-tools`).
- `internal/pages`: the templates' data and the page routes, `pages.ServiceName` and `pages.Description` (`D08-pages`).

`source`, `fmcsa`, `ppp`, `mnparcels`, `form5500` and `scrapers` are six packages, not one, because the registry names each scraper and each scraper builds the envelope: an envelope in the registry's package would make the two import each other, and a scraper in its own package keeps one source's constants and parsing out of the other's. Which imports which is guidance, not contract.

## The run seam

The run seam is `cli.Run`, which takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package and the network, and returns the exit code. It is gmail's seam unchanged. `HTTP` is the client every request to a source goes through: a test hands one whose transport answers every request as a fake Socrata does, counts, pages and failures included, or as a fake of the SBA's file folder does, a small CSV per file name, or as a fake parcel service does, counts and pages of features, or as a fake of the Department of Labor's folder does, a small zip per form and year, so no test reaches data.transportation.gov, data.sba.gov, enterprise.gisdata.mn.gov or askebsa.dol.gov and no `Process` field names a source's address; `internal/fmcsa`'s, `internal/ppp`'s, `internal/mnparcels`' and `internal/form5500`'s own tests may instead point the scraper's base URL at a loopback fake (`D05-scrapers`). A nil `HTTP` is `http.DefaultClient`; the bounds of a request are the scraper's (`fmcsa.RequestTimeout`, `mnparcels.RequestTimeout`, for a PPP file a bound on the headers and another on the body, and for a Form 5500 file a bound on the headers and another from them to its last batch, `D05-scrapers`), not the client's. `Now` is the clock every time scrapes stamps or compares is read from: a run's started and finished, a row's scraped, the prune's ordering, every event's time, and the duration of each write the engine paces by. `Sleep` is the pause the writer and the emitter wait with between delivery attempts, the one a scraper waits with between retries of a source request (`D05-scrapers`), and the engine's pauses for its write budget and while the I/O pressure file reads above the limit (`D06-runs`). `Pressure` is the path of that file; empty means none, and so no pressure pause. A test never names the host's own file: with a `Sleep` that returns at once, a loaded developer machine would turn the pause into a spin, so only `cmd/scrapes` names it, as `cli.PressureFile`, just as only it chooses `Inherit`; a test that proves the pause writes a file of the kernel's form in its own temporary directory and rewrites it from its `Sleep`. `After` is the sweeper's timer (`D06-runs`). `Rand` is the source of every value scrapes mints: request ids, run ids and bus event ids. `Inherit`, `Now` and `Rand` are the caller's to give whenever `Args` is empty: `Run` has no default for any of them, and the choice of the process's own descriptor 3, `time.Now` and `crypto/rand.Reader` is made once, at the process boundary, by `cmd/scrapes`. The event bus and telemetry sockets reach `Run` through the services file `IKIGENBA_SERVICES` names (`D03-serve`). There are no live tests: no test reaches data.transportation.gov, data.sba.gov, enterprise.gisdata.mn.gov or askebsa.dol.gov, and the sandbox check proves the real sources (`D11-on-a-space`). The one test that execs the binary never starts a run: it runs `scrapes` with a nil `HTTP`, so it never asks for a `scrape` and never reaches a source.

## Settings

scrapes reads twelve values at start, in this order: `DRAIN_SECONDS`, the space's, and the eleven its manifest's `[env]` declares: `SCRAPE_KEEP_RUNS`, `SCRAPE_WRITE_BUDGET`, `SCRAPE_PRESSURE_LIMIT`, `FMCSA_STATES`, `FMCSA_MIN_POWER_UNITS`, `FMCSA_STATUS`, `PPP_FILES`, `PPP_STATES`, `MN_PARCELS_COUNTIES`, `FORM5500_YEARS` and `FORM5500_STATES` (decisions 3 and 12; the PPP pass's decision 2; the MN parcels pass's decision 2; the store pass's decision 7; the Form 5500 pass's decision 2). An unset or empty one is its default, the manifest's value: 5 seconds, 2 runs, 4,096,000 bytes a second, 10 percent, `MN,WI`, 5 power units, `A`, `public_150k_plus_240930.csv`, `MN,WI`, the thirteen counties `Carlton,Chisago,Isanti,Mille Lacs,Aitkin,St. Louis,Anoka,Washington,Sherburne,Stearns,Benton,Morrison,Crow Wing`, the seven plan years `2025,2024,2023,2022,2021,2020,2019` and `MN,WI`. `DRAIN_SECONDS` and `SCRAPE_KEEP_RUNS` are spelled as opsctl writes an integer: one or more ASCII digits, no sign, no leading zero, so `0` is refused; `SCRAPE_WRITE_BUDGET` is spelled the same. `SCRAPE_PRESSURE_LIMIT` is too, and further no greater than `100`. `FMCSA_MIN_POWER_UNITS` is the same but `0` is accepted, a floor of none. `FMCSA_STATES` is one or more two-letter capital codes joined by commas with no space, and `PPP_STATES` and `FORM5500_STATES` are spelled the same; `FORM5500_YEARS` is one or more years of four ASCII digits, the first not `0`, joined by commas with no space, walked in the order written, newest first by default, duplicates kept; `FMCSA_STATUS` is one capital letter. `PPP_FILES` is one or more file names joined by commas with no space, each of letters, digits, `_`, `-` and `.`, not beginning with `.`; the files are walked in the order written, duplicates kept. `MN_PARCELS_COUNTIES` is one or more county names joined by commas with no space around them, each of ASCII letters, spaces, periods and apostrophes, beginning with a letter and not ending with a space; the counties are walked in the order written, duplicates kept. The three FMCSA settings are written into a Socrata `$where` and each name of `PPP_FILES` is appended to the path of `ppp.DefaultBaseURL` (`D05-scrapers`), so their spelling is strict: nothing that could close a quoted string or add a clause, and nothing that could leave the folder, start a query or a fragment or be decoded as an escape, gets through. Each year of `FORM5500_YEARS` is written twice into a path under `form5500.DefaultBaseURL` (`D05-scrapers`), so it is held to its four digits. Each name of `MN_PARCELS_COUNTIES` is written into an ArcGIS `where` clause as a quoted string, its apostrophes doubled by `mnparcels.Where` (`D05-scrapers`), so its spelling admits nothing but what a county's name holds. `PPP_STATES` and `FORM5500_STATES` are compared with each record's states rather than sent, and are spelled as `FMCSA_STATES` so the scopes read alike. Digits beyond what an `int64` holds read as the largest `int64`. `settings.Read` refuses the first value in that order that is not acceptable with a `*settings.Error` naming it, quoting its value and saying what was wanted, and `Run` writes its text after `scrapes: ` as a usage error before it looks for its socket. The write budget is the bytes per second each phase of a run writes at most: the default is a third of the space's volume's 3,000 I/Os a second, taken at the worst case of one I/O per 4,096-byte page. The pressure limit is compared with the kernel's `full avg10` reading of `/proc/pressure/io`, a percentage: a quiet host reads near 0 and the run that starved `us` read about 45; `100` can never be exceeded, so it turns the pause off. The page sizes, the hourly sweep, the Socrata and ArcGIS page sizes, the request timeouts and the retry rule are constants of the documents that use them.

## Paths

Relative to `Process.Dir` (the process's working directory when empty) the catalog is `state/scrapes.db`, opened with `db.Open`, the root package's `Migrations()` and `Process.Now`; `state/` is created when absent. Beside `state/`, not under it, is `runs/`: a done run's rows are in `runs/<id>.db`, and while a run is built its temporaries lie beside that file, each named for the run's id followed by `.` (`D04-store`). `runs/` is created by the first write of the first run, not at start, so a fresh `Dir` holds only `state/` when the process is ready. scrapes writes nothing outside `Dir` and nothing under it but the catalog and `runs/`: a Socrata page is held decoded in memory until its rows are handed to the run's build, a PPP file is read as it arrives and only a batch of its rows is held at once, an ArcGIS page of 2,000 features is held decoded until its rows are handed to the run's build, a Form 5500 zip is spooled into one file the run's build makes in `runs/`, named for the run's id followed by `.` as the build's temporaries are, and removed once its CSV has been read, the built rows are buffered and written in sorted chunks to `runs/`, and no raw page and no PPP file is kept on disk (decision 1; the PPP pass's decision 3; the MN parcels pass's decision 11; the Form 5500 pass's decision 4).

## The addresses

`internal/urls` holds the one address scrapes builds that is not its own path: the **auth address**, the `URL` of the services file's entry `auth`, trailing `/` removed, or, with no such entry, built from the request's scheme and host with a leading `scrapes.` removed (`urls.Auth`), which the pages' banner links to (`D08-pages`). The page paths `/runs/<id>` and `/runs/<id>/rows/<source_id>` are spelled by the templates, which build them from the data they receive.

## Recorded decisions

- The layout is gmail's with `internal/source`, `internal/fmcsa`, `internal/ppp`, `internal/mnparcels` and `internal/scrapers` in place of `internal/gmail`, `internal/runs` in place of `internal/transfers`, and no `internal/drafts`. `internal/urls` keeps only `Auth`: scrapes links to no sibling's page, and the templates spell their own paths.
- The root package is named `scrapes`, after its directory; no package below it shares the name, so no file needs an alias.
- No `Process` field names a source's address, as gmail's names none for Gmail: a `Run`-level test reaches its fake Socrata, its fake SBA folder or its fake parcel service through `HTTP`'s transport, and the base URL is a field of each scraper's config that `Run` leaves empty, so its default holds.
- A nil `HTTP` is `http.DefaultClient`, not a client of the app's own with transport bounds as gmail's `DefaultHTTP` is: gmail's bounds guard a 35 MiB upload, while a scraper bounds each request with its own deadlines (decision 3; for a PPP file, one until the headers arrive and a fresh one over the body, the PPP pass's decision 3), which cover the dial, the handshake and the body. The default is not proved by a test, since using it reaches the network.
- `Process.Sleep` gains a third user, the scraper's retry backoff, so a test drives the three retries without waiting real seconds.
- The settings are declared here rather than in the serve document as gmail declares them, because six of them are a scraper's scope and the layout document is the one both the serve path and the scraper stand on.
- The FMCSA settings and `PPP_FILES` are refused unless strictly spelled, rather than quoted or escaped into the query or the path: the operator writes them once per space, a refusal at start says exactly what was wanted, and a value that reached the source malformed would fail every run with `source`, found only at the next scheduled run, a month later for FMCSA and a year later for PPP.
- `FORM5500_YEARS` is held to years of four ASCII digits, the first not `0`, joined by commas (the Form 5500 pass's decision 2), so a year cannot leave the department's folder or start a query, and `2019, 2020` is refused as `MN, WI` is; its refusal's word is `settings.WantYears`. Years are kept as written, strings, since each is spliced into a path and never compared or counted; a year the department has no file for, such as 2008, is answered 404 and fails the run `source` at the first scheduled run, as a misspelled PPP file does. `FORM5500_STATES` takes `FMCSA_STATES`' spelling and `settings.WantStates`, as `PPP_STATES` does.
- `MN_PARCELS_COUNTIES` is held to the document's character set, ASCII letters, spaces, periods and apostrophes (the MN parcels pass's decision 2), and further to a name that begins with a letter and does not end with a space, so `Chisago, Isanti` is refused as `MN, WI` is rather than walking a county named ` Isanti` that the service would answer with no rows and no failure. An apostrophe is admitted, as decision 2 says, and is made safe by `mnparcels.Where`'s doubling, not by the check. Its refusal's word is `settings.WantCounties`.
- `PPP_STATES` takes `FMCSA_STATES`' spelling and its refusal's word, `settings.WantStates`, rather than a constant of its own: the two say the same thing, two-letter capital codes, and a second constant would be the same copy twice. `PPP_FILES` has its own, `settings.WantFiles`.
- What each setting must be is said by a copy constant of `internal/settings` (`settings.WantRuns` and its nine siblings), since the FMCSA and PPP settings have no unit word to put in gmail's `not a positive whole number of <unit>` shape; the refusal's frame, name and quoted value stay contract.
- `runs/` sits beside `state/` rather than under it: the host's backup archives `state/` whole and Litestream replicates the catalog, while a run file is written once and can be made again by a new walk, so neither the snapshot nor the replica should carry it (the store pass's decision 1). It is created lazily, at the first chunk a run writes, so starting the process gains no new way to fail.
- `Process.Pressure` empty means no pressure pause rather than the host's file, and `cmd/scrapes` alone sets it to `cli.PressureFile`: a test must never read the host's real pressure, and a pause decided by another process's load would make a test's outcome depend on the machine it runs on.
- `SCRAPE_WRITE_BUDGET` refuses `0` rather than reading it as no budget: a run without a budget is the run that starved `us`. A value too large for an `int64` reads as `math.MaxInt64`, as `SCRAPE_KEEP_RUNS` does, which is a budget no volume reaches. `SCRAPE_PRESSURE_LIMIT` is a whole percentage from 1 to 100: the kernel reports `full avg10` to two decimals, but a whole number is what an operator writes; `0` is refused, since a pause at any reading above zero would hold every run on a host doing anything.
- `Process.Inherit`, `Process.Now` and `Process.Rand` are required whenever `Args` is empty, as in gmail; no requirement states the precondition, because no permitted test can observe a default.

## Consumer tasks

`main` calls `id := version.Read()` and `v := id.String()` and hands `cli.Run` a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Version` is `v`, whose `Banner` is `page.New(pages.ServiceName, id).Banner`, whose `Inherit` takes the process's own descriptor 3, whose `Now` is `time.Now`, whose `Rand` is `crypto/rand.Reader`, whose `After` is `time.After`, whose `Pressure` is `cli.PressureFile` and whose `MCP` returns `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Version: v, Telemetry: w})`, leaving the rest zero; it cancels the context on `SIGTERM` or `SIGINT` with a cause whose `Error` is the signal's name, and exits with what `Run` returns. `internal/cli` imports the root as `scrapes` and opens `db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "scrapes.db"), Migrations: scrapes.Migrations(), ...})`; it builds the store with `store.New(d, store.Config{Now: p.Now, Rand: rand, Runs: filepath.Join(p.Dir, "runs")})` (`D04-store`), reads `s, err := settings.Read(p.LookupEnv)`, builds the engine with `runs.New(runs.Config{..., Now: p.Now, Budget: s.WriteBudget, PressureLimit: s.PressureLimit, Pressure: p.Pressure})` (`D06-runs`) and builds the registry with `scrapers.Default(scrapers.Config{HTTP: p.HTTP, Telemetry: w, Now: p.Now, Sleep: p.Sleep, UserAgent: pages.ServiceName + " (" + pages.Description + ")", Settings: s})` (`D05-scrapers`). A test of the run seam builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` over a map, an `Inherit` returning a listener it bound, a `Now`, a `Sleep`, an `After` and a `Rand` it controls, a `Pressure` that is empty or names a file in its temporary directory, an `HTTP` whose transport answers as a fake Socrata, a fake SBA folder, a fake parcel service or a fake DOL folder and records each request, and capturing sinks; calls `cli.Run`, waits for `READY=1`, drives `/mcp` with `mcp.Client` and the pages with raw HTTP, cancels, and inspects `Dir`, the transport's requests and the captures. A test of settings calls `settings.Read` with a lookup over a map and compares with `settings.Defaults()` and `Drain()`. The pages build the banner's user with `urls.Auth(r, servicesPath)`.
