# D09-trail

The trail as a whole: the closed set of event names scrapes records and emits, the request pair the telemetry middleware records for every request, deliveries from the bus as appkit records them, `source.called` as the assembled run shows it, the clock and the random source every event is stamped and named from, and decision 13's secrecy, stated once for the whole app. It is gmail's trail document with the run events in place of the transfer and draft events, `source.called` in place of `gmail.called`, and no sibling client.

Who tells each event is another document's. The request pair is appkit's `telemetry.Middleware`'s, which `D03-serve` mounts on every request; `tool.called` is appkit's MCP server's; `service.started` and `service.stopping` are `D03-serve`'s; `event.lost` is appkit's emitter's, since the emitter is built with the writer. `source.called` is `D05-scrapers`' to record (R-6ERS-EQ7R): the scraper is the only thing that sees each request to its source, its status and its timing. `scrape.started` and `scrape.finished`, their attributes, their identity and their cause are `D07-events`'; when each is told is `D06-runs`'. This document states what the assembled run shows of them.

## The request pair and deliveries

Every request, whatever its path and whether or not it carries an identity, is recorded by the telemetry middleware as one `request.started` (method, path) and one `request.finished` (status, duration, bytes), under its request id and its caller's user (`D03-serve`). A delivery from the bus is a request like any other, `POST /events` with the events app's `X-Request-Id` and no user: appkit's delivery handler records nothing of its own, so a delivery is recorded as that request pair, and the run it starts tells its events, and its scraper its `source.called`, under the same request id (`D07-events`).

## source.called

One `source.called` per attempt of a request to a source: `scraper`, the status answered (0 when none came), and `duration_us`, as the run's starter, so a run's source requests are found under the request id of the `scrape` call or delivery that started it. No query, URL, body, record or header travels in it.

## The clock and the random source

Every event's time is read from `Process.Now`, and every request id `Run` mints, every run id and every bus event id are drawn from `Process.Rand` (`D01-layout-and-run-seam`, R-YF8J-6XDA and R-YGGF-KP3Z; the run id R-YMJX-HJTG). Both are seams `cmd/scrapes` fills with `time.Now` and `crypto/rand.Reader` (decision 13); a test fills them with a fixed clock and a constant reader and finds the stamps and ids those give.

## Secrecy

Events and telemetry carry names, ids, words and counts only (decision 13). No record, business name, address, phone or email reaches the trail, the bus, standard output or standard error, on success or failure; scrapes writes no log of its own, and a serving run writes standard error only as `D03-serve` says. Records reach the callers' tool answers, the signed-in pages and the sibling read path, which is what they are for, and nowhere else. A refusal's sentence, of a tool or of the read path, is a fixed copy constant: it holds no value the call or the store supplied, so no record's contents and no `name` filter a caller gave can reach it (decision 13).

The rule is proved at the run seam, by use, as gmail proves its own: a fake Socrata answers records whose names, street, city, officers, phone and email are random **markers**; some of its answers are failures whose bodies echo every marker; the test's `rows` calls filter by a marker; every tool, page, read path and delivery is exercised, with runs ending `done`, `failed` with `source` and `failed` with `interrupted`, a batch refused by the store, and every tool and read path called again with the database broken; and every capture of the run is searched: both sinks, in every field and as JSON, both streams, every refused tool result and every read path refusal.

## Recorded decisions

- The closed set is gmail's with `gmail.called` and `sibling.called` replaced by `source.called`, and the five transfer and draft names by the two run names: scrapes builds no sibling client, so `sibling.called` never occurs.
- `source.called` is recorded for every attempt, retries included, since each is a request to the source; `D05-scrapers` states it per attempt.
- A delivery is recorded by the request pair alone, as appkit's delivery handler records it: the handler takes no writer and records nothing; its outcome is the answer's status and body, which the middleware's `request.finished` carries as the status.
- A city marker is one capital letter followed by lowercase letters, because the scraper title-cases the city (`D05-scrapers`) and a marker must survive into the row unchanged to be searched for. The zip, cut to five, and the state, upper-cased and narrowed by the query, carry no marker.
- A `name` filter given to `rows` is treated as record text: it may be a business's name, so it is a marker in the secrecy conditions and never reaches the trail or a refusal.
- Secrecy is required of the whole run, because the leak it guards against is a wiring one only the assembled process shows. What the tools, the pages and the read path answer is `D10-tools`', `D08-pages`' and `D03-serve`'s.

## Consumer tasks

A test drives `cli.Run` with a `*telemetry.Capture` as `Sink`, an `*events.Capture` as `EventSink`, buffers as `Stdout` and `Stderr`, a `Now` returning one fixed time, a `Rand` yielding `0x5a`, and an `HTTP` whose transport answers as a fake Socrata and records every request; waits for `READY=1`; makes a `scrape` call with `mcp.Client` and a `POST /events` delivery of `cron.scrape_fmcsa.fired` with its own `X-Request-Id`; sends a page request with no `X-Request-Id`; lets the runs end; cancels; and compares each captured event's `Name` with the closed set, its `Time` with the fixed time, the request pair's `RequestID` with the minted id, the bus events' ids, and the count of `source.called` events with the transport's count of requests. A test of secrecy builds the fake's records with markers, makes every call and request R-U54Y-KZ5C names, and searches every capture for every marker.
