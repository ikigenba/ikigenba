# D03-serve

The serve path: what happens between `cli.Run` being called with no arguments and the process being gone, the services file, the listener's life, the route table the handler keeps, and the sibling read path, through which a sibling reads a scraper's current run, a run's record and every row of a run over the socket (decision 8). It is gmail's serve path with the run engine in place of the transfer engine and the drafts service, scripts' two bus routes with scrapes' own handlers, and three read paths of its own. `internal/server` is gmail's, unchanged.

`D01-layout-and-run-seam` declares the run seam, the settings, the database path and the refusal of a setting; `D02-cli` the exit codes; `D06-runs` the engine and everything the start and the stop do to runs: the settling before ready (`Engine.Recover`), the prune before ready and on each sweep, and the drain; `D07-events` what `/declarations` answers; `D08-pages` the pages; `D09-trail` the trail and its secrecy; `D10-tools` the tools; `D11-on-a-space` the nginx fragment.

## The services file

`IKIGENBA_SERVICES` names the services file. scrapes calls no sibling of its own (decision 12): the entries `telemetry` and `events` are appkit's sinks' (`D01-layout-and-run-seam`), and the entry `auth` is read afresh per request by the pages through `urls.Auth` (`D08-pages`). `Run` hands the path to the handler as `web.Config.ServicesPath`. With `IKIGENBA_SERVICES` unset, naming no file, or naming one `services.Read` refuses, the start is not refused.

## The terms scrapes serves on

scrapes serves only on a listening socket it inherits, taken as `sd_listen_fds(3)` documents, and reports readiness with `READY=1` to `NOTIFY_SOCKET` as `sd_notify(3)` documents. It trusts `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx sets them, and trusts the MCP gateway and any sibling calling it at its socket to have forwarded them (decision 16, `D11-on-a-space`). Every request has an id: the one nginx or the caller set, or 32 lowercase hexadecimal digits appkit's telemetry middleware draws from `Process.Rand`.

The events app reaches scrapes at its socket on `/events` and `/declarations`. scrapes emits the two run events of `D07-events` and accepts one exact `cron.scrape_<scraper>.fired` per registered scraper, today `cron.scrape_fmcsa.fired` and `cron.scrape_ppp.fired` (`D06-runs`), so it mounts appkit's `events.DeliveryHandler` over the engine's handlers and `events.DeclarationsHandler` over its emitter, built with `trail.Emits()`, and the same handlers. These two paths sit outside the identity gate, as scripts' do; the fragment answers both 404 at the public name (`D11-on-a-space`).

## The route table

Every request goes through appkit's `telemetry.Middleware`. Then, by the path alone, compared by hand so that nothing is cleaned and nothing redirected, the bus's two paths, `/mcp` and `/_appkit/` on `URL.Path` and the sibling paths on the escaped path, `URL.EscapedPath()`: exactly `/events` and exactly `/declarations` go to the event bus's two handlers; every other request goes through `identity.Require`. Past the gate: exactly `/mcp` goes, through `events.Middleware`, to the MCP server, on which the six tools of `D10-tools` are registered once when the handler is built; a path beginning `/_appkit/` goes to `page.Static()`; a **current path**, `/scrapers/<name>/current`, a **record path**, `/runs/<id>/record`, and a **rows path**, `/runs/<id>/rows`, go to the sibling read path; and every other path to the page handler (`D08-pages`), which answers `/`, `/runs/<id>`, `/runs/<id>/rows/<source_id>`, `/about`, `/tools` and, for everything else, the not-found page.

The handler is built from a `web.Config` carrying what the routes need: the banner source, the MCP server, the services file's path, the store, the registry, the engine, the writer and the emitter.

## The sibling read path

The read path answers JSON to a program, so its answers are contract, and every refusal is plain text, as artifacts' files path refuses: status, `text/plain; charset=utf-8`, a copy constant and a newline, no body on `HEAD`. It is served behind the identity gate like every route but the bus's two, at the socket and at the public name (decision 8); a request without `X-User-Id` gets `identity.Require`'s answer. `GET` and `HEAD` are served; any other method is 405 with `Allow: GET, HEAD` and an empty body, whatever the path.

- A current path answers the scraper's current run (`store.CurrentRun`, the newest `done`) as `json.Marshal(runs.RecordOf(r))` and a newline, `application/json`, status 200. A name the registry does not hold is 404 with `web.NotFound`; a registered scraper with no current run is 404 with `web.NoRun`, as the tools tell `not_found` from `no_run`.
- A record path answers the run's record as `json.Marshal(runs.RecordOf(r))` and a newline, `application/json`, status 200, whatever its status. A run the store does not hold, an unknown or invalid id or a pruned run, is 404 with `web.NotFound`.
- A rows path answers every row of the run, in `source_id` order, one line per row, each `json.Marshal` of the row (`D05-scrapers`) with its `raw`, as `store.EachRow` (`D04-store`) gives it, as `application/x-ndjson`, status 200, streamed: chunked, with no `Content-Length` and no page. A run the store does not hold, an unknown id or a pruned run, is 404 with `web.NotFound`. A run that is not `done` holds no rows (decision 4), so it is answered 200 with an empty body, as the store's `EachRow` answers it; a sibling that needs to know reads the run's status first, and `scrape.finished` with `status` `done` is the signal a run has landed.
- The database failing before the answer has begun is 503 with `store.Unreachable`. A failure after the first line has been sent cannot change the status, so what the client then reads is not contract: no declared seam lets a test fail the store between two rows of one `EachRow` call. A sibling checks a stream's line count against the record's `rows`.

The read path writes nothing, starts no run, and tells no event of its own; each request is recorded by the telemetry middleware (`D09-trail`).

## The start

With `Args` empty, `Run` checks the settings (`D01-layout-and-run-seam`), then whether exactly one socket was passed in, with the diagnostics below. It removes the three `LISTEN_*` variables, takes descriptor 3, and opens the database with `db.Open` at `state/scrapes.db`; a failure is `scrapes: cannot open database state/scrapes.db: ` and the reason, exit 1. It builds the store, the writer, the emitter, the registry and the engine, and records `service.started`, so that it is the first event of every run. Then the engine settles what a dead process left and the store prunes once, as `D06-runs` states; a settling that fails, the database having failed under it, refuses the start with `scrapes: ` and `store.Unreachable`, exit 1. Then `Run` builds the handler, sends `READY=1`, and serves.

## Stopping

When `ctx` is done (in the binary, on `SIGTERM` or `SIGINT`, the signal's name being the cause) `Run` stops the sweep, drains the engine as `D06-runs` states, and at the same time drains the server for `DRAIN_SECONDS`, waits within the same window for the emitter to deliver what it holds, shuts the writer down with the cause's text as `service.stopping`'s reason, shuts the emitter down, and closes the database. From the drain deadline on, `Run` hands neither sink anything: an event recorded after it reaches standard error as appkit's `lost event` and `undelivered event` lines. A run interrupted never makes the exit non-zero; a drain that runs out on requests is `scrapes: stopped with <n> request(s) unfinished`, exit 1. A rows stream still being sent at the signal is a request, drained as every request is.

## Recorded decisions

- **The read path refuses in plain text with copy constants**, as artifacts' files path does (status, `text/plain; charset=utf-8`, the line and a newline): the status is what a program reads, the line is for a person with `curl`.
- **Unknown scraper and no current run are both 404**, with two lines, `web.NotFound` and `web.NoRun`, mirroring the tools' `not_found` and `no_run`: decision 8 gives 404 for no current run, and a name nobody registered is not found by the same rule a run id is.
- **A run not `done` streams nothing, 200**: the store's `EachRow` answers a run not `done` with no rows (`D04-store`), as the `rows` tool answers an empty page; a refusal would make a sibling tell a running run from a failed one by status, which the record already says.
- **An unknown, invalid or pruned run id is 404 `web.NotFound`**, as the pages and the tools treat a pruned run as gone (decision 11).
- **The database failing is 503 `store.Unreachable`**, gmail's page answer and artifacts' files answer. A failure after the stream has begun has no declared shape: `D04-store` gives a test no way to fail the store between two rows of one `EachRow` call, so no requirement could be proved; the record's `rows` is the sibling's check.
- **The record is at `/runs/<id>/record`, not decision 8's `/runs/<id>`.** One path cannot be both the run's page (decision 10, the template `run`) and its JSON record; no sibling in the suite negotiates by `Accept`, so content negotiation would be a first; and `/record` sits beside `/runs/<id>/rows`, so a person with a token can still `curl` it at the public name.
- **Paths are matched on the escaped path** (`URL.EscapedPath()`), as `D08-pages` matches its page paths, so `/runs/<id>%2Frows` is not a rows path and nothing decoded can change which route answers; the bus's two paths, `/mcp` and `/_appkit/` are matched on `URL.Path`, as gmail and scripts match them.
- **Methods**: `GET` and `HEAD`, the rest 405 with `Allow: GET, HEAD` and an empty body, as artifacts and scripts' run files answer; the method is decided first, then the scraper's registration, then the database, then the run.
- **The rows stream is `application/x-ndjson`**, one `json.Marshal` of the row per line, LF-terminated, chunked: decision 8's JSON lines, and the media type JSON-lines readers recognise; no precedent in the suite streams JSON lines, so the choice is ours.
- **The current run and the record are `application/json` with no charset parameter** and a trailing newline, as artifacts answers a record and appkit's delivery and declarations handlers answer JSON: JSON is UTF-8 by definition, so a charset adds nothing.
- **A missing identity is `identity.Require`'s 500**, as every route behind the gate answers it (decision 8: "for a request carrying an identity"); the public name's 302 to sign-in is nginx's (`D11-on-a-space`).
- **The read path takes no event cause**: it tells no event, so it does not go through `events.Middleware`.
- The bus's two routes are scripts': outside the gate, inside the telemetry middleware, over the engine's handlers (`runs.Engine.Handlers`), with the emitter given to `events.DeclarationsHandler` because scrapes emits as well as accepts.
- The settings, the database path and the sweep interval are `D01-layout-and-run-seam`'s; the settling, the prunes, the sweep and the drain's effect on runs are `D06-runs`'; this document states only the order of the start's steps, the refusals of the start, and the stop's effect on the process.
- `web.Config` carries no clock or random source: the store holds `Process.Now` and `Process.Rand`, the writer and the emitter hold both, and the scrapers hold `Process.Now` and `Process.Sleep`.

## Consumer tasks

`Run`, serving, calls `s, err := settings.Read(p.LookupEnv)`, checks the socket, unsets the three `LISTEN_*` variables and takes `ln, _ := p.Inherit(3)`; opens the database (`D01-layout-and-run-seam`); builds `st := store.New(d, store.Config{Now: p.Now, Rand: rand})`, the writer `w`, the emitter `em` with `trail.Emits()`, `reg := scrapers.Default(...)` and `eng := runs.New(runs.Config{Store: st, Scrapers: reg, Telemetry: w, Events: em})`; calls `w.Ready()`; calls `eng.Recover(bg)` and `st.PruneRuns(bg, s.KeepRuns)`; builds `h := web.Handler(web.Config{Banner: p.Banner, MCP: p.MCP(w), ServicesPath: path, Store: st, Scrapers: reg, Runs: eng, Telemetry: w, Events: em})`; sends `READY=1`; and calls `server.Serve(ctx, ln, h, s.Drain(), stop)`, `eng.Drain(drainCtx)` beginning once `ctx` is done. A sibling (the later `candidates`) sends `GET /scrapers/fmcsa/current` with the identity headers over the socket, reads the record's `id` and `rows`, may re-read it with `GET /runs/<id>/record`, then `GET /runs/<id>/rows` and decodes one JSON value per line until the body ends, counting `rows` lines. A test of the handler builds `web.Handler` over a store on its own database, a registry `scrapers.New(fake)`, an engine, a writer and an emitter over captures and a server from `mcp.NewServer`, serves it with `httptest`, seeds runs through the store with `AddRun`, `PutRows` and `FinishRun`, and sends raw requests with the identity headers set or left out, reading `resp.TransferEncoding`, the headers and each line; it fails the store with `SetFailing(true)` on its handle. A test of the start drives `cli.Run` with a listener, a `NOTIFY_SOCKET` it binds, a `Now`, an `After` and a `Rand` it controls, an `HTTP` whose transport answers as a fake Socrata (`D05-scrapers`) and captures; waits for `READY=1`; drives `/mcp` with `mcp.Client`, `POST /events` and the read paths with raw HTTP; cancels; and reopens the database.
