# D04-store

The records: `internal/store`, which owns scrapes' two tables in its SQLite database, `state/scrapes.db`: `runs`, one row per run a `scrape` call or a cron delivery started (decision 4), and `rows`, the rows of each run, addressed by the run and the record's `source_id` (decision 5), each until the prune removes its run. It says what a run holds, the words its status and failure reason are spelled with, how a run is recorded, filled, finished and failed, how the comparison with the run before is counted, which reads the engine, the tools, the pages and the sibling read path have, how the prune decides what is past keeping, the errors every consumer tells apart, the one line every consumer answers when the database cannot be reached, and `db status`. Opening, migrating, transactions and the failure seam are appkit's `db`; `D01-layout-and-run-seam` resolves the path and declares the root package's `Migrations()`. It is gmail's store in shape, with a run in place of a transfer and its rows beside it.

## One database, one writer

scrapes is the only writer of its database, and the database is the only record of its runs and rows; nothing else is kept on disk (decision 1). `store.New` builds a store over a handle and opens or creates nothing. What a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds; a test proves the records that way, never by reading tables. A store whose handle is failing (`SetFailing(true)`) answers every call with `ErrUnreachable` and changes nothing. `Config.Now` is the clock every stamp is read from, and `Config.Rand` the source run ids are drawn from; `Run` hands in `Process.Now` and `Process.Rand`, and the store has no default for either.

## Runs

A **run** is one walk of one scraper's source. Its **id** is `run_` and 16 lowercase hexadecimal digits, 8 bytes drawn from the random source when the run is recorded, drawn again when they are a run's id already. It keeps `scraper`, the registered name it walks; **started** and **finished**, each UTC to the second; the counts `rows`, `new`, `changed`, `unchanged` and `gone`, each 0 until the run is done; and its **starter**: for a `scrape` call, the caller's user id and email; for a cron delivery, the slug of the trigger whose fire was delivered (decision 4). It also keeps the request id it was started under, so the events of a run settled by the next start name the request that started it (`D07-events`), and, for a delivery, the bus event's id, the **delivery**, an internal column no tool, page or sibling answer carries: it is how a redelivered event is told from a new one (`D06-runs`).

Its **status** is one of three words: `running`, `done` and `failed`. A failed run has one of three **reasons**: `source`, `interrupted` and `store`; which failure is which is `D06-runs`'.

A run has four writes. `AddRun` records it `running`, stamping started and minting the id; it is refused `ErrBusy` while a run of the same scraper is `running`, so one run per scraper runs at a time and runs of different scrapers may overlap, and `ErrDelivered` when its delivery is one an existing run already carries, whatever that run's status. `PutRows` stores a batch of rows into a `running` run. `FinishRun` ends a `running` run `done` and writes its counts; `FailRun` ends a `running` run `failed` with a reason and removes its rows, in one write, so a run has rows only once it is done (decision 4). Of two calls racing on the same run one succeeds and the other is told it is no longer running (`ErrEnded`). Nothing moves a run back.

## Rows

A **row** is one record of one run, the envelope `D05-scrapers` declares (`source.Row`) with the raw record beside it. Within a run it is addressed by its `source_id`, unique within the run: a later `PutRows` of a row whose `source_id` the run already holds replaces that row, so a record a paging shift answers twice is kept once, as the later page spelled it (decision log D5). No row id is minted. The store writes the row's `run` and `scraper` from the run it is stored into, whatever the batch says, and keeps every other member as given, byte for byte for `facts` and `raw`.

Rows are read only from `done` runs: a `running` run's rows are a batch in progress and a `failed` run has none, so every row read of a run that is not `done` answers no row. `ListRows` pages a done run's rows in ascending byte order of `source_id`, without `raw`, optionally only those one of whose `names` contains a given text, compared case-insensitively; `GetRow` answers one row with `raw`; `EachRow` hands every row of a done run, with `raw`, in the same order, to a function, one at a time, for the sibling read path's stream.

## The comparison

When a run ends `done`, its counts are written against its **baseline**: the newest `done` run of the same scraper other than itself at that moment, newest meaning latest started and, among equal starts, greatest id (decision log D5). `rows` is the number of distinct rows the run holds. `new` counts its `source_id`s the baseline does not hold; `changed` those the baseline holds with another `digest`; `unchanged` those the baseline holds with the same `digest`; `gone` the baseline's `source_id`s the run does not hold. With no baseline, `new` is `rows` and the other three are 0.

## Reads and the prune

`GetRun` answers any run, whoever started it: runs belong to no one (decision 7). `ListRuns` is the runs of one scraper, or of every scraper, newest first, a window of them at a time. `CurrentRun` is a scraper's newest `done` run, its **current** run; `RunningRun` its `running` run; `RunningRuns` every `running` run, which the start finishes `failed` with `interrupted`. `PruneRuns` removes, in one write, for each scraper, every `done` run beyond the newest keep count of its `done` runs and every `failed` run beyond the newest keep count of its `failed` runs, with their rows; a `running` run is neither counted nor removed (decision 11). A pruned run is gone from every read, its delivery with it. All lists are never nil.

## Errors

`ErrNotFound`, `ErrBusy`, `ErrDelivered` and `ErrEnded` are answers about the records. Every other error satisfies `errors.Is(err, ErrUnreachable)`, and every consumer answers it with `Unreachable` (a tool's `unavailable`, a page's unavailable answer, a delivery's `Fail`), never quoting the cause. A done context, a failing handle, a random source that fails and a write given a value no consumer sends all end there, the last changing nothing.

## `db status`

`scrapes db status` writes what appkit's `db.Status` writes for `state/scrapes.db` and the root package's `Migrations()`, and creates nothing.

## Recorded decisions

- The schema is two migrations. `0001_runs.sql`: `runs` (`id` primary key, `scraper`, `status`, `reason`, `started`, `finished`, `rows`, `new`, `changed`, `unchanged` and `gone` integers, `user_id`, `user_email`, `trigger`, `request_id`, `delivery`), with an index on `scraper` and `started`, and a unique index on `delivery` where it is not empty. `0002_rows.sql`: `rows` (`run`, `source_id`, `scraper`, `collected`, `digest`, `name`, `names` as a JSON array, `names_lower`, the lower-cased names joined for the `name` filter, `street`, `city`, `state`, `zip`, `county`, `lat`, `lon`, `people` as a JSON array, `facts` and `raw` as JSON text kept byte for byte), with a unique index on `run` and `source_id` and an index on `run` and `digest` (decision 11), the latter for the comparison. Times are RFC 3339 UTC to the second; an empty `finished` is one not yet set. No requirement states the schema, since a test proves the records through the store; the sandbox check, which sets a run to `running` by hand, writes these columns. `rows`, `new`, `trigger` and the other SQL keywords as column names are quoted in the migrations.
- The `name` filter scans a lower-cased copy of the names (decision log D5), with no index: a run is about 17,000 rows. The contract is stated per name, as `strings.ToLower` compares; the joined column is how it is answered.
- The delivery is a column of `runs`, not a table of its own, and is forgotten with its run at the prune (decision log D5): the events app's retries end long before a run is pruned, and a delivery is the one place it is read.
- Busy and delivered are refused by `AddRun` itself, in its write, so two starts racing (a tool call and a delivery, or two attempts of one delivery) cannot both record a run.
- Rows are written per batch, one `PutRows` per page the scraper hands over, each in one transaction (decision log D5): nothing holds more than a page.
- The counts are computed by `FinishRun` in the same write that marks the run `done`, against the baseline as it is at that moment, so a run and its counts never disagree.
- `ListRows` answers no `raw`: the `rows` tool and the run page show the envelope only (decision 7), and a page of 25 raw records is 60 KB nobody reads.
- A run that is not `done` answers no rows rather than `ErrNotFound`, so the reads tell an unknown run (`ErrNotFound`) from a known one with nothing to show.
- `source_id` order is byte order: a source id is text, and FMCSA's numeric dot numbers sort as text there. A numeric order would bind the store to one source's ids.
- A write given a value no consumer sends answers an error matching `ErrUnreachable` and changes nothing, as in gmail; there is no `ErrInvalid`. The id redraw is bounded at 8 candidates, as in gmail.

## Consumer tasks

The engine (`D06-runs`), `c` the caller, records a tool start with `r, err := st.AddRun(ctx, store.Run{Scraper: "fmcsa", UserID: c.UserID, UserEmail: c.Email, RequestID: c.RequestID})`, `store.ErrBusy` answering `busy`; a delivery with `st.AddRun(ctx, store.Run{Scraper: name, Trigger: slug, UserID: c.UserID, RequestID: c.RequestID, Delivery: d.Event.ID})`, `store.ErrDelivered` and `store.ErrBusy` answering `Skip`. The work hands each page to `st.PutRows(ctx, r.ID, rows)` and ends with `st.FinishRun(ctx, r.ID)` or `st.FailRun(ctx, r.ID, store.ReasonSource)`. The start calls `st.RunningRuns(ctx)`; the sweep `st.PruneRuns(ctx, s.KeepRuns)`. The tools and pages call `st.ListRuns(ctx, "", 0, 26)`, `st.GetRun`, `st.CurrentRun(ctx, "fmcsa")`, `st.RunningRun`, `st.ListRows(ctx, id, "trucking", 25, 26)` and `st.GetRow(ctx, id, "1023916")`; the sibling read path calls `st.EachRow(ctx, id, func(r source.Row) error { return enc.Encode(r) })`. `store.ErrNotFound` answers not found and `store.ErrUnreachable` `store.Unreachable`. A test opens its own database with `db.Open` and the root package's `Migrations()`, builds `store.New(d, store.Config{Now: clock, Rand: rnd})`, records runs of two scrapers, fills, finishes and fails them, flips `d.SetFailing(true)`, and reopens the path to prove what persists.
