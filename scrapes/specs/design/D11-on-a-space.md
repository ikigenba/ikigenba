# D11-on-a-space

What scrapes contributes when it runs on a space and in a sandbox: the manifest and the nginx fragment it ships, which entries of the services file it uses, the trust it places in the identity it is sent (decision 16), and which of the contract's guarantees the delivery's sandbox check (decision 15) and the `us` smoke test stand on. It follows gmail's on-a-space design. The guarantee such documents end with, that no record, business name, address, phone or email reaches the trail, the bus, a refusal or standard error, is `D09-trail`'s here, as it is gmail's trail document's there.

## What ships

The release holds four members of scrapes' directory: `bin/scrapes`, `etc/manifest.toml`, `etc/nginx.conf` and `share/icon.svg`, the last Tabler's `database-import`, human-authored (decision 1). No test reads the checkout, so the release and the icon are outside what a requirement can state; a developer checks them with `tar`. The two files under `etc/` are what the root package's `Etc` embeds (`D01-layout-and-run-seam`): `etc/manifest.toml` holds the bytes of `cli.Manifest`, which `D02-cli` states byte for byte with the command that prints it, and `etc/nginx.conf` the bytes of `cli.NginxConf`, which this document states.

## The manifest

The manifest is a program-parsed file: opsctl, the sandbox and home read it, so its text is contract, stated byte for byte as `cli.Manifest` in `D02-cli`, which also compares its description with `pages.Description` and its `[env]` with `settings.Defaults()`. What a space takes from it: it names the app `scrapes`; its description, decision 1's text, the same as `pages.Description` (`D08-pages`) and the one the `User-Agent` names (`D05-scrapers`, decision log D2); that it is not the default app; that it is an MCP service (`mcp = true`), so the gateway offers the six tools; that it does not serve guests (`guests = false`), so the host's nginx puts every request through auth's `/check`, to the pages, to `/mcp` and to the sibling read path alike, and a page asked without a credential is sent to sign in (the 302 the checks expect is nginx's and auth's); no secrets, since Socrata needs no key; an `[env]` table holding the four settings' defaults as strings, in the order `settings.Read` reads them (`D01-layout-and-run-seam`), so the values the host writes into scrapes' environment are the ones scrapes applies when a setting is unset; the `[database]` table that has the host keep and replicate `state/scrapes.db`; a `[resources]` table whose only line is `memory_max = "256M"`, room for a Socrata page of 10,000 records held decoded while it is stored (decision 1); and, last, a `[home]` table whose only line is `group = "application"`, so home lists scrapes under Application, the first application on the platform. `DRAIN_SECONDS` is not in `[env]`: it is the space's, as for every app.

## The nginx fragment

The fragment, `NginxConf`, answers the event bus's two paths, `/events` and `/declarations`, 404 at the public name, as every consumer's does (decision 8): a delivery reaches scrapes only over its socket. Nothing else is held back, so the sibling read path, `GET /scrapers/<name>/current`, `GET /runs/<id>/record` and `GET /runs/<id>/rows` (`D03-serve`), is served at the public name too, behind auth, for a person with a token and `curl`. scrapes takes no request body larger than an MCP call or a delivery.

## On a space

scrapes on a space is the same binary on the same terms as under a test: a socket passed as descriptor 3 (`/run/ikigenba/scrapes.sock`), `/var/opt/ikigenba/scrapes` as its working directory, its settings from `/etc/opt/ikigenba/scrapes/env`, and `IKIGENBA_SERVICES` naming the host's services file. Of that file it uses `events` and `telemetry`, appkit's sinks', and `auth`, for the banner's addresses (decision 12); it calls no other sibling. A missing file or entry never refuses the start (`D03-serve`). It reaches one place outside the host, data.transportation.gov, over the host's outbound network.

## In a sandbox

The sandbox builds scrapes from the worktree, gives it the four settings from the manifest's `[env]`, puts every request through auth's `/check`, and includes `etc/nginx.conf` in scrapes' server. Its state is `<data>/apps/scrapes/state/`. It has the developer machine's outbound network, so the sandbox check runs FMCSA for real (decision 15): an agent is curl on the developer's machine with the stored token, at `http://scrapes.<sandbox>.localhost:<port>/` for the pages and the gateway for the tools. With the token, `scrape` of `fmcsa` lands a run of about 16,700 rows and the Verification list runs against it; the trigger `scrape_fmcsa` (decision log D7) is created with cron's `create` on a schedule a minute away; events' `subscribers` is observed to list scrapes `ok`, since scrapes declares the exact name `cron.scrape_fmcsa.fired` (`D06-runs`, `D07-events`); the fire is observed to start a run, and once it has, events' `catalog` to list scrapes among the services accepting `cron.scrape_fmcsa.fired`, its subscribers, an entry the catalog holds only once a fire of that name is retained; and it is updated to `0 6 2 * *`; the failure case is tried by pointing `FMCSA_STATES` at a value Socrata refuses, at most twice, and otherwise the unit test stands (decision log D3); cleanup deletes the trigger and empties the database. The `us` smoke creates `scrape_fmcsa` with the monthly schedule, lands one run and leaves both. These steps are the delivery's: no permitted test reaches Socrata, cron or the gateway, so no requirement here states them.

## Trust

scrapes believes the identity it is sent, as every sibling does: `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx or the gateway set them on a request to its socket. It checks them against nothing and asks auth nothing; a run a `scrape` call starts is recorded as started by the user the request names. It takes a delivery at `POST /events` from any process that can reach its socket, with no identity at all, as appkit's delivery handler admits it (`D03-serve`, `D07-events`), and a delivered `cron.scrape_<scraper>.fired` starts a run. A process that can reach scrapes' socket can therefore name any user, start a run of any scraper as that user or as cron, and read every run and row; every service on the host is trusted, and the gateway and nginx are the only doors from outside, nginx refusing the bus's two paths there.

## Recorded decisions

- **Trust is stated as the design's own decision** (decision 16), as gmail's on-a-space design records its decision 21, for these reasons: the suite's identity model is that auth answers nginx's subrequest and the gateway forwards the caller, and a service that re-checked would ask auth on every call for nothing nginx has not already decided; the evidence scrapes holds is public records, belonging to no one (decision 7), so a forged identity reads nothing it could not read signed in, and what it can do, start a run, is bounded by one run per scraper at a time; and a delivery cannot carry a person's credential, so the bus's paths are closed at the public name instead, which leaves the socket, reachable only on the host, as the one way in.
- **The manifest is `D02-cli`'s and the fragment this document's**, as `D02-cli` divides them: the manifest is what the `manifest` command prints, and the fragment is what a space drops into scrapes' server. This document says what a space does with each and states no manifest requirement of its own.
- **`memory_max` is `256M`** (decision 1), as gmail's, though gmail's is for an attachment: one 10,000-record page decoded is about 25 MB of JSON and its rows, and nothing holds more than a page (decision log D5).
- **The services file gives the events socket**, with telemetry's and auth's entries that every app reads (decision 12); a requirement here proves no other entry is called, which is also the evidence that scrapes asks auth nothing.
- No release is named in the manifest or in any requirement; the release number and the deploy are the delivery's.

## Consumer tasks

An operator installs the release; opsctl reads `etc/manifest.toml`, writes the four settings and `DRAIN_SECONDS` into `/etc/opt/ikigenba/scrapes/env`, drops `etc/nginx.conf` into scrapes' server, adds scrapes' entry to the services file and starts the unit. A test reads `nginx.conf` from the root package's `Etc()` with `fs.ReadFile` and compares it with `cli.NginxConf`. A test builds a `cli.Process` with a temporary `Dir`, a services file whose entries `auth`, `artifacts`, `connections` and `cron` name Unix sockets on which loopback fakes listen and record every request, captures as sinks, an `HTTP` whose transport answers as a fake Socrata, and its own `Now`, `After` and `Rand`; it calls the tools through `mcp.Client` with identity headers of its choosing, posts a delivery to `/events`, asks the pages, waits for the runs to end, cancels, and checks that the fakes received nothing and that the run's record names the user the headers named.
