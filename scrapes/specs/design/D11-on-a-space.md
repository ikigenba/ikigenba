# D11-on-a-space

What scrapes contributes when it runs on a space and in a sandbox: the manifest and the nginx fragment it ships, which entries of the services file it uses, the disk it takes and what of it the host keeps, the trust it places in the identity it is sent (decision 16), and which of the contract's guarantees the delivery's sandbox check (decision 15) and the `us` smoke test stand on. It follows gmail's on-a-space design. The guarantee such documents end with, that no record, business name, address, phone or email reaches the trail, the bus, a refusal or standard error, is `D09-trail`'s here, as it is gmail's trail document's there.

## What ships

The release holds four members of scrapes' directory: `bin/scrapes`, `etc/manifest.toml`, `etc/nginx.conf` and `share/icon.svg`, the last Tabler's `database-import`, human-authored (decision 1). No test reads the checkout, so the release and the icon are outside what a requirement can state; a developer checks them with `tar`. The two files under `etc/` are what the root package's `Etc` embeds (`D01-layout-and-run-seam`): `etc/manifest.toml` holds the bytes of `cli.Manifest`, which `D02-cli` states byte for byte with the command that prints it, and `etc/nginx.conf` the bytes of `cli.NginxConf`, which this document states.

## The manifest

The manifest is a program-parsed file: opsctl, the sandbox and home read it, so its text is contract, stated byte for byte as `cli.Manifest` in `D02-cli`, which also compares its description with `pages.Description` and its `[env]` with `settings.Defaults()`. What a space takes from it: it names the app `scrapes`; its description, decision 1's text, the same as `pages.Description` (`D08-pages`) and the one the `User-Agent` names (`D05-scrapers`, decision log D2); that it is not the default app; that it is an MCP service (`mcp = true`), so the gateway offers the six tools; that it does not serve guests (`guests = false`), so the host's nginx puts every request through auth's `/check`, to the pages, to `/mcp` and to the sibling read path alike, and a page asked without a credential is sent to sign in (the 302 the checks expect is nginx's and auth's); no secrets, since neither Socrata, data.sba.gov, MnGeo's parcel service nor askebsa.dol.gov needs a key; an `[env]` table holding the eleven settings' defaults as strings, in the order `settings.Read` reads them (`D01-layout-and-run-seam`), among them the write budget `SCRAPE_WRITE_BUDGET` and the pressure limit `SCRAPE_PRESSURE_LIMIT`, so the values the host writes into scrapes' environment are the ones scrapes applies when a setting is unset; the `[database]` table that has the host keep and replicate `state/scrapes.db`, the catalog of runs, and nothing under `runs/`; a `[resources]` table whose only line is `memory_max = "256M"`, room for what a run holds at once (see Recorded decisions); and, last, a `[home]` table whose only line is `group = "application"`, so home lists scrapes under Application, the first application on the platform. `DRAIN_SECONDS` is not in `[env]`: it is the space's, as for every app.

## The nginx fragment

The fragment, `NginxConf`, answers the event bus's two paths, `/events` and `/declarations`, 404 at the public name, as every consumer's does (decision 8): a delivery reaches scrapes only over its socket. Nothing else is held back, so the sibling read path, `GET /scrapers/<name>/current`, `GET /runs/<id>/record` and `GET /runs/<id>/rows` (`D03-serve`), is served at the public name too, behind auth, for a person with a token and `curl`. scrapes takes no request body larger than an MCP call or a delivery.

## On a space

scrapes on a space is the same binary on the same terms as under a test: a socket passed as descriptor 3 (`/run/ikigenba/scrapes.sock`), `/var/opt/ikigenba/scrapes` as its working directory, holding the catalog `state/scrapes.db` and, beside `state/`, the run files under `runs/` (`D04-store`), its settings from `/etc/opt/ikigenba/scrapes/env`, and `IKIGENBA_SERVICES` naming the host's services file. Of that file it uses `events` and `telemetry`, appkit's sinks', and `auth`, for the banner's addresses (decision 12); it calls no other sibling. A missing file or entry never refuses the start (`D03-serve`). It reaches four places outside the host over the host's outbound network: data.transportation.gov for FMCSA, data.sba.gov for PPP, enterprise.gisdata.mn.gov for MN parcels and askebsa.dol.gov, redirected to www.askebsa.dol.gov, for Form 5500. On a Linux host the engine reads `/proc/pressure/io` between steps, the file `main` names as `Process.Pressure` (`D01-layout-and-run-seam`), and pauses while its `full avg10` is above `SCRAPE_PRESSURE_LIMIT`; where the file cannot be read there is no such pause.

The disk scrapes takes is the run files. Each done run kept is one file under `runs/`, about 4.03 GB for an MN parcels run of 832,126 rows (observed in the sandbox, about 4.8 KB a row); a run being built holds its chunks, gzip-compressed about 12:1 (observed: 16.78 MB of rows to a 1.43 MB chunk), about 0.23 GB for a parcel run, then the file it loads beside them until the load ends. At `SCRAPE_KEEP_RUNS` 2 the peak for parcels is two retained files, the compressed chunks and the file being built, about 12.3 GB (2 × 4.03 + 0.23 + 4.03) on the space's 80 GB volume, plus the chunks of any other scraper's run walking at the same time, which are small beside a parcel file: runs of different scrapers go side by side, and only one loads at a time (`D06-runs`). A Form 5500 run of about 250,000 rows adds, while it walks, one spooled zip of at most 137 MB beside its chunks (`D05-scrapers`), and its file is smaller than a parcel run's, so the peak stands. The catalog holds run records only and stays small. Neither the backup nor Litestream sees `runs/`: the files are regenerable by scraping again, and opsctl's snapshot of `state/` must not carry them.

## On `us`

The release that moves rows into run files is deployed to `us` after an operator step, confirmed by the owner, that is the delivery's and no requirement's: stop Litestream for the scrapes database, delete the catalog's files, purge its replica prefix (Litestream's retention is off, so the old generation would otherwise stay in S3), start scrapes on the new release, and scrape `fmcsa`, `ppp` and `mn_parcels` again. The old catalog's runs had no files, so kept they would answer missing; the wipe starts the space clean. The MN parcels run is then watched as the table's `us` rows say: `/proc/pressure/io` sampled through it, auth's sign-in tried during it, and its time, its file's size and the catalog's size recorded. The release that adds Form 5500 needs no operator step: once it is deployed, `form5500` is scraped once on `us` and the trigger `scrape_form5500` created with its quarterly schedule; the existing runs and triggers are untouched.

## Trust

scrapes believes the identity it is sent, as every sibling does: `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx or the gateway set them on a request to its socket. It checks them against nothing and asks auth nothing; a run a `scrape` call starts is recorded as started by the user the request names. It takes a delivery at `POST /events` from any process that can reach its socket, with no identity at all, as appkit's delivery handler admits it (`D03-serve`, `D07-events`), and a delivered `cron.scrape_<scraper>.fired` starts a run. A process that can reach scrapes' socket can therefore name any user, start a run of any scraper as that user or as cron, and read every run and row; every service on the host is trusted, and the gateway and nginx are the only doors from outside, nginx refusing the bus's two paths there.

## Recorded decisions

- **Trust is stated as the design's own decision** (decision 16), as gmail's on-a-space design records its decision 21, for these reasons: the suite's identity model is that auth answers nginx's subrequest and the gateway forwards the caller, and a service that re-checked would ask auth on every call for nothing nginx has not already decided; the evidence scrapes holds is public records, belonging to no one (decision 7), so a forged identity reads nothing it could not read signed in, and what it can do, start a run, is bounded by one run per scraper at a time; and a delivery cannot carry a person's credential, so the bus's paths are closed at the public name instead, which leaves the socket, reachable only on the host, as the one way in.
- **The manifest is `D02-cli`'s and the fragment this document's**, as `D02-cli` divides them: the manifest is what the `manifest` command prints, and the fragment is what a space drops into scrapes' server. This document says what a space does with each and states no manifest requirement of its own.
- **`memory_max` is `256M`** (decision 1), as gmail's, though gmail's is for an attachment, and raising it was considered and rejected: the store should not need memory, and the host's constraints stand. What a run holds at once is fixed by the shape of the process, not by the row count: one source page decoded, about 25 MB for a 10,000-record Socrata page (decision log D5), less for a PPP batch of 1,000 rows (the file is streamed, never held, PPP decision 3) or an ArcGIS page of 2,000 features (MN parcels decision 11); the 16 MiB build buffer of encoded rows; one row per chunk while the chunks merge; one load transaction; and SQLite's page cache. The process's high-water mark over a parcel run stayed under 70 MB under the old store (observed). The dirty page cache the budgeted writes leave is charged to scrapes' cgroup, and the kernel throttles the writer when it fills; that is accepted, because every write is sequential.
- **The disk peak is about 12.3 GB for MN parcels at `SCRAPE_KEEP_RUNS` 2** (the store decisions' section 10): two retained files of about 4.03 GB, the run's chunks, about 0.23 GB compressed (gzip about 12:1; uncompressed they were 2.7 GB), and the file being built, on the 80 GB volume, plus the chunks of other scrapers walking beside it. A parcel run's size is the disk's concern, not memory's (MN parcels decision 7).
- **The run files are neither backed up nor replicated.** They lie in `runs/` beside `state/`, so the twice-daily snapshot of `state/` and Litestream see only the catalog, which stays small; a run file is regenerable by scraping again, and a lost one answers missing until the next run (`D04-store`).
- **The finish-line figure is `some avg60` under 20%** on `/proc/pressure/io` throughout the MN parcels run on `us` under the default budget: the run that starved `us` read about 45 on `full avg10`, a quiet host reads near 0, and a minute's average of any stall is the host-wide measure a neighbour feels. The parcels run's expectation is under an hour, the price of the budget; PPP's stays within two minutes, its file far smaller.
- **The services file gives the events socket**, with telemetry's and auth's entries that every app reads (decision 12); a requirement here proves no other entry is called, which is also the evidence that scrapes asks auth nothing.
- No release is named in the manifest or in any requirement; the release number and the deploy are the delivery's.

## Consumer tasks

An operator installs the release; opsctl reads `etc/manifest.toml`, writes the eleven settings and `DRAIN_SECONDS` into `/etc/opt/ikigenba/scrapes/env`, drops `etc/nginx.conf` into scrapes' server, adds scrapes' entry to the services file and starts the unit. A test reads `nginx.conf` from the root package's `Etc()` with `fs.ReadFile` and compares it with `cli.NginxConf`. A test builds a `cli.Process` with a temporary `Dir`, a services file whose entries `auth`, `artifacts`, `connections` and `cron` name Unix sockets on which loopback fakes listen and record every request, captures as sinks, an `HTTP` whose transport answers as a fake Socrata, and its own `Now`, `After` and `Rand`; it calls the tools through `mcp.Client` with identity headers of its choosing, posts a delivery to `/events`, asks the pages, waits for the runs to end, cancels, and checks that the fakes received nothing and that the run's record names the user the headers named.
