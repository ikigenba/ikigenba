# D10-tools

The six MCP tools agents reach scrapes by through the MCP gateway: `internal/tools`. An agent learns what scrapers there are and which run of each is current with `scrapers`, starts a run now with `scrape`, reads the runs with `runs` and `run`, pages a run's rows with `rows` and reads one row with its raw record with `row` (decision 7). Every signed-in caller sees every run and row: runs belong to no one, so no answer depends on who asks, and the caller a tool is handed is used only to start a run as that caller (`D06-runs`). The run record is `D06-runs`' (`runs.Record`), the row's JSON is `D05-scrapers`' (`source.Row`), and the tools answer them as those documents encode them.

## The tools

- `scrapers` takes nothing and answers `scrapers`, one entry per registered scraper in name order, each its `name`, its `current` run (the newest `done`, absent when none) and its `running` run (absent when none), each a run record. Read-kind.
- `scrape` takes `scraper` and answers the run record it started, `running`; it does not wait for the source (`D06-runs`). Additive: it only adds a run.
- `runs` takes optional `scraper` and `page` and answers `runs`, run records newest first (`D04-store`'s run order), of that scraper or of every scraper, 25 at a time, with `next` when more remain. A name no run carries answers an empty list.
- `run` takes `run` and answers its record.
- `rows` takes optional `run`, optional `scraper`, optional `name` and optional `page` and answers `rows`, the rows of one run in `source_id` order, 25 at a time, with `next` when more remain, each the envelope without `raw`. The run is `run` when given; otherwise the current run of `scraper`; one of the two is required. `name` keeps only the rows one of whose `names` contains it, compared case-insensitively (`D04-store`). A run that is `running` or `failed` has no rows to show and answers an empty list (decision 4).
- `row` takes `run` and `source_id` and answers that row's envelope with `raw`.

A **page** is a non-negative integer, `0` the first and also what an absent `page` means; page `p` holds the 25 entries that follow the first `25 × p`. `next` is the number of the page after this one, present only when at least one entry follows this page, so an agent hands `next` back as `page`. The run page shows the same `next` for its first page of rows (`D08-pages`, decision log D6).

## Refusals

A refusal is an MCP error result whose text is `<word>: <sentence>` (decision 7, as gmail's). The words are the five `D06-runs` declares: `not_found`, `busy`, `no_run`, `stopping` and `unavailable`. Each sentence is a copy constant, `tools.Refuse*`, one per word, so a refusal names no scraper, id, business name, address, phone or email the call or the store supplied (decision 13); the name or id the agent passed is already the agent's.

- `scrape`: what `Engine.Start` refuses, in its order (`D06-runs`): an unregistered name `not_found`, the drain `stopping`, a scraper already running `busy`; the database failing `unavailable`.
- `run` and `row`: an id that is not a run id, an unknown or pruned run, and for `row` a row the run does not hold or a run not `done`, are `not_found`.
- `rows`: `run` and `scraper` both absent, an id that is not a run id, an unknown or pruned run, an unregistered `scraper`, and a `scraper` given beside a `run` of another scraper are `not_found`; a registered `scraper` with no current run is `no_run`.
- Every tool: the database failing is `unavailable`. Malformed arguments, a negative `page` among them, are appkit's schema refusal.

## Descriptions

Every tool's description is one line, a copy constant `tools.Describe<Tool>`, which the gateway's `describe` answers as the tool's first line (Verification). `tools.Catalog()` answers each tool's name with that line, in the order `scrapers`, `scrape`, `runs`, `run`, `rows`, `row`, for the tools page (`D08-pages`).

## Recorded decisions

- **Raw registration.** All six tools are registered with appkit's `mcp.AddRawTool` and answer what `encoding/json` writes, as gdrive registers its Drive tools: appkit's typed `mcp.AddTool` refuses a type with its own JSON encoding (`source.Row` has one) and a tag holding a comma, which `runs.Record`'s absent-when-empty members need. They therefore carry no output schema, and the answer's JSON is `D06-runs`' and `D05-scrapers`' contract, stated once there. The argument types are typed, so appkit derives the input schema and refuses malformed arguments before a handler runs; under its schema rules each field carries a `json:"<name>"` tag naming its property, with no `omitempty`, and each required property also `mcp:"required"`. A structured answer is built as gdrive's are: the JSON as the one text block and as `structuredContent`, through `mcp.AddRawTool`.
- **`page` is an integer from 0** (decision log D6 says `next` is a page number the `rows` tool takes). Gmail's `page` and `next` are opaque tokens, and its rule that an absent optional argument means what an empty one means is kept: 0 is both the absent page and the first, so every page has one name. `page` is an unsigned 32-bit integer, so appkit's schema refuses a negative or oversized one and `25 × page` always fits the store's `int64` offset.
- **`rows` with both `run` and `scraper`**: `run` names the run and `scraper` must be its scraper, else `not_found`, since the pair then names no run; answering another scraper's rows would mislead. With neither, `not_found`: no run is named, and decision 7's five words hold no better one.
- **`runs` with an unregistered `scraper`** answers an empty list rather than a refusal: decision 7 gives `runs` no refusal, and the list of a name no run carries is empty.
- **A running or failed run's `rows`** answers an empty list, not a refusal: the run exists, and it has no rows (decision 4); `row` of such a run is `not_found`, as `D04-store`'s `GetRow` answers.
- **Effects**: `scrapers`, `runs`, `run`, `rows` and `row` are `mcp.Read`; `scrape` is `mcp.Additive` (decision 7).
- **Descriptions are one line** with no shared guide line after it: the intent names none, and each first line must be one sentence of at most 120 characters ending with a full stop, which appkit's `mcp` requires.
- **Refusal sentences are constants**, so the secrecy of decision 13 holds by construction; a test compares the whole text.
- **The page size is a constant of this package**, `tools.PageSize`, which the run page uses too.

## Consumer tasks

`D03-serve`'s handler calls `tools.Register(srv, tools.Config{Runs: eng, Scrapers: reg, Store: st})` once on the server `Process.MCP` made; the tools page reads `tools.Catalog()`. A model calls `scrapers` with `{}` and gets `{"scrapers":[{"name":"fmcsa"}]}`; `scrape` with `{"scraper":"fmcsa"}` and gets `{"id":"run_…","scraper":"fmcsa","status":"running","started":"…","rows":0,…,"user":"…","email":"…"}`; `run` with `{"run":"run_…"}` until `done`; `rows` with `{"scraper":"fmcsa","name":"trucking"}` and gets `{"rows":[{"scraper":"fmcsa","run":"run_…","source_id":"1023916",…}],"next":1}`, then `{"scraper":"fmcsa","name":"trucking","page":1}`; `row` with `{"run":"run_…","source_id":"1023916"}` and gets the envelope with `raw`. Or it is refused `busy: <sentence>` and calls `run` on the running run `scrapers` names. A test builds a store over its own database, a registry `scrapers.New(fake)` of fake scrapers it releases, an engine over captures, an `mcp.Server` from `mcp.NewServer`, registers the tools, serves the server inside `identity.Require`, calls `mcp.Client.CallTool` with JSON arguments, decodes a success's `structuredContent`, compares it and the text block with `json.Marshal` of the expected `tools.ScraperList`, `tools.RunList`, `tools.RowList`, `runs.Record` or `source.Row`, and compares a refusal's text with the word, `": "` and the `tools.Refuse*` constant.
