# D05-scrapers

The scrapers: what every scraper shares (`internal/source`: the row envelope, its normalization, the digest, the `Scraper` interface and the name of `source.called`), the scrapers the registry holds (`internal/fmcsa`, the FMCSA motor carrier census on Socrata, `internal/ppp`, the SBA's Paycheck Protection Program loans in CSV files, `internal/mnparcels`, Minnesota's compiled county parcels on an ArcGIS feature service, `internal/form5500`, the Department of Labor's Form 5500 filings in zipped CSV files, and `internal/oshaita`, OSHA's Form 300A injury and illness summaries in zipped and bare CSV files), and the fixed registry that knows scrapers by name (`internal/scrapers`). A scraper is Go code ported from the funnel probe's Python module, not a configuration: it knows where its source is, how it pages or streams and how a record becomes a row (decision 2). Adding a source is adding a scraper to the registry; the run record, the envelope, the tools, the pages and the events hold every scraper without change. `D06-runs` starts a scraper and stores what it hands over; `D04-store` keeps the rows; `D01-layout-and-run-seam` supplies the HTTP client, the clock, the pause and the settings.

## The envelope

A **row** is one record from one source, filled by its scraper before it is stored; there is no ingest step that derives it later (decision 5). Its provenance is the `scraper`, the `run` (written by the store), the `source_id` (the source's own id for the record, unique within a run and stable across runs), `scraped` (when the record was taken from its source, UTC to the second) and `digest`, the lowercase hexadecimal SHA-256 of the raw record's bytes, exactly as the source sent them where the source sends each record as JSON (FMCSA, and for MN parcels the record's `attributes` object without its centroid) and as the scraper encodes them where it does not (PPP, Form 5500, OSHA ITA), so a record the source changed has another digest. Its common fields are the same for every scraper: `name`, the business as the source spells it; `names`, every name the record uses, `name` first, each trimmed, empties dropped, duplicates dropped; `address` with `street`, `city`, `state`, `zip` and `county`, each absent when the source gives none; `lat` and `lon` in WGS84 when the source gives a point; `people`, each a `name` and the `role` the source gives (an LLC is a party like any other); and `facts`, a flat JSON object of source-specific keys. Beside them is `raw`, the record as received, held as JSON: the source's own bytes for FMCSA, an object of the CSV's columns for PPP, Form 5500 and OSHA ITA, the `attributes` object's own bytes for MN parcels.

Nothing a scraper does filters records: the source's query scope is the only narrowing, and every record the source answers inside it becomes a row (decision 2). The normalization is the probe's, the same for every scraper, so it lives in `internal/source`: names are trimmed and deduplicated; the street and the county are trimmed; the city is trimmed and title-cased; the state is trimmed and upper-cased; the zip is trimmed and cut to its first five characters; everything else is as spelled (decision 5).

The row's JSON is the shape the tools and the sibling read path answer (`D10-tools`, `D03-serve`): `source.Row` encodes itself, so that every consumer writes the same members in the same order, `raw` only when it is held; the sibling read path adds one member, `collected`, the same string as `scraped`, for siblings of the release before (`D03-serve`).

## A scraper

A scraper has a name and one operation, `Scrape`: walk the whole source, hand its rows to the function it is given in batches (FMCSA and MN parcels a page at a time, PPP, Form 5500 and OSHA ITA a thousand rows at a time), in the order the source answered them, and return nil once the source is exhausted. A batch the function refuses ends the walk at once: the scraper sends no further request and returns an error. A source that cannot be read ends the walk with an error. A context that is done ends it promptly. Which of these ended a run is the engine's to tell (`D06-runs`): it knows when its own function refused, and when it cancelled.

Every request a scraper makes to its source is recorded in the trail as one `source.called`, carrying the scraper's name, the answer's status (0 when none came) and the time to the response headers, under the caller on the context; no query, no record, no name, address, phone or email travels (decision 13). `D09-trail` names it among the trail's events.

## FMCSA

The FMCSA motor carrier census is the Socrata dataset `az4n-8mr2` at `https://data.transportation.gov/resource/az4n-8mr2.json`, public, no key. The scraper walks it once per state of `FMCSA_STATES`, in the order written, with the filter `phy_state='<state>' AND status_code='<status>' AND power_units::number >= <n>` built from the settings (`power_units` is a text column at Socrata, hence the cast; observed). For each state it first asks the count, `$select=count(*)` with that `$where`, which Socrata answers as a one-element array whose `count` is a string of digits (observed), and then the pages: `$where`, `$order=dot_number`, `$limit=10000`, `$offset` 0, 10000, 20000 and so on, until a page answers fewer than 10,000 records; a page past the end answers `[]` (observed). Socrata answers a page as a JSON array of flat objects of strings, a field the record lacks being absent (observed). The count is read and checked as the probe reads it, but does not bound the walk: a short page does, so a record added between the count and the pages is still scraped. A Socrata `$order` on `dot_number` is numeric (the column's type is `number`, observed), so the pages are stable across the walk unless the dataset changes under it; a record a shift answers twice is kept once by the store, and one it skips shows as `gone` (decision log D5).

Every request carries `User-Agent` naming the service and its description, `scrapes (<description>)`, the description being the manifest's (decision log D2). A request that meets a network error, a timeout, 429 or a 5xx is tried again, up to three more times, after pauses of 1, 2 and 4 seconds on `Process.Sleep`, as the probe's `http.py` does; any other status, and an answer that cannot be read, fails at once. Each attempt is bounded by 60 seconds, the whole exchange, body included (decision log D2): a page of 10,000 records is about 25 MB.

A record becomes a row as the probe's `to_observation` makes it (decision 5): `source_id` is `dot_number`; `names` are `legal_name` then `dba_name`; the address is `phy_street`, `phy_city`, `phy_state`, `phy_zip` and `phy_cnty` (a county code, kept as spelled); there is no point; `company_officer_1` and `company_officer_2` are people with the role `company officer`. The facts carry the probe's keys, each the source's string as received or null when the record has none (decision log D5: no typing or coercion; "five or more power units" is a reading of the string): `dot_number`, `status`, `operation`, `class`, `org_type`, `power_units`, `truck_units`, `total_drivers`, `total_cdl`, `mileage`, `mileage_year`, `owned_trucks`, `owned_tractors`, `owned_trailers`, `hazmat`, `phone`, `email`, `added`, `mcs150_date` and `safety_rating`; and `cargo`, the names of the `crgo_` columns the record marks `X` or `Y`, without the prefix, sorted in ascending byte order. A `crgo_` column with another value, such as `crgo_cargoothr_desc`'s free text, is not cargo (observed).

## PPP

The SBA's Paycheck Protection Program release is a snapshot, not an API: CSV files at fixed URLs under `https://data.sba.gov/sites/default/files/distribution/SBA-OCA-2022-07-001/`, public, no key; `public_150k_plus_240930.csv` is answered 200 as `text/csv` of 452,077,279 bytes, and a name the folder does not hold is answered 404 (observed). The scraper takes the file names of `PPP_FILES` and walks them in the order written, one streaming `GET` per file to the base URL followed by the name, with the same `User-Agent` as FMCSA's. It never holds a file: the body goes through a CSV reader as it arrives, and the rows in scope are handed over a thousand at a time, each batch stored before more of the body is read, and once more at the end of each file for the rest (decision 3); a thousand rows is about 2.5 MB.

The file is CSV with a header row of 53 columns, `LoanNumber` first and `ForgivenessDate` last, every line ended CRLF, the file ending with one, and a field holding a comma quoted (all observed by ranged requests to the first 4,096 and the last 200 bytes). The CSV reader is `encoding/csv`'s with its defaults, so CRLF ends a line, a quoted field is one field and a record whose field count differs from the header's cannot be parsed. A header that is not exactly the 53 columns in order fails the run `source` before any row of that file is stored, so a re-shaped release is noticed, not mis-read (decision 3). The file is not UTF-8: its high bytes are `0xBF` and `0xA0`, mojibake the SBA shipped. Each byte is decoded as the Latin-1 code point of the same value, by hand, with no new dependency (decision 4).

A record is in scope when its state, `BorrowerState` or `ProjectState` when that is empty, upper-cased, is one of `PPP_STATES`. That is the source's query scope expressed on a file that has no query, and the only narrowing (decision 2): nonprofits, franchises, sole proprietors and one-job loans are all rows. The test is made on the record's own fields, so a record in scope whose `LoanNumber` is empty is seen, and fails the run.

A record becomes a row as the probe's `to_observation` makes it (decision 5): `source_id` is `LoanNumber`; `names` is `BorrowerName` alone; the address is `BorrowerAddress`, `BorrowerCity` or `ProjectCity` when blank, the state as above, `BorrowerZip` or `ProjectZip` when blank (cut to five by the envelope), and `ProjectCountyName`, a name such as `HENNEPIN`; no point; no people. The facts are 33 of the columns under the probe's keys plus the loan's status and forgiveness, each the decoded string as received, an empty cell the empty string; every column is present in every record, so no fact is null. `Race`, `Ethnicity`, `Gender` and `Veteran` are not facts; they stay in `raw`. `raw` is a JSON object of every column to its decoded string, in header order, and the digest is over those bytes as the scraper encodes them (decision 6).

The response headers are bounded by the 60-second rule and the retry rule applies to getting them: three retries, after 1, 2 and 4 seconds, on a network error, no headers in time, 429 or a 5xx; any other status fails at once. Once the headers have come, a fresh bound of 20 minutes governs reading the body; a full file took 20 seconds on the runner. A body that ends early (a read error, or a last record not ended by a line end), cannot be parsed, or outlives the bound fails the run `source`; nothing is resumed by byte range (Deferred). Each attempt of a file request is one `source.called`, as FMCSA's are, timed to its response headers.

## MN parcels

Minnesota's county parcel records are MnGeo's dataset "Parcels, Compiled from Opt-In Open Data Counties, Minnesota", served as an ArcGIS feature service at `https://enterprise.gisdata.mn.gov/aghost/rest/services/us_mn_state_mngeo/plan_parcels_open/FeatureServer/1/query`, public, no key, refreshed quarterly; 59 counties opt in, and Pine, Kanabec and Todd do not. The scraper walks it once per county of `MN_PARCELS_COUNTIES`, in the order written, with the clause `co_name='<county>'`, a quote in the name doubled, which the service reads as one quote inside the string (observed: `co_name='O''Brien'` answered a count of 0, `co_name='O'Brien'` an error body). For each county it first asks the count, `returnCountOnly=true`, which the service answers `{"count":n}` (observed), and then the pages, by keyset: each page's clause is the county's followed by ` AND objectid>N`, `N` being `-1` for the first page and afterwards the largest `objectid` the previous page held, with `outFields=*`, `returnGeometry=false`, `returnCentroid=true`, `outSR=4326`, `orderByFields=objectid`, `resultRecordCount=2000` and `f=json` and no `resultOffset`, until a page answers fewer than 2,000 features. Every feature's `attributes` carries `objectid`, a JSON integer, ascending across a page in that order (observed); a full page carries `"exceededTransferLimit":true` and a short one none, as under `resultOffset` (observed), and the walk reads neither. The service answers a page as a JSON object whose `features` is an array of objects, each an `attributes` object, compact, every field present and `null` when empty, then a `centroid` with `x` and `y` in WGS84 degrees; a county the dataset lacks answers a count of 0 and `"features":[]` (all observed). A keyset page answers in under a second however deep the county (observed: Anoka's 140,221 features in 71 pages, the slowest 0.9 s, 53 s in all, the features summing to its count), where a `resultOffset` page's cost grows with the offset (observed: Anoka's offset 138,000 took 4.3 s on a quiet afternoon, and the production host's deep pages 10 to 60 s, past which the service's gateway answered 502). A page is about 2.5 MB; the walk is about 444 requests, 13 counts and about 431 pages for the counties in scope, whose counts sum to about 842,300 features, and a run over them stores about 832,000 rows, since a repeated `state_pin` keeps one row (recorded decisions below).

Every request carries the same `User-Agent` as FMCSA's, which the service answered 200 (observed). The retry rule is FMCSA's classes with a longer schedule, five retries after 5, 10, 20, 40 and 80 seconds, and one addition: the service answers an error as status 200 with a body `{"error":{"code":…,"message":…}}` (observed), and such a body is retried as a 5xx is, failing the run `source` when the retries are spent. Each attempt is bounded by 180 seconds, the whole exchange, body included. Any other answer that is not of the shapes above fails the run at once. Each attempt is one `source.called`, as FMCSA's are.

A record becomes a row as the probe's `to_observation` makes it (decision 4): `source_id` is `state_pin`, or `co_code`, `-` and `county_pin` when `state_pin` is blank, and a record with neither, which the service sends routinely as a placeholder whose every other attribute is null (observed: Isanti's objectid 114728; 22 in the thirteen counties, 9,139 statewide), is skipped: it stores no row and is not counted, its page stays good and the walk goes on, while a page's 2,000 still counts it, since the service did; the owner is `owner_name` and `owner_more` joined by one space, the taxpayer `tax_name`; `names` is the owner then the taxpayer, so a Stearns record, which names nobody, has no name; `people` is the owner with the role `owner` and the taxpayer with the role `taxpayer`, the taxpayer only when it differs from the owner ignoring case; the street is the site address assembled from `anumberpre`, `anumber` (a number at the source), `anumbersuf`, `st_pre_dir`, `st_pre_typ`, `st_name`, `st_pos_typ` and `st_pos_dir`; the city is `ctu_name`, or `postcomm` when blank; the state is `MN`, the zip `zip` and the county `co_name`; `lat` and `lon` are the centroid's `y` and `x`. The facts carry the probe's keys (decision 5), each the JSON value the attribute holds, copied without coercion, so a number stays a number and a date stays the epoch milliseconds the service sends, with three lists assembled as `cargo` is: `owner_address`, `tax_address` and `use_class`. `raw` is the feature's `attributes` object, the bytes as the service sent them, nulls included, and the digest is over those bytes (decision 6).

## Form 5500

Every employer with a retirement or welfare plan files a Form 5500, or the short form 5500-SF for a small plan, with the Department of Labor each year, and the department publishes every filing as a zipped CSV per form and plan year at `https://askebsa.dol.gov/FOIA%20Files/<year>/Latest/F_5500_<year>_Latest.zip` and `F_5500_SF_<year>_Latest.zip`, public, no key; 2008 and earlier answer 404 (observed). The host answers 301 to `www.askebsa.dol.gov` with the same path, its `Location` carrying a literal space, and Go's client follows it, keeping the request's `User-Agent`, to a 200 of `application/x-zip-compressed` with a `Content-Length` (observed). Each zip holds exactly two entries, the CSV, `f_5500_<year>_latest.csv` or `f_5500_sf_<year>_latest.csv`, and a `_layout.txt` beside it (observed). The scraper takes the years of `FORM5500_YEARS` and walks them in the order written, for each year the Form 5500 file and then the 5500-SF file, fourteen files for the seven default years, with the same `User-Agent` as FMCSA's (the Form 5500 pass's decisions 2 and 3). One run walks every file, so a filing's `ACK_ID`, unique across files and years, is its stable `source_id`.

A zip does not stream: `archive/zip` needs random access to the central directory at its end. So each file's body is spooled to disk, into a file the run's build makes beside the run's temporaries, named for the run's id followed by `.` (`D04-store`), which the engine hands the scraper on the context of its walk (`source.SpoolFrom`); the archive is then opened, its one entry whose name ends `.csv` in any case is read through `encoding/csv` with its defaults, and the rows in scope are handed over a thousand at a time, once more at the end of each file for the rest. The spool file is removed once its entry has been read, and on every failure, before the next request, so the disk holds at most one zip (137 MB for the largest, the 2024 5500-SF) above the run itself, and memory one record and one batch (decision 4).

The CSV has a header row, every line ended CRLF, text fields quoted, numeric fields bare, and is pure ASCII (observed). Its header grows by appending: 135 columns for Form 5500 in 2019 and 2020, 136 in 2021 and 2022, 140 from 2023, and 183, 184 and 191 for the 5500-SF in the same years, each earlier header a prefix of the later; no header repeats a name (all observed). So columns are read by name, from an index the reader builds from the header, and a column count is no check (decision 5). The header must hold every column the facts read, `form5500.Columns`; a file whose header lacks one, or repeats a name, fails the run `source` before any row of it is stored, so a re-shaped release is noticed. A record whose field count differs from the header's cannot be parsed and fails the run, as PPP's would.

A record is in scope when its mailing state or its location state, upper-cased, is one of `FORM5500_STATES` (decision 2): multiemployer plans, direct filing entities, welfare plans, final filings and amendments are all rows. The two forms become one row shape, the scraper being the one place their layouts are reconciled (decision 6): `source_id` is `ACK_ID`; `names` is the sponsor's name then its DBA; the address is the location address when its state is not empty and the mailing address otherwise, its street the two address lines joined; no county, no point; `people` are the sponsor's signer and the administrator's signer, the second only when it differs from the first ignoring case. The facts are one fixed set of keys for both forms, each the column's string as received, the street keys joined as the street is, and a key the form lacks the empty string. `raw` is a JSON object of every column of that file's header to its string, in header order, so a 2019 Form 5500 row has 135 members and a 2024 5500-SF row 191, and the digest is over those bytes as the scraper encodes them, the PPP rule (decision 7).

The response headers are bounded by the 60-second rule and the retry rule applies to getting them: three retries, after 1, 2 and 4 seconds, on a network error, no headers in time, 429 or a 5xx; any other status fails at once. A fresh bound of 30 minutes governs each file from its headers to its last batch stored. A body that ends early, a zip that does not open, an archive without exactly one CSV entry, an entry that cannot be parsed or a file that outlives its bound fails the run `source`; nothing is resumed by byte range (Deferred). Each attempt of a file request is one `source.called`, its status the final answer's once the client has followed the redirect.

## OSHA ITA

Every establishment of 20 to 249 people in a high-hazard industry, and every one of 250 or more, sends OSHA its yearly Form 300A injury and illness summary through the Injury Tracking Application, and OSHA publishes the summaries as one file per data year, linked from `https://www.osha.gov/itadata`, public, no key. The names follow no pattern and the current year's file is refreshed through the year and will presumably be renamed and zipped when the year closes, so which files make a run is the setting `OSHA_ITA_FILES` (`D01-layout-and-run-seam`): paths under `https://www.osha.gov/sites/default/`, in the order walked, newest first, each beginning `files/` or `largefiles/`, the default being the ten data years 2025 back to 2016, the current year's bare CSV under `largefiles/` and nine zips under `files/`. A path is asked at the base URL followed by its `/`-separated segments, each path-escaped, a space as `%20`: every default path answers 200 with no redirect and `Accept-Ranges: bytes`, a zip as `application/zip` and the CSV as `text/csv`, while a literal space fails, a `+` answers 404 and a path under `files/largefiles/` answers 404 (observed). The zips are 12.1 MB (2016) to 24.1 MB (2023) and the CSV 88,383,913 bytes, and each downloaded in under 2 seconds (observed). A path ending `.zip`, in any case, is an archive whose one file whose name ends `.csv`, in any case, is the CSV; each zip holds exactly one such file today, named differently every year (`ITA 2021 data.csv`, `CY 2022.csv`), and no companion, which the Form 5500 lesson admits all the same (observed). Any other path's body is the CSV itself. One run walks every file, so a summary's `id`, which repeats in no two of the ten files (observed), is its stable `source_id`; a run over Minnesota and Wisconsin is about 180,700 rows.

The host answers 403 to Go's own agent, `Go-http-client/1.1`, and to the suite's, `scrapes (<description>)`, and 200 to a browser's (observed), so every request this scraper sends carries `oshaita.UserAgent`, a browser's agent string, and not the suite's: a departure the owner accepted for this source alone (recorded below).

Both shapes are spooled as Form 5500's zips are, into the build's spool on the walk's context (`source.SpoolFrom`): a zip because `archive/zip` needs its end, and a bare CSV because a file is read whole before any of its rows is handed, since the duplicate-id rule below cannot know which of two records is kept before the file's last line. The spool is read twice, once to check the file and pick the kept records, and once to hand the rows in scope a thousand at a time, once more at the end of each file for the rest. It is removed once the file's rows are handed, and on every failure, before the next request, so the disk holds at most one file (88 MB) above the run itself, and memory one record, one batch and the source ids in scope of one file (about 22,500).

The CSV has a header row, CRLF between records, a bare LF inside some quoted fields (2016 to 2020 and 2022), quotes inside quoted fields in every file, and every record the header's field count (observed); `encoding/csv`'s defaults read it. Its header has three shapes: 31 columns from 2016 to 2022; 32 from 2023, `naics_year` added and the order changed, differing again between the 2023 and 2024 files; and the current CSV's 32 with `created_timestamp` renamed `date_submitted` and `ID`, `establishment_ID` and `Change_reason` re-cased (observed). So columns are read by name without regard to case, from an index the reader builds from the header. The 2022 CSV alone begins with a UTF-8 byte-order mark (observed), dropped before the reader sees the bytes. The header must hold the eleven columns the row needs, `oshaita.Columns()`, and no name twice ignoring case; a file whose header does not fails the run `source` before any row of it is handed. Every other column the facts read is read when the header holds it and is the empty string when not, `naics_year` before 2023 among them.

Every file is valid UTF-8 but the 2018 one, a line of which holds one byte `0x92`, a Windows-1252 right single quote (observed). A run must not fail for an apostrophe, so a byte that does not begin a valid UTF-8 sequence is read as its Windows-1252 character, by hand, with no new dependency (`oshaita.Decode`), and valid UTF-8 is kept as it is.

A record is in scope when its `state`, upper-cased, is one of `OSHA_ITA_STATES`; nearly every state is `MN` or `WI` exactly, a few are `Wi` or `mn` (2020 to 2022) and none carries a space (observed). Nothing else narrows: government establishments, sites under 20, zero counts and every sector are rows. The 2019 file writes every numeric column with `.00` appended, the ids among them (observed), so `source_id` is `id` with a trailing `.00` removed, and the fact `establishment_id` likewise; every other value is kept as received. `names` is the company name then the establishment name, so a row whose company name is empty is named for its establishment and a site whose name differs carries both; the address is the establishment's `street_address`, `city`, `state` and `zip_code`; no county, no point, no people. The facts are sixteen strings: the two names, the EIN, the two ids, the filing year, the NAICS code with its vintage and description, the establishment type, the size code, the annual average employees, the hours worked, the whether-any-cases flag, the submission timestamp as received under the key `date_submitted`, from whichever of `created_timestamp` and `date_submitted` the header holds, and the change reason. The twelve injury and illness columns stay in `raw` only. `raw` and the digest follow the Form 5500 rule: every column of the header, under its name as received, in header order, `.00` and all.

Only the 2021 file repeats an `id`, an original and its amendment, 2,041 ids in all and 89 in Minnesota and Wisconsin (observed). Of the records in scope of one file that share a source id, the one handed is the one with the latest submission time, read in its three spellings, `1/2/2018 8:16:46` (2016 to 2020), `01JAN22:11:14:00` (2021) and `1/1/2023` (2022 on) (observed), by `oshaita.ParseSubmitted`; a tie, which 8 groups show (observed), or a stamp that is empty, as on 6 rows of 2017 and 4 of 2018 (observed), or that does not read, keeps the later line.

The response headers are bounded by the 60-second rule and the retry rule applies to getting them: three retries, after 1, 2 and 4 seconds, on a network error, no headers in time, 429 or a 5xx; any other status, a 403 or a 404 among them, fails at once. A fresh bound of 30 minutes governs each file from its headers to its last batch stored. A body that ends early, a zip that does not open, an archive without exactly one CSV file, a header without a required column or with a name twice, a record that cannot be parsed, a record in scope without an id, or a file that outlives its bound fails the run `source` with no row of that file handed; nothing is resumed by byte range. Each attempt of a file request is one `source.called`, its status the final answer's.

## The registry

The registry is fixed: `scrapers.Default` builds it with every scraper the service knows, `fmcsa`, `form5500`, `mn_parcels`, `osha_ita` and `ppp`, each configured from the run's settings, client, clock, pause and writer, and every one but `osha_ita` from the suite's `User-Agent`; `scrapers.Config` is unchanged, since the settings carry `PPP_FILES`, `PPP_STATES`, `MN_PARCELS_COUNTIES`, `FORM5500_YEARS`, `FORM5500_STATES`, `OSHA_ITA_FILES` and `OSHA_ITA_STATES` (`D01-layout-and-run-seam`). A test builds a registry of its own scrapers with `scrapers.New`.

## Recorded decisions

- **User-Agent** (decision log D2): `scrapes (Public records about businesses in range, scraped per source as rows per run)`, built as `pages.ServiceName + " (" + pages.Description + ")"` by `cli.Run` and handed to the registry, since the registry cannot import the pages; a request with it was answered 200 (observed).
- **Request timeout** (decision log D2): 60 seconds per attempt, the whole exchange; a 10,000-record page is about 25 MB, and a hung request still fails well inside a monthly run. It is applied by the scraper per attempt, not by the client, so a test can shorten it through `fmcsa.Config.Timeout` and the default client needs no bound of its own.
- **Retries** are the probe's: three after the first attempt, pauses of `2^i` seconds before retry `i+1`, on network errors, timeouts, 429 and 5xx; the probe's last pause before giving up is dropped, since nothing follows it. A body that cannot be read or decoded is not retried, as in the probe.
- **The count is kept** as the probe asks it: it costs one request per state and an unreadable count fails the run `source` before any row is stored. It does not end the walk.
- **The digest** is over the array element's bytes exactly as Socrata wrote them, without the separators between elements (decision log D5: no normalization before hashing). Socrata writes each element compact (observed), so the bytes are the record's own JSON.
- **Facts are strings as received** (decision log D5), with two departures from the probe: the probe made integers of the counts and a boolean of `hazmat`; here they stay the source's strings. `cargo` remains a list, since it is assembled from many columns; the decisions document names it as one fact. A fact the record lacks is null, so every row of a scraper carries the same keys.
- **Title case** is Python's `str.title()` as the probe used it, restated per letter: a letter after a letter is lower-cased, any other letter upper-cased, and every other character kept.
