# D05-scrapers

The scrapers: what every scraper shares (`internal/source`: the row envelope, its normalization, the digest, the `Scraper` interface and the name of `source.called`), the scrapers the registry holds (`internal/fmcsa`, the FMCSA motor carrier census on Socrata, `internal/ppp`, the SBA's Paycheck Protection Program loans in CSV files, and `internal/mnparcels`, Minnesota's compiled county parcels on an ArcGIS feature service), and the fixed registry that knows scrapers by name (`internal/scrapers`). A scraper is Go code ported from the funnel probe's Python module, not a configuration: it knows where its source is, how it pages or streams and how a record becomes a row (decision 2). Adding a source is adding a scraper to the registry; the run record, the envelope, the tools, the pages and the events hold every scraper without change. `D06-runs` starts a scraper and stores what it hands over; `D04-store` keeps the rows; `D01-layout-and-run-seam` supplies the HTTP client, the clock, the pause and the settings.

## The envelope

A **row** is one record from one source, filled by its scraper before it is stored; there is no ingest step that derives it later (decision 5). Its provenance is the `scraper`, the `run` (written by the store), the `source_id` (the source's own id for the record, unique within a run and stable across runs), `scraped` (when the record was taken from its source, UTC to the second) and `digest`, the lowercase hexadecimal SHA-256 of the raw record's bytes, exactly as the source sent them where the source sends each record as JSON (FMCSA, and for MN parcels the record's `attributes` object without its centroid) and as the scraper encodes them where it does not (PPP), so a record the source changed has another digest. Its common fields are the same for every scraper: `name`, the business as the source spells it; `names`, every name the record uses, `name` first, each trimmed, empties dropped, duplicates dropped; `address` with `street`, `city`, `state`, `zip` and `county`, each absent when the source gives none; `lat` and `lon` in WGS84 when the source gives a point; `people`, each a `name` and the `role` the source gives (an LLC is a party like any other); and `facts`, a flat JSON object of source-specific keys. Beside them is `raw`, the record as received, held as JSON: the source's own bytes for FMCSA, an object of the CSV's columns for PPP, the `attributes` object's own bytes for MN parcels.

Nothing a scraper does filters records: the source's query scope is the only narrowing, and every record the source answers inside it becomes a row (decision 2). The normalization is the probe's, the same for every scraper, so it lives in `internal/source`: names are trimmed and deduplicated; the street and the county are trimmed; the city is trimmed and title-cased; the state is trimmed and upper-cased; the zip is trimmed and cut to its first five characters; everything else is as spelled (decision 5).

The row's JSON is the shape the tools and the sibling read path answer (`D10-tools`, `D03-serve`): `source.Row` encodes itself, so that every consumer writes the same members in the same order, `raw` only when it is held; the sibling read path adds one member, `collected`, the same string as `scraped`, for siblings of the release before (`D03-serve`).

## A scraper

A scraper has a name and one operation, `Scrape`: walk the whole source, hand its rows to the function it is given in batches (FMCSA and MN parcels a page at a time, PPP a thousand rows at a time), in the order the source answered them, and return nil once the source is exhausted. A batch the function refuses ends the walk at once: the scraper sends no further request and returns an error. A source that cannot be read ends the walk with an error. A context that is done ends it promptly. Which of these ended a run is the engine's to tell (`D06-runs`): it knows when its own function refused, and when it cancelled.

Every request a scraper makes to its source is recorded in the trail as one `source.called`, carrying the scraper's name, the answer's status (0 when none came) and the time to the response headers, under the caller on the context; no query, no record, no name, address, phone or email travels (decision 13). `D09-trail` names it among the trail's events.

## FMCSA

The FMCSA motor carrier census is the Socrata dataset `az4n-8mr2` at `https://data.transportation.gov/resource/az4n-8mr2.json`, public, no key. The scraper walks it once per state of `FMCSA_STATES`, in the order written, with the filter `phy_state='<state>' AND status_code='<status>' AND power_units::number >= <n>` built from the settings (`power_units` is a text column at Socrata, hence the cast; observed). For each state it first asks the count, `$select=count(*)` with that `$where`, which Socrata answers as a one-element array whose `count` is a string of digits (observed), and then the pages: `$where`, `$order=dot_number`, `$limit=10000`, `$offset` 0, 10000, 20000 and so on, until a page answers fewer than 10,000 records; a page past the end answers `[]` (observed). Socrata answers a page as a JSON array of flat objects of strings, a field the record lacks being absent (observed). The count is read and checked as the probe reads it, but does not bound the walk: a short page does, so a record added between the count and the pages is still scraped. A Socrata `$order` on `dot_number` is numeric (the column's type is `number`, observed), so the pages are stable across the walk unless the dataset changes under it; a record a shift answers twice is kept once by the store, and one it skips shows as `gone` (decision log D5).

Every request carries `User-Agent` naming the service and its description, `scrapes (<description>)`, the description being the manifest's (decision log D2). A request that meets a network error, a timeout, 429 or a 5xx is tried again, up to three more times, after pauses of 1, 2 and 4 seconds on `Process.Sleep`, as the probe's `http.py` does; any other status, and an answer that cannot be read, fails at once. Each attempt is bounded by 60 seconds, the whole exchange, body included (decision log D2): a page of 10,000 records is about 25 MB.

A record becomes a row as the probe's `to_observation` makes it (decision 5): `source_id` is `dot_number`; `names` are `legal_name` then `dba_name`; the address is `phy_street`, `phy_city`, `phy_state`, `phy_zip` and `phy_cnty` (a county code, kept as spelled); there is no point; `company_officer_1` and `company_officer_2` are people with the role `company officer`. The facts carry the probe's keys, each the source's string as received or null when the record has none (decision log D5: no typing or coercion; "five or more power units" is a reading of the string): `dot_number`, `status`, `operation`, `class`, `org_type`, `power_units`, `truck_units`, `total_drivers`, `total_cdl`, `mileage`, `mileage_year`, `owned_trucks`, `owned_tractors`, `owned_trailers`, `hazmat`, `phone`, `email`, `added`, `mcs150_date` and `safety_rating`; and `cargo`, the names of the `crgo_` columns the record marks `X` or `Y`, without the prefix, sorted in ascending byte order. A `crgo_` column with another value, such as `crgo_cargoothr_desc`'s free text, is not cargo (observed).

## PPP

The SBA's Paycheck Protection Program release is a snapshot, not an API: CSV files at fixed URLs under `https://data.sba.gov/sites/default/files/distribution/SBA-OCA-2022-07-001/`, public, no key; `public_150k_plus_240930.csv` is answered 200 as `text/csv` of 452,077,279 bytes, and a name the folder does not hold is answered 404 (observed). The scraper takes the file names of `PPP_FILES` and walks them in the order written, one streaming `GET` per file to the base URL followed by the name, with the same `User-Agent` as FMCSA's. It never holds a file: the body goes through a CSV reader as it arrives, and the rows in scope are handed over a thousand at a time, each batch stored before more of the body is read, and once more at the end of each file for the rest (decision 3); a thousand rows is about 2.5 MB.

The file is CSV with a header row of 53 columns, `LoanNumber` first and `ForgivenessDate` last, every line ended CRLF, the file ending with one, and a field holding a comma quoted (all observed by ranged requests to the first 4,096 and the last 200 bytes). The CSV reader is `encoding/csv`'s with its defaults, so CRLF ends a line, a quoted field is one field and a record whose field count differs from the header's cannot be parsed. A header that is not exactly the 53 columns in order fails the run `source` before any row of that file is stored, so a re-shaped release is noticed, not mis-read (decision 3). The file is not UTF-8: its high bytes are `0xBF` and `0xA0`, mojibake the SBA shipped. Each byte is decoded as the Latin-1 code point of the same value, by hand, with no new dependency (decision 4).

A record is in scope when its state, `BorrowerState` or `ProjectState` when that is empty, upper-cased, is one of `PPP_STATES`. That is the source's query scope expressed on a file that has no query, and the only narrowing (decision 2): nonprofits, franchises, sole proprietors and one-job loans are all rows. The test is made on the record's own fields, so a record in scope whose `LoanNumber` is empty is seen, and fails the run.

A record becomes a row as the probe's `to_observation` makes it (decision 5): `source_id` is `LoanNumber`; `names` is `BorrowerName` alone; the address is `BorrowerAddress`, `BorrowerCity` or `ProjectCity` when blank, the state as above, `BorrowerZip` or `ProjectZip` when blank (cut to five by the envelope), and `ProjectCountyName`, a name such as `HENNEPIN`; no point; no people. The facts are 33 of the columns under the probe's keys plus the loan's status and forgiveness, each the decoded string as received, an empty cell the empty string; every column is present in every record, so no fact is null. `Race`, `Ethnicity`, `Gender` and `Veteran` are not facts; they stay in `raw`. `raw` is a JSON object of every column to its decoded string, in header order, and the digest is over those bytes as the scraper encodes them (decision 6).

The response headers are bounded by the 60-second rule and the retry rule applies to getting them: three retries, after 1, 2 and 4 seconds, on a network error, no headers in time, 429 or a 5xx; any other status fails at once. Once the headers have come, a fresh bound of 20 minutes governs reading the body; a full file took 20 seconds on the runner. A body that ends early (a read error, or a last record not ended by a line end), cannot be parsed, or outlives the bound fails the run `source`; nothing is resumed by byte range (Deferred). Each attempt of a file request is one `source.called`, as FMCSA's are, timed to its response headers.

## MN parcels

Minnesota's county parcel records are MnGeo's dataset "Parcels, Compiled from Opt-In Open Data Counties, Minnesota", served as an ArcGIS feature service at `https://enterprise.gisdata.mn.gov/aghost/rest/services/us_mn_state_mngeo/plan_parcels_open/FeatureServer/1/query`, public, no key, refreshed quarterly; 59 counties opt in, and Pine, Kanabec and Todd do not. The scraper walks it once per county of `MN_PARCELS_COUNTIES`, in the order written, with the clause `co_name='<county>'`, a quote in the name doubled, which the service reads as one quote inside the string (observed: `co_name='O''Brien'` answered a count of 0, `co_name='O'Brien'` an error body). For each county it first asks the count, `returnCountOnly=true`, which the service answers `{"count":n}` (observed), and then the pages, by keyset: each page's clause is the county's followed by ` AND objectid>N`, `N` being `-1` for the first page and afterwards the largest `objectid` the previous page held, with `outFields=*`, `returnGeometry=false`, `returnCentroid=true`, `outSR=4326`, `orderByFields=objectid`, `resultRecordCount=2000` and `f=json` and no `resultOffset`, until a page answers fewer than 2,000 features. Every feature's `attributes` carries `objectid`, a JSON integer, ascending across a page in that order (observed); a full page carries `"exceededTransferLimit":true` and a short one none, as under `resultOffset` (observed), and the walk reads neither. The service answers a page as a JSON object whose `features` is an array of objects, each an `attributes` object, compact, every field present and `null` when empty, then a `centroid` with `x` and `y` in WGS84 degrees; a county the dataset lacks answers a count of 0 and `"features":[]` (all observed). A keyset page answers in under a second however deep the county (observed: Anoka's 140,221 features in 71 pages, the slowest 0.9 s, 53 s in all, the features summing to its count), where a `resultOffset` page's cost grows with the offset (observed: Anoka's offset 138,000 took 4.3 s on a quiet afternoon, and the production host's deep pages 10 to 60 s, past which the service's gateway answered 502). A page is about 2.5 MB; the walk is about 444 requests, 13 counts and about 431 pages for the counties in scope, whose counts sum to about 842,300 features, and a run over them stores about 832,000 rows, since a repeated `state_pin` keeps one row (recorded decisions below).

Every request carries the same `User-Agent` as FMCSA's, which the service answered 200 (observed). The retry rule is FMCSA's classes with a longer schedule, five retries after 5, 10, 20, 40 and 80 seconds, and one addition: the service answers an error as status 200 with a body `{"error":{"code":…,"message":…}}` (observed), and such a body is retried as a 5xx is, failing the run `source` when the retries are spent. Each attempt is bounded by 180 seconds, the whole exchange, body included. Any other answer that is not of the shapes above fails the run at once. Each attempt is one `source.called`, as FMCSA's are.

A record becomes a row as the probe's `to_observation` makes it (decision 4): `source_id` is `state_pin`, or `co_code`, `-` and `county_pin` when `state_pin` is blank, and a record with neither, which the service sends routinely as a placeholder whose every other attribute is null (observed: Isanti's objectid 114728; 22 in the thirteen counties, 9,139 statewide), is skipped: it stores no row and is not counted, its page stays good and the walk goes on, while a page's 2,000 still counts it, since the service did; the owner is `owner_name` and `owner_more` joined by one space, the taxpayer `tax_name`; `names` is the owner then the taxpayer, so a Stearns record, which names nobody, has no name; `people` is the owner with the role `owner` and the taxpayer with the role `taxpayer`, the taxpayer only when it differs from the owner ignoring case; the street is the site address assembled from `anumberpre`, `anumber` (a number at the source), `anumbersuf`, `st_pre_dir`, `st_pre_typ`, `st_name`, `st_pos_typ` and `st_pos_dir`; the city is `ctu_name`, or `postcomm` when blank; the state is `MN`, the zip `zip` and the county `co_name`; `lat` and `lon` are the centroid's `y` and `x`. The facts carry the probe's keys (decision 5), each the JSON value the attribute holds, copied without coercion, so a number stays a number and a date stays the epoch milliseconds the service sends, with three lists assembled as `cargo` is: `owner_address`, `tax_address` and `use_class`. `raw` is the feature's `attributes` object, the bytes as the service sent them, nulls included, and the digest is over those bytes (decision 6).

## The registry

The registry is fixed: `scrapers.Default` builds it with every scraper the service knows, `fmcsa`, `mn_parcels` and `ppp`, each configured from the run's settings, client, clock, pause and writer; `scrapers.Config` is unchanged, since the settings carry `PPP_FILES`, `PPP_STATES` and `MN_PARCELS_COUNTIES` (`D01-layout-and-run-seam`). A test builds a registry of its own scrapers with `scrapers.New`.

## Recorded decisions

- **User-Agent** (decision log D2): `scrapes (Public records about businesses in range, scraped per source as rows per run)`, built as `pages.ServiceName + " (" + pages.Description + ")"` by `cli.Run` and handed to the registry, since the registry cannot import the pages; a request with it was answered 200 (observed).
- **Request timeout** (decision log D2): 60 seconds per attempt, the whole exchange; a 10,000-record page is about 25 MB, and a hung request still fails well inside a monthly run. It is applied by the scraper per attempt, not by the client, so a test can shorten it through `fmcsa.Config.Timeout` and the default client needs no bound of its own.
- **Retries** are the probe's: three after the first attempt, pauses of `2^i` seconds before retry `i+1`, on network errors, timeouts, 429 and 5xx; the probe's last pause before giving up is dropped, since nothing follows it. A body that cannot be read or decoded is not retried, as in the probe.
- **The count is kept** as the probe asks it: it costs one request per state and an unreadable count fails the run `source` before any row is stored. It does not end the walk.
- **The digest** is over the array element's bytes exactly as Socrata wrote them, without the separators between elements (decision log D5: no normalization before hashing). Socrata writes each element compact (observed), so the bytes are the record's own JSON.
- **Facts are strings as received** (decision log D5), with two departures from the probe: the probe made integers of the counts and a boolean of `hazmat`; here they stay the source's strings. `cargo` remains a list, since it is assembled from many columns; the decisions document names it as one fact. A fact the record lacks is null, so every row of a scraper carries the same keys.
- **Title case** is Python's `str.title()` as the probe used it, restated per letter: a letter after a letter is lower-cased, any other letter upper-cased, and every other character kept.
- `internal/source`, `internal/fmcsa`, `internal/ppp`, `internal/mnparcels` and `internal/scrapers` are five packages because the registry names each scraper and each scraper builds the envelope (`D01-layout-and-run-seam`).
- `fmcsa.Where` and `fmcsa.RowOf` are exported so the query and the mapping are proved directly; `Scrape` is proved against a loopback fake through `fmcsa.Config.BaseURL`.
- **PPP scope is the record's state** (decision 2): `BorrowerState`, or `ProjectState` when `BorrowerState` is empty, upper-cased and not trimmed, as the probe's `or` and `.upper()` make it. The same empty-cell rule picks the city and the zip. The test is made on the decoded fields, not on the row, so a record `ppp.RowOf` refuses is still judged in or out of scope; a state with surrounding spaces is out of scope, though the envelope would trim it.
- **PPP is streamed, one request per file** (decision 3), in the order `PPP_FILES` is written, each file read to its end before the next is asked for. A batch holds rows of one file only, so the call at the end of a file hands only its remainder, and none when the remainder is empty.
- **PPP's bounds** (settled by the orchestrator, D1): a per-attempt deadline of `ppp.HeaderTimeout` until the response headers arrive, retried by the retry rule, and then a fresh `ppp.BodyTimeout` from their arrival governing the body's read and parse. Both are the scraper's on the `*http.Client` the seam hands it, not transport settings, and both can be shortened through `ppp.Config` so a test proves them without waiting out the real bounds. FMCSA's single bound over the whole exchange would cut a 452 MB body off at 60 seconds.
- **PPP's CSV reader is `encoding/csv`'s defaults**: a bare `"` in an unquoted field and a record whose field count differs from the header's cannot be parsed and fail the run `source`, as decision 3 has an unparsable body do. A body whose last byte is not a line feed fails too: `encoding/csv` accepts a last record with no line end, and a body cut inside its last record would otherwise be stored as a short record. A body cut exactly at a line end is caught only by the client's read error when the server sent a `Content-Length`, as data.sba.gov does (observed).
- **PPP's Latin-1 is a loop** (decision 4): each byte of a field becomes the rune of the same value; `0xBF` and `0xA0`, the only high bytes seen, mean the same in cp1252, and `0x80` to `0x9F`, where the two differ, were not seen. `golang.org/x/text` is not taken.
- **PPP's `raw` and digest depart from the FMCSA rule** (decision 6): `raw` is the scraper's own JSON encoding of the record, a fixed key order and `encoding/json`'s escaping of each string, and the digest is over those bytes, not over bytes the source sent, because a CSV parser does not hand back a record's own bytes and a re-quoted line is not what the source sent either. The encoding is deterministic, so a changed value is a changed digest and an unchanged record is `unchanged` across runs.
- **PPP's facts are strings as received** (decision 5), as FMCSA's are (decision log D5): the probe's float of the amounts, int of the jobs and boolean of `NonProfit` are dropped, and an empty cell is the empty string, never null.
- **A repeated `LoanNumber`** (decision 7) is not the scraper's to settle: it hands every in-scope record as a row, and the store's upsert on (run, `source_id`) keeps one, as it keeps an FMCSA record a page shift answered twice.
- **A PPP record out of scope is not inspected** beyond its state: one whose `LoanNumber` is empty is skipped like any other out of scope, while an in-scope one fails the run `source`, as an FMCSA element without `dot_number` does.
- `ppp.RowOf` and `ppp.Columns` are exported so the mapping, the raw encoding and the header are proved directly; `Scrape` is proved against a loopback fake through `ppp.Config.BaseURL`.
- `source.Row` has a `MarshalJSON` of its own, so `names` and `people` are always arrays, `facts` always an object, and `address`, `lat`, `lon` and `raw` follow the absent-when-none rule without every consumer re-deciding it.
- **MN parcels' count is asked but does not bound the walk** (settled by the orchestrator): each county's count request is sent first and follows the page's retry rule, failing the run `source` when the retries are spent, and an answer not of the count's shape fails it at once; a count that disagrees with the rows walked does not fail the run, since a quarterly dataset can change between the count and the pages, and a short page ends the county. The number is carried only by the ordinary `source.called` of its request, which records the status and not the body; no new event and no log line carries it.
- **MN parcels pages by keyset, not by offset** (settled by the orchestrator), a departure from the MN parcels decisions document's decision 3, which paged with `resultOffset`: the service's cost grows with the offset, the deep pages of the large counties took 10 to 60 seconds on the production host and its gateway answered 502 past about 60 seconds under load, failing the first real run, and the sandbox's cold run took 40 minutes. A page asks `objectid` above the largest the previous page held, ordered by `objectid`, and the first asks above `-1`, so every page has one shape and an `objectid` of 0 is not lost. The cursor is taken from every feature, a pinless one included, since the service counted it; a feature whose `objectid` is not a JSON integer, or not above the bound asked, makes the page unreadable and fails the run at once, since the next bound cannot be known or the walk would not advance. The end of a county is unchanged: a page of fewer than 2,000 features.
- **MN parcels retries five times, 5 seconds doubling** (settled by the orchestrator), a departure from the decisions document's existing retry rule, three retries after 1, 2 and 4 seconds: that schedule is spent in 7 seconds, inside one of the service's 502 spells, and the first real run failed on it. `mnparcels.Retries` is 5 and `mnparcels.Backoff` is 5 seconds, the first pause, doubled before each later retry, as FMCSA and PPP express theirs; the retry classes and the 180-second bound are unchanged, so a request given up costs at most six attempts and 155 seconds of pauses.
- **MN parcels' bound is one 180-second deadline per attempt** (settled by the orchestrator), over the whole exchange, body included, as FMCSA's single bound, not PPP's split: a page is bounded at 2,000 features, about 2.5 MB, and the service is slower than Socrata. `mnparcels.Config.Timeout` shortens it in a test.
- **An ArcGIS error body is retried** (settled by the orchestrator): a 200 whose body is a JSON object holding a member `error`, whatever its value, is treated as a 5xx would be, since the service reports its own failures that way (observed); a 200 whose body is neither that nor the expected shape fails at once, as an unreadable Socrata answer does. A clause the service rejects is answered the same way and so is retried too; the county check and the quote doubling keep the clause well-formed.
- **The county is quoted, the quote doubled**: `MN_PARCELS_COUNTIES` admits an apostrophe (decision 2), and a name holding one, spliced as written, would close the string and could add a clause of letters and spaces; `mnparcels.Where` doubles each `'` so the name stays one string literal, as the service reads it (observed).
- **MN parcels' facts are JSON values as received**, a departure from "facts are strings as received" (decision 5): the service types its attributes, and the FMCSA rule, "as received", keeps a number a number and a date the epoch-millisecond integer ArcGIS sends. Each is the member's own JSON value, as `json.Marshal` writes it, null when the attribute is null or absent, so every row carries the same keys. `owner_name` is the joined owner, null when empty, as the probe makes it; `tax_name` is the attribute as received, untrimmed, since decision 5 copies every value but the owner and the three lists without coercion. `owner_address`, `tax_address` and `use_class` are always lists, `[]` when nothing is left, as `cargo` is, where the probe wrote null for the two addresses; their lines are trimmed, as the probe trims them.
- **MN parcels' digest excludes the centroid** (decision 6), a departure from hashing the whole record: `raw` and the digest are the `attributes` object's bytes as the service sent them, nulls included, where the probe dropped nulls. The centroid is derived from the polygon and kept as `lat` and `lon`; a float that wobbles between quarters must not make an unchanged record `changed`.
- **A feature's point is optional**: a centroid absent, null, or not an object whose `x` and `y` are numbers gives a row with no `lat` and `lon` rather than failing the run, since the point is derived and a parcel without one is still a record; only a feature with no `attributes` object fails it, and one with no source id is skipped (below).
- **MN parcels' source id** is `state_pin` as received when it is not blank, and otherwise `co_code`, `-` and `county_pin` as received, the probe's fallback; the probe's `or` treats only an empty or null `state_pin` as missing, and blank here also covers one of spaces. A blank `co_code` beside a `county_pin` still makes an id, `-` and the pin, as the probe's f-string would.
- **MN parcels skips a record with no pin** (settled by the orchestrator), a departure from decision 4, which made a record with neither `state_pin` nor `county_pin` fail the run `source`: such records are routine placeholders, so a fatal rule means no run can ever finish. `objectid` was rejected as a fallback id because it is not stable across the quarterly refresh. `mnparcels.RowOf` still refuses such a feature, so the refusal is proved on its own, and the walk leaves out the features it refuses for that reason alone; any other refusal still fails the run at once. No event, no `source.called` attribute and no log line marks a skipped record.
- **MN parcels keeps one row per source id** (settled by the orchestrator): the source repeats a `state_pin` for a multi-polygon parcel, one feature per polygon, the attributes identical apart from `objectid`, the shape sizes and the centroid, with `plat_name` differing in a handful of cases (observed), and some counties carry a few hundred placeholder features whose `state_pin` is just the county code and a hyphen, every other attribute null (observed). A run keeps the last record the walk meets for each source id, as the store's uniqueness on run and source id already does, so a run over the thirteen default counties stores about 832,000 rows, about 10,000 fewer than the service's count. Suffixing the duplicates to keep every polygon was rejected: the id would be unstable across the quarterly refresh, and a parcel is one thing to the funnel. Treating a pin with nothing after the county code as blank, which would skip the placeholders, is deferred.
- **The street takes a number as its text**: `anumber` is an integer at the source (observed), and the probe's `str()` of it is its decimal digits, which are its JSON bytes. Each part is trimmed and the empty ones dropped, so a part of spaces is dropped where the probe kept it.
- **The taxpayer is a person when it differs from the owner ignoring case**, compared with `strings.ToLower`, as the probe's `.lower()`; with no owner the taxpayer alone is the one person.
- `mnparcels.Where` and `mnparcels.RowOf` are exported so the clause and the mapping are proved directly; `Scrape` is proved against a loopback fake through `mnparcels.Config.BaseURL`, the constant's override for tests, as FMCSA's.

## Consumer tasks

`cli.Run` builds `reg := scrapers.Default(scrapers.Config{HTTP: p.HTTP, Telemetry: w, Now: p.Now, Sleep: p.Sleep, UserAgent: pages.ServiceName + " (" + pages.Description + ")", Settings: s})`.
