# D05-scrapers

The scrapers: what every scraper shares (`internal/source`: the row envelope, its normalization, the digest, the `Scraper` interface and the name of `source.called`), the one scraper this pass registers (`internal/fmcsa`, the FMCSA motor carrier census on Socrata), and the fixed registry that knows scrapers by name (`internal/scrapers`). A scraper is Go code ported from the funnel probe's Python module, not a configuration: it knows where its source is, how it pages and how a record becomes a row (decision 2). Adding a source is adding a scraper to the registry; the run record, the envelope, the tools, the pages and the events hold every scraper without change. `D06-runs` starts a scraper and stores what it hands over; `D04-store` keeps the rows; `D01-layout-and-run-seam` supplies the HTTP client, the clock, the pause and the settings.

## The envelope

A **row** is one record from one source, filled by its scraper before it is stored; there is no ingest step that derives it later (decision 5). Its provenance is the `scraper`, the `run` (written by the store), the `source_id` (the source's own id for the record, unique within a run and stable across runs), `collected` (when the record was received, UTC to the second) and `digest`, the lowercase hexadecimal SHA-256 of the raw record's bytes exactly as the source sent them, so a record the source changed has another digest. Its common fields are the same for every scraper: `name`, the business as the source spells it; `names`, every name the record uses, `name` first, each trimmed, empties dropped, duplicates dropped; `address` with `street`, `city`, `state`, `zip` and `county`, each absent when the source gives none; `lat` and `lon` in WGS84 when the source gives a point; `people`, each a `name` and the `role` the source gives (an LLC is a party like any other); and `facts`, a flat JSON object of source-specific keys. Beside them is `raw`, the record exactly as received.

Nothing a scraper does filters records: the source's query scope is the only narrowing, and every record the source answers inside it becomes a row (decision 2). The normalization is the probe's, the same for every scraper, so it lives in `internal/source`: names are trimmed and deduplicated; the street and the county are trimmed; the city is trimmed and title-cased; the state is trimmed and upper-cased; the zip is trimmed and cut to its first five characters; everything else is as spelled (decision 5).

The row's JSON is the shape the tools and the sibling read path answer (`D10-tools`, `D03-serve`): `source.Row` encodes itself, so that every consumer writes the same members in the same order, `raw` only when it is held.

## A scraper

A scraper has a name and one operation, `Scrape`: walk the whole source, hand each page's rows to the function it is given as one batch, in the order the source answered them, and return nil once the source is exhausted. A batch the function refuses ends the walk at once: the scraper sends no further request and returns an error. A source that cannot be read ends the walk with an error. A context that is done ends it promptly. Which of these ended a run is the engine's to tell (`D06-runs`): it knows when its own function refused, and when it cancelled.

Every request a scraper makes to its source is recorded in the trail as one `source.called`, carrying the scraper's name, the answer's status (0 when none came) and the time to the response headers, under the caller on the context; no query, no record, no name, address, phone or email travels (decision 13). `D09-trail` names it among the trail's events.

## FMCSA

The FMCSA motor carrier census is the Socrata dataset `az4n-8mr2` at `https://data.transportation.gov/resource/az4n-8mr2.json`, public, no key. The scraper walks it once per state of `FMCSA_STATES`, in the order written, with the filter `phy_state='<state>' AND status_code='<status>' AND power_units::number >= <n>` built from the settings (`power_units` is a text column at Socrata, hence the cast; observed). For each state it first asks the count, `$select=count(*)` with that `$where`, which Socrata answers as a one-element array whose `count` is a string of digits (observed), and then the pages: `$where`, `$order=dot_number`, `$limit=10000`, `$offset` 0, 10000, 20000 and so on, until a page answers fewer than 10,000 records; a page past the end answers `[]` (observed). Socrata answers a page as a JSON array of flat objects of strings, a field the record lacks being absent (observed). The count is read and checked as the probe reads it, but does not bound the walk: a short page does, so a record added between the count and the pages is still collected. A Socrata `$order` on `dot_number` is numeric (the column's type is `number`, observed), so the pages are stable across the walk unless the dataset changes under it; a record a shift answers twice is kept once by the store, and one it skips shows as `gone` (decision log D5).

Every request carries `User-Agent` naming the service and its description, `scrapes (<description>)`, the description being the manifest's (decision log D2). A request that meets a network error, a timeout, 429 or a 5xx is tried again, up to three more times, after pauses of 1, 2 and 4 seconds on `Process.Sleep`, as the probe's `http.py` does; any other status, and an answer that cannot be read, fails at once. Each attempt is bounded by 60 seconds, the whole exchange, body included (decision log D2): a page of 10,000 records is about 25 MB.

A record becomes a row as the probe's `to_observation` makes it (decision 5): `source_id` is `dot_number`; `names` are `legal_name` then `dba_name`; the address is `phy_street`, `phy_city`, `phy_state`, `phy_zip` and `phy_cnty` (a county code, kept as spelled); there is no point; `company_officer_1` and `company_officer_2` are people with the role `company officer`. The facts carry the probe's keys, each the source's string as received or null when the record has none (decision log D5: no typing or coercion; "five or more power units" is a reading of the string): `dot_number`, `status`, `operation`, `class`, `org_type`, `power_units`, `truck_units`, `total_drivers`, `total_cdl`, `mileage`, `mileage_year`, `owned_trucks`, `owned_tractors`, `owned_trailers`, `hazmat`, `phone`, `email`, `added`, `mcs150_date` and `safety_rating`; and `cargo`, the names of the `crgo_` columns the record marks `X` or `Y`, without the prefix, sorted in ascending byte order. A `crgo_` column with another value, such as `crgo_cargoothr_desc`'s free text, is not cargo (observed).

## The registry

The registry is fixed: `scrapers.Default` builds it with every scraper the service knows, which in this pass is `fmcsa`, configured from the run's settings, client, clock, pause and writer. A test builds a registry of its own scrapers with `scrapers.New`.

## Recorded decisions

- **User-Agent** (decision log D2): `scrapes (Public records about businesses in range, collected per source as rows per run)`, built as `pages.ServiceName + " (" + pages.Description + ")"` by `cli.Run` and handed to the registry, since the registry cannot import the pages; a request with it was answered 200 (observed).
- **Request timeout** (decision log D2): 60 seconds per attempt, the whole exchange; a 10,000-record page is about 25 MB, and a hung request still fails well inside a monthly run. It is applied by the scraper per attempt, not by the client, so a test can shorten it through `fmcsa.Config.Timeout` and the default client needs no bound of its own.
- **Retries** are the probe's: three after the first attempt, pauses of `2^i` seconds before retry `i+1`, on network errors, timeouts, 429 and 5xx; the probe's last pause before giving up is dropped, since nothing follows it. A body that cannot be read or decoded is not retried, as in the probe.
- **The count is kept** as the probe asks it: it costs one request per state and an unreadable count fails the run `source` before any row is stored. It does not end the walk.
- **The digest** is over the array element's bytes exactly as Socrata wrote them, without the separators between elements (decision log D5: no normalization before hashing). Socrata writes each element compact (observed), so the bytes are the record's own JSON.
- **Facts are strings as received** (decision log D5), with two departures from the probe: the probe made integers of the counts and a boolean of `hazmat`; here they stay the source's strings. `cargo` remains a list, since it is assembled from many columns; the decisions document names it as one fact. A fact the record lacks is null, so every row of a scraper carries the same keys.
- **Title case** is Python's `str.title()` as the probe used it, restated per letter: a letter after a letter is lower-cased, any other letter upper-cased, and every other character kept.
- `internal/source`, `internal/fmcsa` and `internal/scrapers` are three packages because the registry names the FMCSA scraper and the FMCSA scraper builds the envelope (`D01-layout-and-run-seam`).
- `fmcsa.Where` and `fmcsa.RowOf` are exported so the query and the mapping are proved directly; `Scrape` is proved against a loopback fake through `fmcsa.Config.BaseURL`.
- `source.Row` has a `MarshalJSON` of its own, so `names` and `people` are always arrays, `facts` always an object, and `address`, `lat`, `lon` and `raw` follow the absent-when-none rule without every consumer re-deciding it.

## Consumer tasks

`cli.Run` builds `reg := scrapers.Default(scrapers.Config{HTTP: p.HTTP, Telemetry: w, Now: p.Now, Sleep: p.Sleep, UserAgent: pages.ServiceName + " (" + pages.Description + ")", Settings: s})`. The engine (`D06-runs`) calls `sc, ok := reg.Get(name)` and, in the background, `err := sc.Scrape(ctx, func(rows []source.Row) error { return st.PutRows(ctx, id, rows) })`; the tools and the landing page list `reg.Names()`. The tools and the sibling read path encode a `source.Row` with `json.Marshal`. A test of `internal/fmcsa` serves a fake Socrata with `httptest`, records each request's query, builds `fmcsa.New(fmcsa.Config{BaseURL: srv.URL, HTTP: srv.Client(), Telemetry: w, Now: clock, Sleep: sleep, UserAgent: "ua", States: []string{"MN", "WI"}, MinPowerUnits: 5, Status: "A", Timeout: 50 * time.Millisecond})`, calls `Scrape` with a function that collects the batches, and compares the requests, the batches, the `Sleep` calls and the captured `source.called` events; it calls `fmcsa.Where("MN", "A", 5)` and `fmcsa.RowOf(raw, t)` on records of its own. A test of the registry builds `scrapers.New(a, b)` from fakes and calls `Names` and `Get`.
