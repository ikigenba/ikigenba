# D08-assets

auth's pages take the platform's visual style and its service launcher from files auth does not author: the stylesheet every page links, the fonts that stylesheet loads, the launcher's script, the button-feedback script every page links, and the licences of the fonts and of the Tabler icons the style draws. They are the platform's shared web files, the same for every app, and they come from appkit's `page` package (`github.com/ikigenba/ikigenba/appkit/page`, `D01-layout-and-run-seam`), which embeds them and serves them through the handler `page.Static()` returns, under the prefix `page.StaticPrefix`, `/_appkit/`. This design is how auth mounts that handler and what a caller observes of it through auth.

auth carries no style file of its own any more. The style files its `assets/` directory once held, the `/assets/` route that served them and auth's own extension-to-`Content-Type` table are gone; a path under `/assets/` is now an ordinary path that does not exist, answered 404 by `D03-serve`'s routing like any other unknown path. `assets/` now holds auth's own page templates, which the root package embeds as `Assets` and the handlers draw into pages, never serve as files (`D01-layout-and-run-seam`); they link the stylesheet this design mounts and carry none of their own.

## Mounting ahead of everything auth keeps

The shared files are served by the `*Server` that `server.New` returns (`D03-serve`), which hands a request whose path begins with `/_appkit/` to the handler `page.Static()` returns, unchanged: that handler compares the request's whole `URL.Path` against `/_appkit/<name>` itself, so no prefix is stripped. `D03-serve` owns the routing that puts this prefix ahead of auth's own routes; this design states what that routing must guarantee.

auth is the platform's identity provider, so no identity gate stands in front of it, and a visitor drawing the sign-in page has no session yet. A request under `/_appkit/` therefore needs no credential and is answered the same whatever `Cookie` or `Authorization` it carries; no answer sets a cookie. Serving a shared file touches nothing auth keeps — the `*Server` never calls its store for such a request — so it changes no state and is answered the same when the store has failed. The bytes come from the binary, through appkit's embedded files; that auth opens no file of its own to answer is `D01-layout-and-run-seam`'s self-containment rule.

Delegation is one requirement: a request under `/_appkit/` gets exactly what appkit's handler gives it. The requirements after it state what auth fixes about that answer, as auth's own observable behaviour, so that auth's tests fail if a different appkit release stopped giving it. Each was observed by driving the published appkit module's static handler, `page.Static()`, with `httptest` for every served name and method, for matching and non-matching `If-None-Match` values with and without `If-Modified-Since`, for the missing paths listed below, and for the plain font names, the font names the served stylesheet carries, their caching, and the value `page.PreloadURL()` returns.

## What is served

Exactly nine paths name a file: `/_appkit/` followed by `theme.css`, `launcher.js`, `feedback.js`, `favicon.svg`, `OFL.txt` or `TABLER-LICENSE.txt`, and the three font paths, compared byte for byte. appkit serves each font only under a hashed name: the font file's stem (`InterVariable`, `InterVariable-Italic` or `JetBrainsMono`), a dot, 16 lowercase hex digits that change whenever the font's bytes do, and `.woff2`. auth names no hash. Its design finds the three **font names** where a browser does, in the `url("…")` references of the stylesheet it serves, and the upright Inter's font path is the value `page.PreloadURL()` returns, the path every auth page preloads (D05). The plain names, `/_appkit/InterVariable.woff2`, `/_appkit/InterVariable-Italic.woff2` and `/_appkit/JetBrainsMono.woff2`, are not served. That the hex digits follow from the font's bytes is appkit's property, not auth's, for the reason the next section gives for the tag. The path compared is the request's `URL.Path`, which `net/http` stores decoded. A plain `GET` of one — carrying none of `If-None-Match`, `If-Modified-Since`, `Range`, `If-Match`, `If-Unmodified-Since`, and `If-Range` — answers 200 with the file and a fixed `Content-Type` per file; a plain `HEAD` answers the same status and headers with no body. The body is the same bytes on every request to one binary, and no requirement says what the bytes are. Every other path under `/_appkit/` — the prefix itself, another name such as `banner.html`, a served name with a further `/` or segment, a served name in other letter case — answers 404, whatever the method; a method other than `GET` and `HEAD` on a served name answers 405 with `Allow: GET, HEAD`. The bodies and other headers of the 404 and the 405 are appkit's and are not fixed here: they are not HTML documents with the banner, and nothing under `/_appkit/` is.

## Revalidation

Every 200 and 304 for a served name carries one strong `ETag` and one `Cache-Control`. For every file but a font it reads `no-cache`, so a browser keeps its copy but asks each time; for a font it reads `public, max-age=31536000, immutable`, so a browser keeps the font a year without asking, since a changed font arrives under a new name. The tag's value is opaque; what is fixed is that it is a well-formed strong entity tag (RFC 9110 section 8.8.3) and that one binary gives one file the same tag every time. The other half of the relation, that different content yields a different tag, is appkit's property and not auth's: auth embeds no content of its own under `/_appkit/`, and R-55ES-LBDV hands every such request to `page.Static()`, so one auth binary only ever serves one content for each file and no auth test could observe two. No auth requirement fixes it. For a request carrying none of `Range`, `If-Match`, `If-Unmodified-Since`, and `If-Range`: one whose single `If-None-Match` line is `*`, or a comma-separated list of tags one of which, with any `W/` removed, is the file's tag, gets 304 with an empty body and the same tag, whatever `If-Modified-Since` says; a well-formed list that names at least one tag, none of them current, gets the 200 as if the field were absent, with the file's `Content-Type`, again whatever `If-Modified-Since` says. Several `If-None-Match` lines, a malformed list, `Range`, `Last-Modified`, `If-Match`, `If-Unmodified-Since`, `If-Range`, and `If-Modified-Since` without `If-None-Match` are not fixed here.

## No other origin

A page needs nothing from any other host: no font service and no third-party request of any kind. A page drawn from an asset template takes its markup and the references it carries from that template; the sign-in, cancelled, non-member, profile, token-created and rejected-create pages are written by `internal/server`, which has no template for them yet (D05, D07). What the stylesheet makes a browser fetch is decided by the URLs appkit's stylesheet carries, which is appkit's content; auth's design reads only the font names from it.

## REQUIREMENTS

- R-SBUI-WZQZ: auth's design defines an **appkit path** as a request path — the value of the request's `URL.Path` field, which `net/http` stores decoded — that begins with `/_appkit/`, the value of `page.StaticPrefix`; a **font name** as a text that ends with `.woff2`, holds no `"`, and occurs immediately after `url("` and immediately before `")` in the body with which the `*Server` answers a `GET` request for `/_appkit/theme.css` carrying none of the header fields `If-None-Match`, `If-Modified-Since`, `Range`, `If-Match`, `If-Unmodified-Since`, and `If-Range`; a **font path** as `/_appkit/` followed by a font name; and a **shared file path** as an appkit path that is exactly `/_appkit/` followed by one of `theme.css`, `launcher.js`, `feedback.js`, `favicon.svg`, `OFL.txt`, and `TABLER-LICENSE.txt`, or is exactly a font path, compared byte for byte and so case-sensitively; and every requirement in auth's design that names an appkit path, a font name, a font path, or a shared file path MUST denote that.
- R-SD2F-ARHO: There MUST be exactly three font names, which MUST be, in some order, `InterVariable.`, `InterVariable-Italic.`, and `JetBrainsMono.`, each followed by exactly 16 characters each of which is an ASCII digit or a lowercase letter `a` to `f`, then `.woff2`, and nothing more; and the font path whose font name begins with `InterVariable.` MUST be exactly the string `page.PreloadURL()` returns.
- R-55ES-LBDV: The `*Server` MUST answer every request whose path is an appkit path, whatever its method and other header fields, exactly as the `http.Handler` that `page.Static()` returns answers the same request: with the same status, the same set of header fields with the same values, and the same body.
