# D21-backup-access

How accounts gives each host short-lived credentials for its backups: host backups outcome 5 (/home/mgreenly/Documents/ikigenba-host-backups.md, with its log). On each poll, accounts answers temporary credentials limited to the prefixes of the host's own accounts and its own host prefix, which expire in about an hour and are replaced before then. They come from one backup role that accounts assumes with a restricting session policy. The host prefix is `hosts/<host>/<seq>/`, one level below outcome 5's `hosts/<host>/`, so a reused host name never shares an earlier host's key backup (plan pick 20). Outcomes 6 (nothing long-lived on a host) and 8 (no credential can remove a hidden version) apply as recorded below. This document owns package `internal/access`. On every desired-state answer, `D13-daemon-endpoints` calls `Issue` with the host's name, the host prefix the store put in the state's `backup` member (`D04-store`, `D11-protocol`'s `HostPrefix`) and the slugs that host is to back up. `Issue` answers one credential set for the host's own key backup and one per account, each obtained from STS `AssumeRole` on the backup role (`D01-layout-and-run-seam`'s `settings.Hosts.BackupRole`) with an inline session policy that names one prefix of the backups bucket (`settings.Hosts.BackupBucket`) and nothing else. The daemon uses them as given (`D14-accountsd`, `D15-machine`); it never holds a long-lived key and never builds a prefix.

## One set per prefix

A session policy can hold one prefix per statement, and AWS caps the plaintext of an inline session policy at 2,048 characters (STS API reference, AssumeRole, parameter `Policy`: "The plaintext that you use for both inline and managed session policies can't exceed 2,048 characters"; checked 2026-11-26). Fifty accounts' prefixes in one policy do not fit, and one set per account also keeps the accounts on one host apart: a set opens exactly one account's prefix, or the host's own. So a host with `n` accounts gets `n + 1` sets.

The policy grants `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` and `s3:AbortMultipartUpload` on the objects below the prefix, `s3:ListBucket` on the bucket only for listings whose `s3:prefix` begins with the prefix, and `s3:GetBucketLocation` on the bucket. It never grants `s3:DeleteObjectVersion`, so every delete a host makes leaves a hidden version that the bucket's lifecycle keeps for 35 days (outcome 8; the bucket policy denies version deletes as well, which is infra's). Its exact bytes are a requirement, because `D16-sandbox`'s memory cloud checks every request it serves against `Policy` byte for byte.

## How long the policy can be

The policy is a fixed text of 356 characters with the partition substituted three times, the bucket three times and the prefix twice, so its length is 356 + 3·P + 3·B + 2·X for a partition of P, a bucket of B and a prefix of X characters. The longest values that can reach it:

- A bucket is at most 63 characters (S3 User Guide, General purpose bucket naming rules: "Bucket names must be between 3 (min) and 63 (max) characters long"; checked 2026-11-26). `settings` bounds no domain, so 63 is the bound and not the derived name's length; a domain whose derived name is longer names no bucket that can exist.
- The longest partition name is `aws-us-gov`, 10 characters. The IAM User Guide's ARN reference (`reference-arns.html`, "ARN format", checked 2026-11-26) lists the supported partitions as `aws`, `aws-cn` and `aws-us-gov`. The S3 page above also names `aws-eusc` among the partitions of the bucket namespace, which is shorter too.
- An account prefix is `accounts/` + slug + `/`; a slug is at most 32 bytes (`D17-names-keys-sizes`, `valid.Slug`), so 9 + 32 + 1 = 42 characters.
- A host prefix is `hosts/` + host + `/` + seq + `/`. A host's `Seq` is a positive `int64` (`D04-store`), at most 9223372036854775807, 19 digits. Its name is `host` and the lowest free number of at least two digits, a number no larger than the count of hosts ever created and so no larger than the newest `Seq`; `valid` bounds no host name, so 4 + 19 = 23 bytes is the bound. The prefix is at most 6 + 23 + 1 + 19 + 1 = 50 characters.

So the longest account policy is 356 + 30 + 189 + 84 = 659 characters and the longest host policy 356 + 30 + 189 + 100 = 675 characters, both computed by printing the policy with those values and counting with `wc -c`. Both are well under `D05-cloud`'s `cloud.MaxPolicyBytes` (2,048), and a requirement states the bound for every input within those lengths. The plan's figures, 659 and 675, agree.

AWS also measures a session policy after packing it with the session's tags, and refuses with `PackedPolicyTooLarge` when the packed form makes the session token too large; the answer reports the share used as `PackedPolicySize`, deprecated for `SessionTokenUtilization` (same API reference, response elements and errors). The packing is AWS's own and cannot be computed locally, so no requirement states it. It is a finish-line check (`D09-on-a-space` lists those): the longest policy accounts sends must be accepted. With no session tags and a policy of at most 675 characters this is expected to pass, but it is not proven here.

## Issue

`Issue` learns accounts' own partition and account id from `cloud.STS.Identity` (the whole `GetCallerIdentity`; the partition is the second field of the caller's `Arn`) once, and keeps them after the first success, a success being a nil error with an `Arn` that names a partition (an answer without one is a failure, and the next `Issue` asks again), as `hostauth` keeps `Account` (`D12-host-identity`). An empty request, one with no host prefix and no account, asks STS nothing, `Identity` included: there is no set to issue, so it answers nothing issued and a nil error whatever `Identity` answered before, and it leaves the partition and account as they were, so the next request that names a set asks `Identity` exactly as if the empty one had not been made. An empty request still drops the cache entries no call has asked for in an hour (below), which needs only the clock. The role it assumes is `RoleARN(partition, account, hosts)`: the backup role in accounts' own account and partition.

For each entry it asks `AssumeRole` with the role, `SessionName(host, slug)` (`backup-<host>` for the host's set, `backup-<host>-<slug>` for an account's), the policy for the entry's prefix and `cloud.RoleSessionDuration` (one hour: AssumeRole's default duration, and the most a chained session may last, since accounts assumes the backup role with its own role's credentials; AssumeRole, `DurationSeconds`, as `D05-cloud` records). A session name starts with `backup-` and is at most 7 + 23 + 1 + 32 = 63 bytes, inside STS's 64; it is cut to 64 bytes all the same, and it never matches `^i-`, so no backup session can pass `D12-host-identity`'s verifier, which accepts only sessions named for an instance on the hosts' role.

**The cache.** `Issue` keeps one entry per (host, host prefix) and one per (host, slug), each the credentials STS answered and the time they were issued. An entry is reused while it was issued less than `ReissueAfter` ago and expires more than `ReissueAfter` from now; otherwise `Issue` asks STS again. The host's entry is keyed by its prefix too, so a later host reusing a name (with a new `Seq`) never receives an earlier host's set. An entry no `Issue` call has asked for in an hour is dropped by the next call, so the cache holds at most the live hosts times `valid.MaxAccountsPerHost` + 1 entries, plus what an hour of churn adds.

**Renewal.** The daemon gets a full answer at least every `protocol.LongPoll` (45 s), so a reissue reaches it within 45 s of becoming due: while STS answers, every set a daemon receives was issued at most `ReissueAfter` (15 min) ago and so has at least about 60 − 15 − 0.75 ≈ 44 minutes left. When a due reissue fails, the older set is answered while it is unexpired (below), so for as long as STS keeps failing a set can arrive with less left, down to none; the daemon then reports no credentials once it expires. A restic run longer than that fails when its credentials expire and is run again on the next pass (pick 17 of the plan, below).

**Partial failure.** A set STS does not issue, or does not issue in time, is answered zero, the answer goes out anyway, and the next answer tries again; the daemon reports `machine.NoCredentials` for that account (`D15-machine`). A cached set that is due for reissue but still unexpired is answered as cached when its reissue fails. `Issue` answers a non-nil error whenever some set is zero; `D13-daemon-endpoints` answers 200 with the sets as they are, zero ones included, so the sets are complete and usable either way.

**Time.** One `Issue` call takes at most `IssueBudget` (8 s) in total, with at most `IssueParallel` (8) `AssumeRole` calls in flight, well inside the daemon's `RequestTimeout` (`LongPoll` + 15 s, `D14-accountsd`). The budget is carried as one deadline, fixed when `Issue` begins and shared by the context of every STS call that `Issue` makes, so waves of calls cannot each take a fresh budget; and `Issue` returns when that context ends, without waiting for a call that ignores it. A test proves the budget without waiting eight seconds: it reads the deadline the fake STS receives, and it ends the caller's context to see `Issue` return with the blocked entries zero.

**Secrets.** The secret key and session token pass from STS to the answer and nowhere else: `access` has no writer, no logger and no store, and no error it returns carries either. `D08-trail` and `D13-daemon-endpoints` keep them out of the trail and the log; `D04-store` never sees them.

**Modes.** Only AWS mode and the sandbox build an `Access`: in AWS mode over the run's cloud, in the sandbox over the memory cloud (`D03-serve`, `D16-sandbox`). In mode none there is no `Access` and the answer's `backup` member carries no credentials; accounts serves no hosts there anyway.

## Bounded work

One `Issue` holds one host's sets, at most `valid.MaxAccountsPerHost` + 1, and at most `IssueParallel` STS answers in progress at a time, for at most `IssueBudget`. The cache holds one entry per (host, slug) and per (host, host prefix) asked for within the last hour; `Cached` exposes its size so a test sees the drop rule.

## Recorded decisions

- **One credential set per account plus one per host** (plan pick 2), forced by the 2,048-character session policy limit and isolating accounts from each other; reissued after 15 minutes (`ReissueAfter`).
- **One-hour credentials accepted** (plan pick 17): `cloud.RoleSessionDuration` is AssumeRole's default duration and the role-chaining maximum AWS documents (`D05-cloud`), so a restic run longer than about 44 minutes fails and is re-run on the next pass. That restic 0.20.0 reuses what an interrupted backup uploaded is not stated in its documents (`D15-machine` records it unproven); the finish line checks that the first account backup reaches healthy, and the delivery stops and reports if it does not.
- **Credentials issued at answer time and never stored** (outcome 6): nothing long-lived leaves accounts; a set lives in accounts' memory, in the daemon's memory and in root-only files on the host (`D15-machine`), and expires within the hour. The hosts' instance role keeps no bucket rights (infra's).
- **No `s3:DeleteObjectVersion`** (outcome 8): the policy grants plain deletes only, so a host's deletes leave hidden versions the lifecycle keeps.
- **Partition and account from `Identity`, cached after the first success** (precedent: `hostauth` caches `Account`, R-4YFX-6U51). `D12-host-identity` accepts only the `aws` partition for hosts' callers; the backup role's ARN takes whatever partition accounts runs in, because it is built from accounts' own caller, not a host's.
- **`Cached` added to the package's surface** (departure from the plan's list for `internal/access`, local to D21): it counts the entries held, each issued successfully and not yet dropped, whatever their age. The drop rule is otherwise invisible at `Issue`'s seam, since any entry unasked for an hour is also older than `ReissueAfter` and would be reissued anyway. No other document uses it.
- **The host's cache entry is keyed by its prefix as well as its name** (local refinement of the plan's "one per host"), so a reused host name never gets an earlier host's set.
- **A cached set still unexpired is answered when its due reissue fails** (local refinement): the plan answers a cached entry still valid as cached when the budget ends; a failed reissue is treated the same way.
- **An empty request asks STS nothing and succeeds** (settled for the issue `empty-backup-credential-request`): with no set to issue, a failed or unasked `Identity` has nothing to make zero, so the request answers the zero host set, no account entries and a nil error, and `R-61BB-CBMJ`'s success rule holds for it without exception.
- **An empty host prefix gets no set**: a policy over the empty prefix would open the whole bucket, so `Issue` asks STS for nothing and answers the host set zero.
- **The budget is a context deadline**, not an injected timer (local to D21): `Config` carries no `After`, and the test discipline forbids waiting eight seconds of real time, so the budget is stated as one deadline shared by the context of every STS call of one `Issue`, which a fake STS reads and compares across calls without waiting, together with `Issue` returning once that context ends, which a test proves by ending the caller's context.
- **No copy constant**: every error `Issue` answers wraps the cloud's own.

## Consumer usage

- accounts' start (`D03-serve`), AWS mode or sandbox: `acc := access.New(access.Config{STS: c, Hosts: hosts, Now: p.Now})`, with `c` the run's `cloud.Cloud` (the memory cloud in the sandbox, `hosts` then `settings.SandboxHosts`), handed to `daemonapi.Config.Access`. Mode none builds none.
- Every state answer (`D13-daemon-endpoints`): with `st` the state the store answered for host `host01` (`st.Backup.HostPrefix` is `hosts/host01/7/`) and `slugs` its `active` accounts plus any `st.Backup.Restore.Accounts` slugs, `hc, ac, err := acc.Issue(ctx, "host01", st.Backup.HostPrefix, slugs)`; then `st.Backup.Host = hc` and `st.Backup.Accounts = ac` (one `protocol.AccountCredentials` per slug, ascending, zero `Credentials` for any set not issued); whatever `err` is, the answer is sent 200 with those sets.
- The memory cloud (`D16-sandbox`) checks a request against `access.Policy(hosts.BackupBucket(), "aws", protocol.AccountPrefix("acme"))`, the bytes its own `AssumeRole` received, and `access.RoleARN("aws", account, hosts)`; `access.SessionName("host01", "acme")` is `backup-host01-acme`.
- A test: `f := &fakeSTS{...}`, `acc := access.New(access.Config{STS: f, Hosts: settings.Hosts{Domain: "example.test", InstanceProfile: "hosts-role"}, Now: clock.Now})`, `acc.Issue(ctx, "host01", protocol.HostPrefix("host01", 1), []string{"zeta", "acme"})`, then compares `f`'s recorded `cloud.RoleRequest`s, advances the clock past `access.ReissueAfter`, and reads `acc.Cached()`.
