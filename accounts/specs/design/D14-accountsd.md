# D14-accountsd

Outcomes cited as outcome N are those of /home/mgreenly/Documents/ikigenba-ssh-hosts.md; log entries are those of /home/mgreenly/Documents/ikigenba-ssh-hosts-decisions.md.

`accountsd` is the second binary of the accounts module (outcome 20), built from `cmd/accountsd` for linux/arm64 with every release (log D5) and served by accounts at `/accountsd` (D13). On a host it runs as root under `accountsd.service`, the unit infra's first-boot user data writes (log D7): `ExecStart=/usr/local/bin/accountsd`, `EnvironmentFile=/etc/accountsd.env` holding `ACCOUNTS_URL`, `Restart=always`, `RestartSec=5`. It takes no arguments. Run under the name `accountsd-session`, through the link D15's `Apply` makes at `/usr/local/libexec/accountsd-session`, the same binary is the PAM session helper that places a person's session in their slice: it calls `linux.Session` and nothing else (D15). This document owns `internal/daemon`, the loop and the process wiring, and `cmd/accountsd`, which only wires the real pieces in: `awshost.Open` (D05) for the presigner and the instance metadata, and `linux.New(linux.Real())` (D15) for the host.

## The cycle

The daemon pulls and is never pushed (outcome 21). One cycle:

1. **Fetch.** `GET <base>/accountsd/v1/state?after=<version>&digest=<own digest>` with a fresh identity header (`hostauth.Header`, D12). accounts answers at once when the host's version differs from `after` or its served digest differs from the daemon's, and otherwise holds the request until something changes or `protocol.LongPoll` passes (D13); either way the answer is the whole desired state. `after` is 0 when the daemon starts and then the version of the last state it fetched, so a restarted daemon always gets the state at once and applies it. Anything but a 200 carrying a well-formed state for a named host is a failed fetch: the daemon changes nothing, reports nothing, says why on stderr, and tries again after a pause that starts at `MinBackoff` and doubles to `MaxBackoff`. A host that cannot reach accounts therefore keeps the state it last applied, and sign-ins keep working (outcome 22).
2. **Update.** When the state names a daemon digest other than the daemon's own, it downloads `<base>/accountsd`, which needs no identity, and streams it into `Machine.InstallDaemon` (D15), which checks the ELF header, the size and the digest before renaming the file over `/usr/local/bin/accountsd`. On success `Run` returns, the process exits 0, and systemd starts the new binary five seconds later. A different digest is all it takes, newer or older, so a rollback of accounts rolls every daemon back the same way (outcome 23). A failed update is said on stderr and in the report's `error`, and the cycle goes on with the old binary; the next fetch then waits out the same backoff, since accounts answers at once while the digests differ.
3. **Apply.** `Machine.Apply` makes the host match the state (D15).
4. **Report.** `Machine.Inspect` gives the host's facts; the daemon adds `protocol`, `attempted` (the state's version), `applied` (the state's version when Apply succeeded, otherwise the last version it applied, 0 when none since it started), `error`, the instance's id, type and AMI from the instance metadata, and `daemon_version`, its own digest, and posts the report with a fresh identity header. A report that fails is said on stderr and not retried: the next cycle reports again.
5. The next fetch starts at once; the long poll is the pacing, so a quiet host reports about every `LongPoll` and accounts calls it silent after five minutes without one (D04).

A daemon restarted in the middle of an apply simply fetches and applies again: every step of `Apply` checks before it acts (outcome 22, finish line step 7).

**Identity headers are never repeated.** A presigned `GetCallerIdentity` URL is a function of the credentials, the signed headers and `X-Amz-Date`, which has one-second resolution (SigV4), so two headers made in the same second by the same host are byte-identical, and D12 refuses the second as a replay. A quiet cycle's report can follow its fetch within a second. So the daemon never makes two headers within one second of its clock: when its previous header was made in the current second it waits, through its injected `Sleep`, until the next one.

## The process

`Main` checks, in order, that there is no argument (exit 2), that `ACCOUNTS_URL` is an absolute `https` URL with a host and nothing after its path (exit 2), digests its own executable with `protocol.Digest` (exit 1 on failure), opens the presigner and metadata (exit 1 on failure), and then runs the loop until its context ends, on SIGTERM or SIGINT, when it exits 0. It exits 0 too after a self-update. Its HTTP client follows no redirect, so a sign-in page in front of accounts is a failed fetch rather than a document, and `Run` bounds each state fetch and report by `RequestTimeout`, which is `LongPoll` plus 15 seconds so a held poll always answers first, and each binary download by `DownloadTimeout` (5 minutes), since a download of up to `protocol.MaxBinaryBytes` needs more than a poll's minute on a slow path.

Every line it writes to stderr is one line beginning `accountsd: ` followed by a copy constant and, after `: `, the error's text with any line break turned into a space; journald keeps them with the unit.

## Recorded decisions

- **Daemon version is a digest** (`sha256:` and 64 lowercase hex digits) of the binary, computed by streaming the executable when the process starts, because `devctl build` passes no `-ldflags` and the binary cannot know its release; a digest also tells a rollback from an upgrade without ordering them. Departure from the suite's display-string version (plan section 8.12; sibling version: every app reports `version.Display()`).
- **Backoff 5 s to 1 min.** `MinBackoff` matches the unit's `RestartSec`; a minute bounds how long a host waits after accounts comes back, well inside the five minutes before it would be called silent.
- **The report is not retried.** The next cycle carries a fresher one within `LongPoll`.
- **Update failure keeps the cycle going** and reports it as the error, so the host keeps being reconciled by the old daemon and the page shows why it is not on the new one.
- **One-line diagnostics.** The suite's command-line convention puts detail after an empty line; a daemon's lines land in the journal one entry per line, so each diagnostic is one line with its detail after `: `. Departure recorded; sibling version: root AGENTS.md, Command-line conventions.
- **A root daemon under a system unit written by infra** (plan section 8.10): no sibling runs this way; the only extra-unit precedent is `turns`' user units. The unit is infra's (log D7), not this design's.
- **A second exec'ing test** (plan section 8.8), in `cmd/accountsd`, beside accounts' one in `cmd/accounts`: it builds the binary and runs it once with an argument, once with `ACCOUNTS_URL` unset, and once through a link named `accountsd-session` with no PAM variables, the three cases that end before anything reaches IMDS, AWS or systemd. Everything else `Main` does is proved in process with an injected `open` and machine.
- **A new daemon that cannot start cannot be rolled back by accounts.** Rollback reaches only a daemon that runs: a binary that exits at start or panics crash-loops under `Restart=always`, never fetches again, and only an operator over SSM can put a working binary back. The guards are before release: the exec'ing test, the arm64 build gate (plan section 9), and the sandbox, whose simulated hosts run this very `daemon.Run` loop (D16). Keeping the previous binary beside the new one was considered and left out: restoring it still needs an operator, who can as well fetch `/accountsd` from a rolled-back accounts. Accepted risk.
- **argv[0] dispatch for the session helper** (D15's pick): the name, not an argument, selects it, so `Main`'s no-argument rule stands for the daemon, and pam_exec runs the helper by its path with no argument to forge.
- **Headers one second apart.** Recorded above; the alternative, a nonce the verifier would have to send to STS, would change D12's signed-header contract.

## Consumer usage

`cmd/accountsd` is `os.Exit(daemon.Main(ctx, daemon.Process{Args: os.Args[1:], LookupEnv: os.LookupEnv, Stderr: os.Stderr, Executable: os.Executable}, awshost.Open, linux.New(linux.Real())))` under a context `signal.NotifyContext` ends on SIGTERM and SIGINT. The sandbox's simulated host (D16) calls `daemon.Run(ctx, daemon.Config{BaseURL: "http://" + binding, HTTP: inProcessClient, Presigner: cloud.Presigner(id), Metadata: cloud.Metadata(id), Machine: machine.NewMemory(...), Digest: served, Now: now, Sleep: sleep, Stderr: io.Discard})` and cancels `ctx` when the instance stops. A test serves a fake accounts with `httptest.NewServer`, hands `Run` a fake `cloud.Presigner`, a fake `cloud.Metadata`, a `machine.Memory`, a clock and a `Sleep` that advances it, and asserts what the fake server received and what `m.State()` holds.

### The loop

- R-6GZK-0IJW: `Run(ctx, cfg)` MUST return a non-nil error without making any request when `cfg.BaseURL` is not an absolute `http` or `https` URL with a host and no user information, query or fragment; the *binding* MUST be that URL's host with its port when it has one, lowercased.
- R-95C2-ZTFX: Each fetch MUST be one `GET` of `cfg.BaseURL` + `protocol.StatePath` with the query parameters `protocol.QueryAfter`, the decimal version of the last state `Run` fetched successfully (0 before the first), and `protocol.QueryDigest`, `cfg.Digest`; with the header `hostauth.HeaderName` set to the value `hostauth.Header(ctx, cfg.Presigner, binding)` returned for that request and `User-Agent` set to `UserAgent`; sent through `cfg.HTTP` under a context whose deadline is `RequestTimeout` after it starts.
- R-97RV-RCXB: A fetch MUST count as failed when the identity header cannot be made, the request fails, the status is not 200, or `protocol.DecodeState` (D11) returns an error for the response body, which `Run` MUST hand it as a stream and never read beyond what `DecodeState` reads.
- R-L1CI-Q6CF: After a failed fetch `Run` MUST call no method of `cfg.Machine`, post no report, write one diagnostic line with `DiagFetch` to `cfg.Stderr`, and call `cfg.Sleep` with `MinBackoff` doubled once per earlier consecutive failed fetch and capped at `MaxBackoff` before the next fetch; a successful fetch MUST reset that count, and after a successful cycle the next fetch MUST start without calling `cfg.Sleep` except as R-6T6J-U7YU and R-L3SB-HPTT require.
- R-L2KF-3Y34: When a fetched state's `daemon` member is non-empty and differs from `cfg.Digest`, `Run` MUST, before calling `Apply`, make one `GET` of `cfg.BaseURL` + `protocol.BinaryPath` with `User-Agent` set to `UserAgent` and no identity header, under a context whose deadline is `DownloadTimeout` after it starts, and, when it answers 200, call `cfg.Machine.InstallDaemon(ctx, body, daemon)` with the response body as a stream, never reading the body into memory itself; when that returns nil, `Run` MUST return nil without calling `Apply` or posting a report. This MUST hold for any differing digest, a digest the daemon reported earlier included.
- R-L3SB-HPTT: When that download does not answer 200, fails, or `InstallDaemon` returns an error, `Run` MUST write one diagnostic line with `DiagUpdate`, carry on with `Apply` and the report of this cycle, give the report's `error` the failure's text unless `Apply` failed, and call `cfg.Sleep` with the backoff of R-L1CI-Q6CF's sequence for consecutive failed updates before its next fetch; a cycle whose state names no other digest MUST reset that sequence.
- R-6PIU-OWQR: After each successful fetch that did not end in a self-update, `Run` MUST call `cfg.Machine.Apply(ctx, state)` once, then `cfg.Machine.Inspect(ctx, state)` once, then `cfg.Metadata.Instance(ctx)` once, then post one report; an `Apply` error MUST also be written as one diagnostic line with `DiagApply`.
- R-6QQR-2OHG: The report MUST be the facts `Inspect` returned (its zero value when `Inspect` failed) with `protocol` set to `protocol.Version`; `attempted` the state's version; `applied` the state's version when `Apply` returned nil and otherwise the version of the last state whose `Apply` returned nil in this `Run`, 0 when none; `error` empty when `Apply` returned nil and no update failed, and otherwise the error's text cut to at most `protocol.MaxErrorBytes` bytes without splitting a UTF-8 sequence; `instance_id`, `type` and `ami` the `InstanceID`, `Type` and `AMI` of `cfg.Metadata.Instance`'s answer, empty when it failed; and `daemon_version` `cfg.Digest`.
- R-98ZS-54O0: Each report MUST be one `POST` of `cfg.BaseURL` + `protocol.ReportPath` with `Content-Type: application/json`, the report's `Bounded()` value (D11) encoded as JSON as its body, the header `hostauth.HeaderName` set to a fresh `hostauth.Header` value, `User-Agent` set to `UserAgent`, under a `RequestTimeout` deadline; any answer but 204, or a failed request, MUST be written as one diagnostic line with `DiagReport` and MUST NOT be retried.
- R-6T6J-U7YU: `Run` MUST NOT call `hostauth.Header` twice within one UTC second of `cfg.Now`: when the previous call was in the second `cfg.Now` shows, it MUST first call `cfg.Sleep` with the time left until the next second, so no two identity headers it sends share an `X-Amz-Date`.
- R-6UEG-7ZPJ: When `ctx` is done, `Run` MUST return `ctx.Err()` without starting another request or `Machine` call, the in-flight request or call receiving the done context.
- R-6VMC-LRG8: Every line `Run` and `Main` write to their stderr MUST be one line ending in LF, beginning `accountsd: ` followed by the diagnostic's copy constant, then `: ` and the error's text with every CR and LF replaced by a space when there is an error.

### The process

- R-6WU8-ZJ6X: `Main` MUST, when `p.Args` is non-empty, write one diagnostic line with `DiagArguments` and return `ExitUsage`, calling neither `p.LookupEnv`, `p.Executable` nor `open`.
- R-6Y25-DAXM: `Main` MUST read `EnvURL` through `p.LookupEnv` and, when it is unset, empty, or not an absolute `https` URL with a host and no user information, query or fragment, write one diagnostic line with `DiagURL` and return `ExitUsage`, calling neither `p.Executable` nor `open`; otherwise the base URL MUST be that value with any trailing `/` removed.
- R-9A7O-IWEP: `Main` MUST then compute its digest with `protocol.Digest` (D11) over the file `p.Executable` names, and then call `open(ctx)`; when either fails it MUST write one diagnostic line with `DiagSetup` and the error and return `ExitFailed`.
- R-70HY-4UF0: `Main` MUST then call `Run` with `BaseURL` the base URL, `HTTP` a client from `NewClient`, the presigner and metadata `open` returned, `Machine` `m`, `Digest` its digest, `Now` `time.Now`, a `Sleep` that waits the duration or until its context is done, and `Stderr` `p.Stderr`, and MUST return `ExitSuccess` when `Run` returns nil or an error for which `errors.Is(err, context.Canceled)` holds, and `ExitFailed` otherwise.
- R-XWM7-5NUE: The `accountsd` binary built from `cmd/accountsd`, when the last element of its `argv[0]` (as `filepath.Base` gives it) is `linux.SessionName` (D15), MUST call `linux.Session(ctx, linux.Real(), os.Getenv, os.Getppid())` and nothing else of this module, ignoring its arguments, and exit 0 when that returns nil and 1 otherwise, writing at most one stderr line beginning `accountsd: `; under any other name it MUST call `daemon.Main` with `Args` its command-line arguments after the program name, `os.LookupEnv`, `os.Stderr`, `os.Executable`, `awshost.Open` (D05) and `linux.New(linux.Real())` (D15), under a context that ends on SIGTERM or SIGINT, and exit with the status `Main` returns; run under its own name with any argument, or with `ACCOUNTS_URL` absent from its environment, it MUST exit 2 with one stderr line beginning `accountsd: `, and run through a link named `accountsd-session` with neither `PAM_TYPE` nor `PAM_USER` set it MUST exit 0 having run nothing.
