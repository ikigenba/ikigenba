# D14-accountsd

Outcomes cited as outcome N are those of /home/mgreenly/Documents/ikigenba-ssh-hosts.md; log entries are those of /home/mgreenly/Documents/ikigenba-ssh-hosts-decisions.md. Outcomes cited as box outcome N are those of /home/mgreenly/Documents/ikigenba-self-service-accounts.md.

`accountsd` is the second binary of the accounts module (outcome 20), built from `cmd/accountsd` for linux/arm64 with every release (log D5) and served by accounts at `/accountsd` (D13). On a host it runs as root under `accountsd.service`, the unit infra's first-boot user data writes (log D7): `ExecStart=/usr/local/bin/accountsd`, `EnvironmentFile=/etc/accountsd.env` holding `ACCOUNTS_URL`, `Restart=always`, `RestartSec=5`. It takes no arguments. Run under the name `accountsd-session`, through the link D15's `Apply` makes at `/usr/local/libexec/accountsd-session`, the same binary is the PAM session helper that places a person's session in their slice: it calls `linux.Session` and nothing else (D15). Run under the name `accountsd-mcp`, through the link D15's `Apply` makes at `linux.MCPHelper`, it is the box's stdio MCP server (box outcome 16): it calls `boxmcp.Run` (D20) and nothing else. This document owns `internal/daemon`, the loop, the box socket and the process wiring, and `cmd/accountsd`, which only wires the real pieces in: `awshost.Open` (D05) for the presigner and the instance metadata, `linux.New(linux.Real())` (D15) for the host, and `boxmcp.SocketPath` (D20) for the box socket.

## The cycle

The daemon pulls and is never pushed (outcome 21). One cycle:

1. **Fetch.** `GET <base>/accountsd/v1/state?after=<version>&digest=<own digest>` with a fresh identity header (`hostauth.Header`, D12). accounts answers at once when the host's version differs from `after` or its served digest differs from the daemon's, and otherwise holds the request until something changes or `protocol.LongPoll` passes (D13); either way the answer is the whole desired state. `after` is 0 when the daemon starts and then the version of the last state it fetched, so a restarted daemon always gets the state at once and applies it. Anything but a 200 carrying a well-formed state for a named host is a failed fetch: the daemon changes nothing, reports nothing, says why on stderr, and tries again after a pause that starts at `MinBackoff` and doubles to `MaxBackoff`. A host that cannot reach accounts therefore keeps the state it last applied, and sign-ins keep working (outcome 22).
2. **Update.** When the state names a daemon digest other than the daemon's own, it downloads `<base>/accountsd`, which needs no identity, and streams it into `Machine.InstallDaemon` (D15), which checks the ELF header, the size and the digest before renaming the file over `/usr/local/bin/accountsd`. On success `Run` returns, the process exits 0, and systemd starts the new binary five seconds later. A different digest is all it takes, newer or older, so a rollback of accounts rolls every daemon back the same way (outcome 23). A failed update is said on stderr and in the report's `error`, and the cycle goes on with the old binary; the next fetch then waits out the same backoff, since accounts answers at once while the digests differ.
3. **Apply.** `Machine.Apply` makes the host match the state (D15).
4. **Report.** `Machine.Inspect` gives the host's facts; the daemon adds `protocol`, `attempted` (the state's version), `applied` (the state's version when Apply succeeded, otherwise the last version it applied, 0 when none since it started), `error`, the instance's id, type and AMI from the instance metadata, and `daemon_version`, its own digest, and posts the report with a fresh identity header. A report that fails is said on stderr and not retried: the next cycle reports again.
5. The next fetch starts at once; the long poll is the pacing, so a quiet host reports about every `LongPoll` and accounts calls it silent after five minutes without one (D04).

A daemon restarted in the middle of an apply simply fetches and applies again: every step of `Apply` checks before it acts (outcome 22, finish line step 7).

**Identity headers are never repeated.** A presigned `GetCallerIdentity` URL is a function of the credentials, the signed headers and `X-Amz-Date`, which has one-second resolution (SigV4), so two headers made in the same second by the same host are byte-identical, and D12 refuses the second as a replay. A quiet cycle's report can follow its fetch within a second, and forwards from the box socket (below) can come at any moment, several at once. So every header the daemon makes, for a fetch, a report or a forward, goes through one gate: one header at a time, and never two in one second of its clock. A caller whose turn comes in the second of the previous header waits, through the injected `Sleep`, until the next one. The gate holds only the making of the header, not the request it goes on, so a long poll accounts holds open never holds up a forward. A forward waiting for its turn stops the moment its connection's `BoxTimeout` passes or the daemon's context ends, even while a slow header call holds the gate, so a stuck presigner cannot pile up waiters. No order among waiters is promised; at most `MaxBoxConns` forwards and the loop's one request can be waiting at once, so about one forward a second gets through and the rest wait inside their `BoxTimeout` (sheet decision 4).

## The box socket

The box's tools reach accounts through the daemon (box outcomes 16 to 18). `accountsd-mcp`, the stdio server a person's `claude` starts (D20), holds no authority: for each `tools/list` or `tools/call` it opens one connection to the daemon's Unix socket, writes the JSON-RPC request line and LF, and reads one answer line, a `boxmcp.Answer` (D20), then the daemon closes the connection. The daemon learns who is asking from the kernel, not from anything the caller says: `SO_PEERCRED` "returns the credentials of the peer process connected to this socket", "those that were in effect at the time of the call to connect(2)" (unix(7)), and the coordinator proved on host03 that this is the SSH user's own uid, also when `claude` starts the binary as a child and under the person's slice.

`Run` serves the socket beside its loop when `Config.Box` is set, taking each connection's uid from `Config.PeerUID`; a nil `Box` serves nothing, so the loop runs exactly as before. Production `Main` sets them itself and nothing else can: with `Process.Socket` set (cmd/accountsd sets `boxmcp.SocketPath`, `/run/accountsd.sock`) it removes whatever non-directory a previous process left there, listens, sets the mode to `SocketMode` (0666) and hands `Run` the listener, `KernelUID` and `time.After`. A previous process's file has to go first because `bind` fails with `EADDRINUSE` when "the filesystem socket object already exists" (unix(7)); removing it is safe because only one `accountsd` runs under the unit, a self-update's old process has exited before systemd starts the new one, and `/run` is writable by root alone. Go's `net` package removes the file itself when a listener it created closes (`UnixListener.SetUnlinkOnClose`: "when the listener and the underlying socket file were created by a call to Listen or ListenUnix, then by default closing the listener will remove the socket file"), so a clean exit leaves nothing behind. Mode 0666 lets every user connect, since "connecting to a stream socket object requires write permission on that socket" (unix(7)); the file is root's because "the owner and group of the socket file are set according to the usual rules" (unix(7)) and the daemon runs as root. A socket that cannot be set up is said on stderr and the daemon runs without it: the box tools then answer that the daemon is not answering, and keys and users keep being reconciled.

Each connection, from the moment it is accepted, has `BoxTimeout` (15 s) to be answered; the stdio server waits up to `boxmcp.AnswerTimeout` (30 s), so a daemon that answers in time is never cut off. The daemon reads one line of at most `protocol.MaxBoxRequest` bytes and its LF, then judges it locally, without asking accounts:

- before any state has been fetched in this run, "cannot reach accounts" (`CannotReach`);
- uid 0, a uid `PeerUID` cannot tell, and any uid that is not an active user of an active account in the last state fetched, "not an active user" (`NotActiveUser`); accounts still checks authoritatively (box outcome 18);
- a line that is not a JSON-RPC 2.0 request with an `id` (a string or a number; one without is a notification, JSON-RPC 2.0 specification, section 4.1) for `tools/list` or `tools/call`, `CannotReach`: the stdio server never sends one, so only a misbehaving client sees it, and refusing it locally keeps such lines from spending the host's one header a second.

Anything else is forwarded: `POST <base>/accountsd/v1/box?uid=<uid>` with the identity header from the gate and the line, byte for byte, as its body (D11, D13). A 200 whose body is at most `protocol.MaxBoxAnswer` bytes and, any trailing LF removed, is exactly one JSON object with no surrounding whitespace and no CR or LF (the shape D11 and D13 promise and D20's client accepts) is relayed as the answer's `message`, byte for byte; a 403 becomes `NotActiveUser`; anything else, a 404 from an accounts that predates the path included (expand then contract), a 503 when accounts cannot verify the host right now, a failed request or the timeout, becomes `CannotReach` and one diagnostic line. The daemon writes every answer line with `boxmcp.WriteAnswer` (D20), which writes the message's bytes verbatim, rather than with `encoding/json`'s `Marshal`, which compacts a `json.RawMessage` and escapes `<`, `>` and `&`, so the relayed bytes would not be accounts' bytes; an answer `WriteAnswer` refuses (`boxmcp.ErrAnswer`) is `CannotReach`. The daemon reads nothing past the request's LF: the client keeps its end open while it waits for the answer.

At most `MaxBoxConns` (8) connections are open at once. One more is answered `CannotReach` at once and closed, so a busy host says "try again shortly" instead of leaving a client waiting in the backlog until it gives up. Each open connection holds at most `protocol.MaxBoxRequest` + 1 bytes of request and `protocol.MaxBoxAnswer` + 1 bytes of answer, so the socket's buffers never exceed 8 × (64 KiB + 1 MiB + 2 bytes), about 8.5 MiB, beyond fixed overhead; the state the daemon judges against is the one its loop already holds (`protocol.MaxStateBytes`).

When `Run` returns, it first closes the listener and lets no connection go unanswered: after a self-update, the forwards in flight finish (each within its `BoxTimeout`) and are relayed, and the new process re-creates the socket when systemd starts it; when its context is done, the forwards in flight end with it and are answered `CannotReach`.

The refusals are copy (sheet decision 7). `NotActiveUser` is to hold the words "your Linux user is not an active user of an account on this host"; `CannotReach` is to hold "the host cannot reach accounts right now; try again shortly". `DiagSocket` and `DiagForward` are diagnostics like the other `Diag` constants.

## The process

`Main` checks, in order, that there is no argument (exit 2), that `ACCOUNTS_URL` is an absolute `https` URL with a host and nothing after its path (exit 2), digests its own executable with `protocol.Digest` (exit 1 on failure), opens the presigner and metadata (exit 1 on failure), sets up the box socket when `Process.Socket` names one, and then runs the loop until its context ends, on SIGTERM or SIGINT, when it exits 0. It exits 0 too after a self-update. Its HTTP client follows no redirect, so a sign-in page in front of accounts is a failed fetch rather than a document, and `Run` bounds each state fetch and report by `RequestTimeout`, which is `LongPoll` plus 15 seconds so a held poll always answers first, and each binary download by `DownloadTimeout` (5 minutes), since a download of up to `protocol.MaxBinaryBytes` needs more than a poll's minute on a slow path.

Every line it writes to stderr is one line beginning `accountsd: ` followed by a copy constant and, after `: `, the error's text with any line break turned into a space; journald keeps them with the unit.

Under the name `accountsd-mcp` the binary is the stdio server and nothing else: stdout belongs to `boxmcp.Run`, since an MCP stdio server "MUST NOT write anything to its stdout that is not a valid MCP message" and "MAY write UTF-8 strings to its standard error" (MCP specification, Transports, stdio).

## Recorded decisions

- **Daemon version is a digest** (`sha256:` and 64 lowercase hex digits) of the binary, computed by streaming the executable when the process starts, because `devctl build` passes no `-ldflags` and the binary cannot know its release; a digest also tells a rollback from an upgrade without ordering them. Departure from the suite's display-string version (sibling version: every app reports `version.Display()`).
- **Backoff 5 s to 1 min.** `MinBackoff` matches the unit's `RestartSec`; a minute bounds how long a host waits after accounts comes back, well inside the five minutes before it would be called silent.
- **The report is not retried.** The next cycle carries a fresher one within `LongPoll`.
- **Update failure keeps the cycle going** and reports it as the error, so the host keeps being reconciled by the old daemon and the page shows why it is not on the new one.
- **One-line diagnostics.** The suite's command-line convention puts detail after an empty line; a daemon's lines land in the journal one entry per line, so each diagnostic is one line with its detail after `: `. Departure recorded; sibling version: root AGENTS.md, Command-line conventions.
- **A root daemon under a system unit written by infra**: no sibling runs this way; the only extra-unit precedent is `turns`' user units. The unit is infra's (log D7), not this design's.
- **What the exec'd cases cannot reach is guidance for the build.** R-BGR6-LSZ9 states only the selection by name and the exits the four exec'd cases of R-KKV0-8QID observe. The rest of `main` is written as follows and proved nowhere but the finish line, because no permitted test signals the child or makes a helper fail: the session helper calls `linux.Session(ctx, linux.Real(), os.Getenv, os.Getppid())`, ignores its arguments, and exits 1 with at most one stderr line beginning `accountsd: ` when that returns an error; the stdio server calls `boxmcp.Run(ctx, os.Stdin, os.Stdout, os.Getenv)` under a context that ends on SIGTERM or SIGINT, ignores its arguments, exits 0 too when the error satisfies `errors.Is(err, context.Canceled)` and otherwise 1 with at most one stderr line beginning `accountsd: `; the daemon calls `daemon.Main` with `LookupEnv` `os.LookupEnv`, `Stderr` `os.Stderr`, `Executable` `os.Executable`, `Socket` `boxmcp.SocketPath`, `open` `awshost.Open` and `m` `linux.New(linux.Real())`, under a context that ends on SIGTERM or SIGINT. Adding exec'd cases that signal the child or break a helper was rejected: it widens the list of process-starting tests (`accounts/AGENTS.md`) to prove wiring the in-process tests of each helper already cover.
- **A second exec'ing test** (`accounts/AGENTS.md`, Which tests start a process), in `cmd/accountsd`, beside accounts' one in `cmd/accounts`: it builds the binary and runs it once with an argument, once with `ACCOUNTS_URL` unset, once through a link named `accountsd-session` with no PAM variables, and once through a link named `accountsd-mcp` with a `ping` on stdin, the four cases that end before anything reaches IMDS, AWS, systemd or a socket. The fourth case is new with the box: which function `main` hands the name to can be proved no other way, and a `ping` is answered by the stdio server itself (D20), so it needs no daemon and tells the stdio server apart from the session helper, which also exits 0 having written nothing. Everything else `Main` does is proved in process with an injected `open` and machine.
- **A new daemon that cannot start cannot be rolled back by accounts.** Rollback reaches only a daemon that runs: a binary that exits at start or panics crash-loops under `Restart=always`, never fetches again, and only an operator over SSM can put a working binary back. The guards are before release: the exec'ing test, the arm64 build gate (`accounts/AGENTS.md`, Gates, gate 4), and the sandbox, whose simulated hosts run this very `daemon.Run` loop (D16). Keeping the previous binary beside the new one was considered and left out: restoring it still needs an operator, who can as well fetch `/accountsd` from a rolled-back accounts. Accepted risk.
- **The daemon's trust roots come in through `Process.RootCAs`.** `Main` admits only an `https` URL, and no test may change the process's trust store through its environment (`accounts/AGENTS.md`, Environment variables), so a test of `Main` reaching `Run` needs its TLS fake's certificate handed in; nil is the system's roots, which is what `cmd/accountsd` passes by leaving it out. Injecting the whole `*http.Client` was rejected: `Main` would no longer build the client that follows no redirect, and that would be proved only at the finish line.
- **argv[0] dispatch for the session helper and the stdio server** (D15's pick, extended by sheet decision 1): the name, not an argument, selects each, so `Main`'s no-argument rule stands for the daemon, pam_exec runs the helper by its path with no argument to forge, and Claude Code's plugin runs `accountsd-mcp` by its path.
- **One signing gate for every header** (sheet decision 4), generalizing the one-header-a-second rule the loop had: fetches, reports and forwards share it, a forward waits for it inside its `BoxTimeout`, and the gate never holds the request a header goes on. The alternative, a nonce the verifier would have to send to STS, would change D12's signed-header contract.
- **Eight connections, the ninth refused at once.** With one header a second and a 15-second bound, more than about fifteen forwards cannot be answered inside one window anyway; eight is plenty for an account's few users and keeps the socket's memory under 9 MiB. Refusing the extra one at once gives the person "try again shortly" rather than a client timing out in the listen backlog. It is answered without its line being read, so a client still writing may see its write fail; the answer is already in its receive buffer, and D20's client reads it regardless.
- **One timeout per connection.** `BoxTimeout` runs from accept and covers reading the line, waiting for the gate and the forward; no separate read timeout. It is driven through `Config.After`, so tests fire it rather than wait 15 seconds (`accounts/AGENTS.md`, Time is driven).
- **Malformed or other methods refused locally with `CannotReach`.** The sheet allows the daemon only its two refusals; a dedicated refusal for a client that is not the stdio server was not worth a third word list, since `accountsd-mcp` never sends one.
- **No uid override in production** (sheet decisions 2 and 11). `Main` hands `Run` `KernelUID` and nothing else; `Process` has no uid input and `Main` reads no variable but `ACCOUNTS_URL`. `Process.Socket` chooses only where the socket is, so `Main`'s tests serve it in their own temporary directory and the uid they see is the test process's own. The sandbox does not use `Main`: it calls `Run` with its own `Box` and `PeerUID` (D16).
- **A box socket that fails does not stop the daemon.** Reconciliation (outcome 22) matters more than the box tools; the failure is said on stderr and the tools answer "not answering" until the next start. Same for an accept that fails: said, and retried after `MinBackoff`.
- **A self-update drains the socket.** The old process finishes the forwards in flight before it exits, so a change accounts made is never answered as a failure; it costs at most `BoxTimeout` before the restart.
- **`KernelUID` uses the standard library's `syscall.GetsockoptUcred`**, so no new dependency.

A `Run` test of the socket listens on a Unix socket in a short temporary directory (or hands a listener whose `Accept` returns one end of `net.Pipe`, to count the bytes the daemon reads), sets `PeerUID` to a function answering the uid it chose, and `After` to one handing out channels it fires; it serves a fake accounts with `httptest.NewServer` (or an `http.Client` with an in-memory transport, to count the answer bytes read), dials, writes a line and LF, and decodes the answer line into a `boxmcp.Answer`. A `Main` test of the socket sets `Process.Socket` to a path in its own short temporary directory and has its fake accounts' state list `os.Getuid()` as an active user, so the forward it receives carries the test process's own uid.
