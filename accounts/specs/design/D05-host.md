# D05-host

Outcomes cited as outcome N are those of /home/mgreenly/Documents/ikigenba-accounts.md, the decisions document that delivers accounts; the interface of `opsctl` stated below is the one the delivery fixed for this release, and it is the proof of what accounts relies on.

The host seam: `internal/host`, the one place accounts reaches the host it runs on. accounts runs unprivileged and makes every change, and reads every list, by running `opsctl` through `sudo` (outcome 16); nothing else in accounts runs a program. This document declares the `Host` interface, one method per `opsctl` command; the three list documents and the types they are read into; how every outcome of a command becomes a nil error, a refusal carrying `opsctl`'s diagnostic, or a failure; the default command and how the value of the variable that names the command is split; the command-backed host; and the in-memory host the sandbox runs on. Which environment variable names the command, and when `Run` builds which host, is `D01-layout-and-run-seam`'s; which tool calls which method, and what a tool answers for each outcome, is `D07-tools`'; the result word each outcome becomes in the trail is `D08-trail`'s; the pages read the three lists (`D06-pages`).

## The interface accounts relies on

`opsctl` is an installed external tool. accounts relies on thirteen commands: `group add SLUG`, `group remove SLUG`, `group list`, `group members SLUG`, `user add NAME GROUP KEY`, `user list`, `user key add NAME KEY`, `user key remove NAME KEY`, `user join NAME GROUP`, `user leave NAME GROUP`, `user lock NAME`, `user unlock NAME` and `user delete NAME`. KEY is one argument holding an OpenSSH `ssh-ed25519` public key line. A changing command prints nothing and exits 0, and a command asked for a relation or state the host already has (a key or membership already present on add or join, or already absent on remove or leave, a user already locked or already active) exits 0 too; a command naming a group or user the host does not hold, a removal included, is refused with exit 4, which accounts relays. A list command prints one JSON document. Exit 1 is a failure on the host; exit 2 is malformed input (an invalid name, a key that is not ed25519, bad arguments); exit 4 is a refusal by the host's state (no such group or user, a name taken, a group not empty, a user not locked). On 2 and 4 the first line of standard error, after the `opsctl: ` prefix, is the diagnostic accounts carries to its caller, byte for byte; what it says is `opsctl`'s.

The command is run through `sudo -n`, so a password prompt never waits: `sudo` refuses at once and exits 1, which is a failure.

## Outcomes

Every method answers nil, a `*RefusedError` or a `*FailedError`, and nothing else, so a consumer classifies an answer with `errors.As` into `ok`, `refused` and `failed`. A refusal is exit 2 or 4 with a diagnostic; it carries the exit status and the diagnostic. Everything else that is not success is a failure: exit 1, any other status, a signal, a command that cannot start, a context done before the command exits, a refusal status with no diagnostic, and a list command that exits 0 with output that is not its document. A failure carries the exit status, 0 for a bad document, and -1 when the command exited with none. A changing command's output is never read: exit 0 is success whatever it printed.

## The list documents

`group list` prints `{"groups":[{"slug":...,"members":N}]}`, `group members SLUG` prints `{"group":SLUG,"members":[...]}`, and `user list` prints `{"users":[{"name":...,"groups":[...],"keys":[...],"state":"active"|"locked","last_sign_in":RFC 3339 or null}]}`. They are read into `Group`, `Members` and `User`. A null or absent array reads as empty, since a Go program that prints a nil slice prints null. A null or absent `last_sign_in` means never and reads as the zero `time.Time`. Members a document carries beyond these are ignored, so `opsctl` can add one without breaking a release of accounts. accounts sorts every list it answers by name in byte order, whatever order the document gave, so paging never depends on the tool's sort; a user's keys keep the document's order, since they are relayed.

## The command

`DefaultCommand` is `sudo -n /usr/local/bin/opsctl`. The value of the variable that names the command is split into fields on white space, the first the program and the rest leading arguments, with no quoting: `Fields` does it, and a value that is empty or only white space means the default. `NewCommand` takes the fields; each call runs the program once, with the leading arguments followed by the command's words and arguments, every argument passed as one argument byte for byte, with nothing on standard input. A test writes a `/bin/sh` stub, hands its path to `NewCommand` (or names it in the variable through `Run`'s `LookupEnv`), and proves each call by the argv and input the stub recorded and each outcome by what the stub chose to answer.

## The in-memory host

Under the sandbox, with no command named, accounts runs on `NewMemory`: a host held in memory that starts empty and follows the same interface, so the sandbox walk drives every page and tool end to end. It has the same names, refusals and states as `opsctl`; it checks a name and a key by its own rule, stated below; it never records a sign-in, so every user's last sign-in is never. Its refusal diagnostics are copy constants, carrying no name. It is designed and tested like the command host, by use.

## Recorded decisions

- **No validation before the host.** accounts checks no name and no key before it calls the host; `opsctl` is the authority and its diagnostic is relayed. Only the in-memory host checks, because it is the host there.
- **The in-memory name rule:** 1 to 32 bytes, the first a lowercase ASCII letter, the rest lowercase ASCII letters, digits, `-` and `_`. The decisions document says only "valid as a Linux account name"; this is the portable subset `useradd(8)` and Debian's `adduser` both accept, chosen for the in-memory host alone. On a host `opsctl`'s rule governs.
- **The in-memory key rule** is the OpenSSH public key line format (`sshd(8)`, AUTHORIZED_KEYS FILE FORMAT, with no options) and the `ssh-ed25519` key blob of RFC 8709 (a string `ssh-ed25519` then a string of 32 bytes, in RFC 4251's encoding), checked with the standard library alone; no dependency is added. Two keys are the same key when their type and base64 fields are equal; the comment is not part of the key.
- **Malformed before state, arguments in order:** the in-memory host refuses an invalid name before an invalid key, and either before any state refusal, as exit 2 precedes exit 4.
- **A group or user that is not there is refused; a relation or state already as asked is not** (the delivery's ruling). A command that names a group or user the host does not hold, `group remove` and `user delete` included, is refused as no such group or user and changes nothing: removing what was never there is a mistake the caller should hear of. A key already absent on `user key remove`, a key already present on `user key add`, a membership already absent on `user leave` or present on `user join`, and a state already held on `user lock` or `user unlock` answer nil and change nothing, as `opsctl` answers a command whose state already holds. `user add` of a name already held, by a user or a group, is `name taken`, since its group and key may differ.
- **A user may be left with no key or no group** by the in-memory host; outcome 11 has the tool say a keyless user cannot sign in, and the landing page shows a user with no groups.
- **A refusal status with no diagnostic is a failure** (the root's ruling): a refusal must give the caller something to read.
- **Exit statuses are carried** on both error types so the tools may choose a refusal word by status and the log can say what happened; `-1` stands for no status.
- **A context done ends the program and abandons its output**, and is a failure: an abandoned tool call returns within a bounded time even when a process the program started, such as `opsctl` under `sudo`, runs on and holds its output open; accounts stops waiting for it and reads nothing more from it.

## Consumer tasks

`D01` builds the host as `h := host.NewCommand(host.Fields(v))` when the variable is set, `host.NewMemory()` when it is unset and the sandbox variable is set, and `host.NewCommand(host.Fields(""))` otherwise. A tool runs `err := h.GroupAdd(ctx, a.Group)` and classifies: `var r *host.RefusedError; var f *host.FailedError`, `errors.As(err, &r)` answers a refusal carrying `r.Diagnostic`, `errors.As(err, &f)` answers failed, nil answers ok and records the group. `gs, err := h.GroupList(ctx)` reads each `g.Slug` and `g.Members`; `m, err := h.GroupMembers(ctx, a.Group)` reads `m.Members`; `us, err := h.UserList(ctx)` reads `u.Name`, `u.Groups`, `u.Keys`, `u.State` against `host.StateActive` and `host.StateLocked`, and `u.LastSignIn.IsZero()` for never. A test of the command host writes a stub, builds `host.NewCommand([]string{stub, "-x"})` and asserts the stub's recorded argv `-x group add acme`; a test of the in-memory host compares `r.Diagnostic` with `host.RefuseNoGroup`.
