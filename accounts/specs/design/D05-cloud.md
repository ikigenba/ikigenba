# D05-cloud

The cloud seam: `internal/cloud`, the interfaces and types through which accounts reaches AWS, and its two adapters over the AWS SDK for Go v2: `internal/cloud/awssdk`, which accounts opens to run EC2 instances, Elastic IPs and EBS volumes, write Route 53 records, execute presigned STS requests, assume the hosts' backup role for short-lived credentials and list and delete keys in the hosts' backups bucket, and `internal/cloud/awshost`, which `accountsd` opens on a host to presign its identity and read the instance's metadata. They are the only importers of the SDK; `accountsd` links only `awshost`, never EC2, Route 53 or S3. The in-memory cloud of the sandbox implements the same interfaces (`D16-sandbox`). This document declares the seam's whole surface, what each adapter method asks of AWS and answers, the error every adapter call returns and the class the engine acts on, and the tag contract the seam enforces before any request leaves. Which step calls which method is `D10-operations`'; the identity check that consumes `CallerOf` and `PresignCallerIdentity` is `D12-host-identity`'s; the DNS check and the backups check at `create_account` are `D07-tools`'; who asks for credentials, with which policy and session name, is `D21-backup-access`'.

## The seam

`Cloud` is four interfaces: `EC2` (instances, addresses, volumes, tags), `Route53` (records in one zone, change status), `STS` (accounts' own account id and whole identity, the execution of a presigned `GetCallerIdentity` a daemon sent, and `AssumeRole` of the hosts' backup role) and `S3` (the keys under a prefix of one bucket, listed a page at a time, looked for, and deleted). `Presigner` and `Metadata` are the host's half. An `Opener` takes a region and answers a `Cloud`; `D01-layout-and-run-seam` carries it in `Process.Cloud`, defaulting to `awssdk.Open`, so tests hand a memory or fake cloud and never reach AWS.

The seam is shaped for idempotent, resumable operations (outcome 11): `RunInstance` and `CreateVolume` carry a client token, every creating call carries its tags, and every kind of resource can be found by tag (`FindInstances`, `FindAddresses`, `FindVolumes`) so a repeated step finds what an interrupted attempt made. The address's deleting calls (`DisassociateAddress`, `ReleaseAddress`) answer nil when the thing is already gone. `DeleteVolume` is the one call that destroys data, and it answers a volume already gone as AWS does, an error of `ClassNotFound`, which the engine counts as done (`D10-operations`): a step that deletes data says itself what gone means, rather than the seam hiding it. There is no record type but `A`: the types cannot express another (log D8, the tag contract). The records accounts writes are of two kinds, each an `A` record below the hosts domain: an account's at `<account>.<domain>` and a host's own at `<host>.<domain>`, both valued with the host's Elastic IP. The seam does not tell them apart: `FindRecords` and `ChangeRecord` take any name, and which step writes which record is `D10-operations`'.

## Errors and classes

Every adapter error is a `*cloud.Error` naming the service, the AWS operation, the subject (the id or name the call was about) and a code, and carrying a `Class` the engine acts on: `ClassRefused` (the operation fails with this error's text as its reason), `ClassNotFound` (the resource is absent; each step says what that means), `ClassMismatch` (a client token reused with other parameters) and `ClassTransient` (throttling, a service error, a state AWS is still settling, or no answer at all; the step is deferred and tried again). `Error()` is devctl's form `<service> <Operation> <subject>: <code>` and never carries AWS's message, a URL or a credential, so a failed operation's reason is safe in the trail and on the page. A code AWS did not give is one of the seam's own: `HTTP <status>` for an answer with no error code, `NoResponse` for no answer, `TagContract` for a call the seam refused before sending, and `BadResponse` for an STS answer it could not read.

The class of each code is a table below. Three codes in it are not proven against AWS: `InvalidAllocationID.NotFound`, `VolumeModificationRateExceeded` and `InvalidVolumeModification.NotFound`. The requirements state only how the adapter maps them, which its tests prove with fixtures; whether AWS sends exactly those strings is proven at the finish line, and a different code would fall to `ClassRefused` (a failed operation, retryable with `retry_host`), never to silent success.

The services are `ec2`, `route53`, `sts` and `s3`. The S3 and STS codes the table names are proven below (Backups: STS and S3), with those it leaves to `ClassRefused` and those still unproven.

## The tag contract

infra's operator policy denies what the contract forbids (log, step 2), and the seam refuses the same calls before sending them, so a mistake shows as a clear `TagContract` failure instead of an AWS authorization error: `RunInstance` must carry `Kind=host` (it lands on the instance, its root volume and its network interface) and launch only a type of the `t4g`, `m7g`, `c7g` or `r7g` family; `AllocateAddress` must carry `Kind=host`; `CreateVolume` must carry `Kind=host-data`; no call carries a `Space` or `Domain` tag; `TagResource` never sets `Kind`, `Space` or `Domain` (Kind never changes later, so orphaned is its own key, `Orphaned=true`); a `Find*` call names at least one tag. Route 53 changes are `A` records by construction. Which tags each step puts is `D10-operations`'. `DeleteVolume` takes no tags, so the seam has nothing to check before sending it; the operator policy allows `ec2:DeleteVolume` only on a volume tagged `Kind=host-data` (infra commit e69e0506, applied to the policy and to the space boundary that carries the same statements), so AWS refuses a delete of any other volume, a root volume among them, with `UnauthorizedOperation`, which falls to `ClassRefused`.

## The adapters

`awssdk.Open` loads the SDK's default configuration and credential chain for the given region (on a space, the instance role through IMDS), signs Route 53 for `us-east-1`, reaches STS at its regional endpoint and S3 at its regional endpoint in virtual-hosted style. `OpenWithLoader` takes the configuration from a supplied loader only; adapter tests use it with fake credentials and an in-memory HTTP transport, never the default chain, the environment, IMDS or the network (`accounts/AGENTS.md`, Test discipline). The SDK reads the process environment and IMDS outside the run seam's `LookupEnv` (recorded in `D01-layout-and-run-seam`). `awshost.Open` loads the default configuration on a host, taking the region from IMDS; `awshost.OpenWithLoader` is its test seam, likewise over a supplied configuration whose HTTP client answers IMDS and STS in memory.

`RunInstance` launches one instance from the launch template by name at its default version with the hosts' instance profile, the type, a gp3 root volume of the asked size on `/dev/xvda` deleted with the instance (the device the template's own root mapping names, `infra/launch.tf`, so the request's mapping overrides it), the client token and the tags. That a request's mapping overrides the template's is AWS's documented precedence but was not observed here; the finish line's first host proves it by its root size. `DeleteVolume` sends EC2's `DeleteVolume` for the one volume id and answers nil when AWS accepts it. What it answers otherwise is proven, not assumed: on 2026-11-25, in account 295229566359, `us-east-2`, `DeleteVolume` and `DescribeVolumes` of `vol-0255fb4c8fc234f63`, a volume deleted by hand earlier that day, both answered `InvalidVolume.NotFound`, which the class table already makes `ClassNotFound`. That observation was made with the owner's SSO session, not the hosts operator role: under the operator policy's tag condition (`aws:ResourceTag/Kind`), a delete of a volume that no longer exists might answer `UnauthorizedOperation` instead, `ClassRefused`. The risk is small, since `D10-operations` describes a volume before deleting it and counts a not-found describe as gone, and the finish line checks it (`D09-on-a-space`). AWS's EC2 API reference for `DeleteVolume` documents the rest: the volume must be in the `available` state, a successful call moves it to `deleting` and it then ceases to exist, and a volume attached to an instance is refused with `VolumeInUse`, which the table leaves `ClassRefused`. Which code AWS gives for a volume in another state than `available` (`creating`, say) is not documented and was not observed; if it is `IncorrectState` the table already makes it `ClassTransient`, and any other code falls to `ClassRefused`, a failed operation retryable with `retry_host`, never a silent success. So the class table needs no new code.

`CallerOf` executes a daemon's presigned URL itself, once, with the binding header accounts chose, following no redirect, within `CallerTimeout`, reading at most `MaxCallerBytes`; `PresignCallerIdentity` signs that header and sets `X-Amz-Expires` (both proven by a probe with the real SDK). The binding header's name and the timeout are declared here because `hostauth` sits beside `cloud/awssdk` in the import order and neither may import the other; `D12-host-identity` uses these values.

## Backups: STS and S3

Host backups (/home/mgreenly/Documents/ikigenba-host-backups.md) add two things accounts asks of AWS, both with its own credentials (on a space, the instance role through IMDS). `D21-backup-access` asks STS for short-lived credentials, one set per account and one per host, each from `AssumeRole` on the backup role with an inline session policy naming one prefix; it learns the partition and account id for the role's ARN from `Identity`, accounts' own `GetCallerIdentity` answered whole, kept beside `Account`, which answers only the account id and which `hostauth` keeps using. `D10-operations` deletes a host's key backup and a removed account's backups with `ListKeys` and `DeleteKeys`, and `D07-tools` asks `HasKeys` whether a slug still has backups before `create_account` reuses it. `RoleRequest` and `Credentials` are the seam's own types; `D21-backup-access` copies a `Credentials` into the protocol's, so `cloud` keeps importing nothing of accounts'. The S3 client is the SDK's `service/s3` module, at the release `accounts/AGENTS.md` names (backups log 7; no requirement names a release).

What AWS documents, and the seam therefore relies on:

- **AssumeRole** (STS API reference, `API_AssumeRole.html`): `DurationSeconds` ranges from 900 seconds up to the role's maximum session duration setting, which is itself from one hour to twelve; the default is 3,600. "Role chaining limits your AWS CLI or AWS API role session to a maximum of one hour", and a chained `AssumeRole` asking for more than one hour fails. The IAM user guide (`id_roles.html`, `id_roles_use.html`) defines role chaining as using the credentials of one role to assume a different role. accounts' own credentials on a space are the instance role's, so `RoleSessionDuration`, one hour, is the most a chained session may last and is never above any role's maximum setting: AWS accepts it whether or not it counts the call as chained. The inline session policy's plaintext "can't exceed 2,048 characters", each an ASCII character from space to `ÿ` or tab, line feed or carriage return; accounts' policies are ASCII, so `MaxPolicyBytes` counts bytes and characters alike. Separately, session policies add to the session token, whose size AWS reports as `PackedPolicySize` (a percentage, now deprecated for `SessionTokenUtilization`) and refuses past its maximum with `PackedPolicyTooLarge`; that cannot be computed locally and is a finish-line check. `RoleSessionName` is 2 to 64 characters of `[\w+=,.@-]`, which `D21-backup-access`' `SessionName` keeps to. The answer's `Credentials` carry `AccessKeyId`, `SecretAccessKey`, `SessionToken` and `Expiration`. The page lists the errors `ExpiredToken` (400), `MalformedPolicyDocument` (400), `PackedPolicyTooLarge` (400) and `RegionDisabled` (403); STS's common errors (`CommonErrors.html`) add `ThrottlingException`, `InternalFailure` and `ServiceUnavailable`, which the table already makes transient. Every other STS code falls to `ClassRefused`, so a refused issue leaves that entry's credentials zero (`D21-backup-access`) and is tried again on the next answer.
- **ListObjectsV2** (S3 API reference, `API_ListObjectsV2.html`): a response holds at most 1,000 keys ("The response might contain fewer keys but will never contain more"), is continued with `NextContinuationToken` while `IsTruncated` is true, and lists current objects only, a key deleted under versioning being hidden from it; general purpose buckets list "in lexicographical order based on their key names", which the user guide (`ListingKeysUsingAPIs.html`) states as "List results are always returned in UTF-8 binary order". An absent bucket is `NoSuchBucket` (404). A response may hold fewer keys than asked, none at all while still truncated (the bucket is versioned, so delete markers hidden from the listing make this likely). So `ListKeys` hands at most `MaxKeysPerPage` keys a page, ascending, skips empty pages without calling `each`, and signals the end only by returning; `HasKeys` asks for one key and follows empty truncated pages until it finds one or the listing ends.
- **DeleteObjects** (`API_DeleteObjects.html`): a request names up to 1,000 keys; S3 deletes each and reports each result in the body of a 200, a failure as an `Error` element carrying `Key`, `Code`, `Message` and `VersionId`; in quiet mode the body lists only the failures; a key that does not exist is reported deleted, so a repeated delete of the same page succeeds. A key named without a version id in a versioning-enabled bucket is not removed: "all versions of that object remain in the bucket. However, Amazon S3 inserts a delete marker." That is outcome 8's part here: accounts' deletes send no version id, so every deleted object stays a hidden version until infra's lifecycle rule expires it, and accounts needs no `s3:DeleteObjectVersion`.
- **S3 error codes** (S3 API reference, Error responses, `ErrorResponses.html`; the live page served the fetcher only a redirect stub, so it was read from the Internet Archive's copy of 2026-05-25): `NoSuchBucket` 404, `SlowDown` 503 ("Please reduce your request rate"), `RequestTimeout` 400 (the socket "was not read from or written to within the timeout period"), `AccessDenied` 403, `ExpiredToken` 400, `InternalError` 500, `ServiceUnavailable` 503. `RequestTimeout` is a 400, so the table names it, since the 500-and-above rule would not reach it; `SlowDown` is named though its 503 already would be, because a per-key failure of `DeleteObjects` arrives in a 200.
- **Virtual-hosted style** (user guide, `VirtualHosting.html`): `https://<bucket>.s3.<region>.amazonaws.com/`; with TLS "the SSL wildcard certificate matches only buckets that do not contain dots". `settings.Hosts.BackupBucket` replaces every dot, so the bucket's host name always matches.

Not settled by the documentation, so kept out of requirements and proven at the finish line (`D09-on-a-space`): which code STS answers when accounts may not assume the role (commonly `AccessDenied`; the common-errors page lists `AccessDeniedException`), either one falling to `ClassRefused`; whether `SlowDown`, `RequestTimeout` or `InternalError` ever appear as a per-key `DeleteObjects` code; that real STS issues session-policy credentials for the backup role under the operator policy; and whether AWS counts an `AssumeRole` made with the instance role's credentials as chained, which changes nothing since one hour is accepted either way.

## Memory

Every `Find*` but `FindAddresses` hands AWS's pages to its `each` callback one page at a time and asks for the next page only after `each` returned true, so a listing is never held whole; `DescribeAddresses` has no pages, so `FindAddresses` makes one request and hands its matches to `each` at most once; `FindRecords` answers only the records at one name. `CallerOf` reads at most `MaxCallerBytes` + 1 bytes of STS's answer, the one byte over telling a body too long, which it refuses. `ListKeys` asks for at most `MaxKeysPerPage` keys a page and hands each page to `each` before asking for the next, so a prefix of any size is listed a page at a time; `HasKeys` asks for one key a request; `DeleteKeys` sends at most `MaxKeysPerPage` keys and, in quiet mode, reads back only the failures. No method buffers more than one AWS response.

## Recorded decisions

- **One `Cloud`, four interfaces**, over devctl's six clients: accounts needs EC2, Route 53, STS and S3 only. devctl: `Clients{EC2; SSM; Route53; S3; IAM; STS}`. `S3` joins for host backups and is no general object store: it lists, looks for and deletes keys, and never reads or writes an object, which the hosts do with their own credentials.
- **`Identity` beside `Account`** (plan 2.3): the backup role's ARN needs the partition, which only the caller's `Arn` gives; `Account` stays as it is because `hostauth` uses it.
- **One-hour credentials** (pick 17): `RoleSessionDuration` is the chaining maximum AWS documents; a restic run longer than the credentials' remaining life fails and is re-run (`D15-machine`).
- **`MaxPolicyBytes` is AWS's documented plaintext limit** (pick 2: one credential set per account and one per host, because fifty accounts' prefixes do not fit one policy). The seam passes the policy unchanged and does not check its length: `D21-backup-access` states its policies' bound, AWS refuses a longer one (`ClassRefused`), and the memory cloud refuses one too (`D16-sandbox`).
- **S3 errors name the bucket as their subject, never a key**: a key below `accounts/<slug>/data/` carries a customer's database path, and a refused delete's text becomes a stored reason (`D10-operations`, `D08-trail`).
- **STS errors keep an empty subject**, `AssumeRole` as `GetCallerIdentity`: every issue assumes the same role, so naming it tells nothing, and the session name would only repeat the host.
- **`DeleteKeys` uses quiet mode**: the answer lists only failures, and the first failure's code is the error, its class from the table; a page partly deleted is simply listed and deleted again, since a missing key reports deleted.
- **`DeleteKeys` refuses an empty or oversized slice before sending**, with the code `MalformedXML` and `ClassRefused`, exactly as the memory cloud answers it (`D16-sandbox`), so a caller sees the same error from either cloud: it is a caller's mistake, and `MalformedXML` is the code S3 itself gives a multi-object delete body that does not validate against its schema (`API_DeleteObjects.html`, the malformed-XML example), which a request of no keys or of more than 1,000 would be. That S3 answers exactly `MalformedXML` for those two cases is not documented; the adapter never sends them, so nothing depends on it.
- **S3 in virtual-hosted style at the regional endpoint**, which the bucket name allows (no dot) and which the SDK uses by default; restic's own path-style URL is the hosts' concern (`D15-machine`).
- **The SDK error mapping covers only errors the SDK returned** (re-minted), since `DeleteKeys`' per-key failures and `AssumeRole`'s unreadable answers carry codes the SDK never raised.
- **Client tokens on `RunInstance` and `CreateVolume`** (outcome 11). Departure from devctl, which has no tokens and relies on tag lookup alone; here both, because a launch interrupted between the call and recording its id must not launch twice. `AllocateAddress` has no token in EC2, so lookup by tag is its only idempotency.
- **Classes on the error**, so the engine never parses codes. devctl classifies nothing: every error ends the command.
- **A seam code for every error without an AWS code** (`HTTP <status>`, `NoResponse`), where devctl puts the underlying error's message in place of an empty code: a reason here is stored and shown, and an SDK message can carry a URL.
- **An STS 5xx is transient** for `CallerOf`, though refusing every non-200 was considered: a 5xx means STS is unavailable, which `D12-host-identity` answers 503 (`ErrUnavailable`) so the daemon backs off, not 401.
- **The seam enforces the tag contract** before sending; the operator policy enforces it again at AWS.
- **Subjects**: the id or name each call is about (instance id, allocation id, association id, volume id, change id, record name); a `Find*` or a create has none.
- **One change per Route 53 request**, where devctl batches changes: each record, an account's or a host's own, is its own change and its own INSYNC wait.
- **`DeleteVolume` joins the seam** (outcomes 8 and 15 of /home/mgreenly/Documents/ikigenba-host-numbers-and-delete.md), reversing log D8's "no `DeleteVolume`". It is the one destroying call, so it answers a volume already gone as `ClassNotFound` rather than nil, unlike `ReleaseAddress`, and its callers count that as done (`D10-operations`). It takes no tags and the seam enforces nothing for it before sending: the seam cannot see a volume's tags without a request of its own, and the operator policy's tag condition (`Kind=host-data`) is the guard. Departure from devctl, which deletes nothing of a host's data.
- **`VolumeModification` answers the latest modification** of a volume, by start time; AWS keeps a history.
- **The seam does not refuse an apex name**: it is not told the hosts domain; `valid.Reserved` keeps `dnd`, `eastmark` and every reserved label out at the tool (`D17-names-keys-sizes`), the operator policy limits Route 53 to `A` records below the apex, and the sandbox's fake refuses the apex (`D16-sandbox`).
- **`awssdk.Open` is `OpenWithLoader` over the SDK's default configuration loader** (`config.LoadDefaultConfig` with the region given). No test reaches it (it would read the environment, IMDS or the network); it is proven at the finish line, where accounts on a space runs every operation through it.
- **Record names compare without the trailing dot and case**, whichever form Route 53 answers (whether it answers the trailing dot is unproven).

## Consumer usage

Agent creates a host (`D10-operations`): the `address` step calls `c.FindAddresses(ctx, cloud.Tags{cloud.TagOperation: op.ID, cloud.TagKind: cloud.KindHost}, each)`, then, finding none, `a, err := c.AllocateAddress(ctx, cloud.Tags{cloud.TagKind: cloud.KindHost, cloud.TagHost: "host01", cloud.TagOperation: op.ID})`; `host_record` calls `rs, err := c.FindRecords(ctx, hosts.ZoneID, "host01."+hosts.Domain)` and, finding none, `id, err := c.ChangeRecord(ctx, hosts.ZoneID, cloud.RecordChange{Action: cloud.RecordCreate, Name: "host01." + hosts.Domain, IP: a.IP, TTL: ops.RecordTTL})`; `wait_host_record` polls `c.ChangeInsync(ctx, id)`; `launch` calls `c.RunInstance(ctx, cloud.Launch{Template: hosts.LaunchTemplate, InstanceProfile: hosts.InstanceProfile, Type: "t4g.medium", RootGB: 20, ClientToken: token, Tags: tags, InstanceTags: cloud.Tags{cloud.TagAccountsURL: url}})`; `wait_running` reads `i, err := c.DescribeInstance(ctx, id)` until `i.State == cloud.InstanceRunning`, learning `i.AZ` and `i.RootVolume`; `volume` calls `c.CreateVolume(ctx, cloud.VolumeSpec{AZ: i.AZ, SizeGB: 50, ClientToken: token, Tags: dataTags})`; `wait_volume` reads `c.DescribeVolume` until `v.State == cloud.VolumeAvailable`; `attach` calls `c.AttachVolume(ctx, v.ID, i.ID, ops.DataDevice)`; `associate` calls `assoc, err := c.AssociateAddress(ctx, a.AllocationID, i.ID)`. Any error: `switch cloud.ClassOf(err)` — `cloud.ClassTransient` defers, `cloud.ClassRefused` and `cloud.ClassMismatch` fail the operation with `err.Error()`, except that a `host_record` or `record` step's `ChangeRecord` create answered either, a host's or an account's, fails it with `ops.ReasonRecordConflict` (and the scan's heal notes that reason on the host instead), `cloud.ClassNotFound` is the step's to judge. Agent places an account: `D07-tools` checks `rs, err := c.FindRecords(ctx, hosts.ZoneID, "acme."+hosts.Domain)`; `D10-operations`' `record` step calls `id, err := c.ChangeRecord(ctx, zone, cloud.RecordChange{Action: cloud.RecordCreate, Name: name, IP: eip, TTL: ops.RecordTTL})` and `wait_record` polls `c.ChangeInsync(ctx, id)`. Resize: `m, err := c.VolumeModification(ctx, vol)` then `c.ModifyVolume(ctx, vol, 60)`, `m.State == cloud.ModificationOptimizing`; type change `c.StopInstance`, `c.SetInstanceType(ctx, id, "t4g.large")`, `c.StartInstance`. Delete: `unrecord` calls `c.ChangeRecord(ctx, hosts.ZoneID, cloud.RecordChange{Action: cloud.RecordDelete, Name: "host01." + hosts.Domain, IP: eip, TTL: r.TTL})` for the host's own record as for each account's, and `wait_unrecord` polls `c.ChangeInsync`; then `c.TerminateInstance`, `c.DisassociateAddress`, `c.ReleaseAddress`, `c.TagResource(ctx, vol, cloud.Tags{cloud.TagOrphaned: cloud.OrphanedTrue})` when the data is kept, or, when it is not, `delete_data` calls `err := c.DeleteVolume(ctx, vol)` for the host's data volume and for each volume `c.FindVolumes(ctx, cloud.Tags{cloud.TagKind: cloud.KindHostData, cloud.TagOperation: createOp}, each)` finds, `cloud.ClassOf(err) == cloud.ClassNotFound` counting as done, and `wait_data_deleted` polls `c.DescribeVolume(ctx, vol)` until it answers `cloud.ClassNotFound` or `v.State == cloud.VolumeDeleted`. Kept-volume delete: `v, err := c.DescribeVolume(ctx, kept.Volume)`, then, unless it is gone or `cloud.VolumeDeleting`, `c.DeleteVolume(ctx, kept.Volume)`. Stray scan: `c.FindVolumes(ctx, cloud.Tags{cloud.TagKind: cloud.KindHostData}, each)`; the same scan heals a live host's own record with `c.FindRecords(ctx, hosts.ZoneID, "host04."+hosts.Domain)` and, finding none, `c.ChangeRecord` with `cloud.RecordCreate`, and removes a deleted host's leftover record with `c.ChangeRecord` and `cloud.RecordDelete` when a record at its name is of type `A` with exactly one value, the address it had. Daemon identity: on the host, `p, m, err := awshost.Open(ctx)`; `u, err := p.PresignCallerIdentity(ctx, binding, 60*time.Second)`; `f, err := m.Instance(ctx)`; in accounts, `who, err := c.CallerOf(ctx, u, binding)` and `acct, err := c.Account(ctx)`. Credentials for a host's backups (`D21-backup-access`, called by `D13-daemon-endpoints` on each state answer): once, `who, err := c.Identity(ctx)`, the partition the second field of `who.Arn` and the account `who.Account`; then per account `cr, err := c.AssumeRole(ctx, cloud.RoleRequest{RoleARN: access.RoleARN(partition, who.Account, hosts), SessionName: access.SessionName("host01", "acme"), Policy: access.Policy(hosts.BackupBucket(), partition, protocol.AccountPrefix("acme")), Duration: cloud.RoleSessionDuration})`, and the same for the host's own set with its session name and the state's `backup.host_prefix`; `cr.AccessKeyID`, `cr.SecretAccessKey`, `cr.SessionToken` and `cr.Expires` are copied into a `protocol.Credentials`; any error, `cloud.ClassOf(err)` of any class, leaves that entry zero until the next answer. Name check (`D07-tools`, `create_account`): `has, err := c.HasKeys(ctx, hosts.BackupBucket(), protocol.AccountPrefix("acme"))` under `tools.BackupCheckTimeout`, true refusing the slug and an error failing the call. Deleting backups (`D10-operations`' `delete_backups` step for `protocol.HostPrefix("host01", seq)`, and the engine's pass over a removed account's `protocol.AccountPrefix("acme")`): `stopped := false; err := c.ListKeys(ctx, hosts.BackupBucket(), prefix, func(keys []string) bool { derr = c.DeleteKeys(ctx, hosts.BackupBucket(), keys); stopped = true; return false })`, one page and one delete per pass; a pass in which `ListKeys` returns nil with `stopped` still false (no key left under the prefix) finishes the work, any other leaves it due again, never judged by a page's length, since S3 may answer a short or empty page before the end; `cloud.ClassOf(err) == cloud.ClassNotFound` (`NoSuchBucket`) counts as done, `cloud.ClassTransient` backs off, `cloud.ClassRefused` fails the row or step with `err.Error()`. Wiring: `cl, err := awssdk.Open(ctx, settings.Hosts.Region)`; a test: `cl, err := awssdk.OpenWithLoader(ctx, "us-east-2", loader)`.
