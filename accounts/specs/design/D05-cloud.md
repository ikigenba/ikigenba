# D05-cloud

The cloud seam: `internal/cloud`, the interfaces and types through which accounts reaches AWS, and its two adapters over the AWS SDK for Go v2: `internal/cloud/awssdk`, which accounts opens to run EC2 instances, Elastic IPs and EBS volumes, write Route 53 records and execute presigned STS requests, and `internal/cloud/awshost`, which `accountsd` opens on a host to presign its identity and read the instance's metadata. They are the only importers of the SDK; `accountsd` links only `awshost`, never EC2 or Route 53. The in-memory cloud of the sandbox implements the same interfaces (`D16-sandbox`). This document declares the seam's whole surface, what each adapter method asks of AWS and answers, the error every adapter call returns and the class the engine acts on, and the tag contract the seam enforces before any request leaves. Which step calls which method is `D10-operations`'; the identity check that consumes `CallerOf` and `PresignCallerIdentity` is `D12-host-identity`'s; the DNS check at `create_account` is `D07-tools`'.

## The seam

`Cloud` is three interfaces: `EC2` (instances, addresses, volumes, tags), `Route53` (records in one zone, change status) and `STS` (accounts' own account id, and the execution of a presigned `GetCallerIdentity` a daemon sent). `Presigner` and `Metadata` are the host's half. An `Opener` takes a region and answers a `Cloud`; `D01-layout-and-run-seam` carries it in `Process.Cloud`, defaulting to `awssdk.Open`, so tests hand a memory or fake cloud and never reach AWS.

The seam is shaped for idempotent, resumable operations (outcome 11): `RunInstance` and `CreateVolume` carry a client token, every creating call carries its tags, and every kind of resource can be found by tag (`FindInstances`, `FindAddresses`, `FindVolumes`) so a repeated step finds what an interrupted attempt made. The address's deleting calls (`DisassociateAddress`, `ReleaseAddress`) answer nil when the thing is already gone. `DeleteVolume` is the one call that destroys data, and it answers a volume already gone as AWS does, an error of `ClassNotFound`, which the engine counts as done (`D10-operations`): a step that deletes data says itself what gone means, rather than the seam hiding it. There is no record type but `A`: the types cannot express another (log D8, the tag contract). The records accounts writes are of two kinds, each an `A` record below the hosts domain: an account's at `<account>.<domain>` and a host's own at `<host>.<domain>`, both valued with the host's Elastic IP. The seam does not tell them apart: `FindRecords` and `ChangeRecord` take any name, and which step writes which record is `D10-operations`'.

## Errors and classes

Every adapter error is a `*cloud.Error` naming the service, the AWS operation, the subject (the id or name the call was about) and a code, and carrying a `Class` the engine acts on: `ClassRefused` (the operation fails with this error's text as its reason), `ClassNotFound` (the resource is absent; each step says what that means), `ClassMismatch` (a client token reused with other parameters) and `ClassTransient` (throttling, a service error, a state AWS is still settling, or no answer at all; the step is deferred and tried again). `Error()` is devctl's form `<service> <Operation> <subject>: <code>` and never carries AWS's message, a URL or a credential, so a failed operation's reason is safe in the trail and on the page. A code AWS did not give is one of the seam's own: `HTTP <status>` for an answer with no error code, `NoResponse` for no answer, `TagContract` for a call the seam refused before sending, and `BadResponse` for an STS answer it could not read.

The class of each code is a table below. Three codes in it are not proven against AWS: `InvalidAllocationID.NotFound`, `VolumeModificationRateExceeded` and `InvalidVolumeModification.NotFound`. The requirements state only how the adapter maps them, which its tests prove with fixtures; whether AWS sends exactly those strings is proven at the finish line, and a different code would fall to `ClassRefused` (a failed operation, retryable with `retry_host`), never to silent success.

## The tag contract

infra's operator policy denies what the contract forbids (log, step 2), and the seam refuses the same calls before sending them, so a mistake shows as a clear `TagContract` failure instead of an AWS authorization error: `RunInstance` must carry `Kind=host` (it lands on the instance, its root volume and its network interface) and launch only a type of the `t4g`, `m7g`, `c7g` or `r7g` family; `AllocateAddress` must carry `Kind=host`; `CreateVolume` must carry `Kind=host-data`; no call carries a `Space` or `Domain` tag; `TagResource` never sets `Kind`, `Space` or `Domain` (Kind never changes later, so orphaned is its own key, `Orphaned=true`); a `Find*` call names at least one tag. Route 53 changes are `A` records by construction. Which tags each step puts is `D10-operations`'. `DeleteVolume` takes no tags, so the seam has nothing to check before sending it; the operator policy allows `ec2:DeleteVolume` only on a volume tagged `Kind=host-data` (infra commit e69e0506, applied to the policy and to the space boundary that carries the same statements), so AWS refuses a delete of any other volume, a root volume among them, with `UnauthorizedOperation`, which falls to `ClassRefused`.

## The adapters

`awssdk.Open` loads the SDK's default configuration and credential chain for the given region (on a space, the instance role through IMDS), signs Route 53 for `us-east-1` and reaches STS at its regional endpoint. `OpenWithLoader` takes the configuration from a supplied loader only; adapter tests use it with fake credentials and an in-memory HTTP transport, never the default chain, the environment, IMDS or the network (`accounts/AGENTS.md`, Test discipline). The SDK reads the process environment and IMDS outside the run seam's `LookupEnv` (recorded in `D01-layout-and-run-seam`). `awshost.Open` loads the default configuration on a host, taking the region from IMDS; `awshost.OpenWithLoader` is its test seam, likewise over a supplied configuration whose HTTP client answers IMDS and STS in memory.

`RunInstance` launches one instance from the launch template by name at its default version with the hosts' instance profile, the type, a gp3 root volume of the asked size on `/dev/xvda` deleted with the instance (the device the template's own root mapping names, `infra/launch.tf`, so the request's mapping overrides it), the client token and the tags. That a request's mapping overrides the template's is AWS's documented precedence but was not observed here; the finish line's first host proves it by its root size. `DeleteVolume` sends EC2's `DeleteVolume` for the one volume id and answers nil when AWS accepts it. What it answers otherwise is proven, not assumed: on 2026-11-25, in account 295229566359, `us-east-2`, `DeleteVolume` and `DescribeVolumes` of `vol-0255fb4c8fc234f63`, a volume deleted by hand earlier that day, both answered `InvalidVolume.NotFound`, which the class table already makes `ClassNotFound`. That observation was made with the owner's SSO session, not the hosts operator role: under the operator policy's tag condition (`aws:ResourceTag/Kind`), a delete of a volume that no longer exists might answer `UnauthorizedOperation` instead, `ClassRefused`. The risk is small, since `D10-operations` describes a volume before deleting it and counts a not-found describe as gone, and the finish line checks it (`D09-on-a-space`). AWS's EC2 API reference for `DeleteVolume` documents the rest: the volume must be in the `available` state, a successful call moves it to `deleting` and it then ceases to exist, and a volume attached to an instance is refused with `VolumeInUse`, which the table leaves `ClassRefused`. Which code AWS gives for a volume in another state than `available` (`creating`, say) is not documented and was not observed; if it is `IncorrectState` the table already makes it `ClassTransient`, and any other code falls to `ClassRefused`, a failed operation retryable with `retry_host`, never a silent success. So the class table needs no new code.

`CallerOf` executes a daemon's presigned URL itself, once, with the binding header accounts chose, following no redirect, within `CallerTimeout`, reading at most `MaxCallerBytes`; `PresignCallerIdentity` signs that header and sets `X-Amz-Expires` (both proven by a probe with the real SDK). The binding header's name and the timeout are declared here because `hostauth` sits beside `cloud/awssdk` in the import order and neither may import the other; `D12-host-identity` uses these values.

## Memory

Every `Find*` but `FindAddresses` hands AWS's pages to its `each` callback one page at a time and asks for the next page only after `each` returned true, so a listing is never held whole; `DescribeAddresses` has no pages, so `FindAddresses` makes one request and hands its matches to `each` at most once; `FindRecords` answers only the records at one name. `CallerOf` reads at most `MaxCallerBytes` + 1 bytes of STS's answer, the one byte over telling a body too long, which it refuses. No method buffers more than one AWS response.

## Recorded decisions

- **One `Cloud`, three interfaces**, over devctl's six clients: accounts needs EC2, Route 53 and STS only. devctl: `Clients{EC2; SSM; Route53; S3; IAM; STS}`.
- **Client tokens on `RunInstance` and `CreateVolume`** (outcome 11). Departure from devctl, which has no tokens and relies on tag lookup alone; here both, because a launch interrupted between the call and recording its id must not launch twice. `AllocateAddress` has no token in EC2, so lookup by tag is its only idempotency.
- **Classes on the error**, so the engine never parses codes. devctl classifies nothing: every error ends the command.
- **A seam code for every error without an AWS code** (`HTTP <status>`, `NoResponse`), where devctl puts the underlying error's message in place of an empty code: a reason here is stored and shown, and an SDK message can carry a URL.
- **An STS 5xx is transient** for `CallerOf`, though refusing every non-200 was considered: a 5xx means STS is unavailable, which `D12-host-identity` answers 503 (`ErrUnavailable`) so the daemon backs off, not 401.
- **The seam enforces the tag contract** before sending; the operator policy enforces it again at AWS.
- **Subjects**: the id or name each call is about (instance id, allocation id, association id, volume id, change id, record name); a `Find*` or a create has none.
- **One change per Route 53 request**, where devctl batches changes: each record, an account's or a host's own, is its own change and its own INSYNC wait.
- **`DeleteVolume` joins the seam** (outcomes 8 and 15 of /home/mgreenly/Documents/ikigenba-host-numbers-and-delete.md), reversing log D8's "no `DeleteVolume`". It is the one destroying call, so it answers a volume already gone as `ClassNotFound` rather than nil, unlike `ReleaseAddress`, and its callers count that as done (`D10-operations`). It takes no tags and the seam enforces nothing for it before sending: the seam cannot see a volume's tags without a request of its own, and the operator policy's tag condition (`Kind=host-data`) is the guard. Departure from devctl, which deletes nothing of a host's data.
- **`VolumeModification` answers the latest modification** of a volume, by start time; AWS keeps a history.
- **The seam does not refuse an apex name**: it is not told the hosts domain; `valid.Reserved` keeps `dnd`, `eastmark` and every reserved label out at the tool (`D17-names-keys-sizes`), the operator policy limits Route 53 to `A` records below the apex, and the sandbox's fake refuses the apex (`D16-sandbox`).
- **`awssdk.Open` is `OpenWithLoader` over the SDK's default configuration loader** (`config.LoadDefaultConfig` with the region given). No test reaches it (it would read the environment, IMDS or the network); it is proven at the finish line, where accounts on a space runs every operation through it.
- **Record names compare without the trailing dot and case**, whichever form Route 53 answers (whether it answers the trailing dot is unproven).

## Consumer usage

Agent creates a host (`D10-operations`): the `address` step calls `c.FindAddresses(ctx, cloud.Tags{cloud.TagOperation: op.ID, cloud.TagKind: cloud.KindHost}, each)`, then, finding none, `a, err := c.AllocateAddress(ctx, cloud.Tags{cloud.TagKind: cloud.KindHost, cloud.TagHost: "host01", cloud.TagOperation: op.ID})`; `host_record` calls `rs, err := c.FindRecords(ctx, hosts.ZoneID, "host01."+hosts.Domain)` and, finding none, `id, err := c.ChangeRecord(ctx, hosts.ZoneID, cloud.RecordChange{Action: cloud.RecordCreate, Name: "host01." + hosts.Domain, IP: a.IP, TTL: ops.RecordTTL})`; `wait_host_record` polls `c.ChangeInsync(ctx, id)`; `launch` calls `c.RunInstance(ctx, cloud.Launch{Template: hosts.LaunchTemplate, InstanceProfile: hosts.InstanceProfile, Type: "t4g.medium", RootGB: 20, ClientToken: token, Tags: tags, InstanceTags: cloud.Tags{cloud.TagAccountsURL: url}})`; `wait_running` reads `i, err := c.DescribeInstance(ctx, id)` until `i.State == cloud.InstanceRunning`, learning `i.AZ` and `i.RootVolume`; `volume` calls `c.CreateVolume(ctx, cloud.VolumeSpec{AZ: i.AZ, SizeGB: 50, ClientToken: token, Tags: dataTags})`; `wait_volume` reads `c.DescribeVolume` until `v.State == cloud.VolumeAvailable`; `attach` calls `c.AttachVolume(ctx, v.ID, i.ID, ops.DataDevice)`; `associate` calls `assoc, err := c.AssociateAddress(ctx, a.AllocationID, i.ID)`. Any error: `switch cloud.ClassOf(err)` — `cloud.ClassTransient` defers, `cloud.ClassRefused` and `cloud.ClassMismatch` fail the operation with `err.Error()`, except that a `host_record` or `record` step's `ChangeRecord` create answered either, a host's or an account's, fails it with `ops.ReasonRecordConflict` (and the scan's heal notes that reason on the host instead), `cloud.ClassNotFound` is the step's to judge. Agent places an account: `D07-tools` checks `rs, err := c.FindRecords(ctx, hosts.ZoneID, "acme."+hosts.Domain)`; `D10-operations`' `record` step calls `id, err := c.ChangeRecord(ctx, zone, cloud.RecordChange{Action: cloud.RecordCreate, Name: name, IP: eip, TTL: ops.RecordTTL})` and `wait_record` polls `c.ChangeInsync(ctx, id)`. Resize: `m, err := c.VolumeModification(ctx, vol)` then `c.ModifyVolume(ctx, vol, 60)`, `m.State == cloud.ModificationOptimizing`; type change `c.StopInstance`, `c.SetInstanceType(ctx, id, "t4g.large")`, `c.StartInstance`. Delete: `unrecord` calls `c.ChangeRecord(ctx, hosts.ZoneID, cloud.RecordChange{Action: cloud.RecordDelete, Name: "host01." + hosts.Domain, IP: eip, TTL: r.TTL})` for the host's own record as for each account's, and `wait_unrecord` polls `c.ChangeInsync`; then `c.TerminateInstance`, `c.DisassociateAddress`, `c.ReleaseAddress`, `c.TagResource(ctx, vol, cloud.Tags{cloud.TagOrphaned: cloud.OrphanedTrue})` when the data is kept, or, when it is not, `delete_data` calls `err := c.DeleteVolume(ctx, vol)` for the host's data volume and for each volume `c.FindVolumes(ctx, cloud.Tags{cloud.TagKind: cloud.KindHostData, cloud.TagOperation: createOp}, each)` finds, `cloud.ClassOf(err) == cloud.ClassNotFound` counting as done, and `wait_data_deleted` polls `c.DescribeVolume(ctx, vol)` until it answers `cloud.ClassNotFound` or `v.State == cloud.VolumeDeleted`. Kept-volume delete: `v, err := c.DescribeVolume(ctx, kept.Volume)`, then, unless it is gone or `cloud.VolumeDeleting`, `c.DeleteVolume(ctx, kept.Volume)`. Stray scan: `c.FindVolumes(ctx, cloud.Tags{cloud.TagKind: cloud.KindHostData}, each)`; the same scan heals a live host's own record with `c.FindRecords(ctx, hosts.ZoneID, "host04."+hosts.Domain)` and, finding none, `c.ChangeRecord` with `cloud.RecordCreate`, and removes a deleted host's leftover record with `c.ChangeRecord` and `cloud.RecordDelete` when a record at its name is of type `A` with exactly one value, the address it had. Daemon identity: on the host, `p, m, err := awshost.Open(ctx)`; `u, err := p.PresignCallerIdentity(ctx, binding, 60*time.Second)`; `f, err := m.Instance(ctx)`; in accounts, `who, err := c.CallerOf(ctx, u, binding)` and `acct, err := c.Account(ctx)`. Wiring: `cl, err := awssdk.Open(ctx, settings.Hosts.Region)`; a test: `cl, err := awssdk.OpenWithLoader(ctx, "us-east-2", loader)`.
