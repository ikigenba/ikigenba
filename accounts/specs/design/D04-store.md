# D04-store

The record: `internal/store`, which owns accounts' tables in its SQLite database, `state/accounts.db`, and every read and write of them. The record is now the source of truth for the whole service (outcome 8 of ikigenba-ssh-hosts.md): hosts, accounts, users and their keys, the operations that change AWS, the latest report of each host, the namespace, the counters that allocate names and numbers, and the strays and volume grows the engine notes. Nothing else holds a host's desired state; the daemon on each host makes the host match what this store answers (`D11-protocol`, `D14-accountsd`). This document declares the store's whole public surface: its types, every method with its signature, what each does, the errors every consumer tells apart, the one line every consumer answers when the database cannot be reached, and the migration. Which tool calls which method is the tools' (`D07-tools`); the pages read the same lists (`D06-pages`); the operations engine drives the operations (`D10-operations`); the daemon endpoints serve `Desired` and take `RecordReport` (`D13-daemon-endpoints`); the trail is `D08-trail`'s. Opening, migrating, transactions and the failure seam are appkit's `db`; `D01-layout-and-run-seam` resolves the path, declares the root package's `Migrations()` and builds the store.

## One database, one writer

accounts is the only writer of its database. `store.New` builds a store over a handle and opens or creates nothing. What a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds; a test proves the record that way, never by reading tables. A store whose handle is failing (`SetFailing(true)`), or closed, answers every call with an error matching `ErrUnreachable` and changes nothing. `Config.Now` is the clock every time the store stamps on its own is read from (created times, an operation's start, a step's start when the engine does not pass one); `Config.Rand` is where operation ids are drawn. `Run` hands in `Process.Now` and `Process.Rand`; the store has no default for either. Every write a method makes is one transaction: a call either changes everything its requirement says or nothing.

## Hosts

A host row is created by `CreateHost` in state `provisioning` with its `create` operation, named `host01`, `host02`, … from a sequence that never goes back, deleted hosts included, so `host100` follows `host99` and a name is never reused. The row is kept after deletion in state `deleted`: no read or list answers it, but its resource ids still explain what AWS holds (`Explains`) and its sequence number stays taken. The host's columns hold everything the landing and the silence sweep need, so neither ever decodes a report body: the state and failure reason, type and sizes, the resource ids AWS gave, the desired-state `Version` and the `Applied` version the host last reported, the `Attempted` version and whether the latest report carried an error, when it last reported and when it last entered `running`, and the `Alarm`, the last abnormal health an event told. `Health` computes the health word from those columns alone.

A host changes state only through the store's operation methods: `CreateHost` and `StartHostOp` move it into the transitional state of the operation they record, `Finish` moves it to the state the operation's kind ends in, `Fail` moves it to `failed` with a reason, and `RetryHost` moves a failed host back into the transitional state of its failed operation. The guards for each tool live here, in the same transaction as the write, so two racing tools never both pass: one host-kind operation at a time, only `retry_host` and `delete_host` act on a failed host, stop needs `running`, start needs `stopped`, resize needs something to grow or change and grows only, and delete needs every account on the host to be already `removing` (the delete guard, stated here once and cited by `D07-tools` and `D10-operations`).

## Operations

An operation is a recorded state machine (`D10-operations` owns the steps): its kind, its current step and generation, its status, the target of a resize, the state a resize returns to, the error a failure recorded, how many deferred attempts the current step has had, when it started, when the current step started, when it may next run, when it finished, and the caller who started it, kept whole as appkit's `identity.Caller` so the engine tells events as that caller. A new operation's step is empty: the engine begins at its kind's first step. `RecordStep` records the step about to run before the AWS call it makes; `Advance` records what the call learned and clears the attempts; `Defer` puts the step off and `NextTry` tells the engine when the earliest deferred step is due; `Finish` and `Fail` end the operation. The step's start time survives a repeated `RecordStep` of the same step and generation, so a step that keeps being retried still times out.

Operation ids are `op_` and 16 lowercase hex digits drawn from `Config.Rand`, redrawn on a collision as gdrive draws its `xfr_` ids.

## Accounts, users and the namespace

An account is placed on one host forever. `PlaceAccount` records it `pending` with its `place` operation; `Finish` of that operation makes it `active`, and `Fail` of it makes it `failed` with the reason, as a failed host operation does to its host; `RemoveAccount` makes a `pending`, `active` or `failed` account `removing` with an `unplace` operation, cancelling a `place` still running; `Finish` of the `unplace` deletes the row. A user belongs to one account, fixed at add. Account slugs and user names share one namespace across every host: a name is taken while its row exists and freed only when the row is gone. Gids and uids come from one counter starting at `FirstID` and are never reused.

Every change that alters what `Desired` answers for a host bumps that host's `Version` by one in the same transaction and stores the new version on what changed (the account's `Version` or `RemovedVersion`, the user's `Version`); a change that is already in effect (a key already held, a user already locked) changes nothing and bumps nothing. A user is `Pending` while its version is above its host's applied version. Purging rows the host already applied (a user deleted and applied, an account removed and applied) bumps nothing.

## Desired state and reports

`Desired` builds `D11-protocol`'s `protocol.DesiredState` for a host from its rows; `D13-daemon-endpoints` fills in the daemon digest. `RecordReport` keeps the latest report of a host and folds it into the host's columns. A report can only ever misreport its own host: its applied version is clamped to the host's own version and never goes backwards, sign-ins and slices count only for the host's own users and accounts, and sign-in times never lie in the future (the trust argument of `D12-host-identity`). A report that applies a removal deletes the removed users and frees their names. `RecordReport` answers a `Transition` from which `D13-daemon-endpoints` tells `host.synced` and `host.apply_failed`; `MarkSilent` marks running hosts that stopped reporting, and `D10-operations` tells `host.silent` for each.

## Strays, grows and watching

`NoteStray` records a resource the stray scan could not explain, answering true only the first time so the event is told once; `Explains` says whether any host row, deleted ones included, holds a resource id. `NoteGrow` records each volume modification accounts started, and `StartHostOp` refuses a resize that would grow a volume already grown `MaxGrows` times within `GrowWindow` (EBS allows four modifications per volume in a rolling 24 hours); expired rows are pruned by the next `NoteGrow` of the same volume and by `PruneGrows`, which the engine's scan pass calls in pages. `Watch` lets the daemon endpoints' long poll wait for a host's version to change; it is in-process only.

## Errors

`ErrUnreachable` covers every failure of the database and every argument no consumer sends; consumers answer it with `Unreachable`, never quoting the cause. `ErrNotFound` says the named entity does not exist (or the host is deleted, for reads). `ErrTaken` says a name is held in the namespace. `ErrConflict` says a state guard failed; each guard has its own error that matches `ErrConflict` under `errors.Is`, so `D07-tools` picks the refusal it words without re-reading state, and `D08-trail`'s `Result` classifies them all as refused. Two not-found cases are told apart the same way: a user that exists but in another account (`ErrNotInAccount`) and a key the user does not hold (`ErrKeyNotHeld`), both matching `ErrNotFound`. Precedence: a done context and a failing or closed handle first, then an argument no consumer sends, then not found, then the method's guards in the order its requirement lists.

## The migration

The schema is `0001_accounts.sql`, unchanged, plus `0002_hosts.sql`, which only adds tables and indexes: `hosts`, `operations`, `accounts`, `ssh_users`, `ssh_keys`, `reports`, `names`, `counters`, `strays` and `volume_grows`, with these indexes (a partial unique index on a live host's instance id, operations by status and next try, accounts by host and slug, users by account and name). The old `groups` and `users` tables are left in place and never read or written: this release is the expand half of outcome 27, and the release before it runs on this schema, since appkit's `db` opens a database whose applied migrations it does not know with a warning only. The next release drops them. The column lists are the build run's, inside the requirements below.

## Memory

Every list takes a `limit` and answers at most that many rows, read by a keyset query over an index; a page asks for one row more than it shows (`D06-pages`, `D07-tools`), so the store accepts up to `paging.MaxLimit + 1`. Passes over operations, silent hosts and grows are in pages of the caller's limit (`BatchSize` for the engine). `AccountsOn`, `UsersOf` and `Desired` answer every row of one host or account, bounded by the caps the store itself enforces (`valid.MaxAccountsPerHost`, `valid.MaxUsersPerHost`, `valid.MaxKeysPerUser`). A report is one body of at most `protocol.MaxReportBytes`. `Watch` holds one channel per waiter.

## Recorded decisions

- **The record is the source of truth** (outcome 8). Previous design: the record held only what accounts created, and the host (opsctl) held keys, memberships, states and sign-ins. That host is gone; there is nothing else to agree with.
- **Guards in the store, one error per guard.** `ErrConflict` stands for every failed guard; each guard also has its own error matching it, so the tool words the right refusal from one transactional answer instead of a racy read before the write. Sibling: gdrive's store answers `ErrEnded` for its one guard.
- **A deleted host is not found to reads and gone to writes.** `Host`, `HostByInstance` and the lists answer `ErrNotFound` for it; `StartHostOp`, `RetryHost` and `PlaceAccount` answer `ErrHostGone`, which `D07-tools` words as `HostGone`.
- **The engine owns step names; the store records them.** A new operation's step is empty, the engine's cue to begin; the store never interprets a step name.
- **Finish and Fail know the kind's end state.** The store, not the engine, moves a host to `running`, `stopped`, the resize's resume state or `deleted`, and an account to `active` or gone, so the state machine's end states hold whatever engine calls them.
- **The step's start time survives a repeated `RecordStep`** of the same step and generation, so `StepTimeout` counts from the step's first attempt.
- **Alarms persist until in sync.** `silent` and `error` stay until a report applies the current version, so `host.synced` is told once per episode and a host that goes silent again while still marked silent is not told twice.
- **Purges bump nothing.** Deleting a user or account row whose removal the host already applied changes nothing the host must do, so it does not wake the long poll for an empty cycle.
- **The Route 53 change id lives on the account** (`Change`), since a host delete records one change per removing account.
- **An unplace records what it superseded** (`Operation.Supersedes`), so the tool that cancelled a running `place` tells its `operation.finished` with status `cancelled` from the answer alone.
- **A failed account is removed, not retried.** A `failed` account (its `place` failed) and a `removing` account whose `unplace` failed are both taken on by `remove_account`: `RemoveAccount` starts an `unplace`, which deletes the account's record only when it points at the host and waits for the host to drop the group; with one running it answers `ErrAccountRemoving`. The agent then creates the account again. This is outcome 10's retry for an account. A retry tool was rejected: it would add a tool, a store method and its errors, and repeating a `place` from its recorded step does not cure its usual failure, a record at the name that is not the host's (`ReasonRecordConflict`). Until it is removed a `failed` account keeps its group on the host (`Desired` sends it `active`) and takes users as a `pending` one does.
- **`RetryHost` keeps the generation**: a create failed with `ReasonTerminated` cannot be retried into a fresh launch; it is deleted instead (`D10-operations`).
- **The last key may be removed.** A user with no key cannot sign in, which is the caller's choice; `remove_key` answers the keys left (`D07-tools`).
- **Who is a user id** for the created-by of a host, account or user, as before; an operation keeps the whole caller because its events are told as that caller (gdrive's transfers keep user id, email and request id the same way).
- **Ids** `op_` + 16 hex from `Config.Rand`, redrawn up to 8 times, as gdrive's `xfr_`.
- **Departure: operations survive a restart.** gdrive, gmail and scripts finish interrupted work `failed` or `interrupted` at start; outcome 11 requires resume, so the store keeps every running operation as it was and the engine continues it (`D10-operations`).
- **Departure: strays are a table**, so each unexplained resource is told once across restarts; devctl reports duplicates on every listing instead.
- **Departure: the old tables stay unused**, not dropped (outcome 27, expand). accounts' previous design kept `groups` and `users` as its whole record.

## Consumer usage

Agent creates a host (`D07-tools`): `h, op, err := st.CreateHost(ctx, store.HostSpec{Type: "t4g.medium", RootGB: 20, DataGB: 50}, c)` answers `h.Name` `host01` in `store.HostProvisioning` and `op.Kind` `store.OpCreate`; the engine (`D10-operations`) pages `st.Runnable(ctx, now, after, store.BatchSize)`, calls `st.RecordStep(ctx, op.ID, step, op.Generation, now)` before each AWS call, `st.Advance(ctx, op.ID, store.Update{Step: next, AllocationID: id, EIP: ip})` after it, `st.Defer(ctx, op.ID, next, attempts)` on a transient error, and `st.Finish(ctx, op.ID, store.Update{AssociationID: assoc})`, after which `st.Host(ctx, "host01")` answers `store.HostRunning`. Daemon first boot (`D13-daemon-endpoints`): `h, err := st.HostByInstance(ctx, instanceID)`, then `ds, err := st.Desired(ctx, h.Name)`, waiting with `ch, release := st.Watch(h.Name)` when nothing changed. Report: `tr, err := st.RecordReport(ctx, h.Name, r, now)`, telling `host.synced` when `tr.Synced` and `host.apply_failed` when `tr.ApplyFailed`. Agent places an account: `a, op, err := st.PlaceAccount(ctx, "acme", "host01", c)` answers `store.AccountPending`; the engine records the Route 53 change with `st.RecordChange(ctx, op.ID, "acme", changeID)` and finishes `place`, after which `a.State` is `store.AccountActive`. Users: `u, err := st.AddUser(ctx, "acme", "bugs", store.Key{Type: t, Body: b, Line: l}, c)` answers `u.Pending` true until a report's applied version reaches `u.Version`; `st.Lock`, `st.Unlock`, `st.Delete(ctx, "acme", "daffy")` (refused with `store.ErrNotLocked` unless locked), after which a report applying it removes the row and `st.AddUser(ctx, "acme", "daffy", k, c)` succeeds again. Stop, start and resize: `st.StartHostOp(ctx, "host01", store.OpStop, store.Target{}, c)`, `store.OpStart`, and `st.StartHostOp(ctx, "host01", store.OpResize, store.Target{Type: "t4g.large", DataGB: 60}, c)`, which the engine reads back as `op.Target` and `op.ResumeState`, noting each modification with `st.NoteGrow(ctx, volume, now)`. Restart: the next `Run` pages `st.Runnable` from the start and every running operation is there at its recorded step and generation. Failure and retry: `st.Fail(ctx, op.ID, reason)` leaves the host `store.HostFailed` with `h.Reason`; `st.RetryHost(ctx, "host01", c)` resumes it. Delete: `st.StartHostOp(ctx, "host01", store.OpDelete, store.Target{}, c)` answers `store.ErrHasAccounts` until `st.RemoveAccount(ctx, "acme", c)` made the account `store.AccountRemoving`; the engine walks `st.OperationsOf(ctx, "host01", after, store.BatchSize)` and its `Finish` leaves the host hidden and the account gone. Silence: `hs, err := st.MarkSilent(ctx, now, after, store.BatchSize)`, one `host.silent` per answered host. Pages: `st.ListHosts(ctx, after, 26)`, `st.ListAccounts`, `st.ListUsers(ctx, "", afterAccount, afterName, 26)`, each row's health from `store.Health(h, now)`.

A test opens its own database with `db.Open` and the root package's `Migrations()` in a temporary directory, builds `store.New(d, store.Config{Now: clock, Rand: rnd})` with a clock it moves and a random source it controls, drives the methods, flips `d.SetFailing(true)` or closes `d`, and reopens the path to prove what persists. A test of the migration reads `fs.ReadFile(accounts.Migrations(), "0002_hosts.sql")`; a test of the old tables' neglect drops them through `DB.Write` on its own database.
