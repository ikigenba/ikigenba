# D04-store

The record: `internal/store`, which owns accounts' tables in its SQLite database, `state/accounts.db`, and every read and write of them. The record is narrow on purpose. It holds the groups and the users accounts itself created, each with its name, when it was created and who created it, and nothing the host already holds: no keys, no memberships, no states, no lock times and no sign-ins. The host is the store every list is read from (`D05-host`); the record only lends each listed entry its created time and creator. This document declares the store's whole public surface: its records, every method with its signature, what each does, the one error every consumer tells apart, the one line every consumer answers when the database cannot be reached, and the migration. Which tool calls which method, and when, is the tools' (`D07-tools`); the pages join the same lookups (`D06-pages`); the trail is `D08-trail`'s. Opening, migrating, transactions and the failure seam are appkit's `db`; `D01-layout-and-run-seam` resolves the path, declares the root package's `Migrations()` and builds the store.

## One database, one writer

accounts is the only writer of its database. `store.New` builds a store over a handle and opens or creates nothing. What a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds; a test proves the record that way, never by reading tables. A store whose handle is failing (`SetFailing(true)`), or closed, answers every call with an error matching `ErrUnreachable` and changes nothing. `Config.Now` is the clock every created time is read from, read once per call that records, so the tools and the pages carry no clock of their own for the record. `Run` hands in `Process.Now`, and the store has no default for it.

## The records

A `Group` is a group accounts created: its `Slug`, the name the host knows it by, its `Created` time and its `CreatedUserID`. A `User` is a user accounts created: its `Name`, the login name, its `Created` time and its `CreatedUserID`. Who created an entry is the caller's user id only, the `UserID` of appkit's `identity.Caller`; neither an email nor a request id is kept. Created times are UTC to the second. Groups and users are separate records: a group and a user may carry the same name in the record, though the host refuses that pair.

## Recording only what the host made

A change is recorded only after the host command for it exited 0 (`D07-tools` orders the calls); the store neither runs nor knows the host. `AddGroup` follows a successful `group add`, `RemoveGroup` a successful `group remove`; `AddUser` follows a successful `user add`, `DeleteUser` a successful `user delete`. No other host change touches the record. The host refuses `group add` and `user add` of a name it holds as name taken (`D05-host`), so a retried `create_group` or `add_user` never reaches the store. An add reaches the store for a name it holds only when the entry was removed on the host outside accounts and then created again through accounts; then the store keeps the entry as first recorded, its created time and creator unchanged, and answers it with false. Removing or deleting a name the store does not hold is not an error: an entry made on the host outside accounts has no record to remove. The store checks no name's shape; the host is the judge of names, and accounts relays its refusals.

## Joining lists

A list is the host's, joined with the record for created times. `Groups` and `Users` take the names of one window, or of one entry, and answer, in one call, a map from each recorded name among them to its record; a name the map lacks has no created time. An entry in the record but not on the host is never asked for, so it is never shown.

## Errors

`ErrUnreachable` is the store's one error, and every consumer answers it with `Unreachable`, never quoting the cause: a failing or closed handle, a done context, and a call given a value no consumer sends (an empty name, an empty user id). Before anything else, a done context and a failing or closed handle answer `ErrUnreachable`, whatever the arguments.

## The migration

The schema is one migration, `0001_accounts.sql`: `groups` keyed by slug and `users` keyed by name, each with its created time as RFC 3339 UTC text to the second and its creator's user id. A later release that needs more adds it by an expand migration.

## Recorded decisions

- **The record is only what accounts created** (the brief's settled record): the host holds keys, memberships, states and sign-ins, and the record never duplicates them, so the two cannot disagree about them.
- **A repeated add keeps the first record**: opsctl refuses `group add` and `user add` of a name it holds, so an `AddGroup` or `AddUser` for a name the store holds can follow only when the entry was removed on the host outside accounts and created again through accounts; keeping the first created time means the store never overwrites what it recorded. The cost: an entry removed on the host outside accounts and later created again through accounts keeps its first created time, since the record never heard of the removal.
- **Who is a user id only**, as the identity's `UserID`.
- **The store reads the clock**, through `Config.Now`, rather than taking times as arguments, so every consumer's created time comes from one place, and the stamp is the store's.
- **Each changing method answers whether it wrote**, a `bool` before the error, so a test and a consumer can tell a first record from a kept one.
- **Lookups by name, one call per window**: the lists are the host's and windowed in memory (`D07-tools` records the departure from shape's Storage), so the store answers the window's names in one call rather than one query per entry, and never more rows than the names asked.
- **A store fails only through its handle**: a failing (`SetFailing(true)`) or closed handle is how a test provokes a database failure, and both answer `ErrUnreachable` whatever the arguments.

## Consumer tasks

The tools (`D07-tools`), `c` the caller and `st` the store, call: `create_group`, after the host's `group add` succeeded, `g, added, err := st.AddGroup(ctx, a.Group, c.UserID)`; `remove_group`, after `group remove` succeeded, `removed, err := st.RemoveGroup(ctx, a.Group)`; `add_user`, after `user add` succeeded, `u, added, err := st.AddUser(ctx, a.User, c.UserID)`; `delete_user`, after `user delete` succeeded, `removed, err := st.DeleteUser(ctx, a.User)`; `groups`, over the window `w` of the host's list, `rec, err := st.Groups(ctx, slugs)` with `slugs` the window's slugs, each entry's created time `rec[slug].Created` when `rec` holds `slug`; `group` `rec, err := st.Groups(ctx, []string{a.Group})`; `users` `rec, err := st.Users(ctx, names)`. The landing page (`D06-pages`) calls `st.Groups` and `st.Users` with each window's names, answering `store.Unreachable` on an error.

A test opens its own database with `db.Open` and the root package's `Migrations()` in a temporary directory, builds `store.New(d, store.Config{Now: clock})` with a clock it moves, adds and removes groups and users, looks them up, flips `d.SetFailing(true)` or closes `d`, and reopens the path to prove what persists. A test of the migration reads `fs.ReadFile(accounts.Migrations(), "0001_accounts.sql")`.
