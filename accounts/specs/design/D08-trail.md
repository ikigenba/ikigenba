# D08-trail

The trail as a whole: the closed set of event names accounts records, the ones it declares itself with their attributes, the functions that record them, the request pair the telemetry middleware records for every request, and secrecy, stated once for the whole app. Outcome 15 of /home/mgreenly/Documents/ikigenba-ssh-hosts.md asks that every change, every host state change and every host going silent, coming back in sync or failing to apply be recorded in telemetry; this document names those events. accounts calls no sibling and joins no bus this release, so it records no `sibling.called` and no `event.lost`, emits nothing on the bus, and its manifest declares no `[events]` (`D09-on-a-space`).

Who records each name is another document's; this one declares the names, their attributes and the functions that hand them to the writer. The request pair is appkit's `telemetry.Middleware`'s, which `D03-serve` mounts on every request, `/accountsd` and `/accountsd/` included; `tool.called` is appkit's MCP server's; `service.started` and `service.stopping` are the run's (`D01-layout-and-run-seam`). `change.finished`, `operation.started`, `host.changed` for a transition a tool makes, and `account.changed` for one a tool makes are told by the tools (`D07-tools`); `operation.finished` by the operations engine (`D10-operations`), except a `place` that `remove_account` cancels, whose `operation.finished` the tool tells (`D07-tools`); `host.changed` and `account.changed` for every transition the engine makes by the engine, which also tells `host.silent` from its silence sweep and `resource.unexplained` from its stray scan; `host.synced` and `host.apply_failed` by the daemon endpoints from the report intake (`D13-daemon-endpoints`).

## The events

Every attribute is always present, empty when it does not apply; every value is a string unless noted. Keys are listed in the order each function takes them.

- `change.finished` — one per accepted call of a changing tool, whatever its ending: `tool`, `host`, `account`, `user`, `result` (`ok`, `refused` or `failed`).
- `operation.started` — an operation recorded: `operation` (its id), `kind`, `host`, `account` (empty for a host kind).
- `operation.finished` — an operation that ended: `operation`, `kind`, `host`, `account`, `status` (`done`, `failed` or `cancelled`), `reason` (empty when done or cancelled; the `cloud.Error` text or a reason constant of `D10-operations` when failed).
- `host.changed` — every stored change of a host's state: `host`, `from` (empty for a host just created), `to`, `operation` (the operation that made it).
- `account.changed` — every stored change of an account's state, and its removal: `account`, `host`, `from` (empty for an account just created), `to` (`removed`, `AccountRemoved`, when its row is deleted).
- `host.silent` — a running host whose daemon has not reported for `store.SilentAfter`: `host`, `applied` (int64, the version it last applied).
- `host.synced` — a report applying the current version after the host was silent or failing to apply: `host`, `applied` (int64).
- `host.apply_failed` — a report carrying an apply error when the host was not already marked so: `host`, `attempted` (int64, the version the daemon tried).
- `resource.unexplained` — a tagged AWS resource no host record explains, told once when first seen: `resource` (its id), `kind` (`instance`, `volume` or `address`), `host` (its `Host` tag, empty when it has none).

The time is the event's own `Time`, from the writer's clock; the caller is the event's `User` and its request id the event's `RequestID`, both from the `identity.Caller` on the context the function is handed. A tool call's events carry that call's caller. The engine tells an operation's events, and the state changes it makes, under the caller stored with the operation (its user id and request id), as gdrive tells background work; the silence sweep, the report intake and the stray scan tell theirs with no caller, so their `User` and `RequestID` are empty. No attribute repeats the user or the request id.

## Secrecy

The trail carries names, ids, states, versions, tool names, results, reasons, methods, paths, statuses and times. No event carries a caller's email, a key or any part of one, a key's comment, AWS's message text (`cloud.Error`'s text is service, operation, subject and code only, `D05-cloud`), a report's body or its error text, or a desired state. The functions take no argument that could carry one: `host.apply_failed` takes the attempted version, not the error. The rule is proved at the run seam, by use, under secrecy conditions: every email and every key a test sends holds a random marker, and every capture of the run is searched for every marker.

## Recorded decisions

- **`change.finished` keeps its name and its three results; the `group` attribute is replaced by `host` and `account`** (departure from accounts' previous trail, which had `tool`, `group`, `user`, `result`): groups are gone, and a change now names the host and the account it touched. A query for one tool's changes still filters on `tool`. Expand-then-contract does not apply to the trail: an event recorded is history, not an interface a later release reads.
- **One name per kind of fact, not per tool** (`<thing>.<past>`, the suite's form, `operation.started|finished` after gdrive's `transfer.started|finished`): an operation's start and end are separate events because its end can be minutes later and under the engine, not the tool.
- **Trail only, no bus** (as sites' and ledger's trail-only names): outcome 15 says recorded in telemetry; no sibling consumes these, and joining the bus is a decision for a later release.
- **`host.changed` and `account.changed` for every stored state change, told by whoever made it**: the tools for the transitions their writes make (a host created `provisioning`, `running` to `stopping`, `failed` back to its operation's state on retry, an account created `pending`, an account to `removing`), the engine for the rest. One rule, every change told once, by the code that committed it.
- **Health events are edge-triggered**: `host.silent`, `host.synced` and `host.apply_failed` are told when the host's stored alarm changes (`D04-store`), never once per report or per sweep, so a host silent for a day records one `host.silent`.
- **`resource.unexplained` is told once per resource**, when the stray table first notes it (`D04-store`, `D10-operations`); it is never deleted or tagged, only reported.
- **`Result` takes the refusal errors as arguments** (departure from the previous `Result(err) string`): the trail imports nothing of accounts' own (plan's import order), so it cannot name `store.ErrTaken` or `valid.ErrName` itself; the tools pass the errors they treat as refusals, and the classification stays one function.
- **The value constants live here**: `AccountRemoved` for `account.changed`'s `to` and the three resource kinds, so the engine and the tests spell them once. Operation statuses and kinds are the store's words (`D04-store`), passed through.
- **The caller is the event's `User`, not an attribute**, as before: appkit's writer stamps every event from the context.
- The functions take plain values, not records, so the trail's contract does not move when a record gains a field; the run-level requirements and `D07-tools`, `D10-operations` and `D13-daemon-endpoints` prove the right values are passed.
- **The run-level promises are bounded to a clean run**, as before: every answered request leaves its pair, and every accepted change its `change.finished`, when the sink delivers without delay, serving does not fail before the stop signal, and no request is cut off at the drain deadline (`D03-serve`).
- Markers are compared without regard to letter case.

## Consumer usage

A tool, after its store write commits (`D07-tools`): `trail.HostChanged(ctx, w, "host01", "", store.HostProvisioning, op.ID)`, `trail.OperationStarted(ctx, w, op.ID, store.OpCreate, "host01", "")`, then `trail.Change(ctx, w, tools.ToolCreateHost, "host01", "", "", trail.ResultOK)`; a refusal by the store, `trail.Change(ctx, w, tools.ToolCreateAccount, "host01", "acme", "", trail.Result(err, store.ErrTaken, store.ErrConflict, store.ErrNotFound))` (every store guard error matches `ErrConflict` or, for `ErrNotInAccount` and `ErrKeyNotHeld`, `ErrNotFound`, so all classify as refused).

The engine (`D10-operations`), under `identity.NewContext(ctx, op.Caller)` (`D04-store`'s `Operation.Caller`): `trail.HostChanged(ctx, w, h, store.HostProvisioning, store.HostRunning, op.ID)`, `trail.OperationFinished(ctx, w, op.ID, op.Kind, h, "", store.OpDone, "")`, `trail.AccountChanged(ctx, w, "acme", h, store.AccountRemoving, trail.AccountRemoved)`; with no caller, `trail.HostSilent(ctx, w, h, applied)` and `trail.Unexplained(ctx, w, "i-…", trail.ResourceInstance, "host03")`.

The report intake (`D13-daemon-endpoints`): `trail.HostSynced(ctx, w, h, applied)` or `trail.HostApplyFailed(ctx, w, h, attempted)` from `store.RecordReport`'s transition.

A unit test builds a writer with `telemetry.New(telemetry.Config{Service: "accounts", Sink: capture, Now: now, Rand: rnd})` over a `*telemetry.Capture`, calls each function under `identity.NewContext(ctx, identity.Caller{UserID: u, Email: e, RequestID: q})` and under a context with no caller, flushes, and compares each captured event's `Name` with the constant, its `Attrs`, `RequestID` and `User`. A run-level test drives `cli.Run` in sandbox mode (`IKIGENBA_SANDBOX` through `LookupEnv`, no hosts variables) with a capture as `Sink`, calls tools with `mcp.Client`, requests pages, and checks the closed set, the request pair, the change events per call, and the markers.
