# D01-layout-and-run-seam

accounts keeps the business groups and the SSH users of the one host it runs on: one Go binary behind the host's nginx that makes every change on the host by running `opsctl` through `sudo`, keeps its own record of the groups and users it created, records every change in telemetry's trail, offers thirteen MCP tools at `/mcp`, its only API, and serves a read-only landing page, a tools page, an about screen and the not-found page to a signed-in user (outcome 1). The **host** is reached only through `internal/host` (`D05-host`); the **record** lives in the app's own SQLite database, `state/accounts.db` (`D04-store`). It emits nothing on the bus and accepts nothing from it. Among its siblings it calls none, and outside the suite it reaches only the host, by running one command. Outcomes cited as outcome N are those of /home/mgreenly/Documents/ikigenba-accounts.md.

This design is the structural ground the others stand on: where the code lives and what each package is for, the seam through which the process is run so every part can be tested without a real process, the settings and how they are read, how the host is chosen, the database path, where the identity and the display string come from, the binary's wiring, and the rule that accounts calls no sibling. It follows the suite's app layout less what accounts has no use for: no bus, no sibling client, no guest route, no address package.

The module is `github.com/ikigenba/ikigenba/accounts`, rooted at the sub-project directory, with `go.mod` beside `specs/`. Its `main` package sits at `cmd/accounts`, because `devctl build` finds an app as a `package main` in `cmd/<app>` under the directory that holds `etc/manifest.toml`. `cmd/accounts` is wiring only.

## The dependencies

accounts depends on one module besides the standard library: appkit, required at a published release with no `replace` directive. Its `db` package brings the pure-Go SQLite driver, which keeps the release build cgo-free. accounts uses appkit's `db`, `version`, `services`, `page`, `paging`, `identity`, `mcp` and `telemetry`, and restates none of their contracts. It uses neither `events` nor any sibling client.

## Where the environment is read

`main` makes the one read of the environment that is not `Run`'s own: it calls appkit's `version.Read` exactly once, first, and holds the result, the **identity**, whose `String()` is the **display string**. It hands the identity to `page.New`, whose banner carries its `Release` and `Commit` to every page's footer and to the about screen, and the display string to the `mcp.ServerConfig` its `Process.MCP` builds and to `Run` as `Process.Version`. Nothing below `main` calls `version.Read`.

`Run` reads every variable through `Process.LookupEnv`: `DRAIN_SECONDS`, `ACCOUNTS_HOST_COMMAND` and `IKIGENBA_SANDBOX` once at start, through `settings.Read`; `LISTEN_PID`, `LISTEN_FDS` and `NOTIFY_SOCKET` for the socket and readiness; and `IKIGENBA_SERVICES` once, when it starts to serve. That is the whole set of seven. appkit's constructors also read `IKIGENBA_SERVICES` from the process environment; that read is appkit's.

## Packages

The root package, named `accounts`, holds what the module embeds: `Assets` (the four templates `about.html`, `landing.html`, `notfound.html` and `tools.html`), `Etc` (`manifest.toml` and `nginx.conf`) and `Migrations` (`0001_accounts.sql`, whose bytes `D04-store` states). `share/icon.svg` is packed beside `bin/` and `etc/` by `devctl build` and is not embedded (`D09-on-a-space`).

The internal packages hold the concerns, one each; the document named declares each package's shapes and their behavior:

- `internal/cli`: the run seam, `cli.Process` and `cli.Run` (this document); the command, the exit codes, `cli.Manifest` and `cli.Usage` (`D02-cli`); the serve path (`D03-serve`); `cli.NginxConf` (`D09-on-a-space`).
- `internal/settings`: the settings, `DRAIN_SECONDS`, `ACCOUNTS_HOST_COMMAND` and `IKIGENBA_SANDBOX`, and the host command they choose (this document).
- `internal/server`: a listener's life (`D03-serve`).
- `internal/web`: the route table, `web.Config` and `web.Handler` (`D03-serve`).
- `internal/host`: the host seam, the `Host` interface, the command host and the in-memory host (`D05-host`).
- `internal/store`: the record of the groups and users accounts created, and the migration (`D04-store`).
- `internal/trail`: the telemetry trail of every change (`D08-trail`).
- `internal/pages`: the templates' data and the page routes, `pages.Handler`, `pages.Config`, `pages.Description`, and the auth and sign-in addresses (`D06-pages`); `pages.ServiceName` (this document).
- `internal/tools`: the thirteen tools, `tools.Register` and `tools.Config`, their descriptions and refusals (`D07-tools`).

There is no events package: accounts emits no bus event and accepts none. Which package imports which is guidance, not contract. Template data types, tool argument and result types, copy constants and the constants a package uses only itself are declared by the document that owns the package's behavior, not here.

## The run seam

The run seam is `cli.Run`, which takes a context and a `cli.Process` carrying everything the program would otherwise take from the `os` package, and returns the exit code. accounts reaches no sibling, so `Process` carries no client and no sibling's address, and the host is not a field: a test names a stub program in `ACCOUNTS_HOST_COMMAND` through the `LookupEnv` it gives `Run`. `Now` is the clock every time accounts stamps is read from: a group's and a user's created time, read by the store (`D04-store`), and every event's time. `Sleep` is the pause the writer waits with between delivery attempts. `Rand` is the source of every request id the run mints; accounts mints no id of its own. `Inherit`, `Now` and `Rand` are the caller's to give whenever `Args` is empty: `Run` has no default for any of them, and the choice of the process's own descriptor 3, `time.Now` and `crypto/rand.Reader` is made once, at the process boundary, by `cmd/accounts`. Telemetry's socket reaches `Run` through the services file `IKIGENBA_SERVICES` names (`D03-serve`).

## Settings

accounts reads three values at start. `DRAIN_SECONDS`, the space's, is how long a stopping server waits for requests in progress (`D03-serve`); unset or empty it is 5 seconds, spelled as opsctl writes an integer, and refused otherwise, as every app of the suite reads it. `ACCOUNTS_HOST_COMMAND` names the command the host is reached by: a command line split into fields on white space, the first the program and the rest leading arguments (`D05-host`); it is never refused. `IKIGENBA_SANDBOX` is set by the sandbox and never in production; accounts asks only whether it is present, whatever its value, as the suite does.

## Choosing the host

`Settings.HostFields` states the rule. When `ACCOUNTS_HOST_COMMAND` holds a character that is not white space, the host is the command host over its fields, sandbox or not. When it is unset, empty or only white space and `IKIGENBA_SANDBOX` is present, the host is the in-memory host, new and empty for each run. Otherwise the host is the command host over the fields of `host.DefaultCommand`. `Run` builds one host and every tool and every page of the run reaches that one; it builds one store, over the database, and every tool and page reads that one.

## Paths

Relative to `Process.Dir` (the process's working directory when empty) the database is `state/accounts.db`, opened with `db.Open`, the root package's `Migrations()` and `Process.Now`; `state/` is created when absent. accounts writes nothing outside `Dir` and nothing under it but the database.

## What reaches the server, the tools and the pages

`Run` hands `web.Handler` (`D03-serve`) one `web.Config` holding the banner source, the MCP server, the services file's path, the store, the host, the writer and the settings. From it the tools take the store, the host and the writer (`tools.Config`, `D07-tools`), and the pages take the banner source, the template set, the services file's path, the store, the host and the MCP server whose tools the tools page lists (`pages.Config`, `D06-pages`). No consumer holds a clock of its own: the store stamps created times with the `Now` it was built with and the writer stamps events with its own. Those three documents declare the fields; this one fixes only what reaches them.

## Siblings and the outside

accounts calls no sibling; telemetry is reached through appkit's sink, as every app reaches it. Outside the suite it reaches only the host, by running the command the settings chose (`D05-host`). The design makes this observable at three seams: `cli.Process` has no HTTP client and no sibling address; `Run` looks up no variable but the seven this document names; and a `Run`-level test that names every sibling in the services file, each on a listener that records every connection, exercises every tool and page and proves none is reached.

## Recorded decisions

- **No events package and no `EventSink`** (brief, settled 8): accounts emits and accepts no bus event, so `Process` has no `EventSink`, `trail` holds only telemetry events, and the manifest declares no `[events]`.
- **`Rand` stays** although accounts mints no id: appkit's writer and request middleware draw request ids from it, and the test discipline injects it.
- **`IKIGENBA_SANDBOX` is read, and present means set**: present whatever its value, empty included, as the suite's other reader treats it; the sandbox sets it to the space's name. It matters only when `ACCOUNTS_HOST_COMMAND` is blank, so a test's stub always wins.
- **A blank `ACCOUNTS_HOST_COMMAND` counts as unset**, matching `host.Fields`, where an empty or all-white-space value is the default command.
- **The host command is a setting**: `ACCOUNTS_HOST_COMMAND` and `IKIGENBA_SANDBOX` join `DRAIN_SECONDS` in `settings.Settings`, and `Settings.HostFields` answers the fields the command host runs or nil for the in-memory host, so the choice is proved by use at the settings seam, the default included, without running a real `sudo`. At `Run` level the command and in-memory cases are proved through tool calls; the default case is proved by the exec'ing test, which composes the child's environment whole: with neither variable set and `PATH` naming only a directory holding a stub `sudo`, the stub stands in for `sudo` and receives the default command's arguments, so no real `sudo` runs.
- **The value is a command line, not a path**: `AGENTS.md` speaks of the command's path; the brief's settled value is a command line split on white space, and that governs.
- **No `Process.Host`**: the host reaches `Run` only through the environment, so the binary and a test take the same path; code below `Run` takes a `host.Host` in its config (`D06-pages`, `D07-tools`).
- `Process.Inherit`, `Process.Now` and `Process.Rand` are required whenever `Args` is empty; no requirement states the precondition, because no permitted test can observe a default.
- **`Migrations` names its one file here**, `0001_accounts.sql`, whose bytes `D04-store` states.
- **The exec'ing test calls `create_group` and `groups`** against a stub named in `ACCOUNTS_HOST_COMMAND`, and once against a stub `sudo` found through a `PATH` it composes, so the binary never reaches a real host command.
- **Host calls are not counted**: the `Run`-level and binary requirements ask that the stub receive the change's arguments, not that a tool runs the host exactly once, so whether a change also reads a list is `D07-tools`' to decide.
- **`pages.ServiceName` is declared here**: `main`, the banner kit, the MCP server, the database and the manifest all need the name; `pages.Description` stays `D06-pages`'.

## Consumer tasks

`main` calls `id := version.Read()` and `v := id.String()` and hands `cli.Run` a `cli.Process` whose `Args`, `LookupEnv`, `Unsetenv`, `Pid`, `Stdout` and `Stderr` are the real process's, whose `Version` is `v`, whose `Banner` is `page.New(pages.ServiceName, id).Banner`, whose `Inherit` takes the process's own descriptor 3, whose `Now` is `time.Now`, whose `Rand` is `crypto/rand.Reader`, and whose `MCP` returns `mcp.NewServer(mcp.ServerConfig{Name: pages.ServiceName, Version: v, Telemetry: w})` over the writer `w` it is given, leaving the rest zero; it cancels the context on `SIGTERM` or `SIGINT` with a cause whose `Error` is the signal's name, and exits with what `Run` returns.

`internal/cli`, serving, reads `s, err := settings.Read(p.LookupEnv)`; builds `h := host.NewCommand(f)` when `f := s.HostFields()` is non-nil and `h := host.NewMemory()` when it is nil; opens `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "accounts.db"), Migrations: accounts.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: p.Stderr})`; builds `st := store.New(d, store.Config{Now: p.Now})` and the writer `w := telemetry.New(telemetry.Config{Service: pages.ServiceName, Version: p.Version, Sink: sink, Stderr: g, Now: p.Now, Sleep: p.Sleep, Rand: rnd})`, `g` being a gate over `p.Stderr` that passes lines until `Run` closes it, once the writer is shut down, and drops them after, so nothing reaches `p.Stderr` after `Run` returns (`D03-serve`); and hands `web.Config` the banner, `p.MCP(w)`, the services path, `st`, `h`, `w` and `s`, and `s.Drain()` to `server.Serve` (`D03-serve`).

A test of the run seam builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` over a map whose `ACCOUNTS_HOST_COMMAND` names a `/bin/sh` stub it wrote, or which leaves it unset and holds `IKIGENBA_SANDBOX`, an `Inherit` returning a listener it bound, a `Now`, a `Sleep` and a `Rand` it controls, and a `*telemetry.Capture` as `Sink`; calls `cli.Run`, waits for `READY=1`, drives `/mcp` with `mcp.Client` and the pages with raw HTTP, cancels, and inspects `Dir`, the stub's record and the capture. A test of settings calls `settings.Read` with a lookup over a map and compares `HostFields()` with `host.Fields`.
