# D03-serve

The serve path: what happens between `cli.Run` being called with no arguments and the process being gone, the terms accounts serves on, the listener's life, and the route table its one handler keeps with the identity each route takes. It is the suite's app serve path less everything accounts has no use for: no sibling client, no bus paths, no guest route. The identity gate keeps the suite's shape (appkit's `identity.Optional` before the pages and the shared files, `identity.Require` at `/mcp`), while the manifest's `guests = false` has nginx gate every path as well. This document declares `internal/server` and `internal/web`. Outcomes cited as outcome N are those of /home/mgreenly/Documents/ikigenba-accounts.md.

`D01-layout-and-run-seam` declares the run seam (`cli.Process`, `cli.Run`), the settings (`settings.Settings`, `settings.Read`, `Drain()`, `HostFields()`), the choice of host, the database path, `pages.ServiceName`, the identity and display string of a run, and the root package's `Migrations()`; `D02-cli` the exit codes (`ExitSuccess`, `ExitUsage`, `ExitServerFailed`) and the manifest; `D04-store` the store (`store.New`, `store.Config`); `D05-host` the host (`host.Host`, `host.NewCommand`, `host.NewMemory`); `D06-pages` the pages (`pages.Handler`, `pages.Config`), the sign-in redirect a guest gets and the addresses it is built on; `D07-tools` the tools (`tools.Register`, `tools.Config`) and their answers; `D08-trail` the trail, `service.started` and `service.stopping` among it; `D09-on-a-space` the manifest's `guests = false`, the nginx fragment and the environment. appkit's `db`, `telemetry`, `identity`, `page`, `mcp` and `services` packages own their contracts; this document wires them and restates none of them.

## The services file

`IKIGENBA_SERVICES` names the services file. accounts uses two of its entries: `auth`, read afresh per request by the pages for the banner's links and a guest's sign-in address (`D06-pages`), and `telemetry`, appkit's sink's, which reads the file afresh on each delivery. accounts builds no sibling client, so `Run` reads nothing from the file at the start: it hands the path on. With `IKIGENBA_SERVICES` unset, naming no file, or naming one `services.Read` refuses, the start is not refused and accounts serves as with a file holding no entry; the pages then build their addresses on the request's scheme and host (`D06-pages`). A changed `auth` entry reaches the next page request.

## The terms accounts serves on

accounts serves only on a listening socket it inherits, taken as `sd_listen_fds(3)` documents, and reports readiness with `READY=1` to `NOTIFY_SOCKET` as `sd_notify(3)` documents. It trusts `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx sets them, and trusts the MCP gateway to have forwarded them (`D09-on-a-space`). Every request has an id: the one nginx or the caller set, or one appkit's telemetry middleware draws from `Process.Rand`.

The manifest declares `guests = false`, so nginx admits no request without a credential, to the pages and to `/mcp` alike. A request with no `X-User-Id`, or an empty one, is a **guest**, whatever `X-User-Email` it carries; on a host none reaches accounts, and the handler still answers one as below.

## The route table

Every request goes through appkit's `telemetry.Middleware` over `Config.Telemetry`, which records the request pair (`D08-trail`) and puts the request's caller on its context. Then, by `URL.Path` alone, compared by hand, so nothing is cleaned and nothing redirected:

- exactly `/mcp`: `identity.Require`, then the MCP server `Config.MCP`, on which the tools of `D07-tools` are registered with `tools.Register` once, when the handler is built. A guest is answered `identity.Require`'s 500 with `identity.MissingBody`, which on a host never happens because nginx demands a credential first.
- a path beginning `/_appkit/`: `identity.Optional`, then `page.Static()`; nothing there is private.
- every other path: `identity.Optional`, then the page handler, `pages.Handler` over `pages.Config` (`D06-pages`), which sends a guest a 302 to the sign-in address and draws the page for a signed-in user. So `/`, `/about`, `/tools`, and `/nope`, `/mcp/`, `/events` and `/_appkit` all reach it.

There is no guest route and there are no bus paths: accounts emits no bus event and accepts none, so `/events` and `/declarations` are paths like any other. Only `/mcp` changes anything: a page reads the host's lists and the store, and changes neither (outcome 1). No answer on any route carries `Set-Cookie`.

The handler is built from a `web.Config` carrying what its routes need: the banner source, the MCP server, the services file's path, the store, the one host, the writer and the settings. `web.Handler` builds the page handler and the tool registration from it, both over the same store and the same host; which fields each of `pages.Config` and `tools.Config` takes is that document's.

## The start

With `Args` empty, `Run` checks the settings (`D01-layout-and-run-seam`), then whether exactly one socket was passed in, with the diagnostics below. It removes the three `LISTEN_*` variables, takes descriptor 3, chooses the host (`D01-layout-and-run-seam`), and opens the database with `db.Open` at `state/accounts.db` with `accounts.Migrations()` and `Process.Now`; a failure is `accounts: cannot open database state/accounts.db: ` and the reason, exit 1. It builds the store with `store.New` over `Process.Now`, the run's writer, records `service.started`, so that it is the first event of every run, builds the handler, calling `Process.MCP` once with the writer, sends `READY=1`, and serves. Nothing is read from the host or the store at the start: accounts works nothing in the background.

## Stopping

When `ctx` is done (in the binary, on `SIGTERM` or `SIGINT`, the signal's name being the cause) `Run` drains the server for `DRAIN_SECONDS` (`settings.Settings.Drain()`), shuts the writer down with the cause's text as `service.stopping`'s reason, and closes the database. From shortly after the drain deadline on, `Run` hands the sink nothing: an event not handed to it by then is never handed to it, and reaches standard error, if at all, only as appkit's `undelivered event` line, and only before the drain line; after the drain line `Run` writes nothing more to standard error, not even after it returns. A drain that runs out on requests is `accounts: stopped with <n> request(s) unfinished`, exit 1. Serving that fails before `ctx` is done, as when the listener's `Accept` fails, is `accounts: ` and the error, exit 1. A request still in progress when the drain runs out has its context done, so a host command it runs is ended (`D05-host`) and is not waited for beyond the deadline.

## The binary

The one exec'ing test proves the wiring of `cmd/accounts`. `D01-layout-and-run-seam` states what the binary does at the start (it creates `state/accounts.db` in its working directory, keeps what it records across runs, carries the display string in `serverInfo` and `service.started`, carries the release and commit to the about screen) and that `SIGTERM` stops it cleanly; this document adds the bare start with no socket and the stop on `SIGINT`.

## Recorded decisions

- **`internal/server` is the suite's, unchanged**: one function and one error type, declared here because `D01-layout-and-run-seam` assigns the listener's life to this document.
- **Pages use `identity.Optional` and a 302 to sign in, and the manifest says `guests = false` so nginx gates too** (brief, settled 7). `identity.Require` sits at `/mcp` alone, so a guest that reaches a page anyway is sent to sign in by the page handler (`D06-pages`) rather than answered a 500.
- **No guest route and no bus paths.** accounts has no record a visitor without a credential may reach, and it neither emits nor accepts a bus event, so no path sits outside identity and `/events` and `/declarations` are the page handler's like any other path.
- **`/_appkit/` goes through `identity.Optional`**: the shared files are not private, and the wrapper changes no answer.
- **`web.Config` carries the one `host.Host`** in place of a sibling client and an emitter: the tools change the host and the pages read it, and both must see one host (`D01-layout-and-run-seam`, R-PGO7-YBVB), so the run builds it once and the handler hands the same value to both.
- **`web.Config` carries the settings whole**, though the handler reads none of them; a setting a handler needs later is added to `settings` without reshaping `web.Config`.
- **`web.Config` carries no clock and no random source**: every created time is the store's `store.Config.Now` (`D04-store`), the writer holds its own, and accounts mints no id of its own.
- **`Run` reads nothing from the services file at the start**: it builds no sibling client, so the file is read only by the pages, per request, and by appkit's sink, per delivery. A missing or unreadable file never stops the start.
- **The `/mcp` server's identity is `main`'s**: `Run` mounts the server `Process.MCP` returns and builds none itself; `main` names it `pages.ServiceName` with the display string (`D01-layout-and-run-seam`, R-DJ49-440R). This document requires only that `Run` calls `MCP` once with the run's writer and mounts what it returns.
- **The drain line is the last line on `Stderr`, though a cut-off request may still record an event.** appkit's writer, once shut down, writes an event recorded through it to its `Stderr` as an `undelivered event` line at once, from the goroutine that records it; a request cut off at the drain deadline records its `request.finished` whenever its handler ends, which may be after the drain line. `Run` meets R-UXXX-WNEY, which forbids any line after the drain line even once `Run` has returned, by handing the writer a `Stderr` of its own that passes lines to `Process.Stderr` until `Run` closes it, and drops them after. `Run` closes it on every return once the writer is shut down, before the drain line when there is one, so that an event recorded after `Run` returns writes nothing, a clean stop included (R-EJOM-URNY). A serving failure before `ctx` is done (an `Accept` error) is the third way out: `accounts: ` and the error's text, exit 1 (R-AESO-HDDX); the gate is closed before that line too, so nothing follows it, even after `Run` returns, and `server.Serve` answers that failure with an error that is not a `*server.DrainError` (R-MY4W-C8QN).
- **The start's answer to a failing database after `db.Open` is not required.** The start reads nothing from the store before ready; a store failure is provoked only on a handle a test hands in, which `cli.Run` never takes. What a page or a tool answers over a failing store is `D06-pages`' and `D07-tools`'.
- **The binary's bare start and `SIGINT` are stated here**, beside the `Run`-level requirements they exercise; the binary's other serve expectations are `D01-layout-and-run-seam`'s.

## Consumer tasks

`Run`, serving, calls `s, err := settings.Read(p.LookupEnv)`, checks the socket, unsets the three `LISTEN_*` variables and takes `ln, _ := p.Inherit(3)`; builds the host from `s.HostFields()`; opens `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "accounts.db"), Migrations: accounts.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: p.Stderr})`; builds `st := store.New(d, store.Config{Now: p.Now})` and `w := telemetry.New(...)`, the writer's `Stderr` being a gate over `p.Stderr` that passes lines until it is closed and drops them after; reads the path `IKIGENBA_SERVICES` names; calls `w.Ready()`; builds `hd := web.Handler(web.Config{Banner: p.Banner, MCP: p.MCP(w), ServicesPath: path, Store: st, Host: h, Telemetry: w, Settings: s})`; sends `READY=1`; and calls `server.Serve(ctx, ln, hd, s.Drain(), stop)`, `stop` calling `w.Shutdown(c, context.Cause(ctx).Error())`; closes the gate once `server.Serve` has returned, however it returned; answers a `*server.DrainError`, after closing the gate, by writing `accounts: ` and its text, `ExitServerFailed`; closes `d`.

`web.Handler(cfg)` calls `tools.Register` once over `cfg.MCP` and a `tools.Config` built from `cfg`'s store, host and writer, builds `pages.Handler` over a `pages.Config` built from `cfg`'s banner, services path, store, host and MCP server, mounts `identity.Require(cfg.MCP)` at `/mcp`, `identity.Optional(page.Static())` under `/_appkit/` and the page handler, `identity.Optional` over `pages.Handler` (`D06-pages`), everywhere else, and returns `telemetry.Middleware(cfg.Telemetry, mux)`.

A test of the handler builds `web.Handler` over a store on its own database, `host.NewMemory()` or `host.NewCommand` over a stub it wrote, a writer over a capture, a server from `mcp.NewServer` and `settings.Defaults()`, serves it with `httptest`, and sends raw requests with the identity headers set or left out, and `/mcp` calls through `mcp.Client`. A test of the start drives `cli.Run` with a listener, a `NOTIFY_SOCKET` it binds, a `Now`, a `Sleep` and a `Rand` it controls, an `ACCOUNTS_HOST_COMMAND` naming a stub (one that blocks on demand, for the drain), a services file whose `auth` entry names a URL of its own; waits for `READY=1`; drives `/mcp` with `mcp.Client` and the pages with raw HTTP; rewrites the services file; cancels; and inspects the stub's record, the capture, the streams and the exit code. The exec'ing test runs the binary bare with no socket, and serving, stops it with `SIGINT`.
