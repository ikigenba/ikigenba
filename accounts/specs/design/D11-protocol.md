# D11-protocol

The daemon protocol: the wire between accounts and `accountsd`, the daemon on every host. A host's daemon pulls one document, the host's desired state, applies it, and posts back one report. This document owns package `internal/protocol`. It holds the paths, the two JSON documents and their member types, the size limits, the long-poll duration, the daemon's version form, the decoders both sides use, and the rule by which the protocol changes from one release to the next (outcome 23 of ikigenba-ssh-hosts.md). It also owns the report's schema (outcome 24's schema half). `protocol` imports no other package of accounts. It sits at the bottom of the import order, so both `internal/daemonapi` (`D13-daemon-endpoints`), which serves the protocol, and `internal/daemon` (`D14-accountsd`), which speaks it, import it without either importing the other. That is why `LongPoll` is declared here and not in either of them.

## The three paths

`BinaryPath` (`/accountsd`) serves the daemon's own binary, unauthenticated. `StatePath` (`/accountsd/v1/state`) answers the host's desired state, by long poll, with the query members `QueryAfter` and `QueryDigest`. `ReportPath` (`/accountsd/v1/report`) takes the report. What each answers, and when, is `D13-daemon-endpoints`'. How a request proves which host it comes from is `D12-host-identity`'s. The path constants are declared here so that the server and the client spell them from one place.

## Desired state

`DesiredState` is the whole document for one host. It holds the protocol number, the host's name, the host's version, the digest of the daemon binary accounts serves, the data volume's EBS id, the root and data sizes, the accounts placed on the host and their users. accounts builds it from its record (`D04-store`'s `Desired`, which also states the order: accounts by slug, users by name, keys sorted); `D13-daemon-endpoints` fills `Daemon`. An account is `active` or `removed`. A pending account is sent as `active`, because the host must make its group before the account can turn active, and a failed one stays `active` until it is removed. A user is `active`, `locked` or `deleted`. The document is bounded by `D17-names-keys-sizes`' caps: at most 50 accounts and 200 users, each user with at most 10 keys of at most 512 bytes. That comes to about 1.1 MB, under `MaxStateBytes` (2 MiB).

## Report

`Report` is what the daemon posts each cycle. It carries the version the daemon tried (`Attempted`), the version it applied (`Applied`, 0 for none), the error of the attempt (empty on success), what the instance is, its load, memory and disks, its sessions, pending security updates and whether a reboot is wanted, its failed units, the use of each account slice, and the last sign-in of each user who has signed in. `D15-machine`'s `Inspect` collects the facts and `D14-accountsd` fills in the versions, the error and its own digest. `D04-store`'s `RecordReport` keeps the latest report. `D06-pages` shows it and `D07-tools`' `host` returns it. Three lists can grow with the host: the failed units, the slices and the sign-ins. `Bounded` sorts each one and caps it, and it caps the error text, so a report is canonical and small on both sides. `DecodeReport` applies `Bounded`, so accounts never keeps more than the caps, whatever a daemon sends.

## Decoding

`DecodeState` (the daemon's) and `DecodeReport` (accounts') read one document from a body. Neither reads past its limit plus one byte. Each refuses three things: a body over its limit (`ErrTooLarge`), anything that is not exactly one JSON object of the right shape (`ErrMalformed`), and a `protocol` member other than `Version` (`ErrVersion`). Unknown members are ignored, absent members and members whose value is `null` read as their zero values, and member names match as `encoding/json` matches them (without regard to case, the last duplicate deciding). That is the standard decoder's behaviour, accepted rather than replaced by a stricter one. The state decoder also refuses a document with no host or a version below 1. It never judges an enumerated value such as an account's or a user's state. A daemon that cannot decode a document changes nothing, and that includes not updating itself. A decoder that refused a new state word would therefore strand every old daemon. What a daemon does with a word it does not know is `D15-machine`'s concern.

## The daemon's version

The daemon's version is the digest of its binary: `sha256:` followed by 64 lowercase hex digits. devctl builds a release with no `-ldflags`, so the binary cannot know which release it belongs to. A digest also tells a rollback apart from an upgrade. `Digest` computes it by streaming the bytes through one buffer of at most `DigestBuffer` bytes. accounts digests the binary it serves (`D13-daemon-endpoints`), and the daemon digests its own executable (`D14-accountsd`). An empty `Daemon` member means "do not update".

## Changing the protocol: expand, then contract

Hosts and accounts upgrade at different times. The protocol therefore changes the way every interface between releases does in this repository (root `AGENTS.md`): expand, then contract.

- Both sides ignore unknown members and read an absent member as its zero value. The decoders here guarantee this for every member.
- A member is added by its producer in one release and relied on by its consumer in the next. It is removed in the reverse order: the consumer stops relying on it in one release and the producer stops sending it in the next. A new value of an enumerated member is a new member for this rule. Accounts sends a new user or account state only in a release after the one whose daemon knows it.
- `protocol` stays `Version` (1) for every change that can be made this way. A change that cannot be made this way adds `/accountsd/v2/…` beside v1 for at least one release. v1 is removed only in a later release, after every daemon has updated itself. Daemons update within one cycle of an accounts deploy, because the digest a waiting poll compares changes and the poll answers at once.
- The self-update channel is frozen forever: `BinaryPath`, `StatePath`, and the `protocol`, `host`, `version` and `daemon` members of v1 state. A daemon of any age can always fetch v1 state, find a new digest and fetch the new binary. `DecodeState` accepts a document made of only those four members, so contracting every other member can never strand a daemon.

This rule is process, not code. Its testable half is in the requirements: the decoders' tolerance, the frozen names, and the minimal document. The other half binds the authors of later releases.

## Bounded work

Each decoder reads at most its limit plus one byte, and holds the decoded document, which the caps bound. `Digest` holds one buffer of at most `DigestBuffer` (32 KiB) and the hash state, whatever the binary's size. `Bounded` keeps at most `MaxFailedUnits`, `MaxSlices` and `MaxSignIns` entries and `MaxErrorBytes` of error text. Each of these is a requirement below.

## Recorded decisions

- **Long poll of 45 seconds.** `LongPoll` sits under nginx's default `proxy_read_timeout` of 60 seconds (nginx's `ngx_http_proxy_module` documentation), which opsctl's generated server block leaves unset, with a 15-second margin for the apply that follows. It is declared here because both `D13-daemon-endpoints` (how long a poll waits) and `D14-accountsd` (its client timeout, `LongPoll + 15s`) depend on it, and neither may import the other.
- **Limits.** `MaxStateBytes = 2 MiB` is about twice the bounded document's worst case. `MaxReportBytes = 256 KiB` comfortably holds 200 sign-ins, 50 slices, 100 failed units and a 4 KiB error. `MaxBinaryBytes = 64 MiB` is several times a static Go binary built with the AWS SDK's STS and IMDS clients. `MaxErrorBytes = 4096` keeps a whole command diagnostic while bounding the page. `MaxFailedUnits = 100`. `MaxSlices = 50` and `MaxSignIns = 200` equal `D17-names-keys-sizes`' `MaxAccountsPerHost` and `MaxUsersPerHost`. They are restated here as wire bounds because `protocol` may import nothing; if those caps change, these change with them.
- **Typed decoders and `Bounded` in `protocol`.** They are additions inside this package. They give one definition of "a valid v1 document" for both sides, and of the caps accounts trusts. The sibling precedent is appkit's `paging` package, where one package owns both ends of a token.
- **Times as `time.Time`.** `Booted` and a sign-in's `At` are `time.Time`, so both sides use the standard JSON form (RFC 3339). A producer writes UTC to the second. An absent member decodes as the zero time, which the pages show as empty.
- **Version is a digest, not the display string** (a departure `D14-accountsd` records). Sibling apps report their version with appkit's `version` display string. accounts' daemon cannot: devctl's build stamps nothing into a binary, and a host must also tell a rollback from an upgrade. The digest does both.
- **Unknown enumerated values pass through.** If the decoder refused them, it would block the self-update that teaches a daemon the new value.

## Consumer usage

The consumer tasks that touch this surface, written against exactly these names:

- Daemon first boot (task 2): `D14-accountsd` digests its own executable with `protocol.Digest(f)` and requests `BinaryPath` and `StatePath + "?" + QueryAfter + "=0&" + QueryDigest + "=" + digest`. It reads the answer with `protocol.DecodeState(body)`, gets a `DesiredState` back, and changes nothing on `ErrTooLarge`, `ErrMalformed` or `ErrVersion`.
- Daemon applies and reports (task 3): the daemon fills `Report{Protocol: protocol.Version, Attempted: s.Version, Applied: …, Error: …, DaemonVersion: digest, …}` from `Machine.Inspect` (`D15-machine`), calls `r.Bounded()`, and posts it as `ContentJSON` to `ReportPath`. accounts decodes it with `protocol.DecodeReport(body)` (`D13-daemon-endpoints`), maps `ErrTooLarge` to 413 and the other two errors to 400, and records it (`D04-store`'s `RecordReport`).
- Users and accounts (tasks 4–6): `D04-store`'s `Desired` builds `DesiredState{Protocol: Version, Host, Version, DataVolume, RootGB, DataGB, Accounts: []Account{{Slug, GID, State: AccountActive}}, Users: []User{{Name, Account, UID, State: UserLocked, Keys}}}`. `D13-daemon-endpoints` sets `Daemon` to its digest and encodes the document with `encoding/json`.
- Self-update (task 13): the waiting poll answers when `QueryDigest` differs from accounts' digest. The daemon downloads `BinaryPath` up to `MaxBinaryBytes` and checks it against `DesiredState.Daemon`. Its next report's `DaemonVersion` equals `Daemon`.
- The report page (task 3): `D06-pages` builds its view from `Report`'s members (`Root`, `Data` as `Disk`; `Slices` as `[]Slice`), and `D07-tools`' `host` returns them.
