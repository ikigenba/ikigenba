# D17-names-keys-sizes

What accounts accepts as a name, a key and a size, decided in one place: `internal/valid`. It holds the rule for a user's login name and the narrower rule for an account's slug, the one reserved list both kinds are refused against, the parser of an OpenSSH ed25519 public key line, the instance types and volume sizes a host may have with the defaults a host gets when its creation names none, the rule for an IP address and an allowlist entry with the test of whether an entry covers an address, and the caps that bound one host's accounts, users, keys, pending unbans and allowlist entries. It imports nothing of accounts' own and holds no copy: every refusal a person or an agent reads is worded by the tools (`D07-tools`), which map this package's errors to their own constants. Outcomes cited as outcome N are those of /home/mgreenly/Documents/ikigenba-ssh-hosts.md; those cited as bans outcome N are those of /home/mgreenly/Documents/ikigenba-ssh-bans.md.

Who uses it: `D07-tools` checks every argument with it before the record is touched, `unban_ip`'s address with `Address` and `allow_ip`'s and `disallow_ip`'s with `AllowEntry`, and takes a host's defaults from it; `D04-store` bounds the rows of one host by its caps, keeps keys in the form `Key` gives them and refuses an address or entry that is not already canonical; `D11-protocol` sizes the desired-state document from the caps and `MaxKeyBytes` and restates the unban and allowlist caps on the wire; `D15-machine` writes the key lines `Key.Line` gives, refuses a state whose addresses or entries are not canonical, reads the bans' addresses with `Address` and lifts every ban an allowlist entry `Covers`, on a host and in the memory machine; `D16-sandbox` reads the addresses of its bans file with `Address`; `D06-pages` shows the defaults on the about screen.

## Names

accounts keeps one namespace of names: an account's slug and a user's login name are unique across both kinds and every host while the row exists (`D04-store`). The two kinds have different shapes because an account's slug is two things at once.

A **user name** is a Linux login name and nothing else: `Name` keeps the rule opsctl has always applied to user names, a lower-case letter or `_` first, then lower-case letters, digits, `_` and `-`, one to 32 bytes.

An **account slug** is a Linux group name, a service account name, a folder under `/srv` and the first label of the DNS name `<slug>.<hosts domain>` (outcome 12). `Slug` takes the intersection of the Linux rule and a DNS label (RFC 1035 §2.3.1, as RFC 1123 §2.1 relaxes it to allow a leading digit; accounts keeps the stricter leading letter that the Linux rule wants): a lower-case letter first, then lower-case letters, digits and `-`, never ending in `-`, one to 32 bytes. No `_` (not a hostname character), no upper case (DNS is case-blind and Linux names are not; one spelling avoids two accounts that read alike).

Both refuse a **reserved** name with `ErrReserved` after its shape passes, so the tools can say which refusal applies. One list serves both kinds, because a user name and a slug share the namespace: a user called `www` would block the account `www` as surely as the reverse. The list is the reserved DNS labels and the system names below, every name matching `^host[0-9]+$` (so no account ever reads as a host, `host01` and its successors), and every name beginning `_` (DNS service labels such as `_dmarc` and `_acme-challenge`).

## Keys

A key is one OpenSSH public key line, `ssh-ed25519 BASE64 [COMMENT]`, the form `authorized_keys` and `ssh-keygen -y` use. `ParseKey` accepts exactly the ed25519 type, its base64 body in the standard padded alphabet, decoding to the 51-byte wire form RFC 8709 §4 defines (the string `ssh-ed25519` and the 32-byte public key, each length-prefixed as RFC 4251 §5 `string`), and an optional comment. No options prefix, no other key type, no control character, at most `MaxKeyBytes` bytes. Two lines name the same key when type and body agree, whatever the comment (the identity opsctl's `key remove` used, and that `D04-store` keys rows by). `Key.Line` gives the canonical line the store keeps and the host writes: type, one space, body, then one space and the comment when there is one.

## Addresses

An **address** is one IPv4 or IPv6 address, the argument of `unban_ip` and what a host reports as banned. It reaches a command on the host (`fail2ban-client set sshd unbanip <address>`, `D15-machine`), so it is parsed strictly (bans outcome 6): `Address` accepts exactly what Go's `net/netip.ParseAddr` accepts, minus a zone, and gives the address in one canonical spelling, `a.Unmap().String()`: an IPv4-mapped IPv6 address becomes the IPv4 address it maps, and IPv6 is lower case and compressed (RFC 5952, as `netip` writes it). `ParseAddr` refuses surrounding white space, an IPv4 octet with a leading zero (`192.0.2.07`, which some parsers read as octal) and a CIDR, so `unban_ip` refuses a CIDR (bans outcome 6) with `ErrAddress`.

An **allowlist entry** (bans outcome 10) is an address or a CIDR prefix. `AllowEntry` tells them apart by the `/`: without one, it is `Address`; with one, `netip.ParsePrefix` reads it, an IPv4-mapped prefix of 96 bits or more becomes the IPv4 prefix of 96 fewer bits, a prefix wider than `MinPrefixIPv4` (IPv4) or `MinPrefixIPv6` (IPv6) is refused with `ErrPrefix`, apart from `ErrAddress`, so the tools can say which applies, and the rest is written masked to its network address (`192.0.2.77/24` is `192.0.2.0/24`), a full-length prefix (`/32`, `/128`) as the bare address it names. Two spellings of one entry thus have one canonical string, the identity `D04-store` keys entries by; entries that overlap but differ (`192.0.2.0/24` and `192.0.2.7`) are two entries.

An entry **covers** an address when it is that address or a prefix holding it. `Covers` answers this only for canonical strings, the form every list in accounts and on a host keeps, and answers false for anything else, so a caller never learns coverage of a spelling the store would not hold.

Each function holds one string and the parsed address or prefix; none allocates in proportion to anything but its argument.

## Sizes and caps

A host's type is one of `AllowedTypes`: the Graviton families the infrastructure's operator policy permits (`t4g`, `m7g`, `c7g`, `r7g`; the tag contract of the decisions log), from `t4g.small` and each family's `medium` up to `16xlarge`. No `nano` or `micro` (under 2 GiB of memory one person's 1 GiB ceiling, `D15-machine`, leaves no room) and no `metal`. Volumes are gp3 (`D05-cloud`) and only grow: root 20 to 100 GB (the root holds the OS only; 20 is the launch template's size and the default), data 10 to 1024 GB (above 1 TiB a modification can take hours; going there is an owner decision). Defaults, outcome 16: `t4g.medium`, 20 GB root, 50 GB data.

The caps bound everything that grows per host: 50 accounts and 200 users on one host, 10 keys per user, 50 unbans not yet applied (`MaxUnbansPerHost`, bans outcome 8) and 50 allowlist entries (`MaxAllowlistPerHost`, bans outcome 10). With `MaxKeyBytes` they bound the desired-state document `D11-protocol` sends (about 1.1 MB at the caps, under its 2 MiB limit; the unbans and entries, at most 43 bytes each as text, add a few KB), the report's sign-ins, and every per-host read the tools, the pages and the daemon endpoints make, as root `AGENTS.md`'s bounded-work rule asks.

The user-name rule and the key rule are opsctl's, unchanged, so an account that moves between the two keeps working.
- **Slugs are narrower than opsctl's name rule** (departure): opsctl's rule admits `_` and a trailing `-`, which a DNS label does not. The reason is outcome 12: a slug is a DNS label as well as a Linux name.

- **The lists are functions returning copies**, `ReservedLabels()` and `SystemNames()`, not package variables: a caller that appends to or sorts what it got cannot change what `Reserved` refuses.
- **`ParseKey`, not `Key`**, is the parser's name: Go cannot declare a function and a type both named `Key` in one package, and the type is the one other packages hold.
- **One `Name`/`Slug` call answers both shape and reservation**, shape first, so a tool asks once and words `ErrName`/`ErrSlug` and `ErrReserved` differently (`D07-tools`); `Reserved` is exported as well for the reserved list alone.
- **`Type`, `RootGB` and `DataGB` return errors** rather than booleans so the tools classify every argument refusal the same way and `D08-trail` can count all of this package's errors as refusals.
- **Errors carry no contract text.** Each `Err*` is a distinct sentinel, compared with `errors.Is`; what a person reads is `D07-tools`' copy.
- **Instance type list** (pick): `t4g.small`, `t4g.medium`, `t4g.large`, `t4g.xlarge`, `t4g.2xlarge`, then for each of `m7g`, `c7g`, `r7g` in that order `medium`, `large`, `xlarge`, `2xlarge`, `4xlarge`, `8xlarge`, `12xlarge`, `16xlarge`: every size of the four families the operator policy admits, minus the ones too small for one person's slice and the bare-metal sizes.
- **Bounds** (pick, outcome 16): root 20–100 GB, data 10–1024 GB, grow only (the growing rule is `D07-tools`' and `D10-operations`'; this package states the range).
- **Caps** (pick): 50 accounts per host, 200 users per host, 10 keys per user, 512 bytes per key line: generous for a small business's people on one host and small enough that one host's whole desired state fits one bounded document.
- **Ban caps** (the decisions document's picks, bans outcomes 6, 8 and 10): at most 50 unbans not yet applied per host and at most 50 allowlist entries per host; an allowlist prefix no wider than /24 for IPv4 and /48 for IPv6, so one entry never opens more than one site's network; a CIDR refused on unban. The caps live here beside the other per-host caps; `D11-protocol` restates them on the wire as it restates `MaxAccountsPerHost`.
- **Go's `net/netip` is the address grammar** (pick): it is the standard library, strict where strictness matters (no leading zeros, no white space, no zone in a prefix), and its `String` is RFC 5952's canonical form, so the check and the spelling come from one place. A zone (`fe80::1%eth0`) is refused because it names an interface of the machine that wrote it and fail2ban reports none.
- **IPv4-mapped addresses are unmapped** (pick): fail2ban reports an IPv4 client as dotted IPv4, so `::ffff:192.0.2.7` and `192.0.2.7` must be one address, or an unban and an allowlist entry could miss the ban they name. A mapped prefix shorter than /96 is not an IPv4 prefix and stays an IPv6 prefix, masked like any other (`::ffff:192.0.2.0/95` is `::fffe:0:0/95`), and covers only the IPv6 addresses it holds, never an IPv4 address, since `Address` never answers a mapped one; an odd entry, but no wider than `MinPrefixIPv6` allows.
- **A full-length prefix is the bare address** and every prefix is masked (pick): one entry, one string, so allowing `192.0.2.7/32` after `192.0.2.7` changes nothing, and a non-masked spelling never reaches the jail.
- **`Covers` answers false on a non-canonical argument** rather than canonicalising it: its callers hold canonical strings only (`D04-store` refuses any other, `D15-machine` refuses a state holding one), so a non-canonical argument is a caller's bug, and refusing coverage is the safe side.

Tests (in `internal/valid`, which `accounts/AGENTS.md` lists among its test files) call each function with the examples the requirements give and with keys built from 32 random bytes of the test's own source, encoded as the RFC 8709 wire form; no fixture holds an id-shaped literal.

## Consumer usage

`create_account{account: acme, host: host01}` (`D07-tools`): `if err := valid.Slug("acme"); errors.Is(err, valid.ErrReserved) { refuse ReservedName } else if err != nil { refuse InvalidName }`, then the store's checks against `valid.MaxAccountsPerHost`.

`add_user{account: acme, user: daffy, key: line}`: `valid.Name("daffy")` likewise; `k, err := valid.ParseKey(line)`; `errors.Is(err, valid.ErrKey)` refuses `InvalidKey`; the store keeps `k.Type`, `k.Body` and `k.Line()` (`D04-store`), bounded by `valid.MaxKeysPerUser` and `valid.MaxUsersPerHost`.

`create_host{}`: `typ := valid.DefaultType; root := valid.DefaultRootGB; data := valid.DefaultDataGB`, each replaced by an argument when given, then `valid.Type(typ)`, `valid.RootGB(root)`, `valid.DataGB(data)`; `resize_host{host, type: t4g.large, data_gb: 60}` the same checks, then grow-only against the host.

The about screen (`D06-pages`): `AboutData{…, DefaultType: valid.DefaultType, DefaultRootGB: valid.DefaultRootGB, DefaultDataGB: valid.DefaultDataGB}`.

`unban_ip{ip: "::ffff:192.0.2.7", host: host01}` (`D07-tools`): `ip, err := valid.Address(arg)`; `errors.Is(err, valid.ErrAddress)` refuses `InvalidAddress`; otherwise the store records `192.0.2.7`, bounded by `valid.MaxUnbansPerHost`.

`allow_ip{host: host01, ip: "192.0.2.77/24"}`: `e, err := valid.AllowEntry(arg)`; `ErrAddress` refuses `InvalidAddress`, `ErrPrefix` (`10.0.0.0/8`) refuses `PrefixTooWide`; otherwise the store keeps `192.0.2.0/24`, bounded by `valid.MaxAllowlistPerHost`. `disallow_ip` the same check. The store's own methods take only what these return: `c, err := valid.AllowEntry(entry); err != nil || c != entry` is an argument no consumer sends.

The daemon's cycle (`D15-machine`): for each banned address `a` it read, `c, err := valid.Address(a)`, and the ban is lifted when `err == nil && c == a` and `valid.Covers(e, a)` for some entry `e` of the state's allowlist: `valid.Covers("192.0.2.0/24", "192.0.2.77")` is true.
