# Decision 30 — Testing-language conformance: adopt the suite contract and normalize the live layer

**Decision.** dropbox adopts the suite testing-language contract
**`root project/design/D23.md`** by value: the four layer names
(hermetic / composed / live / manual), the rule that the default gate contains
only hermetic and composed tests, the single live mechanism (`//go:build live`
plus a documented invocation, hard-failing on absent credentials), the ban on
`t.Skip` outside live-tagged files, and the requirement that the tree declare its
testing facts in `AGENTS.md`. The contract is cited, never restated — nothing in
this Decision redefines a layer or re-specifies the mechanism.

**dropbox's declared facts.** These are the tree-specific values the contract
asks each adopter to state; they are what the `AGENTS.md` Tests section and the
design Conventions must say:

| fact | value |
|---|---|
| default-gate test command | `cd dropbox && go test ./...` |
| layers present | **hermetic**, **composed**, **live** |
| environmental preconditions beyond the Go toolchain | none |
| GOWORK mode | workspace (the repo-root `go.work`); the production build forces `GOWORK=off` via `bin/ship dropbox` |
| live invocation | `cd dropbox && go test -tags live ./...` |
| live credentials | `DROPBOX_APP_KEY` / `DROPBOX_APP_SECRET` from the operator's environment (channel 2) and `DROPBOX_REFRESH_TOKEN` from the local `state/` file the client reads (channel 5, `project/design/D33.md`; seeded by `opsctl seed-state`); optional `DROPBOX_APP_FOLDER_ROOT` scopes the smoke below the app-folder root — all required, the live test **fails loudly** if any is missing |
| when the operator runs live | at **deploy verification** for dropbox, and whenever a change touches the Dropbox write client (`internal/dropbox/client.go`) or the uploader |

The **composed** layer is `cmd/dropbox`'s boot/wiring tests over the shipped
`share/www` tree and the assembled chassis handler; the **live** layer is
`internal/dropbox/client_live_test.go` alone (D17's R-KEIO-B98F, R-KFQK-P0Z4,
R-KGYH-2SPT). dropbox has no **manual**-layer check of its own — the suite-level
"the whole stack composes" item is the umbrella's, per the contract.

**Two conformance defects, normalized.** dropbox is the tree the contract's
"silently live when secrets are present, silently green when they are not"
rejection was written about, and it carries that shape twice:

1. **`TestLiveProbe` in `internal/dropbox/client_test.go` is deleted.** It is
   untagged, env-gated on `DROPBOX_*`, and reaches the real Dropbox API from the
   default gate whenever the `DROPBOX_*` credentials are present in the
   environment — violating both the default-gate hermeticity rule and the
   single-live-mechanism rule. It is also
   **redundant**: its two assertions are that a refresh token yields a non-empty
   access token and that `ListFolder` returns a non-empty cursor, and both are
   strict prerequisites of every test in `client_live_test.go` — each one
   authenticates through the same `token.token` path before its first call and
   reads its result back through `ListFolder`/`ListFolderContinue`, so a broken
   token refresh or a broken `list_folder` fails all three tagged smokes first
   and louder. It carries no minted id, so nothing leaves the design with it.
   Deletion, not relocation, is the resolution.
2. **`newLiveClient` in `internal/dropbox/client_live_test.go` hard-fails.** The
   helper currently calls `t.Skip` when a `DROPBOX_*` variable is empty, which
   makes an explicitly-invoked `go test -tags live ./...` report green having
   proven nothing. Each missing variable becomes a `t.Fatalf` naming the variable
   — the shape gmail's `requiredLiveCredential` already uses. After this change
   `t.Skip` does not appear anywhere in the tree.

**Rejected.**

- *Moving `TestLiveProbe` behind `//go:build live` instead of deleting it.* It
  would become a fourth live test whose claims are a strict subset of the other
  three's preconditions — extra live API calls and extra rate-limit exposure on
  every deploy verification, buying no falsification the tagged smokes do not
  already deliver.
- *Keeping the probe untagged as a "cheap smoke that runs when secrets happen to
  be around."* That is exactly the defect the contract bans: a test whose
  substrate depends on the ambient environment is neither hermetic nor reliably
  live, and its green tells the reader nothing about which it was.
- *Letting the live helper keep skipping "so an operator without credentials
  isn't blocked."* An operator without credentials cannot verify the deploy;
  a loud failure says so, a skip launders it into a pass.
- *Restating D23's layer definitions in this design.* A local copy of a suite
  contract is drift by construction — the citation is the whole mechanism.
- *Minting fresh dropbox ids for the two contract behaviors.* The contract marks
  both `[proof: per-service]`; citing them is adoption, and re-minting would
  create a second handle for one behavior.
