# Decision 29 — Env-channel conformance: the sync tuning knobs surface in the manifest

**Problem.** dropbox's two operator-facing sync knobs sit outside every
configuration channel (root `project/design/D21.md`):
`DROPBOX_LONGPOLL_TIMEOUT` (seconds the delta longpoll holds open, default
`480`) and `DROPBOX_MAX_ENTRY_RETRIES` (the poison-entry bound, default `5`)
are env reads whose defaults only the code states — no production channel
carries them, while the retention knobs in the same `Spec` are already
manifest-surfaced. Inconsistent treatment of the same kind of knob.

**Decision.**

1. **The sync knobs are channel-1 manifest knobs.** `Spec.ManifestExtras`
   gains, after the existing retention pair:

   ```go
   {Key: "DROPBOX_LONGPOLL_TIMEOUT", Value: "480"},
   {Key: "DROPBOX_MAX_ENTRY_RETRIES", Value: "5"},
   ```

   and the committed `dropbox/etc/manifest.env` gains the same two lines in
   the same order. The reads at `cmd/dropbox/main.go` are unchanged
   (`config.EnvOrInt`); in production the launcher exports every manifest key,
   so the manifest line is what the process receives, and the code defaults
   become dev fallback that must agree with the manifest's stated values. The
   existing drift proof (R-8IAN-FB87, adopted in D10) pins the byte agreement
   automatically.

2. **Channel classifications recorded**, so no value is channel-less (root
   `project/design/D21.md`): `DROPBOX_APP_KEY` / `DROPBOX_APP_SECRET` /
   `DROPBOX_REFRESH_TOKEN` are customer data in the app-config parameter
   (channel 2, already declared by `.envrc`); `DROPBOX_MIRROR_PATH` is the
   state-path override analogous to `<APP>_DB_PATH` (channel 4 — its
   production value derives from the composed DB path, per D28);
   `DROPBOX_APP_FOLDER_ROOT` is a dev-only override (channel 4, empty means
   the app-folder root).

3. **Adoption of the box-path-literal guard.** This Decision adopts the root
   env contract's `[proof: per-service]` id **R-VKB6-SHHV** (root
   `project/design/D11.md`): a source-scan test in `cmd/dropbox/main_test.go`
   walks dropbox's non-test `.go` files and fails on any `"/opt` string
   literal — dropbox is clean today, and the guard keeps it that way.

**Rejected.**
- *Leave the sync knobs code-default-only.* They are exactly the class of
  operator tuning the retention knobs already surface; two channels for one
  class is the inconsistency this session removes suite-wide. Rejected.
- *Promote `DROPBOX_APP_FOLDER_ROOT` too.* Its empty default is semantic
  ("the app-folder root"), it is not operator tuning, and a non-empty value
  would be account-specific anyway. Rejected — channel 4.

**Verification.**
- R-M0AZ-C8H7 — with no environment set, the resolved values of
  `DROPBOX_LONGPOLL_TIMEOUT` and `DROPBOX_MAX_ENTRY_RETRIES` equal the values
  stated in the committed `dropbox/etc/manifest.env` (parse the committed
  file, compare against the code's resolved defaults) — an edit to either side
  alone fails. Substrate: unit test in `cmd/dropbox/main_test.go` reading the
  committed manifest.
- Adopts **R-VKB6-SHHV** (root `project/design/D11.md`, `[proof: per-service]`)
  — no `"/opt` string literal in dropbox's non-test Go source. Substrate: the
  source-scan test in `cmd/dropbox/main_test.go`.
