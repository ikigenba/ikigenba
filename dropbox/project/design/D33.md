# Decision 33 — `DROPBOX_REFRESH_TOKEN` adopts the rotating-credential channel (channel 5, `state/`)

**Problem.** `DROPBOX_REFRESH_TOKEN` is classified as channel-2 customer data
(D29), seeded to the app-config parameter and exported read-only into the
service's environment at launch. But it is an OAuth **refresh token**: a
single-holder credential the provider may rotate and revoke, so two deployments
cannot hold the same one, and a value the service rotates cannot live in a
seed-once, read-only parameter. The suite contract for exactly this class is
`root project/design/D32.md` (channel 5): a per-environment credential the
service owns and rotates in its `state/`.

**Decision.** dropbox adopts channel 5 for its refresh token; the two static
OAuth credentials are unchanged.

1. **Reclassification.** `dropbox/etc/env.list` declares `rotating
   DROPBOX_REFRESH_TOKEN` (no longer `secret`), so `bin/push-secrets` never
   pushes it to SSM (`root project/design/D32.md`; `push-secrets` pushes `secret`
   lines only). `DROPBOX_APP_KEY` and `DROPBOX_APP_SECRET` stay channel 2
   (`secret` lines), identical across environments and read from the environment
   as today.

2. **The client reads the token from `state/`.** At the composition root
   (`cmd/dropbox/main.go`) the refresh token is read from the file
   `${IKIGENBA_ROOT}/dropbox/state/DROPBOX_REFRESH_TOKEN`, composed from the
   box-global `IKIGENBA_ROOT` exactly as the SQLite path is
   (`root project/design/D05.md`, `root project/design/D11.md`), **not** from the
   environment. A missing file is a **loud boot failure** naming the credential,
   mirroring the launcher's hard-fail on a missing parameter.

3. **Rotation persists back to `state/`.** When the provider returns a new
   refresh token during a refresh, it is written back to the same `state/` file
   atomically (`0600`), so the next boot reads the rotated value. The service is
   the only steady-state writer of that file.

4. **Bootstrap.** dropbox has no interactive consent tool of its own; each
   environment is seeded once with its own independently-obtained token via
   `opsctl seed-state dropbox DROPBOX_REFRESH_TOKEN` (`root project/design/D32.md`,
   opsctl D19) — the local checkout's `state/` and each production box
   separately, so no two environments ever share a token.

The channel classifications this changes are corrected in place: D29 (§2), D30
(live credentials, and the `TestLiveProbe` hazard note), and CONVENTIONS now
state that the refresh token is channel 5 held in `state/`, the
app-key/app-secret pair channel 2 from the environment.

**Rejected.**
- *Keeping `DROPBOX_REFRESH_TOKEN` in channel 2 (the app-config parameter).* It
  would be seeded once from a single shared value and exported read-only, so
  every environment would boot from the same token — the first rotation revoking
  the others — and a rotation the service performs could never be written back
  (`root project/design/D32.md`). Rejected — channel 5.
- *Reading the refresh token from the environment and merely persisting rotations
  to `state/`.* Two sources of truth for one value; the first boot would take the
  env seed and a later boot the `state/` copy, diverging silently. Rejected —
  `state/` is the single source of truth after bootstrap.

**Verification.** The read-at-boot and persist-on-rotation behaviors are the
umbrella contract's per-service ids, adopted here (citation is adoption); dropbox
mints no local id (it has no consent tool, and the two contract behaviors are the
whole surface of this change).

- R-ENXH-KJ01 (owned by `root project/design/D32.md`, `[proof: per-service]`) —
  dropbox reads its refresh token from
  `${IKIGENBA_ROOT}/dropbox/state/DROPBOX_REFRESH_TOKEN` at boot and **fails
  loudly, naming the credential, when the file is absent**. Substrate: hermetic
  test over a temp-dir `IKIGENBA_ROOT` (present file → resolved value; absent
  file → loud error).
- R-EP5D-YAQQ (owned by `root project/design/D32.md`, `[proof: per-service]`) —
  when the OAuth token source yields a rotated refresh token, dropbox writes it
  back to the same `state/` file, so a re-read returns the rotated value.
  Substrate: hermetic test driving the token source with a fake that returns a
  new refresh token (round-trip: seed, rotate, re-read).
