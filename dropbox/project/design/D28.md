# Decision 28 — State paths come from `appkit/config`, never from a hardcoded `./tmp` default

## Decision

The composition root resolves dropbox's durable state paths through
`appkit/config`, the same resolver the chassis itself uses, instead of reading
`DROPBOX_DB_PATH` out of the environment with a hardcoded fallback.

`config.Resolve` already composes the suite's fixed on-box layout from
`IKIGENBA_ROOT`, honouring an explicit `DROPBOX_DB_PATH` /
`DROPBOX_GENERATION_PATH` override when one is set:

```go
// appkit/config: <root>/<app>/state/<app>.db, or ./tmp/<app>.db when unrooted.
cfg, err := config.Resolve("dropbox", "/srv/dropbox/", registry.MustPort("dropbox"), os.Getenv)
```

`cmd/dropbox` calls it once at startup and derives the mirror root from
`cfg.DBPath`:

```go
// defaultMirrorPath keeps DROPBOX_MIRROR_PATH as the explicit override and
// otherwise places the mirror beside the durable DB.
func defaultMirrorPath(getenv func(string) string, dbPath string) string {
	if mirrorPath := getenv("DROPBOX_MIRROR_PATH"); mirrorPath != "" {
		return mirrorPath
	}
	return filepath.Join(filepath.Dir(dbPath), "mirror")
}
```

**The resolved values do not change.** With `IKIGENBA_ROOT=/opt` the mirror
resolves to `/opt/dropbox/state/mirror`, exactly where the live mirror already
sits, so nothing on disk moves. With the root unset, as in a repo-root dev
launch, it resolves to `./tmp/mirror`, exactly today's dev default. This
Decision changes only *where the default comes from*, not what it is.

**What the old shape got wrong** is that the fallback was written as a literal
`"./tmp/mirror"` reached whenever `DROPBOX_DB_PATH` was absent, so the binary
ignored `IKIGENBA_ROOT` entirely and depended on something outside it exporting
the variable. The on-box manifest stopped carrying that key, which left the
default reachable in production, where `./tmp` resolves under the root-owned
service directory and startup fails on `mkdir`.

**`DROPBOX_MIRROR_PATH` is retained** unchanged. The mirror is a dropbox concept
the chassis knows nothing about, and the override is the only way to site it
away from the DB. `bin/start` sets it in dev.

**Nothing else moves.** The sync engine, the uploader, the mirror's confinement
model (D14/D24), the write API (D16), and the event surface (D22) are untouched;
they receive the same absolute root they receive today.

## Rejected

**Keep reading `DROPBOX_DB_PATH` directly and re-add the key to
`etc/manifest.env`.** Rejected: the manifest is committed and shipped per
version, so it can only carry facts true in every environment, and an absolute
`/opt/...` is a box fact. The root is already supplied per environment by
`IKIGENBA_ROOT`, and duplicating the composed layout in a config file lets the
two drift.

**Delete `DROPBOX_MIRROR_PATH`.** Rejected: this Decision exists to make default
*computation* consistent, not to change behaviour. Removing a working override
is a separate question with its own cost, and `bin/start` depends on it.

**Add a `Router` accessor (`rt.DBPath()`) and read it from `Spec.Handlers`.**
Rejected: that is an `appkit` change, outside this project's scope boundary.
`config.Resolve` is already exported and pure, so the composition root can call
it directly with no chassis change at all.

## Verification

- R-L7TF-ZAFX — with `IKIGENBA_ROOT=/opt` in the injected environment and
  neither `DROPBOX_DB_PATH` nor `DROPBOX_MIRROR_PATH` set, the composition
  root's mirror-path resolution returns exactly `/opt/dropbox/state/mirror`; a
  build that still falls back to a `tmp`-rooted literal fails.
- R-L91C-D26M — with `DROPBOX_MIRROR_PATH` set to an unrelated absolute path and
  `IKIGENBA_ROOT=/opt` also set, resolution returns the override verbatim, so
  the explicit knob still wins over the composed default.
- R-LA98-QTXB — with `IKIGENBA_ROOT` absent from the injected environment (the
  repo-root dev launch) and no explicit overrides, resolution returns a
  `tmp`-rooted mirror path, preserving today's dev default.
