# D08-visitors-and-trail

Visitors and the trail: the package `internal/visitor`, which tells one browser from another with the cookie `ikigenba_visitor` and reads the host of a request's `Referer`, and the contract of every `site.*` event sites records — the closed set of event names, each `site.*` event's attributes with their keys, types and values, which outcome records which event, the order of a request's events, and what no attribute ever carries. `D01-layout-and-run-seam` declares the names this design behaves through for a whole run (`cli.Process`, `cli.Run`); `D03-serve` declares `web.Config` and `web.Handler`, records the framework events (`service.started`, `service.stopping`, and the request pair through appkit's `telemetry.Middleware`) and wires identity; `D04-store` declares the site record (`store.Site`, `store.ValidID`, `store.Private`); `D05-git-and-cache` declares `cache.Cache`, `cache.ValidRepo` and the five reason constants; `D07-site-serving` declares `serving.Config` and `serving.Sites` and states every answer a site path gets (its status, headers and body, the slash redirect, the `404`s, the `503`s); `D09-tools` declares `tools.Config` and `tools.Register`, the seven tools, their results and refusals, and each tool's `tool.called`. This document says, for those answers and those calls, which carry the visitor cookie and which `site.*` events they record with which values; it restates none of them.

## What is someone else's

The envelope of an event (`Time`, `Service`, `RequestID`, `User`), its JSON form, delivery, retries and the `undelivered event` line are appkit's telemetry contract and writer (appkit's telemetry designs); sites records every event through a `*telemetry.Writer` with `Emit`. The registered entity prefixes `sit_` (entity type `site`) and `vis_` (entity type `visitor`), both owned by sites, are in appkit's telemetry contract; this design holds the requirements that sites' values fit them. `request.started`, `request.finished`, `service.started` and `service.stopping` are `D03-serve`'s; `tool.called` and its `tool`, `kind` and `outcome` per tool are `D09-tools`'. Which reason a failed rebuild has is decided by the cache (`D05-git-and-cache`, `cache.Reason`); this document fixes that the event carries it.

## Visitors

A **visitor** is a browser, known by the cookie `ikigenba_visitor`, whose value is a **visitor id**: `vis_` followed by exactly 16 lowercase hexadecimal digits, drawn as 8 bytes from the random source the run is given. sites keeps no record of visitors: an id lives in the browser's cookie and in the trail and nowhere else.

The cookie is set only on a **view** — an answer to a `GET` or `HEAD` for a path of a known site that a visitor may see, from the redirect to the slug's `/` on: `200`, `301`, `304`, `404` within a site or for an unpublished one, and every `503` but the catalog refusal (`D07-site-serving` states each). A view whose request carries no well-formed visitor id is answered with exactly one `Set-Cookie`, `ikigenba_visitor=<id>; Path=/; Max-Age=34560000; HttpOnly; SameSite=Lax`, followed by `; Secure` when the request's first `X-Forwarded-Proto` is `https` in any letter case (see Decisions for a random source that fails). The string is built by hand, because Go's `http.Cookie` writes `Secure` before `SameSite`. A request that carries a well-formed id keeps it: no `Set-Cookie`, so its lifetime is not renewed either. The id checked is the value `r.Cookie("ikigenba_visitor")` returns, the first cookie of that name; a value that is not a visitor id (wrong prefix, wrong length, an upper-case or non-hexadecimal digit, empty) counts as none and is replaced. No other answer — the landing and about pages, `/_appkit/`, `/mcp`, an unknown slug, a guest sent to sign in, a method other than `GET` and `HEAD`, the catalog-unreachable `503`, the apex host — sets the cookie or records a `site.*` event.

`referrer_host` is the host of the request's first `Referer`, as `url.Parse` gives it (port kept, user information left out), and empty when there is no `Referer`, it cannot be parsed, or it has no host: `http://[example.org/` and `about:blank` both give the empty string.

## The trail

sites records exactly twelve events: `service.started`, `service.stopping`, `request.started`, `request.finished`, `tool.called`, and the seven `site.*` events below. Every attribute is a basic form appkit's contract accepts: `string`, `bool` or `int64`.

| Event | Attributes | Recorded when |
|---|---|---|
| `site.viewed` | `site`, `visitor`, `path`, `referrer_host`, `commit` (`string`); `status` (`int64`) | every view, once (see Decisions) |
| `site.unavailable` | `site`, `commit`, `reason` (`string`) | a view answered with the `unavailable` page, after its `site.viewed` |
| `site.created` | `site`, `repo`, `visibility` (`string`); `listed` (`bool`) | a `create` that succeeds |
| `site.published` | `site`, `commit`, `ref` (`string`) | a `publish` that succeeds, the same commit again included |
| `site.updated` | `site`, `field`, `value` (`string`) | an `update` that succeeds, once per field it changed, in the order `visibility`, `listed`, `ref` |
| `site.deleted` | `site` (`string`) | a `delete` that succeeds |
| `site.apex` | `site` (`string`, empty when cleared) | an `apex` that sets or clears, even to what it was; and after `site.deleted` when the deleted site was the apex |

A request's events come in this order: `request.started`, its `site.*` events, its `tool.called` if it called a tool, `request.finished`. A refused tool call, `list`, `show` and an `apex` that only reads record no `site.*` event; a failed `publish` is never a `site.unavailable`, which only serving records. A `create` or `publish` whose git run was halted or ended with its request's context gets no answer and is no tool request (`D09-tools`), and a view waiting on a rebuild in that state gets no answer and is no view (`D07-site-serving`); a view whose request's context is done by the time its answer has been written records no `site.*` event (R-LM7A-DIVU). Which requests cut off at the drain deadline record nothing from it on is `D03-serve`'s to state (R-BH93-MQG1). Every `site.*` event holds exactly the attributes the table names (a `site.viewed` recorded after a failed random read holds a subset of them, R-RFVG-0T9A), each valued as the requirements fix, so nothing else of a request (an email, a query, the rest of a `Referer`, another cookie, a file's content, a site's name) can reach the trail. Attributes name what happened and the ids of what it touched: a site by its id under `site`, a repository by its id under `repo`, a visitor by its id under `visitor`. The one place a slug reaches an attribute is `path`, the URL path as it arrived, without its query.

## Decisions

- A visitor id is `vis_` and the lowercase hexadecimal form of 8 bytes read with one `io.ReadFull`. When the random source cannot give those 8 bytes for a view, whether that view sets a cookie or records `site.viewed` is not contract; the answer is otherwise as `D07-site-serving` states it.
- The id a request carries is the value `r.Cookie` returns for `ikigenba_visitor`: the first such cookie, unquoted as the standard library unquotes it. A later cookie of the same name is not looked at.
- `Secure` follows the first `X-Forwarded-Proto` value compared with `https` ASCII case-insensitively; a list such as `https, http` in one header is not `https`.
- `referrer_host` keeps the host exactly as `url.Parse` gives it, letter case included; a scheme-relative `//example.org/x` gives `example.org`.
- `commit` in `site.viewed` is the commit of the site record the answer was made from, so a view answered from the old tree while a publish runs carries the old sha, the same one its `ETag` names.
- `site.updated`'s `value` is the field's new value as a JSON string: the visibility or ref as stored, `true` or `false` for `listed`.

## Consumer tasks

`serving.Sites(cfg)`, answering a view of the site `s` (a `store.Site`): `id, ok := visitor.FromRequest(r)`; when `!ok`, `id, err := visitor.Mint(cfg.Rand)`; when `Mint` errors, whether the cookie is set and `site.viewed` recorded is not contract, R-RFVG-0T9A bounding its attributes; otherwise `w.Header().Add("Set-Cookie", visitor.Cookie(id, visitor.Secure(r)))` before the header is written; after the answer, unless `r.Context()` is done by then (R-LM7A-DIVU), `cfg.Telemetry.Emit(r.Context(), "site.viewed", telemetry.Attrs{"site": s.ID, "visitor": id, "path": r.URL.Path, "status": int64(status), "referrer_host": visitor.ReferrerHost(r), "commit": s.Commit})`, and for a rebuild failure then `cfg.Telemetry.Emit(r.Context(), "site.unavailable", telemetry.Attrs{"site": s.ID, "commit": s.Commit, "reason": cache.Reason(treeErr)})`, `treeErr` being the error `cfg.Cache.Tree` returned. Constants a reader of the cookie needs are `visitor.CookieName`, `visitor.IDPrefix` and `visitor.MaxAge`; `visitor.ValidID` decides whether a value is an id.

`tools.Register(srv, cfg)`'s tools, on success and before returning their result: `create` calls `cfg.Telemetry.Emit(ctx, "site.created", telemetry.Attrs{"site": site.ID, "repo": site.Repo, "visibility": site.Visibility, "listed": site.Listed})`; `publish` emits `site.published` with `site`, `commit` and the `ref` as given or the site's `Ref`; `update` emits one `site.updated` per name in the changed list `store.Update` returns; `delete` emits `site.deleted` and, when `store.Delete` answers `wasApex`, `site.apex` with `""`; `apex` emits `site.apex` with the apex site's `ID`, or `""` after a clear.

A visitor test calls `visitor.Mint(bytes.NewReader([]byte{0x1a, 0x2b, 0x3c, 0x4d, 0x5e, 0x6f, 0x70, 0x81}))` and compares with `"vis_1a2b3c4d5e6f7081"`, builds requests with `httptest.NewRequest` carrying `Cookie`, `X-Forwarded-Proto` and `Referer` headers, and compares `visitor.FromRequest`, `visitor.Secure`, `visitor.Cookie` and `visitor.ReferrerHost` with the texts below. A view test opens a store over a temporary directory with a fixed `Now` and a seeded `Rand`, a cache over a bare repository fixture made with the isolated git environment, a writer over a `*telemetry.Capture`, and serves `web.Handler(cfg)` (whose `Rand` is a `bytes.Reader` the test filled) with `httptest`; it sets `X-Request-Id`, `Host`, `X-Forwarded-Proto` and, for a user, `X-User-Id`, reads `Set-Cookie` from the response, calls `Writer.Flush` and reads `Capture.Events()`. A tool test builds `mcp.NewServer` over the same writer, `tools.Register`, serves it inside `identity.Require` inside `telemetry.Middleware`, and calls `mcp.Client.CallTool` as a user; it compares each `site.*` event's `Attrs` with the call's `structuredContent`. A trail test runs `cli.Run` with a `*telemetry.Capture` as `Sink` and a fixed `Now`, makes requests over the inherited listener, stops the run, and checks every event's name and envelope.
