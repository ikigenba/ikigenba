# D04-store

The catalog: `internal/store`, which owns sites' one SQLite database, `state/sites.db`, and everything it records — every site's id, name, slug, owner, repository, ref, visibility, listing, published commit and times, and the one setting `apex` — together with the rules a site's name, slug and id obey and the one line every consumer answers when the catalog cannot be reached. `D01-layout-and-run-seam` declares `cli.Process`, whose `Database`, `Now` and `Rand` reach the store through `cli.Run`, and resolves the path the catalog lives at; `D03-serve` opens the store at start, writes the diagnostic for a catalog that will not open, and closes it after the drain. This document declares every exported name of `internal/store` and states what each does. What a tool checks before it calls the store, in which order, and what it answers is `D09-tools`'; what the landing page shows of a site is `D06-pages`'; how a site path or the apex host is answered from a record is `D07-site-serving`'s; the trees under `cache/sites/` and the repositories under `REPOS_DIR` are `D05-git-and-cache`'s. The store holds no file but the database and runs no git.

## One catalog, one writer

sites is the catalog's only writer, and the catalog is the only record of its sites: `cache/sites/` is disposable and rebuilt from a record, never the reverse. sites never rebuilds a catalog: a lost `state/sites.db` comes back only from the host's replica, so a start that finds no database begins an empty one and looks at nothing else on disk to fill it. Which tables hold a record is not contract: no sibling reads the database, and the host's replication copies it whole. What is contract is what a reader and a restart see: what a `*Store` holds when it is closed is what the next `Open` of the same source holds, field for field and with the same apex. A test proves the catalog that way, by closing and reopening, never by reading tables.

`Open` takes the source `cli.Run` gives it. An ordinary filesystem path is a database file whose missing parent directories `Open` creates; a missing file, or one of no bytes, is a new empty catalog. The empty string and `:memory:` are a catalog in memory that lives as long as the `*Store`, which a test may use where it needs no catalog to survive. A file that is not a database, one the process cannot write, a directory that cannot hold the database, and a parent that cannot be created are failures matching `ErrDatabase`, whose text is the underlying failure's alone so `D03-serve` can write it after `sites: cannot open database state/sites.db: `; a failed `Open` leaves an existing file exactly as it was and begins no new one. A catalog `Open` returns is in SQLite's WAL journal mode, because the host's replica needs it: the manifest's `[database]` (`D02-cli`) has opsctl back `state/sites.db` up with litestream, which follows the `-wal` file beside it. `Open` learns at once whether it can write, so a file or a directory it cannot write is refused there and not at the first write.

A catalog that fails in the middle of the work is a closed store: once `Close` has returned, every method answers a catalog error. A test that needs a call's reads to succeed and its write to fail closes the store from a hook the call runs between them (the `limits.Clock.After` the cache calls before each git run, or `cache.Config.Joined`), never by taking a permission away after `Open`: under WAL that does not reliably fail a write on the connection the store already holds. A call that changes nothing (an `Update` that changes no field, a `SetApex` of the site already the apex, a `ClearApex` with none set) writes nothing that can fail on its own; its answer is decided by its reads.

## Sites

A site's **id** is `sit_` and 16 lowercase hexadecimal digits, under appkit's registered entity prefix for the entity type `site` (appkit's telemetry contract), drawn from the random source when the site is created and never changed. Its **name** is 1 to 64 bytes, each a lowercase ASCII letter, a digit or `-`, the first not `-`, and neither `about` nor `mcp`, since `/about` and `/mcp` are sites' own paths; it is taken as given, never trimmed or folded. Its **slug** is the first segment of its URL: its name when it is created listed, and its name, `-`, and 8 lowercase hexadecimal digits drawn from the random source when it is created unlisted; it is fixed at create and nothing changes it, `listed` included. Names are one namespace for the whole space, because the slug is the URL: a name is **taken** when any site, of any owner, has it as its name or as its slug, so an unlisted site takes two strings, and a drawn slug that is already taken is drawn again rather than refused. Its **owner** is the user id of the caller that created it, the `UserID` of the `identity.Caller` appkit's identity gives the request (`D03-serve`). Its **repository** is a repository id as repos names its directory, kept verbatim, so a site keeps working across a rename in repos; the store never looks at it. Its **ref** is the ref a publish without one resolves, its **visibility** `public` or `private`, and **listed** whether the landing page shows it to others. **Created** is the time of the create and **published** the time of the last publish, both in UTC to the second, the precision the tools answer them in; **commit** is the sha that publish named, empty and with a zero `Published` until the first publish. A site is **unpublished** while its commit is empty.

## Reads and writes

The reads are what the consumers are built from: `Find` is a caller's own site by name, so another owner's site is indistinguishable from none; `BySlug` is any owner's site by slug, for serving; `List` is one owner's sites; `Visible` is what the landing page lists to a user, every listed site and that user's own unlisted ones; `Taken` is the space-wide name check. All lists are in ascending byte order of name and are never nil.

Every write names its site by id, which a consumer learned from a read. `Create` mints the id and the slug and stamps the created time; `Publish` sets the commit and the published time together, so a reader sees a site at its old commit or its new one and never a mix; `Update` changes any of visibility, listing and ref, all or nothing, and says which it changed; `Delete` removes a site and, when it was the apex, the apex with it. A field sent with the value it already has is not a change.

## The apex

The catalog holds one setting, `apex`: one site's id or nothing, nothing when a catalog begins. `Apex` reads it as the site it names, `SetApex` sets it to a public site, published or not, replacing whatever was there, and `ClearApex` unsets it. The apex site is always public: `SetApex` refuses a private site and `Update` refuses to make the apex site private, each with `ErrNotPublic` and changing nothing, and both decide against the same moment of the catalog, so no interleaving leaves a private apex. Deleting the apex site clears the setting in the same step, so the setting never names a site that is gone. Who may set or clear the apex is `D09-tools`'; the store takes any id.

## Errors

`ErrNotFound`, `ErrNameTaken` and `ErrNotPublic` are answers about the catalog's content; `ErrDatabase` is `Open`'s failure. Every other error from a method is answered as the catalog being unreachable: every consumer answers it with `Unreachable`, the one line a tool refuses with, the landing page and every site path answer `503` with, and the apex host answers too, never quoting the underlying error. A closed `*Store`, a database that fails, a random source that fails and a context already done all end there. So does a write given a value no consumer sends — a name `ValidName` refuses, an empty owner or ref, a visibility other than `public` or `private`, a commit that is not a sha — which changes nothing: `D09-tools` refuses each of those first, with its own line. When one call meets several of these conditions, one fixed precedence decides its answer: a done context, then a closed store, then an invalid argument, then a missing site, then a taken name or a private apex.

## Decisions

- Ids are 8 bytes of `Rand`, slug suffixes 4 bytes; a create reads id candidates first, then, for an unlisted site, slug candidates, so a test handing in known bytes knows both in advance.
- A drawn id already catalogued and a drawn slug already taken are drawn again, never refused.
- `Update` and `SetApex` check apex-must-be-public in the same step as the write.
- A zero-length database file counts as absent; created directories get mode `0700`.
- A deleted site's id is not remembered, so a later create may in principle draw it again; with 64 random bits the odds are negligible, and keeping tombstones was not worth it.
- The catalog is in WAL journal mode (R-I173-6PUZ), because litestream, which backs it up on a host, needs it. So a permission taken away after `Open` is no test seam; closing the store is.
- The store validates nothing a tool has not already refused, beyond keeping its own invariants (name rule, owner, visibility, non-empty ref, commit shape).

## Consumer tasks

`cli.Run` opens the catalog with `store.Open(ctx, store.Config{Source: src, Now: p.Now, Rand: p.Rand})`, `src` being `p.Database` or, when that is empty, `state/sites.db` under `p.Dir` (`D01-layout-and-run-seam`); on any error while `ctx` is not done it writes `D03-serve`'s diagnostic `sites: cannot open database state/sites.db: ` with `err.Error()` as the reason, whether or not `errors.Is(err, store.ErrDatabase)` holds; an error from a `ctx` already done is a stop, not a failure, and `D03-serve` says what `Run` does then; otherwise it hands the `*store.Store` to `web.Config.Store` and calls `Close` after the drain.

The tools (`D09-tools`), `u` being the `identity.Caller` of the call: `list` is `s.List(ctx, u.UserID)`; `show` is `s.Find(ctx, u.UserID, name)`; `create` checks `store.ValidName(name)`, then `s.Taken(ctx, name)`, then the repository and ref, then the visibility against `store.Public` and `store.Private`, and calls `s.Create(ctx, store.Draft{Owner: u.UserID, Name: name, Repo: repo, Ref: ref, Visibility: visibility, Listed: listed})`, `store.ErrNameTaken` still answering `already exists` when a racing create won; `publish` is `s.Find`, then the cache's resolve and unpack, then `s.Publish(ctx, site.ID, sha)`; `update` is `s.Find` then `s.Update(ctx, site.ID, store.Change{Visibility: v, Listed: l, Ref: r})`, the names it returns deciding the `site.*` events `D08-visitors-and-trail` states, and answering `apex site must be public` for `store.ErrNotPublic`; `delete` is `s.Find`, `s.Delete(ctx, site.ID)`, the cache's removal, and the apex event `D08-visitors-and-trail` states when `wasApex`; `apex` is `s.Apex(ctx)`, or `s.Find` then `s.SetApex(ctx, site.ID)`, or `s.ClearApex(ctx)`. `store.ErrNotFound` from `Find` is `no site named '<name>'`; an error matching none of the sentinels is the refusal `store.Unreachable`. A site object's `id` satisfies `store.ValidID`, which is also how every `site` event attribute is checked.

Pages and serving (`D06-pages`, `D07-site-serving`): the landing page is `s.Visible(ctx, u.UserID)`, `u` being the `identity.Caller` of the request, a row being the user's own when `Owner` equals that user id and published when `Commit` is not empty; a site path is `s.BySlug(ctx, slug)`, its `Visibility` compared with `store.Private` and its `Commit` naming the tree; the apex host is `s.Apex(ctx)` and the site's `Slug`. Each answers `store.Unreachable` and a newline, as plain text with status `503`, for an error matching no sentinel.

A test opens a store with `store.Open(ctx, store.Config{Source: filepath.Join(t.TempDir(), "state", "sites.db"), Now: clock, Rand: bytes.NewReader(known)})`, or with `Source` empty where nothing must survive; creates with `s.Create`, reads back with `Find`, `BySlug`, `List`, `Visible` and `Taken`, publishes, updates and deletes, sets and clears the apex, and closes and reopens to see the same sites. It puts a regular file where `state` goes, writes a file that is not a database at the source, or removes a permission, to see `ErrDatabase` and its text; it closes the store, before a call or from a hook the call runs after its reads, to see an unreachable catalog; it reads `PRAGMA journal_mode` on a connection of its own to the file, with the store open and after `Close`, to see `wal`; and it hands in a `Rand` that fails.
