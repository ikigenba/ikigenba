# D04-store

The catalog: `internal/store`, which owns sites' one SQLite database, `state/sites.db`, and everything it records — every site's id, name, slug, owner, repository, ref, visibility, listing, published commit and times, and the one setting `apex` — together with the rules a site's name, slug and id obey and the one line every consumer answers when the catalog cannot be reached. `D01-layout-and-run-seam` declares `cli.Process`, whose `Dir`, `Now` and `Rand` reach the catalog through `cli.Run`, resolves the path the catalog lives at, and declares the root package's `Migrations`, the schema's migrations; `D03-serve` opens the catalog with appkit's `db.Open` at start, builds the store over that handle, writes the diagnostic for a catalog that will not open, and closes the handle after the drain. Opening, migrating, the journal mode, transactions and the failure seam are appkit's `db` (its D15 and D16), which this document restates none of. This document declares every exported name of `internal/store` and states what each does. What a tool checks before it calls the store, in which order, and what it answers is `D09-tools`'; what the landing page shows of a site is `D06-pages`'; how a site path or the apex host is answered from a record is `D07-site-serving`'s; the trees under `cache/sites/` and the repositories under `REPOS_DIR` are `D05-git-and-cache`'s. The store holds no file but the database and runs no git.

## One catalog, one writer

sites is the catalog's only writer, and the catalog is the only record of its sites: `cache/sites/` is disposable and rebuilt from a record, never the reverse. sites never rebuilds a catalog: a lost `state/sites.db` comes back only from the host's replica, so a start that finds no database begins an empty one and looks at nothing else on disk to fill it. What is contract is what a reader and a restart see: what a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds, field for field and with the same apex. A test proves the catalog's content that way, by closing and reopening, never by reading tables.

The schema is contract too, because a migration is applied to a catalog that already exists and the migrations must agree with what earlier releases left on disk. It is the one migration `0001_catalog.sql`, the schema sites has always created: a table `sites` with the columns `id`, the primary key, `name`, `slug`, `owner` and `payload`, the last holding the whole record as JSON, and a table `settings` of `key` and `value` holding the apex. Written with `CREATE TABLE IF NOT EXISTS` and seeding nothing, it creates both tables on a fresh catalog and changes nothing on a catalog an earlier sites kept, which `db.Open` then records as having had `0001`, so that catalog's sites and apex are served as they were. Its test is one of the shape every service has: open a fresh catalog with `sites.Migrations()` and inspect `sqlite_master` and `PRAGMA table_info`; and, for adoption, build a catalog in the shape an earlier sites wrote, with no `schema_migrations`, and see a store over the opened handle answer its sites and apex.

The store does not open anything. `store.New` builds a store over a handle `db.Open` returned, with the clock and random source it stamps and draws from; every read is a `DB.Read` and every write a `DB.Write` on that handle, so the handle's one writer serializes the writes and the store keeps no lock of its own. A write that must check and change together — a create's name check and insert, a publish's commit and time, an update's apex check, a delete of the apex — does both inside one `DB.Write`, which is what keeps the catalog's invariants under concurrent calls.

A catalog that fails is a **failing** store: from a `SetFailing(true)` on its handle until a `SetFailing(false)`, and once its handle is closed, every method answers a catalog error and changes nothing. That is the one failure seam: a test that needs a call's reads to succeed and its write to fail turns it on from a hook the call runs between them (the `limits.Clock.After` the cache calls before each git run, or `cache.Config.Joined`), and never takes a permission away, which under WAL does not reliably fail a write. A call that changes nothing (an `Update` that changes no field, a `SetApex` of the site already the apex, a `ClearApex` with none set) writes nothing that can fail on its own; its answer is decided by its reads.

## Sites

A site's **id** is `sit_` and 16 lowercase hexadecimal digits, under appkit's registered entity prefix for the entity type `site` (appkit's telemetry contract), drawn from the random source when the site is created and never changed. Its **name** is 1 to 64 bytes, each a lowercase ASCII letter, a digit or `-`, the first not `-`, and none of `about`, `mcp` or `api`, since `/about` and `/mcp` are sites' own paths and `/api` is reserved across the suite on every app's host, sites' included; it is taken as given, never trimmed or folded. Its **slug** is the first segment of its URL: its name when it is created listed, and its name, `-`, and 8 lowercase hexadecimal digits drawn from the random source when it is created unlisted; it is fixed at create and nothing changes it, `listed` included. Names are one namespace for the whole space, because the slug is the URL: a name is **taken** when any site, of any owner, has it as its name or as its slug, so an unlisted site takes two strings, and a drawn slug that is already taken is drawn again rather than refused. Its **owner** is the user id of the caller that created it, the `UserID` of the `identity.Caller` appkit's identity gives the request (`D03-serve`). Its **repository** is a repository id as repos names its directory, kept verbatim, so a site keeps working across a rename in repos; the store never looks at it. Its **ref** is the ref a publish without one resolves, its **visibility** `public` or `private`, and **listed** whether the landing page shows it to others. **Created** is the time of the create and **published** the time of the last publish, both in UTC to the second, the precision the tools answer them in; **commit** is the sha that publish named, empty and with a zero `Published` until the first publish. A site is **unpublished** while its commit is empty.

## Reads and writes

The reads are what the consumers are built from: `Find` is a caller's own site by name, so another owner's site is indistinguishable from none; `BySlug` is any owner's site by slug, for serving; `List` is one owner's sites; `Visible` is what the landing page lists to a user, every listed site and that user's own unlisted ones; `Taken` is the space-wide name check. All lists are in ascending byte order of name and are never nil.

Every write names its site by id, which a consumer learned from a read. `Create` mints the id and the slug and stamps the created time; `Publish` sets the commit and the published time together, so a reader sees a site at its old commit or its new one and never a mix; `Update` changes any of visibility, listing and ref, all or nothing, and says which it changed; `Delete` removes a site and, when it was the apex, the apex with it. A field sent with the value it already has is not a change.

## The apex

The catalog holds one setting, `apex`: one site's id or nothing, nothing when a catalog begins. `Apex` reads it as the site it names, `SetApex` sets it to a public site, published or not, replacing whatever was there, and `ClearApex` unsets it. The apex site is always public: `SetApex` refuses a private site and `Update` refuses to make the apex site private, each with `ErrNotPublic` and changing nothing, and both decide against the same moment of the catalog, so no interleaving leaves a private apex. Deleting the apex site clears the setting in the same step, so the setting never names a site that is gone. Who may set or clear the apex is `D09-tools`'; the store takes any id.

## Errors

`ErrNotFound`, `ErrNameTaken` and `ErrNotPublic` are answers about the catalog's content. Every other error from a method is answered as the catalog being unreachable: every consumer answers it with `Unreachable`, the one line a tool refuses with, the landing page and every site path answer `503` with, and the apex host answers too, never quoting the underlying error. A failing store, a random source that fails and a context already done all end there. So does a write given a value no consumer sends — a name `ValidName` refuses, an empty owner or ref, a visibility other than `public` or `private`, a commit that is not a sha — which changes nothing: `D09-tools` refuses each of those first, with its own line. When one call meets several of these conditions, one fixed precedence decides its answer: a done context, then a failing store, then an invalid argument, then a missing site, then a taken name or a private apex.

## Decisions

- Ids are 8 bytes of `Rand`, slug suffixes 4 bytes; a create reads id candidates first, then, for an unlisted site, slug candidates, so a test handing in known bytes knows both in advance.
- A drawn id already catalogued and a drawn slug already taken are drawn again, never refused.
- `Update` and `SetApex` check apex-must-be-public in the same step as the write.
- A deleted site's id is not remembered, so a later create may in principle draw it again; with 64 random bits the odds are negligible, and keeping tombstones was not worth it.
- The store has no `Open` and no `Close`: the handle is appkit's, opened and closed by `cli.Run`, and a store over it lives as long as it does. The mutex the store once held is gone, since `DB.Write` already runs one writer at a time.
- The schema is contract (R-9U9Q-8OGL, R-XXRB-CKYB, R-Y074-44FP), and so is the record's JSON in `payload`, as far as a catalog an earlier sites kept must be read (R-RIWA-WS33).
- Only whole-second UTC times are accepted from an earlier catalog's `payload`, because every earlier sites wrote `Created` and `Published` as its clock's time in UTC truncated to the second, and so that every `Site` the store returns has the shape R-2K28-H01H states.
- The store validates nothing a tool has not already refused, beyond keeping its own invariants (name rule, owner, visibility, non-empty ref, commit shape).

## Consumer tasks

`cli.Run` opens the catalog with `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "sites.db"), Migrations: sites.Migrations(), Now: p.Now})`; on any error while `ctx` is not done it writes `D03-serve`'s diagnostic `sites: cannot open database state/sites.db: ` with the error's text as the reason; an error from a `ctx` already done is a stop, not a failure, and `D03-serve` says what `Run` does then; otherwise it hands `store.New(d, store.Config{Now: p.Now, Rand: p.Rand})` to `web.Config.Store` and calls `d.Close()` after the drain.

The tools (`D09-tools`), `u` being the `identity.Caller` of the call: `list` is `s.List(ctx, u.UserID)`; `show` is `s.Find(ctx, u.UserID, name)`; `create` checks `store.ValidName(name)`, then `s.Taken(ctx, name)`, then the repository and ref, then the visibility against `store.Public` and `store.Private`, and calls `s.Create(ctx, store.Draft{Owner: u.UserID, Name: name, Repo: repo, Ref: ref, Visibility: visibility, Listed: listed})`, `store.ErrNameTaken` still answering the taken rule's refusal when a racing create won; `publish` is `s.Find`, then the cache's resolve and unpack, then `s.Publish(ctx, site.ID, sha)`; `update` is `s.Find` then `s.Update(ctx, site.ID, store.Change{Visibility: v, Listed: l, Ref: r})`, the names it returns deciding the `site.*` events `D08-visitors-and-trail` states, and answering `apex site must be public` for `store.ErrNotPublic`; `delete` is `s.Find`, `s.Delete(ctx, site.ID)`, the cache's removal, and the apex event `D08-visitors-and-trail` states when `wasApex`; `apex` is `s.Apex(ctx)`, or `s.Find` then `s.SetApex(ctx, site.ID)`, or `s.ClearApex(ctx)`. `store.ErrNotFound` from `Find` is `no site named '<name>'`; an error matching none of the sentinels is the refusal `store.Unreachable`. A site object's `id` satisfies `store.ValidID`, which is also how every `site` event attribute is checked.

Pages and serving (`D06-pages`, `D07-site-serving`): the landing page is `s.Visible(ctx, u.UserID)`, `u` being the `identity.Caller` of the request, a row being the user's own when `Owner` equals that user id and published when `Commit` is not empty; a site path is `s.BySlug(ctx, slug)`, its `Visibility` compared with `store.Private` and its `Commit` naming the tree; the apex host is `s.Apex(ctx)` and the site's `Slug`. Each answers `store.Unreachable` and a newline, as plain text with status `503`, for an error matching no sentinel.

A test opens a handle with `db.Open(ctx, db.Config{Path: filepath.Join(t.TempDir(), "state", "sites.db"), Migrations: sites.Migrations()})` and builds a store with `store.New(d, store.Config{Now: clock, Rand: bytes.NewReader(known)})`; creates with `s.Create`, reads back with `Find`, `BySlug`, `List`, `Visible` and `Taken`, publishes, updates and deletes, sets and clears the apex, and closes the handle and opens another on the same path to see the same sites. It calls `d.SetFailing(true)`, before a call or from a hook the call runs after its reads, to see an unreachable catalog, and `d.SetFailing(false)` to see the same store answer again; and it hands in a `Rand` that fails. A schema test opens a fresh catalog with `sites.Migrations()` and, inside a `d.Read`, queries `sqlite_master` and `PRAGMA table_info`; an adoption test opens a handle on a file with an empty migrations file system, creates the two tables and writes rows in the earlier shape through `d.Write`, drops `schema_migrations`, closes it, and opens it again with `sites.Migrations()`.
