# D05-git-and-cache

How sites reads repos' repositories and keeps the trees it serves. This document is `internal/git`, the one way sites runs the host's `git`, and `internal/cache`, which reads a repository through it (its owner, a ref resolved to a commit, a commit's files) and keeps the trees under `cache/sites/`: the unpack bounded by the limits, the atomic install, the lazy rebuild a request triggers, the single rebuild requests for one tree share, pruning after a publish, removal on delete, and the one word that says why a tree could not be put back. It declares every exported name of both packages. `D01-layout-and-run-seam` declares `Process`, whose `Environ` is the environment of every git run, resolves `REPOS_DIR` into the directory `Config.Repos` names, and fixes `cache/sites` under `Dir` as `Config.Root`; `D03-serve` finds git with `git.Find` and opens the cache with `cache.Open` at start, and turns their failures into its start refusals; `D10-limits` owns `SITE_MAX_BYTES` and `OPERATION_SECONDS` as applied, `limits.Limits` with its `Settings`, `Clock`, `Operation`, `Draining` and `Halt`, and the sentinels `ErrTooLarge`, `ErrTimedOut`, `ErrDraining` and `ErrHalted` this document returns; `D04-store` owns the catalog and `store.ValidID`; `D07-site-serving` calls `Tree` and answers the `503` a failed rebuild earns; `D08-visitors-and-trail` owns the `site.unavailable` event and its attributes, whose `reason` is `Reason`'s; `D09-tools` calls `ValidRepo`, `ValidRef`, `Owner`, `Resolve`, `Unpack`, `Prune` and `Remove` and owns every refusal text built from what they return.

## Reading a repository

repos publishes its on-disk layout for siblings (repos' published disk layout): one bare repository per repository at `<REPOS_DIR>/<rep id>.git`, the id being `rep_` and 16 lowercase hexadecimal digits, `HEAD` naming `refs/heads/main`, and the repository's own config holding `ikigenba.id`, `ikigenba.name`, `ikigenba.owner` and `ikigenba.created`. sites reads it with the host's `git` and nothing else, three ways and no other, each with the argument list fixed below; repos receives no request and records no event on sites' account, and sites never writes there. A read never names a repository by its name, so a rename in repos changes nothing for sites.

- **Owner**: `git config --file <dir>/config --get ikigenba.owner`. git-config(1): `get` "emits the last value" of a key present several times and "Returns error code 1 if key is not present"; with `--file` only that file is read, so neither the system nor the global config can supply an owner the repository does not hold, and a directory with no `config` file is exit 1 too. Exit 1 is an unset owner, which `create` refuses as `no repository` (`D09-tools`).
- **Resolve**: `git --git-dir=<dir> rev-parse --verify -q --end-of-options <ref>^{commit}`. git-rev-parse(1): `--verify -q` prints the object name on success and otherwise exits non-zero, silently when the argument is not a valid object name; a valid object that does not peel to a commit (the sha of a tree) also exits 1 but writes `expected commit type` to standard error, which the cache discards; `--end-of-options` keeps a ref that begins with `-` from being read as an option, as the manual advises. A probe confirmed exit 0 and the full sha for a branch, an annotated or lightweight tag, a full or abbreviated sha; exit 1 for an unknown ref, a malformed one (`..bad`), the empty string, an absent sha and the sha of a tree; exit 128 for a `--git-dir` that is not a repository, which is why the cache looks at the directory first.
- **Archive**: `git --git-dir=<dir> archive --format=tar <sha>`. git-archive(1): the commit id rides in a global extended pax header, which is not a file of the tree; regular files, directories and symbolic links are the entries, a submodule is an empty directory, an empty tree is no entry at all.

`<dir>` is `RepoDir(repo)`, a relative `Config.Repos` being taken relative to the process's working directory. The proofs of these facts are the probes recorded beside this design's drafting; the manual pages are cited where they state the behaviour.

## The trees

A site's tree is `<Root>/<site id>/<sha>/`, the files of the commit exactly as `git archive` emits them: the same paths, the same bytes, symbolic links as links. An unpack writes into a staging directory beside the tree whose name begins with `.`, and renames it to `<sha>` only when it is whole, so a tree that exists is whole and a tree that is partly unpacked is never at the path `Tree` answers. A failed unpack leaves nothing of itself behind. A tree that already exists is kept, never unpacked again, never measured again. `git mktree` will make trees git itself would never check out — a symbolic link and a directory of the same name, or two files of one name — and `git archive` emits them; the cache refuses such a stream instead of writing through the link.

`Prune` keeps one tree of a site and removes everything else in its directory: other trees, and staging left by unpacks that are no longer running; `Remove` removes the site's directory. Neither removes the staging of an unpack still running on the same cache, which would turn a rebuild into a spurious `git_failed`; instead such an unpack, of a sha other than the one kept or of a removed site, finishes, answers its callers what it would have answered, and leaves no tree behind, so after a publish the site holds only its published tree and after a delete nothing. A request that read the catalog before the publish and holds the old commit may therefore be answered from a tree that is already gone, which `D07-site-serving` answers as it answers a missing file; it promises nothing more for that request. A rebuild of an old commit that starts only after the `Prune` (a request that read the catalog before the publish but reached the cache after it) installs its tree like any other, and that tree stays until the site's next `Prune` or `Remove`. `cache/` is disposable: an operator may empty it, or remove `cache/` itself, while sites runs, and the next unpack makes the directories again.

## Bounds

Every unpack, a publish's and a rebuild's alike, is bounded by `SITE_MAX_BYTES` (`D10-limits`): the sum of the sizes of the regular files in the tar stream, symbolic links and directories counting nothing; a sum of exactly the limit unpacks, one byte more does not, and the unpack stops when the sum passes the limit, deciding from the entry headers as they arrive: a commit whose first archived file is far over the limit and whose next file's blob is missing is `too_large`, never git's failure (git streams tar records of 10240 bytes, so a first file of 65536 bytes reaches the reader before git fails). Every git run — an owner read, a resolve, a rebuild's commit check, an archive — is timed on its own under `OPERATION_SECONDS`, through the context of its own `Limits.Operation` call — one call per git start attempt, made just before it, and none for a call that starts no git — and killed with every process it started when that context ends: at its deadline, at `Limits.Halt`, or when its caller's context ends. Once `Halt` has returned no git starts at all, and a call that would start one answers `limits.ErrHalted`.

## Rebuilding on demand

`Tree` answers the path of a site's tree. When the tree is there it answers at once and runs no git, whatever the repository, the limits or a publish in progress are doing. When it is missing, `Tree` rebuilds it: it looks for the repository's directory, checks that the repository still holds the commit with the resolve read, and unpacks it. Calls for the same site and commit that arrive while a rebuild runs wait for it and share its result; one archive runs. The rebuild belongs to no single request: a caller that gives up stops waiting, and the rebuild goes on for the others and, when it succeeds, leaves the tree for the next request. Nothing remembers a failure, so the next call tries again. Once draining has begun, a call that would start a new rebuild is refused with `limits.ErrDraining` and runs no git; a call that finds one running still shares it. `Unpack` ignores draining: a publish accepted before the signal unpacks and finishes within the drain.

## Why a tree is unavailable

`Reason` turns a `Tree` error into the `reason` of `site.unavailable` (`D08-visitors-and-trail`; `D07-site-serving` records it):

| `reason` | when |
|---|---|
| `repository_missing` | `RepoDir(repo)` is not a directory (or the id is not a repository id) |
| `commit_missing` | the resolve read of the published sha exits 1: the repository no longer holds that commit |
| `too_large` | the tree's files sum to more than `SITE_MAX_BYTES` |
| `timed_out` | a git run of the rebuild passed `OPERATION_SECONDS` |
| `git_failed` | anything else: git exited non-zero otherwise, git could not be started (removed from the host after start), a refused tar stream, a disk error, `Limits.Halt` |

## What is someone else's

The refusal texts of the tools and the order they check in are `D09-tools`'; the `503` answers, the drain `503` and the unavailable page are `D07-site-serving`'s; the events are `D08-visitors-and-trail`'s; the limit values, their defaults and parsing are `D10-limits`' and `D01-layout-and-run-seam`'s; the start refusal `sites: git not found on PATH` and the refusal when `cache/sites` cannot be made are `D03-serve`'s. Nothing in these two packages records an event or writes to the process's standard streams.

## Decisions

- The owner is read with `config --file <dir>/config` rather than `--git-dir=<dir> config`, so a global or system config can never make a repository look owned, and a directory with no config reads as unowned.
- Resolve passes `--end-of-options`, so a branch named `-x` resolves and no ref is read as an option.
- `ValidRef` is git-check-ref-format(1)'s rules 1 and 3 to 10 with rule 2 waived (`--allow-onelevel`), checked in process; a leading `-` in a component is allowed, as the manual says.
- A rebuild checks the commit with the resolve read before the archive, so a pruned commit is `commit_missing` rather than `git_failed`, within the three reads.
- Live staging is out of reach of `Prune` and `Remove`; an unpack superseded by either answers its callers and leaves nothing (see The trees).
- Every git runs in the process's own working directory, so a relative `Config.Repos` is read relative to it; `D01-layout-and-run-seam` has already joined a relative `REPOS_DIR` with `Dir`.
- `Config.Joined` and `Config.Unpacked`, nil in production, are the two test hooks: `Joined` tells a test that a second call is waiting on a running rebuild, so single-flight is proved without sleeping; `Unpacked` holds an unpack whose tree is whole but not yet installed, so a test can look at the catalog and at what a site's path answers at the last moment before a publish's tree is in place (`D09-tools`).
- An id that is not a repository id never reaches git (`ErrRepositoryMissing`), a site id `store.ValidID` refuses never reaches the disk, and a sha that is not 40 lowercase hexadecimal digits never reaches git (`ErrNoCommit`).

## Consumer tasks

At start (`D03-serve`): `g, err := git.Find(path, p.Environ)` with the `PATH` value, `errors.Is(err, git.ErrNotFound)` being the start refusal; then `c, err := cache.Open(cache.Config{Root: <Dir>/cache/sites, Repos: <resolved REPOS_DIR>, Git: g, Limits: l})`, `Joined` and `Unpacked` left nil.

Serving a site path (`D07-site-serving`), for a published site `s`: `dir, err := c.Tree(r.Context(), s.ID, s.Repo, s.Commit)`; with a nil error the request's path is resolved inside `dir`; `errors.Is(err, limits.ErrDraining)` is the drain `503`; an error matching `limits.ErrHalted`, or one matching the request's own ended context (`context.Cause(r.Context())`), gets no answer and records no event (`D07-site-serving`); any other error is the unavailable `503` and `site.unavailable` with `reason` `cache.Reason(err)` (one of `cache.ReasonRepositoryMissing`, `cache.ReasonCommitMissing`, `cache.ReasonTooLarge`, `cache.ReasonTimedOut`, `cache.ReasonGitFailed`).

Creating a site (`D09-tools`): `cache.ValidRepo(repo)`, then `owner, err := c.Owner(ctx, repo)` — `errors.Is(err, cache.ErrRepositoryMissing)` or `owner` other than the caller's id is the repository rule's refusal, `errors.Is(err, limits.ErrTimedOut)` is the time-out refusal, a `*git.Error` found with `errors.As` (or an error matching `git.ErrNotFound`) is the git failure text with the `Stderr` lines; `cache.ValidRef(ref)` decides the ref rule. Updating a ref uses `cache.ValidRef` alone and runs no git.

Publishing (`D09-tools`): `sha, err := c.Resolve(ctx, s.Repo, ref)` — `cache.ErrRepositoryMissing` is `tools.RepoUnavailable`, `cache.ErrNoCommit` is `tools.NoCommit`; then `err = c.Unpack(ctx, s.ID, s.Repo, sha)` — `limits.ErrTooLarge` is the size refusal, `limits.ErrTimedOut` the time-out refusal, a `*git.Error` the git failure text with its `Stderr`, and any other error (a refused hostile stream, a tree that cannot be written) `tools.GitFailed` alone; only after a nil `Unpack` does the store repoint the site (`D04-store`), and then `c.Prune(s.ID, sha)` leaves that one tree. A refused publish touched neither the catalog nor the site's old tree, which `Tree` goes on answering throughout. Deleting: the store removes the record, then `c.Remove(s.ID)`.

A test finds the real git with `exec.LookPath`, calls `git.Find` with a `PATH` holding its directory and an `environ` returning its own git environment, builds `limits.New` with a `limits.Clock` whose `After` returns channels it fires, and opens a cache over a temporary `Root` and `Repos` holding bare repositories it made with fixed dates (and hostile trees made with `git mktree`). It holds any git run at its start by putting `GIT_TRACE=<fifo>` in that environment and opening the FIFO when it chooses, and reads the same trace to count and see the git commands run; it sets `Joined` to learn that a second `Tree` call is waiting, and `Unpacked` to act while an unpacked tree is whole and not yet installed; it calls `Limits.Halt` before a call to see a halted one start nothing; it snapshots the repository directory before and after to see nothing written; it removes the git it found (a symbolic link in its own `PATH` directory) to see a start failure; and it removes the write permission of `Root/<site>`, or of `Root`, before a call to see a tree that cannot be written.
