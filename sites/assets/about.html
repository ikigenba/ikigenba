How it works

A site is a repository that repos holds, published at one commit. An agent makes one with create, naming the repository and the ref it tracks, main unless given, and publish resolves that ref and serves the commit's files exactly as git holds them, at /<slug>/.

A site may name a path, a directory of its repository, such as a build's output. A publish then serves only that directory, as the root of the site, and nothing above it can be reached through the site, so one repository can hold a site's source beside what it serves. A site with no path serves the whole tree.

What a site serves changes only when it is published: after a push, or a change to its ref or its path, publish again.
