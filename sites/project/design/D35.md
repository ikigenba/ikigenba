# Decision 35 — The `repos:push` consumer: re-materializing a site from `main`

**Decision.** sites becomes an **event-plane consumer** — its first subscription,
and the only one. It consumes repos' `push` family so that a change made outside
sites (a laptop push over the git door, a merged branch, a workflow's commit)
becomes live on the served site without anyone calling an MCP tool. This is the
"external changes arrive as `repos:push` events, on which the owning service
refreshes its copy" half of root D24; the envelope, routing key, glob matcher,
cursor, and the stall/skip semantics are `root project/design/D18.md`'s and are
not restated here.

sites remains **not a producer**: no `Spec.Feed`, no outbox, no `/feed` route.
Its reflection graph gains subscriptions and keeps an empty `publishes` (D13).

**The subscription**, declared in `cmd/sites/main.go`:

```go
Consumers: []appkit.Consumer{{
    Source: "repos",
    Subscriptions: []consumer.Subscription{{
        Source:      "repos",
        Filter:      "repos:push/sites/**",
        Description: "re-materialize a site's served files when its repository's main branch moves",
    }},
    Handler: func(rt *appkit.Router) consumer.Handler { /* materializer over store, layout, version client */ },
}},
```

The filter selects only pushes whose subject names the `sites` kind; a push to
`scripts/…` or `code/…` never reaches the handler. Feed URL and start position
resolve through the chassis' per-source convention (`SITES_REPOS_FEED_URL`,
`SITES_REPOS_FROM`) over `registry.BaseURL("repos")` — no literal address in
sites' source (D9).

**What the handler does**, in order:

1. **Branch gate.** If the event's branch is not `main`, return `nil` — advance
   the cursor, touch nothing. Proposed branches, CI branches, and run branches
   are not what is served, and re-materializing from them would publish
   unreviewed content.
2. **Resolve the site.** Take the slug from the subject's last segment and
   `Store.Get` it. `ErrNotFound` → return `consumer.ErrSkip`: the event names a
   repository sites has no row for (a site deleted here whose archived repo still
   emits, or a repository created directly through repos). It is not poison the
   handler can ever process, so it is logged loudly and skipped, never stalled.
3. **Echo gate.** If the event's sha equals the site's recorded `repo_sha`
   (D15), return `nil`. This is sites' own write coming back around: the copy is
   already exactly that tree, and exporting it again would be pure work. sites
   does **not** rely on an actor field in the payload for this — the recorded sha
   is a fact sites owns, so the gate is correct even if repos never marks the
   originator, and it is equally correct for an external push that happens to
   land the sha sites already has.
4. **Export and reconcile.** `version.Export(ctx, slug)` returns the whole tree
   at `main` as plain files. Reconcile them **in place** into
   `SiteDir(site.Visibility, slug)` — write every exported file, delete every
   file present locally and absent from the export — then record the export's sha
   on the row. Any export or filesystem failure returns that error, which
   **stalls** the consumer per the contract: the cursor does not advance and the
   same event re-delivers, so a site never silently stays stale.

**In place, not build-and-swap.** The obvious alternative — materialize into a
temporary directory and atomically rename it over the live one — is wrong *here*
specifically, because the served parents are exactly what `internal/serve` and
nginx expose: a scratch directory under `SITES_ROOT/public/` is a **servable
URL**, and a crash mid-swap leaves it there. In-place reconcile reuses
`sites.Reconcile` (D34's step 5, unchanged) and its worst case is a few seconds
in which a visitor may fetch a mix of old and new files — the same window a
sequence of `file_write` calls already has, and the site is self-healing on the
next event.

**No VCS metadata ever reaches the served tree, and it is checked.** The export
is plain files by contract, so `.git` cannot appear — which is precisely why
`internal/serve` needs **no** deny rule and the file tools need **no** exclusion
list: there is nothing to hide. Because that safety rests on another tree's
contract, the materializer does not take it on faith: it **rejects** any export
entry whose slash-separated path has a `.git` segment, is absolute, or contains
`..`, failing the whole materialization rather than writing part of it. A
malformed or hostile export is a stall the operator sees, not a `.git` directory
served to the internet.

**Rejected.**

- **Polling repos for changes instead of consuming events.** The plane exists;
  polling N sites on a timer is strictly worse (latency, load, and a second
  mechanism to keep honest).
- **Re-materializing on non-`main` pushes.** It would serve unmerged work, and
  root D24 is explicit that what is served is the tip of `main`.
- **Suppressing self-writes with the event's `actor` field.** The payload does
  carry one, and it is **not a self-write marker**: a merge of a laptop branch
  performed by a sites-initiated call carries sites' actor while containing
  changes sites has never seen, so an actor check would skip exactly the event
  that mattered. (repos confirms this and recommends against leaning on it.) It
  would also make sites' correctness depend on a payload field another tree
  owns, and it would wrongly skip the case where sites' local apply failed after
  a successful commit (D33), leaving the copy permanently stale. The recorded sha
  has none of these failure modes: it is local, needs no cooperation, and is
  right in every one of those cases. Being a pure optimization over an already
  idempotent re-materialization, it is also safe when it does nothing.
- **Treating an unknown slug as a stall.** It would wedge the cursor forever on
  an event no future state can make processable, blocking every later event for
  every other site.
- **Treating an export failure as a skip.** The opposite error: it would advance
  past a change the site needs and leave it serving stale bytes with no signal.
  Stall is the safe direction the contract names.
- **A build-and-swap materialization.** Covered above: the staging directory
  would itself be served.
- **Deleting local files the export omits only when the export is "trusted".**
  A conditional reconcile is a divergence generator. The export is the tree;
  the copy matches it or it is not a copy.

**Verification.** (Substrate: hermetic. The handler is driven directly with
constructed envelopes over a temp `SITES_ROOT`, a real migrated SQLite DB, and
the contract-conforming `httptest` repos server of D32 serving scripted exports —
no feed, no network, no running suite.)

- R-F3GA-3K1N — **a `main` push re-materializes the tree in both directions.**
  With a site whose copy holds `index.html` (old bytes) and `stale.html`, and an
  export offering `index.html` (new bytes) and `about.html`, a
  `repos:push/sites/<slug>` event on branch `main` with a new sha leaves the
  copy holding exactly `index.html` (**new** bytes) and `about.html`, with
  `stale.html` **gone**, and the row's `repo_sha` equal to the pushed sha. An
  implementation that only adds files fails on `stale.html`; one that only
  replaces existing files fails on `about.html`.
- R-F4O6-HBSC — **a non-`main` push is ignored.** An otherwise identical event
  on branch `feature/x` returns `nil` (the cursor advances), makes **zero**
  export calls against the repos server, and leaves every byte under
  `SiteDir(v, slug)` and the row's `repo_sha` unchanged.
- R-OEVK-U243 — **the echo is suppressed.** An event on `main` whose sha equals
  the site's recorded `repo_sha` returns `nil`, makes **zero** export calls, and
  writes nothing; the immediately following event with a *different* sha does
  export and does rewrite the tree — proving the gate keys on the sha rather
  than disabling the consumer.
- R-F5W2-V3J1 — **an unknown slug skips, it does not stall.** An event whose
  subject names a slug with no row returns an error satisfying
  `errors.Is(err, consumer.ErrSkip)` and writes nothing. A handler returning a
  plain error (which the engine would treat as a stall) fails.
- R-F73Z-8V9Q — **an export failure stalls.** With the repos server made to fail
  `Export`, the handler returns a non-nil error that is **not** `ErrSkip`, the
  row's `repo_sha` is unchanged, and the site's files are byte-identical to
  before — so the engine re-delivers the same event and the site is not left
  silently stale. A handler that swallows the failure and returns `nil` fails.
- R-F8BV-MN0F — **a VCS-metadata or escaping path in an export is refused
  whole.** An export containing a legitimate `index.html` plus an entry at
  `.git/config` causes the handler to return a non-`ErrSkip` error, and
  **neither** file is written: no `.git` exists anywhere under `SITES_ROOT` and
  `index.html` was not applied either (all-or-nothing, not partial). The same
  holds for an entry at `nested/.git/HEAD`. A materializer that filters the bad
  entry and applies the rest fails — silently dropping content is how a copy
  diverges from its repository.
- R-F9JS-0ER4 — **materialization is confined to the site directory.** An export
  entry at `../../escape.html` (and one at `/etc/escape.html`) causes the same
  whole-materialization refusal, and no file named `escape.html` exists anywhere
  outside `SiteDir(v, slug)` — checked against the temp root's parent, not only
  against the site directory.
