# Decision 31 — Adopt the suite testing-language contract

**Decision.** sites adopts the suite's testing-language contract,
`root project/design/D23.md`, by citation. That contract owns the four test
layers (**hermetic / composed / live / manual**) and what each may touch, the
single mechanism for live tests (`//go:build live`, invoked as
`go test -tags live ./...`, hard-failing on absent credentials), the ban on
`t.Skip` outside live-tagged files, and the requirement that every tree declare
its own testing facts in its `AGENTS.md`. This Decision restates none of that.
It records only the sites-specific facts the contract asks this tree to declare,
and adopts the contract's two per-service ids.

The `root` prefix on the citation is load-bearing here beyond the suite-wide
reason: this tree has its **own** local D23 (the headless-browser wiring
Decision), so a bare `project/design/D23.md` would name that one.

**The layers sites has.** Two, both in the default gate:

- **hermetic** — the bulk of the suite: `internal/serve` driven through
  `net/http/httptest` over a `t.TempDir()` `SITES_ROOT`; `internal/sites`
  against a real temp-file SQLite database through the real appkit migration
  runner (including the `pragma table_info` and rejected-INSERT schema
  assertions); `internal/mcp` at the handler boundary with injected Identity
  headers; the landing render over the repo-real `share/www` tree loaded with
  `appkit/web.Load`; the `share/www/static/landing.js` logic tests, which read
  the shipped file and evaluate it in `goja` in-process; the
  `etc/nginx.conf` content assertions; the injected-outbound-client tests, whose
  substrate is a recording `RoundTripper`; the version-plane tests (D32–D37),
  whose substrate is a contract-conforming, recording `httptest` repos server on
  loopback plus the real temp-dir filesystem and DB; and the import-graph guard, which
  shells out to `go list -deps ./cmd/sites` to prove the two test-only
  dependencies link into no shipped binary. **The headless-browser wiring test
  (local D23) is hermetic too**: it launches a local `google-chrome` subprocess
  against an `httptest` render on a loopback address — a local subprocess and a
  loopback listener, which is precisely what the contract's hermetic row
  allows. It never builds or runs sites' own binary.
- **composed** — the boot smoke in `cmd/sites/main_test.go`: it assembles an
  `/opt/sites/`-shaped tree under `t.TempDir()`, `go build`s the real `cmd/sites`
  binary into it, runs that binary's `serve` verb on a free loopback port, and
  drives `/health`, the landing route, and (for D32's R-ER9A-9UMP) one MCP
  `file_write` against a stub repos server on loopback, over loopback HTTP.

sites has **no live layer**: it contacts no external service and reads no
credential — the dropbox mirror client is exercised only through an injected
recording `RoundTripper`, never against real Dropbox, and the version-plane
client only against an in-test loopback server, never a running repos — so no
`//go:build live` file exists here and the `-tags live` invocation is not part of
this tree's testing story. sites also carries **no manual-layer runbook**: no
committed check of its own requires the operator. Adding either later is a
Decision, not a drift.

**Why no test here drives a real repos.** It would be the substrate that could
falsify "repos accepts what sites sends" — and it is out of bounds twice over: a
`project/` governs only its own tree, so no sites phase may build, run, or test
repos; and root `project/design/D24.md` already assigns that claim to repos' own
ids. sites proves its half against a conforming fake and says so on every id.

**GOWORK mode.** sites tests, builds, and vets in **workspace mode** through the
repo-root `go.work`; the production build forces `GOWORK=off` (driven by
`bin/ship sites`) and is not part of the default gate. This is already stated in
this design's *Conventions*; the contract's declaration requirement is what makes
it `AGENTS.md`-visible.

**Environmental preconditions beyond the Go toolchain.** Two, both hard failures
when absent, never skips:

- A **`google-chrome` binary on `PATH`** of the box running the suite, for the
  local D23 browser-wiring test. This design's *Conventions* and the tree's
  `AGENTS.md` already say so in prose; the contract's declaration requirement and
  the doc-truth id below are what make the statement mechanically re-checked
  rather than asserted once at authoring time.
- The **`go` binary on `PATH` in the test process's environment** (not merely the
  toolchain that compiled the tests), with the module cache already resolving
  sites' `replace` siblings. The composed boot smoke shells out to `go build` and
  the import-graph guard to `go list`; neither does a network fetch and neither
  may acquire one.

**Where this lands.** Nothing in sites' shipped source changes. The adoption is
carried by two tagged tests and by the `AGENTS.md` Tests section stating the
facts above; the plan phase that realizes this Decision does both.

**Rejected.**

- *Restating the layer definitions, the live-tag mechanism, or the skip ban in
  this design.* Citation is the mechanism (`$ikispec`, "cite, never restate"): a
  local copy of a suite contract is drift by construction the moment the umbrella
  moves. This file names only what is particular to sites.
- *Re-minting local ids for the two behaviors.* The umbrella marks R-O1AD-MRKW
  and R-O2IA-0JBL `[proof: per-service]`; citing those exact ids **is** the
  adoption, and a fresh local id would be a second handle for one behavior.
- *Classifying the browser-wiring test as composed because it drives a real
  browser.* The layer is defined by what a test may **touch**, not by how heavy
  it is. That test touches a local subprocess and a loopback `httptest` server
  and never the sites binary — the hermetic row's own description. Filing it as
  composed would make the label track cost instead of reach, and would leave the
  actual composed boot smoke indistinguishable from it.
- *Declaring `google-chrome` an optional precondition and skipping when absent.*
  That is exactly the shape the contract bans: a requirement test that is
  silently green on a box without the browser launders a gap into a pass. Both
  this design's *Conventions* and the contract agree — no Chrome means the suite
  is **red**.
- *Treating the `go`-on-`PATH` requirement as implied by "it's a Go project".*
  The toolchain that compiles the tests and the `PATH` the test process inherits
  are different things; the composed smoke needs the latter, and an undeclared
  precondition is the failure the doc-truth id exists to catch.

**Verification.**

- R-O1AD-MRKW — cited from `root project/design/D23.md` (`[proof:
  per-service]`); adopted here. A test reads sites' committed `AGENTS.md` from
  disk and asserts its Tests section declares the default-gate test command, the
  layers present in the contract's vocabulary (hermetic and composed), every
  environmental precondition beyond the Go toolchain (`google-chrome` and the
  `go` binary), and the tree's GOWORK mode. Substrate: hermetic (real committed
  file read from disk).
- R-O2IA-0JBL — cited from `root project/design/D23.md` (`[proof:
  per-service]`); adopted here. A source scan over sites' `*_test.go` files,
  excluding files carrying the `live` build constraint, finds **zero**
  occurrences of `t.Skip`, `t.Skipf`, or `t.SkipNow`. The scan assembles its
  needle from parts so it never matches itself. Substrate: hermetic (source
  scan).
