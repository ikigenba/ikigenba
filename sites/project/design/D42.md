# Decision 42 — The in-place reconcile is type-change-safe and deletes before it writes

**Decision.** The shared in-place reconcile — `sites.Reconcile`, the single
helper every inbound door reuses (`sync` D34 step 5, the `repos:push`
materializer D35, and `set_path` D38) — makes a served directory match a desired
set of files **without failing on a file/directory type change**. This is the
sites-side fix for the class of failure where a path that is a **directory**
in the served copy must become a **file** (or the reverse) because the
authoritative source (the mirror, or the repository at `main`) now says so.

The naïve reconcile — "write every desired file, then/whilst delete every local
file absent from the desired set" — breaks on exactly that transition: writing a
regular file at a path where a directory currently sits fails at the filesystem
with `open <path>: is a directory` (and the reverse, needing a directory where a
regular file sits, fails with `not a directory`), leaving the served copy in the
partial, wrong state the operator observed. The doors above are **authoritative
materializers** — they must faithfully reproduce the source tree, so unlike the
interactive single write (D33, which *refuses* a type change) they must *perform*
it.

**The contract.** `Reconcile(dir string, desired map[string][]byte)` (or the
existing `Reconcile(dir, desired, existing)` shape — the walk that produces
`existing` is unchanged) applies `desired` to `dir` so that, on success, `dir`
contains **exactly** the paths in `desired` with their bytes and nothing else:

1. **Deletes run before writes.** Every local path absent from `desired` is
   removed first. A removed file whose parent directory is thereby left empty has
   that now-empty directory pruned. Ordering deletes ahead of writes is what makes
   both type transitions resolve *for free*: when a former directory `qr/` must
   become a file `qr`, every file under `qr/` is (by definition) absent from
   `desired` and so is deleted, the emptied `qr/` is pruned, and the later write
   of `qr` lands on clear ground; when a former file `qr` must become a directory
   `qr/`, the file `qr` is absent from `desired` (which holds `qr/…` entries) and
   so is deleted before those entries are written.
2. **A write clears a wrong-typed node at its own path.** As a backstop for any
   case ordering alone does not cover, before writing a file at path `P` the
   reconcile removes anything of the wrong type sitting at `P` (a directory) or at
   an ancestor of `P` (a regular file where a parent directory is needed), then
   creates the parent directories and writes. No `is a directory` / `not a
   directory` error escapes for a well-formed desired set.
3. **In place, never build-and-swap.** The reconcile continues to mutate the
   served directory directly (D35's constraint: a staged sibling under
   `SITES_ROOT/public/` would itself be a servable URL, so building beside and
   renaming over is forbidden here). "Type-safe" is therefore about never
   *erroring* on a legitimate transition, not about hiding the brief window in
   which a visitor may fetch a mix of old and new files — that window is the same
   one a sequence of `file_write` calls already has and each door already
   documents (D35).
4. **A filesystem error is returned, not swallowed.** If an OS operation still
   fails (a genuine I/O error, a permission problem), `Reconcile` returns that
   error unchanged. Each door keeps its own failure semantics on top: `sync`
   (D34) and `set_path` (D38) have already committed/exported first, so a local
   failure is a process-local error the caller retries; the push materializer
   (D35) stalls the cursor and re-delivers. Type-safety removes the *spurious*
   errors (the type-change ones), leaving only real ones.

**Input assumption (asserted, not validated at runtime).** `desired` comes from a
filesystem tree — a mirror enumeration (D34), a repository export (D35), or a
subtree map (D38) — so it is internally type-consistent by construction: no path
is present both as a file and as a directory prefix. The export refusal rules
(D35: `.git`, absolute, and `..` entries) already reject malformed or hostile
inputs *before* reconcile is reached, so `Reconcile` does not re-validate the set;
a caller handing it a self-inconsistent map is a programming error upstream, not a
runtime branch here.

**Rejected.**

- **Refusing the type change in the doors too (as D33 does for the single write).**
  D33 refuses because an *interactive* write onto a directory is almost always a
  mistake and silently destroying a subtree is the wrong default. The doors are the
  opposite case: they exist to make the copy equal the source, and the source has
  legitimately restructured `qr/` into `qr`. Refusing there would freeze a site's
  served copy permanently out of sync with its repository — the very failure this
  Decision fixes.
- **Build-and-swap for atomicity.** Rejected by D35 for the reason restated above:
  the staging directory is itself served. In-place with deletes-first is the
  reconcile shape this tree can actually use.
- **A two-phase "delete all then write all" that empties the tree first.** It would
  make *every* reconcile pass through a moment where the whole site is missing, not
  just the handful of transitioning paths — a strictly larger bad window for no
  benefit over deleting only the paths that are actually leaving.
- **Leaving the ordering unspecified and letting the writer `MkdirAll`/`Remove` ad
  hoc.** That is the status quo, and its unspecified order is exactly why a
  dir→file case hit `is a directory`. The order is the contract.

**Verification.** (Substrate: hermetic. The transition ids drive `sites.Reconcile`
over a real tree under a `t.TempDir()`; the dir→file id additionally drives the
transition end-to-end through the assembled `set_path` MCP handler over a temp
`SITES_ROOT`, a real migrated SQLite DB, and the contract-conforming recording
`httptest` repos server of D32, so the type-safe reconcile is proven wired into a
real door, not only as an isolated helper.)

- R-FJYN-3U1U — **directory → file, through a real door.** A site whose served
  copy holds `qr/index.html` (and `index.html`), reconciled toward a desired set
  in which `qr` is a **regular file** (and `index.html` unchanged) — exercised via
  `set_path` whose export maps to exactly that set — ends with `qr` a regular file
  carrying the desired bytes, **no** directory `qr/` and no `qr/index.html`
  remaining, and no `is a directory` error returned. A build that writes before
  deleting, or that does not prune the emptied `qr/`, fails with the filesystem
  error this Decision removes.
- R-FL6J-HLSJ — **file → directory.** `Reconcile` over a tree whose served copy
  holds a regular file `qr`, toward a desired set holding `qr/index.html`, ends
  with `qr/index.html` present with the desired bytes and **no** regular file `qr`
  remaining, no `not a directory` error. A build that tries to `MkdirAll` under
  the existing file `qr` without removing it first fails.
- R-FMEF-VDJ8 — **deletes precede writes and emptied directories are pruned.** A
  reconcile whose desired set simultaneously (a) omits every file under an existing
  directory `d/` and (b) writes a regular file at path `d`, applied to a copy that
  holds `d/a.txt` and `d/b.txt`, completes without error and leaves exactly the
  desired paths — proving the delete-before-write ordering rather than an
  interleaving that would hit `open d: is a directory`. A build whose write phase
  can run before the corresponding deletes fails.
