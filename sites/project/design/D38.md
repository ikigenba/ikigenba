# Decision 38 — The publish root: `path` selects the repository subfolder the site serves

**Decision.** A site gains one new row fact: its **publish root** — the `path`
column (D15), a repository-relative folder whose contents are what the site
serves. The default, `""`, means the repository root and is exactly today's
behavior; a non-empty value (e.g. `the/content/is/here`) narrows the site to
that subtree. This is the shape a static-site generator produces — sources and
build config in the repository, output in a `public/` folder — and the publish
root is how that output folder, and only it, becomes the site.

The invariants, stated once:

- **The path is a row fact only.** It never appears in the site's URL (the slug
  is the whole address), never appears in any on-disk sites path
  (`SiteDir(v, slug)` is unchanged), and survives every visibility transition,
  slug rotation, and `rename` — like the display name, only its own tool
  changes it.
- **The served copy is the materialized subtree.** Everything D16 says about the
  served tree holds with one refinement: the copy is the repository's tree at
  `main` **under the publish root**, with the root prefix stripped. A repository
  file outside the root is not served, is not on sites' disk, and is invisible
  to sites' file tools — it is repos' domain, reached through the git door and
  repos' own surface (settled with the operator).
- **The commit boundary maps the prefix.** sites' file tools keep addressing the
  served copy exactly as before; the publish root exists only where bytes cross
  to or from the repository: outbound, every committed `FileChange.Path` is the
  site-relative path **prefixed with the root**; inbound, every export is
  **filtered to the root and stripped of it**.
- **An absent subtree is an empty site, not an error.** The natural order is
  create → `set_path("public")` → wire up the generator, so `main` may hold no
  such folder yet (and a later push may delete it). An export with no entries
  under the root materializes as an empty served tree, exactly as an empty
  repository already does (D32).

**The validator** (`internal/sites`), beside `ValidateName`/slug validation:

```go
var ErrInvalidPath = errors.New("invalid publish path")

// ValidatePath normalizes a publish-root path. "" and "/" normalize to ""
// (the repository root). Any other value has leading and trailing slashes
// stripped and must then be a relative, slash-separated path; it is returned
// in that normalized form. ErrInvalidPath when: any segment is empty, ".",
// "..", or ".git" (case-insensitively); the path contains a backslash or a
// control character; or the normalized form exceeds 255 bytes.
func ValidatePath(raw string) (string, error)
```

The **normalized** value is what is stored (D15's `path` column) and what every
projection returns. There is no requirement that the folder exist anywhere —
validation is grammar, not repository state.

**The subtree mapping** (`internal/sites`), used by every inbound door — the
push materializer (D35) and `set_path` below:

```go
// Subtree filters an exported tree to the entries under root (a normalized
// publish root; "" is the identity) and strips the "<root>/" prefix from each
// kept entry's Path. Entries outside root are dropped. It performs no
// validation of its own — entries are still subject to the materializer's
// refusal rules (D35) after mapping.
func Subtree(entries []TreeEntry, root string) []TreeEntry
```

**The MCP surface** (extending D20's table; D20 cites this Decision rather than
restating it):

- **`create(name, slug?, visibility, path?)`** — `path` is optional; omitted or
  empty means the repository root. It is validated by `ValidatePath` (an
  invalid path is a `validation` error before any row, directory, or repository
  exists) and the normalized value is stored on the row at birth. Everything
  else about `create` (D20, D36) is unchanged.
- **`set_path(slug, path)`** — the publish-root mutator, a small dedicated tool
  like `rename`. `path` is **required** (pass `""` or `"/"` to return to the
  repository root — requiring the argument keeps "change it" and "forgot it"
  distinguishable). It validates via `ValidatePath` (`validation`), resolves
  the site (`not_found`), and then re-materializes so the change is visible at
  once rather than waiting for the next push:

  1. **Export first.** `version.Export(ctx, slug)` — the only plane call this
     tool makes (never `Create`/`Rename`/`Commit`). If repos is unreachable the
     tool fails `source_unavailable` and **nothing** has changed — no row
     write, no file touched. This is D36's plane-first ordering for the same
     reason: the common failure (repos down) is a clean refusal.
  2. On success: `Store.SetPath(slug, path)` (D15), then reconcile
     `Subtree(entries, path)` in place into `SiteDir(v, slug)` (the same
     in-place reconcile as D35 — write every mapped file, delete every local
     file absent from the mapped set), then record the export's sha
     (`SetRepoSha`). A local failure after the row update is a process-local
     failure the caller sees and retries — `set_path` is idempotent, and the
     next `repos:push` also heals it.

  Returns the site projection. Setting the path a site already has is an
  idempotent success that still re-materializes (a cheap way to force a
  refresh, not worth special-casing away).
- **The projection gains `path`.** `renderSite` (D20) and every declared site
  `outputSchema` (D25) carry `path: string` — the stored normalized value, `""`
  for the repository root — so an agent can read the setting back from
  `create`/`list`/`set_visibility`/`rename`/`set_path` alike.
- `set_path` is a **structured** tool (D25): `outputSchema` is the site
  projection; failures use the closed vocabulary above. The tool count facts
  are D13's and D21's and are updated there (15 domain / 17 total).

**The write path through the root** (the mapping D33/D34 cite):

- `file_write` / `file_edit` commit their single `FileChange` at
  `<path>/<site-relative>` (e.g. root `public`, write `index.html` → commit
  `public/index.html`) and apply locally at `SiteDir(v, slug)/<site-relative>`
  exactly as today. Commit-then-apply ordering, failure semantics, and `mkdir`'s
  no-commit rule are D33's, unchanged.
- `sync` builds its one batch (D34) the same way: every write and every delete
  in the change set carries the root prefix; the local walk and apply are
  root-relative to the served copy as today. With `path == ""` every mapping in
  this Decision is the identity and the committed bytes are byte-identical to
  the current design.
- The push materializer (D35) applies `Subtree` to the export before its
  existing refusal checks and reconcile; its branch gate, echo gate, skip/stall
  semantics, and confinement refusals are unchanged. A push that only touches
  files outside the root still re-materializes (the sha moved); the reconcile
  finds the subtree unchanged and the copy stays byte-identical — accepted
  redundant work, the same overwrite-all posture as D34.
- Seeding (D37) is untouched by construction: it applies only to pre-plane rows,
  which the additive migration lands at `path = ''`, and their served tree *is*
  their repository root.

**Rejected.**

- **File tools spanning the whole repository.** It would require a second full
  copy of the repository on sites' disk beside the served subtree, new
  confinement rules for a tree that is not served, and it rebuilds repos inside
  sites. The operator settled it: sites sees only the publish root; the rest of
  the repository is reached through repos.
- **The path as a URL segment or an on-disk segment.** The operator's intent is
  explicit: the public URL is still just the slug. And an on-disk `<path>`
  segment would leak a repository-layout fact into served paths and `Move`.
- **Create-time-only (immutable) path.** The real workflow sets the path after
  the repository grows its generator layout; immutability forces
  delete-and-recreate, which burns an unlisted site's link.
- **`set_path` refusing a folder absent from `main`.** Ordering-dependent (a
  placeholder commit would be needed first) and unenforceable — a later push
  can always delete the folder, so the empty state must be handled regardless.
- **Row-first `set_path` (update the row, then export).** An unreachable repos
  would then leave the row saying `public/` while the copy still shows the old
  root — a lie until some future push. Export-first makes the common failure a
  clean no-op refusal.
- **Waiting for the next push instead of re-materializing in `set_path`.** The
  change would be invisible until unrelated activity; and no push may ever come
  (the echo gate does not re-fire on an unchanged tip).
- **A repos-side subtree export parameter.** It narrows bytes on the wire but
  puts sites' publish-root concept into repos' contract; the whole-tree export
  already exists and the filter is a few lines here. Revisit only if export
  size ever hurts.

**Verification.** (Substrate: hermetic — the same seams as D20/D33/D34/D35: the
assembled `appkit/mcp` handler and the directly-driven consumer handler over a
temp `SITES_ROOT`, a real migrated SQLite DB, and the contract-conforming
recording `httptest` repos server.)

- R-3TWL-UEHA — `ValidatePath` normalizes and rejects per its contract: `""`
  and `"/"` return `""`; `"public"` returns `"public"`; `"/the/content/is/here/"`
  returns `"the/content/is/here"` (leading and trailing slashes stripped, inner
  segments kept); and each of `"a//b"` (empty segment), `"a/./b"`, `"a/../b"`,
  `".git"`, `"a/.GIT/b"` (case-insensitive), `"a\\b"`, `"a\nb"`, and a
  normalized form longer than 255 bytes returns `ErrInvalidPath`. A validator
  that accepts `..`, is case-sensitive on `.git`, or slash-trims into accepting
  `"//"` as root fails.
- R-3V4I-867Z — `create` takes the publish root at birth: a
  `create(name, slug, visibility:"public", path:"/docs/site/")` persists the
  **normalized** `docs/site` (readable via `Get` and in the returned
  projection's `path` field), while a `create` omitting `path` persists `""`
  and its projection carries `path: ""`; a `create` with `path:"a/../b"`
  returns `validation` and creates **no** row, **no** directory, and **no**
  repository (zero repos calls). A build that stores the raw un-normalized
  string, or defaults the field to anything but `""`, fails.
- R-3WCE-LXYO — `set_path` re-materializes export-first: with a site at
  `path ""` whose copy holds `index.html` and `readme.md`, and the repos server
  exporting `{project.txt, public/index.html, public/css/app.css}` at sha `S`,
  `set_path(slug, "public")` makes **exactly one** repos call (`Export` — no
  `Commit`, no `Rename`, no `Create`), and afterwards the row's `path` is
  `"public"`, the served copy holds exactly `index.html` (the **exported**
  `public/index.html` bytes) and `css/app.css` — prefix stripped, `project.txt`
  absent, the old `readme.md` gone — the row's `repo_sha` is `S`, and the
  returned projection carries `path: "public"`. A build that serves
  `public/…`-prefixed paths, keeps stale files, or writes entries from outside
  the root fails.
- R-3XKA-ZPPD — a failed `set_path` changes nothing: with the repos server
  refusing connections, `set_path(slug, "public")` returns the
  `source_unavailable` error envelope and the row's `path`, the row's
  `repo_sha`, and every byte of the served copy are unchanged; with the server
  answering `400`, the result is `internal` and equally nothing changed. A
  build that updates the row before the export succeeds fails.
- R-3YS7-DHG2 — `set_path` refuses bad input cleanly: an invalid path
  (`"a/../b"`) is `validation`, an unknown slug is `not_found`, and a call
  **omitting** `path` is `validation` — in all three cases zero repos calls are
  made and nothing changes. (Returning to the root is `path: ""`, which
  succeeds — the required-argument rule rejects *absence*, not the empty
  string.)
- R-4003-R96R — the write path carries the prefix: on a site with
  `path "public"`, `file_write(site, "css/app.css", …)` records exactly one
  `Commit` whose single `FileChange.Path` is `public/css/app.css` with the
  written bytes, while the file lands locally at
  `SiteDir(v, slug)/css/app.css`; `file_edit` of that file commits the
  post-edit bytes at the same prefixed path; and `mkdir` still makes zero repos
  calls. A build that commits the unprefixed path, or applies locally under a
  `public/` directory, fails.
- R-4180-50XG — `sync` batches through the prefix: on a site with
  `path "public"`, a mirror offering `{index.html}` while the copy holds
  `{index.html, stale.html}` yields **one** `Commit` whose change set is a
  write at `public/index.html` and a delete at `public/stale.html`, and the
  served copy afterwards holds exactly `index.html` with the mirror's bytes. A
  build whose deletes are unprefixed (or whose writes are double-prefixed)
  fails.
- R-42FW-ISO5 — the push materializer maps through the root: on a site with
  `path "public"` and a `main` push whose export is `{project.txt (new bytes),
  public/index.html (new bytes), public/new.html}` while the copy holds
  `{index.html (old), stale.html}`, the handler leaves the copy holding exactly
  `index.html` (**new** bytes) and `new.html`, with `stale.html` gone,
  `project.txt` never written anywhere under `SITES_ROOT`, and `repo_sha` at
  the pushed sha. The refusal rules still hold after mapping: the same push
  with an added export entry at `public/.git/config` is refused whole
  (non-`ErrSkip` error, nothing written). A build that writes `project.txt` or
  serves `public/index.html` un-stripped fails.
- R-43NS-WKEU — an absent subtree is an empty site: `set_path(slug, "public")`
  when the export contains **no** entry under `public/` succeeds — the row's
  `path` is `"public"`, the served copy is empty (its previous files removed),
  and the sha is recorded; a subsequent `main` push whose export now carries
  `public/index.html` leaves the copy serving `index.html`. A build that errors
  on the empty subtree, or refuses to delete the now-out-of-root files, fails.
