# Decision 28 — The dropbox mirror client takes the Router-provided instrumented outbound HTTP client

**Decision.** This Decision owns the **dropbox-mirror** outbound call: the `sync`
verb's traffic in `internal/sites/sync.go` (`GET <base>/list`,
`GET <base>/content`). That client stops being `http.DefaultClient` and becomes
the **instrumented outbound HTTP client the chassis Router provides** —
`rt.HTTPClient(…)`, which hands back a client already wired to the recorder, so
sites never touches the recorder itself.

sites' *other* outbound traffic — the version-plane calls to repos — follows the
same rule for the same reasons, and is D32's to state and prove. The principle is
shared and stated once here: **every** outbound client in sites comes off the
Router, is injected at the composition root, and is handed the live request
context.

The Router is reachable at the composition root, not from inside
`internal/sites`, so the client is **injected**: `NewMirrorClient` takes it as a
parameter and `cmd/sites/main.go` — which already holds `rt` and builds the
mirror client (`sites.NewMirrorClient(base)`) inside the `Spec.Handlers` closure
— supplies it.

```go
// internal/sites/sync.go — MirrorClient, List, and Fetch keep their signatures;
// only where the *http.Client comes from changes.
type httpMirrorClient struct {
	base string
	hc   *http.Client   // was http.DefaultClient; now the Router's instrumented client
}

func NewMirrorClient(base string, hc *http.Client) MirrorClient

// cmd/sites/main.go, inside Spec.Handlers
mirror := sites.NewMirrorClient(base, rt.HTTPClient(30*time.Second))
```

`rt.HTTPClient(timeout)` (appkit D20) wires the service's recorder for sites and
keeps `appkit/telemetry` out of sites' imports. The lower-level
`appkit/httpclient.New(Options{…})` exists for callers needing a custom
transport or redirect policy; sites needs neither.

**One operational hazard, recorded because the code invites it.** Propagation is
keyed on the target host being a **loopback IP literal** (`127.0.0.0/8` or
`::1`); the *name* `localhost` deliberately does not qualify. sites' mirror base
is `config.EnvOr(os.Getenv, "DROPBOX_BASE_URL", registry.BaseURL("dropbox"))` —
the registry default is `http://127.0.0.1:<port>` and qualifies, but a
`DROPBOX_BASE_URL` set to `http://localhost:<port>` would silently stop
propagating the id while everything else kept working. That is a deployment
note, not a code branch: sites does **not** normalize or rewrite the configured
host, because a service second-guessing its own configuration is worse than the
gap it patches. The env var stays as documented and the default stays the
registry's IP literal.

**What the chassis client is (consumed as an external fact).** appkit's design
owns this client — its package, its constructor name, and everything it records.
sites consumes only its contract:

- It is an `*http.Client`; nothing about `MirrorClient`, `List`, or `Fetch`
  changes shape, so this is a one-line construction change plus its wiring.
- Every call through it is recorded as a telemetry record of kind `outbound`,
  with the operation, elapsed time, status class, and a size + SHA-256 digest of
  the response body. **sites asserts none of that** — it is appkit's behavior,
  proven by appkit's own ids, and re-proving it here would duplicate chassis
  coverage.
- It propagates the ambient `X-Correlation-Id` **only when the target host is a
  loopback IP literal** (`127.0.0.0/8` or `::1`) — never to a third party, and
  notably not to the name `localhost`. dropbox resolves through the registry to
  `127.0.0.1`, so every mirror call carries the id.

**Which half is sites' to prove.** Putting the header on the wire is the Router
client's transport doing its job — appkit's behavior, appkit's ids. It works only
if sites holds up its two ends, and those are what sites proves:

1. **Every** outbound request actually goes through the injected client (a path
   that quietly falls back to `http.DefaultClient` would be silently
   uninstrumented), and
2. the **live request context** reaches that client, since the transport reads
   the id off the outgoing request's `Context()`.

Both are observable from `internal/sites` and `internal/mcp` with an injected
`*http.Client` whose `Transport` is a recording `RoundTripper` — the recorder
sees each request and its `Context()`. No `*appkit.Router` is needed in a test,
and no test re-asserts the transport's own header logic.

Today's threading is already correct and must stay that way: `internal/mcp`'s
`sync` verb passes its handler `ctx` into `mirror.List` / `mirror.Fetch`, and
sites' non-test source contains no `context.Background()` / `context.TODO()`. A
future detach in the verb path would silently break the chain with no other
symptom, which is why R-BPLY-KD8S pins the property at the MCP verb boundary
rather than only at the client seam.

**Scope: what else sites does and does not instrument.** sites is **not** an
event-plane producer — no `Spec.Feed`, no outbox — so it makes **no**
`eventplane` `Append` call and the `Append` signature change that carries
`correlation_id` cannot reach it; sites' rebuild against the new
`appkit`/`eventplane` is a recompile, not a code change. It **is** a consumer
(D35, the `repos:push` subscription); the consumer engine's own instrumentation
is `eventplane`'s and appkit's, and the version-plane calls the handler makes go
through D32's injected client. Inbound MCP and plain HTTP recording, `lifecycle`
records at boot and shutdown, and the read-or-mint correlation middleware all
arrive through the chassis with no sites-side code. The static tiers
(`internal/serve`) are ordinary inbound requests the chassis records; sites
spawns no subprocess and runs no sandbox.

**Rejected.**
- **Keeping `http.DefaultClient` and setting `X-Correlation-Id` by hand in
  `List`/`Fetch`.** Two hand-written header lines that no test can keep honest as
  the fleet grows, and they would still produce no `outbound` record — the whole
  point of the shared client. It also re-implements the loopback-only propagation
  rule in a thirteenth place.
- **Reaching for the instrumented client from inside `internal/sites`.** It would
  spare `NewMirrorClient` a parameter, but the client comes off the Router and
  the Router lives at the composition root; grabbing it deeper would mean either
  a package-level global or threading `*appkit.Router` into the domain package.
  Config is chosen at the composition root (Conventions) and this is config.
- **Adding a nil-client fallback to `http.DefaultClient`** for callers that pass
  nothing, mirroring what other suite peers do. A silent fallback is precisely
  how an uninstrumented client survives a refactor unnoticed; `NewMirrorClient`
  has exactly one production caller, so the parameter is always supplied and a
  nil client is a programming error, not a mode.
- **Proving the `outbound` record itself from sites (standing up a fake ingest
  endpoint in sites' suite).** That is appkit's behavior with appkit's ids;
  asserting it here would duplicate chassis coverage and would fail for reasons
  that have nothing to do with sites.

That `http.DefaultClient` is gone from sites' shipped source is a mechanical
property, not a behavior: it is a `project/`-excluded grep over the non-test
source in the realizing phase's exit conditions, and carries no id — a grep
proves absence, a test proves the wire.

**Verification.**
- R-BOE2-6LI3 — **every** request the mirror client issues goes through the
  injected `*http.Client`: driven against an `httptest` server with a client
  whose `Transport` is a recording `RoundTripper`, a `List` spanning **at least
  two cursor pages** followed by a `Fetch` yields a recorded request for *every*
  request the server received — counts equal, none escaping to
  `http.DefaultClient`. An implementation that uses the injected client for the
  first page and a package default elsewhere fails; so does one that ignores the
  parameter entirely.
- R-BPLY-KD8S — driving the **`sync` MCP verb** end to end (the `internal/mcp`
  tool handler over a temp `SITES_ROOT` and a real migrated DB, with the dropbox
  mirror as an `httptest` server and the injected recording transport in place)
  with a correlation id on the inbound request context: the transport observes
  that exact id on the `Context()` of **every** outgoing request — proving the
  live request context reaches the wire, which is what the Router client's
  transport reads to set the header. A verb path that detaches with
  `context.Background()` before reaching the mirror fails this even though
  R-BOE2-6LI3 still passes.
