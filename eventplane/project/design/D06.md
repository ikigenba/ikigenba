# Decision 6 — `eventplane/correlation`: the suite's correlation-id leaf package

**Decision.** A new package `eventplane/correlation` owns everything
correlation-id-shaped: the wire header name, the id format and its minter, the
validity rule, and the request-scoped context accessor. It is a **stdlib-only
leaf** — it imports nothing from `outbox`, `consumer`, or `routing`, and adds
no `require` to `go.mod` — so anything downstream of this module (the appkit
chassis, every service) can import it without dragging the event plane along.
It is the *single* home of these primitives suite-wide: a second context key
anywhere would silently split the chain (research names this as the failure
mode the placement avoids).

```go
package correlation

// Header is the HTTP header carrying a correlation id between suite
// processes. Loopback callers are inside the trust boundary, so a received
// value is trusted; the edge overwrites anything a public client supplied.
const Header = "X-Correlation-Id"

// New mints a fresh root correlation id: a 26-character Crockford base32
// ULID — 48 bits of millisecond timestamp, then 80 bits of crypto/rand —
// per project/design/D14.md at the repo root. Mint only at the outermost cause of a chain.
func New() string

// Valid reports whether s is a well-formed correlation id: exactly 26
// characters, every one drawn from Crockford's uppercase alphabet
// (0-9 A-Z excluding I, L, O and U).
func Valid(s string) bool

// WithContext returns a child of ctx carrying id. An id that is not Valid is
// IGNORED — ctx is returned unchanged — so a malformed id can never enter a
// chain and no caller has to check before attaching.
func WithContext(ctx context.Context, id string) context.Context

// FromContext returns the correlation id ctx carries, or "" when it carries
// none.
func FromContext(ctx context.Context) string

// Ensure returns ctx's existing correlation id unchanged, or — when ctx
// carries none — mints one, attaches it, and returns the new context and id.
// It is the read-or-mint primitive every inbound edge uses; on an already
// correlated context it never mints, because re-minting mid-chain severs the
// trail.
func Ensure(ctx context.Context) (context.Context, string)
```

The context key is an unexported zero-size struct type, so no other package can
collide with it or read the value except through these accessors.

*Alphabet.* Crockford base32 is `0123456789ABCDEFGHJKMNPQRSTVWXYZ` — `I`, `L`,
`O` and `U` are excluded. The minter encodes the 16 bytes most-significant
first into 26 characters exactly as the ULID specification does, so ids are
lexicographically time-sortable. This is the discriminating difference from RFC
4648 base32 (`A`–`Z`, `2`–`7`), which the chassis previously used: RFC 4648
output can contain `I`/`L`/`O`/`U` and can never contain `0`, `1`, `8` or `9`.

*Not in scope for this package.* It does not read or write HTTP headers (the
chassis middleware does that, using `Header` and `Ensure`), and it does not
know about events. The library's own `newULID` (event ids, generation tokens)
is untouched — those are not correlation ids and are not governed by the
correlation standard.

**Rejected.**

- *Putting the primitives in appkit* — the natural home for request scope, but
  `appkit` requires `eventplane`, so this library importing the chassis is an
  import cycle. The dependency direction decides the placement.
- *Defining a context key in both appkit and eventplane* — compiles cleanly and
  fails silently: two distinct keys means the id a handler carries is invisible
  to the producer it calls, with no error anywhere. Exactly the class of bug a
  single shared home exists to prevent.
- *A third-party ULID library (`oklog/ulid`)* — a dependency for a dozen lines,
  against this module's deliberate one-entry dependency footprint (the same
  ground on which the hand-rolled matcher was chosen).
- *Reusing `outbox.newULID` for correlation ids* — it emits RFC 4648 base32,
  which violates the suite standard's alphabet; changing it instead would alter
  event ids and generation tokens for no reason, and those are not correlation
  ids. The two minters stay separate.
- *`WithContext` validating by returning an error* — every call site would then
  branch on an impossible-in-practice error; silently ignoring an invalid id
  gives the same guarantee (nothing malformed enters a chain) with no
  ceremony, and `Ensure` is the path that always yields a usable id.
- *Normalizing lowercase or ambiguous characters (`l`→`1`, `O`→`0`) in
  `Valid`* — Crockford's decoding leniency is for humans typing ids. These ids
  are propagated verbatim between machines; accepting a variant spelling would
  mean two spellings of one chain.

**Verification.**

- R-UBWK-3IAS — `New()` returns exactly 26 characters, every character drawn
  from `0123456789ABCDEFGHJKMNPQRSTVWXYZ`; across 1000 mints no id contains
  `I`, `L`, `O` or `U`, and the characters `0`, `1`, `8` and `9` each appear
  in at least one id (the discriminating property against RFC 4648 base32,
  whose alphabet is `A`–`Z`/`2`–`7`).
- R-UD4G-HA1H — ids are unique and time-ordered: 1000 successive mints yield
  1000 distinct values, and an id minted after a ≥2ms pause sorts strictly
  greater than one minted before it (byte-wise string comparison), for 20
  consecutive pairs.
- R-UECC-V1S6 — `Valid` accepts every id `New()` produces and rejects: `""`,
  a 25-character and a 27-character id, a lowercase-spelled id, and an
  otherwise well-formed 26-character string containing `I`, `L`, `O` or `U`.
- R-UFK9-8TIV — context round trip: `FromContext(context.Background())` is
  `""`; `FromContext(WithContext(ctx, id))` returns `id` verbatim for a minted
  `id`; and `WithContext(ctx, "not-a-correlation-id")` yields a context whose
  `FromContext` is still `""` — the malformed value is not stored, not
  returned in any form.
- R-UGS5-ML9K — `Ensure` never re-mints mid-chain: on a context already
  carrying `id`, it returns exactly `id` and a context whose `FromContext` is
  still `id`; on a bare context it returns a `Valid` id equal to the
  `FromContext` of the context it returns, and two `Ensure` calls on two bare
  contexts return two different ids.
- R-UI02-0D09 — `Header` is exactly the string `"X-Correlation-Id"`
  (byte-for-byte, including capitalization) — the suite-wide contractual name
  every hop keys on.
