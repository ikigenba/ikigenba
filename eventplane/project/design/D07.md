# Decision 7 — Correlation on the producer path: outbox column, envelope field, ctx-bearing `Append`

**Decision.** The correlation id becomes a first-class fact of a published
event, carried from the caller's context into a durable column and out onto the
wire. It is never a payload convention: the payload stays an opaque domain
snapshot the library does not touch.

*Append takes a context.* The signature becomes:

```go
func (o *Outbox) Append(ctx context.Context, tx *sql.Tx, ev Event) error
```

`Append` reads `correlation.FromContext(ctx)` (D6) and stores it on the row.
`outbox.Event` gains **no** correlation field: the context is the propagation
channel, and a per-call field would invite each producer to source the id its
own way. An absent id stores `""` — `Append` does **not** mint, because minting
belongs at the outermost cause of a chain and the library cannot see where that
is: it cannot distinguish work that genuinely has no root from a caller that
forgot to thread its context. A producer that *is* an outermost cause (a poll
or sync cycle, a timer tick, a spawned run) mints its own root before appending;
that is the service's call, made in the service's spec. The library mints in
exactly one place, and it is not here: the consumer's mint-on-absence (D8),
where the standard's durable-root rule sanctions it because no root can exist by
then. An empty stored `correlation_id` is therefore a truthful record of a gap,
never something the library papers over. The context is also threaded into the insert
(`tx.ExecContext`), so a cancelled request no longer performs the write.

The parameter is leading, per Go convention. The change is compile-caught at
every in-suite call site (research lists eight, all already inside
request- or job-scoped functions); each service threads its context in its own
spec, exactly as each service applies its own migration.

*Schema.* `SchemaSQL` gains one column, declared **last** so a fresh table and
an upgraded table are column-for-column identical:

```sql
CREATE TABLE outbox (
  seq            INTEGER PRIMARY KEY AUTOINCREMENT,
  event_id       TEXT    NOT NULL,
  kind           TEXT    NOT NULL,
  subject        TEXT    NOT NULL DEFAULT '',
  payload        TEXT    NOT NULL,
  created_at     TEXT    NOT NULL,
  correlation_id TEXT    NOT NULL DEFAULT ''
);
CREATE INDEX idx_outbox_created_at ON outbox(created_at);
```

(D1 holds the authoritative statement of this DDL; the block above is that
statement, and the semantics of the added column are this Decision's.)

*Upgrading an existing table.* The library owns the upgrade text as well as the
create text, so fourteen services cannot spell it fourteen ways:

```go
// AddCorrelationIDSQL upgrades an outbox table created before the
// correlation_id column existed. A service applies it as one new timestamped
// migration; applying it to a table SchemaSQL just created is not required and
// not supported (the column is already there).
const AddCorrelationIDSQL = `ALTER TABLE outbox ADD COLUMN correlation_id TEXT NOT NULL DEFAULT '';`
```

This is additive by construction: `ADD COLUMN` rewrites no rows, back-fills
existing rows with `''`, and leaves both the `seq` values and SQLite's
`sqlite_sequence` high-water mark untouched — so no consumer's cursor moves and
the `AUTOINCREMENT` guarantee (D1) is undisturbed. eventplane still applies
nothing itself: services own their migration runners.

*Wire.* The envelope gains `correlation_id`, and `fetch`/`eventRow` carry it
from the row:

```go
type envelope struct {
    ID            string          `json:"id"`
    Source        string          `json:"source"`
    Time          string          `json:"time"`
    Kind          string          `json:"kind"`
    Subject       string          `json:"subject"`
    CorrelationID string          `json:"correlation_id"`
    Payload       json.RawMessage `json:"payload"`
}
```

The field is **always present**, `""` when the event had no chain — the frame's
key set is a constant, never a function of the data. This is additive on the
wire: a consumer decoding the envelope into a struct without the field is
unaffected. The `id:` cursor line, the `event:` canonical key, and the control
frames are untouched.

Because id and time are already stored once at append and replayed verbatim
(D1), the correlation id inherits the same stability for free: it is written
once and every replay of that event carries the identical value.

**Rejected.**

- *A `CorrelationID` field on `outbox.Event`* — makes correlation something
  each producer must remember to populate, from a source of its choosing;
  the whole promise is that a producer does nothing beyond passing its context.
  A field would also let a caller's explicit value silently disagree with the
  context the chain actually runs in.
- *Minting in `Append` when the context carries no id* — the library is
  mid-chain by definition; minting there is exactly the "re-minting mid-chain"
  the correlation standard forbids, and it would manufacture a root for work
  that genuinely has none, making an orphan indistinguishable from a chain.
- *`omitempty` on the envelope field* — makes the frame's key set depend on the
  data, so the exact-keys guarantee (D1) becomes conditional and a consumer
  cannot tell "no chain" from "old producer".
- *Storing the id in the payload (the superseded convention in
  `project/design/D14.md` at the repo root)* — the library would have to parse and rewrite
  payloads it deliberately treats as opaque, every producer would have to add
  the field to every payload type, and selection rules that forbid matching on
  payload contents could never see it.
- *A separate correlation table joined by `event_id`* — a join and a second
  write for a single short string on a table that is already
  written-once/read-sequentially; the column costs nothing.
- *Having eventplane run the `ALTER` itself (a library-owned migration)* — the
  library has never applied DDL, and each service's migration runner is the
  single migration authority for its database file. Owning the *text* gets the
  anti-drift benefit without taking that authority.

**Verification.**

- R-UJ7Y-E4QY — the revised `SchemaSQL` applies cleanly to a real SQLite
  database (`modernc.org/sqlite`) and the resulting table's columns are
  exactly `seq, event_id, kind, subject, payload, created_at, correlation_id`
  in that order (`PRAGMA table_info`), with `correlation_id` `NOT NULL` and
  defaulting to `''`; after one insert, a `sqlite_sequence` row for `outbox`
  exists — the `AUTOINCREMENT` high-water mark survives the schema change.
- R-UKFU-RWHN — upgrade equivalence on real SQLite: creating the pre-column
  table (its DDL embedded literally in the test), inserting a row, then
  applying `AddCorrelationIDSQL` yields a `PRAGMA table_info` — names, types,
  notnull and default flags, and order — **identical** to a table freshly
  created by `SchemaSQL`, and the pre-existing row reads back
  `correlation_id = ''` (not NULL).
- R-ULNR-5O8C — the upgrade disturbs no cursor on real SQLite: rows inserted
  before `AddCorrelationIDSQL` keep their exact `seq` values afterwards,
  `MAX(seq)` is unchanged, and an `Append` after the upgrade receives
  `seq = pre-upgrade MAX(seq) + 1` — including when every pre-existing row is
  deleted first (the AUTOINCREMENT high-water mark, not a re-used rowid).
- R-UMVN-JFZ1 — `Append` persists the context's id verbatim: appending under
  `correlation.WithContext(ctx, X)` for a minted `X` stores exactly `X` in that
  row's `correlation_id` (read back by SQL on a real database), and appending
  under a bare context stores exactly `""` — not a minted value, not NULL.
- R-UO3J-X7PQ — the id reaches the wire unchanged: an event appended under
  correlation `X` and served by the real `FeedHandler()` over an `httptest`
  HTTP connection carries `"correlation_id": X` on its `data:` line, and an
  event appended under a bare context carries `"correlation_id": ""` — the key
  present in both cases.
- R-UPBG-AZGF — `Append` honours its context: called with an
  already-cancelled context on a real SQLite transaction it returns a non-nil
  error and inserts no row (the outbox row count is unchanged), proving the
  insert runs under the context rather than ignoring it.
