# Decision 13 — Suite-contract conformance: the opsctl install layout and the authored env contract

## Decision

`github` is an ordinary deployable service of the suite, so it **conforms by
default** to the suite-wide contracts the umbrella project owns. Two of those
contracts carry `[proof: per-service]` Verification ids, which means each adopting
service proves them **in its own tree**:

- **The `/opt/<svc>/` install layout** — `project/design/D08.md` at the repo root.
- **The portable authored `manifest.env` and the composed data paths** —
  `project/design/D11.md` at the repo root.

This Decision is the **citation**, and citation is adoption: `github` owns none of
those contracts' content, restates none of it, and takes each by value from the
umbrella Decision named above. What is local to `github` — and all this Decision
adds — is *where the proof lives* and *what substrate can falsify it here*:

- The proofs live in **`cmd/github/main_test.go`**, the composition root's test
  file, matching every other adopting service (`crm`, `ledger`, `notify`,
  `dropbox`). No new package is introduced for them.
- The committed authored manifest is **`github/etc/manifest.env`**; the compiled
  default it must agree with is the one `internal/githubapp.Spec()` declares
  (`APP=github`, `MOUNT=/srv/github/`, `DEFAULT=false`, `PORT=3203`, `MCP=true` —
  no `FEED=`, no `CONSUMES=`, no outbox retention keys, since `github` is neither
  producer nor consumer per D1).
- The boot proof runs the **built binary against a temporary root**, not the live
  box. Two facts particular to `github` shape it:
  - `Spec().Config` constructs the `internal/gh` client and **fails if
    `IKIGENBA_APP_PRIVATE_KEY` does not parse** (D2), so the boot smoke must
    supply a locally generated throwaway RSA key. It is a parse gate, not an
    authentication gate — no GitHub call is made to satisfy it.
  - The chassis `/health` route is a **liveness** route: it answers `200` with
    `status: "ok"` and folds a reporter failure into `details`. `github`'s health
    reporter drives a real GitHub call, so offline it reports its failure inside
    `details` while the envelope still proves the process booted, bound its port,
    and served on the composed paths. That the *credentials* actually work is a
    different claim, owned by `R-DMUT-QF4A` under D2 against the live substrate;
    the boot smoke deliberately does not duplicate it and must not require
    network access or real credentials.
- `github` serves its landing page and static assets from disk under
  `share/www` (D6), so it declares `Spec.WWW = true` and the layout proof
  **includes the `share/` tier** — `share/<version>/www` with the `share/current`
  symlink selecting it — alongside `state/`, `cache/`, `libexec/`, `bin/run`, and
  `etc/<version>/manifest.env` with `etc/current`. Because the chassis loads the
  `share/www` site at startup and `serve` fails loudly if the root is missing, the
  boot smoke (`R-4LKF-FB23` below) stages a `share/<VERSION>/www` copy of the
  committed `github/share/www` tree with a `share/current` link before booting.

Conformance is the default and this Decision records no deviation: `github`
departs from neither contract.

## Rejected

- **Restate the two contracts' requirements locally so the design reads
  self-contained.** A local restatement is drift by construction — it goes stale
  the moment the umbrella Decision is rewritten, and the suite's rule is cite,
  never restate. Rejected for citation by path.
- **Fold the citation into D1 (the chassis/skeleton Decision).** D1 is explicitly
  structural and carries no ids; giving it three would blur the one Decision that
  states *placement and posture only*. A small, separate conformance Decision
  keeps both readable.
- **Treat the contracts as proven elsewhere and cite only the Decision paths,
  without the ids.** Both contracts are marked `[proof: per-service]`: a service
  that adopts them must carry its own tagged tests. Citing the paths alone would
  leave `github` unproven against layout and env drift that only its own tree can
  detect.
- **Assert a live-GitHub-green `health` inside the boot smoke.** That is not
  reachable in the offline unit suite and would make the phase's exit condition
  non-deterministic; it is already owned by `R-DMUT-QF4A` as an out-of-loop live
  verification. Rejected.

## Verification

Each id below is **adopted**, not minted here: it belongs to the umbrella
Decision cited beside it, which states the behavior. These lines say only what
substrate proves it inside `github/`.

- `R-4LKF-FB23` — adopted from `project/design/D08.md` at the repo root.
  Substrate: a Go test in `cmd/github/main_test.go` that assembles a fresh
  `/opt/github/`-shaped tree under `t.TempDir()` (`state/`, `cache/`, `libexec/`,
  `bin/run` → the built binary, `etc/<VERSION>/manifest.env` copied byte-for-byte
  from the committed authored file, `etc/current` → `<VERSION>`,
  `share/<VERSION>/www` copied from the committed `github/share/www` tree and
  `share/current` → `<VERSION>`), runs `bin/run serve` on a free loopback port
  with a generated throwaway RSA app key, and asserts the served `/health` is
  `200` with `service: "github"` and `status: "ok"`, that the DB was created under
  `state/` and the generation sidecar under `cache/`, and that `bin/run`,
  `etc/current`, and `share/current` resolve to their intended targets. Offline:
  no network, no real credentials.
- `R-8DF1-W89F` — adopted from `project/design/D11.md` at the repo root.
  Substrate: a Go test in `cmd/github/main_test.go` scanning the committed
  `github/etc/manifest.env` bytes and failing on an absolute `/opt/` path or a
  `GITHUB_DB_PATH=` / `GITHUB_GENERATION_PATH=` line.
- `R-8IAN-FB87` — adopted from `project/design/D11.md` at the repo root.
  Substrate: a Go test in `cmd/github/main_test.go` comparing
  `manifest.Emit(...)` over the fields `internal/githubapp.Spec()` declares
  against the committed `github/etc/manifest.env` bytes, failing on any
  difference in either direction.
