# Decision 14 — Adopt the suite testing-language contract

**Decision.** github adopts the suite's testing-language contract,
`root project/design/D23.md`, by citation. That contract owns the four test
layers (**hermetic / composed / live / manual**) and what each may touch, the
single mechanism for live tests (`//go:build live`, invoked as
`go test -tags live ./...`, hard-failing on absent credentials), the ban on
`t.Skip` outside live-tagged files, the requirement that a manual-layer check
live in a committed runbook stating a positive check, a negative check, and
where the result is recorded, and the requirement that every tree declare its own
testing facts in its `AGENTS.md`. This Decision restates none of that. It records
only the github-specific facts the contract asks this tree to declare, and adopts
the contract's two per-service ids.

**The layers github has.** Three:

- **hermetic** — the bulk of the suite, and fully offline: the `internal/gh`
  REST client and app-JWT signing driven against an injected
  `http.RoundTripper` stub; the `internal/mcp` tool surface at the handler
  boundary; the `internal/db` bootstrap migration set against a real temp-file
  SQLite database through the real appkit migration runner; the landing render
  over the disk-served `share/www` tree through appkit's WWW loader; and the
  committed-file scans over `etc/nginx.conf` and `etc/manifest.env`. No hermetic
  test performs network I/O or reads a credential.
- **composed** — the install-layout boot smoke in `cmd/github/main_test.go`
  (`R-4LKF-FB23`): it assembles an `/opt/github/`-shaped tree under
  `t.TempDir()`, `go build`s the real `cmd/github` binary into `libexec/` with a
  `bin/run` symlink and a byte-copied `etc/<VERSION>/manifest.env`, runs
  `bin/run serve` on a free loopback port with a throwaway RSA key, and asserts
  the served `/health` envelope, the created database and generation sidecar,
  and that the layout symlinks resolve. It runs offline: the throwaway key makes
  the health reporter surface its own error rather than reach GitHub, which is
  itself part of what the smoke asserts.
- **manual** — `project/github-verification.md`, the committed runbook the
  operator runs against the live box. It is this tree's manual-layer document in
  the contract's sense and already carries the shape the contract asks for: the
  positive check (with correct credentials, `health` reports healthy, observable
  only if a real authenticated call to the `@ikigenba` installation succeeded),
  the negative check that proves the positive one exercised the real thing
  (point `IKIGENBA_APP_PRIVATE_KEY` at a corrupted key, restart, and require a
  loud unhealthy `ErrAppAuth` rather than a silent OK), and where the result is
  recorded (the box's deploy/acceptance log, deliberately not `STATUS.md`).

**`R-DMUT-QF4A` is a manual-layer id, proven out of gate.** Its correctness
depends on real GitHub accepting the app JWT and issuing an installation token —
a stub accepts any JWT and cannot falsify it. Under the contract's vocabulary
that makes it a **manual-layer** id, owned by D2 and proven in
`project/github-verification.md`; it is deliberately not scheduled as
loop-gating work by any plan phase, and `project/plan/README.md` already records
that carve-out. It is **not** a live-layer id: the contract's live layer is
automated Go tests behind `//go:build live`, and no such file exists here.
Converting it into one would be a Decision, not a drift — and would require
credentials in the test process, which this tree deliberately does not take.

**github has no live layer.** Every automated test here is offline; the only
real-GitHub proof is the manual runbook above. The `-tags live` invocation is
not part of this tree's testing story.

**GOWORK mode.** github tests, builds, and vets with **`GOWORK=off`** — the
default gate is `GOWORK=off go test ./...` from `github/`, alongside
`GOWORK=off go build ./...`, `GOWORK=off go vet ./...`, and `gofmt -l .`.
Forcing the workspace off mirrors the deterministic production build and proves
the module resolves standalone through its committed `replace` directives. This
is already stated in this design's *Conventions*; the contract's declaration
requirement is what makes it `AGENTS.md`-visible, and the contract deliberately
does not unify GOWORK mode across trees.

**Environmental preconditions beyond the Go toolchain.** One: the **`go` binary
on `PATH` in the test process's environment** (not merely the toolchain that
compiled the tests), with the module cache already resolving github's `replace`
siblings. The composed boot smoke shells out to `go build` with `GOWORK=off`; it
does no network fetch and must not acquire one. A hard failure when absent,
never a skip.

**Where this lands.** Nothing in github's shipped source changes. The adoption is
carried by two tagged tests and by the `AGENTS.md` Tests section stating the
facts above; the plan phase that realizes this Decision does both.

**Rejected.**

- *Restating the layer definitions, the live-tag mechanism, or the skip ban in
  this design.* Citation is the mechanism (`$ikispec`, "cite, never restate"): a
  local copy of a suite contract is drift by construction the moment the umbrella
  moves. This file names only what is particular to github.
- *Re-minting local ids for the two behaviors.* The umbrella marks R-O1AD-MRKW
  and R-O2IA-0JBL `[proof: per-service]`; citing those exact ids **is** the
  adoption, and a fresh local id would be a second handle for one behavior.
- *Filing `R-DMUT-QF4A` as a live-layer id.* The live layer means an automated
  Go test behind `//go:build live` that hard-fails on absent credentials. This
  check is a human observing `health` against the deployed box with a
  key-swap step in the middle — automation cannot reach it as written, which is
  the contract's own definition of manual.
- *Rewriting `R-DMUT-QF4A` into a `//go:build live` test to get it into an
  invocable gate.* Tempting, and possibly right later, but it is a real change:
  it puts a production private key in the test process's environment and moves
  the negative check from a deliberate operator action to a fixture. That is a
  Decision to take on its merits, not a side effect of adopting a vocabulary.
- *Declaring the boot smoke hermetic because it runs offline.* The layer is
  defined by what a test may **touch**, not by whether it reaches the network.
  It builds and runs github's own real binary and drives it over loopback HTTP —
  the contract's own description of composed.
- *Declaring github's layers as hermetic plus manual only.* That was the
  intuition (github is "the offline unit suite plus the runbook"), but
  `cmd/github/main_test.go` demonstrably builds and runs the real binary in the
  default gate. A declaration that omitted the composed layer would be false on
  the first read of the tree, and the doc-truth id exists to catch exactly that.

**Verification.**

- R-O1AD-MRKW — cited from `root project/design/D23.md` (`[proof:
  per-service]`); adopted here. A test reads github's committed `AGENTS.md` from
  disk and asserts its Tests section declares the default-gate test command, the
  layers present in the contract's vocabulary (hermetic, composed, and manual
  with its runbook named), every environmental precondition beyond the Go
  toolchain (the `go` binary), and the tree's GOWORK mode (`GOWORK=off`).
  Substrate: hermetic (real committed file read from disk).
- R-O2IA-0JBL — cited from `root project/design/D23.md` (`[proof:
  per-service]`); adopted here. A source scan over github's `*_test.go` files,
  excluding files carrying the `live` build constraint, finds **zero**
  occurrences of `t.Skip`, `t.Skipf`, or `t.SkipNow`. The scan assembles its
  needle from parts so it never matches itself. Substrate: hermetic (source
  scan).
