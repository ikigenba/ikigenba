# Decision 12 — nginx fragment: forward the edge-minted `X-Correlation-Id` on gated locations, blank it on ungated ones

**Decision.** `github/etc/nginx.conf` gains one more forwarded header,
`X-Correlation-Id`, under the same identity-hygiene rule the fragment already
applies to the owner headers (D6): on every **gated** location the value comes
from the dashboard's `auth_request` subrequest and **overwrites** anything the
client sent; on the **ungated public** location it is explicitly set to the
empty string so the service mints its own.

The suite's correlation id is a bare 26-character Crockford base32 ULID carried
in `X-Correlation-Id` (see `project/research/research.md`). The dashboard's
introspection endpoints mint it per gated request and return it as a response
header on the auth subrequest; nginx is the only place that value can be
captured, so each service fragment must do so for itself. `github` is not the
minter and never validates the value — it forwards what the edge resolved.

## The gated locations

Each gated location captures the subrequest header into a **service-prefixed**
variable (the fragment's existing `$github_…` convention, so names stay unique
when every service fragment is included into the one apex `server` block) and
forwards it:

```
# Bearer-gated prefix — every path under the mount except the exact matches.
location /srv/github/ {
    auth_request /_authn;
    …                                                       # D6 owner headers, unchanged
    auth_request_set $github_correlation $upstream_http_x_correlation_id;
    proxy_set_header X-Correlation-Id $github_correlation;
    …
}

# Session-gated landing page (exact match) and its static asset tier.
location = /srv/github/ {
    auth_request /_session-authn;
    …                                                       # D6 owner headers, unchanged
    auth_request_set $github_session_correlation $upstream_http_x_correlation_id;
    proxy_set_header X-Correlation-Id $github_session_correlation;
    …
}

location /srv/github/static/ {
    auth_request /_session-authn;
    auth_request_set $github_session_correlation $upstream_http_x_correlation_id;
    proxy_set_header X-Correlation-Id $github_session_correlation;
    …
}
```

`$github_session_correlation` is declared by `auth_request_set` in both
session-gated locations. That is legal and unambiguous: exactly one location
handles a given request, so the variable is set at most once per request.

**Why this is safe against a smuggled id.** nginx does not pass an inbound
client header through as a proxy header unless a `proxy_set_header` names it,
and the last `proxy_set_header` for a name wins. A single set from the
subrequest variable therefore **replaces** any client-supplied
`X-Correlation-Id` on the upstream request. A public caller cannot inject an id
into the chain.

## The ungated public location

The PRM bootstrap is deliberately unauthenticated — there is no auth subrequest
and therefore no minted id to capture. It sets the header to the empty string
so nothing a client sent survives, and the `github` process mints its own id
for that request:

```
location = /srv/github/.well-known/oauth-protected-resource {
    proxy_pass http://127.0.0.1:3203/.well-known/oauth-protected-resource;
    proxy_set_header X-Correlation-Id "";
    …
}
```

**Locations that proxy nothing are untouched.** `location = /srv/github/pr` and
`location = /srv/github/token` are bare `return 404;` stubs (D5, D10) and
`@github_authn_500` re-emits a status — none reaches an upstream, so none
carries a `proxy_set_header`. The real callers of `/pr` and `/token` are
loopback peers (`scripts`, `repos`) that bypass nginx entirely and carry their
own correlation id on the wire.

**No Go change.** Reading the header (trust it when present, mint when absent)
is the appkit chassis's middleware, not `github`'s code; this Decision covers
the shipped `etc/nginx.conf` artifact only.

**Rejected.**
- **Letting the client's `X-Correlation-Id` pass through on gated locations** —
  a public caller could then join or forge another actor's chain. The edge
  strips and the edge mints; that is the whole trust argument.
- **Omitting the header on the ungated location instead of setting it empty** —
  omitting is not stripping: the explicit `""` states the intent in the shipped
  artifact, survives a future edit that adds header pass-through, and makes the
  rule greppable.
- **Capturing the id in the `/pr` and `/token` 404 stubs** — they return 404
  without proxying; there is no upstream request to set a header on.
- **One shared `include` for the correlation lines across all service
  fragments** — nginx `include` cannot parameterize the per-location variable
  name, and the fragment ships verbatim with no templating. Explicit
  per-location directives are the only form that loads directly.
- **Minting the id in `github`'s fragment (e.g. from `$request_id`)** — nginx's
  `$request_id` is a hex UUID, not the suite's Crockford ULID, and a
  per-service minter would break the one-id-per-causal-chain rule. The
  dashboard mints; services forward.

**Verification.** This is a **structural, artifact-only Decision and owns no
requirement ids**: it changes a shipped nginx config, not `github`'s Go
behavior, and the recording behavior it feeds is the chassis's promise (proven
by appkit's own ids), not `github`'s. Its proof is the deterministic content
check on the phase that realizes it — a `project/`-excluded grep over
`github/etc/nginx.conf` asserting each gated location carries its
`auth_request_set … $upstream_http_x_correlation_id` and matching
`proxy_set_header X-Correlation-Id`, and that the PRM bootstrap sets the header
empty — plus a green suite.
