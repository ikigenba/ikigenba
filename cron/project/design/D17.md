# Decision 17 — Adopt the suite testing-language contract

## Decision.

cron adopts the suite's testing-language contract — `root project/design/D23.md`
— by value and without deviation. That contract owns the four layer names
(**hermetic**, **composed**, **live**, **manual**), the rule fixing each layer by
what a test may touch, the `//go:build live` mechanism, the ban on `t.Skip`
outside live-tagged files, and the requirement that every tree declare its
testing facts in its `AGENTS.md`. None of that is restated here, and this design
uses no testing vocabulary of its own.

What is local to cron — and all this Decision adds — is **which layers this tree
has, what it must declare, and where the proof of that declaration lives**:

- **Layers present: hermetic and composed.** cron has **no live layer**: nothing
  in the tree contacts a real external service or reads a credential, and the
  tick worker's only outside contact is an `outbox` row in its own SQLite file.
  It has no tree-local manual layer either; the suite-level full-stack check the
  contract names belongs to the repo root.
- **The composed tests are the boot smokes in `cmd/cron/main_test.go`**, which
  shell out to `go build` for the real `cron` binary, run `serve` against a
  temporary install tree on an ephemeral loopback port, and drive it over real
  HTTP. Building and running the tree's own binary is exactly the composed
  boundary.
- **Everything else is hermetic**: the landing-handler and static-asset tests
  over the repo-real `cron/share/www` tree, the `httptest`-driven route and MCP
  tests, the crontab store and migration tests against temp-file SQLite through
  the real appkit migration runner, the tick worker's correlation and
  `(schedule, slot)` tests over that same database, and the `etc/nginx.conf`
  content assertions. Every one of them is already network-free and
  credential-free; adoption names the property rather than changing it.
- **Environmental preconditions beyond the Go toolchain: none.** The boot smokes
  invoke `go build`, which is the Go toolchain itself and so not an additional
  precondition. Nothing in the gate needs `git`, `python3`, a browser, a
  credential, or a running suite — which is why the design already refuses to
  stand up nginx to prove the fragment.
- **GOWORK mode: workspace for local development, `GOWORK=off` for the
  production build** (`bin/ship cron`, which adds
  `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 GOWORK=off -buildvcs=false`), where
  `appkit`, `eventplane`, and `registry` resolve through their committed
  `replace` directives. cron sits on the standalone-build side of the split the
  contract deliberately declines to unify.
- **The default gate is unchanged**: `cd cron && go test ./...`, green meaning
  clean `go build ./...`, `go vet ./...`, and `gofmt -l .` alongside it, exactly
  as the Conventions state.
- **The declaration is proved, not asserted once.** Both proofs live in
  `cmd/cron/main_test.go`, beside the other whole-tree conformance proofs
  (`R-4LKF-FB23`, the manifest and registry drift checks), matching the suite
  pattern of a composition-root test reading `../../AGENTS.md` from disk.

The two ids below are the contract's `[proof: per-service]` ids; citing them is
adoption, so they enter cron's coverage denominator and are realized by tests in
`cron/`.

## Rejected.

- **Restate D23's layer table locally so this design reads self-contained.** A
  local copy of a suite contract goes stale the moment the umbrella Decision is
  rewritten; the suite rule is cite, never restate, and the citation is the whole
  mechanism.
- **Keep the design's existing informal phrasings ("no test makes a network call
  and no test needs a running suite") as the normative statement.** They describe
  hermeticity without naming it, so two trees could describe the same property in
  two vocabularies — the exact fragmentation D23 exists to end. Kept as
  per-Decision colour; the layer names are now the contract terms.
- **Declare cron's tick tests a live layer because they exercise the event
  plane.** The event plane cron touches in a test is a row in its own temp-file
  SQLite database — a real local substrate, squarely hermetic. Nothing crosses to
  a non-loopback address or reads a credential.
- **Prove the `AGENTS.md` declaration by review at authoring time.** A
  declaration checked once decays silently; the contract's id exists precisely so
  the gate re-checks it on every run.
- **Put the source scan in a new `internal/` package.** It needs only the tree
  root and `filepath.WalkDir`; a new package for one scan buys nothing, and
  keeping both proofs in `cmd/cron/main_test.go` puts cron's self-truth claims in
  one place.

## Verification.

Both ids are **adopted**, not minted here: they belong to `root
project/design/D23.md`, which states the behavior. These lines say only what
substrate proves them inside `cron/`.

- R-O1AD-MRKW — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/cron/main_test.go` reads the committed `../../AGENTS.md` from
  disk and asserts its Tests section declares the default-gate command
  (`go test ./...` from `cron/`, green also meaning clean `go build ./...`,
  `go vet ./...`, and `gofmt -l .`), names the layers present in the contract's
  layer names (**hermetic** and **composed**, and that there is no live layer),
  states that there are no environmental preconditions beyond the Go toolchain,
  and states the GOWORK mode (workspace for development, `GOWORK=off` for the
  production build). A missing or reworded declaration fails the gate.
- R-O2IA-0JBL — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/cron/main_test.go` walks every `*_test.go` file in the
  `cron/` tree, excludes any file carrying a `live` build constraint, and asserts
  **zero** occurrences of `t.Skip`, `t.Skipf`, or `t.SkipNow`. The needle is
  assembled from parts at runtime so the scanning file never matches itself, and
  the scan names the offending file and line on failure.
