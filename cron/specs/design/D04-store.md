# D04-store

The triggers' records: `internal/store`, which owns the one table of cron's SQLite database, `state/cron.db`, and everything it records of each trigger — its id, slug, schedule, owner, status, creation time and latest fire — together with the rules a trigger's slug, schedule and id obey, the errors every consumer tells apart, and the one line every consumer answers when the database cannot be reached. `D01-layout-and-run-seam` declares `cli.Process`, whose `Dir`, `Now` and `Rand` reach the store through `cli.Run`, resolves the path the database lives at, and declares the root package's `Migrations`; `D03-serve` opens the database with appkit's `db.Open` at start, builds the store over that handle, writes the diagnostic for a database that will not open, and closes the handle after the drain. Opening, migrating, transactions and the failure seam are appkit's `db`, which this document restates none of. This document declares every exported name of `internal/store` and states what each does. Who may change a trigger, and when a change moves its next slot, is `D05-scheduler`'s; what a tool checks before it calls, in which order, and what it answers is `D08-tools`'; what the landing page shows of a trigger is `D06-pages`'.

## One table, one writer

cron is the database's only writer, and the database is the only record of its triggers: nothing else on disk rebuilds it, so a start that finds no database begins an empty one, and a lost `state/cron.db` comes back only from the host's replica. What is contract is what a reader and a restart see: what a store holds when its handle is closed is what a store over the next `db.Open` of the same path holds, field for field. A test proves the records that way, by closing and reopening, never by reading tables.

The store does not open anything. `store.New` builds a store over a handle `db.Open` returned, with the clock and random source it stamps and draws from; every read is a `DB.Read` and every write a `DB.Write` on that handle, so the handle's one writer serializes the writes and the store keeps no lock of its own. A write that must check and change together — a create's slug check and insert — does both inside one `DB.Write`, which is what keeps slugs unique under concurrent calls.

A store whose handle fails is a **failing** store: from a `SetFailing(true)` on its handle until a `SetFailing(false)`, and once its handle is closed, every method answers `ErrUnreachable` and changes nothing. That is the one failure seam a test uses; it never takes a permission away or corrupts the file.

## Triggers

A trigger's **id** is `crn_` and 16 lowercase hexadecimal digits, the 8 bytes drawn from the random source when the trigger is created, and never changed. Ids are drawn at random and are not derived from the slug; a create draws again when the drawn id is the id of a trigger the store holds, and nothing else is promised of them. Its **slug** is 1 to 64 characters: a lowercase ASCII letter, then lowercase letters and digits, with single underscores between them, never two together, never at the end; it is taken as given, never trimmed or folded, and no slug is reserved. Slugs are one namespace for the whole space: no two triggers, of any owners, share one. Its **when** is its schedule, kept exactly as it was sent: one of the five descriptors `@hourly`, `@daily`, `@weekly`, `@monthly` and `@yearly`, or five fields separated by single spaces that the standard five-field parser of `github.com/robfig/cron/v3` accepts, read in UTC. A `when` the parser accepts but that names no moment that will ever come, such as `0 0 30 2 *`, is valid; such a trigger simply never has a next slot (`D05-scheduler`). Its **owner** is the user id of the caller that created it, kept with the email that caller's request carried, which the tools and the landing page show; the email is never in an event. Its **status** is `active` or `paused`. **Created** is the time of the create and **last fired** the slot of its latest fire, zero until it first fires, both in UTC to the second.

The store checks the rules it keeps — a valid slug and schedule, a non-empty owner id, a known status — and answers `ErrInvalid` to a write that breaks one, changing nothing; the tools refuse each of those first, with their own lines, so no consumer sends one. The store does not decide ownership: its writes name a trigger by id, which a consumer learned from a read, and `D05-scheduler` refuses a change to another owner's trigger before it writes.

## Reads and writes

`List` is every trigger, of every owner, in ascending byte order of slug, the order the tools' `list` and the landing page show; `Get` is any owner's trigger by slug. `Create` mints the id and stamps the created time; `SetWhen` replaces the schedule, `SetStatus` the status and `SetLastFired` the latest fire, each leaving every other field as it was and answering the trigger as it is after the call; `Delete` removes a trigger and answers it as it was, so its consumer can still name what it had. A value written equal to the one already there is not an error. A deleted trigger's slug is free at once for any owner's `Create`; a trigger created with it is a new trigger, whose id is drawn as every create draws one.

## Errors

`ErrNotFound`, `ErrSlugTaken` and `ErrInvalid` are answers about the records. Every other error from a method satisfies `errors.Is(err, ErrUnreachable)`: a failing store, a random source that fails and a context already done all end there, and every consumer answers it with `Unreachable`, the one line a tool refuses with and the landing page answers `503` with, never quoting the underlying error. When one call meets several of these conditions, one fixed precedence decides its answer: a done context, then a failing store, then an invalid argument, then a missing trigger, then a taken slug, then a random source that fails.

## Recorded decisions

- The schema is the one migration `0001_triggers.sql`, which creates one table, `triggers`, with the columns `id` (the primary key), `slug` (unique), `owner_id`, `owner_email`, `schedule` (the trigger's `when`, named so because `WHEN` is an SQL keyword), `status`, `created` and `last_fired`, every one `TEXT` and not null but `last_fired`, which is null until the first fire; times are written as RFC 3339 in UTC to the second. There is no fire history: the latest fire's slot is the only fire the database keeps. A later change to the table is a new migration under the expand-then-contract rule.
- Ids are 8 bytes of `Rand`, in the order read; a drawn id that is the id of a trigger the store holds is drawn again, never refused. Nothing else is promised: no requirement promises or denies that a create may draw the id of a trigger since deleted, and the store keeps no record of deleted ids.
- The store keeps no lock: `DB.Write` runs one writer at a time, and `D05-scheduler` serializes each change with every fire.
- The store has no `Open` and no `Close`: the handle is appkit's, opened and closed by `cli.Run`, and a store over it lives as long as it does.
- A nil `Now` or `Rand` in `Config` means the production source (`time.Now`, `crypto/rand.Reader`), which `cmd/cron` wires; no requirement states it because no permitted test can observe it.
- `when` and slug validation live here, beside the records whose invariants they are, so that the tools, the scheduler and a test reach one rule; `D05-scheduler` computes slots from a `when` this package accepts.

## Consumer tasks

`cli.Run` opens the database with `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "cron.db"), Migrations: cron.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: stderr})`, writes `D03-serve`'s diagnostic `cron: cannot open database state/cron.db: <reason>` on an error, and otherwise builds `st := store.New(d, store.Config{Now: p.Now, Rand: rand})`, `rand` being the guarded reader over `p.Rand` that `D03-serve` hands every consumer of it (`D01-layout-and-run-seam`, R-C4FX-SNE2), hands it to `scheduler.Start` and `web.Config.Store`, and calls `d.Close()` after the drain.

The scheduler (`D05-scheduler`) reads `st.List(ctx)` at start for every active trigger, and for a change looks the trigger up with `st.Get(ctx, slug)`, compares its `OwnerID` with the caller's, and calls `st.Create(ctx, store.Draft{Slug: slug, When: when, OwnerID: u.UserID, OwnerEmail: u.Email})`, `st.SetWhen(ctx, t.ID, when)`, `st.SetStatus(ctx, t.ID, store.Paused)` or `store.Active`, or `st.Delete(ctx, t.ID)`; on a fire it calls `st.SetLastFired(ctx, t.ID, slot)`. The tools (`D08-tools`) check `store.ValidSlug` and `store.ValidWhen` before they call, answer `list` from `st.List` and `show` from `st.Get`, and answer `tools.NoTrigger(slug)` for `store.ErrNotFound`, `tools.SlugTaken(slug)` for `store.ErrSlugTaken`, and `store.Unreachable` for an error that satisfies `errors.Is(err, store.ErrUnreachable)`. The landing page (`D06-pages`) reads `st.List` once per request and answers `store.Unreachable` and a newline, as plain text with status `503`, when it fails. Every `trigger` attribute of an event satisfies `store.ValidID`.

A test opens a handle with `db.Open(ctx, db.Config{Path: filepath.Join(t.TempDir(), "state", "cron.db"), Migrations: cron.Migrations(), Now: clock})` and builds a store with `store.New(d, store.Config{Now: clock, Rand: bytes.NewReader(known)})`; creates with `s.Create`, reads back with `Get` and `List`, changes with `SetWhen`, `SetStatus` and `SetLastFired`, deletes, and closes the handle and opens another on the same path to see the same triggers. It builds the four triggers (R-41CY-BTCY) this way, with the ids, created times and latest fires they have, by handing `Rand` the id's bytes and `Now` the created time and calling `SetLastFired` and `SetStatus`. It calls `d.SetFailing(true)` before a call to see an unreachable store, and `d.SetFailing(false)` to see the same store answer again; it hands in a `Rand` that fails and a context already cancelled. It calls `store.ValidSlug`, `store.ValidWhen` and `store.ValidID` on the accepted and refused values the requirements list.
