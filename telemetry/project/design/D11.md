# Decision 11 — The canonical landing page

## Decision.

telemetry serves the suite's **uniform landing page** at its mount root,
byte-for-byte the canonical Carbon template every non-custom service ships
(crm, ledger, cron, gmail, notify, dropbox, scripts), with **only its text
changed**. Three pieces:

**The asset tree.** `share/www/landing.html` plus `share/www/static/` carrying
`tokens.css` and the four vendored fonts (`space-grotesk.woff2`,
`ibm-plex-sans.woff2`, `ibm-plex-mono-400.woff2`, `ibm-plex-mono-500.woff2`).
All files are copied **verbatim from the crm/ledger cluster** (their
`share/www/` trees are byte-identical suite-wide); `landing.html` then differs
in exactly three text values and nothing else:

- `<title>`: `{{.Service}} · telemetry`
- eyebrow: `Forensic record store`
- lead: `Telemetry keeps the box's audit trail: who did what, when, and in
  what order across every service — MCP calls, HTTP requests, events, and
  lifecycle.`

Everything else is the template's: the top-left `Home` link to `/`, the
`{{.Service}}` display name, the Service/Version/API panel with
`<code>POST /mcp</code>` (true for telemetry: the agent surface is MCP), the
inline stylesheet, the relative `static/` links, the `<head>` font preloads,
and `font-display` handling — the FOUT elimination is a property of the copied
template, not new work here.

**The chassis wiring.** `Spec.WWW: true` (D1): the chassis loads `share/www` at
startup — failing loudly at boot if the tree is missing — mounts
`GET /static/` on the embedded handler, and exposes the site through
`rt.WWW()`. The composition root registers the one route:

```go
rt.Handle("GET /{$}", http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    if r.URL.Path != "/" {
        http.NotFound(w, r)
        return
    }
    if err := rt.WWW().Render(w, "landing.html", struct {
        Service string
        Version string
    }{Service: rt.Service(), Version: rt.Version()}); err != nil {
        http.Error(w, "template error", http.StatusInternalServerError)
    }
}))
```

No new package: the handler lives in `cmd/telemetry/main.go` like every other
conformed service's, and no domain code knows the page exists.

**The routing.** Reaching the page from a browser is D6's session-gated tier
(the exact-match mount root and the `/static/` prefix); this Decision owns the
page and its loopback behavior, D6 owns the edge.

The landing `GET /` and `GET /static/*` requests are ordinary chassis-recorded
HTTP requests — only `/ingest` is excluded from recording (D1), so a page view
appears in the store like any other request, which is correct: it is front-door
traffic.

## Rejected.

- **Staying without a page.** D1 previously deferred it; every other suite app
  now serves the uniform page and an empty mount root reads as a broken deploy.
  The deferral's own terms said adding it later is additive — this Decision is
  that addition.
- **A telemetry-specific page** (record counts, retention horizon, a search
  box). The suite's landing pages are identity cards, not UIs; a live surface
  would need session-scoped data plumbing and would drift from the uniform
  template the operator expects on every mount. Product scopes the human UI to
  exactly this page.
- **Copying the repos variant of the template.** repos localized one comment
  line in `tokens.css`; the crm/ledger cluster is the larger byte-identical
  set, so it is the canonical source and keeps the "same html/css everywhere"
  property greppable.
- **Serving the fonts from a CDN or the dashboard.** The suite convention is
  self-served assets under the service's own session-gated `/static/`; a
  cross-origin font is a new failure mode and a tracking surface.
- **A dedicated `internal/web` package.** One route rendering one template is
  composition-root glue; a package would be structure without a seam.

## Verification.

- R-6B96-6B5S — Against the real composed Spec on a loopback listener,
  `GET /` renders the landing page: status 200, HTML containing the display
  name `telemetry`, the running version, the eyebrow `Forensic record store`,
  and the `Home` link — and the served bytes are **byte-identical to the
  canonical template** (the committed crm `landing.html`) apart from the three
  service-specific text values (`<title>` suffix, eyebrow, lead). A page that
  diverges from the template anywhere else, or renders a wrong/empty service
  name or version, fails.
- R-6CH2-K2WH — Through the same composed service, `GET /static/tokens.css`
  answers 200 with a CSS content type and bytes identical to the committed
  file, and `GET /static/fonts/space-grotesk.woff2` answers 200 with the
  vendored font's bytes; a missing asset tree fails the boot itself
  (`Spec.WWW` loads it at startup), which the test asserts by the successful
  serve.
