# Decision 8 — MCP input schemas conform to the agentkit tool-schema subset

## Decision.

Every schema telemetry advertises as a tool's **`inputSchema`** conforms to the
agentkit tool-schema subset (`project/research/research.md` §8.2). This is a
hard constraint on the surface D5 declares, not a new surface: the tool set,
the argument names, the handlers, and every behavior D5 promises are unchanged.

The constraint applies to **input schemas only**. agentkit reads a server's
`inputSchema` and discards `outputSchema` entirely (research §8), so telemetry's
output schemas are outside the subset's reach and keep their current closed
shape. This is deliberate asymmetry, and the two must not be collapsed.

Conformance is not a matter of discipline. A test drives the **real agentkit
gate** over the real tool table, so the claim is checked against the thing that
actually rejects us rather than against a local restatement of its rules.

### The two helpers

`internal/mcp` builds every advertised schema through one helper today, and that
helper stamps `"additionalProperties": false` on whatever it builds. That single
fact is the violation: the subset rejects `additionalProperties` **in any
authored form**, so every input schema telemetry declares is out of subset,
including the argument-less `guide`.

One helper cannot serve both roles, because the roles now disagree. It splits
in two, named for the role rather than the shape, so a future schema cannot be
built through the wrong one by accident:

```go
// inputObjectSchema builds an advertised inputSchema. It authors no
// additionalProperties: agentkit's subset rejects the keyword in any form,
// and closed-ness there is the provider adapter's to express, not ours.
func inputObjectSchema(properties map[string]any, required ...string) map[string]any

// outputObjectSchema builds an advertised outputSchema, closed with
// "additionalProperties": false. agentkit never reads output schemas; the
// closed declaration is real information for a client validating
// structuredContent, and it is kept.
func outputObjectSchema(properties map[string]any, required ...string) map[string]any
```

`searchInputSchema` and the inline `chain`/`get`/`guide` schemas build through
`inputObjectSchema`. `searchOutputSchema`, `chainOutputSchema`, and
`recordSchema` build through `outputObjectSchema`. `recordSchema`'s nested
open-object properties (`params`, `detail`, declared
`{"type": "object", "additionalProperties": true}`) are untouched: they appear
only inside output schemas.

### `search.limit`

`limit` drops `minimum: 1` and `maximum: 500` — both are excluded constructs —
and carries the range in its `description` instead:

```go
properties["limit"] = map[string]any{
    "type":        "integer",
    "description": "1 to 500, default 50",
    "default":     50,
}
```

`description` and `default` are both inside the subset, so the ceiling stays
visible in `tools/list`.

**No enforcement is lost.** The range was never enforced by the schema: the
handler validates it directly and returns a `validation` error naming `limit`
for anything outside 1–500. D5's rejection of silent clamping stands untouched,
and R-VYP4-2C07 already pins that behavior. What changes is only where an agent
reads the ceiling before calling — a schema keyword becomes a description
string.

### The conformance test and its substrate

The claim "agentkit accepts our schemas" hinges on an external contract, so it
is proven against the real dependency, not a local re-encoding of the subset's
rules. A restatement passes exactly when our transcription is correct and goes
silently stale the moment agentkit's subset moves; the real gate cannot.

A test in `internal/mcp` builds `Tools(...)` — the actual production tool
table — wraps each entry's real `InputSchema` in an `agentkit.Tool`, and runs
one `Conversation.Send` over a stub provider:

```go
// package mcp_test

// stubProvider records whether the orchestrator reached a provider call.
// The schema gate runs before any round-trip, so "RoundTrip ran" is the
// observable proof the whole tool set passed it.
type stubProvider struct{ called bool }

func (p *stubProvider) RoundTrip(ctx context.Context, req *agentkit.Request) *agentkit.RoundTrip
func (p *stubProvider) Identity() agentkit.Identity

// rawTool carries a schema to the gate verbatim. agentkit.Tool is sealed by an
// unexported method, so the interface is embedded (nil) to satisfy it; the
// four exported methods are overridden. Nothing on the validation path calls
// the sealing method. agentkit's own external test package uses this same
// form (research §8.5).
type rawTool struct {
    agentkit.Tool
    name   string
    schema json.RawMessage
}
```

`agentkit.NewTool` is not usable here: it derives a schema by reflecting a Go
input struct and cannot carry a hand-authored one (research §8.5).

telemetry therefore gains `github.com/ikigenba/agentkit` as a module
dependency, imported **only** from `_test.go` files, so no production binary
links it. It is a tagged external module (`v0.17.0` at the time of this
Decision), not an in-repo `replace`, and the pinned version is `go.mod`'s to
carry — this Decision does not restate it. A subset change in a later agentkit
release surfaces here as a red test on the next bump, which is the point.

This stays inside the scope boundary: the test lives in `telemetry/internal/mcp`
and builds, edits, and asserts nothing outside the telemetry tree. It makes no
claim about agentkit's own correctness — only that telemetry's advertised
schemas survive agentkit's gate.

### What this Decision does not do

It does not widen appkit's construction-time guard. appkit's
`conformsToStrictClient` encodes the strict-MCP-client rule, and neither it nor
the agentkit subset contains the other (research §8.4); making appkit carry the
subset suite-wide is appkit's decision in appkit's own spec, outside this scope
boundary. telemetry keeps passing appkit's guard and additionally proves the
agentkit subset for itself.

## Rejected.

- **Restating the subset in a telemetry-local validator.** Self-contained and
  dependency-free, and it verifies the wrong thing: it passes when our
  transcription of D34 is faithful, which is not the claim we care about. Worse,
  it fails silently in the direction that matters — agentkit widens or narrows
  the subset and our checker keeps agreeing with its own stale copy. The real
  gate is one exported interface away (research §8.5), so the proxy buys only
  the blind spot.
- **Fixing the schemas and adding no guard.** The offending keywords are exactly
  the ones a well-meaning author reaches for when adding the next bounded
  argument. Willpower is not a mechanism.
- **Dropping `additionalProperties` from output schemas too**, for one uniform
  helper. It would delete real information — a closed output declaration tells a
  `structuredContent` consumer the record shape is exhaustive — to satisfy a
  rule that does not apply to output schemas. Uniformity of the helper is not
  worth a weaker contract.
- **Keeping one helper with a boolean or role parameter.** The call sites then
  read `objectSchema(props, true, ...)`, and the failure mode of passing the
  wrong value is a silent conformance break rediscovered at an agent. Two names
  make the role explicit at every call site.
- **Leaving `limit` undescribed, with the validation error as the only signal.**
  An agent then discovers the ceiling by tripping it, having already spent a
  call. D5 chose the loud error over a silent clamp precisely so the agent
  learns the bound; declaring it up front serves the same intent and costs a
  string.
- **Validating conformance at construction, in `Tools()` or `NewHandler`.** It
  would put a schema-subset checker in the production binary to re-prove a
  property of static literals that cannot vary at runtime. The literals are
  fixed at compile time, so a test is the earliest point the defect is
  detectable and the only place it needs checking.
- **Waiting for appkit to widen its guard.** It is the right suite-wide fix and
  it is a different `project/` (research §8.4). telemetry is out of conformance
  now, and a service proving its own advertised contract is correct regardless
  of whether the chassis later enforces it too.

## Verification.

- R-D2X0-57VI — The **real agentkit gate** accepts telemetry's whole advertised
  input surface: a `Conversation` over a stub provider, carrying one tool per
  entry of the production `Tools(...)` table with each tool's real
  `InputSchema` as its schema, completes a `Send` whose `Err()` is nil — and the
  stub provider's `RoundTrip` is recorded as **having been called**, proving the
  gate ran and passed rather than the tool set never reaching it. Reintroducing
  any excluded construct (`minimum`, an authored `additionalProperties`, a
  non-string `enum` value) into any one of the four tools' input schemas fails
  this with `errors.Is(err, agentkit.ErrInvalidConfig)` and no `RoundTrip`.
- R-D44W-IZM7 — In `tools/list` over the real MCP handler, `search`'s
  `inputSchema` property `limit` carries **no** `minimum` and **no** `maximum`
  key, carries `"default": 50`, and carries a non-empty `description` containing
  both `1` and `500`; and no property of any of the four tools' input schemas,
  at any depth, carries an `additionalProperties` key. The runtime bound is
  unchanged: `limit: 0` and `limit: 501` still return a `validation` error
  naming `limit` and no records.
- R-D5CS-WRCW — The output surface is not collateral damage: in the same
  `tools/list`, `search`, `chain`, and `get` each still declare an
  `outputSchema` whose root carries `"additionalProperties": false`, and
  `recordSchema`'s `params` and `detail` still declare
  `"additionalProperties": true`; `mcp.New` constructs the handler without
  error, so appkit's own advertised-schema guard still passes. A build that
  strips `additionalProperties` from output schemas along with input schemas
  fails this.
