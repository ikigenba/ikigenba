# Decision 1 — Service skeleton, chassis Spec & composition root

## Decision.

telemetry is an ordinary appkit service with an unusually small chassis
footprint: an MCP surface, one extra loopback route, no event-plane role, no web
surface. `cmd/telemetry/main.go` is the whole composition root and contains no
domain logic.

```go
func main() { appkit.Main(telemetrySpec()) }

func telemetrySpec() appkit.Spec {
    return appkit.Spec{
        App:        "telemetry",
        Mount:      "/srv/telemetry/",
        Port:       registry.MustPort("telemetry"),
        MCP:        true,
        Migrations: db.FS,
        // The one Spec field unique to this service: the chassis's HTTP request
        // recorder produces no record for these exact paths (research §2.4).
        // Recording the ingest path would be an infinite regress.
        TelemetryExclude: []string{"/ingest"},
        ManifestExtras: []appkit.ManifestKV{
            {Key: "TELEMETRY_RETENTION_DAYS", Value: "90"},
        },
        Handlers: func(rt *appkit.Router) error {
            conn := rt.DB()
            if conn == nil {
                return fmt.Errorf("telemetry: no DB handle on router")
            }
            store := db.NewStore(conn)
            clock := telemetry.RealClock{}

            // The agent-facing surface: gated behind nginx-injected identity,
            // and recorded by the chassis like any other service's MCP traffic.
            h, err := mcp.NewHandler(store, clock, rt)
            if err != nil {
                return err
            }
            rt.Handle("POST /mcp", rt.RequireIdentity(h))

            // The reporting surface: loopback-only (D3). Its exclusion from
            // request recording is the Spec field above, not anything here.
            ingest.Mount(rt, store, clock)

            // The retention pruner runs for the lifetime of the process (D4).
            retention.Start(rt, store, clock)
            return nil
        },
    }
}
```

Deliberate non-fields: **no `Feed`** (telemetry publishes nothing), **no
`Consumes`** (it subscribes to nothing), **no `Events`** (it has no event
families), **no `WWW`** (no browser surface in v0.1.0 — see product Scope). The
chassis's `reflection` tool therefore reports an empty publish/subscribe pair,
which is the honest answer.

**What telemetry does not build.** Its own instrumentation is the chassis's:
appkit records MCP dispatch, plain-HTTP requests, and `lifecycle` start/stop in
`Run`. telemetry writes no recorder, no correlation middleware, and no ingest
*client* — only the ingest *server*. This is why the service's own tools show up
in its own store with no code here (research §2.4).

**Three chassis seams telemetry deliberately never touches**, named here so a
builder does not reach for them:

- `rt.Recorder()` — telemetry emits no records of its own. Every record in the
  store arrives over `/ingest`, including telemetry's own, which the chassis
  recorder POSTs to the loopback address like any other service's. A service
  that wrote directly into its own store would be the one reporter whose records
  bypassed the protocol, and its behavior would stop matching everyone else's.
- `rt.HTTPClient(timeout)` — telemetry makes no outbound HTTP calls at all.
- `Recorder.StartRoot` / `StartChain` — telemetry originates no chain. Its only
  background loop is the retention pruner (D4), which is internal housekeeping
  causing no cross-service work; a `root` record per hourly prune would add a
  daily 24 records of pure noise to the forensic timeline. The protocol's `root`
  origins are cron ticks, run spawns, and poll cycles, and pruning is none of
  them.

**Shipped configuration.** `etc/manifest.env` is authored in-repo and shipped
verbatim; the ordered `ManifestExtras` above make the emitted manifest
byte-stable, so `telemetry manifest` and the committed file can be compared
byte-for-byte:

```
APP=telemetry
MOUNT=/srv/telemetry/
DEFAULT=false
PORT=<registry port>
MCP=true
TELEMETRY_RETENTION_DAYS=90
```

`VERSION` is committed at `v0.1.0` (product's contractual constant).
`etc/nginx.conf` is D6's.

**Package boundaries.** `internal/record` is the leaf: it owns the record type
and its validation and imports nothing else of ours. `internal/db` imports
`internal/record`. `internal/ingest`, `internal/retention`, and `internal/mcp`
each import `internal/db` and `internal/record`; none imports another of the
three. `cmd/telemetry` imports all of them and is imported by none.

## Rejected.

- **A `share/www` landing page like webhooks D9 / the cron canonical.** Every
  other service serves one, so this is a real deviation. It is deferred because
  telemetry's mount is agent-only in v0.1.0 and a page would add an embedded
  Carbon asset tree, a session-gated nginx tier, and a phase, to show a service
  name and a version that `health` already reports. Adding it later is additive
  (a new Decision, a new fragment location, a new phase) and breaks nothing.
- **Making telemetry an event-plane producer** (publishing e.g. `record
  received`). It would make the store a traffic source for the very plane it
  observes, invite feedback loops, and serve no consumer that exists.
- **Hard-coding the loopback port** in the Spec. The registry owns the
  `name → port` table; a literal here is a second, drifting source of truth.
- **Putting the domain in `cmd/`.** The composition root must be readable in one
  screen and testable only through the surfaces it wires.
- **Building a telemetry-specific recorder** so telemetry could instrument
  itself independently of appkit. Two recorders is two definitions of the record;
  the protocol has exactly one, and it is the chassis's.

## Verification.

- R-V6NF-9LY8 — `telemetry manifest` emits exactly the committed
  `etc/manifest.env` bytes, including `MCP=true`, `TELEMETRY_RETENTION_DAYS=90`,
  a `PORT` equal to `registry.MustPort("telemetry")`, and **no** `FEED=` or
  `CONSUMES=` key. (Run the manifest verb's emitter over the real Spec and
  byte-compare against the file read from disk; a hand-edited manifest or a
  reintroduced feed role fails.)
- R-V7VB-NDOX — The Spec's `Port` equals `registry.MustPort("telemetry")`, that
  number appears as a literal in **no** Go source file in the module (the test
  walks `*.go`, excluding `project/`, and fails if it finds the digits), and a
  served instance binds the port its resolved config names — proven by starting
  the real server with the port overridden to an ephemeral loopback port and
  completing a real HTTP request against it. (A hard-coded port, or a Spec that
  ignores its config, fails.)
