# Decision 2 — The record type, the schema, and the append-only store

## Decision.

### The record type (`internal/record`)

One Go type mirrors the protocol record (research §1.1) exactly — no field the
protocol does not define, which is what makes "the store never contains bodies"
structural rather than disciplinary:

```go
type Record struct {
    ID            string          `json:"id"`
    Time          string          `json:"time"`            // RFC3339Nano from the reporter
    CorrelationID string          `json:"correlation_id"`
    Service       string          `json:"service"`
    Kind          Kind            `json:"kind"`
    Actor         Actor           `json:"actor"`
    Op            string          `json:"op"`
    Params        json.RawMessage `json:"params,omitempty"`  // JSON object or absent
    Outcome       Outcome         `json:"outcome"`
    Detail        json.RawMessage `json:"detail,omitempty"`  // JSON object or absent
}

type Actor struct {
    OwnerEmail string `json:"owner_email,omitempty"`
    ClientID   string `json:"client_id,omitempty"`
}

type Outcome struct {
    Status     string `json:"status,omitempty"`
    Error      string `json:"error,omitempty"`
    DurationMS *int64 `json:"duration_ms,omitempty"`
    Bytes      *int64 `json:"bytes,omitempty"`
    SHA256     string `json:"sha256,omitempty"`
}

type Kind string

const (
    KindEdge      Kind = "edge"
    KindRequest   Kind = "request"
    KindOutbound  Kind = "outbound"
    KindPublish   Kind = "publish"
    KindConsume   Kind = "consume"
    KindRoot      Kind = "root"
    KindLifecycle Kind = "lifecycle"
)

// Validate enforces the protocol's shape. It never rewrites or enriches.
func (r Record) Validate() error
```

`Validate` requires: a 26-character Crockford-base32 `id`; a `time` that parses
as RFC3339; a `kind` in the closed vocabulary above; a non-empty `service` and
`op`; a non-empty `correlation_id` **unless** `kind == lifecycle`; and `params`
/ `detail`, when present, being JSON **objects** (not arrays or scalars). It
does not cap sizes: thresholds are the reporter's job (research §1.3), and
re-imposing them here would silently discard records a correct reporter sent.

`params` and `detail` are kept as `json.RawMessage` and stored as text
unchanged. telemetry never parses inside them, never indexes their contents, and
never re-encodes them — a record read back is byte-identical to what was
reported.

### Timestamp normalization

```go
const TimeLayout = "2006-01-02T15:04:05.000000000Z07:00"

// Normalize parses an RFC3339 timestamp and renders it in fixed-width UTC form.
func NormalizeTime(s string) (string, error)
```

Every stored/compared/indexed/cursor-carried timestamp is the normalized form
(research §6): `2026-08-03T04:05:06.000000000Z`. This is what makes text
comparison in SQLite a correct time comparison; without it
`…:06.5Z` sorts before `…:06.45Z`. Normalization happens once, at the store
boundary.

### The schema (`internal/db/migrations/`)

Two bootstrap files: `001_schema_migrations.sql` copied verbatim from the suite
(appkit's migration-tracking table) and `002_records.sql`:

```sql
CREATE TABLE records (
    id             TEXT PRIMARY KEY,          -- reporter-minted ULID; idempotency key
    time           TEXT NOT NULL,             -- NORMALIZED fixed-width UTC
    correlation_id TEXT NOT NULL DEFAULT '',  -- '' only for kind='lifecycle'
    service        TEXT NOT NULL,
    kind           TEXT NOT NULL,
    owner_email    TEXT NOT NULL DEFAULT '',  -- flattened from actor
    client_id      TEXT NOT NULL DEFAULT '',  -- flattened from actor
    op             TEXT NOT NULL,
    status         TEXT NOT NULL DEFAULT '',  -- flattened from outcome
    error          TEXT NOT NULL DEFAULT '',
    duration_ms    INTEGER,
    bytes          INTEGER,
    sha256         TEXT NOT NULL DEFAULT '',
    params         TEXT,                      -- verbatim JSON object, or NULL
    detail         TEXT,                      -- verbatim JSON object, or NULL
    received_at    TEXT NOT NULL              -- NORMALIZED; when telemetry stored it
);

CREATE INDEX idx_records_time    ON records(time, id);
CREATE INDEX idx_records_chain   ON records(correlation_id, time, id);
CREATE INDEX idx_records_service ON records(service, time, id);
CREATE INDEX idx_records_kind    ON records(kind, time, id);
CREATE INDEX idx_records_owner   ON records(owner_email, time, id);
CREATE INDEX idx_records_client  ON records(client_id, time, id);
CREATE INDEX idx_records_sha     ON records(sha256, time, id);

CREATE TABLE ingest_drops (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    time        TEXT NOT NULL,   -- NORMALIZED; when telemetry was told
    service     TEXT NOT NULL,   -- who dropped them ('' when the batch named none)
    dropped     INTEGER NOT NULL CHECK (dropped > 0)
);
CREATE INDEX idx_ingest_drops_time ON ingest_drops(time);
```

The `actor` and `outcome` sub-objects are **flattened into columns** because
every one of them is a search axis; `params` and `detail` are **not** search
axes and stay as opaque JSON text. Each search axis gets one composite index
ending in `(time, id)` — the ordering/keyset columns — so an equality filter on
the axis is served by the index *and* returns rows already in cursor order
(research §6). `op` gets no index of its own: it is a substring filter, which
SQLite cannot index for a leading wildcard, so it is applied as a predicate over
the candidate set the indexed axes narrowed. `status` and `error` likewise get
no index — they are low-cardinality outcome classes that never usefully narrow
on their own, and are cheap predicates once time and service have narrowed.

`ingest_drops` is what makes lost records visible (product: "Loss is visible,
not silent"). It is a separate table, never a synthetic `records` row, because
the `kind` vocabulary is the protocol's and closed — inventing a kind would
break every other consumer of the model.

### The store (`internal/db`)

```go
type Store struct{ db *sql.DB }

func NewStore(db *sql.DB) *Store

// InsertRecords is the ONLY record write path. It is idempotent per record id
// (INSERT OR IGNORE) and inserts all records in one transaction. Returns how
// many rows were newly stored.
func (s *Store) InsertRecords(ctx context.Context, rs []record.Record, receivedAt time.Time) (stored int, err error)

// NoteDropped records a reporter's discarded-record count. No-op when n <= 0.
func (s *Store) NoteDropped(ctx context.Context, service string, n int64, at time.Time) error

// DroppedTotal is the total discarded count telemetry has been told about.
func (s *Store) DroppedTotal(ctx context.Context) (int64, error)

func (s *Store) Get(ctx context.Context, id string) (record.Record, bool, error)
func (s *Store) Chain(ctx context.Context, correlationID string) ([]record.Record, error)
func (s *Store) Search(ctx context.Context, q Query) ([]record.Record, Cursor, error)

// Oldest is the earliest stored record time (the effective retention horizon).
func (s *Store) Oldest(ctx context.Context) (string, bool, error)

// PruneBefore is the ONLY delete path: removes records and drop rows strictly
// older than cutoff. Returns the number of records removed.
func (s *Store) PruneBefore(ctx context.Context, cutoff time.Time) (removed int, err error)
```

There is deliberately **no** `Update…`, no `Delete(id)`, and no method taking
raw SQL. Append-only is a property of this interface (spine, *Conventions*).

```go
type Query struct {
    Since, Until  string   // normalized bounds; empty = unbounded
    Service, Kind string
    OwnerEmail    string
    ClientID      string
    SHA256        string
    Status, Error string   // outcome class; predicates, not index axes
    OpContains    string   // case-insensitive substring; not an index axis
    Limit         int      // resolved by the caller (D5)
    Cursor        Cursor   // keyset position; zero value = first page
}

// Cursor is the keyset position (time, id) of the last row of the previous
// page, opaque to callers and rendered as a single string on the wire.
type Cursor struct{ Time, ID string }

func (c Cursor) String() string
func ParseCursor(s string) (Cursor, error)
```

`Search` orders by `(time DESC, id DESC)` — newest first, the useful order in an
incident — and pages with the keyset predicate `(time, id) < (cursor.Time,
cursor.ID)`, never `OFFSET`, because inserts arrive continuously while an agent
pages (research §6). `Chain` orders `(time ASC, id ASC)` — a chain reads
forward — and is unbounded: a causal chain is the unit the product promises
whole.

## Rejected.

- **Storing the record as one JSON blob with a few extracted columns.** Simpler
  to write, but then every search axis is either a JSON extraction (unindexable
  here without generated columns) or a duplicate of the blob. The flattening is
  the whole reason search is index-backed.
- **Storing `params` / `detail` parsed and re-encoded.** Re-encoding would
  reorder keys and change the bytes an investigator sees; a forensic store must
  return what it was told, verbatim.
- **Indexing `op` with a trigram/FTS index.** FTS5 on `op` is real weight for a
  field that is short, already narrowed by service/kind/time, and searched with a
  substring not a query language. If op search ever becomes the bottleneck it is
  an additive Decision.
- **A single wide composite index instead of seven.** No single column order
  serves equality on seven different leading columns; SQLite would scan for six
  of the seven axes.
- **`OFFSET` pagination.** Under continuous insert it both repeats and skips
  rows — precisely the failure a forensic tool cannot have.
- **Storing the raw RFC3339Nano string and ordering on it.** Its fractional part
  is variable-width, so text ordering is wrong (research §6) and both the
  indexes and the cursors silently misbehave for records whose sub-second digits
  differ in length. Normalizing at the boundary costs one parse per record.
- **Recording drops as `records` rows with a new `kind`.** The kind vocabulary
  is the protocol's; extending it unilaterally breaks every reader of the model.
- **A `UNIQUE` constraint plus an error on duplicate id.** Delivery is
  at-least-once by design (research §1.5); a retried batch must be a no-op, not a
  failure that makes a reporter retry harder.
- **Rejecting records whose `params` exceed the protocol budget.** The reporter
  owns thresholds; a receiver that re-checks them turns a reporter bug into
  silent data loss at the only place that could have shown it.

## Verification.

- R-V938-15FM — Applying the full migration set to a fresh real temp-file SQLite
  database via the appkit runner yields a `records` table carrying every column
  above with the stated NOT NULL constraints, an `ingest_drops` table, and
  **exactly** the seven named `idx_records_*` indexes — asserted from
  `PRAGMA table_info(records)` and `PRAGMA index_list(records)`, so a missing
  index or a renamed column fails.
- R-VAB4-EX6B — `InsertRecords` is idempotent per id: inserting a record, then
  inserting a batch containing that same id with a **different** `op` and
  `service`, leaves exactly one row whose `op`/`service` are still the first
  values, and reports `stored == 0` for the repeat. (Real SQLite; the
  first-write-wins property distinguishes `INSERT OR IGNORE` from an upsert,
  which would pass a weaker "still one row" check.)
- R-VBJ0-SOX0 — Timestamps are stored normalized and order correctly as text: a
  record at `…:06.5Z` and one at `…:06.45Z` (differing only in fractional
  width) come back from `Chain` in true chronological order — the later one
  second. (Real SQLite; storing the raw RFC3339Nano string reverses this pair.)
- R-VCQX-6GNP — `Chain(cid)` returns every record carrying `cid` **across
  multiple services**, ascending by `(time, id)`, and no record carrying a
  different correlation id — including when records were inserted in reverse
  time order and across separate batches. Two records sharing one timestamp are
  ordered by `id`.
- R-VDYT-K8EE — `Search` keyset pagination partitions the result set exactly:
  over a seeded set larger than the limit, and where several records share one
  identical `time`, page 1 followed by page 2 (via the returned cursor) yields
  every matching record exactly once, in strictly descending `(time, id)` order,
  with no repeat and no gap — and a record inserted between the two calls with a
  `time` newer than page 1's first row does not shift or duplicate page 2.
- R-VF6P-Y053 — The search axes are index-backed on a real database:
  `EXPLAIN QUERY PLAN` for a `Search` filtered by each of `service`, `kind`,
  `owner_email`, `client_id`, `sha256`, `correlation_id`, and a bare time range
  reports a `SEARCH` using the corresponding `idx_records_*` index, never a
  `SCAN records`. (Dropping any one index turns its case into a table scan and
  fails this.)
- R-VGEM-BRVS — `PruneBefore(cutoff)` removes records **strictly older** than
  the cutoff and nothing else: a record whose time equals the cutoff exactly
  survives, one a nanosecond older is removed, one a nanosecond newer survives;
  `ingest_drops` rows are pruned on the same boundary; the returned count equals
  the number of records actually removed. (Real SQLite, deterministic clock.)
