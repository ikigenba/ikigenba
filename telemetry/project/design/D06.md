# Decision 6 — The nginx location fragment

## Decision.

`telemetry/etc/nginx.conf` is a **location fragment, not a vhost**: the
dashboard owns the apex `server{}` block, the single TLS cert, and the `/_authn`
introspection hook. Per the app-layout contract the fragment is authored in-repo,
shipped verbatim in the deploy bundle, and symlinked live by `opsctl setup` —
nothing substitutes it, so it must be directly loadable by nginx, which is why
the mount and the loopback port appear as literals in this one file (spine,
*Conventions*).

telemetry's mount serves exactly **three** kinds of route, one fewer than
webhooks (there is no public ingress tier and no landing page):

1. **Ungated PRM bootstrap** — `location = /srv/telemetry/.well-known/oauth-protected-resource`,
   exact-match so it wins over the catch-all, no `auth_request`. An MCP client
   with no token must be able to discover the authorization server. Because it
   is a public location it **clears** the correlation header
   (`proxy_set_header X-Correlation-Id "";`) so a public caller cannot inject a
   chain id and the service mints its own.
2. **Gated MCP endpoint** — `location = /srv/telemetry/mcp`, exact-match, behind
   `auth_request /_authn`, with each identity header set **exactly once** from
   the auth subrequest (`X-Owner-Id`, `X-Owner-Email`, `X-Owner-Name`,
   `X-Owner-Picture`, `X-Client-Id`) so a client-supplied value can never be
   smuggled upstream. It captures the correlation id the dashboard's
   introspection endpoint minted
   (`auth_request_set $tm_corr $upstream_http_x_correlation_id;`) and
   **overwrites** anything the client sent
   (`proxy_set_header X-Correlation-Id $tm_corr;`). It carries the same
   rate-limit fidelity shim every gated location uses: `auth_request` collapses
   any non-2xx/401/403 subrequest status into a synthetic 500, so the real
   status and `Retry-After` are captured and an internal 500 is re-emitted as a
   faithful 429 through a named `@telemetry_authn_500` location.
3. **Catch-all shield** — `location /srv/telemetry/ { return 404; }`. Everything
   else under the mount is unreachable.

**`/ingest` gets no location at all.** It is not gated, not shielded by a
dedicated `return 404` — it simply does not appear in the fragment, so it falls
to the catch-all like any other unlisted path, and appkit's `LoopbackOnly` guard
(D3) refuses it even if a future fragment edit exposed it. The two mechanisms
are independent on purpose. For the same reason the fragment contains the string
`ingest` **nowhere**, which is a greppable invariant.

There is no `/feed` location because telemetry is not a producer, no
session-gated mount root because there is no landing page (D1), and no
`/static/` tier because there are no assets.

## Rejected.

- **An explicit `location = /srv/telemetry/ingest { return 404; }`.** It reads
  as belt-and-braces but writes the ingest path into the one file an operator
  edits under pressure, turning "this path is not routable" into "this path is
  routable, and currently denied". Absence is the stronger statement, and the
  no-`ingest`-string grep can then be a real invariant.
- **Templating the port into the fragment at deploy time.** The app-layout
  contract ships fragments verbatim; a substitution step would need a renderer
  on the box and would break the "the bundle is the artifact" property. The
  literal plus a drift test is the sanctioned shape.
- **Gating the whole mount with one prefix `auth_request`.** The PRM doc must be
  reachable without a token; a prefix gate would make token bootstrap
  impossible.
- **Trusting a client-supplied `X-Correlation-Id` on the gated location.** The
  edge is the strip-and-mint point (research §1.2); accepting an inbound id from
  a public client would let anyone merge their traffic into someone else's chain
  or forge a chain wholesale.
- **A session-gated mount root proxying to a landing page.** No page exists in
  v0.1.0 (D1); adding the location before the page would serve a 404 through an
  auth chain.

## Verification.

- R-W60I-CYGD — The fragment is a pure location fragment and its literals match
  the registry: parsing `etc/nginx.conf` finds no `server`, `listen`,
  `ssl_certificate`, or `http` block, every `proxy_pass` targets
  `127.0.0.1:<p>` where `p == registry.MustPort("telemetry")`, and every
  `location` path begins with the mount `/srv/telemetry/`. (Changing the
  registry port without the fragment fails this.)
- R-W78E-QQ72 — The gated MCP location is exact-match, carries
  `auth_request /_authn`, and sets each of `X-Owner-Id`, `X-Owner-Email`,
  `X-Owner-Name`, `X-Owner-Picture`, and `X-Client-Id` **exactly once** from an
  `auth_request_set` variable — a header set zero times, twice, or from anything
  other than the auth subrequest fails.
- R-W8GB-4HXR — The fragment never routes ingest and shields everything
  unlisted: the file contains the substring `ingest` **zero** times, and the
  only prefix `location /srv/telemetry/` is a `return 404;` with no `proxy_pass`.
- R-W9O7-I9OG — The PRM location is exact-match, carries **no** `auth_request`,
  and proxies to the upstream `/.well-known/oauth-protected-resource` path — so
  a tokenless client can still bootstrap.
- R-WAW3-W1F5 — Correlation handling matches the edge rule: the gated MCP
  location captures the introspection response's correlation id via
  `auth_request_set` and sets `X-Correlation-Id` from that captured variable,
  while the ungated PRM location sets `X-Correlation-Id` to the empty string —
  a fragment that omits either, or that passes the client's value through on the
  gated location, fails.
