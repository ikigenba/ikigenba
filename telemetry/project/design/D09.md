# Decision 9 — Suite-contract conformance: the opsctl install layout & the authored env contract

## Decision.

telemetry is an ordinary deployable service of the suite, so it **conforms by
default** to the suite-wide contracts the umbrella project owns. Two of those
contracts carry `[proof: per-service]` Verification ids, which means each
adopting service proves them **in its own tree**:

- **The `/opt/<svc>/` install layout and its per-service adoption** —
  `project/design/D08.md` at the repo root.
- **The portable authored `manifest.env` and the composed data paths** —
  `project/design/D11.md` at the repo root.

(Those are the *umbrella's* D08 and D11, at the repo root — not this design's
own `D08.md`, which is the agentkit tool-schema subset.)

This Decision is the **citation**, and citation is adoption: telemetry owns none
of those contracts' content, restates none of it, and takes each by value from
the umbrella Decision named above. What is local to telemetry — and all this
Decision adds — is *where the proof lives* and *what substrate can falsify it
here*:

- The proofs live in **`cmd/telemetry/main_test.go`**, the composition root's
  test file, matching every other adopting service (`crm`, `ledger`, `notify`,
  `dropbox`, `github`, `repos`). It is already `package main`, so
  `telemetrySpec()` is directly callable and the manifest comparison can read
  the compiled Spec rather than re-typed literals. No new package is introduced.
- The committed authored manifest is **`telemetry/etc/manifest.env`**; the
  compiled default it must agree with is the one `telemetrySpec()` declares —
  `APP=telemetry`, `MOUNT=/srv/telemetry/`, `DEFAULT=false`, `PORT` from
  `registry.MustPort("telemetry")`, `MCP=true`, the single manifest extra
  `TELEMETRY_RETENTION_DAYS=90`, and — per D1's deliberate non-fields — **no**
  `FEED=` and **no** `CONSUMES=`.
- This is a **different claim** from `R-V6NF-9LY8` (D1), which pins the built
  binary's `manifest` **verb** output against the same file. `R-8IAN-FB87` is
  about the compiled `Spec`'s defaults through the `appkit/manifest.Emit`
  **library function**, and is the drift check that survives the verb's removal
  under the root D11 (whose verb-dispatch id is proven in `appkit`, not here, so
  it is cited by Decision path only). Both stand; neither is
  folded into the other, and this Decision does not touch D1.
- The boot proof runs the **built binary against a temporary root**, not the
  live box. Five facts particular to telemetry shape it:
  - The Spec has **no `Config` hook** and needs no credentials, key material, or
    provider access to serve. `Handlers` requires only a non-nil DB handle on the
    router, which the chassis supplies because the Spec carries `Migrations`.
    Nothing gates boot behind an external contract, so the smoke needs no
    throwaway secrets at all.
  - The `Health` reporter reads **only telemetry's own SQLite store**
    (`Store.DroppedTotal`), so the health envelope is genuinely green offline:
    `status: "ok"` with a `details.dropped_total` of `0` against a fresh DB. No
    network dependency is folded into it, and none may be introduced to make the
    smoke pass.
  - telemetry declares **no `WWW`** and embeds no web assets (D1: no browser
    surface), so the layout proof involves **no `share/` tier** and no
    `TELEMETRY_WWW_PATH` — only `state/`, `cache/`, `libexec/`, `bin/run`, and
    `etc/<version>/manifest.env` with `etc/current` selecting it.
  - telemetry is **neither an event-plane producer nor a consumer** (D1; it does
    not depend on `eventplane` at all), so there is no feed to be unreachable
    offline and no consumer loop to tolerate one. The `cache/` tier is still
    falsifiable regardless: appkit's `serve` calls `outbox.EnsureGeneration` on
    the composed generation path **unconditionally**, before any producer branch,
    so the sidecar lands under `cache/` for telemetry exactly as it does for a
    producer.
  - telemetry holds **no durable state beyond its DB**: `internal/ingest` and
    `internal/retention` write only through the store, so `state/` needs to hold
    nothing but `telemetry.db`.
- One hazard is telemetry's alone and the smoke must avoid it. The chassis
  recorder's ingest URL defaults to `registry.BaseURL("telemetry") + "/ingest"`
  — for *this* service, the shared host port that a running suite (possibly
  another worktree's) may own. A boot smoke that left the recorder enabled would
  post its own records into a stack it does not own and would read as passing
  only when such a stack happens to exist. The smoke therefore disables the
  recorder (`TELEMETRY_ENABLED=false`) or points `TELEMETRY_INGEST_URL` at the
  temp instance's own ephemeral port; it never touches the registry port.

Conformance is the default and this Decision records no deviation: telemetry
departs from neither contract. Its absent `share/` tier is not a deviation but
the shape the layout takes for a service with no web surface.

## Rejected.

- **Restate the two contracts' requirements locally so the design reads
  self-contained.** A local restatement is drift by construction — it goes stale
  the moment the umbrella Decision is rewritten, and the suite's rule is cite,
  never restate. Rejected for citation by path.
- **Fold the citation into D1 (service skeleton, chassis Spec & composition
  root).** D1 owns the Spec's shape and its three ids; hanging three adopted,
  externally-owned ids off it would blur which Decision states the behavior. A
  small, separate conformance Decision keeps the ownership legible.
- **Treat the contracts as proven elsewhere and cite only the Decision paths,
  without the ids.** Both contracts are marked `[proof: per-service]`: a service
  that adopts them must carry its own tagged tests. Citing the paths alone would
  leave telemetry unproven against layout and env drift that only its own tree
  can detect.
- **Reuse `R-V6NF-9LY8`'s manifest-verb assertion as the drift proof.** The verb
  is on its way out under the root D11 while the authored file stays; a drift
  check anchored to the verb disappears with it. Rejected for the library-level
  comparison against the compiled `Spec`.
- **Reuse the existing `assertServeHonorsPortOverride` boot (`R-V7VB-NDOX`) as
  the layout proof.** That helper starts the binary with an overridden port and a
  `TELEMETRY_DB_PATH` pointing anywhere convenient — it proves the port claim and
  says nothing about the install tree, the symlinks, or the composed
  `state/`/`cache/` placement, which is exactly what the layout contract is
  about. Rejected: a separate smoke that builds the tree is what can fail.
- **Prove the boot against the running suite (`bin/start`) instead of a temp
  root.** That makes the phase's exit condition depend on shared host ports and
  another worktree's stack — doubly wrong for telemetry, whose recorder already
  aims at the registry port. The contract's own substrate line admits either; the
  temp root is the deterministic one, and is what every adopting service uses.

## Verification.

Each id below is **adopted**, not minted here: it belongs to the umbrella
Decision cited beside it, which states the behavior. These lines say only what
substrate proves it inside `telemetry/`.

- R-4LKF-FB23 — adopted from `project/design/D08.md` at the repo root.
  Substrate: a Go test in `cmd/telemetry/main_test.go` that assembles a fresh
  `/opt/telemetry/`-shaped tree under `t.TempDir()` (`state/`, `cache/`,
  `libexec/telemetry-<VERSION>`, `bin/run` → that binary,
  `etc/<VERSION>/manifest.env` copied byte-for-byte from the committed authored
  file, `etc/current` → `<VERSION>`), asserts `bin/run` and `etc/current`
  resolve to their intended targets and that the manifest selected through
  `etc/current` equals the committed one, then runs `bin/run serve` on a free
  loopback port and asserts the served `/health` is `200` with
  `service: "telemetry"`, `status: "ok"`, and `details.dropped_total` `0`, and
  that the DB was created under `state/` and the generation sidecar under
  `cache/`. Offline: no network, no credentials, no `bin/start`, and the chassis
  recorder disabled so nothing is posted at the registry port.
- R-8DF1-W89F — adopted from `project/design/D11.md` at the repo root.
  Substrate: a Go test in `cmd/telemetry/main_test.go` scanning the committed
  `telemetry/etc/manifest.env` bytes and failing on an absolute `/opt/` path or
  a `TELEMETRY_DB_PATH=` / `TELEMETRY_GENERATION_PATH=` line.
- R-8IAN-FB87 — adopted from `project/design/D11.md` at the repo root.
  Substrate: a Go test in `cmd/telemetry/main_test.go` comparing
  `manifest.Emit(...)` over fields read off the `appkit.Spec` that
  `telemetrySpec()` returns against the committed `telemetry/etc/manifest.env`
  bytes, failing on any difference in either direction.
