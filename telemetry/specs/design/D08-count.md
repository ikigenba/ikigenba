# D08-count

`count` says how many records match a filter, and how they split. Its list entry, schemas and annotations are `D06-mcp`'s; this document is its call: the filter it shares with `search`, the one argument it adds, `by`, the refusals and their words, and the shape of its answer. It reads the trail through `store.Count` and `store.CountBy` (`D05-store`) and nothing else.

## The filter and the grouping

The filters are `search`'s, read the same way into the same `store.Filter` (`D07-search`'s search filter): `since` inclusive and `until` exclusive, `services` and `events` any-of, `user` and `request_id` exact, `attrs` every pair equal with a number matching a number and a string a string, all optional and ANDed. `by` is optional and says how to group what matched: a field of the envelope, `service`, `event`, `user` or `request_id`; a time bucket, `minute`, `hour` or `day`; or an attribute, `attrs.<key>`. The spelling is handed to the store as a `store.GroupBy`, whose constants are those eight forms, and a spelling that is none of them is the store's `ErrGroupBy`, which the tool answers with the refusal that names what is allowed. `attrs.` followed by any non-empty key is a grouping, whether or not a record carries the key: a key nothing carries gives a total and no groups, not an error, as a service nothing recorded gives `catalog` an empty answer.

## Refusals

Three, checked in this order and the first one found answered: `since` that is not an RFC 3339 time, `until` that is not one, each in the words `search` uses, and a `by` that is none of the eight forms, `by must be service, event, user, request_id, minute, hour, day, or attrs.<key>, got '<value>'`, with the value quoted as given, so a path or a bare attribute name without `attrs.` is refused naming what is allowed.

## The answer

Without `by`, `{"total":<n>}`. With `by`, `{"total":<n>,"groups":[...]}`, where `total` is the same number as without `by` and each group is `{"key":<text>,"count":<n>}`. The key is always a JSON string: a field's value as stored, the empty string included, so the groups still add up to the total; a bucket's start as RFC 3339 UTC without a fraction; or an attribute's value as text, a string as itself and a number or a boolean as its JSON text, `200` for the status 200. It is a string even for a number because an output schema in appkit's subset describes each member with one JSON type and the server refuses an output that does not honour its schema, so a `key` that was sometimes a number and sometimes a string could not be promised; a model that wants the number parses the text. The groups of a field or an attribute are ordered by count descending, then by key ascending, so the noisiest comes first and ties read in name order; a record without the attribute is in the total and in no group. The buckets of a time grouping are oldest first, a bucket with no record left out, so the agent reads them as a timeline. A filter that matches nothing is `{"total":0}`, with `"groups":[]` when `by` was given. Only retained records are counted.

## Consumer tasks

A model counts the whole trail before its own calls with `{"until":"2026-10-02T14:30:00Z"}`; by service with `{"until":"2026-10-02T14:30:00Z","by":"service"}`, getting `{"total":25,"groups":[{"key":"dummy","count":10},...]}`; by an attribute with `{"by":"attrs.status"}`, getting groups keyed `"200"` and `"500"`; by hour with `{"by":"hour"}`, getting buckets keyed `"2026-09-30T08:00:00Z"` and on, oldest first; and narrows with `{"services":["dummy"],"events":["request.finished"],"attrs":{"status":500}}`, getting `{"total":1}`. It is refused with `by must be service, event, user, request_id, minute, hour, day, or attrs.<key>, got 'path'` or `until is not an RFC 3339 time: '2026-10-02 14:00'`.

A test fills a store through `Deliver`, calls `count` through `mcp.Client` with and without `by`, and asserts `structuredContent` against the totals and the ordered groups it expects, and the text of each refusal.

## REQUIREMENTS

- R-CAIG-HK21: A `tools/call` of `count` on a tools server whose `since` argument is a string `v` for which `time.Parse(time.RFC3339, v)` returns a non-nil error MUST return a refusal with `since is not an RFC 3339 time: '<v>'`, and one whose `since` is absent or parses and whose `until` argument is a string `v` that does not parse MUST return a refusal with `until is not an RFC 3339 time: '<v>'`, where `<v>` is the value exactly as given.
- R-CBQC-VBSQ: A `tools/call` of `count` on a tools server whose `since` and `until` are absent or parse and whose `by` argument is present and is a string `v` for which `store.CountBy` with `store.GroupBy(v)` returns an error wrapping `store.ErrGroupBy` (a string that is none of `service`, `event`, `user`, `request_id`, `minute`, `hour` and `day` and is not `attrs.` followed by one or more characters, `path`, `status`, `attrs.` and the empty string included) MUST return a refusal with `by must be service, event, user, request_id, minute, hour, day, or attrs.<key>, got '<v>'`, where `<v>` is the value exactly as given.
- R-CCY9-93JF: A `tools/call` of `count` on a tools server over `s` whose `arguments` hold no offence appkit's argument decoding finds, that R-CAIG-HK21 does not refuse, and whose `by` is absent MUST return a success result with exactly `{"total":<n>}`, where `<n>` is the JSON integer `s.Count(ctx, <filter>)` returns at the time of the call and `<filter>` is the search filter (`D07-search`) of the arguments.
- R-CE65-MVA4: A `tools/call` of `count` on a tools server over `s` whose `arguments` hold no offence appkit's argument decoding finds, that R-CAIG-HK21 and R-CBQC-VBSQ do not refuse, and whose `by` is present MUST return a success result with `{"total":<n>,"groups":[<groups>]}`, where `<n>` and `<groups>` come from the total and the groups `s.CountBy(ctx, <filter>, store.GroupBy(<by>))` returns at the time of the call, `<filter>` being the search filter of the arguments and `<by>` the `by` argument: `<n>` the total as a JSON integer and `<groups>` holding, for each `Group` in order, `{"key":<Key>,"count":<Count>}` with `<Key>` the `Key` as a JSON string, a number or boolean attribute value included, and `<Count>` the `Count` as a JSON integer.
- R-CFE2-0N0T: The `groups` of a `count` success result MUST be ordered as `store.CountBy` orders them: for `by` `service`, `event`, `user`, `request_id` or `attrs.<key>`, by `count` descending and then by `key` ascending in byte order, and for `by` `minute`, `hour` or `day`, by the bucket's start ascending, with no group for a bucket no matching record falls in and no group for a matching record that does not carry the attribute.
- R-CGLY-EERI: The `key` of a group in a `count` success result MUST be, for `by` `service`, `event`, `user` or `request_id`, the value of that field of the grouped records as stored, the empty string included; for `by` `minute`, `hour` or `day`, the start of the bucket in UTC formatted with the layout `2006-01-02T15:04:05Z`; and for `by` `attrs.<key>`, the text of the attribute's value, a string as itself and a number or boolean as its JSON text, so that records ingested with `"status":200` are grouped under the key `200`.
- R-CJ1R-5Y8W: A `tools/call` of `count` on a tools server whose `arguments` hold no offence, that no requirement above refuses, and whose search filter no record matches MUST return a success result with exactly `{"total":0}` when `by` is absent and exactly `{"total":0,"groups":[]}` when `by` is present and acceptable.
