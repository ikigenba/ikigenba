# D02-cli

telemetry as a command: what `cli.Run` does with the arguments that `D01-layout-and-run-seam` hands it through `Process`. This design covers the three commands (`--version`, `manifest`, `--help`), the usage error, and the rule that a command never looks at the environment, the socket or the database. When `Args` is empty, telemetry serves, and everything from there — the drain deadline, the retention window, the socket the host passes in, the store, the sweeps, readiness, the drain on a signal, and the failures of each — is `D03-serve`; what the handler then answers is `D04-pages` and the designs it leads to.

`Run` takes at most one argument and the argument decides everything. An empty `Args` means serve. The three recognised single arguments each write one product to `Stdout` and return `ExitSuccess` without touching the environment: `--version` writes `Version` and a newline, `manifest` writes `Manifest` exactly as `D01-layout-and-run-seam` declares it, and `--help` writes `Usage`, the constant `D01-layout-and-run-seam` declares and whose value this design fixes byte for byte, so the help text is contract. Any other `Args` is a usage error. The argument telemetry complains about is the first one it does not take: the first element when that is not a recognised word, otherwise the second element, which is surplus whatever it says. An argument that starts with `-` is an unknown option; any other is an unknown command. Both diagnostics follow the repository's command-line conventions: the first line begins `telemetry: `, and after exactly one empty line comes the hint to run `telemetry --help`, unprefixed because telemetry is speaking for itself. The usage text is never written to `Stderr`.

The help text says what telemetry serves — ingest at `/ingest`, the MCP tools at `/mcp`, and a landing page at `/` — and where — on the socket systemd passes in — and names the exit codes, which is where the contract the rest of the design realises is declared: 0 for success, 1 for a server that failed, 2 for a usage error. `D03-serve` leans on that split: a start the caller got wrong (no socket, several sockets, a drain deadline or a retention window that is not a number) exits 2, while trouble on the host once telemetry is past its checks — a database it cannot open, a drain that runs out — exits 1.

Arguments are checked before anything else. A command never needs a socket or a database, so `telemetry --version` succeeds with nothing passed in and `telemetry bogus` fails as an unknown command whatever the environment holds; `Run` touches none of the environment, the inherited descriptor, systemd's notification socket, the banner source, the server maker or the database source unless `Args` is empty. A command records no event: the trail is what telemetry records while it serves, and a command never builds the writer. That a command opens no database is observable: with `DBSource` naming a path inside a directory that does not exist, the directory still does not exist when `Run` returns.

Every failure leaves `Stdout` empty, so a caller that reads the streams separately sees a product or a complaint, never a mixture. Every diagnostic is one write to `Stderr`, so a two-line diagnostic lands whole even when another writer such as journald interleaves with the same stream.

## The two files under etc/

The manifest and the nginx fragment are facts about the binary, so the binary carries them as the constants `Manifest` and `NginxConf`. The committed `etc/manifest.toml` holds exactly the text of `Manifest`, so the checkout can be read without a build, and `devctl build` refuses an app where the two differ; `etc/nginx.conf` holds exactly the text of `NginxConf`, and the host's nginx includes it in telemetry's server block so that the public `/ingest` answers 404. The build run writes both files from the constants and keeps them in step, as `D01-layout-and-run-seam` records. Neither file is a requirement: `AGENTS.md` forbids every test to read the checkout, `etc/` included, and a requirement no admitted test can decide is not a requirement. The constants' values are contract, proved by use — `manifest` prints `Manifest`, and `NginxConf` is a declared constant a test compiles against — and the files are their copies. Nothing prints the fragment: the bootstrap story fixes the usage text and its one command, `manifest`, and a second command would be a story change.

## REQUIREMENTS

- R-ONDD-GG0V: `Usage` MUST be exactly `"Usage: telemetry [command]\n\nServe the suite's trail of events: ingest at /ingest, MCP tools at /mcp, and\na landing page at /, on the socket systemd passes in. With no command, serve.\n\nCommands:\n  manifest   print the app manifest\n\nOptions:\n  --help      print this help\n  --version   print the version\n\nExit codes:\n  0  success\n  1  the server failed\n  2  usage error\n"`.
- R-OOL9-U7RK: When `Args` is exactly `["--version"]`, `Run` MUST write `Version` followed by a single `"\n"` to `Stdout` and nothing else, write nothing to `Stderr`, and return `ExitSuccess`.
- R-OPT6-7ZI9: When `Args` is exactly `["manifest"]`, `Run` MUST write exactly `Manifest` to `Stdout` and nothing else, write nothing to `Stderr`, and return `ExitSuccess`.
- R-OR12-LR8Y: When `Args` is exactly `["--help"]`, `Run` MUST write exactly `Usage` to `Stdout` and nothing else, write nothing to `Stderr`, and return `ExitSuccess`.
- R-OS8Y-ZIZN: `Run` MUST treat `Args` as a usage error unless `Args` is empty or is exactly one of `["--version"]`, `["manifest"]`, or `["--help"]`.
- R-OTGV-DAQC: On a usage error from `Args`, the offending argument MUST be `Args[0]` when `Args[0]` is none of `--version`, `manifest`, or `--help`, and `Args[1]` otherwise.
- R-OUOR-R2H1: On a usage error from `Args`, `Run` MUST write exactly `"telemetry: unknown option '" + arg + "'\n\nsee 'telemetry --help' for usage\n"` to `Stderr` when the offending argument `arg` begins with `-`, and exactly `"telemetry: unknown command '" + arg + "'\n\nsee 'telemetry --help' for usage\n"` otherwise, MUST write nothing to `Stdout`, and MUST return `ExitUsage`.
- R-OVWO-4U7Q: When `Args` is not empty, `Run` MUST return without calling `LookupEnv`, `Unsetenv`, `Inherit`, `Banner`, `MCP`, `Now`, `Sleep` or `Rand`'s `Read`, without taking file descriptor 3, without sending anything to a notification socket, and without opening, creating or writing anything at `DBSource` — so that when `DBSource` names a path inside a directory that does not exist, that directory still does not exist when `Run` returns — so that the outcome of a command or a usage error is the same whatever the environment holds, and so that a `Process` whose `Banner`, `MCP`, `Inherit`, `Now`, `Sleep` and `Rand` are nil is enough for every command.
- R-OYCG-WDP4: Whenever `Run` returns a value other than `ExitSuccess` it MUST have written nothing to `Stdout`, and every diagnostic `Run` writes MUST be delivered as a single call to `Stderr.Write` whose first line begins `telemetry: `.
