# D07-search

`search` lists the records that match a filter, newest first, a page at a time. Its list entry, schemas and annotations are `D06-mcp`'s; this document is its call: how the arguments become the store's filter, which arguments it refuses and in what words, and what a page holds. It reads the trail through `store.Search` (`D05-store`) and nothing else.

## From arguments to a filter

Every argument is optional and the ones given combine. `since` and `until` are RFC 3339 times, read with the standard library's `time.Parse` and the `time.RFC3339` layout, which accepts a fractional second and any offset, so a time written in another offset means the same instant as in UTC; `since` is inclusive and `until` exclusive, so hour-wide ranges tile without overlap, and a `since` not before `until` is a range holding no instant, which matches nothing and is not an error. `services` and `events` each match any of the names given. `user` and `request_id` match exactly, the empty string included, which is why they are pointers in the input type. `attrs` arrives as the open object appkit decodes for a `json.RawMessage`, and the tool reads its members itself with the same rule the ingest handler reads an event's attributes by: a string is a string, `true` and `false` are booleans, and a number is an integer when it parses as one and a float otherwise, so that `500` written by a model and `500` written by a sibling compare equal while `"500"` does not. A member whose value is none of those, `null` or a nested value, can match no record, since no record carries one, and the filter matches nothing; a member name repeated in the object is read as the last of its values, as `encoding/json` reads a repeated name.

## Refusals

A tool that cannot do what it was asked returns an error from its handler, which appkit answers as an `isError` result with one text block (`D06-mcp`). `search` has four, checked in this order and the first one found answered: `since` that is not an RFC 3339 time, `until` that is not one, `limit` outside 1 to 500, and a `cursor` the store does not recognise as one a search issued. Each names the argument and quotes the value as the stories fix. `limit` left out is 50; a `limit` given is checked as given, so `0` is refused rather than taken as the default. A cursor is only what a search answered: the store's `ErrCursor` for a string of any other shape becomes `cursor is not one search issued`, so a made-up cursor or one damaged in transit is refused rather than guessed at.

## The page

A page is the first `limit` records matching the filter in the store's search order: newest first, and among records with one time the reverse of the order telemetry received them, so a search reads the trail backwards exactly and `trace` reads the same records the other way round. The result is `{"records":[...]}` and, when more records match than the page holds, `"cursor":"<cursor>"`, the store's `Next`; the last page has no `cursor` member, which is how the agent knows it has everything. Passing a cursor back with the same filters answers the next page, and the pages together are every matching record once, none on two pages and none skipped. The cursor encodes a position and nothing else, so one sent with other filters is not refused: it continues from the same position under the filters it came with. Only retained records are found: a record the sweep has removed is on no page.

## Consumer tasks

A model searches by request id with `{"request_id":"9b2e4d6f8a1c3e5b7d9f0a2c4e6b8d1f"}`; by user with `{"user":"u_1e9b4d07"}`; by names and a bound with `{"services":["mcp"],"events":["sibling.called","tool.called"],"until":"2026-10-02T14:30:00Z"}`; by an attribute's value with `{"attrs":{"status":500}}`; a time range with `{"since":"2026-10-02T13:00:00Z","until":"2026-10-02T14:00:00Z"}`; and pages with `{"until":"2026-10-02T14:30:00Z","limit":10}`, then the same with `"cursor":"<cursor>"` from each answer until one has none. It is refused with `since is not an RFC 3339 time: 'yesterday'`, `limit must be between 1 and 500, got 0` or `cursor is not one search issued`.

A test fills a store through `Deliver` with records of known times, some sharing a time, registers the tools on a server over a capturing writer and calls `search` through `mcp.Client`, asserting the `records` array of `structuredContent` against the record objects it expects in order, the presence and absence of `cursor`, and the text of each refusal.

## REQUIREMENTS

- R-BZJD-1MDS: telemetry's design defines the **search filter** of a `tools/call`'s arguments as the `store.Filter` whose `Since` and `Until` are nil when `since` and `until` are absent and otherwise point to the times `time.Parse(time.RFC3339, <value>)` returns for them; whose `Services` and `Events` are the `services` and `events` arrays as given, nil when absent; whose `User` and `RequestID` are nil when `user` and `request_id` are absent and otherwise point to their strings as given; and whose `Attrs` is nil when `attrs` is absent and otherwise holds one entry per distinct member name of the `attrs` object, the last value given for a repeated name, a string member as a `string`, `true` and `false` as a `bool`, a number as the ingest handler of appkit's `telemetry` package decodes an attribute number (`int64`, `uint64` or `float64`, negative zero as `float64`), and any other member value (`null`, an object or an array) as a value that is not a valid attribute value; every requirement of telemetry's design that names the search filter MUST denote this.
- R-C0R9-FE4H: A `tools/call` of `search` on a tools server whose `since` argument is a string `v` for which `time.Parse(time.RFC3339, v)` returns a non-nil error MUST return a refusal with `since is not an RFC 3339 time: '<v>'`, and one whose `since` is absent or parses and whose `until` argument is a string `v` that does not parse MUST return a refusal with `until is not an RFC 3339 time: '<v>'`, where `<v>` is the value exactly as given.
- R-C1Z5-T5V6: A `tools/call` of `search` on a tools server whose `since` and `until` are absent or parse and whose `limit` argument is present and is less than 1 or greater than 500 MUST return a refusal with `limit must be between 1 and 500, got <n>`, where `<n>` is the decimal text of the limit as decoded, so `0` and `501` are refused with `got 0` and `got 501`.
- R-C372-6XLV: A `tools/call` of `search` on a tools server whose `since`, `until` and `limit` are absent or acceptable and whose `cursor` argument is present and is a string for which `store.Search` returns an error wrapping `store.ErrCursor` (a string that is not the `Next` of some page, `page2` and a page's `Next` with one character changed included) MUST return a refusal with `cursor is not one search issued`.
- R-C4EY-KPCK: A `tools/call` of `search` on a tools server over `s` whose `arguments` hold no offence appkit's argument decoding finds and that R-C0R9-FE4H, R-C1Z5-T5V6 and R-C372-6XLV do not refuse MUST return a success result with the object whose first member is `records`, an array holding the record object of each `Record` of the `Page` that `s.Search(ctx, <filter>, <limit>, <cursor>)` returns at the time of the call, in order, and whose only other member, present exactly when that `Page`'s `Next` is not empty, is `cursor`, the JSON string of that `Next`; where `<filter>` is the search filter of the arguments, `<limit>` the `limit` argument or 50 when absent, and `<cursor>` the `cursor` argument as a `store.Cursor` or the empty `Cursor` when absent, whatever the other arguments are when a `cursor` is given.
- R-C5MU-YH39: The `records` of a `search` success result MUST be in the search order `D05-store` defines: a record whose `time` is later before one whose `time` is earlier, and of two records with the same `time` the one delivered later before the one delivered earlier, so that `trace` of one request answers two such records in the opposite order.
- R-C6UR-C8TY: When a `tools/call` of `search` returns a success result holding `cursor`, a later `tools/call` of `search` on the same tools server with the same `since`, `until`, `services`, `events`, `user`, `request_id`, `attrs` and `limit` arguments and that `cursor` MUST return a success result whose `records` are the records that follow the first result's last record in the search order among those matching the search filter, up to `limit` of them, and the sequence of such calls, each given the previous result's `cursor`, until a result without one, MUST together answer every record matching the search filter exactly once, each page holding `limit` records except the last, when the trail does not change between the calls.
- R-C82N-Q0KN: A `tools/call` of `search` on a tools server whose `arguments` hold no offence and that no requirement above refuses, and whose search filter no record matches, a `since` that is not before `until` and an `attrs` member whose value is `null`, an object or an array included, MUST return a success result with exactly `{"records":[]}`.
- R-YRW2-2166: A `tools/call` of `search` on a tools server over `s` whose `attrs` argument is `{"<k>":<v>}` with `<v>` a JSON number MUST answer a record whose `Attrs` has the member `<k>` with a number whose JSON text is the text `json.Marshal` gives for `<v>`, as R-JV3T-CFV2 compares them, and MUST NOT answer one whose member `<k>` is a string, so that `{"status":500}` answers a record ingested with `"status":500` and not one ingested with `"status":"500"`, and `{"status":"500"}` the reverse.
