# D07-search

`search` lists the records that match a filter, newest first, a page at a time. The trail is a list every service adds to, so `search` pages as the suite's listing rule asks (`shape/`, Listing), on the contract of appkit's `paging` package (appkit's D25), which this document cites and never restates; `dummy`'s `list_widgets` is the precedent `shape/` names. Its list entry, schemas and annotations are `D06-mcp`'s; this document is its call: how the arguments become the store's filter, which arguments it refuses and in what words, and what a page holds. It reads the trail through `store.Search` (`D05-store`) and nothing else.

## From arguments to a filter

Every argument is optional and the ones given combine. `since` and `until` are RFC 3339 times, read with the standard library's `time.Parse` and the `time.RFC3339` layout, which accepts a fractional second and any offset, so a time written in another offset means the same instant as in UTC; `since` is inclusive and `until` exclusive, so hour-wide ranges tile without overlap, and a `since` not before `until` is a range holding no instant, which matches nothing and is not an error. `services` and `events` each match any of the names given. `user` and `request_id` match exactly, the empty string included, which is why they are pointers in the input type. `attrs` arrives as the open object appkit decodes for a `json.RawMessage`, and the tool reads its members itself with the same rule the ingest handler reads an event's attributes by: a string is a string, `true` and `false` are booleans, and a number is an integer when it parses as one and a float otherwise, so that `500` written by a model and `500` written by a sibling compare equal while `"500"` does not. A member whose value is none of those, `null` or a nested value, can match no record, since no record carries one, and the filter matches nothing; a member name repeated in the object is read as the last of its values, as `encoding/json` reads a repeated name. A top-level member given as JSON `null`, where appkit's decoding accepts one, is read as left out, for `search` and `count` alike: `"user":null` says no more than an absent `user`, and is never a search for the records that have no user.

## Refusals

A tool that cannot do what it was asked returns an error from its handler, which appkit answers as an `isError` result with one text block (`D06-mcp`). `search` has four, checked in this order and the first one found answered: `since` that is not an RFC 3339 time, `until` that is not one, a `limit` that `paging.Window` refuses, and a `page` that `paging.Token{Tool: "search"}.Decode` refuses. The two times are refusal constants of `internal/tools` (`D06-mcp`), formatted with the value exactly as given; the limit is refused with the text of the error `Window` returns, which names the range and the value, and the page with `paging.BadPage`. A page is only what a search answered: a made-up string, one damaged in transit and one another tool issued are refused rather than guessed at. Both the limit and the page are refused before the store is read, so the refusal is the same while the trail cannot be read: arguments that can never succeed are not `tools.ReadFailed`, which would invite a retry. `limit` left out, or `null`, is `paging.DefaultLimit`, so the default moves from the 50 `search` had to the suite's 25; the largest is `paging.MaxLimit`, the 500 it was. A `limit` given is checked as given, so `0` is refused rather than taken as the default. The order puts `limit` before `page`, as the input schema lists them, where `cursor` stood after `limit`, so the page size is read first, as appkit's D25 has it.

## The page

A page is the first page-size records matching the filter in the store's search order: newest first, and among records with one time the reverse of the order telemetry received them, so a search reads the trail backwards exactly and `trace` reads the same records the other way round. The result is `{"records":[...]}` and, when at least one more matching record follows the page, `"next":"<token>"`; the last page has no `next` member, which is how the agent knows it has everything. The token is `paging.Token{Tool: "search"}` over two `int64` fields, in the order the search sorts by: the `ts` of the page's last record, its time in microseconds, then its `id`, which is the store's `Next` (`D05-store`). An absent, `null` or empty `page` is the first page; a `page` handed back reads the matching records after that position. Passing `next` back as `page` with the same filters answers the next page, and the pages together are every matching record once, none on two pages and none skipped. A token does not bind its filters (appkit's D25), so one sent with other filters is not refused: it continues from the same position under the filters it came with. Only retained records are found: a record the sweep has removed is on no page, and a token naming it still continues from its place. Paging adds nothing to the trail: `tool.called` carries no arguments, so a token appears in no event and no log line. No page of telemetry's lists records, so no asset changes.

The store's own cursor, its encoding, its `ErrCursor` and the tool's `BadCursor` and `BadLimit` are gone: the opaque token is appkit's, and the store takes and answers a plain `store.Position`. A checksum rather than a key still suffices, since a forged token only skips to a position of the caller's choosing in a trail the caller may read in full.

## Consumer tasks

A model searches by request id with `{"request_id":"9b2e4d6f8a1c3e5b7d9f0a2c4e6b8d1f"}`; by user with `{"user":"u_1e9b4d07"}`; by names and a bound with `{"services":["mcp"],"events":["sibling.called","tool.called"],"until":"2026-10-02T14:30:00Z"}`; by an attribute's value with `{"attrs":{"status":500}}`; a time range with `{"since":"2026-10-02T13:00:00Z","until":"2026-10-02T14:00:00Z"}`; and pages with `{"until":"2026-10-02T14:30:00Z","limit":10}`, then the same with `"page":"<next>"` from each answer until one has no `next`. It is refused for a `since` of `yesterday`, a `limit` of `0` with the text `paging.Window` gives, or a made-up `page` with `paging.BadPage`.

An agent reading every `tool.called` record of the gateway, today and as proposed:

- Today: `search` with `{"services":["mcp"],"events":["tool.called"]}` answers up to 50 records and, when more match, `cursor`; the agent calls again with the same filters and `"cursor":<that value>`, and stops when an answer has no `cursor`.
- Proposed: the same call answers up to `paging.DefaultLimit` records and, when more follow, `next`; the agent calls again with the same filters and `"page":<that value>`, `"limit"` too if it wants other than the default, and stops when an answer has no `next`.

A test fills a store through `Deliver` with records of known times, some sharing a time, registers the tools on a server over a capturing writer and calls `search` through `mcp.Client`, asserting the `records` array of `structuredContent` against the record objects it expects in order, the presence and absence of `next` and its value against `paging.Token{Tool: "search"}.Encode` of the store's `Next`, each refusal's text against the refusal constant or the `paging` text it names, the limit and page refusals again with `SetFailing(true)` in force, and the descriptions of `limit`, `page` and `next` in `tools/list` against the `paging` constants.

## REQUIREMENTS

- R-CAKF-ZA46: telemetry's design defines the **search filter** of a `tools/call`'s arguments as the `store.Filter` whose `Since` and `Until` are nil when `since` and `until` are absent and otherwise point to the times `time.Parse(time.RFC3339, <value>)` returns for them; whose `Services` and `Events` are the `services` and `events` arrays as given, nil when absent; whose `User` and `RequestID` are nil when `user` and `request_id` are absent and otherwise point to their strings as given; and whose `Attrs` is nil when `attrs` is absent and otherwise holds one entry per distinct member name of the `attrs` object, the last value given for a repeated name, a string member as a `string`, `true` and `false` as a `bool`, a number as the ingest handler of appkit's `telemetry` package decodes an attribute number (`int64`, `uint64` or `float64`, negative zero as `float64`), and any other member value (`null`, an object, an array, or a number that decoding fails for, such as `1e400`) as a value that is not a valid attribute value; every requirement of telemetry's design that names the search filter MUST denote this.
- R-BBES-HOSE: A `tools/call` of `search` or `count` on a tools server whose `arguments` hold no offence appkit's argument decoding finds and hold one or more top-level members whose value is JSON `null` MUST be answered, on the same trail, exactly as the same call with those members left out, so that `{"user":null}` is answered as `{}` and never as a search for the records that have no user; a `null` inside the `attrs` object is not a top-level member and is read as the search filter states.
- R-9T3P-0WHP: A `tools/call` of `search` on a tools server whose `arguments` hold no offence appkit's argument decoding finds and whose `since` argument is a string `v` for which `time.Parse(time.RFC3339, v)` returns a non-nil error MUST return a refusal with `fmt.Sprintf(tools.BadSince, v)`, and one whose `since` is absent or parses and whose `until` argument is a string `v` that does not parse MUST return a refusal with `fmt.Sprintf(tools.BadUntil, v)`, where `v` is the value exactly as given.
- R-IE9U-ES89: A `tools/call` of `search` on a tools server whose `arguments` hold no offence appkit's argument decoding finds, whose `since` and `until` are absent or parse and whose `limit` argument is present and is an integer `l` less than 1 or greater than `paging.MaxLimit` MUST return a refusal with exactly the `Error()` of the error that `paging.Window` returns when passed a pointer to `l`, whether or not the trail can be read, `SetFailing(true)` being in force on the store's handle included, so that `0` and `paging.MaxLimit` plus one are both refused.
- R-IFHQ-SJYY: A `tools/call` of `search` on a tools server whose `arguments` hold no offence appkit's argument decoding finds, whose `since` and `until` are absent or parse, whose `limit` is absent or R-IE9U-ES89 does not refuse it, and whose `page` argument is a non-empty string `p` for which `paging.Token{Tool: "search"}.Decode(p, &ts, &id)`, `ts` and `id` being `int64` variables, returns a non-nil error MUST return a refusal with exactly the value of `paging.BadPage`, whether or not the trail can be read, `SetFailing(true)` being in force on the store's handle included; so that `page2`, a token `paging.Token{Tool: "search"}.Encode` returned for one `int64` or for three, and a token `Encode` returned for two `int64` values under a `paging.Token` whose `Tool` is another tool's name are refused, the last unless the two names give it the same checksum.
- R-IGPN-6BPN: A `tools/call` of `search` on a tools server over `s` whose `arguments` hold no offence appkit's argument decoding finds and that R-9T3P-0WHP, R-IE9U-ES89 and R-IFHQ-SJYY do not refuse MUST return a success result with the object whose first member is `records`, an array holding the record object of each `Record` of the `Page` that `s.Search(ctx, <filter>, <limit>, <after>)` returns at the time of the call, in order, and whose only other member, present exactly when that `Page`'s `Next` is not nil, is `next`, the JSON string `paging.Token{Tool: "search"}.Encode(<n>.TS, <n>.ID)`, `<n>` being that `Next`; where `<filter>` is the search filter of the arguments, `<limit>` the `int` that `paging.Window` returns for a pointer to the `limit` argument, or for nil when it is absent, and `<after>` nil when the `page` argument is absent or empty and otherwise a pointer to the `store.Position` whose `TS` and `ID` are the first and the second `int64` that `paging.Token{Tool: "search"}.Decode` stores for it, whatever the other arguments are when a `page` is given.
