# D12-telemetry-writer

A service records events through one `telemetry.Writer`, built at start-up with `telemetry.New` from a `Config` naming the service, its release version, the sink events go to, and the writer standard-error lines go to (normally `os.Stderr`). The app hands the writer to everything that records for it: the request middleware and sibling client (D14) and the `mcp` server (D07). The service's own handlers call `Emit` with the request's context, so their domain events carry the request id and the user.

## Off the request path

`Emit` forms the event, queues it, and returns; it never waits for delivery. The event's time comes from the config's clock at the moment of the call, in UTC and truncated to the microsecond. The request id and the user come from the context: `identity.FromContext` (D06) gives the `Caller`, whose `RequestID` and `UserID` fill the envelope, and both are empty when the context carries none. The attributes are copied at the call, converted to their basic forms (D11), so the caller may reuse or change its map at once.

An event that breaks D11's rules (a bad name, a bad key, a value that is not a scalar) can never be delivered, since telemetry's ingest would refuse it. It is a bug in the emitting service, so it goes straight to standard error as a `malformed event` line and never reaches the sink. Its JSON shows every offending value as `null`, never the value itself: a value that is not a scalar may hold exactly the data the metadata rule keeps out of the trail.

## One queue, one sender

The writer has one bounded queue of `QueueCapacity` events and one sender, which hands events to the sink one at a time, in the order they were emitted, one event per delivery and never two deliveries at once. Each delivery gets up to `Attempts` attempts. An attempt that fails is followed by a pause of `RetryBackoff` before the second attempt and twice that before the third. An attempt is bounded by `AttemptTimeout` through its context; the context is the writer's own, never the emitting request's, so a request that has already finished cannot cancel the delivery of its own `request.finished`. A sink that answers with an error wrapping `ErrRejected` says the event itself is at fault (telemetry answered 4xx, D13), so the writer does not retry it. An event whose body is longer than `MaxEventBytes` (D13) is one of these: telemetry answers it 413, so it is not retried and goes to standard error as an `undelivered event` line.

An event that cannot be delivered (every attempt failed, or the sink rejected it) goes to standard error as one `undelivered event` line holding the event's JSON exactly as it would have been posted, so nothing in the trail is lost without trace. When the queue is full, a new event goes to standard error the same way at once, and `Emit` still returns without blocking. The numbers are small on purpose: one host, a socket systemd holds open through a restart, and a few users, so a delivery that fails three times in 150 milliseconds is failing for a reason a retry will not fix.

Time, waiting, and randomness are injected. `Config.Now` is the clock, `Config.Sleep` the pause between attempts, and `Config.Rand` the random source the request middleware mints request ids from (D14); each defaults to the real one (`time.Now`, a real pause, `crypto/rand.Reader`). `Writer.Now` reads the clock the way `Emit` does, so everything built on the writer measures a duration with it: the middleware and sibling client (D14) and the `mcp` server's `tool.called` (D08). A test supplies a `Sleep` that records the pause and returns at once, so retry and backoff are observed without sleeping; a clock it advances by hand, so a recorded duration is an exact value; a reader of known bytes, so a minted id is known in advance; and calls `Flush` to wait until every event emitted so far is delivered or written out.

## Lifecycle

The writer starts its sender in `New`. The app calls `Ready` once it is serving, which records `service.started` with the configured version: a new version in a start event is the visible effect of a deploy. On a stop signal the app drains its HTTP server first, so every request finishes and records its `request.finished`, and then, inside the same drain window, calls `Shutdown` with the reason and the drain window's context. `Shutdown` queues `service.stopping` with the reason, even when the queue is full, as the last event the sink will see (should the clock read a year that no event can carry, it goes to standard error as a `malformed event` line instead and nothing is queued); it then waits until everything queued is delivered or written out. When the context ends first, every event not yet delivered, the one in flight included, goes to standard error in queue order and `Shutdown` returns at once. From then on the writer begins no new delivery: at most one call it had already set out to make may still reach the sink or the pause, with a context that is already done, and nothing more is written for it. An event emitted after `Shutdown` began is never delivered and goes to standard error.

The writer's states, then, are new, ready (after `Ready`), stopping (once `Shutdown` begins), and stopped (once it returns); `Shutdown` may come straight from new. `Ready` after the first call, or after `Shutdown`, does nothing; a second `Shutdown` records nothing.

## Sinks

The writer targets the `Sink` interface. A nil `Config.Sink` means the socket sink of D13, which posts to the telemetry service, and is what every ordinary service uses. The telemetry service supplies its own sink that stores an event directly, so its own events never loop through its socket. A test supplies a `*telemetry.Capture`, which records every event it receives in order and is ready to use as its zero value: a service's test builds its writer on one, drives the service, calls `Flush`, and asserts on `Capture.Events`.

## Safety

Every method of `Writer` and `Capture` is safe to call from many goroutines at once. The writer never writes to `Config.Stderr` from two goroutines at once, so a test may hand it a `bytes.Buffer`, and writes each line in a single `Write` call, so lines from concurrent services sharing a journal never interleave. A nil `Config.Stderr` discards the lines. `Emit` never panics, whatever name and attributes it is handed.

## REQUIREMENTS

- R-VJ55-LGRZ: Package `telemetry` MUST export `type Sink interface { Deliver(ctx context.Context, e Event) error }`, where `context` is the standard library's `context`.
- R-VKD1-Z8IO: Package `telemetry` MUST export `var ErrRejected error`, non-nil.
- R-ISVO-ANR1: Package `telemetry` MUST export `type Config struct { Service, Version string; Sink Sink; Stderr io.Writer; Now func() time.Time; Sleep func(ctx context.Context, d time.Duration); Rand io.Reader }`, with exactly these fields in this order, where `io` is the standard library's `io`.
- R-VMSU-QS02: Package `telemetry` MUST export type `Writer` and `func New(cfg Config) *Writer`.
- R-VO0R-4JQR: Package `telemetry` MUST export the methods `func (w *Writer) Emit(ctx context.Context, event string, attrs Attrs)`, `func (w *Writer) Ready()`, `func (w *Writer) Shutdown(ctx context.Context, reason string)`, and `func (w *Writer) Flush(ctx context.Context) error`.
- R-VP8N-IBHG: Package `telemetry` MUST export the constants `QueueCapacity = 1024`, `Attempts = 3`, `RetryBackoff = 50 * time.Millisecond`, and `AttemptTimeout = time.Second`, the first two untyped integer constants and the last two of type `time.Duration`.
- R-VQGJ-W385: Package `telemetry` MUST export type `Capture` and the methods `func (c *Capture) Deliver(ctx context.Context, e Event) error` and `func (c *Capture) Events() []Event`, so `*Capture` implements `Sink`.
- R-VROG-9UYU: `telemetry.New` MUST panic, with a message that says the service name is empty, when `cfg.Service` is the empty string, and MUST otherwise return a non-nil `*Writer`.
- R-VSWC-NMPJ: When `cfg.Sink` is nil, the `Writer` `telemetry.New` returns MUST deliver to a `Sink` that behaves as the one `telemetry.NewSocketSink` returns.
- R-IWJD-FYZ4: When `cfg.Rand` is nil, the `Writer`'s random source MUST be `crypto/rand.Reader` (the standard library's `crypto/rand`); otherwise it MUST be `cfg.Rand`, and the `Writer` and everything built on it MUST NOT read from that source from two goroutines at once.
- R-IYZ6-7IGI: Package `telemetry` MUST export the method `func (w *Writer) Now() time.Time`.
- R-J1EY-Z1XW: Each `Writer.Now` call MUST read the `Writer`'s clock once (`cfg.Now`, or the standard library's `time.Now` when `cfg.Now` is nil) and return that time converted to UTC and truncated with `Time.Truncate(time.Microsecond)`.
- R-VU49-1EG8: When `cfg.Now` is nil, the `Writer` MUST take each event's time from the standard library's `time.Now`; when `cfg.Sleep` is nil, each pause between attempts MUST last the stated duration or until the pause's context is done, whichever comes first.
- R-VVC5-F66X: The `Event` the sink receives for an `Emit` call, and the event R-W07Q-Y95P writes out, MUST have `Time` equal to `cfg.Now()` read during the call, converted to UTC and truncated to a whole microsecond with `Time.Truncate(time.Microsecond)`; `Service` equal to `cfg.Service`; `Name` equal to `event`; `RequestID` and `User` equal to the `RequestID` and `UserID` of the `Caller` that `identity.FromContext(ctx)` returns, both empty when it returns false; and `Attrs` a non-nil map holding exactly the keys of `attrs`, each with the basic form of its value.
- R-VWK1-SXXM: Changing, adding, or deleting entries of the `attrs` map after `Writer.Emit` returns MUST NOT change the `Event` the sink receives or the line written for it.
- R-VXRY-6POB: `Writer.Emit` MUST return without waiting for any `Deliver` call to begin or return, so it returns while the sink is blocked in a `Deliver` call.
- R-W07Q-Y95P: When `event` is not a valid event name, a key of `attrs` is not a valid attribute key, a value of `attrs` is not a valid attribute value, or the year of the time R-VVC5-F66X states is below 0 or above 9999, `Writer.Emit` MUST NOT hand the event to the sink, and MUST, before it returns, write to `cfg.Stderr` in a single `Write` call exactly `cfg.Service`, then `: malformed event: `, then the bytes `json.Marshal` returns for the value R-V22K-8OE9 describes, formed from the event R-VVC5-F66X states with `nil` in place of the basic form of each value that is not a valid attribute value, then LF.
- R-W1FN-C0WE: `Writer.Emit` MUST NOT panic, whatever `event` and `attrs` hold.
- R-W2NJ-PSN3: The `Writer` MUST call its sink's `Deliver` with the events it queues in the order it queued them, so events queued by `Emit`, `Ready`, and `Shutdown` calls that one goroutine makes in sequence reach the sink in that sequence, MUST NOT call `Deliver` concurrently, and MUST NOT call `Deliver` for an event until every attempt for each event queued before it has returned.
- R-E16G-QBY3: When `Deliver` returns a nil error, the `Writer` MUST NOT call `Deliver` for that event again and MUST write nothing to `cfg.Stderr` for it other than an R-W7J5-8VLV line R-WEUJ-JI21 wrote for it.
- R-E2ED-43OS: When `Deliver` returns a non-nil error for which `errors.Is(err, telemetry.ErrRejected)` is false, the `Writer` MUST, unless R-WEUJ-JI21 has applied, call `Deliver` again for the same event, up to `Attempts` calls in all for that event, and before the attempt numbered n + 1 (counting from 1) MUST call `cfg.Sleep` exactly once with the duration `RetryBackoff << (n - 1)`, so the pauses are 50 and 100 milliseconds; it MUST NOT call `cfg.Sleep` after an attempt that returns a nil error or that is the `Attempts`-th.
- R-W6B8-V3V6: When `Deliver` returns an error for which `errors.Is(err, telemetry.ErrRejected)` is true, the `Writer` MUST NOT call `Deliver` for that event again and MUST NOT call `cfg.Sleep` for it.
- R-W7J5-8VLV: For each valid event that is rejected as R-W6B8-V3V6 states, whose `Attempts`-th attempt returns a non-nil error, that R-W9YY-0F39 or R-WDMN-5QBC keeps from the queue, or that R-WEUJ-JI21 writes out, the `Writer` MUST write to `cfg.Stderr`, in a single `Write` call, exactly one line: `cfg.Service`, then `: undelivered event: `, then the bytes `Event.MarshalJSON` returns for the event, then LF.
- R-LOYL-PZYW: The context the `Writer` passes to each `Deliver` call MUST have a deadline no later than `AttemptTimeout` after that call began, as the standard library's `time.Now` measures it, MUST NOT be done because the context given to the `Emit` that formed the event is canceled, and MUST be done once the context given to the first `Shutdown` call is done; when that `Shutdown` context is done before a `Deliver` call begins, that call's context MUST already be done as the call begins, so `ctx.Err()` read on entry to `Deliver` is non-nil, including the `Deliver` call for `service.stopping` on a `Writer` with no event queued or in progress whose first `Shutdown` call is given a context that is already done; the context passed to each `cfg.Sleep` call MUST be done once the context given to the first `Shutdown` call is done.
- R-W9YY-0F39: When `Writer.Emit` is called for a valid event while the `Writer` holds `QueueCapacity` queued events whose first `Deliver` call has not begun, the `Writer` MUST NOT queue the event and MUST write its R-W7J5-8VLV line before `Emit` returns.
- R-WB6U-E6TY: The first `Writer.Ready` call, when no `Shutdown` call has begun, MUST behave as the call `w.Emit(ctx, "service.started", telemetry.Attrs{"version": cfg.Version})` with a `ctx` for which `identity.FromContext` returns false; every other `Ready` call MUST emit nothing and write nothing.
- R-DZYK-CK7E: The first `Writer.Shutdown` call MUST form an event named `service.stopping` as `Emit` would form it from the call's `ctx` and the attributes `{"reason": reason}`; when that event is valid, it MUST queue it, even when R-W9YY-0F39's queue is full, and when it is not (R-W07Q-Y95P applies to it, as when the year of `cfg.Now()` is below 0 or above 9999), it MUST write that event's R-W07Q-Y95P line and queue no event. The `Writer` MUST NOT hand any event to the sink after `service.stopping`; every later `Shutdown` call MUST queue no event.
- R-WDMN-5QBC: A valid event `Writer.Emit` is called for after the first `Shutdown` call began MUST NOT be queued, and its R-W7J5-8VLV line MUST be written before `Emit` returns.
- R-WEUJ-JI21: The first `Writer.Shutdown` call MUST return once every queued event, `service.stopping` included, has been delivered or written to `cfg.Stderr`, and not before, unless `ctx` is done first; when `ctx` is done first, it MUST write the R-W7J5-8VLV line of every queued event not yet delivered, the one whose `Deliver` call is in progress included even if that call later returns nil, in queue order, and return without waiting for a `Deliver` call in progress to return.
- R-E4U5-VN66: After the first `Writer.Shutdown` call has returned, the `Writer` MUST begin at most one more call to `Deliver` or `cfg.Sleep`, MUST give that call a context that is already done, and, when it is a `Deliver` call, MUST make it for the first event whose R-W7J5-8VLV line that `Shutdown` call wrote; and the `Writer` MUST NOT call `cfg.Stderr`'s `Write` except for the lines R-W07Q-Y95P and R-WDMN-5QBC state for later `Emit` calls.
- R-WII8-OTA4: `Writer.Flush` MUST return nil once every event queued before the call has been delivered or written to `cfg.Stderr`, and MUST return `ctx.Err()` without waiting further when `ctx` is done before that; it MUST NOT prevent the `Writer` from queuing or delivering events.
- R-WJQ5-2L0T: The `Writer` MUST NOT call `cfg.Stderr`'s `Write` from two goroutines at once, and MUST write nothing and not panic when `cfg.Stderr` is nil.
- R-DAQ0-H1OR: Everything the `Writer` writes to `cfg.Stderr`, whether from `New`, `Emit`, `Ready`, `Flush`, `Shutdown`, or its sender, MUST be a line of the form R-W07Q-Y95P states or a line of the form R-W7J5-8VLV states, and nothing else.
