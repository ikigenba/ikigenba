# D09-mcp-schema

A tool's author writes Go types; the model sees JSON Schema. This document is the one rule that turns the `In` and `Out` types of a registration (D08) into the `inputSchema` and `outputSchema` a `tools/list` result carries, decides which `arguments` a `tools/call` accepts for `In`, and fixes how an `Out` value is written back. The same rule serves both directions, so what the schema promises and what the server accepts or returns never drift apart. There is no exported derivation function: a consumer meets these rules only through `tools/list` and `tools/call`, and that is how they are tested.

## Why a small subset

Schemas without a `$schema` member are read as JSON Schema 2020-12 by the 2025-11-25 and 2026-07-28 revisions ("When a schema does not include a `$schema` field, it defaults to JSON Schema 2020-12", S1125/basic#json-schema-usage and S26/basic), and 2025-06-18 states no dialect, so the server emits no `$schema` and uses only keywords that read the same everywhere: `type`, `properties`, `required`, `additionalProperties`, `items`, `enum`, `minimum`, and `description`. Every revision requires `type: "object"` at the root of `inputSchema`, and 2025-06-18 and 2025-11-25 require it of `outputSchema` too (TS0618, TS1125, TS26 `interface Tool`), so both `In` and `Out` must be structs. Objects are closed with `additionalProperties: false`, the form 2025-11-25 and 2026 recommend for a tool without parameters (S1125 and S26, server/tools#tool); a struct with no properties emits exactly that recommended form.

A Go type the subset cannot describe exactly — a map, an interface, a type with its own JSON or text marshalling, an embedded field whose promotion rules are subtle — panics at registration rather than producing a schema that lies. The one exception is `json.RawMessage` as a struct field: it stands for "any JSON object", schema `{"type":"object"}`, carried byte-for-byte in both directions. The gateway needs it to pass a backend's arguments and schemas through untouched. It is never the whole `In` or `Out`, and never a slice element or pointer target. Pointers mark optional values; a `required` tag option marks a member that must be present. In `Out`, a required pointer could be nil and break the promise "Servers MUST provide structured results that conform to this schema" (server/tools#output-schema, all revisions), so it panics too.

Property names are restricted to ASCII identifiers. That keeps every name valid for the stricter clients models run behind and keeps the argument error paths of D08 unambiguous.

## Acceptance follows the schema

Decoding `arguments` is validation against the derived schema plus the limits of the Go type the schema stands for. Every violation is an offence, and every offence is reported, not just the first (D08 fixes the text). An integer is any JSON number with a zero fractional part, in any notation, because that is what `"type": "integer"` means in JSON Schema 2020-12 (Validation, section 6.1.1); a compliant client may send `3.0` and is not refused. A Go integer kind narrower than the JSON number is a range limit the schema does not state for signed kinds, and is reported with the bounds so a model can correct it.

One leniency is deliberate and recorded: a pointer field accepts JSON `null` as nil although its schema is the element's schema, as agreed in the interface brief. A client that validates against the schema never sends it; one that does is not punished for it.

## Writing Out

An `Out` value is written as the object its schema describes: members in field order, non-pointer members always present, nil pointers omitted, nil slices written as empty arrays so `type: "array"` holds. A value the schema cannot carry — a non-finite float, or an enum-typed string outside its list — makes the value unencodable, which D08 turns into a generic error result and a log line.

## REQUIREMENTS

- R-M2F0-08NM: `AddTool` MUST panic, as D08 states for registration panics, when `In` or `Out` is not a struct type, and `AddRawTool` MUST panic when `In` is not a struct type.
- R-M3MW-E0EB: The schema of a struct type MUST be a JSON object with, in this order, `type` equal to `"object"`; `properties`, an object holding one member per property of the struct, present only when the struct has at least one property; `required`, an array of the names of the properties whose field carries the `required` tag option, in property order, present only when that array is non-empty; and `additionalProperties` equal to `false`.
- R-M4US-RS50: The properties of a struct MUST be its exported, non-embedded fields other than those whose `json` tag is exactly `-`, in field declaration order, each named by the name part (the text before the first comma) of its `json` tag; unexported fields MUST contribute nothing.
- R-M62P-5JVP: `AddTool` and `AddRawTool` MUST panic when a property's field has no `json` tag or an empty name part, when a property name does not match `^[A-Za-z_][A-Za-z0-9_]*$`, or when two properties of one struct have the same name.
- R-M7AL-JBME: `AddTool` and `AddRawTool` MUST panic when a field's `json` tag carries any option other than `required`.
- R-M8IH-X3D3: When a property's field carries a non-empty `description` struct tag, the property's schema MUST end with a member `description` whose value is the tag's value unaltered; otherwise the property's schema MUST have no `description` member.
- R-M9QE-AV3S: The schema of a type of kind `string` that does not implement `Enumerator` MUST be `{"type":"string"}`, of kind `bool` `{"type":"boolean"}`, of kind `int`, `int8`, `int16`, `int32`, or `int64` `{"type":"integer"}`, of kind `uint`, `uint8`, `uint16`, `uint32`, or `uint64` `{"type":"integer","minimum":0}`, and of kind `float64` `{"type":"number"}`.
- R-MAYA-OMUH: The schema of a type `T` of kind `string` where `T` or `*T` implements `Enumerator` MUST be `{"type":"string","enum":[...]}`, whose `enum` holds the values `Enum` returns on the zero value of `T` at registration, in that order.
- R-MC67-2EL6: `AddTool` and `AddRawTool` MUST panic when, for a type `T` of kind `string` where `T` or `*T` implements `Enumerator`, `Enum` returns no values or the same value twice, and when `T` or `*T` implements `Enumerator` for a non-pointer type `T` whose kind is not `string`.
- R-GRZU-AE8W: The schema of a slice type other than `json.RawMessage` MUST be `{"type":"array","items":<element schema>}`, where `<element schema>` is the schema of the element type, and `AddTool` and `AddRawTool` MUST panic for any other slice whose element kind is `uint8`.
- R-MFTW-7PT9: The schema of a struct-typed field MUST be the schema of that struct type, and a struct type nested in `In` or `Out` MUST follow the same rules as the top-level struct.
- R-MH1S-LHJY: The schema of a field of type `*T` MUST be the schema of `T`, and `AddTool` and `AddRawTool` MUST panic for a pointer type anywhere other than as the type of a struct field, and for a pointer to a pointer.
- R-GY3C-78YD: The schema of a struct field of type `json.RawMessage` MUST be `{"type":"object"}` (with no `additionalProperties` member), and `AddTool` and `AddRawTool` MUST panic when `json.RawMessage` appears anywhere other than as the type of a struct field, including as a slice element type and as the type a pointer points to.
- R-GZB8-L0P2: A JSON object received for a `json.RawMessage` field MUST be accepted whatever its members, and any other JSON value, `null` included, MUST be a type-mismatch offence against `object`.
- R-MI9O-Z9AN: `AddTool` MUST panic when a field of type `*T` anywhere in `Out` carries the `required` tag option.
- R-MJHL-D11C: `AddTool` and `AddRawTool` MUST panic when `In` or `Out` contains a type of kind `map`, `interface`, `array`, `float32`, `complex64`, `complex128`, `chan`, `func`, `uintptr`, or `unsafe.Pointer`.
- R-GT7Q-O5ZL: `AddTool` and `AddRawTool` MUST panic when `In` or `Out` contains a type `T` other than `json.RawMessage` where `T` or `*T` implements `json.Marshaler`, `json.Unmarshaler`, `encoding.TextMarshaler`, or `encoding.TextUnmarshaler`.
- R-MLXE-4KIQ: `AddTool` and `AddRawTool` MUST panic when a struct in `In` or `Out` has an embedded (anonymous) field, whatever its tag.
- R-MN5A-IC9F: `AddTool` and `AddRawTool` MUST panic when `In` or `Out` contains a struct type that contains itself, directly or through other types.
- R-MOD6-W404: A derived schema MUST contain no members other than those these requirements state, and in particular no `$schema` member.
- R-MPL3-9VQT: Every schema member these requirements list in a given order MUST appear in that order, with `description` always last.
- R-MQSZ-NNHI: A JSON value whose JSON type does not match its schema's `type` — `null` for anything other than a field of pointer type, any number for `integer` or `number` being a match — MUST be a type-mismatch offence.
- R-MS0W-1F87: A member of an arguments object that names no property of its schema MUST be an unknown-member offence, once per occurrence.
- R-MT8S-F6YW: A property marked required whose member is absent from an arguments object MUST be a missing-required-member offence.
- R-MUGO-SYPL: A property whose member appears more than once in an arguments object MUST be a single duplicate-member offence, and none of that member's values MUST be validated further.
- R-MVOL-6QGA: A JSON number received for an `integer` schema MUST be accepted exactly when its value has a zero fractional part, whatever its notation (so `3`, `3.0`, and `3e0` are the integer 3); otherwise it MUST be a non-integral-number offence.
- R-MWWH-KI6Z: An integral JSON number outside the range of the field's Go integer kind MUST be an integer-range offence.
- R-MY4D-Y9XO: A JSON number received for a `float64` whose magnitude exceeds the largest finite `float64` MUST be a float-range offence; any other JSON number MUST be accepted as the nearest `float64`.
- R-N0K6-PTF2: A JSON string received for an `Enumerator` type that is not one of the values in its schema's `enum` MUST be an enum offence.
- R-N1S3-3L5R: JSON `null` received for a field of type `*T` MUST be accepted, whether or not the field is required, and decoded as a nil pointer.
- R-N2ZZ-HCWG: Every offence in an arguments value MUST be found, including offences in every element of an array and in every member of nested objects, except within a duplicated member's values.
- R-GUFN-1XQA: When the arguments hold no offence, the handler's `In` MUST hold, for every property whose member is present, the member's value — strings unaltered, integers and numbers as received, arrays as slices of the same length and order, objects for a struct-typed field decoded by the same rule, objects for a `json.RawMessage` field as its bytes unaltered — and for every absent property the field's zero value, a nil pointer for an absent or `null` pointer field and a nil `json.RawMessage` for an absent `json.RawMessage` field.
- R-GVNJ-FPGZ: The JSON encoding of an `Out` value MUST be an object with, in property order, one member per property of its struct type, where a non-pointer field other than a `json.RawMessage` is always present, a nil pointer field is absent, a non-nil pointer field is encoded as the value it points to, a nil slice other than a `json.RawMessage` is encoded as `[]`, a non-nil `json.RawMessage` is written as its bytes unaltered, a nil `json.RawMessage` in a field without the `required` tag option is absent, and nested structs are encoded by the same rule.
- R-N6NO-MO4J: In the JSON encoding of an `Out` value, a string MUST be encoded with each invalid UTF-8 byte replaced by U+FFFD, a `bool` as `true` or `false`, an integer kind as a JSON integer of the same value, and a `float64` as a JSON number that parses back to the same `float64`.
- R-GWVF-TH7O: An `Out` value MUST be unencodable when it contains a `float64` that is NaN or infinite, a value of an `Enumerator` type that is not one of the values in its schema's `enum`, a nil `json.RawMessage` in a field carrying the `required` tag option, or a non-nil `json.RawMessage` that is not exactly one JSON object.
