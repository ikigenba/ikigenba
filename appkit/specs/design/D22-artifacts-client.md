# D22-artifacts-client

Package `artifacts` is the client a service uses to keep and fetch binary files in the artifacts app, the suite's store for files agents and services share. A connector that moves a file between the suite and an outside service streams its bytes through here rather than through an agent's context: it asks what an artifact is, fetches its bytes as a stream, and puts a stream of bytes at a path with a content type and, for scratch files, an expiry. A service that keeps references to artifacts by path also asks for an artifact's full metadata, its id included, to link to the artifact's page. The client speaks artifacts' published files contract over the app's unix socket, `PUT`, `GET` and `HEAD` of `/files/<path>`, and calls one of its MCP tools, `show`, at `/mcp` on the same socket. It does nothing else: listing, deleting and the other MCP tools stay with artifacts and the agents that call it.

## The client

A `Client` is built from a `ClientConfig` holding the artifacts entry of the services file (D05) and the service's telemetry writer (D12). Every `Put`, `Get` and `Head` request goes to `http://<name>/files/<path>`, and every `Show` request to `http://<name>/mcp`, over the entry's `Socket`, sent through `telemetry.SiblingClient` over `telemetry.SocketTransport` (D14), so every call is recorded as `sibling.called` with the entry's name as its target, and the caller in the request's context is forwarded with `identity.Forward` (D06). The constructor panics without a telemetry writer, as `telemetry.SiblingClient` and `mcp.NewServer` do; given one, it does no I/O and cannot fail. A client is safe for concurrent use, and it follows no redirect: a 3xx answer is an `*HTTPError`, and only one request is sent. Package `connections` (D23) is built the same way, with the same `ClientConfig` shape and the same `*HTTPError`.

Decisions recorded: unlike the `mcp` client (D10), the calls take no explicit `identity.Caller`: the sibling client already forwards the caller from the context, and a connector always calls with its handler's request context, so a second source of the caller could only disagree with the first. The config takes the services entry and the writer rather than an endpoint and an `*http.Client`, because there is exactly one way to reach a sibling on the host, and the client takes no name or version of its own. The client does not forward an event's cause (`events.Forward`, D17).

## The path

The path is sent as given, byte for byte, as the rest of the request target after `/files/`: artifacts matches the path on the escaped form it receives, so the client never escapes, unescapes, cleans or checks it, and artifacts alone decides what a valid path is. A path artifacts refuses comes back as 400 and so as `ErrBadPath`. The one exception is a path that cannot travel in a request target unaltered: a byte outside the characters RFC 3986 allows in a path (section 3.3, `pchar` and `/`), or a `%` not followed by two hexadecimal digits. Such a path is refused with `ErrBadPath` before any request is sent. Go's `url.URL` carries a path with escapes through `RawPath`, which `net/http` sends as the request target when it is a valid encoding of `Path`; a probe over a unix socket confirmed that `a%2Fb`, `a%41`, `a//b`, `../x`, `./x`, `a/`, `/a` and the empty path each arrive as `/files/` followed by the path, unaltered, as the server's `RequestURI`.

## Putting

`Put` sends the body as a stream. artifacts takes a body with or without a `Content-Length`, so a body of unknown length goes out chunked, its bytes sent as they are read and never gathered in memory first; a nil body is an empty file. The body stays the caller's: `Put` reads it to its end and never closes it. `PutOptions` carries the content type, sent only when not empty (artifacts stores `application/octet-stream` without one), and the expiry, sent only when not the zero time, as `X-Artifact-Expires` in RFC 3339 UTC to the second: Go's `time.RFC3339` layout drops the fraction, so the instant sent is the expiry truncated to the second, and an expiry less than a second ahead can reach artifacts as not later than its clock. The answer, 201 for a new path or 200 for a replace, is the metadata object, decoded into `Metadata`; members the client does not know are ignored, since artifacts may add members.

## Getting and heading

artifacts answers `GET` and `HEAD` with the bytes and their headers, not the metadata object, so `Get` and `Head` fill `Metadata` from the headers: `Path` is the path asked for, `Bytes` the `Content-Length`, `ContentType` the `Content-Type`, `SHA256` the `ETag` without its quotes, `Modified` the `Last-Modified` time in UTC, and `URL` the artifact's address, built as artifacts builds it, the entry's `URL` without a trailing `/` followed by `/files/` and the path. `ID`, `Owner`, `Created` and `Expires` stay zero: those headers do not carry them. A 200 answer missing `Content-Length`, `ETag` or `Last-Modified`, or carrying one that does not parse, is an error: artifacts always sends all three. `Get` returns as soon as the headers arrive and hands back the response body as a stream the caller reads and closes; when `Get` returns an error it has closed the body itself and returns none.

## Showing

`Show` reads one artifact's metadata object through artifacts' `show` tool, the only way to learn an artifact's `id`, which the `HEAD` headers do not carry. It reaches the app through appkit's `mcp.Client` (D10) at the endpoint `http://<Service.Name>/mcp`, over the same sibling client and socket, so each call is one `tools/call` POST recorded as `sibling.called` with the method `POST` and the path `/mcp`, exactly as `candidates` (D28) and `prompts` (D27) call their tools. The caller is taken from the context with `identity.FromContext` and passed to `CallTool` as its explicit caller, the zero `Caller` when there is none, so the headers agree with what the sibling client forwards; artifacts' `/mcp` requires a caller, so a consumer calls from a context holding the one it acts for.

The arguments are `{"path":<path>}`. The path travels as a JSON string, not in the request target, so `Show` checks nothing about it: any string is sent, and which paths are valid is artifacts' to say. It never returns `ErrBadPath`.

artifacts answers a success with the metadata object (`files.Metadata` of its D05) as the result's `structuredContent`, repeated as text; the client decodes `structuredContent` alone, member for member as `Put` decodes its answer: `id` to `ID`, `path` to `Path`, `bytes` to `Bytes`, `content_type` to `ContentType`, `sha256` to `SHA256`, `owner` to `Owner`, `created`, `modified` and `expires` to `Created`, `Modified` and `Expires` parsed as RFC 3339 and held in UTC, `Expires` the zero time when `expires` is absent, and `url` to `URL` as artifacts answered it. Unknown members are ignored. A success whose `structuredContent` is not that shape is a plain error: the app answered and the answer is wrong. A live `show` on the dev space answered exactly those ten members, `expires` absent for an artifact that does not expire.

artifacts' `show` refuses with an `isError` result whose text is copy and nothing else: a path no artifact has (`tools.NoArtifact`), an invalid path (`tools.InvalidPath`), the store unreachable (`store.Unreachable`). A live `show` of a missing path on the dev space answered the bare sentence, with no code a program could read. So, as in `prompts` (D27), every refusal is one `*Refusal` carrying the result's text, `Text` the `text` of each `text` item of `content`, in order, joined by a newline; `Refusal.Error` is `artifacts: ` followed by `Text`. `Show` never returns a sentinel: matching copy would break on the first reworded message.

A JSON-RPC error is an error of its own, beginning `artifacts: `, that wraps the `*mcp.RPCError`. An answer that is not JSON-RPC at all, or any status other than 200 that is not a JSON-RPC error, is, while the context has not ended, the package's `*HTTPError`, whatever the status, a 404 or a 503 included: those statuses are the files contract's, and the `/mcp` endpoint does not give them that meaning. When the context is done by the time a call that has not decoded a success, a refusal or a JSON-RPC error returns, the error satisfies `errors.Is(err, ctx.Err())`. `Show` follows no redirect and closes every response body before it returns; a body that is not a 200 event stream `mcp.Client` reads whole first.

Decisions recorded: `Show` answers the existing `Metadata`, since the `show` answer is the same object `Put` answers. Transport is `mcp.Client` because the files contract has no route that answers the id. There is one `*Refusal` and no sentinel because artifacts' `show` refusals are copy with no code (D27's precedent, not D28's, whose candidates gives a code word). The path is not checked as a sendable path because it never enters a request target. R-P9S4-MPBO, R-Z9HA-UNW2, R-ZBX3-M7DG and R-PC7X-E8T2 hold for `Show` as for the other calls; the requirements on statuses, redirects and closing bodies that the files contract shapes name `Put`, `Get` and `Head`, and `Show` has its own.

## Errors

The refusals artifacts answers `Put`, `Get` and `Head` by status are sentinels, matched with `errors.Is`: 400 is `ErrBadPath`, 403 `ErrForbidden`, 404 `ErrNotFound`, 413 `ErrTooLarge`, and 503 `ErrUnavailable`. Their bodies are copy, so the client never reads meaning from them. Any other status a call does not take as success is an `*HTTPError` holding the status and the first 4096 bytes of the body, the same shape and cap as `mcp.HTTPError` (D10). A success whose body or headers the client cannot read is a plain error, neither a sentinel nor an `*HTTPError`. A failure to reach the socket at all wraps the HTTP client's own error, so `errors.Is` and `errors.As` tell a cancelled or timed-out call from a missing socket, as D10 does.

Every 400 is `ErrBadPath`, whichever refusal artifacts meant. For `Get` and `Head` that is the path; for `Put` it may also be an `X-Artifact-Expires` artifacts refuses as malformed or as not later than its clock, which the client cannot tell from a bad path, because the refusal's words are copy. A body the client does not hand back is read no further than it needs, at most its first 4096 bytes for an `*HTTPError`, and closed before the call returns.

artifacts refuses an oversized `Put` with 413 once it has read past its cap, and closes the connection. When the client still had body to send, the transport may report the failed write instead of the answer; that is a transport error, wrapped as above and matching no sentinel, not `ErrTooLarge`.

## Consumer tasks

A connector app, gdrive, reads the services file at the path `services.Variable` names with `services.Read`, finds the `artifacts` entry with `List.Find`, and in its handler setup builds `artifacts.NewClient(artifacts.ClientConfig{Service: entry, Telemetry: w})` with its one telemetry writer. Uploading an artifact to Google, its handler calls `Head(r.Context(), path)` and reads `Bytes` and `ContentType` from the `Metadata`, then calls `Get(r.Context(), path)`, streams the returned `io.ReadCloser` into its request to Google, and closes it. Importing a file from Google, it calls `Put(r.Context(), path, artifacts.PutOptions{ContentType: ct, Expires: exp}, resp.Body)` with the body of Google's response, leaving `Expires` zero for a file that should not expire, and closes Google's body itself. Because every 400 is `ErrBadPath`, it checks the expiry itself first, refusing one not at least a second later than its own clock, so a 400 it gets back means the path; it answers the `Metadata`'s `ID`, `Bytes`, `SHA256` and `URL`. On any error it checks `errors.Is` against `ErrBadPath`, `ErrNotFound`, `ErrForbidden`, `ErrTooLarge` and `ErrUnavailable`, each mapped to its own refusal word, uses `errors.As` for an `*HTTPError` to report the status, and `errors.Is(err, context.DeadlineExceeded)` to tell a timeout.

campaigns holds references to artifacts by path and links each to the artifact's page `/art_<id>`. It builds the client the same way, from the `artifacts` entry and its writer, calling from the request context that holds its caller. Its `add_material` tool first calls `_, err := client.Head(ctx, path)`: on an error for which `errors.Is(err, artifacts.ErrBadPath)` or `errors.Is(err, artifacts.ErrNotFound)` is true it refuses its own call with its own refusal for each, and any other error it reports as a failure. Then it calls `m, err := client.Show(ctx, path)` and links to `/` followed by `m.ID`, the id `Head` leaves zero. Any error from `Show`, a `*artifacts.Refusal` (its `Text` for the log), a `*artifacts.HTTPError`, an `*mcp.RPCError`, a malformed answer or a transport failure, it reports as a failure: the path was just found, so a refusal now is not the caller's mistake.

Its tests write a services file in their temporary directory naming a unix socket there, serve a handler on that socket that speaks the files contract and records each request's method, `RequestURI`, `Host`, headers and body, build the client over a writer whose sink is a `*telemetry.Capture`, and call it with a context carrying an `identity.Caller` they make up. A `Show` test serves an `mcp.Server` (D07, D08) or a hand-written handler at `/mcp` on that socket, as D28's tests do, and checks the request (method, path, query, host, identity headers, the JSON-RPC method, tool name and arguments) and what `Show` returns for a success, a malformed success, an `isError` result, a JSON-RPC error, a non-JSON-RPC status, a 3xx, a closed socket and a context cancelled mid-answer.
