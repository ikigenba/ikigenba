# D22-artifacts-client

Package `artifacts` is the client a service uses to keep and fetch binary files in the artifacts app, the suite's store for files agents and services share. A connector that moves a file between the suite and an outside service streams its bytes through here rather than through an agent's context: it asks what an artifact is, fetches its bytes as a stream, and puts a stream of bytes at a path with a content type and, for scratch files, an expiry. The client speaks artifacts' published files contract over the app's unix socket: `PUT`, `GET` and `HEAD` of `/files/<path>`. It does nothing else: listing, deleting and the MCP tools stay with artifacts and the agents that call it.

## The client

A `Client` is built from a `ClientConfig` holding the artifacts entry of the services file (D05) and the service's telemetry writer (D12). Every request goes to `http://<name>/files/<path>` over the entry's `Socket`, sent through `telemetry.SiblingClient` over `telemetry.SocketTransport` (D14), so every call is recorded as `sibling.called` with the entry's name as its target, and the caller in the request's context is forwarded with `identity.Forward` (D06). The constructor panics without a telemetry writer, as `telemetry.SiblingClient` and `mcp.NewServer` do; given one, it does no I/O and cannot fail. A client is safe for concurrent use, and it follows no redirect: a 3xx answer is an `*HTTPError`, and only one request is sent. Package `connections` (D23) is built the same way, with the same `ClientConfig` shape and the same `*HTTPError`.

Decisions recorded: unlike the `mcp` client (D10), the calls take no explicit `identity.Caller`: the sibling client already forwards the caller from the context, and a connector always calls with its handler's request context, so a second source of the caller could only disagree with the first. The config takes the services entry and the writer rather than an endpoint and an `*http.Client`, because there is exactly one way to reach a sibling on the host, and the client takes no name or version of its own. The client does not forward an event's cause (`events.Forward`, D17).

## The path

The path is sent as given, byte for byte, as the rest of the request target after `/files/`: artifacts matches the path on the escaped form it receives, so the client never escapes, unescapes, cleans or checks it, and artifacts alone decides what a valid path is. A path artifacts refuses comes back as 400 and so as `ErrBadPath`. The one exception is a path that cannot travel in a request target unaltered: a byte outside the characters RFC 3986 allows in a path (section 3.3, `pchar` and `/`), or a `%` not followed by two hexadecimal digits. Such a path is refused with `ErrBadPath` before any request is sent. Go's `url.URL` carries a path with escapes through `RawPath`, which `net/http` sends as the request target when it is a valid encoding of `Path`; a probe over a unix socket confirmed that `a%2Fb`, `a%41`, `a//b`, `../x`, `./x`, `a/`, `/a` and the empty path each arrive as `/files/` followed by the path, unaltered, as the server's `RequestURI`.

## Putting

`Put` sends the body as a stream. artifacts takes a body with or without a `Content-Length`, so a body of unknown length goes out chunked, its bytes sent as they are read and never gathered in memory first; a nil body is an empty file. The body stays the caller's: `Put` reads it to its end and never closes it. `PutOptions` carries the content type, sent only when not empty (artifacts stores `application/octet-stream` without one), and the expiry, sent only when not the zero time, as `X-Artifact-Expires` in RFC 3339 UTC to the second: Go's `time.RFC3339` layout drops the fraction, so the instant sent is the expiry truncated to the second, and an expiry less than a second ahead can reach artifacts as not later than its clock. The answer, 201 for a new path or 200 for a replace, is the metadata object, decoded into `Metadata`; members the client does not know are ignored, since artifacts may add members.

## Getting and heading

artifacts answers `GET` and `HEAD` with the bytes and their headers, not the metadata object, so `Get` and `Head` fill `Metadata` from the headers: `Path` is the path asked for, `Bytes` the `Content-Length`, `ContentType` the `Content-Type`, `SHA256` the `ETag` without its quotes, `Modified` the `Last-Modified` time in UTC, and `URL` the artifact's address, built as artifacts builds it, the entry's `URL` without a trailing `/` followed by `/files/` and the path. `ID`, `Owner`, `Created` and `Expires` stay zero: those headers do not carry them. A 200 answer missing `Content-Length`, `ETag` or `Last-Modified`, or carrying one that does not parse, is an error: artifacts always sends all three. `Get` returns as soon as the headers arrive and hands back the response body as a stream the caller reads and closes; when `Get` returns an error it has closed the body itself and returns none.

## Errors

The refusals artifacts answers by status are sentinels, matched with `errors.Is`: 400 is `ErrBadPath`, 403 `ErrForbidden`, 404 `ErrNotFound`, 413 `ErrTooLarge`, and 503 `ErrUnavailable`. Their bodies are copy, so the client never reads meaning from them. Any other status a call does not take as success is an `*HTTPError` holding the status and the first 4096 bytes of the body, the same shape and cap as `mcp.HTTPError` (D10). A success whose body or headers the client cannot read is a plain error, neither a sentinel nor an `*HTTPError`. A failure to reach the socket at all wraps the HTTP client's own error, so `errors.Is` and `errors.As` tell a cancelled or timed-out call from a missing socket, as D10 does.

Every 400 is `ErrBadPath`, whichever refusal artifacts meant. For `Get` and `Head` that is the path; for `Put` it may also be an `X-Artifact-Expires` artifacts refuses as malformed or as not later than its clock, which the client cannot tell from a bad path, because the refusal's words are copy. A body the client does not hand back is read no further than it needs, at most its first 4096 bytes for an `*HTTPError`, and closed before the call returns.

artifacts refuses an oversized `Put` with 413 once it has read past its cap, and closes the connection. When the client still had body to send, the transport may report the failed write instead of the answer; that is a transport error, wrapped as above and matching no sentinel, not `ErrTooLarge`.

## Consumer tasks

A connector app, gdrive, reads the services file at the path `services.Variable` names with `services.Read`, finds the `artifacts` entry with `List.Find`, and in its handler setup builds `artifacts.NewClient(artifacts.ClientConfig{Service: entry, Telemetry: w})` with its one telemetry writer. Uploading an artifact to Google, its handler calls `Head(r.Context(), path)` and reads `Bytes` and `ContentType` from the `Metadata`, then calls `Get(r.Context(), path)`, streams the returned `io.ReadCloser` into its request to Google, and closes it. Importing a file from Google, it calls `Put(r.Context(), path, artifacts.PutOptions{ContentType: ct, Expires: exp}, resp.Body)` with the body of Google's response, leaving `Expires` zero for a file that should not expire, and closes Google's body itself. Because every 400 is `ErrBadPath`, it checks the expiry itself first, refusing one not at least a second later than its own clock, so a 400 it gets back means the path; it answers the `Metadata`'s `ID`, `Bytes`, `SHA256` and `URL`. On any error it checks `errors.Is` against `ErrBadPath`, `ErrNotFound`, `ErrForbidden`, `ErrTooLarge` and `ErrUnavailable`, each mapped to its own refusal word, uses `errors.As` for an `*HTTPError` to report the status, and `errors.Is(err, context.DeadlineExceeded)` to tell a timeout.

Its tests write a services file in their temporary directory naming a unix socket there, serve a handler on that socket that speaks the files contract and records each request's method, `RequestURI`, `Host`, headers and body, build the client over a writer whose sink is a `*telemetry.Capture`, and call it with a context carrying an `identity.Caller` they make up.

## REQUIREMENTS

- R-YSEP-HVIC: Package `artifacts` MUST export `type ClientConfig struct { Service services.Entry; Telemetry *telemetry.Writer }`, with exactly these fields in this order, where `services` and `telemetry` are appkit's packages of those names.
- R-YTML-VN91: Package `artifacts` MUST export type `Client` and `func NewClient(cfg ClientConfig) *Client`.
- R-YUUI-9EZQ: Package `artifacts` MUST export the method `func (c *Client) Put(ctx context.Context, path string, opts PutOptions, body io.Reader) (Metadata, error)`, where `context` and `io` are the standard library's packages of those names.
- R-YW2E-N6QF: Package `artifacts` MUST export the method `func (c *Client) Get(ctx context.Context, path string) (Metadata, io.ReadCloser, error)`.
- R-YXAB-0YH4: Package `artifacts` MUST export the method `func (c *Client) Head(ctx context.Context, path string) (Metadata, error)`.
- R-YYI7-EQ7T: Package `artifacts` MUST export `type Metadata struct { ID, Path string; Bytes int64; ContentType, SHA256, Owner string; Created, Modified, Expires time.Time; URL string }`, with exactly these fields in this order, where `time` is the standard library's `time`.
- R-YZQ3-SHYI: Package `artifacts` MUST export `type PutOptions struct { ContentType string; Expires time.Time }`, with exactly these fields in this order.
- R-PB01-0H2D: Package `artifacts` MUST export `var ErrBadPath, ErrNotFound, ErrForbidden, ErrTooLarge, ErrUnavailable error`, each non-nil, the five different values, none wrapping another, so `errors.Is` with any one of them and another is false, and the `Error` method of each returning a string beginning `artifacts: `.
- R-Z25W-K1FW: Package `artifacts` MUST export `type HTTPError struct { StatusCode int; Body string }`, with exactly these fields in this order, and the method `func (e *HTTPError) Error() string`.
- R-P8K8-8XKZ: `NewClient` MUST panic, with a message that says the telemetry writer is nil, when `cfg.Telemetry` is nil; for every `ClientConfig` whose `Telemetry` is not nil it MUST return a non-nil `*Client` without panicking, performing I/O or returning an error, whatever its `Service` holds, nothing existing at `Service.Socket` included.
- R-P9S4-MPBO: When `cfg.Service.Name` is non-empty and consists only of lowercase ASCII letters, ASCII digits and `-`, every HTTP request a `Client` sends MUST be sent over a connection to the unix-domain stream socket at `cfg.Service.Socket` as given, whatever `cfg.Service.URL` holds, with the host `cfg.Service.Name`.
- R-Z5TL-PCNZ: A **sendable path** is a string each of whose bytes is an ASCII letter, an ASCII digit, `/`, or one of `-._~!$&'()*+,;=:@`, or is a `%` immediately followed by two ASCII hexadecimal digits; for every sendable `path`, the empty string included, `Put`, `Get` and `Head` MUST each send exactly one request, with the method `PUT`, `GET` and `HEAD` respectively, whose request target as the server receives it (`http.Request.RequestURI`) is `/files/` followed by `path` byte for byte; so that `a%2Fb`, `a%41`, `a//b`, `../x`, `./x`, `a/`, `/a` and the empty string each arrive unescaped, unencoded and uncleaned.
- R-Z89E-GW5D: When `path` is not a sendable path, as `a b`, `a?b`, `a#b`, `a%zz` and `é` are not, `Put`, `Get` and `Head` MUST return an error for which `errors.Is(err, ErrBadPath)` is true without sending any request, `Put` reading nothing from `body`.
- R-Z9HA-UNW2: When `identity.FromContext` of a call's context returns true, every request the call sends MUST carry the `X-User-Id`, `X-User-Email` and `X-Request-Id` headers exactly as `identity.Forward` sets them from that `Caller`; when it returns false, the request MUST carry none of those headers.
- R-PH3I-XBRU: For each request a `Client` sends, it MUST emit through `cfg.Telemetry` exactly one event named `sibling.called`, whose `target` attribute is `cfg.Service.Name`, whose `method` attribute is the request's method, and, when `path` holds no `%`, whose `path` attribute is `/files/` followed by `path`, and whose other attributes and envelope are as R-3V3W-TS7E, R-3WBT-7JY3, R-3YRL-Z3FH and R-JM59-H5JP state for a client `telemetry.SiblingClient` returns, so that a request that fails before any response records the status 0.
- R-ZBX3-M7DG: A request a `Client` sends MUST NOT carry an `X-Event-Cause` or `X-Event-Depth` header, whatever the call's context carries.
- R-ZD4Z-ZZ45: The request `Put` sends MUST carry exactly one `Content-Type` header whose value is `opts.ContentType` byte for byte when that is not empty, and no `Content-Type` header when it is empty; and it MUST carry exactly one `X-Artifact-Expires` header whose value is `opts.Expires.UTC().Format(time.RFC3339)` when `opts.Expires` is not the zero time, and no `X-Artifact-Expires` header when it is.
- R-ZECW-DQUU: The body of the request `Put` sends MUST be exactly the bytes `body` yields until a `Read` returns `io.EOF`, whether or not `body`'s length is known before it is read, and empty when `body` is nil; and `Put` MUST NOT call `Close` on `body`, even when `body` implements `io.Closer`.
- R-ZFKS-RILJ: When a `Read` of `body` returns an error other than `io.EOF`, `Put` MUST return a non-nil error and the zero `Metadata`.
- R-PIBF-B3IJ: `Put` MUST send the bytes `body` has yielded without waiting for `body` to return `io.EOF`: when `body` is the reading half of an `io.Pipe` and some bytes have been written to its writing half, which is not yet closed, a handler at the server MUST receive those bytes.
- R-ZGSP-5AC8: The requests `Get` and `Head` send MUST have an empty body and MUST carry none of the headers `Range`, `If-Range`, `If-Match`, `If-None-Match`, `If-Modified-Since` and `If-Unmodified-Since`.
- R-ZI0L-J22X: When the answer to `Put` has status 201 or 200 and its body is one JSON object whose members `id`, `path`, `content_type`, `sha256`, `owner` and `url` are strings, whose member `bytes` is a number `encoding/json` decodes into an `int64` without error, whose members `created` and `modified` are strings `time.Parse(time.RFC3339, s)` accepts, and whose member `expires` is absent or such a string, `Put` MUST return a nil error and the `Metadata` whose `ID`, `Path`, `ContentType`, `SHA256`, `Owner` and `URL` are those strings unaltered, whose `Bytes` is that number, whose `Created`, `Modified` and `Expires` are those instants in UTC, `Expires` being the zero time when the member is absent, whatever other members the object holds and whatever the answer's `Content-Type`.
- R-ZJ8H-WTTM: When the answer to `Put` has status 201 or 200 and its body is not as R-ZI0L-J22X describes, `Put` MUST return the zero `Metadata` and a non-nil error that is not an `*HTTPError` and for which `errors.Is` is false for each of `ErrBadPath`, `ErrNotFound`, `ErrForbidden`, `ErrTooLarge` and `ErrUnavailable`.
- R-ZKGE-ALKB: When the answer to `Get` or `Head` has status 200, a `Content-Length` header whose value is a non-negative decimal integer, an `ETag` header whose first value is `"` followed by a non-empty string `s` holding no `"` and then `"`, and a `Last-Modified` header whose first value `http.ParseTime` accepts, the call MUST return a nil error and the `Metadata` whose `Path` is `path`, `Bytes` that `Content-Length`, `ContentType` the first `Content-Type` value (empty when absent), `SHA256` the string `s`, `Modified` the instant `http.ParseTime` returns in UTC, and `URL` R-ZLOA-ODB0's address, with `ID`, `Owner`, `Created` and `Expires` zero.
- R-ZLOA-ODB0: The address `Get` and `Head` give as `Metadata.URL` MUST be `cfg.Service.URL` with every trailing `/` removed, followed by `/files/` and `path`; so that the `URL` `https://artifacts.sbx.ikigenba.dev/` and the path `a/b.bin` give `https://artifacts.sbx.ikigenba.dev/files/a/b.bin`, and an empty `URL` gives `/files/a/b.bin`.
- R-ZMW7-251P: When the answer to `Get` or `Head` has status 200 and lacks a `Content-Length` header, as a chunked answer does, or lacks an `ETag` or `Last-Modified` header, or carries one whose first value is not of the form R-ZKGE-ALKB states, the call MUST return a non-nil error that is not an `*HTTPError` and for which `errors.Is` is false for each of `ErrBadPath`, `ErrNotFound`, `ErrForbidden`, `ErrTooLarge` and `ErrUnavailable`.
- R-ZO43-FWSE: When `Get` returns a nil error, the `io.ReadCloser` it returns MUST be non-nil and MUST yield exactly the bytes of the answer's body, and its `Close` MUST release the connection, so that a server still writing the body observes the end of the connection.
- R-PJJB-OV98: `Get` MUST return once the response's headers have arrived, without waiting for its body: when the server writes the headers of a 200 answer that R-ZKGE-ALKB accepts and part of its body, flushes, and then waits before writing the rest, `Get` MUST return a nil error and an `io.ReadCloser` from which that part can be read while the server is still waiting.
