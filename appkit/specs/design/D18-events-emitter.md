# D18-events-emitter

A service puts events on the bus through one `events.Emitter`, built at start-up with `events.New` from a `Config` naming the service, the sink events go to, the writer standard-error lines go to (normally `os.Stderr`), the service's telemetry writer (D12), and the events the service emits. The service's handlers call `Emit` with the request's context after each change they announce, so every event carries the request id and user of the request that caused it, and, inside a delivery, the event that caused it (D17).

## Declaring what it emits

A producer declares, once, every event it emits and the attribute keys each carries: `Config.Emits` is a list of `Emission`s, fixed when the emitter is built. The declaration is published: D20's declarations handler reads it through `Emitter.Emits`, so the broker and an agent can see what a service puts on the bus without reading its code. `Emit` holds every event to its declaration: the attributes it is handed must have exactly the declared keys, none missing and none extra, as well as D17's validity, so what `/declarations` publishes is what the bus carries. An emitter refuses a declaration that could never be honoured (a name or key that is not valid, a name declared twice, a key repeated within one emission) by panicking in `New`, as it refuses an empty service name: both are bugs a service's first test run finds. An `Emit` for a name the service never declared, or whose attributes miss a declared key or carry one not declared, is a bug of the same kind, and is treated as a malformed event.

## Stamping

`Emit` forms the event, queues it, and returns; it never waits for delivery. It stamps the envelope D17 defines. The id is `evt_` and sixteen lowercase hexadecimal digits encoding eight bytes read from the config's random source, so a test that supplies known bytes knows the id in advance; should the source fail, the bytes come from `crypto/rand` instead and the event is still sent. The time comes from the config's clock at the moment of the call, in UTC and truncated to the microsecond. The request id and the user come from `identity.FromContext` (D06), both empty when the context carries no caller. The cause and depth come from `events.FromContext` (D17): with a cause in the context the event names that cause's id and has its depth plus one; without one, its cause is empty and its depth 0. The attributes are copied at the call, converted to their basic forms, so the caller may reuse its map at once.

An event that is not a valid emitted event (D17), whose name the service did not declare, or whose attribute keys are not exactly the declared ones can never be accepted by the broker. It goes straight to standard error as a `malformed event` line, exactly as telemetry's writer writes one (D12), and never reaches the sink. Its JSON shows every invalid attribute value as `null`, never the value itself; an extra key's valid value is printed as is.

## One queue, one sender

The emitter has one bounded queue (`QueueCapacity`, `DefaultQueueCapacity` when zero) and one sender, which hands events to the sink one at a time, in the order they were emitted. Unlike telemetry, the bus is not best-effort over milliseconds: an event is a fact another service acts on, so the sender keeps trying one event for up to `RetryWindow` (`DefaultRetryWindow`, five minutes, when zero) before it gives up, and every event behind it waits, so order is never broken by a retry. The window is long enough to ride out a broker restart or redeploy; the queue is large enough to hold what a service emits meanwhile.

Each attempt is bounded by `AttemptTimeout` through its context, which is the emitter's own and never the emitting request's. After a failed attempt the sender pauses and tries again, the pauses growing exponentially:

| After attempt | Pause |
|---|---|
| 1 | `RetryBackoff` (100 ms) |
| 2 | 200 ms |
| n | `RetryBackoff` × 2^(n−1), at most `MaxRetryBackoff` (30 s) |

So the pauses run 100 ms, 200 ms, 400 ms and so on to 25.6 s after the ninth attempt, and 30 s after every later one. The window is measured on the config's clock, from just before the first attempt to just after each failed one: once a failed attempt ends at least `RetryWindow` after the first began, the event is given up. A test supplies a `Sleep` that records each pause and advances its clock by that pause, so the whole curve and the moment of giving up are observed without sleeping.

A sink that answers with an error wrapping `ErrRejected` says the event itself is at fault (the broker answered 4xx, D19), so the emitter does not retry it.

## Lost events

An event that was valid but never reached the broker is lost: the sink rejected it, its retry window ran out, the queue was full when it was emitted, it was emitted after `Shutdown` began, or `Shutdown`'s context ended before it was delivered. The emitter reports each lost event in two places. It writes one `lost event` line to standard error holding the event's JSON exactly as it would have been posted, so nothing is lost without trace. And, when the config has a telemetry writer, it emits `event.lost` through it, carrying the lost event's id under the key `event` (the entity type D11 registers for `evt_`) and its cause under `cause`, with the lost event's request id and user in the envelope, so the trail shows the loss beside the request that caused it.

## Lifecycle

The emitter starts its sender in `New`. `Shutdown` takes only a context: unlike telemetry's `Writer.Shutdown` (D12), which records the reason in `service.stopping`, the bus has no stop event to carry one. `Ready` exists so an app's start-up reads the same for both writers, and does nothing: unlike telemetry, the bus carries no start event. On a stop signal the app drains its HTTP server first, so every handler has emitted, and then calls `Shutdown` with the drain window's context. The first `Shutdown` waits until every queued event is delivered or reported lost; when the context ends first, every event not yet delivered, the one in flight included, is reported lost in queue order and `Shutdown` returns at once. From then on the emitter begins no new delivery: at most one call it had already set out to make may still reach the sink or the pause, with a context that is already done. An event emitted after `Shutdown` began is never queued and is reported lost. A later `Shutdown` does nothing more.

`Flush` waits until every event queued so far is delivered or reported lost, which is how a test waits for delivery.

## Sinks

The emitter targets the `Sink` interface. A nil `Config.Sink` means the socket sink of D19, which posts to the broker, and is what every ordinary service uses. The broker supplies its own sink to D19's emit handler, never to an emitter of its own events. A test supplies a `*events.Capture`, which records every event it receives in order and is ready to use as its zero value.

## Safety

Every method of `Emitter` and `Capture` is safe to call from many goroutines at once. The emitter never writes to `Config.Stderr` from two goroutines at once and writes each line in a single `Write` call; a nil `Config.Stderr` discards the lines. `Emit` never panics, whatever name and attributes it is handed.

## Consumer tasks

A producer (repos-like) builds its emitter at start-up: `events.New(events.Config{Service: "repos", Stderr: os.Stderr, Telemetry: tw, Emits: []events.Emission{{Event: "repo.pushed", Attrs: []string{"repo", "ref", "old", "new"}}}})`, leaving `Sink` nil so events go to the broker. It hands the emitter to D20's `events.DeclarationsHandler`, which lists `Emitter.Emits`. After a push its handler calls `em.Emit(r.Context(), "repo.pushed", events.Attrs{"repo": id, "ref": ref, "old": old, "new": new})`. On a stop signal it drains its server, calls `em.Shutdown(ctx)`, and then shuts down its telemetry writer, so any `event.lost` reaches the trail.

A consumer's handler that reacts to a delivery emits a follow-up with the context D20 gave it; the follow-up's `Cause` and `Depth` come from that context without the handler doing anything.

A service's test builds its emitter over a `*events.Capture` with a fixed `Now`, a `Rand` of known bytes, and a `Sleep` that records each pause, emits with a context built by `events.NewContext`, calls `Flush`, and asserts on `Capture.Events`: the stamped `ID`, `Cause` and `Depth`. A test of declarations emits a declared name once with a declared key left out, once with an undeclared key added, and once with as many keys as declared but not the declared ones (declared `a` and `b`, emitted `a` and `c`), and asserts that each produced a `malformed event` line in its `Stderr` buffer and nothing in `Capture.Events`. A test of retry builds its emitter over a sink that fails, with a `Sleep` that advances its clock by each pause, and asserts on the recorded pauses, on the `lost event` line in the `bytes.Buffer` it passed as `Stderr`, and on the `event.lost` event in the `*telemetry.Capture` behind its telemetry writer.
