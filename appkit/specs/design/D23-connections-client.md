# D23-connections-client

Package `connections` is the client a connector on the host uses to get a caller's access token from the connections app, the suite's OAuth broker. The connections app keeps each person's grant at an outside provider and answers its token route, `GET /token/<provider>`, on its unix socket with the identity headers of the user the connector acts for; this package speaks that route and nothing else. It holds no state of its own: every call is one request, and the access token it returns is the caller's to use until its expiry, then ask again.

A `Client` is built from a `ClientConfig` naming the connections app's entry in the services file (D05) and the service's telemetry writer (D12). `NewClient` panics without the writer, as `telemetry.SiblingClient` and `mcp.NewServer` do; given one, it does no I/O and cannot fail. It reaches the app the way every sibling call does (D14): through `telemetry.SiblingClient` over `telemetry.SocketTransport` on the entry's `Socket`, at `http://<name>/token/<provider>`, so every call is recorded as `sibling.called` and carries the caller in the call's context onto the request. The `ClientConfig` has the same fields in the same order as `artifacts.ClientConfig` (D22), so a connector builds both the same way.

## The answer

A 200 answer is a JSON object with `access_token`, `expires` (RFC 3339), `account` and `scopes` (an array of strings). `Token` returns them as a `Token`, its `Expires` parsed into a `time.Time`, so the connector compares it with its clock rather than with a string. Members the client does not name are ignored, so the app may add one without breaking it. A 200 whose body is not that shape is an error of its own, neither a refusal nor an `*HTTPError`: the app answered and the answer is wrong.

## Refusals

Every refusal from the token route is a JSON object whose `error` member is one fixed word, with `url` beside it for `reconnect`. The client maps each word, at the status the app pairs it with, to an error a connector tells apart with `errors.Is` or `errors.As`, and maps each to its own refusal word:

- 404 `unknown_provider` is `ErrUnknownProvider`: the app knows no provider by that name.
- 404 `not_connected` is `ErrNotConnected`: the caller has not connected an account at that provider.
- 409 `reconnect` is a `*ReconnectError` whose `URL` is the connect page the person must open; the grant is gone and only the person can restore it.
- 502 `provider` is `ErrProvider`: the provider could not refresh the token; the next call tries again.
- 503 `unavailable` is `ErrUnavailable`: the app's database is unreachable.

Anything else is an `*HTTPError` holding the status and the first 4096 bytes of the body, as `mcp.HTTPError` (D10) does: another status, or one of those statuses with a body that does not carry the word paired with it (a 404 from something that is not the token route, a 409 with no `url`). The word decides only together with its status, so an unexpected answer is never mistaken for a refusal the connector would act on. A failure to reach the app at all, a missing socket or the caller's context ending, is returned wrapped so `errors.Is` and `errors.As` see the transport's own error.

## The request path

The provider is sent unescaped and unmodified: the request's URL path is `/token/` followed by the provider exactly as given, with no query, and Go's standard path encoding puts it on the wire. A provider holding `/` therefore names a deeper path and one holding `?` is sent with the `?` encoded in the path rather than starting a query; the app answers both `unknown_provider`, as it does an empty provider. The client checks nothing about the provider itself: which names exist is the app's to say.

Decisions recorded: the caller is forwarded by `telemetry.SiblingClient` from the call's context, not passed as an explicit argument as `mcp.Client` (D10) takes it, because a connector calls from a handler whose context already holds the caller and the sibling client already forwards it; a second source of the caller could only disagree. The client sets no `X-Event-Cause` or `X-Event-Depth` header. It does not check a response's `Content-Type`: the token route is a trusted sibling on the host and its body decides. The `*HTTPError` type and its text mirror `mcp.HTTPError` and are the same in `artifacts` (D22). A response body is read no further than the client needs, at most its first 4096 bytes for an `*HTTPError`, and closed before `Token` returns. The client follows no redirect: a 3xx answer is an `*HTTPError`, and only one request is sent. The rule that a shared package has two callers is set aside for this one: the gdrive connector is its only caller so far, and the token route's contract belongs beside the other sibling clients.

## Consumer tasks

A connector reads the services file with `services.Read` at the path `services.Variable` names and finds the `connections` entry with `List.Find`. In its handler setup it builds `connections.NewClient(connections.ClientConfig{Service: entry, Telemetry: writer})`, beside its `artifacts` client. Before each transfer its handler calls `tok, err := client.Token(r.Context(), "google")` and uses `tok.AccessToken` until `tok.Expires`. On an error it checks `errors.Is(err, connections.ErrNotConnected)`, `errors.Is(err, connections.ErrUnknownProvider)`, `errors.Is(err, connections.ErrProvider)` and `errors.Is(err, connections.ErrUnavailable)`, and `errors.As(err, &re)` with `re` a `*connections.ReconnectError`, handing `re.URL` to the person; each maps to its own refusal word, and any other error, an `*connections.HTTPError` or a transport failure, is the connector's own internal failure.

A test serves a loopback HTTP server on a unix socket in its temporary directory, names that socket as the `Socket` of a `services.Entry`, builds a writer over the capturing sink (D12), and checks the request the server receives (method, path, query, host and identity headers) and what `Token` returns for each answer the server gives. To prove the body is closed, its server answers a status that maps to `*HTTPError` with a body far larger than the transport buffers and waits for its write to fail.

## REQUIREMENTS

- R-POEX-7Y80: Package `connections` MUST export `type ClientConfig struct { Service services.Entry; Telemetry *telemetry.Writer }`, with exactly these fields in this order, where `services` and `telemetry` are appkit's packages of those names.
- R-ZO9M-NIZT: Package `connections` MUST export type `Client` and `func NewClient(cfg ClientConfig) *Client`.
- R-ZPHJ-1AQI: Package `connections` MUST export the method `func (c *Client) Token(ctx context.Context, provider string) (Token, error)`.
- R-ZQPF-F2H7: Package `connections` MUST export `type Token struct { AccessToken string; Expires time.Time; Account string; Scopes []string }`, with exactly these fields in this order.
- R-ZT58-6LYL: Package `connections` MUST export `var ErrUnknownProvider, ErrNotConnected, ErrProvider, ErrUnavailable error`, each non-nil, the four different values, none wrapping another, so `errors.Is` with any one of them and another is false, and the `Error` method of each returning a string beginning `connections: `.
- R-ZY0T-POXD: Package `connections` MUST export `type ReconnectError struct { URL string }`, with exactly this field, and the method `func (e *ReconnectError) Error() string`.
- R-ZZ8Q-3GO2: Package `connections` MUST export `type HTTPError struct { StatusCode int; Body string }`, with exactly these fields in this order, and the method `func (e *HTTPError) Error() string`.
- R-PPMT-LPYP: `NewClient` MUST panic, with a message that says the telemetry writer is nil, when `cfg.Telemetry` is nil; for every `ClientConfig` whose `Telemetry` is not nil it MUST return a non-nil `*Client` without panicking, performing I/O or returning an error, whatever its `Service` holds, nothing existing at `Service.Socket` included.
- R-PQUP-ZHPE: When `cfg.Service.Name` is non-empty and consists only of lowercase ASCII letters, ASCII digits and `-`, every HTTP request a `Client` sends MUST be sent over a connection to the unix-domain stream socket at `cfg.Service.Socket` as given, whatever `cfg.Service.URL` holds, with the host `cfg.Service.Name`.
- R-PS2M-D9G3: Each `Token` call MUST send exactly one HTTP request, with the method `GET`, no body, and a URL whose `Path` is `/token/` followed by `provider` unaltered and whose query is empty; so that a server at the socket sees `r.URL.Path` equal to `/token/a?b` and `r.URL.RawQuery` empty for the provider `a?b`, `/token/a/b` for `a/b`, and `/token/goo%67le` for `goo%67le`.
- R-044B-MJMU: When `identity.FromContext` of the `ctx` passed to `Token` returns true, the request `Token` sends MUST carry the `X-User-Id`, `X-User-Email` and `X-Request-Id` headers exactly as `identity.Forward` sets them from that `Caller`; when it returns false, the request MUST carry none of those three headers.
- R-PTAI-R16S: For each request a `Client` sends, it MUST emit through `cfg.Telemetry` exactly one event named `sibling.called`, whose `target` attribute is `cfg.Service.Name`, whose `method` attribute is the request's method, whose `path` attribute is the request's URL `Path` (R-PS2M-D9G3), and whose other attributes and envelope are as R-3V3W-TS7E, R-3WBT-7JY3, R-3YRL-Z3FH and R-JM59-H5JP state for a client `telemetry.SiblingClient` returns, so that a request that fails before any response records the status 0.
- R-PUIF-4SXH: A request a `Client` sends MUST NOT carry an `X-Event-Cause` or `X-Event-Depth` header, whatever the call's context carries.
- R-06K4-E348: In R-07S0-RUUX, R-08ZX-5MLM, R-0A7T-JECB, R-0CNM-AXTP and R-0DVI-OPKE, a member `m` of a response body MUST mean a member of the one JSON object (RFC 8259) the whole body is, whose name equals `m` exactly, letter case included, the last occurrence counting when the name repeats; a body that is not exactly one JSON object has no members, and members those requirements do not name MUST be ignored.
- R-07S0-RUUX: When the response status is 200 and the body (R-06K4-E348) has a member `access_token` that is a string, `expires` that is a string `time.Parse(time.RFC3339, expires)` accepts, `account` that is a string, and `scopes` that is an array whose every element is a string, `Token` MUST return a nil error and the `Token` whose `AccessToken` is `access_token`, `Expires` is the value that `time.Parse(time.RFC3339, expires)` returns, `Account` is `account`, and `Scopes` is a non-nil slice holding the elements of `scopes` in order, empty when `scopes` is empty.
- R-08ZX-5MLM: When the response status is 200 and the body is not as R-07S0-RUUX states, `Token` MUST return a non-nil error whose `Error` method returns a string beginning `connections: `, for which `errors.Is` with each of `ErrUnknownProvider`, `ErrNotConnected`, `ErrProvider` and `ErrUnavailable` is false and `errors.As` finds neither a `*ReconnectError` nor an `*HTTPError`.
- R-0A7T-JECB: When the response status is 404 and the body's member `error` (R-06K4-E348) is the string `unknown_provider`, `Token` MUST return an error for which `errors.Is(err, ErrUnknownProvider)` is true; when it is the string `not_connected`, one for which `errors.Is(err, ErrNotConnected)` is true; in each case `errors.Is` with each of the other three sentinels of R-ZT58-6LYL MUST be false and `errors.As` MUST find neither a `*ReconnectError` nor an `*HTTPError`.
- R-0CNM-AXTP: When the response status is 409, the body's member `error` (R-06K4-E348) is the string `reconnect` and its member `url` is a string, `Token` MUST return an error for which `errors.As` finds a `*ReconnectError` whose `URL` is that string, for which `errors.Is` with each sentinel of R-ZT58-6LYL is false and `errors.As` finds no `*HTTPError`.
- R-0DVI-OPKE: When the response status is 502 and the body's member `error` (R-06K4-E348) is the string `provider`, `Token` MUST return an error for which `errors.Is(err, ErrProvider)` is true; when the status is 503 and that member is the string `unavailable`, one for which `errors.Is(err, ErrUnavailable)` is true; in each case `errors.Is` with each of the other three sentinels of R-ZT58-6LYL MUST be false and `errors.As` MUST find neither a `*ReconnectError` nor an `*HTTPError`.
- R-0F3F-2HB3: When a response is received whose status is not 200 and to which neither R-0A7T-JECB, R-0CNM-AXTP nor R-0DVI-OPKE applies, among them a 404, 409, 502 or 503 whose body does not carry the word that requirement pairs with its status, `Token` MUST return an `*HTTPError` whose `StatusCode` is the response status and whose `Body` is the first 4096 bytes of the response body, all of it when shorter, for which `errors.Is` with each sentinel of R-ZT58-6LYL is false.
- R-0GBB-G91S: `HTTPError.Error` MUST return `connections: unexpected HTTP response (status <code>)`, with `<code>` the decimal `StatusCode`.
- R-PY64-A45K: `ReconnectError.Error` MUST return a string beginning `connections: ` that contains the value of the `URL` field.
- R-0IR4-7SJ6: When `Token` returns a non-nil error, it MUST return the zero `Token`.
- R-0JZ0-LK9V: When the request `Token` sends fails before any response is received, `Token` MUST return an error that wraps that failure so that `errors.Is` and `errors.As` reach it, including `context.Canceled` or `context.DeadlineExceeded` when `ctx` ends first and a `*net.OpError` whose `Op` is `"dial"` when nothing accepts connections at `cfg.Service.Socket`, and for which `errors.Is` with each sentinel of R-ZT58-6LYL is false and `errors.As` finds neither a `*ReconnectError` nor an `*HTTPError`.
- R-7DJ4-L6KG: When a call receives a response whose body it does not return to its caller, it MUST close that body before it returns; so that a server answering a 500 whose body is 64 MiB sees its write fail once the call has returned.
- R-PVQB-IKO6: A `Client` MUST NOT follow a redirect: when the response to a request it sends has a 3xx status, whether or not it carries a `Location` header, the call MUST send no further request and MUST return an `*HTTPError` whose `StatusCode` is that status.
- R-0MET-D3R9: A `Client` MUST be safe for concurrent use: `Token` calls on the same `Client` from multiple goroutines MUST each behave as if made alone.
