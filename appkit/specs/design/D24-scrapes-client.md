# D24-scrapes-client

Package `scrapes` is the client a service on the host uses to read a scrapes run and its rows from the scrapes app, the suite's public-records collector. The scrapes app keeps each run of each scraper and the rows it collected, and answers its sibling read path on its unix socket with the identity headers of the caller: `GET /scrapers/<name>/current` for a scraper's current run, `GET /runs/<id>/record` for one run's record, and `GET /runs/<id>/rows` for every row of a run as a stream. This package speaks those three routes and nothing else: starting runs, filtering rows and the MCP tools stay with scrapes and the agents that call it. It holds no state of its own: every call is one request.

A `Client` is built from a `ClientConfig` naming the scrapes app's entry in the services file (D05) and the service's telemetry writer (D12). `NewClient` panics without the writer, as `telemetry.SiblingClient` and `mcp.NewServer` do; given one, it does no I/O and cannot fail. It reaches the app the way every sibling call does (D14): through `telemetry.SiblingClient` over `telemetry.SocketTransport` on the entry's `Socket`, at `http://<name>/` and the route's path, so every call is recorded as `sibling.called` and carries the caller in the call's context onto the request (D06). A client is safe for concurrent use.

## The answer

`Current` and `Record` answer a run record: a JSON object with `id`, `scraper` and `status`, `reason` when the run failed, `started` and, once it ended, `finished` (RFC 3339), the counts `rows`, `new`, `changed`, `unchanged` and `gone`, and its starter, `user` and `email` for a run an agent started or `trigger` for one cron started. Both return it as a `Run`, its times parsed into `time.Time` in UTC, so a caller compares instants rather than strings, and an absent member left empty or zero. The client checks no value: which statuses and reasons exist is scrapes' to say.

`Rows` answers newline-delimited JSON: each line, the bytes up to a `\n`, is one row, a common envelope (`scraper`, `run`, `source_id`, `collected`, `digest`, `name`, `names`, `address`, `lat`, `lon`, `people`, `facts`) plus `raw`, the record exactly as the source gave it. `Rows` decodes each line into a `Row` as it arrives and hands it to the caller's function, so a run of any size passes through without being held: a line is decoded once it has arrived, without waiting for the rest of the body, and no fixed limit caps a line's length. `Facts` keeps each fact's value and `Raw` the record as the bytes the line carries, for the caller to decode as it needs. A run that is not done holds no rows and answers an empty body, which `Rows` returns as no rows.

Members the client does not name are ignored, so scrapes may add one without breaking it. A 200 whose body is not that shape is an error of its own, neither a refusal nor an `*HTTPError`: the app answered and the answer is wrong. For `Rows` that error comes at the first line that is not a row, after every row before it has been handed over; a body that ends with bytes after its last `\n` is such an error too, since a line without its `\n` is a stream cut short. A stream that fails while being read, the connection closing or the context ending, returns that failure wrapped. When the caller's function returns an error, `Rows` stops and returns that same error, so the caller tells its own stop from the client's failures.

## Refusals

scrapes refuses by status, and its refusal bodies are copy, so the client never reads meaning from them:

- 404 is `ErrNotFound`: the scraper is not registered or has no current run, or the run is unknown or pruned.
- 503 is `ErrUnavailable`: scrapes' database is unreachable.

Anything else that is not a 200 is an `*HTTPError` holding the status and the first 4096 bytes of the body, as `mcp.HTTPError` (D10) does. A failure to reach the app at all, a missing socket or the caller's context ending, is returned wrapped so `errors.Is` and `errors.As` see the transport's own error.

## The request path

The scraper's name and the run's id are sent unescaped and unmodified: the request's URL path is `/scrapers/` followed by the name and then `/current`, or `/runs/` followed by the id and then `/record` or `/rows`, with no query, and Go's standard path encoding puts it on the wire. A name or id holding `/` therefore names a deeper path, and one holding `?` is sent with the `?` encoded in the path rather than starting a query; scrapes answers both 404, as it does an empty one. The client checks nothing about the name or the id itself: which exist is scrapes' to say.

Decisions recorded: the caller is forwarded by `telemetry.SiblingClient` from the call's context, not passed as an explicit argument as `mcp.Client` (D10) takes it, because a service calls from a handler whose context already holds the caller and the sibling client already forwards it; a second source of the caller could only disagree. The client sets no `X-Event-Cause` or `X-Event-Depth` header. It does not check a response's `Content-Type`: the read path is a trusted sibling on the host and its body decides. The `*HTTPError` type and its text mirror `mcp.HTTPError`. A response body is read no further than the client needs, at most its first 4096 bytes for an `*HTTPError`, and closed before the call returns, `Rows` included when it stops early. The client follows no redirect: a 3xx answer is an `*HTTPError`, and only one request is sent. `Rows` hands each row to a function rather than returning a slice or an iterator, so a run of any size streams through without being held and the body's life ends inside the call, and it returns the function's own error unwrapped so the caller can tell its own stop. Bytes after the last `\n` are an error, not a final row: scrapes ends every line with `\n`, so such a tail means the stream was cut short mid-line. A stream cut short exactly at a line boundary cannot change the 200 already sent and reads as complete; the run's `rows` count is the check, and a caller that must know compares the rows it was handed with it. Times are `time.Time` and counts `int64`, so a caller compares instants and sums counts without parsing.

## Consumer tasks

A service that reads public records, one that wants a scraper's latest finished run, reads the services file with `services.Read` at the path `services.Variable` names and finds the `scrapes` entry with `List.Find`. In its handler setup it builds `scrapes.NewClient(scrapes.ClientConfig{Service: entry, Telemetry: writer})`. Its handler calls `run, err := client.Current(r.Context(), "fmcsa")`, then `err = client.Rows(r.Context(), run.ID, func(row scrapes.Row) error { ... })`, reading each `row.SourceID`, `row.Name`, `row.Address.City`, `row.Lat`, `row.People`, `row.Facts` and `row.Raw` and counting the rows, and compares the count with `run.Rows` to learn whether the stream was cut short. A function that has seen enough returns its own sentinel stop error, and the handler tells it apart from the client's errors with `errors.Is(err, stop)`. A delivery handler reacting to a scrapes run event calls `rec, err := client.Record(ctx, id)` and reads `rec.Status`, `rec.Reason`, `rec.Finished` and the counts. On an error it checks `errors.Is(err, scrapes.ErrNotFound)` and `errors.Is(err, scrapes.ErrUnavailable)`, and `errors.As(err, &he)` with `he` a `*scrapes.HTTPError` to report the status; any other error is a malformed answer, a stream that failed, or a transport failure, and is the service's own internal failure.

A test serves a loopback HTTP server on a unix socket in its temporary directory, names that socket as the `Socket` of a `services.Entry`, builds a writer over the capturing sink (D12), and checks the request the server receives (method, path, query, host and identity headers) and what each call returns for each answer the server gives. To prove a row is handed over as it arrives, its server writes a line, flushes and waits on a channel the test's function closes. To prove the body is closed, its server answers a status that maps to `*HTTPError`, or a stream the function stops early, with a body far larger than the transport buffers and waits for its write to fail.
