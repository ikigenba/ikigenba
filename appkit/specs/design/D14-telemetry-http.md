# D14-telemetry-http

Two of the framework events (D11) come from HTTP traffic: a service records every request it serves, and every call it makes to a sibling. Package `telemetry` produces both, so no service author can leave a hop out of the trail. `telemetry.Middleware` wraps a service's whole handler tree and records each request it serves; `telemetry.SiblingClient` is the `*http.Client` a service calls a sibling with, and records each call. Both emit through the service's one `telemetry.Writer` (D12), and neither ever writes to standard error itself: an event the writer cannot deliver goes there by the writer's own rule.

## The request middleware

The middleware is the outermost layer of a service's handler tree, outside `identity.Require` (D06), so it sees every request, including the ones `Require` refuses and the pages that never go through `Require` at all (auth's sign-in pages, say). It therefore cannot take the caller from `identity.FromContext`; it reads the identity headers nginx set directly.

Every request gets a request id. nginx mints one and sets it on every proxied request; when a request arrives without one (a local run without nginx, a test) the middleware mints one in nginx's shape, 32 lowercase hex digits encoding 16 bytes read from the writer's random source (`Config.Rand`, D12), and sets it on the request as `X-Request-Id`, so `Require`, the handlers, and every sibling call downstream see the same id and no record is untraceable. An id that is present is used exactly as received. Should the random source fail, the middleware takes the 16 bytes from `crypto/rand` instead, which cannot fail: a request is never refused for want of an id, and a test that injects a known source knows the id in advance.

The middleware also puts the caller it read into the request's context with `identity.NewContext`, the user id empty when nginx sent none, so an event a handler emits with the request's context carries the request id and user even on a page `Require` does not guard. `Require`, inside it, replaces that caller with its own, which holds the same values. Because the middleware's caller may have an empty user id, only `Require` guarantees one; the `mcp` server checks for that (D07).

The middleware emits `request.started` before it calls the handler and `request.finished` after the handler returns. Two events rather than one at the end is deliberate: a start with no finish is evidence the process died mid-request. `request.started` carries the method and the URL path; the query is left out, because it can carry data and the trail carries metadata only (D11). `request.finished` carries the status the handler wrote and how long the handler took, in whole microseconds, measured with the writer's clock (`Writer.Now`, D12) read just before and just after the handler, so a test whose clock moves only inside its handler records exactly that movement. A handler that writes nothing has answered 200, as `net/http` answers for it. A handler that panics has its `request.finished` emitted with the status it wrote, or 500 when it wrote none, and the panic then continues unchanged, so `net/http`'s own recovery behaves as before; the trail still shows that the request finished.

The handler receives a response writer that records the status and otherwise passes everything through. It unwraps to the writer the middleware received, so `http.ResponseController` reaches flushing, hijacking, and deadlines on the real connection.

## The sibling client

A service calling a sibling on a caller's behalf must copy the caller onto the call (D06's forwarding rule) and must leave a record of the hop. `telemetry.SiblingClient` does both for every request sent through the `*http.Client` it returns. It takes the caller from the request's context with `identity.FromContext` and applies `identity.Forward` to the request it sends; a request whose context carries no caller is sent with its headers as they are. It then emits `sibling.called` naming the target service, the method, the URL path (no query), the status, and the duration of the exchange up to the response headers, measured with the writer's clock as the middleware measures a request. A call that fails before any response (a dial failure, a cancelled context) has the status 0, which no HTTP response carries, so a failed hop is told apart from every answered one. The client follows redirects as `http.Client` does, and each hop is a request of its own, recorded once.

The client changes nothing else: the base transport sends the request, and its response and error come back unaltered, so `errors.Is` and `errors.As` see the same failures they would without the client. That is what lets the gateway hand it to the `mcp` client as `ClientConfig.HTTPClient` (D10): the gateway's calls to backends are recorded, and the gateway still tells an unreachable backend from a timed-out one.

`target` is the service name the caller gives, normally the `Name` of the sibling's entry in the services file (D05). The client does not look the sibling up; reaching it is the base transport's job. `telemetry.SocketTransport` is the base transport for a sibling on this host: it connects every request to the unix socket at the path it is given, whatever the URL's host, so a service reaches a sibling at `http://<name>/<path>` over the `Socket` of its services-file entry. A test passes the transport of its own `httptest` server instead.

## Consumer tasks

An app wires its handler tree at start-up: it builds its writer (D12), builds its mux, wraps the mux in `identity.Require`, wraps that in `telemetry.Middleware` with the writer, and serves the result. A handler's domain events are emitted with the request's context and carry its request id and user.

A service calls a sibling: it reads the services file with `services.Read` at the path `services.Variable` names, finds the sibling's entry with `List.Find`, builds a client with `telemetry.SiblingClient(writer, entry.Name, telemetry.SocketTransport(entry.Socket))`, and sends a request to `http://<name>/<path>` whose context is the handler's request context.

The gateway builds an `mcp.Client` per backend with `ClientConfig.HTTPClient` set to such a client (D10), so every backend call is recorded as `sibling.called` and the backend's own trail shows the same request id.

A service's test serves its handler tree wrapped in `telemetry.Middleware` with a writer over the capturing sink (D12), sends requests with and without `X-Request-Id`, and asserts on the recorded `request.started`, domain, and `request.finished` events in order.

## REQUIREMENTS

- R-34A4-ETW4: Package `telemetry` MUST export `func Middleware(w *Writer, next http.Handler) http.Handler`, where `http` is the standard library's `net/http`.
- R-35I0-SLMT: Package `telemetry` MUST export `func SiblingClient(w *Writer, target string, base http.RoundTripper) *http.Client`.
- R-36PX-6DDI: Package `telemetry` MUST export `func SocketTransport(socket string) *http.Transport`.
- R-37XT-K547: `telemetry.Middleware` MUST panic, with a message that says the telemetry writer is nil, when `w` is nil.
- R-DU8E-LDJV: The request id of a request served by the handler `telemetry.Middleware` returns MUST be the request's first `X-Request-Id` value, unaltered, when that header is present and its first value is not empty, and otherwise the id R-DWO7-CX19 or R-DRSL-TU2H states.
- R-DWO7-CX19: For each request for which R-DU8E-LDJV requires a minted id, the handler `telemetry.Middleware` returns MUST make exactly one `io.ReadFull` call for 16 bytes from `w`'s random source (R-IWJD-FYZ4), and, when that call returns a nil error, the id MUST be `hex.EncodeToString` (the standard library's `encoding/hex`) of those 16 bytes; it MUST NOT read from that source for a request whose id R-DU8E-LDJV takes from the header.
- R-DRSL-TU2H: When the `io.ReadFull` call of R-DWO7-CX19 returns a non-nil error, the id MUST still be 32 lowercase hexadecimal digits, MUST NOT depend on any bytes that call read, and MUST differ between any two such requests, and the handler MUST otherwise serve the request exactly as it serves a request whose read succeeded.
- R-3BLI-PGCA: The handler `telemetry.Middleware` returns MUST call `next` exactly once for each request, with a request that has the incoming request's method, URL, headers, and body, except that, when the handler minted the request id, its `X-Request-Id` header MUST hold exactly one value, that id; and with a context derived from the incoming request's context, so the incoming context's values, deadline, and cancellation remain visible through it.
- R-E0BW-I89C: The context of the request `next` receives from the handler `telemetry.Middleware` returns MUST make `identity.FromContext` return true and the `Caller` whose `UserID` is the incoming request's first `X-User-Id` value (empty when absent), `Email` its first `X-User-Email` value (empty when absent), and `RequestID` the request id of R-DU8E-LDJV.
- R-E2RP-9RQQ: For each request, the handler `telemetry.Middleware` returns MUST emit through `w`, before it calls `next`, exactly one event named `request.started`, whose envelope request id is the request id of R-DU8E-LDJV, whose envelope user is the request's first `X-User-Id` value (empty when absent), and whose attributes are exactly `method`, the request's method, and `path`, the request's `URL.Path`.
- R-3GH4-8JB2: For each request, the handler `telemetry.Middleware` returns MUST emit through `w`, after `next` returns or panics and so after `request.started` and every event emitted during the call to `next`, exactly one event named `request.finished`, with the same envelope request id and user as that request's `request.started` and attributes exactly `status` and `duration_us`.
- R-3HP0-MB1R: The `status` attribute of a `request.finished` event MUST be, when the first of `next`'s calls to its response writer that is either a `Write` or a `WriteHeader` with a status code of 200 or above is such a `WriteHeader`, that status code; when it is a `Write`, 200; when `next` made neither call, 200 if `next` returned and 500 if it panicked.
- R-JJPG-PM2B: The `duration_us` attribute of a `request.finished` event MUST be `int64(t1.Sub(t0) / time.Microsecond)`, or 0 when that is negative, where `t0` is what one `w.Now()` call returns after the request's `request.started` is emitted and before `next` is called, and `t1` is what one `w.Now()` call returns after `next` returns or panics and before `request.finished` is emitted.
- R-3K4T-DUJ5: When `next` panics, the handler `telemetry.Middleware` returns MUST emit the `request.finished` event R-3GH4-8JB2 states and then panic with the value `next` panicked with.
- R-3LCP-RM9U: The status, headers, and body the handler `telemetry.Middleware` returns writes to its response writer MUST be exactly those `next` writes to the response writer it receives.
- R-3MKM-5E0J: An `http.ResponseController` made from the response writer `next` receives MUST reach the response writer the handler `telemetry.Middleware` returns was given, so its `Flush` flushes that writer.
- R-3NSI-J5R8: The handler `telemetry.Middleware` returns MUST be safe to serve concurrent requests from multiple goroutines, the events of each request carrying that request's own values.
- R-3P0E-WXHX: `telemetry.SiblingClient` MUST panic, with a message that says the telemetry writer is nil, when `w` is nil.
- R-3Q8B-AP8M: The `*http.Client` `telemetry.SiblingClient` returns MUST have a zero `Timeout` and nil `CheckRedirect` and `Jar`, and MUST send every request through `base`, or through `http.DefaultTransport` when `base` is nil, exactly once per request it sends.
- R-3RG7-OGZB: When `identity.FromContext` of a request's context returns true, the request the client `telemetry.SiblingClient` returns hands to its base transport MUST carry the `X-User-Id`, `X-User-Email`, and `X-Request-Id` headers exactly as `identity.Forward` sets them from that `Caller`; when it returns false, those headers MUST be as the request carried them; and in both cases the request MUST otherwise have the method, URL, other headers, body, and context of the request sent.
- R-3SO4-28Q0: The client `telemetry.SiblingClient` returns MUST NOT modify a request a caller sends through it, its headers included.
- R-3TW0-G0GP: For each request the client `telemetry.SiblingClient` returns hands to its base transport, the response and error the client's transport returns for it MUST be those the base transport returned, unaltered.
- R-3V3W-TS7E: For each request the client `telemetry.SiblingClient` returns hands to its base transport (each redirect hop included), the client MUST emit through `w`, after the base transport returns and before the client's transport returns, exactly one event named `sibling.called`, whose attributes are exactly `target`, equal to `target`; `method`, the request's method; `path`, the request's `URL.Path`; `status`; and `duration_us`.
- R-3WBT-7JY3: The `status` attribute of a `sibling.called` event MUST be the response's `StatusCode` when the base transport returned a nil error, and 0 when it returned a non-nil error.
- R-3YRL-Z3FH: The envelope request id and user of a `sibling.called` event MUST be the `RequestID` and `UserID` of the `Caller` that `identity.FromContext` returns for the request's context, and empty when it returns false.
- R-JM59-H5JP: The `duration_us` attribute of a `sibling.called` event MUST be `int64(t1.Sub(t0) / time.Microsecond)`, or 0 when that is negative, where `t0` is what one `w.Now()` call returns before the base transport's `RoundTrip` is called and `t1` is what one `w.Now()` call returns after it returns.
- R-417E-QMWV: The client `telemetry.SiblingClient` returns MUST be safe for concurrent use from multiple goroutines, the event of each request carrying that request's own values.
- R-E57I-1B84: The `*http.Transport` `telemetry.SocketTransport` returns MUST connect every request it sends whose URL has the scheme `http`, whatever the URL's host and port, to the unix-domain stream socket at `socket`, as given (a relative path resolves against the process working directory at the time of the connection), and MUST have a nil `Proxy`, so a request reaches that socket even when the environment variable `HTTP_PROXY` is set.
- R-DO4W-OIUE: `telemetry.SocketTransport` MUST return a non-nil transport and MUST NOT panic for any `socket`, nothing existing at that path when it is called included, and a request sent through the transport after a socket accepting connections is created at `socket` MUST reach that socket; when nothing accepts connections at `socket`, a request sent through the transport MUST fail with an error for which `errors.As` finds a `*net.OpError` whose `Op` is `"dial"`.
