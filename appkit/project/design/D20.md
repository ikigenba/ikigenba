# Decision 20 — Chain roots: the root-start helper, and the chassis's recorder reach

**Problem.** Two gaps sit between the recorder (D15) and the services that must
use it. First, **not all work has an inbound request to inherit a chain from**:
a cron tick, a run spawn, a gmail poll loop, a dropbox sync cycle, a wiki
pipeline pass. Each is the origin of a chain and must mint an id, install it on
the context everything downstream will use, and emit a `root` record. Left to
each service that is a five-line idiom copied nine times — precisely the drift
the chassis exists to end, and the suite contract names appkit as the owner of
the helper. Second, a service's domain code has **no way to reach the recorder
at all**: `runServe` constructs it, but `*appkit.Router` — the seam every
service's `Handlers` hook gets — exposes `DB()`, `Logger()`, `Service()`,
`Version()`, `WWW()` and no recorder, so every outbound client a service builds
could only pass `Recorder: nil` and the outbound blind spot (D19) would survive
the work meant to close it.

**Decision.**

**(a) The root-start helpers** live on the recorder, in `appkit/telemetry`:

```go
// StartRoot begins a NEW chain: it mints a fresh correlation id (ignoring any
// id ctx already carries), installs it on the returned context, and records a
// `root` record with the caller's op. Use it at a true origin — a timer tick,
// a poll/watch/sync cycle, a daemon pass — where inheriting an ambient chain
// would wrongly attribute the work to whatever ran before it.
//
// One call per CYCLE, not per item: everything one cycle causes shares one
// chain. detail may be nil.
func (r *Recorder) StartRoot(ctx context.Context, op string, detail map[string]any) (context.Context, string)

// StartChain marks a named origin WITHIN a possibly-existing chain: it adopts
// ctx's correlation id when it already carries one (correlation.Ensure
// semantics) and mints only when it does not, then records a `root` record
// with the caller's op either way. Use it where the work has a name worth
// recording as an origin but may have been caused by a request — a run spawn
// reached through an MCP tool call, a consumer delivery.
func (r *Recorder) StartChain(ctx context.Context, op string, detail map[string]any) (context.Context, string)
```

Both are **nil-safe on a nil `*Recorder`**: they still mint and install the id
and return it, they simply record nothing — so a service's correlation
behavior never depends on whether telemetry is enabled. The `op` is the
caller's (`cron:tick/<name>`, `run:<run-id>`, `gmail:poll-cycle`,
`dropbox:sync-cycle`); appkit fixes the mechanism, never the vocabulary.

The choice rule, stated once here so nine services do not each decide it:
**`StartRoot` when the work has no cause outside itself; `StartChain` when it
might.**

**The `op` vocabulary.** A forensic agent greps on `op`, so nine services
picking nine spellings would make root records unsearchable as a class. appkit
does not validate the string (the chassis fixes mechanism, not vocabulary), but
the convention every caller follows is **`<service>:<origin>`**, matching the
event plane's own `<source>:<kind>/<subject>` shape:

| origin | `op` |
|---|---|
| a cron tick | `cron:tick/<name>` |
| a run spawn (prompts, scripts) | `run:<run-id>` |
| a background poll/watch/sync cycle | `<service>:<cycle-name>` — `gmail:poll-cycle`, `dropbox:sync-cycle`, `wiki:pipeline-cycle` |
| a consumer delivery that carried no chain | the routing key, `<source>:<kind>/<subject>` (chassis-emitted, D18) |

The first two are fixed by the suite contract; the third is the shape this
Decision settles for the cycle case. The normative home of the vocabulary is
the suite protocol document — this table is appkit's statement of what its
helper's callers pass, not a competing authority.

**(b) `Router.Recorder()`** exposes the serve-wired recorder to service code:

```go
// Recorder returns the telemetry recorder appkit wired at serve, so a service
// hands it to the domain objects it builds (an outbound client, a background
// worker). It is nil when telemetry is disabled; every Recorder method is
// nil-safe, so callers need no check.
func (rt *Router) Recorder() *telemetry.Recorder
```

`server.Options` already carries the recorder (D17); this is its accessor,
mirroring `DB()`. A service captures it in `Handlers` exactly as it captures
`rt.DB()` today, and hands it to a `Spec.Workers` worker or a `Spec.Producer`
injection — which is how a background worker with no inbound request reaches it.

**(c) `Router.HTTPClient(timeout)`** is the one-liner for the eight outbound
services, so most of them never name `appkit/telemetry` at all:

```go
// HTTPClient returns an instrumented outbound client (D19) already wired to
// this service's recorder, with the given timeout. Equivalent to
// httpclient.New(httpclient.Options{Recorder: rt.Recorder(), Timeout: timeout}).
// A service needing a custom transport or redirect policy calls
// httpclient.NewTransport directly instead.
func (rt *Router) HTTPClient(timeout time.Duration) *http.Client
```

**(d) `Spec.Config` gets no recorder.** It runs before the serve wiring exists
and is a construction-validation hook; a client built there passes
`Recorder: nil` and records nothing, which is correct — no chain exists yet.

**Judgment calls recorded.** (a) Two helpers rather than one flag argument: the
mint-vs-adopt choice is a real semantic difference and a boolean at the call
site reads as noise. (b) Both are recorder methods rather than package
functions, so the recorder reaches them without a global. (c) `Recorder()` and
`HTTPClient()` are both sealed: `HTTPClient` keeps the common case to one line
and `appkit/telemetry` out of most services' imports, while `Recorder()` is
unavoidable for the services that emit their own records (cron, scripts,
prompts). (d) Nil-safety extends to the helpers, so disabling telemetry never
changes correlation behavior — only whether it is recorded.

**Rejected.**
- **Leaving the root idiom to each service** — nine copies of mint + install +
  record, drifting on op format and on whether the id is installed before or
  after the work starts.
- **A package-level default recorder (`telemetry.Default`)** — a global that
  makes tests order-dependent and two services in one test binary impossible.
- **Only `Recorder()`, no `HTTPClient()`** — every outbound service would
  import `appkit/telemetry` solely to name a type in a constructor argument.
- **Only `HTTPClient()`, no `Recorder()`** — cron, scripts, and prompts must
  emit their own `root` records and cannot do it through an HTTP client.
- **Passing the recorder into `Spec.Handlers` as a second argument** — changes
  a signature every service already implements, to deliver what an accessor on
  the seam they already hold delivers additively.
- **One helper with `correlation.Ensure` semantics only** — a poll cycle that
  happened to be triggered from a request would silently join that request's
  chain, attributing an hour of background work to one user action.

**Verification** (records observed at a **live in-process HTTP sink**, and the
outbound claim against a **live** `httptest` peer — a stub recorder cannot
falsify that the accessor returns the *serve-wired* recorder rather than a
fresh one).
- R-XP15-H34E — `StartRoot` on a context **already carrying** a valid
  correlation id returns a **different**, valid id, installs it on the returned
  context, and emits exactly one `root` record carrying the new id and the
  caller's `op` — a build that adopts the ambient id fails this.
- R-XQ91-UUV3 — `StartChain` on a context carrying a valid id returns **that
  same** id and emits one `root` record carrying it; on an uncorrelated context
  it returns a fresh valid id and emits one `root` record carrying that — one
  record in both cases, never zero and never two.
- R-XRGY-8MLS — both helpers called on a **nil** `*Recorder` return a context
  whose `correlation.FromContext` is non-empty and `correlation.Valid`, do not
  panic, and produce no records — correlation survives telemetry being off.
- R-XSOU-MECH — a record emitted through `rt.Recorder()` from inside a
  `Handlers` hook on a server built by the real serve wiring arrives at the live
  sink that serve's recorder posts to — proving the accessor returns the wired
  recorder, not a fresh unwired one (which would deliver nothing).
- R-XTWR-0636 — `rt.HTTPClient(3*time.Second)` returns a client whose
  `Timeout` is exactly 3s and whose real request to a live `httptest` peer
  produces an `outbound` record at the live sink — a build returning a bare
  `http.DefaultClient` fails both halves.
