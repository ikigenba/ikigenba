# Decision 15 — The `appkit/telemetry` recorder: bounded ring, batched fire-and-forget ingest, recorder-stamped identity

**Problem.** Every service must ship telemetry records to the telemetry
service's ingest endpoint, and the one absolute constraint is that **telemetry
being down never blocks, errors, or crashes anything**. A synchronous POST per
tool call would put a network round-trip on the hot path and a dead sink would
stall every request. The chassis needs one shared, bounded, asynchronous sink
that degrades to silence. The record's identity (`id`) and observation time
(`time`) must additionally be assigned exactly once, by one authority: a field
that every instrumentation site across fifteen services must remember to set is
a field that will eventually be missing or wrong, and the ingest protocol
rejects a record whose `id` is not a 26-character Crockford ULID.

**Decision.** A new package `appkit/telemetry` owns the recorder. It is a
value a service never constructs itself: `runServe` builds one and wires it
into the middleware chain, the MCP handler, the lifecycle records, the
eventplane hooks, and the outbound client.

```go
package telemetry // appkit/telemetry

// Options configures a Recorder. Zero values take the documented defaults.
type Options struct {
    Service   string        // recording service name (spec.App)
    IngestURL string        // default: registry.BaseURL("telemetry") + "/ingest"
    Enabled   bool          // false ⇒ Record is a no-op and no HTTP is ever done
    Capacity  int           // ring capacity, default 4096
    BatchMax  int           // max records per POST, default 256
    FlushEvery time.Duration // default 1s
    Client    *http.Client  // default: 2s-timeout client, never the shared instrumented one
    Logger    *slog.Logger
    Now       func() time.Time // default time.Now; source of each accepted record's time
    NewID     func() string    // default logging.NewULID; mints each accepted record's id
}

type Recorder struct{ /* ring, mutex, dropped counter, flush loop */ }

func New(opts Options) *Recorder

// Record enqueues r, stamping its wire identity and time at acceptance. It
// NEVER blocks on I/O and NEVER returns an error: a full ring drops the OLDEST
// record and increments the dropped counter. Safe for concurrent use; safe on
// a nil *Recorder (a no-op), so instrumentation sites need no nil checks.
func (r *Recorder) Record(rec Record)

// Start launches the flush loop until ctx is cancelled.
func (r *Recorder) Start(ctx context.Context)

// Close stops the loop and makes one final best-effort flush attempt of
// everything buffered, bounded by its own short timeout. It returns nil always.
func (r *Recorder) Close(ctx context.Context) error
```

- **The recorder owns record identity and time.** The caller-facing `Record`
  (D16) carries **no `id` and no `time` field** — they are not expressible by
  an instrumentation site, so a missing, malformed, or duplicate id is
  impossible by construction. At the moment `Record` accepts an entry it stamps
  an internal **wire envelope** with `id` = `NewID()` (default
  `logging.NewULID`, a 26-character Crockford ULID per D14) and `time` =
  `Now().UTC()` (marshalled RFC3339Nano). Stamping happens at **acceptance,
  not flush**: flush time is transport, not observation, and a batch stamped at
  flush would erase intra-batch ordering. `Now`/`NewID` are injected seams for
  deterministic tests, following the existing `Client`/`Logger` pattern.
- **Ring buffer, drop-oldest.** Capacity 4096 records. When full, the oldest
  record is discarded (the newest data is the data a forensic agent is
  chasing) and a `dropped` counter increments.
- **Batching.** The flush loop wakes every `FlushEvery` (~1s), or immediately
  when the buffer reaches `BatchMax`, and POSTs
  `{"records":[…]}` — at most 256 records — to `IngestURL`. When the counter is
  non-zero the body carries `"dropped": N`; the counter is cleared **only on a
  successful (2xx) POST**, so a drop is reported exactly once and is never lost
  to a failed flush.
- **Fire-and-forget.** A non-2xx response, a transport error, or a timeout is
  logged at debug and the batch is **discarded** (not retried, not re-queued):
  retry queues are how a best-effort sink turns into a memory leak. No error
  ever propagates to the caller.
- **Config.** `appkit/config` gains two resolved fields on `Config`, read in
  `Resolve` from the **unprefixed** suite-wide env vars (matching
  `OUTBOX_RETENTION_DAYS` / `TELEMETRY_RETENTION_DAYS`, not the `<APP>_` idiom —
  the ingest endpoint is one suite-wide address, not per-service):
  - `TelemetryIngestURL` — `TELEMETRY_INGEST_URL`, defaulting to
    `registry.BaseURL("telemetry") + "/ingest"`, which resolves to
    `http://127.0.0.1:3008/ingest`. Deriving from `registry` rather than
    hard-coding keeps the port table the single source of the address.
  - `TelemetryEnabled` — `TELEMETRY_ENABLED`, default **true**; the values
    `0`/`false`/`no` (case-insensitive) disable recording entirely.
- **The recorder's own HTTP client is a plain `http.Client`,** never the
  instrumented client of D19 — recording the recorder is an infinite regress.

**Judgment calls recorded.** (a) The default ingest URL is derived from
`registry.BaseURL("telemetry")` instead of the literal string, so the contract
value `http://127.0.0.1:3008/ingest` has exactly one home. (b) Env vars are
unprefixed and suite-wide. (c) `Record` is nil-safe so every instrumentation
site is unconditional. (d) Failed batches are dropped rather than retried.
(e) Identity and time are stamped by the recorder at acceptance, never
supplied by callers — one writer per field, enforced by the type system.

**Rejected.**
- **A per-record goroutine POST** — unbounded goroutines under load and no
  batching; a dead sink accumulates them until the box dies.
- **A blocking bounded channel** — back-pressures the request path, which is
  precisely the failure mode the capability forbids.
- **Drop-newest on a full ring** — loses the most recent (most relevant) trail
  exactly when the system is busiest.
- **On-disk spooling** — durable telemetry is not the promise; the record is
  best-effort by contract and a spool adds a second storage system to every
  service.
- **`<APP>_TELEMETRY_INGEST_URL`** — fifteen names for one address.
- **Caller-supplied `id`/`time` (including fill-if-empty)** — two writers for
  one field makes the invariant conditional: every instrumentation site becomes
  a potential source of missing or malformed identity, and the ingest endpoint
  the only place the mistake surfaces. Determinism for tests belongs in the
  injected `Now`/`NewID` seams, not in a production-writable field.
- **Stamping at flush time** — a whole batch would share one timestamp,
  erasing intra-batch ordering; observation time is when the fact was recorded,
  not when it was shipped.

**Verification** (driven against a **real in-process HTTP sink** —
`httptest.NewServer` — because "the records actually arrive over loopback HTTP",
"a dead sink does not block", and "every arriving record is protocol-valid" are
precisely the claims a stub sink cannot falsify).
- R-1AU5-EUU8 — with `Capacity` 4096 and the flush loop stopped, enqueuing
  4096+64 records, each carrying a distinguishing `op`, leaves the ring holding
  the **newest** 4096: the 64 oldest ops are absent and the newest is present —
  a drop-newest build fails this.
- R-1C21-SMKX — records enqueued against a live `httptest` sink arrive at that
  sink as `POST` bodies of the form `{"records":[…]}` with every enqueued `op`
  present and **no batch carrying more than 256 records**, when 1000 records
  are enqueued.
- R-1D9Y-6EBM — after N records are dropped, the **next successful** batch body
  carries `"dropped": N`, and the batch after that carries no `dropped` field
  (the counter cleared exactly once).
- R-1EHU-K62B — with the sink a **closed** listener (connection refused), 5000
  `Record` calls all return, the whole loop completes well under a second, no
  error surfaces, and a subsequent live sink still receives records — the
  drop-not-block claim, exercised against a real refused TCP connection.
- R-1FPQ-XXT0 — `Close` delivers records still buffered at shutdown to a live
  sink before returning (a record enqueued immediately before `Close` is
  observed by the sink, matched by its `op`), and returns nil.
- R-1GXN-BPJP — config resolution: with no env set, `Config.TelemetryIngestURL`
  equals `registry.BaseURL("telemetry")+"/ingest"` (i.e.
  `http://127.0.0.1:3008/ingest`) and `TelemetryEnabled` is true;
  `TELEMETRY_INGEST_URL` overrides the URL; `TELEMETRY_ENABLED=false`
  (case-insensitive) resolves `TelemetryEnabled` to false.
- R-PTNV-XRYV — a recorder constructed with `Enabled: false` performs **zero**
  requests against a live sink no matter how many records are enqueued — a
  recorder that flushes despite being disabled fails this.
- R-PKUI-T1UT — with default options, 1000 records enqueued against a live
  sink arrive with every record's `id` matching `^[0-9A-HJKMNP-TV-Z]{26}$` and
  all ids **pairwise distinct** — a recorder that omits ids, reuses an id, or
  emits a non-Crockford id fails this.
- R-PNAB-KLC7 — every record arriving at a live sink carries a `time` that
  parses as RFC3339Nano with a `Z` offset and lies within the UTC wall-clock
  window the test captured immediately before and after enqueueing — a zero
  time, a non-UTC offset, or an unstamped field fails this.
- R-POI7-YD2W — with `Options.Now` pinned to a fixed instant and
  `Options.NewID` a deterministic sequence, records arriving at a live sink
  carry exactly that instant and exactly that sequence of ids in enqueue
  order — proving the injected seams, not wall-clock accident, control the
  stamps.
