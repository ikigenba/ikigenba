# Decision 16 — The record shape and the capture-under-threshold param encoder

**Problem.** A telemetry record must be rich enough to reconstruct a chain and
poor enough that it never becomes a second copy of the suite's data. Two
failure modes have to be impossible **by construction**, not by discipline: a
raw header dump or raw body leaking secrets into the store, and a large payload
inflating every record. The suite contract fixes the record's fields, the size
thresholds, and the elision representation; appkit owns their Go shape.

**Decision.** `appkit/telemetry` declares the record as an **allowlist** — a
struct with exactly the contract's fields and no escape hatch for arbitrary
maps, so a field can only appear because an instrumentation site chose it.

```go
package telemetry // appkit/telemetry

type Kind string

const (
    KindEdge      Kind = "edge"
    KindRequest   Kind = "request"
    KindOutbound  Kind = "outbound"
    KindPublish   Kind = "publish"
    KindConsume   Kind = "consume"
    KindRoot      Kind = "root"
    KindLifecycle Kind = "lifecycle"
)

type Actor struct {
    OwnerEmail string `json:"owner_email,omitempty"`
    ClientID   string `json:"client_id,omitempty"`
}

type Outcome struct {
    Status     string `json:"status,omitempty"`   // "ok" | "error" | an HTTP status
    Error      string `json:"error,omitempty"`    // error CLASS, never a raw message body
    DurationMS int64  `json:"duration_ms"`
    Bytes      int    `json:"bytes,omitempty"`    // response body size
    SHA256     string `json:"sha256,omitempty"`   // lowercase hex digest of that body
}

type Record struct {
    ID            string         `json:"id"`             // logging.NewULID()
    Time          time.Time      `json:"time"`           // RFC3339Nano, UTC
    CorrelationID string         `json:"correlation_id,omitempty"`
    Service       string         `json:"service"`
    Kind          Kind           `json:"kind"`
    Actor         *Actor         `json:"actor,omitempty"`
    Op            string         `json:"op"`
    Params        map[string]any `json:"params,omitempty"`
    Outcome       *Outcome       `json:"outcome,omitempty"`
    Detail        map[string]any `json:"detail,omitempty"` // small kind-specific extras only
}
```

`Time` marshals RFC3339Nano in UTC (the recorder stamps `time.Now().UTC()`).
`CorrelationID` is empty only for `lifecycle`. There is **no** field for headers
and **no** field for a response body: response content is represented solely by
`Outcome.Bytes` + `Outcome.SHA256`, which is also what keeps show-once secrets
out of the store by construction.

**Digests.**

```go
// Digest returns the byte length and the lowercase-hex SHA-256 of b.
func Digest(b []byte) (int, string)
```

**The param encoder.** Structured arguments are captured under two thresholds
from the suite contract — per-value **1024 bytes**, per-record **8192 bytes**,
both measured on the compact JSON encoding:

```go
// EncodeParams renders raw tool/request arguments under the capture policy.
// sensitive names are ALWAYS elided regardless of size. Non-object or
// unparseable input yields a single {"$elided":…} entry under the key "params".
func EncodeParams(raw json.RawMessage, sensitive []string) map[string]any
```

Algorithm, in order:
1. Unmarshal into `map[string]any`. On failure, elide the whole thing.
2. For every key named in `sensitive`, replace the value with its elision
   marker — **before** any size test, so a two-byte API key is still elided.
3. For every remaining value whose compact JSON encoding exceeds **1024**
   bytes, replace it with its elision marker.
4. While the compact encoding of the whole map exceeds **8192** bytes, elide
   the **largest remaining** non-elided value, repeatedly, until it fits.

The elision marker replaces the value **in place**, preserving the key:

```json
{"$elided": {"bytes": 40312, "sha256": "<64 lowercase hex chars>"}}
```

`bytes` is the length of the value's own compact JSON encoding and `sha256` is
the digest of exactly those bytes, so two records that elided the same value
carry the same digest — this is what makes the telemetry service's
"where else did these bytes appear" search work across services.

**Judgment calls recorded.** (a) Elision is per-value and in place, never a
whole-params replacement, so the *shape* of a call stays legible even when its
payload does not fit. (b) Ties in step 4 (equal encoded sizes) are broken by
key name ascending, so the encoder is deterministic and testable. (c) Params
that are not a JSON object at all (an array, a string) are elided wholesale
under the key `params` rather than dropped, so the record still shows that
arguments existed and how large they were.

**Rejected.**
- **`map[string]any` as the record type** — an allowlist that anything can add
  a key to is not an allowlist; the struct is the enforcement.
- **Truncating oversized values instead of eliding** — a truncated secret is
  still a leaked secret prefix, and a prefix does not support digest search.
- **A global params budget applied by dropping keys** — loses which arguments
  were passed, which is the single most useful forensic fact about a call.
- **Hashing every value regardless of size** — costs a digest per argument on
  the hot path for values whose literal is already cheaper to store.

**Verification** (pure functions over real `encoding/json` and real
`crypto/sha256` — the substrate is the actual encoder and hash, not a stand-in).
- R-1I5J-PHAE — a fully populated `Record` marshals to JSON carrying exactly
  the contract keys (`id`, `time`, `correlation_id`, `service`, `kind`,
  `actor`, `op`, `params`, `outcome`, `detail`) and **no others**; a `Record`
  with empty optional fields omits `correlation_id`, `actor`, `params`,
  `outcome`, and `detail`; `time` marshals as RFC3339Nano with a `Z` offset.
- R-1JDG-3913 — a param value whose compact JSON encoding is 2000 bytes is
  replaced by `{"$elided":{"bytes":2000,"sha256":…}}` where `bytes` equals that
  exact encoded length and `sha256` equals the independently computed SHA-256
  of those exact bytes; a value of 1024 bytes is **kept literally** (the
  threshold excludes only what exceeds 1024, not what merely approaches it).
- R-1LT8-USIH — given four values of encoded sizes ~5000, ~4000, ~200, ~100
  (each under 1024 except the first two), the encoded map ends **≤ 8192 bytes**
  with the two largest elided and the two smallest present verbatim — a build
  that elides everything, or elides in map order, fails this.
- R-1N15-8K96 — a param declared sensitive is elided even when its encoded
  value is 3 bytes, while an undeclared sibling of the same size is kept
  literally.
- R-1O91-MBZV — `Digest` returns the exact byte length and a 64-character
  lowercase-hex digest matching `crypto/sha256` over a fixed known input
  (uppercase hex or a truncated digest fails), and every `sha256` an elision
  marker carries matches `^[0-9a-f]{64}$`.
