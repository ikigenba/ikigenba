# Decision 21 — Adopt the suite testing-language contract

**Decision.** appkit adopts the suite's testing-language contract, `root
project/design/D23.md`, by citation. That contract owns the four test layers
(**hermetic / composed / live / manual**) and what each may touch, the single
mechanism for live tests (`//go:build live`, invoked as `go test -tags live
./...`, hard-failing on absent credentials), the ban on `t.Skip` outside
live-tagged files, and the requirement that every tree declare its own testing
facts in its `AGENTS.md`. This Decision restates none of that. It records only
the appkit-specific facts the contract asks this tree to declare, and adopts the
contract's two per-service ids.

**The layers appkit has.** appkit is the chassis library, not a deployable
service, and its suite spans three of the four layers:

- **hermetic** — the bulk of the suite: `appkit/config` over injected `getenv`
  maps, `appkit/web` over `t.TempDir()` roots, `appkit/db` and `appkit/feed`
  over real `t.TempDir()` SQLite databases through the real migration runner,
  `appkit/mcp` and `appkit/server` through `net/http/httptest`, and
  `appkit/telemetry` / `appkit/httpclient` against `httptest` sinks and a
  genuinely closed TCP port.
- **composed** — the boot smoke in `appkit_test.go`: it writes a minimal
  chassis-based service into `t.TempDir()`, `go build`s it, runs the resulting
  binary's `serve` verb, and reaches its `health` over a loopback address.
  A chassis library's "own real binary" is a service composed on it, so this is
  a composed boot smoke rather than a hermetic fixture subprocess — it exercises
  the real `Main` → verb dispatch → listener path end to end.
- **manual** — `project/appkit-verification.md`, the committed live-box runbook
  the operator runs against `int.ikigenba.com` for the two design ids whose
  pass-predicate only the deployed suite can express.

appkit has **no live layer**: it touches no external service and reads no
credential, so no `//go:build live` file exists here and the `-tags live`
invocation is not part of this tree's testing story. Adding one later is a
Decision, not a drift.

**GOWORK mode.** appkit tests and vets in **workspace mode** through the
repo-root `go.work`, and additionally carries an **isolated build check**,
`GOWORK=off go build ./...`, that mirrors the deterministic production build and
proves the module resolves standalone through its committed `replace` directives.
Both are already stated in this design's *Conventions*; the contract's
declaration requirement is what makes them `AGENTS.md`-visible.

**Environmental preconditions beyond the Go toolchain.** appkit has one: the
composed boot smoke shells out to `go build` **at test time**, so the `go`
binary must be on `PATH` in the test process's environment (not merely the
toolchain that compiled the tests), and the module cache must already resolve
appkit's `replace` siblings — the smoke does no network fetch and must not
acquire one. This is a hard failure when absent, never a skip.

**Where this lands.** Nothing in appkit's source changes. The adoption is
carried by two tagged tests and by the `AGENTS.md` Tests section stating the
facts above; the plan phase that realizes this Decision does both.

**Rejected.**

- *Restating the layer definitions, the live-tag mechanism, or the skip ban in
  this design.* Citation is the mechanism (`$ikispec`, "cite, never restate"): a
  local copy of a suite contract is drift by construction the moment the
  umbrella moves. This file names only what is particular to appkit.
- *Re-minting local ids for the two behaviors.* The umbrella marks
  R-O1AD-MRKW and R-O2IA-0JBL `[proof: per-service]`; citing those exact ids is
  the adoption, and a fresh local id would be a second handle for one behavior.
- *Declaring the boot smoke hermetic on the strength of the contract's
  "a compiled fixture" allowance.* The smoke builds and runs a real chassis
  service and drives it over loopback HTTP — the contract's own description of
  composed. Filing it as hermetic would make the layer label describe the
  fixture's provenance instead of what the test touches.
- *Treating appkit as exempt from the per-service ids because it is a library.*
  This design's *Conventions* correctly say appkit never adopts a per-service
  **behavioral** contract on a service's behalf. These two ids are different in
  kind: they prove facts about **this tree's own** committed `AGENTS.md` and
  **this tree's own** test sources, which exist here and nowhere else.

**Verification.**

- R-O1AD-MRKW — cited from `root project/design/D23.md` (`[proof:
  per-service]`); adopted here. A test reads appkit's committed `AGENTS.md` from
  disk and asserts its Tests section declares the default-gate test command, the
  layers present in this tree's contract vocabulary, every environmental
  precondition beyond the Go toolchain, and the tree's GOWORK mode. Substrate:
  hermetic (real committed file read from disk).
- R-O2IA-0JBL — cited from `root project/design/D23.md` (`[proof:
  per-service]`); adopted here. A source scan over appkit's `*_test.go` files,
  excluding files carrying the `live` build constraint, finds **zero**
  occurrences of `t.Skip`, `t.Skipf`, or `t.SkipNow`. The scan assembles its
  needle from parts so it never matches itself. Substrate: hermetic (source
  scan).
