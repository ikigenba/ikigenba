# Decision 18 — Lifecycle records and event-plane hop recording in `serve`

**Problem.** Two parts of the chain have no HTTP request behind them. A
service's **boot and shutdown** are invisible to request instrumentation, yet
they are what bounds a forensic timeline: without them a crash is
indistinguishable from an idle period, and a deploy is invisible. And an
**event-plane hop** — a service appending an event, another consuming it — is
the suite's main asynchronous causal edge, but eventplane must never import
appkit, so the recording cannot live inside eventplane.

**Decision.** `runServe` is the single wiring point for both.

**(a) Lifecycle.** `runServe` constructs the recorder immediately after
resolving config and starts its flush loop on the serve context. It then emits:

- at boot, before `ListenAndServe`: `kind` `lifecycle`, `op` `start`,
  `detail` `{"version": versionString()}` — the same
  `<version> (<commit>)` string `appkit.versionString()` builds from the
  `-ldflags`-stamped `appkit.version` / `appkit.commit`, which is exactly what
  makes a deploy or rollback legible as a version change between two starts;
- on graceful shutdown, after `runServerAndWorkers` returns and **before**
  `Close`: `kind` `lifecycle`, `op` `stop`, no `detail`;
- then `recorder.Close(ctx)`, which makes the final best-effort flush so the
  `stop` record leaves the process.

Both carry an empty `correlation_id` — the only kind permitted to. A crash
produces no `stop` record; the next `start` bounds the gap, which is the
intended semantics, not a gap in coverage.

**(b) Event-plane hops.** eventplane owns the seam: `eventplane/observe`
declares `observe.Hook` and the skeleton `observe.Event` handed to it, and
`outbox.Options` / `consumer.Config` each accept one (see
`project/research/research.md`). appkit supplies **one** hook closure over the
recorder, wired at both ends, so the dependency arrow stays eventplane ← appkit:

```go
// in runServe, over the constructed recorder
hook := func(ctx context.Context, ev observe.Event) {
    rec.Record(telemetry.Record{
        Kind:          kindFor(ev.Hop),   // HopPublish → publish, HopConsume → consume
        Op:            ev.Key(),          // <source>:<kind>/<subject>
        CorrelationID: ev.CorrelationID,
        Outcome: &telemetry.Outcome{
            Status:     statusFor(ev.Err),  // "ok" | "error"
            Error:      classFor(ev.Err),   // a class, never the raw message
            DurationMS: ev.Duration.Milliseconds(),
        },
        Detail: detailFor(ev),            // {"event_id": …} when non-empty
    })
}
```

wired into `feed.Options` (which passes it to `outbox.Options`) for the publish
side and into each `consumer.Config` for the consume side. The hook body only
calls `Recorder.Record`, which never blocks and never errors, honoring
eventplane's "must not block" contract; eventplane additionally recovers from a
panicking hook, so observation can never affect delivery.

**(c) The consumer root record.** An event delivered with no correlation id is
a chain origin, and the suite contract requires a `root` record for it. The
`observe` hook cannot supply that fact — it reports only the id the handler
context ended up with, never whether it was propagated or minted — but appkit
does not need it to: appkit **builds the consumer's handler** in
`buildConsumerWorkers`, and the delivered `consumer.Event.CorrelationID` carries
the **wire** fact verbatim (eventplane never synthesizes it; `""` means the
event genuinely carried no chain). So the chassis wraps each declared
consumer's handler:

```go
inner := entry.Handler(rt)
handler := func(ctx context.Context, ev consumer.Event) error {
    if ev.CorrelationID == "" {
        // eventplane already minted the root onto ctx; name the origin.
        ctx, _ = rec.StartChain(ctx, routing.Key(ev.Source, ev.Kind, ev.Subject), nil)
    }
    return inner(ctx, ev)
}
```

`StartChain` (D20) adopts the id eventplane minted onto the handler context
rather than minting a second one, and emits the `root` record. A correlated
event gets no `root` record — it is not an origin.

**Judgment calls recorded.** (a) The `stop` record is emitted before `Close`
rather than being synthesized by the telemetry service, so a clean shutdown is
self-reported. (b) The lifecycle version comes from `versionString()` (version
+ commit) rather than the bare `version`, so an ad-hoc dirty build is
distinguishable from a released one. (c) One hook closure serves both hops,
switching on `ev.Hop`, rather than two near-identical builders. (d) The
consumer `root` record is driven from the **handler wrapper**, not the observe
hook, because only the wrapper sees the wire correlation id; the hook stays a
pure recorder of hops.

**Rejected.**
- **eventplane recording its own hops** — would force `eventplane → appkit`,
  inverting the dependency the whole chassis rests on.
- **Emitting `stop` from a `defer` in `Main`** — the recorder is already closed
  by then, and `os.Exit` paths skip defers.
- **A synthetic "service went away" record written by the telemetry service** —
  guesses a fact instead of recording one, and cannot distinguish a graceful
  stop from a crash, which is the exact distinction the pair exists to draw.
- **Treating a missing correlation id on an envelope as an error** — legitimate
  producers exist that were never on a request path; eventplane's mint-on-absence
  onto the handler context is the designed answer, and the chassis names the
  origin rather than re-minting.
- **Asking eventplane to flag "this id was minted" on `observe.Event`** — a
  cross-workspace change to a settled seam, for a fact the handler wrapper
  already has verbatim in `consumer.Event.CorrelationID`.
- **Minting the consumer root id in the wrapper instead of adopting
  eventplane's** — two ids for one delivery, with the handler running under one
  and the record naming the other.

**Verification** (against real substrates: a live in-process HTTP sink for the
records, and a real `t.TempDir()` SQLite database with a real `feed.Start`
SSE feed for the hops — the same substrate D10/D11 use, because delivery and
envelope carriage are exactly the claims a stub cannot falsify).
- R-1WSC-AQ6Q — a `serve` run against a live sink delivers a record with
  `kind` `lifecycle`, `op` `start`, empty `correlation_id`, and
  `detail.version` equal to the binary's `versionString()` (a build stamped
  with a known version/commit shows that exact string).
- R-1Y08-OHXF — cancelling the serve context makes the live sink receive a
  `lifecycle`/`stop` record **before** `serve` returns, and both the `start`
  and the `stop` record are present at the sink — a build that closes the
  recorder before emitting `stop` fails this.
- R-1Z85-29O4 — appending an event through the real producer outbox on a real
  SQLite database records `kind` `publish` with `op` equal to the routing key
  `<source>:<kind>/<subject>` and `correlation_id` equal to the id on the
  append context.
- R-20G1-G1ET — consuming that event through a real `feed.Start` SSE feed
  records `kind` `consume` with `op` equal to the same routing key and
  `correlation_id` equal to the **publisher's** id — the id survived the wire,
  which a same-process stub could not prove.
- R-21NX-TT5I — delivering an envelope carrying **no** correlation id produces a
  `root` record whose op is the routing key and whose `correlation_id` is
  non-empty, `correlation.Valid`, and **identical** to the `consume` record's
  for that same delivery; a second uncorrelated event yields a **different**
  id; and a **correlated** envelope produces **no** `root` record at all — a
  build that copies the empty wire value, that mints a second id for the
  record, or that roots every delivery, fails this.
