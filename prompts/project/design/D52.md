# Decision 52 — The version-plane client: one seam, injected at the composition root

> **External ordering.** See the banner in D51: repos' surface is an external
> precondition, owned by repos' spec. The request shapes pinned below are
> **prompts' own emission contract** — what this client sends — sourced from
> repos' shipped door at seal time. The one repos-side addition prompts relies
> on, the optional `ttl` field on run-token minting, is repos' own queued work
> (operator-sequenced: run repos' loop first); until it ships, repos ignores
> the unknown field and mints with its env default, so nothing here hard-fails.

## Decision

`prompts/internal/version` is prompts' **entire** dependency on the version
plane. It is a narrow client interface plus one HTTP implementation, injected
at the composition root over `registry.BaseURL("repos")` — the same
registry-by-name addressing D14 established, with no port literal and no second
copy of the address.

```go
// prompts/internal/version — the version-plane client.
package version

// Owner is the identity a domain verb is scoped to — the same owner_id /
// owner_email the prompts row already stores.
type Owner struct {
    ID    string
    Email string
}

// File is one path in a batch write. Delete removes the path instead of
// writing Data.
type File struct {
    Path   string
    Data   []byte
    Delete bool
}

// Definition is the three addressable files of a prompt tree (D51) read at one
// ref. Missing system.md yields an empty SystemPrompt; a missing prompt.md or
// config.json is an error.
type Definition struct {
    UserPrompt   string
    SystemPrompt string
    ConfigJSON   []byte
}

// Credential is a short-lived, single-repository run token plus the clone URL
// it authenticates (root project/design/D24.md: fetch, and push to non-main
// refs only).
type Credential struct {
    CloneURL  string
    Username  string
    Password  string
    ExpiresAt time.Time
}

// Client is the version plane as prompts sees it. Every method addresses a
// prompt repository by its name key (D51); the "prompts" kind is the client's
// own constant, so no caller can reach another kind's repositories.
type Client interface {
    Create(ctx context.Context, nameKey string, owner Owner, actor string) error
    Commit(ctx context.Context, nameKey string, files []File, message, actor string) (sha string, err error)
    Head(ctx context.Context, nameKey string) (sha string, err error)
    Read(ctx context.Context, nameKey, ref string) (Definition, error)
    Rename(ctx context.Context, fromKey, toKey string, owner Owner, actor string) error
    Archive(ctx context.Context, nameKey string, owner Owner, actor string) error
    RunToken(ctx context.Context, nameKey, runID string, ttl time.Duration) (Credential, error)
}
```

**The kind is baked in.** `prompts` is a package constant in the client's
request construction. Nothing in prompts can address `sites/…` or `code/…`, so
the scope boundary is structural rather than a review habit.

**Two wire families, matching the two things the plane offers.**

**Domain verbs speak MCP.** `Create`, `Rename`, and `Archive` (repos' `delete`
tool) each issue exactly one `POST {base}/mcp` carrying a JSON-RPC 2.0
`tools/call` envelope:

```json
{"jsonrpc":"2.0","id":"create","method":"tools/call",
 "params":{"name":"create",
           "arguments":{"kind":"prompts","name":"<name key>"}}}
```

(`rename` adds `"to":"<new name key>"`; `Archive` calls the tool named
`delete`.) These requests carry three identity headers — `X-Owner-Id` and
`X-Owner-Email` (the owner the prompts row stores; repos owner-scopes every
verb on `X-Owner-Id`), and `X-Client-Id: prompts:<prompt id>` (attribution).
prompts is inside the trust boundary and asserts the identity itself — the same
contract nginx fulfills for outside callers, and the same shape sites' client
already speaks.

**Bytes speak the plumbing routes**, `kind=prompts` in every query or body, and
**no** owner headers and **no** `X-Forwarded-Proto` (the marker repos' loopback
guard keys on to refuse front-door traffic):

| seam method | request |
|---|---|
| `Commit` | `POST {base}/commit` — JSON body `{"kind":"prompts","name":"<name key>","message":…,"actor":"prompts:<id>","changes":[{"op":"put","path":…,"content_b64":…} \| {"op":"delete","path":…}, …]}` → `{"rev":"<sha>"}` |
| `Head` | `GET {base}/list?kind=prompts&name=<name key>&ref=main` → the top-level `"rev"`; an empty `rev` (no commits yet) maps to `ErrNotFound` |
| `Read` | `GET {base}/archive?kind=prompts&name=<name key>&ref=<ref>` → a tar of the tree at that ref, decoded in memory |
| `RunToken` | `POST {base}/run-token` — JSON body `{"kind":"prompts","name":"<name key>","ttl":"<Go duration>"}` → `{"token":…,"expires_at":…,"clone_url":…}` |

**`Read` is one snapshot, not three requests.** The archive tar is a single
consistent tree at one resolved ref — three separate `GET /content` calls
against `main` could straddle a concurrent push. The client extracts
`prompt.md`, `config.json`, and `system.md` from the tar and ignores the
author's other files; a missing `system.md` yields an empty `SystemPrompt`, a
missing `prompt.md` or `config.json` is an error naming the absent file, and an
archive **404** (a repository with no commits has no tree) maps to
`ErrNotFound`.

**Attribution rides `X-Client-Id`; scoping rides `X-Owner-Id`.** Every request
names the acting client (`prompts:<prompt id>`, the exact `suite.go` convention
D26 already uses) — on the MCP verbs as the `X-Client-Id` header, on `Commit`
as the body's `actor`, which the plane writes as the commit author and the
`push` event's origin. The owner's identity **is** sent on the MCP verbs,
because repos custody is owner-scoped there: prompts vouches for the owner its
own row already binds the prompt to.

**One commit per call.** `Commit` takes a **batch** of files and produces
exactly one commit: create's whole initial layout, an update's changed files,
an import's body. Per-file commits would turn one user action into a burst of
`repos:push` events and an unreadable history.

**Run-token TTL.** `RunToken` sends the requested lifetime as a Go duration
string — the run TTL plus a five-minute margin, per D56 — and builds the
`Credential` from the response: `CloneURL` verbatim, `Username` the fixed
`run`, `Password` the token, `ExpiresAt` parsed from `expires_at`. The plane
owns the ceiling and may grant less; prompts asks honestly for what the run
needs.

**Failures are typed**, so a plane-side refinement flows through with no
prompts change. Plumbing routes map from the HTTP status; the MCP door returns
200 with an error envelope, so the domain verbs map from `result.isError` +
`result.structuredContent.code`:

```go
var (
    ErrNotFound    = errors.New("version: not found")    // 404 / code "not_found"
    ErrConflict    = errors.New("version: conflict")     // 409 / code "conflict"
    ErrValidation  = errors.New("version: invalid")      // 400 / code "validation"
    ErrUnavailable = errors.New("version: unavailable")  // refused, timeout, 5xx, any other status or code
)
```

Domain callers map `ErrValidation`/`ErrConflict` to the MCP `isError` content
envelope (D17's mapping) and `ErrUnavailable` to a plain internal error naming
the version plane — never a silent success.

**Test seam.** `Client` is an interface, so the domain's write-path and
seeding tests (D53, D54) drive a recording fake. The **client itself** is
proven against a real local HTTP server (`httptest`) recording method, path,
query, headers, and body — and the recorded **paths and envelopes are asserted
against the literal shapes pinned above**, so a client speaking any other
surface fails mechanically in this tree.

## Rejected

**A REST twin for the domain verbs (`POST /repositories/create` and kin).**
The first build of this Decision invented exactly that surface, and it does not
exist: repos serves domain verbs only on its MCP door (`root
project/design/D24.md`'s single-verb-surface rule), and every prompt create
404ed against the live plane until this rewrite. The JSON-RPC envelope is a
real cost, but the alternative is a surface repos deliberately refuses to
ship — and sites' working client is the precedent that the cost is one encode,
one decode, one error field.

**Leaving the wire shapes out of this design ("they are repos' spec's").**
That was the prior text, and it is what let an invented surface pass a green
suite: with no shape pinned in-tree, the recording test peer mirrored the
client's own wrong paths and agreed with them. What this client **sends** is
prompts' own observable behavior; pinning it here states our contract, not
repos'. A future repos surface change is an operator-sequenced cross-tree move
that revisits this Decision — exactly as this rewrite is.

**Three `GET /content` calls instead of the archive tar for `Read`.** Three
reads against a moving `main` are not a snapshot; the tar is, and it is one
round trip.

**A materialized local copy of each prompt definition under `state/`.** `root
project/design/D24.md` provides for one because a service that *serves* an
artifact cannot pay a network hop per request. prompts serves nothing from a
definition: it reads one at create/update/get and once per run start. A local
copy would be a second source of truth, a refresh path, and a `repos:push`
consumer, all bought for a read that happens a few times an hour.

**A generic "git client" taking a kind parameter.** One extra argument, and
prompts can write another service's histories. The constant costs nothing.

## Verification

(Real substrate: a real local HTTP server — `httptest` on loopback standing in
for the plane's loopback surface — recording method, path, query, headers, and
body. Rejection and mapping claims assert what the server actually received,
against the literal shapes pinned above.)

- R-IRRX-XZQ2 — `Create`, `Rename`, and `Archive` each issue **exactly one**
  `POST` whose recorded path is exactly `/mcp`, whose body is a JSON-RPC 2.0
  `tools/call` naming the tool `create`/`rename`/`delete` with arguments
  carrying `"kind":"prompts"` and the bare name key (and `to` on rename), and
  whose recorded headers carry `X-Owner-Id`, `X-Owner-Email`, and
  `X-Client-Id: prompts:<id>` exactly as supplied; a client asked for a name
  key of `../sites/blog` still sends `"kind":"prompts"` with the key escaped,
  never a `sites` address. A client issuing `/repositories/*` paths or
  omitting the owner headers fails it.
- R-ISZU-BRGR — against a 200 response whose envelope carries
  `result.isError: true` and `structuredContent.code` of `conflict`,
  `not_found`, and `validation` in turn, the domain verbs return `ErrConflict`,
  `ErrNotFound`, and `ErrValidation` respectively (each carrying the
  envelope's message); a non-error envelope returns nil; an unrecognized code
  returns `ErrUnavailable`.
- R-IU7Q-PJ7G — `Commit`'s **one** recorded request has path exactly
  `/commit` and a body carrying `"kind":"prompts"`, the name key, the message,
  the `actor`, and a `changes` array where each write's `content_b64` decodes
  **byte-identical** to its `File.Data` (proven with data containing NUL and
  non-UTF-8 bytes) and each `File.Delete` entry is `{"op":"delete"}` with no
  content field.
- R-IVFN-3AY5 — `Read` issues `GET /archive` with query `kind=prompts`, the
  name key, and the requested `ref`, and decodes the returned tar: a tree with
  all three files yields their exact bytes in `Definition`; a tree without
  `system.md` yields an empty `SystemPrompt`; a tree missing `prompt.md` (and
  separately `config.json`) yields an error naming that file; a **404**
  response maps to `ErrNotFound`.
- R-IWNJ-H2OU — `Head` issues `GET /list` with `kind=prompts` and the name
  key, returns the response's top-level `rev` verbatim, and maps an **empty**
  `rev` to `ErrNotFound` — distinguishing "no commits yet" from a transport
  failure.
- R-IXVF-UUFJ — `RunToken(ctx, key, runID, 35*time.Minute)` issues **exactly
  one** `POST /run-token` whose body carries `"kind":"prompts"`, the name key,
  and `"ttl":"35m0s"`, and returns a `Credential` with the server's
  `clone_url` and token verbatim, `Username` `run`, and `ExpiresAt` equal to
  the served `expires_at`; and **no** plumbing request across `Commit`,
  `Head`, `Read`, and `RunToken` carries an `X-Owner-Id`, `X-Owner-Email`, or
  `X-Forwarded-Proto` header.
- R-RIBB-1RMT — the status mapping against the real local server: **404** →
  `errors.Is(err, ErrNotFound)`; **409** → `ErrConflict`; **400** →
  `ErrValidation` with the response body's detail in the message; **500** and
  a connection-refused base URL → `ErrUnavailable`. A build collapsing
  everything to one error type fails the discrimination.
- R-RJJ7-FJDI — `Commit` with three `File` entries (two writes and one delete)
  issues **exactly one** request whose body carries all three paths, and
  returns the sha the server reports; the server records no second request. A
  build looping one request per file fails the count.
- R-RKR3-TB47 — the literal service name `"repos"` and the call
  `registry.BaseURL("repos")` appear in **no** non-test Go source outside
  `internal/version` and `cmd/prompts` (a source scan excluding `project/` and
  `*_test.go`). This pins the seam: a build reaching the plane from the domain
  or runner packages fails it.
