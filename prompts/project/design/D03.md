# Decision 3 — Validation

## Decision

`validateConfig` in `prompts/internal/prompt/service.go` is the create/update gate. It validates the stored config against the **agentkit model catalog** (`github.com/ikigenba/agentkit/catalog`) — the authoritative table of supported provider/model/effort combinations — and returns the (possibly provider-filled) config on success:

```go
func validateConfig(c Config, getenv func(string) string, subAuthAvailable func() bool) (Config, error)
```

Callers pass `os.Getenv` and the composition root's `subAuth.Available` (the file-presence probe for the subscription credential, D38); tests inject a fake environment and a stub probe. The exported form `prompt.ValidateConfig` (used by `/complete`, D29) carries the same signature. On success the returned Config is what gets stored (it differs from the input only when `provider` was derived).

**Provider env var map** (contractual — must match exactly):

| provider   | env var              |
|------------|----------------------|
| anthropic  | `ANTHROPIC_API_KEY`  |
| openai     | `OPENAI_API_KEY`     |
| google     | `GEMINI_API_KEY`     |
| zai        | `ZAI_API_KEY`        |
| openrouter | `OPENROUTER_API_KEY` |

**Validation steps** (in order — fail fast, each failure a `*ValidationError`):

1. **Model in catalog.** `catalog.Lookup(c.Model)`; a miss rejects, naming the unknown model. Chat use requires at least one entry in `entry.Offerings` (an embedding-only entry carries none and is not a runnable prompt model — it rejects the same way). The old `entry.Pricing != nil` test is gone: rates moved onto the offering (research §3).
2. **Provider resolution.** If `c.Provider` is empty, set it to `entry.Offerings[0].Provider` — the catalog's default route is the first offering in authored preference order. The derived value is stored. If non-empty, it must appear in the env var map (unknown strings reject) **and** the catalog must carry an offering for that pair: `catalog.Offer(c.Model, agentkit.ProviderID(c.Provider))` must return `ok`. A provider the catalog does not serve that model through rejects, naming both.

   `catalog.Resolve` is **not** the gate here. It returns a single `Resolution` with no `ok` and always yields a runnable model, reporting `Coverage: Passthru` for an unknown pair rather than refusing it (research §3). Validation wants the stricter question — "does the catalog carry terms for this pair?" — which is `Offer`. Keeping the gate on `Resolve` would silently accept every provider/model combination.
3. **Reasoning control vs the offering's `ReasoningSpec`.** The first non-zero reasoning control (precedence per D2: `effort` → `thinking_level` → `thinking_budget` → `thinking:false`) is mapped to its `agentkit.ReasoningValue` form (`Level`, `Level`, `Budget`, `DisableReasoning`) and checked against the **resolved provider's offering**, via `catalog.Check(c.Model, agentkit.ProviderID(c.Provider), v)`. Not accepted rejects, naming that offering's accepted vocabulary (its levels, or its budget range and sentinels, or that reasoning cannot be disabled). An offering with a nil `Reasoning` spec accepts no reasoning control — any set control rejects. No control set is always valid (provider default).

   **The vocabulary is per offering, not per model.** The same model reached through its vendor and through OpenRouter can accept different reasoning values, because the two wires differ; `Check` gained its provider argument for exactly this reason (research §3). Validating against a model-wide spec would accept values one route rejects and reject values another accepts. Because step 2 has already resolved `c.Provider` to a concrete value, step 3 always has a provider to check against.
4. **Auth mode.** `c.Auth` must be `""`, `"key"`, or `"sub"`; any other string rejects, naming the accepted vocabulary. `"sub"` additionally requires the **resolved** provider to be `openai` (any other provider rejects, naming both), requires `base_url` to be unset (the subscription credential pins its own base URL — the combination rejects), and requires `subAuthAvailable()` to be true (rejects naming `PROMPTS_OPENAI_AUTH_PATH` and the state-dir default so the operator knows what to provision).
5. **API key present** (skipped when `auth` resolved to `"sub"` — subscription auth needs no key). The resolved provider's env var must be non-empty via `getenv`.

The old blanket `provider: "anthropic"` default (`applyProviderDefault`) is removed — the default is per-model, from the catalog's first offering. `providerRegistry` and every per-provider `Pricing` lookup are removed (the providers have no `Pricing` method; the catalog is the truth).

**Stored configs are not re-validated.** Validation is a write-path gate only — create, update, import, and each `/complete` request. The runner never re-checks a pinned config against the catalog beyond D7's `Coverage` test, so a stored config that would no longer validate keeps running until someone edits it. No migration re-validates existing rows.

**Import changes**: `service.go` drops the provider sub-package imports (`agentkit/anthropic`, `.../openai`, `.../google`, `.../zai`) and imports `github.com/ikigenba/agentkit` + `github.com/ikigenba/agentkit/catalog` instead.

`Import` (Dropbox adoption) keeps seeding `importDefaultModel = "claude-sonnet-4-6"` — a catalog entry — and now stores its derived provider the same way as create.

## Rejected

**Advisory validation (agentkit's own stance)** — the catalog upstream never blocks a model from being sent; prompts deliberately does. A hosted service's stored configs should fail at authoring time, not mid-run (operator decision).

**Synthesizing OpenRouter wire slugs for unrouted models** — rejected: prompts would be guessing slugs the catalog does not vouch for; an explicit provider is honored exactly when the catalog carries the route. Widening coverage is an agentkit catalog change.

**Validate reasoning at run time only** — rejected for the same fail-fast reason as models; `catalog.Check` makes the create-time check one call.

**Validate reasoning against the model's first offering regardless of the configured provider** — rejected: it reintroduces the model-wide assumption the catalog restructure exists to correct, and would reject legitimate values on an alternate route while accepting values that route refuses.

## Verification

- R-JVR2-WAUP — `validateConfig` with an unknown provider string (e.g. `"badprovider"`) returns a non-nil `*ValidationError`.
- R-JWYZ-A2LE — `validateConfig` with a model name absent from the agentkit catalog returns a non-nil `*ValidationError`.
- R-1ONM-PPDU — `validateConfig` with an empty provider and a catalog model returns a Config whose `Provider` equals that model's catalog default provider (e.g. `"grok-4.5"` → `"openrouter"`, `"gpt-5.5"` → `"openai"`).
- R-1PVJ-3H4J — `validateConfig` with an explicit provider the catalog does not route the model through (e.g. `provider: "google"`, `model: "claude-sonnet-4-6"`) returns a non-nil `*ValidationError`.
- R-1R3F-H8V8 — `validateConfig` with an enum-reasoning model and an `effort`/`thinking_level` value outside the model's catalog `Levels` (e.g. `effort: "ultra"` on `claude-sonnet-4-6`) returns a non-nil `*ValidationError`.
- R-1SBB-V0LX — `validateConfig` with a range-reasoning model and a `thinking_budget` outside the model's catalog range and sentinels (e.g. `1_000_000` on `gemini-2.5-pro`, whose max is 32768) returns a non-nil `*ValidationError`.
- R-1TJ8-8SCM — `validateConfig` with `thinking: false` on a model whose catalog spec has `CanDisable: false` (e.g. `claude-fable-5`) returns a non-nil `*ValidationError`.
- R-1UR4-MK3B — `validateConfig` with a reasoning control the model's catalog spec accepts (a listed level, an in-range budget, or a sentinel value) returns a nil error.
- R-1VZ1-0BU0 — `validateConfig` with an openrouter-resolved model and `OPENROUTER_API_KEY` empty in the injected environment returns a non-nil `*ValidationError` naming `OPENROUTER_API_KEY`.
- R-JY6V-NUC3 — `validateConfig` with a valid provider and catalog model, but the provider's API key env var empty, returns a non-nil `*ValidationError`.
- R-JZES-1M2S — `validateConfig` with a valid provider, catalog model, and the API key env var set returns a nil error.
- R-SVPV-O479 — `validateConfig` with an `auth` value outside `""`/`"key"`/`"sub"` (e.g. `"oauth"`) returns a non-nil `*ValidationError` naming the accepted vocabulary.
- R-SWXS-1VXY — `validateConfig` with `auth: "sub"` and a resolved provider other than `openai` (e.g. `model: "claude-sonnet-4-6"`) returns a non-nil `*ValidationError` naming both.
- R-SY5O-FNON — `validateConfig` with `auth: "sub"`, an openai-resolved model, and a non-empty `base_url` returns a non-nil `*ValidationError`.
- R-SZDK-TFFC — `validateConfig` with `auth: "sub"`, an openai-resolved model, and an injected `subAuthAvailable` returning false returns a non-nil `*ValidationError` whose message contains `PROMPTS_OPENAI_AUTH_PATH`.
- R-T0LH-7761 — `validateConfig` with `auth: "sub"`, an openai-resolved model, `subAuthAvailable` returning true, and `OPENAI_API_KEY` empty in the injected environment returns a nil error (subscription auth requires no API key).
- R-ZAC5-D0ZY — for a model the catalog serves through two providers whose offerings carry **different** reasoning vocabularies, a config naming the first provider with a value native to that offering validates, while the same model and value with the second provider is rejected with an error naming the second offering's vocabulary — and the mirrored pair holds in the other direction. A build checking a single model-wide spec accepts or rejects both identically and fails this.
