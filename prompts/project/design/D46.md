# Decision 46 — nginx fragment: capture the edge-minted chain id on gated locations, strip it on the ungated one

## Decision

nginx is the sole trust boundary, so it is also where a **client-supplied**
correlation id must die. The dashboard's introspection endpoints mint the chain
id for every gated route and return it on the auth subresponse; prompts'
fragment captures it and forwards it, overwriting anything the client sent. The
one location that is not gated forwards an explicitly empty header, so the
service mints its own and a public caller can never inject a chain id.

**Gated locations — capture and forward.** Every location in
`prompts/etc/nginx.conf` that runs an `auth_request` gains the same two lines,
beside the existing owner-header capture (D10):

```
auth_request_set $prompts_corr $upstream_http_x_correlation_id;
proxy_set_header X-Correlation-Id $prompts_corr;
```

applied to all four gated locations:

- `location /srv/prompts/` — the bearer tier (`auth_request /_authn`): MCP.
- `location = /srv/prompts/` — the session root (`auth_request /_session-authn`).
- `location /srv/prompts/ui/` — the session-gated browse UI prefix.
- `location /srv/prompts/static/` — the session-gated assets prefix. It
  forwards **no owner headers** (unchanged, D10) but does forward the chain id,
  so an asset fetch is attributable like any other gated request.

Identity hygiene is the same argument D10 already makes for the owner headers:
nginx does not pass an inbound client header as a proxy header unless
explicitly set, and the last `proxy_set_header` for a name wins — so one set
from the auth-subrequest variable **replaces** any client-smuggled
`X-Correlation-Id` entirely.

**The ungated location — strip.** The unauthenticated PRM bootstrap
(`= /srv/prompts/.well-known/oauth-protected-resource`) has no auth subrequest
and therefore no minted id; it forwards an explicitly empty header so the
service's read-or-mint middleware mints:

```
proxy_set_header X-Correlation-Id "";
```

**The `/feed` guard needs nothing.** `location = /srv/prompts/feed { return
404; }` proxies to nothing — there is no upstream request to stamp or strip.
Direct loopback `/feed` consumers are inside the trust boundary and carry their
own id.

**Variable naming** follows D10: one `$prompts_corr` variable reused across the
gated locations (nginx evaluates `auth_request_set` per request), service-
prefixed so it stays unique when every service fragment is included into the
one apex `server` block.

## Rejected

**Trusting a client-supplied `X-Correlation-Id` at the edge** — the whole point
of the edge rule: outside the loopback trust boundary anyone could join, poison,
or merge another chain by sending a header. Inside it, the header is trusted;
at nginx it is overwritten.

**Omitting the header on the ungated PRM location instead of setting it
empty** — nginx would then forward nothing *and* nothing would stop a future
`proxy_pass_request_headers`-style change from letting the client's value
through. The explicit empty set states the intent and is greppable.

**Skipping the static-assets location** — it is gated, the dashboard mints an
id for it anyway, and letting the service mint a second one for a request the
edge already identified splits one request across two chains for no reason.

**Substituting the header name or port at install time** — the fragment is
authored and shipped verbatim (D01/D04); every value in it is a literal.

## Verification

(String assertions over the repo-real `etc/nginx.conf`, in
`cmd/prompts/web_test.go` beside the existing fragment assertions — the
fragment is config, not Go.)

- R-HWX8-NVCX — each of the four gated blocks in `etc/nginx.conf` — `location
  /srv/prompts/`, `location = /srv/prompts/`, `location /srv/prompts/ui/`, and
  `location /srv/prompts/static/` — contains **both** `auth_request_set
  $prompts_corr $upstream_http_x_correlation_id;` and `proxy_set_header
  X-Correlation-Id $prompts_corr;`. A block carrying the capture without the
  forward (or vice versa), or any gated block missing the pair, fails.
- R-HY55-1N3M — the ungated PRM block `location =
  /srv/prompts/.well-known/oauth-protected-resource` contains
  `proxy_set_header X-Correlation-Id "";` and contains **no**
  `auth_request_set` for the correlation header — a build that forwards a
  client-supplied id, or forwards nothing at all, fails.
