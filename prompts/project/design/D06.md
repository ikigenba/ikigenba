# Decision 6 — Suite discovery

## Decision

`prompts/internal/suite/suite.go` returns the suite's peers as **agentkit MCP server attachments** — `[]agentkit.MCPServer`, one entry per non-self peer in the box inventory — instead of pre-listed tool groups. prompts no longer lists, wraps, or dispatches peer tools itself; agentkit owns the MCP client from `tools/list` through `tools/call`.

This is forced, not preferred. `agentkit.Tool` is a sealed interface and `agentkit.RawTool` — the only constructor accepting a runtime-discovered JSON schema — was removed from agentkit (research §2). A peer's tool schemas are learned over MCP at spawn and are not Go types, so `NewTool[In]` cannot express them. `Conversation.MCPServers` is the sole remaining route.

**Signature** (owner-id keyed, `docs/owner-id-design.md`):

```go
func Discover(ctx context.Context, manifestRoot, ownerID, ownerEmail, promptID, correlationID string) []agentkit.MCPServer
```

It reads the box inventory under `manifestRoot`, excludes `prompts` itself (a run must not spawn a run), and returns one entry per remaining service. It performs **no network I/O** — it is now a pure inventory-to-attachment mapping, so it still cannot fail and still returns a non-nil (possibly empty) slice. The trailing `correlationID` is the run's chain id (D44/D45): when non-empty it joins each entry's `Headers` map as `X-Correlation-Id`; when empty the key is absent.

**Entry shape**, per peer:

- `Name` — `"ikigenba_" + svc.Name`. agentkit names each discovered tool `sanitizeMCPToolName(server.Name + "_" + tool.Name)`, and peers register **bare verbs** since the bare-name rename (`docs/adr-mcp-tool-bare-names.md`). So `Name: "ikigenba_crm"` against a peer publishing `health` yields `ikigenba_crm_health` — byte-identical to the names the retired `qualify()` helper produced. The prefix is carried in `Name` precisely so agentkit's own concatenation reproduces the existing contract.
- `URL` — the peer's loopback MCP endpoint, `http://127.0.0.1:<port>/mcp`, with the port resolved by service name through the shared `registry` (D14).
- `Headers` — the run's identity, unchanged and still load-bearing: `X-Owner-Id: ownerID` (the key peers gate on since appkit D13), `X-Owner-Email: ownerEmail` (display only), `X-Client-Id: "prompts:" + promptID` — plus `X-Correlation-Id: correlationID` when non-empty, chaining every peer hop to the run that caused it (owned and proven by D45). agentkit injects them on every request it makes to that server, covering both its `tools/list` and each `tools/call`.

**Best-effort discovery is lost, deliberately.** agentkit's `resolveMCPTools` is all-or-nothing: any server whose `tools/list` fails tears down every connection and returns an error, failing the whole `Send`. A peer that is down therefore fails the run with an error naming it, where discovery previously logged and skipped it. This is a real regression against the prior contract and is accepted as a temporary cost of the bump. The fix belongs in agentkit — per-server tolerance is a property of the component that owns the connection — and layering a prompts-side reachability probe in front of it would be prompts compensating for a defect in a dependency, a workaround that would outlive the defect. Nothing in prompts pre-probes.

**Deleted with this Decision:** the `mcpclient.Initialize` method and the peer-blurb concept (agentkit's MCP path takes no group blurb), the `qualify()` helper, the `agentkit.RawTool` wrapping and its dispatch closure, and the within-service duplicate guard (agentkit's `validateAndSortTools` now enforces name uniqueness across the whole tool set). `internal/mcpclient` itself survives only if another caller needs it; nothing in the run path does.

## Rejected

**A prompts-side reachability probe before attaching** — the shape would be: call each peer's `tools/list` at spawn, discard the results, and attach only those that answered, so agentkit never sees a dead server. It restores best-effort exactly, at the cost of one redundant list call per peer per run. Rejected as the wrong repository for the fix: it is prompts writing code whose only purpose is to correct a dependency's behavior, and such compensation is never removed once the dependency is fixed. The regression is recorded here instead, where it stays visible.

**Freeze agentkit on the last release that carried `RawTool`** — rejected in D1; it holds prompts on an old release permanently to preserve one mechanism.

**Keep prompts' own MCP client and dispatch through a fixed-schema meta-tool** (`suite_call(service, tool, arguments string)`) — this is expressible under the sealed `Tool` interface, because the meta-tool's input *is* a Go struct. Rejected: the model would drive every real tool through a stringly wrapper with no provider-native schema on the actual call, losing argument validation, tool-choice signal, and per-tool descriptions. The prior D19 rejected this same shape for the same reason; nothing about the agentkit change makes it better.

**Let agentkit resolve peers lazily at `Send` without an inventory read** — agentkit has no discovery of its own; it attaches what it is given. The inventory read stays prompts' job.

## Verification

- R-ZDZU-IC81 — `Discover` called with an inventory holding two non-`prompts` services and a `prompts` self entry returns exactly two `agentkit.MCPServer` values: one per non-self peer, each `Name` equal to `"ikigenba_" + svc.Name`, each `URL` equal to that service's registry loopback `/mcp` address, and no entry for `prompts`. A build that omits the `ikigenba_` prefix from `Name` fails this (the discriminating property against tool names regressing to bare verbs).
- R-EF0V-TP9R — the `Headers` map of every returned entry carries `X-Owner-Id` equal to the `ownerID` argument, `X-Owner-Email` equal to `ownerEmail`, and `X-Client-Id` equal to `"prompts:" + promptID`; a build forwarding only `X-Owner-Email` sets no `X-Owner-Id` and fails this (the discriminating property against the header set id-gated peers would 401).
- R-ZF7Q-W3YQ — end-to-end through a `Conversation`: with a stub MCP peer served over `httptest` whose `tools/list` publishes the bare verb `health`, attached via `Discover`'s output, the tool reaching the recording provider's `Request` is named `ikigenba_<svc>_health`, and invoking it dispatches `tools/call` to that peer with the bare verb `health` and the identity headers intact. This drives the real agentkit MCP client against a real HTTP server — a stub provider alone cannot show that agentkit's own name concatenation reproduces the contract.
- R-ZGFN-9VPF — with two peers attached where one's `tools/list` returns an error, the run terminates as `failed` with an error naming that peer, and the other peer's tools are not reachable. This pins the accepted regression as deliberate: a build that silently skipped the failing peer and completed the run would fail this id, which is what makes the behavior a decision rather than an accident.
