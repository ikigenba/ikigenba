# Decision 39 — The run directory is durable state, and holds the whole run

## Decision

A run's on-disk artifacts live under the service's **durable state tree** in one
directory per run, and that directory holds everything the run produced:

```
<stateDir>/runs/<run_id>/
    input/          # event.json — an event-triggered run only (D55)
    output.jsonl    # the agentkit LogRecord log
    sandbox/        # the run's working directory: the git clone, .git included
```

`<stateDir>` is `filepath.Dir(PROMPTS_DB_PATH)` — the same tree that already
holds `prompts.db` and `auth.json`, chowned to the service and never touched by
deploy. On the box that is `/opt/prompts/state/runs/<run_id>/`.

**The run directory is not scratch.** Nothing derives it from the generation
cache and nothing recreates it at boot: `recreateRunsDir` does not exist, and
the runs tree survives every restart, deploy, and reboot. A `runs` row and the
directory it points at have the same lifetime, which is what lets the product
promise that a run's record survives indefinitely.

**One run is one directory.** The sandbox lives *inside* the run directory
rather than in a sibling `sandboxes/` tree, so a run is never two half-records
with two lifetimes keyed by the same id. `sandbox.New` is rooted at
`<stateDir>/runs` and resolves a run's root as `<run_id>/sandbox`; that root is
the confinement root the toolkit tools are given, and since D55 it is also a git
clone — the `.git` directory is part of the run and is removed with it.

**`input/` holds only the triggering event.** The definition a run executes is
not copied here: it is the commit named by `runs.definition_sha`, held in the
run's own clone (D55). A manual run therefore writes no `input/` files at all.

**Nothing is reclaimed automatically.** Run directories accumulate until
explicitly deleted (D41). No retention window, no pruning pass, no size cap.
This is deliberate: the alternative is a policy with a default that silently
destroys production records, and the box has no evidence yet about what growth
actually looks like.

## Rejected

**Leave `runs/` in the generation cache** — rejected: the cache is by definition
reclaimable, and a future cache-clearing step (a deploy, an operator, a
disk-pressure hook) would take the run history with it. Durability belongs in
the tree whose contract is durability, and a record that outlives what it
describes is worse than no record.

**Keep `sandboxes/` as a sibling tree** — rejected: it keeps a run split across
two trees with the same key, so deletion (D41) has to remember both, and any
future per-run operation has to as well. One run, one directory.

**Add a retention window now (age out run directories after N days)** —
rejected as scope: it is a product promise about destroying customer data, it
needs a default nobody has evidence for, and the `calls` table already carries
its own separately-specified retention for bodies. Deletion is explicit until
there is a reason for it not to be.

**Store `output.jsonl` in the database instead** — rejected: it is an
append-only log of unbounded size written during the run; SQLite is the wrong
shape and the streaming write is the point.

**Exclude `.git` from the run directory by cloning elsewhere and exporting a
tree in** — rejected: it would give the run a working tree it cannot commit or
push from, which is the capability D55 exists to provide, and it would put the
run's history somewhere `run_delete` does not reach.

## Verification

- R-ZNR1-KI5L — a run's directory and every file in it survive a service
  restart: with a completed run on disk, running the composition root's startup
  a second time against the same state directory leaves `output.jsonl` and the
  whole `sandbox/` clone — working tree **and** `.git` — byte-identical,
  `run_output` returns the same content afterwards, and
  `git -C <sandbox> rev-parse HEAD` still equals the run's `definition_sha`. A
  build that recreated or pruned the runs tree at boot deletes it and fails —
  the discriminating property, since a test that only checked the path would
  pass on a boot-scratch implementation.
