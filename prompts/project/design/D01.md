# Decision 1 — Module dependency

## Decision

`prompts/go.mod` requires the published agentkit at the current release:

```
require github.com/ikigenba/agentkit v0.16.0
```

There is no local `replace` for agentkit. The `appkit`, `eventplane`, and `registry` replace directives are unchanged.

The repo-root `go.work` resolves prompts' agentkit dependency from the module cache during local development, exactly as production (`GOWORK=off`) does. The import-guard tests continue to assert that no retired local-fork import path appears, and that the required version matches the pin above.

The surface prompts consumes:

- the advisory `catalog` package — `Lookup`, `Offer`, `Offerings`, `Resolve`, `ListCurated`, `Check`, `Entry`, `Offering`, `Resolution`, `Coverage`, `ReasoningSpec` — research §3;
- typed-credential provider constructors (`New(cred Credential, opts ...Option)` on every provider sub-package), with credentials now resolved lazily at send rather than at construction (research §3);
- `agentkit.Identity` / `ProviderID` / `AuthMode`, the typed replacement for the retired `Provider.Name() string`;
- the `github.com/ikigenba/agentkit/openrouter` provider;
- consumer-owned cost resolution via `Conversation.Pricing`, sourced from an offering rather than an entry;
- `Conversation.MCPServers` — the only supported route for foreign, runtime-discovered MCP tools now that `RawTool` is gone and `agentkit.Tool` is sealed (research §2), consumed by D6/D19;
- the `github.com/ikigenba/agentkit/toolkit` subpackage — the six standard coding tools as ready-made `agentkit.Tool` values, consumed by D5 — research §4.

**Scope of the bump.** This is a version bump, not a capability adoption. Three capabilities the release carries are deliberately left unconsumed: `toolkit.WebSearch`, `toolkit.WebFetch`, and the `ocr` subpackage (research §4). Each is a candidate for a later spec extension; none is wired here.

## Rejected

**Stay on v0.7.0** — rejected: the pin is nine minor releases behind, and the gap is not additive. `RawTool` removal (v0.12.0), the catalog's offering restructure (v0.10.0), and the `Identity` conversion (v0.10.0) all land whether or not prompts wants them, and each further release widens the eventual jump.

**Stay on v0.11.0 — the last release carrying `RawTool`** — rejected: it preserves deferred suite tools (the old D19) at the cost of freezing prompts one release behind indefinitely, and it forgoes the corrected per-offering catalog data, on which validation now depends. The deferral loss is real and is accepted in D19 rather than paid for with a permanent pin.

**Adopt the new capabilities in the same change** — rejected: `ocr` and the network tools each carry their own contracts, credentials, and cache semantics, and `ocr` in particular reopens D23's PDF non-goal. Bundling them into a bump that must land atomically (every compile break is in one phase) would make an already-large unit unreviewable.

**Vendor a model list inside prompts** — rejected: the catalog is agentkit's authoritative, versioned statement of the supported provider/model/effort combinations; a private copy would drift.

## Verification

Pure structural decision — enables D2–D5, D7, D9, D19, D29, D30. No behavior ids of its own; correctness is implied when the suite compiles against v0.16.0 and the behavioral ids of the dependent decisions pass.
