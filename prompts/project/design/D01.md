# Decision 1 — Module dependency

## Decision

`prompts/go.mod` requires the published agentkit module, `github.com/ikigenba/agentkit`, pinned to an exact released version. There is no local `replace` for agentkit. The `appkit`, `eventplane`, and `registry` replace directives are unchanged.

**Which version is `go.mod`'s to say, and this design's never.** The pin is a single value with one authoritative home, and naming it here would create a second one that drifts. Moving to a newer agentkit is therefore ordinary operational work — edit the requirement, run the suite — and not a spec change: no Decision is rewritten, no phase is appended, and nothing in `project/` records the number. What this Decision owns is the *shape* of the dependency: published module, exact pin, no local fork.

The repo-root `go.work` resolves prompts' agentkit dependency from the module cache during local development, exactly as production (`GOWORK=off`) does. The import-guard tests continue to assert that no retired local-fork import path appears.

The surface prompts consumes:

- the advisory `catalog` package — `Lookup`, `Offer`, `Offerings`, `Resolve`, `ListCurated`, `Check`, `Entry`, `Offering`, `Resolution`, `Coverage`, `ReasoningSpec` — research §3;
- typed-credential provider constructors (`New(cred Credential, opts ...Option)` on every provider sub-package), with credentials now resolved lazily at send rather than at construction (research §3);
- `agentkit.Identity` / `ProviderID` / `AuthMode`, the typed replacement for the retired `Provider.Name() string`;
- the `github.com/ikigenba/agentkit/openrouter` provider;
- consumer-owned cost resolution via `Conversation.Pricing`, sourced from an offering rather than an entry;
- `Conversation.MCPServers` — the only supported route for foreign, runtime-discovered MCP tools now that `RawTool` is gone and `agentkit.Tool` is sealed (research §2), consumed by D6/D19;
- the `github.com/ikigenba/agentkit/toolkit` subpackage — the six standard coding tools as ready-made `agentkit.Tool` values, consumed by D5 — research §4.

**Consuming a version is not adopting its capabilities.** Three capabilities agentkit offers are deliberately left unwired: `toolkit.WebSearch`, `toolkit.WebFetch`, and the `ocr` subpackage (research §4). Each is a candidate for a later spec extension. A newer agentkit that adds further capabilities does not thereby adopt them either — wiring one up is a design change, while moving the pin is not.

## Rejected

**Naming the version in this design** — rejected: it duplicates a fact `go.mod` already owns, so the two drift, and it turns every library upgrade into a spec session. A pin has one home.

**Freezing on the last release that carried `RawTool`** — rejected: it preserves deferred suite tools (the shape D19 previously carried) at the cost of holding prompts on an old release indefinitely, and it forgoes the corrected per-offering catalog data on which validation now depends. The deferral loss is real and is accepted in D19 rather than paid for with a permanent freeze.

**A floating requirement (a branch, `latest`, or a pseudo-version)** — rejected: it makes a build's dependency unreproducible and lets agentkit change under prompts without anyone choosing it. Exact pin, moved deliberately.

**Adopt the new capabilities in the same change** — rejected: `ocr` and the network tools each carry their own contracts, credentials, and cache semantics, and `ocr` in particular reopens D23's PDF non-goal. Bundling them into a bump that must land atomically (every compile break is in one phase) would make an already-large unit unreviewable.

**Vendor a model list inside prompts** — rejected: the catalog is agentkit's authoritative, versioned statement of the supported provider/model/effort combinations; a private copy would drift.

## Verification

Pure structural decision — enables D2–D5, D7, D9, D19, D29, D30. No behavior ids of its own; correctness is implied when the suite compiles against the pinned agentkit and the behavioral ids of the dependent decisions pass.
