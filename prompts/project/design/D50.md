# Decision 50 — Adopt the suite testing-language contract

## Decision.

prompts adopts the suite's testing-language contract — `root project/design/D23.md` —
by value and without deviation. That contract owns the four layer names
(**hermetic**, **composed**, **live**, **manual**), the rule for what each layer
may touch, the `//go:build live` mechanism, the ban on `t.Skip` outside
live-tagged files, and the requirement that every tree declare its testing facts
in its `AGENTS.md`. None of that is restated here.

What is local to prompts — and all this Decision adds — is **which layers this
tree has, which of its tests sit in each, what it must declare, and where the
proof of that declaration lives**:

- **Layers present: hermetic and composed.** There is no live layer (prompts
  reaches a real provider only from inside a run, never from a test) and no
  tree-local manual layer; the suite-level manual check the contract names lives
  at the repo root, not here.
- **The composed tests are the boot smokes in `cmd/prompts/main_test.go`.** They
  shell out to `go build` for the real `prompts` binary, run `serve` against a
  temporary root on an ephemeral loopback port, drive `/health` and `POST /mcp`
  over real HTTP, and restart a second instance over the same database. Building
  and running the tree's own binary is exactly the composed boundary.
- **Everything else is hermetic**, including the file whose *name* suggests
  otherwise: `internal/consume/smoke_test.go` wires the real `consume.Handler`
  to the real `prompt.Service` and store over a temp-file SQLite database
  through the real migration runner, with a stubbed runner and no server and no
  binary. Under the contract a layer is fixed by what a test may touch, never by
  its file name, so that file is hermetic and the conventional word "smoke" in
  its name is an informal alias with no contractual force. The same holds for
  every `net/http/httptest` page, tool, and runner test, the `share/www` asset
  tests over the repo-real tree, and the `etc/nginx.conf` string assertions.
- **Environmental preconditions beyond the Go toolchain: none.** The boot smokes
  invoke `go build`, which is the Go toolchain itself and therefore not an
  additional precondition; nothing else in the gate needs `git`, `python3`, a
  browser, credentials, or a running suite.
- **GOWORK mode: workspace for local development, `GOWORK=off` for the
  production build** (`bin/ship prompts`), where `github.com/ikigenba/agentkit`
  resolves from the module cache and `appkit`/`eventplane`/`registry` resolve
  through their committed `replace` directives. prompts is deliberately on the
  standalone-build side of the split the contract declines to unify, and the
  existing import guards (`module_import_guard_test.go`,
  `agentkit_import_guard_test.go`) are what keep that resolution honest.
- **The declaration is proved, not asserted once.** Both proofs live in
  `cmd/prompts/main_test.go`, beside the other whole-tree conformance proofs
  (`R-4LKF-FB23`, the manifest checks) and matching the established suite
  pattern of a composition-root test reading `../../AGENTS.md` from disk. The
  source scan walks the tree from the same package.

The two ids below are the contract's `[proof: per-service]` ids; citing them is
adoption, so they enter this tree's coverage denominator and are realized by
tests in `prompts/`.

## Rejected.

- **Restate D23's layer definitions locally so this design reads
  self-contained.** A local copy of a suite contract is drift by construction —
  it goes stale the moment the umbrella Decision is rewritten. The suite rule is
  cite, never restate; the citation is the whole mechanism.
- **Rename `internal/consume/smoke_test.go` to match its layer.** The contract
  fixes layers by what a test touches, not by file name, and deliberately keeps
  the conventional words as informal aliases. Renaming a committed test file to
  chase a label would be churn that proves nothing; naming the file's layer here
  and in `AGENTS.md` is the fix.
- **Claim a live layer for prompts because runs reach real providers.** Provider
  traffic happens inside a *run*, driven by the service at runtime — no test in
  this tree contacts a provider, and inventing a live-tagged test to have the
  layer would add a credential dependency the tree does not otherwise carry.
  Declared as absent instead.
- **Prove the `AGENTS.md` declaration by review at authoring time instead of by
  a test.** A declaration checked once decays silently; the contract's id exists
  precisely so the gate re-checks it on every run.
- **Put the source scan in a new `internal/` package.** It needs only the tree
  root and `filepath.WalkDir`; a new package for one scan buys nothing, and
  keeping both proofs in `cmd/prompts/main_test.go` puts the tree's self-truth
  claims in one place.

## Verification.

Both ids are **adopted**, not minted here: they belong to `root
project/design/D23.md`, which states the behavior. These lines say only what
substrate proves them inside `prompts/`.

- R-O1AD-MRKW — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/prompts/main_test.go` reads the committed `../../AGENTS.md`
  from disk and asserts its Tests section declares the default-gate command
  `go test ./...` run from `prompts/`, names the layers present using the
  contract's layer names (**hermetic** and **composed**, and that there is no
  live layer), states that there are no environmental preconditions beyond the
  Go toolchain, and states the GOWORK mode (workspace for development,
  `GOWORK=off` for the production build). A missing or reworded declaration
  fails the gate.
- R-O2IA-0JBL — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/prompts/main_test.go` walks every `*_test.go` file in the
  `prompts/` tree, excludes any file carrying a `live` build constraint, and
  asserts **zero** occurrences of `t.Skip`, `t.Skipf`, or `t.SkipNow`. The
  needle is assembled from parts at runtime so the scanning file never matches
  itself, and the scan reports the offending file and line on failure.
