# Decision 57 — The framing prompt tells the run its folder is a git clone

## Decision

The run's folder stopped being scratch and became a checkout (D55), so the
framing prompt must say so — a model told only "a single persistent folder"
will not think to commit, and will not know that `main` is out of reach or that
merging is a verb it has.

`framingPrompt` stops being a package constant and becomes a function of the
run's two facts:

```go
// prompts/internal/runner — the base system instruction, now per-run because
// the branch and the pinned commit are per-run.
func framingPrompt(branch, sha string) string
```

**What the new text states** (the load-bearing facts; exact wording is polished
at build time):

- The folder is a **git clone of this prompt's own repository**, checked out on
  branch `<branch>` at commit `<sha>` — the exact definition this run is
  executing.
- Ordinary git works: the run may commit its work and **push its branch**.
- New branches belong under the **`ikigenba/`** namespace.
- **`main` is off limits**: pushes to it are refused and it must never be
  force-pushed. Work lands on a branch.
- Getting a branch into `main` is a **merge**, done through the version-control
  service's `merge` tool — and **only if these instructions ask for it**. There
  is no automatic merge at the end of a run.

**What does not change**, and is asserted so it cannot drift: the verbatim
"You have NO network access from bash" sentence (git talks to the box's own
loopback door, not the internet, so the sentence stays true and stays as-is);
the sandbox-tool sentence; the file-share paragraph (D26); the PDF tooling
sentence (D23); and the standing constraint that the framing prompt names **no
individual suite service** (R-P2Y5-6GL6, R-6AUG-NHQY) — it says "the
version-control service", exactly as it says "the account's file share".

## Rejected

**Leaving the framing prompt a constant and describing git in prose only.** The
branch name is the one string the agent must type to push, and a model asked to
guess it will invent one. Interpolating the two facts is what makes the
instruction actionable.

**Naming repos in the framing text.** The tools the run reaches are named by
what they do; the backing service's name is not the run's business and adding
it would need R-P2Y5-6GL6 amended for no gain.

**Telling the run to merge when it is done.** That is the platform relocating
intent from the prompt's author, which `root project/design/D24.md` explicitly
rejects. The framing says merging is *available* and *conditional on these
instructions*.

**Dropping the "NO network access from bash" sentence now that git runs over
HTTP.** The sentence is about the internet, the door is on loopback, and the
sentence is load-bearing against a model that would otherwise try to `curl` its
way out. It stays verbatim.

**Instructing the run to commit at the end.** Some prompts produce files that
belong in the repository and some produce a report that does not. Committing is
offered, not mandated.

## Verification

- R-S953-GPY3 — the framing prompt assembled as the conversation `System` for
  a run states that the folder is a git clone at the run's pinned commit, names
  the `ikigenba/` branch namespace, states that `main` cannot be pushed or
  force-pushed, and states that merging happens through the version-control
  service's merge tool only when the prompt's instructions ask for it — while
  still containing the verbatim sentence "You have NO network access from
  bash:" and naming **no** individual suite service (no `repos`, no
  `ikigenba_` prefix, no per-service enumeration; composes with R-P2Y5-6GL6,
  R-6AUG-NHQY, R-6I5U-Y474, R-FEGC-LVD7).
- R-SACZ-UHOS — the branch name and commit sha appearing in the assembled
  `System` string for a spawned run are **exactly** the workspace's real
  values: equal to `git -C <sandbox> rev-parse --abbrev-ref HEAD` and
  `git -C <sandbox> rev-parse HEAD` respectively. A build interpolating a
  hard-coded or stale branch name passes a substring check against the
  template and fails this.
