# Decision 55 — A run pins a sha and executes a real clone

> **External ordering.** See the banner in D51. This Decision additionally
> requires the **`git` binary** on the box and on any machine running the test
> suite; it is box-baseline provisioning owned by `opsctl` (its D10) and is
> declared as an environmental precondition by D50.

## Decision

The run's sandbox stops being an empty directory prompts fills. **The run
workspace *is* a git clone of the prompt's own repository, checked out at a
commit pinned on the run row.** That single change replaces both the empty
sandbox and `materializeInput`'s definition copies, and it is what makes a run
exactly reproducible: the run does not merely record what it ran, it records
the immutable commit it ran, in a workspace that still holds it.

**Spawn, in order** (`Service.startRun`):

1. `sha, err := version.Head(nameKey)` — the tip of `main` at this instant.
2. Build the run row with `DefinitionSha: sha` and insert it.
3. Mint the run credential (D56) and materialize the workspace:

```
git clone --no-checkout <cloneURL> <stateDir>/runs/<run_id>/sandbox
git -C … checkout -b ikigenba/run-<run_id> <sha>
git -C … config user.name  "prompts:<prompt id>"
git -C … config user.email "prompts@localhost"
```

   The run starts on a **branch off the pinned sha**, in the `ikigenba/*`
   namespace the plane's run token can push to — never on `main`, so an
   accidental `git push` from the run cannot even name a ref it is forbidden
   to write. The local `user.name` carries the same client id the loopback
   writes use, so a commit made inside a run is attributable to the prompt that
   made it.
4. Spawn the runner.

A failure at any step fails the run start loudly, naming the version plane —
the same posture as a suite service that will not answer at run start
(D19/product), and for the same reason: a run whose workspace is not what it
claims is worse than no run.

**The run directory, revised** (D39's shape, now that the clone is the
workspace):

```
<stateDir>/runs/<run_id>/
    input/          # event.json ONLY — and only for an event-triggered run
    output.jsonl    # the agentkit LogRecord log
    sandbox/        # the clone: the working tree AND its .git
```

`input/` no longer holds `name.txt`, `user_prompt.txt`, `system_prompt.txt`, or
`config.json`. A manual run writes no `input/` files at all. The frozen-input
guarantee that those copies provided is now **the pinned sha plus the
immutability of the commit it names** — a stronger guarantee, because a commit
cannot be edited in place the way a file in `input/` could.

**Reading a past run's definition is a local git read at the pinned sha**, not
a plane call and not a read of the working tree:

```go
// prompts/internal/prompt — LoadFromRun reads the definition out of the run's
// own clone at the run's pinned commit: `git -C <sandbox> show <sha>:<path>`
// for prompt.md, config.json, and (when present) system.md.
func LoadFromRun(runsDir, runID, sha string) (Executed, error)
```

Reading the **commit object** rather than the working tree is the load-bearing
detail: the agent may rewrite `prompt.md` and `config.json` during its run —
that is the point of a writable workspace — and the run must still report what
it executed. Reading locally rather than from the plane is what keeps a run
readable after its prompt is deleted and its repository archived (D53), and
after the plane is down.

The runner reads the same way at start: `config.json` at the pinned sha builds
the conversation, `prompt.md` is the single user turn, `system.md` precedes the
framing prompt. It never reads the working tree for these, so an agent editing
its own definition changes the *next* run, not this one.

**`run_fs_list` and `run_fs_read` exclude `.git`.** The MCP read surface over a
run's workspace hides the `.git` directory entirely — a listing of git
internals is noise, and `.git/config` holds the run credential (D56). The
exclusion is by top-level path, and a read of any path under `.git` returns
not-found.

`run_delete` (D41) is unchanged in substance: one `RemoveAll` of the run
directory now removes the clone with everything else.

## Rejected

**Keep writing the definition into `input/` as well.** Two copies of one
immutable fact, one of them redundant with a commit that cannot change. It also
re-opens the question the sha closes: which copy is authoritative when they
disagree.

**Clone at `main` and record the sha afterwards.** The clone would race a push
landing between the `Head` call and the fetch, and the run would then be pinned
to a sha its workspace does not contain. Resolve first, check out that exact
sha.

**Check out the pinned sha detached.** A detached HEAD makes the agent's first
commit an object nothing references and its first push a puzzle. Branching off
the sha costs one command and puts the run on a ref the token can push.

**Let the run work directly on `main`.** The token cannot push it, the plane
refuses force-pushes to it, and a local `main` invites the run to try. The
`ikigenba/*` namespace makes the allowed thing the default thing.

**Read the definition from the working tree instead of the commit.** An agent
that rewrites its own `prompt.md` — a legitimate self-editing workflow — would
retroactively rewrite the record of every past run. The commit is the record.

**Read a past run's definition from the plane at the pinned sha.** Correct
while the repository exists, and exactly wrong at the moment it matters most: a
deleted prompt's archived repository, or a plane that is down, would make a
run's own history unreadable. The clone is durable state under the run
directory; use it.

**Expose `.git` through the run fs tools for transparency.** The owner already
has full authority and a real clone on their laptop; what the surface would
actually add is the run token in a readable file and a hundred object paths in
every listing.

## Verification

(Real substrates: every claim below runs the **real `git` binary** against a
**real bare repository** created in a temp directory and served over
`file://`; the authenticated HTTP door is D56's. Store claims use a temp-file
SQLite database through the real migration runner.)

- R-RWY3-N0J5 — a run spawned against a prompt whose repository head is sha `A`
  persists `runs.definition_sha == A`; after a second commit moves the head to
  `B`, a second run persists `B`, and the first run's row still reads `A`. A
  build recording the branch name or nothing at all fails.
- R-RY60-0S9U — after spawn, `<stateDir>/runs/<run_id>/sandbox/.git` exists,
  `git -C <sandbox> rev-parse HEAD` equals the run's `definition_sha`,
  `git rev-parse --abbrev-ref HEAD` equals `ikigenba/run-<run_id>`, and the
  working tree contains the definition files from that commit. The
  branch-name assertion is discriminating: a plain `git clone` with no checkout
  step leaves HEAD on `main` and fails it.
- R-S0LS-SBR8 — with a run completed, overwriting `prompt.md` and
  `config.json` **in the run's working tree** leaves `RunExecuted` for that run
  returning the committed text and config, and a subsequent commit to the
  prompt's `main` also leaves it unchanged; `LoadFromPrompt` for the same
  prompt returns the new `main` content. A build reading the working tree
  returns the overwritten text and fails the first clause.
- R-S1TP-63HX — after an event-triggered run, `<stateDir>/runs/<run_id>/input/`
  contains **exactly** `event.json` and no `user_prompt.txt`,
  `system_prompt.txt`, `config.json`, or `name.txt`; after a manual run, no
  `input/` files exist at all, and both runs still read back their definitions
  through `RunExecuted`.
- R-S31L-JV8M — `run_fs_list` at the workspace root returns the definition
  files and **no `.git` entry**, and `run_fs_read` of `.git/config` returns the
  not-found error while a read of `prompt.md` returns its bytes. A build
  filtering only the exact listing string passes the first assertion and fails
  the read.
