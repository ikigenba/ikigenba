# Decision 4 — Provider factory

## Decision

A shared package `internal/provider` owns the single factory that constructs the correct `agentkit.Provider` from a pinned `Config` and a `getenv` accessor — consumed by both the runner (agent sessions, D7) and the one-shot inference paths (`/complete`, D29):

```go
package provider

func Build(cfg prompt.Config, getenv func(string) string) (agentkit.Provider, error)
```

The function switches on `cfg.Provider` and:

1. Reads the appropriate API key via `getenv` (same env var map as D3, five providers).
2. Calls the matching provider sub-package's constructor with its **typed credential** — the constructors take a `Credential`, not a string:
   - `anthropic.New(anthropic.APIKey(key), opts...)`
   - `openai.New(openai.APIKey(key), opts...)`
   - `google.New(google.APIKey(key), opts...)`
   - `zai.New(zai.APIKey(key), opts...)`
   - `openrouter.New(openrouter.APIKey(key), opts...)`
3. Passes `WithBaseURL(cfg.BaseURL)` for **any** provider when `cfg.BaseURL` is non-empty.
4. Returns the constructed provider, or an error if the provider string is unrecognised (should not happen since validateConfig gated create/update, but fail loudly).

**Credentials are resolved lazily by agentkit.** A provider constructs successfully without a credential and reports the problem from the operation that needs it: `agentkit.ErrMissingCredential` for an absent one, `agentkit.ErrInvalidConfig` for one that is present but unusable for the operation (research §3). `Build` therefore no longer rejects an empty key at construction — the empty string is handed to the typed credential and the failure surfaces at `Send`. The observable contract is preserved deliberately: a run configured for a provider whose key is unset must still end `failed` with an error naming the missing credential, and it now does so one layer later. The factory does not re-add its own emptiness check to pull the error earlier, because agentkit's message names the credential precisely and a duplicate check would drift from it.

**Identity, not name.** `agentkit.Provider` exposes `Identity() agentkit.Identity` (typed `ProviderID` + `AuthMode`); `Name() string` is retired. Anywhere prompts logged or compared a provider name now reads `Identity().Provider`, or `Identity().String()` where the combined `openai.subscription` display form is wanted. Note the `zai` provider reports the id `z-ai`, matching the vendor namespace — the Go package name is unchanged, so a string comparison against `"zai"` is now wrong.

The package also owns the embedding-provider factory consumed by `/embed` (D30):

```go
func BuildEmbedder(providerName string, getenv func(string) string) (agentkit.EmbeddingProvider, error)
```

covering the providers with embedder constructors (`openai.NewEmbedder`, `google.NewEmbedder`) and failing loudly for any other name.

`Build` is the **key-mode** path (`auth` empty or `"key"`). Subscription mode (`auth: "sub"`, openai only) is dispatched above it by the closure `provider.NewBuilder(sub *SubAuth)` returns — see D38 for the credential file, store lifecycle, and wiring.

The injectable seams are unchanged in shape: `Runner.buildProvider` (D7) and the inference executor's factory field (D29) are both of type `func(prompt.Config, func(string) string) (agentkit.Provider, error)`. The composition root injects `provider.NewBuilder(subAuth)` into both (D38); `Build` remains the key-only core the builder falls through to.

## Rejected

**Keeping `buildProvider` package-level in `runner`** — the original home; with `/complete` and `/embed` needing the identical five-way switch, a second copy or a cross-import of `runner` from `inference` would both be wrong shapes. One leaf package, two consumers.

**A generic credential abstraction over the five sub-packages** — each provider defines its own closed `Credential` type; a prompts-side unifying interface would add a layer over a five-case switch that is already trivial.

**Subscription credentials rejected here entirely** — the original stance (API keys only). Overturned by D38: openai subscription auth is now an opt-in `auth: "sub"` mode, layered over this factory by `NewBuilder` without changing the seam type or the key path.

## Verification

Pure structural decision — no behavior of its own. Its correctness is exercised by D7's runner tests and D29/D30's handler tests, which inject fake factories or exercise `provider.Build`'s error paths through their own ids, and by the compile against agentkit's typed-credential constructors.

- R-ZBK1-QSQN — a run pinned to a provider whose API-key environment variable is unset is marked `failed` with an error that names the missing credential, and `provider.Build` itself returns no error for that config (the failure arrives from the send, not the factory). A build that reinstated a construction-time emptiness check would fail the second half of this.
