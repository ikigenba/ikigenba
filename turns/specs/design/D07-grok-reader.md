# D07-grok-reader

Package `internal/grok` reads Grok CLI's sessions into the vocabulary of D04. Its one entry point, `Read`, takes the Grok home (`$GROK_HOME`, else `~/.grok`, as D03 resolves it) and returns every session it finds under `sessions/`. D04 owns the rules every reader shares (at least one turn, ordering, UTC millisecond moments, count ranges, skips, a missing root, the unterminated final line, never writing, sessions ordered by id, a nil `Command`); this document says only what is particular to Grok.

Grok CLI keeps one directory per session at `sessions/<encoded-cwd>/<session-id>/`, where `<encoded-cwd>` is the working directory percent-encoded (`/` written `%2F`). That directory is the session source D04 speaks of: it is read, skipped or passed over as a whole. Of the many files in it, `grok.Read` reads exactly two. `summary.json` is written whole as one JSON document and is the only whole-JSON file the reader names; it carries the session's id (`info.id`, which in practice equals the directory's name), its working directory (`info.cwd`), its kind (`session_kind`) and, for a session resumed or forked from another, `parent_session_id`. `updates.jsonl` is the only JSON Lines file the reader names; each line is an envelope with an integer `timestamp` in epoch seconds (the time the line was written, sometimes seconds after the event), an integer `params._meta.agentTimestampMs` in epoch milliseconds (the time of the event) and the update at `params.update`, discriminated by `params.update.sessionUpdate`. A turn's moment is `agentTimestampMs`, falling back to `timestamp` when it is missing: whole seconds would merge many person, agent and tool turns of one second into one turn on the space, whose key holds the moment to the millisecond. Every turn comes from `updates.jsonl`: Grok's `chat_history.jsonl` records no time on any line, so it cannot place a person or tool turn in time, and the reader does not read it at all, nor `events.jsonl`, `prompt_context.json` or the rest.

Three kinds of update become turns. A `turn_completed` update is one agent turn: its `usage` carries `inputTokens`, `cachedReadTokens`, `outputTokens` and `reasoningTokens`, and its `usage.modelUsage` holds one key, the model that answered. On this machine that key is always one of the session's assistant chat lines' `model_id` values, so reading it gives the model the stories ask for without pairing chat lines to turns; Grok writes the model with a `-build` suffix, which the reader removes so the space sees `grok-4.7` rather than `grok-4.7-build`, as the decisions log asks. A `user_message_chunk` update is one person turn: Grok writes one per prompt the person typed (it matches the chat history's non-synthetic user lines). A `tool_call_update` whose `status` is `completed` or `failed` is one tool turn: each tool call gets exactly one such update when its result is returned to the model.

A session is headless when `session_kind` is `headless`, `subagent` or `subagent_resume`; interactive sessions carry no `session_kind`, and any other value is read as interactive. `subagent_resume` is a subagent resumed from an earlier one and runs unattended as its parent does. A session's parent is its `parent_session_id` when it names one. A subagent's own `summary.json` names no parent, but Grok records every subagent it spawns as a directory `subagents/<child-id>/` inside the spawning session's directory, so a session whose id appears there has that spawning session as its parent; `parent_session_id` wins when both are present (a resumed subagent names the subagent it resumed, which in turn rolls up to the top session).

A directory with turns but no `summary.json` is skipped rather than guessed at: its headless flag and parent are unknown, and the space keeps the headless flag of a session's first push forever, so a later run, when the file exists, does better than a guess today.

## REQUIREMENTS

- R-SMKS-IV4W: Package `internal/grok` (import path `github.com/ikigenba/ikigenba/turns/internal/grok`) MUST export `func Read(root string) session.Found`, where `session` is the package `internal/session`.
- R-SNSO-WMVL: `grok.Read` MUST treat each directory exactly two levels below `root/sessions/` (`root/sessions/<encoded-cwd>/<name>/`) as one session source, and a non-directory entry at either of those two levels, or any directory deeper than them, MUST yield no session and contribute nothing to `Found.Skipped`.
- R-SP0L-AEMA: `grok.Read` MUST read, of the files in a session directory, only `summary.json` as a file read whole as one JSON document and only `updates.jsonl` as a JSON Lines file, so that any other file in the directory (such as a `chat_history.jsonl` holding a line that is not JSON) is never a skip cause and yields no turn.
- R-6EKQ-8U1C: `grok.Read`, given a directory one level below `root/sessions/` that it cannot list, MUST count it exactly once in `Found.Skipped` and MUST still return the sessions of every other directory.
- R-6FSM-MLS1: `grok.Read`, given a `root/sessions/` that exists but cannot be listed, MUST return no session and a `Found.Skipped` of exactly 1.
- R-6H0J-0DIQ: `grok.Read`, given a directory `root/sessions/<encoded-cwd>/<P>/subagents/` that it cannot list, MUST treat it as naming no subagent (it gives no session a parent) and MUST NOT count it in `Found.Skipped`, so that the session `<P>` and every other session are returned as if that `subagents/` directory were empty.
- R-SRGE-1Y3O: `grok.Read`, given a session directory with no `summary.json` whose `updates.jsonl` yields at least one turn, MUST return no session for it and MUST count it in `Found.Skipped`; given one with no `summary.json` whose `updates.jsonl` is absent or yields no turn, it MUST neither return a session nor count it in `Found.Skipped`.
- R-SSOA-FPUD: `grok.Read` MUST return each session with `Ref.ID` equal to the `id` of the `info` object of its directory's `summary.json` when that `id` is a non-empty JSON string, even when it differs from the directory's name.
- R-STW6-THL2: `grok.Read` MUST return each session whose `summary.json` has no `info` object, or whose `info.id` is absent, not a JSON string, or empty, with `Ref.ID` equal to the name of its session directory.
- R-SV43-79BR: `grok.Read` MUST return each session with `Directory` equal to `filepath.Clean` of the `cwd` of the `info` object of its `summary.json` when that `cwd` is a non-empty JSON string, and when that string is not an absolute path the session directory MUST be skipped as one with no usable directory.
- R-SWBZ-L12G: `grok.Read` MUST return each session whose `summary.json` has no `info` object, or whose `info.cwd` is absent, not a JSON string, or empty, with `Directory` equal to `filepath.Clean` of the name of its `<encoded-cwd>` directory percent-decoded (each `%XX` replaced by the byte it encodes, so `%2Fhome%2Fpat%2Fshop` yields `/home/pat/shop`), and a name that does not percent-decode or decodes to a path that is not absolute MUST be skipped as one with no usable directory.
- R-SXJV-YST5: `grok.Read` MUST return a session with `Headless` true exactly when its `summary.json` has `session_kind` equal to the JSON string `headless`, `subagent` or `subagent_resume`, and with `Headless` false when `session_kind` is absent, null, not a string, or any other string.
- R-SYRS-CKJU: `grok.Read` MUST return a session whose `summary.json` has `parent_session_id` as a non-empty JSON string with `Parent` pointing to `Ref{Tool: session.ToolGrok, ID: <that string>}`, whatever any `subagents/` directory says.
- R-6I8F-E59F: `grok.Read` MUST return a session whose `summary.json` has no `parent_session_id` that is a non-empty JSON string, and whose `Ref.ID` is the name of a directory `root/sessions/<any encoded-cwd>/<P>/subagents/<Ref.ID>/` for some `<P>` other than the session's own `Ref.ID`, with `Parent` pointing to `Ref{Tool: session.ToolGrok, ID: <P>}`, choosing the least such `<P>` by Go string comparison when several directories qualify, whether or not the directory `<P>` is itself a session it returns.

- R-T3ND-VNIM: `grok.Read` MUST return one turn with `Whose` equal to `session.WhoseAgent` for each line of `updates.jsonl` whose `params.update.sessionUpdate` is the JSON string `turn_completed`, whatever the line's `method`.
- R-T4VA-9F9B: `grok.Read` MUST set an agent turn's `Tokens` from the line's `params.update.usage` object as `Input` = `inputTokens`, `Cached` = `cachedReadTokens`, `Output` = `outputTokens` and `Reasoning` = `reasoningTokens`, each 0 when its key is absent, all four 0 when `usage` is absent or not a JSON object, and no other key of `usage` (such as `cacheCreationTokens` or `totalTokens`) changes any of them; these four keys are the counts D04's count rules apply to.
