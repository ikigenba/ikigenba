# D07-grok-reader

Package `internal/grok` reads Grok CLI's sessions into the vocabulary of D04. Its one entry point, `Read`, takes the Grok home (`$GROK_HOME`, else `~/.grok`, as D03 resolves it), a cutoff `since` and a list of session ids, and returns the sessions it reads under `sessions/`. D04 owns the rules every reader shares (at least one turn, ordering, UTC millisecond moments, count ranges, skips, a missing root, the unterminated final line, never writing, sessions ordered by id, a nil `Command`); this document says only what is particular to Grok.

Grok CLI keeps one directory per session at `sessions/<encoded-cwd>/<session-id>/`, where `<encoded-cwd>` is the working directory percent-encoded (`/` written `%2F`). That directory is the session source D04 speaks of: it is read, skipped or passed over as a whole. Of the many files in it, `grok.Read` reads exactly two. `summary.json` is written whole as one JSON document and is the only whole-JSON file the reader names; it carries the session's id (`info.id`, which in practice equals the directory's name), its working directory (`info.cwd`), its kind (`session_kind`) and, for a session resumed or forked from another, `parent_session_id`. `updates.jsonl` is the only JSON Lines file the reader names; each line is an envelope with an integer `timestamp` in epoch seconds (the time the line was written, sometimes seconds after the event), an integer `params._meta.agentTimestampMs` in epoch milliseconds (the time of the event) and the update at `params.update`, discriminated by `params.update.sessionUpdate`. A turn's moment is `agentTimestampMs`, falling back to `timestamp` when it is missing: whole seconds would merge many person, agent and tool turns of one second into one turn on the space, whose key holds the moment to the millisecond. Every turn comes from `updates.jsonl`: Grok's `chat_history.jsonl` records no time on any line, so it cannot place a person or tool turn in time, and the reader does not read it at all, nor `events.jsonl`, `prompt_context.json` or the rest.

Three kinds of update become turns. A `turn_completed` update is one agent turn: its `usage` carries `inputTokens`, `cachedReadTokens`, `outputTokens` and `reasoningTokens`, and its `usage.modelUsage` holds one key, the model that answered. On this machine that key is always one of the session's assistant chat lines' `model_id` values, so reading it gives the model the stories ask for without pairing chat lines to turns; Grok writes the model with a `-build` suffix, which the reader removes so the space sees `grok-4.7` rather than `grok-4.7-build`, as the decisions log asks. A `user_message_chunk` update is one person turn: Grok writes one per prompt the person typed (it matches the chat history's non-synthetic user lines). A `tool_call_update` whose `status` is `completed` or `failed` is one tool turn: each tool call gets exactly one such update when its result is returned to the model.

A session is headless when `session_kind` is `headless`, `subagent` or `subagent_resume`; interactive sessions carry no `session_kind`, and any other value is read as interactive. `subagent_resume` is a subagent resumed from an earlier one and runs unattended as its parent does. A session's parent is its `parent_session_id` when it names one. A subagent's own `summary.json` names no parent, but Grok records every subagent it spawns as a directory `subagents/<child-id>/` inside the spawning session's directory, so a session whose id appears there has that spawning session as its parent; `parent_session_id` wins when both are present (a resumed subagent names the subagent it resumed, which in turn rolls up to the top session).

Push reads only what changed since the last successful push started (D10, D03), so `Read` does not read every session directory; D04 owns the cutoff rules every reader shares (`since`, the zero `since` reading everything, an unread source contributing nothing, a read source yielding what it yields uncut). What is particular to Grok is what judges a session directory: it has changed when its `updates.jsonl` or the directory itself has a modification time that is not before `since`, either sufficing. `updates.jsonl` changes with every update Grok writes, and the directory's own time changes when a file in it is created, removed or replaced, as `summary.json` is when Grok rewrites it whole, so between them they catch a session that gained turns or changed its kind or parent. A directory whose session id is in `ids` is read changed or not: D08 passes the session ids of the dispatch jobs a read Claude session names, so a Grok job's session is read and linked to its parent even when it finished long ago. The session id is the `Ref.ID` the directory would yield, `info.id` from `summary.json` or else the directory's name, so an unchanged directory is opened to read its `summary.json` when `ids` is not empty, as D06 opens a rollout file for its first `session_meta` line. An unchanged directory whose id cannot be learned, because `summary.json` is missing, unreadable or not one JSON object, is not read, whatever `ids` holds; it is read once it changes. A subagent finds its parent in the `subagents/` of a spawning directory whether that directory was read or not, since listing `subagents/` is not reading the session. A modification time that cannot be learned, other than a missing `updates.jsonl`, counts as changed, so the failure is reported as a skip rather than hidden.

A directory with turns but no `summary.json` is skipped rather than guessed at: its headless flag and parent are unknown, and the space keeps the headless flag of a session's first push forever, so a later run, when the file exists, does better than a guess today.
