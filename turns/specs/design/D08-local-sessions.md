# D08-local-sessions

This document covers two packages. `internal/dispatch` reads the dispatch tool's job directories and gives a dispatched Codex CLI or Grok CLI session its Claude Code parent. `internal/local` reads every session on this machine: it runs the three readers (D05-D07) over the roots `paths.Paths` names (D03), links them, and answers one result. `local.Read` is the one entry point `turns push` (D10) and `turns status` (D12) use to read sessions, so both commands read the same files the same way and see the same sessions and skips. The commands' own documents state what each does with the result.

The dispatch skill hands a task to `codex exec` or `grok -p` in the background. Each job gets a directory `<Jobs>/<job>/` (the job name carries a date, a time, the tool and a task name; turns does not interpret it), and once the child starts, the file `session-id` in that directory holds the child's session id: on this machine a 36-character uuid followed by a newline. Some jobs have no `session-id` file, because the child never started or the job predates the file; such a job is not a job for turns. `dispatch.Jobs` lists the jobs it can read, each as its directory path and the id with surrounding white space removed. The directory path is the jobs directory joined with the job's name, so it is absolute when the caller passes an absolute directory, as `local.Read` always does (`paths.Paths.Jobs` is absolute). Nothing about a job is ever written.

A dispatched child carries no link to the session that dispatched it: a top-level `codex exec` rollout names no parent thread and a headless Grok session no parent session. The link comes from the other side. The dispatching Claude session reads the job's files, so its tool results name the job directory's path. `local.Read` gives `claude.Read` the directory of every job, and `claude.Read` answers a `Mention` for each Claude session whose tool results name one of them, carrying the path exactly as it was given, the Claude session, and the earliest moment that session named it (D05). `dispatch.Link` then takes each Codex or Grok session that has no parent, finds the jobs whose session id is that session's id, and gives the session as its parent the Claude session of the earliest mention of any of those jobs' directories. When two mentions share the earliest moment, the one whose session id sorts first wins, so the result never depends on input order. A session that already has a parent, such as a Codex subagent thread, keeps it: the tool's own record wins over a path match. Claude sessions are never changed, since a Claude session is never a dispatch child. A job no Claude session names, or whose id matches no session read, links nothing; a parent found by a later run reaches the space because push re-sends each session's latest held turn and the space sets a parent while it holds none.

The match is on the session id alone, not the tool: the job's name carries the tool, but turns does not parse it, and a uuid shared by a Codex and a Grok session is not a case that arises; both would be linked. `Link` returns a new slice and leaves its arguments as they were, so a caller may keep the readers' results unchanged beside the linked one.

`local.Found` is the gathered result: the sessions of all three tools, Claude's first, then Codex's, then Grok's, each tool's in its reader's order (by id), and the skip count per tool, with an entry for every tool even when it is zero so a caller can print a line per tool without checking for absence. A home where none of the tools was ever installed reads as no session and nothing skipped, and nothing is created.

## REQUIREMENTS

- R-ZJM2-5AAF: Package `internal/dispatch` (import path `github.com/ikigenba/ikigenba/turns/internal/dispatch`) MUST export `type Job struct` whose fields are exactly `Dir string` and `SessionID string`.
- R-ZKTY-J214: Package `internal/dispatch` MUST export `func Jobs(dir string) []Job`.
- R-ZM1U-WTRT: Package `internal/dispatch` MUST export `func Link(sessions []session.Session, jobs []Job, mentions []session.Mention) []session.Session`, where `session` is package `internal/session` (D04).
- R-ZN9R-ALII: `dispatch.Jobs(dir)` MUST return one `Job` for each entry `<name>` of `dir` that is a directory holding a regular file `session-id` whose content, with leading and trailing white space removed as `strings.TrimSpace` removes it, is non-empty, with `Dir` equal to `filepath.Join(dir, <name>)` and `SessionID` equal to that trimmed content, judging a symbolic link (for the entry or for `session-id`) by what it points to, verified at least with contents `<id>` followed by `\n`, `<id>` with no newline, and `<id>` surrounded by spaces and ending in `\r\n`, each giving `SessionID` `<id>`.
- R-ZOHN-OD97: `dispatch.Jobs(dir)` MUST return no `Job` for an entry of `dir` that is a directory with no `session-id`, whose `session-id` is a directory, cannot be read, is empty or holds only white space, and MUST still return the `Job` of every other readable entry as if those entries were absent.
- R-ZPPK-24ZW: `dispatch.Jobs(dir)` MUST return no `Job` for an entry of `dir` that is not a directory, such as a regular file named like a job.
- R-ZQXG-FWQL: `dispatch.Jobs(dir)`, given a `dir` that does not exist, is not a directory, or cannot be read, MUST return a slice of length 0 and MUST NOT create `dir`.
- R-ZS5C-TOHA: `dispatch.Jobs` MUST return its `Job`s ordered by `Dir` ascending, comparing paths as Go strings (byte by byte), whatever order the entries were created in.
- R-ZTD9-7G7Z: `dispatch.Jobs(dir)` MUST leave everything under `dir` as it found it: no file or directory is created, changed (contents, mode or modification time) or removed.
- R-ZUL5-L7YO: `dispatch.Link` MUST return a slice of the same length as `sessions` whose element at each index equals the element of `sessions` at that index in `Ref`, `Directory`, `Headless`, `Command` and `Turns`, and in `Parent` as well except where R-ZVT1-YZPD gives it one.
- R-ZVT1-YZPD: `dispatch.Link` MUST return, for an element of `sessions` whose `Ref.Tool` is `session.ToolCodex` or `session.ToolGrok`, whose `Parent` is nil, and for which `jobs` holds a `Job` whose `SessionID` equals its `Ref.ID` and `mentions` holds a `Mention` whose `Path` equals that `Job`'s `Dir`, that session with a non-nil `Parent` equal to the `By` of the earliest such `Mention`, earliest meaning the smallest `Moment` as an instant (compared with `time.Time.Before`, whatever location each carries).
- R-ZX0Y-CRG2: When several `Mention`s qualify under R-ZVT1-YZPD with the same earliest `Moment`, `dispatch.Link` MUST give as `Parent` the `By` with the smallest `ID` comparing as Go strings, and among those with equal `ID` the smallest `Tool`, so that the result does not change when `mentions` is reordered.
- R-ZY8U-QJ6R: When `jobs` holds several `Job`s whose `SessionID` equals a Codex or Grok session's `Ref.ID`, `dispatch.Link` MUST choose that session's `Parent` under R-ZVT1-YZPD and R-ZX0Y-CRG2 from the `Mention`s of all of those `Job`s' `Dir`s together, verified at least by two such jobs whose directories are named by different Claude sessions, the later-listed job's mention being the earlier one.
- R-ZZGR-4AXG: `dispatch.Link` MUST match a `Mention`'s `Path` to a `Job`'s `Dir` only when the two strings are equal byte for byte: a `Path` that differs from `Dir` only by a trailing `/`, by letter case, or by being a longer path under `Dir` MUST NOT link that job.
- R-00ON-I2O5: `dispatch.Link` MUST return a session whose `Parent` is non-nil with a `Parent` equal to the one it was given, even when a `Job` and a `Mention` would qualify it under R-ZVT1-YZPD.
- R-034G-9M5J: `dispatch.Link` MUST return every session whose `Ref.Tool` is not `session.ToolCodex` or `session.ToolGrok`, in particular every `session.ToolClaude` session, with its `Parent` as given, even when its `Ref.ID` equals a `Job`'s `SessionID` named by a `Mention`.
- R-04CC-NDW8: `dispatch.Link` MUST leave a Codex or Grok session's nil `Parent` nil when no `Job` in `jobs` has a `SessionID` equal to its `Ref.ID`, and when such `Job`s exist but no `Mention` has a `Path` equal to any of their `Dir`s.
- R-05K9-15MX: `dispatch.Link` MUST disregard a `Mention` whose `By` equals the session's own `Ref` when choosing that session's `Parent`, so that the next earliest qualifying `Mention` decides it, or the `Parent` stays nil when there is none.
- R-06S5-EXDM: `dispatch.Link` MUST disregard a `Mention` whose `By.ID` is empty when choosing a session's `Parent`, so that the next earliest qualifying `Mention` decides it, or the `Parent` stays nil when there is none.
- R-0801-SP4B: `dispatch.Link` MUST give a `Parent` under R-ZVT1-YZPD to every Codex and every Grok session that qualifies, including a Codex session and a Grok session that share one `Ref.ID` matched by one `Job`.
