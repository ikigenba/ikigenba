# D12 — status

`turns status` tells a person where turns stands: the space it pushes to, whether a token is stored, when it last pushed, and per tool how many sessions and turns are on this machine against how many of them the space holds. It is the `status` command of `cli.Run` (D02 declares Run, its exit codes, the root refusal that comes before any argument is looked at, and the top-level usage line for `status`). This document states everything status does after the root refusal.

Arguments come first, under D02's rules for every command: `--help` or `-h` anywhere among status's arguments prints the usage this document states and wins over every other argument, reading nothing and making no request; status declares no option and no positional argument, so any other argument is refused as an unknown option or with `status takes no arguments`, the first refused argument deciding. D02 owns those refusals and help's precedence; this document owns only status's usage text.

Then the configuration. `paths.Resolve` over `Deps.Getenv` and `Deps.Etc`, then `config.Load` (D03). An error from `paths.Resolve` is reported as the single line `turns: <error text>` (for example `turns: HOME is not set`); an error from `config.Load` as `turns: could not read the configuration` with the error text as unprefixed detail. Either error's text is written in its diagnostic rendering (D02), so a control byte in a path or a HOME value is escaped and never breaks a line. Either way status exits 1, writes nothing to stdout, and nothing else happens. A missing file is not an error: an unconfigured account is a normal case for status.

Then the report. Six lines, always in this order: `space:`, `token:`, `last push:`, then `claude:`, `codex:`, `grok:`. The space is `config.Config.Space`, the effective space (the user's config, else the host default). The token line says only `set` or `none`; the token never appears in anything status writes. The last-push line shows the moment held in `State/last-push`, the moment the last successful push started; D03 owns the file's meaning and format and D10 writes it. status reads it by D03's rule for `last-push`: the content with at most one trailing LF removed, when that is exactly a valid `YYYY-MM-DDTHH:MM:SSZ` moment, is printed as held; a missing file, an unreadable one and any other content (empty, a second LF, a carriage return or space, any other shape, an impossible date) are what push reads as no cutoff, and status shows them as `never`, as it always has for a file that holds no moment. Since the accepted shape is fixed, printing as held and reformatting are the same thing. status only reads the file: nothing it counts depends on what the file holds.

The local half of each tool line counts the sessions `local.Read(p, time.Time{})` (D08) returned for that tool and the sum of their turns. The zero cutoff reads every session file whatever `last-push` holds, the files `turns push --all` reads, so the difference between a line's two halves is what `turns push --all` would send; a plain push sends only the part of it in files changed since the last push started. Sessions the readers skipped are not counted and are not mentioned: the six lines are fixed by the story, and skips are push's to report.

The space's half is present only when both Space and Token are non-empty. Then status asks the space for the latest held turn of every session it read, through `space.Client.Latest`, in `local.Read` order across the three tools, in consecutive requests of exactly `space.MaxLatest` sessions each but the last, which holds the remaining 1 to `space.MaxLatest`. A session the space holds (non-zero `Held.Latest`) counts toward the space's sessions, and its local turns at or before that moment count toward the space's turns. This is what the story means by "the turns up to the latest one the space holds": the held turn itself is included, later local turns are not. When no session was read, no request is made and the space's half reads zero. When Space or Token is empty, the half is left off, no request is made, and status still succeeds.

When a `Latest` call fails, status makes no further request and reports that call's error: the report still prints whole with `; unknown on the space` as the space's half of all three tool lines, then stderr carries `turns: could not read the space: <Reason>` and, only when the error's Detail is non-empty, an empty line and that Detail, quoted with `seam.QuoteOutput` when the error says so and unprefixed in its diagnostic rendering otherwise; the space client has already replaced the token in Detail with `<token>`; a quoted Detail counts as empty when `seam.QuoteOutput` makes nothing of it; exit 1.

status never takes `State/lock`, never writes or creates any file or directory, and never calls `push_turns`. A successful run writes nothing to stderr.
