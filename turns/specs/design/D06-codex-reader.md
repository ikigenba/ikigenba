# D06-codex-reader

Package `internal/codex` reads Codex CLI's session files into the vocabulary of D04. Its one entry point, `Read`, takes the Codex home (`$CODEX_HOME`, else `~/.codex`, as D03 resolves it) and returns every session it finds there. The invariants every reader shares (at least one turn, ordering, moments in UTC to the millisecond, the count range, skip causes, the missing-root rule, never writing, ordering by id, no two sessions with one id, a nil `Command`) are D04's and are not repeated here; this document says which files are Codex sessions and how their lines map.

Codex CLI writes one rollout file per thread. Live threads sit under `sessions/` in a dated tree, `sessions/YYYY/MM/DD/rollout-<moment>-<thread id>.jsonl`; archived threads sit under `archived_sessions/`, which on the machines observed is flat, though `Read` accepts rollout files at any depth under it in case Codex dates it later. Codex compresses older rollout files with zstd, both in `archived_sessions/` and in older days of `sessions/`, as `rollout-*.jsonl.zst`; such a file is read as the JSON Lines it decompresses to. Reading zstd needs a module outside the Go standard library, an external dependency the user must approve; if it is refused, `.jsonl.zst` files are instead ignored like any other foreign file, and the six requirements that name them change accordingly.

Every line of a rollout file is an envelope with a `timestamp` (an RFC 3339 string), an `ordinal`, a `type` and a `payload`. The first `session_meta` line names the thread: its `payload.id` is the session id, its `payload.cwd` the directory, its `payload.originator` says whether it ran headless (`codex_exec`) or with a person attending (anything else), and for a subagent thread (`payload.thread_source` `subagent`) its `payload.parent_thread_id` names the parent thread. A forked thread's file carries a second `session_meta`, the source thread's, which is ignored, and begins with history copied from the source thread, restamped at the moment of the fork; lines before the first `session_meta`'s `subagent_history_start_ordinal` are that copy and yield nothing, since the source thread's own file already holds them.

Three kinds of line are turns. A `token_usage_record` line is one response of the model, an agent turn, with its counts from `payload.usage` and its model from the latest `turn_context` line before it; Codex's `event_msg` `token_count` lines repeat the same usage without a response id and are not read. An `event_msg` line whose payload is an `item_completed` of a `UserMessage` item is something the person typed; a `response_item` message with role `user` is not, because Codex also records injected instructions that way. A `response_item` whose payload is a `function_call_output` or `custom_tool_call_output` is a tool result. Every other line yields no turn.

When one thread id appears in more than one rollout file, as it would if a thread were both live and archived, one file speaks for it: a file under `sessions/` before one under `archived_sessions/`, and otherwise the file whose path sorts first, so an uncompressed `.jsonl` wins over a `.jsonl.zst` of the same name.

## REQUIREMENTS

- R-1YNS-PKZ9: Package `internal/codex` (import path `github.com/ikigenba/ikigenba/turns/internal/codex`) MUST export `func Read(root string) session.Found`, where `session` is `github.com/ikigenba/ikigenba/turns/internal/session`.
- R-1ZVP-3CPY: `codex.Read` MUST treat as one session source each regular file exactly three directory levels below `root/sessions/` (as in `root/sessions/2026/10/21/<name>`, whatever the three directories are named) whose name begins with `rollout-` and ends with `.jsonl` or `.jsonl.zst`.
- R-213L-H4GN: `codex.Read` MUST treat as one session source each regular file at any depth below `root/archived_sessions/` (directly in it or in any subdirectory) whose name begins with `rollout-` and ends with `.jsonl` or `.jsonl.zst`.
- R-22BH-UW7C: `codex.Read`, given under `root` a file that R-1ZVP-3CPY and R-213L-H4GN do not name, such as a file under `root/sessions/` whose name does not begin with `rollout-` or does not end with `.jsonl` or `.jsonl.zst`, a rollout file directly in `root/sessions/` or at another depth than three levels below it, or any file elsewhere under `root`, MUST neither return a session for it nor count it in `Found.Skipped`, whatever it holds.
- R-23JE-8NY1: `codex.Read` MUST read a source whose name ends with `.jsonl` as its JSON Lines file (the file D04's line rules apply to), and MUST read a source whose name ends with `.jsonl.zst` as the JSON Lines file its zstd-decompressed content forms, so that a `.jsonl.zst` source yields exactly the session, turns and skip outcome a `.jsonl` source holding the decompressed content would yield.
- R-24RA-MFOQ: `codex.Read`, given a source whose name ends with `.jsonl.zst` and whose content is not a complete, valid zstd stream (such as plain JSON Lines or a truncated stream), MUST return no session for it and MUST count it in `Found.Skipped`.
- R-25Z7-07FF: `codex.Read` MUST return as each session's `Ref.ID` the `payload.id` string of the first line in its source, in line order, whose `type` is `session_meta`, and MUST take nothing from any later `session_meta` line of that source.
- R-2773-DZ64: `codex.Read`, given a source from which at least one turn is read but which has no `session_meta` line, or whose first `session_meta` line's `payload.id` is absent, not a JSON string, or empty, MUST return no session for it and MUST count it in `Found.Skipped`.
- R-28EZ-RQWT: `codex.Read` MUST return as each session's `Directory` the `payload.cwd` string of its source's first `session_meta` line (cleaned as D04 requires), and a source with at least one turn whose first `session_meta` line's `payload.cwd` is absent, not a JSON string, or not an absolute path MUST yield no session and count in `Found.Skipped`.
- R-29MW-5INI: `codex.Read` MUST return a session with `Headless` true when its source's first `session_meta` line's `payload.originator` is exactly the string `codex_exec`, and with `Headless` false otherwise, including `codex-tui`, `Codex Desktop`, any other value, and an absent `payload.originator`.
- R-1CNQ-0MG4: `codex.Read` MUST return a session whose source's first `session_meta` line has `payload.thread_source` equal to `subagent` and a non-empty JSON string `payload.parent_thread_id` with `Parent` pointing to `Ref{Tool: session.ToolCodex, ID: <that payload.parent_thread_id>}` (subject to D04's rule on a parent equal to the session itself).
- R-1DVM-EE6T: `codex.Read` MUST return a session whose source's first `session_meta` line has `payload.thread_source` equal to `subagent` and a `payload.parent_thread_id` that is absent or not a non-empty JSON string, but a non-empty JSON string at `payload.source.subagent.thread_spawn.parent_thread_id`, with `Parent` pointing to `Ref{Tool: session.ToolCodex, ID: <that value>}` (subject to D04's rule on a parent equal to the session itself), and with a nil `Parent` when neither is a non-empty JSON string.
- R-2DAL-ATVL: `codex.Read` MUST return a session with a nil `Parent` when its source's first `session_meta` line's `payload.thread_source` is absent or is any value other than `subagent`, even when that line names a `payload.parent_thread_id`.
- R-2FQE-2DCZ: `codex.Read` MUST return, for each line of a source whose `type` is `token_usage_record` and that no other requirement here excludes, a turn with `Whose` equal to `session.WhoseAgent` and `Moment` equal to that line's `timestamp`.
- R-2GYA-G53O: `codex.Read` MUST return each agent turn with `Tokens.Input`, `Tokens.Cached`, `Tokens.Output` and `Tokens.Reasoning` equal to the line's `payload.usage` values `input_tokens`, `cached_input_tokens`, `output_tokens` and `reasoning_output_tokens` respectively, each 0 when its key or `payload.usage` itself is absent, and MUST NOT add `cache_write_input_tokens`, `total_tokens` or any other key into any of the four.
- R-2I66-TWUD: `codex.Read` MUST return each agent turn with `Model` equal to the `payload.model` string of the last line of type `turn_context` that precedes its `token_usage_record` line in the source, and `""` when no `turn_context` line precedes it or that line's `payload.model` is absent or not a JSON string.
- R-1BFT-MUPF: `codex.Read`, given a source with two or more `token_usage_record` lines that R-1900-VB81 and R-1A7X-92YQ do not exclude and that carry the same non-empty `payload.response_id`, MUST return at most one agent turn for that response id, with `Tokens` and `Model` as the last of those lines yields them and with `Moment`, and position among turns of equal `Moment`, as the first of those lines with a usable moment (in the sense of D04) yields them; when none of them has a usable moment, no turn is returned for that response id; lines that R-1900-VB81 or R-1A7X-92YQ exclude MUST NOT take part in this merge.
- R-2KLZ-LGBR: `codex.Read` MUST return one agent turn for each `token_usage_record` line whose `payload.response_id` is absent, not a JSON string, or empty, without merging it with any other line.
- R-1900-VB81: `codex.Read` MUST return no turn for a `token_usage_record` line whose `payload.thread_id` is a JSON string different from the session's `Ref.ID`, and MUST return the line's turn when `payload.thread_id` is absent, is not a JSON string (such as a number or null), or equals the session's `Ref.ID`.
- R-2N1S-CZT5: `codex.Read` MUST return, for each line of a source whose `type` is `event_msg`, whose `payload.type` is `item_completed` and whose `payload.item.type` is `UserMessage`, a turn with `Whose` equal to `session.WhosePerson`, `Moment` equal to that line's `timestamp`, `Model` equal to `""` and all four `Tokens` fields 0.
- R-2O9O-QRJU: `codex.Read` MUST return, for each line of a source whose `type` is `response_item` and whose `payload.type` is `function_call_output` or `custom_tool_call_output`, a turn with `Whose` equal to `session.WhoseTool`, `Moment` equal to that line's `timestamp`, `Model` equal to `""` and all four `Tokens` fields 0.
- R-2PHL-4JAJ: `codex.Read` MUST return no turn for a line that R-2FQE-2DCZ, R-2N1S-CZT5 and R-2O9O-QRJU do not name, including a `response_item` whose `payload.type` is `message` with `payload.role` `user`, an `event_msg` whose `payload.type` is `token_count`, an `event_msg` `item_completed` whose item is of any type other than `UserMessage`, and `session_meta` and `turn_context` lines.
- R-1A7X-92YQ: `codex.Read`, given a source whose first `session_meta` line has a JSON integer `payload.subagent_history_start_ordinal` N, MUST return no turn for any line whose own `ordinal` value (not its position in the file) is a JSON integer less than N, and such a line of type `turn_context` MUST NOT supply the `Model` of any turn; lines whose `ordinal` is N or greater, or absent, are read as if the key were absent; this holds when verified at least with `ordinal` values that differ from the lines' positions in the file and with a turn line whose `ordinal` is exactly N.
- R-2RXD-W2RX: `codex.Read` MUST read a line's `timestamp` as a JSON string in RFC 3339 form, with or without fractional seconds and with any offset; a turn whose line's `timestamp` is absent, not a JSON string, or not in that form has an unusable moment in the sense of D04.
- R-2T5A-9UIM: `codex.Read`, given a source under `root/sessions/` and a source under `root/archived_sessions/` that both yield a session with the same `Ref.ID`, MUST return the session the source under `root/sessions/` yields.
- R-2UD6-NM9B: `codex.Read`, given two or more sources under the same one of `root/sessions/` and `root/archived_sessions/` that yield sessions with the same `Ref.ID`, MUST return the session of the source whose path relative to `root` is smallest in byte order, so that `rollout-x.jsonl` wins over `rollout-x.jsonl.zst` in one directory.
- R-2VL3-1E00: `codex.Read` MUST apply R-2T5A-9UIM and R-2UD6-NM9B only among sources that yield a session: a source that is skipped still counts in `Found.Skipped`, and a source with the same id that does yield a session is then returned.
