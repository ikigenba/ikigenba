# D10 — push

`turns push` is the command the timer runs every five minutes and a person runs by hand. It reads this home's session files changed since the last successful push started through `local.Read` (D08), asks the space which turns it already holds, sends the latest held turn of each session again with every turn after it, and prints one report line per tool. It is stated here through `cli.Run` (D02), with the selection, batching and counting rules factored into the pure package `internal/push` so their boundaries can be tested without a session tree or a fake space.

## Order of a run

After the root refusal and the shared argument frame of D02 (help anywhere wins; an unknown option or a positional argument is refused, the first in argument order deciding, so `turns push extra --bogus` says `push takes no arguments` and `turns push --bogus extra` says `unknown option '--bogus'`), push does, in order: read the configuration (`paths.Resolve`, `config.Load`, D03); refuse when the space or the token is missing; take the start moment; take the lock, except on `--dry-run`; read the host name; read `last-push` for the cutoff, unless `--all` is given; read the sessions; ask the space for the latest turn it holds of every session read, unless none was read; push, except on `--dry-run`; print the report; write `last-push`, except on `--dry-run`. Help and usage refusals read nothing. When the paths cannot be resolved (no `HOME`, say) the diagnostic is that error's text alone on the `turns: ` line; when the configuration files cannot be read it is `turns: could not read the configuration` with the error as detail. A refusal of the paths or the configuration reads no session and makes no request.

## Which files a run reads

A run reads only the session files changed since the last successful push started. The start moment is the first `Deps.Now()` of the run, taken before it waits for the lock and before it reads any session file. The cutoff `since` is the moment `State/last-push` holds, read as D03 states (a missing, unreadable or malformed file counts as none, so the zero time); with `--all` it is the zero time whatever the file holds. The sessions are `local.Read(p, since)` (D08), which decides which files a cutoff reads: a file modified within the cutoff's second or after it is read, one modified before is not, and every dispatch job is read on each run. `--dry-run` reads by the same rule, `--all` with it, so `turns push --dry-run --all` reports what `turns push --all` would send. The cutoff is read after the lock is taken, so a run that waited reads the `last-push` the run it waited for wrote, and a file written while that run was under way is read again.

A run that read no session asks the space nothing: it prints the three zero lines (and any skipped lines), and without `--dry-run` writes `last-push`, since a quiet run is a successful one. A skipped file that has not changed since is not read by a plain run, so it is not reported again; `--all` reads it and reports it. `last-push` is written with the start moment only after a successful push; a failed push, refused part way included, and every dry run leave it unchanged, so the next run reads again every file the failed run read. The options are `--dry-run` and `--all`, in either order; giving one twice is the same as giving it once, following the precedent the design already set for `--dry-run`.

## The lock

Two runs never push at once. A non-dry run takes an exclusive `flock(2)` on `State/lock`, creating the state directory and the file as needed, and waits for it with no time limit, holding it until it has written `last-push`. The lock is advisory and its file is never removed; its contents mean nothing. When the file cannot be opened or locked (a `State` that is a regular file, say), the run fails before any request with `turns: could not lock '<path>'`, an empty line, and the error's text unprefixed. A dry run sends nothing, so it neither takes nor waits for the lock, and the not-configured refusal comes before the lock, so an inert host account never contends for it. A test proves the lock in-process without sleeping: it checks from inside a fake transport that the lock is held, and it may hold the `flock` on the file itself and watch `/proc/locks` for the run's blocked wait. The absence of a time limit is a SHOULD, since no finite test proves it.

## The host

The host every entry carries is `Deps.Hostname` up to its first dot. A host name that cannot be read, or whose short form is empty, fails the run before any session is read and before any request, with no report: there is nothing a partial report could say, and every entry would be refused by the space anyway.

## Selection

The space answers, per session, the moment of the latest turn it holds (`space.Held`, zero when none). A session's turns to send are those whose moment is not before that latest, or all of them when it is zero; so the latest held turn is always sent again, which is how a turn first pushed while its lines were still being written gets its complete fields, and how a parent found late reaches a session already held. A turn is new, and counted, when its moment is after the latest, or always when the latest is zero. A session the space holds turns of but which, locally, has no turn at or after the latest (its file lost turns) is omitted: nothing is sent for it and nothing is counted. Every other field of the session goes as `local.Read` returned it.

## Batches

The pending sessions, in `local.Read` order, are cut into batches of at most `space.MaxPushSessions` entries and `space.MaxPushTurns` turns. A batch is closed when it holds either limit exactly; a session whose turns do not fit in the room left continues as the first entry of the next batch, its earliest turns in the earlier batch. So 500 sessions or 1000 turns fit in one batch and the 501st session or 1001st turn opens a second. A split session is one entry per batch it spans, each carrying every field of the session.

## The report

The report is one line per tool, claude, codex, grok, `<tool>: <s> sessions, <t> turns pushed` (`to push` on a dry run), with `session` and `turn` singular exactly at 1, so 0 is plural. Under a tool's line, only when `local.Read` skipped any of its files, comes `<tool>: <n> sessions skipped`, singular at 1. The counts are those of accepted batches: a tool's turns are its new turns in them and its sessions the distinct sessions with at least one new turn in them, so a split session counts once and a re-sent turn never counts. The report prints whole on success and on a push failure, and never on a failed dry run or before the sessions are read.

## Failures

Every error of the space client is a `space.Error` (D09). On any of them push stops: no further request is made, the report prints with the counts of the batches accepted so far (all zeros when the latest query failed), and stderr carries `turns: push failed: <Reason>`, then, when the detail is non-empty, one empty line and the detail, quoted with `seam.QuoteOutput` when the error says it is another program's output and unprefixed otherwise; a quoted detail counts as empty when `seam.QuoteOutput` makes nothing of it, so a body of only newlines adds no empty line. `last-push` is untouched. Nothing is kept for a retry but the unchanged `last-push`: the next run reads again every file changed since the last successful push started, asks the space again and resends from what it holds, the refused batch included.

After a run that pushed everything, or read no session, push writes the start moment in UTC as `YYYY-MM-DDTHH:MM:SSZ` and a newline to `State/last-push`. If that write fails, the push itself happened, so the report still prints, and the run fails with `turns: could not write '<path>'`, an empty line, and the error's text unprefixed.

## Notes

The story's opening paragraph and decision D4 say every exchange goes through the gateway's `mutate`; the latest query goes through `call`, because the gateway refuses a read tool through `mutate` (proven live, recorded in D09). Push relies on D09 for the wire envelope and the entry shape and states only which fields and counts it sends.

Departure from `shape/` "Bounded work": that rule bounds a service's memory by a page over a store. turns is a client CLI with no store: it holds in memory the sessions of one person's machine, as `local.Read` returns them, and the latest moment of each. That set grows only with one person's use of three tools on one machine, the session files are already read whole to find their turns, and the space bounds every exchange (500 refs per query, 500 entries and 1000 turns per push) so nothing the client sends grows with the set. Paging the local tree would only add a cursor over files that have no stable order across runs.
