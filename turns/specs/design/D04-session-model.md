# D04-session-model

Package `internal/session` holds the vocabulary every other part of turns shares: the three readers (D05-D07) produce it, D08 links and gathers it, the space client (D09) sends it, and push (D10) and status (D12) count it. It holds types and one function only; it reads nothing and writes nothing.

A session is one conversation one tool recorded on this machine, named by a `Ref`: the tool (`claude`, `codex` or `grok`) and the tool's own id for it. Session identity on the space is the same pair. A session may have a parent, the session that started it: a Claude Code subagent's enclosing session, a Codex CLI subagent thread's parent thread, a Grok CLI session's parent session. Readers only find parents within their own tool; the cross-tool parent of a dispatched Codex or Grok job is set later by D08's `Link`. A session also carries the working directory it ran in, whether it ran headless (no person attending) or interactive, at most one first command, and its turns.

A turn is one step of the conversation at one moment, and its `Whose` says who took it: `person` is something the person typed, `agent` is one response of the model (with the model's name and its token counts: input, cached input, output and reasoning), and `tool` is a tool result returned to the model. Person and tool turns usually carry zero counts and may carry an empty model; each reader's document says exactly how its lines map. No text of any turn is kept.

A `Command` is the first slash command the person ran in a session, its name with its slash and its argument, the one piece of typed text that leaves the machine. Only Claude Code records commands in a form turns reads, so only Claude sessions ever carry one; D05 says which command is first.

A `Mention` is a sighting, in a Claude session's tool result, of the path of a dispatch job directory: which path, which Claude session (`By`) and when. `claude.Read` returns them beside its sessions, given the job directories to look for, and D08's `Link` uses the earliest mention of a job's directory to give that job's Codex or Grok session its parent. Nothing else of the tool result is looked at.

A reader's result is a `Found`: the sessions it could read and `Skipped`, how many session sources it could not read as sessions. A source is what one session is read from: a session file for Claude Code and Codex CLI, a session directory for Grok CLI (D07 names the files in it that are read). A source that is not a session at all, such as a file that never recorded a turn, is simply not a session and is not counted; a source that looks like a session but is broken (a complete line that is not a JSON object, turns with no usable id or directory, an impossible token count, a file that cannot be read) is skipped whole and counted once. Push reports the count per tool so a format change in a tool does not go unnoticed, and a later run tries the source again. Most session files are JSON Lines, one JSON object per line; a final line not ended by a newline is a line the tool is still writing, and readers ignore it until it is complete. A Grok session directory also holds files written whole as one JSON document, which have no line rules: such a file either parses as one object or skips its directory.

The invariants below are owned here so D05-D07 do not repeat them. They exist so that the space never refuses a batch for turns' own data: every rule the space checks (a known tool, a non-empty id, a parent different from the session, an absolute directory with no trailing slash, a moment at or after 1970, a known whose, counts from 0 to 10^12) holds of everything a reader returns. A turn whose moment is missing, unparsable or before 1970 is dropped rather than skipping its session, because one bad timestamp says nothing about the rest of the file; a count out of range skips the whole source because it means the reader has misread the format. Each requirement naming the three readers holds of each of them separately. The per-line turn rules of D05, D06 and D07 yield candidate turns; candidates of one session that share a moment and a whose are then merged into one turn, their counts summed, because the space keys a turn by its moment to the millisecond and its whose and would otherwise keep only one of them. So a reader requirement stating one turn per line or per id, or the tokens and model a turn takes from its line, holds as written whenever no two candidates share a moment and a whose; when they do, the merge decides.

- R-E90Y-BSQO: Package `internal/session` (import path `github.com/ikigenba/ikigenba/turns/internal/session`) MUST export `type Tool string` and the constants `ToolClaude Tool = "claude"`, `ToolCodex Tool = "codex"` and `ToolGrok Tool = "grok"`.
- R-EA8U-PKHD: Package `internal/session` MUST export `func Tools() []Tool`.

- R-ECON-H3YR: `session.Tools` MUST return a fresh slice on every call: after a caller changes any element of a slice it returned, the next call MUST still return `ToolClaude`, `ToolCodex`, `ToolGrok` in that order.
- R-EDWJ-UVPG: Package `internal/session` MUST export `type Whose string` and the constants `WhosePerson Whose = "person"`, `WhoseAgent Whose = "agent"` and `WhoseTool Whose = "tool"`.
- R-EGCC-MF6U: Package `internal/session` MUST export `type Ref struct` whose fields are exactly `Tool Tool` and `ID string`.
- R-EHK9-06XJ: Package `internal/session` MUST export `type Command struct` whose fields are exactly `Name string` and `Argument string`.
- R-EIS5-DYO8: Package `internal/session` MUST export `type Tokens struct` whose fields are exactly `Input int64`, `Cached int64`, `Output int64` and `Reasoning int64`.
- R-EK01-RQEX: Package `internal/session` MUST export `type Turn struct` whose fields are exactly `Moment time.Time`, `Whose Whose`, `Model string` and `Tokens Tokens`.
- R-EL7Y-5I5M: Package `internal/session` MUST export `type Session struct` whose fields are exactly `Ref Ref`, `Parent *Ref`, `Directory string`, `Headless bool`, `Command *Command` and `Turns []Turn`.
- R-EMFU-J9WB: Package `internal/session` MUST export `type Found struct` whose fields are exactly `Sessions []Session` and `Skipped int`.
- R-ENNQ-X1N0: Package `internal/session` MUST export `type Mention struct` whose fields are exactly `Path string`, `By Ref` and `Moment time.Time`.
- R-EOVN-ATDP: Each of `claude.Read`, `codex.Read` and `grok.Read` MUST return in its `Found.Sessions` only sessions whose `Turns` holds at least one turn.
- R-EQ3J-OL4E: Each of `claude.Read`, `codex.Read` and `grok.Read`, given a session source (as D05, D06 or D07 names that reader's sources) that has no skip cause but from which no turn is read, such as an empty file, MUST neither return a session for it nor count it in `Found.Skipped`.
- R-ERBG-2CV3: Each of `claude.Read`, `codex.Read` and `grok.Read` MUST return only sessions whose `Ref.ID` is non-empty.
- R-ESJC-G4LS: Every session `claude.Read` returns MUST have `Ref.Tool` equal to `session.ToolClaude`, every session `codex.Read` returns `session.ToolCodex`, and every session `grok.Read` returns `session.ToolGrok`.
- R-ETR8-TWCH: Each of `claude.Read`, `codex.Read` and `grok.Read` MUST return only sessions whose `Parent` is nil or points to a `Ref` whose `Tool` equals the returning reader's tool, whose `ID` is non-empty, and which is not equal to the session's own `Ref`.
- R-EUZ5-7O36: Each of `claude.Read`, `codex.Read` and `grok.Read`, given a session source that names its parent with an empty id or with the session's own id, MUST return that session with a nil `Parent` and MUST NOT count the source in `Found.Skipped`.
- R-EW71-LFTV: Each of `claude.Read`, `codex.Read` and `grok.Read` MUST return only sessions whose `Directory` is absolute (`filepath.IsAbs` reports true) and equal to `filepath.Clean` of itself, so that a source recording an absolute directory with a trailing slash or with `.` or `..` elements yields that directory in its cleaned form.
- R-OX0X-GWCI: Each of `claude.Read`, `codex.Read` and `grok.Read` MUST return each session's `Turns` ordered by `Moment` ascending, and turns with equal `Moment` MUST keep the order the source records them (for `claude.Read` the order of their lines in the session file, an agent turn built from several lines standing at the first line carrying its `message.id`; for `codex.Read` the order of their lines in the session file, as D06 places a turn built from several lines; for `grok.Read` the order D07 defines).
- R-EZUQ-QR1Y: Each of `claude.Read`, `codex.Read` and `grok.Read` MUST return every `Turn.Moment` with location `time.UTC` and equal to the instant the source records truncated toward the past to the whole millisecond (a recorded `09:00:00.0009Z` yields `09:00:00.000Z`, never `09:00:00.001Z`), whatever offset the source wrote it with.
- R-F12N-4ISN: Each of `claude.Read`, `codex.Read` and `grok.Read`, given a session source in which a turn's recorded moment is missing, cannot be parsed in the form that reader's document names, or after truncation to the millisecond lies before `1970-01-01T00:00:00Z`, MUST return the source's other turns without that turn and MUST NOT count the source in `Found.Skipped` for that reason; a source left with no turn by this rule is then neither a session nor skipped.
- R-OY8T-UO37: Each of `claude.Read`, `codex.Read` and `grok.Read` MUST treat the turns that the per-line turn rules of D05, D06 and D07 yield (one turn per line, per `message.id`, per `response_id` or per `turn_completed` line, with the tokens and model each takes from its line or lines) as candidate turns, and MUST return in each session those candidates merged so that no two returned turns of one session share both `Moment` and `Whose`: candidates that would share them MUST be returned as one turn with that `Moment` and `Whose`, each of its four `Tokens` fields the sum of theirs and its `Model` that of the last of them in the order the source records them (for `claude.Read` the order of their lines in the session file, an agent turn built from several lines standing at the first line carrying its `message.id`; for `codex.Read` the order of their lines in the session file, as D06 places a turn built from several lines; for `grok.Read` the order D07 defines), standing where the first of them stands in that order.
- R-OZGQ-8FTW: Each of `claude.Read`, `codex.Read` and `grok.Read`, given a session source in which candidates merged into one turn have, for any `Tokens` field, a sum greater than 1000000000000 or too large to hold in an `int64`, MUST return no session for that source and MUST count it in `Found.Skipped`.
