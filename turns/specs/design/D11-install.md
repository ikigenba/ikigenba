# D11-install

`turns install` puts turns on the person's user timer. It is a command of `cli.Run` (D02 owns the grammar, the root refusal, the help precedence and the usage-error frame every command shares; this document states only what `install` adds). The timer is the two user units `turns.Units()` carries, `turns.service` and `turns.timer`, in their host form; the one line of them that varies is `ExecStart=`.

Two cases, told apart by one file. A host is a machine where `os.Stat` succeeds on `<HostUnits>/turns.timer`, whatever kind of file it is (opsctl puts a regular file there; turns asks only that something stands there), where `HostUnits` is the `paths.Resolve` field naming the global user-unit directory (`<Etc>/systemd/user`, empty when `Deps.Etc` is empty, so a test that leaves `Etc` empty is always on a laptop). On a host opsctl owns the units and keeps them current, so `install` writes nothing and only enables the timer: a copy under the person's home would shadow the host's, since `systemd.unit(5)` searches the user configuration directory (`$XDG_CONFIG_HOME/systemd/user` or `~/.config/systemd/user`) before `/etc/systemd/user`. Everywhere else, including when the stat fails for any reason, is a laptop: `install` writes both units into `UserUnits`, reloads the user manager and enables the timer.

On a laptop the service names the turns that ran `install`. Its path is `Deps.Arg0` made absolute without resolving symlinks, the way a shell found it: a name containing a slash is taken as a path, joined to `Deps.Dir` when relative, and used without checking that a file exists there (the story is silent; the kernel ran turns by that name, so it names the running binary); a bare name is looked up in the `PATH` that `Deps.Getenv` answers, the first entry holding an executable regular file of that name winning, an empty or relative entry taken against `Deps.Dir`. The result is cleaned; a result that is still not absolute (an empty `Deps.Dir` with a relative name or entry) counts as not found. A symlink is kept as the name, never its target, so a person who points a stable link at a new build keeps a working timer. The host case never needs the path, so it never fails for want of one.

The path goes into a unit file, and `systemd.service(5)` ("Command lines") unquotes the command per `systemd.syntax(7)` ("Quoting"), expands `%` specifiers (`systemd.unit(5)`), substitutes `$` variables, merges a line ending in a backslash with the next, and forbids control characters in the command. Quoting can carry spaces, quotes and backslashes, and `%%` carries a percent sign, but the manual leaves open whether `$$` is honored in the program path itself (it says only that the program may not be a variable), and it offers no way to carry a control character. turns therefore refuses rather than quotes: a path holding a space, a quote, a backslash, `%`, `$`, a control character or bytes that are not UTF-8 is reported and nothing is written. Such a path is rare for a binary that `go install` or the install script puts under `$GOBIN` or `$GOPATH/bin`, and refusing keeps every written `ExecStart=` line one that systemd reads exactly as written, with no reliance on behavior the manual does not state. Every other byte, including ordinary UTF-8 letters, which `systemd.syntax(7)` says are accepted, is written as is.

The units are written whole every time, so a second `install` repairs a unit an older turns or another copy wrote: the files end up byte for byte what this turns writes, mode 0644, whatever they held before. Directories `install` has to create are mode 0755. Both files are in place before systemctl runs.

systemctl runs through `Deps.Exec`. On a laptop it is `systemctl --user daemon-reload`, which `systemctl(1)` says reloads all unit files, so the manager sees the files just written, then `systemctl --user enable --now turns.timer`, which creates the symlinks the timer's install section names and, with `--now`, starts it after they are created. Enabling a timer that is already enabled leaves its symlinks in place, and `systemd.timer(5)` says that, under the timer's persistence setting, the time of the last trigger is stored on disk and is removed only by `systemctl clean --what=state`; so a repeated `install` keeps the record, and a missed run is still caught up. `--user` talks to the calling user's manager (`systemctl(1)`). A failed reload stops the run before the enable. A failure leaves the written units in place, so a later `install` with a user manager running succeeds. The failure diagnostic quotes what systemctl said, stderr in preference to stdout, each judged by what `seam.QuoteOutput` makes of it, so output of only newlines counts as nothing; when it said nothing the diagnostic is one line, and when it could not be started at all turns' own error text follows unquoted, since it is not another program's output.

The order is observable at every step: D02's frame (root refusal, help, usage errors), then `paths.Resolve` (a rejected `HOME` fails before anything else is looked at, the binary's path included), then the host check, then on a laptop the lookup and check of the binary's path, then the two writes, then the reload, then the enable. Each failure stops the run where it occurs.

`install` reads no configuration, token, state or session file, writes nothing but the two units and the directories leading to them (nothing at all on a host), and sends nothing: a timer installed before `turns configure` is inert (each run exits 4, which the service unit counts as success), so `install` works with no configuration at all. It succeeds silently.

## REQUIREMENTS

- R-7NA6-G3RR: `turns install --help` and `turns install -h`, and any `install` invocation with `--help` or `-h` among its arguments, MUST make `cli.Run` print exactly this text to stdout, each line ended by a newline and nothing after the last, write nothing to stderr, write no file, pass no `seam.Cmd` to `Deps.Exec`, and return `cli.ExitOK`:

  ```
  Usage: turns install

  Write turns.service and turns.timer under ~/.config/systemd/user/, reload the
  user manager, and enable and start the timer, which runs 'turns push' every
  five minutes. On a host whose /etc/systemd/user/ already holds the units, only
  enable and start the timer. Safe to run again.

  Options:
    -h, --help   print this help
  ```
