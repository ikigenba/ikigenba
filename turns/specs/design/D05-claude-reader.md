# D05-claude-reader

Package `internal/claude` reads Claude Code's session files into the vocabulary of D04. Its one entry point, `Read`, takes the Claude config directory (`$CLAUDE_CONFIG_DIR`, else `~/.claude`, as D03's `Paths.Claude` resolves it), the absolute paths of the dispatch job directories D08 found, and a cutoff `since`, and answers the sessions it read with the mentions of those job directories it saw in their tool results. D04 owns everything common to the three readers: the session types, at least one turn per session, the order of turns and of sessions, moments in UTC truncated to the millisecond, the count range, what skips a file (a complete line that is not a JSON object, an unreadable file, a count out of range or not an integer, turns with no usable directory or id), blank lines and an unterminated final line ignored, a missing root or a missing `projects/` directory, turns with an unusable moment dropped, a parent equal to the session read as none, no duplicate ids, and that readers never write. This document says which files are sessions, which of them a call reads, and how their lines map.

A call reads only the session files changed since the cutoff: a file is read when its own modification time is not before `since`, so a file modified within the second the cutoff names is read again, and the zero `since` reads every file. Each file is judged alone: a top-level file and each of its subagent files are read or not on their own modification times, whatever the others' are, and a subagent read without its top file still names that file's session as parent. A file that is not read yields nothing, no session, no mention and no skip. A file that is read is read whole, exactly as it would be with no cutoff. The reader keeps nothing between calls, so a file skipped by one call is read again by a later one once its modification time passes that call's cutoff, and `--all` (the zero cutoff) reads it whatever its time.

A session file is JSON Lines under `root/projects/<dir>/`, where `<dir>` encodes the working directory the session started in. A top-level session is `<dir>/<stem>.jsonl`, its id the stem whatever its form (uuids, and `ssh-` prefixed stems too). Each subagent the session ran is a file `agent-<x>.jsonl` under `<dir>/<stem>/subagents/`, or under `<dir>/<stem>/subagents/workflows/<wf>/` for a subagent a workflow ran. A subagent's id is `<stem>/agent-<x>`, never the bare file stem, since agent ids are only unique within their session, and its parent is the top session `<stem>`: a subagent another subagent started has the same parent, so the `.meta.json` beside each file, which names the agent that started it, is not read. A subagent is always headless. The subagent directory exists or not independently of `<stem>.jsonl`, so a subagent keeps its parent even when the top file is gone. The same session id can appear under two project directories (a session resumed in another directory); the copy at the shallower, then lexically first, path wins.

Only `user` and `assistant` lines are turns. A user line is a tool result when Claude Code marks its origin as a task notification, a peer or a coordinator, or when its content holds a `tool_result`; otherwise it is the person's turn when its content is a string and it is not `isMeta`. Everything else a user line can be (text-only arrays, meta lines) is no turn. Claude Code writes one assistant response as several lines sharing a `message.id`, one content block each, each with its own timestamp; the response is one agent turn at the moment of its first line, carrying the model and usage of its last line, so a response still being written when one run reads it is completed by a later run. Claude Code records reasoning tokens nowhere at the top of `usage`: they appear, when at all, under `usage.output_tokens_details.thinking_tokens`, so reasoning is read there unless a top-level `thinking_tokens` appears. Lines whose model is `<synthetic>` (responses Claude Code made up itself, with zero usage) are kept as ordinary agent turns. `isSidechain` is true on every subagent line and false on every top-level line, so it says nothing the file's place does not, and it is ignored.

A session is headless when the first line naming an `entrypoint` names `sdk-cli`; any other value, or none, is interactive. Its directory is the first non-empty `cwd` in the file, since the first lines are often bookkeeping lines with none. Its first command is the first `<command-name>` pair found anywhere in a person turn's content, not only at its start, since Claude Code can write a caveat or a `<command-message>` before it; a pair naming `clear` or `exit`, with or without the slash Claude Code writes, is passed over and the search goes on in the same content and then in later person turns. The name is kept as written. The argument is the first `<command-args>` pair after the chosen name in that turn, and only its first line, cut to at most 256 bytes without splitting a character: what the person typed on later lines is prompt text, which never leaves the machine.

A mention is a dispatch job directory's path seen in the text of a tool result: the absolute path, ending there or followed by a slash and a file name, or the same path written from `~`. The match is on whole path segments, so one job's path never matches a job whose name extends it. Only tool results count, not the assistant's tool calls or the lines Claude Code keeps of its own requests, so the mention dates from when the dispatched job's output came back to the session.
