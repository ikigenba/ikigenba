# D05-claude-reader

Package `internal/claude` reads Claude Code's session files into the vocabulary of D04. Its one entry point, `Read`, takes the Claude config directory (`$CLAUDE_CONFIG_DIR`, else `~/.claude`, as D03's `Paths.Claude` resolves it) and the absolute paths of the dispatch job directories D08 found, and answers the sessions it read with the mentions of those job directories it saw in their tool results. D04 owns everything common to the three readers: the session types, at least one turn per session, the order of turns and of sessions, moments in UTC truncated to the millisecond, the count range, what skips a file (a complete line that is not a JSON object, an unreadable file, a count out of range or not an integer, turns with no usable directory or id), blank lines and an unterminated final line ignored, a missing root or a missing `projects/` directory, turns with an unusable moment dropped, a parent equal to the session read as none, no duplicate ids, and that readers never write. This document says which files are sessions and how their lines map.

A session file is JSON Lines under `root/projects/<dir>/`, where `<dir>` encodes the working directory the session started in. A top-level session is `<dir>/<stem>.jsonl`, its id the stem whatever its form (uuids, and `ssh-` prefixed stems too). Each subagent the session ran is a file `agent-<x>.jsonl` under `<dir>/<stem>/subagents/`, or under `<dir>/<stem>/subagents/workflows/<wf>/` for a subagent a workflow ran. A subagent's id is `<stem>/agent-<x>`, never the bare file stem, since agent ids are only unique within their session, and its parent is the top session `<stem>`: a subagent another subagent started has the same parent, so the `.meta.json` beside each file, which names the agent that started it, is not read. A subagent is always headless. The subagent directory exists or not independently of `<stem>.jsonl`, so a subagent keeps its parent even when the top file is gone. The same session id can appear under two project directories (a session resumed in another directory); the copy at the shallower, then lexically first, path wins.

Only `user` and `assistant` lines are turns. A user line is a tool result when Claude Code marks its origin as a task notification, a peer or a coordinator, or when its content holds a `tool_result`; otherwise it is the person's turn when its content is a string and it is not `isMeta`. Everything else a user line can be (text-only arrays, meta lines) is no turn. Claude Code writes one assistant response as several lines sharing a `message.id`, one content block each, each with its own timestamp; the response is one agent turn at the moment of its first line, carrying the model and usage of its last line, so a response still being written when one run reads it is completed by a later run. Claude Code records reasoning tokens nowhere at the top of `usage`: they appear, when at all, under `usage.output_tokens_details.thinking_tokens`, so reasoning is read there unless a top-level `thinking_tokens` appears. Lines whose model is `<synthetic>` (responses Claude Code made up itself, with zero usage) are kept as ordinary agent turns. `isSidechain` is true on every subagent line and false on every top-level line, so it says nothing the file's place does not, and it is ignored.

A session is headless when the first line naming an `entrypoint` names `sdk-cli`; any other value, or none, is interactive. Its directory is the first non-empty `cwd` in the file, since the first lines are often bookkeeping lines with none. Its first command is in the first of its person turns that carries a `<command-name>` other than `clear` or `exit`, with or without the slash Claude Code writes; the name is kept as written and the argument is what `<command-args>` holds.

A mention is a dispatch job directory's path seen in the text of a tool result: the absolute path, ending there or followed by a slash and a file name, or the same path written from `~`. The match is on whole path segments, so one job's path never matches a job whose name extends it. Only tool results count, not the assistant's tool calls or the lines Claude Code keeps of its own requests, so the mention dates from when the dispatched job's output came back to the session.

## REQUIREMENTS

- R-VSA4-JDQJ: Package `internal/claude` (import path `github.com/ikigenba/ikigenba/turns/internal/claude`) MUST export `func Read(root string, jobs []string) (session.Found, []session.Mention)`.
- R-VTI0-X5H8: `claude.Read` MUST treat each regular file whose name ends in `.jsonl` and that lies directly in a directory `root/projects/<dir>/` as one session source whose session, when returned, has `Ref.ID` equal to the file name without its `.jsonl` suffix, whatever form that stem has (such as one beginning `ssh-`), and a nil `Parent`.
- R-VUPX-AX7X: `claude.Read` MUST treat each regular file named `agent-<x>.jsonl` that lies directly in `root/projects/<dir>/<stem>/subagents/` or directly in `root/projects/<dir>/<stem>/subagents/workflows/<wf>/` as one session source whose session, when returned, has `Ref.ID` equal to `<stem>/agent-<x>`.
- R-VVXT-OOYM: `claude.Read` MUST return each session read from a subagent source (R-VUPX-AX7X) with `Parent` equal to `session.Ref{Tool: session.ToolClaude, ID: <stem>}`, whether or not `root/projects/<dir>/<stem>.jsonl` exists and whatever any other file beside the subagent file (such as its `.meta.json`) holds.
- R-VX5Q-2GPB: `claude.Read` MUST return each session read from a subagent source (R-VUPX-AX7X) with `Headless` true, whatever `entrypoint` its lines carry.
- R-VYDM-G8G0: `claude.Read` MUST treat no file under `root` other than those R-VTI0-X5H8 and R-VUPX-AX7X name as a session source: any other file (such as `journal.jsonl` in a workflows directory, a file in `subagents/` not named `agent-<x>.jsonl`, a `.jsonl` file directly in `root/projects/`, or one nested deeper than those paths) MUST yield no session, no mention and nothing in `Found.Skipped`, whatever it holds.
- R-VZLI-U06P: `claude.Read`, given two or more sources that would each be returned as a session with the same `Ref.ID`, MUST return the one whose path relative to `root/projects` has the fewest elements and, among those, the lexically first relative path (compared byte by byte), and MUST return no mention read from the others.
- R-W0TF-7RXE: `claude.Read` MUST read a turn only from a line whose `type` is `user` or `assistant`: a line of any other type (such as `attachment`, `system` or a bookkeeping type) MUST yield no turn, whatever else it holds.
- R-W21B-LJO3: `claude.Read` MUST read a `user` line whose `origin.kind` is `task-notification`, `peer` or `coordinator` as one turn with `Whose` `session.WhoseTool`, whatever its `message.content` and `isMeta` hold.
- R-W397-ZBES: `claude.Read` MUST read a `user` line whose `message.content` is an array holding at least one item whose `type` is `tool_result` as one turn with `Whose` `session.WhoseTool`, whatever other items the array holds.
- R-W4H4-D35H: `claude.Read` MUST read a `user` line whose `message.content` is a string, whose `isMeta` is absent or not `true`, and whose `origin.kind` is none of those R-W21B-LJO3 names, as one turn with `Whose` `session.WhosePerson`.
- R-W5P0-QUW6: `claude.Read` MUST read no turn from a `user` line that neither R-W21B-LJO3, R-W397-ZBES nor R-W4H4-D35H makes a turn, such as one whose content is an array of only `text` items or a string line whose `isMeta` is `true`.
- R-W6WX-4MMV: `claude.Read` MUST return every person and tool turn with `Model` "" and all four `Tokens` fields 0, and with `Moment` the instant of the line's top-level `timestamp`, an RFC 3339 string (the form in which D04's rule on unusable moments applies to `claude.Read`).
- R-WXSV-4EK2: `claude.Read` MUST return at most one turn with `Whose` `session.WhoseAgent` for each distinct non-empty string `message.id` that the file's `assistant` lines carry, and exactly one unless R-W9CP-W649 drops it, however many lines carry it and whether or not they are adjacent.

- R-WAKM-9XUY: `claude.Read` MUST return each agent turn with `Model` equal to the `message.model` string of the last line in file order carrying its `message.id`, as written (a model of `<synthetic>` included), or "" when that line has no string `message.model`.
- R-WBSI-NPLN: `claude.Read` MUST return each agent turn with `Tokens.Input` equal to `input_tokens` plus `cache_creation_input_tokens`, `Tokens.Cached` equal to `cache_read_input_tokens` and `Tokens.Output` equal to `output_tokens`, each read from `message.usage` of the last line in file order carrying its `message.id`, a key that is absent (or a `usage` that is absent) counting as 0.
- R-WE8B-F931: `claude.Read` MUST return each agent turn with `Tokens.Reasoning` equal to `message.usage.thinking_tokens` of the last line carrying its `message.id` when that key is present, else `message.usage.output_tokens_details.thinking_tokens` when that key is present, else 0.
