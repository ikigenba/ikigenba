# D09-space-client

`internal/space` is how turns talks to a space. It reaches the `sessions` service through the space's MCP gateway at `https://mcp.<space>/mcp` and asks it two things: which turns it already holds of some sessions (`get_latest_turns`), and to keep some more (`push_turns`). `push` (D10) uses both; `status` (D12) uses only the first. Everything the package says to the gateway and everything it makes of the answer is here; what a command prints for a failure is the command's own design, built from the `Error` this package returns.

## The request

Each method call is one HTTP request, one JSON-RPC `tools/call` of a gateway tool. The gateway's `call` tool reaches a service's read tools and its `mutate` tool the changing ones, each taking `service`, `tool` and `args`; a read tool sent through `mutate` is refused, so `Latest` goes through `call` and `Push` through `mutate`. The protocol is the stateless 2026-07-28 revision of MCP: every request stands alone, carrying its protocol version in a header and in `params._meta` with empty client capabilities, so there is no `initialize`, no session header and no state between calls. The headers are the ones that revision names, plus the token as a Bearer credential.

These wire facts were proven live on 2026-11-01 against `https://mcp.us.ikigenba.dev/mcp`: the request shape below was answered 200 `application/json` with a JSON-RPC result holding `content` (one text item) and `structuredContent`; a gateway or tool refusal (an unknown service, a read tool sent through `mutate`, invalid arguments) is a 200 result with `isError` true and the reason in its text content; a bad token is 401 `text/plain` with a one-line body; `MCP-Protocol-Version` without `Mcp-Method` is a 400 JSON-RPC error. The `sessions` side (argument and answer shapes, limits, millisecond moments ending `Z`) is the service's published tool contract.

A push entry carries a session as D04 holds it: its ref, its parent and command only when it has them (the members are omitted, never `null`), the host the caller names, its directory and headless flag, and the turns the caller chose, each moment in UTC to the millisecond in the form the service answers, `2026-10-13T14:02:11.250Z`. Nothing else is sent: the service sets host, directory and headless on first push and keeps them, and an unknown member would be a contract the service never published.

## The answer

Both tools answer `structuredContent.sessions`, one entry per sent ref or entry, in order, each with the `tool` and `id` sent and `latest`, the latest moment the space holds of that session, absent when it holds none. The client checks the answer against what it sent, count, tool, id and order, so a caller can pair each `Held` with its session by position, and parses `latest` to UTC. Members the client does not read are ignored, so the service can add to its answer without breaking turns.

## Failures

Every failure is a `*space.Error`: `Reason` is the text after a command's `turns: push failed: ` or `turns: could not read the space: `, `Detail` what goes after the empty line, and `Quoted` whether Detail is another program's words (the gateway's) to be quoted with `> `. The classes, checked in this order: the request could not be completed at all (network, including the caller's context ending); 401; any other non-200 status; a 200 that is not a readable answer to this request; a JSON-RPC error; a tool result with `isError`. A body or text carried into Detail is cut at 4096 bytes, the cap appkit's MCP client uses for an HTTP error's body, so a gateway that answers a megabyte of HTML cannot flood the journal. A redirect is never followed: a 3xx is an HTTP answer like any other non-200, so a token is never carried to another URL, and this holds whatever the `http.Client` the caller passes would do with a redirect: the request still goes through that client's `Transport` (or `http.DefaultClient`'s), but the client's own redirect policy is overridden, for instance by sending through a shallow copy of it whose `CheckRedirect` returns `http.ErrUseLastResponse`. A Content-Type is compared by media type, case-insensitively, its parameters (`; charset=utf-8`) ignored. The token is never part of a Reason; it can reach a Detail only if the gateway or the transport echoed it.

## Recorded decisions

- turns has its own small client, standard library only, and does not require appkit. appkit's `mcp.Client` could target the URL and carry the Bearer through an injected transport, but its `Result` is opaque where turns needs `structuredContent`, it forwards identity headers meant for services behind nginx, it pulls the server library's module graph into a laptop CLI, and devctl and opsctl, the CLI precedents, take no appkit; turns' AGENTS.md prefers the standard library.
- `Accept` is `application/json` alone: the gateway answers JSON, and an event stream is not a readable answer.
- A `latest` that is present but not a string holding an RFC 3339 moment, JSON `null` included, makes the answer unreadable; the service omits the member when it holds nothing.
- `resultType` is not read; a result that is not complete lacks the expected `structuredContent` and is unreadable.
- Preconditions are the caller's: `Latest` takes 1..`MaxLatest` refs; `Push` takes 1..`MaxPushSessions` sessions, at most `MaxPushTurns` turns over all of them, no two with the same `Ref`. D10 and D12 keep them; what either method does when one is broken is unspecified, beyond still returning only `*space.Error` errors.
- The nil-`hc` case is proven by a non-parallel test that sets `http.DefaultClient.Transport` to a recording fake, restored in `t.Cleanup`, and sets `http.DefaultTransport` to a fake that always fails, also restored, so an implementation that builds its own client instead of using `http.DefaultClient` fails offline rather than reaching the network.
- The request carries the caller's context, so a cancelled or expired context ends the call as a network failure.
