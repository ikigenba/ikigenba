# Decision 20 — Testing-language conformance: the suite's four layers, declared in `AGENTS.md`

**Decision.** notify adopts the suite's **testing-language contract** —
`root project/design/D23.md` — which owns the four layer names, the rule for what
each layer may touch, the `//go:build live` mechanism, the ban on skipping outside
live-tagged files, and the requirement that every tree declare its testing facts in
its `AGENTS.md`. This Decision is the **citation, and citation is adoption**: notify
owns none of that contract's content and restates none of it normatively. What is
local — and all this Decision adds — is **notify's own testing facts** and **where
the proof of the declaration lives**.

The contract carries two `[proof: per-service]` ids, which notify therefore proves
in its own tree:

- `R-O1AD-MRKW` — the doc-truth test over the committed `AGENTS.md`.
- `R-O2IA-0JBL` — the source scan banning `t.Skip` outside live-tagged files.

**notify's testing facts** (the content its `AGENTS.md` Tests section must declare,
and what the doc-truth test asserts):

- **Default-gate test command:** `cd notify && go test ./...`, inside the green bar
  the design Conventions already fix (`go build ./...`, `go vet ./...`,
  `gofmt -l .` silent, `go test ./...`).
- **Layers present: hermetic and composed — no live layer and no manual layer.**
  - **hermetic** is the bulk of the suite: the `internal/push` client and consumer
    handler tests against a **mock ntfy server on `127.0.0.1`** — a real
    `httptest` listener, never ntfy.sh; the `internal/mcp` tests driving
    `NewHandler` through the real `appkit/mcp` `ServeHTTP` seam; the `internal/db`
    load and feed-offset guards; the `cmd/notify` Spec, consumer-declaration, and
    web tests loading the repo-real `share/www` tree through `appkit/web` and
    driving it with `net/http/httptest`; the event chain that drives the real
    revised outbox, `FeedHandler`, and `consumer.Run` over `httptest` to the mock
    ntfy server; the telemetry-adoption tests that install a recording
    `http.RoundTripper` through the composition root's own wiring path — all
    in-process, loopback only; and the **shipped-file guards** — the
    `etc/nginx.conf` fragment content assertions (D4, D8, D10, D19), the
    committed-`manifest.env` scans, and the `loopback_guard` source scan — which
    read committed files from disk and touch nothing else.
  - **composed** is the boot smoke in `cmd/notify/main_test.go`: it builds
    notify's own binary, assembles an `/opt/notify/`-shaped tree under
    `t.TempDir()`, runs it on a free loopback port, and asserts the served
    `/health`. It is offline by construction.
  - **no live layer.** notify carries no `//go:build live` file. It is the one
    service in this group with a genuine external dependency — ntfy.sh, reached
    with `NTFY_TOPIC` / `NTFY_API_KEY` — and a live layer would be a defensible
    future addition; today no such test exists, so the honest declaration is that
    the layer is absent. Every current push claim is proven against the loopback
    mock, and adding a live layer later means adding a `//go:build live` file, the
    declared invocation, and the credentials it needs, not relabelling these.
  - **no manual layer.** notify commits no runbook of its own; the suite-level
    "the whole stack composes" check belongs to the umbrella, not here.
- **Environmental preconditions beyond the Go toolchain: none.** The composed boot
  smoke shells out only to `go build` and the binary it just built; no test needs
  `git`, `python3`, a browser, a real ntfy credential, or a running suite. In
  particular, no test changes behavior based on whether `NTFY_TOPIC` or
  `NTFY_API_KEY` happen to be set — hermeticity is a property of the code, and
  notify's push config is injected, not read from the ambient environment.
- **GOWORK mode: workspace.** The gate resolves `appkit`, `eventplane`, and
  `registry` through the repo-root `go.work` and the committed replace-siblings.
  The production build's `GOWORK=off` is `bin/ship notify`'s, not the test gate's,
  and notify commits no separate standalone build check.

**Where the proof lives.** Both adopted ids are proven in
**`cmd/notify/docs_test.go`** — a new file at the composition root, the package
that already owns notify's read-from-disk assertions over shipped artifacts
(`etc/nginx.conf`, `etc/manifest.env`, `share/www`). No new package is introduced.
The doc-truth test reads the committed `notify/AGENTS.md` from disk and asserts its
Tests section declares the four facts above; the source scan walks the tree's
`*_test.go` files, skips any file carrying the `live` build constraint, and asserts
zero occurrences of the skip verbs — assembling its needle from parts so the scan
never matches its own source.

**Rejected.**

- **Restate the contract's layer definitions locally so this design reads
  self-contained.** A local restatement is drift by construction: it goes stale the
  moment `root project/design/D23.md` is rewritten, and the suite's rule is cite,
  never restate. The citation is the whole mechanism. Rejected.
- **Keep the conventional `unit` / `integration` / `end-to-end` names and map them
  in prose.** Rejected by the contract itself, and for notify specifically:
  `AGENTS.md` today calls the whole suite "Unit", which mislabels both a boot smoke
  that compiles and runs a real binary and an event chain that runs a real outbox,
  feed, and consumer loop. The layer names say what a test may *touch*, which is
  the property actually being policed.
- **Re-mint local ids for the two behaviors instead of citing
  `R-O1AD-MRKW` / `R-O2IA-0JBL`.** Both are `[proof: per-service]`: the ids are the
  suite's handles for one behavior each, proven once per adopting tree. Minting
  parallel local ids would give one behavior two handles and break the
  id-to-behavior invariant. Rejected.
- **Declare a `live` layer now, on the strength of notify having a real external
  dependency.** The declaration states what the tree *has*, not what it could have.
  No `//go:build live` file exists, so declaring the layer would make the
  `AGENTS.md` false on the first read and the doc-truth test would be asserting a
  fiction. Rejected — declared absent, and addable later as a visible change.
- **Call the mock-ntfy push tests `live` because they exercise the real HTTP
  client.** The mock is an `httptest` server on `127.0.0.1`: no external service,
  no credential. Under the contract that is squarely hermetic, and calling it live
  would both mislabel it and push it out of the default gate, where it belongs.
  Rejected.

**Verification.**

Both ids below are **adopted**, not minted here: each belongs to the umbrella
Decision cited beside it, which states the behavior. These lines say only what
substrate proves it inside `notify/`.

- `R-O1AD-MRKW` — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/notify/docs_test.go` that reads the committed
  `notify/AGENTS.md` from disk and asserts its Tests section declares the
  default-gate test command (`go test ./...`), the layers present (hermetic and
  composed; no live, no manual), that there are no environmental preconditions
  beyond the Go toolchain, and the GOWORK mode (workspace).
- `R-O2IA-0JBL` — adopted from `root project/design/D23.md`. Substrate: hermetic —
  a Go test in `cmd/notify/docs_test.go` that walks the `notify/` tree's
  `*_test.go` files from disk, excludes any file carrying the `live` build
  constraint, and fails on any occurrence of `t.Skip`, `t.Skipf`, or `t.SkipNow`,
  with the needle assembled from parts so the scan cannot match itself.
