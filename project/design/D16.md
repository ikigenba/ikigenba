# Decision 16 — The manifest-reader scripts are proven under the green gate (`bintest`)

**Decision.** The two repo-root manifest readers — `bin/registry` and the
staging half of `bin/start` (`stage_manifest_root`, which builds the prod-shaped
runtime manifest root under the run dir) — graduate out of the
deliberately-untested `bin/` tier. They define the dev/prod layout parity
(`etc/<version>/manifest.env` + `current`, D1/D2's on-disk contract), and both
have already diverged silently once (the sibling-path drift the layout-parity
fix repaired). They are proven by a new Go test module, **`bintest/`** (module
`bintest`), added to the root `go.work`, so its tests run under the existing
green gate (`go test ./...` from the repo root, workspace mode) with no new
runner.

- **Tests exec the real scripts** — `../bin/registry` and `../bin/start`,
  resolved relative to the `bintest` package directory — never a
  reimplementation of their logic. The scripts are the substrate that can
  falsify the claims.
- **`bin/registry` needs no seam.** `REGISTRY_ROOT` already parameterizes it;
  tests point it at a fixture root in `t.TempDir()`.
- **`bin/start` gains two small seams**, inert when unused:
  - `--stage-only` — stage the runtime manifest root, then exit `0` **before**
    building or launching anything.
  - `START_RUN_DIR` — env override of the run dir:
    `RUN_DIR="${START_RUN_DIR:-$repo/tmp}"`, so a test stages into a
    `t.TempDir()` instead of the shared `tmp/` (which may belong to a running
    dev stack).
- **The rest of `bin/`** (`bump`, `ship`, `push-secrets`, `stop`,
  `create-migration`, …) stays in the untested tier per Conventions; this
  Decision carves out only the two layout-parity readers.

**Rejected.**
- *A `bin/*.test.sh` shell-test tier* (the substrate the appkit workspace's
  since-re-homed `bin/registry` Decision originally named). That tier existed
  and was removed (commit `019a99ee`) because nothing automated ran it — a test
  outside the gate rots. The Go module rides the gate that is already enforced
  on every build.
- *Proving staging against the live suite* (`bin/start` up, then
  `GET /services` on the running dashboard). Not hermetic and not runnable
  under the gate (needs ports, secrets, and a full build); the reader half of
  that end-to-end claim is already pinned hermetically by appkit's `inventory`
  tests, so what remains to pin here is only the launcher's staged shape.
- *Leaving both in the untested tier.* Their ids sat unrealizable in the appkit
  workspace (whose scope cannot reach repo-root scripts) and the behavior went
  unproven; the coverage check reported permanent false alarms.

**Verification** (in `bintest/*_test.go`, each test execing the real script).
- R-V3XG-PB8R — against a fixture `REGISTRY_ROOT` in a temp dir, `bin/registry`
  resolves a service whose manifest is at
  `<root>/<name>/etc/<version>/manifest.env` behind an `etc/current` symlink
  (`port`, `addr`, `mount`, and `feed-url` print the manifest-derived values;
  `list-mcp` includes the name when `MCP=true`), and does **not** resolve a
  service whose manifest exists only at the sibling
  `<root>/<name>/etc/manifest.env` (lookups exit nonzero; `list-mcp` omits it).
- R-V6D9-GUQ5 — `bin/start --stage-only` with `START_RUN_DIR` pointed at a temp
  dir exits `0` and stages, for every service with an authored
  `<svc>/etc/manifest.env`, `<run>/opt/<svc>/etc/<version>/manifest.env` plus
  `etc/current` as a **relative** symlink to the version dir (`<version>` from
  the service's `VERSION` file, else `dev`), while creating no `*.pid` file and
  no built service binary under `<run>/bin`, and leaving the authored source
  manifests unmodified.
- R-V7L5-UMGU — with `APPKIT_PORT_OFFSET=<n>`, the staged manifest's `PORT`
  equals the authored `PORT` plus `n` while the authored source file keeps its
  base value; with the offset unset, the staged manifest's bytes equal the
  source's.
