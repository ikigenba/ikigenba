# Decision 14 — The telemetry contract docs: `docs/telemetry-protocol.md` + the correlation-standard amendment

**Decision.**

The suite-wide telemetry contract is stated **once, normatively**, in a new
committed document, **`docs/telemetry-protocol.md`**, and the existing
correlation standard **`docs/correlation-ids.md`** is amended in place to agree
with it. These two documents are the ground truth every implementing workspace
(appkit, eventplane, the `telemetry` service, dashboard, and each adopting
service) records in its own `project/research` and designs against; no workspace
restates the contract normatively.

`docs/telemetry-protocol.md` states, exactly:

- **The record allowlist.** A forensic record carries only explicitly chosen
  fields: `id` (recorder-minted ULID), `time` (RFC3339Nano UTC),
  `correlation_id`, `service`, `kind`, `actor` (`owner_email`, `client_id`,
  omitted when unknown), `op`, `params`, `outcome` (`status`, `error`,
  `duration_ms`, `bytes`, `sha256`), `detail`. Raw header dumps and raw bodies
  are never captured; response content is never stored (outcome + size + digest
  only); digests are SHA-256, lowercase hex.
- **The seven kinds** and their `op` idioms: `edge` (`<METHOD> <original-uri>`,
  `detail.decision` ∈ allow/deny/rate_limited), `request` (`mcp:<tool>` or
  `<METHOD> <path>`), `outbound` (`<METHOD> <host><path>`), `publish` /
  `consume` (the routing key `<source>:<kind>/<subject>`), `root` (the origin,
  e.g. `cron:tick/<name>`, `run:<run-id>`), `lifecycle` (`start`|`stop`,
  `detail.version`).
- **Param capture under threshold.** Structured params are recorded per-field:
  a JSON-encoded value ≤ **1024 bytes** is literal; over the cap — or declared
  sensitive at tool registration — it is replaced in place by
  `{"$elided":{"bytes":N,"sha256":"<hex>"}}`; the per-record params budget is
  **8192 bytes**, largest values elided first until under budget.
- **Correlation rules.** One id per causal chain: a bare 26-char
  Crockford-base32 ULID in the **`X-Correlation-Id`** header (the product's
  contractual constant). The chassis reads-or-mints; the edge strips and mints
  (the introspection endpoint mints for gated routes and returns the id in its
  auth response; fragments overwrite anything client-supplied; ungated public
  locations blank the header so the service mints); self-originated work mints
  a root; the id rides the event envelope as a first-class field; outbound
  propagation is loopback-peers-only, never to third parties.
- **The ingest API.** `POST http://127.0.0.1:<telemetry-port>/ingest`
  (loopback-only; the port is `registry.MustPort("telemetry")`), body
  `{"records":[…],"dropped":<count, optional>}`, answered `202`. Delivery is
  **best-effort**: bounded buffering, batching, fire-and-forget; a down or slow
  sink drops records and never blocks, errors, or crashes a sender.
- **The recursion boundary.** The ingest path itself is never recorded; the
  telemetry service's own MCP tools are recorded like any service's.
- **Lifecycle records** at start (with version) and graceful stop, from every
  service including telemetry itself.
- **The scope exclusions**: operator tooling, sandbox internals, and
  nginx-answered requests that reach no service.

`docs/correlation-ids.md` is amended in place so the standard stays single and
current: Crockford base32 is confirmed as the sole alphabet; `X-Correlation-Id`
is named as the HTTP transport of the id; the event-payload-field convention is
**superseded** by the envelope field (the one existing adopter, wiki→prompts
`group_id`, is re-homed by those services' own specs); and the edge
strip-and-mint rule is added (a public caller can never supply the id).

**Rejected.**

- **W3C Trace Context (`traceparent`) / OpenTelemetry.** A span model with
  parent ids, sampling flags, and a 16-byte hex trace id — none of which the
  forensic goal needs — and its id format conflicts with the suite's
  already-committed ULID standard. The suite wants chains, not spans, and one
  doc, not an SDK.
- **Leaving the contract implicit in the implementations.** Fourteen adopters
  reading each other's code is how the correlation standard ended up with one
  adopter and a wrong alphabet in the chassis. The normative doc is the fix,
  not more convention.
- **A new standalone doc replacing `docs/correlation-ids.md`.** Two overlapping
  standards is worse than one amended one; the correlation doc stays the home
  of the id rules, the protocol doc the home of the record rules.

**Verification.**

This Decision produces committed documents at repo root that no module owns —
per Conventions (the same tier as D13's static artifacts and `bin/` tooling),
the green gate has no faithful assertion to make about them, so it mints **no
ids**. Its phase carries deterministic structural checks (exact-string greps
against both docs), and the contract's *behaviors* are proven where they are
implemented: the chassis behaviors by appkit's workspace ids, the envelope by
eventplane's, the store and forensic surface by the `telemetry` service's, the
edge by dashboard's, and per-service adoption by each service's — with the
suite-level end-to-end outcomes checked against the running stack by this
workspace's verification gate (product's success criteria).
