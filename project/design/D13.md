# Decision 13 — The parked `default_server` front door for non-apex hosts

**Decision.**

A second nginx server file, **`/etc/nginx/conf.d/parked.conf`**, sits beside the
rendered apex block (`dashboard.conf`) and claims `default_server` on both `:80`
and `:443`. It serves one static page from **`/var/www/parked/index.html`** to
every request whose `Host` the apex block does not match — the operator's other
registered domains, and the box's bare address. The apex block is **not
modified**: `int.ikigenba.com` continues to match by name and keeps serving the
dashboard and every `/srv/<svc>/` fragment unchanged.

Both artifacts are **committed source** in this repo, at repo root:

    parked/nginx.conf      the server file, installed to /etc/nginx/conf.d/parked.conf
    parked/index.html      the page,        installed to /var/www/parked/index.html

Both land on the box **root-owned, `0644`**, `/var/www/parked/` itself `0755`.
Neither is per-box-parameterized: there is no placeholder to render, so the
committed bytes and the installed bytes are identical, and `diff` is the drift
check.

**The page** is a bare-bones HTML5 document and nothing more — no CSS, no
favicon, no robots directives, no scripts. Every element earns its place; the
viewport meta is the one concession, without which the line renders at desktop
zoom on a phone:

```html
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>These aren't the droids you're looking for!</title>
</head>
<body>
<p>These aren't the droids you're looking for!</p>
</body>
</html>
```

It is served **`200`**, not `404`: the request reached the machine it was aimed
at, and the page is the honest answer, not an error.

**The server file** mirrors the apex block's port shape so behavior is uniform.
The `:80` block keeps its own ACME location on the **shared** webroot
(`/var/lib/letsencrypt`) so renewals for parked names work once `parked.conf` is
the default, then redirects everything else to HTTPS. The `:443` block serves the
page:

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;

    location ^~ /.well-known/acme-challenge/ {
        root /var/lib/letsencrypt;
        default_type "text/plain";
    }

    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    http2 on;
    server_name _;

    ssl_certificate     /etc/letsencrypt/live/parked/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/parked/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;

    root /var/www/parked;
    index index.html;
    location / { try_files /index.html =404; }
}
```

`server_name _;` is a non-matching placeholder, not a wildcard — these blocks are
selected purely by `default_server`, which is the explicit form of the
first-block-wins behavior the box relies on implicitly today (research). No HSTS
is set: an unrelated domain must not be pinned to HTTPS by a parking page.

**The certificate** is one lineage, **`--cert-name parked`**, covering **nine**
names:

    ikigenba.com          ikigenba.dev          logic-refinery.com
    logic-refinery.io     logic-refinery.net    logic-refinery.tv
    metaspot.net          metaspot.org          michaelgreenly.com

Issued by HTTP-01 webroot against the existing `/var/lib/letsencrypt`:

    certbot certonly --webroot -w /var/lib/letsencrypt --cert-name parked \
      -d ikigenba.com -d ikigenba.dev -d logic-refinery.com \
      -d logic-refinery.io -d logic-refinery.net -d logic-refinery.tv \
      -d metaspot.net -d metaspot.org -d michaelgreenly.com \
      --non-interactive --agree-tos -m "$CERTBOT_EMAIL" \
      --deploy-hook "systemctl reload nginx"

Three properties of this choice:

- **The lineage name is `parked`, not a domain.** The lineage name is the
  directory nginx reads, so naming it after any member domain would couple a
  config path to that registration's survival. `parked` says what it is and the
  domain list stays pure data.
- **`ikigai-group.io` is excluded** — the one registration not on auto-renew,
  expiring within weeks (research). Inside a shared lineage a lapsed name fails
  HTTP-01 and fails the **whole** renewal, so including it would let a domain
  being abandoned strip HTTPS from the eight being kept. Because the `:80` block
  redirects every host to HTTPS, an excluded domain does **not** show the page:
  it is redirected and then fails certificate validation, so it goes dark. That
  is the accepted, intended outcome for a domain being let go — the exclusion is
  bought for containment, not for a degraded-but-working page. The same is true
  of the bare IP, which can never match a certificate name.
- **`int.ikigenba.com` stays its own lineage**, untouched. `certbot renew` walks
  lineages independently (research), so the apex certificate cannot be affected
  by a parked-lineage failure, and the worst case is that the nine parked names
  lose TLS together.

**Bootstrap order is cert-then-config**, and needs no `--standalone` dance. The
apex `:80` block already answers `/.well-known/acme-challenge/` for *any* `Host`
from the shared webroot (research), so issuance succeeds while `parked.conf` does
not yet exist. Therefore: `certbot certonly …` → install both files → `nginx -t`
→ `systemctl reload nginx`. Reversing the order would fail `nginx -t`, because
the `:443` block references a certificate path that does not exist yet.

**Installation is an operator runbook step, not code.** No `opsctl` verb, no
`init-box` change, no new systemd unit. `deploy.md` gains one section giving the
exact certbot invocation, the two `install` commands, the validate-and-reload, and
the post-install verification. This is the deliberate consequence of the work
being two static files on one box: adding an `opsctl` verb would mean shipping
ikigenba's own domain portfolio inside app-agnostic tooling, or a verb no other
box would ever run.

Two existing mechanisms absorb the ongoing cost with **no change**:

- **Renewal** rides `ikigenba-certbot-renew.timer`, which runs `certbot renew`
  over every lineage.
- **Backup and restore** ride the existing cert stream (D7), which archives
  `/etc/letsencrypt/{archive,renewal,live}` wholesale, so the parked lineage is
  captured and restored like the apex one. Only the two flat files are outside
  that, which is exactly why they are committed rather than hand-written on the
  box — a rebuild replays the runbook from source.

**Rejected.**

- *Hand-written config on the box, nothing in the repo.* Cheapest, and precisely
  the failure this project exists to eliminate: config "applied out-of-band, by
  hand, at setup time and never re-applied," so the box drifts from source and a
  rebuild silently loses it. Rejected — committed artifacts cost almost nothing
  more and survive a rebuild.
- *An `opsctl parked` verb, or an `init-box` step.* Compiles ikigenba's domain
  portfolio into app-agnostic tooling (or adds a flag only one box ever passes),
  and makes a domain lapsing a binary rebuild. An `init-box` step is worse still:
  it would call certbot for domains pointing at a different machine on every
  future customer box and fail provisioning outright. Rejected for the runbook.
- *One certificate per registered domain.* Isolates renewal failures perfectly,
  but costs nine lineages and nine server blocks (or `ssl_certificate` by
  variable, which forfeits OCSP stapling) to protect a parking page. Rejected;
  the shared lineage's blast radius is the parked names only, never the apex.
- *Including `ikigai-group.io` in the certificate.* Lets one unrenewed domain
  fail the whole lineage's renewal. Rejected; see above.
- *Serving the page inline from nginx (`return 200 '<html>…'`).* Removes a file
  and its permissions, but forces the HTML through nginx string escaping and
  makes the page unreadable as a page. Rejected — a real file is greppable,
  diffable against the committed source, and editable.
- *Answering `404`, or serving an error page.* Misrepresents what happened: the
  request arrived at the right machine and got a deliberate answer. Rejected.
- *Mirroring the parked block into the local dev front door (`nginx/`).* The dev
  front door is localhost-only on a high port with no TLS and no parked DNS, so a
  mirrored `default_server` would prove nothing the live check does not. Rejected.
- *Adding `$host` to `log_format`.* Genuinely useful — its absence is why
  unknown-`Host` traffic had to be probed rather than read from logs (research) —
  but it is an unrelated observability change to the apex configuration. Rejected
  for this Decision; noted for a future one.

**Verification.**

This Decision mints **no requirement ids** — deliberately, on the same grounds as
D12. Its output is two static committed files plus an operator runbook; no code
runs, and no module owns the repo-root `parked/` tree, so the green gate
(`go test ./...` over the workspace modules) has nothing it could faithfully
assert. A test that grepped the committed page for its own sentence would be a
tautology, not a falsifiable behavior.

The claim that actually matters — that a parked domain answers with this page
over valid TLS while the apex is unaffected — hinges entirely on a real external
contract: a real certificate authority issuing for names that really resolve to
this box, and a real nginx selecting a real `default_server`. Nothing reachable
in-gate can falsify it. It is therefore verified **once, manually, outside the
build loop**, by the runbook's own verification steps, which must include:

- a cert-validating request to at least two of the nine certificate names
  returning `200` with the page text, one of them `metaspot.org` (the permanent
  anchor);
- a request to `ikigai-group.io` still **failing** certificate validation over
  HTTPS — proving the exclusion is in force rather than the domain having been
  accidentally swept into the certificate;
- a request to the box's bare IP, with validation skipped (an address can never
  match a certificate name), returning the page rather than a service — proving
  `default_server` selection, not name matching;
- a cert-validating request to `int.ikigenba.com` still returning the dashboard,
  and one `/srv/<svc>/` path still routing — proving non-interference;
- `certbot certificates` showing **two** lineages, `int.ikigenba.com` and
  `parked`, with the parked lineage naming exactly the nine domains.

The build phase realizing this Decision therefore carries deterministic
**structural** exit conditions (the exact committed files, the exact runbook
section), not id-tagged tests.
