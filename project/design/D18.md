# Decision 18 — The event-plane contract: envelope, routing keys, and the SSE wire

**Decision.** This is a **suite contract**: the normative wire contract of the
suite's internal event plane — the envelope services publish, the routing key
consumers select on, and the SSE feed the two halves speak over. For years the
library and several trees cited an "event protocol" document under `docs/` as the
normative wire contract; that file never existed in the repo. **This Decision is
that contract.**

The plane is **internal, loopback-only, and unauthenticated**: one box is one
owner, so there is no second principal to authenticate. `GET /feed` must never be
reachable from outside, enforced three ways — loopback binding, an nginx
exact-match 404 on the public mount, and the feed handler's own rejection of any
request arriving with nginx-injected identity headers.

## The envelope

Every event on the wire is:

```json
{
  "id":             "<26-char ULID>",
  "source":         "dropbox",
  "time":           "<RFC3339 UTC>",
  "kind":           "create",
  "subject":        "/bills/aws/2026-06.pdf",
  "correlation_id": "<26-char ULID>",
  "payload":        { }
}
```

- **`source`** — the producing service name, stamped by the library.
- **`kind`** — the fact class, lowercase `[a-z0-9_.-]+`: the operation or fact
  that occurred (`create`, `delete`, `tick`, `recorded`). Kinds carry no
  redundant noun prefix — `source` already says what the service deals in, so a
  file service publishes `create`, not `file.created`.
- **`subject`** — a `/`-rooted, `/`-separated routing **name** for the thing it
  happened to, or empty when the kind has no natural subject. It is a name, never
  data: a mirror path, a schedule name, a prompt name. Anything a consumer acts
  on beyond routing stays in the payload.
- **`correlation_id`** — the causal-chain id, a first-class envelope field
  (D14), never a payload convention.
- **`id`**, **`time`**, **`payload`** — the event's own ULID, its UTC timestamp,
  and the producer's opaque domain snapshot.

**Structure in the envelope, string for matching.** `kind` and `subject` are
fields; the key below exists for matching, logs, and human eyes. Producers never
build a key by concatenation and consumers never parse one apart.

## The routing key and the matcher

The `eventplane` library owns **one** join rule and **one** matcher; nothing else
in the suite renders or interprets keys.

```
key(source, kind, subject) = source + ":" + kind + subject
```

Since `subject` is either empty or `/`-rooted, no further delimiter is needed:

```
dropbox:create/bills/aws/2026-06.pdf
cron:tick/bill-sweep
prompts:run.succeeded/collect-bills
ledger:recorded
```

**Matching is a single glob over the whole key**, doublestar dialect: `*` matches
within a path segment (never `/`), `**` matches across segments, `?` and
character classes as in standard glob, **no brace expansion**. The stdlib
`path.Match` cannot express `**`, so the matcher is hand-rolled once in
`eventplane` and used by every selector in the suite — trigger filters, consumer
config filters, any future subscriber. Filter semantics can never diverge,
because there is exactly one implementation.

```
dropbox:create/bills/**/*.pdf     files under /bills/, any depth, PDFs only
dropbox:*/bills/aws/**            any operation under one vendor's folder
cron:tick/bill-sweep              one schedule, exactly
ledger:recorded                   a subjectless kind matches literally
```

**Reflection describes families, not enumerations.** A producer declares
`{kind, subject pattern, description, payload schema/sample}` — `create/<mirror
path>`, `tick/<schedule name>` — and a filter is accepted when it is well-formed
and **could match some family** of the named source (glob intersection on `kind`,
subject left open). Dynamic subjects are therefore ordinary, not a special case.

## The SSE wire

A producer serves its outbox as a Server-Sent-Events stream at `GET /feed`. One
event is one frame:

```
id: <opaque cursor>
event: <routing key>
data: <the envelope, one compact JSON line>
```

- The **`id:` line carries the opaque cursor** the consumer echoes back in
  `Last-Event-ID` on reconnect. It is `<generation>.<seq>` — the live epoch token
  (D06) joined to the outbox row's `seq` — single-line and newline-free so it
  rides both the wire and the header verbatim. **The consumer never parses it.**
- The **`event:` line carries the canonical routing key**, so a client can select
  without decoding the body.
- Exactly **one `data:` line per event**, the whole envelope as compact JSON.

Three **control frames** ride the same stream:

| frame | body | meaning |
|---|---|---|
| `event: resync` | `{"reason":"<reason>"}` | the presented cursor cannot be honored; re-bootstrap |
| `event: status` | `{"behind":<int>}` | how many events the consumer is behind at connect |
| `event: caught-up` | `{}` | the backlog is drained; the stream is live |

A `resync` names its reason so the consumer can log it at the severity it
warrants — a **stale epoch** is normal after a restore or rebuild, a **diverged**
or **unintelligible** cursor is a warning, and **past-horizon** is data loss and
logged as an error.

## The two halves

**The producer** writes events into a local `outbox` table **inside the same
transaction as the domain change that caused them** — the atomic outbox: an event
exists if and only if the fact it reports does. The library owns that table's DDL
so every producer's outbox is byte-identical (`seq INTEGER PRIMARY KEY
AUTOINCREMENT` is load-bearing: AUTOINCREMENT makes `seq` a persistent
high-water mark, so retention emptying the table can never restart rowids at 1
and silently strand a cursored consumer). Retention trims the outbox on a
background timer by age and row count.

**The consumer** streams one upstream's feed past a **durable per-upstream
cursor** (`feed_offset`, also library-owned DDL), calling a handler for **every**
event — filtering is the consuming service's job — and gating the cursor on the
handler's return:

- `nil` → advance (commit the cursor).
- `ErrSkip` → log loudly and advance (poison the handler can never process).
- any other error → **stall**: do not advance, tear down the connection, and
  reconnect from the last committed cursor so the same event re-delivers before
  any later one.

Default-on-unknown-error is therefore **stall**, the safe at-least-once
direction; best-effort is a *handler* choice (swallow the failure, return `nil`),
never an engine policy.

**Structural versus transport faults** is the load-bearing split: a `feed_offset`
read/write failure — a missing table, a closed DB, i.e. a deploy or programming
bug — escapes the engine so the process crashes and systemd restart-loops
visibly; a connect failure, a non-200, a dropped connection, or a stalled
keepalive is a transport fault the engine retries internally, indefinitely, with
backoff, and never surfaces.

**Rejected.**

- **A closed per-service type registry (the old flat `type` field).** cron
  already violated it by design (dynamically minted `cron.<name>`), forcing a
  special case in every validator, while every other producer's subject stayed
  locked inside the payload where filters could not see it — so a consumer that
  cared about one folder had to be woken for every event on the box. cron was not
  the exception; it was the correct model, generalized here.
- **Payload querying.** The subject is the only routable dimension beyond source
  and kind. A consumer needing payload-level selection filters in its handler.
- **A broker, topics, or central routing.** Each consumer matches keys against
  each upstream's feed; nothing central routes. The bet of the whole suite is no
  broker.
- **Cross-source subscription syntax.** A filter applies to one upstream's feed.
  `source:` in the key makes filters self-describing and leaves the door open,
  but no multi-source selector is being built.
- **A dual-format compatibility period.** The envelope, key, matcher,
  registries, trigger storage, and every consumer filter moved together; a
  compatibility mode would have doubled the surface permanently to smooth a
  migration measured in days.
- **Authenticating the feed.** One box is one owner; there is no second
  principal. Confinement (loopback + nginx 404 + the header guard) is the
  mechanism, and adding a credential would imply a trust split that does not
  exist.

**Verification.** This is a **prose contract with no testable behavior of its
own**, so it carries **no ids**. Its behaviors are proven where they are
implemented, informationally: the envelope, canonical key, glob matcher, producer
families, outbox and `feed_offset` DDL, the SSE frames and control frames, the
cursor/epoch handling, and the stall/skip semantics in **eventplane**; the feed
guard and the epoch sidecar in **appkit** (D06); the public-mount 404 in the
shipped **nginx** fragments; and each producer's own kinds, subjects, and
consumer filters in that **service**'s tree.
