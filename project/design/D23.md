# Decision 23 — The testing-language contract

**Decision.** This is a **suite contract**: the single vocabulary every tree uses
to talk about its tests, the rule for what each kind of test may touch, and what
every tree must declare about its own testing. It exists because the suite had
one strong shared practice ("prove the claim on the substrate that can falsify
it") and no shared names for it — "unit" labeling suites that spawn subprocesses,
"e2e" meaning something different per tree, and four incompatible mechanisms for
tests that reach real external services.

**The four layers.** Every test in the suite belongs to exactly one layer,
defined by what it is **allowed to touch** — not by size, speed, or file name:

| layer | may touch | runs in |
|---|---|---|
| **hermetic** | in-process code and real local substrates: temp-dir filesystems, real SQLite files through the real migration runner, `net/http/httptest`, loopback listeners, local subprocesses (`go build`, `git`, `tar`, a compiled fixture). Never a non-loopback network address, never a credential, never a running suite. | the default gate |
| **composed** | everything hermetic may, **plus** building and running the tree's own real binary (boot smokes, `internal/e2e/`-style tests driving the composed service over loopback HTTP, restart-survival checks). | the default gate |
| **live** | a real external service or the live box, using real credentials. | only under the `live` build tag, by explicit invocation — never the default gate |
| **manual** | anything automation cannot reach even with credentials: interactive auth, privileged on-box state, real TLS on the apex, the assembled stack. | a committed runbook, run by the operator, outside any gate |

The layer names are the normative vocabulary. Conventional words map onto them
informally ("unit" ≈ hermetic, "e2e" ≈ composed) but are never the contract
terms; a `Substrate:` clause on a Verification id names real substrates and,
when the id is not hermetic, its layer.

**The default gate is hermetic by construction.** A tree's default gate (its
`go test ./...` plus clean `go build ./...`, `go vet ./...`, and `gofmt -l .`)
contains only hermetic and composed tests. No test outside a live-tagged file
may contact a non-loopback address, read a credential, or change behavior based
on what secrets happen to be in the environment — hermeticity is a property of
the code, not of an empty shell.

**One mechanism for live tests.** A test that touches a real external service
carries the `//go:build live` constraint and compiles only under the explicit
invocation `go test -tags live ./...`. When required credentials are absent it
**fails loudly** (`t.Fatal`), never skips. A tree with a live layer states in
its own design Conventions the invocation, the credentials it needs, and when
the operator runs it (the natural moment is deploy verification). Live ids are
minted like any others; because id tags are found textually, the coverage grep
sees them regardless of the build tag, and the documented invocation is what
makes them reachable rather than dead.

**Skipping is banned in the default gate.** `t.Skip` and its variants may not
appear outside live-tagged files. A tool a tree's tests need (`git`, a browser,
`python3`, the `go` toolchain itself) is an **environmental precondition**:
declared in the tree's `AGENTS.md`, and a hard failure when absent — a skipped
requirement test launders a gap into green.

**The manual layer is committed, not tribal.** A check that cannot be automated
even with credentials lives in a committed runbook document in the owning tree
(the pattern: `github/project/github-verification.md`), stating the positive
check, the **negative** check that proves the positive one exercised the real
thing, and where the result is recorded. The suite-level check that the whole
stack composes — bring the suite up via `bin/start`, verify every service's
health through nginx on `:8080` — is a manual-layer item; no automated
suite-level gate exists or is wanted (it would be slow, contend for shared host
ports, and duplicate what per-tree composed tests and deploy verification
already prove).

**Every tree declares its testing facts.** Each subproject's `AGENTS.md` Tests
section states: the exact default-gate test command; which layers the tree has;
every environmental precondition beyond the Go toolchain; and its GOWORK mode
(workspace or `GOWORK=off`, which the suite deliberately does not unify —
libraries resolve through the workspace, standalone-build trees mirror the
production build). A tree with **no test suite at all** (today: `nginx/`)
still commits the declaration ("layers: manual only") and conforms
structurally, without the tagged tests below.

**Rejected.**

- *Conventional unit/integration/e2e as the normative names.* "Unit" already
  mislabels every service's boot smoke, "integration" and "e2e" mean a
  different thing in each tree that uses them, and none of the three says what
  a test may *touch* — which is the property the suite actually polices.
  Kept only as informal aliases.
- *Env-gated skips for live tests* (`t.Skip` when credentials are missing).
  The suite's worst live-test defects were exactly this shape: a test that is
  silently live when secrets are present and silently green when they are not.
  Banned outright.
- *Env-variable gating instead of a build tag* (`LIVE=1 go test ...`). The
  test still compiles into the default gate and must decide at runtime to
  skip or fail; the build tag keeps live code out of the default binary
  entirely and makes the boundary a compile-time fact a source scan can check.
- *An automated suite-level end-to-end gate over `bin/start`.* Slow, flaky on
  shared host ports, unrunnable in parallel worktrees, and redundant with
  per-tree composed tests plus the deploy runbook's verification checklist.
  The full-stack check is manual-layer instead.
- *Forcing one GOWORK mode on every tree.* The split is load-bearing:
  `GOWORK=off` proves standalone resolution where the prod build needs it,
  workspace mode is correct for in-repo libraries. Declared per tree instead.

**Verification.**

- R-O1AD-MRKW [proof: per-service] — a test reads the tree's committed

  default-gate test command, the layers present (using this contract's four
  layer names), every environmental precondition beyond the Go toolchain, and
  the tree's GOWORK mode — so the declaration is re-checked on every gate run,
  not once at authoring time. Substrate: hermetic (real committed file read

- R-O2IA-0JBL [proof: per-service] — a source scan over the tree's

  default gate cannot skip. The scan assembles its needle from parts so it
  never matches itself. Substrate: hermetic (source scan).
