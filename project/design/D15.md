# Decision 15 — Suite wiring for the `telemetry` service (go.work, `bin/start`, `nginx/run`)

**Decision.**

The `telemetry` service joins the suite's shared plumbing exactly as its
fourteen peers did, in the three repo-root seams the suite-level workspace owns:

- **`go.work`** gains a `./telemetry` use-entry, so workspace-mode dev and the
  root green gate (`go test ./...`) cover the new module. (The service's own
  build loop builds `GOWORK=off` with committed `replace` directives, per suite
  convention, so it does not depend on this entry — the entry is for the
  operator's workspace and the gate.)
- **`bin/start`** builds and launches `telemetry` with its peers, resolving the
  port from the registry as it does for every service, logging to
  `tmp/telemetry.log`.
- **`nginx/run`** includes `telemetry` in the fragment list it copies, so the
  dev front door on `:8080` routes `/srv/telemetry/` exactly as prod will.

No port literal appears in any of the three: the number is
`registry.MustPort("telemetry")` (Go) or derived from the service's
`etc/manifest.env` (shell), same as every peer. This wiring lands **after** the
`telemetry` module exists (its greenfield build loop having produced
`telemetry/go.mod`, its binary, `etc/nginx.conf`, and `etc/manifest.env`) — a
`go.work` entry naming a nonexistent module would break every workspace build.

**Rejected.**

- **Wiring first, service later.** Breaks the workspace build for every module
  until the telemetry loop runs; the reverse order costs nothing.
- **Hardcoding `3008` in `bin/start`/`nginx/run`.** The registry exists so port
  literals are written in exactly one place; the wiring resolves, never
  restates.

**Verification.**

Pure `bin/` shell tooling and repo-root config — the deliberately untested tier
per Conventions; **no ids**. The phase carries deterministic structural checks
(greps for the `go.work` entry and the service lists, a clean workspace build),
and the real behavior — fifteen services up behind the dev front door — is
product's success criterion, checked against the running stack.
