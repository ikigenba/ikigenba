# Decision 30 — The lint contract: tiered mechanical style gate, per-tree ratchet, enforced by `bin/lint`

**Decision.** This is a **suite contract**: one mechanical code-style gate for
every Go tree in the mono-repo, enforced by shared tooling so style holds by
system rather than by prompt or review discipline. It binds every Go module in
`go.work` (the trees being linted), the off-box tooling in `bin/` (which builds
the runner, owns the committed lint configs, and gates shipping), and every
spec-governed tree's verify loop (which gates building). The runner's own
mechanics are specified in `bin/project/` (informational), which adopts this
contract.

**The tier model.** Every Go tree is registered at exactly one lint tier:

- **`off`** — the gate passes vacuously; findings are reported, never enforced.
- **`cheap`** — mechanical, low-judgment rules only (list below).
- **`strict`** — `cheap` plus the judgment rules and complexity thresholds.

A tree's tier only ever **ratchets up** (`off → cheap → strict`), never down; a
deviation that needs a lower bar is a visible local Decision naming this
contract, never a quiet tier edit.

**The tier marker.** A tree's registered tier is a committed one-line file at
the tree's root: **`<tree>/.lint-tier`**, containing exactly `cheap` or
`strict` (a trailing newline is permitted). **Absence of the file means
`off`** — no tree needs a marker until it adopts. The marker lives inside the
tree it describes so a tier flip is a purely local write, inside that tree's
own spec move, never a cross-tree edit. Any other content in the file is an
error (see the runner's error surface).

**Adoption is a local spec move.** A tree adopts a tier via a small structural
phase in its own `project/`: bring the tree to zero findings at the target
tier, commit the `.lint-tier` flip in the same completion, done when
`bin/lint <tree>` exits 0 and the tree's suite is green. Citing this contract
(`root project/design/D30.md`) is adoption of the marker semantics; no
per-service proof ids exist (the runner's behavior is proven once, in `bin`).
Trees without their own spec (the repo-root module and `bin/bintest`) are
flipped by the operator directly, the same way `VERSION` files are operator
data.

**The cheap tier — rule list.** Formatting plus analyzers whose findings have
one obvious fix:

- **gofumpt** (as golangci-lint's formatter — no separate binary).
- **govet**, **staticcheck**, **unused**, **unparam**.
- **gocritic** with the `diagnostic` and `style` tags enabled and exactly
  these checks disabled: `unnamedResult`, `paramTypeCombine` (judgment calls —
  they move to strict), and `whyNoLint`.

**The strict tier — rule list and thresholds.** Everything in cheap, plus:

- **dupl** at token threshold **120**.
- **gocyclo** at minimum complexity **15**.
- **funlen** at **80** lines / **50** statements.
- **nestif** at minimum complexity **5**.
- **gocritic** additionally enabling `unnamedResult` and `paramTypeCombine`.

These values are contractual: the committed configs in `bin/` realize them
verbatim, and changing a rule list or threshold is an amendment to this
Decision (followed by re-conformance of affected trees), never a config-only
edit.

**Test files: analyzers excluded, formatting included.** For now, every
analyzer in both tiers skips `*_test.go` files. Formatting (`gofumpt`) applies
to **every** Go file, tests included — it is autofixable and free. The configs
therefore express the exclusion as per-linter path rules, never as a global
"skip tests" switch that would also silence the formatter. Widening analyzers
to test files later is an amendment to this Decision.

**The pinned tool.** The gate runs on **golangci-lint v2.12.2**, exactly.
`bin/lint` verifies the installed binary's version before linting and refuses
to run on any other, so a verdict can never change because of tool drift;
upgrading is a deliberate commit that bumps the pin here and in `bin`, with
re-conformance where the new version's verdicts differ. The tool is installed
by the operator; `bin/lint` never downloads or installs anything.

**The runner: `bin/lint`.** One entry point; nothing invokes golangci-lint
directly.

- `bin/lint <tree>` lints one module at its registered tier and is the gate:
  exit **0** when the tree is clean at its tier (or its tier is `off`),
  nonzero when enforced findings exist. An `off` tree's findings are printed
  as a report but never fail the run.
- `bin/lint` (no arguments) is the suite scoreboard: it lints every `go.work`
  module at its registered tier, prints one line per module (tier and finding
  count), and exits nonzero iff any `cheap`- or `strict`-tier module fails.

Error surface, distinguishable to the caller and each written to stderr:

- **Version mismatch** — installed golangci-lint is not the pinned version:
  exit nonzero *without linting*, naming the pinned and found versions and how
  to install the pinned one.
- **Invalid marker** — `.lint-tier` exists but contains anything other than
  `cheap` or `strict`: exit nonzero naming the tree, the bad content, and the
  valid values. Never guess a tier.
- **Unknown tree** — the named argument is not a `go.work` module: exit
  nonzero listing the valid trees.

`bin/lint` panics never; every failure above is an expected operator-facing
error.

**Enforcement points.** Exactly two, and one deliberate non-point:

- **Every spec-governed tree's verify gate** includes `bin/lint <tree>`
  exiting 0. Because `off` passes vacuously, this lands in each tree's
  generated loop prompts as they are next regenerated, ahead of or alongside
  the tree's adoption move — no big-bang regeneration.
- **`bin/ship`** refuses to ship an app whose tree fails `bin/lint` at its
  registered tier, exiting nonzero having staged nothing.
- **Dev startup is not gated**: `bin/start` and local runs never invoke the
  gate, so a red tree can always be brought up for debugging.

**Rejected.**

- *A central tier-registry file in `bin/`.* A subproject's adoption phase may
  not write outside its own tree, so every tier flip would be a forbidden
  cross-tree edit or a two-move dance. Per-tree markers make the flip local;
  the no-argument scoreboard replaces the one-glance file.
- *One suite-wide adoption commit (mechanical autofix across all trees).*
  Cheaper, but it edits governed source outside every tree's build loop and
  needs a special maintenance carve-out from the direction gate. Per-tree
  adoption keeps the gate pure and gives each tree its own proof; the cost is
  many small moves, accepted deliberately.
- *A strictly-autofixable cheap tier (demoting `unused`/`unparam`).* A
  parameter that always receives one value and code nothing calls are pure
  dead weight with unambiguous fixes; keeping them cheap maximizes what the
  suite-wide floor catches.
- *Excluding tests via the global test switch (`run.tests: false`).* It would
  silence the formatter on test files too; unformatted tests were among the
  most common findings surveyed. Per-linter path exclusion keeps gofumpt
  total.
- *Unpinned or auto-installed golangci-lint.* Linter upgrades change
  verdicts; an unpinned tool means the gate flips red from drift rather than
  from code, and auto-install hides the drift. Pin plus refuse is smaller and
  louder.
- *Gating `bin/start`.* A style gate that blocks bringing the suite up
  punishes debugging, the one activity that must never wait on formatting.
- *Per-service proof ids.* The behaviors below are the runner's, implemented
  once in `bin`; services carry no lint test of their own. A service's
  conformance is proven by its own adoption phase's exit condition, not by a
  contract id.
- *An LLM-review tier.* Deliberately out of this contract: no such machinery
  exists yet. If built, it enters as its own Decision; nothing here
  presupposes it.

**Verification.** All behaviors are `bin/lint`'s and `bin/ship`'s; each id's
tagged test lives in `bin`'s declared proof tier.

- R-WW5B-L155 — for a tree whose `.lint-tier` is `cheap`, `bin/lint <tree>`
  exits nonzero when the tree contains a cheap-tier finding (e.g. an
  unformatted file) and exits 0 when the tree is clean at cheap.
  [proof: bin]
- R-WXD7-YSVU — for a tree with **no** `.lint-tier` file, `bin/lint <tree>`
  exits 0 even when findings exist, and still prints their count as a report.
  [proof: bin]
- R-WYL4-CKMJ — a tree containing a strict-only finding (a function of
  cyclomatic complexity ≥ 16, none of the cheap rules violated) passes
  `bin/lint` with marker `cheap` and fails it with marker `strict` — the
  marker selects the tier. [proof: bin]
- R-WZT0-QCD8 — an analyzer finding located in a `*_test.go` file (e.g. a
  function of cyclomatic complexity ≥ 16) does **not** fail `bin/lint` at
  `strict`, while the same finding in a non-test file does — analyzers skip
  test files. [proof: bin]
- R-X10X-443X — an unformatted (non-gofumpt) `*_test.go` file **does** fail
  `bin/lint` at `cheap` — formatting applies to test files despite the
  analyzer exclusion. [proof: bin]
- R-X28T-HVUM — when the installed golangci-lint version differs from the
  pinned v2.12.2, `bin/lint` exits nonzero before linting anything, and its
  stderr names both the pinned and the found version. [proof: bin]
- R-X3GP-VNLB — a `.lint-tier` file containing anything other than `cheap`
  or `strict` makes `bin/lint <tree>` exit nonzero naming the offending tree
  and content, and an argument naming no `go.work` module exits nonzero
  listing the valid trees — the runner never guesses. [proof: bin]
- R-X4OM-9FC0 — `bin/lint` with no arguments exits nonzero when any
  `cheap`/`strict` module has enforced findings and exits 0 when every
  enforced module is clean, regardless of findings in `off` modules; its
  output carries one line per `go.work` module with the module's tier.
  [proof: bin]
- R-X5WI-N72P — `bin/ship` for an app whose tree fails `bin/lint` at its
  registered tier exits nonzero and stages no release artifact; the same
  ship succeeds once the tree is clean at its tier. [proof: bin]
