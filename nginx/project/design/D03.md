# Decision 3 — The parked `default_server` front door for non-apex hosts

**Decision.**

Every host that reaches the live box but is not the account's apex is answered by
a second nginx server file that claims **`default_server`** on both `:80` and
`:443` and serves one static page. This tree owns the two artifacts, and only
them:

    nginx/parked/nginx.conf      the server file, installed to /etc/nginx/conf.d/parked.conf
    nginx/parked/index.html      the page,        installed to /var/www/parked/index.html

They are **committed source, not templates**: nothing in either is
per-box-parameterized, so the committed bytes and the installed bytes are
identical and `diff` is the drift check. The account's apex block is **not
modified** — it continues to match by name and keeps serving the dashboard and
every `/srv/<svc>/` fragment unchanged.

**The page** is a bare-bones HTML5 document and nothing more — no CSS, no
favicon, no robots directives, no scripts. Every element earns its place; the
viewport meta is the one concession, without which the line renders at desktop
zoom on a phone. Its message is the product's contractual constant, in both the
title and the body:

```html
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>These aren't the droids you're looking for!</title>
</head>
<body>
<p>These aren't the droids you're looking for!</p>
</body>
</html>
```

It is served **`200`**, not `404`: the request reached the machine it was aimed
at, and the page is the honest answer, not an error.

**The server file** mirrors the apex block's port shape so behavior is uniform.
The `:80` block keeps its own ACME location on the **shared** webroot
(`/var/lib/letsencrypt`) so renewals for parked names keep working once this file
is the default, then redirects everything else to HTTPS. The `:443` block serves
the page:

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    location ^~ /.well-known/acme-challenge/ {
        root /var/lib/letsencrypt;
        default_type "text/plain";
    }

    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    http2 on;

    ssl_certificate     /etc/letsencrypt/live/parked/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/parked/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;

    root /var/www/parked;
    index index.html;
    location / { try_files /index.html =404; }
}
```

**The blocks deliberately declare no `server_name`.** Selection is purely by
`default_server` — the explicit form of the first-block-wins behavior the box
relied on implicitly before (see the umbrella's research,
`project/research/research.md` at the repo root) — so a `server_name` would
contribute nothing to which block answers. It would cost something, though: the
box's stock `/etc/nginx/nginx.conf` (Amazon Linux 2023's `nginx-core` package,
unmodified) ships its own inert `server_name _` block on `:80`/`[::]:80`, so a
second block naming `_` on the same ports makes every `nginx -t` and reload warn
`conflicting server name "_" … ignored`. With no `server_name` here, these
blocks carry the empty default name, which collides with nothing; the distro
block stays what it is — never selected, since it is not `default_server` and
`_` never matches a real `Host`. No HSTS is set: an unrelated domain must not be
pinned to HTTPS by a parking page.

**The certificate these files name is one shared lineage, `parked`**, covering
the operator's kept non-apex domains. Three properties of that choice shape the
bytes above and are recorded here because they explain them:

- **The lineage name is `parked`, not a domain.** The lineage name is the
  directory nginx reads, so naming it after any member domain would couple the
  `ssl_certificate` path to that registration's survival. `parked` says what it
  is and the domain list stays pure data — data this tree does not carry.
- **A domain not on auto-renew is deliberately excluded from the lineage.**
  Inside a shared lineage a lapsed name fails HTTP-01 and fails the **whole**
  renewal, so including one would let a domain being abandoned strip HTTPS from
  the ones being kept. Because the `:80` block redirects every host to HTTPS, an
  excluded domain does **not** show the page: it is redirected and then fails
  certificate validation, so it goes dark. That is the accepted, intended outcome
  for a domain being let go — the exclusion is bought for containment, not for a
  degraded-but-working page. The same is true of the bare IP, which can never
  match a certificate name.
- **The account's apex keeps its own lineage**, untouched. `certbot renew` walks
  lineages independently, so the apex certificate cannot be affected by a
  parked-lineage failure, and the worst case is that the parked names lose TLS
  together.

**Installation is an operator runbook step, not code in this tree.** No `opsctl`
verb, no provisioning change, no systemd unit: the exact certificate issuance,
the two `install` commands, the validate-and-reload, and the post-install
verification checklist live in the repo-root `deploy.md`, which this Decision
cites and does not restate. Bootstrap order there is **cert-then-config** — the
apex `:80` block already answers `/.well-known/acme-challenge/` for any `Host`
from the shared webroot, so issuance succeeds while this server file does not yet
exist; the reverse order would fail `nginx -t`, because the `:443` block names a
certificate path that is not there yet.

That division is the deliberate consequence of the work being two static files on
one box. Two existing suite mechanisms then absorb the ongoing cost with **no
change**: renewal rides the box's existing certbot renew timer, which walks every
lineage; and backup/restore rides the existing certificate stream
(`opsctl/project/design/D13.md`), which archives
`/etc/letsencrypt/{archive,renewal,live}` wholesale. Only these two flat files
sit outside that, which is exactly why they are committed rather than
hand-written on the box — a rebuild replays the runbook from source.

**Rejected.**

- *Hand-written config on the box, nothing in the repo.* Cheapest, and precisely
  the failure this work exists to eliminate: config applied out-of-band, by hand,
  at setup time and never re-applied, so the box drifts from source and a rebuild
  silently loses it. Rejected — committed artifacts cost almost nothing more and
  survive a rebuild.
- *An `opsctl` verb, or a provisioning step.* Compiles ikigenba's domain
  portfolio into app-agnostic tooling (or adds a flag only one box ever passes),
  and makes a domain lapsing a binary rebuild. A provisioning step is worse
  still: it would call certbot for domains pointing at a different machine on
  every future customer box and fail provisioning outright. Rejected for the
  runbook.
- *One certificate per registered domain.* Isolates renewal failures perfectly,
  but costs one lineage and one server block per domain (or `ssl_certificate` by
  variable, which forfeits OCSP stapling) to protect a parking page. Rejected;
  the shared lineage's blast radius is the parked names only, never the apex.
- *Including the not-on-auto-renew domain in the certificate.* Lets one unrenewed
  domain fail the whole lineage's renewal. Rejected; see above.
- *Serving the page inline from nginx (`return 200 '<html>…'`).* Removes a file
  and its permissions, but forces the HTML through nginx string escaping and
  makes the page unreadable as a page. Rejected — a real file is greppable,
  diffable against the committed source, and editable.
- *Answering `404`, or serving an error page.* Misrepresents what happened: the
  request arrived at the right machine and got a deliberate answer. Rejected.
- *Keeping `server_name _;` on the blocks.* The conventional catch-all spelling,
  but on this box it is a name collision: the stock package `nginx.conf` already
  claims `_` on `:80`, so every `-t` and reload warns, and the name buys nothing
  `default_server` does not already decide. Rejected — a warning on every reload
  trains operators to ignore warnings.
- *Removing or managing the distro's default `server` block instead.* Kills the
  same warning from the other side, but makes the suite own a package-config
  file (`nginx-core`'s `/etc/nginx/nginx.conf`, currently pristine per
  `rpm -V`), inheriting rpmnew/drift questions on every nginx package update and
  needing an opsctl or runbook change to carry it. Rejected — the fix lands
  entirely inside files this tree already owns.
- *Mirroring the parked block into the local dev front door (D1).* The dev front
  door is localhost-only on a high port with no TLS and no parked DNS, so a
  mirrored `default_server` would prove nothing the live check does not.
  Rejected.
- *Adding `$host` to the apex `log_format`.* Genuinely useful — its absence is
  why unknown-`Host` traffic had to be probed rather than read from logs — but it
  is an unrelated observability change to a configuration this tree does not own.
  Rejected here; it belongs to whoever owns the apex block.

**Verification.**

This Decision mints **no requirement ids**, deliberately. Its output is two
static committed files plus an operator runbook; no code runs, no module owns
this tree, and the suite's green gate (`go test ./...`) has nothing it could
faithfully assert about it. A test that grepped the committed page for its own
sentence would be a tautology, not a falsifiable behavior.

The claim that actually matters — that a parked domain answers with this page
over valid TLS while the apex is unaffected — hinges entirely on a real external
contract: a real certificate authority issuing for names that really resolve to
the box, and a real nginx selecting a real `default_server`. Nothing reachable
in-gate can falsify it. It is therefore verified **once, manually, on the live
box**, by the runbook's own verification checklist in the repo-root `deploy.md`,
which must include:

- a cert-validating request to at least two of the certificate's names returning
  `200` with the page text, one of them the permanent anchor domain;
- a request to the excluded domain still **failing** certificate validation over
  HTTPS — proving the exclusion is in force rather than the domain having been
  accidentally swept into the certificate;
- a request to the box's bare IP, with validation skipped (an address can never
  match a certificate name), returning the page rather than a service — proving
  `default_server` selection, not name matching;
- a cert-validating request to the account apex still returning the dashboard,
  and one `/srv/<svc>/` path still routing — proving non-interference;
- `certbot certificates` showing exactly two lineages, the apex one and `parked`,
  with the parked lineage naming exactly the kept domains;
- a `diff` of each installed file against its committed source here, reporting no
  difference.

A build phase realizing this Decision therefore carries deterministic
**structural** exit conditions (the exact committed files at their exact paths),
not id-tagged tests.
