# Decision 4 — The testing-language contract: `nginx/` is manual-only, and its conformance is a committed `AGENTS.md`

**Decision.** This tree adopts the suite's testing-language contract,
`root project/design/D23.md` — cited **by path only**, never restated, and
deliberately **not by id**. Adoption here is structural rather than tested, and
this Decision records why and what it obliges the tree to commit.

**Why the citation carries no ids.** The contract mints two ids marked
`[proof: per-service]`, and citing an id is adoption: the id must be realized by
a tagged test in the citing tree. `nginx/` has no Go module, no `go.mod`, no
test file, and no glob where an id tag could live — the repo-root `go.work` does
not and must not name it (D1 Conventions). No test suite here can tag those ids,
so citing them would create a coverage obligation nothing in this tree could
ever discharge. The contract anticipates exactly this case: a tree with **no
test suite at all** still commits its declaration and "conforms structurally,
without the tagged tests". `nginx/` is the tree that clause names.

**The layers this tree has.** **Manual only.** Every claim that matters here —
a request actually refused at the boundary, a real certificate authority issuing
for names that really resolve to the live box, a real nginx selecting a real
`default_server`, the local `:8080` chain routing a real request through
introspection — needs a real nginx, real DNS, or real TLS. None is reachable
even with credentials, which is the contract's definition of the manual layer.
There is no hermetic layer, no composed layer, and no live layer, and the tree
commits no `//go:build live` file.

This does not leave the tree unchecked. Two mechanical checks stand where a test
suite would (D1 and D2 Conventions, unchanged and not restated here): nginx's
own configuration test, and `bash -n` over `run`. They are configuration and
syntax checks, not tests, and neither is a layer in the contract's sense. The
manual-layer checks themselves are already committed — D3's live-box checklist
lives in the repo-root `deploy.md`, and D1's local-chain check is the suite-level
"bring the stack up and verify health through the front door" item the contract
itself places in the manual layer.

**What adoption obliges: an `AGENTS.md`.** The contract requires every tree to
commit its testing declaration, and `nginx/` has no `AGENTS.md` today — the one
tree-level fact it is missing. This Decision requires the file, and fixes what
it declares:

| fact | value |
|---|---|
| check command (this tree has no test command) | run from this tree (`nginx/`): `mkdir -p tmp && nginx -p . -c nginx.conf -t`, plus `bash -n run` |
| layers present | manual only — no hermetic, no composed, no live |
| preconditions | an `nginx` binary on `PATH` for the config check; no Go toolchain, since no Go code lives here |
| GOWORK mode | not applicable — no Go module, and the repo-root `go.work` must not name this tree |

`AGENTS.md` also carries the ordinary tree preamble — what `nginx/` is (the
local-dev front door on `:8080` mirroring prod `/srv/<svc>/` routing, plus the
committed `parked/` `default_server` files), that it is spec-governed by
`nginx/project/`, and that it is not versioned — so the file is a real tree doc
rather than a single stanza. **The committed `AGENTS.md` is this tree's whole
conformance to the declaration contract**: there is nothing else to conform
with, and its existence with the declared facts is the checkable outcome.

**Rejected.**

- *Citing the contract's two `[proof: per-service]` ids anyway, and marking them
  "not applicable".* An id in a design demands a local tagged test; there is no
  file in this tree that could carry one, so the citation would be a permanent
  hole in the coverage denominator — a red check that no work could ever turn
  green. The contract's no-test-suite clause exists precisely to avoid this.
  Rejected.
- *Creating a Go module in `nginx/` just to host the two contract tests.* It
  would put a module in a tree that deliberately has none, force `go.work` to
  name it, and buy a doc-truth test over an `AGENTS.md` at the cost of the
  tree's defining property. The declaration is checkable structurally without
  it. Rejected.
- *Having another tree's suite (`bin/bintest`) assert `nginx/AGENTS.md`.* A
  tree's spec governs only its own codebase; a phase here may not build or test
  in `bin/`, and a check living in `bin/` would be `bin/`'s to own and to
  delete. Rejected.
- *Declaring the `nginx -t` and `bash -n` checks as a hermetic layer.* Neither
  runs a test; the contract's layers classify tests by what they may touch, and
  labelling a syntax check "hermetic" would misreport this tree as having an
  automated gate it does not have. Rejected.

**Verification.**

This Decision mints **no requirement ids**, for the reason stated above: there
is no test file in this tree that could carry an id tag, and the contract's
own no-test-suite clause makes structural conformance the correct form of
adoption. Its proof is structural instead — the committed `nginx/AGENTS.md`
exists and carries the declared facts, checked by the exact-match greps its
phase names (`project/`-excluded, so a phrase in this spec can never satisfy
them).
