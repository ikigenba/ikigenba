# Decision 26 — Browser wiring proof: one minimal headless-Chrome test (chromedp)

**Decision.** The one claim the goja tier structurally cannot see — that
`initController` (D25) actually connects the tested logic to a live DOM — is
proven by a **single real-browser test**: `github.com/chromedp/chromedp` (pure
Go, no node/npm, drives Chrome over the DevTools protocol; footprint and facts
in `project/research/research.md`) launches one headless Chrome, loads a
seeded landing page from an in-test HTTP server, and touches **each
interactive control exactly once**. The governing principle is **minimal
chromedp**: logic is tested in goja, never in the browser; the browser asserts
only that each control's wiring does *something* correct once. "Minimal" is
measured in browser sessions, not assertions — the expensive, flake-bearing
step is the one Chrome launch.

**The harness — real page, no auth, no suite.** The test builds an
`httptest.Server` whose handler is the **real landing render**: the D24
handler over a real migrated store and real bare repositories under
`t.TempDir()` (commits made through the real `git` binary so the shas are
real), plus the repo-real `share/www` static assets (`tokens.css`, fonts,
`landing.js`) — the same bytes production serves. Authentication is
structurally absent: the session cookie is consumed at nginx, a layer this
test deliberately excludes, and the controller makes zero network requests
(D25). For the copy step the harness grants the browser context clipboard
permission for the test origin (CDP `Browser.grantPermissions`,
`clipboardReadWrite`); the `httptest` origin is `127.0.0.1`, a secure context
where `navigator.clipboard` is available, so the real async-clipboard path is
exercised. The test runs in the **default gate** (hermetic under the suite
testing contract: local subprocesses and loopback listeners only, D16).

**One session, one straight-line scenario.** The seeded store holds **twelve
live repositories** across the kinds, constructed so that exactly **one** key
carries the subsequence `cdm` (`code/demo`) and no other key or filler does,
each repository holding at least one real commit. The steps:

1. **Boot** — after `Navigate`, the search input and the pager become visible
   (the controller parsed the island and removed `hidden`). A stubbed
   controller, a 404'd or throwing `landing.js`, or a mis-wired island id
   fails here by timeout.
2. **Filter** — type `cdm` → exactly one row remains, its Name cell reading
   `code/demo`. This pins the browser to the goja-proved subsequence
   semantics and to the key being what the rebuilt row displays.
3. **Sort** — clear the query, then click the **Name** header: the default
   order is ascending, so the first click flips to **key-descending** (the
   exact reverse of the seeded kind-then-name order) with
   `aria-sort="descending"` stamped; a second click restores ascending with
   `aria-sort="ascending"`.
4. **Clear** — after the above, click Clear → search box empty, full list
   back in the default key-ascending order, first page.
5. **Page** — with 12 rows the pager reads `Page 1 of 2`; click Next →
   `Page 2 of 2` and the `<tbody>` shows the remaining 2 rows; Prev returns
   to page 1.
6. **Copy** — before clicking, assert the copy button's icon renders: the
   glyph inside the JS-rebuilt button is in the **SVG namespace**
   (`namespaceURI === "http://www.w3.org/2000/svg"`) with a non-zero rendered
   box. Record the table's rendered width, then click one row's copy button →
   `navigator.clipboard.readText()` returns exactly
   `<srv.URL>/srv/repos/git/<kind>/<name>.git` for that row (the page origin
   plus the row's `clonePath` — the D25 `cloneURL` join, proven against the
   real system clipboard), and the button's label reads `Copied`. Finally
   assert the table's rendered width is identical to the pre-click
   measurement — the `Copy`→`Copied` swap must not reflow (D24's
   width-stable control).

**Chrome is a hard requirement of the green bar.** The suite requires a
`google-chrome` binary on `PATH` of the box running `go test ./...` (present:
`/usr/bin/google-chrome`; the deploy box never runs tests). No Chrome, or
Chrome fails to launch → the test **fails** — never skips (the D16/suite skip
ban). One narrow concession: the harness may retry the **browser launch**
once; a scenario assertion that fails, fails — no scenario retries. The whole
session runs under a `context.WithTimeout` (~30s). The browser is chromedp's
own: `--headless=new`, a fresh temporary user-data-dir, isolated from any
desktop Chrome.

**The dependency boundary.** `chromedp` joins `repos/go.mod` as a
**test-only** dependency, exactly the goja precedent: imported only from
`*_test.go`, so the shipped binary links zero bytes of it. Enforced
mechanically, not by intention (Verification below).

**Rejected.**
- **Playwright / any node-based runner.** A second-language toolchain in a
  pure-Go repo; chromedp does what this needs over the same DevTools protocol
  with zero node.
- **A goja DOM shim.** A hand-rolled fake `document` passes whatever it is
  taught; it cannot falsify real event wiring.
- **`t.Skip` when Chrome is absent.** A soft gate: an environment
  misconfiguration silently un-proves the wiring and reads as green. The
  requirement is hard and declared (D16).
- **Scenario retries.** Retrying assertions hides real intermittent bugs;
  only the launch (an environment step) gets one retry.
- **One browser session per assertion.** Pays the launch cost and its flake
  surface repeatedly for no added independence.
- **Testing logic boundaries in the browser** (pagination arithmetic, clamps,
  case folding). goja owns logic (D25); duplicating it here couples broad
  coverage to the flakiest substrate.
- **Driving the live `bin/start` suite / the nginx front door.** Drags the
  session-cookie auth chain in for zero added proof; the gate is D10's,
  already content-asserted, and no `bin/start` proof lives in this tree (D16).

**Verification.** (R-SPNZ-LS3V through R-SY7A-A6AQ are one chromedp scenario —
a single headless-Chrome session over the seeded `httptest` landing page
described above; R-SZF6-NY1F is a mechanical import-graph assertion.)

- R-SPNZ-LS3V — **boot:** navigating to the seeded page, the search input and
  the pager region become **visible** (bounded wait) — the controller parsed
  the island and removed the `hidden` markers. A stubbed controller or broken
  `landing.js` fails here by timeout.
- R-SQVV-ZJUK — **filter wiring:** typing `cdm` into the search input (real
  key events) leaves exactly **one** row in the table body, whose Name cell
  text is `code/demo` — among the twelve seeded rows only that key carries
  the subsequence. A dead input listener, a broken dispatch chain, or a
  never-rebuilt `<tbody>` fails.
- R-SS3S-DBL9 — **sort wiring:** clicking the **Name** header reverses the
  default ascending order to key-**descending** and stamps
  `aria-sort="descending"` on that header; clicking it again restores
  key-ascending and `aria-sort="ascending"`. A dead header listener, a toggle
  that never flips, or a controller that never stamps `aria-sort` fails.
- R-STBO-R3BY — **clear wiring:** after filtering and sorting, clicking Clear
  empties the search input and restores the full first-page listing in
  key-ascending order. A dead Clear listener or a partial reset fails.
- R-SUJL-4V2N — **pager wiring:** with twelve seeded rows the pager is
  visible reading `Page 1 of 2`; clicking Next changes the readout to
  `Page 2 of 2` and the table body to the remaining 2 rows; clicking Prev
  returns to the first 10.
- R-SVRH-IMTC — **copy wiring:** in the same session (clipboard permission
  granted, `127.0.0.1` secure context), clicking a row's copy button, then
  reading the clipboard back via `navigator.clipboard.readText()`, returns
  **exactly** the page origin plus that row's `/srv/repos/git/<kind>/<name>.git`
  clone path — the string `git clone` accepts against this box — and the
  clicked button's label reads `Copied`. A dead copy listener, a wrong or
  empty copied string, or a missing confirmation fails. This drives the real
  system clipboard — the substrate a mock cannot falsify.
- R-SWZD-WEK1 — **icon renders:** in the same session, the copy glyph inside
  a JS-rebuilt copy button is an element in the **SVG namespace**
  (`namespaceURI === "http://www.w3.org/2000/svg"`) whose
  `getBoundingClientRect()` reports non-zero width and height. A controller
  building the icon with `createElement("svg")` + `innerHTML` produces an
  unpainted HTML-namespaced node and fails.
- R-SY7A-A6AQ — **no reflow on copy:** the table's rendered width, measured
  immediately before the copy click and again after the label shows `Copied`,
  is **equal** — the confirmation must not change the button, cell, or table
  width. An un-reserved label grows the button and fails.
- R-SZF6-NY1F — **dependency boundary:** the production import graph of the
  binary (`go list -deps ./cmd/repos`) contains **neither**
  `github.com/chromedp/chromedp` **nor** `github.com/dop251/goja` — both are
  test-only and the shipped binary links zero bytes of either.
