# Decision 17 — Custody: the bare-repo store, the `Git` seam, and the ref choke point

**Decision.** repos holds one **bare** git repository per artifact under its own
state root, and every mutation of every ref in every repository passes through
**one** function. That is the whole of custody: a validated path, a real git
subprocess, and a single choke point.

## State layout

`REPOS_STATE_DIR` (absolute, resolved at the composition root) is the durable
root, primary customer data under `root project/design/D05.md`:

```
state/repos.db                                  the metadata DB (D2)
state/git/<kind>/<name>.git/                    the live bare repository
state/archive/<kind>/<name>.<unix-nanos>.git/   an archived bare repository
```

Nothing else of repos' lives under `state/`, and nothing repos writes lives
outside it.

## Naming and path safety

```go
// internal/repos/custody.go
var Kinds = []string{"sites", "scripts", "prompts", "code"}

// ValidName reports whether n is a legal repository name:
//   ^[a-z0-9][a-z0-9._-]{0,63}$ , and never "." or ".."
func ValidName(n string) bool
```

`Custody.Path(kind, name)` validates the kind against `Kinds` and the name
against `ValidName` **before** joining, and returns `ErrValidation` otherwise.
Because a legal name contains no `/` and cannot be `..`, no caller-supplied
value can escape the state root — the validation, not a post-hoc
`filepath.Clean`, is the confinement mechanism.

## The `Git` seam

Every git invocation in the service goes through one interface, so the binary
path (`REPOS_GIT_BIN`), the scrubbed environment, and the streaming shape are
set in exactly one place:

```go
type Git interface {
    // Run executes git in dir and returns stdout; a non-zero exit is an error
    // carrying stderr.
    Run(ctx context.Context, dir string, args ...string) ([]byte, error)
    // RunIn is Run with stdin, extra environment, and a caller-supplied stdout
    // writer — used for hash-object, archive, and the CGI door (D19).
    RunIn(ctx context.Context, dir string, env []string, stdin io.Reader, stdout io.Writer, args ...string) error
}
```

The production implementation shells out to the real `git` binary with a fixed,
minimal environment (`PATH`, `HOME` pointed at a scratch dir, `GIT_TERMINAL_PROMPT=0`,
`GIT_CONFIG_NOSYSTEM=1`, `GIT_AUTHOR_*`/`GIT_COMMITTER_*` supplied per call).
**There is no fake implementation in the gate** — see the spine's Conventions.

## Custody operations

```go
type Custody struct { root string; git Git; clock Clock }

func (c *Custody) Init(ctx context.Context, kind, name string) error
func (c *Custody) Path(kind, name string) (string, error)
func (c *Custody) Exists(kind, name string) bool
func (c *Custody) Rename(ctx context.Context, kind, from, to string) error
func (c *Custody) Archive(ctx context.Context, kind, name string) (relPath string, err error)
func (c *Custody) EnsureHooks(ctx context.Context, kind, name string) error
func (c *Custody) Refs(ctx context.Context, kind, name string) (map[string]string, error) // refs/heads/* → sha
```

- **`Init`** runs `git init --bare --initial-branch=main`, then `EnsureHooks`.
  A fresh repository has **no commits**; `refs/heads/main` does not exist until
  the first commit (D18) or the first push (D19) creates it. `HEAD` points at
  `refs/heads/main` from the start so a clone of an empty repository lands the
  client on the right branch.
- **`Rename`** is a directory rename within the same kind — the object database
  moves untouched, so history is preserved by construction. It refuses when the
  target key exists (`ErrConflict`) or the source does not (`ErrNotFound`).
- **`Archive`** renames the bare repository into
  `state/archive/<kind>/<name>.<unix-nanos>.git` and returns that relative path
  for the `repositories.archived_path` column. **Nothing is ever removed from
  disk**: there is no code path in this service that deletes a git object, a
  ref, or a repository directory. The timestamp suffix means repeated
  create/archive cycles of the same key never collide.
- **`EnsureHooks`** writes the `pre-receive` hook below, mode `0755`, replacing
  whatever is there. It runs at `Init` and again for every live repository in a
  boot-time Worker sweep (D1), so a repository restored from a backup that
  dropped file modes, or created by an older build, is repaired rather than left
  silently unguarded.

## The `pre-receive` hook — the door's half of the choke point

A push arrives inside `git receive-pack`, which decides *before* writing whether
to accept each ref. That decision cannot be made after the fact, so it lives in
a hook. The hook is a self-contained POSIX shell script using only `git` — it
calls back into no service and needs no network:

```sh
#!/bin/sh
# repos: pre-receive. REPOS_PUSH_SCOPE is exported by the door (D19):
#   owner -> main may advance only by fast-forward; other refs unrestricted
#   run   -> main may not be touched at all; other refs unrestricted
zero=0000000000000000000000000000000000000000
while read -r old new ref; do
    [ "$ref" = "refs/heads/main" ] || continue
    if [ "$REPOS_PUSH_SCOPE" = "run" ]; then
        echo "repos: this token may not push to main" >&2
        exit 1
    fi
    if [ "$new" = "$zero" ]; then
        echo "repos: main may not be deleted" >&2
        exit 1
    fi
    [ "$old" = "$zero" ] && continue
    if ! git merge-base --is-ancestor "$old" "$new"; then
        echo "repos: force-push to main is rejected" >&2
        exit 1
    fi
done
exit 0
```

`receive.denyNonFastForwards` is deliberately **not** set: it would apply to
every ref, and every ref but `main` is unrestricted.

## The ref choke point — the in-process half

Every ref update repos performs itself (a commit, a merge) goes through one
function, which enforces the same rule the hook enforces and appends the event:

```go
type RefUpdate struct {
    Kind, Name string
    Ref        string // "refs/heads/<branch>"
    OldSHA     string // "" when the ref is being created
    NewSHA     string // "" when the ref is being deleted
    Actor      string // X-Client-Id, or the owner email on the door's owner path
}

// ApplyRefUpdate validates the update, performs `git update-ref` with the
// compare-and-swap old value, and appends the D23 push event on tx.
func (s *Service) ApplyRefUpdate(ctx context.Context, tx *sql.Tx, u RefUpdate) error
```

- On `refs/heads/main`: a delete, or a `NewSHA` that does not have `OldSHA` as
  an ancestor, returns `ErrForcePush` (surfaced as the `conflict` MCP code) and
  performs no write. Any other ref is unrestricted.
- The `git update-ref <ref> <new> <old>` form is a compare-and-swap: a
  concurrent update that moved the ref since the caller read it fails the
  command rather than clobbering it.
- **Ordering.** git is not transactional with SQLite, so the order is fixed and
  stated: validate, `git update-ref`, then append the outbox row on the caller's
  `*sql.Tx`. A failure of the DB transaction after the ref moved means the ref
  moved with no event — at-most-once, in the direction that never announces a
  commit that does not exist. The append and every other row the caller writes
  in that transaction still commit together or not at all.

The door (D19) does **not** call `ApplyRefUpdate` — `receive-pack` moves those
refs itself under the hook — but it publishes through the same event path by
diffing `Refs()` around the invocation. The two halves enforce one rule in the
two places a ref can move, and D19's verification proves the door's half against
real `git push`.

**Rejected.**
- **A bare `git` mock behind the `Git` seam in the gate.** The seam exists to
  centralize the binary path and environment, not to enable a fake. Every claim
  in this service is a claim about what git does; a fake would accept the
  arguments and prove nothing. The seam is injected in tests only to point at a
  different binary path, never at a different behavior.
- **Enforcing force-push protection in Go after `receive-pack` returns**, by
  resetting `main` when it moved backwards. The bad state exists on disk, and
  concurrently a clone can observe it and an event can fire. The hook refuses
  before the write.
- **`receive.denyNonFastForwards = true`.** Correct for `main`, wrong for every
  other ref: an automated actor rewriting its own branch is normal and
  explicitly allowed.
- **A `post-receive` hook that publishes the events.** It would need to reach
  back into the running service (a URL, a token, a curl dependency) from a shell
  script, and its failure mode is a silently unpublished event. Diffing refs in
  process around the `receive-pack` call needs nothing and cannot half-fire.
- **Nesting archives under the live tree** (`state/git/<kind>/<name>.archived`).
  A listing or a glob over the live tree would have to know to exclude them, and
  a subsequent create of the same key would collide. A separate root makes "live"
  a directory listing.
- **Deleting a repository's directory on `delete`.** Product forbids destroying
  history and the plane contract forbids casual deletion; keeping *no* delete
  path in the code is the enforcement.
- **Allowing `/` in a name to express nesting.** The plane's key is exactly
  `<kind>/<name>`; a slash inside `name` would make the door's URL parse
  ambiguous and reopen the traversal question the charset closes.

**Verification.** (All against the real `git` binary; bare repositories and
client working copies under `t.TempDir()`.)
- R-J4Y9-H96C — `Init("code","demo")` creates `state/git/code/demo.git` such
  that real git reports it bare (`git rev-parse --is-bare-repository` → `true`)
  and `HEAD` resolves symbolically to `refs/heads/main` **before any commit
  exists**, and `git ls-remote` against it lists zero refs.
- R-J665-V0X1 — `Path` returns `ErrValidation` for the kind `nope`, and for the
  names `""`, `.`, `..`, `../escape`, `a/b`, `Upper`, and a 65-character name;
  after all of those calls no directory or file exists anywhere under the state
  root other than the ones the test created itself (the escape attempts land
  nowhere, inside or outside).
- R-J7E2-8SNQ — `Rename(kind, "old", "new")` on a repository holding two
  commits leaves nothing at the old path, a bare repository at the new path, and
  a real `git clone` of the new path whose `git rev-list --count HEAD` is 2 with
  the same tip sha as before the rename; renaming onto an existing key returns
  `ErrConflict` and moves nothing; renaming an absent key returns `ErrNotFound`.
- R-J8LY-MKEF — `Archive` moves the bare repository under `state/archive/`,
  leaves nothing at the live path, and a real `git clone` of the returned
  archived path still yields **every** commit (same tip sha, same commit count);
  a subsequent `Init` of the same `(kind, name)` succeeds and yields a fresh
  empty repository, and archiving that one too produces a **second, distinct**
  archived path with the first still intact.
- R-J9TV-0C54 — `Init` leaves an executable `hooks/pre-receive` in the bare
  repository; deleting that file and running `EnsureHooks` restores it with mode
  `0755` and byte-identical content; the boot sweep repairs every live
  repository that is missing it in one pass.
- R-JB1R-E3VT — `ApplyRefUpdate` on `refs/heads/main` returns `ErrForcePush`
  and leaves the ref at its previous sha when (a) `NewSHA` is empty (a delete)
  and (b) `NewSHA` does not have `OldSHA` as an ancestor (a rewrite onto a
  divergent commit) — while the *same* divergent rewrite applied to
  `refs/heads/ikigenba/work` **succeeds** and moves that ref. A fast-forward on
  `main` also succeeds. (Real git commits and real `update-ref`; the sha is read
  back with `git rev-parse` after each call.)
- R-JC9N-RVMI — every accepted `ApplyRefUpdate` appends **exactly one** `push`
  outbox row on the supplied transaction, carrying the branch, the new sha, the
  old sha, and the actor; a **rejected** update appends **none** and leaves the
  outbox empty; and a rejected update never reaches `git update-ref` at all —
  proven by the ref's sha being unchanged *and* the row count being zero after
  a force-push attempt on `main`.
