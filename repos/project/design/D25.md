# Decision 25 — Client-side filter, sort, and pagination of the landing listing

**Decision.** The landing page (D24) carries an in-browser control layer over
the repository listing: a fuzzy **search filter** on the `kind/name` key,
a **sortable Name column** (the one sort key), **pagination** past ten rows, a
one-click **Clear**, and the per-row **copy button** that puts the absolute
clone URL on the clipboard. All of it runs client-side in JavaScript — the
`GET /{$}` handler, the store, custody, and nginx are unchanged; this is
purely additive to D24's server render. A no-JS browser still gets the
complete server-rendered table, un-enhanced.

**Where the logic runs and why.** The box holds a modest roster of
repositories; the server already ships every row, and shipping it once more as
island data is trivial. Client-side gives instant per-keystroke filtering with
no round-trip and keeps the feature a self-contained layer touching no Go
request path.

**The data path — the JSON island (D24).** The controller does not scrape the
DOM. It parses `#repos-data` once on load and drives everything from plain row
objects (`{kind, name, key, sha, clonePath}`), never DOM nodes. The controller
makes **zero network requests** — no fetch, no XHR, no cookie reads; the
session cookie is spent at nginx, a layer the page never sees (which is why
its browser test needs no auth, D26).

**The module — pure functions plus a thin controller.**
`share/www/static/landing.js` keeps almost all logic in pure functions, with
DOM work reduced to glue:

```js
// Pure — no DOM, no globals, deterministic. Exposed for testing.
function filterRepos(rows, query)   // subsequence-fuzzy predicate on the key
function sortRows(rows, dir)        // by key, 'asc'|'desc'; keys are unique
function paginate(rows, page, size) // rows.slice((page-1)*size, page*size)
function nextSort(state)            // header-click: flip dir asc<->desc
function defaultState()             // {query:'', dir:'asc', page:1}
function reduce(state, action)      // setQuery|setSort|setPage|clear -> new state
function computeView(rows, state)   // orchestrates the above -> a view model
function cloneURL(origin, clonePath)// origin + clonePath, exactly one join

// view model: { rows, showControls, empty, noMatch, showPager,
//               page, pageCount, rangeFrom, rangeTo, dir }

globalThis.ReposLanding = {
  filterRepos, sortRows, paginate, nextSort, defaultState, reduce,
  computeView, cloneURL,
};

// DOM bootstrap — inert under a non-browser runtime (goja).
if (typeof document !== 'undefined') {
  document.addEventListener('DOMContentLoaded', () => initController());
}
```

There is one sortable column, so sort state is just `dir`: `nextSort` flips
it, and `sortRows` takes no key argument.

**`initController` — a real, branchless transcription.** On `DOMContentLoaded`
it parses `#repos-data`, initializes `state = defaultState()`, flips the root
`no-js` class to `js`, removes `hidden` from the controls the view model says
to show (`showControls` gates the filter bar, `showPager` the pager; with zero
repositories everything stays hidden and D24's server empty state stands),
wires the listeners — `input` on `#repo-search` (`setQuery`), Escape in the
search box (`setQuery('')`), `click` on the Name header (`setSort`), Prev/Next
(`setPage`), Clear (`clear`), and **one delegated `click` on the table body
for `.copy-btn`** — and on every action dispatches through `reduce`, calls
`computeView`, and transcribes the view model onto the DOM: rebuilds `<tbody>`
from `view.rows` (key and sha cells set via `textContent`, never `innerHTML`;
an empty `sha` renders the em-dash; a far-right copy button carrying
`cloneURL(location.origin, row.clonePath)`), sets the `Page X of Y` readout,
toggles the pager and no-match message, and stamps `aria-sort`
(`ascending`/`descending` per `view.dir`) on the Name header. The controller
has no branching logic of its own; every decision comes from `computeView`.

**The copy icon is built in the SVG namespace.** The row rebuild creates the
icon `<svg>` and its children with
`document.createElementNS("http://www.w3.org/2000/svg", …)` — never
`document.createElement("svg")` + `innerHTML`, which yields HTML-namespaced
nodes the browser will not paint. That the icon actually renders is a
real-browser fact; its proof is D26's.

**The copy control is a side effect, outside the reduce cycle.** Because
`<tbody>` is rebuilt on every action, copy is wired once as a delegated click
on the stable table body: a click on a `.copy-btn` reads the button's absolute
URL and writes it to the clipboard, replicating the suite copy-button
behaviour captured in `project/research/research.md` —
`navigator.clipboard.writeText` in a secure context, else the hidden
`<textarea>` + `execCommand` fallback — then swaps the label to `Copied` and
toggles `.is-copied` for ~1.6s before reverting. It changes no app state and
does not pass through `reduce`/`computeView`. Its runtime proof (a real click
lands the URL on the system clipboard) is D26's; goja cannot see a clipboard.

**The behaviors (pure):**

- **Filter — subsequence fuzzy, case-insensitive, over the key, predicate.**
  `filterRepos` keeps a row when the lowercased query is a **subsequence** of
  the lowercased `key` (characters in order, not necessarily adjacent — the
  query may span the `/`). It is a predicate: it preserves input order among
  survivors and never re-ranks. An empty query returns all rows unchanged.
- **Sort — one key, two directions, deterministic.** `sortRows(rows, dir)`
  orders by `key` ascending or descending; keys are unique (the `(kind, name)`
  primary key), so order is total with no tie-break needed. `nextSort` flips
  `dir` on each Name-header click. The default is `asc` — the same
  kind-then-name order the server rendered.
- **Paginate — fixed page size 10.** `paginate(rows, page, 10)` returns exactly
  `rows.slice((page-1)*10, page*10)`. `computeView` shows the pager only when
  the filtered set exceeds 10 rows, derives `pageCount`, a `Page X of Y` label
  and an `N–M of T` range, and clamps `page` into `[1, pageCount]`.
- **State & clear.** `defaultState()` is `{query:'', dir:'asc', page:1}`.
  `reduce`: `setQuery` and `setSort` reset `page` to 1; `setPage` changes only
  the page; `clear` returns exactly `defaultState()`. Escape in the search box
  fires `setQuery('')`.
- **Empty states (derived by `computeView`).** Zero repositories →
  `{showControls:false, empty:true}` (no dead search box; the server empty
  state stands). Rows present but the filter matching none →
  `{noMatch:true, showPager:false}` with the controls kept visible.
- **The clone URL.** `cloneURL(origin, clonePath)` is the one place the
  absolute address is composed: `origin + clonePath`, with exactly one `/`
  at the join (`location.origin` carries no trailing slash; `clonePath` is
  root-anchored). No second computation exists anywhere in the page.

**Progressive enhancement.** The controls are hidden-until-JS and the
stylesheet guarantees hidden hides (D24). JS off → the plain full table; JS on
→ the controller reveals the controls and the table becomes live.

**Testing — two tiers, each covering the other's blind spot.**

- **goja owns the logic.** A Go test loads the repo-real
  `share/www/static/landing.js` into `github.com/dop251/goja` (pure-Go ES
  engine, test scope only, inside `go test ./...`) and drives the exposed
  `ReposLanding.*` pure functions against fixed inputs. goja has no
  `document`, so the controller bootstrap is inert. Logic is tested here,
  never in the browser.
- **The browser proves the wiring (D26).** One headless-Chrome session over a
  seeded, auth-free `httptest` page touches each control exactly once. This
  Decision's ids stay pure/structural; the wiring ids are D26's.
- **Accepted residual risk: the Escape binding.** Its semantics are
  goja-covered and its listener target (the search input) is proven live by
  D26's filter step; the specific key binding is deliberately not
  browser-driven (minimal-chromedp, D26).

**Rejected.**
- **Server-side query params (`?q=&sort=&page=`).** A round-trip per keystroke
  and handler-side sort/paginate machinery for an always-shipped list;
  rebuilds the request path this Decision leaves untouched.
- **DOM manipulation of server rows (no island).** DOM-bound logic cannot be
  tested in goja; everything would need the browser.
- **A node/vitest runner.** A second-language toolchain in a pure-Go repo;
  `go test ./...` would no longer be the whole green bar.
- **A multi-key sort state machine (sites' shape).** repos has one sortable
  column; carrying `sortKey` state and a key-switch rule for a single key is
  dead machinery. `nextSort` flips a direction, nothing more.
- **Ranking filtered results by match score.** The filter is a predicate;
  the sort owns order.
- **Numbered page buttons; URL/hash-persisted state.** Prev/Next with a
  readout suffices; in-memory state keeps clear trivially total.
- **Computing the absolute clone URL at copy-click time from the DOM row.**
  One pure, goja-testable join (`cloneURL`) stamped at rebuild beats string
  assembly buried in an event handler.

**Verification.** (All ids except R-SOG3-80D6 drive the real shipping
`landing.js` in goja with fixed inputs; R-SOG3-80D6 is a structural assertion
over the shipped `share/www` tree. The runtime wiring ids live in D26.)

- R-S7DH-V7ZG — `filterRepos` matches the query as a **subsequence of the
  key**: given rows keyed `["code/demo", "code/alpha", "sites/blog"]`, query
  `cdm` returns exactly the `code/demo` row (not a substring anywhere; a
  substring implementation returns `[]` and fails), and query `c/a` returns
  exactly `code/alpha` (the query spans the slash).
- R-S8LE-8ZQ5 — `filterRepos` is case-insensitive: query `CDM` matches key
  `code/demo` and query `Sites/B` matches key `sites/blog`. A case-sensitive
  implementation returns `[]` for at least one and fails.
- R-S9TA-MRGU — `filterRepos(rows, "")` returns **all** rows in the original
  input order.
- R-SB17-0J7J — `filterRepos` preserves input order among survivors and does
  not re-rank: with keys ordered `["sites/zapp", "code/app"]` and query `app`,
  the result keeps that input order.
- R-SC93-EAY8 — `sortRows(rows,'asc')` orders rows by key ascending and
  `sortRows(rows,'desc')` is its exact reverse: keys
  `["sites/blog","code/demo","prompts/weekly"]` come back
  `code/demo, prompts/weekly, sites/blog` ascending. An implementation that
  ignores `dir` or sorts another field fails.
- R-SDGZ-S2OX — `nextSort({dir:'asc'})` yields `dir:'desc'` and
  `nextSort({dir:'desc'})` yields `dir:'asc'` — the Name-header click always
  flips.
- R-SEOW-5UFM — `paginate(rows, page, 10)` returns exactly
  `rows[(page-1)*10 .. page*10)`: for 34 rows, page 1 has the first 10, page 4
  has the last 4, page 5 returns `[]`. An off-by-one fails at one of these
  boundaries.
- R-SFWS-JM6B — `computeView` reports `showPager:true` **iff** the filtered
  row count is **> 10**: exactly 10 → `false`; 11 → `true`.
- R-SH4O-XDX0 — `computeView` derives a correct `pageCount`, `Page X of Y`
  label, and `N–M of T` range, and clamps an out-of-range `page` into
  `[1, pageCount]`: 34 rows at `page:4` → `pageCount:4`, range `31–34 of 34`;
  `page:9` clamps to page 4 with the same range.
- R-SICL-B5NP — `computeView` empty-state kinds: zero input rows →
  `{showControls:false, empty:true}`; rows present but the query matching none
  → `{showControls:true, noMatch:true, showPager:false}`. Conflating the two
  fails.
- R-SJKH-OXEE — `defaultState()` deep-equals `{query:'', dir:'asc', page:1}`,
  and `reduce(anyState, {type:'clear'})` returns exactly that default
  regardless of prior state; a partial reset fails.
- R-SKSE-2P53 — `reduce` page-reset invariant: `setQuery` and `setSort` from
  `page:3` both return `page:1`, while `setPage` to 2 returns `page:2`.
- R-SN86-U8MH — `cloneURL("https://acct.example.com",
  "/srv/repos/git/code/demo.git")` returns exactly
  `https://acct.example.com/srv/repos/git/code/demo.git` — one slash at the
  join, no encoding, no second scheme.
- R-SOG3-80D6 — the shipped tree contains `share/www/static/landing.js`, and
  the rendered `landing.html` references it with a
  `<script src="static/landing.js">` (deferred). A tree missing the file, or
  an HTML that never loads it, fails.
