# Decision 1 — Composition root & chassis boot

**Decision.** repos is a core-block service on the appkit chassis, composed
exactly like the newest services: `cmd/repos/main.go` is
`func main() { appkit.Main(reposSpec()) }`, and `reposSpec()` returns one
inline `appkit.Spec`:

```go
appkit.Spec{
    App:            "repos",
    Mount:          "/srv/repos/",
    Port:           registry.MustPort("repos"),   // 3007, Core
    MCP:            true,
    WWW:            true,
    Feed:           "/feed",
    Migrations:     db.FS,
    Events:         repos.Events,                 // D23 registry
    Handlers:       handlers,                     // below
    Producer:       producer,                     // injects the outbox into the Service (D23)
    Workers:        workers,                      // hook self-heal + token sweep (D17, D20)
    Health:         health,                       // repository count, archived count
    ManifestExtras: extras,                       // D15
}
```

repos declares **no `Consumers`**: it subscribes to no other service's feed and
has no `feed_offset` state. It is a producer only. It also holds no peer
clients — no `HTTPClient` is taken off the Router, because repos makes no
outbound HTTP call to anything.

`Handlers(rt)` reads all `REPOS_*` env at this root (the config set in the
spine's Conventions), constructs the `Git` runner over `REPOS_GIT_BIN`, the
`Custody` over the resolved state root, the one domain `*repos.Service` over
`rt.DB()`, and then mounts:

| route | gate | Decision |
|---|---|---|
| `POST /mcp` | `rt.RequireIdentity` | D22 |
| `GET /{$}` (landing) + `GET /static/…` | `rt.WWW()` | D10 |
| `GET /content`, `GET /list`, `GET /stat`, `GET /archive`, `PUT /content`, `DELETE /content`, `POST /commit` | `rt.HandleLoopback` | D18 |
| `POST /run-token` | `rt.HandleLoopback` | D20 |
| `/git/` (prefix) | the door's own two-path auth | D19 |

The `/git/` prefix is the one route that is **neither** identity-gated by the
chassis **nor** loopback-private: it authenticates itself, both ways, inside
D19's handler. Every other non-public route uses the shared chassis guard.

`POST /mcp` is reached by **both** kinds of caller: a remote agent whose
identity headers nginx injected, and a sibling service on loopback that asserts
the same headers itself (D22's caller model). The identity gate is indifferent
to which — it requires `X-Owner-Id` and nothing more — so no second mount, no
service-only mode, and no REST twin of any domain verb exists at this root.

Hook order is the chassis's `Handlers → Producer → Workers`. The Worker set is
two small loops, both cheap and both idempotent: a boot-time sweep that
re-materializes any missing `pre-receive` hook (D17) and a periodic sweep that
deletes expired run tokens (D20).

Internal layout: `internal/db` (migration embed + DDL guards only),
`internal/repos` (domain: custody, git seam, refs, commits, statuses, merge,
events, store), `internal/mcp` (`mcp.go` + `tools.go`, D22), `share/www/`
(D10), `etc/manifest.env`, `etc/nginx.conf`, `.envrc`, `AGENTS.md`
(+ `CLAUDE.md` symlink), `VERSION` (the committed, `v`-prefixed version source
of truth, `root project/design/D03.md`; its *starting* value is product's
contractual constant, and no spec document states its current value).

Suite-level preconditions this module consumes but does not own: the registry
row `{"repos", 3007, Core}`, the `./repos` entry in `go.work`, and the `repos`
entry in `bin/start`'s `SERVICES`. No Decision or phase here edits those files.

**Rejected.**
- **A worker pool service outside appkit** — every deployable app rides the
  chassis; the fixed verb set, the manifest render, and deploy tooling assume it.
- **Registering repos under Connectors (32xx)** — repos owns a first-party
  domain (git custody), not a third-party bridge; it is a Core service and 3007
  is frozen.
- **Reading env below the composition root** — suite convention: config is
  resolved once at the root and passed down as values.
- **Putting the git door behind `rt.RequireIdentity`.** The door must accept a
  loopback run-token bearer that carries no owner headers at all, and must
  refuse an nginx-crossed request that carries no owner headers. Neither the
  identity gate nor the loopback guard expresses that pair; D19's handler does.

**Verification.**
- R-EISY-2LYZ — the Spec's manifest render (`appkit/manifest.Emit`, the library
  form) emits exactly `APP=repos`, `MOUNT=/srv/repos/`, `PORT=3007` (from the
  registry, no literal in source — a source-scan test proves no
  `127.0.0.1:30` literal outside tests), `MCP=true`, `FEED=/feed`, and
  **no `CONSUMES` line at all** (repos consumes nothing), plus the D15 manifest
  extras.
- R-EL8Q-U5GD — through the assembled handler over `httptest`: `POST /mcp`
  without identity headers is refused, with asserted identity reaches the D22
  tool table; `GET /{$}` renders the D10 landing; `GET /feed` serves the
  eventplane SSE handler; and `GET /content` — mounted through
  `rt.HandleLoopback` — answers 404 for a request carrying
  `X-Forwarded-Proto`, proving the loopback routes are wired through the guard
  at this root rather than only inside their own package.
