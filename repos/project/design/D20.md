# Decision 20 — Run tokens: short-lived, repository-scoped push credentials

**Decision.** An on-box run (a scripts or prompts sandbox) performs **real
`git clone` and `git push`** against the door (D19) — there is no second
materialization API for runs — so it needs a credential. It gets a **run
token**: minted on demand by the service that is about to start the run, scoped
to exactly one repository, short-lived, and unable to touch `main`.

## Minting

```
POST /run-token           (loopback-private via rt.HandleLoopback)
  → {"kind":"code","name":"demo","ttl":"40m"}        (ttl required)
  ← {"token":"<43-char base64url>","expires_at":"<RFC3339Nano UTC>",
     "clone_url":"http://127.0.0.1:3007/git/code/demo.git"}
```

- The token is 32 bytes from `crypto/rand`, base64url without padding.
- **Only its `sha256` is stored** (`run_tokens.token_sha256`, D2). The raw token
  is returned once and never again — repos cannot show it, and a database dump
  is not a set of credentials.
- **`ttl` is the caller's lifetime, required and honored verbatim**, a Go
  duration string. The value is deterministically derived at the caller's
  single mint site — the run's TTL plus a fixed margin, per the run-lifetime
  contract (`root project/design/D26.md`) — so repos applies no ceiling, no
  default, and no clamp: `expires_at` is `Clock.Now().Add(requested)` exactly.
  The bound on run lifetimes (and therefore on token lifetimes) is the
  contract's 6h cap, enforced in each run-spawning service at startup, not
  here.
- A missing `ttl`, one that does not parse as a Go duration, or one that
  parses to a zero or negative duration, is **400** and mints nothing. A
  caller that omits the field is misconfigured by construction; guessing a
  lifetime on its behalf would be a silent second policy.
- `clone_url` is assembled from `registry.BaseURL("repos")`, so the caller never
  builds an address.
- Minting for an unknown or archived repository is **404**; an invalid key is
  **400**.

Callers embed the token as the Basic password in the URL they hand the run
(`http://run:<token>@127.0.0.1:3007/git/<kind>/<name>.git`), which is what makes
an ordinary `git` client send it.

## Validation

The door hashes the presented credential and looks the row up by hash:

| condition | result |
|---|---|
| no row for the hash | **401** |
| `expires_at` ≤ now | **401** |
| row's `(kind, name)` ≠ the requested repository | **403** |
| otherwise | authenticated; actor `run:<kind>/<name>`, push scope `run` |

The **403** is deliberate and distinct from 401: a run that was handed the wrong
repository has a real credential and a wrong target, and conflating that with
"unauthenticated" would send it into a credential-refresh loop.

Push scope `run` is passed to `receive-pack` as `REPOS_PUSH_SCOPE=run`, which
the `pre-receive` hook (D17) reads as "`refs/heads/main` may not be touched at
all" — not even fast-forward. Fetch is unrestricted within the one repository.

## Expiry

Expiry is enforced at **validation** time, by comparing against the injected
clock — so an expired token is refused whether or not it has been swept. A
periodic Worker (D1) calls `SweepExpiredTokens(now)` purely to keep the table
small; deleting rows is housekeeping, never the security boundary.

**Rejected.**
- **A long-lived per-service credential.** A token that never expires is a
  standing key to a repository sitting in whatever a run wrote it into; the
  whole point of minting per run is that a leaked token is worthless in hours
  and scoped to one artifact.
- **Reusing the dashboard's personal access tokens for on-box runs.** A PAT is
  the *owner's* credential with the owner's push rights, including `main`; a run
  must not have those. The two paths are separate because the scopes are.
- **Storing the token in plaintext so it can be re-shown.** There is no case for
  re-showing it: the caller that minted it is the caller that injects it, in the
  same operation. Storing the hash costs nothing and removes the DB from the
  credential blast radius.
- **Scoping a token to a kind, or to all of an owner's repositories.** A run is
  dispatched about one artifact; a broader scope buys nothing and lets a
  compromised run walk sideways.
- **Refusing an expired token only after the sweep has run.** That would make
  the security property depend on a background loop's schedule. Validation
  compares timestamps; the sweep only reclaims rows.
- **Returning 401 for a token presented against the wrong repository.** It
  misdirects the client into re-authenticating for a problem that is not
  authentication.
- **A plane-side TTL ceiling (`REPOS_RUN_TOKEN_TTL`) with `min()` capping.**
  The prior shape. repos cannot see its callers' run TTLs, so the ceiling
  could never be validated against them: a run TTL raised past it produced
  tokens silently shorter than their runs — a mid-run authentication failure
  instead of a loud startup error. The bound now lives at the source
  (`root project/design/D26.md`), where the run TTL is configured and can be
  refused at boot.
- **A default lifetime for requests that omit `ttl`.** The value is derived
  deterministically at the caller's one mint site; an omitted field is a bug,
  and a repos-chosen fallback would hide it behind a lifetime nobody computed.
- **A separate env knob for a per-service default TTL.** The caller already
  knows its run TTL precisely at mint time; a second knob would be a stale copy
  of that knowledge.

**Verification.**
- R-36US-ASST — `POST /run-token` with `"ttl":"40m"` returns a token and an
  `expires_at` equal to the injected clock's now plus **exactly 40 minutes**
  (the request, no cap and no default applied — a second mint with
  `"ttl":"3h"` returns now plus exactly 3 hours), and a `clone_url` built from
  `registry.BaseURL("repos")`; the stored `run_tokens` row's `token_sha256`
  equals `sha256(token)` in lowercase hex and **the raw token appears in no
  column of the row** (every column is scanned for the literal). Minting for
  an unknown repository returns **404**.
- R-KAEU-HGDY — a **real `git clone`** of the loopback door using a valid run
  token as the Basic password **succeeds** and retrieves the full history; the
  **same** token presented against a **different** repository's door path is
  refused **403** and no clone occurs.
- R-KBMQ-V84N — with the injected clock advanced past `expires_at`, the same
  token is refused **401** by the door, **without** the sweep having run (the
  Worker is not started in the test) — proving expiry is enforced at validation.
- R-KCUN-8ZVC — over the run path, a **real `git push`** of
  `HEAD:refs/heads/ikigenba/work` **succeeds** and the ref lands, while a
  **fast-forward** `git push HEAD:main` **fails** with the hook's rejection text
  and leaves `main` at its previous sha — the run scope refuses `main` even when
  the owner scope would have accepted it.
- R-KE2J-MRM1 — `POST /run-token` returns **404** for a request carrying the
  nginx-crossed marker (`X-Forwarded-Proto`), and succeeds for the same request
  without it; and `SweepExpiredTokens` deletes only rows whose `expires_at` is
  before the injected now.
- R-382O-OKJI — `POST /run-token` with `"ttl":"banana"`, with `"ttl":"-5m"`,
  with `"ttl":"0s"`, and with the field **omitted entirely** each return
  **400** and insert **no** `run_tokens` row. The omitted case is
  discriminating: a handler that falls back to any default lifetime fails it.
