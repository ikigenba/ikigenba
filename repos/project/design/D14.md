# Decision 14 — Suite-contract conformance: the opsctl install layout & the authored env contract

**Decision.** repos is an ordinary deployable service of the suite, so it
**conforms by default** to the suite-wide contracts the umbrella project owns.
Two of those contracts carry `[proof: per-service]` Verification ids, which
means each adopting service proves them **in its own tree**:

- **The `/opt/<svc>/` install layout and its per-service adoption** —
  `root project/design/D08.md`.
- **The portable authored `manifest.env` and the composed data paths** —
  `root project/design/D11.md`.

This Decision is the **citation**, and citation is adoption: repos owns none of
those contracts' content, restates none of it, and takes each by value from the
umbrella Decision named above. What is local to repos — and all this Decision
adds — is *where the proof lives* and *what substrate can falsify it here*:

- The proofs live in **`cmd/repos/main_test.go`**, the composition root's test
  file, matching every other adopting service. No new package is introduced for
  them.
- The committed authored manifest is **`repos/etc/manifest.env`**; the compiled
  default it must agree with is the one `reposSpec()` declares — `APP=repos`,
  `MOUNT=/srv/repos/`, `DEFAULT=false`, `PORT` from
  `registry.MustPort("repos")`, `MCP=true`, `FEED=/feed`, **no `CONSUMES`
  line** (repos consumes nothing, D1), plus the D15 manifest extras. Because
  `cmd/repos/main_test.go` is `package main`, the test derives the
  `manifest.Fields` it renders **from the `appkit.Spec` `reposSpec()` returns**,
  not from re-typed literals, so a Spec edit not mirrored into the committed
  file fails the comparison.
- This is a **different claim** from `R-EISY-2LYZ` (D1), which pins the built
  binary's manifest output. `R-8IAN-FB87` is about the compiled `Spec`'s
  defaults through the `appkit/manifest.Emit` library function. Both stand;
  neither is folded into the other.
- The boot proof runs the **built binary against a temporary root**, not the
  live box. Four facts particular to repos shape it:
  - repos declares `WWW: true` (D1/D10) and serves its landing page and static
    assets from **`share/www/`** on disk, so its install-layout proof must build
    a real **`share/<version>/www` tier with a `share/current` symlink**. A
    missing or unresolvable web root fails the chassis boot outright, which is
    what makes that tier falsifiable here.
  - repos owns **durable file space beyond its DB** (D17): `REPOS_STATE_DIR`
    holds every bare repository and the archive area. Under the root D08 that
    space belongs under `state/`, so the smoke points it there and the proof
    includes that repos creates its git root **inside** the layout's `state/`
    tier rather than beside the process's working directory.
  - repos boots with **no credentials in its environment at all**: it
    authenticates nobody itself and calls no external service, so the smoke
    supplies none and any code path that demanded one would fail the boot. This
    is a stronger offline property than the smoke had when an agent provider key
    was required, and it is asserted rather than assumed.
  - repos **consumes no feed**, so there is no unreachable-peer question at boot
    and the smoke asserts nothing about consumption.
- repos' `Health` reporter (D1) reads only its own SQLite store (repository and
  archived counts), so the health envelope is genuinely green offline: no
  network dependency is folded into it and none may be introduced to make the
  smoke pass. In particular the health check does **not** shell out to `git`:
  boot health must not depend on a subprocess.

Conformance is the default and this Decision records no deviation.

**Rejected.**
- **Restate the two contracts' requirements locally so the design reads
  self-contained.** A local restatement is drift by construction — it goes stale
  the moment the umbrella Decision is rewritten, and the suite's rule is cite,
  never restate.
- **Fold the citation into D1 (composition root & chassis boot).** D1 owns the
  Spec's shape and its two ids; hanging three adopted, externally-owned ids off
  it would blur which Decision states the behavior.
- **Treat the contracts as proven elsewhere and cite only the Decision paths,
  without the ids.** Both contracts are marked `[proof: per-service]`: a service
  that adopts them must carry its own tagged tests.
- **Prove the boot against the running suite (`bin/start`) instead of a temp
  root.** That makes the phase's exit condition depend on shared host ports and
  another worktree's stack. The temp root is the deterministic one, and is what
  every adopting service uses.

**Verification.** Each id below is **adopted**, not minted here: it belongs to
the umbrella Decision cited beside it, which states the behavior. These lines
say only what substrate proves it inside `repos/`.

- `R-4LKF-FB23` — adopted from `root project/design/D08.md`. Substrate: a Go
  test in `cmd/repos/main_test.go` that assembles a fresh `/opt/repos/`-shaped
  tree under `t.TempDir()` (`state/`, `cache/`, `libexec/`, `bin/run` → the
  built binary, `etc/<VERSION>/manifest.env` copied byte-for-byte from the
  committed authored file with `etc/current` → `<VERSION>`, and
  `share/<VERSION>/www` populated from the committed `share/www/` with
  `share/current` → `<VERSION>`), runs `bin/run serve` on a free loopback port
  with **no credentials in the environment** and the state root under `state/`,
  and asserts the served `/health` is `200` with `service: "repos"` and
  `status: "ok"`, that the DB was created under `state/`, the git root was
  created under `state/`, and the generation sidecar under `cache/`, that the
  landing page renders through the `share/current` web root, and that `bin/run`,
  `etc/current`, and `share/current` resolve to their intended targets. Offline:
  no network, no real credentials, no `bin/start`.
- `R-8DF1-W89F` — adopted from `root project/design/D11.md`. Substrate: a Go
  test in `cmd/repos/main_test.go` scanning the committed `repos/etc/manifest.env`
  bytes and failing on an absolute `/opt/` path or a `REPOS_DB_PATH=` /
  `REPOS_GENERATION_PATH=` line.
- `R-8IAN-FB87` — adopted from `root project/design/D11.md`. Substrate: a Go
  test in `cmd/repos/main_test.go` comparing `manifest.Emit(...)` over fields
  read off the `appkit.Spec` that `reposSpec()` returns against the committed
  `repos/etc/manifest.env` bytes, failing on any difference in either direction.
