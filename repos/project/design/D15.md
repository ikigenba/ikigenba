# Decision 15 — Env-channel conformance: repos' four knobs, and an environment with no credentials

**Decision.** Route every repos value per the root configuration-routing
contract (`root project/design/D21.md`). repos' whole configuration surface is
four `REPOS_*` values, and after the v2 rewrite **none of them is a secret and
none is customer data** — the service authenticates nobody and calls nothing
outside the box.

1. **Two channel-1 manifest knobs.** `REPOS_RUN_TOKEN_TTL` (D20) and
   `REPOS_MAX_COMMIT_BYTES` (D18) are operator-facing tuning knobs: one bounds
   how long a run's push credential lives, the other bounds how large a single
   commit request may be. Both are identical on every box, so both belong in the
   committed manifest. The `Spec` declares them and `repos/etc/manifest.env`
   carries the same lines:

   ```go
   ManifestExtras: []appkit.ManifestKV{
       {Key: "REPOS_RUN_TOKEN_TTL",    Value: "2h"},
       {Key: "REPOS_MAX_COMMIT_BYTES", Value: "67108864"},
   },
   ```

   The reads in `reposSpec()`'s `Handlers` stay `config.EnvOrDuration` /
   `EnvOrInt64`; in production the launcher exports every manifest key, so the
   manifest line is what the process receives and the code defaults are the dev
   fallback that must agree with it. R-8IAN-FB87 (adopted in D14, derived from
   `reposSpec()`) pins the byte agreement automatically.

2. **Two channel-4 dev-only overrides.** `REPOS_STATE_DIR` is the state-root
   override analogous to `<APP>_DB_PATH`, and `REPOS_GIT_BIN` names the `git`
   binary (default `git`, resolved on `PATH`) so a test or a box with git
   somewhere unusual can point at it. Neither is an operator tuning knob and
   neither enters the manifest.

3. **No channel-2 values at all.** repos' `.envrc` carries **no credential
   line**: `ANTHROPIC_API_KEY` and `REPOS_GITHUB_ORG` are removed with the
   capabilities that needed them, and `bin/push-secrets` ships nothing for
   repos. The `.envrc` keeps exactly `source_up` and the local
   `REPOS_STATE_DIR` export. An environment with no secrets in it is the
   strongest form of the routing contract's compliance, and it is what makes the
   D14 boot smoke run with an empty credential set.

4. **Adoption of the box-path-literal guard.** This Decision adopts the root env
   contract's `[proof: per-service]` id **R-VKB6-SHHV**
   (`root project/design/D11.md`): a source-scan test in
   `cmd/repos/main_test.go` walks repos' non-test `.go` files and fails on any
   `"/opt` string literal.

**Rejected.**
- *Keep `REPOS_GITHUB_ORG` routed through the app-config parameter.* There is no
  GitHub in v2 — no org to name, no call to make. The value is deleted, not
  rerouted, and `~/.secrets/REPOS_GITHUB_ORG` stops being a seeding step.
- *Promote `REPOS_STATE_DIR` to the manifest.* The install layout composes the
  state root from `IKIGENBA_ROOT` in-binary (root D11); a manifest line naming a
  path would be exactly the box-path literal that contract removes.
- *Put the run-token TTL in the DB as per-repository policy.* It is one number
  an operator might tune once; a schema column and a management verb for it
  would be machinery with no caller.
- *Drop `REPOS_MAX_COMMIT_BYTES` and hard-code the cap.* The cap is the only
  thing standing between a runaway sync and the box's memory; an operator who
  hits it needs a way to raise it without a release.

**Verification.**
- R-L9EG-DDWC — with no environment set, the resolved values of
  `REPOS_RUN_TOKEN_TTL` and `REPOS_MAX_COMMIT_BYTES` equal the values stated in
  the committed `repos/etc/manifest.env` (parse the committed file, compare
  against the code's resolved defaults) — an edit to either side alone fails —
  and the committed manifest contains **no** key outside the Spec's declared
  set, in particular no `REPOS_PROVIDER`, `REPOS_MODEL`, `REPOS_SESSION_TTL`,
  `REPOS_MAX_SESSIONS`, or `CONSUMES` line. Substrate: unit test in
  `cmd/repos/main_test.go` reading the committed manifest.
- Adopts **R-VKB6-SHHV** (`root project/design/D11.md`, `[proof: per-service]`)
  — no `"/opt` string literal in repos' non-test Go source. Substrate: the
  source-scan test in `cmd/repos/main_test.go`.
- The `.envrc` content is config, not testable behavior; that it carries no
  credential line is checked in the phase's done bar (an exact-line grep), not
  as an id.
