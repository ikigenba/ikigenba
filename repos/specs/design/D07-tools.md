# D07-tools

The five tools that tell a caller what repositories it has and change them: `list`, `show`, `create`, `rename` and `delete`, and the package `internal/clone` whose clone address and credential guidance `show`, `create` and `rename` answer with and the landing page shows (`D04-pages`). Each tool's `tools/list` entry, its input and output schemas, its kind, the refusal of arguments as they are read against the input schema, and the one answer every tool gives when the store cannot be reached are `D06-mcp`'s; `status` is `D09-limits`'. This document is the call: which repository an argument names, the rules a tool holds its arguments to and the words of each refusal, what a success answers member by member, what it changes in the catalog and on disk, and the events it records. The store's behaviour (how a repository is minted, written, renamed, removed, measured and verified) is `D05-store`'s; busy and `TryHold` are `D09-limits`'.

## The caller's repositories

Every tool works for its caller alone. The caller is the `identity.Caller` the tool's handler receives (D01's vocabulary), and its repositories are what `Store.List` answers for its user id. A `repo` argument names the caller's repository whose id it equals when it begins `rep_`, and whose name it equals otherwise; another user's repository, an id never minted, a value that is not a well-formed id (`rep_zz`) and a value that is not a valid name all name none, and are refused alike with `repo: no repository '<repo>'`, quoting the value exactly as sent. Because the answer is the same for an id another user holds and one never minted, the caller learns nothing about other users' repositories.

## Rules and refusals

A tool's handler is reached only with arguments appkit's decoding found no offence in (`D06-mcp`). From there each tool holds them to repos' rules, checks every rule, and reports every broken one in one answer, `invalid arguments:` and then one `<field>: <reason>` line per offence in the order of the tool's input schema: `repo` before `name`. The reasons are exactly three: `name: must be 1 to 64 lowercase letters, digits, or '-', starting with a letter or digit` for a name `store.ValidName` refuses (nothing is trimmed or folded, so ` notes`, `Notes` and `notes.git` are all refused); `name: '<name>' is already one of your repositories` for a valid name another of the caller's repositories holds; and the `repo` line above. A name is held to the first rule before the second, so one `name` line at most. `rename` judges a taken name among the caller's repositories whatever `repo` says, so a model that misnames the repository and picks a taken name learns both. A taken name is decided by the catalog: if `Store.Create` or `Store.Rename` answers `store.ErrNameTaken` (another call took the name first), the answer is the same taken line.

`delete` alone has a refusal that is not a rule offence: while the repository is busy (a fetch, a push or a maintenance run on it in flight, or a `TryHold` on it held), it answers `repository '<name>' is busy; try again once its git operations finish`, with the repository's own current name however `repo` named it. `delete` takes the repository with `Limits.TryHold(id)`; when that fails the repository is busy, and when it succeeds the hold is kept until the directory and the catalog entry are gone and then released, so nothing starts on the repository while it is being removed. An operation still waiting for its slot is not in flight and does not make the repository busy (`D09-limits`); one whose repository is deleted while it waits is answered `repository not found` when it leaves the queue (`D08-git`, `D09-limits`). `rename` is never refused while git runs: it moves nothing on disk.

Any other error a store method returns (one that is neither `store.ErrNotFound` nor `store.ErrNameTaken`) is an unreachable store, answered as `D06-mcp` states for every tool (R-ZCXC-ZLTY), having changed nothing (R-ZFD5-R5BC), except that a `name` the naming rule refuses is still answered with the naming line (R-ZE59-DDKN); a `rename` so refused carries no `repo` line, since whether the repository exists could not be read. A refusal of any kind creates, renames and removes nothing and records no domain event; its `tool.called` has the outcome `error`, as appkit records for a handler that returned an error.

## What a success answers

Each answer is made from these store methods, in this order, and from nothing else of the store; any of them failing is the unreachable store of `D06-mcp`: `list` from `List`, then `Size` and `Head` for each repository; `show` from `Find`, then `Size` and `Head`; `create` from `Create`, then `Size`; `rename` from `Find`, then `Rename` when `Find` found the repository, then `List` (to judge a taken name) when `Find` or `Rename` found nothing, else `Size` and `Head`; `delete` from `Find`, then (after `Limits.TryHold`, which is not the store) `Delete`. A `Rename` that answers `store.ErrNameTaken` gives the taken line, and one that answers `store.ErrNotFound` (the repository deleted between `Find` and `Rename`) gives the `repo` line, as if `Find` had found nothing.


`show`, `create` and `rename` answer the **repository object**: `id`, `name`, `default_branch`, `head`, `size_bytes`, `available`, `created`, `clone_url`, `credentials`, in that order. `default_branch` is always `main` (`store.DefaultBranch`). `head` is the sha `Store.Head` answers, the one the ref named exactly `refs/heads/main` points at, and absent when it answers the empty string: before the first push, and always for an unavailable repository, whose directory is not read (and `show` never verifies it again; only a restart does, `D05-store`). `size_bytes` is what `Store.Size` measures when the call runs, 0 for an unavailable repository whose directory is gone. `created` is the catalog's created time, RFC 3339 in UTC to the second. `clone_url` and `credentials` are built for the request the call came in, not stored: `clone_url` is `clone.URL(base, name)` and `credentials` is `clone.Guidance(base).Text()`, where `base` is the clone address the request's context carries (`clone.FromContext`), which `web.Handler` puts there as `clone.Base` of the request and its services path (`D03-serve`). `list` answers `{"repos":[...]}`, one **listing entry** per repository the caller owns, by name ascending, each `id`, `name`, `size_bytes`, `head`, `available`, valued as in the repository object. `delete` answers `{"id":"<id>","name":"<name>"}`, what the repository was.

`head` is absent, not `null`, when there is no sha to give: appkit's schema rule has no nullable form, so `D06-mcp` makes `head` an optional string that a result leaves out. Restoring `null` takes an appkit release whose schema rule has one.

## Effects and events

`create` makes the repository through `Store.Create` (`D05-store` fixes its id, created time, directory and configuration): afterwards the catalog holds it, owned by the caller, available, and `state/repos/` holds one more entry, `<id>.git`, a bare repository with no refs whose `HEAD` is `refs/heads/main`; no directory is ever named by the name. `rename` changes the catalog's name and, for an available repository, the directory's `ikigenba.name`, and nothing else: the id, the directory's path, the refs and the created time stay; for an unavailable repository the directory is not written to at all. Renaming to the current name is a success that writes nothing. `delete` removes the catalog entry and whatever is at the directory's path, an unavailable repository's included; a second delete finds nothing and is refused as for any repository the caller does not have.

A `create` that makes a repository records `repo.created`, a `rename` that changes a name `repo.renamed`, and a `delete` that removes one `repo.deleted`, each once, with the attributes and envelope D01 fixes (R-TS0F-02ZY): the repository's id and its owner, the caller. Each is recorded before the call's `tool.called`, so the trail of the request reads `request.started`, the domain event, `tool.called`, `request.finished`. `list` and `show` record nothing of their own. That no answer writes to stderr is `D03-serve`'s.

## Clone address and credential guidance

`clone.Base(r, servicesPath)` is `<repos-url>` of `S03`: the `url` of the services file's first entry named `repos`, with one trailing `/` dropped, read afresh for the call; when the file names no such entry, its `url` is empty, or the file cannot be read, it is the request's scheme, `://`, and its `Host` exactly as it arrived, port kept. The scheme is `X-Forwarded-Proto` when that header is exactly `http` or `https`, and `https` for anything else. Nothing else of the request is read, so the address never carries a credential whatever the request held. `clone.Guidance(base)` splits the guidance into the three parts the landing page shows separately: `Intro`, the first line; `Helper`, the command whose credential scope is the base's scheme, `://*.`, and its **space** (its host, port kept, with one leading `repos.` label dropped); and `Warning`, the last line. `Text` joins them with an empty line between each, the five lines `S03` fixes. The scope's `*.` matches any single leading label (gitcredentials(7), "Credential contexts"), which is why the space keeps its port and drops only `repos.`: the helper answers for every service of the space, the same command the mcp gateway's connect page gives.

## Decisions

- A base with no `://` (a services entry whose `url` names no scheme) is read as scheme `https` with the whole base before its first `/` as the host; the stories leave this case open.
- `list` sorts by name in byte order; names are ASCII, so this is the alphabetical order the stories show.
- `delete` checks `repo` before busy: an unknown repository has no name to quote.
- A rename to the name the repository already has is checked before the taken rule, so it is a success and never `already one of your repositories`.
- A `rename` whose `name` breaks the naming rule while the store cannot be reached answers the naming line alone, with no `repo` line.
- A create or rename that loses a race for a name to another call is answered with the taken line, never as an unreachable store.

## Consumer tasks

A model creates a repository with `{"name":"drafts"}`, pushes to the `clone_url` it was answered after running the helper command from `credentials`, lists with `{}`, shows with `{"repo":"drafts"}` or with the id it was given, renames with `{"repo":"drafts","name":"notebook"}`, and deletes with `{"repo":"notebook"}`, retrying a `delete` refused as busy once `status` shows the repository not busy. It is refused with `invalid arguments:` and `name: must be 1 to 64 lowercase letters, digits, or '-', starting with a letter or digit` for `{"name":"My Drafts"}`, with `name: 'site' is already one of your repositories` for a name it has, and with `repo: no repository 'drafts'` for a repository it lacks.

The landing page (`D04-pages`) builds its `Clone with git` section from the same values a tool answers: it takes `base` as `clone.Base(r, cfg.ServicesPath)` for the page's request, shows `clone.URL(base, "<name>")` as the clone address, and `clone.Guidance(base)`'s `Intro`, `Helper` and `Warning` as the paragraph, the command and the paragraph `S03` names.

A tools test sets `IKIGENBA_SERVICES` with `t.Setenv` to the empty string, opens a catalog with appkit's `db.Open` in a temporary directory, with `repos.Migrations()` and a fixed clock, and a store over it with `store.Open`, a fixed `Now` and a seeded `Rand`, builds `limits.New` with its own clock, a writer over a `*telemetry.Capture`, `mcp.NewServer` over that writer and `tools.Register`, serves the server on loopback inside a wrapper that adds `clone.NewContext(ctx, "https://repos.sbx.ikigenba.dev")`, inside `identity.Require`, inside `telemetry.Middleware` over the same writer (so each call records `request.started` and `request.finished` under the request id the client's `X-Request-Id` carries), and calls the tools with `mcp.Client.CallTool` as a caller with user id `u_7f3a9c21`. It reads `Result` as JSON and compares `structuredContent` member by member, in order, and the single text block; it reads a created repository back with real `git --git-dir=<Store.Dir(id)>` (`for-each-ref`, `symbolic-ref HEAD`, `config --file <dir>/config --get ikigenba.name`) under its isolated git environment; it calls `Writer.Flush` and reads the `Capture` for `repo.created` before `tool.called`. Busy is made with `Limits.TryHold(id)` on the test's own `*limits.Limits` before the call, and released after; a fetch in flight making a repository busy is proved here too (R-8YQS-MEOV): the test builds one `*limits.Limits` and hands it both to the tools server and to `smarthttp.Handler`, starts a `POST /<name>.git/git-upload-pack` whose request body it holds open with an `io.Pipe`, calls `delete` while that fetch is in flight, checks the busy refusal, then closes the body, lets the fetch end, and calls `delete` again to see it succeed; a push is held the same way, and maintenance with `maintenance.Config.Hold`. A store that cannot be reached is made by calling `SetFailing(true)` on the handle the store was opened over (`D05-store`), and `SetFailing(false)` before the test ends. An unavailable repository is made by removing a directory (or its `HEAD`) before `Store.Verify`. `clone.Base` is tested directly on `httptest.NewRequest` values with services files the test writes; that `web.Handler` carries it into the tools is `D03-serve`'s. No fixture, name, argument or expected text in such a test has the shape of a requirement id.
