# D03-serve

The serve path: what happens between `cli.Run` being called with no arguments and the process being gone, the trail connections records of itself, and the route table its handler keeps. It is artifacts' serve path with three differences: there is no sweeper and no blob directory, so the start opens the database, removes the pending states whose expiry has passed, and serves; the route table sends the provider paths, `/<provider>/connect`, `/<provider>/callback` and `/<provider>/disconnect`, and the token paths under `/token/` to the routes other documents define, and everything else that is not the bus's, the MCP server's or appkit's to the page handler; and the handler carries what those routes need to speak to a provider: a `providers.Client` per entry, the callback origin and the clock and randomness for state values and verifiers. `internal/server` is artifacts', unchanged.

## The terms connections serves on

connections serves only on a listening socket it inherits, taken as `sd_listen_fds(3)` documents, and reports readiness with `READY=1` to `NOTIFY_SOCKET` as `sd_notify(3)` documents. It trusts `X-User-Id`, `X-User-Email` and `X-Request-Id` as nginx sets them, and trusts the MCP gateway and every sibling calling it at its socket to have set them truly: a process that can reach the socket can name any user, and every service on the host is trusted, as artifacts decided (decision 17). That trust is what makes the token route safe to serve at all: the fragment answers `/token/` 404 at the public name (`D02-cli`), so only a process on the host reaches it, and it answers for whichever user the headers name. Every request has an id: the one nginx set, or 32 lowercase hexadecimal digits appkit's request middleware draws from `Process.Rand`.

The events app reaches connections at its socket on `/events` and `/declarations`. connections accepts no event, so it mounts appkit's `events.DeliveryHandler` with no handlers, and `events.DeclarationsHandler` over its emitter, built with the declarations of `trail.Emits()` (`D09-trail`). These two paths sit outside the identity gate, since a delivery carries no user; the fragment answers both 404 at the public name.

## The route table

Every request goes through appkit's `telemetry.Middleware`, which records `request.started` and `request.finished`; the path it records is the URL path alone, so a callback's `code` and `state`, which travel in the query, never reach the trail. Then, by the URL path alone, whatever the host, compared by hand so that nothing is cleaned and nothing redirected: exactly `/events` and exactly `/declarations` go to the event bus's two handlers; every other request goes through `identity.Require`, which answers a request with no `X-User-Id` 500 with `identity.MissingBody` before its path or method is looked at. Past the gate:

- exactly `/mcp` goes, through `events.Middleware`, to the MCP server, on which the three tools of `D10-tools` are registered once when the handler is built;
- a path that begins `/token/` goes, through `events.Middleware`, to the token route whatever its method (`D07-token-and-disconnect`), which answers JSON for every outcome, an unknown provider included;
- a provider path, `/<name>/<action>`, whose `<name>` is the `Name` of an entry of the table: `connect` with `GET` or `POST` goes to the connect route and `callback` with `GET` to the callback route (`D06-connect`), and `disconnect` with `POST` to the disconnect route (`D08-pages`), each through `events.Middleware`; a `POST` of either the connect or the disconnect route is refused 403 by that route unless its `Origin` names connections' own origin (`urls.SameOrigin`, `D06-connect`);
- a path beginning `/_appkit/` goes to `page.Static()`;
- every other path, a provider path naming no entry or asked with another method included, goes to the page handler (`D08-pages`), which answers `/`, `/about`, `/tools`, a disconnect path asked with another method (405) and, for everything else, the not-found page.

On a host nginx demands a credential before any of these, so the gate's 500 is only seen by a caller on the socket.

## The start

With `Args` empty, `Run` checks the secrets and then the settings (`D01-layout-and-run-seam`), then whether exactly one socket was passed in, exactly as artifacts does, with the same diagnostics after `connections: `. It removes the three `LISTEN_*` variables, takes descriptor 3, and opens the database with `db.Open` at `state/connections.db`; a failure is `connections: cannot open database state/connections.db: ` and the reason, exit 1, with nothing sent to the notification socket and no connection accepted. It builds the store, the writer and the emitter, records `service.started`, so that it is the first event of every run, removes every pending state whose expiry has passed (`D04-store`), builds the handler, sends `READY=1`, and serves. A removal that fails, the database being unreachable, is silent: the next pending state stored removes them again (`D04-store`).

## Stopping

When `ctx` is done `Run` drains the server for `DRAIN_SECONDS`, waits within the same window for the emitter to deliver what it holds, shuts the writer down with the cause's text as `service.stopping`'s reason, shuts the emitter down, and closes the database. A drain that runs out is `connections: stopped with <n> request(s) unfinished`, exit 1. Between its start and its return a serving `Run` writes nothing to standard output or standard error.

## Recorded decisions

- No sweeper (decision 7): nothing runs on a timer. Expired pending states go at start and whenever one is stored (decision 6); an expired connection's access token is refreshed only when asked for.
- `guests = false`, so the gate is `identity.Require` on every route but the events paths, the callback included, as in artifacts. A browser returning from the provider carries the person's session cookie to connections' host, so nginx's check admits it with their identity, and the callback can tell a foreign state (`D06-connect`).
- Unknown providers are settled in the route table: a provider path naming no entry never reaches the connect, callback or disconnect route, so those routes see only known providers and decision 1's not-found answer is the page handler's. The token route is the exception: it answers JSON, the not-found page being HTML, so it decides an unknown provider itself (`D07-token-and-disconnect`).
- A provider path asked with a method its route does not take, `PUT /google/connect`, `POST /google/callback` or `GET /google/disconnect` say, goes to the page handler, and its answer is `D08-pages`': the not-found page for a connect or callback path, and 405 with `Allow: POST` for a disconnect path, since the page handler owns the disconnect route whole. The route table answers nothing of its own.
- The token route takes every method under `/token/`, so its JSON contract covers a wrong method too; `D07-token-and-disconnect` says what it answers.
- The connect, callback, disconnect and token routes go through `events.Middleware`, as artifacts' `/files/` does, so an event they cause carries the cause and depth a sibling forwarded: a script run by an event that asks for a token whose refresh is refused emits `connection.broken` under that cause.
- `service.started` is recorded before the expired pending states are removed, as artifacts records it before its reconcile. The removal emits nothing either way.
- A failed removal at start is silent and does not refuse the start, unlike artifacts' failed reconcile: an expired pending state that survives is refused as expired by the callback (`D06-connect`) and removed when the next one is stored, so serving over it is harmless.
- `web.Config` carries the callback origin as the setting's value, empty when unset, and the services file's path; `D06-connect`'s `urls` derives the origin from the two. It carries the provider table as `providers.Client` values (`D05-providers`), which `Run` builds from each entry, the secrets it read under the entry's `ClientIDVar` and `ClientSecretVar`, its `HTTP` and its `Now`, so nothing below `Run` looks a variable up again.
- No `Process` hook fails the database `Run` opens: a failing store is proved through `web.Handler` over a store whose handle the test fails, by the documents that own each route.

## Consumer tasks

`Run`, serving, collects `names` over its table, calls `sec, err := settings.Secrets(p.LookupEnv, names)` and `s, err := settings.Read(p.LookupEnv)`, checks the socket, unsets the three `LISTEN_*` variables and takes `ln, _ := p.Inherit(3)`; calls `d, err := db.Open(ctx, db.Config{Path: filepath.Join(p.Dir, "state", "connections.db"), Migrations: connections.Migrations(), Now: p.Now, Service: pages.ServiceName, Stderr: p.Stderr})`; builds the store over `d`, one `providers.Client{Provider: e, ID: sec[e.ClientIDVar], Secret: sec[e.ClientSecretVar], HTTP: hc, Now: p.Now}` per entry `e`, `w := telemetry.New(...)` and `em := events.New(events.Config{..., Telemetry: w, Emits: trail.Emits()})`; calls `w.Ready()`; removes the expired pending states; builds `h := web.Handler(web.Config{Banner: p.Banner, MCP: p.MCP(w), ServicesPath: path, CallbackURL: s.CallbackURL, Clients: clients, Store: st, Telemetry: w, Events: em, Now: p.Now, Rand: rand})`; sends `READY=1`; and calls `server.Serve(ctx, ln, h, s.Drain(), stop)`. A test of the start drives `cli.Run` with a temporary `Dir`, a listener on a Unix socket in a short temporary directory, a `NOTIFY_SOCKET` it binds, a `Now` and a `Rand` it controls, a table pointing at a loopback fake provider, a `*telemetry.Capture` and an `*events.Capture`; it seeds `Dir` beforehand with a pending state from an earlier run whose expiry has passed by the later run's `Now`, or with a regular file at `state`. A test of the handler builds `web.Handler` over a store on its own database, a writer and an emitter over captures, a server from `mcp.NewServer`, `Clients` whose entries point at a fake provider, serves it with `httptest`, and sends raw requests with the identity headers set or left out.
