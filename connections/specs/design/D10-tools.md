# D10-tools

The three MCP tools agents reach connections by through the MCP gateway: `internal/tools`. No tool accepts or returns a token, a code or a secret; that is the point of the service. An agent lists the caller's connections, hands the person the link that connects one, and disconnects one. A connector gets its token on the host from the token route (`D07-token-and-disconnect`), never through a tool.

## The tools

- `list` takes nothing and answers one row per provider the broker knows, in the provider table's order (`D05-providers`), for the caller: the provider's name and display name, its status, and, when the caller has a connection for it, the connected account and the connection's created time, and always the granted scopes as stored (`[]` when not connected), under `connections`.
- `connect` takes `provider` and answers `{url, instructions}`: the connect page's absolute address on the connections host and one line telling the agent to hand it to the person. It stores nothing and emits nothing: the pending state is stored when the person opens the page (`D06-connect`).
- `disconnect` takes `provider`, disconnects the caller's connection through the broker's `Disconnect` (`D07-token-and-disconnect`), which revokes the grant at the provider and deletes the connection whatever the provider answers, and answers `{"deleted":true,"id":"con_…"}`. The broker records and emits `connection.deleted` as the caller (`D09-trail`).

Every tool acts on the caller's connections alone: another user's connection is never listed, and never disconnected.

## Status

A row's status is one of three words, declared once here and used by the landing page (`D08-pages`) too: `connected`, `broken` and `not_connected`. A provider the caller has no connection for is `not_connected`. A connection is `broken` when its stored status is `store.StatusBroken`, which the token route sets when the provider refuses a refresh, or when its granted scopes lack the name under which the provider grants any scope it requests (`D05-providers`: Google grants `email` as `https://www.googleapis.com/auth/userinfo.email`); otherwise it is `connected`. A scope-lacking connection still answers its token on the token route; only its status shows it needs reconnecting.

## The connect address

`connect`'s `url` is the connect page of the base the tools are registered with: the services file's entry `connections`, read once when `web.Handler` is built, followed by `/<provider>/connect`; with no entry it is relative, `/<provider>/connect`, as artifacts' `import` plan is. Through the gateway the request's `Host` is the gateway's backend name, so the services file's entry decides it, never the request; on `us` it is `https://connections.us.ikigenba.dev/google/connect`. The 409 the token route answers names the same address (`D07-token-and-disconnect`).

## Descriptions

Every tool's description is its own first line, an empty line, and `tools.CredentialGuide`, one constant line shared by all three: no tool carries a credential, `connect` answers the URL the person opens to connect, and connectors get their tokens on the host. It names no host, so the catalog takes no base, and every `ListTools` and the tools page give the same text whatever the services file says.

## Refusals

A provider that is no entry of the table is refused with `tools.UnknownProvider`; a `disconnect` for a provider the caller has no connection for with `tools.NoConnection`; and the database with `store.Unreachable`. A refusal is an MCP error result whose text is the copy function's answer, which appkit makes of a handler's error, as artifacts'.

## Recorded decisions

- `list` and `connect` are `mcp.Read`; `disconnect` is `mcp.Destructive`. `connect` changes nothing, as artifacts' `import` is a read tool for the same reason (decisions document, decision 9).
- `connect` checks the provider against the table and reads nothing else: it does not look at whether the caller is connected, so reconnecting a broken connection takes the same link.
- `disconnect` with no connection is refused, not answered as a no-op (decision 9), while the landing page's form answers 302 to `/` for the same case (`D08-pages`): an agent is told nothing happened; a person is shown the list.
- The status words and `StatusOf` live in `tools`, not `pages`: `pages` already imports `tools` for the catalog, so both reach one declaration without a new package.
- `account` and `connected` are pointers, absent for `not_connected`, as artifacts' `expires` is absent when nil. `scopes` is always present, `[]` for `not_connected` (root decision): appkit's tool registration takes no `omitempty` tag and its encoder omits only nil pointers, so a slice member cannot be absent.
- With no services entry `connections`, `connect`'s `url` is the relative `/<provider>/connect`, a departure from decision 9's "absolute URL": there is no absolute address to give, and artifacts' `import` answers its relative `/files/<path>` in the same case (artifacts' import design). On a host and in a sandbox the entry exists, so the answer is absolute there.
- `connected` is the connection's created time, RFC 3339 UTC to the second (decision 9 and the brief); a reconnect keeps it (`D04-store`).
- Description shape is artifacts': first line, an empty line, the shared constant. Non-normative guidance for the copy `tools.CredentialGuide` holds, which binds nothing: "No tool carries a credential: connect answers the URL a person opens to connect an account, and connectors get their tokens on the host."
- `tools.Config` carries the broker for `disconnect` and no writer or emitter of its own: the broker records and emits (`D07-token-and-disconnect`).

## Consumer tasks

`D03-serve` registers the tools on the server it mounts at `/mcp` with `tools.Register(srv, tools.Config{Base: base, Providers: provs, Store: st, Broker: b})`, `base` being the services file's entry `connections` with no trailing `/`, empty with none, which is `urls.Configured(cfg.ServicesPath)` (`D06-connect`), and `provs` each `cfg.Clients[i].Provider` in table order. The tools page reads `tools.Catalog()` and `tools.FirstLine`, and the landing page `tools.StatusOf` and the three status constants (`D08-pages`). A test builds a store over its own database, a broker over it whose providers point at a loopback fake provider, an `mcp.Server` with a capturing writer, an emitter over `events.Capture`, registers the tools, serves the server inside `identity.Require`, and calls `mcp.Client.CallTool` with `tools.ListArgs{}` and `tools.ProviderArgs{Provider: "google"}` encoded as JSON, decoding a success result's structured content into `tools.ConnectionList`, `tools.Link` or `tools.Deleted` and comparing a refusal's text with `tools.UnknownProvider(p)`, `tools.NoConnection(p)` or `store.Unreachable`.
