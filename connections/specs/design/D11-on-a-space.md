# D11-on-a-space

What connections contributes when it runs on a space and in a sandbox, and the one guarantee no earlier document owns whole: no credential connections holds, mints or is handed reaches anything it records or writes, or any page or tool answer, in whole or in part. It follows artifacts' on-a-space design.

## What ships

The release holds four members of connections' directory: `bin/connections`, `etc/manifest.toml`, `etc/nginx.conf` and `share/icon.svg`, the last Tabler's `plug-connected` outline, human-authored. No test reads the checkout, so the release and the icon are outside what a requirement can state; a developer checks them with `tar`. The manifest's lines carry what a space asks of it (`D02-cli`): `guests = false`, so the host's nginx puts every request through auth's `/check` and admits only one with a credential; `mcp = true`, so the gateway offers its tools; `secrets` naming `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`, auth's names, so the host gives connections auth's Google client; no `[env]`; `[database]` naming `state/connections.db`, which the host keeps and replicates; `[resources]` with `memory_max = "128M"`; and `[home]`, which puts connections in the `core` group of home's landing page. The fragment answers `/token/` and the bus's two paths 404 at the public name.

## On a space

connections on a space is the same binary serving on the same terms as under a test: a socket passed as descriptor 3 (`/run/ikigenba/connections.sock`), `/var/opt/ikigenba/connections` as its working directory, so its state is `/var/opt/ikigenba/connections/state/`, its secrets and settings from `/etc/opt/ikigenba/connections/env`, and `IKIGENBA_SERVICES` naming the host's services file. No `IKIGENBA_CALLBACK_URL` is set on a host, so the redirect URI is the services file's entry `connections` followed by `/<provider>/callback`; on `us` that is `https://connections.us.ikigenba.dev/google/callback`, registered on the production web client beforehand.

## In a sandbox

The sandbox builds connections from the worktree, gives it `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` mapped from the Desktop client's keyring entries, as it does for every app that lists them, puts every request through auth's `/check` because the manifest has `guests = false`, and includes `etc/nginx.conf` in connections' server. It gives every app `IKIGENBA_CALLBACK_URL`, the bare-localhost origin, so the redirect URI is `http://localhost:<port>/google/callback`; the sandbox's bare-localhost server sends a request whose `state` begins `connections.` on to connections' origin at the same path and query, which is the sandbox's own rule (decision 16) and outside this design; connections' part is the state's prefix (`D06-connect`). Its state is `<data>/apps/connections/state/`. An agent is curl on the developer's machine with the stored token at `http://connections.<sandbox>.localhost:<port>/`, the gateway for the tools, and the connections socket with the identity headers for `/token/<provider>`; the sandbox check seeds a grant straight into `state/connections.db` and removes it afterwards.

## The guarantee

Decision 12 forbids any access token, refresh token, authorization code, PKCE verifier, state value or client secret to reach telemetry, the bus, a page, a tool answer, standard error or the logs, in whole or in part, on success or failure. The logs are standard error, so five channels are searched. A test can choose four of these values and so mark them as artifacts marks a body: the client secret, handed in as a setting; the code, handed in on the callback's query and received by the fake provider in a token request, whether it accepts it or not; and the access and refresh tokens, issued by the fake provider or seeded through the store. The other two, the state value and the verifier, connections mints from `Rand`, so the test takes `Rand` nil, lets them be random, and learns each where it must travel: the state from the connect route's `Location`, the verifier from the token request the fake provider receives. A random value cannot be shaped like a marked one, so it is searched for by longer runs, where a coincidence is negligible.

The access token is the token route's product: a 200 answer of `GET /token/<provider>` carries it, and nothing else does. The state travels to the provider in the connect route's `Location` and back on the callback's query, and nowhere else. The verifier travels only in the token request to the provider.

## Recorded decisions

- Decision 12's six values are covered: the client secret, the code and the access and refresh tokens as marked values, the state and the verifier as minted values. The caller's own credential never reaches connections, since nginx consumes it, and the identity headers carry no secret; neither is marked.
- The account's email, its subject, the provider's name and the granted scopes are not secrets and do travel on the trail and the bus (`D09-trail`) and on the pages and in `list`.
- Departure from artifacts' and webhooks' guarantees: the state and verifier are minted, not chosen. The test takes `Rand` nil and learns them where they must travel (the connect route's `Location`, the fake's token request), where artifacts and webhooks marked only values the test chose or derived from a `Rand` it controlled. A shaped `Rand` cannot make a hexadecimal state satisfy the marked-value rule, and a controlled one would make request ids and states coincide.
- Departure from artifacts' guarantee: answers are searched in their headers as well as their bodies, since the state travels in a `Location` header and a credential could leak into any header; artifacts searched page bodies and tool results only.
- The state and verifier are searched by runs of 16 characters, a marked value by runs of 8, as artifacts' and webhooks' guarantees search: 16 characters of a random hexadecimal or base64url value cannot coincide with a request id or an event id drawn from the same reader with any probability a test would meet.
- The code a refused or failed callback carried, and the error a provider answered, are left out of the notice page and the trail as well: the notice names the failure only (`D06-connect`, `D08-pages`).

## Consumer tasks

A test builds a `cli.Process` with a temporary `Dir`, a `LookupEnv` over a map giving the fake entry's client id and a marked client secret and an `IKIGENBA_CALLBACK_URL`, capturing `Sink` and `EventSink`, a `Stderr` buffer, its own `Now` and a nil `Rand`, and a `Providers` table and `HTTP` pointing at a loopback fake provider that issues marked codes and tokens, refuses or fails on demand, and records each request it receives. It drives the connect, callback, token and disconnect routes with raw HTTP as two users, `/mcp` with `mcp.Client`, and the pages with raw `GET`s, seeds a connection with marked tokens through the store, then searches every captured event's JSON, every bus event's JSON, `Stderr`, every tool result's JSON, and every answer's headers and body for each run of each marked or minted value, ignoring ASCII case.

## REQUIREMENTS

- R-0Y6K-XN5C: connections' design defines a **marked value** as a value a test chooses of at least 16 ASCII letters and digits in which every run of 8 consecutive characters holds a letter outside `a`–`f` and `A`–`F`, used as exactly one of a client secret, which the test hands connections only as the value `LookupEnv` gives for an entry's `ClientSecretVar`; an authorization code, which the test hands connections only as the `code` query parameter of a callback, counted as marked once its fake provider receives it in a token request, whether the fake accepts it or not; or an access or refresh token, which the test's fake provider answers in a token response or the test stores in a connection it seeds through the store (`D04-store`); and which occurs nowhere else in what the test hands connections — no path, header, other query parameter, tool argument, other value `LookupEnv` gives, or part of the services file; every requirement of connections' design that names a marked value MUST denote such a value.
- R-2LCX-7DO1: connections' design defines a **minted value** of a run of `cli.Run` whose `Rand` is nil as either the 32 hexadecimal digits after `connections.` of a state value that run put in the `Location` of a connect route's answer, or a PKCE verifier that run sent as the `code_verifier` of a token request to a provider; every requirement of connections' design that names a minted value MUST denote such a value.
- R-0ZEH-BEW1: Over a run of `cli.Run` with capturing sinks, a nil `Rand`, a `Providers` table and `HTTP` reaching a fake provider, and marked values (R-0Y6K-XN5C), that serves, for two users, a `GET` of a connect route and a `POST` of one carrying an `Origin` header for which `urls.SameOrigin` (`D06-connect`) is true; callbacks with no state, with an unknown state, with an expired state, with the other user's state, with `error=access_denied`, with a code the provider refuses, with a code whose exchange fails, with an id token lacking `email`, and with a code that succeeds; `GET /token/<name>` for a fresh access token, for one that needs a refresh the provider grants with new access and refresh tokens, for one whose refresh fails, for one whose refresh the provider refuses, and for a connection already stored as broken; a reconnect; a `POST` of the disconnect route, carrying such an `Origin` header, whose revoke the provider refuses, a disconnect whose revoke fails, the provider being unreachable or answering 5xx, and a `disconnect` call whose revoke succeeds; `list` and `connect` calls; and `GET`s of `/`, `/about`, `/tools` and a path that is not a page; no event the `Sink` is handed, no bus event the `EventSink` is handed, and nothing written to `Stderr` MUST contain, ignoring ASCII case, any run of 8 or more consecutive characters of any marked value, or any run of 16 or more consecutive characters of any minted value (R-2LCX-7DO1), of that run.
- R-10MD-P6MQ: In the run R-0ZEH-BEW1 states, no tool result `mcp.Client` returns, in any member of its JSON, and no header or body of any answer the run gives MUST contain, ignoring ASCII case, any run of 8 or more consecutive characters of a client secret, an authorization code or a refresh token that is a marked value, or any run of 16 or more consecutive characters of a verifier that is a minted value; no header or body of any answer but a 200 answer of a `GET /token/<name>` MUST contain such a run of an access token that is a marked value; and no header or body of any answer but the `Location` of a connect route's answer MUST contain such a run of a state's minted value.
