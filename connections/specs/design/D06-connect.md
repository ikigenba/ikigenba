# D06-connect

Connecting an account: `internal/urls`, the addresses connections builds, and `internal/broker`, the operations the routes and the tools share, with the two routes a browser walks through to connect, `/<provider>/connect` and `/<provider>/callback`. A person presses Connect on the landing page, or opens the link the `connect` tool handed an agent; the connect route stores a pending state and sends the browser to the provider; the provider sends it back to the callback route, which takes the pending state, exchanges the code for a grant, stores the connection and sends the browser to the landing page. It follows auth's sign-in for the authorization-code flow with PKCE and its pending states, and artifacts' `urls` for the addresses. The token route and the broker's disconnect are `D07-token-and-disconnect`'s.

## Addresses

connections' **base** is the `URL` of the services file's entry `connections` without a trailing `/`, `urls.Configured`, or the empty string when the file has no such entry. The **connect page** of a provider is the base followed by `/<provider>/connect`, `urls.Connect`, which is relative when the base is empty, as artifacts' `import` plan is; the `connect` tool (`D10-tools`) and the token route's 409 (`D07-token-and-disconnect`) both name it. The **callback origin**, where a provider returns the browser, is `IKIGENBA_CALLBACK_URL` when it is set and the base otherwise, `urls.Callback`; in the sandbox it is the bare-localhost origin, whose nginx server sends a request whose `state` begins `connections.` on to connections, and on a host it is `https://connections.<space>`, registered with Google. The **redirect URI** of a provider is the callback origin followed by `/<provider>/callback`. `urls.Auth` is auth's address for the banner (`D08-pages`), as artifacts builds it.

A form that acts posts to connections' own origin. `urls.SameOrigin` says whether a request's `Origin` header names that origin, the forwarded scheme, `://` and the request's `Host`, as auth's forms require (auth's tokens design); a `POST` of the connect route that fails it is refused 403 with `urls.CrossOrigin`, and so is a `POST` of the disconnect route (`D08-pages`).

## The broker

`broker.New` builds the one broker `web.Handler` keeps, over the run's `providers.Client` values, the store, the writer, the emitter, the callback setting, the services file's path, the clock and the random source (`D03-serve`). Every operation acts for the caller its context carries, as appkit's `identity.FromContext` answers it, and for a provider named by the `Name` of a client's entry; a name no client has is `broker.ErrUnknownProvider`, and nothing is read, stored or asked.

`Begin` draws 16 random bytes for the state value, `connections.` and 32 lowercase hexadecimal digits, then a PKCE verifier, stores a pending state for the caller expiring ten minutes after now, and answers the provider's authorization URL with the redirect URI. With no callback origin it answers `ErrNoCallback` and draws and stores nothing.

`Complete` judges a callback's query in the order the decisions fix: no `state` is `ErrMissing`; then the pending state is taken (`D04-store`), its absence, including a state stored for another provider, being `ErrUnknown`, its expiry `ErrExpired` and another user's `ErrForeign`; then an `error` parameter is `ErrDenied`; then a missing code, or an exchange the provider refuses or fails, is `ErrExchange`, and an exchange with no account `ErrAccount`. Every failure after the state is taken has consumed it. Otherwise the grant is upserted, `connection.created` recorded and emitted (`D09-trail`), first connect and reconnect alike, and the connection answered.

## The routes

`GET` and `POST /<provider>/connect` are one route: the landing page's Connect and Reconnect buttons post, and the link the `connect` tool hands out is opened with a `GET`. Both answer 302 to the provider with an empty body; only the `POST` checks `Origin`. With no callback origin the route answers a plain 500 with `broker.NoCallback`, and with no randomness a plain 500 with `broker.NoRandom`.

`GET /<provider>/callback` answers 302 to `/` when the connection is stored, and otherwise the notice page with the provider's display name and the failure (`D08-pages`): 400 for `missing`, `unknown`, `expired`, `foreign` and `denied`, which are about the request, and 502 for `exchange` and `account`, which are about the provider's answer. Neither the notice page nor the trail carries the code, the state or the provider's error text. A database that cannot be reached is a plain 503 with `store.Unreachable` on either route.

Unknown providers and other methods never reach these routes: the route table sends them to the page handler (`D03-serve`).

## Recorded decisions

- The state value is `connections.` and 32 lowercase hexadecimal digits from 16 random bytes (brief, decision 2): the prefix is what the sandbox's bare-localhost server routes on (the decisions document's decision 16), and the digits are drawn before the verifier, so a test with a fixed random source knows both.
- The pending state's expiry is ten minutes after `Now` truncated to the second, as the decisions document says, and is declared as `broker.PendingLifetime`.
- `POST /<provider>/connect` must carry an `Origin` equal to the request's own origin, and is otherwise refused 403 with `urls.CrossOrigin` before anything is drawn or stored (root decision, after auth's `POST /tokens`). A `GET` has no such check: it is the link an agent hands a person, opened by a browser that sends no `Origin`. A cross-site `GET` can only start a flow that the provider's consent screen and the caller's own session finish, and the callback stores the grant against the caller, never the attacker.
- The request's own origin is the forwarded scheme (`https` unless `X-Forwarded-Proto` says `http`), `://` and `Host` as received. On a host nginx sets `Host` to `$host` and `X-Forwarded-Proto` to `$scheme`; in the sandbox `Host` is `$http_host`, port included, and `X-Forwarded-Proto` is `http`; in both, a browser's same-origin form post carries exactly that `Origin`. An `Origin` that is absent, `null`, repeated or differs in any byte is refused.
- The callback's checks run in the brief's order (decision 3). A callback whose `error` parameter is present, empty or not, is `denied` after the pending state is consumed. A callback with no `error` and no non-empty `code` is `exchange`, with no request to the provider, since a provider answering neither is malformed; the decisions document does not settle it.
- The notice statuses are 400 for the five failures a person's own request causes and 502 for the two a provider's answer causes (brief, decision 3).
- A database outage on the connect or callback route is a plain 503 with `store.Unreachable`, as artifacts' pages answer, never the notice page; a random source that fails is a plain 500 with `broker.NoRandom`, which the decisions document does not settle.
- With no callback origin, the connect route answers a plain 500 with `broker.NoCallback` and stores nothing (brief, decision 9): a space with neither the setting nor a services entry is misconfigured, and a redirect URI on the request's own host might not be registered with the provider.
- The callback origin is taken from the setting and the services file, never from the request: the redirect URI must equal one registered with the provider, and the request's `Host` on the socket can be anything.
- The broker returns its own sentinel errors for the seven failures, and the callback route maps them to `pages`' failure constants: `pages` imports `broker` for the disconnect (`D08-pages`), so `broker` cannot name `pages`' constants.
- A broker operation is stated for a context carrying a caller: every route is behind `identity.Require` and every tool is called with one, so a context without one is no case to design.
- The broker reads the services file for the callback origin and the base whenever an operation needs it; nothing in this design changes the file while connections runs.
- Only the callback answers the notice page. The notice template's comment also allows it "when the connect fails", but the connect route's failures are plain refusals instead: 500 with `broker.NoCallback`, 500 with `broker.NoRandom`, 503 with `store.Unreachable` and 403 with `urls.CrossOrigin`. Each is a fault of the space or a request no person's own click makes, not a failure of the person's connect with a provider, and the notice's failures name only the callback's seven.
- No `Cache-Control` and no body on the 302s: a body would repeat the `Location`, and with it the state value.

## Consumer tasks

`web.Handler` builds `b := broker.New(broker.Config{Clients: cfg.Clients, Store: cfg.Store, Telemetry: cfg.Telemetry, Events: cfg.Events, CallbackURL: cfg.CallbackURL, ServicesPath: cfg.ServicesPath, Now: cfg.Now, Rand: cfg.Rand})` and hands `b` to `pages.Config.Broker` and `tools.Config.Broker`, and `urls.Configured(cfg.ServicesPath)` to `tools.Config.Base`. The connect route refuses a `POST` for which `urls.SameOrigin(r)` is false with a plain refusal of 403 and `urls.CrossOrigin`, calls `loc, err := b.Begin(r.Context(), name)`, and answers 302 with `Location: loc`, or 500 with `broker.NoCallback` when `errors.Is(err, broker.ErrNoCallback)`, 500 with `broker.NoRandom` for `broker.ErrRandom`, and 503 with `store.Unreachable` for `store.ErrUnreachable`. The callback route calls `_, err := b.Complete(r.Context(), name, r.URL.Query())`, answers 302 to `/` on nil, maps `broker.ErrMissing` to `pages.FailureMissing` with 400 and so on through `broker.ErrAccount` to `pages.FailureAccount` with 502, and writes `set.Write(w, r, status, "notice", pages.NoticeData{Banner: banner, DisplayName: cl.Provider.DisplayName, Failure: f})`. The disconnect form (`D08-pages`) checks `urls.SameOrigin(r)` the same way. A test builds the handler over a store on its own database, a fake provider on `httptest`, `Clients` copied from `providers.Table()` pointed at it, a services file it writes or none, a `Rand` that yields bytes it chose and a fixed `Now`; it sends `GET /google/connect`, reads the state and the redirect URI from `Location`, checks the pending state with a later `TakePending`, sends the callback with the state and a code the fake accepts, and compares the store, the captured events, and the notice bodies with what its own `pages.Load()` set writes. A sibling's pending state is stored through `store.PutPending` under another user id.
